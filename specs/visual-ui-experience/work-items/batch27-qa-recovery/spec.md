## 文件与做法

- 写后检查由工作台拥有。将原有警示从 `.mw-form__body` 移到 `[data-wc=dialog]` 自己的固定操作栏首行，使用现有 `renderDialog`、`form-error` 与按钮。长文案换行，正文保有独立滚动。改动集中在 `apps/workbench/src/write-checkers-section.ts`、`apps/workbench/src/styles/settings.ts` 的对应标记与局部规则。请求、聚焦、版本检查和重读沿用现有逻辑。
- Pages 查找由 Pages 编辑器拥有。基点的查找栏定位在 Pages 的独立插件框架内，390 宽度的两行工作台页签在框架之外。真实滚动与内外两层命中已核回，本片补浏览器回归。
- 待办的 `flush` 已在详情显示无法保存的原因。`commands.ts`、`events.ts`、`quick.ts` 各自遇到这一步失败时停止原操作。真正读取不到选择的对象才会从 `events.ts` 报 `item-unreadable`。确认框沿用已有的异步确认，在 `detail.ts` 通过同一详情读取接线成功加载仍选中的记录后才接替草稿，失败在原确认框内显示并可取消或重试。`types.ts` 仅定义私有 `reloadDetail`，读取使用已有 `detailTicket`。详情成功后刷新当前过滤列表，列表读错显示在列表反馈区。
- 回归在 `tests/write-checkers-settings.e2e.test.ts`、`tests/pages-find.e2e.test.ts`、`tests/todo-draft-recovery.e2e.test.ts`。`tests/fixtures/goal-browser.ts` 从已拥有的公共测试浏览器打开第二页，沿原清理流程关闭两页和隔离 Home。截图在忽略的 QA 目录或临时目录。使用同一生产 Host、既有 HTTP 和浏览器入口，核对命中、键盘、落库和后续重读。

## 验证

基线和候选先 `pnpm build`，再经 `node scripts/machine-slot.mjs run browser --label "batch27 QA recovery" -- node scripts/run-tests.mjs --jobs 1` 点名上述三个用例文件。候选另查 `git diff --check` 与 `node scripts/check-health-gates.mjs --base origin/main`。包 README 的回归、页面资源比较和 CI Full 随整批执行。

### 基点实操

- QA-029 的 15 个组合都触发宿主版本冲突和非法程序拒绝，保存与取消可用，错误区域在当前视口内无法完整命中。1440×900 和 390×844 的截图可见表单保留输入，警示已被滚动区裁掉。额外测试的短窗为 1440×640、1024×600、390×500。
- QA-033 的 12 个组合均通过，尺寸为 1440×900、1024×768、390×844。390 的四个组合均验证真实两行标题栏，鼠标滚轮移动正文后查找控件仍可命中。替换后从 Pages owner 核对正文，再刷新并重新查找。原查找与替换回归同样在基点通过。
- QA-034 的真实双页签交错在 1440×900 实测留下旧列表红字。详情已经显示正确修订，再保存并返回列表也仍然出现旧冲突。390×844 的 Back 在拦住离开时把详情里的恢复提示换成宿主原始拒绝。

### 候选工程与实操

- 整体 `pnpm build`、健康门禁（`origin/main` 的共同基点 `54a12642`）和 `git diff --check` 通过。Chrome for Testing 157.0.8103.38 使用隔离 Home 和独立浏览器资料。首候选三文件运行中，Pages 14/14、Todo 15/15，写后检查的旧有 PA-40～43 三个用例通过。末轮经机器浏览器槽执行 `node scripts/run-tests.mjs --jobs 1 --verbose --test-name-pattern='QA-029|QA-034' tests/write-checkers-settings.e2e.test.ts tests/todo-draft-recovery.e2e.test.ts`，仅匹配新增两项，分别为 16/16、14/14。首轮与末轮日志分别为 `candidate-qa.log` 和 `final-qa029-034.log`。
- QA-029 的 15 个组合中，两种错误和操作按钮都可见并能命中。旧版在同一可见性断言稳定失败。候选首轮的测试输入只发 `keyDown`／`keyUp` 和 `windowsVirtualKeyCode: 13`，焦点在保存按钮，但未触发键盘提交。保留首轮日志，按仓库已有键盘测试补上 `nativeVirtualKeyCode: 13`、`text` 和 `unmodifiedText` 的 CR 字符。可见性断言与等待原样保留。最终以 Enter 修正保存后从 owner 读回新值和恰好一个新版本。英文界面的非法程序错误沿用宿主现有中文原因。
- QA-033 的同一 12 个组合在候选再次通过。基点的两行页签、滚动、指针命中、Esc、重开及替换后刷新证据保留，查找与替换算法沿原回归。
- QA-034 的 12 个组合验证真实 409、保稿、取消、确认重读、修正写入和前后两处反馈。列表／Back 的失败前置仅发被拒的原待办 POST。扩展场景通过工作台的事件桥尝试打开另一项。快建在详情打开期间由现有表单的 `requestSubmit()` 验证生产事件路径，返回列表后再真实点击验证错误及仅新建一次。以受控 HTTP 503 验证确认框保持可重试、原草稿与选中修订保留且输入不可聚焦，随后取消并真实重读。恢复请求为一次详情读取、一次链接候选读取、一次当前「未安排」列表读取，期间零写入。实际删除后的保存 404 与真实目标打开 404 分开验证。
