## 怎么打开

在仓库根目录运行，然后打开 <http://127.0.0.1:4471>：

```sh
python3 -m http.server 4471 --bind 127.0.0.1 --directory docs/design/sessions-sources
```

也可以直接用浏览器打开本目录的 `index.html`。底下一条斜纹是**原型控制**，不是产品的一部分：选「块」「方案」「状态」，切中英文和浅深色；「标出组件」见下；「还原」清掉本页记住的选择（`localStorage` 键 `molis-proto.sessions-sources.v1`）。读取范围 Sheet 打开时控制条跟着进 Sheet 的顶层，所以开着 Sheet 也能换状态；产品里没有这一条。

## 三处要定的

| 块 | 方案 | 取舍 |
| --- | --- | --- |
| 发现会话 | **A 按工具分组**：列表按工具分节，每节标题带数量；没读成、暂不支持的工具在自己那一节里占一行，点开看原因 | 每个工具的状态最清楚；但同一件事在两个工具里做的会话被拆开，工具多了要往下翻 |
| | **B 按时间排，来源条看状态（推荐）**：所有工具的会话按最近活动排在一起，行里写是哪个工具；读取进度、哪几个来源没读成放在列表上方一条提示里，「看每个来源」展开逐个看和处理 | 天天回来看最顺手，跨工具接着做的事挨在一起；来源都正常时只剩一行安静的说明。代价是来源细节要多点一下 |
| | **C 先看来源总览**：三栏，最左是来源（每个工具的数量和状态），中间是会话，右边是历史；1024 以下来源栏收成工具下拉 | 来源多、经常排查读取问题时最直观；平时多占一栏，详情变窄 |
| 归属建议 | **A 在会话里就地确认**：打开一个待归类的会话，顶上就是 AI 建议、理由与依据，确认、改选或先不归 | 不用另进一处；但要一个个打开，看历史时也一直被问 |
| | **B 待归类集中处理（推荐）**：「待归类 N」一处，每个会话一张卡：建议、理由、依据，下拉可改选，确认或先不归；看历史时只留一行提示和入口 | 一次处理完，看历史不被打扰；理由和依据都摆在眼前 |
| | **C 按建议的项目成组**：「建议归到 Molis Work · 3 个」一组，勾选后一次归入；没找到合适项目、没生成建议的各成一组 | 会话多时最快；但容易不看理由就整组确认 |
| 查看历史 | **A 原文对话（推荐）**：你、那个工具、它的工具步骤按原样往下排；顶上可搜索，往上读更早的 | 最接近原工具，什么都不加工；长会话靠搜索和往上读 |
| | **B 左边提问目录，右边原文**：左边是你每一次提问，点了跳过去；1100 以下目录收成下拉 | 长会话找段落快；详情区更挤 |
| | **C 要点在上，原文在下**：AI 按原文整理定下的、做出来的、还没完的，每条连回原文第几条，可纠正、按最新内容重整 | 冷启动接手最省事；要点是 AI 推断，要标清、要能纠正，模型不可用时只剩原文 |

三处在所有方案里都一样的：读取只在「读取范围」一处允许（Sheet：勾选工具、选目录；暂不支持的工具不能勾、写明原因），查看和搜索不会让原工具运行或发消息（详情顶上写明「只读」），改归属只改这一个会话（Dialog：不改目录与项目的关系、不搬文件、不改原工具里的记录）。

## 每块的状态

| 块 | 状态 |
| --- | --- |
| 发现会话 | 正在读（先出一部分）；全部读完；有来源没读成（需要登录、这一版读不了、没读成可重试，与「没有会话」分开）；读完了范围内没有会话；还没允许读；收窄了范围 |
| 归属建议 | 有建议待确认（含多候选、AI 没找到合适项目）；卡片先到，建议随后到（到之前能改选和先不归，你先选的不被覆盖；只画在方案 B 上）；建议没生成（模型不可用，保持待归类）；你改选后来了新建议（不覆盖你的选择）；都处理完了 |
| 查看历史 | 正常（原工具还在运行，只显示已读到的）；长历史在读更早的；会话里搜索；读到一半断了（已读的照常显示）；这一版读不了（不是没有历史）；已停止读取这个工具（之前读到的也不显示）；这个工具暂不支持读取（回到原工具） |

分叉出来的会话是新会话，带「从……分叉」的来源（盘点 §4 第 2 条）。

## 第四块：项目 AI 读取（待用户定）

需求来源：[原需求 §8](../../../specs/sessions-rebuild/spec.md#8-决策记录) 2026-11-06「读取权与归属分开」、[合同设计稿](../../../specs/sessions-rebuild/contract-design.md)第 6.5、7.4 节。已定不再讨论：一项目一个，默认关，开一次长期有效，只有本人能改，归在读取范围这件事里，团队项目先不开放。这里只定它的样子。

| 方案 | 开关放哪、怎样认项目、怎样看全部 | 取舍 |
| --- | --- | --- |
| **A Sheet 分两页，全部项目一张表（推荐）** | 读取范围 Sheet 分「工具与目录」「项目的 AI」两页；第二页一行一个项目，项目标识加名字加目录，当前项目在最上并标「当前」，其余按开着、关着分组，超过 8 个出搜索；页签上写 3/28 | 一处看全、改全，不多一个地方。两页把「点底下按钮才生效」的工具和「按下就生效」的开关分开，不用文字解释。被挡时 Sheet 盖在当前页上，不离开对话。代价：工具和项目要翻一页才同时看到；要看全部、改别的项目，合同还差两处（见下） |
| **B Sheet 顶上是当前项目，其他只看** | Sheet 不分页：最上是当前项目的开关，下面是工具和目录，「其他项目」收起，只看开关状态，要改先切过去 | 最贴现有合同：只改当前项目，只差一个只读列表。代价：同一屏里开关立刻生效、工具要点底下按钮，两种规则混在一起；改别的项目要先切项目；Sheet 最长 |
| **C 项目总览放进主区** | 主区多一个「项目的 AI」视图，一张表写归到这里多少、AI 现在读得到多少；Sheet 里只留一行摘要和「管理」入口 | 信息最全，项目多时最好扫。代价：多一个地方，和「界面在读取范围这一处」有出入；被挡时要离开当前页，靠「回到对话」回来；合同缺口和 A 一样，还要两个数字 |

**推荐 A。** 这个开关平时很少碰，第一次碰到多半是被挡的时候：A 让人留在原处，一眼看到是哪个项目，按一下就回去。B 是退路：合同那两处定不下来时用它。

三个方案共用的：

- **第一次碰到。** AI 要读被挡时，对话里在那一步下面出一张 `info` 提示，写明是默认关着、不是出错、不开也能接着做；两个按钮分量相当（「看看这个开关」「这次不用」），不用主按钮。场景页的卡片写「未就绪」，其他卡片不受影响。`next_step: open_project_ai_read` 带到开关：这个项目那一行染上 `--accent-soft`，焦点落在开关上。开了之后按钮变成「回到对话」，回去后可以「让它再试一次」；选了「这次不用」，这一轮不再提。缺工具和缺许可分开显示（[设计稿第 6.5 节](../../../specs/sessions-rebuild/contract-design.md#65-第-20-批怎样用)），先过工具这一关才出现许可这一关。
- **开之前看得到后果。** 每行写「N 个会话归到这里」，碰到的那一行多一个「看是哪些」。
- **开和关的回执写在这一行。** 开：「已开」和一直有效、随时能关。关：之前读到的不再给 AI，在跑的读取也会停下，已经写进回答的不会收回，自己照常能看。回执留到 Sheet 关上，不用一闪而过的 Toast。行不跟着跳组，下次打开才归到新组。
- **不诱导。** 默认全关，没有推荐标、没有红点、没有「开启后更好」，「这次不用」之后不再追问。

| 状态 | 看到什么 |
| --- | --- |
| 第一次碰到：AI 要读被挡 | 对话里的提示；开、这次不用、回到对话后再试一次，三条路都能走 |
| 第一次碰到：场景未就绪 | 场景卡「未就绪」；开了之后卡片错开列出最近 3 个会话 |
| 场景未就绪：还没允许工具 | 去处是选工具，不是这个开关；选完才露出许可这一关 |
| 没有项目 | 说明一项目一个、自己看外部会话不受影响，去处「管理项目」 |
| 一个项目 | 只有一行，不出搜索，页签上不写数字 |
| 很多项目（28 个） | 真实量：有搜索，含超长名字、0 个会话、部分读得到（「AI 能读 11 个；另 6 个在 Codex 里，那个工具没允许」） |
| 开着，但工具没允许 | 顶上一条提示和「选择工具」，开着的行写「开着，现在读不到」；选完工具就读得到 |
| 团队项目暂不开放 | 没有开关（不画一个灰开关让人去点），写「暂不开放」、原因一次写在分组上，去处「看这些会话」；当前项目就是团队项目时排在最上 |
| 切换失败，就地重试 | 开关弹回原位，这一行写「没存上，还是关着」和「重试」，轻推一下；第一次失败，重试成功。`expected_revision` 对不上时走同一行，这里不单画 |

动效都取令牌：回执 `--dur-move` 升起，失败多一次轻推，场景卡片错开 60ms 到达，Sheet 从边上滑入，页签切换 `--dur-hover` 淡入；减少动态效果时全部去掉，靠文字和底色说明。键盘：开 Sheet 焦点在标题（被挡时在开关上），Tab 依次走关闭、页签、搜索、开关，左右键换页签，Esc 关闭，焦点回到打开它的按钮。

**合同还没有的**（本目录不改 spec，由主会话定）：

| 缺什么 | 影响 |
| --- | --- |
| `sessions.scope.read@1` 只返回当前项目的 `project_ai_read`，没有全部项目的状态 | A、B、C 的「看全部项目」都要一个只读列表 |
| `sessions.project_ai_read.set@1` 的项目取自调用上下文，不能在全局 Sheet 里改别的项目（也不能写进输入，硬约束） | A、C 要在目标项目的调用上下文里发这个请求；做不到就走 B |
| 「归到这里」「AI 现在读得到」的项目级数字没有来源 | 行里的数字要 `sessions.list@1` 按项目计数，或在上面的列表里一起给 |
| 项目还没有团队标记（设计稿第 12 节第 19 行） | 团队状态这里只是模拟，团队批才判得出 |
| `open_project_ai_read` 要把 Sessions 的 Sheet 盖在别的插件页上 | 工作台浮层要接这个去处；C 不用，但要离开当前页 |
| 「已经写进回答的不会收回」是这里加的 | 第 7.4 节只写了在途调用被拒；AI 已写出的内容本来就收不回，写明以免人以为关掉能撤回，用户看样时确认这句 |

## 这一版改的三处文案

- **读取范围 Sheet：** 「只读项目连着的目录」下写明含子目录和这些项目的 git worktree；已删或认不出的 worktree 要选「所有目录」才看得到。没有目录的云端会话同样不在范围内（[设计稿第 7.1 节](../../../specs/sessions-rebuild/contract-design.md#71-归谁)），一起写了。
- **待归类：** 写明标题、目录和开头几句会发给你配置的模型，并按第 7.4 节写明这和项目 AI 能不能读是两件事。加了「卡片先到，建议随后到」的状态。
- **改归属 Dialog：** 加了「它连着的工具调用仍落在旧项目」（设计稿第 8.2 节第 4 行）。

## 模拟边界

所有工具、会话、目录、对话都是示例数据（`data.js`），没有读任何工具的记录，没有调用模型，也没有连真实 Home。按钮只改本页状态：允许读取后用计时器模拟读完；「在终端接着做」「打开原工具」「去登录」「重试」不做任何事。第四块的项目、会话数、对话和场景页都是示例：对话与项目首页标了「示意」，只为给出碰到开关的地方，样子不在这里定；开关的保存用计时器模拟，失败是写死的第一次；「看是哪些」只接了 Molis Work 的筛选；项目标识用快照里的统一色，没有按 id 取色（[DESIGN.md](../../../DESIGN.md) 写的是按 id 取色，两边不一致）。
