## 1. 背景

来源：MISC「T-400 二审 建议」（6537141182，统筹 10-31）；T-400（#1637）已合入。

`horizontal/search/src/index.ts` 约 :98 `revokedReader = (error) => error instanceof ActionError && (error.kind ?? platformErrorKind(error.code)) === "forbidden"`，:105、:116 两处：读取器抛 forbidden 时 `reader.valid = false` 并整个弃掉，不留任何痕迹。方向是安全的（结果只会更少）；但插件若把一个真故障标成 forbidden，搜索结果会无声地变少，没人看得出来。包里已有 `onError`（`git grep -n onError -- horizontal/search/src` 核）。

## 2. 目标

先在 #1332 贴【方案】（写清用哪个现成出口，不新造）。
1. 弃掉读取器时，经现有 `onError`（或包里已有的 debug 日志出口）记一条：读取器标识（插件 id／读取器名）与错误**码**；不记错误消息、不记查询词、不记任何内容。
2. RAC-2715：构造一个抛 forbidden 的读取器，断言 (a) 它被弃、其余读取器的结果照常返回（原行为不变），(b) 出口收到恰好一条记录，含码、不含消息正文；先对旧源码证明 (b) 红。

## 3. 不做

- 不改“弃掉”的行为本身，不改 kind 判定，不加重试。
- 不改 `onError` 的签名；没有可用的出口就停下来问。
