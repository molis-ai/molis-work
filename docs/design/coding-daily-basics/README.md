## 四块的方案

### 命令与说明文件（A1、A2）

| 方案 | 样子 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 放进现有斜杠菜单，按来源分组（✓ 已定）** | `/` 菜单分三组：内置、这个项目的（`.molis/commands`）、我的（所有项目，也读 `.claude/commands`）；选了带参数的命令，输入框里出一个命令签，后面打的字就是参数，下面能展开看发出去的完整提示 | 不用学新入口；和现有界面动作同一份表；来源一眼分清 | 命令多了菜单变长（现有上限 12 条，要靠搜索） |
| B 单独的「命令」面板 | 输入框上方一个「命令」按钮，打开带搜索的面板 | 命令多时好找 | 多一个入口，和斜杠菜单重复 |
| C 输入框上方常用命令签 | 输入框上方排三个最近用的命令，「全部命令」打开菜单 | 常用的一下就点到 | 一直多一行；签怎么排要猜 |

状态：打 `/` 看全部命令、用一个带参数的命令、项目还没有命令（菜单里教怎么放一个 `.md`）、有一个命令文件读不了（标「读不了」，别的照常）、`/init` 起草 AGENTS.md（进审查卡，你批了才写进仓库）、这一轮读到了哪些说明文件（文件、管哪部分、哪天改的）。

三个方案都写明：命令只是一段提示文字，不带任何权限；同名时项目的优先；项目没被信任时不读仓库里的说明文件，信任只决定读不读。

### 图片（A3）

| 方案 | 样子 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 输入框里一排缩略图（✓ 已定）** | 粘贴或拖进来的图在输入框里排成一排缩略图，带名字、大小、「已存一份」和去掉按钮 | 和要发的文字在一起；常见做法，不用学 | 输入框变高；缩略图排是新部件 |
| B 附件签，和材料一样 | 输入框上方一排带小缩略图的附件签 | 和材料、文件的样子一致 | 图太小，看不清贴的是哪张 |
| C 先进对话的待发图片卡 | 图先变成对话里一张大卡，发之前能放大、圈出要改的地方 | 能在图上标出要改哪 | 还没发就进了对话，容易误以为已经发出；部件最多 |

状态：贴了两张截图、发出后在消息里、当前模型看不到图（发送按钮先停用，给「换成能看图的模型」或「不带图发」，**不静默丢图**）、图片太大（给缩小到上限内再发）、Coding 自己看了工作区里的图（过程里写看了哪张，只读）。

### 代码理解工具（A4 工具获取，CLS-01～03）

| 方案 | 样子 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 过程里一行，展开看（✓ 已定）** | 「代码理解 · 2 种语言好了」一行过程折叠，展开是每种语言用的哪个、从哪来；出问题自动展开，下面接恢复块 | 全用组件板的过程折叠，新部件最少；出问题时处理就在那 | 正常时细节藏着 |
| B 输入框底栏的状态签 | 输入框底栏一个「代码理解 · TS Py」签，点开看每种语言 | 一直看得见，不占对话 | 签是新部件；出问题时只靠颜色和一行提示 |
| C 文件栏底部的语言面板 | 文件栏底部常驻一块，和 33 环境方案 C 同位置 | 跨轮都在 | 窄屏收成抽屉后看不到 |

状态：用本机已有的（写明版本合不合项目要求）、缺了正在下载（大小、来源、放进 Molis 自己的工具目录，不改你的环境）、不允许联网没法下载（别的照做，**「没查」不说成「没有错误」**，给只为这次放行）、下载失败（半截的删掉、不当成能用，给重新下载）、重启后核对（工具目录里的是完整的，不重下）。

### 写后检查与格式化（A4-2）

| 方案 | 样子 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 审查卡顶部一行检查结果（✓ 已定）** | 审查卡标题下面一行：有没有新错误、格式化了几处，各带来源；有错误时下面逐条列出 | 批之前先看到检查结果；行用组件板的状态词 | 错误多时这一块变长，离出错的行远 |
| B 差异里出错的行就地标出 | 顶部只留一行安静的结果，错误说明直接插在差异里出错的那行下面 | 原因和代码贴在一起 | 改动大时要滚着找；差异视图要加一种行 |
| C 审查卡底部的检查分区 | 差异下面一个「检查」分区 | 差异不被打断 | 看完差异才看到有没有问题 |

状态：没有新错误且已格式化、写完有 2 个新错误（主按钮变成「先让 Coding 修」）、Coding 修好后再给你看、这次没查（工具没准备好，写明没查）、格式化失败（按写的原样给你看，写明哪个配置文件错了）。能切「看格式化前」对比。三个方案都写明：格式化在审查之前做完，你批的就是写进去的那一版。

## 推荐走一遍

1. 命令 A：打开就是 `/` 菜单 → 用一个带参数的命令（展开看完整提示）→ 项目还没有命令 → 有一个读不了 → `/init` → 读到了哪些说明；切 B、C。
2. 图片 A：贴了两张 → 当前模型看不到图（点「换成能看图的模型」）→ 图片太大 → 发出后 → Coding 看了工作区里的图；切 B、C。
3. 代码理解工具 A：本机已有 → 下载中 → 不允许联网 → 下载失败（点「重新下载」）→ 重启后核对；切 B、C。
4. 写后检查 A：没有新错误（点「看格式化前」）→ 2 个新错误 → 修好后 → 这次没查 → 格式化失败；切 B、C。
5. 每块切一次 EN 和「深」，把窗口拉到 1024 和 390 宽看一次；勾「标出组件板新增」看新做的部件。

## 模拟边界

- 不读文件夹、不跑命令、不下载、不调模型；命令文件、版本号、大小、错误码、模型名都是示例。截图用三条色块代替，产品里显示存下的那一份；「放大看」只出提示，产品里用组件板的看图放大。
- 「当前模型看不到图」只是示意：MiniMax-M3 实际能不能看图还没核实（核账待核项）。
- 方案、状态、语言记在本机 `localStorage` 的 `molis-proto.coding-daily-basics.v1`，读不到就从初始状态开始；外观记在 `molis-work:theme`。
