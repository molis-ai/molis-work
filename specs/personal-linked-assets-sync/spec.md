# 个人空间关联资产同步

状态：开发中。承接 personal-pages-sync；仅隔离本机联调，不部署公网，不启用真实资产上传。

目标：让目标、文档和固定版本成果在另一端保持关联，而不是只复制目录或标题。

实现顺序：

1. Artifact owner 提供受空间/项目约束的固定版本导出与原子恢复；不覆盖同版本不同内容，不把本机内容引用冒充可携带正文。
2. 公共协调层支持集合依赖与等待依赖重试，保留独立版本/游标。
3. Goal owner 定义包含工作事实、决定依据和日志顺序的可移植协议，再接真实 Host。不得将另一设备的 SQLite seq 当作本机事件游标，不通过裸表复制绕过完成/决定规则。
4. 在隔离双 Home、Rust/D1 与浏览器验证完整关联和冲突、撤权、缺依赖。

比较方案：直接复制项目库会混入运行状态、密钥引用及设备路径；只复制 Goal 基本字段会丢失完成依据；选择 owner 定义的可移植事实协议、公共引擎传输。

完成标准：新设备能打开同一 Goal、文档正文和固定 Artifact 版本；引用不丢失，业务状态相同，旧版本不被覆写，离线修改有冲突而非静默覆盖。未达到此标准不宣称完整 Goal 同步已完成。

## 本次进展

- 已实现阶段 1、2：Artifact owner 的固定版本携带协议、同事务变更记录、Host 分区收发、文档引用检查与持久等待重试。
- 已覆盖固定版本和归档/不可用状态重放、不同内容拒绝、跨空间拒绝、撤权回滚、缺失依赖自动恢复、收发无回声；真实 Chrome 覆盖等待提示、重试与窄屏。
- Goal 仍未注册：完成状态依赖 `goal_work_events`、requirements、用户决定及 governance owner 事实；其中 `journal_seq` / `based_on_cursor` 只能在本机解释。下一阶段必须用稳定事件 ID 携带顺序依赖，在接收端映射本地序号，并由各 owner 验证/恢复，不复制远端日志序号，也不把标题同步称为 Goal 同步。
- `context_edges` 的 Goal ↔ Artifact 关系属于 Context Ledger，不等于 Pages 行上的固定成果引用；本次未实现该关系集合，不能称为完整的目标—文档—成果闭环。
- 仅 inline、单身份完整版本包（≤512 KiB、≤1000 版本），不读取或上传附件文件，拒绝 file/blob 内容引用；超限项当前会阻止该集合继续上传（不阻塞其他集合），后续需分版本流式队列与隔离错误项。
