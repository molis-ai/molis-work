# Desktop work tab visibility

> 归档（2026-10-01，合入后梳理）：判定为**已被取代**。src/web/visual-foundation.ts 已删除，标签栏已重做。没有剩余事项。

## 背景与目标

Goal 工作台允许在同一项目中打开最多 8 个标签。标签轨道在空间不足时横向滚动，以保留标题的可读宽度。

当前问题：恢复已打开标签、重新渲染标签，或标签轨道因收起目录和窗口变窄而缩小时，当前标签可能只显示一部分。截图中第 4 个标签的右半段被轨道边界裁掉，用户无法完整确认当前标签，也不容易发现关闭入口。

目标：只要某个 Goal 是当前标签，它都应自动滚动到完整可见的位置；标签轨道宽度变化后仍保持这一保证。

## 当前行为与问题证据

- `src/web/visual-foundation.ts` 明确让 `.desktop-work-tabs` 使用横向滚动，并保持每个标签的可读宽度。
- `src/web/render.ts` 的 `renderWorkTabs()` 会恢复和重建当前标签，但重建后没有校正滚动位置。
- `focusWorkTab()` 只在少数显式聚焦路径运行；初始恢复和单纯的宽度变化不经过该路径。
- 用户截图显示当前标签已经渲染，但仅部分落在标签轨道可视区域内。

## 范围

- 在标签重建并完成布局后，把当前标签校正到标签轨道的完整可视区域内。
- 监听标签轨道本身的尺寸变化，并再次执行同一校正。
- 保留现有标签数量、宽度、标题省略、关闭行为、键盘行为、存储键与工作台视觉样式。
- 补充定向自动化测试，覆盖初始渲染和轨道缩窄。

## 非目标

- 不改变“最多 8 个标签”的规则。
- 不把标签压缩成状态点，不改成换行标签，也不重做标题栏。
- 不修改 Goal 选择、持久化、关闭邻居选择或 Runtime 状态逻辑。
- 不处理本任务之外的现有未提交改动。

## 用户场景

1. 用户打开多个较长标题的 Goal，退出后重新进入。若恢复的当前 Goal 在轨道末端，它会完整显示。
2. 用户收起目录或调整窗口宽度，导致标签轨道尺寸变化。当前 Goal 会继续完整显示，不停留在半遮挡状态。
3. 用户切换标签。新的当前标签会在标签轨道内完整显示，原有键盘与关闭行为不变。

## 方案与边界

- 在工作台客户端脚本内建立一个单一的“确保当前标签可见”函数。
- 函数比较标签和轨道的真实矩形；只有标签越过左右可视边界时才调整 `scrollLeft`，避免无意义滚动。
- `renderWorkTabs()` 替换 DOM 后，在下一帧布局完成时调用该函数。
- 使用 `ResizeObserver` 观察标签轨道宽度变化；环境不支持时不影响基本渲染，初始与切换路径仍工作。
- 修改范围限定为 `src/web/render.ts`、对应测试，以及本需求书。
