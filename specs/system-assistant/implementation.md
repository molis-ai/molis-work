## 2. 架构决定

1. **助理是 Host 级系统模块**，不是某个插件页面：服务代码在 `apps/local-host/src/assistant/`，对外约定在 `packages/contracts/src/services/assistant.ts`，界面在 Workbench 底栏。插件通过约定贡献上下文、能力、方法与交互，不需要助理为某个插件写专属分支。
2. **一项“工作”（work）是助理的事实单位**：有自己的作用域、标题、Prologue 会话、授权方式、草稿、材料和成果关系。统一的助理身份 + 多项独立工作并存。存储在 Home 级 `assistant` 库（`openHomeSqliteDatabase`），只保存助理自己的事实与引用；会话内容、运行状态、TaskBoard 归 Prologue，业务结果归原模块。
3. **作用域是真实的**：个人工作 = Home 作用域（动作服务已有的 `scope: "home"`、`homeActionClient()`），项目工作 = 项目作用域。不虚构项目，不虚构目录。
4. **一般业务授权与代码目录授权分开**：
   - SDK 新增 `workspace: "app"`：没有授权根；只能用这条会话安装的包工具（应用自己的业务动作）和不依赖目录的系统工具（提问、待办、任务图、会话协同、子任务等，逐步开放）；文件、命令类工具一律不可用。原 `workspace: "none"` 的纯推理语义不变。
   - Agent Host 新增角色工作区方式 `business`，映射到 SDK `app`；原 `none`、`required` 不变。
5. **动作按效果授权**：读取（query/read）助理可直接调用；可撤回的写入在本工作的授权方式允许时直接执行，否则停在审查上等用户对具体参数确认；不可撤回的每次都要确认。审查沿用 Host 已有的 AgentReviewQueue（tool-operation）。
6. **可直接操作的建议**：助理通过应用工具 `propose-action` 生成“动作意图卡”——绑定真实能力的精确版本与提供方、目标、已准备参数、可调整项与缺失项、前置状态；卡片由助理服务持久化，点击由服务端按当时状态核对后经动作服务执行，带幂等键，结果回写卡片。模型不能靠文字改变能力定义。
7. **Coding 从底栏进入同一会话**：选中 Coding Agent 时，底栏发送走 Coding 插件自己的会话与运行路由；助理工作只保存对该会话的引用，两个入口看的是同一份运行事实。
8. **主动协助与记忆**先用确定性规则（条件、范围、例外、到期）决定能不能打扰，模型只在规则放行后判断价值；记忆复用 Prologue Memory，并补齐项目作用域的真实隔离（见第 4 节缺口）。

### 2.1 用户拍板（2026-09-28）

- **助理的默认授权**：本作用域内所有对 Agent 开放的能力默认可用（个人工作：个人范围；项目工作：该项目与个人范围）。读取直接用；写入在执行前把准确参数交给用户确认；不可撤回的每次确认。助理有自己的授权集合，与 Coding、外部 Agent 分开；用户可在设置里对助理单独关掉某项能力（`/api/assistant/capabilities`）。
- **Character／Prompt／Skill 统一经 Host 登记并纳入开发流程**，是 P13 的前提（spec 第 9.1 节、AC45）。
- 2026-09-28：执行类轮次只以“宣布要做”的文字结束、没有调用任何工具时，**自动续做一次**，并在轮次里标明“自动续做”（每次多一次模型调用）。实现：SDK `session-stop` 钩子（提交 22a1be08）＋ Host `announce-guard.ts`（只对可写角色、每轮最多一次）。

- 2026-09-28：用户授权后续任务全部由我推进，需要判断时按推荐执行。以下标“按推荐（用户授权）”的都是这样定的，可随时改回。
- 按推荐（用户授权）· P13 登记与覆盖：Agent 定义（Prompt、角色、Skill）登记在 Home 级的 Host 服务里；系统与内置插件在启动时登记，插件随安装、升级、停用、卸载登记。用户修改是 Home 级覆盖层（对所有项目生效），记录基于哪个默认版本；默认升级后标“默认已更新”并可对比，不自动合并；“恢复默认”撤掉覆盖层但保留历史。项目说明仍归项目设置，这里只显示并链接。
- 按推荐（用户授权）· 直接调用模型的插件：插件在包内声明“指令 Prompt”（标识、版本、用途、正文），调用时交给 Host 登记的引用与数据，由 Host 取有效正文拼接；过渡期尚未迁移的调用列在自动检查的清单里并写明原因，逐个清零，不允许新增。
- 按推荐（用户授权）· Character 设置：系统与插件的角色列为“系统 Character / 插件 Character”（名称、用途、来源版本、组成它的 Prompt），可改的是文字；角色能做什么（目录、工具、审批）由 Host 在代码里强制，界面写明改文字不改权限。用户自己的 Character 沿用现有管理。
- 按推荐（用户授权）· 执行记录：Agent 轮次的冻结记录里写明每段 Prompt 用的是默认版还是用户版（含版本号）；直接调用记在登记服务的使用记录里（每段保留最近 200 次）。

## 4. 已知缺口与待用户决定

- SDK Memory 只有 user/app/character/session 作用域，不能把项目标签当项目隔离。P8 需要在 SDK 增加真实的项目作用域或按项目分库，届时再定。
- 关闭应用后的持续执行：当前 Host 只在服务进程活着时运行。P10 会如实标注，不承诺超出环境的后台能力。
- “只说不做”：MiniMax-M3 在 Coding 执行轮次里多次只回一句“现在改 calc.js…”就结束本轮、没有调用任何工具（Coding 基础提示词已明确禁止；同一会话历史里出现过几次后更容易重复，新会话正常）。用户拍板自动续做一次，已实现（见 2.1）；真实模型下的复现验证待补。
- **Prologue 缺口**：一轮停在修改确认上时被停止，被撤回的那次写入在运行时的活动记录里一直是“进行中”（同批的另一次写入正确记为“运行取消，未执行”）。助理现在把结束轮次里未收尾的步骤显示为“结果未确认”；根本修复在 SDK（停止时为等待审批的工具补记取消），归入 P10。

### 6.2 缺口（本期要补）

1. **关系没有记下来**：助理产出或修改的对象、本轮材料、起始对象、交给的专业会话，目前只散在轮次文本里；换入口或重启后无法回答“结果在哪里”。
2. **对象上下文读取缺 Pages 与 Coding**（以及其他官方插件）：助理无法按统一方式读取文档/会话的当前版本与背景。
3. **手动修改不可见**：工作不知道用户在 Pages 里改过它的成果；下一轮要靠模型碰巧重读。
4. **“正在看”与“当前工作”混在一起**：继续一件工作时，当前页面的对象会自动作为材料并入，浏览无关页面可能把无关对象带进运行中的工作。
5. **一件工作不能换执行者**：助理工作不能交给 Coding 继续，Coding 的结果也回不到原工作。
6. **没有“与这个对象相关的工作”的公开查询**：插件页面无法显示或继续相关工作。
7. **写入不强制版本前提**：模型可能在修改时漏掉 `expected_version`。
8. **插件开发手册没有这套约定**。

### 6.3 做法（不新建总账）

- 关系：Assistant 作为语义所有者，在自己的数据库事务资源里用 `createContextLedger` 写关系边（同其他所有者的做法）。`ObjectRef` 增加 `assistant`（工作）与 `plugins`（插件对象，`object_type` 为对象种类、`project_id` 为项目）两个命名空间。关系类型：`assistant.work.origin`（从哪个对象开始）、`assistant.work.material`（用户明确带上的对象，当时版本）、`assistant.work.result`（产出或修改的对象，产出时版本；再次修改追加新版本记录）、`assistant.work.session`（交给的专业会话）。
- 何时写：助理的能力调用成功后（在助理自己的授权客户端里，按能力声明的结果对象或通用规则取出对象与新版本）；卡片执行成功后；发送时的明确材料与起始对象；交给 Coding 时。
- 手动修改：工作视图与每一轮开始时，按关系边经对象上下文读取当前版本，与记下的版本比较，得出“未变／已被修改／已删除／暂不可读”；只读所有者，不记操作流水。
- 版本前提：能力输入声明了 `expected_version`/`expected_revision` 而助理调用没带时，在确认前拒绝并说明要先读取当前版本。
- 公开查询：`assistant.works.related`（按对象查相关工作）供插件页面与底栏使用。
- 界面：工作视图列出“这项工作的对象”（起点、材料、成果、专业会话，当前版本与是否被改过，可打开）；底栏把当前页面分成两种——已与当前工作相关的对象自然并入，无关对象显示“正在看：X · 加入本轮”；新工作仍以当前页面为起点。
- 交接：助理工作可“交给 Coding 继续”（带工作约定、材料与成果引用创建 Coding 会话并记关系），工作视图合并显示两边的轮次；可“回到助理”，下一轮助理拿到 Coding 的结果。
- 兜底：插件没有声明页面上下文时，工作台按当前标签页（插件、条目标识、标题）与该插件的对象上下文读取给出对象身份。
- 官方插件：先 Pages、Coding，再逐个补对象上下文读取与页面声明，完成情况列在 6.4。
