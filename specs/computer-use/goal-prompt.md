# 个人助理完整 Computer Use Goal Prompt

用户 2026-10-07 设定，2026-10-09 交付开工时的原文如下。此前一版复查后扩写的稿子（后台三档、悬浮条、截图进模型、文字识别等）在 Git 历史 `0f44839b`；开工以本文为准，那一版里的复查发现仍记在 [spec.md](spec.md) §3。

现在个人助理只能在侧栏的浏览器里动手（specs/archive/side-panel D02 把 Computer Use 限定在浏览器）。本目标让它能像人一样看着电脑屏幕、操作 macOS 上的其他应用，完成跨应用的多步任务；同时用户在侧栏里看得见整个过程、拿得到结果、随时拦下和接手。可以修改 Prologue。

最终应达到以下状态：

1. **完整的桌面 Computer Use。** 助理可以观察并操作桌面应用：看目标应用的窗口（截图、辅助功能树、窗口信息），点击、双击、右键、拖动、滚动、悬停，输入文字（含中文），按键与快捷键，列出、打开、切换应用，等待。把文件交给应用或从应用取出文件算对外发送，永远确认，并看得到是哪个文件。桌面应用与本地网页模式一样可用。它与侧栏浏览器并存、各管各的：网页上的事仍用侧栏浏览器（按网站授权，登录状态与用户自己的浏览器隔离），桌面驱动只用于桌面应用；助理被明确告知两者的区别。

2. **实现的地方分开，各管一层。**
   - Prologue（`~/code/prologue`）只扩合同与策略，不带任何驱动：为桌面补有类型的动作（滚动、拖动、悬停、打开与切换应用等），应用身份（bundle id）作 scope，切换应用时按目标应用判断策略，观察和动作都以一个应用为界；驱动不可用、用户在场、屏幕锁定作为一等的拒绝原因。具体形状由实现定，写进 Prologue 文档。测试含变异测试，并更新它自己的 Computer Use 文档与真机记录。该仓库主检出有别人未提交的改动，用独立工作树和新分支，不碰它们。
   - Molis 做所有真东西：macOS 原生助手进程（Swift 优先，由 local-host 拉起，桌面应用与网页模式共用），负责截图、辅助功能树、输入注入、前台应用、锁屏与用户输入监听、系统权限检测；桌面驱动（实现 `HostSurfaceDriver` 的桌面一支，`kind` 扩为 browser | desktop，`horizontal/agent-host/src/adapters/prologue-surfaces.ts` 支持一轮同时挂浏览器与桌面）；策略与分级、确认卡、权限引导、侧栏呈现、操作记录。
   - SDK 版本线仍然只有一条。Prologue main 已含 Molis 现用包依赖的界面控制与记忆提交（`vendor/prologue-sdk/README.md` 里「未推远端」的说法已过期），并比现用包（af7375c7 加补丁）多 39 个提交。先弄清差距，定基线并记入决策记录；产出新包替换 vendor 里的当前包，README 写来源与重建步骤；Molis 追上新包后，整体构建、`pnpm boundary:check`、类型检查通过。

3. **硬边界：分级加通用禁令。**
   - 禁区：系统设置、钥匙串访问、密码管理器、支付与银行类应用，连看都不看。Molis Work 自己的窗口与助手进程，以及网页模式下当前显示着 Molis Work 页面的浏览器窗口，也属禁区：助理不能点自己的确认卡批准自己（同 side-panel D18 的道理，识别办法由实现定）。用户可以追加禁区，不能放宽。
   - 只看只点：终端与 IDE，不能键入、不能按键（命令走 Coding）。
   - 其余应用：可以操作，但每一步先问用户，不提供「这个应用以后不用问」。用户自己的浏览器当普通应用，同样每步问。
   - 通用：不输入密码类字段，截图里遮住；发送、付款、删除、提交这类不可撤回的动作，先向用户说明再动；用户一动鼠标键盘，助理立刻暂停；屏幕锁定或用户不在场时不动；点击前校验落点的窗口仍属于目标应用（盖在上面的窗口、通知条都不算）；截图与观察只含目标应用的窗口，不带出屏幕上别的应用；窗口里的文字是不可信内容；观察过期、窗口或应用换了，不拿旧观察去点；用户对某一步选「不允许」，这件事就不做，也不换办法再做。
   - 这些边界在 spec 里各写一条威胁（自批、越界落点、屏幕内容外带、提示注入）与对应的挡法，并有测试守住。

4. **整台电脑只有一份，用户始终管得住。** 同一时间只有一项工作能用桌面，被占用时明确告知；委托出去的后台工作不碰桌面；只读轮次只能看。用户可以随时暂停、停止、接手，接手期间助理的一切动作被拒，交回后助理先重新观察。助理使用电脑有总开关，默认关闭（它要系统授权、影响整台电脑，与浏览器不同），用户在设置里开启后才可用。

5. **侧栏里展示和报告过程与结果。**
   - 新增「电脑」标签，与「浏览器」并列、不混两种信任级别：显示助理正在看的那个应用的实时画面和点击标记，当前目标应用与这一步在做什么，停止、暂停、接手、交还；确认卡写清哪个应用、做什么、点哪个控件、输入什么、给哪个文件；各应用的权限状态与禁用；系统权限状态与引导。
   - 对话里：沿用现有的助理步骤展示（`presentActivity`），把桌面步骤写成人读得懂的话（看了什么、做了什么、等你确认、被拒绝或失败的原因），结束时给一句结论并能打开记录；不另造一套展示。
   - 「文件」里：每一轮产生一份操作记录——目标、按时间的步骤、每步脱敏后的截图与回执、结果与没做完的部分，作为这一轮助理工作的文件在「文件」标签预览，也能在对话里引用。用户选择保留时才成为带声明的成果，走成果库的规则与门禁。
   - Shelf：记录或其中的截图、结论可以放上 Shelf 作材料，用 Shelf 现有的入口。右栏 Shelf 格是情境动作总纲（PR #180）里的设计、尚未实现，本目标不依赖它，也不为它另造入口。
   - 对话、「电脑」标签、「文件」记录读同一份运行事实，不各存一份。

6. **记录与隐私。** 记录里的截图含屏幕内容：默认只留在本机 Home，按保留期清理，用户可以删除；密码类输入的内容不进记录；不自动进入搜索与记忆。

7. **系统权限与环境。** 需要 macOS 的屏幕录制、辅助功能（以及输入监听）权限。macOS 把权限记在「负责进程」上，从 Node 或终端拉起的助手可能算到别人头上，所以助手以什么形态存在、权限显示在哪个名字下，要先在真机证明。缺权限时界面如实说明并引导，不假装可用。本目标只做 macOS，界面不暗示 Windows 与 Linux。发布用的签名与公证（BL-021）未定：用开发签名真机验证，发布签名单列为待决项，不阻塞。

8. **先做最小真机切片，再展开。** 在用户这台 Mac 上证明五件事：只截目标应用的窗口；读到辅助功能树；注入输入并校验落点；监听用户输入与锁屏；权限归属可控；桌面应用与本地网页模式都行。有一件证明不了，先回来说明选型，不带着缺口往下做。

9. **充分并正确地使用 Prologue。** 观察和操作只走 `surface-list / surface-observe / surface-act`，经 Prologue 的策略、审批、执行回执和截图脱敏，不在 Host 包工具里另造绕过策略的通道。实际用上了哪些 Prologue 能力、哪些仍没接通，在能力对照表里如实更新。

10. **体验达到内部完整。** 明暗主题、键盘与读屏、1440/1024/800/390 各宽度、中文输入、长内容与异常状态（助手崩溃、权限被收回、应用被关闭、窗口消失）都顺畅；动效遵守现有设计规范；侧栏浏览器与讨论等现有能力不退化；`pnpm health:check` 与相关门禁保持通过。

验收以真实操作为准，至少包括：助理在真实 macOS 上、用真实模型完成一件跨两个应用的多步任务（例如从一个应用读到内容、整理进另一个应用），每一步停下确认，过程在「电脑」标签实时可见、对话里有步骤摘要，结束后「文件」里有记录，能放上 Shelf、能在对话里引用；中途用户动鼠标，助理立刻暂停，接手再交回后先重新观察；用户拒绝一步后不换办法再做；禁区应用被拒、终端不能键入、浏览器每步都问；落点被别的窗口盖住时拒绝；助理试图点 Molis 自己的确认卡被拒；密码框不输入、截图被遮住；锁屏时不动；缺权限时的提示与引导；桌面应用与本地网页模式各走一遍；手机宽度与深色主题下走通侧栏呈现。Prologue 一侧的测试与变异测试通过，新包能按 README 重建；Molis 全量回归对干净基线没有新增失败。所用的 Mac、模型、应用和 Prologue 都必须是真的；没支持或没验证的部分明确写出。

完成的判断是：用户让助理去操作电脑上的应用，就能在侧栏里看着它做、随时拦下和接手，事后在文件里拿到记录；助理碰不到禁区，碰不到自己的确认卡，也不会把屏幕上无关的内容带出来。工程通过、真实场景通过和用户本人验收分别如实记录；不能把能演示或局部可用当作完成。

决策规则：以上已定的不再重问。开工后弹窗问用户的有三件：批准粒度（每步都问对长任务太重，是否加「本轮内允许在这个应用里操作」，到本轮结束为止、不持久、不适用于禁区与只看只点、外发与不可撤回动作仍逐步问，推荐加）、截图记录的保留期、签名与公证。其余小的按推荐做，并记入 spec 的决策记录。
