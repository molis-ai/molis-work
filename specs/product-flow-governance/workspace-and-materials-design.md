# 项目目录、文件与资料统一设计

状态：目录模型已确定（2026-10-27），负责人：本会话 Codex。每个项目可选择多个输入目录，有一个固定且可修改的输出目录；输入与输出可以指向同一目录，用于直接修改原仓库，其他输入目录作为参考。保留默认联动、临时查看不改变执行位置的决定，并按去掉独立 Files 插件、项目内插件共用文件与资料源的方向细化。本文交付需求与设计，未开发、删除插件或迁移真实数据。

本文承接[动线治理 §4.3](spec.md)；联动行为的唯一合同是 [Coding 优化 R1、CHO-36～39](../coding-harness-optimization/spec.md)，项目资料的既有范围与权限原则来自[项目资料需求](../archive/project-knowledge/spec.md) §2。这里负责把入口和职责收敛，不另建资料库或执行系统。

## 2. 已确定：多个输入，一个输出

**输入目录：这个项目可以参考哪些本机内容。** 用户可以添加多个目录，也可以修改路径或移除。它们与导入文件、Pages、Shelf、成果库等已授权内容共同进入“项目资料”。内容仍保存在原主人处；入口统一不代表复制一份正文。没有本机输入目录的项目仍能使用插件内容。

**输出目录：这个项目的本机产出写在哪里。** 每个项目持久保存一个输出目录，用户可以修改；各插件使用同一项目配置，不由每个会话另选一份长期输出位置。新项目流程应提供默认位置并允许修改，具体路径沿用项目／Home 的存储约定，避免要求只做讨论或写作的人先配置磁盘。这里管本机文件产出；Pages、成果版本等内容仍由原主人保存，不因此搬出原存储。

**输入与输出允许相同（用户已选）。** 做现有代码项目时，把仓库同时设为输入和输出，Coding 可在授权范围内直接修改原仓库；其他输入目录作为参考，不因为被添加为输入就获准写入或执行。路径相同仍只有一份目录身份，在界面标明“输入／输出”，不重复关联。

项目设置中的输入集合与输出位置是持久事实；当前任务的实际执行位置和面板正在浏览的位置是不同用途。Coding 默认在项目输出目录工作；已有并行工作树机制可提供临时隔离环境，仍按既有整合审查把结果交回项目输出，不形成第二个项目输出配置。公共文件浏览与 Git 默认跟随当前任务实际执行位置；临时打开输入目录或其他资料只改变查看位置。

修改目录配置对后续轮次生效；正在运行的轮次保留已冻结的输入／输出与执行位置，并明确显示与当前项目设置的差异。移除授权、取消或目录失效仍按现行边界立即拒绝后续访问／副作用，不能以“已冻结”为由继续越权。更换输出目录不自动搬移或删除旧文件，不复制旧目录覆盖新目录；历史结果保留实际位置与版本，新轮次使用新配置。

## 3. 入口怎样合并

- 工作台提供统一“项目资料”入口，承接现有侧栏“文件”的聚合能力，也容纳本机文件树与预览。按来源展示，搜索和选取共用；不强迫把代码树拍平成文档卡片。
- 项目设置与“项目资料”共用一份“输入与输出”管理：输入目录可添加多个，输出目录显示一个并提供“更改”；关联、修复位置、移除输入不再各做一套。在输入目录上可明确“设为项目输出”，这是项目级配置变化，不是临时浏览动作。
- Coding 顶部显示项目输出目录；使用临时工作树或本轮仍采用旧配置时，另显示本轮实际位置。默认的文件浏览和 Git 跟随本轮；临时查看时显示所看的位置及“回到工作目录”。多个会话／窗口的浏览不会改写项目输入／输出配置。
- 项目内插件通过同一公开协议选择资料、列举来源、读取内容、预览与引用。需要本机文件写入的插件另调用已有受授权的工作区操作；修改 Pages 等对象则调用该对象主人的动作，不把所有内容伪装成本机文件。
- 去掉 Files 的安装、启用、独立导航、Runtime 实例与以 Files 为中心的嵌入接线。文件树、阅读器与选择器成为工作台的公共 UI 能力；Git 继续负责版本管理，Coding 继续负责任务执行。

保留：现有目录身份、真实文件、读取失败与截断提示、快照和选区、资料出处、权限与引用。替换：重复入口、项目全局浏览选择承载会话状态、必须启用 Files 才能使用公共文件能力的依赖。忽略：上一版“可选主工作目录＋会话各自改长期目录”的建议，以及为保留旧插件形态而维持的专属配置与面板嵌套。

## 4. 三条完整路径

### 做代码，同时参考其他资料

进入“网站改版”项目，输入目录为 `website` 与 `brand-assets`，输出目录也设为 `website`。Coding 直接修改原仓库，公共文件树与 Git 默认显示同一目录。打开 `brand-assets` 中的品牌指南时，Coding 仍在 `website`，不会改写参考目录。把选中的段落加入任务后，显示其来源；回到工作目录即可继续看代码。

用户在“输入与输出”中改输出位置，后续轮次使用新位置；正在运行的轮次保留原位置并显示提示。目录不可用、授权撤销或工作树删除时明确阻塞和给出修复入口，不偷偷落到其他目录继续写。

### 只有研究、写作和项目内容

用户选择访谈记录、市场材料等多个输入目录，也可只使用导入文件和插件内容。助理与领域插件通过统一资料源完成讨论和写作，导出的文档或生成文件进入同一个项目输出目录；无需逐个插件或会话重复选位置。即使没有本机输入，项目仍有默认输出位置，用户随时可以修改。

### 两个任务共用项目输出

同一项目中，任务 A 修改页面，任务 B 根据另一个输入目录生成报告，最终文件都归该项目输出目录。需要并行隔离时使用现有工作树与整合审查；文件浏览和 Git 跟随正在查看的任务实际位置，不把临时工作树设成新的项目输出目录。另一窗口的浏览不影响任何运行中的任务。

## 5. 文件、资料与 AI 的边界

| 来源 | 默认读什么 | 怎样改变内容 |
| --- | --- | --- |
| 项目输入目录 | 当前文件；标明路径与读取时版本，变化后可刷新 | 作为参考不授予写入／执行；同一目录也被设为输出时按输出授权处理 |
| 项目输出目录 | 已产生或原有文件；可同时作为输入 | 获准的任务经工作区公开操作写入，保持路径与对象权限边界 |
| 导入的 PDF、图片、Office 等文件 | 已导入的原件与可用解析结果；解析失败仍说明原件状态 | 由导入文件的现有主人更新；不把导入自动当作实时同步 |
| Pages、Shelf、成果等插件对象 | 由原主人返回当前对象或指定版本 | 调原主人公开动作；公共资料入口不越权写其表 |
| 文件快照、选区 | 取用时固定的内容与出处 | 新选取产生新版本；不让源文件变化改写历史引用 |

人可以主动选择，AI 也可以按任务查找。沿用既有资料目录摘要和按需读取机制，不把全部文件正文自动塞进上下文。引用显示来源、当前文件或固定版本，以及读取失败／截断情况。资料只读授权不等于命令执行或对象写入授权；内置、个人、创作台与第三方插件使用同一合同，按各自声明和获准范围访问。

文件预览、手工选择和原文检索不依赖模型成功。模型摘要失败时保留可用原文与人工入口；文件离线、来源插件停用或撤权时保留历史引用的说明，拒绝新的未授权读取，不用缓存绕过授权。已有固定版本仍按其自身 owner 与授权读取。

## 6. 复用现有主人，先接好再退役

目录身份、项目关联及项目的输入目录集合／唯一输出目录配置归 `modules/projects`，复用同一目录身份；路径授权与文件系统操作沿用 Host 现有工作区服务；跨来源查找读取继续归 `horizontal/knowledge` 及系统搜索；正文和对象仍归原插件／Module。公共 UI 归工作台，对外可复用的客户端能力经 SDK 暴露，不让插件 import 工作台或彼此的实现。

Files 的集合、before／after 快照、选区当前是**过程项**，不是成果；迁移后仍保留这一语义。实施前必须把产生动作、版本读取、原输出绑定与历史引用逐项交给明确的现有 owner，优先使用既有工作区合同和过程项设施；不能简单删除 Files 安装记录而连带丢失历史过程项。具体承接位置和数据维护步骤须在实施切片中写清，本文不提前虚构一个新文件存储包。

推荐切换顺序：

1. 用现有目录与资料合同接出公共浏览、选择和引用路径；用真实目录、导入文件、插件对象及权限失败做高保真切片。
2. Coding、Git 和其他消费者改用共同入口，落实多输入／唯一输出配置、同目录双角色、临时浏览、运行冻结的职责；核对 Diff、Text Stats 与现有工作流绑定仍能消费固定快照／选区。
3. 完成过程项与引用的数据维护、消费者切换及回读，再删除 Files 包、登记、安装项和专属装配；同步生成包清单、公共 API／动作快照及相关文档。现行 owner 表在实际切换时更新，本次不虚报 Files 已退役。
4. 在隔离 Home 覆盖首次使用、旧项目、重启恢复后再安排真实 Home 的已授权维护。遵守仓库现行合同切换政策，不新增长期兼容层；有必要保留的临时机制先走已有规则。切换前保留可恢复备份，失败恢复同一批数据与对应版本，不让两套 owner 同时写入。

实现沿原路线：Coding 联动归 1·B 的 R1；跨入口整理归动线治理与项目资料；Files 退役与防腐线的插件装配事项协调为同一份切换。各部分都未因设计完成而标成实现完成，不新开一套排期。

下列为方案验收候选，未运行产品测试。后续采用后由实际用例在测试名或注释引用编号；联动本身复用 CHO-36～39，不重复定义。

| 编号 | 验证结果应是什么 |
| --- | --- |
| WMD-01 | 不安装／启用 Files，Coding 与另一个独立插件仍能使用获准的同一资料源、选择器、文件树和引用 |
| WMD-02 | 同一文件夹只关联一次，项目设置、资料入口及任务选择引用同一身份；移除关联不删除磁盘文件 |
| WMD-03 | 无本机输入的项目可完成资料导入、阅读、讨论和写作；项目仍有一个可修改的输出位置，导出时无需逐会话重复选目录 |
| WMD-04 | 当前文件更新可见，固定快照／选区不变；迁移前后已有引用、Diff 和 Text Stats 输入可回读，过程项不混进成果库 |
| WMD-05 | 跨项目、未授权、撤权、来源停用及非法路径被实际拒绝；内置与外部插件遵守同样边界 |

| WMD-08 | 输入与输出为同一目录时可直接修改原仓库；其他仅作输入的目录没有因此获准写入，不产生重复目录记录 |
| WMD-09 | 修改输入／输出配置只改变后续轮次；运行中的实际位置可见且不被改写，撤权仍即时生效；更换输出不搬移、删除或覆盖原有文件 |

文档检查使用 `git diff --check` 和仓库文档门禁；实施时按真实修改面选择相关 Files、项目目录、资料和 Coding 回归，并遵守共享核心与整体构建规则。当前证据只支持现状判断与方案可讨论，不支持内部完整或用户验收通过。

本轮已确定多输入、唯一且可修改的输出、输入输出可重合；不再保留“可选主工作目录”待决项。项目身份仍由用户确认，不恢复 [PRODUCT](../../PRODUCT.md) 已取消的 workspace 默认项目绑定。具体默认输出路径、存量配置维护及公共 UI 切片由实施方案结合现有 Home 规则细化；这些实现细节不把已定产品规则重新变成未决定。
