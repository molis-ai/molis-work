## 1. 背景

依据都在 main `249369c40`。

- 现在的样子（`comments-store.ts:17-31`）：

  ```ts
  /** Reads the current document's marks; there is no text-search reattachment. */
  export function pageAnnotations(body: PagesRecord["body"]): Map<string, { text: string; excerpt: string }> {
    const marks = new Map<string, { text: string; excerpt: string }>();
    const visit = (value: unknown): void => {
      if (!value || typeof value !== "object") return;
      const node = value as { text?: string; marks?: Array<{ type: string; attrs?: { id?: string; text?: string } }>; content?: unknown[] };
      for (const mark of node.marks ?? []) if (mark.type === "comment" && mark.attrs?.id) {
        const previous = marks.get(mark.attrs.id);
        marks.set(mark.attrs.id, { text: String(mark.attrs.text ?? ""), excerpt: ((previous?.excerpt ?? "") + (node.text ?? "")).slice(0, 2000) });
      }
      node.content?.forEach(visit);
    };
    visit(body);
    return marks;
  }
  ```

  深度优先，每遇到一个带 comment mark 的文本节点，就把它的文字接在这个 mark 已有的摘录后面，再截。所以截一次的结果会被后面的节点接着用。
- 摘录的去处：
  - 发新评论（`append`，`:63-70`）：新线程的 `anchor.excerpt` 取 `pageAnnotations(page.body).get(mark_id)` 的摘录（`:66-68`），`save`（`:80`、`:103-106`）把整个线程 `JSON.stringify` 存进 `page_comments`；
  - `list`、`get`、`append`、`reply` 读线程时再调一遍 `pageAnnotations`（`:40`、`:49`、`:61`、`:66`、`:81`、`:91`、`:95`），但只用它判断标注还在不在（`present`，`:107-109`），读回来的 `anchor.excerpt` 是存下的那份；
  - 助理的上下文（`comment-actions.ts:59`）：`引用: ${found.anchor.excerpt}`；
  - 侧栏（`comment-side-client.ts:43`）：`thread.anchor.excerpt` 原样显示。
- 浏览器发评论时只送 `anchor: { kind, mark_id }`（`comment-side-client.ts:56`、`:88`），摘录由库从文档重新算，所以存下的摘录只出自这一处。
- 输出 schema 里的 `excerpt` 是 `text`，没有长度上限（`comment-actions.ts:12`、`:17`）。2000 是库自己定的上限，没有 schema、界面文案点名它。按字：
  - 同一个文件里评论的长度，T-085 已改成按字数（`:57`）；
  - 摘录最后给人看、给模型读，半个字只是一个「�」，一个字就是一个字。
- 为什么新函数只读到上限、不用 `[...value].slice(0, 2000).join("")`：
  - `pageAnnotations` 每次 `list`、`get`、`append`、`reply` 都把整篇文档走一遍；
  - 一个被标注的文本节点可以很长：`parsePagesBody` 只查 `type` 是 `doc`、编码后不超过 `MAX_BODY_CHARS`（1 500 000）、内容是列表（`document.ts:8-23`），不拆文本节点，一整篇正文可以是一个文本节点；
  - 展开成数组，每次读都要为这个节点分配一个同样长的数组；`for…of` 遍历字符串，数够了就停。
- 已存的线程：`anchor.excerpt` 是建线程时算好存下的，以前截出的半个字留在库里。照 AGENTS.md「合同读写都只认现行取值」，读取时不兜底、不迁移；现在只有开发版（第 8 节第 4 条）。
- 现在的用例：
  - `tests/pages-comments.test.ts`（121 行）：`PAS-02 PAS-09`（`:19`）断言短摘录 `可定位的原文` 原样（`:27`）；`RAC-1632`（`:88`，走动作分派）、`RAC-1633`（`:108`，直接调库）是 T-085 的，量评论正文的 20000；
  - 没有一个用例调 `pageAnnotations`（`git grep pageAnnotations -- tests` 无命中），也没有一个量过超过 2000 个字的摘录；
  - 文件用 `openPagesStore(home)`（`:13`，`tests/fixtures/plugin-home-stores.ts:87`）开临时 Home 里的 Pages 库，`body(marked)`（`:17`）造文档，comment mark 的写法是 `{ type: "comment", attrs: { id, text } }`（与 `schema.ts:462-465` 的 mark 定义一致）。

## 2. 目标

1. 摘录取前 2000 个字（码点）：超过 2000 个字的，取前 2000 个字，不留下半个字；不超过的原样保留。
2. 不含两单元字的摘录与现在一字不差：没有两单元字时，2000 个字就是 2000 个单元。
3. 一个 mark 跨几个文本节点时，累加后仍不超过 2000 个字；读到上限就停，不把长节点展开成数组。
4. `RAC-1690` 的两个用例钉住上面几条：下面五个变异，每个都有一句断言红（第 6 节）。

   ```ts
   /** The first `limit` whole characters of `value`: never half of one (an emoji is one character, two UTF-16 units), and read no further than that. */
   function firstCharacters(value: string, limit: number): string {
     let end = 0, count = 0;
     for (const character of value) {
       if (count === limit) break;
       end += character.length;
       count += 1;
     }
     return value.slice(0, end);
   }

   ```

   - 不导出，不加到 `index.ts`；
