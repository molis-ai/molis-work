## 1. 背景

- `renderPluginRail`（`immersive-shell.ts:131-212`）的参数表是 `primitives, enabled, personalIsland = "", directory = builtinPluginDirectory(), options = {}`。模板里 `${personalIsland}` 写在 nav 里、`.plugin-rail-items` 之前（`:209-212`）。灵光和个人入口早就挪到了底栏，岛位不再有人填。T-040（#1368）删掉了同一位置的 `accountFooter` 参数，T-084（#1400）删了 `renderAccountGlobalItems`，这个参数是同一条线上的尾巴。
- `.assistant-island` 是旧版 rail 顶部那块「个人入口岛」的类，`.assistant-island-card` 是岛里的卡。岛没了，类没人写；样式表里 41 行规则还在，每一份样式表（进入页、设置页、工作台）都带着它们，页面资源的字节数也算着它们。
- 同一个旧位置还留在市场入口上：市场按钮现在是切换器头部 `.plugin-picker-extend`（`data-global-menu`）里的第一个按钮（`renderPickerExtend`，`:220-231`），客户端用 `[data-global-menu] [data-plugin-id="market"]` 找它。`plugin-workbench.ts:22` 和 `plugin-notifications.ts:13` 的第二个备选 `[data-plugin-strip] [data-plugin-id="market"]` 指向 rail，rail 里没有这个格子；`pluginLink` 的 `market` 分支同理。
- 删之前要确认三件事，起草线在 main 上核过：
  - `renderPluginRail` 的调用点：
    - 生产两处，都传 `""`；
    - 测试 17 处：`tests/plugin-picker-pins.test.ts` 14 处传 `""`（`:106 :118 :122 :129 :131 :133 :138 :157 :165 :191 :197 :201 :202 :209`），`tests/agent-built-plugins-workbench.test.ts:9` 传 `''`，`tests/characters-appearance.test.ts:51` 传一段手写的岛，`tests/plugin-picker-pins.test.ts:214` 传 `'<div data-island-marker></div>'`；
    - 另有不传第三个参数的（`pins` 的 `:41 :57 :69 :81 :87 :145 :181`，`characters-appearance:63`，`agent-built-plugins-workbench:16`），不用改；
  - 41 行样式的清单（第 5 节逐行写）里，每一条的选择器要么是 `.assistant-island*` 单独成条，要么是 `:is(.plugin-rail, .assistant-island)` 或 `:is(…, .assistant-island-card, …)` 这样「列表里多一项」的写法；去掉那一项后，列表里剩下的项特异性不低于它，所以别的元素的匹配和层叠顺序都不变；
  - 活的东西不碰：`[data-assistant-island]`（底栏元素 `bar-center` 上的属性，`assistant-dock.ts:14`，被 `assistant-stage.ts`、`craft-finish-assistant.ts`、`craft-finish-pages.ts`、`craft-finish.ts`、`global-search.ts:70` 和几个客户端脚本用着）与 `--assistant-island-row`（`immersive-navigation.ts:463 :479 :483 :489`、`craft-finish-bar.ts:218`、`craft-finish-pages.ts:8`）。
- 页面资源：这些样式进四个冻结的文件，`tooling/gates/page-assets.json` 的 `/assets/molis-work-arrival.css`（`:5`）、`/assets/molis-work-settings.css`（`:48`）、`/assets/molis-work-workbench.css`（`:49`）和 `/assets/molis-work-workbench.js`（`:50`）。删规则只会让它们变小。冻结数只许变小，所以本单要在同一个 PR 里用 `--update` 把它们降下来（第 5 节步骤 10）。

## 2. 目标

1. `renderPluginRail` 没有 `personalIsland` 参数；它返回的 nav 以 `.plugin-rail-items` 开头，前面没有岛位，后面没有账号尾部。
2. 目录里 id 为 `market` 的条目在 rail 里和别的插件一样，aria-label 是「切换到插件：名字」；只有 `home` 是例外。
3. 进入页、设置页、工作台三张样式表以及设计系统的 `MICRO_INTERACTION_STYLES`、`MICRO_INTERACTION_CLIENT_SCRIPT`、`INTERACTION_TEXTURE_STYLES` 里，不再出现 `.assistant-island`、`.assistant-island-card`；rail 没有市场格的规则；分段滑块的脚本只按「当前项」找滑块位置。
4. 客户端找市场入口只用 `[data-global-menu] [data-plugin-id="market"]`，更新数的点只点亮 `.plugin-picker`。
5. 页面显示没有任何变化：`pnpm visual:compare` 零差异（图片和逐元素的计算样式都不变）。
6. 用例钉住上面几条：把参数、岛位、市场分支、任何一处 `.assistant-island*`、任何一处旧找法放回去，各自都红。

- RAC-1823：
  - 三张表从 `tests/workbench-renderer-fixture.js` 读，就是页面发出去的表（`chrome-inner-scroll` 第一个用例同一写法）。`/\.assistant-island/` 要求前面有句点，`data-assistant-island`（前面是 `-`）和 `--assistant-island-row`（前面是 `-`）不会匹配；

- RAC-1824：
