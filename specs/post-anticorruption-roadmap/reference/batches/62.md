## 给人讲清楚

补上第 61 批列出的缺口：技能包、上下文、外部工具连接这几类能力里缺的部分，必要时请上游的 AI 底座一起改；然后逐个服务验收真实连接、断线、撤销授权和恢复。同时落实「项目能用哪些模型、能连哪些外网」的限制，并给智能组合一份统一的可选清单。用不了、还缺外部资格、没验证的，逐项如实标出。需要你做的：几项策略的余项、这次底座换到哪个版本、向上游要什么，以及决定 16，要你定；可见策略、纠正、权限和恢复的样子并定下要你看过定下；外部资格只挡对应的那个服务。

  1. 开轮任务召回收一段由可信 App 提供、有长度上限的召回文本（工作标题、当前对象、已选引用、本轮原话），回执写明召回文本来源；页面声明只收窄（P2-02，MEM-64）。**2026-11-14 上游已做**：molis-ai/molis-prologue#121（`4493a5eb`）的 `agent.memory.taskText`（≤ 2000 字）与 `retrieval.queryFrom`；同一 PR 让空 `resident` 不召回、不授权
  2. **Host 侧（不请上游）** 召回候选按 scope 公平收，大个人库不挤掉小项目库，并按 scope 报扫描量（P2-02，MEM-65）。**2026-11-14 上游试做后撤回**：所有 scope 的记忆行在同一份 kind 列表里，每个 scope 都从头翻再过滤，轮转救不了小 scope、页数反而变多；改由 [63A 第 2 项](63a.md#batch-63a-item-2) 让 Host 能按 scope 区间列记忆行，要不要改 Host 存储窄口在那里实现时定，不再算上游项
  3. `sessions.search`：点名会话按 id 直接读，不先翻全部列表、不被会话数上限静默跳过；连续 `text-delta`／`reasoning-delta` 合成一段再匹配；报告扫描覆盖、截断原因和取消（P2-03，MEM-66）。**2026-11-14 上游已做**：#121 的点名直读、`endSeq`、`scannedSessions`、`truncatedBy`
  4. 视 P2-01 合同冻结结果：提炼结果能带「与哪条旧条目（ref、version）是什么关系」，整理（Dreaming）复用同一 extractor 窄口与写入口，不加新槽（P2-01、P2-04，MEM-60、69）。当前 SDK 已能表达的就不改
- **粒度**（批内子分支怎么分，全批仍是一个 PR；开工建议，执行时按[开发流程第 8.4 节](../development-workflow.md#batch-grouping)判断）：换包窗口是固定窗口，单独一个 PR（第 8.4 节的提前切出）；安全边界与合同各一个子分支，随本批 PR，安全边界的拒绝测试和不变量表同一个提交、评审单独审一遍；逐服务验收一次走完。
