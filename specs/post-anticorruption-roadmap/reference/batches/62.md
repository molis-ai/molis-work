## 给人讲清楚

这一批承接第 61 批梳理出的服务缺口与上游 AI 底座（`molis-prologue`）的「窗口 B 核心升级包」，因为跨度是整本路线书最大的一批，按 **4 个职责分明的有序 PR** 稳步交付：

1. **AI 底座窗口 B 增量换包（`62-0`）**：先在上游补齐窗口 B 剩余能力（OpenAI Responses 新协议、DeepSeek 思考链回放、`apply_patch`、大输出按需查阅、修好 `invokeAll` 工具并发调用、长会话跨轮持久压缩检查点与「干净交接开新局 Clean Handoff」、`SKILL.md` 头部说明解析、子代理模型路由、4 个缺失钩子与 5 个付费面预算门；注：`91-2` 窗口 A 已带进来的缓存与记忆原语直接用，不重复做），经你确认具名提交号后做一次干净换包并过全部金样。
2. **Agent 底座与四策略（技能、上下文、工具、外部连接）核心接线（`62-1A`）**：接通静态工具面（`act__` 前缀 8 处安全点同步更新）、将 `invokeAll` 并行波接上第 `105-1` 批已铺好的宿主同波次批量审批底座（读工具默认自动并行，写工具过同波次原子审批）、长会话压缩检查点与 Clean Handoff、上传附件转按需查阅的虚拟知识件（阅后立即删原临时文件）、按范围列记忆行（供下一批 `63A` 用）、按发布前 Clean v1 直接拍平合并两条「MCP 工具转动作」流水线（不背 4 份历史迁移段包袱），以及用「先起草，别发」这类日常话术实测双路工具发现并把数据交给第 `63` 批。
3. **项目模型与外网边界 + 智能组合统一候选目录（`62-2/3`）**：落实「某个项目只准用哪些模型、只准连哪些外网」（供第 `65` 批 Coding 联网开关消费）；给页面智能组合提供统一的动作、MCP 与技能可选清单；同时按你拍板的结论收口 `BL-128`（插件动作引用声明若前后自相矛盾，在注册启动时直接报错指明，不再留到运行时悄悄失效）。
4. **外部服务缺口收口与逐服务真实连接验收（`62-1B`）**：让信息流（Feed）网页查询直接跟随「设置 › 网页搜索」的默认来源（无需改造第三方 SEL 包，且剔除已删旧炼金术）、把操作卡字段名升为中 / 英 / 日三语、插件撞 ID 时写明被谁占用、把角色开关并入采用卡，并逐个服务实测连接、断线、撤权和恢复（缺外部平台开发者审批资格的服务如实单列，只挡那一行，不卡其他服务）。

需要你做的：`62-0` 换包前确认一次上游 `main` 提交号；`62-1A` / `62-2` 开工前看一次可见策略（Clean Handoff、模型与外网权限提示、服务恢复）的轻量样稿并定下。
