- 归档[需求清单 1](requirements.md#section-3-1)里已做完的 spec；状态句与代码对不上的（产品建议 H7 点过名的几份）一并改。
- 按当前状态核对原在途清单 #1101、#1059（记忆）、#784（QA）、#734（CI）及其成果去向，不沿旧快照直接合并；Memory 保留暂停边界。10-28 已核实 #1306 关闭未合入，逐项找替代提交或未完成项；#1328 采集层需求、#1324 新需求已合入；#1730 的个人助理增量尚在途，按 [近期 PR 来源对照](requirement-prs.md#recent-requirement-prs) 和固定头需求承接；工作简报设计稿 #1312 已合。状态在真正开工时再核。
- 对齐需求正文和验收中的授权边界：已许可工作持续执行、Coding 可选 AI 低风险审批、显式人审的版本／人员要求；不实施一刀切的全量真人批准门。
- `personal`（个人同步）与 CGS 两个分支都不在阶段 0 盘点：个人同步在服务端批 SRV-1 对账，CGS 随 81 的场景批再看（用户 2026-11-03 定）。

- 对外许可口径（A4）改官网仓库的文案。
- 重排 BACKLOG：[决策记录](decisions.md#section-7)、[暂缓与条件项](deferred.md#section-8) 剩下的条目按 [需求清单 7](requirements.md#section-3-7)归进轨道。

**退出**：防腐收尾基线、需求与实现差距、原在途 PR 去向已核对；完成项可归档，未开始和未验收需求如实保留；验收单已备好；阶段 1 的目录、输入、用途分工与风险定位已有决定。验收方式等未定项按实际依赖处理，不阻塞独立设计。

执行安排以 03～27 为主；其中 16 做 B 段真实切片并把现有入口一次切到新格式，26 的发行准备跨阶段 1～2。主线与工作台共同定样；智能呈现第一片与基础首页共用呈现合同／组件并接前三个插件；U1/U2、SDK 共用工具先于新存储和新插件，U3/U4 接后续队列。

文案与引导：D 与 F 按 VUX-51～59、ONB-47～49 清点全产品入口，先做首次使用、再次使用和缺项/失败恢复的高保真切片，确定名称、按钮、默认内容与帮助时机。各轨道提供真实能力、状态和配置来源；新要求不阻塞 Onboarding 已有材料基础路径，也不依赖完整字体/皮肤系统才开始设计。

### 阶段 2：个人工作完整可用

主要对应 28～56，消费前面已交付的 16 与 26；#1730 的逐项交付与返工实操在 32／56 形成退出证据，未合入不等于取消需求。新增主线前两片、智能呈现第二片均在本阶段接通；U4～U6 与其他 M1 前置在 56 会合。[决策记录](decisions.md#section-7)关于缩小 M1、拆首条场景退出条件的建议仍待决定。

D 统筹全产品文案与按需帮助，各功能轨道在所属表面落实，F 接通从当前缺项进入准备并返回原任务的路径。复用现有语言系统与配置/进度，不另建事实来源；已实现入口逐项验收，后续新增或生成页面随所属功能采用同一规则。覆盖与体验未完成时不把这项归为“只差本人验收”。

- **A**：先接个人助理与引导的上下文、问题及继续入口；复用 C 的公共合同，接通明确交办任务的后台执行、主对话及时答复、任务可视化、输入归属、控制及恢复，按个人助理 PWA-127～140 及 [#1730 增量][PAEXT] PWA-144～147 验证逐项证据与返工复核，保留人工体验项。此项不等采集和简报；每日状态简报先有 C 轨的真实采集与历史查询再接（产品建议 E0：只报变化、取不到的标过期、底部三个能点的下一步），由场景技能包驱动、Schedule 按时跑、写进同一 Work Brief 并在综合首页呈现，Feed 归属及计数随公共来源核对（BL-098）；回执余项 BL-314～317、BL-148、BL-162；卡片撤销 BL-343 与同排推荐 BL-344；本机语音（真机验收麦克风、中文输入法、中英混说）。
- **B**：harness B 批（R4 上下文、R5 完成闭环、R6 环境准备、R14 估点与进度）；下一阶段 A 期（说明文件与 `/init`、斜杠命令、图片输入、代码智能，开工前先核哪些已有）；Coding 目标芯片 BL-342。
- **C**：观测和采集第一版先接通手动工作、各类 AI、动作、工作流、定时及后台与实际入口的事实、历史读取、缺口和恢复，再交报告／记忆等消费者使用；接通 Sessions 历史发现、读取、项目归属与引导接续（按完整厂商清单逐项接入），以及最小真实证据读取到判定的评测路径；随后补场景需要的角色与设置公开读写、生成页面定义／校验／隔离／保存恢复能力和引导必需的只读推荐片；按阶段 0 边界接授权与显式人审合同；Skill 策略；换包窗口一（子代理的 Prologue 能力、项目助理团与主对话／后台任务实际执行的必要缺口、P5 协作 BL-307、P6 旧路径退出 BL-308、原暂停解除后的记忆 SDK 余项）；创作台新能力插件交付所需的公共能力；Attention 的稍后提醒与定时唤醒（给 F 轨的角标与通知用）。
- **D**：沿公共合同与 E 的 Work Brief 接通生成首页的交互预览、工作台挂载、页面保存、修改与版本恢复，供 F 的首条场景使用，保留新交互能力和基础首页回退；字体皮肤语言 B、C 段已在 16 完成，本阶段新入口直接按新格式写，55 复核文字与翻译缺口。
- **E**：推进创作台“新能力插件创建→构建试用→安装→独立使用→修订”路径，与 C/D 协作，C 段之后验证正式产物；先补所选场景的插件公开配置/采用能力和真实结果落点；情境 W4（BL-330～334、BL-174，按新格式写），与 F 对接通用任务的准备声明；交互第二批入口 BL-341 与键盘多选 BL-340；插件小功能第二批；Dataset 大数据性能（harness R9）。
- **F**：先沿原主人修顺并实走材料基础路径，包括真实文件支持、大清单、模型往返、生成失败/改范围/重启、材料带入项目与 Coding 接续；不等场景公共能力齐备才处理这些断点。接入 Sessions 的已有外部会话背景和项目归属后，消费 C/D/E 公共能力，走通首次使用、新项目和已有项目增加场景：动态补问、个人助理与项目助理团、真实配置、新交互首页、第一件工作及中断恢复；再接快速创建和不同类型任务，共用准备过程，并支持个人场景保存/复制。复用阶段 1 的技能包与已有模型/材料/连接，完整导入导出留阶段 3；签名、升级链、真实 Home 维护收尾（M1；R-B 改名经你同意的几项随这次维护）；M1 发出时写下兼容起点；原生组件自检；「需要你」的角标与通知。
- **G**：不开工；同步核心在服务端批 SRV-2。

**退出**：所声明覆盖的手动与 AI 工作可从实际操作追到版本、执行和结果，缺口、权限与恢复可核对，评测和其他消费者能经公共能力读取同一事实；分批接入未齐时不称采集内部完整。公共资料消费者、历史引用和过程项接好并回读通过后才退役 Files；Sessions 已有历史可发现、读取并正确归入项目，未接通来源仍列缺口；采集、历史查询和最小评测路径使用同一真实事实，报告不把导入历史算作新增工作；真实代码与混合材料可多位置带入，返回、模型失败、改范围和重启后仍能在项目中接着工作，未处理文件有明确去处；用户能从用途或材料开始，经引导配成场景和可实际执行的项目助理团，生成新的交互首页、完成真实第一件工作，重启后继续；不同类型任务可复用同一准备过程，设置从引导与正式设置入口读写一致，关键失败/撤权可恢复；按用户设定周期生成的简报能刷新、追溯变化并点进去处理，跨重启和错过时刻可恢复；回执在中断、换轮、重启后说得清当前要求；个人助理能在 A 运行时接住 B、回答 C、把补充送回 A，任务进展和控制可见，刷新／重启无重复派出，真实操作与本人体验分别记录；Coding 一个真实任务从开始到交付、中途补充和重启后都接得上；能装到第二台 Mac，升级不丢数据；语言与皮肤切换后所有插件文字、样式一致。

连续两周的简报效果观察从可用时启动，记录实际覆盖、失败及未完成项；与阶段 3 的独立开发并行。两周未结束不能宣称稳定性已验收，但不让所有能力共同等待。创作台的新能力插件路径可延续至阶段 3，阶段 2 的局部通过不代表 BL-377 完成。

主要对应 57～75。智能呈现第三片接助理组合、外部文本形态及其余插件，第四片开始接生成插件与保存视图；主线第三片接助理建议和跨项目个人视图，跨设备同步随服务端批。升级 U7 随完整导入导出交付，U6 接 M2 自动更新在服务端批 SRV-8；长期效果观察随已可用能力启动。
