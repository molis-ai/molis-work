本轮交付是完整需求书；功能目标为「内部完整」：用户能在个人助理对话中完成接入，在必要的登录或授权界面完成本人操作后，回到同一任务，让助理真实调用服务并交付结果。保存配置、登录成功、列出工具和工程测试通过，都不能单独证明这个目标完成。

## 1. 用户目标与产品承诺

用户希望把 Molis Work 中已经接入的服务交给个人助理使用，也能直接说“帮我接入这个服务”，提供服务名、MCP 地址或安装说明，由助理完成检查、选择方式、安装、配置、连接、验证及后续管理。用户只在必须本人登录、填写凭据、选择账号或批准新增权限时介入。

同一 Home 内，连接最初从服务连接、Coding 或其他产品入口添加，不应决定助理能否使用它。助理在已有有效授权覆盖的范围内自动发现和使用实际能力，与其他插件配合完成任务；需要扩展授权时，解释具体差额并提供操作入口，不要求用户重配一份连接。

产品必须同时回答四个问题：配置是否完整、现在能否连通、当前身份获准做什么、具体能力现在能否调用。任何失败都说明停在哪一步、已完成什么、下一步如何恢复；已经完成的任务结果不因接入失败丢失。

## 2. 核心使用场景

| 用户表达 | 助理应完成的行为 | 用户看到的结果 |
| --- | --- | --- |
| “用我接好的知识库，整理这次发布需要关注的内容” | 检查当前授权与可用能力，读取资料，调用 Pages 等插件整理 | 内容、来源链接及保存位置；不再索要地址或密钥 |
| “Coding 里已经接过这个 MCP，帮我查项目资料” | 找到同一连接，沿用其账号与项目范围；若仅缺助理授权，只申请这一差额 | 能用就直接用；不能用时准确解释限制，不复制配置 |
| “帮我接入这个 MCP，地址是……” | 识别远程接入、检查已有连接、配置、引导必要授权、发现并验证能力 | 对话显示进度；成功后继续原任务 |
| “按这份安装说明装好本地 MCP，然后查一下……” | 读取说明、核对来源与环境、安装必要依赖、配置启动、连接并验证 | 安装位置、当前结果及可用操作；失败保留可恢复进度 |
| “连接我的某某服务账号” | 从产品支持的方式中选择适合任务的一种，复用有效登录或打开本人操作入口 | 所选账号与实际权限、已发现能力和缺失项 |
| “现在连了哪些服务？为什么这个不能用了？” | 列出连接，按配置、网络、进程、授权、能力和目标对象逐层诊断 | 具体原因、受影响任务和可执行恢复入口 |
| “重新授权／更新／停用／删除这个连接” | 解析准确对象，展示必要影响，执行对应管理操作并验证结果 | 状态变化、依赖影响、保留的任务结果；无需编辑配置文件 |

例如：“接入公司的知识库 MCP，找出 Alpha 项目的上线要求，整理成 Pages 文档。”成功路径是：查重 → 选定服务与账号 → 必要授权 → 发现检索和读取能力 → 真实读取 Alpha 资料 → 调用 Pages 保存 → 返回文档及引用。登录结束只完成其中一步。

## 3. 连接、权限与能力的统一规则

### 3.1 一份连接，多个入口

连接保存稳定身份、服务、账号/租户、接入方式、授权使用范围及来源入口。来源入口用于解释来历，不作为能力隔离的理由。设置页、Coding、个人助理和其他消费方引用同一连接，不各维护一份可独立变化的凭据或能力清单。

连接的可用生命周期不依附添加它的页面或会话。关闭 Coding 页面、结束原会话或停用仅作为添加入口的插件后，其他已授权消费方仍能使用同一连接；必要时由连接的运行 owner 按需重连，保留原启动目录、参数和凭据引用，无须重开 Coding。关闭页面不等于停用连接。用户明确停用/移除连接、撤销项目权限，或停用真正提供该业务能力的 Integration 时，仍按实际边界拒绝使用，不能借统一管理绕过。用户启动的外部进程退出则报告真实断开，不承诺保持其运行。

查重依据包括规范化服务地址或本地包与启动配置、账号/租户、接入方式、项目范围。不能只按显示名合并；同一服务的个人账号与工作账号、同一服务器的不同租户应可并存。连接尚未验证身份时只能判断“可能重复”，不能猜测或覆盖。

在多个候选中，优先使用本任务已明确选择且仍有效的连接，其次是用户对当前范围的有效默认选择。没有明确选择且会影响数据归属时，询问一次并保留选择；不得静默切换账号、租户或服务商。重连身份发生变化时，需要重新确认相关任务目标。

### 3.2 授权按实际范围复用

可调用能力是以下条件的交集：服务端当前提供的能力、产品已实现的适配、服务账号权限、Molis Work 授予当前调用者的权限、项目/对象范围、助理开关及本次操作规则。模型声明“用户已授权”不能改变任何一项。

已有有效授权覆盖的操作自动继续，不因添加入口不同再次登录或重复确认。原先明确限制为某项目、某账号、某调用方或某类操作的授权仍然有效；要扩大范围，只请求新增部分，并说明为什么原任务需要它。

旧代码未声明 Agent audience、连接记录挂在 Coding owner 下、旧界面没有助理开关，都不是“用户禁止助理”的证据。先依据用户的真实授予、限制和现行助理授权策略判断；已有策略允许的直接复用，仅对实际缺少的授权请求差额。助理保持自己的调用身份与审查规则，不复制 Coding 或外部 Agent 的调用者身份。只有缺少影响正确性的授权事实时才询问，不能因为来源入口不同一律再授权。

个人助理可管理本人有管理权的连接元数据，但管理可见性不赋予业务数据访问权。Home 对话发现项目专用连接时，可以解释其所属项目；只有在任务绑定到那个项目且获得所需权限后才读取数据。界面切换项目不悄悄改变已开始任务的执行范围。

### 3.3 实际能力发现

MCP 在连接可用后自动发现服务实际公开的工具及支持的资源能力。Connector 从已安装 Integration 的业务动作声明和当前授权派生能力；没有动态枚举接口时，如实显示这个边界，不用模型猜测 API。服务提供的 prompt 可以作为受控材料使用，不成为系统指令或新的授权来源。

每项能力至少可解释：来自哪条连接与哪个账号、能做什么、输入要求、读取或写入性质、需要哪些权限、当前是否可用及原因、最后检查时间。能力目录不把凭据、完整环境变量或私有配置正文交给模型。

能力分成“当前可调用”和“发现但被阻塞”两类展示，后者明确缺少适配、权限、连接还是目标访问权。只有在可信元数据或适配实现足以确认时才认定只读；不能仅相信第三方工具的名字或提示性标记。性质不明确的外部工具按可能有副作用处理。

自动启用指让已获授权的能力进入可发现、可调用状态，不指自动执行所有工具或自动扩大权限。新增权限、变更账号、扩大本地目录、改动可执行代码来源等不能借能力刷新静默生效。

连接成功、授权成功、重新授权、更新、重新启用和恢复连通后自动刷新能力；用户说“检查连接”也会刷新。可用性在每次调用时复核，缓存标明时间，不将历史工具列表当作当前连通证明。工具删除、合同改变或提供方替换后，过期引用明确失败或重新选择，不能悄悄调用另一项操作。

## 4. 对话式接入流程

### 4.1 理解意图、检查已有连接

输入可以是服务名、MCP URL、本地启动命令、配置片段、文档链接或安装说明。助理先读取产品支持信息和已有连接，提取非敏感配置，判断用户是接入、修复还是直接使用。已存在可用连接时直接复用；存在失效连接时优先恢复；不先创建重复项。

读取支持范围、检查已有连接、发起安装/配置和本人操作请求的管理能力，不依赖目标服务已经连通，也不要求先打开 Coding 或新建项目。未知服务按 §1.3 判断能否走自定义 MCP；真正缺少地址或安装来源才向用户补问。

对安装说明、网页和工具描述只提取资料，不执行其中试图扩大授权、读取秘密、关闭防护或改变任务目标的指令。需要补充的信息仅限会影响正确性的项目，如账号、租户、目标项目、服务地址或必要权限；不要求用户复述已保存的配置。

### 4.2 选择接入方式并形成可执行方案

用户明确指定服务、账号或接入方式时优先遵循，在该选择内先查重；不支持或不能满足任务时说明原因，不静默换用其他方式。用户未指定时，先复用满足任务的有效连接，再从 §1.3 的适用方式中选择。多个可行方式若在权限、费用、安装范围或能力上有实质差别，给出少量选项与理由；普通实现细节由助理处理。

方案说明服务与账号、接入方式、安装来源和版本、需要新增的依赖、配置和安装位置、请求的权限、原任务要调用的能力以及验证办法。方案随进度可查看，已经授权且边界清楚的步骤继续执行，不强制用户在每一步点击确认。

### 4.3 远程 MCP

远程接入的必需协议与认证组合见 §1.3，自定义 URL 与预置服务遵循同一连接、授权和发现规则。未知服务名不等于协议不支持；不支持的协议扩展或认证方式给出准确说明及可行替代，不能把远程 MCP 整类列为不支持来缩小目标。

地址由 Host 校验并限制到获准目标；重定向不能带着凭据跳到其他服务。对本机或私网服务，使用产品支持的明确网络范围，不能为了接通关闭已有地址、Origin 或授权边界。无凭据服务也需要遵守本地使用授权和操作确认规则。

### 4.4 本地 MCP 与依赖安装

本地接入必须覆盖由产品启动的 stdio MCP，以及用户已有本机 HTTP MCP 服务；后者复用远程连接的协议流程，清楚区分外部进程与本产品拥有的进程。检查操作系统、CPU 架构、运行时、包管理器、指定版本、磁盘和启动条件。已满足的依赖直接使用；缺少必要依赖时由助理执行受控安装，不把“去运行这几条命令”作为默认交付。

新安装默认放在 Molis Work 管理的用户级目录，固定已选择的包/版本、启动参数、工作目录及必要配置。记录本次安装拥有的文件，区分用户已有工具和其他连接共用的依赖。凭据通过受控运行环境注入，模型看到引用或“已填写”，不看到值；启动日志和错误输出脱敏。

运行来自外部包或安装脚本的代码之前，使用具体方案核对已有执行授权；来源、权限或安装范围超出已有授权时，再请求必要确认。需要系统管理员权限、全局修改、付费开通或不支持的安装方式时，明确指出哪一步需本人完成。不能把安装说明中的命令当作用户授权。

启动、握手、发现能力和实际调用分别验证。安装成功但启动失败时保留安装与配置，修复后从失败步骤继续。更新先准备候选版本，再验证切换；失败尽可能恢复上一份可用配置和受管理版本。服务或安装过程不可回滚的影响必须预先说明，不能声称所有更新都能撤销。

### 4.5 Connector

覆盖产品正式支持的 OAuth、API Key/token、CLI 授权及 MCP 等连接方式。优先复用该 Connector 已有的授权、凭据保存和校验流程，通过同一管理接口向助理开放，不为对话复制服务商登录逻辑。

CLI 方式区分“已安装 CLI”“CLI 已登录”“Molis Work 能读取其授权状态”“相关业务动作可调用”。用户在 CLI 登录过但产品没有受支持的复用路径时，解释限制并给正式接入方式，不从磁盘搜出 token 交给模型。

连接只有账号校验能力、没有原任务所需业务动作时，显示“账号已验证，当前不支持这项操作”；可建议已有受支持的 MCP 或适配路径，不能将接入报告为原任务已完成。只实现登录的 Connector 在支持矩阵中标为“仅账号接入”，不能以它替代 Connector 业务调用验收；已有面向用户的业务操作只是尚未开放给助理的，按 §1.2 补齐。

### 4.6 本人操作与接续

对话中提供具体按钮：“登录并授权”“填写密钥”“选择账号”“允许新增权限”“重试此步骤”，以及含对象的“取消这次接入”或“停止这项任务”。按钮打开 Molis Work 的受保护表单或服务商的官方授权页；凭据直接提交到安全保存路径，不能以聊天消息、Agent 工具参数或截图内容进入模型上下文。需要手动提交含授权码的返回地址时，也使用受保护表单，不让用户粘贴到对话。

登录等待不让模型持续空转。系统保留原任务、待完成步骤和授权请求的关联；用户完成、拒绝、关闭、超时或返回错误页面后，都得到明确状态。用户直接问“好了吗”，助理查询真实状态，不根据按钮被点击就认定成功。

授权回调绑定发起的连接及该次有效授权请求，核对账号、配置和当前取消状态后才提交；任务关联用于找到等待项，不赋予回调任意启动任务的权力。过期、已取消、被后续请求替代或属于其他连接的回调不能提交该次接入；重复回调不重复创建连接。登录页可关闭后重开；Host 重启后恢复有效等待，过期的请求给出重新发起入口。

凭据只由专用界面接收。若用户主动在聊天中粘贴秘密，不复述、不用于长期记忆或常规日志，并提示改走安全输入；不承诺已发给模型的内容可以被事后“从上下文抹除”。

### 4.6.1 关闭、取消和停止分别处理

| 用户动作 | 对连接/接入的影响 | 对原业务任务的影响 |
| --- | --- | --- |
| 关闭登录页、切换页面或收起对话 | 不视为拒绝或取消；仍可提交有效授权，重新打开可查看状态 | 保持等待；Host 可运行且条件满足时自动续接，不能要求页面一直打开 |
| 取消本次授权或“取消这次接入” | 使本次请求及关联的待提交配置失效；晚到回调不得保存/替换凭据、创建/启用连接。已有有效连接不因取消一次重授权而被删除；失效的旧凭据也不能被标成有效 | 不再因本次授权结果启动；保留输入和已完成工作，显示接入被取消，可由用户重新发起 |
| “停止这项业务任务，连接可以继续” | 独立接入授权仍有效时可完成连接并报告状态；没有独立保留意图时按下一行处理 | 立即停止后续派出，授权完成不能重启该业务任务 |
| 对“接入并完成任务”的整体请求说“取消/不用做了” | 默认同时取消尚未完成的接入；不自动删除此前已存在或已成功提交的连接，不撤销其他任务独立发起的授权 | 停止该任务；不复活、不自动重做；报告已完成部分和仍保留的连接 |
| 停用或移除连接 | 新调用被拒绝，未提交的相关接入/重授权不得将其重新启用或创建回来 | 所有依赖任务看到明确阻塞；只有用户重新启用/新建并满足各任务当前条件后才可继续 |

取消与提交并发时以 owner 实际确认的先后为准：取消先被接受，之后不得提交；提交已经完成，则报告连接已建立，停止后续任务，并提供停用/移除入口，不能把取消说成已回滚。若服务商已独立授予权限但本地请求已取消，本地不激活连接，说明服务端授权可能仍在，并按现有支持提供撤销入口。已有业务结果和用户文件不因这些取消动作被删除。

### 4.7 验证并继续原任务

完成必要授权后，自动连通检查、能力发现、授权范围核对及最小必要验证。优先使用无副作用检查；禁止为了验证而擅自发信、删文件或创建业务数据。

在助理、设置页、Coding 或另一会话完成同一连接的有效授权、凭据更新或修复后，都由连接 owner 更新真实状态。Host 随后检查已登记为等待该连接的任务，而不是由回调指定要执行的任务。仅当任务仍在等待、最新需求仍需此连接、账号/项目/目标未错配、所需能力和当前操作授权满足，才自动继续；无关、已完成、用户主动暂停、已停止和已取消的任务不启动。若只解决部分权限或依赖，继续不受阻且仍获授权的部分，剩余明确等待，不能把登录成功当成所有条件满足。

同一连接可以解除多个任务各自的阻塞，但每个任务的一次等待只续接一次。重复通知、重复回调、重新打开页面及 Host 重启不能重复派出；任务已在执行时只更新可用状态，不再启动第二轮。关闭页面时 Host 仍运行就正常接续；Host 不运行时在下次启动后复核，不承诺离线后台执行，也不依赖模型持续轮询登录状态。

续接使用同一任务中最新有效的用户要求、账号/项目/对象选择、已完成步骤及待做部分，不重放最初计划。等待期间用户说“只查资料，先别保存文档”，恢复后只读，不再调用 Pages 写入；改账号、对象或扩大操作范围时重新检查差额授权，不能沿用原对象的批准。尚未派出的旧步骤失效，已派出的操作按真实回执处理，不承诺撤回。恢复判断和真正派出之间再次修改任务，也必须在派出前核对，旧计划不能穿过这个间隙继续执行。

修改业务步骤但仍需原连接时，接入可继续；用户改为接入另一服务/账号或撤回本次接入权限，使原授权请求不再符合新意图时，该任务发起的旧请求失效，按新选择重新准备。晚到结果不能提交旧接入；其他任务独立的请求和此前有效连接不因此被删除。部分授权足以完成修改后的任务就继续，不为已删除的步骤再请求权限。

新增能力不能扩大正在运行的 Agent 角色；必要时由 Host 在同一任务下开始新一轮，按最新需求读取当前授权及角色边界。用户无需新建对话或重复下达原任务。等待、修改和续接复用已有任务记录与运行恢复能力，不另建通用工作流引擎。

接入成功后应说明所选账号、可执行的相关能力和仍受限的部分。真正业务调用的返回、目标系统结果和插件保存结果共同证明任务完成。只要求接入而没有后续任务时，报告具体验证范围；未实际调用的能力不能标成“已验证调用成功”。

## 5. 状态与用户可见反馈

四个维度分别可查、可解释，附检查时间和事实来源；它们不是只能单向前进的四个阶段。能从连接配置、授权事实、能力目录和调用回执推导的状态直接推导，不要求四套独立持久状态机或复制记录。停用/移除是连接管理状态，可与配置完整性分别显示。

| 维度 | 状态含义 | 不能据此推断 |
| --- | --- | --- |
| 配置 | 未配置、缺少字段、完整；另示连接是否启用、停用或已移除 | 配置完整不代表地址可达或进程能启动 |
| 连接 | 未检查、连接中、连通、断开、失败 | 握手成功不代表账号有读取或写入权限 |
| 授权 | 分别说明服务端账号授权与 Molis Work 当前调用者授权；可为无需服务端登录、待本人操作、已获部分/所需范围、过期、被拒绝、未知 | 有 token 不代表权限足够；无需登录不取消 Molis Work 授权 |
| 能力 | 未发现、发现中、当前可调用、部分可调用、无可用能力、已失效 | 列出工具不代表每个目标对象都能访问或每次调用都会成功 |

“当前可调用”表示已发现有效实现且当前检查通过，派出仍复核；另外记录“最近一次实际调用成功/失败/结果未确认”及时间。没有 scope 查询能力的服务应显示授权范围未知，依据具体调用反馈逐项收敛，不能显示“全部授权”。

接入任务另有进度：检查已有连接 → 准备安装/配置 → 等待本人操作（如需要）→ 连接与发现 → 验证 → 继续原任务；任一步都可能失败、取消或等待恢复。显示当前步骤、关键结果、等待原因和下一步，不把工具内部日志堆成对话正文。

同一连接可能“已配置、断开、授权有效、能力暂不可用”，也可能“已连接、账号有效、只有读取能力”。错误提示必须反映这种组合，不用一个绿色“已连接”覆盖所有状态。

## 6. 对话中的持续管理

| 管理动作 | 必须兑现的行为 |
| --- | --- |
| 查看连接与能力 | 按服务、账号、项目列出四维状态、最近检查和调用结果；支持追问“能做什么”“为什么不能做” |
| 检查与修复 | 区分安装、启动、网络、认证、权限、能力合同和对象访问问题；已授权的安全修复直接执行，不能自动换账号或扩大范围 |
| 重新授权 | 保留连接身份、配置和已有任务结果，只请求缺少/失效的授权；成功后自动刷新并继续仍有效的原任务 |
| 更新 | 说明更新对象、版本和影响；支持本地包、非敏感配置及能力刷新。远程服务商版本不受本产品控制，不能假装本地已回滚服务商 |
| 停用 | 立即拒绝新调用，阻止未派出的操作；释放自有运行资源。保留配置与历史，明确正在执行且无法撤回的外部操作 |
| 重新启用 | 复核当前配置、依赖与权限，再连接、发现和验证；用户主动停用后不得被任务或自动修复悄悄重新启用 |
| 移除 | 核对准确连接与依赖影响，删除本产品拥有的配置和不再被引用的凭据/运行资源；保留用户文件、既有业务成果和必要调用记录 |

移除本地连接不等于卸载用户已有 Node、Python、CLI 或共享包；可清理的受管理依赖明确列出。移除连接也不等于撤销服务端 OAuth 授权：若支持撤销则报告真实结果，不支持则给服务商操作入口。依赖它的工作流程、插件和任务进入可解释的不可用状态，不静默指向另一条连接。

同一连接被多个会话同时接入、授权或修改时，避免重复安装、相互覆盖和同一等待的重复接续；后到的操作看到当前状态或冲突说明。不同任务各自的有效等待可以按 §4.7 分别恢复；取消一个任务不取消其他任务独立持有的请求。一个连接出错不能阻塞其他连接的发现或调用。

## 7. 失败与恢复规则

| 失败类别 | 用户必须知道 | 恢复方式与保留内容 |
| --- | --- | --- |
| 服务、协议或平台不支持 | 哪个组合不支持，是产品缺适配还是服务商有限制 | 给受支持的选项；保留意图与非敏感方案，不伪造成功连接 |
| 运行环境或安装失败 | 缺少哪个依赖、失败步骤、可读的脱敏原因 | 从失败步骤重试；保留已成功安装且可复用的部分，清理自身无效临时文件 |
| 登录取消、超时或回调失效 | 本人操作是否完成、授权请求是否仍有效 | 保留任务和配置，提供重新发起入口，不循环弹登录窗 |
| 权限或对象访问不足 | 缺少的具体能力/权限或目标访问权；已知与未知分开 | 只申请差额，或更换明确选定的任务目标；保留能继续完成的其他部分 |
| 网络断开、进程退出、服务限流 | 哪条连接暂不可用、何时检查、服务给出的等待提示 | 对安全读取与连接检查做有界重试；退避等待可取消，不阻塞整个助理 |
| 工具删除或输入合同变化 | 哪项操作变了，当前计划为什么不能照旧执行 | 刷新并重新选取；需新权限或参数变化时重新核对原授权 |
| 外部写入超时或返回丢失 | 请求未派出、明确失败、已成功或结果未确认 | 未确认时先查原请求或目标状态；无可靠幂等/核对能力时等待用户决定，禁止盲目重发 |
| 接入成功但后续插件失败 | 外部调用已完成什么、哪个插件尚未写入 | 保留可用的中间结果，从失败的插件步骤继续，避免重做已发生的外部操作 |

重启后恢复连接元数据、等待事项、已完成步骤与未确认调用，重新检查运行状态、最新任务要求与授权。不会因为恢复记录存在就再次执行安装或外部写入。已取消的接入不能被晚到回调提交；只停止业务任务而仍独立授权继续的接入，才可更新连接，且不重启该业务任务。具体以 §4.6.1 和 §4.7 为准。

在对应的任务、接入请求或连接被取消、撤权或停用后，不再派出其受影响的新调用，返回结果也不能继续触发下游业务写入；其他独立且仍获授权的操作不随之取消。已经派出的外部操作可能无法撤销，应保留由执行 owner 记录的真实回执，解释已发生、未发生和未知部分；不能承诺外部系统自动回滚。

## 8. 界面、隐私与执行边界

主入口是个人助理当前对话，服务连接设置页提供同一事实的完整视图。对话中的状态、授权入口、修复与结果可就地使用，不强迫用户去 Coding 或新建项目完成接入。服务商登录可使用外部浏览器；完成后有明确的返回位置。

对话应显示账号标签与使用范围，敏感账号信息按产品规则遮蔽。授权页面提供所需权限与用途，不默认勾选与任务无关的额外范围。密钥输入表单、OAuth code/token、环境中的秘密、CLI 登录输出不能进入模型提示、记忆、诊断导出或截图采集；Computer Use 也不得绕过此边界。模型只看到提交状态和非敏感引用。

读资料和安装/写操作遵循现有可信调用身份和副作用审查规则；账号授权不代替具体发送、发布、删除等操作授权。已有同范围有效授权可复用，是否仍需逐次确认由现行动作策略决定。

读取外部内容时保留来源并视为数据；不接受它要求调用其他服务或泄漏本地资料的指令。调用记录足以解释谁以哪个账号对什么目标执行了哪项能力、结果如何；只记录定位所需的非敏感摘要，原始资料与成果归原插件，不另建一份业务事实库。

## 9. 实现边界与依赖

本节约束职责和合同，不提前固定新动作名称、数据库 schema 或另建服务。实现前需在同一需求书补充实际接口设计。一份连接指唯一的配置与授权事实及共同管理合同，不要求所有协议共享一个物理会话、把所有存储合成一张表或新建一套包管理/任务调度系统；消费方使用公开引用，技术缓存可以重建。

| 现有模块 | 本需求中的职责 |
| --- | --- |
| Local Host 的连接管理（`apps/local-host/src/connector-*`） | Home 内连接配置、账号与范围、凭据引用、接入进度和授权回调的唯一管理入口；设置页与助理共用 |
| `horizontal/connector-host` 与 Integration Provider | 现有 Connector 的协议适配、健康检查和技术回执；提供方拥有自身业务能力实现，不在助理内重写各服务 API |
| `horizontal/agent-host` | 通过同一 Prologue Runtime 使用 MCP、执行 Agent、审查与恢复；维持角色和调用授权边界，不为助理另起一套 Runtime |
| Kernel 动作目录与服务 | 注册一次，按身份发现、校验与执行；连接管理和业务能力均通过共同合同开放，无助理专用服务白名单 |
| Local Host 的 Assistant | 理解用户意图、选择连接、协调本人操作、保留任务并接续；不保存另一份连接或凭据 |
| Workbench | 对话状态、授权表单、连接详情与设置视图；只呈现服务真实状态，不自行判定授权成功 |
| Coding 与其他业务插件 | 引用同一连接和公开动作；资料、文档、待办、流程等结果仍由各自 owner 读写 |

模型需要的上下文只有：用户意图、任务与项目范围、连接的非敏感摘要、当前能力及阻塞原因、已有步骤和有效操作授权。模型产出接入方案、管理动作调用与任务结果；凭据提交、权限裁决和状态提交由可信 Host 完成。

管理合同至少覆盖：列出与检查连接、准备接入方案、执行已授权安装与配置、创建本人操作请求、读取进度、连接和发现、诊断、重新授权、更新、启停和移除。输入不接受伪造 actor、项目、安装身份或凭据正文；输出包含当前状态、原因、下一步操作和原任务关联。具体操作仍按风险拆分，不能用一个任意 shell/API 执行入口代替。

### 9.1 存量连接收敛

保留：现有有效连接、账号与凭据引用、用户明确选择的范围、已获授权、任务记录和成果。替换：按添加入口分割的连接管理、重复目录维护及必须手动发现后助理才看见的步骤。忽略：必须进入 Coding 才能使用同一服务等历史界面限制。

先盘点当前 Home 级连接与项目/Coding MCP 的字段、owner、授权和消费引用，确定唯一写入路径；再提供统一管理与发现，切换原入口和助理，最后移除被替代路径。不能让新旧管理入口长期双写，也不能只加 agent audience 就宣称统一完成。

存量授权无须用户重填，按 §3.2 区分用户真实限制与旧实现的入口隔离：仅因 Coding owner 或缺少 Agent audience 而受限的路径应打通；用户明确限制的范围仍保留，实际缺少助理授权时才对同一连接请求新增授予。助理身份和审查保持独立。切换后连接运行不再依附添加入口的页面/会话，按 §3.1 验证其生命周期；无法可靠识别账号或有效授权的记录保留原状并明确请求所缺信息。

涉及真实 Home 结构维护或现行合同改变时，按[合同变更流程](../../docs/system/CONTRACT-CHANGES.md)设计一次性维护、备份和回滚，不新增读取旧值的兜底。具体维护方案须在实现阶段给出，未验证前不对真实 Home 执行；本轮需求编写不构成迁移、安装、登录或外部写入授权。

### 9.2 建议实施顺序

1. 用真实或逼真内容制作高保真可交互切片：已有连接复用、新建连接、等待登录、权限不足、失败恢复、成功后继续任务。模拟部分明确标出。
2. 统一连接身份、授权和目录合同，打通“已有 Coding 连接 → 助理真实调用”这一纵向路径，包含失败与重启。
3. 接通远程 MCP 和现有 Connector 的对话接入、本人操作与自动接续。
4. 接通本地 MCP 的依赖安装、运行、更新、停用和移除；所有入口消费统一管理服务。
5. 完成组合场景、异常、并发与真实账号验收，再按独立发布任务处理安装包和发布。

以上是有依赖的实施顺序，不把远程接通或单个服务成功当作完整需求完成；本地 MCP 和已支持 Connector 同属本次目标，不默认为后续版本。
