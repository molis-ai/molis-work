# 市场分析

形成市场格局、差异、选项和待验证假设，而不是堆资料。

适用于：市场研究、竞品分析、进入策略。

## 规划路径

1. 定义市场边界和决策
2. 分层识别用户、替代方案和价值链
3. 比较关键差异与证据
4. 形成方向选项和验证计划

## 必须覆盖

| area | label | question |
| --- | --- | --- |
| market_boundary | 市场边界 | 在解决什么问题的哪一层竞争？ |
| customer_moment | 用户时刻 | 谁在什么场景下选择或放弃现有方案？ |
| alternatives_competition | 替代与竞争 | 真正的替代方案和结构性差异是什么？ |
| strategic_options | 方向选项 | 对当前项目意味着哪些可选路径？ |

## 依赖规则

| rule_id | statement | direction_hint |
| --- | --- | --- |
| comparison-after-boundary | 竞品和替代比较依赖已经明确的市场边界、用户时刻和比较维度。 | comparison depends_on market boundary |
| recommendation-after-landscape | 方向建议依赖市场边界、用户和替代证据。 | recommendation depends_on market evidence |

## 完成证据

- 一手或权威市场来源
- 真实用户/产品证据
- 关键假设的验证方式

## 收口检查

- 选项而非唯一武断结论
- 明确对当前项目的含义

## 常见误拆

- 竞品功能表代替市场分析
- 用没有表达需求否定创新
- 堆链接没有决策

## 怎样用这份方法

- 先按「规划路径」把事情想完整，再把每个能独立交付、独立验收的结果列成一项；一项里不混入几个主要结果。
- 「必须覆盖」里与当前任务有关的每个问题都要有答案；答不上来的关键问题列为待确认，不用含糊的条目盖过去。
- 依赖只表示结果消费：乙开始或完成时必须用到甲的可验收产出，乙才依赖甲。讨论顺序、时间先后、同一个人负责、改同一份文件都不算依赖；没有结果消费关系的保持并行。逐条判断「依赖规则」，不适用的要说得出缺了哪一种产出消费。
- 每一项写明完成时拿什么证明（见「完成证据」），收尾前过一遍「收口检查」。
- 只描述有限、能完成的改变；持续运行的事不写成永远做不完的一项。
- 和别的规划方法一起用时，把各自的关键结果放在一起看谁消费谁，缺了提供方的再补上相应的方法。
- 拆出来的结果先给用户看。用户要落到某个工具里（例如已装的 Goals 插件）时，用那个工具自己的动作写入，由用户确认。
