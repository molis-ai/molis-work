真实创作台现在卡在哪，要等批次 03 交付项 2 在隔离 Home 里复现以后才知道（PBU §1「首要问题与证据」）。复现找出的新状态会补进这一页；它不改变这里要选的布局。场景组装的合同（决策 11 留给批次 03 细化的部分）不在这一页定。

## 打开

```bash
python3 -m http.server 4410 --bind 127.0.0.1 --directory docs/design
```

再打开 `http://localhost:4410/plugin-studio-main-path/`。顶部带斜纹边的一条是原型控制：方案、剧本（上一步／下一步）、情况、中英文、深浅、重置。

剧本是一个真实大小的任务：「每周例会前导入参会名单，开会时一键签到；会后看谁没到，在 Goals 里给『团队例会』记一条」。它从准备走到再改，共八个阶段：准备 → 想法 → 方案 → 构建 → 试用 → 安装 → 使用（创作台关掉以后）→ 再改（从已装版本）。

## 三个方案

三个方案只差**对话、阶段内容和这份插件的定义怎样摆**；每个阶段里的内容（问题、方案卡、构建步骤、试用、权限、版本差异）三个方案完全一样：

| 方案 | 怎样摆 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 对话加阶段 | 左边一直是和创作助理的对话，右边是当前阶段；澄清问题和构建中要定的事出现在对话里 | 像和人一起做：助理说了什么、问了什么、你答了什么都在一条线上；手机上「对话／阶段」切换 | 这份插件现在定了什么要看右边当前阶段，前面阶段定的东西要点回去看 |
| B 分步向导 | 顶上一条八个阶段的进度，一次只看一个阶段，整页给它；助理收在「问助理」里，点开从右边滑出 | 最像向导，一步一步不会乱；每个阶段地方最大（试用、方案卡最舒服） | 助理是附属的，问它要多点一下，打开时盖住一部分页面；前后阶段之间来回要靠进度条 |
| C 规格板领头 | 左边是这份插件的规格板：想法与范围、方案、步骤与能力、构建、试用与修订、权限与版本，逐项写着状态、要你定的标黄；右边是当前阶段；助理收在「问助理」里 | 一眼看到这份插件现在定了什么、还缺什么；手动和助理改的是同一份板（PBU-01）；从已装版本回来再改时，板就是两版的对照 | 左栏信息多，第一次进来比 A、B 难懂；对话不常驻，来龙去脉要打开助理看 |

三个方案共用的部分（不在比较之列，也请一起看）：

- **准备**：进来先看缺什么（模型、试用项目、可组合的能力）；缺模型时在原地选一个，想法不丢（§3.1「进入与准备」）。
- **想法**：只问会改变做法的问题，每个问题写着为什么问；答完才出方案（§3.2 第 1 步）。
- **方案**：三个有实质差别的方案（谁来点、在哪用、接哪些已有能力），每个方案列出关键状态；第三个是组合方案，用到 Inbox、Goals 的已有能力，「提醒没到的人」没有对应能力，标成缺口、不编造（PBU-02）。组合方案的步骤可以上移、删掉，也可以「让助理调整」；每步写着谁改的。你在助理改的时候动了草稿，助理晚到的结果不直接套用，先给你看（PBU-06）。
- **构建**：每一步写着产出了什么；中途有一件事要你定（名单按部门分组还是按姓名排）；能停止，停止先显示「正在停止」再变「已停止」，继续从没做完的那步接着做。
- **试用**：在隔离的试用项目里用逼真的名单，标着「试用数据 · 不进正式记录」；写明哪些能力是真接通的、哪些缺连接被跳过。「指着改」以后点界面上的地方，说要怎么改，只改那一处，并写明其他已确认的没动、可以撤回这次修订（§3.1「试用与修正」）。
- **安装**：装之前列出它能做的事（自己的数据、调用哪个能力、在哪个范围、联网与否），本机构建没有签名要再确认一次；装好以后的回执写明装在哪。
- **使用**：创作台关掉以后，插件从工作台里单独打开，之前的签到记录还在（PBU-13）。
- **再改**：从已装的 v1 开一份草稿 v1.1；v1 照常在用；写明和 v1 的差别、旧记录怎么保留；试用通过才能采用（§3.1「持续迭代与恢复」）。
- 「情况」里的每种失败（PBU-14）：缺模型配置（准备里原地配）、构建时模型超时（重试这一步或换模型，前面的步骤留着）、构建失败（自查发现权限没声明，补上再自查）、界面验收没过（2026-11-03 按[真实复现](../../../specs/plugin-builder-upgrade/reproduction-2026-11.md)补：功能自查都过了，只有一条界面验收超时；分清是界面该改还是验收写得太死，可以先在试用里看一眼，改哪一边都只重验这一条，没过之前不能安装）、构建中断后重开（先核对第 3 步有没有写过，再从第 3 步接着做，不重复写）、试用发现缺陷（大名单 51 人以后不显示，修好才能安装）、安装失败（声明了动作却没有处理代码，什么都没装上，回构建修）。没通过的验证不会显示成完成。
- 看之前的阶段时顶上有一条「在看之前的阶段」，一键回到当前。

## 建议走一遍

1. 方案 A，一路按「下一步」走完；在第 2 阶段选第三个组合方案，试一下上移、删掉、「让助理调整」时马上上移一步（看晚到的结果怎样处理）。在试用里点「指着改」再点签到按钮。
2. 切到 B、C 再走一遍（「上一步」退回开头）。
3. 「情况」逐个切一遍，每种失败看它出现在哪、保留了什么、怎样继续。
4. 换 EN、深色，窗口缩到 1024 和手机宽度。

## 模拟的部分

- 构建按计时器往前走，不调模型；产出、自查结果、用量都是写死的。
- 试用里的插件是原型画的，签到按钮能点，但不存任何东西；「指着改」只画出签到列挪位置这一种修订，指别的地方只记一句话。
- 安装、关掉创作台、在工作台里打开都是画出来的；「使用」阶段的工作台不是真的工作台外壳。
- 对话框只演剧本里的话，输入别的不处理；「附上」「从已有能力拼一个」「看调用记录」「放弃草稿」「回到 v1」只弹一条提示。
- 按钮、标签、分段、状态记号、状态环和提示条用的是组件板实件（共用的 `docs/design/kit/`）；对话与阶段的版面还是原型的写法。功能验收要在隔离 Home 里用真实模型、真实构建、真实安装再走同一路径（PBU-10、PBU-15）。
- 状态存在浏览器 localStorage（键 `molis-proto.plugin-studio-main-path.v1`），「重置」清掉。
