# 27-4 · 沙箱插件包不能开终端时说明原因

状态：第 27 批实施中（2026-11-09）；本片实现与隔离环境实操通过，待整批集成验证及本人验收。目标：功能可用，覆盖本人从设置选择签名包、看到拒绝原因并换包重试。

[BL-910](../../../backlog/BL-910.md) 的 2026-11-04 决定保留沙箱终端拒绝。终端在沙箱外以本人的系统权限运行。基点 `a2a792684408bbcd327355a38428ba77d14c2dbe`：Runtime 启动前已按 [S-103](../../../../docs/system/security-invariants/S-103.md) 拒绝所需或已批准的 `terminal:run`；RAC-2557 注入定义验证启动边界。本人选签名文件时，安装预演在更早的清单一致性检查处只返回形状不符，解释不到终端和本机权限。签过名不改变沙箱隔离。

本人从项目设置的「插件」选择签名包。通过验签、包内外清单一致且到达现有清单投影拒绝分支的沙箱 app（个人空间、项目）或 integration（个人空间），若清单明列必需或可选的 `terminal:run`，预演仍返回原来的拒绝类型，并说明沙箱插件不能打开终端，因为终端会在沙箱外以本人的系统权限运行。没有预演确认界面；选另一份有效包，旧错误清除，正常预演可继续。现有按钮外观保留，改用原生按钮打开文件选择器，Tab 后可按 Enter 或空格。文件预演失败继续在选择器上方的错误行说明原因和未安装结果。实操发现重复通知在重选后仍停留数秒，窄屏上遮住新预演确认区，因此文件预演只显示就地错误，重选即清除。随包、确认与管理失败沿用现有通知。工作台用既有词典给 Host 固定原因英文译文；无需新定样。

只在 app 和 integration 已有的不相等分支选理由。验签、清单解析、包内外一致性、各自所有严格校验及相对顺序保留；其他拒绝继续报原原因。对比过在预演另扫原始清单、移到 SDK 投影处、按错误码在 UI 猜原因：前两者重复校验或提早投影拒绝，后者会混淆其他声明错误。修改只涉及 `apps/local-host/src/sandbox-package.ts`、`apps/workbench/src/settings-plugins.ts`、`apps/workbench/src/i18n/plugin-trust-en.ts`、`tests/security-invariants-plugin-install.test.ts`、`tests/security-invariants-plugin-trust-http.test.ts`、[S-103](../../../../docs/system/security-invariants/S-103.md) 和本任务书。不改 Runtime 判定、权限分类、SDK、动作或 HTTP 结构、版本、签包格式、安装状态机、现有插件恢复文案与信任机制；不接触真实 Home。不涉及并行实现，整批由统筹集成。

## 验收与验证

- **BL910-01**：真实 Ed25519 签包通过签名检查，项目 / 个人空间 app 的必需及可选声明、个人空间 integration 的声明，仍以 `plugin.declaration_invalid` / `invalid` 拒绝，明确说明终端在沙箱外以本人系统权限运行；不发预演 ID，不固定信任、不留包、不装、不启动。对照允许的私有存储包仍可预演。
- **BL910-02**：带相同终端声明但无签名、签后篡改、换公钥或包内外清单不一致时，仍由原来的检查先拒绝，无写入；原 Runtime 启动防线保留。
- **BL910-03**：本人管理 HTTP 返回 400 和原错误码及明确理由，概览、固定与留包状态不变；实际文件选择中英文、浅深色、1440 / 1024 / 390 可读，换有效包能继续，旧错误和重复通知不会挡住新预演；拒绝时一次预演请求且无确认请求。
- **BL910-04**：Tab 可到原样式的选择按钮；Enter 与空格分别打开系统文件选择器。用测试浏览器的实际按键触发文件选择器事件，测试工具只代替操作系统填入临时文件；选择之后仍走页面和 Host 原路径。

以 `pnpm build` 后的 `node scripts/run-tests.mjs --jobs 1 tests/security-invariants-plugin-install.test.ts tests/security-invariants-plugin-trust-http.test.ts` 验 BL910-01～03 的签包、管理边界；基点与候选用同一签包用例。独立测试浏览器和临时 Home 实操 BL910-03～04，保留截图和请求计数；定向运行走公共槽。交回前 `node scripts/check-health-gates.mjs --base origin/main` 与 `git diff --check`。原 Runtime 用例、包 README 回归、页面资源总账及本人验收由统筹按整批安排。

2026-11-09 定向记录：基点六种真签包在相同错误码和类别下只报通用清单形状不符，本人管理 HTTP 同样返回通用理由；实际设置页两个抽样组合的旧 label 都不在 Tab 顺序。候选六种真签包均明确拒绝；无签名、签后篡改、错公钥、有效签名下包内外不一致以及其他权限声明错误仍由原检查拒绝。本人管理 HTTP 仍答 400，不发预演 ID，概览、信任和留包无变化。

实际工作台内嵌设置在三种宽度、中英文及浅深色共 12 组实操通过：Tab 可到、Enter 与空格打开选择器，拒绝只发一次预演，未发确认；换受限的有效签包后原错误清除，可当即取消新预演。测试仅替代系统文件对话框填入临时路径。中英文验收覆盖本片拒绝理由；有效包原有的私有存储权限描述在英文页仍有中文，未纳入本片。与子分支基点相比，Host 下发的工作台脚本原始体积增加 110 字节，没有新增资源；整批以合入前基点统一核算。
