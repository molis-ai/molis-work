# 打开 Molis Work：项目选择、Welcome 与新建项目

状态：已实现，PR 评审中（2026-10-01）。高保真设计与可交互原型经用户认可（「整体设计不错」），用户授权开发并在完成后推送 PR（须检查边界场景、元素重叠、组件沿用项目整体设计、动线）；这些检查已写成真实浏览器里的版面审计与动线测试，见本文末「实现记录」。设计图、动效录屏与原型见 [docs/design/project-arrival-flow/README.md](../../docs/design/project-arrival-flow/README.md)；实现记录见本文末「实现记录」。分支 `feature/project-arrival-flow`。上一轮概念稿与需求书已删除。

## 要解决什么

- **项目选择页**是每天打开 Molis Work 的第一页，问题最大：现在是一面卡片墙，只看得到项目名和「本地项目」，看不到描述、进度、下一步，也没有「上次打开」。要重新设计，保证实用、有体验感、风格统一。
- **Welcome（首次启动的语言、外观）**保留现有内容与节奏，只换进统一框架与组件。
- **新建项目引导**保留现有来源、授权、读取上限、模型与整理逻辑；提高信息密度和质感，删掉无关的引导文字。
- 三者只用全项目的组件板（`/__ui/catalog`，`mw-*`），动线和交互串起来看。

## 已定

| 问题 | 决定 |
| --- | --- |
| 视觉方向 | 统一在现有 Soft Workbench 组件板。Molis Club 只借字标打字机、AI 字幕和页头的字体节奏，不再分三个方向。 |
| 底部 | Welcome、新建引导、项目选择页和项目内用同一条底栏：位置、高度、外框一致，内容随情境变。 |
| 打开时 | 停在项目选择页，预选上次的项目，回车即继续。 |
| 旧需求书 | `specs/project-directory-redesign/` 已删。 |

## 开场：新老用户的仪式感不同

每次打开 Molis Work 都有开场，参考 Molis Club 的 Edition C（巨型字标打字、A/I 字幕）与 Daylight（暖光渐亮）。新用户给完整的仪式；老用户的开场不能挡在进入工作之前。

- **新用户（首次启动）**：一屏全窗开场。暖光从左上渐亮，大号「Molis Work_」逐字打出，下方 AI 字幕开始变换；打完后右下出现「开始 ↵」。任意键或点击可直接跳到结束状态。之后进入语言、外观和新建项目引导。
- **老用户**：没有单独的开场页，项目选择页本身就是开场。页面一出现就能操作：上次的项目已预选，回车立即进入，键盘和点击不等动效。标题栏里字标打字一次，AI 字幕在页头变换；列表行依次到达、详情从 40% 透明度上浮 7px（420ms），不从全透明闪入。目录栏顶部有一行问候：「下午好 · 上次在 FlyLeaf-V0.1 · 2 小时前」。**项目选择页不用渐变**，暖光只属于新用户的开场和 Welcome（沿用「渐变只属于 onboarding」；目标卡里的暖光是产品 Home「正在推进」卡片已有的）。
- 从项目内回到项目选择页、切换项目、搜索都不重播。减少动态效果时全部静止，直接显示终态。
- 已定：老用户的轻开场**每次冷启动**都有（约 1.3 秒、只在标题栏与到达动效里发生、全程可操作）；新用户的完整开场**单独一屏**，打完出现「开始 ↵」，任意键可跳过。

## 共同框架

- **标题栏**（桌面色）：左为字标 Molis Work，冷启动时按 Club 节奏打字一次（250ms 起，每字 170ms，光标闪三下）；项目选择页在字标旁放 AI 字幕（八组词，A/I 常驻，每字 90ms 打出，停 2.3s，45ms 逆序删除）。悬停、聚焦、页面隐藏、离屏、减少动态效果时暂停，切换项目不重播。右侧是后台任务（有任务才出现）、能力、设置。
- **工作面**：沿用产品「目录在桌面上、右边一张白色工作面」的做法（`--paper`，14px 圆角，`--sheet-shadow`）：项目选择页和新建引导的左栏（目录、问题与来源）直接放在桌面色上，右边是一张白纸；开场与 Welcome 是整张白纸。不再有居中小窗或装饰插画。
- **底栏**：沿用生产常驻底栏的几何。左、中、右三块的内容按下表变化，外框不动、不重挂载。

| 页面 | 左 | 中 | 右 |
| --- | --- | --- | --- |
| Welcome（语言、外观） | 上一步 + 进度短线 | — | 继续 ↵ |
| 新建 · 来源 | ← 返回项目 + 进度短线 | 已添加 N 份 · M 组 · 正文尚未读取 | 空白开始 · 确认范围 ↵ |
| 新建 · 确认 | 同上 | 已选 N 份 · X MB · 开始后读取正文并发给所选模型 | 上一步 · 开始整理 ↵（无模型时：带入资料，先开始） |
| 新建 · 整理 | 同上 | 进行中的阶段 · 可以离开，回来接着整理 | 在后台继续 · 整理中（禁用） |
| 新建 · 命名开始 | 同上 | 项目建议已就绪 · N 项待办 | 调整来源 · 采用，加入 N 项待办并开始 ↵ |
| 新建 · 空白 | 同上 | 将创建「名字」 | 带入材料 · 创建项目 ↵ |
| 项目选择 | 所选项目（徽标 + 名字 + 预览中 · 回车进入） | 助理输入，作用于所选项目，按项目保留草稿 | 新建项目 · 进入项目 ↵ |
| 项目内（现状） | 插件切换器与 Dock | 助理输入 | 常驻入口 · 项目按钮 |

## 每屏结构

**项目选择页**（组件板「目录与详情」组合）

- 左栏 Directory Panel：搜索（⌘K），「个人空间」置顶一行，项目按最近打开排序。每行是 Directory Row：项目徽标、名字、一行说明（当前目标 / N 项等你确认 / 还没有目标 · 最近打开）、行尾目标完成数（3/5）。
- 右侧详情：状态行（进行中 · 最近打开 · 材料数）、项目名、一句描述、目标卡（当前目标 + 完成数 + 一段一个目标的分段条，沿用 Home「正在推进」的暖光卡片）、接下来三条（由你推进 / 等你确认 / 助理在做，用 StatusMark）、最近三条动静、材料与文档数和本机路径。
- 交互：单击预览，回车或双击进入，方向键切换，⌘K 搜索，Esc 清空搜索。
- 状态：正常、长项目名、没有描述、没有目标、没有描述也没有目标、目标全部完成、个人空间、搜索、搜索无结果（给「以这个名字新建」）、还没有任何项目（只剩个人空间和新建两个入口）、加载失败（Alert + 重试）。设计图都在 `docs/design/project-arrival-flow/images/state-chooser-*.png`。

**Welcome**：内容不变（语言 Choice + 右侧「你好。」；外观 Choice + 小样），只放进共同框架，页脚换成底栏的引导态。

**新建项目引导**：工作面两栏，说明就近、一句话为限。

- 来源：左为来源目录（五行 Directory Row，行尾是待添加 / 已添加 N / 暂不可连接）；点开一行就地配置（位置用 Choice，时间范围用 Toggle Group，整个子目录用 Checkbox，主按钮「选择并授权」）。右为材料清单，按来源分组，文件行用 Directory Row 的文件名模式，行尾是大小和移除。空态用 Empty：「从你正在做的事开始」加三个快捷添加。
- 确认：左为两个 Meter（份数 / 50、大小 / 6 MB）、模型行（状态 + 更换）、一句隐私说明、折叠的「读取规则」。右为逐项 Checkbox，分组可全选。
- 整理：左为三个阶段；右为进度条、当前文件、已读回执。
- 命名开始：左为表单（项目名、摘要、来源快照、调整来源）；右为新项目预览，**与项目选择页的详情是同一个组件**，待办草稿在「接下来」里逐条勾选。
- 空白：左为项目名与「先在个人空间开始」；右为同一个详情组件的空状态。
- 要删的文字：右侧示意插画；「勾选不会读取正文…」、recap、脚注三处重复的读取说明合并为底栏中间一处加折叠的读取规则；空白页关于个人空间的长提示。

## 动线

1. **首次打开**：开场 → 语言 → 外观 → 来源 → 确认 → 整理 → 命名开始 → 进入新项目。来源页选「空白开始」→ 空白 → 进入新项目。Welcome 选「稍后再说」→ 项目选择页的空状态。
2. **日常**：项目选择页（预选上次项目）→ 回车 → 项目首页。项目内项目按钮菜单的「全部项目」回到这里，并预选当前项目。
3. **新建**：项目选择页「新建项目」→ 来源 …（不再出现语言、外观）→ 进入新项目。任一步「← 返回项目」回到项目选择页，原来的选中和助理草稿不丢；整理中离开会进后台任务，从那里回到整理或命名开始。
4. **搜索**：无结果 →「以「关键词」新建」→ 空白页，名字已带入。

## 高保真阶段的取舍

高保真用产品真实的样式表与设计系统的 `render*` 函数打成原型，所以控件、底栏几何、颜色、字重、焦点环、减少动态效果的规则都是产品里那一份。和线框相比做过的取舍：

- **目录列在桌面上，右边一张白纸**，不是一整张纸（与产品现有的目录与详情一致，也让列表和详情的层次靠表面而不是线）。
- **助理输入作用于所选项目**，按项目保留草稿；选个人空间时是个人范围。现状是这一页的助理固定在个人范围里，这是一处行为变化，等评审确认（见下）。
- **命名并开始的预览与项目选择页的详情是同一块简介**；待办草稿就是它的「接下来」，不再另列一份。
- **再点「新建项目」接着上次没做完的材料**，并给「重新开始」；只保留还没整理的来源与范围，不复活旧的命名步骤。整理进行中离开则进后台任务，不丢。
- **字号只用固定阶梯**（11 / 12 / 13 / 15 / 17 / 20 / 24 / 30），开场的巨型字标是「问候字」，按窗口宽度分档（200 / 160 / 128 / 96 / 68px），不用流体字号。
- **设计稿里的标注**：标题栏中间的「示例数据 · 未接入真实项目」只在原型里，产品里没有；开场与 Welcome 里没有数据，不显示。
- 补进组件板的候选：`mw-steps`（进度短线）、`mw-bar-context` / `mw-bar-status`（底栏的所选项目 / 处理状态）、`mw-goal-track`（分段目标条）、项目简介块（作为「目录与详情」的组合标本）、`mw-wordmark` / `mw-caption`（动效标本）、`mw-file-group` / `mw-file-row` / `mw-file-kind`（材料清单）、`mw-check` 的部分选中状态。引导现有的 `cx-button`、`cx-row`、`cx-check`、`cx-field` 换成对应的 `mw-*`。

### 数据与 owner

- **简介只读公开读口**，按所选项目逐个读，不批量预取：目标条与当前目标来自 Goals 目录（`goals.list`）；当前目标那一行进展来自它自己的记录（`goals.state` 的进展摘要，没有就用它为什么存在）；接下来与最近来自 Home 事项（`home.events.read`，各插件共用同一个口）；描述是采用时保存的一句话，没有就用项目长期背景里的 context 条目的第一段。读不到的部分在简介里写「暂时读不到」，不猜、不补示例数据；每个读口 8 秒内没答就当读不到，项目照样能进。读一个项目就要打开它，所以页面在人停在某个项目上约 160 毫秒后才来读（经过的不读，读过的先显示上次的），服务端同时最多读两个项目，同一个项目几秒内不重复读。
- **最近打开**与采用时保存的一句话描述放在 `<home>/config/project-arrival.json`（原子改名写）：项目自己的页面被请求时写入（窗格、嵌入、非文档请求不算；5 秒内重开不重记）；选择页渲染时对照目录清理已不存在的项目（个人空间除外）；写失败不挡路。它只是展示记忆，不存任何项目事实，也不参与权限。
- **描述**取采用时摘要的第一段有内容的段落（标题不算，去掉强调、链接和 [S1] 引注，最长 240 字）；空白开始没有描述，简介里如实写「还没有项目描述」。

### 与设计稿的差异

- **没有材料数、文档数、「助理在做」**：这几项没有公开读口（要读各插件私有存储或跨项目汇总），按「不猜」不显示；设计稿里的示例数字没有照搬。
- **开场里也有「稍后再说」**：设计稿的开场没有它，但首次使用要能不经任何步骤离开，`#cx-exit` 也是既有测试与动线的钩子，所以开场的底栏左侧保留它。
- **两个文档、一个框架**：`/`（选择页）和 `/onboarding`（开场、Welcome、引导、更新页）仍是两个服务端渲染的文档，用同一个外壳与同一张样式表；冷启动用 `sessionStorage` 判定，开场进度用 `molis-work:onboarding-intro`。没有改成单页应用。
- **「在后台继续」未做**：整理由 Host 在后台读取，离开页面不会中断、回来接着看（`/api/onboarding/context` 的阶段不变）；把它登记为后台任务没有 owner，不在这次范围。
- **选择页助理的范围**按所选项目（个人空间则个人范围），按项目各留一份草稿；占位语写明在为哪个项目说话。这是设计稿里写明、随整体设计一并获认可的行为变化（原先这一页的助理固定在个人范围）。
- **字号**只用固定阶梯；开场的大字标按窗口宽度分档（200 / 160 / 128 / 96 / 68px）。
- **个人空间那一行**的说明是固定的一句话「不属于任何项目的资料和工作」：设计稿里的「灵光 12 · Shelf 34 · 待办 5」要读各插件的私有计数，没有公开读口。
