## 1. 背景

来源：MISC「T-157/T-158 起草」行里没进 T-204 的第二组。Pages 的浏览器客户端按 UTF-16 单元截文字，截点落在两单元字（emoji 等）中间时留下落单的半个字，显示成乱码，或交给下游后被拒。T-204（前六处）、T-202、T-203 已分别处理别的位置。本单是这五处（行号按 main `51c94ae22`；都是浏览器客户端代码，打进 Pages 的页面资源包）：

1. `plugins/native/pages/src/browser/import.ts:86`：导入预览 `text.slice(0, 4000) + (text.length > 4000 ? "…" : "")`，只显示给人看。
2. `plugins/native/pages/src/comment-side-client.ts:41`：评论列表每条的标签 `….slice(0, 36)`，显示给人看。
3. `plugins/native/pages/src/comment-editor-client.ts:30`：编辑器里点评论时带去侧栏的引文 `excerpts.join('').slice(0, 2000)`。
4. `comment-editor-client.ts:41`：交给助理的整篇文稿 `textBetween(...).slice(0, 100000)`。
5. `comment-editor-client.ts:46`：块备注里的摘要 `node.textContent.slice(0, 100)`。

## 2. 目标

1. 五处截完的结果都不以落单的半个字结尾。
2. 每一处的上限数法（按字数还是按单元）与接收它的那一侧一致，【方案】里逐处写明依据。
3. 有真浏览器用例证明至少第 1、2、3 处（人看得到的）：含两单元字的内容在截点处不再出现乱码。

## 3. 不做

- 不改评论输入框本身（T-203）。
- 不改服务端和库。

## 5. 做法

**每一处先查接收侧怎么数上限，再选写法：**

- 接收侧按“字数”数（动作 schema 的 `maxLength` 由 Ajv 按码点数，库里 `[...x].length`）→ 按字数截，先截前 2N 个单元再展开，不要展开整段：

  ```ts
  const firstChars = (text: string, n: number) => [...text.slice(0, 2 * n)].slice(0, n).join('');
  ```

- 接收侧按“单元”数（`x.length > N` 一类）→ 上限不变，只去掉末尾落单的高位代理：

  ```ts
  const cutUnits = (text: string, n: number) => { const cut = text.slice(0, n); const last = cut.charCodeAt(cut.length - 1); return last >= 0xd800 && last <= 0xdbff ? cut.slice(0, -1) : cut; };
  ```

- 只显示给人看、没有接收侧（第 1、2 处）→ 按字数截（用 `firstChars`）。第 1 处的省略号条件也要按字数判断：`text.length > 8000 || [...text].length > 4000` 才加 “…”。

第 3 处的接收侧是侧栏收到后存进评论的引文，看 `plugins/native/pages/src/comments-store.ts:25` 附近怎么数；第 4 处的接收侧有两道：动作 schema `apps/local-host/src/assistant/assistant-thread-actions.ts:16` 的 `draft.text` `maxLength: 100000`（Ajv 按字数），和 `apps/local-host/src/assistant/assistant-threads.ts:227` 的 `context.text.length > 100000`（按单元）。取更严的一道：按单元，所以第 4 处应选 `cutUnits(…, 100000)`，不能改成按字数（含两单元字的文稿会超过 100000 个单元被拒）；第 5 处看备注字段的存取代码。先读代码再下结论，写进【方案】。

两个小函数放在哪：两个客户端文件各自打包，在各自文件顶部各放一份，或放进已有的共用小模块，【方案】里选一个；不要新增页面资源文件（新增资源要先问）。

**页面资源：** 改完先 `pnpm workspace:build`，`pnpm page-assets:check` 看涨多少字节；要放行时按第 11 节第 3 条办。
