## 1. 背景

依据都在 main `39f9a1bbe`：

- 失败怎么走到退出：`LocalMcpServer.handleMessage`（`apps/local-host/src/mcp-server.ts:292-297`）把 `tools: async () => (await this.ensureCatalog()).tools` 交给 `handleLocalMcpRequest`；`ensureCatalog`（`:167-199`）里，恢复绑定那一步（`:168-171`）和发现那一步（`:175-185`）对「常驻服务不可用」（`mcpResidentUnavailable`，`mcp-start-preflight.ts:7-10`）会吞掉、只剩连接工具，别的失败照抛（`:170`；`:182` 对 runtime 受众同理）。抛出的错一路到 `mcp-request-lifetime.ts:37`，没人接。
- 两种「拒」都会这样走：

| 情形 | 谁抛 | 码 | 说明 |
| --- | --- | --- | --- |
| 已安装启动器（`createMcpResidentStarter().ensure` 作为第 7 个参数，`apps/desktop/launchers/mcp/server.ts:14-16`）遇到 4173 上是另一个 Home 的服务 | `probeMcpResident`（`mcp-resident-health.ts:52`、`:57`，由 `mcp-resident-start.ts:68` 调） | `actions.transport_invalid`，文案「监听服务未通过当前 Home 的健康认证」或「监听服务的 Home 健康签名无效」 | 这是现在启动器真正走的路：探测先于任何带令牌的 POST，`tests/security-invariants-mcp-autostart.test.ts:103-119` 已断言它拒绝且不发令牌 |
| 没有 `ensure`（嵌入或测试里直接给地址），常驻服务拒绝控制令牌 | `forwardMcpContext` 的 describe 步（`mcp-context-client.ts:24-32`）→ `actionErrorFromResponse(403, …)` | `host.request_refused`（`host-errors.ts:14-18`，kind `forbidden`），文案「本地控制请求校验失败」（`web-http.ts:69-72`） | 这是 BL-108 当年描述的 403；那条回答故意不说哪一项校验失败（`docs/system/SECURITY-INVARIANTS.md` S-02、S-03 行） |

- 没有现有测试依赖「发现失败时进程退出」：`tests/mcp-stdio-lifetime.test.ts` 的三例（`:10`、`:34`、`:48`）只测取消、EOF 和队列上限；`tests/resident-management-actions.test.ts:56` 的 `tools/list` 是成功路径；按 `tools/list` 加 `rejects` 搜 `tests/` 没有命中。
- 取消不能变成应答：`stdio.ts:36` 对已取消的请求丢掉错误，`:35` 的写出也要求没被取消。所以取消里的 `tools/list` 失败必须仍然 reject，不能被新的处理变成一条应答。

## 2. 目标

1. 常驻服务拒绝发现时（上表两种），`tools/list` 得到一条 JSON-RPC 错误应答：`id` 是请求的 `id`，`error.code` 是 `-32603`，`error.message` 是现有的统一错误文本（`formatMcpToolError` 的 JSON），其中的 `code` 是原来的码；不再 reject，也没有 `result`（`RAC-1470`）。
2. 走真实的 `serveMcpStdio`：`tools/list` 被拒之后，同一个进程照常回答下一条请求（`ping`），直到输入关闭才结束，且正常结束，不 reject（`RAC-1471`）。
3. 请求被取消时，`tools/list` 的失败仍然 reject 成取消原因，不产生应答（`RAC-1472`）。

## 5. 做法

统筹已定的决定，照做，不另选：

1. **接在 `handleLocalMcpRequest`，不在传输层，也不在 `LocalMcpServer`。** 传输层（`stdio.ts`）共用，且「处理器抛错就应答」会掩盖流故障；`mcp-server.ts` 是装配文件（`scripts/affected-tests/rules.mjs:57`），碰它 `full` 变 true。`handleLocalMcpRequest` 已经是「宿主给每条消息一个编号、取消由传输层给」的那个地方（`:34-36`），失败的回法放这里最贴。
2. **只接 `tools/list` 的发现，不接别的。** `tools/call` 自带 `try/catch`，别的方法没有 IO。
3. **应答是 JSON-RPC 错误 `-32603`，`message` 用 `formatMcpToolError(error, recordedCallId())` 的原文。** 协议要求 `tools/list` 失败只能回 `error`（它没有 `isError`）；文本沿用 `apps/mcp/src/tool-error.ts:3-10` 的统一形状（`error`、`code`、可选 `details`、可选 `call_id`），不另开第二种错误形状。`message` 会是一段 JSON 文本，客户端怎么显示不归本单管。
4. **不加「不是这个 Home 的服务」的新文案。** 403 那条回答故意不说哪一项校验失败（S-02、S-03；`host-errors.ts:14-17`），客户端一侧也不知道是 Home 不对还是令牌不对，加一句猜测是在补一个这条边界故意不给的信息。启动器真正走的路是健康探测，它的文案已经说「监听服务未通过当前 Home 的健康认证」，等于 BL-108 要说的话。要在错误里写地址和 `MOLIS_WORK_WEB_URL` 的提示，是另一件事，统筹不定，不做。
5. **取消先于应答。** `catch` 里先 `signal?.throwIfAborted()`：请求已被取消时，错误换成取消原因 reject，`stdio.ts:36` 会丢掉它，不会写出一条没人要的应答。
6. **测试放新文件，不进 `ci-product-subset.txt`**（T-041 的名单不碰；这里要起 `LocalMcpServer` 和本机 HTTP 桩，不是纯内存）。造法（建议）：
   - 每例一个临时 Home（`mkdtemp`，里面 `config/web-control-token` 写一串 `randomBytes(32).toString("base64url")`，写法同 `tests/security-invariants-mcp-autostart.test.ts:69-70`），一个 `node:http` 桩监听 `127.0.0.1:0`。`fixture` 在那个文件里没有导出，只照它的写法自备一份，不 import。
   - 服务端：`new LocalMcpServer(withMolisWorkProjectCatalog, "runtime", null, { homeDirectory: home, runtimeContext: { runtime_id: "t051", stable_work_context_id: "t051", host_declares_stable: true } }, undefined, origin, ensure)`；参数顺序和前 6 个的写法照 `tests/resident-management-actions.test.ts:39`，第 7 个是 `ensureResident`。`t.after` 里 `await server.close()`、`starter.close()`、桩 `closeAllConnections()`、删目录。只用包名导入：`LocalMcpServer`、`createMcpResidentStarter` 都从 `@molis-ai/molis-work-app-local-host` 取（`apps/local-host/src/index.ts:201`、`:46`；`security-invariants-mcp-autostart.test.ts:10` 同样写法），`serveMcpStdio` 从 `@molis-ai/molis-work-app-mcp` 取；不需要 `@molis-ai/molis-work-app-desktop`。

     - 拒绝桩：任何 POST 回 403，体是 `{ error: "本地控制请求校验失败", code: "host.request_refused" }`，不传 `ensure`。
     - 外来监听桩：`GET /health` 回 200、带 `content-length`、体 `{"status":"ok","desktop_tui":true}`、不带 `x-molis-work-proof`（即 `security-invariants-mcp-autostart.test.ts:111` 的 `missing-proof`），传 `createMcpResidentStarter().ensure`。
