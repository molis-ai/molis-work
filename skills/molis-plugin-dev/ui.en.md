## Quality bar (all plugins)

First-party and Studio-generated plugins follow the same standard. The renderer ensures much of it for generated plugins, and design must still follow it.

- **Use the UI catalog only** (`/__ui/catalog`, `mw-*`). Do not invent a control or interaction. Add needed components to the catalog first.
- **Three states**: show a centered empty state (icon, one title, useful next step and one primary action), a loading skeleton instead of a blank area, and an error that names the problem and next step while keeping input.
- **One primary action**: one graphite primary button per view. Secondary actions use softly washed buttons without an outline. Place new-item controls at the title area or toolbar's end, or at the end of the list. Give dangerous actions less emphasis and confirm before executing.
- **Words**: name the person's action, not the mechanism. Show a locale-appropriate time like “Today at 14:30” and keep the underlying value. Show familiar labels (e.g. “Want to read,” not the enum `unread`).
- **Hierarchy starts with type**: weight 600 for headings, 500 for rows and controls, 400 for body. Then use size and `--ink`, `--ink-soft`, `--muted`; spacing and a few dividers come last. Do not outline the stage, nest cards or pile on decorative labels.
- **Color conveys state and selection**: selection uses neutral wash (`--nav-active`) or graphite. Copper is for focus, links and progress; a plugin has no identity color and icons stay neutral. Business views have no gradients; soft warm/cool light is reserved for onboarding.
- **Shadows lift** menus, overlays, dialogs and Toast. Use the overlay shadow without an added border. Ordinary content has no shadow.
- **Do not repeat location**: the Workbench tab already names the plugin. Leave the plugin name out of the stage heading except on a separately opened preview or trial.
- **Light and dark both work**: use tokens, no fixed color values, and inspect both appearances.
- **Visible feedback**: a press responds; a saved row visibly arrives where it belongs. Success fades after a short display; failure stays until the next success.
- **One Toast**: use the design system's `.mw-toast` (server `renderToast`). Set `data-mw-state` to `done` or `failed`; `is-error` gives one small shake on failure. Undo or next step uses `.mw-toast__action`. Plugin code only places it: for centering use `inset-inline: 0` and `margin-inline: auto`, not `transform`; do not set color, radius or motion.
- **Use the shared mechanisms** shown on the component board and available in Workbench/sidebar:
  - Scrollbars are hidden by one design-system rule. Plugins do not set `scrollbar-width`, `scrollbar-color` or `::-webkit-scrollbar`; `tests/scrollbars-hidden.test.ts` refuses them.
  - Horizontal tabs, chips or view switches that can overflow use `data-overflow-fade`, fading only a side with more content.
  - Copy uses `window.molisCopy(button, text, { done: "Copied", failed: "Copy failed" })`. Report success only after the clipboard accepts it, without a width change. Icon-only buttons show a tick or cross and announce the label. The return tells whether it succeeded; explain how to copy manually when it failed.
  - Collapsible detail uses `<details class="mw-collapsible"><summary>…</summary><div class="mw-collapsible__body">…</div></details>`. Expand to natural height and continue from the current height when reversed midway.
  - Counters, times and positions use `<span class="mw-num" data-num-ghost="widest permitted value">value</span>`. Tabular numbers and the ghost keep neighboring controls from jumping when digits or fonts change.
  - Long conversations and logs use `window.molisFollow(scrollContainer)`. Follow at the bottom; scrolling up, keyboard or selection releases it. Call `pin()` when content arrives, `toLatest()` for the latest action, `release()` before jumping to a card, `restore(top)` for a remembered conversation position and `resume()` for a new conversation. Register `lifetime.own(() => follow.dispose())`. One container has one follow owner; later callers get the existing object and cannot replace its `onChange`. Scripted scrolling does not count as user input. Do not invent a distance-to-bottom threshold.
  - After drawing a long list, call `window.molisShowMore(list, { key, label: "Show {n} more", keep })`. Keep the first five visible, fold the remainder behind one button, and show a lone extra item directly. `keep` identifies rows always visible, such as failures. Redrawing the same `key` retains expansion.
- **Code blocks grow in place**: stream with `window.molisStreamText(container, html, { reveal, grow })`. Delegate code to SDK `growCodeTokens` from `@molis-ai/molis-work-plugin-sdk/highlight`, coloring from the first changed line (normally the last). Preserve the block, copy control, highlighted parts and opened disclosures; copy the current source. Do not replace or recolor the whole block (the 1,000-line comparison was 19.5 ms versus 3.7 ms). Parse diffs by block: a line inside a block is interpreted by its first character, even if it resembles a file header.
- **Render and redact foreign text with the SDK**: for subscriptions, pages and model replies, use `renderRichText` from `@molis-ai/molis-work-plugin-sdk/rich-text` to render Markdown and allowed sanitized HTML, keeping only HTTP(S) links. Use `richPlainText` for list rows and summaries. Declare `marked` and `sanitize-html` as plugin dependencies for this subpath. Use SDK `redactSecrets` before displaying foreign text or sending it to the model. Do not make another parser, sanitizer or highlighter.
- **Narrow layouts work**: touch targets near 44px, row actions can wrap below, and toolbar labels can collapse into icons while retaining accessible names.
- **Hidden hover actions work with keyboard and touch**: show them under `:focus-within` and always under `@media (hover: none)`. Actions revealed by explicit row selection need no hover rule. For a control outside normal Tab order (such as closing a tab), place the equivalent shortcut in the row's `aria-keyshortcuts`.
- **Truncated words can be recovered**: ellipsis or line clamp for long names, paths and summaries belongs in a control or row that can be focused or pressed. The platform hint reveals the full value on hover, keyboard focus or touch hold. Do not add `title` or private hints. Do not truncate errors, statuses or action labels without a containing control.
