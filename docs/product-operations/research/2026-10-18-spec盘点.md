# Part A：活跃 spec 逐份盘点

## A1. proactive-assistant（主动式工作助理）
1. **一句话**：用户不用反复发话，助理能根据近期行为与跨插件内容发现值得推进的事，按用户可改的"场景 Skill"准备结果、写周报/复盘、在首页和侧栏给出可点选的下一步，并能接续、等待、重启后恢复。
2. **状态句**："需求已整理（2026-10-15），尚未实现。功能目标完成程度为**内部完整**……本次交付为需求定义，不代表功能已实现。" → **仅设计**。（但依赖的助理、定时、记忆、角色、侧栏、成果能力已在 main 上。）
3. **承诺（验收 PWA-01…PWA-17+，共约 17 条以上）**
   - PWA-01 未发新请求、未预建 Goal，助理也能从真实行为+跨插件内容发现具体下一步并交付可接续的建议/已获准的准备结果。
   - PWA-02 观察范围可查看可调；排除/撤权后不再用于新判断。
   - PWA-04 工作理解要说明目标、进展、缺口与依据，依据不足不编造。
   - PWA-05 用户纠正（"这是同一件事/这份资料不属于这"）影响后续判断；短期选择不自动变长期偏好。
   - PWA-07 无实质变化时保持安静；不重复提示、不被自己的产物触发。
   - PWA-09/10 场景 Skill 真正驱动行为：改 Skill 后行为（取材、分析、跟进）变化，不只改文案；初始 Skill 开箱即用（近期梳理、周期报告、提前准备、阻塞跟进、跨插件衔接、结果核对、机会发现）。
   - PWA-13…16 Skill 可直接编辑/对话修改、试用只读、保存后版本化、停用即停效。
   - PWA-17 有效同范围授权下不重复请求批准。
   - 另有：周期报告（日/周/月/自定义范围、可核对来源、保留人工修改、保存版本不被暗改）；可点选的决定（选项绑定版本，旧选项失效）；项目首页总览（重点/需你处理/可接续/周期回顾）；侧栏卡片点击→主区打开对应插件并高亮定位；平台级"完整工作记录"支撑端到端效果评测。
4. **角色/场景**：个人开发者/产品负责人/小团队；早上回到项目要"一眼知道进展并接着做"；周五要周报；会议前要准备材料；等待回复后被唤醒接续；发现重复劳动→建议固化成 Skill。
5. **依赖**：work-brief（周期报告载体）；context-program/side-shelf（侧栏联动与定位高亮）；prologue-adoption（持续执行/等待/恢复）；记忆、角色、搜索、成果库；ai-input-receipts；ai-interaction-experience（统一选项交互）。
6. **愿景句**
   - "减少重复解释和资料搬运，缩短从材料到结果的过程，让未完成的工作更容易接续，让需要本人决定的事更明确。"（§1）
   - "提示数量、对话轮数、运行次数和 Agent 数量不作为成功指标。"（§1）
   - "暂不行动也是有效选择……应保持安静或只提出必要问题。"（§4.3）
   - 首页："回来就知道进展、马上能接着做。"（§11）
   - 产品形态原则："通用平台能力 + 个人助理 + 可配置场景 Skill"，场景不固化成产品代码里的专属功能。（§1）
   - 7 天默认回看；跨设备常驻、团队协同、Skill 商店、观察整台电脑——明确不做（§1/17）。
   - 可选扩展（未纳入验收）：Skill 效果对比（原版 vs 新版在历史工作上的差异）、计划变更影响预演、决定与结果历史回溯。

## A2. work-brief（工作简报插件）
1. **一句话**：周报、专题分析、会前准备、方案对照这类"跨插件综合结果"有了固定的家：有正文、来源、版本和修订，首页/侧栏/助理打开的是同一份。
2. **状态句**："需求已整理（2026-10-15），尚未实现。用户已确认纳入独立的工作简报插件，仍由个人助理与场景 Skill 驱动。目标完成程度为内部完整。" → **仅设计**。
3. **承诺（WBR-01…09）**
   - WBR-01 周期报告/专题分析/准备材料/方案对照由助理按 Skill 生成并存入简报；临时提示不强制成简报。
   - WBR-02 首页、侧栏、助理打开的是同一份内容和版本；业务状态仍归原插件。
   - WBR-03 重要结论能核对来源、范围、材料时点；缺数据/过期明确说明，不编造。
   - WBR-04 保存或分享过的版本可回看，不被暗改。
   - WBR-05 用户改写后再次生成：对照差异、冲突处理、采用/放弃，人工修改不丢，不自动改写源业务事实。
   - WBR-06 简报里的后续选项接回同一助理+真实业务能力；旧版本/错误对象/切项目/撤权不误操作。
   - WBR-07 中断/部分成功/重试保留有效结果，不重复生效。
   - WBR-08 改场景 Skill（不改代码）即改变取材与分析；插件没有按场景名写死的流程。
4. **角色/场景**：周度复盘引用待办+文档+代码+会议；会议前准备材料；交付说明准备。
5. **依赖**：proactive-assistant、成果库（固定版本走现有成果机制）、各业务插件的读取/定位能力。
6. **愿景句**："临时提示、一句建议和普通运行通知继续留在助理中，不要求每次都生成简报。"；"插件提供创建、读取、更新、比较和展示简报的通用能力……不在插件代码中固化'周报流程'。"

## A3. unified-input-voice（统一输入与本地语音）
1. **一句话**：首页、助手、Coding 三个输入框用同一套熟悉的输入/草稿/发送行为，并能"点麦克风→口述→本地转写→进草稿→检查再发"，断网也能用，音频不上传。
2. **状态句**："需求已整理（2026-10-15），尚未实现……目标完成程度为内部完整。" → **分支（PR #631 Draft，实现完待真人验收；main 未合，main 上的状态句写"尚未实现"，对 main 是对的）**；基线时 PR 105 文件 +6126。（Jelly 有 whisper 本地原生素材包，但统一输入框未做；见 BACKLOG BL-122 `jelly-whisper`）。
3. **承诺（UIV-01…11）**
   - UIV-01 三入口控件、状态、键盘行为一致。
   - UIV-02 中文输入法选词不误发送；默认 Enter 换行、Cmd/Ctrl+Enter 发送。
   - UIV-03 发送成功/失败/结果不确定三态都有明确反馈，不丢草稿、不重复提交。
   - UIV-04 草稿属于入口+会话，切换/刷新/重启后恢复，互不串写。
   - UIV-05 首次准备（权限、本地识别资源下载）→ 录音 → 停止 → 转写 → 修改 → 发送全流程。
   - UIV-07 转写期间编辑/切会话/清空，不覆盖、不误填、不"复活"被清空的内容。
   - UIV-08 识别资源准备完成后断网仍可转写，音频不发往远端；本地不可用时不静默切云端。
   - UIV-09 [人工] 中/英/混说/技术词的真实准确性与等待时间实测。
4. **角色/场景**：想口述需求而不想打字的用户；中英混说的开发者。
5. **依赖**：ai-interaction-experience、visual-ui-experience（VUX-16 输入）、subagent-interaction（复用输入语义）、ai-input-receipts。
6. **愿景句**："用户……都能用熟悉的方式输入、补充上下文、口述和发送内容，不需要在不同入口重新学习操作。"；"本地识别表示音频在当前使用设备上处理，不发送到远端服务器"；不含语音通话/播报/唤醒词/后台监听。

## A4. coding-harness-optimization（Coding 与 Agent 工作流优化）
1. **一句话**：让"选真实目录→在 Coding 或助理发起开发任务→改、验、交付"这条主链可靠：Finder 选目录真能用、助理委派 Coding 不再说"不支持"、上下文窗口按模型最大值、长任务不跑偏、UI 不抖、Dataset 大表不卡、Git/PR/CI 紧凑集成、Builder 真能出可用插件。
2. **状态句**："需求已整理（2026-10-15）。本次交付为完整需求与职责划分，尚未授权本需求的实现。目标完成程度为内部完整。" → **仅设计/未授权实现**（部分现状修复可能已被其他 PR 做）。
3. **承诺（R1–R13，无 ID 前缀；以 R 编号计）**
   - R1(P0) Finder 选目录等待真正完成、回填完整路径，取消/占用/超时各有表现。
   - R2(P0) 助理能发现并委派所有已注册且获准的能力；委派 Coding 时带上 Skill/MCP/模型等配置；"不可用"区分未安装/停用/无权限等并给恢复动作。
   - R3(P0) 可信项目按层级加载 AGENTS.md/CLAUDE.md 并展示实际生效来源；开发请求进入可执行模式或明示只读。
   - R4 上下文窗口默认取所选模型可信最大值，可调低；不再固定 12,000 tokens 就压缩。
   - R5 "本轮结束/代码写入/测试通过/任务完成/用户接受"分别表达；验证失败继续修复或以具体原因结束，不无限循环；重启后核对再续。
   - R6 首次执行识别依赖、测试命令、既有失败；工作树真可用。
   - R7 状态更新不重启动画、不抖动，向上阅读时不被拽走。
   - R8 浏览器/桌面 Computer Use 接入真实目录 Coding；多动作并发与依赖顺序。
   - R9 Dataset 列表摘要+分页/虚拟化，编辑草稿不丢。
   - R10 紧凑 Git/PR/CI/CD：连接身份、PR 状态、当前提交检查、失败日志、重跑；先 GitHub。
   - R11 Plugin Builder 产物必须在隔离 Home 安装并完成核心操作才算通过。
   - R12 可重复的真实任务评估集；R13 有证据才加效率增强。
4. **角色/场景**：个人开发者/小团队：在真实仓库里让 AI 修 bug、改 UI 并浏览器验证、处理 PR 检查；非开发者通过 Builder 做插件。
5. **依赖**：coding-plugin、ai-input-receipts §20（用户纠正）、prologue-adoption、computer-use、status-ring-system、coding-quality-assurance、plugin-builder(已归档 spec)。
6. **愿景句**："中途补充、更正、失败、模型超时或宿主重启后，仍能知道当前要求、完成到哪里、为什么停下以及如何继续。"；"模型结尾不能单独使任务完成。"；"构建通过、截图好看或结构化设计答卷合法都不能独立证明插件可用。"

## A5. visual-ui-experience（视觉细节、个人助理信息与 UI 性能）
1. **一句话**：阅读更耐久、操作更跟手：版式/字阶/动效统一打磨；个人助理里按"环境、上下文、连接与工具、产出、变更、后台任务"六类折叠分组说清自己在做什么；长内容与持续使用不卡。
2. **状态句**："需求已整理（2026-10-15；2026-10-16 补充动态数字布局验收）……整项目标仍为内部完整，尚未开始产品实现。" → **仅设计（含初始 HTTP 性能基线）**。
3. **承诺（VUX-01…45）**
   - VUX-08 助理按相关性折叠分组呈现六类信息，后台更新不抢焦点、不推走阅读位置。
   - VUX-10/11 草稿待提交 vs 本次实际使用 vs 历史引用不混淆；上下文窗口/token/账户额度分开显示，没数据就写"暂不可用"，不拿估算顶替。
   - VUX-14 新生成文字有克制的"模糊到清晰"（~90ms 候选），历史重开不重播。
   - VUX-16/17/18 输入区稳定、@ / 引用来自同一目录、附件失败可重试且不复活。
   - VUX-19/20 工具状态来自执行/授权 owner；发送失败保留正文附件可重试；限流倒计时按截止时间。
   - VUX-23/24/26 拖拽/分屏/滚动跟随（离底不抢回、有"回到最新"入口）。
   - VUX-35…37 性能：基线先行、同条件前后对比、不整页重建。
   - VUX-42…45 动态数字（倒计时等）等宽、不推挤布局。
4. **角色/场景**：长时间使用助理/Coding 的人；非编程任务也适用（VUX-09）。
5. **依赖**：font-and-skin-system、ai-interaction-experience、craft-finish、status-ring-system。
6. **愿景句**："Molis Work 保留自己的色彩、工作台与导航结构，让阅读更耐久、操作更跟手、信息更清楚；个人助理能说明工作范围、上下文、连接、产出、变更和任务。"

## A6. font-and-skin-system（字体、皮肤与语言系统）
1. **一句话**：用户可独立选字体、皮肤、界面语言，也能对助理说"做一套圆润、蓝绿、活泼但能专心工作的皮肤"，预览、局部修订、应用、撤销；外观与语言由文件定义，切换无需重启，插件/生成插件/外部插件全部跟随。

# Part C：spec 之间的空白与矛盾（产品优化建议）
