# 产品运营文档

这里维护 Molis Work 面向用户的产品表达与运营研究，供官网、产品介绍、推广和用户运营取材：产品是什么、能做哪些事、谁会在什么时候用它、哪几个场景最值得主推、推之前产品还缺什么。

## 成熟度标签

| 细标签 | 含义 | 官网简标签 |
| --- | --- | --- |
| **已发布** | 在公开 Release 里，用户今天能取到。现在唯一的公开正式版是 v0.2.0（2026-09-11）：当时名 GoalBoard，只有源码、没有安装包，MIT 许可，main 打不开它的数据；只有它里面已有的能力能标已发布（清单见[产品介绍第 9 节](产品介绍.md#9-现在走到哪了)） | 已发布 · v0.2.0（源码，当时名 GoalBoard） |
| **main 可用** | 已合入 main，主路径能走通，未公开发布 | 开发中 |
| **main 部分** | 已合入 main，但只有部分路径、或缺关键一环 | 开发中 |
| **分支** | 在分支或开放 PR 上实现，未合入 | 开发中 |
| **规划** | 有 spec 或用户确认的需求，尚未实现 | 规划中（演示标"示意"） |
| **撤回** | 曾经规划或实现，后来放弃或删除 | 不对外 |

**需模型**：只因要先配模型的能力不降级，标签后注"需模型"；配模型是首次设置的一步。推荐、判断这类直接决定流程走向的模型输出（浮条推荐、判断规则），没做命中率评估的标 main 部分；模型那一环自述未接通的，同样标 main 部分。写作、整理、问答这类输出不因没做正式评估降级。

**建议（未立项，不对外）**：只出现在[产品优化建议](产品优化建议.md)里、没有 spec 也没有用户确认需求的项，标"建议"，不标"规划"，不进官网。

**团队协作的例外**：人与人的团队协作内部标**规划**（还没有 spec，需求记在 BACKLOG BL-071 等）；官网对外标"开发中"，这是负责人的决定（2026-10-18 记入），不按上表"规划 → 规划中"的映射。

**示意**：演示和故事是构造的，不是客户实绩。**内部**：Issue 等内部工具，任何对外材料都不出现。

## 口径

- 产品介绍以 spec、[PRODUCT.md](../../PRODUCT.md) 和[事实归属矩阵](../SSOT-MATRIX.md)为准，讲完整的产品；成熟度标清，不因为没合入就不写。
- 场景故事都是示意。没有实测就不写节省时间的比例。
- 官网实现在 Molis Club 仓库，这里只提供内容输入，不代替官网修改授权。
