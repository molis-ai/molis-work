# 项目工具条横跨插件栏，栏与目录同高

状态：已实现，行位置已被 `specs/archive/project-chrome-titlebar-row/spec.md` 改写。完成等级 **3：功能可用**。不宣称可发布。不改用户真实库、不提交、不发布。

本文件是这次壳层栅格微调的唯一需求书。它改写：

- `specs/archive/chrome-plugin-rail/spec.md` 里「有目录时项目工具条落在目录列宽内」；
- 同一文件里插件栏从 titlebar 下一行通到窗口底（`grid-row: 2 / -1`），因而比目录多出项目条那一截。

标签、红绿灯、点插件/目录的预览钉住仍走既有合同。

## 背景目标

项目条（项目名、搜索、设置、收起目录）现在从插件栏右边才开始。插件栏从 titlebar 底下一直拉到窗口底，第一颗图标和项目名齐平，目录却从项目条下面才开始，两列不同高。

目标：项目条占满「插件栏 + 目录」这一整段宽；插件栏和目录从项目条底下对齐，同高。完成等级 **3：功能可用**。

## 当前行为与问题证据

- `.workspace-chrome`：`grid-column: 2; grid-row: 2`。实屏 `left=48`，等于 `--plugin-rail-width`。
- `.plugin-rail`：`grid-row: 2 / -1`。`.tree-pane`：`grid-row: 3`。
- 首页/收起目录时项目条已经是 `grid-column: 2 / -1`，舞台 `grid-row: 3`，但插件栏仍从第 2 行起，和项目条抢左上角。

## 范围与非目标

做：

- 有目录：项目条视觉上横跨插件栏+目录，右缘对齐目录右缘；实现上项目条只占栅格第 1 列，宽度为 `插件栏 + --tree-width`，避免跨列把目录列卡死。
- 插件栏改为 `grid-row: 3 / -1`，与目录同顶同底。
- 首页/市场/收起目录：项目条 `grid-column: 1 / -1`，插件栏同样从第 3 行起，不和项目条叠在左上角。
- 目录拖拽条仍贴目录右缘，可盖住项目条那一行的右缘。
- 有目录时：项目名靠左；搜索、项目设置、收起/展开靠右贴齐目录右缘分割线。首页/收起后（无分割线）这三个控件仍跟在项目名后面，不飞到窗口最右。

不做：

- 不把项目切换搬回 titlebar，不改红绿灯 88px 留白。
- 不改插件栏宽度、目录默认宽度、点按合同。
- 不改 ≤600px 抽屉：它已经是项目条通栏、栏和目录从项目条下面滑出。

## 使用场景

1. 打开 Goals：titlebar 下面一条项目条从窗口左伸到目录右；项目名在左，搜索/设置/收起贴在这条右缘；其下左边插件图标，右边 Goals 列表，两列顶边齐。
2. 回首页：项目条仍通到内容区；插件栏从这条下面开始，第一颗图标不再和项目名抢位。
3. 拖目录宽度：项目条右缘跟着目录走。

## 方案与关键决策

栅格第三行才是「栏 | 目录 |（内容在有目录时从第二行通下来）」。项目条是第二行里覆盖左两列的一条，不是目录列的私有头。

## 输入输出与依赖

- 输入：现有三列栅格、目录显隐 class。
- 输出：项目条与插件栏的 grid 定位。
- 依赖：immersive 导航样式、目录 e2e 几何断言。

## 文件 / 模块边界

允许改：`apps/workbench/src/styles/immersive-navigation.ts`、`linear-density.ts`（若有同位规则）；`DESIGN.md` / surface 一句；`specs/archive/chrome-plugin-rail/spec.md` 被改写的句子；`tests/immersive-directory.e2e.test.ts` 及对照 stylesheet 的断言。

不改：用户库、Tauri 红绿灯坐标、插件列表行为。

## 验收标准

1. 有目录时：项目条左缘对齐插件栏左缘，右缘对齐目录右缘；插件栏顶边与目录顶边相差不超过 1px。
2. 无目录/收起目录时：项目条左缘仍对齐插件栏左缘（通栏）；插件栏顶边在项目条底边之下。
3. titlebar 仍只放上一步/下一步和标签；桌面红绿灯合同不变。
4. 点插件栏、收起目录、拖目录宽度仍可用。
5. 有目录时，收起按钮右缘贴项目条右缘（距分割线不超过 8px）；搜索、设置在它左边，与项目名之间留空。

## 假设与开放问题

- 项目条横跨后，栏和目录之间在这一行不画竖线，整条是连续底边。
- 首页通栏项目条会让内容区比有目录时少 32px 顶；舞台在无目录时本来就是 `grid-row: 3`。
