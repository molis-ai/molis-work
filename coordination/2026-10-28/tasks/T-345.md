## 1. 背景

来源：MISC「干净 Home 批 Opus 二审 建议④」（统筹 10-30 转）；#1633 已合 main，各库回到第 1 版，不再有维护脚本。

`plugins/native/feed/src/home-plugin.ts` 约 :21-25：“A Home that has no installation of Feed anywhere has no body to miss: its ledger is complete from the start. Any other waits for the maintenance that reads each project once, and until then releases nothing”——`if (!ledger.isComplete()) { const where = installations.projects(); if (where.complete && where.project_ids.length === 0) await ledger.markComplete(...) }`。`plugins/native/feed/src/content-ledger.ts` 约 :60-65：`isComplete`／`markComplete` 读写 `feed_content_meta` 里的 `COMPLETE` 键。干净重建后“读每个项目一次的维护”已经没有出口，这个分支只剩“永远等”的可能：有 Feed 安装的 Home，台账永远不完整、什么也不释放。

## 2. 目标

先在 #1332 贴【方案】（乙档，写到函数级）：谁还读 `isComplete`（释放正文的闸门）、删 `COMPLETE` 键后释放逻辑怎么变、`feed_content_meta` 表是否还有别的用途（有就留，没有才删，表结构改动属 Feed 库 v1 的 DDL，可以直接改，不写维护）。
1. 先写 RAC-2718 红：一个已有 Feed 安装的 Home 启动后，台账可以释放（不再卡在“未完成”），对现行源码证明红（现在它不会释放）。
2. 删等待分支：台账创建即完整；`isComplete`／`markComplete`／`COMPLETE` 及只服务它们的代码、测试一并删；home-plugin 里对 `installations.projects()` 的读取若只为这个分支，一并去掉。
3. 保留台账其余语义（`hold`／释放的先登记后写、按引用计数）不变，既有用例照绿。

## 3. 不做

- 不加兼容旧库（已有 `COMPLETE` 键的库）的逻辑：干净重建后没有存量。
- 不改 Feed 其余部分（T-336 #1644 在改 Feed 路由与动作，不同文件）。

## 4. 范围

`plugins/native/feed/src/home-plugin.ts`、`content-ledger.ts`、Feed 的库结构文件里 `feed_content_meta`（若可删）、对应测试（`git grep -ln 'content-ledger\|isComplete' -- tests plugins/native/feed`）。
