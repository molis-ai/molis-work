# 创作台做的插件怎样安装、升级和恢复（第 47 批定样）

状态：待用户选（2026-11-21 出样）。三个方案，推荐 A。产品没有实现；整页是按情形演的模拟，不连 Home、不调模型、不真的打包或安装，插件「会议签到」和它的数据都是假的（沿[创作台主路径定样](../plugin-studio-main-path/README.md)的例子）。

需求出处：[第 47 批](../../../specs/post-anticorruption-roadmap/reference/batches/47.md)「先定样：范围、权限、安装／升级／恢复」；[创作台升级](../../../specs/plugin-builder-upgrade/spec.md) §3.1「安装」「持续迭代与恢复」、PBU-13～15；[防腐 PG-083](../../../specs/archive/repository-anti-corruption/privileges.md)（创作台做的插件和别的插件同一套机制，只按签名决定安装信任）。

## 为什么要定

第 47 批把创作台做出来的插件搬到和所有插件同一条安装路上：创作台只打一份在这台 Mac 上签了名的安装包，装不装、给哪些权限，由 Molis Work 自己画的确认界面让本人确认——和装别人做的插件是同一个确认。插件页面（包括创作台）不能替人显示、预先勾选或按下这个确认。

所以要定的是：**这个确认出现在哪里**。创作台「对话加阶段」的版面已在第 03 批定过，不在这里重选。

## 打开

```bash
pnpm build
node docs/design/studio-package-install/export.mjs
python3 -m http.server 4447 --bind 127.0.0.1 --directory docs/design
```

再打开 <http://127.0.0.1:4447/studio-package-install/>。第二步生成设置页「插件」自己的样式（`dist/`，不入库）。顶上一条是原型控制：方案、情形、中英文、深浅、重来。

## 三个方案

三个方案只差**确认出现在哪里**；确认里写什么、装好和出错怎么说，三个方案完全一样。

| 方案 | 怎样走 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 就地弹出确认（推荐） | 在安装阶段点「安装…」，Molis Work 在创作台上弹出自己的确认框；确认完留在创作台看回执 | 不离开正在做的事，一步到位；确认框是外壳的，创作台碰不到；恢复时在插件打不开的地方也能就地弹 | 内容多时框里要滚动，手机上几乎占满一屏 |
| B 去 设置 › 插件 确认 | 点了以后打开项目设置的「插件」页，在那里确认，装好后一键回创作台 | 和从文件安装是同一个地方，不新增任何界面（能力包交接已经是这样） | 要离开创作台再回来，来回两次跳转；出错要回创作台才能修 |
| C 确认嵌在安装阶段里 | 确认直接摆在安装阶段里，标着「这一块由 Molis Work 显示」 | 不弹框、不跳转，地方最大 | 这一块和创作台自己的内容挨着，只靠一行标记区分谁画的；要为「插件页面里嵌一块外壳区域」新做一套机制，这是别的插件都没有的私路 |

推荐 A 的理由：注意力留在创作台这一件事上；确认由外壳画这一点靠「弹出来的框」天然就看得出，不用额外解释；设置页里的管理（改权限、停用、卸载）照旧在 设置 › 插件，回执里给入口。

## 三个方案共用的（也请一起看）

- **确认里写什么**：谁做的（你，在这台 Mac 上）、装在哪里（这个项目，或所有项目共用的个人空间）、它一定要用的、你可以选的（每项一个开关，默认不开，写着不开会怎样）、它在后台会做的。全部用人话写，不出现权限编号。
- **范围**：装进项目还是个人空间，在「方案」阶段就定了（它是插件怎么做的一部分），确认里只如实写出来；情形「装进个人空间」看它怎么说。
- **升级**：从已装的 1.0.0 到 1.1.0，确认里先说数据保留，再列和 1.0.0 相比多了什么、多要了哪项权限（标「1.1.0 新要的」，不开也能升级）。
- **安装没通过**：什么都没装上、数据没动，说清哪里不对，给「回到构建去修」和「再试一次」。
- **升级没成功**：自动回到 1.0.0，数据没动，1.0.0 照常能用。
- **安装文件坏了**：在打开这个插件的地方就地说（沿第 25 批定的「就地说明」），数据还在；可以用创作台里保存的安装包原样装回去（权限照原来的，不用重新选），也可以卸载。
- **装好以后**：回执写装在哪、有几项可选权限没开；之后改权限、停用、卸载都在 设置 › 插件（沿第 27 批已定的卸载交互）。

## 建议走一遍

1. 方案 A、情形「第一次安装」：点「安装…」，开一项可选权限，点「同意并安装」，看回执。
2. 情形换成「升级到 1.1.0」「安装没通过」「升级没成功」「安装文件坏了」，各走一遍。
3. 方案换 B、C，同样的情形再看。
4. 换 EN、深色，把窗口缩到 1024 和手机宽度（手机上创作台用「对话／阶段」切换）。

## 组件板新增

- **带图标的权限行**（`.proto-grant`）：图标在前，名字和理由在中间，可选的行尾是开关（`mw-switch`）。现在设置页「插件」的权限行只有文字、显示的是权限编号；这一行是它的人话版本。选定后先在本批分支上补成组件板标本，再写产品界面。

其余都是组件板已有的：`mw-btn`、`mw-alert`、`mw-dialog`、`mw-switch`、`mw-toast`、`mw-empty`、`mw-badge`、`mw-toggle-group`，以及设置页「插件」自己的折叠行与确认面板。

## 模拟的部分

- 安装、升级、恢复都是 1.3 秒的定时器；「安装没通过」「升级没成功」第一次必定失败，「再试一次」就成功。
- 创作台只画了标题、阶段条、几句对话和安装阶段；别的阶段不展开。插件自己的页面只画了一张签到名单。
- 「回到构建去修」「卸载」「停用」「选择安装包」只弹一条提示。
- 状态存在浏览器 localStorage（键 `molis-proto.studio-package-install.v1`），「重来」清掉；`window.protoJump` 只用于截图时直接跳到某个状态。
