# 91 · 对话与执行流式丝滑化

[执行目录](../../spec.md#execution-batches) · 阶段 2：个人工作完整可用 · [上一批 90](90.md) · [执行规则](../execution-rules.md)

## 给人讲清楚

[第 36A 批](36a.md)把对话栏、右侧信息栏和 Coding 卡片的静态版式收干净了，但真正跑任务时还有一层动态体验债：个人助理每半秒才轮询刷新一次、吐字一顿一顿；流式快的时候新字会把前几个字的渐显动画掐断，粗体和代码块一闭合已读过的字又闪一下；工具一换字转圈就归零；Coding 往上翻历史会话会因为高度没量过而猛跳一截；大工具生成参数或等子代理时画面像卡住一样。这一批把底层的流式平滑引擎、平台共用的单连接实时增量推送、长会话零跳变滚动和过程信号端到端一次做透，让个人助理、Coding 以及后续插件从点下发送到流式吐字、看思考、跑命令、翻历史都像水墨晕开一样顺滑跟手、安静清楚。本批按最大批号编为 91，但**不等 38～89**：一旦 35-2、36A 和 37-2 合入即可开工，[第 90 批](90.md)仍在最后对整条路线（含本批）做最终对账（[决定 54](../decisions.md#decision-54)）。需要你做的：定本批是否顺带换一次 `vendor/prologue-sdk` 包（不换则上游改动先入 `molis-prologue` 主线、随[第 62 批](62.md)窗口二换入）；做完看组件板流式标本并在隔离环境走一遍真实对话与编码手感。

- **阶段／类型**：2；体验与效果（流式动画、滚动物理、运行时热路径）；横向能力 + 产品线（助理、Coding）
- **需求来源**：[对话与执行流式体验][CUI]（验收 CUI-01～09），衔接[逐屏打磨][POLISH]、[Coding Harness][CHO]、[子代理交互][SUB]、[视觉与 UI 体验][VUX]
- **前置／待决**：本批按最大号编在 90 之后，实际执行只看各子项前置，**不等 38～89**（[决定 54](../decisions.md#decision-54)）。共用前置：[36A](36a.md) 的动效曲线收口（第 7 项）；第 3 项另等 [36A](36a.md) 壳层（第 1～3 项，底栏第十三版「对话栏 + 右侧信息栏」）与 [37-2](37.md#batch-37-item-2)（按事项工作台状态与每事项主对话）；第 4 项另等 [35-2](35.md#batch-35-item-2) 与 [36A-4](36a.md#batch-36a-item-4)（Coding 逐屏前后半）。待你定：第 2 项的 `molis-prologue` 上游改动是否授权随本批换一次 `vendor/prologue-sdk`（若不跨窗口换包，上游先合入 `molis-prologue` main，包随 [62](62.md) 窗口二换入，`molis-work` 四项照常一次做完）
- **可并行项**：38、40、44、46～48 等不碰对话流、流式路由快照与 Coding 时间线的批次；上游 `molis-prologue` 热路径优化可先独立开发验证
- **UI 要求**：沿 [36A](36a.md) 已定版式与 `DESIGN.md` 令牌，不新增顶层壳层区域；新增流式平滑、状态环原位流转与微阻尼追底先补进组件板 `/__ui/catalog` 标本（D 轨合审）；若思考折行或紧凑命令尾窗超出组件板既有控件形态，按手册第五节先出样确认
- **粒度**（批内子分支怎么分，全批仍是一个 PR；执行时按[开发流程第 8.4 节](../development-workflow.md#batch-grouping)判断）：按四条轨道拆四个子分支先后叠——先落 91-2（C1 合同先行，带 `pnpm api:update`、`pnpm actions:update`，再落 `agent-host`／宿主流桥接与 Prologue 热路径，最终头请公共合同台 C 轨合审）与 91-1（`packages/design-system` 原语与组件板标本，D 轨合审），再落 91-3（个人助理 SSE 与对话流）和 91-4（Coding SSE、200 轮回滚零跳变与执行过程），最后在最终头上统一跑门禁、安全不变量拒绝测试、页面资源核对与共享核心全量。
