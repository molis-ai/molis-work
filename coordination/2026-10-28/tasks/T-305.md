## 1. 背景

来源：T-275（#1567）二审建议，统筹 2026-10-30 定为测试自身的缺陷：`tests/installed-plugin-host.test.ts` 的 RAC-2406（约 :1098，“closing the Host keeps going when an installation record goes between the read and the stop”）里第二个安装的 `pluginId = 'io.molis.work.generated.' + randomUUID()`，而 Host 关闭时按 pluginId 排序依次停；被删记录的那个安装约一半运行排在最后，排最后时“另一个安装在失败之后仍被停”这半句断言抓不住“第一个失败就中断”的改法（正确代码上不会红，M1 变异仍确定性红，但这半句断言有一半运行在空转）。不是环境问题，不记 R-73。行号以 `origin/main` 为准，开工先核。

这条用例在 Linux 上因 `mac` 标记被跳过，只能在 macOS 上跑（官方或静态 node；Homebrew 共享库版 node 会整文件大面积红，不要拿它判断）。

## 2. 目标

1. 给被删记录的安装和保持运行的安装各一个固定、可比较的 pluginId（例如保持运行的以 `…-a` 结尾、被删的以 `…-z` 结尾，或反过来，按 Host 关闭的排序规则选能让被删的那个**排在最前**的和**排在最后**的两种），不再用 `randomUUID()` 决定顺序；`buildId` 仍可随机，只固定会参与排序的 `pluginId`。
2. 两种顺序都要有断言：被删记录的排最前、排最后，关闭都继续，另一个仍被停、保持 enabled。可以把用例参数化成两个用例（RAC-2406 的两种顺序，名字带编号和 first/last），不新占 RAC 号。
3. 变异：把关闭循环改成“第一个失败就中断”，**排最后**那个顺序下，用例变红（现在只有一半运行红）。贴输出。

## 3. 不做

- 不改源码；不放宽断言；不改其它用例。
- 不引入 sleep/随机。
