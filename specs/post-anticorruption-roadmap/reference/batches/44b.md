## 给人讲清楚

第 44 批（含 `#2258` 独立复核清扫）清掉了 Goals 的大部分私路，但系统里还留着一批「名义上是插件、实际上被平台开后门」的遗留：Shelf 挂着插件壳却独占常开与双实例、Alchemist 仍是构建期手写装配和全仓唯一的 `better-sqlite3` 例外、官方集成绕过统一运行时并把 20 个 CLI 与各厂商分支写死在宿主里、Characters 与 Assistant 漏出保留 id 安全缺口、`#2231` 的同步目录借用 Inbox 一拔就崩。这一批把必须跨全局打底的能力（Shelf、成果库、Characters、创作台、`planning-methods` 系统技能）彻底收归纯平台，删掉旧 Alchemist，把其余插件特例全部收敛成公开声明并上线 **G1「平台不点名插件」门禁**。做完后全仓 `always_on = 0`、构建期例外 `= 0`、`better-sqlite3 = 0`、第三方插件拿得到和内置完全一样的公开声明能力。

需要你做的：如提前切出 `44B-0` 安全小 PR，确认合并；本批其余按已拍板的[决定 66](../decisions.md#decision-66)直接实施，不动真实 `~/.molis-work`。

## 44B-0 实施记录

- 2026-11-23 起，分支 `feat/44b-0-host-prefix`，单独一个 PR。
- 插件命名放开（V16）：contracts 新增 `PLUGIN_ID_PATTERN`（通用反向域名）与 `HOST_PLUGIN_ID_PREFIX`，SDK `PLUGIN_ID`、连接器插槽、同意动作、技能包 id 与创作台两条路由都取这一份；创作台生成的叫 `studio.<编号>`（`horizontal/plugin-studio/src/studio-plugin-id.ts`）；从外部 AI 工具导入的技能包同理叫 `imported.<工具>-<来源摘要>`（`apps/local-host/src/skill-import.ts`，原 `io.molis.work.imported-skills.*` 会被保留前缀拒绝）；在设置里自己写的技能包（本 Home 签名）改叫 `my-skills.home` / `my-skills.project`（`SKILL_AUTHORED_PLUGIN_IDS`）；示例与测试里的 `io.molis.work.example.*` 改 `com.example.*`，`io.molis.work.generated.*` 改 `studio.*`。
- `S-reserved-host-prefix`：Runtime（`assertInstallIdentity`）与安装预览（`assertNotHostId`）都拒非宿主包用 `io.molis.work.*`；唯一放行是本次发布随包文件夹里带的 id（现为官方内容包 `io.molis.work.content.design-accessibility`，`RELEASE_PACKAGE_IDS`），而且只在从随包文件夹装时放行。
- 测试里代替官方插件直接起 Runtime 的夹具（如以 `io.molis.work.coding` 身份调宿主动作）显式传 `releaseIds: HOST_STAND_IN_IDS`（`tests/fixtures/isolated-host.ts`），前缀规则本身只在不传它的拒绝测试里证明。
- 金样：按 U13 不写迁移，`0.1.0` 与 `0.1.0-dev.1` 里装着的两个签名样例就地换成新 id 与重签的包（id、发布者密钥、Manifest 摘要、包目录名、安装号、沙箱库名一并换，摘要重算）；两份金样保留，因为初始版本门禁要它们留着旧版本格式，拍平随 44B-1。回放样例 `generated-counter`/`generated-list` 与 `golden-home-library` 用一次性测试发布者重签。录下来的模型答卷（`tests/fixtures/builder-designer/minimax-notes-v1.json`）保持原样。
- 创作台可移植格式 `format.builder.portable` 不升版本：结构没变，只是 `pluginId` 取值换成 `studio.<编号>`；旧导出会被当作无效拒绝，没有真实用户，不做兼容（U13）。`work-records/gaps.ts` 的显示名只剥宿主前缀，第三方插件显示完整 id，不用改。
