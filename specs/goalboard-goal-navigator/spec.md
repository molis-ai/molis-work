# Molis Work Goal Navigator 视觉重组

## 完成等级

本 Goal 达到 **功能可用的 UI 重组（Level 3）**：真实 Goal Tree 使用紧凑、可扫读的层级和关系摘要，原有 Goal 数据、关系、筛选、新建、归档、回收站和导航行为保持不变。

## 背景与目标

当前列表把 Goal 标题、状态、标识和每一条依赖的原因、等待链与结果同时铺开。项目稍复杂时，用户很难先看到树形结构和异常位置。目标是让用户在一眼扫过列表时先理解：它在树里的位置、现在是什么状态、子项完成了多少、是否存在前置或阻塞；详细关系只在需要时展开。

## 范围

- 保留 `part_of` 关系作为树形层级来源。
- 状态继续使用现有状态解释，但呈现为紧凑标签。
- 有子 Goal 的节点显示完成数量和进度，不创造新的业务进度。
- 依赖默认显示数量与健康状态，展开后可查看每个依赖、方向、原因和完成情况。
- 搜索仍覆盖 Goal ID、标题、依赖 Goal 和依赖原因。
- 保留创建、筛选、折叠、归档、回收站和 Goal 跳转入口。

## 非目标

- 不修改 Goal、Relation、状态或进度计算规则。
- 不新增关系类型、接口或持久化字段。
- 不在本 Goal 中实现 Graph。
- 不改 Goal Detail 或 Runtime/TUI 的业务行为。

## 方案

`renderGoalTree` 继续读取现有 `WebGoalView` 与 Relation 快照，只重新组织输出：主行负责标题和状态，次要行负责 ID 与子项进度，依赖关系收进原生 `details` 摘要。样式延续 Quiet Intent Workspace，以分隔、缩进和小面积状态色建立层级，不使用卡片堆叠。

## 验收标准

1. 树形层级、状态标签、子项完成数量、阻塞和依赖数量可在默认列表中快速识别。
2. 依赖原因不再默认占据多行；展开后仍能查看依赖 Goal、状态和原因，并可跳转。
3. 搜索、状态筛选、折叠、新建、归档、回收站和选择 Goal 均保持可用。
4. Light、Dark 和窄屏下均保持清晰，无文本溢出或不可达操作。
5. 不修改后台、数据模型、状态机、权限、API 或 Runtime/TUI 契约。
