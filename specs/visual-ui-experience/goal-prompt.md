# Goal Prompt

以 `specs/visual-ui-experience/spec.md` 为本目标的总需求与验收入口，完整满足其中 45 项验收标准、20 组设计机制和采用边界，让 Molis Work 的视觉、交互、个人助理信息组织与 UI 性能达到“内部完整”。本书约定的视觉与几何以本书为准；明确引用其它 spec 的行为，以其对应需求为准：输入（按键、发送、草稿）归统一输入，附件状态与「@」「/」建议归本书，排队与转向归输入回执，Coding 流式行为归 Coding 与平台性能，标签条归插件标签组，字体方案归字体与皮肤系统。分工不缩小本目标的完整体验、性能和恢复验收范围，也不另建已有能力的第二套实现。保留现有色彩、工作台结构、业务能力、权限和事实归属。

文字耐读、层级清楚，阅读区舒展，目录和工具区紧凑；居中、留白、字重、换行、动态数字、图标、控件和边界协调。新回答自然显现且不拖慢输出，拖拽、吸附、分屏、折叠和浮层衔接准确，快速操作、反向、中断及取消后仍落到正确状态。

个人助理清楚呈现工作环境、上下文、连接与工具、产出、变更和后台任务，兼顾编程与非编程场景。用户能看懂当前范围、正在发生的事和需要自己处理的事项；草稿、本次执行与历史引用不混淆，模型、状态、权限和用量真实，来源、结果及详情可打开并返回。

阅读与输入始终由用户掌控：不抢滚动、焦点或选区，不丢草稿、附件和引用；输入法、建议、发送、停止、重试与恢复可靠。附件部分失败可见，正文与 Markdown 在流式完成和历史重开后内容一致；图片、代码、Diff 及嵌入预览保持正确内容、版本、定位和就绪状态。复制完整，失败可恢复，不重复消息、业务记录或外部副作用。

当前可复现的 UI 性能瓶颈得到解决，首次反馈、实际可操作和完成耗时有同条件前后对照证据；输入、搜索、插件切换、长会话、持续输出、多分屏与反复开关保持顺畅，不产生无谓请求或资源持续累积。新增视觉效果不造成明显退化，时间、内存与资源成本的取舍清楚。

这些结果在浏览器与 macOS 产品、所支持语言、明暗模式、标准与紧凑密度、窄分屏、缩放、字体加载与后备、键盘、触控及减少动态效果下成立。真实工作台、现存插件、生成插件和组件板保持一致，开发规范及插件创作台能持续产出符合这些规则的结果。

完成标准是 spec 全部约定范围有可操作的真实成果，逐项验收、异常恢复与性能对照有充分证据，共有组件、实际消费者、组件板及后续开发规则一致。工程通过、真实场景通过和本人验收状态分别如实记录；未完成或未验证项明确保留，不能据此宣称整个目标完成。方案、局部切片、模拟演示、静态截图或参数接近样张均不能代替完整交付。
