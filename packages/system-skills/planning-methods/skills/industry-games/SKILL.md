# 游戏

在核心玩法之外补齐内容生产、经济、社区、平台和持续运营的行业闭环。

适用于：商业游戏、在线游戏、持续运营游戏。

## 规划路径

1. 从核心循环、目标玩家和情绪体验确认可玩价值
2. 连接成长、奖励、资源、难度和长期经济
3. 建立关卡、叙事、美术、音频与配置的内容生产管线
4. 补齐社交、社区、安全、平台、商业化和客服边界
5. 用真实游玩、留存、经济健康、内容节奏和社区反馈验证

## 必须覆盖

| area | label | question |
| --- | --- | --- |

| progression_economy | 成长与经济 | 奖励、资源、难度、付费和长期目标如何保持健康？ |
| content_pipeline | 内容管线 | 玩法、关卡、叙事和资产如何持续生产、验证和发布？ |
| social_community | 社交与社区 | 合作、竞争、表达、举报和社区治理如何运作？ |
| platform_commerce | 平台与商业化 | 平台能力、存档、交易、权益和退款如何一致？ |
| live_operations | 持续运营 | 活动、版本、客服、数据和事件响应如何闭环？ |

| live-launch-after-operations | 在线或持续运营发布消费平台、经济、社区安全、客服和恢复准备。 | live launch depends_on operational readiness |

## 完成证据

- 真实玩家对核心循环和成长的行为反馈
- 内容从制作到验证和发布的完整样例
- 经济、社区、平台与事件恢复演练

## 收口检查

- 已同时组合游戏设计领域方法，不用行业运营替代玩法验证
- 商业化没有破坏核心乐趣和公平预期
- 涉及未成年人或 UGC 时已组合相应叠加层

## 常见误拆

- 核心循环未验证就批量生产内容
- 只设计数值不观察真实玩家行为
- 把上线当终点而没有持续运营和社区治理

## 怎样用这份方法

按「规划路径」把每个可独立交付、有限可验收的结果拆成一项；覆盖「必须覆盖」相关问题（缺事实列待确认）；依赖只按结果消费连边、其余并行；逐项标明「完成证据」并过「收口检查」；先给用户确认，再按要求用对应工具写入。
