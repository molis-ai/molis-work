# 项目多方法组合规划

## 完成等级

内部完整：项目可以同时纳入多套规划方法；Web、Desktop 与 Runtime 看到同一份组合，复杂 Goal 的拆分审查会完整使用这组方法，而不是只采用其中一套或依赖 Runtime 临时猜测。

## 背景与问题证据

- 方法模型和 `decomposition_review.method_pack_ids` 已允许一次拆分引用多套方法，校验器也会合并必须覆盖项。
- 但项目“工作规划”仍把“选用”表达成复制一份项目方法，没有把多套方法呈现为一个项目规划组合。
- Runtime 读取接口只返回平铺的方法库，不单独返回当前项目已经纳入的组合，也没有汇总步骤、依赖规则、证据与完成检查。
- 拆分校验只检查 Runtime 自己填入的 `method_pack_ids`；即使项目已经配置多套方法，Runtime 漏掉其中一套也不会被发现。

## 目标

1. 一个项目可以同时启用多套互补方法，例如“构建与改变 + 软件开发 + 产品与 UX”。
2. 项目组合不是把三套步骤机械串成十二个任务，而是：工作类型提供主路径，领域和自定义方法补充覆盖、依赖、证据、完成检查与失败提醒。
3. Runtime 一次读取即可获得当前项目的方法库和已经汇总好的项目组合。
4. 项目组合是复杂 Goal 拆分的必选下限，不是方法上限；Runtime 仍需检查当前任务，并补充所有确实相关的方法。
5. 不引入第二套方法定义或新的选择表：当前项目中 `scope=project && enabled=true` 的方法就是组合成员；已有项目数据直接兼容。

## 产品与交互

### 项目工作规划

- 页面第一部分为“当前规划组合”，优先回答当前项目用了哪些方法，以及合并后覆盖多少检查维度。
- 组合成员以紧凑列表呈现，显示类型、名称、作用和查看/调整入口；多套方法并列生效，不出现单选语义。
- 第二部分为“添加规划方法”，从全局可用方法中继续加入，操作名称为“加入组合”。
- 未启用的项目方法保留在页面中，用户仍可进入编辑页重新启用；不会因为停用而丢失。
- 空组合明确说明 Runtime 会检查当前任务的实际工作、专业领域、交付方式和风险，再选用所有相关方法；不预设方法类型或数量。

### Runtime 读取

`molis_work_v1_planning_methods` 在保留 `methods` 的同时新增 `composition`：

- `method_pack_ids`、`method_names`；
- 各方法各自的规划路径，避免错误串行化；
- 合并去重后的必须覆盖项、依赖规则、证据要求、完成检查和失败提醒。

无论组合是否为空，Runtime 都必须检查当前 Goal。组合成员全部必选；组合之外，任何能补充尚未覆盖的重要检查的方法也必须加入。`composition` 为空时，Runtime 直接从完整方法库选择所有适用方法，不追求数量最少。

## 实现方案

- `src/planning/method-packs.ts`：新增纯函数 `composePlanningMethodPacks`，稳定排序组合成员，保留各自步骤路径，并合并其余规则。
- `src/v1/coordinator.ts`：新增项目组合读取；Proposal 提交和确认时把组合 ID 交给拆分校验。
- `src/v1/goal-decomposition-validation.ts`：当项目组合非空时，检查 `decomposition_review.method_pack_ids` 是否覆盖全部组合成员；额外方法仍允许。
- `src/mcp/server.ts`：读取接口同时返回方法库与组合。
- `src/web/render.ts`：把工作规划页改为“当前规划组合 / 添加规划方法 / 未启用方法”的清晰路径。
- `skills/goal-advance/`：Runtime 先检查当前任务；项目组合是必选下限，并继续补充所有实际相关的方法。

## 非目标

- 不自动调用模型生成一套融合后的新方法文本。
- 不把多套方法步骤机械转换为串行 Goal。
- 不新增推荐算法、方法权重、拖拽排序、组织级方法或方法市场。
- 不修改既有 Goal；组合变化只影响后续新拆分或主动重规划。
- 不新增数据库表、checksum、锁或额外一致性协议。

## 验收标准

1. 项目能连续加入两套及以上方法，刷新后组合成员完整保留。
2. Runtime 读取结果同时包含平铺方法库和合并后的 `composition`。
3. 组合保留每套方法自己的步骤路径；覆盖、依赖、证据、检查和失败提醒合并且稳定去重。
4. 项目组合非空时，复杂 Goal 提案遗漏任一组合方法会被拒绝，并明确列出遗漏方法。
5. 组合为空时保持原有 task context 兼容逻辑。
6. 工作规划页先展示当前组合，再展示可加入方法；控件明确表达多选，不出现单选或“只能选一套”的暗示。
7. Runtime 方法选择不偏向某个方法类型、列表顺序或固定数量；遗漏仍有重要检查未覆盖的方法时，不得认为 Goal 拆解完整。
8. Web、Desktop、Light、Dark 与窄宽度可读；中英文文案完整。
9. 既有规划、Goal 生命周期、MCP、Web 和 Desktop 测试通过。
