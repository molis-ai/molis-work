## 1. 背景

终端井搬进 Shelf 包（PG-053）之后，Shelf 的代码已经不再自己渲染终端，渲染器是平台的（`terminal.ts` 的注释写明），但包里还留着两样东西：一是 `@xterm/xterm`、`@xterm/addon-fit` 的依赖声明和一个没有人 import 的类型声明文件；二是终端井里两句恢复提示是写死的中文，没有走 `messages.ts`，英文界面也显示中文。来源是 `specs/BACKLOG.md` 的 BL-638 行和 `specs/repository-anti-corruption/slices/pg053-terminal-clients.md` §3。这两处都只在 Shelf 包内，也不涉及任何 Manifest 或动作合同。

## 2. 目标

1. `plugins/native/shelf` 不再声明 `@xterm/*`：`package.json` 的 `dependencies` 与 `molis-work.extraDependencies` 里没有，`src/xterm-css.d.ts` 删除，`pnpm-lock.yaml` 里 shelf 的 importer 块里没有。工作台（`apps/workbench/package.json:63-64`）仍用 xterm，锁文件里 xterm 的包条目留着。
2. 终端井的两句恢复提示经 `page.L("shelf.tui.…")` 取，两个键在 `SHELF_MESSAGES` 里中英都有；英文界面显示英文，中文界面的两句与原来逐字相同。
3. `/assets/molis-work-plugins/shelf.js` 的字节数不比现在的 64717 大（`tooling/gates/page-assets.json:42`），变小就同一个 PR 里降下来。

## 3. 不做

- `plugins/native/shelf/src/browser/confirm.ts:8` 的 `|| "动作"`：这是文件名缺省值，不是界面提示，不动，也不另开行。
- `plugins/native/shelf/src/styles.ts:395` 的 `.xterm` 选择器：它给平台渲染器出的节点定高，不是对 xterm 包的引用，不动。
- 终端井里 `recover(error.message)`、`recover(event.message)` 传的是平台和后端给的错误文字，不在本任务里翻译。
- 其他插件的写死中文不在这里扫，发现了在 PR 正文里列一行，不顺手改。

## 5. 做法

已定的决定：

- 两个新键放进 `SHELF_MESSAGES`，不放别处。中文就是原来那两句，一字不改：「终端会话已结束，未发送的输入已恢复。」「终端连接已断开，未发送的输入已恢复。」英文参照同段里 `shelf.tui.the-terminal-is-not-connected`（`messages.ts:123`）的语气，例如 “The terminal session ended. Your unsent input was restored.” 与 “The terminal connection dropped. Your unsent input was restored.”。
- 键名照 `messages.ts:121-124` 的写法：`shelf.tui.` 加英文前几个词连字符。键越长，`shelf.js` 越可能变大（见第 8 节），可以在不失去意思的前提下取短。
- 取值放在 `installTerminal(page)` 里，用 `page.L`，写法照 `plugins/native/shelf/src/browser/tui.ts:21`（`page.L("shelf.tui.agent-sent-to-the-terminal", …)`）；不要在模块顶层调用，那里拿不到 `page`。
- 删依赖用 `package.json` 改完后 `pnpm install --lockfile-only --offline` 更新锁文件。如果它要联网，停下来问，不要手工大段改锁文件。

乙档【方案】里要回答的问题：

1. 两个键的最终名字与英文句子，各自多少字符。
2. `page.L` 是在 `installTerminal` 开头取一次，还是每次用的地方取；按字节数回答你选的那种比现在的 `shelf.js` 小还是大（先在本地构建量一次，再在方案里写数字）。
3. 测试夹具读 `SHELF_MESSAGES` 用 `import { SHELF_MESSAGES } from "@molis-ai/molis-work-plugin-shelf"`（公开出口，`plugins/native/shelf/src/index.ts:12`）还是别的办法；这个测试现在是用 esbuild 从源码路径打包 `terminal.ts`，再加一条包名 import，`node scripts/test-imports.mjs --check` 会不会报同一个包源码与构建混用，先跑一次再答。
