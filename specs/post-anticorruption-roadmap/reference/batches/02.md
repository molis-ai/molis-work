## 给人讲清楚

防腐整理留下几类收尾：零散的待办和风险散在几个地方，有的没人负责；几份共用的基础代码有重复，版本号也各自涨过、没有统一；以后升级要从哪个版本算起也还没定下来。这一批把它们收干净：每件遗留的事都有主人、只记在一个地方，共用代码各留一份，所有版本回到同一个起点，并写好「从此以后改结构要怎样升级」的规则。做完之后，后面每一批都在一个干净、统一的起点上开工。需要你做的：你已在 11-04 确认维护窗口。重建仍排在本批相关改动合入和备份恢复核验之后，旧 Home 整个搬开保留；版本号回到 0.1.0 之前，要先在 GitHub 上删掉旧的发布和标签，这一步只能你来。官网许可的说法、安全表怎样写测试名，以及怎样限制新增的截断写法，你已经定下。
