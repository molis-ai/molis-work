# T-151 终端被停掉或重启换下的旧进程，之后的输出不再进重放、不再转给面板

> **这条在 main 上成立：旧进程被 `kill` 后，只要它还活着，它的输出照样进这个面板的重放，并以这个面板的名义转发。**
> - `MolisWorkPtyHost`（`horizontal/runtime-host/src/adapters/terminal-pty.ts:350`）用两张表管终端：
>   - `sessions`（`:351`）放进程句柄；
>   - `replay`（`:352`）放重放缓冲。
> - `spawn` 给每个进程挂两个回调：
>   - `onExit`（`:393-398`）第一句是守卫 `if (this.sessions.get(request.panelId) !== proc) return;`（`:394`），只认这个面板当前的那个进程；
>   - `onData`（`:389-392`）没有这句。来一段输出就追加进 `replay` 里这个面板的那一项（`:390`），再转给 `handlers.onData`（`:391`）。
> - `kill`（`:414-419`）删掉 `sessions` 和 `replay` 里的这一项，再给进程发信号（`terminatePtyProcess`，`:325-344`）。它不关 PTY：node-pty 1.1.0 的 `IPty.kill` 只发信号（`unixTerminal.js:226-231`），关读取的是 `destroy()`（`:215-225`），宿主从不调。所以扛过信号的进程，输出还会到 `onData`：
>   - **重启后**（同一面板 `kill` 再 `spawn`）：追加进新进程的重放，转给面板；
>   - **只 `kill`、不重启**：在 `replay` 里把这个面板的那一项重新建起来（`:390`），转给面板；
>   - 这一项要等这个面板下一次起进程才被置空（`:388`）。
> - 对人看得见：宿主的回调把输出原样广播给这个面板（`apps/local-host/src/pty-socket.ts:110`、`:90-95`）。
>   - 重启后，新终端里会出现旧进程的字；
>   - 停掉以后，宿主已经替面板报过退出（`pty-socket.ts:102-107`），之后还会有这个面板的输出。

## 1. 背景

- `onData` 和 `onExit` 现在的样子（`terminal-pty.ts:388-400`）：

  ```ts
      this.replay.set(request.panelId, "");
      proc.onData((data) => {
        this.replay.set(request.panelId, clipReplay((this.replay.get(request.panelId) ?? "") + data));
        this.handlers.onData(request.panelId, data);
      });
      proc.onExit(({ exitCode, signal }) => {
        if (this.sessions.get(request.panelId) !== proc) return;
        this.sessions.delete(request.panelId);
        this.replay.delete(request.panelId);
        this.handlers.onExit(request.panelId, { exitCode: exitCode ?? -1, signal: signal ?? 0 });
      });
      this.sessions.set(request.panelId, proc);
  ```

  - `onExit` 的守卫是 `3634ad7ba` 加的，T-088 用 `RAC-1646` 钉住（`tests/runtime-host.test.ts:149-182`）：重启后旧进程晚到的退出，不删新进程的句柄和重放，也不替面板报退出。
  - `onData` 缺的就是同一句。本单照抄成 `onData` 的第一句。

- **为什么用和 `onExit` 一样的写法，不改成 `kill` 时关掉 PTY**：
  - 关 PTY（`destroy()`）会改 `kill` 的行为：先关读取，再发 SIGHUP（`unixTerminal.js:215-225`）。旧进程从此读写都断，这和现在「发信号、让进程自己收尾」不是一回事；
  - 已经在走的退出路径（`:394` 的守卫）也会跟着变；
  - 守卫只管宿主自己记账和转发，不碰进程。

- **为什么守卫在起进程的那一刻也不会误拦**：
  - 回调在 `:389` 注册，`sessions.set` 在 `:400`，中间都是同步代码；
  - node-pty 的输出要等 socket 的 `data` 事件，事件只在下一轮事件循环里来；
  - 所以第一段输出到的时候，`sessions` 里已经是这个进程。

- **时序为什么稳**（node-pty 1.1.0，在 `node_modules/.pnpm/node-pty@1.1.0/node_modules/node-pty/` 下）：
  - `lib/terminal.js:140-146`：`on('data')` 挂在 PTY 的 socket 上；`:92` 把 socket 的 `data` 转成 `onData` 的回调；
  - `lib/eventEmitter2.js:35-43`：`onData` 的回调按注册顺序调。宿主的回调在 `spawn` 里先注册（`:389`），测试后注册的回调拿到某一段时，宿主已经处理完这一段；
  - `lib/unixTerminal.js:65-89`：进程退出后，要等 socket 关掉才发 `exit`。所以输出都在 `exit` 之前到，一个自己退出的进程，最后那段输出到的时候它还在 `sessions` 里，守卫不会吞掉它；
  - `lib/unixTerminal.js:226-231`：`IPty.kill(signal)` 只发信号，进程已经不在时吞掉错误；
  - `src/unix/pty.cc:324`：PTY 默认开着 `ECHO`。往旧进程的 PTY 写一行，终端先回显这一行，`cat` 再原样输出一次，两次都从这个 PTY 的 `onData` 出来。

- 没有测试量到这一处：
  - `tests/runtime-host.test.ts:9-51` 在 `kill`（`:35`）后起了新进程，但旧进程不扛信号，没有再输出；
  - `RAC-1646`（`:149-182`）的旧进程扛住了信号，可用例只看退出，没让它再输出。

## 2. 目标

1. 同一面板 `kill` 后重新起进程，旧进程之后的输出不进新进程的重放，也不转给 `handlers.onData`；新进程的重放照旧（`RAC-1672`）。
2. 面板只 `kill`、不重启，旧进程之后的输出不在 `replay` 里把这个面板的那一项重新建起来，也不转给 `handlers.onData`（`RAC-1673`）。
3. README 的不变量写上「一个面板只认它当前的进程」。

```ts

test("RAC-1672: after a restart, output the old process still prints stays out of the new process's replay and is not sent to the panel", async () => {
  // kill() then spawn() on one panel is a restart; the guard at the top of the data handler drops what the old process prints afterwards.
  let output = "";
  const host = new MolisWorkPtyHost({
    onData(_panelId, data) { output += data; },
    onExit() { /* the restarted terminal stays open until killAll */ },
  });
  const tick = () => new Promise<void>(resolve => setTimeout(resolve, 25));
  // The old shell ignores the SIGHUP and SIGTERM that kill() sends, so it outlives the restart and still echoes what it is sent.
  host.spawn({ panelId: "restart", command: "/bin/sh", cwd: os.tmpdir(), args: ["-c", 'trap "" HUP TERM; printf "old:%s\\n" "$$"; exec cat'] });
  const old = host["sessions"].get("restart");
  let oldOutput = "";
  // Added after the host's own listener, so a chunk reaches it only after the host has handled that chunk.
  old.onData((data) => { oldOutput += data; });
  try {
    await waitUntil(() => /old:\d+\r?\n/.test(output), tick);
    host.kill("restart");
    host.spawn({ panelId: "restart", command: "/bin/sh", cwd: os.tmpdir(), args: ["-c", 'printf "new:%s\\n" "$$"; exec cat'] });
    await waitUntil(() => /new:\d+\r?\n/.test(output), tick);
    old.write("stale\n");
    await waitUntil(() => oldOutput.includes("stale"), tick);
    assert.match(host["replay"].get("restart") ?? "", /new:\d+/, "the new process keeps its own replay");
    assert.doesNotMatch(host["replay"].get("restart") ?? "", /stale/, "the old process's late output stays out of the new process's replay");
    assert.doesNotMatch(output, /stale/, "the old process's late output is not sent to the panel");
  } finally {
    host.killAll();
    old.kill("SIGKILL");
  }
});

test("RAC-1673: after a kill with no restart, output the old process still prints does not put a replay back and is not sent to the panel", async () => {
  // kill() drops the session and its replay; the guard at the top of the data handler keeps the old process from writing a replay back.
  let output = "";
  const host = new MolisWorkPtyHost({
    onData(_panelId, data) { output += data; },
    onExit() { /* the host ignores the exit of a process it has killed */ },
  });
  const tick = () => new Promise<void>(resolve => setTimeout(resolve, 25));
  // The old shell ignores the SIGHUP and SIGTERM that kill() sends, so it outlives the kill and still echoes what it is sent.
  host.spawn({ panelId: "gone", command: "/bin/sh", cwd: os.tmpdir(), args: ["-c", 'trap "" HUP TERM; printf "old:%s\\n" "$$"; exec cat'] });
  const old = host["sessions"].get("gone");
  let oldOutput = "";
  // Added after the host's own listener, so a chunk reaches it only after the host has handled that chunk.
  old.onData((data) => { oldOutput += data; });
  try {
    await waitUntil(() => /old:\d+\r?\n/.test(output), tick);
    host.kill("gone");
    assert.equal(host["replay"].has("gone"), false, "kill drops the replay");
    old.write("stale\n");
    await waitUntil(() => oldOutput.includes("stale"), tick);
    assert.equal(host["replay"].has("gone"), false, "the old process's late output does not put a replay back");
    assert.doesNotMatch(output, /stale/, "the old process's late output is not sent to the panel");
  } finally {
    host.killAll();
    old.kill("SIGKILL");
  }
});
```
