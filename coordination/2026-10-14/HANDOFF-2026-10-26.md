## 批流程（MERGE-QUEUE §1a）

1. 评过的片并进当前批头 `batch/<日期>-NN`（工作树 `.claude/worktrees/ac-batch42`）；冲突统筹一次解。
2. `node scripts/machine-slot.mjs run build --label X -- pnpm build`（后台跑）；`pnpm api:update`、`pnpm actions:update` 应无改动或随批提交。
3. 页面资源：`node scripts/gates/page-assets.mjs --base origin/main`；必需增长在 `scripts/gates/page-assets.mjs` 的 `APPROVED_CEILINGS` 写 `[merge-base 字节, 实测]`（用完的删掉），`tooling/gates/page-assets.json` 等于实测；单资源 >10 KB 或新增资源先问用户。
4. `node scripts/check-health-gates.mjs --base origin/main` 通过；改到的切片用例：`node scripts/machine-slot.mjs run browser --label X -- node scripts/run-tests.mjs --jobs 1 <文件…>`（后台跑，整机一次一个测试、一个构建）。
5. `git fetch origin main && pnpm secrets:check` 后推批头；开批 PR（正文列各片、防腐复查节）；把同一头推到 `integration/carrier-<日期>-NN` 触发全量（carrier 全量在排队或在跑时不再推它）。
6. 全量红的文件和 `known-red-main.md`、上一批红单比对；本批引入的在批头修（不重跑全量），在 PR 写归因评论。
7. Verify 绿后 `gh pr merge <n> --squash --match-head-commit <sha>` 入队。落地后：核对 main 树等于批头；删 carrier 与批工作树；下一批 `git merge -s ours origin/main`；privileges.md 对应行补「随 batch-NN（#PR，main `sha`）」；`LINES.md`、`RISKS-AND-DEFERRED.md` 记一条。
