# 推广与用户运营

最近更新：2026-10-18 · 依据 [killer 场景](killer场景.md)、[角色与使用链路](角色与使用链路.md)、[外部补研 §4–§6](research/2026-10-18-外部补研.md)。

这份文档回答：先找谁、从哪里进、第一次用什么、靠什么留下来、怎么传出去。它是运营建议，不是已执行的计划；招募、访谈、发帖、联系用户都要先经用户授权（见第 9 节）。

> **前提：** 推广之前先过[产品优化建议](产品优化建议.md#一p0-推广阻断)的 P0 阻断项：签名公证的安装包、数据升级、正式 OAuth、许可口径、后台运行条件。没有这些，第一批用户会在安装和升级时流失，口碑会反过来伤产品。

## 1. 一句话和三句"不"

**一句话：** 让工作，在人、工具与 AI 之间继续。

**解释句：** 装在你电脑上的 AI 工作台：你和你用的每一个 AI，对着同一份目标、资料和成果干活。

**三句"不"**（借 Granola"不往通话里放机器人"的打法，用否定式说清差异）：

- **不把你的工作锁在某一家 AI 里。** 目标、文档、待办在你的电脑上，今天用 Claude Code，明天用 Codex，都接得上。
- **不把"AI 说做完了"当成做完了。** 每条要求有依据，要你验收的，你说了才算。
- **不替你派单，也不替你点头。** AI 可以记录、提议；改约好的事、替你确认，得你来。

## 2. 首批人群与入口顺序

| 波次 | 人群 | 主推场景 | 为什么先找他们 | 入口 |
| --- | --- | --- | --- | --- |
| 第一波 | 同时用两家以上 AI 编码工具的独立开发者、技术负责人 | K1 + K4 | 痛点证据最强；核心能力已发布；装得上 MCP、愿意配置 | 在 Claude Code、Codex 里装一个 Skill（`goal-advance`）和 MCP 条目；Show HN |
| 第二波 | 独立顾问、行业分析、研究型作者、产品负责人 | K2 + K5 | 反复交付有依据的判断；对"出处"敏感；Feed→Pages 已在 main | 行业周报模板包；顾问与研究者社群 |
| 第二波 | 项目经理、交付协调、自由职业者、财务与人事 | K8 + K1 约定版 | 每周被会议和邮件推着走；入口最短（粘一段纪要就能开始）；K8 已在 main | 项目经理与自由职业者社群；少数派、即刻 |
| 第三波 | 一人公司、自由职业者、小服务商、运营 | K3 + S2 | 最需要"顺手的小工具"；产出最容易传播 | 样例插件库；"我用一句话做的工具"征集 |
| 之后 | 小团队 | K7 | 团队协作上线后；工作室自己先用 | 内部协作的真实案例 |

**国内**：第一波同样是双 AI 开发者（即刻、V2EX、掘金）；第二波加上自媒体与咨询（少数派、小红书）。默认用国产模型模板（DeepSeek、通义千问、Kimi、GLM、MiniMax 都已内置）。国内口碑集中在中文社区，本次调研没能系统检索，是缺口。

## 3. 增长打法

外部补研里有证据的几条，以及对 Work 的落法：

| 打法 | 谁在用 | Work 怎么落 |
| --- | --- | --- |
| **出现在别人的 AI 生态里** | Readwise 给 Claude Code、Codex 发 Skills；Notion 的 Skills API 同步到 ChatGPT、Claude；Zapier 进第三方 Agent 的连接器目录 | Work 的第一个入口不是自己的窗口，而是装进 Claude Code、Codex 的一个 Skill 和 MCP 条目；把 `goal-advance` 做成"装一个就能用"（K1、K4） |
| **一句否定式差异 + 一个高端早期人群** | Granola：不往通话里放机器人，从 VC 与创始人圈扩散 | 三句"不"（第 1 节）+ 双 AI 开发者 |
| **生态先于规模** | Obsidian 社区目录 5 个月翻倍到 8,000 多个插件，被迫改成自动审查与能力披露 | 生成插件和技能包的分享，上线前先设计审核与权限披露（建议 C4、G3） |
| **安全讲到具体** | OpenClaw 的传播伴随大量安全事件 | 讲"拒绝了什么"：密码管理器在禁区、撤权后下一次调用就被拒、外部内容里的指令不会被执行 |
| **演示视频** | Manus 的邀请码 + 演示视频带来一次爆发 | 每个 killer 一支 60 秒视频，镜头见 [killer 场景](killer场景.md)；不靠饥饿营销 |
| **可分发的产出** | 插件市场、模板库 | 插件、技能包、工作流程、带出处的报告都能导出成文件分享（建议 I2） |

## 4. 分角色上手路径

每个主推角色的"十分钟—第一周—第一个月"。模板包内容见第 5 节。

| 角色 | 十分钟内看到什么 | 第一周做成什么 | 第一个月留下来的理由 |
| --- | --- | --- | --- |
| 双 AI 开发者 | 在 Claude Code 里装上 Skill，为手头的功能建第一个目标；Agent 报一次进度 | 换一次 Agent 接着做；一次决定中心；一次"没算完"→本人验收 | 每个新功能开一个目标；菜单栏每天看等你的事；规则和 Skills 只维护一份 |
| 技术负责人 | 导入团队已有的 `CLAUDE.md` 和 Skills，写项目长期说明 | 两个人的 Agent 读同一份约定；一次多代理评审（规划） | 质量标准写一次，每个 AI 照着做 |
| 独立顾问 / 分析师 | 新建项目时拖进客户资料文件夹，拿到一分钟项目建议 | 第一份带"本期采用材料"的周报，固定成果交出去 | 第二期从上一期开始；被追问时一键回查 |
| 项目经理 / 交付 | 粘一段周会纪要，看到"你答应的""在等别人的"分开，3 条已有的被认出来 | 等待清单每天早上刷新，催到一次；一个客户的范围写成约定 | 每个项目一个目标，范围变更走约定、你点头才改 |
| 产品经理 | 用 PRD、竞品分析、用户访谈模板起草；选中一段让助理挑刺 | 一个目标的要求与验收；问卷收回来做成表、做成演示稿 | 需求、决定、验收在一处；Agent 不会悄悄改范围 |
| 内容创作者 | 灵光读一条视频字幕；选好句子放进稿子，出处跟着走 | 一篇稿子 + 一份选题库插件 | 每周的选题和素材流程固定下来 |
| 一人公司 / 自由职业者 | 说一句"做个报价前核对"，装上用一次 | 客户改单两次，界面和 AI 各处理一次 | 第二次改规则后仍在用；数据在自己电脑上 |

## 5. 模板包

一个模板包 = 插件组合 + 技能包（规划中，先用项目说明和提示词代替）+ 工作流程 + 示例项目 + 一个样例插件。按[建议 I1](产品优化建议.md) 做。

| 模板包 | 插件组合 | 做法 / 流程 | 样例插件 |
| --- | --- | --- | --- |
| 双 AI 开发 | Goals、Sessions、Coding、Files、Git、Diff、Feed（GitHub 通知） | 规划方法"软件开发"；流程：GitHub issue → 判断是不是 bug → Inbox → 新建目标 | 发版清单 |
| 行业周报 | Feed、Inbox、Pages、PPT、Cognia、成果、待办 | 流程：每周读报告写成一页；Pages 周报模板 | 来源核对台 |
| 产品经理 | Goals、Pages、Forms、Dataset、PPT、炼金术士、待办 | Pages 的 PRD / 用户访谈 / 竞品分析模板；规划方法"产品 UX""增长" | 需求优先级打分 |
| 内容创作 | Feed（YouTube、RSS）、灵光、Shelf、Pages、图片、Jelly | 流程：视频 → 灵光转写 → 选句 → 稿子 | 选题库 |
| 独立执业 | Pages、待办、Jelly、Dataset、Forms、Shelf | Shelf 本机提取文字（脱敏配方要配本机模型才不出机器）；待办的"在等别人" | 报价前核对器、发票台账 |
| 学生与研究 | Cognia、Pages、Shelf、灵光、Jelly、待办 | Cognia 导入 Obsidian；"提反例与反驳" | 文献阅读卡 |

## 6. 内容与渠道

| 内容 | 形式 | 渠道 | 对应 |
| --- | --- | --- | --- |
| "Agent 说做完了，Work 说还差你" | 60 秒视频 + 长文（多 Agent 时代谁来验收） | Show HN、Claude Code / Codex 社区、即刻、V2EX | K1 |
| 把 `CLAUDE.md` 写一次，所有 AI 都照着做 | 短教程 | 开发者社区、掘金 | K4 |
| 一年后还答得上"这个结论从哪来" | 案例长文（示意）+ 模板包下载 | 咨询、投研、研究者社群；少数派 | K2 |
| 新项目第一天 | 30 秒录屏 | 首次使用引导、官网首屏 | K5 |
| 开完会，你答应的和别人欠你的分开记 | 60 秒视频 + 一份"等待清单"模板 | 少数派、即刻、项目经理与自由职业者社群 | K8 |
| 我用一句话做的工具 | 用户征集 + 样例插件 | 社区、小红书 | K3 |
| 我们怎么用 Work 开发 Work | 连载：工作室自己的目标、验收、协作 | 博客、即刻 | K1、K7 |
| 本机 AI，但它碰不到你的钥匙串 | 安全说明页：逐条写拒绝了什么 | 官网、开发者社区 | S3 |

## 7. 指标

**北极星（建议）：每周被两个以上入口读写过的工作对象数。** 入口指人、内置助理、外部 AI、工作流程。它直接量 Work 的定位："你和你用的每个 AI 对着同一份东西干活"。只有一个人在 Work 里写东西、或者 AI 只是读，都不算。备选：每周收尾生效、且有依据的交付数（偏 K1、K2）。

**每个 killer 的激活与留存：**

| 场景 | 激活 | 留存信号 | 流失信号 |
| --- | --- | --- | --- |
| K1 | 一个目标被两家 Agent 写过进度，并完成一次本人验收 | 第二个、第三个功能也开目标 | 只建了目标，Agent 从不回写 |
| K2 | 第一份带快照的交付，被回查过一次 | 第二期从上一期开始 | 交付后再没打开过 |
| K3 | 一个生成插件被 AI 调用过一次 | 改过一次规则后仍在用 | 装完没用第二次 |
| K4 | 导入一组规则或 Skills，并在两个入口生效 | 项目说明被改过版本 | 导入后从未被用到 |
| K5 | 从装好到第一个带内容的项目 | 第一周回来处理那几条待办 | 项目建议没被采用 |
| K8 | 第一次整理采用三条以上，至少一条进"等待他人" | 第二周还有"等待他人"被标完成 | 整理后不再打开等待清单，或重复识别被大量否掉 |
| K6 | 连续三天打开简报并点过一个选项 | 两周后仍每天打开 | 一周后不再打开，或被标为噪音 |

## 8. 用户运营节奏

1. **内测招募**：用 Work 自己的 Forms 做招募问卷，导出填写页发出去；按角色和"现在用几家 AI"分组。招募对象先是第一波人群。
2. **对照访谈**：每个主推场景按 [killer 场景](killer场景.md)第 3 节的"怎么验证"跑一轮；记录他们停掉了哪份旧记录或哪段旧操作，这是迁移的唯一硬信号。
3. **反馈回收**：内测用户的反馈进 Feed / Inbox，按 killer 场景归类，每周一次在本目录更新打分和建议。
4. **自己先用**：工作室团队接下来就用 Work 协作，把真实过程写成连载（征得团队同意后）。
5. **社区**：插件、技能包、流程的分享先在内测群里跑，审核与权限披露设计好之后再公开。

## 9. 待授权的事

以下需要用户明确授权后才做，本次只准备了方案：

- 发帖、投稿、录制和发布演示视频。
- 招募内测用户、发问卷、做访谈、联系任何外部人士。
- 登录、试用或购买竞品做对照实操。
- 改官网（Club 仓库）文案与下载页。
