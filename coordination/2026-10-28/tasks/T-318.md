## 1. 背景

来源：统筹 2026-10-30 的风险登记（`coordination/2026-10-14/RISKS-AND-DEFERRED.md` R-62，ac-review 评 `20940b4b1`，#1310 评论 6406643839）。已对 `origin/main`（`07b73f9f8`）核过。`apps/local-host/src/plugin-project-rows.ts` 的 `removeNamedFiles`（约 :69-90）：先 `paths.inspect("<目录>/<名>", "file")`（`plugin-owner-files-paths.ts` 约 :72，逐级 `lstat` 祖先目录、拒绝链接和硬链接），通过后在约 :88 `if (target.stat?.isFile()) rmSync(target.path, { force: true })`。检查和 `rmSync` 之间有空档：父目录若在这中间被换成指向声明目录之外的链接，`rmSync` 跟着链接删到目录外面（这是原来就有的）。风险低：只有内置插件能声明 `project_rows`，且要有人在删除那一刻改动插件文件目录。同一种空档在 `plugin-owner-files.ts` 约 :108 的 `unlinkSync(node.path)` 也有，那是文件服务的删除，不在本单。行号以 `origin/main` 为准，开工先核。

## 2. 目标

先在 #1332 贴【方案】（乙档，写到函数级）：打算怎么关上空档、测试怎么在不起竞态的情况下钉住、先红预期。两条路任选并写明理由：(甲) 删之前再对同一相对路径调一次 `paths.inspect(...)`，并核对 `realpathSync(dirname(target.path))` 等于 `join(realpathSync(home), store_name, directory)`，不等就当不安全；(乙) 先 `withOwnerFile(directoryPath, O_RDONLY, "directory", fd => …)` 打开声明目录（`O_NOFOLLOW`），在持有句柄期间核对并删除（Node 没有 `unlinkat`，如果 `/dev/fd` 一类的做法在 macOS 与 Linux 上不能都成立就不用）。两条都只是缩小窗口还是能彻底关上，在方案里如实写，不夸大。
1. 按方案改 `removeNamedFiles`。被拒绝的名字照旧「不是插件的，留着」（跳过，不抛），不要让删除失败回滚整个项目删除；文件已不在不算错。
2. 用例 RAC-2435：在 `tests/project-rows-deletion.test.ts`（已有 `symlinkSync` 的夹具，约 :316 的 `linked.png`）里，让 `removeNamedFiles` 走到“检查通过、父目录随后变成链接”的状态——需要一个确定的接缝：例如把“检查之后、删除之前”抽成一个可传入的步骤，或让再核对的那一步成为单独导出的函数，在测试里直接调它；**不要**靠睡眠或线程抢时间。断言：声明目录之外的同名文件还在、被拒绝的名字没有触发错误、其余合法名字照常删除。
3. 用例 RAC-2436：正常路径（普通文件、目录里没有链接）仍被删除，已不存在的文件不报错；证明再核对没有误伤。
4. 变异：把再核对去掉，RAC-2435 必须红；贴红的输出。
