## 1. 背景

依据都在 main `4d0f52c91`：

- `releaseJson`（`connector-native-release.ts:15-19`）：先 `nativeReleaseBytes` 取字节（上限 4 MiB，只许 `hosts` 里的官方域名，`:5-6`），再 `JSON.parse(…toString("utf8"))`，再 `object(value)` 判断，不是对象回 `toolInstallErrors.failed("官方发布元数据格式无效")`。`JSON.parse` 抛的 `SyntaxError` 没人接。
- 调用方两处，都在这个文件里：`githubRelease`（`:20-28`，给 `githubCliDistribution`，`:29-38`）和 `gitlabCliDistribution`（`:40-56`，`:43` 调 `releaseJson`）。这个文件里没有别的 `JSON.parse`。
- 谁会走到：`cliSetupPlan`（`apps/local-host/src/connector-cli-setup.ts:17`，`:23` 是 `distribution.resolve(...)` 唯一的调用处）← `connectors.cli.prepare@1` 的处理器（`apps/local-host/src/connector-cli-actions.ts:27`，动作声明 `scheduling: "concurrent"`）。用到这两个分发的服务：`github`（`connector-cli.ts:23`）、`gitlab`（`:24`）、`stripe`（`:36`）、飞书与 Lark（`:28-29`）、Outlook 与 OneDrive（`:27`），以及 PowerShell（`connector-powershell.ts:13`）。
- 影响范围只有这一次 `prepare` 调用：`prepare` 在 `cliSetupPlan` 成功之后才写授权请求（`connector-cli-actions.ts:27-29`），所以抛出时没有写任何记录；不影响启动，也不影响别的列表或读取。人看到的是一句英文的 JSON 解析原话，不知道是网络（比如酒店 Wi-Fi 的登录页）的问题。
- 没有测试量到这一种：`tests/security-invariants-native-cli.test.ts:70-89`（S-36 ASC-07 ASC-14）只用 `[null]` 这样的「合法 JSON、形状错」的资产条目，断言是 `/元数据/`，走不到 `JSON.parse` 抛错这一支。`git grep -n "不是 JSON\|SyntaxError" -- tests/security-invariants-native-cli.test.ts` 没有命中。
- 错误规矩：坏数据要报清楚的声明码，不悄悄吞掉、不兜底（AGENTS「合同读写都只认现行取值」；T-050 同样的读法）。这里的「坏数据」是网络回来的内容，不是存量数据：不换成空对象、不重试、不回退到别的来源。
- 相邻的同类问题我看过，不在本单：`connector-tool-install.ts:33`、`:85`、`:96` 的裸 `JSON.parse` 是本地安装记录，归 T-049 / MISC 第 13 行；`connector-cli.ts:62` 的 `parse` 有 `catch { return clean(raw) }`，读的是 CLI 的输出，不是发布元数据。

## 2. 目标

1. 官方发布元数据取回来、但不是合法 JSON 时（HTML、空体、截断），`connectors.cli.prepare@1` 以 `connector.install.failed` 拒绝，文案 `官方发布元数据读不出来，请检查网络后重试`；GitHub 一支（`RAC-1515`）、GitLab 一支（`RAC-1516`）。
2. 拒绝之后什么都没留下：只读了一次发布源，没有 `runtime/connectors/installs` 目录，连接表仍空。
3. 护栏（`RAC-1517`）：合法 JSON 但不是对象仍回原来的 `官方发布元数据格式无效`；发布源回非 2xx（如 503）仍回原来的 `运行时下载失败，请检查官方发布源与网络`，不被改标成新文案。

## 5. 做法

统筹已定的决定，照做，不另选（【方案】里不用再问这几条）：

1. **只在 `releaseJson` 里接，`try` 只包 `JSON.parse` 一句。** 写成：

   ```ts
   const text = (await nativeReleaseBytes(url, 4 * 1024 * 1024, signal)).toString("utf8");
   let value: unknown;
   try { value = JSON.parse(text); } catch { throw toolInstallErrors.failed("官方发布元数据读不出来，请检查网络后重试"); }
   if (!object(value)) throw toolInstallErrors.failed("官方发布元数据格式无效");
   return value;
   ```

   `catch` 里有 `throw`，不算空 `catch`；不要写 `catch (error) { throw error }`、不要 `return {}`。
2. **码用 `connector.install.failed`（`toolInstallErrors.failed`，kind 为 unavailable）**：和本文件其余的元数据错误同码，也是用户重试能好的那一类。不用 `invalid`（那是调用方的输入错）。
3. **测试造法**（照 `tests/security-invariants-native-cli.test.ts:70-89` 的写法，三个用例共用一个文件内的小函数，不写进 `tests/fixtures`）：
   - `const home = await openTestHome(t), actions = home.host.homeActionClient();` `const fetch = globalThis.fetch; t.after(() => { globalThis.fetch = fetch; });`，替换 `globalThis.fetch`，按请求地址 `assert.equal(String(input), …)`，数读取次数；每次调用返回新的 `Response`（一个 `Response` 的体只能读一次）。
   - `RAC-1515`：服务 `github`、版本 `1.2.3`（`{ service_id: "github", display_name: "GitHub managed", version: "1.2.3" }`），地址 `https://api.github.com/repos/cli/cli/releases/tags/v1.2.3`。三种体各试一次（每次状态 200）：`<!DOCTYPE html><html><body>Sign in</body></html>`、空字符串、`{"tag_name":"v1.2.3","assets":[`。每次 `await assert.rejects(actions.invoke(caller, connectorCliActions.prepare, input), { code: "connector.install.failed", kind: "unavailable", message: "官方发布元数据读不出来，请检查网络后重试" })`，整句文案都要比（不能只比码，M2 靠它）。经动作客户端抛出的错误若不带 `kind`，只比 `code` 与 `message`，在【方案】里说明。
   - 每次之后：读取次数只增 1；`existsSync(join(home.home, "runtime/connectors/installs"))` 为 `false`；`withConnectorConnections(home.home, store => store.list())` 深等于 `[]`。
   - `RAC-1516`：服务 `gitlab`、版本 `1.2.3`，地址 `https://gitlab.com/api/v4/projects/gitlab-org%2Fcli/releases/v1.2.3`，同样三种体、同样断言；另断言没有请求过 `checksums.txt`（读取次数不增、地址只有上面这一个）。
   - `RAC-1517`：（i）状态 200，体分别是 `[]`、`null`、`"text"`、`42`（合法 JSON，不是对象），GitHub 一支，断言 `{ code: "connector.install.failed", kind: "unavailable", message: "官方发布元数据格式无效" }`；（ii）状态 503（`new Response(null, { status: 503 })`），断言 `{ code: "connector.install.failed", kind: "unavailable", message: "运行时下载失败，请检查官方发布源与网络" }`。
4. **构建**：测试 `import` 的是 `@molis-ai/molis-work-app-local-host`，加载的是 `apps/local-host/dist/index.js`，所以**每改一次源码（含弄红和还原）都要重建 `dist`**，不重建测的是旧代码。第一次在新工作树里：`pnpm install --frozen-lockfile --offline`，再整体 `pnpm build`；之后改一次源码只重建这一个包：`pnpm --filter @molis-ai/molis-work-app-local-host run build`（设备 A 上包成 `node scripts/machine-slot.mjs run build --label "<谁> T-056" -- pnpm --filter @molis-ai/molis-work-app-local-host run build`；darwin 上这一步还会编译 Swift 的本地小程序，比较慢，弄红前先攒好要试的几项）。
5. 代码里不要出现 `legacy`、`compat`、`backfill`，不加空 `catch`、`as unknown as`、`any`、`console`（按文件计数只许减少）。

步骤：

4. 改 `connector-native-release.ts`，重建 `dist`，三条全绿，同文件原有四个用例仍绿。
5. 弄红四次，每次改前先 `cp` 一份源文件（还原用 `cp`，不用 `git checkout`，会丢本单的改动），每次改完、每次还原之后都重建 `dist`，PR 里贴出各自红在哪一句：
   - **M1** 还原成裸 `JSON.parse`（不接）：`RAC-1515`、`RAC-1516` 红（错误没有 `connector.install.failed` 这个码），`RAC-1517` 仍绿。
   - **M2** `catch { return {}; }`（悄悄吞掉）：`RAC-1515`、`RAC-1516` 红，红在文案：码和 kind 仍是 `connector.install.failed`、`unavailable`，但文案变成 `GitHub 官方发布元数据格式无效` / `GitLab 官方发布元数据格式无效`。这是最像真的错修法：只比码的断言会放过它。
   - **M3** `catch` 里改抛 `toolInstallErrors.invalid(…)`：`RAC-1515`、`RAC-1516` 红在码和 kind。
   - **M4** `try` 扩到包住 `nativeReleaseBytes`（把 503 也改标成新文案）：`RAC-1515`、`RAC-1516` 仍绿；`RAC-1517`（ii）红在文案。
6. PR 正文写：对调用方的影响（官方发布元数据不是 JSON 时，`connectors.cli.prepare@1` 以前得到 500 的 `actions.execution_failed` 和 JSON 解析的英文原话，现在得到 `connector.install.failed`（503 类）和一句中文提示；其余拒绝的码与文案不变；没有放宽任何拒绝；没有改动作 schema，`pnpm actions:update` 无 diff）；`runtimeReleaseBytes` 的 `fetch failed` / `TimeoutError` 没有动，已报给统筹；没有用真实界面或真实网络点过，不要写成测过。
