## 比较条件与验收

- **BFP-01** 使用固定构建、Node 24.15、独立 Chrome、1440×950，真实 Host 和隔离 Home。Feed 用固定 20 条来源消息，Inbox 至少 20 个可处理事项与固定已绑定规则。Todo 由页面实际创建。规则返回固定业务结果，说明样本不含外部模型延迟。记录 SHA、依赖版本、项目规模、冷暖状态和运行环境。各场景至少五个串行独立样本，同一快照或等价种子可重建。冷首开与重复打开分列，未覆盖真实用户规模时留缺口。
- **BFP-02** 点击、首次可见反馈、可操作与完成各有独立时间点。用页面元素与实际请求记录对照，按 HTTP 分开记响应和页面更新；记录 Node CPU/内存统计的实际范围、浏览器堆的采样点、期间的请求数、响应体量与错误。报告原样本、p50 和波动。空闲样本分列，旧记录里的并发刷新只在同条件真实复现时作为另一组。所有探针在隔离夹具，源码和持久化合同只读。
- **BFP-03** 先锁定基线再决定是否已有现行修复、需要补哪一段。候选沿相同起止点、数据和样本数复测。保留点击、授权、原事项、建议与重试结果。将工作移到更早时仍计入用户实际等待和请求，报告总耗时与新增代价。工程、隔离实操与本人验收分别记。
