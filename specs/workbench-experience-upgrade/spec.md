# Molis Work 用户体验评估与升级方案

状态：概念方案已整理，待评审（2026-11-13）。需求维护由 Codex 负责。第一轮「全局设计语言」（设计原则、色彩搭配、布局分区、动效语法、组件板分章，以及首页与列表的低风险收拢）在分支 `feat/workbench-comfort` 实现并自测，未合入，等用户在组件板上定样；其余实施待分配。

从项目选择页进工作台后，用户要能认出当前项目或事项、读到此刻最重要的事实、直接继续手头的工作。2026-11-12 的走查看到，项目选择页的简报已经把进度和下一步排在一起，项目首页却把首屏让给页面说明、空状态和最近更新。建议先把首页、Goals 列表和详情连成一条「定位 → 看清事实 → 做下一步」的路径，再用组件板验证能否复用到其他插件。

完整评估、标注截图、界面样稿和两段交互动效收在[体验升级方案原稿](index.html)。将本目录取到本地后，在浏览器打开 `index.html`，可点选「淡入／标题走过去」比较列表到详情的转场，也可点击「让它办完一步」看节点进入待验收状态。

## 走查看到的问题

走查基于 `main` 的 `1a3a3ae1f`，使用隔离的示例 Home。选择页、首页、插件切换器、Goals 列表与详情、待办、助理、设置、侧边资料和组件板有实看记录。Inbox 和 Feed 在示例宿主里未加载，只按规范评估。Coding、插件创作台和完整新手旅程留待实测。原稿中的数量、色值和对比度对应当时的界面样本。

| 表面 | 观察 | 对使用路径的影响 |
| --- | --- | --- |
| 项目首页 | 「等你 0」占首段，暂停和已完成的目标排在前面，目标行重复「打开」 | 用户要先扫过空状态和旧工作，再判断手头有什么可做 |
| 工作台外壳 | 项目名收在头像后，插件、侧边视图和项目入口分布在窗口四角，插件切换器混用用途和归属分组 | 用户靠记忆找入口，跨视图切换时缺少稳定的位置线索 |
| Goals 列表与详情 | 列表用多处胶囊和状态环重复表达常态，列缺表头。详情展示「可记录，尚不可完成」，处理问题的入口缺少主次 | 要本人决定的条目不易扫到，读完详情还要自己找下一步 |
| 助理与引导 | 助理面板覆盖工作面，开口前先看到「谁来做」「放在哪」和输入语法。待办的单句入口与设置的空态更直接 | 缺少结合当前 Goal 或事项的起手动作，新用户要从空白开始 |
| 视觉、动效与组件板 | 浅色工作面与目录对比弱，辅助灰阶接近，中文沿用负字距。已有按压与进出场动效，列表与详情之间缺少对象连续性。组件板条目平铺 | 层次难以快速辨认，转场需要重新定位，作者也要逐项找合适的组件 |

## 建议方案

稳定的项目、事项和对象名提供位置线索。按任务相关性把需要人决定、验收或回答的内容放在前面，用表头、整行对齐和动作动词减轻回忆负担。可推断的默认值先显示出来，让人一步改动。新手先从版面和可操作的示例学会一件事，再按需要遇到贴近控件的提示。

### 外壳与首页

- 顶部常驻「项目 / 事项」作为位置提示。宽屏给常用侧边视图加名称，空间不足时优先保留当前视图的名称。沿用已定的事项线，事项切换在线头。起始页先给最近使用和固定入口，再按「想做什么」找插件，并提供搜索与插件用途。既有决定见[事项线](../work-line/spec.md)和[主线](../work-mainline/spec.md)。
- 首页建议用事项名作标题，未选事项时显示项目名。正文依次是「该你了」「接着做」「接下来」「各处动态」。没有等用户处理的事时收成一句提示，把首屏空间留给正在做的事。动态每个插件一行，具体条目提供「验收」「接着写」「看进展」等操作。
- 首页与事项线共用事实和操作，继续使用公开来源、智能呈现和组合服务。Goal 状态、任务进展、插件对象和实际权限继续从各自的主人读取。依据见[工作简报](../work-brief/spec.md)、[智能呈现](../intelligent-surfaces/spec.md)和[组合服务](../surface-composition/spec.md)。

### 列表、详情与引导

- Goals 列表让标题回到普通行，给列加表头、数字对齐和行悬停。常态用灰字，等你决定、受阻和进行中用可区分的标签。带计数的筛选直接到达例外项。详情旁的窄目录只留名称与状态点，当前项有明确选中态。
- 详情先用一句话说清还差什么或在等谁，再给一个符合实际状态和权限的主操作。用词稿提出「还差 1 项」「去决定」「处理这个问题」「收尾」，沿用 Goals 已有的事实，定稿时对照[用词与按需帮助](../visual-ui-experience/spec.md)及[术语表](../../docs/system/GLOSSARY.md)。
- 引导依次由版面、可一键清除的示例空态、首次出现的一行提示和自动勾选的起步清单承担。助理根据当前对象给可直接使用的起手句，清楚显示作用范围和去向，用户可直接改。示例与真实数据应可辨认，清单进度取真实完成记录。引导落点见[首次使用覆盖](../onboarding-coverage/spec.md)。

### 视觉、动效与组件板

- 样稿拉开桌面、工作面和辅助面的明度差，合并两档接近的辅助灰色，把文字收为三档。主按钮与正文拉开色差，中文取消负字距。用暖色标出「该你了」是待评审的提案，同时要考虑现有琥珀状态的去向，以及两套皮肤、浅深色与可访问性。
- 转场拟补四类语义。列表标题和节点可以跟随对象移动，前进和返回有方向，等待本人时提醒一次，进行中的节点更新真实步骤。先验证桌面 WebKit、分屏和插件 iframe 中的 View Transitions，再决定实现手段。减少动态效果时保留状态和操作反馈。
- 组件板拟按基础、控件、模式、平台区域、页面样张组织。标本展示适用场景、禁用场景、完整状态、变量与可复制用法，并支持统一切换主题、语言、皮肤、密度、宽度和减少动效。优先定样「今天」首页、列表与详情、空态与首次提示、等待验收节点。

### 文档

本次提交同步已有界面文档的配色叫法。`--action` 称墨蓝，`--accent` 称雾蓝，桌面称雾蓝桌面。方案进一步提议让 `DESIGN.md` 管设计语言、组件板管组件与模式、工程文档管浏览器实现，界面用词有固定归属。评审同时讨论从设计基线生成共享取值、旧词检查、英文文档覆盖和 Skill 如何引用组件板。

## 第一轮：全局设计语言（2026-11-13，分支 `feat/workbench-comfort`）

用户 2026-11-13 定方向：不围着 Goals 做（Goals 之后降为普通插件），先把全局的设计语言、组件板、动效与界面的搭配、色彩搭配定下来，并和之后的全局布局调整（事项线、主线）接得上。这一轮只做平台共用的部分，按「界面先定样」放在组件板上，由用户看实件定。

| 做了什么 | 在哪里 | 对应 |
| --- | --- | --- |
| 设计原则：每一屏按顺序回答「我在哪、现在怎样、下一步」，五条搭配规则 | 组件板 `#language`；`DESIGN.md` Overview | UXUP-01、UXUP-05 |
| 色彩搭配：每种颜色一个意思（墨蓝是你做的，雾蓝是你在哪，琥珀是轮到你，青是等别人，红是走不通，绿是落定，灰是歇着）；角色放在同一张工作面上的标本；当前主题和皮肤下字在面上的实测对比度 | 组件板 `#pairing`；`DESIGN.md` Colors → Pairing | UXUP-02、UXUP-05 |
| 插件身份色只取冷色（blue、indigo、purple、slate、steel），暖色、红、绿、青、灰留给状态。此前按 id 在全部色相里取，Feed 会取到红色，和「走不通」撞色 | `packages/plugin-sdk/src/ui/presentation-form.ts` 的 `presentationOwnerHue` | UXUP-02 |
| 布局分区：标题栏、工作面、右侧、底栏、浮层各回答哪个问题，用哪一层面、哪一种动效；事项线落地时沿用底栏那一行 | 组件板 `#zones`；`DESIGN.md` Layout → Zones | UXUP-01 |

## 后续验收

- **UXUP-01 位置与下一步。** 请首次使用者看首页、Goals 列表和详情各三秒，回答当前在哪、事实怎样、下一步能点什么。用有待验收、无待处理和有阻塞的样例覆盖三种路径。
- **UXUP-02 信息层次。** 1440×900 首页首屏有可操作事项时，至少露出一项操作。列表有列名，键盘和触摸能打开行与主操作，例外状态有文字或图标提示。覆盖 1440、1024、390 宽度及浅深色，记录原稿建议的带色标签占比和无名称图标数。
- **UXUP-03 交互连续性。** 从列表进出详情、事项线节点展开与恢复，能看出前后是同一对象。减少动态效果时即时更新状态并保持键盘可操作。用组件板实件与桌面壳验证。
- **UXUP-04 首次使用。** 新用户可以从示例空态或助理起手句完成第一件事。清除示例后无残留，清单按真实操作更新，已完成的提示在重启后仍保持完成。
- **UXUP-05 组件与文档。** 共享组件的常态、选中、等待、失败和窄屏标本可从组件板找到，插件作者能循标本定位用法，现行配色词与设计系统一致。
