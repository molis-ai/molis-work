# 桌面里的插件界面要能打开

状态：待验收。桌面窗口里 Pages 停在「无法加载界面，请重试」；同一页在 Chrome 里能打开。页面策略已写上本次请求自己的回环 origin。隔离的 WebKit 视图加载「数小智」并点开 Pages 后，界面状态是 ready，没有「无法加载界面」。桌面那扇窗口停在首页，点进去即可。

## 原因

插件界面画在沙箱 iframe 里（srcdoc，没有 allow-same-origin）。这个框会继承父页面的内容安全策略。父页面只写了 `'self'`。WebKit 在这个不透明源里不把 `'self'` 当成 `http://127.0.0.1:<端口>`，框里的脚本和样式被拒绝，父页面大约 10 秒后收起框并显示重试。Chrome 把继承来的 `'self'` 当成父页面的源，所以同一页能开。

## 做法

请求入口在带 `script-src 'self'` 的页面策略上，写上这次请求自己的回环 origin（脚本、样式、图片、字体）。父页面能加载的地址没有变宽。不给 iframe 加 `allow-same-origin`。

## 验收

- FRAME-WEBKIT-01：页面回答的内容安全策略里，`script-src`、`style-src`、`font-src` 带有这次请求自己的 `http://127.0.0.1:<端口>`。测试名或注释写出该编号。
- 桌面窗口打开项目「数小智」的 Pages，能看到文档界面，不再停在「无法加载界面，请重试」。
