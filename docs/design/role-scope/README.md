在仓库根目录运行，然后打开 <http://127.0.0.1:4431/role-scope/>：

```sh
pnpm build
node docs/design/_catalog/export.mjs
python3 -m http.server 4431 --bind 127.0.0.1 --directory docs/design
```

## 三个方案只差在一件事

项目里的角色和你自己的原件是什么关系：

| 方案 | 怎样 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 一份角色，各处选用 | 角色只有你自己的一份。项目只定「默认用哪个」，不改内容；想在某个项目里不一样，就另存一个新角色 | 最简单，没有「跟随」「覆盖」的概念 | 改一次原件，用它的所有项目的新任务都跟着变；按项目微调会攒出一堆相似的角色 |
| B 复制进项目，各自演进 | 角色加进项目时复制一份，成了项目成员，之后在项目里怎么改都只改这一份。原件更新了，提示「原件有新版本」，看过差异再决定采不采用 | 项目之间互不影响 | 原件改好了要逐个项目去采用；不采用就一直停在旧内容 |
| **C 默认跟随，改了才覆盖（推荐）** | 项目里的角色默认跟随你的原件。在项目里改了「做事方式」或「能用什么」中的一节，那一节就成了本项目自己的，标「本项目改过」，可以恢复跟随；没改的那一节照旧跟随 | 和记忆、运行时设置一样是「沿用上一层，改了就覆盖，可以恢复」；原件改好了，没改过的项目自动受益 | 要写清哪一节跟随、哪一节是本项目的；原件也改了覆盖过的那一节时要提示 |

三个方案共用的部分：

- **取值从近到远**：任务里另选 → 本项目 → 你的默认 → 助理自己。选择器里每一项标出它是「项目默认」还是「我的默认」，项目设置里用「来源」一行把这几层排出来。
- **任务里换一个只管这一次**；选了别的，下面出现「设为本项目默认」「设为我的默认」，点了才扩大范围。
- **保存并使用**：每次保存都固定成一个版本；进行中的任务继续用它开始时的版本，新任务用新的。弹窗里写清这次保存影响哪些地方。
- **选角色不授权**：「能用什么」只能在任务允许的范围里再收窄。
- **个人工作也能用角色**（今天会被拒），取「你的默认」。

## 画面和状态

| 画面 | 状态 |
| --- | --- |
| 任务里选角色（助理输入框旁的选择） | 来自项目默认、这次换一个、个人工作、要的工具这里没开放、项目默认的角色已停用、进行中任务的版本不能用了 |

| 改角色并保存使用 | 改了做事方式（点「保存并使用」看弹窗）、已保存（可撤销）、别处刚改过、版本与恢复 |
| 全局设置 › 角色（请 D 轨共审） | 有几个角色、还没有角色、停用一个在用的角色 |
