## 3. 连接、权限与能力的统一规则

### 3.1 一份连接，多个入口

连接保存稳定身份、服务、账号/租户、接入方式、授权使用范围及来源入口。来源入口用于解释来历，不作为能力隔离的理由。设置页、Coding、个人助理和其他消费方引用同一连接，不各维护一份可独立变化的凭据或能力清单。

连接的可用生命周期不依附添加它的页面或会话。关闭 Coding 页面、结束原会话或停用仅作为添加入口的插件后，其他已授权消费方仍能使用同一连接；必要时由连接的运行 owner 按需重连，保留原启动目录、参数和凭据引用，无须重开 Coding。关闭页面不等于停用连接。用户明确停用/移除连接、撤销项目权限，或停用真正提供该业务能力的 Integration 时，仍按实际边界拒绝使用，不能借统一管理绕过。用户启动的外部进程退出则报告真实断开，不承诺保持其运行。

查重依据包括规范化服务地址或本地包与启动配置、账号/租户、接入方式、项目范围。不能只按显示名合并；同一服务的个人账号与工作账号、同一服务器的不同租户应可并存。连接尚未验证身份时只能判断“可能重复”，不能猜测或覆盖。

在多个候选中，优先使用本任务已明确选择且仍有效的连接，其次是用户对当前范围的有效默认选择。没有明确选择且会影响数据归属时，询问一次并保留选择；不得静默切换账号、租户或服务商。重连身份发生变化时，需要重新确认相关任务目标。

### 3.2 授权按实际范围复用

可调用能力是以下条件的交集：服务端当前提供的能力、产品已实现的适配、服务账号权限、Molis Work 授予当前调用者的权限、项目/对象范围、助理开关及本次操作规则。模型声明“用户已授权”不能改变任何一项。

已有有效授权覆盖的操作自动继续，不因添加入口不同再次登录或重复确认。原先明确限制为某项目、某账号、某调用方或某类操作的授权仍然有效；要扩大范围，只请求新增部分，并说明为什么原任务需要它。

用户权限选项按 [主动助理 §7.1](../proactive-assistant/spec.md#71-行动范围与授权)的同一合同（2026-10-27 已定）：只读协助、修改前确认、授权内自动执行。连续工作推荐自动执行，AI 根据任务提出账号/目标/允许操作的范围，由用户采用或调整；默认只覆盖本次工作，长期委托可明确保存持续授权。连接页、对话与任务入口共用同一有效选择和授予，显示作用范围并提供查看、收窄、撤销及切回确认的入口，不要求逐个配置工具，也不覆盖已有更严格的选择。

登录成功和服务商账号 scope 不等于允许所有业务操作。用户明确包含在自动执行授权中的修改、发送、发布、删除等操作可连续完成，不因属于外部服务而逐次再问；未包含的目标/效果、新账号或权限差额仍明确处理。跨轮、等待、关页面和重启只恢复仍有效的原工作许可，不延长已到期授权或将其用于新任务；撤权、收窄、切模式及换账号后，旧发现结果和待执行请求不能放行后续不再获准的操作。

旧代码未声明 Agent audience、连接记录挂在 Coding owner 下、旧界面没有助理开关，都不是“用户禁止助理”的证据。先依据用户的真实授予、限制和现行助理授权策略判断；已有策略允许的直接复用，仅对实际缺少的授权请求差额。助理保持自己的调用身份与审查规则，不复制 Coding 或外部 Agent 的调用者身份。只有缺少影响正确性的授权事实时才询问，不能因为来源入口不同一律再授权。

个人助理可管理本人有管理权的连接元数据，但管理可见性不赋予业务数据访问权。Home 对话发现项目专用连接时，可以解释其所属项目；只有在任务绑定到那个项目且获得所需权限后才读取数据。界面切换项目不悄悄改变已开始任务的执行范围。

### 3.3 实际能力发现

MCP 在连接可用后自动发现服务实际公开的工具及支持的资源能力。Connector 从已安装 Integration 的业务动作声明和当前授权派生能力；没有动态枚举接口时，如实显示这个边界，不用模型猜测 API。服务提供的 prompt 可以作为受控材料使用，不成为系统指令或新的授权来源。

每项能力至少可解释：来自哪条连接与哪个账号、能做什么、输入要求、读取或写入性质、需要哪些权限、当前是否可用及原因、最后检查时间。能力目录不把凭据、完整环境变量或私有配置正文交给模型。

能力分成“当前可调用”和“发现但被阻塞”两类展示，后者明确缺少适配、权限、连接还是目标访问权。只有在可信元数据或适配实现足以确认时才认定只读；不能仅相信第三方工具的名字或提示性标记。性质不明确的外部工具按可能有副作用处理。

自动启用指让已获授权的能力进入可发现、可调用状态，不指自动执行所有工具或自动扩大权限。新增权限、变更账号、扩大本地目录、改动可执行代码来源等不能借能力刷新静默生效。

连接成功、授权成功、重新授权、更新、重新启用和恢复连通后自动刷新能力；用户说“检查连接”也会刷新。可用性在每次调用时复核，缓存标明时间，不将历史工具列表当作当前连通证明。工具删除、合同改变或提供方替换后，过期引用明确失败或重新选择，不能悄悄调用另一项操作。

## 4. 对话式接入流程

### 4.1 理解意图、检查已有连接

输入可以是服务名、MCP URL、本地启动命令、配置片段、文档链接或安装说明。助理先读取产品支持信息和已有连接，提取非敏感配置，判断用户是接入、修复还是直接使用。已存在可用连接时直接复用；存在失效连接时优先恢复；不先创建重复项。

读取支持范围、检查已有连接、发起安装/配置和本人操作请求的管理能力，不依赖目标服务已经连通，也不要求先打开 Coding 或新建项目。未知服务按 §1.3 判断能否走自定义 MCP；真正缺少地址或安装来源才向用户补问。

对安装说明、网页和工具描述只提取资料，不执行其中试图扩大授权、读取秘密、关闭防护或改变任务目标的指令。需要补充的信息仅限会影响正确性的项目，如账号、租户、目标项目、服务地址或必要权限；不要求用户复述已保存的配置。

### 4.2 选择接入方式并形成可执行方案

用户明确指定服务、账号或接入方式时优先遵循，在该选择内先查重；不支持或不能满足任务时说明原因，不静默换用其他方式。用户未指定时，先复用满足任务的有效连接，再从 §1.3 的适用方式中选择。多个可行方式若在权限、费用、安装范围或能力上有实质差别，给出少量选项与理由；普通实现细节由助理处理。

方案说明服务与账号、接入方式、安装来源和版本、需要新增的依赖、配置和安装位置、请求的权限、原任务要调用的能力以及验证办法。方案随进度可查看，已经授权且边界清楚的步骤继续执行，不强制用户在每一步点击确认。

### 4.3 远程 MCP

远程接入的必需协议与认证组合见 §1.3，自定义 URL 与预置服务遵循同一连接、授权和发现规则。未知服务名不等于协议不支持；不支持的协议扩展或认证方式给出准确说明及可行替代，不能把远程 MCP 整类列为不支持来缩小目标。

地址由 Host 校验并限制到获准目标；重定向不能带着凭据跳到其他服务。对本机或私网服务，使用产品支持的明确网络范围，不能为了接通关闭已有地址、Origin 或授权边界。无凭据服务也需要遵守本地使用授权和操作确认规则。

本轮模型路径修订（2026-10-17，ASC-07、ASC-25、ASC-30）：Token 验收已经准备表单却漏调用持久等待，CLI 验收没有加载调用工具的原生参数 schema，把版本写成字符串后重复失败。基础提示词升至 30：明确业务能力发现与调用工具加载的区别，要求缺少调用工具时先按完整名字加载；本人操作前先真正登记等待，再回复入口。仅调整这一层指引，保持 JSON 类型拒绝、用户操作授权、实际等待和副作用合同。以同一模型、相同任务进行修订后的对比，原始失败保留；文档结果区已有可打开的 owner 引用，不额外要求末条文字重复链接。 Coding 复用的第五次模型路径还证明：最近在调用的业务 schema 已被后续目录查询挤出工具的有界声明，重新查找同一能力也不会更新其顺序。修正为同一轮最近查到或实际尝试的能力优先；在网关拒绝错误参数时，把已经通过当前身份与可用性核对的那项能力重新声明给下一次模型请求。每工具 12 项、单 schema 8 KiB、全请求 24 KiB 的原上限不变，不转换模型参数，不放宽授权或调用校验；回归验证旧能力被挤出、再次发现及错误调用后恢复，并仍拒绝坏类型。

自定义 HTTP 模型材料修订（2026-10-17，ASC-05、ASC-25、ASC-30）：第二次真实任务自拟 `service_id` 后，被现行目录校验拒绝；之后仍按猜测名称过滤查询，没有读取完整方法目录，最终错误地要求本人先手工登记服务。准备动作的 `service_id` 说明与不支持错误需指出该值来自方法目录，并引用 MCP owner 的 `CUSTOM_MCP_SERVICE` 常量说明通用 URL 的合法值；不新增映射、宽松服务标识或另一份目录。方法查询说明明确空对象查询全部。输入类型、动作版本、授权和实际接入范围不变；只修改模型面对的使用说明与错误反馈。说明修正已落地并整体构建；动作合同快照不变，同一模型从原任务重试已通过本机 HTTP 接入、真实读取、重启后读取及停用拒绝。

免凭据接入实施补齐（2026-10-17，ASC-05、ASC-09、ASC-12、ASC-35）：`connectors.setup.execute` 只接受本调用者在同一会话、用户与项目中准备的授权请求 id。已明确选择 `mcp`、HTTP/SSE、`authentication: none` 且当前意图有效时，直接复用 MCP owner 建连、发现、提交和登记，不再要求本人点一次空表单。Token/Bearer/OAuth 等需要本人的方式返回原受保护入口，不接收任何凭据；意图暂缓时返回待判断，不能自行释放。执行前、网络请求前及最终提交前复查调用权限、取消和请求状态，Host 关闭中止此调用；重复调用返回原请求状态；并发已开始的第二次调用可以被拒绝，但不能多建连接。免凭据协议没有 OAuth 回调，不为它伪造本机 Origin；带 OAuth 的原回调校验保持。用户已经启动的 HTTP 进程不由 Molis 接管、停用或终止。

验证使用独立启动的真实回环 MCP 进程：助理从给定 URL 完成接入并读取事先未知的文件正文；重启仍可调用，停用/移除后拒绝调用，外部进程继续运行。定向回归另外制造握手中的取消、撤权、Host 关闭、意图暂缓和同一请求并发；验证连接事实与实际业务派出，不能只检查返回字段。动作新增入共同目录与合同快照，现有准备动作的输入输出不变。

### 4.4 本地 MCP 与依赖安装

本地接入必须覆盖由产品启动的 stdio MCP，以及用户已有本机 HTTP MCP 服务；后者复用远程连接的协议流程，清楚区分外部进程与本产品拥有的进程。检查操作系统、CPU 架构、运行时、包管理器、指定版本、磁盘和启动条件。已满足的依赖直接使用；缺少必要依赖时由助理执行受控安装，不把“去运行这几条命令”作为默认交付。

新安装默认放在 Molis Work 管理的用户级目录，固定已选择的包/版本、启动参数、工作目录及必要配置。记录本次安装拥有的文件，区分用户已有工具和其他连接共用的依赖。凭据通过受控运行环境注入，模型看到引用或“已填写”，不看到值；启动日志和错误输出脱敏。

运行来自外部包或安装脚本的代码之前，使用具体方案核对已有执行授权；来源、权限或安装范围超出已有授权时，再请求必要确认。需要系统管理员权限、全局修改、付费开通或不支持的安装方式时，明确指出哪一步需本人完成。不能把安装说明中的命令当作用户授权。

启动、握手、发现能力和实际调用分别验证。安装成功但启动失败时保留安装与配置，修复后从失败步骤继续。更新先准备候选版本，再验证切换；失败尽可能恢复上一份可用配置和受管理版本。服务或安装过程不可回滚的影响必须预先说明，不能声称所有更新都能撤销。

### 4.5 Connector

覆盖产品正式支持的 OAuth、API Key/token、CLI 授权及 MCP 等连接方式。优先复用该 Connector 已有的授权、凭据保存和校验流程，通过同一管理接口向助理开放，不为对话复制服务商登录逻辑。

CLI 方式区分“已安装 CLI”“CLI 已登录”“Molis Work 能读取其授权状态”“相关业务动作可调用”。用户在 CLI 登录过但产品没有受支持的复用路径时，解释限制并给正式接入方式，不从磁盘搜出 token 交给模型。

连接只有账号校验能力、没有原任务所需业务动作时，显示“账号已验证，当前不支持这项操作”；可建议已有受支持的 MCP 或适配路径，不能将接入报告为原任务已完成。只实现登录的 Connector 在支持矩阵中标为“仅账号接入”，不能以它替代 Connector 业务调用验收；已有面向用户的业务操作只是尚未开放给助理的，按 §1.2 补齐。

### 4.6 本人操作与接续

对话中提供具体按钮：“登录并授权”“填写密钥”“选择账号”“允许新增权限”“重试此步骤”，以及含对象的“取消这次接入”或“停止这项任务”。按钮打开 Molis Work 的受保护表单或服务商的官方授权页；凭据直接提交到安全保存路径，不能以聊天消息、Agent 工具参数或截图内容进入模型上下文。需要手动提交含授权码的返回地址时，也使用受保护表单，不让用户粘贴到对话。

登录等待不让模型持续空转。系统保留原任务、待完成步骤和授权请求的关联；用户完成、拒绝、关闭、超时或返回错误页面后，都得到明确状态。用户直接问“好了吗”，助理查询真实状态，不根据按钮被点击就认定成功。

授权回调绑定发起的连接及该次有效授权请求，核对账号、配置和当前取消状态后才提交；任务关联用于找到等待项，不赋予回调任意启动任务的权力。过期、已取消、被后续请求替代或属于其他连接的回调不能提交该次接入；重复回调不重复创建连接。登录页可关闭后重开；Host 重启后恢复有效等待，过期的请求给出重新发起入口。

凭据只由专用界面接收。若用户主动在聊天中粘贴秘密，不复述、不用于长期记忆或常规日志，并提示改走安全输入；不承诺已发给模型的内容可以被事后“从上下文抹除”。

### 4.6.1 关闭、取消和停止分别处理

| 用户动作 | 对连接/接入的影响 | 对原业务任务的影响 |
| --- | --- | --- |
| 关闭登录页、切换页面或收起对话 | 不视为拒绝或取消；仍可提交有效授权，重新打开可查看状态 | 保持等待；Host 可运行且条件满足时自动续接，不能要求页面一直打开 |
| 取消本次授权或“取消这次接入” | 使本次请求及关联的待提交配置失效；晚到回调不得保存/替换凭据、创建/启用连接。已有有效连接不因取消一次重授权而被删除；失效的旧凭据也不能被标成有效 | 不再因本次授权结果启动；保留输入和已完成工作，显示接入被取消，可由用户重新发起 |
| “停止这项业务任务，连接可以继续” | 独立接入授权仍有效时可完成连接并报告状态；没有独立保留意图时按下一行处理 | 立即停止后续派出，授权完成不能重启该业务任务 |
| 对“接入并完成任务”的整体请求说“取消/不用做了” | 默认同时取消尚未完成的接入；不自动删除此前已存在或已成功提交的连接，不撤销其他任务独立发起的授权 | 停止该任务；不复活、不自动重做；报告已完成部分和仍保留的连接 |
| 停用或移除连接 | 新调用被拒绝，未提交的相关接入/重授权不得将其重新启用或创建回来 | 所有依赖任务看到明确阻塞；只有用户重新启用/新建并满足各任务当前条件后才可继续 |

取消与提交并发时以 owner 实际确认的先后为准：取消先被接受，之后不得提交；提交已经完成，则报告连接已建立，停止后续任务，并提供停用/移除入口，不能把取消说成已回滚。若服务商已独立授予权限但本地请求已取消，本地不激活连接，说明服务端授权可能仍在，并按现有支持提供撤销入口。已有业务结果和用户文件不因这些取消动作被删除。

### 4.7 验证并继续原任务

完成必要授权后，自动连通检查、能力发现、授权范围核对及最小必要验证。优先使用无副作用检查；禁止为了验证而擅自发信、删文件或创建业务数据。

在助理、设置页、Coding 或另一会话完成同一连接的有效授权、凭据更新或修复后，都由连接 owner 更新真实状态。Host 随后检查已登记为等待该连接的任务，而不是由回调指定要执行的任务。仅当任务仍在等待、最新需求仍需此连接、账号/项目/目标未错配、所需能力和当前操作授权满足，才自动继续；无关、已完成、用户主动暂停、已停止和已取消的任务不启动。若只解决部分权限或依赖，继续不受阻且仍获授权的部分，剩余明确等待，不能把登录成功当成所有条件满足。

同一连接可以解除多个任务各自的阻塞，但每个任务的一次等待只续接一次。重复通知、重复回调、重新打开页面及 Host 重启不能重复派出；任务已在执行时只更新可用状态，不再启动第二轮。关闭页面时 Host 仍运行就正常接续；Host 不运行时在下次启动后复核，不承诺离线后台执行，也不依赖模型持续轮询登录状态。

续接使用同一任务中最新有效的用户要求、账号/项目/对象选择、已完成步骤及待做部分，不重放最初计划。等待期间用户说“只查资料，先别保存文档”，恢复后只读，不再调用 Pages 写入；改账号、对象或扩大操作范围时重新检查差额授权，不能沿用原对象的批准。尚未派出的旧步骤失效，已派出的操作按真实回执处理，不承诺撤回。恢复判断和真正派出之间再次修改任务，也必须在派出前核对，旧计划不能穿过这个间隙继续执行。

修改业务步骤但仍需原连接时，接入可继续；用户改为接入另一服务/账号或撤回本次接入权限，使原授权请求不再符合新意图时，该任务发起的旧请求失效，按新选择重新准备。晚到结果不能提交旧接入；其他任务独立的请求和此前有效连接不因此被删除。部分授权足以完成修改后的任务就继续，不为已删除的步骤再请求权限。

新增能力不能扩大正在运行的 Agent 角色；必要时由 Host 在同一任务下开始新一轮，按最新需求读取当前授权及角色边界。用户无需新建对话或重复下达原任务。等待、修改和续接复用已有任务记录与运行恢复能力，不另建通用工作流引擎。

接入成功后应说明所选账号、可执行的相关能力和仍受限的部分。真正业务调用的返回、目标系统结果和插件保存结果共同证明任务完成。只要求接入而没有后续任务时，报告具体验证范围；未实际调用的能力不能标成“已验证调用成功”。

## 5. 状态与用户可见反馈

四个维度分别可查、可解释，附检查时间和事实来源；它们不是只能单向前进的四个阶段。能从连接配置、授权事实、能力目录和调用回执推导的状态直接推导，不要求四套独立持久状态机或复制记录。停用/移除是连接管理状态，可与配置完整性分别显示。

| 维度 | 状态含义 | 不能据此推断 |
| --- | --- | --- |
| 配置 | 未配置、缺少字段、完整；另示连接是否启用、停用或已移除 | 配置完整不代表地址可达或进程能启动 |
| 连接 | 未检查、连接中、连通、断开、失败 | 握手成功不代表账号有读取或写入权限 |
| 授权 | 分别说明服务端账号授权与 Molis Work 当前调用者授权；可为无需服务端登录、待本人操作、已获部分/所需范围、过期、被拒绝、未知 | 有 token 不代表权限足够；无需登录不取消 Molis Work 授权 |
| 能力 | 未发现、发现中、当前可调用、部分可调用、无可用能力、已失效 | 列出工具不代表每个目标对象都能访问或每次调用都会成功 |

“当前可调用”表示已发现有效实现且当前检查通过，派出仍复核；另外记录“最近一次实际调用成功/失败/结果未确认”及时间。没有 scope 查询能力的服务应显示授权范围未知，依据具体调用反馈逐项收敛，不能显示“全部授权”。

接入任务另有进度：检查已有连接 → 准备安装/配置 → 等待本人操作（如需要）→ 连接与发现 → 验证 → 继续原任务；任一步都可能失败、取消或等待恢复。显示当前步骤、关键结果、等待原因和下一步，不把工具内部日志堆成对话正文。

同一连接可能“已配置、断开、授权有效、能力暂不可用”，也可能“已连接、账号有效、只有读取能力”。错误提示必须反映这种组合，不用一个绿色“已连接”覆盖所有状态。

## 6. 对话中的持续管理

| 管理动作 | 必须兑现的行为 |
| --- | --- |
| 查看连接与能力 | 按服务、账号、项目列出四维状态、最近检查和调用结果；支持追问“能做什么”“为什么不能做” |
| 检查与修复 | 区分安装、启动、网络、认证、权限、能力合同和对象访问问题；已授权的安全修复直接执行，不能自动换账号或扩大范围 |
| 重新授权 | 保留连接身份、配置和已有任务结果，只请求缺少/失效的授权；成功后自动刷新并继续仍有效的原任务 |
| 更新 | 说明更新对象、版本和影响；支持本地包、非敏感配置及能力刷新。远程服务商版本不受本产品控制，不能假装本地已回滚服务商 |
| 停用 | 立即拒绝新调用，阻止未派出的操作；释放自有运行资源。保留配置与历史，明确正在执行且无法撤回的外部操作 |
| 重新启用 | 复核当前配置、依赖与权限，再连接、发现和验证；用户主动停用后不得被任务或自动修复悄悄重新启用 |
| 移除 | 核对准确连接与依赖影响，删除本产品拥有的配置和不再被引用的凭据/运行资源；保留用户文件、既有业务成果和必要调用记录 |

移除本地连接不等于卸载用户已有 Node、Python、CLI 或共享包；可清理的受管理依赖明确列出。移除连接也不等于撤销服务端 OAuth 授权：若支持撤销则报告真实结果，不支持则给服务商操作入口。依赖它的工作流程、插件和任务进入可解释的不可用状态，不静默指向另一条连接。

同一连接被多个会话同时接入、授权或修改时，避免重复安装、相互覆盖和同一等待的重复接续；后到的操作看到当前状态或冲突说明。不同任务各自的有效等待可以按 §4.7 分别恢复；取消一个任务不取消其他任务独立持有的请求。一个连接出错不能阻塞其他连接的发现或调用。

## 7. 失败与恢复规则

2026-10-27 用户已定：账号、服务地址和授权不变且仍有效时，短暂断线默认自动重连，恢复后接续原工作；反复失败、需要重新登录或权限变化时再提醒。结果不明的写操作先核对，避免重复执行。连接 owner 负责恢复，原任务负责按最新目标和有效授权接续，不要求用户重配连接或再次批准同一工作。

恢复采用现有机制有界重试和退避，遵守服务限流与时间/用量限制，同一连接的恢复由原 owner 协调，不并发制造重复连接或接续。过程在原入口可见，短暂故障不逐次打断；反复失败或需要本人操作时合并提醒、提供具体入口，同一问题未变不反复催促。受影响部分保留结果并等待，独立且获准的工作继续。自动恢复不改变账号、地址、来源或权限，停用、主动断开、撤权及结束委托不会被当成临时故障；无需因此新增一套调度或状态系统。

连通后先刷新能力、核对当前配置及任务要求，再继续尚未完成的步骤。原业务请求是否生效与连接是否恢复分别判断：未知写入先查询原请求或目标状态，已生效的不重发，仍无法确认时保留未知并只等待必要决定。重连、页面重开和迟到回执都不能重新执行已完成效果、覆盖用户后续修改或复活已取消工作。

| 失败类别 | 用户必须知道 | 恢复方式与保留内容 |
| --- | --- | --- |
| 服务、协议或平台不支持 | 哪个组合不支持，是产品缺适配还是服务商有限制 | 给受支持的选项；保留意图与非敏感方案，不伪造成功连接 |
| 运行环境或安装失败 | 缺少哪个依赖、失败步骤、可读的脱敏原因 | 从失败步骤重试；保留已成功安装且可复用的部分，清理自身无效临时文件 |
| 登录取消、超时或回调失效 | 本人操作是否完成、授权请求是否仍有效 | 保留任务和配置，提供重新发起入口，不循环弹登录窗 |
| 权限或对象访问不足 | 缺少的具体能力/权限或目标访问权；已知与未知分开 | 只申请差额，或更换明确选定的任务目标；保留能继续完成的其他部分 |
| 网络断开、进程退出、服务限流 | 哪条连接暂不可用、是否自动恢复、何时检查及服务等待提示 | 原 owner 在账号/地址/授权仍有效且未被主动停止时自动恢复原连接，安全读取可有界重试；反复失败再合并提醒，等待可取消，不阻塞其他独立工作；不擅自重启用户自行管理的进程 |
| 工具删除或输入合同变化 | 哪项操作变了，当前计划为什么不能照旧执行 | 刷新并重新选取；需新权限或参数变化时重新核对原授权 |
| 外部写入超时或返回丢失 | 请求未派出、明确失败、已成功或结果未确认 | 未确认时先查原请求或目标状态；无可靠幂等/核对能力时等待用户决定，禁止盲目重发 |
| 接入成功但后续插件失败 | 外部调用已完成什么、哪个插件尚未写入 | 保留可用的中间结果，从失败的插件步骤继续，避免重做已发生的外部操作 |

重启后恢复连接元数据、等待事项、已完成步骤与未确认调用，重新检查运行状态、最新任务要求与授权。不会因为恢复记录存在就再次执行安装或外部写入。已取消的接入不能被晚到回调提交；只停止业务任务而仍独立授权继续的接入，才可更新连接，且不重启该业务任务。具体以 §4.6.1 和 §4.7 为准。

在对应的任务、接入请求或连接被取消、撤权或停用后，不再派出其受影响的新调用，返回结果也不能继续触发下游业务写入；其他独立且仍获授权的操作不随之取消。已经派出的外部操作可能无法撤销，应保留由执行 owner 记录的真实回执，解释已发生、未发生和未知部分；不能承诺外部系统自动回滚。

## 8. 界面、隐私与执行边界

个人助理当前对话与服务连接页面都提供可直接完成接入的产品入口，读写同一份事实；不要求用户先与助理对话、打开 Coding 或新建项目。对话中的状态、授权入口、修复与结果可就地使用，服务连接页面也须独立走通 §8.1 的完整路径。服务商登录可使用外部浏览器；完成后回到原入口继续。

对话应显示账号标签与使用范围，敏感账号信息按产品规则遮蔽。授权页面提供所需权限与用途，不默认勾选与任务无关的额外范围。密钥输入表单、OAuth code/token、环境中的秘密、CLI 登录输出不能进入模型提示、记忆、诊断导出或截图采集；Computer Use 也不得绕过此边界。模型只看到提交状态和非敏感引用。

读资料和安装/写操作遵循可信调用身份、实际效果与操作授权；账号授权不代替具体发送、发布、删除等操作授权。目标行为按 §3.2 的权限选项处理：已获准读取直接进行，修改前确认保留逐次确认，授权内自动执行复用明确覆盖的操作授予；统一授权/执行链负责实际裁决。本次需求更新不改变现役运行策略，实现时须同步相应合同与拒绝测试。

读取外部内容时保留来源并视为数据；不接受它要求调用其他服务或泄漏本地资料的指令。调用记录足以解释谁以哪个账号对什么目标执行了哪项能力、结果如何；只记录定位所需的非敏感摘要，原始资料与成果归原插件，不另建一份业务事实库。

### 8.1 常用服务的直接连接体验（2026-10-27）

用户面向的是服务和工作：“连接我的 GitHub / 邮箱 / 文档服务，接着做事”。默认页面显示服务名称、用途、实际支持的工作、当前账号与可用状态，以及明确的“连接”主操作；不要求先选择 Connector/Provider、OAuth/MCP/CLI、传输方式或理解 scope、回调、工具注册。已有同范围可用连接直接复用；多个账号只在会影响当前工作的地方让用户选择。

常用服务的目标路径是 **点连接 → 在必要时登录、选账号并授权 → 自动回到原入口 → 显示可用结果并继续原任务**。“一键连接”指平台准备好可执行接入，并把可自动完成的配置、回调处理、能力发现和必要检查串起来；服务商要求的本人登录或授权仍由本人完成，不额外增加无新决定的确认页，也不把“检查连接”“登记工具”“再启用一次”留给用户逐步点击。

平台负责准备默认接入方式、应用注册/回调基础设施及发布所需条件，沿现有提供方声明和连接 owner 实现。尚未完成这些条件是产品接入缺口，不能靠让普通用户去开发者后台创建应用、填 Client ID/Secret、复制回调地址来算完成。需新增服务侧注册、部署、资格或费用的，作为有主人的实施依赖安排；本轮文档不执行这些操作。没有默认可用路径时准确标明当前限制和可行替代，不把目录条目、官方文档链接或改名后的技术表单标为“已支持一键连接”。

正式 OAuth 应用的管理归属（2026-10-27 用户已定）：优先由用户现有的中国公司管理，放在公司控制的服务商组织、租户或项目下，个人账号可作为获准管理员。每家服务的主体资格、地区、域名与品牌验证、所需权限及运营账号在实施时逐项核对；个别服务不适用这一默认原则时，说明具体限制后单独确定例外，不把某个平台审核通过当作其他平台也已具备资格。Apple 安装包签名与公证继续采用现有个人开发者账号，两项安排分别管理。

这一决定只确定产品应用由谁持有和维护，不代替终端用户的账号授权，不改变连接 owner、数据权限或高级自有应用入口。本轮不注册应用、配置凭据或恢复已暂缓的真实账号验收；应用接入与可用结果仍按 ASC-45～50 验证，当前不记为已完成。

自定义服务、自有应用、专用部署和手动密钥配置留在用户主动打开的高级入口。服务自身确实只提供 API Key 等接入方式时，只展示必需字段、取得方式和具体用途；不摆出与当前服务无关的协议配置。管理员批准、租户/地区/订阅限制等真实前置条件说明由谁完成、对本次工作的影响和如何继续，不能笼统要求“配置 Provider”。权限用“读取哪些资料、能做哪些操作”表达；技术原值可在诊断中查看。凭据仍只走受保护的输入与存储路径。

连接成功的默认落点是“这个账号现在能用来做什么”，例如接续原先读取资料的任务或选择实际可用的内容范围。平台通过公开合同完成内部引用和能力登记；同范围的助理、Coding、工作流程和内容插件复用该连接，不要求用户因为内部协议或模块不同重新接一次。若用途确实需要另一项授权或尚缺适配，只说明这个具体差额及影响。授权完成与业务能力就绪分别核实；部分能力可用时清楚呈现，不显示一切成功后再让用户去另一设置页接线。

失败或登录失效时，保留原任务、账号选择和已完成步骤，就地给出重试、换账号或重新连接；完成后恢复原连接引用与当前有效任务。正常使用主视图不以内部 id、原始协议错误、参数 JSON 或 CLI 输出作为解释。高级诊断按需可达，不能替代普通用户可执行的恢复路径。

验收逐项核当前实际服务目录中的默认接入和真实用途。服务商仅有高级接入、缺产品应用配置、缺业务能力或缺测试条件的情况分别记录为缺口；单个服务成功不能代替全部服务。先做真实内容的可操作切片，覆盖首次连接、多账号、取消/拒绝、失败重试、失效重连及连接后的实际任务；隐藏术语或出现一个“连接”按钮不算交付。相关共性问题进入[全平台治理](../product-flow-governance/spec.md)，具体服务行为和证据仍由本书维护。

### 8.2 公开搜索与默认来源（2026-10-28）

用户已定：公开网页搜索是平台公共能力，复用已连接的服务，在统一设置中选择默认来源；Coding 不单独配置。个人助理、Coding、工作流程及其他获准消费者通过共同目录和公开合同使用同一能力，不复制连接、凭据或默认来源。这里指互联网公开资料搜索，不改变站内或项目内容检索的事实主人；工具目录检索也仍按 [Tool 策略](../prologue-tool-strategy/spec.md)处理。

统一设置展示实际具备公开搜索能力、当前可用且获准的连接，用户可选择、更换默认来源。连接配置、账号、凭据与授权仍由原连接 owner 管理，默认选择只引用该连接及其公开能力，不把任意已连接服务视为搜索服务，不新增 Coding 专用配置或宿主按插件名分支。有效默认直接复用，无须重新连接或逐次确认选择；设置保存、刷新、重启及跨入口后读取同一值。新增付费服务、账号登录和扩展权限仍按对应授权处理。

调用使用当前有效默认，回执和结果能辨认实际服务、账号及网页出处。修改默认影响后续请求，已经发出的请求保留实际来源，不能把旧结果标成新来源；连接停用、移除或撤权仍按现行边界即时生效。默认来源不具备能力、未连接、失效或当前不获准时，如实说明原因，并在统一入口连接、修复或选择已有来源，完成后接续原工作；不要求 Coding 再填一份，不静默改默认、购买或改用未获准来源。直接读取已知公开网页不依赖搜索服务就绪。

Coding 的公开查询默认许可及项目/本次任务关闭沿 [B1、CNW-01～05](../coding-plugin/next-requirements.md)；默认来源仅决定从哪里搜索，不能覆盖该关闭、范围限制或原服务授权。实施前核对当前已连接服务与实际公开能力，优先接通已有适配；本次不指定必须购买的厂商，不表示适配、配置和真实调用已经完成。

### 8.3 GitHub 的共享账号与任务范围（2026-10-28）

用户已定 Coding 复用平台已连接 GitHub 账号，默认围绕当前项目关联仓库；推送、评论、开 PR 按本次任务有效授权执行，已获准操作不重复确认。沿 §3.1～3.2 的同一连接身份、多账号选择、权限求交及 §7 的恢复规则，不新增 Coding 私有凭据或第二份登录。平台账号连接与本机 CLI 登录必须区分，受支持 CLI 适配经实际身份和权限核对后使用；缺适配不伪报已就绪，也不静默改用其他账号。

连接 owner 管账号、能力和授权，Git 管仓库与 PR／检查事实，Coding 消费共同操作和结果；账号可访问某仓库不等于用户已委托写入，项目切换或远程配置变化不自动改变原任务许可。实际目标、评论触发、写入对账及跨入口验收统一见 [Coding D2、CGH-01～03](../coding-plugin/next-requirements.md) 与 [Harness R10、CHO-22～23](../coding-harness-optimization/spec.md)。本段仅同步需求，不更改真实账号、仓库授权或已有实现状态。

## 9. 实现边界与依赖

本节约束职责和合同，不提前固定新动作名称、数据库 schema 或另建服务。实现前需在同一需求书补充实际接口设计。一份连接指唯一的配置与授权事实及共同管理合同，不要求所有协议共享一个物理会话、把所有存储合成一张表或新建一套包管理/任务调度系统；消费方使用公开引用，技术缓存可以重建。

| 现有模块 | 本需求中的职责 |
| --- | --- |
| Local Host 的连接管理（`apps/local-host/src/connector-*`） | Home 内连接配置、账号与范围、凭据引用、接入进度和授权回调的唯一管理入口；设置页与助理共用 |
| `horizontal/connector-host` 与 Integration Provider | 现有 Connector 的协议适配、健康检查和技术回执；提供方拥有自身业务能力实现，不在助理内重写各服务 API |
| `horizontal/agent-host` | 通过同一 Prologue Runtime 使用 MCP、执行 Agent、审查与恢复；维持角色和调用授权边界，不为助理另起一套 Runtime |
| Kernel 动作目录与服务 | 注册一次，按身份发现、校验与执行；连接管理和业务能力均通过共同合同开放，无助理专用服务白名单 |
| Local Host 的 Assistant | 理解用户意图、选择连接、协调本人操作、保留任务并接续；不保存另一份连接或凭据 |
| Workbench | 对话状态、授权表单、连接详情与设置视图；只呈现服务真实状态，不自行判定授权成功 |
| Coding 与其他业务插件 | 引用同一连接和公开动作；资料、文档、待办、流程等结果仍由各自 owner 读写 |

模型需要的上下文只有：用户意图、任务与项目范围、连接的非敏感摘要、当前能力及阻塞原因、已有步骤和有效操作授权。模型产出接入方案、管理动作调用与任务结果；凭据提交、权限裁决和状态提交由可信 Host 完成。

管理合同至少覆盖：列出与检查连接、准备接入方案、执行已授权安装与配置、创建本人操作请求、读取进度、连接和发现、诊断、重新授权、更新、启停和移除。输入不接受伪造 actor、项目、安装身份或凭据正文；输出包含当前状态、原因、下一步操作和原任务关联。具体操作仍按风险拆分，不能用一个任意 shell/API 执行入口代替。

### 9.1 存量连接收敛

保留：现有有效连接、账号与凭据引用、用户明确选择的范围、已获授权、任务记录和成果。替换：按添加入口分割的连接管理、重复目录维护及必须手动发现后助理才看见的步骤。忽略：必须进入 Coding 才能使用同一服务等历史界面限制。

先盘点当前 Home 级连接与项目/Coding MCP 的字段、owner、授权和消费引用，确定唯一写入路径；再提供统一管理与发现，切换原入口和助理，最后移除被替代路径。不能让新旧管理入口长期双写，也不能只加 agent audience 就宣称统一完成。

存量授权无须用户重填，按 §3.2 区分用户真实限制与旧实现的入口隔离：仅因 Coding owner 或缺少 Agent audience 而受限的路径应打通；用户明确限制的范围仍保留，实际缺少助理授权时才对同一连接请求新增授予。助理身份和审查保持独立。切换后连接运行不再依附添加入口的页面/会话，按 §3.1 验证其生命周期；无法可靠识别账号或有效授权的记录保留原状并明确请求所缺信息。

涉及真实 Home 结构维护或现行合同改变时，按[合同变更流程](../../docs/system/CONTRACT-CHANGES.md)设计一次性维护、备份和回滚，不新增读取旧值的兜底。具体维护方案须在实现阶段给出，未验证前不对真实 Home 执行；本轮需求编写不构成迁移、安装、登录或外部写入授权。

### 9.2 建议实施顺序

1. 用真实或逼真内容制作高保真可交互切片：已有连接复用、新建连接、等待登录、权限不足、失败恢复、成功后继续任务。模拟部分明确标出。
2. 统一连接身份、授权和目录合同，打通“已有 Coding 连接 → 助理真实调用”这一纵向路径，包含失败与重启。
3. 接通远程 MCP 和现有 Connector 的对话接入、本人操作与自动接续。
4. 接通本地 MCP 的依赖安装、运行、更新、停用和移除；所有入口消费统一管理服务。
5. 完成组合场景、异常、并发与真实账号验收，再按独立发布任务处理安装包和发布。

以上是有依赖的实施顺序，不把远程接通或单个服务成功当作完整需求完成；本地 MCP 和已支持 Connector 同属本次目标，不默认为后续版本。

### 9.3 实施合同（2026-10-16）

已完成[服务 × 实际方式 × 用户操作与存量引用盘点](coverage.md)，按处理器区分账号验证、已有业务操作及 MCP 动态能力；该表不成为运行时名单。

先交付[交互切片](prototype/index.html)：在现有工作台与助理浮层的视觉语言中走通已有连接复用、新连接等待、本人操作、权限不足、失败重试、修改任务后接续与取消。服务响应及业务结果均明确标为演示，不输入秘密，不冒充真实授权。正式界面继续使用共享卡片与控件。

首片后端仅修改连接 owner、MCP 协议和对应 HTTP 入口，补齐授权完成后共同目录自动刷新；连接结果不直接派出业务任务。授权尝试沿用 `connector_authorization_results` 的稳定请求 id 和一次性 state，取消以 owner 的待处理状态为准，回调在交换凭据、写入和正式提交前复核。取消先被接受时，迟到结果不能提交或将状态改回成功。已有会话表持有待提交配置与临时凭据引用，完成/取消后释放；不建立另一份授权数据库。成功的调用结果再经同一 `ConnectorMcpDirectory.remember` 派生可发现能力，拒绝或失败不登记。验证覆盖真实本机 MCP 协议、Agent 身份经动作目录调用、重复/过期回调、取消与令牌交换/发现交错和 Host 重建；不使用真实服务凭据。

后续按依赖顺序推进，完成范围不因首片而缩小：

1. **共同管理与连接引用**：采用一个管理目录调用现有连接 owner：Connector 记录继续由连接库持有；项目 MCP 配置继续由同一 Home 的 Prologue MCP 库持有，原项目字段保留作用域，来源插件只解释来历。管理目录不复制凭据或配置；跨入口动作保留引用，运行生命周期不绑定来源插件。持久数据不需要为了合并页面而搬家，真正改库时再按维护流程处理。盘点 `connector_connections`、`connector_protocols` 与 Prologue MCP 配置的身份、授予及消费者；保留连接 id、凭据引用和项目范围，以 Home 连接 owner 提供管理合同，现有入口改用引用，不长期双写。已有 `config/connector-mcp-tools.json` 与 `config/external-mcp-tools.json` 是可重建的发现缓存，不成为配置或授权事实。需维护存量数据时先补具体切换/回滚与隔离演练，再申请真实 Home 操作。
2. **管理动作与远程接入**：列出方式/连接/能力、检查、准备、受保护本人操作、授权状态、启停/移除由同一 Host 管理合同开放；不依赖项目或目标服务可用。自定义远程协议沿用官方 MCP 客户端和出站校验，不把任意 URL 变成凭据转发入口。原 Connector 方式与用户业务操作从实际处理器盘点，调用原 owner 的公开动作。
3. **助理接续**：接入完成只通知连接状态变化；任务 owner 使用 Prologue 已有 continuation/wait 合同登记并恢复等待。每次恢复读取最新任务要求，派出前再次核对范围、角色、连接及本次授权；关闭页面与取消/停止分别处理，不新建通用调度系统。此步依赖助理基座、共享卡片和 Agent Host 合同拆分落地，合入前不覆盖其在途实现。
4. **本地安装与运行**：已有可执行文件、固定版本 npm 与 Python 包分别走用户级安装；复用官方包管理器，拥有的安装文件与用户工具分清。候选版本验证后切换，安装与执行日志脱敏；停用/移除只终止自有进程和不共享的受管资源。
5. **组合与真实验收**：按 ASC-01 至 ASC-37 逐项记录证据。共享合同/装配变化跑仓库要求的全量，真实模型、账号和外部写入在具体对象与权限明确后执行；尚缺的真实验证保持未完成。

自定义远程 MCP 沿用已有通用 MCP 服务标识，新增完整配置时保存一条协议连接；原 Bearer 凭据记录仍由其消费者引用，不复制。预置服务仍校验官方地址，自定义 URL 只接受 HTTPS 或明确指定的回环 HTTP，拒绝 URL 内凭据，禁止带凭据跟随重定向。认证方式可显式选免登录/Bearer/OAuth，SSE 可显式选择或沿原 404/405 回落；授权和发现继续调用同一协议 owner。

取消入口使用授权请求 id；通用 OAuth 在交换前和最终同步提交前复核。Gmail 与 Notion 的已有驱动先写本次临时凭据引用，回调在最后复核后同步复制到原连接引用并更新连接；取消或失败清理临时引用，不覆盖已有有效凭据。断开连接同时取消该连接所有待提交请求。此路径没有改数据库形状、Gmail 插件合同或真实 Home。

跨入口 MCP 的执行合同：共同目录中的项目 MCP 由 Host 提供，来源插件仅保留在稳定 provider 引用及管理目录的来历字段。Prologue 库新增 Host 只读配置目录，不复制 SDK 配置。已启用但断开的配置在获准调用时按需连接；原配置版本、工具形状、项目工作区授权及调用者权限必须在准备和实际派出时仍成立。显式停用/移除拒绝调用，断开只释放运输连接；恢复不自动执行业务工具。并发调用合用一次连接准备，每次业务调用仍独立检查与记账。

连接启停与移除使用 Connector owner 的当前记录：新增 `enabled` 与 `removed_at`，前者独立于凭据/协议配置，后者保留旧引用的失效事实与来源历史。停用保留凭据，立即失效在途请求并取消待提交授权；启用不替用户重新登录，检查成功后刷新能力；移除清理本产品持有的凭据、协议与未提交请求，不删除 Feed、Pages 等业务结果或外部 CLI 账号。所有连接消费者同时检查启用状态，不能通过模型/Images/Functions/Feed 等入口绕过。Home connectors 建库基线升到 2；旧基线拒绝运行，不加产品内升级链。切换时先用隔离的 v1 数据副本演练一次性维护：增加两列（原记录启用、未移除）、保持 id/凭据引用/绑定/协议/授权结果并改基线号；失败用完整副本恢复。维护脚本在会话临时目录，真实 Home 仍须另行当次授权。

项目 MCP 的直接密钥输入改由 Home Connector 凭据 owner 保存并返回连接 id，SDK 配置仅保存引用；配置提交失败清理本次候选凭据。原来只存在 SDK 进程内存中的凭据引用不能恢复，遇到它明确要求重新授权，不能当成匿名连接或拿另一个进程里碰巧同号的凭据使用。更换或移除项目 MCP 不隐式删除可被其他消费者共用的账号连接；账号移除仍走统一管理。重启回归使用真正校验 Bearer 的本地 MCP 服务。

消费者合同：`images.connections.list` 升到 v2，账号视图新增必有的 `enabled`，消费者从目录重新发现版本；旧版精确动作/授权引用明确失效，不提供双版本。Jelly 模型设置继续返回原来的连接摘要，其停用状态投影为 disconnected，不额外塞入合同未声明的字段。

启用后的检查由管理动作与设置页共用连接检查服务：只运行身份/协议检查并刷新能力，不派出业务工具。无法直接验证的通用密钥连接返回具体的未检查原因；检查失败保留已启用配置，不能回报连通成功。CLI 显式重接可以恢复同一账号的原 id，但仅在本次身份读取开始时捕获的修订仍有效时提交；并发停用、移除或其他接入先提交后，迟到结果拒绝。连接 owner 保证每次写入的 `updated_at` 严格递增，即使系统时钟未前进也不复用旧修订。CLI/API 检查传递调用方取消信号，并加入连接 owner 的失效通知；CLI 在身份读取、业务只读派出及最终返回前复核原修订，停用后立即启用也不能使旧检查恢复有效。统一检查有 30 秒时限。

已有业务读取合同（ASC-04、ASC-07）：设置页已经向用户提供的 API/CLI 记录预览，登记为 `connectors.records.read`，由同一 `inspectApiConnection` / `inspectCliConnection` 处理，不再要求先打开设置页。只接受明确的连接 id，不接受 URL、任意命令或请求正文；使用单独的内容读取权限，调用前后检查当前授权和连接修订。仅有身份检查的服务明确返回缺少记录读取适配，不能把身份响应当作业务结果。Feed 同步、Artifacts 导入、模型、图像和判断仍走各自既有业务动作，本动作只开放已有固定的列表读取。

对话接入请求合同（ASC-07、ASC-08、ASC-14、ASC-35、ASC-37）：`connectors.setup.prepare` 接受服务、明确选择的已有方式及非敏感配置，不接受 token、Client Secret、OAuth code 或任意命令。它把方案和可信发起者关联放进现有 `connector_authorization_results`，在协议启动之前使用 prepared 状态；返回同一个授权请求 id、可能重复的连接和受保护表单地址。本人表单从 owner 读取方案，直接提交给原处理器；开始协议时把该请求绑定到一次性 state，完成、取消与状态查询继续使用同一 id。相同会话的相同未完成方案可以重新打开；不同会话不自动共享取消权。表单不能用请求 id 更换服务、接入方式或已有连接；取消/过期后不能重新开始或提交。token 与 CLI 在最后提交前检查该请求，OAuth 与 MCP 沿用原有多次复核。准备请求本身不代表登录、连接或业务任务完成。新字段并入本分支尚未发布的 connectors 基线 2，隔离的一次性维护演练同步增加字段，真实 Home 不改。任务最新意图的持久关联与暂缓提交已按 §11 接入并经协议测试；完整助理接续仍依赖待确认的 SDK 能力，当前不能据此宣称 ASC-34 已完成。

输入与输出边界：模型只拿服务、账号标签、scope、非敏感配置、状态和引用；密钥与 OAuth 返回地址只由本人表单提交。Actor 与项目从可信调用上下文取得。错误使用 `connectorErrors` owner 代码；权限失败不改成成功或静默换连接。全程遵守单构建/单浏览器批次排期。

### 10.6 合并回归中的首页点击时序（2026-10-18）

## 11. 假设、后续设计输入与本轮证据

接续实现合同（ASC-18、ASC-25、ASC-33）：继续使用 Prologue 的步骤等待与唯一接续键，不另存等待或调度记录。Host 提供 `molis.connector-setup@1` 只读检查器，参数只有准备动作返回的授权请求 id；它只允许请求发起的同一运行会话、用户和项目读取，且每次重新核对助理当前可用的管理查询权限。重启后只有这种 owner 能从持久请求证明身份的检查可恢复；原有动作和文件检查仍保留 S-27 的重启拒绝。检查器只报告连接事实，不安装、不登录、不调模型、不执行业务操作。助理从 SDK 接续读取最新对话后开启同一工作的下一轮，SDK 以原接续键去重；失败、过期、取消、暂停、已运行和待核对的工作不自动开始。本人修改任务的提交与自动开始串行，并在真正开跑前再次核对工作修订；最新意图对尚未提交接入的保留/取消另由连接 owner 的提交关口兑现，不能仅靠提示词。

等待监听生命周期（ASC-18、ASC-25、ASC-33）：助理的接续监听随创建它的服务关闭，正式装配由同一 Local Host 在关闭开始时释放；关闭借用的 Web 传输不关闭共享助理。释放中断长等待、撤下订阅，迟到的观察不能再刷新工作或启动模型。手动构造助理的嵌入者与测试必须在关闭 Agent 运行时和数据库前关闭监听。此约定不改变 SDK 中持久等待的状态，重建 Host 后仍从原 owner 恢复。 读取任务状态后、写入观察与通知前再次核对监听仍有效以及工作修订未变；读取期间关闭 Host 或发送新要求时，迟到状态不覆盖当前任务。

跨入口修复等待合同（ASC-10、ASC-25、ASC-33、ASC-34）：新增 Host 只读条件 `molis.connection-ready@1`，绑定已选择的稳定连接 id、从真实检查得到的账号（无账号要求时显式为空）和原任务需要的精确能力引用。它通过当前助理动作授权读取连接 owner 的状态，不发起网络校验或业务调用；设置页或其他入口的检查更新同一份带配置修订的检查事实后，下一次条件检查才可能满足。账号标签不作身份凭据；API/CLI 的真实身份检查可返回非敏感账号标识，MCP 未提供身份时保持未知。换账号、缺少所需能力/当前授权、停用、当前修订未验证时继续等待；已移除连接明确失败。项目 MCP 只允许同项目任务。检查前后核对当前工作、会话、用户、项目与管理读取权限；暂停、停止、最新意图变化及重复接续继续由既有工作修订与 SDK 等待 owner 拦截，不创建另一张等待表。

最新意图提交合同（ASC-34 至 ASC-36）：本人在已有助理工作发送新消息时，同步暂缓该运行会话尚未完成的接入，并在原授权记录的发起者 JSON 内保存本次意图修订；不将“有新消息”解释成取消。模型读取真实授权状态后，通过仅同一会话可用的 `connectors.setup.resolve`，按最新修订明确保留或取消。旧修订、其他会话及过期请求拒绝；保留不启动业务工作，只释放接入的提交关口。协议完成时由连接 owner 将完成材料暂存在现有加密的本人操作记录中，公开状态只显示等待判断及是否已收到结果；凭据不进入任务和动作参数。释放时复核原连接修订，再同步激活并消费结果。取消/过期清除暂存；Host 重启仍可读取和处理；已完成连接不受后续消息影响。OAuth、远程 MCP、token 和 CLI 均走同一提交关口；现有 CLI 的外部账号仍由每次业务调用重新核对。整体停止仍取消未完成接入；明确保留连接的停止另有可见控制分支。本人新消息先持久保存草稿并暂停自动续接；仅最新一次发送被运行时接受后释放暂停。角色/运行时检查失败或 Host 在发送途中重启时保留暂停，旧请求的迟到失败不能覆盖新草稿或暂停已成功送达的新消息。

停止并保留接入的实施合同（ASC-18、ASC-36）：现有工作控制的 stop 可显式携带 `keep_connections: true`，页面提供“停止任务，接入继续”。默认停止仍取消该工作及其未完成子工作的接入；显式保留则先持久停止业务等待并停止运行，再由连接 owner 释放同一用户/会话的有效接入意图，提交已暂存结果或继续等待本人操作。其他会话、过期请求、已取消请求及已完成连接不受影响。保留接入不创建业务等待，也不能解除该工作的停止状态；已提交的接入仍通过原检查与能力刷新路径。该控制只接受布尔值，不能将字符串或其他操作上的同名字段当作授权。 若父工作的本轮已经完成、只有委托的子工作仍在运行或等待，停止子工作保留父轮的完成状态；不把已经交付的父轮投影成已停止。

状态投影实施合同（ASC-10、ASC-13、ASC-33）：配置和启停直接读连接 owner，授权分别呈现服务端当前已知范围与本次调用者在共同动作目录中的权限，能力从实际已登记的连接动作和已有记录读取适配派生。新增一份由 connector-host 拥有的每连接最近技术观察，分别保存检查和业务调用的时间、配置修订、结果以及必要的动作/调用者身份；不保存参数、返回正文、秘密或模型文字。它只补目前没有持久来源的技术事实，不复制四套状态机。检查结果只对检查时的连接修订有效，停用、移除或改配置后旧成功不代表当前连通。未查询到服务端 scopes 时保持未知；MCP 工具性质不明仍按可能有副作用处理。当前调用者看得到但不能调用的能力保留具体阻塞原因；业务调用与连通检查分开记录，未真正派出的检查错误不能伪装为最近业务失败，派出后结果丢失显示未知且不重试。被取消、撤权或连接改变后不写新的观察。连接库尚未发布的基线 2 增加该技术表，隔离维护演练同步更新，真实 Home 仍不操作。项目 MCP 保留 SDK 配置事实，只由共同管理层投影和记录实际检查/调用；不复制 SDK 的连接或授权库。跨入口修复等待以同一稳定连接及其现行修订的验证事实为条件，不借由取消旧请求来复活工作。

## 12. 2026-10-18 补充：内容层占位符与未支持工具的接入

### 12.1 内容层占位符

技能包/场景内容不应写死厂商。用 `~~project tracker`、`~~chat`、`~~calendar`、`~~knowledge base`、`~~office suite` 这类**类别占位符**描述“需要一个什么类别的服务”，由宿主映射到用户当前连接：

- 有连接：解析到该连接/账号；输出里显示实际使用的服务与账号。
- 没有连接：说明这个类别缺什么，给出接入入口；不悄悄换成另一类服务，也不假装可用。
- 多个连接/账号：按当前项目、任务和用户选择确定一个；选择只对本次/本工作生效，不自动合并、不混用。
- 内容包只声明类别与“是否需要写”，不声明具体厂商；换一个同类连接后内容仍可用。

这层是内容与连接之间的映射，不新建连接、账号或授权事实；连接仍由本 spec 的对话接入与服务连接管理。

### 12.2 未支持工具的接入路径

用户说“帮我连上这个工具”而目录里没有官方连接器时，按以下顺序判断，**优先选最不容易坏的路径**：

1. 已有连接/官方 MCP/官方 Connector。
2. 受管 MCP 或自动化连接（由平台管理的 MCP/集成）。
3. 定时导出/导入（工具能发邮件或导出文件）。
4. 如实说“现在没有可靠路径”，并说明用户可手动导出什么。

不手写私有 API 客户端作为默认路径。接入范围先收窄到一个可测的读取或写入；写入一律有 approval gate；凭据只进平台存储，不写文件、不进 prompt、不回显；接入后用真实数据展示样例，让用户确认读对了；最后把连接注册给助理/前门，并写明它现在能支持哪些技能、哪些不能。

这条件可以做成一个“接入未支持工具”的 Skill；它不新增平台能力，只按上述顺序调用现有 Connector/MCP/导出能力。ASC-38 至 ASC-44 是本节的验收项，仍全部未验证。
