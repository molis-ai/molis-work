# 页面动线与导航模型全量修复

状态：实现完成、全量回归已对照基线，待用户验收；未提交（2026-09-30）。工作树 `.claude/worktrees/page-interaction-flow-redesign-49fe35`，分支 `claude/page-interaction-flow-redesign-49fe35`（从 main fa27207a）。

## 背景

用户 2026-09-30 反馈（原话摘要）：

1. Character 插件可读性、可用性都很差，缺少交互引导和动线。
2. 设置页、Shelf、灵光等，点击之后关不掉，想回到上个页面做不到；底栏内容应该都是**再次点击就关闭，回到之前状态**。
3. 页面状态没有暂存；标签页什么时候增删改查都有问题，要从动线角度重新设计。
4. 各个页面都要梳理交互和动线。
5. 设置页很多还没收拢：Characters 里点一个角色会跳到 `/settings/prompts?role=…`，那是一张独立页面，没有和外壳整合；是不是该把 Character 做成设置而不是插件。
6. 参照以上诉求找出其他问题，一次全量修复和优化升级。

## 走查证据（demo 项目，1440×900，main fa27207a 构建）

**关不掉、回不去**

- 底栏 Shelf、灵光再点一次没有任何反应；Dock 上的插件同样。
- 设置 / 项目设置 / 插件市场 / 能力是盖在窗格上的"覆盖层"，打开后：Esc 不关；标题栏「上一步」被禁用（`syncHistoryButtons` 在覆盖层时直接 disabled）；覆盖层芯片没有关闭按钮；再从菜单点「设置」只会重开。唯一出路是去点标签条上别的标签，没有任何提示。
- 「上一步 / 下一步」的历史只在内存里，刷新就没了；没有快捷键，鼠标侧键会让浏览器离开工作台。

**看不出在哪**

- 覆盖层打开时，底栏插件切换器仍写「项目首页」、Dock 高亮首页（`shown()` 只看插件列表的当前项，设置等不在列表里就回落到 home）；浏览器标题还是下面那个插件的名字。
- 标签条最前面的「位置芯片」表示本窗格在哪个插件，但切到别的插件留下的条目标签时芯片不跟着变：在 Feed 页点开之前留下的 Inbox 条目标签，芯片仍是「Feed」，点芯片会去 Feed。
- 关掉当前的条目标签，会落到那个陈旧的芯片插件（关掉 Inbox 条目 → 显示 Feed），而不是回到打开它之前的地方。

**状态不暂存**

- 插件页每次重新显示都会被复位到列表（`applyPluginDefault` → `collapsePluginStage`）：灵光打开一条笔记，切到 Goals 再回来，笔记收起；Feed 从 Inbox 标签切回来，正在读的文章没了。
- 刷新后插件页里打开的东西全部丢失。

**设置没收拢**

- 工作台里的设置覆盖层只有 界面与语言 / 模型设置 / AI 与执行工具 / 诊断 + 插件页；独立设置页多出 助理、Prompt 与 Character、能力。两份分类表各写一份。
- 覆盖层只拦截它认识的分类链接，`/settings/prompts` 不在里面，所以 Characters 的角色链接整页跳走，离开外壳（没有底栏、标签、项目）。诊断页里的「开发者诊断」同样跳走。
- Prompt 页的脚本只在整页加载时运行，嵌进覆盖层也不会工作。

**Characters**

- 空状态占满整屏，把「系统与插件带来的角色」挤到折叠线以下；这些角色是一串纯文字链接，看不出每个角色做什么、谁带来的、能不能改；页头随列表滚走。
- 编辑页是一长串未分组的表单，保存、发布、停用、删除、重新读取、版本列表混在一起，不知道先做什么、做完去哪用。
- 角色（个人的做事方式、系统与插件的角色 Prompt）是"AI 怎么做事"的配置，跨项目、属于人，不是项目里的工作内容；它和「Prompt 与 Character」分在插件和设置两处。

## 导航口径（本次定下，写入 DESIGN.md）

1. **底栏是开关。** Dock 上的插件、Shelf、灵光、项目讨论：显示着它时再点一次，回到打开它之前的位置（本窗格历史里上一个不属于它的位置；没有就回项目首页）。项目首页是底，不做开关。
2. **覆盖层一定有出口。** 设置、项目设置、插件市场、能力：覆盖层芯片带关闭按钮；Esc 关闭（焦点不在输入框、没有打开的对话框或菜单时）；「上一步」关闭；在菜单里再选一次同一项也关闭。关闭后窗格原样还在。
3. **历史覆盖一切位置。** 窗格历史记录插件页、条目标签和覆盖层；按窗格存到 sessionStorage，刷新后还在。⌘[ / ⌘]（其他平台 Alt+← / Alt+→）与鼠标侧键走同一历史，不再让浏览器离开工作台。
4. **位置芯片永远说真话。** 芯片跟着当前内容所属的插件走；覆盖层打开时，切换器与 Dock 显示覆盖层本身，不再显示下面的插件。
5. **关标签回到来处。** 关掉当前标签，回到历史里上一个还在的位置；没有就回它所属插件的页面。
6. **页面状态暂存。** 插件页离开再回来保持原样（打开的条目、滚动、筛选）；只有明确回到列表（点芯片、插件自己的返回）才复位。刷新后插件页重新打开上次打开的那条记录。
7. **设置只有一份分类表。** 覆盖层与独立页读同一份；工作台里任何 `/settings/*` 链接都在覆盖层里打开，不离开外壳。
8. **角色归设置。** Characters 仍是插件（动作、发布、搜索、MCP 都由它拥有），但它的界面从插件切换器挪到 设置 › 角色，和 Prompt 放在一起；点系统或插件角色在同一覆盖层里打开它的 Prompt。

## 方案

### 第一阶段 · 外壳导航（`tab-workspace.ts`、`tab-workspace-ops.ts`、`navigation-presentation.ts`）

- ops：`normalizeLayout` 保证位置芯片 = 当前条目标签的插件；`closeTab` 支持指定回落位置。
- 客户端：历史项加入 `cover:<kind>`；历史按窗格存 sessionStorage；`goHistory` 能重开覆盖层（覆盖层注册自己的打开方式）；`leavePlugin(plugin)` 实现开关；关当前标签回到历史上一处；Esc / 快捷键 / 鼠标侧键；覆盖层芯片的关闭按钮；覆盖层标题。
- 暂存：记住每个插件表面上一次显示的是"页面"还是"条目标签"，只有从条目标签回到页面、或明确点芯片时才复位；插件页里点开的记录按插件记在本机，刷新后重开。
- 底栏：Dock 与常驻按钮的开关；切换器和 Dock 在覆盖层时显示覆盖层；菜单里的覆盖层入口标出当前并可再点关闭。

### 第二阶段 · 设置收拢

- 一份全局设置分类表（`settings-sections.ts`），独立页导航和覆盖层目录都从它渲染。
- 覆盖层支持 助理、Prompt、角色、MCP、连接器；把对应脚本改成可重复绑定。
- 独立设置页带 `?project=` 且来自工作台时回到工作台覆盖层打开。

### 第三阶段 · Characters

- manifest 的界面位置从 `navigator` 改为 `settings`（角色），工作台覆盖层里挂载已有的 Characters 表面。
- 重排列表：页头与一句话说明、三步引导、我的角色（名称、做事方式首行、状态、已发布版本）、系统与插件角色按来源分组（做什么、权限、是否改过）。
- 编辑页分组：基本 / 来源 / 工具与能力范围 / 发布到项目 / 停用与删除；固定底部操作条。

### 第四阶段 · 逐页动线

逐页核对进入、离开、打开条目、返回、空状态引导与失败恢复，问题与处理记在下方「逐页记录」。

## 实现中定下的口径

- **标签与原地打开。** 插件页里点开的记录原地打开（Goals 列表的 Goal、Feed 消息、灵光笔记、Pages 文档、表单、角色……），插件页记住它；标签留给要来回切换的工作对象（会话、Inbox 条目）和从别处打开的东西（首页、搜索、助理、链接）。没有把会话/Inbox 改成原地打开：它们本来就是工作对象，而且标签拖动、分屏、宽度分配的回归都以会话标签为样本。
- **覆盖层内的位置进历史。** 历史项写成 `cover:<kind>|<分类>[ <地址>]`；设置覆盖层每切一个分类记一步，从「角色」点进某个角色的提示词后，上一步回到「角色」，再上一步回到打开设置前的位置。
- **覆盖层怎么重开由拥有者登记。** `registerCover(kind, open(place))`：设置/项目设置由设置目录脚本登记（能带分类和地址），能力由底栏脚本登记，市场用默认。
- **进入项目（非刷新）落在首页，并关掉上次留着的覆盖层**；刷新保持原样。
- **底栏托盘。** 用户 2026-09-30 追加：左右两组加外部容器。实测后采用：桌面宽度下左组（Dock 菜单 + Dock）与右组（Shelf、灵光、讨论）各一个与输入框同高的凹陷色托盘；讨论按钮移进 `.bar-residents`；手机宽度不加（第二行本身已成组，托盘让行距过紧）。
- **角色的挂法。** Characters manifest 1.6.0（兼容 1.0–1.5）：工作台页面改为 `stage` view，新增 `settings` view（order 35，排在「助理」后），页面根标 `data-settings-page="characters"`。设置覆盖层直接挂载这块已绑定的页面；独立 `/settings/characters?project=<id>` 302 回 `/projects/<id>/?settings=characters`，没有项目时列出项目。旧的标签/插件页状态里残留的 characters 在恢复时清掉；搜索、市场「打开」、旧链接都改为打开设置 › 角色。
- **提示词页改名。** 「Prompt 与 Character」→「提示词」；角色聚焦时横幅带「返回角色」。页头说明从标题行里移出（之前标题被挤成两行）。
- **单一分类表。** `settings-sections.ts`：本机（界面与语言）· AI（模型设置、助理、角色、提示词）· 工具与接入（AI 与执行工具、能力）· 系统（诊断）· 插件（Coding、Shelf、Goals…）。能力行打开能力覆盖层。
- **可重复绑定。** 提示词、助理两页脚本改成 `globalThis.molisWorkBindPromptSettings(root, {search, hash})` / `molisWorkBindAssistantSettings(root)`，独立页加载时绑定一次，覆盖层每次挂载时绑定（按 `data-*-bound` 去重）。
- **插件页里打开的记录也是历史的一步。** 历史项写成 `plugin:<插件>|<记录>`：点记录行、或插件自己展开一条记录（如「记下」新建后直接打开，按插件标出的选中行认出记录），都记一步；插件自己的返回箭头或位置芯片回到列表，再记一步 `plugin:<插件>`。上一步 / 下一步走到这些项时重开那条记录或回到列表。壳自己复位列表（首次显示、从标签回来）不产生历史，也不会被一条等着重开的记录反悔（明确的选择会取消等待中的重开）。只在单窗格生效；分屏时各窗格在 iframe 里，不追踪。
- **刷新后回到那条记录。** 这条规则同样覆盖新建后直接打开的记录；四个插件 e2e（Dataset / Forms / PPT / Pages）原来在刷新后点列表行把记录重新打开，手机宽度下列表收起就点不到——改为断言「刷新后记录自己回来」。
- **给其他会话的口子。** `document` 事件 `molis-work:place-changed` {paneId, place, previous}（动态交互线要用）；`molis-work:open-settings-section` {section}。
