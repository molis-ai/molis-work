# 交付流程：每个插件都走这八步

官方插件（手写、接进产品）和插件创作台生成的插件走同一套流程，只是每一步由谁来做不同。跳步的代价总是在验收时才看见，所以不要跳；用不到的产物可以省，但那一步的判断要做。

| # | 阶段 | 做什么 | 做完的标准 |
|---|---|---|---|
| 1 | 弄清需求 | 用 [SKILL.md](SKILL.md) 的四问：人在看什么、什么时刻、点下去发生什么、还要给谁用 | 四问都答得出。答不出的只问一轮，问真正会改变做法的点；不问样式和示例内容 |
| 2 | 比较方案 | 给 2–3 个在页面结构或关键行为上真正不同的方案，各写使用路径和取舍 | 每个方案能说清"最适合谁、放弃了什么"；不是换名字 |
| 3 | 写说明书 | 功能清单（每件事的输入输出）、每件事的例子、界面由哪几块组成、验收步骤 | 说明书自洽：例子对得上输入输出，验收从空数据开始能走通，每件事都有界面入口 |
| 4 | 选定能力与组件 | 每件事要用的平台能力、每块界面用的 UI 目录组件，从合法候选里定下来 | 只用能力目录和 UI 目录里有的；用到本项目还没启用的插件，开工前由用户确认启用 |
| 5 | 绘制与接通 | 界面按说明书放组件；功能写成代码并接上能力 | 每件事单独过关后才接通；不能用的部分明确标"待接通" |
| 6 | 检查 | 合同未被改、类型、打包、越权、测试与例子、隔离运行 | 全部关卡通过；失败原因原文可见 |
| 7 | 验收 | 像真人一样按验收步骤点一遍 | 主路径、空态、出错、窄屏都走过；全部通过才可以发布 |
| 8 | 发布与升级 | 递增版本，声明数据兼容；安装时列出权限 | 升级保留数据；卸载可选保留或删除；旧版本不被静默破坏 |

## 谁来做

| 阶段 | 官方插件 | 生成插件（插件创作台） |
|---|---|---|
| 1–3 | 作者写 `specs/{slug}/spec.md` | 主线设计出方案和说明书（格式见 [generated-design.md](generated-design.md)）；宿主检查自洽，能自动整理的写明整理了什么 |
| 4 | 作者按 [ui.md](ui.md) 和 [capabilities.md](capabilities.md) 选 | 能力在写说明书之前定：方案里写的每个能力，由系统算出同一提供方、同读写类别、同样贴近这项功能的候选，Jev 选定（Jev 不可用时沿用主线设计的选择）。组件在说明书之后定：Jev 从合法候选里挑，只有一个时按规则，拿不准时问用户 |
| 5 | 作者写 Manifest、UI、客户端、Host 接线 | UI Agent 放组件；代码 Agent 按 [generated-code.md](generated-code.md) 写每件事的代码与测试 |
| 6 | 测试 + 类型检查 + `molis-work plugin validate` | 宿主关卡 G1–G6（合同冻结、类型、打包、越权、测试与例子、沙箱运行） |
| 7 | 浏览器走一遍主路径 | 宿主用无头浏览器按验收步骤走一遍（G7） |
| 8 | `version` + `upgrade_compatibility` | 发布版本、安装授权、升级、卸载由创作台完成 |

## 按模型能力伸缩

流程固定，每一步用什么做随当前模型的能力增减；缺某种能力就跳过对应的增强，主线不变，也不报错。

- **只有文字**：方案阶段用真实组件实时预览每个方案。
- **能出图**（图片插件里配置了生图服务）：方案阶段另给每个方案一张效果图，每个方案只请求一次，失败不重试（可能已经计费）。画图不耽误选择，用户可以先选。效果图只定方向；最终样子以用真实组件画出的预览为准，效果图里出现目录没有的东西时，以预览为准并说明。
- **能读图**：验收后加一轮截图走查，看空态、密度、对齐、文案是否符合 [ui.md](ui.md)。

## 什么算"验过了"

- 单元测试通过 ≠ 可以发布。改了可见界面，要在浏览器里把主路径真的点一遍。
- 用了平台能力的功能，要在真实安装后用一次真实能力（试用和验收阶段用的是替身；联网在安装前只真的读取）。
- 声称完成时附上证据：跑了什么、看到了什么、哪一步没验到。没验到的要说出来。
