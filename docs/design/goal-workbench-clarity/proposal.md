# Goal 工作台：目标节点直接在画布上展开

状态：历史方案 v6，已由 [Goal 画布工作区开发需求书](../../../specs/goal-canvas-workspace/spec.md) 取代。2026-09-12 用户明确要求开发，并补充「Goal 展开状态不能挪动」。以下保留方案演进记录；其中展开后拖动、多个 Goal 同时展开、标题栏拖动等描述不再生效。已交付的 HTML 示意不再修改。

## 1. 方向与边界

进入项目先看目标之间的关系，选择一个目标后在同一工作空间里看现状、读记录、处理事项、打开工具。用户不用在看关系、读目标、继续执行之间反复跳页。

- 保留：左上项目入口、左侧目标列表与父子层级、依赖关系、真实成果与来源、已有决定与完成检查、终端的目标归属。
- 替换：项目主视图改为无限画布；Goal 节点本身展开为更大的工作台，Hero、统一时间线和 TUI 都属于这个画布对象。
- 忽略：旧版「聚焦 / Runtime」互斥模式、有限网格、打开 Goal 必须离开关系图、时间索引与正文永久分列，以及前三版的固定页面或右侧详情栏结构。

「直接展开」按用户截图的含义执行：小节点在自己的画布位置变成完整工作台，依赖线改连展开后节点的边界，拖动和缩放时内容随节点一起移动。页面固定结构只有左侧列表和主画布。每个展开节点内部，左侧默认约 70% 放 Goal Hero 和 Terminal；右侧默认约 30% 放 Timeline，从节点内容顶部贯穿到底部，与左区等高。Hero 只属于左区。用户可拖动分隔线调整比例，不把 70/30 固定为不可修改的宽度。允许多个 Goal 同时展开，各自保持内容、位置和会话归属。

本轮不改真实 Goal 内容、数据库协议、执行授权、终端连接，也不扩展为自动派单或全站重做。

## 3. 项目入口与节点内工作台

### 左侧：项目和目标列表

左上是当前项目与项目切换入口，下方保留目标列表。列表表达父子层级，适合按名称定位；画布表达目标之间如何配合。

点击项目或「项目画布」回到总览。点击列表目标或画布小节点，都先记住当前视野，再展开这个节点并将它居中显示，几乎铺满右侧主内容区。目录、节点摘要和展开后的 Hero 使用同一份当前状态。

首次进入项目适配全图，之后恢复该项目上次的视野。查看其他项目或目标，不自动启动 AI、不改变现有终端归属。

### 中央：持续存在的关系画布

画布始终占用左侧列表以外的全部空间。点击 Goal 后，节点尺寸按当前主内容区的宽、高确定，视野同步移到这个节点，四周保留约 18px 的窄边距；主内容区大小变化时随之适配。这里的全屏范围仅是主内容区，桌面的左侧列表和项目栏保留。节点仍是画布对象，依赖线跟随实际边界重绘；放大阅读时收起画布底部工具条，避免遮住终端输入。

节点展开时若与邻居重叠，只让相邻节点必要地让位，不改变依赖或父子关系。收起时恢复本次自动让位且未被用户继续拖动的邻居位置。保留其他 Goal 的展开状态和各自内容。

右上角「收起」将工作台恢复为画布小节点，并恢复点击展开之前的平移位置和缩放倍率。已经调整的左右比例与终端草稿保留。多个节点仍可同时展开：选中另一个 Goal 会将它放大到主内容区，原 Goal 的展开状态与会话保留。用户手动平移、缩放后可以看到其他节点，也可用节点角落的展开按钮重新放大查看。标题栏负责拖动，正文可选择、滚动、展开事件或操作终端。

正常桌面列表约 180–220px，工作台默认使用主内容区扣除四周窄边距后的可用尺寸，不再采用固定的 740px 展开宽度。内部左右两区初始比例为 70/30，分隔线支持拖动和键盘左右方向键；比例按节点保留，选择或收起另一个节点不会覆盖它。生产实现需将比例随个人布局保存；本轮只保留在示意当前会话内。最小宽度保证终端和时间线仍能操作。较小屏幕先收起列表，极窄屏节点内部上下排列，节点仍位于画布里。

### 节点内部：目标工作台

展开节点内部顶部的紧凑标题栏显示 Goal 名称，右上角是展开/收起控制。在默认放大状态主要显示「收起」，离开放大视野后可以用展开图标重新适配主内容区。标题栏下方，左区上方是紧凑 Hero，下方 Terminal 填满剩余高度；右区整条 Timeline 与左区等高，拥有独立滚动区。Hero 的横向边界到内部的分隔线为止。TUI 可单独收起，重新展开时保留草稿，时间线不移动到左区。关闭节点只是改变画布呈现，不完成目标、不停止执行。

节点内部使用有界阅读区，Timeline 与 Terminal 各自滚动，不推动另一侧内容或平移画布。时间线标题和终端输入保持在各自区域内。拖动分隔线只分配宽度，不改变整个节点高度、目标关系、展开事件或终端输入。打开长成果在该节点内阅读，返回后保留事件位置。本轮示意已提供随主内容区适配的等高工作台、独立滚动、内部宽度拖动和收起返回；生产布局持久化与真实会话恢复待高保真切片验证。

## 4. 无限画布的阅读与操作规则

### 先后、并行和父子关系

默认沿依赖方向从左向右布局。箭头从提供前置成果的目标指向依赖它的目标。没有互相依赖的分支上下错开，表示可以并行；纵向位置不表示重要程度或必须先做。不显示 L0 / L1 / 消费层级。

父子关系表达拆分，依赖关系表达先后：前者使用可折叠的包围分组，后者使用箭头，不能混成一种线。折叠父目标后显示子目标摘要与跨组关系，展开回到原位置。没有父子关系的独立目标不硬塞进虚构父 Goal。

默认保留已经完成的前置节点，以较轻样式显示，用户仍能看懂成果从哪来。新进展只更新内容和状态，不自动重排整图；新增目标尽量安排到相关位置。用户主动整理布局时才整体整理。

依赖图表达结构，不自动等于调度。前置目标仍在推进，不代表后续完全不能准备；可以并行也不意味着已经启动多个 Agent。

### 节点信息与路径

收起的节点只保留目标名、一个主状态、一句关键进展或下一步，以及有依据的完成要求计数。展开后就在同一个节点内呈现 Hero、历史和 TUI。缩小到总览时临时隐藏工作台细节，保留可读名称与状态；重新靠近时恢复，不丢失展开状态和输入。

选中节点时突出它的前置链和后续链，无关节点与线适度淡化。选中边框与状态颜色各自表达选择和进度。依赖密集时先看相关路径，不让每条边都配永久长标签。选中依赖后按需显示「A 的结果用于 B」和已有说明；数据中没有记录原因或具体成果时，不臆造理由。

### 操作

| 操作 | 结果 |
| --- | --- |
| 拖动空白 / 触控板平移 | 移动画布视野，没有固定页面边界 |
| 捏合或 Ctrl / ⌘ + 滚轮、缩放按钮 | 围绕手势位置缩放，保持方向感 |
| 看全图 | 同时按可用宽度与高度适配目标范围，保留边距 |
| 定位当前目标 | 找回选中节点，保留详情内容 |
| 点击小节点 / 左侧目标 | 展开该 Goal，默认居中占满大部分主内容区，四周保留窄边距 |
| 拖动节点标题 | 移动整个工作台，内容和连线一起移动；依赖关系保持原义 |
| 拖动节点内部的纵向分隔线 | 调整左侧 Hero + Terminal 与右侧 Timeline 的宽度，默认 70/30，双方保持等高 |
| 右上角收起工作台 | 恢复小节点和点击前的画布视野，保留内容、左右比例与会话 |

日常浏览不出现容易误拖的连线把手。修改依赖从节点的「关系」操作进入，明确选择前置目标、预览关系再保存；移除关系有明确动作，不靠误拖触发。

若真实数据存在循环或不可解析关系，展示具体冲突，不编造先后顺序。个人布局的保存方式、既有依赖编辑协议和循环约束，需要在开发前做定向调查。

## 5. Hero：回答现在怎样、需要我做什么

Hero 保持紧凑，按顺序呈现：

1. 目标名与一个当前状态。
2. 一句预期结果：完成后用户能做什么。
3. 可核对的进度，例如「4 项完成要求，3 项已满足，1 项待验证」。展开可看每条要求与依据。没有要求时不虚构进度条，也不阻止记录或工作。
4. 当前需要本人处理的具体事项；没有待办时显示一个下一步。
5. 按真实能力命名的工具入口：「打开 Codex 对话」或「打开 Codex 终端」。只有确认可恢复已有会话时才写「继续对话」。

「目标与完成要求」在 Hero 内按需展开，包含要做到什么、怎样才算完成、范围与限制。子目标完成数与父目标自身完成要求分开表达。

Hero 的待确认计数只是时间线未处理事项的索引，点击定位原事件，不另建一份“需关注”内容面板。

读右侧旧事件时，左侧 Hero 继续描述当前情况，不随时间线滚动。Hero 保持紧凑，给下方 Terminal 留足工作空间。

## 6. 一条时间线容纳成果、问题、决定和进展

用户界面名称为「进展记录」。没有「成果 / 需关注」页签或筛选区，它们通过事件类型和正文中的真实内容融入同一条时间线。

默认最新在前，按日期分组。每条摘要是带色类型、具体标题、最多一句结果；时间与参与者退到次要层级。点击原位展开，收起恢复短行。

| 事件 | 摘要示例 | 展开后看什么或做什么 |
| --- | --- | --- |
| 黄 · 需你确认 | 已有文件，是否保留？ | 原因、选择的影响、明确选择按钮 |
| 蓝 · 提交成果 | 项目创建流程已更新 | 改了什么、演示或文件、相关依据，直接打开成果 |
| 绿 · 验证通过 | 创建与项目切换检查通过 | 验证范围、结果、仍未验证的部分 |
| 红 · 执行中断 | 工具连接意外断开 | 最后可靠进展、是否已恢复、继续入口 |
| 蓝 · 已恢复 | 工具连接已恢复 | 从哪里继续、尚待检查什么 |
| 灰 · 添加备注 | 先保留手动创建入口 | 备注原文，不暗示自动改要求或指挥 AI |
| 绿 · 目标已完成 | 首次使用范围已确认 | 当前完成结论与相关成果 |

成果在对应事件内直接显示文件、页面、截图或报告的清楚名称与打开入口，不让用户去另一页找。长内容可独立阅读，保留来源与原文。

待确认事件就地处理。处理后保留原请求并标记「已处理」，关联后续决定；新决定仍按时间进入记录流。Hero 随当前有效事项更新，过去的请求不反复召唤用户。

普通连接、保存等低价值系统事件合并折叠；失败、中断、要求变化、决定和完成结果保持可见。旧数据无法可靠归类时写「历史记录」并保留原文，不根据标题含“完成”等词猜测效果。

实时更新不抢阅读位置、不清空展开状态或输入；阅读旧记录时提示有新进展，保留返回位置。

## 7. TUI 属于画布上的这个 Goal 节点

展开 Goal 时显示它的 TUI，位于节点左侧、Hero 下方，填满左区剩余高度；右侧 Timeline 独立贯穿全高。用户可单独收起或再次展开 TUI，或拖动分隔线给它更多宽度。整个工作台随节点移动和缩放，不挂靠屏幕边缘。

终端顶部显示工具名、会话状态、所属目标。工作目录与连接细节按需查看，不设置独立常驻环境大面板。工具运行状态与 Goal 状态分开。

展开/收起只是显示操作，启动/终止执行使用明确动作。多个 Goal 同时展开时，每个节点只展示自己的会话或连接入口；选择其他节点不改绑会话、不发送原节点输入。没有可恢复会话时按真实能力新建或提供继续说明。需要大终端时可放大节点或临时聚焦这个节点，保持明确的返回位置。

AI 在现有工具里读取目标、完成要求、前置成果、既有决定和未解决问题，产出工作记录、成果、验证、问题或调整建议。用户在对应事件处审阅和干预。Molis Work 不从打开页面推断 AI 已经开始工作。

断开或超时展示最后可靠状态和继续方式；重新连接不清空记录。重启恢复工作位置，但不自动启动执行。

## 8. 文案与状态

| 当前表达 | 建议表达和去向 |
| --- | --- |
| 聚焦 | 移除含义不明的模式名，直接「展开目标」或「定位目标」 |
| Runtime | 使用具体工具名和「打开对话 / 打开终端」 |
| 工作规划 | 拆开：完成要求在 Hero，日常动作在时间线，记录类型与模板在设置 |
| 目标说明 | 「目标与完成要求」，正文用「要做到什么」「范围与限制」 |
| 补充一条 | 实际保存备注时写「添加备注」，按钮写「保存备注」 |
| 处理 Concern | 「查看问题」「标记已解决」「查看待确认事项」等具体动作 |
| 显式收尾 | 「检查并完成目标」，展示已通过与还缺什么 |
| 显式继续 | 「重新开始这项目标」，保留上一轮结果 |
| 设为当前 Goal | 「设为当前目标」，与仅查看目标区分，不改变已有终端归属 |
| depends_on / part_of / L0 | 用户界面使用「前置目标 / 子目标」，技术字段放原始信息 |

目录、画布和 Hero 共用当前状态判断：

- 灰「待开始」：有新建事实且尚未开始；历史不足则写「进展待更新」并附最后记录时间。
- 蓝「推进中」：有支持当前推进情况的事实，不等于工具此刻在运行。
- 黄「需你确认 / 待你验收 / 有待解决」：分别对应当前有效决定、已经提交且需要本人验收的结果、真实未解决事项；说明是否影响其他工作。
- 绿「已完成」：当前完成结论已生效。
- 灰「已取消 / 已归档」：区分停止工作与收起目标。
- 红：用于真实执行失败、中断、验证未通过等具体事实。

颜色同时配文字。允许记录是能力，不是进度，不能把「可记录」机械替换成待开始或推进中。

「提交成果」「验证通过」「你已验收」「目标已完成」分别表达不同事实。AI 报告通过不能冒充用户验收，保存完成请求不能直接显示目标已完成。没有完成要求不阻止记录或准备工作。

## 9. 关键用户路径

1. 回到项目：看全图理解前置、并行和未决事项 → 点目标 → Hero 看当前情况 → 时间线看依据或作决定 → 需要时在 TUI 继续。
2. 新项目：空画布直接创建第一项目标，只需说明想实现什么，不先配置事件类型或规划模板；创建节点并展开详情，给一个具体开始动作。
3. 更新工作：明确选择记录进展、添加备注、记录问题或提交成果。表单说明保存结果；备注不自动发送给 AI 或修改要求。
4. 处理确认：Hero 定位原事件 → 看原因和影响 → 明确选择 → 原事件已处理，新决定入时间线。请求过期时说明实际变化，已有有效决定不重复索取。
5. 完成目标：检查要求与依据 → 完成人工验收（确有要求时）→ 真实完成结论生效 → 节点和 Hero 一致更新，成果留给后续目标使用。
6. 失败恢复：保存失败保留输入；工具断开保留记录和归属；重启恢复位置但不自动启动执行。

## 10. 实施边界与验收

后续开发先形成正式 spec，再做小而真的高保真切片：列表、无限画布、目标详情、统一时间线和目标内 TUI。旧图的统计与行动队列不作为本次主视图默认内容。

模块和依赖：

1. 工作空间壳：固定为列表和画布；保存项目视野、选中项和各节点展开状态。
2. 关系画布：读取目标摘要、父子与依赖关系，负责位置、尺寸、视野、选中和导航；节点展开或尺寸改变后更新连线并处理必要的邻近避让，拖动位置不写回依赖。
3. 统一呈现数据：从有效记录与完成判断得到同一份状态、进度和当前事项，供列表、节点和 Hero 使用。
4. 节点工作台：左侧 Hero + Terminal、右侧全高 Timeline，默认 70/30 且可调整；每个节点消费自己的目标和事件，提供成果阅读、记录、决定和完成检查，复用真实读写协议。多个节点的阅读状态、输入和布局比例互不覆盖。
5. 节点内会话区域：按真实目标归属展示与恢复终端，草稿与进程不随画布选择变化；连接状态独立于目标状态。

先对齐布局与交互，再接真实读写，最后验证 TUI、重启与异常恢复。不能只改按钮名称或 CSS，却保留互斥模式和矛盾状态。
