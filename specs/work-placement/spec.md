# 放在哪里、属于哪里、从哪里继续：插件使用闭环与产物归属

状态：执行中（2026-09-28 起）。目标完成等级**内部完整**。本文件是本任务唯一需求书与实施方案；进度与证据在第 12 节，未完成与受阻在第 13 节。

完成等级分开记：**工程通过**（构建、定向测试）／**真实场景通过**（真实 Host、真实插件数据、浏览器操作、真实文件被外部软件打开）／**用户验收**（只由用户本人给出）。

工作树 `~/code/goalboard-placement`，分支 `feature/work-placement`，基于 8aef07b8；搜索分支已以 #96 合入 main（22f383cb），main 目前与本分支基线内容相同。合入顺序：助理 → 本分支；提交 PR 前再同步一次 main 与助理分支（第 10 节）。主检出有其他会话未提交的改动，不在主检出工作。

## 1. 要解决什么

用户用 Molis Work 完成一件事时，常在两处断掉：

1. **插件给出的不是能用的结果。** PPT 只能导出内部 JSON；问卷“标记已发布”只改本机状态，别人没法填；数据表、灵光、图片的结果停在插件里，进不了下一步工作。按钮名称与完成提示比真实能力大。
2. **每次都要重新判断“放哪里、属于哪里”。** “个人插件”一词同时表示“每个项目都默认开着”和“内容属于我个人”，实际上 Pages、问卷、数据表、PPT、灵光、图片、炼金术士、工作流程的内容按**当前项目**分区，Shelf、Cognia、Jelly、角色才真正属于个人。没有项目时什么都做不了（“空白开始”也要先起项目名）。把个人材料用到项目，只有“再存一份到项目成果”一种做法，看不出这是复制。保存后只见插件内的一条记录或一个内部 ID。

判断标准（全部以真实操作验证，第 11 节）：

- 每个插件承诺的结果，用户能以承诺的形式真正拿到并用起来（演示文稿能放映、能被 PowerPoint/Keynote 打开；问卷能让别人填、答卷能汇总与导出）。
- 任何创建、导入、生成、保存，用户事先知道会存到哪里，事后看得到存在哪里、和哪项工作有关、谁能看到，并能改。
- 没有项目也能完成一件完整的工作，之后再整理到项目。
- 同一对象从个人空间、项目、插件目录、搜索、Goal 进入时是同一个对象，显示同一身份和来源；移动、复制、引用、关联行为明确，删除和移除关联的后果如实显示。
- 中途失败、切换页面、关闭或重启后，已做的工作不丢，恢复路径清楚。

### 2.2 没有项目时

- `/` 没有项目时重定向 onboarding；“空白开始”要求先给项目起名（实测 2026-09-28）。有项目后 `/` 是“选择一个项目”，底栏助理可切“个人”，但没有任何插件页面可用。
- Web 工作台只在 `/projects/<id>/` 下存在（`apps/local-host/src/web-routing.ts`）。
- 架构文档把“个人空间”列为 Identity & Space 的一种 Space（`docs/goalboard-product-family-and-module-architecture.md` 4.1），Context Ledger 与 Artifacts 已有 `personal` 范围，但产品里没有“个人空间”这个可去的位置。

## 3. 统一语义

### 3.1 四个概念

| 概念 | 含义 | 一个对象有几个 | 例子 |
| --- | --- | --- | --- |
| **位置**（存放位置） | 对象存在哪里、归谁管、跟着谁的生命周期 | 恰好一个：**个人空间**或**某个项目** | 这篇文档在“项目「Q4 新版发布」” |
| **访问范围** | 除你本人外，哪些工作环境能读取它 | 由位置决定 | 个人空间分区（Pages、PPT、问卷、数据表、灵光、图片等）：只有你；只存个人的插件（Shelf、Cognia、Jelly）：你，以及你授权使用该插件的项目环境（它们是 Home 级能力，任何项目获授权后都能调用），界面写“只有你和获授权的助理”；项目：该项目里的助理、Runtime、工作流、MCP 客户端 |
| **关联** | 对象和某项工作（项目、Goal、会话、助理工作、另一对象）有关 | 零到多个；不改位置，不改访问范围（“用于项目”除外，见 3.3） | 这份 Shelf 材料用于项目 Q4；这篇文档挂在 Goal「发布说明」上 |
| **入口** | 从哪里能打开它 | 多个；不代表归属 | 插件目录、项目首页“关联资料”、Goal 的“绑定资料”、搜索、助理工作视图、完成提示 |

**个人空间**是这台电脑上只属于你的位置。没有项目也能在里面用 Pages、问卷、数据表、PPT、灵光、图片等全部插件；Shelf、Cognia、Jelly、角色、实验的内容一律在个人空间。项目是和别人（或别的工作环境）共同推进一件事的位置。Goal、会话是**工作**，不是存放位置——从 Goal 发起的产物存在 Goal 所在的项目里，并关联到这个 Goal。

界面上位置一律写成“个人空间”或“项目「名称」”，不出现内部 ID 或“插件名 + 记录”。

### 3.2 五种操作

| 操作 | 身份 | 原对象 | 访问范围 | 界面名称 |
| --- | --- | --- | --- | --- |
| **移动** | 不变（同一 id，所有关联、引用继续有效） | 离开原位置 | 变为新位置的范围；变窄时先说明谁将看不到 | “移到…” |
| **复制** | 新对象，记“复制自” | 不变，之后互不影响 | 新位置的范围 | “复制到…” |
| **转成** | 新对象（另一种插件），记“来自” | 不变，显示“已转成…” | 新位置的范围 | “转成文档”“建成 Goal”“存成数据表” |
| **固定版本** | Artifacts 里一份不可变版本，记来源与版本号 | 可继续编辑，之后可再存一版 | 所在位置的范围 | “存为固定版本”（Shelf：“存一份固定版本到项目”） |
| **关联** | 不变 | 不变 | 不变；“用于项目”见 3.3 | “用于项目…”“关联到 Goal…” |

**引用**是对象内部指向另一对象（文档提及、Coding 的“＋材料”、工作流交接记录、答卷来源）。读取永远回到所有者；所有者删除或不可用时，引用处显示“原对象已删除/暂时读不到”，不静默换成别的版本。

### 3.3 跨范围：把个人的东西用到项目

“用于项目「X」”默认是**关联**：项目 X 的首页“关联资料”列出它，你在项目里能直接打开；它仍在个人空间，你在个人空间里改，项目里看到的是最新内容。个人空间分区里的对象，项目里的 Runtime、项目助理、工作流、MCP 客户端**不能**读取正文，需要时用“移到…”放进项目；Shelf 材料另有“存一份固定版本到项目”（复制到项目材料，之后改原件不影响这一版），界面并列给出两种选择与后果。Shelf、Cognia、Jelly 的内容是否能被项目环境读取，取决于你给该插件的授权，界面照此说明。不默认复制，也不静默改变原对象的访问范围。

移动到另一个位置时，如果它已被别处关联，先列出关联并说明移动后仍然有效；从项目移回个人空间会让项目环境读不到，先说明。

### 3.4 默认位置规则

| 从哪里发起 | 默认位置 | 自动关联 | 用户看到什么 |
| --- | --- | --- | --- |
| 项目工作台里的插件、项目首页 | 当前项目 | — | 新建处写“存到 项目「X」”；完成后可一键“移到个人空间” |
| 某个对象上（Goal、文档、Feed 消息、灵光、答卷…） | 该对象所在位置 | 关联到该对象（Goal 走 Goal 输入绑定） | 完成提示写明位置与关联，可移除关联 |
| 个人空间、`/`、个人范围助理 | 个人空间 | — | “存到 个人空间” |
| 只存个人的插件（Shelf、Cognia、Jelly、角色、实验） | 个人空间 | 在项目里操作时可“用于本项目” | 位置条写“个人空间” |
| 有歧义：个人对象要转成项目分区的对象，而你正在项目里 | 给简短选择：当前项目（推荐，写明理由）／个人空间 | — | 两个按钮，不静默猜测。当前界面不会出现这种情况：个人空间分区的对象只在个人空间里打开，转成默认存到原对象所在位置；Home 级插件（Shelf、Cognia、Jelly）目前不提供转成。以后增加时按此规则 |

允许先放下、以后整理：任何位置的对象都可以之后“移到…”“用于项目…”“关联到 Goal…”，不要求一开始分类正确。

### 3.5 生命周期与异常，按真实状态反馈

| 情况 | 要求 |
| --- | --- |
| 未保存 | 插件已有“尚未保存/保存中/保存失败”状态继续显示；位置条同时显示；关闭标签前有未保存内容时按插件既有保护处理 |
| 删除原对象 | 关联它的项目首页、Goal 绑定、复制品的“复制自”处显示“原对象已删除”，保留删除前的标题，可一键移除关联；不出现能点却打开空白的入口 |
| 移除关联 | 只去掉关系，不删除对象，不影响复制品与固定版本；有历史 |
| 移动后 | 旧位置的入口按对象身份找到新位置（位置索引），显示“已移到 X” |
| 来源不可用（插件停用、项目已删、读取失败） | 显示“暂时读不到”与原因，和“已删除”分开；不把不可用说成已删除 |
| 跨范围引用 | 项目里显示“来自个人空间，只有你能打开”；从项目环境（Runtime/MCP）读取被拒时给出这句话 |
| 复制品 | 显示“复制自 个人空间《原标题》”，原对象删除后仍保留这句话与“原对象已删除” |

## 4. 创建、工作中、完成、再次进入的共同规则

1. **创建或导入时**：入口处写明“存到 <位置>”；导入/生成说明会得到什么（如“导入后成为可编辑的文档”“生成的是 PPTX 文件，会下载到浏览器的下载位置”）。
2. **工作中**：打开的对象在插件标题附近有**位置条**：`位置 · 访问范围 · 关联 N · 保存状态`。点开是位置面板：当前位置、谁能看到、关联的工作（可打开、可移除）、操作（移到…、复制到…、用于项目…、关联到 Goal…）。
3. **完成时**：插件发出完成事件，工作台显示**完成提示**：做成了什么、存在哪里（或文件去了哪里）、适合的下一步（打开、继续编辑、用于项目、移到…、导出）。导出类写实际格式与去处；固定版本写“项目成果 · 第 N 版”并能打开。
4. **再次进入**：从插件目录（按位置）、项目首页“关联资料”、Goal“绑定资料”、搜索、完成提示都能打开同一对象；打开后位置条相同。
5. **按用户目的组织**：对象上的“下一步”来自同一套协议：工作流内容站的 `receive`（转成文档等）、放置协议（移动/复制）、Goals（建成 Goal、关联到 Goal）、插件自己的导出。页面不各自手写跳转目标。

## 5. 公共层与插件的分工

| 事 | 负责方 | 合同 |
| --- | --- | --- |
| 个人空间这个位置：登记、`/` 与项目切换中的入口、onboarding“空白开始” | Local Host（项目目录）＋ Workbench | 保留登记项 `project_id = "personal"`，显示名“个人空间”；不改项目表结构（`data_class` 的 CHECK 约束不动），按保留标识判断；不可删除、不可改名；卸载按用户数据保留 |
| 位置、访问范围、关联、移动记录、复制/转成来源 | 新横向服务 `horizontal/placement`（只依赖 contracts），Host 装配 | 消费合同 `services/placement.ts`：`placement.describe / spaces / related / locate / link / unlink / move / copy / convert / goals / goal.bind / create`；关系写入 Home 级 Context Ledger（`{home}/placement/placement.db`），语义所有者 `module:placement` |
| 对象能否移动、复制，怎样移动 | 各插件 | 提供协议 `platform/placement.ts`：`molis.placement.move.v1`、`molis.placement.copy.v1`（按 `input_type/output_type` 发现，与对象读取、搜索条目同一套协议型动作机制）；只对 `user` 开放 |
| 对象当前事实（存在、标题、版本、所属 Goal/会话、打开位置） | 各插件 | 已有 `*.subject.read`；缺的补上 |
| 关联到 Goal | Goals | 扩展 Goal 输入绑定到插件对象（`source_type: "plugin_object"`，关系边目标 `module: "plugins"`），新增 `goals.inputs.bind`/`goals.inputs.release` |
| 转成 | 接收方插件 | 已有工作流内容站 `receive`；来源关系由放置服务记 `placement.derived_from` |
| 位置条、位置面板、完成提示、“存到…”标签、项目首页“关联资料” | Workbench | 读 `data-assistant-context` 得到当前对象；插件用 `molis:placement-result` 事件报告完成；插件在需要处放 `data-placement-slot` |
| 导出、放映、填写、汇总等插件自己的结果 | 各插件 | 插件内实现，完成时发 `molis:placement-result` |

不做：不强制统一存储、不合并插件页面、不改插件表结构以外的业务模型；不为放置另建权限表（访问检查沿用动作目录的调用者权限）；不复制系统能力到插件里。

## 6. 各插件闭环核对与本任务处理

“纳入”列写本任务要补的；“无需调整”写依据。

| 插件 | 承诺 | 当前断点（按用户目的） | 本任务处理 |
| --- | --- | --- | --- |
| **PPT** | 写幻灯片、预览、交付演示文稿 | 只能导出 JSON（按钮写“导出 JSON”）；不能放映；不能得到 PowerPoint/Keynote 能打开的文件 | 纳入：放映模式（全屏、键盘翻页、讲者备注）；导出 PPTX（本机生成，含标题、要点、备注、配色）；打印/存为 PDF；JSON 收进“更多·导出数据”；位置条、移动/复制、完成提示 |
| **问卷** | 建问卷、让人填写、看结果 | “标记已发布”只改本机状态，不产生任何可填写的东西；结果只有份数和原始 JSON；答卷不能进入后续工作 | 纳入：“开始收集/停止收集”（诚实写明在这台电脑上收集）；填写模式（整屏，逐人提交）；导出填写页（单个 HTML 文件，别人在自己的浏览器里填，生成答卷文件发回）＋导入答卷；逐题汇总；导出 CSV；“存成数据表”；位置条、移动/复制、完成提示。外网公开链接不做（第 9 节） |
| **数据表** | 改表格、导入、留版本 | 只能粘贴 CSV；结果只能导出文件 | 纳入：从文件导入 CSV；接收问卷结果；位置条、移动/复制、完成提示 |
| **Pages** | 写文档、导入、导出、挂 Goal、存成果 | 导出只有 HTML；导入完成后不说存在哪里；个人文档无处可放 | 纳入：导出 Markdown、打印/存为 PDF；位置条、移动/复制、完成提示；作为“转成文档”的接收方记录来源 |

## 7. 合同

### 7.1 放置协议（插件实现）：`packages/contracts/src/platform/placement.ts`

- `defineObjectMoveAction(capabilityId, kinds, title, permissions)`：`input_type: molis.placement.move.input.v1`，输入 `{ subject: {kind,id}, to_project_id }`，输出 `PlacementResult = { subject, project_id, revision }`。在对象当前所在项目（调用者项目）执行，`bindObjectMoveHandler` 把调用者项目作为 `from_project_id` 交给处理器；对象改到目标项目分区，身份不变；有进行中的发布等不能移动的情况拒绝并说明原因。只对 `user` 开放，项目作用域。
- `defineObjectCopyAction(...)` / `bindObjectCopyHandler`：`molis.placement.copy.*.v1`，输入另带 `request_id`，输出新对象；同一 `request_id` 重试返回同一副本。
- `inspectActionDeclarations` 用 `placementDeclarationProblems` 校验：受众只能是 `user`、作用域是项目（移动另可为 Home）、schema 与协议一致。
- Home 作用域的移动（`defineObjectMoveAction(..., "home")` + `bindHomeObjectMoveHandler`）：给把对象存在 Home、自己记“属于哪个项目”的插件（Todo）。放置服务在 Home 调用它，`to_project_id` 是新的归属（`personal` 为个人空间）；对象身份与存储不变，放置服务记下之前的归属，显示“从 … 移来”。对象属于哪个项目由对象读取告诉放置服务（见第 10 节助理合同项）。
- Plugin SDK 导出以上定义、处理器绑定与 `PERSONAL_SPACE_PROJECT_ID`。

### 7.2 放置服务（系统动作）：`packages/contracts/src/services/placement.ts`

提供方 `system.placement`，Home 作用域。读取类（`placement.describe / spaces / related / locate / goals`）受众 `user`、`agent`，权限 `placement:read`；写入类（`link / unlink / move / copy / convert / goal.bind / create`）只对 `user`，权限 `placement:write`。Web 经 `/api/placement/<动作>` 调用。

- `PlacedObject = { kind, id, project_id }`：个人空间分区的对象 `project_id = "personal"`，Home 级插件的对象 `project_id = null`（位置恒为个人空间）。
- `describe({ object })` → `{ state: ok|missing|unavailable, reason, object, title, plugin, location: { kind, project_id, title, access: private|home|project, access_label }, moved_from, associations, can: { move, copy, use_in_project }, open }`。对象事实向所有者读取（`*.subject.read`，以对象所在位置为调用上下文）；“已删除”（所有者回答 `not_found` 或所在项目已删除）与“暂时读不到”（插件停用、读取失败）分开；删除后仍用最后见过的标题称呼它。关联包括：用于项目、Goal 资料（向 Goal 所在项目的 Goals 读取，含对象移走后仍然有效的绑定）、插件自己的 Goal 挂接（不可在此移除）、来自/已转成、复制自/复制到。
- `link / unlink`：用于项目（关联），有历史；Goal 资料的移除调用 `goals.inputs.release`。
- `move`：调用插件移动协议，成功后更新位置索引，旧引用经 `locate` 找到新位置；移进某个项目时，“用于该项目”的关系自然收起。
- `copy`：调用插件复制协议，记 `copied_from`。
- `convert({ source, to: {station} | {goal: true}, to_project_id, request_id, payload? })`：交给工作流内容站 `receive` 或 `goals.create`，记 `derived_from`；原对象读不到但带了内容时仍可转成，原对象已删除则拒绝。
- `goals({ project_id })`、`goal.bind({ object, project_id, goal_id })`：列出与绑定 Goal；对象不在该项目时同时记“用于该项目”，并记下绑定所在项目，使对象移走后仍能显示这个 Goal。
- `create({ station, project_id, title?, goal_id?, request_id })`：在指定位置新建（工作流内容站 `create`），可同时绑定到 Goal。
- 关系边（`{home}/placement/placement.db`）：`placement.location`、`placement.used_in`、`placement.derived_from`、`placement.copied_from`、`placement.goal_in`。

### 7.3 工作台约定

- 当前对象：插件根元素的 `data-assistant-context`（`object: { kind, id, version, title }`、`unsaved`）。工作台把插件收回列表时去掉其中的 `object`。
- 位置条：插件在标题行放 `data-placement-slot`（自己显示保存状态时加 `data-placement-saved="off"`，Home 级插件加 `data-placement-scope="home"`）；工作台随对象、可见性与展开状态重画。窄屏只显示位置，访问范围与关联在面板里。
- “存到…”标签：`data-placement-target` 由工作台填为当前位置名称。项目首页 `data-placement-related`、Goal 资料行 `data-placement-material`、新建入口 `data-placement-create`。
- 事件：`molis:placement-result`（`verb: created|imported|generated|converted|versioned|exported|printed|received|failed`，`object?`、`title`、`note?`、`file?: { name, format }`）；`molis:placement-request`（共用对话框）；`molis:placement-convert`（交给别的插件或建成 Goal）；`molis:placement-changed`（移动/复制/转成后，相关插件重读列表）；`molis:shelf-admit`（把文件放进 Shelf）。
- 打开：和全局搜索同一规则（标签页打开或按插件列表行打开）；跨位置时带 `openPlugin`、`openItem`/`openRecord`、`openTitle`，Goal 资料场景带 `openGoalView=work`。对象移走后，旧位置里它的标签页关闭。

## 9. 超出既有定位、本任务不做（单独列明）

- **问卷外网公开链接、邮件收集、托管填写服务**：需要常在线的外部托管与身份，和“本机优先、单设备”的定位不符。本任务用“填写页文件 + 答卷文件”实现别人在自己设备上填写，名称写清。
- **团队空间、多人共享项目**：Identity & Space 的团队部分属于 Molis Work Server，未开始。访问范围本期只区分“只有你”和“项目里的工作环境”。
- **跨项目库对象的移动**（Goals、Feed、Inbox、Artifacts、Schedule、Coding）：它们存在各项目自己的数据库，搬动涉及事件历史与所有权，本期不支持，界面写明“这类内容不能移动，可以复制或关联”。
- **PPT 富排版**（图片、图表、母版编辑）：本期按现有结构（标题、要点、备注、配色）生成 PPTX。
