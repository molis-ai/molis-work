P0 让普通文档在 PR 和合并队列均省掉无关构建与运行测试；将检查当前代码和测试检查工具自身区分。P1 用更多独立 runner 缩短一个 PR 的关键路径，按真实耗时和浏览器槽位平衡负载。原有断言、测试集合、失败与重试语义保持。

## 范围与行为

### P0：选择与汇总

沿用 `scripts/ci-test-selection.mjs`，不新建第二套选测器。PR 使用实际合并基点，合并队列使用 `merge_group.base_sha`，对整个合并组计算变化；路径改名的两端均参与判断。新增的选择结果随原有输出写入摘要。

- 普通文档：已知文档路径下的 Markdown，以及明确列出的根文档。`AGENTS.md`、`skills/`、包 README、安全/包边界/SSOT 等机器读取的规范、发布资料、工具和运行配置不进入此路径。混入代码、未知类型、无法读取基点、无法判断变化时回到正常路径。
- 文档路径保留 `gates` 中对当前仓库的真实健康检查、版本一致性和验收编号报告，以及逐提交密钥扫描。首先复用完整健康检查，避免复制文档规则；省掉工作区构建、动作合同、产品、安全、原生和 shell 运行，以及门禁自身测试。预计每轮 1–3 分钟，须云端实测。
- 门禁自身测试：修改工作流、scripts、tooling、测试及夹具、依赖和构建配置、Skill 或机器读取的规范时运行；普通产品源码改动运行当前代码的门禁，不重复运行与其无关的门禁自身测试。夜间、手动、非复用的 main push 仍运行完整检查。
- 局部产品 PR 保留现有受影响选测；非纯文档的合并队列仍跑完整核心测试，避免未经验证就把现有启发式选测推广到队列。
- `Verify` 名字与必需检查身份不变。只有本次选择成功、该项明确允许跳过且实际结果为 skipped 时可豁免；失败、取消、未知/空输出不豁免。保留现有队列结果复用规则。
- shell/Python 与 macOS 原生检查按自身输入判定。普通 `.sh`、`.py` 不单独触发 macOS；桌面、原生辅助程序、Rust/Swift、工具链及检查实现等继续触发。

### P1：更多分片，负载平衡

- 完整安全测试 4 → 8 片，产品子集 3 → 6 片；局部 PR 按选中测试的预测时间分配所需片数，少量用例不展开全部 runner；单文件超过六分钟时以最长单文件作为分片目标，避免为无法继续缩短的长文件空增 runner。动作合同与门禁自身测试维持各 2 片。
- Full 16 → 32 片，一轮最多同时运行 16 片，单台仍最多 2 个文件、1 个浏览器文件。普通 Full 保留 bail/fail-fast，集成分支保留完整收集失败。分片恰好只有一个文件时仍使用分片协调器，执行相同的超时、重试和计时摘要；只有不带 `--shard` 的单文件调用保留直出入口。
- 分片遵循同一份输入清单和同一份耗时权重。按文件耗时及浏览器单独容量预测每片完成时间，优先安排长任务；相同输入必须得到确定分配，每个测试恰好分到一片，不丢失、不重复。新文件没有耗时记录时采用已有估计，不能因此被遗漏。片内启动顺序在私有缓存缺失时同样使用提交的耗时表，避免新分片把已知长文件排到最后；私有缓存只修正启动顺序，不改变分片归属。
- 扩展现有耗时刷新工具读取 Full 及核心 CI 的成功测试日志，补齐 Full 权重；剔除已删除文件，不把失败或重试通过的耗时误当稳定基准。报告预测片间偏差、实际片间耗时与慢文件，供后续更新；不让每片独立缓存决定分片归属。
- Team 的 60 个标准并发为组织共享容量，不能理解成每个 PR 都独占 60 台。先以一轮核心约 22 个任务、Full 最多 16 个并发运行，观测排队后再决定是否调整合并队列最多同时构建的条目。仓库服务器端队列设置不在本地配置修改中隐式改变。

### 非目标

P2（共享构建产物、夜间 probe 合并、发布优化）、产品源码/公共 API、真实 Home、凭据、版本、签名和发布不在本轮。不上新构建框架或跨运行调度服务，不以改超时、放宽断言或删除测试来提速。

## 验收标准

1. **CIP-01** 普通文档 PR 与纯文档合并组保留真实门禁和密钥扫描，跳过无关构建及运行测试；混入代码或受保护文档不能走轻量路径。
2. **CIP-02** 选择比较整个合并组的基点，识别新增、删除、改名两端；选择错误、未知输出和取消回退完整检查。
3. **CIP-03** `Verify` 对每项实际结果进行判断：合法 skipped 可以通过，失败、取消、未经允许的 skipped 必须失败，现有精确队列复用继续有效。
4. **CIP-04** 门禁自身测试按其输入触发，当前产品代码的门禁仍运行；夜间和手动完整运行不受减量影响。
5. **CIP-05** 单独 shell/Python 改动不占用 macOS；原生源码、相关脚本、配置和工具链变动仍运行原生检查。
6. **CIP-06** 完整核心使用 8 个安全分片和 6 个产品分片，局部选测按预计耗时确定片数；Full 使用 32 片、最多 16 片同时运行，保留每台及浏览器并发和失败语义；单文件分片也执行超时、重试并输出可采集的文件耗时。
7. **CIP-07** 分片在增加片数、缺权重、新增/删除文件、混合浏览器长短任务下保持确定性与完整集合；构造倾斜负载时能降低预测的最长分片时间。
8. **CIP-08** 耗时工具能读 Full 和核心运行的稳定成功样本，拒绝拿失败/重试结果刷新权重；输出各片负载及慢文件，更新不再存在的文件。
9. **CIP-09** 工作流结构、选测端到端、原有 CI 安装/超时/复用/产品子集/runner 回归以及健康门禁通过；未通过项记录根因及基线对照。
10. **CIP-10** [人工] 在最终候选上验证真实 GitHub Actions：正常代码路径、文档 PR/队列路径和 Full 分片；记录准确 head、运行链接、排队/构建/测试时间、分片偏差及偶发失败。未运行时明确标为未验证，不用本地单测宣称云端提速已达成。
