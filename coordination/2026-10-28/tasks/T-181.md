# T-181 读材料的标题按整字截到 500 个字，不再截出半个字

> **可领，依赖无。成立：读材料时标题按 UTF-16 单元截到 500，截点落在两个单元的字（如 😀，U+1F600）中间，标题就以半个字结尾；引导材料把这个标题一路带到 `encodeURIComponent`，抛 `URIError: URI malformed`，那一轮引导失败。对灵光没有影响，但灵光不是唯一的下游。**
>
> - 截取发生在 `apps/local-host/src/material-text.ts:122`（main `892879eba`，函数 `extractMaterialText`，`:112-125`），原样：
>
>   ```ts
>     return { text, ...(parsed.title ? { title: parsed.title.slice(0, 500) } : {}), extractor,
>   ```
>
>   标题来自 `:115-116`：HTML 文件取 `<title>`（`extractMaterialHtml`，`:86-87`，那里不截），`.md`、`.markdown` 取第一行 `# ` 标题（`/^# ([^\r\n]+)/mu`），别的扩展名没有标题。
> - 读材料的几条路都走这一行（第 1 节的表逐个写了）：引导材料、插件的材料服务、本机页面。其中引导材料会在 `context-onboarding-service.ts:488` 对标题做 `encodeURIComponent`，半个字就在这里抛错；`context-onboarding-documents.ts:28` 又按单元截一次 500，只改 `:122` 会让它开始按单元截一个最长 1000 单元的标题，所以两处一起改。
> - 来源：协调分支 `007f9d07a` 的 `coordination/2026-10-28/MISC.md:53`（`59c782502` 上是 `:54`），原文：「T-176 发布 | `apps/local-host/src/material-text.ts:122` | 读材料时标题 `parsed.title.slice(0, 500)` 按 UTF-16 单元截，可能截出半个字。对灵光没影响（T-156 随后按字截到 200，半个字落在被截掉的部分）；别的调用方先核一遍再定改不改」。别的调用方核过了，结论是改。

## 2. 目标

1. `extractMaterialText` 返回的标题是整字，至多 500 个字；一个两单元的字（如 😀）算 1 个字；Markdown 与 HTML 都是；
2. 引导材料读到的标题（`prepareContextDocument` 返回的 `reference.title`）是整字，至多 500 个字，对它做 `encodeURIComponent` 不抛；
3. 放得下的标题、没有标题时的备用标题（去掉扩展名的文件名）与现在一字不差；
4. 用例钉住上面三条：撤销任一处、改错截点，各自都红。

## 5. 做法

统筹已定之外的决定都是起草线定的，照做；觉得不对在【方案】里说，不要自己换（第 8 节写了理由）：

1. **`material-text.ts`**：只改 `:122` 并在它前面加一行注释，其余一个字不动。

   原（两个空格缩进）：

   ```ts
     return { text, ...(parsed.title ? { title: parsed.title.slice(0, 500) } : {}), extractor,
   ```

   新（同样缩进；注释一行加改后的一行，后面的 `pages: …` 与 `coverage: …` 两行顺延为 `:124`、`:125`，`}` 为 `:126`）：

   ```ts
     // Whole characters, not UTF-16 units: unit 500 can fall inside a two-unit character. The first slice bounds what is spread.
     return { text, ...(parsed.title ? { title: [...parsed.title.slice(0, 1000)].slice(0, 500).join("") } : {}), extractor,
   ```

   说明：
   - 先 `slice(0, 1000)` 再展开：1000 个单元里至少有 500 个完整的字，再取前 500 个，和不先截的 `[...parsed.title].slice(0, 500).join("")` 结果相同（独立脚本对 20000 个随机串和 20000 个贴近边界的串比过，0 个不同）；如果这 1000 个单元以一个高代理结尾，它是展开后的第 501 个或更后的元素，被丢掉；
   - 标题没有半个字的前提在第 1 节：输入是严格解码后的文本，所以输出一定是整字；
   - `parsed.title` 在这一行里已经判过真值，类型是 `string`。

2. **`context-onboarding-documents.ts`**：只改 `:28`。

   原（四个空格缩进）：

   ```ts
       const title = (result.title || filename.replace(/\.[^.]+$/u, "")).slice(0, 500);
   ```

   新：

   ```ts
       const title = [...(result.title || filename.replace(/\.[^.]+$/u, ""))].slice(0, 500).join("");
   ```

   说明：这里用 T-079 的原样写法，不先截：`result.title` 经 `:122` 之后至多 1000 个单元，`filename` 是文件系统里的一个名字。

3. **`tests/material-extraction.test.ts`**：在文件末尾（`:201` 的 `});` 之后）空一行，原样加下面的常量和三个 test。`test`、`assert`、`mkdtempSync`、`rmSync`、`tmpdir`、`path`、`randomUUID`、`extractMaterial`、`prepareContextDocument` 文件开头已有（`:1-6`、`:13`、`:15`），不加 `import`。
