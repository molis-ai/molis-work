## 1. 按价值支柱看

八个支柱的定义见[产品介绍第 5 节](产品介绍.md#5-八个价值支柱)。下表是每个支柱由哪些功能撑起来、最弱一环在哪。

| 支柱 | 主要功能 | 最弱一环 |
| --- | --- | --- |
| M1 同一份工作记录，多个 AI 记账 | Goals、Sessions、项目长期说明、MCP 对外接入、Runtime 接入、角色导入 | Claude Code 等的原生会话读取（只有 Codex 有原生适配） |
| M2 完成要对得上 | 要求与依据、本人验收、决定中心、显式收尾、输入回执、当前约定 | 依据都是 Agent 自报，Work 不自己核（建议 B1） |
| M3 接着眼前的东西做 | 浮条、落点、右栏、一句话新建、下一步、提问卡、操作卡、Shelf 热键、语音 | 右栏插件选区（分支）、语音（分支）、推荐模型未做真实评估 |
| M4 材料到成果，出处跟着走 | 来源、Feed、Inbox→Pages 带快照、Cognia、PPT、Forms、Dataset、成果库、外部文档导入、首次使用向导 | 正式 OAuth 与真实账号验收；来源变化复核（建议 D2） |
| M5 长出工具，人和 AI 共用 | 插件创作台、工作流程、判断规则、Skill、角色、提示词设置 | 生成插件不是一等公民（建议 C1）；技能包只在 spec |
| M6 助理主动推进 | Schedule、提醒、受托跟进、子任务、后台作业 | 主动助理、工作简报只在 spec；关掉应用后不执行 |
| M7 本机优先、模型自选、边界清楚 | 本机 SQLite、模型设置、预算、服务连接、授权、审查队列、调用记录、对话里接入服务 | 安装包未签名公证；真实账号 OAuth |
| M8 和别人一起 | 项目讨论、Agent 任务板 | 人与人的团队协作依赖服务端，规划中 |

## 7. 让人眼前一亮的细节

文档里讲得少、代码里有的东西，适合做演示里的"哦？"时刻：

1. Shelf 抽字完全离线，首次打开自带一份能试的示例 PDF，没配模型也能走完一遍。
2. ⌃⌥W 一键抓下当前浏览器页，⌃⌥A 收 Finder 选中的文件；拖到屏幕边缘出投放轮盘。
3. Forms 导出一个独立填写页文件，发给任何人在自己浏览器里填，答卷文件发回导入，全程不上传。
4. 待办从会议纪要里分出"你的承诺"和"在等别人的事"，日期由程序算，不信模型算数。
5. 灵光能读视频字幕和播客音频，本机转写。
6. 规划方法库 37 份：电商、教育、医疗、支付、SaaS、游戏、开发者工具等行业各一份；改需求只重排受影响的子图。
7. "必须由人验收"的要求，Agent 报再多次"通过"也收不了尾；约定一改，旧的点头作废。
8. 你在 AI 干活时补的话，能看到它读到没有、打算怎么处理；没读到的可以撤回。
9. AI 的问题在 Work 重启后还在等你答。
10. 系统和插件交给模型的每一段说明文字都能看、能改，每一轮记录用的是哪一版。
11. 记忆可以导出成去掉密钥与本机路径的"记忆包"，带到另一台电脑。
12. 接上一个外部 MCP 服务，它的工具立刻能当工作流程的一步。
13. 右栏浏览器的登录状态和你自己的浏览器分开，可以按网站给助理权限。
14. 电脑操作把密码管理器、系统设置、支付类应用设为禁区，连看都不看。
15. 炼金术士的市场与成本研究都齐了才能记"做 / 等 / 不做"，预算不够只出部分报告并明说。
16. PPT 用 Markdown 直接分页，`>` 写讲者备注，不调模型。
17. 删除项目会给一张收据，列出每个插件清掉了什么。

## 9. 用户能感觉到的边界

推广前要心里有数的地方，详细建议见[产品优化建议](产品优化建议.md)：

- 没有签名公证的安装包；只有 macOS 桌面 App（浏览器版可在其他系统前台运行）。
- 大多数 AI 功能要先配模型；判断规则要先连判断服务。
- 关掉应用或电脑休眠时，定时、提醒、Feed 拉取都不执行。
- 邮箱、Google 等账号来源依赖尚未发布的正式 OAuth 客户端。
- 部分插件英文界面不全。
- 已知体验债：Feed 失败提示露原码、首次打开 Feed 详情较慢、窄屏助理面板会盖住确认卡。
