1. 云端大厂已经把"项目 + 记忆 + 定时 + connectors + 审批提示"打包进订阅（Claude、ChatGPT、Cursor、Notion）。差异不再是"有没有"，而是"在谁的云里、管到哪些智能体"：Claude、ChatGPT、Cursor 自带的总览主要管自家的智能体；Notion 3.8 已能让外部 Agent 经 MCP 读写，管理员可见可撤（[官方 3.8](https://www.notion.com/releases/2026-10-13)），Linear 能把 issue 委派给 Cursor、Codex、Devin 等外部 Agent（[Linear](https://linear.app/agents)），Conductor 能在一个应用里并行跑 Claude Code、Codex、Cursor 等（[Conductor](https://www.conductor.build/docs)）。
2. 每个笔记与阅读产品都各自开了 MCP（Readwise、Granola、Tana、Capacities、Notion、Anytype 本地 API）。用户的外部 AI 要连多个孤岛，各有各的授权。
3. "AI 生成小工具"在云端已有 Claude Artifacts（无后端单页，[官方](https://code.claude.com/docs/en/artifacts)）、ChatGPT Sites（2026-07-09 公测，跑在 Cloudflare Workers 上，自带 D1 数据库与 R2 文件存储，[playcode 说明](https://playcode.io/blog/chatgpt-sites-explained)，二手）、Cursor canvas（可分享的交互页）。所以"有后端"不是差别；表里没有哪个写明的是：生成的工具跑在你本机、进同一个动作目录，让你的 AI 和工作流程都能调。
4. 验收（"这件事是否真的做完"）这一维，我读到的官方页面里多数停在"运行日志"和"批准动作"；有任务级的完成门禁，例如 Conductor 的待办没勾完就不能合并（[Conductor Todos](https://www.conductor.build/docs/reference/todos)）、Traycer 拿实现对照计划逐条出评审意见（[Traycer verification](https://docs.traycer.ai/tasks/verification)），但没读到目标级、由本人验收的。

契合度判断依据 `PRODUCT.md` 与既有调研里的机制：Goals（验收、人工验收门禁）、Sessions（交接）、Feed/Inbox（来源 → 待办）、Pages 与固定成果、Cognia（固定引用）、Workflows、Schedule、插件创作台、动作目录加授权、审查队列。

| # | 场景 | 证据 | 强度 | 与 Molis 机制的契合度 |

| U1 | **多个 Agent 并行时的"等我"总览与交接** | Anthropic 在 2026-05-11 推 agent view，把会话分成等我、运行中、已完成（[官方](https://claude.com/blog/agent-view-in-claude-code)）；Claude Code Projects 的 Overview 有"等你回复"和"待评审 PR"分组，Cursor Projects 让协调者并行派活；Linear 编码会话 diff 实时更新（均为官方页面，见 1.1、1.3）；HN 上多位开发者自做侧栏工具（见 2.2） | 多人讨论加厂商一致动作 | **高**。Claude、Cursor 自带的总览主要管自家 Agent；Notion 3.8 与 Linear 已能接外部 Agent（Notion 经 MCP 读写、管理员可见可撤；Linear 可把 issue 委派给 Cursor、Codex、Devin 等，[Notion](https://www.notion.com/releases/2026-10-13)、[Linear](https://linear.app/agents)），Conductor 能在一个应用里并行跑几家 Agent（[Conductor](https://www.conductor.build/docs)）。Molis 的差别只在具体一环：Sessions + Goals + Inbox 把"目标级的要求、本人验收、改约定要人批，并且绑定到约定版本"放在一起。风险：各家都在补自己的版本，需证明这一环本身值得 |

| U8 | **客户反馈归类** | 一家厂商博客称 47.1% 团队用 AI 把原始反馈压成主题（[Rocket.new](https://www.rocket.new/blog/ai-for-product-managers)），来源可疑；Linear 有分诊智能 | 弱 | **中低**。Forms、Dataset、Feed 能搭，但没有可靠需求数据 |
| U9 | **合同 / 文档审阅** | LexisNexis：94% 的英国法律从业者在用 AI，83% 担心编造；Cowork 数据里"法务与合规"只占 1.3% | 采用强，通用 Agent 内用量低 | **低**。隐私叙事契合本地优先，但需要行业依据库和责任界定，Molis 没有；单靠"数据不出机器"撑不起 |
| U10 | **跨 AI 工具的一个知识 / 记忆中枢（经 MCP）** | Readwise、Notion、Capacities、Granola、Anytype 都把自己的数据开给外部 AI（见 1.2）；Notion 3.8 把 Skills 同步到 ChatGPT、Claude；HN 多位作者各自写 MCP 记忆桥（见 2.2） | 产品动作多，用户自制工具多 | **高**。这是 Molis "一个动作目录、外部 AI 共用"的直接叙事，且各家只开自家数据，用户要连很多个 |
| U11 | **每个 Agent 动作可审可追** | 多个 Agent 的审批 / 审计诉求：markamo（2026-03-11）要先看清 Agent 做了什么再落进系统；Linear 标明作者是人还是 loop；Zapier 演示"只给建草稿权限"；Stack Overflow 60% 阻止未批准的系统改动 | 多人讨论加调查 | **高**。Molis 的审查队列和授权按调用方裁决正对此；但不是单点卖点，要和 U1、U10 合在一起讲 |

**判断**：
- 最契合且证据最强的组合是 **U1 + U10 + U11**：跨工具、本地、可审的中立层。
- U2、U3 是"证明机制可用"的好演示，但每家都在做，不适合做差异化。
- U6、U9 不要投入。

| **Readwise、Notion** | 不只做产品，也把自己的能力打包成 skills 放进别人的 AI 生态：Readwise 提供 Claude Code、Codex 用的 skills；Notion 3.8 的 Skills API 把 Notion 里的 skills 同步到 ChatGPT 与 Claude（官方，见 1.2） | **最直接可借鉴**：Molis 的入口不必是自己的界面，而是外部 AI 里的一个 skill。用户已在 Claude Code、Codex 里，Molis 作为他们装上的一个 skill 出现 |
| **Zapier** | MCP 与连接器目录：Zapier 称连接 9,000 多个应用，连接器进入 Meta Muse 等第三方智能体平台（[Zapier](https://zapier.com/blog/zapier-connector-in-muse/)） | 被动分发：谁的 AI 工具流行，就出现在谁的连接器目录里 |
| **Cursor** | 2026-10-13 开放 App Marketplace 接受公开提交（官方更新日志） | 市场开放给第三方，是从内容到平台的标准一步 |

**可操作的归纳**：
1. 增长靠"别人的生态里出现你"（skills、MCP 目录、插件市场），而不是靠自己的新界面。
2. 一句否定式差异加一个高端早期人群（Granola）；Molis 现在的候选是开发者与独立研究者。
3. 本地 Agent 的传播天然伴随安全话题，要抢先把安全设计讲清楚。
4. 市场与审核机制要在量起来之前准备（Obsidian 的教训）。

### 5.2 对 Molis 的含义（国内）

- 国内大厂把智能体做在已有的数据与权限底座上（飞书多维表格、WPS、钉钉），"继承现有权限"和"运行日志、变更历史"已是标配话术；Molis 想讲权限，要讲到调用方级别的授权与撤销后不再写任何记录，而不是"我们也有权限"。
- 本机智能体在国内被官方、媒体、监管同时盯着（国企与银行限制、MIIT 提醒），个人与小团队用户对"本机运行、数据不出设备"的认同，和对"配置复杂、花钱、出事"的担心同时存在。Molis 的安装与授权体验要对非技术用户可用。
- 国内口碑集中在自媒体、知乎、小红书、V2EX，不在英文社区；这些平台上的真实评价本次没有系统检索，属于调研缺口。

## 6. 对 Molis Work 的启发

### 6.1 最有机会的差异化方向（按建议优先级）

1. **跨厂商的"谁在等我 / 做到哪了 / 是否验收"中立总览。**
   - 依据：Anthropic 的 agent view（2026-05-11）、Claude Code Projects 的"等你回复"、Cursor Projects 主要管自家 Agent；Notion 3.8、Linear、Conductor 已能接或并行跑外部 Agent（见 1.2、1.3 与 U1）；开发者仍在自己做侧栏工具（见 2.2）。
   - 差异：Molis 的 Sessions、Goals、Inbox 在 Codex、Claude Code、Cursor 之上，并把目标级的要求、本人验收、改约定要人批绑定到约定版本。
   - 注意：既有调研已提醒，Goals 管的是目标记录和完成生效，不控制外部 Agent 的所有操作，文案不能越界。

2. **"完成"要有依据，必要时必须人验收。**
   - 依据：Stack Overflow 只有 6.6% 愿意让 AI 参与重要决定、近半只在能验证时信任；微软 50% 把质量把关列为首要技能；Adaptavist 42% 复核时间超过节省的时间。
   - 我读到的竞品官方页面里，没有哪个把验收做成目标级、由本人验收的对象（Notion 是运行日志，Linear 是标明作者；Conductor 的待办拦合并、Traycer 逐条对照计划，是任务级的完成门禁）。这是 Goals 要讲清的具体一环，别淹没在"又一个任务板"里。

3. **一个动作目录，替用户收拢多个孤岛式 MCP。**
   - 依据：Readwise、Granola、Notion、Capacities、Anytype 都各开自己的 MCP；Tana 在 10 月才处理"工具特别多的 MCP 服务器"。
   - 差异：Molis 注册一次，页面、助理、工作流和外部 AI 共用，并有统一搜索。
   - 机会：同时把 Granola、Readwise 这类产品当上游来源接入，而不是替代它们。

4. **本机常驻加"可审、可撤销"的 Agent 安全故事。**
   - 依据：OpenClaw 的传播与安全事件（CrowdStrike 记录用户授予 root 级权限；中国监管限制；The Register 评 2.0 缺文件系统与网络边界）。
   - Molis 已有的是回环绑定、调用方级授权、撤权后不写入、副作用进审查队列。要写成具体能拒绝什么，而不是"更安全"。

5. **来源可回查：固定到当时的版本。**
   - 依据：Stack Overflow 78.7%、Elsevier 59%、LexisNexis 83% 都把来源和引用列为信任条件；Capacities、Readwise、NotebookLM 都已能"带引用回答"。
   - 差异只能是"随成果保存当时采用的材料快照"，也就是既有 O01 的机制。不要宣称"有引用"。

6. **带后端、本地存储、进共用动作目录的 AI 生成小工具，并且平台替你维护。**
   - 依据：云端的 Artifacts 是无后端单页，Sites 是云端托管、带数据库的小应用（[playcode 说明](https://playcode.io/blog/chatgpt-sites-explained)，二手），canvas 是可分享的交互页；而"个人小工具难维护"是最稳定的反对声音。
   - 差异：生成的工具跑在你本机，有安装、权限、升级，进同一个动作目录，你的 AI 和工作流程都能调；既有 O02 已认定"先用现有创作台做一个业务样例再判断"，本文只补充：不要用"AI 能帮你做软件"做宣传，要用"做出来的东西你不用自己养"。

7. **以外部 AI 里的一个 skill / MCP 条目作为入口，而不是自己的新界面。**
   - 依据：Readwise 和 Notion 都在往 Claude、Codex、ChatGPT 的 skills 生态里分发；Zapier 靠连接器目录分发。
   - 对 Molis：先拿下开发者与独立研究者这批已在 Claude Code、Codex 里的人，让 Molis 作为他们装上的 skill 出现。

8. **面向有保密义务的职业，只在"本地加可控模型"成立时才讲隐私。**
   - 依据：LexisNexis 53% 担心泄露；Stack Overflow 13% 因隐私避免使用 AI；Raycast、Anytype 把本地模型作为选项。
   - 条件：Molis 的模型调用统一经运行时，可配多家模型；如果不能让用户选本地模型，就不要说"数据不出机器"，只能说"可审、可预算"。

### 6.2 最大的竞争威胁与"不该正面竞争"的地方

1. **Claude 与 ChatGPT 的桌面端 + 项目 + 定时 + connectors 打包进订阅。**
   - Claude：Cowork、Claude Code Projects、Routines、Artifacts、记忆；官方说"Cowork 现在就是 Claude"在逐步铺开。
   - ChatGPT：Work（2026-07-10）合并 Codex 和桌面端，Sites，项目记忆。
   - 不要在"通用 Agent 帮你干活"上竞争，那是用户已有订阅里的功能；Molis 要成为这些 AI 之下的状态与授权层。

2. **各编码工具自带的多 Agent 管理（agent view、Cursor Projects、Codex worktree 与子智能体）以及能接外部 Agent 的 Linear、Conductor。**
   - 单个工具内部的并行管理，用户已经在用，Molis 做不赢；Linear 能把 issue 委派给 Cursor、Codex、Devin 等（[Linear](https://linear.app/agents)），Conductor 能在一个应用里并行跑几家 Agent 且有待办拦合并（[Conductor](https://www.conductor.build/docs)）。
   - 价值只在具体的一环：同一份目标级的要求、本人验收、改约定要人批，并绑定到约定版本。

3. **Notion。**
   - 150 多个 MCP 连接、Custom Agents、Skills API、版本历史、列级权限，而且自己成了外部 Agent 读写的中枢（官方 3.8）。
   - 团队文档与协作、结构化数据库不要碰；Molis 的"每项事实一个主人"和单机属性不适合做团队知识库。

4. **"Claude Code 加一个 Markdown 库"这条自己动手路线（Obsidian、纯文件）。**
   - HN 上大量开发者就这么用，且有 Obsidian CLI、Bases 的持续更新；它零迁移成本。
   - Molis 必须证明比"一个库加 `CLAUDE.md`"更省事：例如跨会话的验收、授权和来源，而不是又一个存笔记的地方。

5. **OpenClaw 类开源本地 Agent 和国内大厂的变体（WorkBuddy、QClaw、悟空、Coze）。**
   - 它们已占据"本地 Agent"的心智和社区；国内还有补贴与线下活动。
   - Molis 的位置是"可控"而不是"能做更多"，在安全事件频发的环境里更有说服力，但不要在 Agent 数量、渠道（微信、WhatsApp）上硬拼。
