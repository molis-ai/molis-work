# 可信决定与项目审批规则回平台

状态：2026-11-14 用户批准隔离迁移及第 39 批先写共用合同。同一只读代理完成共用类型、原队列投影及项目库与同步方案的设计复核。接口见[授权需求 §3.5–3.6](spec.md#review-contract)，原需求见 [D3 与片 3](../plugin-equal-standing/spec.md)，交付见 [39-2](../post-anticorruption-roadmap/reference/batches/39.md#batch-39-item-2)。

## 1. 要闭合的路径

任一插件声明某项动作需要本人决定。平台固定项目、安装、动作和待审版本，提供当前可决定的选项。人在页面或受保护的管理 MCP 入口操作，两端交给同一个平台入口。原业务主人负责确认待审对象仍可决定，并提交本次变化。平台保存决定与可信来源，用户可从统一授权管理页打开项目规则，Goals 的现有页面沿同一份规则显示。

没有装 Goals 的项目同样能发起、决定、查看和撤回适用的规则。Goals 仍拥有目标、提案、事件及物化结果。第 32-2 批拥有要求、产物关联及返工的业务事实，沿用第 39 批先写的要求、依据、决定请求共用形状。已有审查请求通过原 owner 定位，工作台和智能呈现负责展示。在 39-2 上线以前，第 32-2 批的认可沿现有页面入口执行。

### 2.1 共用公共合同与原队列

在 `platform/reviews.ts` 扩展已有公共类型和只读投影。原 Agent 队列继续出入原二元记录；共同决定引用使用原不可复用 review id 作为该审查的唯一决定 id，固定 `reference.version`，直接从存储 owner 读。已有的 `agent-review` 和 `goal-acceptance` 引用沿原 owner 身份。通用决定服务增加平台签发的一种路由，覆盖所有具备现行声明的插件；服务按引用内项目、插件及安装找唯一登记，并在每次读取时按原调用者验证。项目内同 id 的另一 owner 或同插件重装都不可替代原请求。`ReviewRequest` 在 owner 端投影接受的要求、当前可用性和过去决定引用。任何卡片上的按钮信息都只用于显示。

选择固定前，由要求 owner 读取各目标及证据的原提供方、安装世代、存储作用域、当前可见性和精确版本。项目动作的通用入口只接收登记查询在同一原项目、提供方和安装下投影的事实，打开历史仍复核该查询和原动作的当前授权。跨 owner 的证据由实际依据的原 owner 在调用者权限内读取。为具体选项冻结每条要求的 id、版本、产物、证据和认可／退回范围。32-2 使用现有队列的每次二元决定核准一份已冻结选择，按原决定引用原子应用这份逐项结果。旧版本可以回看原决定。对版本失配、未知或有反证的条目，在同一要求 owner 的业务规则里重开。完成审批沿独立请求检查。

### 2.2 决定入口和业务提交

Web 复用已有受保护的门和页面生命周期。管理 MCP 复用 resident gateway 的 Home、项目、管理认证、许可及断线检查，在入口新增明确的决定命令。两端在内部把一次凭据与原请求的 owner、版本、选项、本人、项目和本次重放键绑定。业务输入仅带原版本、选项和备注。调用方给出的 `evidence` 和通常转调继承的 `ActionUserAction` 均无权签发凭据。网关在进入标记动作时区分申请与最终执行。申请验证原 schema 和申请权限，实际执行只接受该入口交给当前原 owner 的单次凭据，并在 `beforeEffect` 核实时权限和有效期。

Goals 原按请求决定、逐项树案、无请求的明确本人决定都要先读出并固定实际被决定对象。有固定请求沿原 id、版本与选项。逐项树案把原提案、项目、影响项和独立 scope／整案确认一起固定。一次冻结选择拥有自己的请求 id，同一提案中仍可决定的余项有新请求 id。原提案 id 持续关联各次选择，已决定或版本变化的条目由 Goals 复核。无请求的原操作先由 owner 冻结作用范围、引用和对应版本再进入同一审批入口。保留可审核的原 scope 和整案确认，入口从用户实际见到的版本生成，复核发生在原业务提交处。

同一项目库的写入由原 owner 打开 `immediate`。先在事务外准备目录、安装、规则和目标版本，事务中写入平台决定、去重收据与原业务结果。原生写入在同一进程同步复核原调用和最新对象／规则版本后提交。签名插件的隔离 SQL 写进程在事务中核版本，备妥后向 Host 请求一次提交许可。Host 同步核当前原调用及安装，再发对应事务的许可。许可发出前失权，或写进程明确拒绝提交时，原业务和决定一并回滚。许可发出后遇到迟到错误、回复丢失或权限变化，用原决定引用、选择和操作编号核对持久回执。当前仍获准且回执匹配时返回原回执，无法确认时显示待核对。另一选择或同请求另一去重键均冲突。模型、网络和远端效果沿各 owner 的实际派发边界。

### 3.1 同一个项目库的结构与记录交接

入口为现有显式项目库升级流程。平台项目库 `3 → 4` 核对 Goals 官方发布者、原私有库定义、对象清单、同步触发器和原项目身份。本次交接分别验证 Goals v1、v2、v3 的完整源结构，沿原升级步骤补齐事件证据和第 17 批的风险引用。平台 v4 和 Goals v4 在同一 SQLite 写事务提交，普通的插件升级看到 v4 即结束。无 Goals 账本且无旧表的项目只建平台表。未知版本、混合所有权或无账本的旧表明确拒绝并保全。启动、同步和普通读取使用现行 owner。

平台决定表保留原决定 id 与对象引用，项目规则表保留原 id、scope 与优先级。Goals 的物化记录已有 `governance_decision_id`，保存不透明决定 id，沿同事务及同步关联校验。平台表只引用项目根记录，Goals 表保持其本有外键。决定历史可含旧来源和只供回看的记录，原审批请求上下文不可获得时保持缺证据。逐键核对主键、结论、引用、规则效果、历史来源、幂等回执，再删除旧写表和换触发器。现有升级事务在提交前校验结构、完整性、外键及行数，额外验证逐键转换。任一步失败原账本、数据和触发器一起回滚。真实 Home 的执行窗口另行确认。

### 3.2 同步和恢复

当前 `project_goals@1` 在一份快照里替换 Goals、治理、上下文及相关 Journal 与去重回执。换版后，平台审批集合唯一拥有全部决定和规则，项目未安装 Goals 或卸载 Goals 时也可读回。Goals 的 `project_goals@2` 只拥有业务、关联与现有 Journal。平台先按原项目、可信集合和完整冻结身份验收决定，按 id 逐条比对原不可变内容，重复一致时幂等，漏行及恢复都不得删除已知决定。规则保留独立版本及撤回事实，消费时复核实际对象和当前规则。同步进来的决定是已发生的历史，不能复用为一次执行许可。

本机本人决定和业务物化仍在同一个写事务。同步收件按现有平台集合、插件集合的顺序执行。Host 在精确的现行 Goals 集合装配平台审批依赖，核两个集合均有当前授权。Goals 的 apply、重试、冲突处理和恢复在自己的事务内先经受限的 Host 读接口核对全部原决定。缺少决定时沿已有等待机制保存原收件并保全原业务图。相同 id 的项目、来源、冻结版本或内容不符时保持原图并记录冲突。平台历史可以先到，不要求对端已应用业务图。每个所有者承担自己的事务，Goals 的物化在所有引用到齐后一次写入。卸载、重新启用、撤销同步和回收项目均核原项目及集合权限，目录的待同步检查登记平台审批子集。

原决定随同一事务内计算的业务结果摘要保存。事件摘要绑定已应用记录、稳定事件和完整逐项结论，允许接收端重编本地事件序号。旧事件也要对齐原批准、已应用记录和原生产方写出的完整事件字段，缺字段时回滚移交。目标树摘要绑定逐项效果，接收端另核对对应条目的状态和物化引用。冲突可以在后续重查或新决定中演进。目标或提案仍在时，收到的快照省略已知结果会被拒绝。旧目标树决定按历史出处展示，留存提案必须带回每个有终态决定的原条目。

旧端先停写，保留备份中的原游标、outbox、冲突及回执。已启用同步的项目先由旧端排空并核云端水位；缺旧端或有未决效果时保持待处理。新流使用独立结构版本和游标，只从已验证的快照首次建立。现行服务的 policy CAS 在选中 v2 时会拒 v1 的写入，但有权限的旧设备可重新选回 v1。现有过程项封存只识别其专属集合。正式启用前仍需明确的停旧设备和云端写入窗口，或对精确旧集合提供服务端的单向退场。隔离旧库可验证本地移交、原 outbox 的保留、新流收件和失败恢复；来自旧流的已选状态、队列和回执不会自动变成新流授权或进度。真实云端和 Home 单独批准执行。

## 4. 跨批预警

2026-11-14 用户确认由 39 先交共用草案并由同一代理合审。第 32-2 批沿用，负责已有的业务 owner 与验收。第 44-1 批消费同一受保护决定入口。

目的是让没有 Goals 的项目也能走本人审批，同时保留 Goals 已有记录。影响 32-2、39-1、44-1、Goals 及平台库版本。[#2069](https://github.com/molis-ai/molis-work/pull/2069) 已交共用形状。两条管理工具和 CLI 原审批命令由文档中同一组通用读取与决定入口替换，调用方查原请求并提交原选择。认领板的写入经自动审批拒绝，跨批提醒仍待补发。
