# 事项线：在一条线上办事

状态：需求已整理（2026-11-12；2026-11-14 用户改方向，见 §12），尚未实现；正式定样随第 32 批做。把工作台底部做成当前事项的一条线：左边是办过的，中间是现在（输入框），右边是接下来。线是平台能力：线上的每一项叫事件，由插件和助理按同一份登记放上来——一条到期的待办、一个会、一个 Coding 会话、一份交回的结果、一件值得跟的交办、一个建议；点一个事件它移到中间，展开成一张卡，在卡上点、或接着说就能把它办完。后台任务是事件背后的执行，不是线上的东西：一个事件背后可以有零到多个任务，也有不属于任何事件的任务；全部任务在输入框上方的后台任务面板里。说完一句话，助理（或你选的 Character）先马上回应，能后台办的派到后台，再写明这件事的去处；任务的结果回到它，由它按上下文判断并推进。线头切换事项。线不是新的事实：它把各插件的登记、任务板、工作记录和呈现声明读出来排在一起。需求维护：Claude（本机）；实现按 §9 的批次由各批主会话做。

## 1. 要解决的问题

对照 main `c2266974b9` 的现状：

- **底栏是一排互不相干的东西。** 左边是 Dock 与插件切换，中间是输入框，右边是个人插件入口和项目头像。它们各管各的，看不出「我现在在办哪件事、办到哪了」。
- **输入框写到多行就不好看。** 框向上长时盖住主区底部，或把底栏撑高，版面跟着跳。第 11 批把静止高度收成一行（62px），多行时的样子没有解决。
- **助理的对话是另一块面板。** 交给助理的事、它的进展、要你点头的地方，都在助理面板里一条条消息往下排。要看一项工作办到哪，得翻对话；对话一长，早先交办的事被顶上去。
- **后台任务的入口还要再加一条。** 主动助理 §12.8 定的是「对话顶上的任务条」（2026-11-03，方案 A）：助理面板顶上再加一条概况，点开换成任务详情。它解决了看得见，但任务仍然关在助理面板里，和主区、和手头这件事没有关系。
- **事项切换器在顶部，和底部的输入没有关系。** 主线 §4.1 把切换器放在标题栏最前。切了事项，底部看不出变化；助理范围靠输入框上一行小字说明。
- **等你、待办、日程、建议各在各的地方。** 等你在底栏的数字里，待办在待办插件，今天的会在日程，下一步在 Goal 页。它们都是「这件事接下来要处理的」，但没有一个地方按先后排在一起。
- **卡片有了规格，缺一个把它们串起来的地方。** 智能呈现定了名字片、行、卡片、活卡、决定请求、验收卡等形态，落点是对话、讨论、首页、Shelf、等你。它们各自出现，没有时间上的先后。

- **任务和事情混在一起。** 2026-11-12 的写法里，线上第一批东西就是助理交办的工作本身（进行中、等你、已办），线成了一条任务条：随口交代的小事也要占一个位置，而待办、日程这些真正「接下来要处理的事」要等后面几片才上线。用户 2026-11-14 改：线上放的是事件，任务在它背后（§12）。

要的不是再加一块面板，而是让版面本身说清三件事：办过什么、现在在办什么、接下来该办什么。

## 2. 一条线是什么

三个词（用户 2026-11-14 定）：**事项**是线头切换的那一层（[主线](../work-mainline/spec.md)里的容器）；**事件**是线上的一项；**任务**是事件背后的执行。代码和合同里「事件」另有系统事件的意思（DOM 事件、Board 事件），本书里不加限定的「事件」都指线上的一项，系统事件写「变更通知」。

- **事项线。** 工作台底部的一条线，属于当前事项。没选事项时，是这个项目的线。
  - 左翼「已办」：办完的事件，越靠中间越新；
  - 中间「现在」：输入框。有任务在办的、等你的事件紧挨在它左边；
  - 右翼「接下来」：有时间的（日程、到期的待办）按时间排，然后是建议的下一步。
- **事件。** 线上的一个小胶囊：图标、名字、一个状态词或数字。它是平台能力：插件按同一份登记（§5）把自己的对象放到线上，助理也按这一份登记，线不为它另存内容：

  | 事件 | 是什么 | 谁登记、事实归谁 |
  | --- | --- | --- |
  | 插件对象 | 这件事里带时间或要处理的对象：待办、日程、Coding 会话、要你看的条目 | 各插件 |
  | 结果 | 办完交回的东西（一份文稿、一张表、一次改动） | 结果对象的主人插件 |
  | 交办的工作 | 你交给助理、值得跟的一件工作：有产出物、你说了要跟，或和线上已有的事件相关（§6.4） | 助理；工作的事实在任务板与助理工作 |
  | 建议 | 一个可以开始的下一步 | 来源对象的主人（装着 Goals 时是 Goal 的下一步）；第三片起也来自主动助理 |
  | 新的事 | 聚焦别的事件时，「现在」留在线上的记号，点它回到现在 | 无 |

- **任务。** 为某个事件在后台办的一次执行：助理或 Character 派出的工作、Coding 的一次运行、工作流程的一次运行、插件自己的后台作业。
  - 一个事件背后可以没有任务、有一个、有几个；任务办完了事件还在（一份公告先后有过起草、改语气、配图三个任务）。
  - 任务也可以不属于任何事件：随口交代的小事只在后台任务面板里，不上线。
  - 任务的事实在任务板和发起它的一方；「这个任务为哪个事件办」是 placement 的一条关联，不在线上另存。
- **事件的状态。** 来自两处，读出来不另存：主人给的对象状态（到期、已完成、要你看），和它背后任务的状态（有任务在办就是进行中，有任务停下来等你就是等你，任务都办完就回到主人给的状态）。
- **焦点。** 线的正中间一次只放一样东西。平时是「现在」：空的输入框，说一件新的事。点任何一个事件，它移到中间：事件展开成一张卡，输入框接在卡的下面，这时说的话是对这个事件说的。
- **事件卡。** 聚焦后展开的卡，按事件种类内容不同（§4.4），并列出它背后的任务。它用智能呈现的形态（活卡、决定请求、验收卡、卡片），由组合服务给出，线不自己画。
- **后台任务面板。** 输入框上方常驻的一小块：正在办的、排队的、等你的任务，每行标出为哪个事件办（或「不属于事件」）、谁在办（助理、哪个 Character、哪个插件）。都正常时收成一句，没有任务时不占地方。全部后台任务只在这一处看：线上不放任务按钮，右侧也不再有「后台任务」页（§8）。
- **对话的对方。** 输入框平时发给个人助理；在「发给」里可以选一个 Character 直接对它说。两者是同一套：先回应、能后台办的派到后台、结果回到说话的这一方。
- **回流。** 任务办完、失败、缺信息、要你定，或它等的条件到了，结果先回到派出它的助理（或 Character）；它按当时的上下文判断：告诉你、接着派下一步、问你，或者先不打扰。行为与边界归[主动助理](../proactive-assistant/spec.md) §7.5.4，本书管它在线上和面板里怎样显示。
- **手边。** 输入框左边的「＋」：Shelf、灵光、资料，拿一样附到正在写的话上；可以钉到侧边。
- **线头。** 线最左端的事项按钮：状态环、事项名、等你的数量。点开向上展开事项列表，切换事项。
- **安放。** 说完一句话，助理先马上回应，再判断这件事的去处：是对线上某个事件背后任务的补充，是为某个事件办的一个新任务，值得登记成一个新事件，属于另一件事项，还是不属于任何事件、只在后台任务面板里。去处写在回应里，一点就能改。

## 3. 原则

1. **线是读出来的，不是存出来的。** 一个事件背后的事实各有主人（任务板、插件、工作记录）。线只存两样属于它自己的东西：焦点在哪、用户对建议的移走与固定，都放在已有的地方（§6.2）。
2. **一个输入框，一个焦点。** 工作台仍然只有底部这一个输入框（UIV-18）。焦点决定这句话发给谁：在「现在」是交办新的事，在事件上是对这件事接着说。发给谁在框里一直看得见。
3. **不盖住正在做的内容。** 输入框多行时向上长，被它压到的工作面和侧边向上让出同样的高度，底部这条线的高度不变。事件卡的处理在定样里定（§10）。
4. **点和说都能办。** 事件卡上能点的（同意、勾掉、打开、开始办）不要求打字；要说的（改一下、补充）不要求先找到对话。两种办法作用于同一件事，结果一致。
5. **查看不等于切换。** 聚焦一个事件不改当前事项，不改在跑工作的范围；点开另一件事项的事件先切事项（切换是显式的，主线原则 4）。
6. **进展是真的。** 事件的状态词、步骤、等待原因都来自任务板和插件的事实；读不到就写「读不到，最后更新于…」，不沿着旧状态转圈（PWA-132）。
7. **插件同等待遇。** 任何插件按同一份登记让自己的对象成为事件、给出下一步；助理登记「交办的工作」走的也是这一份；宿主里没有按插件名的分支。
8. **安静。** 线上只放有时间意义或要你处理的东西；资料、文稿这类静态的东西在「这件事的东西」里（侧边），不上线。后台更新不抢焦点、不推走正在读的内容（PWA-139）。
9. **先回应，再安放。** 输入送达后助理先给一句真实的回应（接单、直接回答或缺什么），不等判断完放到哪、更不等办完。安放是助理的判断，可能不准：结果一定显示、一步能改，改了不重做已经做的部分。安放只决定这件事显示在哪、带哪件事项的上下文，不授予任何权限。
10. **不是每件事都属于这条线。** 随口交代的、和当前事项无关的事照样能办，不为了上线硬登记成事件；它在后台任务面板里，有自己的卡。
11. **版面就是引导。** 新用户不用学：左边是过去，中间是现在，右边是下一步，点右边的一项就开始。不靠常驻的说明文字。
12. **事件在线上，任务在背后。** 线上只放事件。任务不单独占线上的位置：它让所属事件的状态变化，自己在后台任务面板里。看这件事接下来要处理什么看线，看现在都在办什么看面板（用户 2026-11-14 定）。
13. **结果回到说话的那一方。** 后台任务的结果、提问和失败先回到派出它的助理或 Character，由它判断并推进；不要求用户去各个任务里收结果、再回来转告。

## 4. 用户能做什么

可点的方向原型在 [`docs/design/work-line/`](../../docs/design/work-line/README.md)（§10）。下面写行为，样子以定样为准。

### 4.1 外壳

窗口从上到下三段：

- **顶部一条。** 后退、前进；固定的插件图标；标签；「＋」打开起始页（全部插件与快捷入口）；最右是侧边开关、头像。原来底栏左边的 Dock 与插件切换、右边的个人插件入口与项目头像，都到这一条。
- **中间。** 工作面（标签对应的页面，可分屏）和右侧的侧边。侧边保留：Shelf、灵光、资料、浏览器、对话，以及「这件事的东西」（主线 §4.3）。
- **底部一条线。** 线头、已办、输入框、接下来。高度固定。输入框上方是后台任务面板（§4.5），它和多行输入一样只让工作面让位，不改线的高度。

这是对第 07 批工作台分区的改动，见 §8。

### 4.2 说一件事

- 输入框静止时一行。写到多行，框向上长，工作面和侧边的下边一起向上让，内容不被盖住；删回一行，原样落回。
- 「＋」打开手边：Shelf、灵光、资料三页，点一项附到这句话上；右上角可以把它钉到侧边。
- 发送后输入框立即清空，可以马上说下一件；上一件还在办也一样（PWA-128）。助理（或你选的 Character）的回应出现在输入框上方，分两拍：
  1. **马上回应**：一句话说明收到了什么、打算怎么办；能当场答的直接答；缺必要信息就问那一处。要持续办的派到后台，这一轮就结束，不占着对话。
  2. **安放**：回应末尾写明去处，例如「为：设计评审会 · 新任务」「补充给：起草公告」「新事件：发布公告」「放到：整理评审反馈（另一件事项）」「不属于事件 · 在后台任务里」，旁边一个「改」。
- 安放的五种去处：
  - 对线上某个事件背后已有任务的补充或修改：成为那项任务的一轮输入；
  - 为线上某个事件办的新任务（比如为「设计评审会」准备材料）：任务出现在后台任务面板，标着这个事件；事件变成进行中；
  - 值得跟的新工作：助理登记一个新事件（「交办的工作」），落在输入框左边，任务挂在它后面。什么算值得跟见 §6.4；
  - 另一件事项的工作：事件或任务落在那件事项里，当前的线不变；回应里可以一步切过去；
  - 不属于任何事件：不上线，只在后台任务面板里。
- 拿不准而且放错会影响结果时，只问必要的那一处（「是给『起草公告』的补充，还是另一件事？」），其余照常进行；不默认塞给最近的事件（PWA-129）。
- 用户自己选了去处时不再判断：聚焦在一个事件上说的话就是给它的（§4.4）；在「发给」里选了收件人的照选的来。
- 点右翼的一个建议：它移到中间，卡上写着它从哪来，「开始办」把它填进输入框，可以改了再发。
- 临时问一句、能当场答的，直接在「现在」答，不建事件（PWA-127）。回答显示在输入框上方，下一次交办或点别处后收起，记录里仍能找到。
- 一句话里交代几件事，各成一个任务，值得跟的各登记事件；有先后的，后一个标「等前一件」。
- 后台任务有了结果、要你定或办不下去时，助理在输入框上方说一句归属明确的话：哪个任务、结果或问题、能点的下一步。你正在写字或在看别的事件时不抢焦点，面板上那一行亮起（PWA-133、PWA-139）。助理在原交办范围内自己接着派了下一步的，也说一句做了什么（主动助理 §7.5.4）。

### 4.3 看进展

- 有任务在办的事件显示当前这一步的名字（「查资料」「起草中」），不是百分比；面板里对应的任务行显示同一句。
- 任务需要你的时候，它所属的事件变成「等你」，轻轻闪动，面板里这一行排到最前；这时如果输入框空着、你没有在别的事件上，这个事件自己移到中间并展开，不打断正在写的话。不属于事件的任务等你时，只在面板里亮起，并由助理在对话里说一句。
- 任务办完，事件回到主人给的状态；产出的结果对象由它的主人登记成「已办」的事件，留在左翼。
- 助理用到浏览器时，侧边「浏览器」页亮一个点，打开能看到它在看什么；不打开不影响你。

### 4.4 点一个事件

点事件，它移到中间，后面的事件挪到右翼并多一个「＋ 新的事」。展开的卡按种类：

| 事件 | 卡上有什么 | 能点什么 | 接着说会怎样 |
| --- | --- | --- | --- |
| 交办的工作 | 交办的原话；背后的任务与拆解，每步写明谁在办、做到哪一步 | 暂停、停止；点一步看它的产物 | 作为补充交给对应的任务，回执写明「已收到」还是「已用上」 |
| 结果 | 结果的预览、来自哪里、关联到什么；过程折叠 | 打开（成为一个标签）、放到 Shelf、验收或再改改 | 在这个结果上继续改，产生新版本 |
| 待办 | 清单 | 勾掉、改期 | 让助理处理其中一项：一个为它办的新任务 |
| 日程 | 时间、地点、参加的人 | 让助理准备材料 | 同上 |
| Coding 会话 | 这次会话在做什么、改动概况 | 打开会话、停止 | 作为补充交给这次会话 |
| 建议 | 从哪来、为什么是现在 | 开始办、以后再说、不再建议 | 改了说法再开始 |

- 任何事件背后有任务时，卡上多一段「在办」：一个任务一行，写当前这一步或等待的原因，可以就地暂停、停止，点开看拆解与对话。
- 有任务停下来等你时，卡顶上是决定请求：要你定的事、为什么问、会改动哪几处；同意、改一下、拒绝，可以逐项同意。「改一下」后说的话作为修改意见，回到这项任务。
- 卡的头上是事件本身（它是从线上移上来的）、状态、「停到侧边」和关闭。
- 关闭、按 Esc、点「新的事」或点别处，回到现在；事件回到线上原来的位置。
- 「停到侧边」：这张卡搬到侧边「对话」页，一直开着，可以一边在主区做事一边看它、点它。
- 「打开」：结果飞到顶部，成为一个标签。

### 4.5 后台任务面板

- 输入框上方常驻的一小块，属于你和助理的对话，不属于某条线：切换事项它不换，列的是这个项目里你交办的和各插件在后台跑的全部任务。
- 平时只占一行：进行中、排队、等你各几件；都正常时收成一句（「3 件在办，都正常」）；没有任务时不出现、不占高度。
- 展开后一项一行：名字、当前这一步或等待的原因、为哪个事件办（或「不属于事件」）、谁在办；等你的排最前，失败的其次。可以就地补充、暂停、停止。
- 点一行打开这项任务的卡：原话、拆解、对话、同意、结果，内容和事件卡里「在办」那一段一样；挂着事件的可以一步聚焦到那个事件。
- 可以把一项「不属于事件」的任务挂到线上的一个事件，或登记成新事件；也可以把任务从事件上移开，它回到「不属于事件」。已经在办的不停、不重做。
- 面板出现、展开和增减行时，工作面和侧边向上让出同样的高度，线的高度不变（原则 3）。更新不移动正在操作的行、不抢焦点；办完的保留到用户看过或收起，之后在侧边「对话」页的历史里找（PWA-132、PWA-139）。
- 所有插件的后台工作按同一个形状报到这里（§6.4），面板里没有按插件名的分支。
- 没有第二个入口：线上不放后台任务按钮，右侧没有「后台任务」页（用户 2026-11-14 定，§8）。要一边看主区一边看一项任务，把它的卡停到侧边（§4.4）。
- 面板展开多高、和助理的回应怎样上下排，由定样定（§10）。

### 4.6 切换事项

- 线头按钮显示当前事项；点开向上展开列表：最近切过的 3 件、按组折叠的事项（各带等你的件数和是否有在跑的工作）、「新建事项」「整理主线」「不选事项」。列表的内容与规则照主线 §4.1、MLN-23，只是位置从顶部换到线头。
- 切换后，线、标签、侧边一起换成那件事的；正在跑的工作不停、不改归属，切回来还在原处。
- 别的事项有事件等你时，线头的数字包含它们；列表里看得出是哪一件。

### 4.7 助理对话并进来

- 「现在」就是主对话的入口：交办、提问都从这里；对方是个人助理，或在「发给」里选的 Character。主对话每一轮都短：回答、派出、收尾；持续的工作在后台任务里办，所以随时能说下一句（主动助理 §7.5）。
- 每项任务的对话在它的卡里（从事件卡或后台任务面板打开）：交办的原话、回复、你的补充、它的提问，按这项任务排，不和别的任务混在一起。
- 要按时间看全部（跨事件的来往），打开侧边「对话」页的「整条线」：一条时间线，每段标明属于哪个事件或任务，点一段聚焦过去。
- 原来的助理面板不再单独存在；它能做的事（选角色、看用量、历史）进事件卡的「更多」、后台任务面板和侧边。

### 4.8 侧边联动

- 主区条目上的「放到 Shelf」落到侧边 Shelf；Shelf 里点一项附到正在写的话上。
- 事件卡停到侧边后，主区、侧边、线三处是同一件事：在侧边点了同意，线上的事件跟着变。
- 侧边打开时线缩到工作面的宽度（窄窗口），或保持整宽（宽窗口），由定样定。

### 4.9 窄屏与键盘

- 390 宽：线只留线头（收成状态环与数字）、输入框和一个「线」按钮；点「线」从底部升起整条线的列表。后台任务面板收成输入框上的一个件数，点开是底部弹层；事件卡也是底部弹层。
- 键盘：一个快捷键把焦点放到线上；左右在事件间移动，回车聚焦，Esc 回到现在；事件卡里 Tab 走按钮，回车是主操作。全程不用鼠标能走完交办、同意、打开。
- 读屏：线是一个列表，每个事件读出名字、种类、状态；状态变化用礼貌的播报，不抢断。
- 减少动态效果时，事件直接出现在目标位置，不飞。

### 4.10 异常

- 发送失败：话留在框里，写明原因，可重发（沿输入回执）。
- 排队、缺授权、模型连不上：任务行和它所属的事件写真实状态（「排队中」「缺授权」「连不上模型」），卡里给下一步。
- 工作失败或部分完成：事件标出，卡里列出做成的和没做成的，可以只重做没成的。
- 对象被删、被移走或没有权限：事件显示「已不在」或「无权查看」，可从线上移走，不显示旧内容（主线原则 7）。
- 断线、宿主重启：回来后线先显示最后一次确知的样子并标「正在核对」，核对完再更新；不重复派出（PWA-137）。
- 事件很多：两翼放不下的收成「更早 N」「之后 N」，点开在侧边列出。

## 5. 插件要登记的

线上的事件靠登记，不靠宿主认识插件。登记是一份声明加一个读取动作，不是往平台里存东西：

| 登记什么 | 说明 | 写在哪 |
| --- | --- | --- |
| 哪些对象是事件 | 对象种类（`ActionSubject` 的种类），以及一个读取动作：给定项目（第二片起加事项）与时间范围，返回这个插件此刻该在线上的事件引用 | 一个插件只报一遍：首选在今天的首页事项读取上扩（Feed、Inbox、待办已在报），线和首页读同一份；是扩它还是并成一份新的，由第 32 批的合同稿定 |
| 时间角色 | 对象的哪个时间是「发生于」（办完的时间）、哪个是「排在」（开始或到期）；没有时间、也不等你的对象不上线，只进「这件事的东西」 | 呈现声明的字段（智能呈现 §4.1 已有「时间」这个语义角色，补上两种用途） |
| 要你处理 | 对象处在哪些状态时算「等你」 | 呈现声明的状态映射（§4.1 已有「要你决定」「要你验收」） |
| 下一步（可选，第二片） | 一个读取动作：给定一个对象，返回它的下一步（文字、能不能直接开始、开始时调哪个动作） | 事项来源声明里，与「自家关联」并列 |

- 事件卡用哪种形态、带哪些操作，全由呈现声明和组合服务定；插件不为线另写样式或另给一套操作。
- 状态变化经呈现声明里的变更通知（智能呈现 §4.6）告诉线，线不轮询。
- 全部是动作目录里的动作，按调用方的权限调用；可信身份从调用上下文来。
- 助理按同一份登记放「交办的工作」，没有只给助理的通道。第一片的登记方是助理、Coding（会话）、待办（到期的待办），另加一个测试用的沙箱插件，证明装上的插件同样能登记；日程、Inbox、工作流程、Pages 在第三片接。
- 后台任务不在这份登记里：插件自己的后台工作报到后台任务总表（§6.4）。一个插件可以两样都报，用同一个对象引用把任务挂到事件上。
- 第一个用上「下一步」的是 Goals；待办的到期、日程的开始时间走「时间角色」。Goals 不在时线照常工作，只是没有 Goals 的下一步（2026-11-13 按插件同等地位收口改，[决定 42](../post-anticorruption-roadmap/reference/decisions.md#decision-42)）

## 6. 平台负责的

### 6.1 线读取

- 主线服务（主线 §6 的 `horizontal/` 包）多一个只读的系统动作：给定项目与事项（可以不选），返回这条线上的事件引用和排法。它自己不存事件，一次调用里合并：
  - 各插件与助理登记的事件（§5）；
  - 这件事里装的、带时间角色或处在「等你」的对象（placement 关联加来源插件的自家关联，第二片）；
  - 每个事件背后任务的状态：任务 ↔ 事件的关联（placement）对上后台任务总表（§6.4），推出进行中与等你；
  - 来源对象的下一步（§5，第二片）；
  - 第三片起：主动助理给的建议。
- 返回的是引用（`ActionSubject`）、种类、时间、状态家族和排位，不带标题和正文；标题、状态词、卡的内容由组合服务按呈现声明取。
- 页面、助理、工作流程、MCP 调同一个动作；外部 Agent 读到的是同一条线的文本形态（智能呈现 §4.5）。
- 调用次数：切到一件事项，线读取一次、组合服务一次批量给出两翼的胶囊；事件卡在聚焦时才取。不按事件逐个请求。

### 6.2 每样事实归谁

| 事实 | 主人 | 线怎样用 |
| --- | --- | --- |
| 事项、分组与顺序、当前事项 | 主线服务 | 线头与切换 |
| 哪些对象是事件 | 登记它的插件；一件交办是不是事件记在助理工作上 | 线读取 |
| 任务、步骤、依赖、等待、接续 | Prologue 任务板（采用线），经 `horizontal/agent-host` 读 | 事件背后的任务与拆解；后台任务面板 |
| 还在跑或等人的后台工作（跨插件的概况） | 各插件与平台按同一形状报的后台任务总表（§6.4） | 后台任务面板；事件的进行中与等你 |
| 交办的原话、补充、回执 | 发起这项工作的一方（助理工作、Coding 会话）与输入回执 | 事件卡里的对话 |
| 插件对象的标题、状态、时间 | 各插件 | 待办、日程、结果等事件 |
| 这件事里装了什么；一个任务为哪个事件办、一项工作归哪件事项 | `horizontal/placement` | 哪些对象可能上线；安放的结果 |
| 发生过什么、先后 | 工作记录（观测和采集层） | 「整条线」的时间线 |
| 卡长什么样、能点什么 | 插件的呈现声明加组合服务 | 胶囊与事件卡 |
| 焦点在哪个事件、卡停没停到侧边 | 工作台状态（PFG-22，按事项那一层） | 切回事项时恢复 |
| 移走、固定、不再建议 | 组合服务的纠正记录（智能呈现 §5「纠正」） | 建议的显示 |

线读取的结果可以缓存，但不是事实：缓存和主人不一致时以主人为准，重读即可。

### 6.3 输入框与焦点

- 聚焦一个事件，等于在统一输入里把它选成收件人（UIV-19、UIV-23）：框里的「发给」标签显示它的名字；「发给」菜单列的和线上的事件是同一批，只是另一种选法。
- 页面登记的收件人（比如 Coding 页里的会话）在线上也是事件；页面在前台时它排在「现在」左边第一位。
- 草稿按收件人分开存：聚焦事件时写了一半，回到现在再回来，字还在。
- 助理工作的范围不因聚焦别的事件改变；补充何时生效按输入回执如实写。
- 「发给」里也能选一个 Character：这句话由它接，它派出的任务结果回到它；框里一直看得见现在是对谁说。切回助理后，两边的草稿、对话与任务互不串。

### 6.4 安放与后台任务总表

- **谁来判断。** 接这句话的一方（助理或所选的 Character，经 `horizontal/agent-host` 调模型）。平台给它两样东西，插件和页面不各写一份：
  - **提示词**：平台维护的一段安放说明，随角色定义下发（[Prologue AI 手册](../../docs/platform/PROLOGUE-AI.md)的提示词管理），讲清五种去处、什么算值得跟、什么时候该问、不该默认塞给最近的事件；回复语言照平台给的回复语言。
  - **工具**：动作目录里的系统动作，助理和页面、MCP 用同一组——读这条线的文本形态（当前事项、线上的事件、别的事项的名字）；把一个任务挂到线上的一个事件；把一件交办登记成事件；作为补充交给已有的任务；把工作归到另一件事项（第二片）；标为不属于事件。
- **什么算值得跟。** 会交回东西的（一份文稿、一张表、一次改动）、用户说了要跟的、和线上已有事件相关的，登记成事件或挂到那个事件；随口的、当场能了结的不登记。这是模型的判断，写在安放说明里，不写成关键词规则。
- **顺序。** 输入送达 → 第一句回应开始输出（不等安放）→ 安放的工具调用 → 回应末尾补上去处。安放没完成时这件事已经在后台任务面板里（去处写「正在安放」），不会看不见。
- **改。** 「改」调同一组动作换去处；已经开始的任务不停、不重做，只换它显示在哪和之后带的上下文。
- **事实。** 一个任务为哪个事件办、一项工作属于哪件事项，是 placement 的关联（任务 ↔ 事件、工作 ↔ 事项）；一件交办是不是事件记在助理工作上。都不在线上另存。安放不改这项工作的授权、预算与数据范围（PWA-135）。
- **模型不准时。** 不为个别说法加措辞禁令、正则或特例；靠三件事兜住：去处永远显示、一步能改；改不产生副作用；安放的工具只接受这个调用方读得到的事项与事件，别的引用被拒。
- **后台任务总表。** 后台任务面板读一份总表（[平台能力审查](../../docs/reviews/platform-capability-audit-2026-11-14.md)第 3 项）：平台跑的后台作业与调度任务由平台自动报，插件自己的长任务用现有的首页聚合读取报，助理与 Character 派出的工作也报这一形状；暂停、停止沿用行里带的命令。面板和线读取是同一份事实的两种排法，不另存任务清单（PWA-138）。
- **等你只读一处。** 线头的数字、事件上的等你、面板里的等你读同一份（平台能力审查第 4 项的读侧）；写侧的收拢在第 56 批。
- **回流。** 任务的结果回到派出它的一方，由它判断并推进；归[主动助理](../proactive-assistant/spec.md) §7.5.4 与 [Prologue 采用](../prologue-adoption/spec.md) §4.6.11，这里不另造消息通道。

### 6.5 外壳

- 顶部一条、底部一条线的版面由工作台外壳提供；插件只提供内容，不各自画线或在页面里放第二个输入框（`AGENTS.md` 外壳约束、UIV-18）。
- 让位：外壳量出输入框与后台任务面板合起来的高度，给被它们压到的工作面和侧边加同样高的下边距；线的高度是常量。
- 线、事件、事件卡、后台任务面板是共用部件，先成组件板标本再进产品。

### 6.6 记录

聚焦、点同意、从卡里开始办、安放与改去处、移走建议写进工作记录，只记谁、哪件事项、哪个事件引用、什么操作，不记正文（同 MLN-18）。

## 10. 定样

- **方向原型**（不是定样）：[`docs/design/work-line/`](../../docs/design/work-line/README.md)。单文件、演示数据、自带一套颜色，没有用组件板的实件。用户 2026-11-12 看过第二版并认可方向；第三版加了线头切换、分种类的事件卡、点事件到中间、助理对话并入，以及用户看过第三版后提的右下角后台任务列表和「先回应、再安放」。原型早于 2026-11-14 的改动：里面线右端的后台任务按钮、把交办直接画成线上一项的做法是旧写法，定样不照它。
- **正式定样**在第 32 批开工时做，照[需求开发流程](../post-anticorruption-roadmap/reference/development-workflow.md)第 5 节：用组件板实件重做，1440、1024、390，中英文，深浅色，正常与异常（排队、失败、断线后核对、读不到）都有。至少对比这几处的方案：
  1. 事件卡展开时主区怎么办：浮在线上方（可一步停到侧边）、让主区让位、还是默认就开在侧边；
  2. 顶部一条里固定插件与标签的排法，以及标签很多时怎么收；
  3. 侧边打开时线的宽度；
  4. 390 宽的线；
  5. 回应与去处的样子：两拍怎样出现、「改」怎样选；
  6. 后台任务面板：收成一行与展开的样子、展开多高、和助理的回应怎样上下排、让位的动效；「发给」选了 Character 时框里怎样显示；
  7. 事件背后有任务时胶囊与卡怎样表达（进行中、等你、几个任务）。
- 线、事件、事件卡、线头按钮、手边、后台任务面板是组件板新增，定下后先补标本。
- 主线切换列表（`docs/design/work-mainline-switch/`）与四种基础形态（`docs/design/intelligent-surfaces-forms/`）已定的部分照用。

## 11. 验收标准

1. **WLN-01** 底部是一条高度固定的线：线头、已办、输入框、接下来，线上没有后台任务按钮；输入框从一行写到多行再删回一行、后台任务面板出现与展开，线的高度都不变。
2. **WLN-02** 输入框多行或后台任务面板展开时，与它们横向重叠的工作面和侧边的下边向上让出同样的高度，内容不被盖住；分屏、侧边打开、1024 宽下同样成立。
3. **WLN-03** 工作台只有这一个输入框；聚焦事件时框里的「发给」显示这个事件，回到现在时显示助理，和「发给」菜单的选择一致（UIV-19、UIV-23 仍然成立）。
4. **WLN-04** 发送一句交办后输入框立即可用，后台任务面板里出现这项任务；登记成事件的，线上在输入框左边同时出现它的事件；连续交办两件，各自更新，互不影响。
5. **WLN-05** 有任务在办的事件与面板里的任务行显示当前步骤的名字，来自任务板的事实；读不到状态时显示最后更新时间与「读不到」，不继续转动。
6. **WLN-06** 任务停下来等用户时，它所属的事件变成等你；输入框为空且焦点在现在时，这个事件自动聚焦，输入框里有字或焦点在别的事件时不自动聚焦、不夺走键盘焦点；不属于事件的任务等你时只在面板里标出。
7. **WLN-07** 点一个事件，它成为焦点并展开事件卡；关闭、Esc、点「新的事」都回到现在，事件回到线上原位；聚焦不改当前事项。
8. **WLN-08** 事件卡的内容与操作来自组合服务按呈现声明给出的操作面描述；工作台里没有按事件种类或插件名手写的卡片内容。
9. **WLN-09** 背后有任务的事件，卡上显示交办的原话与任务板的拆解，每一步标出谁在办与状态；一个事件有几个任务时各自列出；拆解与任务板不一致的用例失败。
10. **WLN-10** 有任务等你的卡列出要改动的地方；点同意后任务继续，事件回到进行中；同意只作用于这个任务对应的那个问题与版本（PWA-135）。
11. **WLN-11** 已办的卡显示结果预览；「打开」把它开成一个标签，「放到 Shelf」落到侧边 Shelf；过程默认折叠。
12. **WLN-12** 聚焦事件时发送的话，作为对这个事件背后任务的补充或修改交给对应的工作（没有在办的任务时，是为这个事件办的新任务），回执如实显示已收到与已用上；不新建无关的工作，也不发给最近的另一项工作（PWA-129）。
13. **WLN-13** 聚焦事件时写了一半的话，回到现在再回到这个事件仍在；各事件与现在的草稿互不串。
14. **WLN-14** 「停到侧边」后，卡在侧边「对话」页保持打开；在侧边点的操作与在线上点的结果相同，线上的事件同步变化。
15. **WLN-15** 原来的助理面板不再作为单独的面板出现；它的功能在事件卡、侧边或线上都能到达，逐项对照清单见证据节。
16. **WLN-16** 顶部一条有固定插件、标签、起始页入口、侧边开关与头像；底部没有 Dock；从起始页能打开任一已装插件。
17. **WLN-17** 键盘：一个快捷键聚焦到线，左右移动、回车聚焦、Esc 回到现在；交办、同意、打开三条主路径不用鼠标能走完；读屏读出事件的名字、种类与状态。
18. **WLN-18** 390 宽下线收成线头、输入框和「线」按钮，整条线在底部弹层里；事件卡是底部弹层；触控目标不小于 44px。
19. **WLN-19** 线头按钮显示当前事项的名字、状态环与等你的数量；点开的列表向上展开，内容与规则符合 MLN-23；没选事项时显示项目的线。
20. **WLN-20** 切换事项后，线、标签、侧边换成那件事的；切换前聚焦的事件与停在侧边的卡，切回来时恢复；在跑的工作不停、不改归属（MLN-06）。
21. **WLN-21** 线读取是主线服务的一个只读系统动作，返回事件引用、种类、时间、状态家族与排位；它的返回与主线服务的存储里查不到插件对象的标题、状态词或正文。
22. **WLN-22** 一个装上的第三方插件在事项来源里给了下一步后，它的对象与内置插件一样带着下一步出现在线上；宿主没有按插件名的分支；项目里没装 Goals 时，线与事件照常工作（事件登记本身在第一片验，WLN-37）。
23. **WLN-23** 「整条线」按时间列出这件事的来往，每段标明所属事件，点一段聚焦该事件；内容读工作记录与各主人，不另存一份对话。
24. **WLN-24** 两翼放不下时收成「更早 N」「之后 N」，点开在侧边列出；线上事件数不随历史无限增长。
25. **WLN-25** 用了子代理的工作，拆解里能看到各子代理这一步；聚焦这一步即对它直接说话，输入归属正确（子代理交互的验收照原样验）。
26. **WLN-26** 主动助理的建议出现在「接下来」，可开始、以后再说、不再建议；移走后同一位置不再出现同一条，记录在组合服务的纠正里。
27. **WLN-27** 切到一件事项时，线读取一次、两翼的胶囊由一次批量组合给出；事件卡在聚焦时才读取；状态更新靠变更通知，没有定时轮询。
28. **WLN-28** 对象被删、被移走或调用方失去权限时，事件显示「已不在」或「无权查看」并可移走，不显示旧标题或内容；未授权的线读取被拒并留诊断行。
29. **WLN-29** 刷新、断线与宿主重启后，线先显示最后确知的状态并标明正在核对，核对后更新；不重复派出工作，已取消的不恢复（PWA-136、PWA-137）。
30. **WLN-30** [人工] 用真实项目连续工作半天：交办三件事、中途补充一件、同意一次、打开两个结果、切换两次事项。全程看得出每件事办到哪，不需要翻对话找进展；多行输入、事件卡、切换时版面不跳、不盖住正在读的内容；深浅色、中英文、三种宽度都看过。

31. **WLN-31** 发送后助理的第一句回应不等安放完成、不等工作办完就开始出现；回应是真实的接单、回答或提问，不是固定的占位话（PWA-128）。输入反馈、首次有意义回应、安放完成三个时刻分别计时。
32. **WLN-32** 每次交办的回应末尾写明去处（补充给某个任务、为某个事件办的新任务、新事件、另一件事项、不属于事件），带「改」；改去处后这项工作不停、不重做，线与后台任务面板随之更新。
33. **WLN-33** 聚焦在事件上、或在「发给」里选了收件人时，不再做安放判断，话直接给所选的对象；助理不把它改投别处。
34. **WLN-34** 安放经动作目录里的系统动作完成，页面、助理、MCP 调同一组；提示词由平台随助理角色下发，插件与页面里没有另一份安放提示词；工具收到调用方读不到的事项或事件引用时拒绝并留诊断行；安放前后这项工作的授权、预算、数据范围不变。
35. **WLN-35** 后台任务面板在输入框上方：显示本项目进行中、排队、等你的件数，都正常时收成一句，没有任务时不占高度；展开后每行标出为哪个事件办或「不属于事件」、谁在办，等你的排最前、失败的其次；线上没有任务按钮，右侧没有「后台任务」页。
36. **WLN-36** 从面板点一项打开它的任务卡，内容与操作和事件卡里「在办」那一段一致；挂着事件的可一步聚焦到那个事件，别的事项的可切过去或把卡停到侧边；把任务挂到事件、登记成新事件或从事件移开后，已在办的不停、不重做。面板、线、卡三处状态一致，没有第二份任务清单（PWA-138）。
37. **WLN-37** 事件登记：助理、Coding、待办和一个装上的沙箱插件按同一份登记把事件放到线上；宿主与工作台里没有按插件名、也没有按「是不是助理」的分支；一个插件只报一遍，线与首页读同一份登记；某个登记方读取被拒或失败时，线照常显示其余事件并标出读不到的来源。
38. **WLN-38** 事件的状态来自主人的对象状态与它背后任务的状态：有任务在办显示进行中，有任务等你显示等你，任务都结束后回到主人给的状态；任务结束不移走事件；同一事件先后的几个任务都能在卡里查到。任务 ↔ 事件的关联在 placement，线读取的返回与主线服务里查不到任务进度的副本。
39. **WLN-39** 后台任务总表：平台跑的后台作业与调度任务、Coding、助理与 Character 派出的工作，以及至少一个别的插件的长任务，以同一形状出现在面板里，并能用行里带的命令停止；面板与工作台里没有按插件名的分支。线头的数字、事件上的等你与面板里的等你读同一份，三处件数一致。
40. **WLN-40** 在「发给」里选一个 Character 后，这句话由它先回应、能后台办的派到后台、结果回到它，面板里标出是它在办；切回助理后两边的草稿、对话与任务互不串；这个 Character 被停用或移除时，它在办的任务如实显示并可停止。

### 15.2 平台能力检查

1. **别的插件会不会也要做。** 会。事件登记：待办、Feed、Inbox 今天已在报首页事项，Coding、助理本批接，日程、工作流程、Pages 在第 53 批接。后台任务总表：Coding 已在报，生图、Feed 拉取、定时执行、Alchemist、助理本批接。对象引用与打开：第 44、53、56 批都要用。「等你」读取：第 53、56 批读同一份。
2. **平台里有没有现成的。** 有四份底子，都是补，不另写：首页事项读取、首页聚合的后台任务合同、呈现声明与组合服务、placement。没有的只有两样：线读取（新的主线服务包）和「启动接续」的宿主回调（SDK 里已经留了口子，Molis 没实现）。
3. **是不是插件之间怎样协作的问题。** 是。「谁的任务为谁的事件办」是跨插件的关联，用 placement 一份统一的关联加主人自带的关联，不按一对插件各写一条路。
4. **第三方插件能不能同样做到。** 能：登记、报任务、声明呈现都在 Manifest 与 SDK 里，沙箱插件用例验证。只有内置做得到的一处要收掉：今天总表的停止命令是插件自己的路径，改成动作引用后装上的插件同样能给。
5. **助理和 Agent 能不能发现、调用。** 能：线的文本形态、安放、总表、等你都是系统动作，MCP 读到同一条线；没有界面时，助理靠这几个动作就能说清一件事在哪、谁在办、卡在哪。

### 15.3 五个场景与比较过的做法

| 场景 | 结论 |
| --- | --- |
| 插件 | 作者多做的只有一件：给要上线的对象补呈现声明里的时间与等你。登记本身沿用已有的首页事项读取，已经在报的三家不用报第二遍 |
| 平台 | 线读取、总表、等你读取归平台；内容与状态仍归各主人。外壳要跟着变（顶部一条、底部的线、面板的让位），运行时与授权不变，只是启动接续多一次复核 |
| 助理 | 主对话变短、任务在后台、结果回流，都落在助理已有的工作、委派与接续上，不新造调度；Character 用同一套 |
| 各类平台能力 | 接统一输入（「发给」里加 Character、聚焦事件即选收件人）、呈现与组合（事件卡）、placement（任务与事件的关联）、Attention（等你）、观测采集（聚焦、同意、安放写工作记录）、输入回执（补充的两步）。和技能包、连接器、成果库、同步没有重叠 |
| 后续开发 | 第 36 批在主线服务包上加事项与存储，第 53 批只多接登记方，第 58、59 批沿用「发给」，第 56 批做等你的写侧，第 44 批让 Goals 消费要求认可能力。再加一家登记方只改那个插件自己的 Manifest 与一个读取动作 |

比较过的做法：

- **事件登记另起一份合同，还是扩首页事项读取。** 选扩。另起一份会让待办、Feed、Inbox 报两遍，线与首页对不上；扩的代价是要同时改三家提供方和三处消费者，本批付。
- **任务与事件的关联放哪。** 比过三种：都由任务主人自己记（每家都要做一个「改挂到哪」的动作，面板里的「挂到事件」就得按插件分支）；都放 placement（主人本来就知道的归属要再写一遍）；主人自带的由主人报、后挂的放 placement。选第三种，和主线里「placement 关联加来源插件的自家关联」是同一个做法。代价是 placement 要先接受不止一个关联名，这一步第 36 批本来也要做，提前到本批。
- **等你在读的时候合并，还是写的时候投成 Attention 条目。** 本批选读时合并：写侧的收拢排在第 56 批，本批先让三处读同一份、件数一致。代价是读取要问几处，用并行与变更通知压住；第 56 批收拢后读取变成只问一处，调用方不用改。
- **回流在宿主里补，还是改 Prologue。** 选改 Prologue（用户已授权并定了随本批换包）：在宿主里补要另写一份「子任务要输入」和「一个会话同时一轮」，以后还得搬回去。代价是本批多一次换包。
- **主对话是新的一种东西，还是一项助理工作。** 选后者：每个范围（个人、每个项目）与每个对话对方有一项常驻的工作当主对话，后台任务是它名下的子工作。不新增存储与运行时概念；代价是今天「子任务只能一层、同时三个」的限制要按预算重定。
- **本机导入的原生 Character 能不能直接对话。** 本批不能：它在终端里跑，不经平台的运行时，没有回流与记录。「发给」里只列平台能跑的 Character，原生的标明原因；等它接进运行时再开。

让谁多付了代价：本批多了换包、placement 的一步、六十来个浏览器用例的重写；第 37 批的定样要按没有「线右端列表」重看一处（已在认领板留言）。
