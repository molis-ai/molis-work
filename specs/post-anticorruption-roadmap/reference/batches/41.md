## 给人讲清楚

技能包装上以后，什么时候用哪个还不清楚：你点名的、AI 自动挑的、只许手动用的混在一起，也看不出它为什么选了这个。这一批定下选用规则：你点名的优先，可以设成自动或只手动，告诉你选它的依据，选错了能改、能停用。需要你做的：看选用说明、改选和停用的样子并定下。

### 第 1 项 · Skill 选用

- **定样**：用户选 A「回复上方一行」；怎么自动选，用户定「AI 按任务自己选，平台限三个，原话匹配的旧逻辑删减」。两项决定与按推荐直接定的取舍都在 [Skill 策略 §10](../../../prologue-strategies/skill.md)，开工前检查在 §11。
- **做了什么**：
  - 关口在 Skill 目录一处：带轮次号的一轮里，未点名的自动技能最多读三个不同的，第四个拒绝（`over_limit`）；「这次不用技能」的一轮里未点名的自动技能读不了；点名的不占名额；仅手动照旧不能绕过。
  - 「这一轮用了哪些技能」不另存：Agent Host 从这一轮自己的工具调用里派生 `skill_reads`，助理与 Coding 各按自己的轮次记录拼出「你点名的／自动选的」。
  - 回复上方一行（SDK `/ui` 的 `renderSkillLine`），助理与 Coding 同一个部件；依据面板归工作台外壳，页面经登记的 `molis:skill-pick-open` 请它打开，改选经 `molis:skill-redo` 回到那一行所在的页面再发一轮；插件 iframe 由插件框转发。
  - 面板里：为什么用它、做什么、什么时候用、来自哪个包哪一版、现在的设置；这一轮可以换一个重做、这次不用技能重做；以后可以改成仅手动／恢复成自动、停用（都带撤销）、去设置里看。保存失败在面板里就地说「什么都没改」并可重试。
  - 点名的技能用不了（SKL-16 基础层）：这一轮不开始，不换成别的，每个各说原因，再给三件能做的事。
  - 组件板新增两件标本：选用行、依据面板。
- **与需求或原型不同的地方**：
  - 不用底座的 `selectSkills`／`config.skill.selection`（用户定）；Molis 工具目录里没有消费者的 `find-skills`／`read-skill` 不再提供，原因记在 `RUNTIME_TOOLS_NOT_OFFERED`，原 BL-skill-hand-and-tools-consumers 关闭。
  - 依据不显示「对上的词」：没有原话匹配就没有这一项。
  - 来路只分「你点名的」「自动选的」两种；原型里的「你改选的」并入「你点名的」（重做那一轮里就是你选的，不另存一种来路）。
  - 「几个技能各自的结果」列表（原型的 `sel-steps`）不做：Molis 没有分步执行技能这回事，随第 62 批的方法链做，不进组件板。
  - SKL-15（工具面可见或可找）、SKL-16 的依赖暂停与重启接续属完整上游策略，由第 62 批收口；本批不宣称。
- **已知局限**：
  - 轮次进行中的名额记在目录的进程内存里（最多 512 轮）；宿主中途重启，未结束的那一轮名额重新算。
  - `skill_reads` 从读取调用的结果里解析；结果被截断时这一次读取记不进「用了」那一行（限数与用量不受影响，它们在目录里记）。
  - 给人看的拒绝说明是中文原句（宿主存量写法，随第 16 批的服务端文字清理一起换成键）。
- **验证**：`tests/security-invariants-skill-selection.test.ts`（限三个、点名不占名额、不用自动技能、无轮次号不计不记、读取只从自己的工具调用派生）、`tests/agent-host-skill-reads.test.ts`（SKL-16 基础层、轮次号）、`tests/assistant-methods.test.ts`（点名与「这次不用技能」）、`tests/coding-interaction-html.test.ts`（Coding 的选用行）、`tests/sdk-ui-markup.test.ts`（部件标记）、`tests/skill-picks.e2e.test.ts`（真实 Host 与测试浏览器里的依据面板、助理的选用行）。`pnpm health:check --base origin/main`、`pnpm boundary:check`、`pnpm page-assets:check` 通过；页面资源单项均不到 10 KB，许可在 `tooling/gates/page-asset-allowances/skill-selection-b41.json`。

### 第 2 项 · 规划方法变成技能

用户 2026-11-14 的几次决定见 [Skill 策略 §10](../../../prologue-strategies/skill.md)，合起来：规划与拆解是独立的技能包，随系统自带、默认自动、在设置里统一管理，**和 Goals 没有关系**；不迁移、不留迁移代码。交付表里「个人存量方法搬成技能」随之不做。

- **已做（技能一侧）**：
  - `plugins/content/planning-methods`：37 个技能，中英两份正文与目录词条，只给个人助理。
  - 随系统自带的技能包：`pack-content.json` 写 `system`，构建打到 `apps/local-host/dist/system-skills/`，技能目录直接读，不经安装；默认档可由包声明，关掉会记住。
  - 技能正文可带译文（`SKILL.<语言>.md`，声明 `locales`）。
  - 随包带上、要本人安装的包（「设计与无障碍」）在官方密钥之前以待签形式发，安装时由本机身份签名；`S-bundled-packages` 同步。
- **在做（Goals 一侧）**：删 Goals 的内置方法库、个人库与 Home 半实例、项目方法、采用规划方法、相关动作与页面；目标关系图检查与变更影响分析保留。
- **待做**：设置里新建、修改自己的技能（先定样，用户确认后再写）。
- **验证**：`tests/system-skill-packs.test.ts`（37 个技能的内容、译文声明的拒绝、新 Home 里不装就在目录且默认自动、按语言读正文、关掉记住）、`tests/security-invariants-bundled-packages.test.ts`（待签包只在本人安装时由本机签名）。
