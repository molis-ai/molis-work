## 1. 背景

来源：MISC「T-124 二审 @68a240244 建议 1、2、4」的①②。T-124（#1448）让 Runtime 在读不到安装记录时仍放掉本进程激活的实例。`packages/plugin-runtime/src/activation-context.ts` 里（约 :33-41，先核）：

```ts
export async function releaseUnrecorded(activation, executor, revoke): Promise<never> {
  revoke();
  // A failing stop hook has nothing left to mark crashed: the missing record is the failure reported either way.
  if (activation) await Promise.allSettled([outsidePluginAction(() => executor.stop(activation.definition, activation.context))]);
  throw pluginErrors.definition_missing("Plugin installation 不存在");
}
```

注释说“钩子抛不抛，报的都是记录不存在”。但 `outsidePluginAction(run)`（`action-scope.ts:182`）同步调用 `run`。如果执行器的 `stop` 是一个**同步抛错**的普通函数（不是 async），错误在数组字面量里就抛出了，`Promise.allSettled` 根本接不到，`releaseUnrecorded` 以钩子的错误码退出，而不是 `definition_missing`。现有的执行器都是 async（所以走不到），但合同 `PluginExecutor.stop` 没有要求 async，注释承诺的行为应该对所有执行器成立。

另外 `packages/plugin-runtime/README.md` 的不变量里（约 :79 附近，`stop()` 那一条）没有写 T-124 新加的语义：读不到安装记录时 `stop` 仍放掉本进程激活的实例（先撤销授权，再调执行器的 `stop`），缺记录本身是这次 `stop` 的失败，钩子是否抛错都一样。

## 2. 目标

1. `releaseUnrecorded` 里让执行器的 `stop` 无论同步抛还是异步抛都被 `allSettled` 接住：例如把调用包成 `async () => outsidePluginAction(() => executor.stop(...))`，或 `Promise.resolve().then(...)`（但保持“在撤销授权之后、仍在 outsidePluginAction 里调用”这两点不变）。之后一律抛 `definition_missing`。
2. 用例 `RAC-2400`：执行器的 `stop` 是同步抛错的函数时，`runtime.stop(...)`（读不到安装记录的那条路）抛 `plugin.definition_missing`，不是钩子的错；同一条里再断言钩子被调用过一次、授权已撤销（照 T-124 加的同类用例的写法，放在 `tests/plugin-lifecycle-states.test.ts` 里，`git show 1d2057c8a7 -- tests/plugin-lifecycle-states.test.ts` 能看到 T-124 加的 52 行）。
3. README 的 `stop()` 一条补上第 2 段说的语义，一两句话，写法照该条现有的风格。

## 3. 不做

- 不改“放掉实例”的顺序（先撤销授权，再调 `stop`）、不改 `definition_missing` 的码和信息、不改别的路径（有记录时的停止、`preserve_enabled`）。
