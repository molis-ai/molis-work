# 工作台品味

Molis Work 是 **Linear × coss 的个人工作台**：连续纸面、细边界、紧凑控件、短反馈。北星是 **Operate**——先找到当前工作，读清事实，再做下一步。

本文从历次纠偏、对话，以及后来写进 spec / [`DESIGN.md`](../../DESIGN.md) 的要求里抽出，作为切片验收口径。不另起一套风格。实现细节、token、控件几何以 `DESIGN.md` 和 `/__ui/catalog` 为准；工艺禁令见 [`ui-craft-floor`](../../specs/ui-craft-floor/spec.md)。

参考可以换（Linear、coss、Codex、Notion、DropAgent、Chrome 标签），但整站只准一套皮。

**验收口头禅：** 像不像真正好用的工具、和整站是否一致、动线顺不顺、会不会廉价 / 毛坯。

有几处当场拧过方向，标在对应条的「纠偏」里。

---

## 视觉

1. **气质是专业工具。** 首页可以更有空间感，工作台必须是工具密度。默认卡片墙、大数字看板、装饰性图表属于后台和营销站，工作台不用。
2. **颜色分层：壳是冷锌；靛只给链接、选区、进行中。** 插件用稳定身份色找路（Goals 蓝、Feed 棕、Inbox 薄荷…）。色只编码所有权和状态，整张纸不要涂成插件色。
   - 纠偏：「太素了要合理配色」；GoalTree「太花晃眼睛」。
3. **层级靠字号和 ink / muted / faint，默认字重 400。** 选中改底和颜色，不加粗。中文界面文案走 i18n；Goal 标题和用户正文保持原文。
4. **状态不能只靠颜色。** 语义字 + Lucide + 浅色洗底标签（约 11%、5px 圆角）。不要描边胶囊，不要球场形 pill。绿 / 琥珀 / 红是完成 / 注意 / 阻塞；闲置、进行中、等人另有一套安静伴色。
5. **图标只走 Lucide，和所在表面成套上色。** 插件身份用 `--plugin-tint`，状态走 status family，chrome 用 ink / muted。禁止 emoji / Unicode 当图标，禁止灰图标配随机强调色。空态要有对象图标，不能只剩一行灰字。
6. **薄边界 + 色阶表达结构，少阴影少圆角表演。** 目录行平；工作区贴齐、直角、无投影。升起面才用发丝边 + 克制投影。
   - 纠偏：点名讨厌无用边框、双层描边、廉价阴影。
7. **深浅色是同一套语义，禁止浅色硬编码白底。** 深色场 / 导航 / 纸面 / 升起必须能分开，遮罩压暗不提亮。
8. **编译绿、测试绿不等于视觉过关。** 改了人能看见的界面，要在真页面上看焦点、hover、打开、到达、空态、窄屏。文字方案不能验收视觉。

## UI / 控件

9. **只用 `mw-*` 和 Catalog，不要每页再发明一套按钮。** 对照 `/__ui/catalog`。达标的共享控件、状态、微动效要补标本。进产品主链前换成 `mw-*`。
10. **操作系统默认控件不准当产品 UI。** 下拉打开必须是 `mw-menu`，不要 macOS 白底菜单。禁止系统色盘、系统日期时间、`alert` / `confirm`、未换肤的 range。
    - 纠偏：为此专门要求写进开发规范。
11. **焦点是贴在控件内侧的 1px ink 实线，不要外扩蓝框。** 全局禁止粗靛紫 / 蓝色描边和 3.5px 光晕。书写面（新建 Goal 那种）用底线，不要框。
    - 纠偏：「蓝框太丑、被裁切、很廉价」。
12. **主按钮要够明显。** Light 是黑底白字、圆润边（Coss）；次按钮纸面；幽灵默认透明。Hover 变色阶，不浮起。禁用必须仍看得见，不能藏掉。危险操作（删除）走红，和导出 / 保存不要同等权重。
13. **表单动作同一栏：取消在左，主操作在右。** 独立保存区要写清保存的是哪一块。弹窗正文不要把提交和取消拆到两个世界。
14. **列表像表，不像卡片。** Feed 关闭态是来源 + 标题，摘要点开才出现。行要对齐列轨（标题 / 类型芯片 / 事实 / 状态），类型用色标签，不要「所有列表都太干」。
15. **空态教用法，并给出一个真实可点的动作。** 不要假按钮、不要未接通功能装成已接通。
16. **Shelf 是例外：跟 DropAgent，不跟 Coss 锌壳。** 其余插件跟工作台，不搬 Adeptify React/CSS，不另起皮肤。

## 交互

17. **每个控件要有默认 / hover / focus / press / disabled（异步再加 loading）。** 缺一态就是半成品。
18. **Hover 是行自己在让位，不是一块跟着鼠标走的高亮。** 长文件名尽量展开，动作出现时标题被挤短，180ms 缓出。不是 `display:none` 硬切。
    - 纠偏：参考 DropAgent。
19. **Notion 式「动作适时出现」。** 行头手柄、块操作、次要动作跟鼠标 / 焦点走，不要一上来摆满工具。
20. **点对象就进工作面。** 列表 / 画布 / 看板是三种并行视图，点 Goal 都进 Frame。插件母页默认全屏列表，点进详情再收；插件默认页不要自动开标签。
21. **同一分屏内部点击不重装、不搬工作面。** 标签、正文、目录选中、终端身份保持一致。打开 Goal 不启动 Runtime。未提交输入要保住。
22. **失败保留草稿，给出重试，不丢字。** 在途禁止重复提交和误取消。部分成功要说清哪步成了、哪步没成。
23. **键盘能走完主路径。** 焦点可见、Esc 取消、⌘/Ctrl+Enter 提交、焦点回到入口。尊重 `prefers-reduced-motion`。
24. **文案短、准、从用户视角。** 不要过度解释，不要 AI 味。状态用白话中文，原始 ID 后置给追溯。

## 动效

25. **动效表达状态变化，不为动而动。**
    - 纠偏：首页方案「不要花里胡哨，是工作台风格」。
26. **走过去或到达，不要硬切。** 切插件、分段选择用滑块位移；菜单 / 舞台用 6px 上升 + 透明度（`creative-arrive`）。重绘不要整页再播一遍入场。
27. **时长短、曲线固定。** Hover / press 约 90ms；边界约 130ms；到达约 190ms。分段滑块可以略带过冲。Press 是色调下压，不做位移缩放。
28. **质感要对标 DropAgent 那种「自然、丝滑、高级」。** 列表 hover、标签拖拽换位、时间流 / 百叶窗，都要像材料在让位，不像特效。
29. **切页签不要从全透明闪白。** 加载进任务，不要编排开场动画。

## 布局

30. **外壳钉在一屏里，滚动发生在内容自己的容器。** 顶栏、标题、搜索、工具条不动；只有列表 / 正文 / 卡片区滚。矮窗口（1024×400）也成立，根页面不滚。
    - 纠偏：「上面都不动，只有下面会滚动。」
31. **桌面默认就是 Linear 工具密度，不要靠用户去开紧凑。** 目录行约 28px，标签条约 32px，侧栏约 240px。窄屏 / 触控仍 44px，输入 16px。首页诗意留白是例外：不要拿它去收工作台，也不要用工作台密度去毁首页。
32. **结构是 48px 插件轨 + 当前插件目录 + 一块连续舞台。** 项目切换 / 搜索 / 设置在标题栏，占轨 + 目录那一段宽，和目录同高、顶边对齐。各插件目录默认宽度对齐。
33. **连续工作面，减弱弹窗感。** 内容贴齐 pane，不要居中悬浮大框、大圆角、投影、遮罩。新建用居中、按内容长高的 modal；改已有关系用右侧贴边编辑器。搜索和破坏性确认才用短浮层。
34. **分屏是细缝 + 呼吸（约 8px），不要高亮整条分割线。** Hover / 拖时中间出手柄。VS Code 那种换布局，新分屏先出 `+` 让人挑 tab，不要默认填内容。
35. **对齐是底线。** 插件轨上下间距一致；列表相对分组标题要缩进；搜索不要两层边框；标题栏和目录对齐；列芯片不要随标题长短乱跑。
    - 纠偏：为此发过火。
36. **设置是独立文档，不是再塞一层工作台目录。** Codex 式分类轨 + 居中约 760px 栏，一组卡片、左文案右控件。工作台密度和设置文档密度可以不同。
37. **原生窗口细节算产品。** 红绿灯不被盖住，拖动区不是按钮，标题栏控件和系统按钮视觉中线对齐。

## 用户动线

38. **主路径永远是：定位 → 看清事实 → 做下一步。** 打开项目先能找到当前工作；详情先给未完成要求、待决定、阻塞和入口，历史默认收起。
39. **导航按插件，不按后台模块。** 轨选插件，目录只显示当前插件的列表，舞台是该插件的工作。切插件时目录和下方内容一起换，带切换反馈。
    - 纠偏：左栏已经切走、右边还停在旧 Goal，明确否掉。
40. **配置发生在现场，不要总控台。** Feed 规则在 Feed 任务里配，Inbox 下一步在 Inbox 配，函数用在哪由那个场景选择。总览页可以列「被用在哪」，开关不搬到一个超级设置页。
41. **动作放在手边。** 标题 / 状态在左，动作在右；对话入口是窄的适时浮层（约 300×32），不要横幅盖住工作面。
    - 纠偏：Inbox 处理条「放底部动线太长」。
42. **去哪、从哪回来，必须还在。** 设置返回原先项目和工作；当前标签缩放后仍可见；收起分组不能把当前工作藏掉。取消回到原入口并还焦点。
43. **读和处置分开。** Feed 先读正文再处理；已读 ≠ 去向。Inbox 是要人介入的注意力，不是 Feed 换皮。
44. **创建轻、编辑贴边、空态有一条真实下一步。** 新建 Goal 是两行书写（名字 + 结果），次要字段收进一处披露，不要技术字段前置。空画布 / 空列表只留一个真实创建口，不要重复按钮。
45. **注意力要保护，尤其是首页。** 第三栏适时出现；不要一上来把一天全摊开。工作台则相反：有内容的列表必须密，空页才可以呼吸。
46. **AI 不是加一个 Chat。** 要说清它看什么、产出什么、人在哪干预、失败怎么恢复。首页「说一句」可以在，但不能冒充已开放 Agent，不能挡住主工作。

先做真内容的高保真切片；用 Impeccable 打磨，但切片方向以当场纠偏为准。端到端从真人路径验，不拿局部截图代替。
