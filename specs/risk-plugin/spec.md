# 风险插件：专门记录风险

状态：已定方向，待设计与实现（2026-10-05 用户提出：做一个专门记录风险的插件；2026-10-27 确定风险独立记录、Goal 顾虑按需引用）。项目视图与复查提醒仍待决定，当前未实现或验证。

## 为什么

Goal 里原有的风险（风险表、Goal–风险关联、风险决定与安全面板）在防腐整理中连表带显示删除（#272）：它们是旧「领取」流程的一部分，与事件流程两套记账。用户希望风险作为独立的东西被认真记录，而不是挂在 Goal 结构里，所以另做一个插件。

## 要做到

- 记一条风险：说明、影响、可能性、处置办法、负责人、状态（打开、缓解中、已接受、已关闭）。
- 风险可以关联 Goal、Coding 会话、Feed 消息、成果等对象，经公开的对象引用，不 import 其他插件的实现。
- 风险独立记录，Goal「顾虑」按需引用（2026-10-27 用户已定）：风险说明、影响、可能性、处置和状态只由风险插件拥有；同一风险可以关联多个 Goal，不在 Goals 复制风险记录。
- 人或执行 AI 判断某条风险确实影响当前 Goal 时，可按 Goals 原合同提出顾虑并引用它，写明对具体要求、事件或动作的影响。风险不自动生成顾虑，也不要求所有顾虑都关联风险。
- 风险与顾虑各自表达状态：风险被接受、缓解或关闭，不自动接受/解除顾虑，也不直接决定 Goal 是否能完成；顾虑处理继续使用 Goals 的既有证据与授权规则。反过来，一个 Goal 的顾虑解决也不自动关闭其他 Goal 仍在引用的风险。
- 能力注册到共同目录（列出、读取、记录、更新状态），页面、工作流、Agent、MCP 用同一套动作。
- 只走 Plugin Runtime 装配，插件只提供内容，挂在工作台的位置。

## 已定关系的验收

以下为后续实现的标准，本次只写需求；证明行为的测试须引用对应编号。

| 编号 | 可观察结果 |
| --- | --- |
| RISK-01 | 风险可独立存在，同一风险被多个 Goal 引用时只有一份风险事实；修改风险后各引用可读取该事实，Goals 不复制风险字段与状态 |
| RISK-02 | 记录或关联风险不自动创建顾虑；人或执行 AI 可按 Goals 既有合同提出具体范围的顾虑并引用风险，未关联风险的顾虑仍可正常使用 |
| RISK-03 | 风险与顾虑的状态变化不互相机械覆盖；风险关闭不绕过 Goal 收尾条件，一个 Goal 的顾虑解决不替其他 Goal 关闭风险，既有证据与授权检查有效 |
