# T-034 停止一个崩掉或还没启动的安装时，Runtime 记 `disabled`，人的停用才撑得过 Host 重启

> **这条在 main 上成立，修的地方在 Runtime，不在 Host。** T-032（#1357，起草时还开着，head `88311d557`）让 `lifecycle('disable')` 吞掉 `plugin.state_invalid`，停用不再被拒；但 Runtime 里的记录仍是 `crashed`。Host 重启时只看这条记录：`apps/local-host/src/installed-plugin-host.ts:195-203` 把除 `disabled`、`quarantined` 以外的状态都当「启用」，提示词登记成 `enabled`，再去启动它（`home-installed-plugins.ts:158-161` 同样）。统筹实测的结果是：`state: 'failed'`、提示词 `enabled`、没有 `generated.` 动作；`offering`（`apps/local-host/src/agent-definitions/agent-definitions.ts:316`）于是又把提示词的方法提供出去。人关掉的东西，重启后又回来了。起草时我没有重跑这个现象，下面「Runtime 才对」的依据都是读代码。

## 1. 背景

为什么不在 Host 修（依据都在 main `b707895b4`）：

- 从 `crashed` 到 `disabled`，Runtime 现在只有一条路：`recover`（`packages/plugin-runtime/src/index.ts:567-613`）再 `stop`。`recover` 会跑插件的启动代码、花恢复预算（`:582`、`:592`）、还可能把它隔离（`:570-578`、`:600-606`）；`assertRecoverableState` 也只放 `crashed` 进（`runtime-rules.ts:40-44`）。Host 想「先恢复再停」，等于为了关掉一个崩掉的插件先把它再启动一次。
- 在 Host 另记一个「人关过」的标记，是同一项事实有两个主人（`docs/SSOT-MATRIX.md`）：重启时 Host 唯一读的就是 Runtime 记录（`installed-plugin-host.ts:195-196`、`home-installed-plugins.ts:158-159`）。
- 崩掉的安装没有活实例：`reportCrashOnce` 已经停了执行器、撤了上下文（`index.ts:547-556`），启动失败和恢复失败也撤上下文（`:478`、`:600`）。所以 `stopOnce` 对它只差一次写记录，不需要等任何东西。

`stopOnce` 现在（`index.ts:493-537`）：`disabled` 当重放（`:495`）；除 `running` 外一律 `plugin.state_invalid`（`:496-498`）；没有活实例时直接写 `disabled`，带 `preserve_enabled` 写 `installed`（`:499-510`）；执行器停止失败写 `crashed` 并抛 `plugin.executor_failed`（`:511-527`）。

其他状态怎么办：

- `quarantined` 必须继续拒绝：`disabled` 可以被 `start` 启动（`:458`），记成 `disabled` 就等于一次停止解除了隔离；`packages/plugin-runtime/README.md:69` 写明隔离不能被普通恢复绕过，要显式 `release_quarantine`。
- `installed` 一起改。刚安装还没启动的记录就是 `installed`（`:261`）；`installed-plugin-host.ts:191` 让发布者被撤信任的安装只被「挂起」，而挂起只停 `running` 的（`installed-publisher-standing.ts:42`），所以这类安装重启后停在 `installed`，人此时停用它，同样会丢（我读代码得出，没有跑过）。在运行中的 Host 里别的路到不了 `installed`：启动失败写 `crashed`（`:477-486`），`regrant` 的停止带 `preserve_enabled` 且在同一把锁里接着启动（`regrant.ts:36-44`）。`installed` 本来就可启动（`:458`），记成 `disabled` 绕不开任何检查。
- 带 `preserve_enabled` 的停止对 `crashed`、`installed` 仍拒绝：那是 Host 关闭时用的，把崩掉的记成 `installed` 会抹掉崩溃，记成 `disabled` 会替人做决定。`installed-plugin-host.ts:183` 只按 Supervisor 的状态判断 `running`，一个崩掉、没被人停用的安装在 Host 关闭时仍会因此抛出：这是另一个问题（T-035），不在这里修，见第 3 节。T-032 的 RAC-1150 第一例里 `finally` 吞 `AggregateError` 的 `.catch` 多半是多余的：那一例先停用，停用先 `supervisor.revoke`（`installed-plugin-lifecycle.ts:163`），被撤的插件不在 `enabledPluginIds()` 里（`supervisor.ts:572-575`、`:325-329`），关闭循环不会碰它（统筹 2026-10-28 读代码的推断，没跑）。

谁会受影响（`runtime.stop` 的调用，加了 `running` 判断的不受影响）：

- 不受影响：`supervisor.ts:292-294`、`:475`、`:601`，`regrant.ts:40`，`index.ts:326`，`installed-publisher-standing.ts:42`，`project-plugins.ts:97-98`，`home-plugins.ts:168-169`，关闭用的 `installed-plugin-host.ts:183`（带 `preserve_enabled`）。
- 变好：`installed-plugin-lifecycle.ts:163` 的停用（T-032 已吞掉拒绝，现在记录也改对）；`home-plugin-http.ts:111` 的 Home 内置插件停用路由，崩掉的现在会抛、停用做不成（T-005 锁着该文件，本任务不改它）。
- 行为变了：T-032 的曝光失败清理（`installed-plugin-exposure.ts:50`，T-032 head `:53-55`）和 T-007 的启停刷新（`project-plugin-enablement.ts:36`，#1340 加了吞拒绝）。两处的吞拒绝以后只剩 `quarantined` 会碰到，保留。刷新停掉一个崩掉的项目插件，现在记 `disabled`，不再「保持原样」；加回名单时走启动，不再走恢复（`supervisor.ts:455-493` 的 `#restart` 只对 `crashed` 恢复）。
- 没有测试和 S 号钉着「停止拒绝非 running」：`git grep` 测试里的 `不能停止`、`stop` 加 `state_invalid` 都没有命中；`SECURITY-INVARIANTS.md` 没有隔离、停止这一条；`plugin-runtime-integration.test.ts:517-520` 钉的是 `start` 不能启动 `crashed`，本任务不碰。

测试放哪里（原则上不往 `tests/installed-plugin-host.test.ts` 加新例，RAC-1195 是统筹同意的例外，理由如下）：Runtime 层放 `tests/plugin-lifecycle-states.test.ts`（文件头 `:16-20`、`:23-66` 有「新建一个 Runtime 接着读同一个仓库」的写法，`probe()` 在 `:195`，`reportCrash` 的用法在 `:560-582`）。Host 重启那一例**只能**放回 `tests/installed-plugin-host.test.ts`：`ensureInstalledPlugins` 不从包入口导出（`apps/local-host/src/index.ts` 里没有），只能走 `../apps/local-host/dist/...` 相对路径；「测试引用包内部」对任何 `tests/**` 新文件从 0 起算（`scripts/check-health-gates.mjs:372-405`），一条就红。而且本任务不得不改那个文件里 T-032 的两例，见第 4 节。

## 2. 目标

1. 不带 `preserve_enabled` 停止 `crashed` 或 `installed` 的安装：记录变 `disabled`，`last_error_code`、`recovery_count` 不动，不再调执行器的 `stop`，回执 `replayed: false`；新建的 Runtime 读同一个仓库仍是 `disabled`，`start` 能把它启动（`RAC-1193`）。
2. 拒绝不变：`quarantined` 仍以 `plugin.state_invalid` 拒绝且保持隔离；`crashed` 带 `preserve_enabled` 仍拒绝；`uninstalled` 仍拒绝；运行中的安装停止钩子失败仍记 `crashed` 并抛 `plugin.executor_failed`（`RAC-1194`）。
3. 停用一个崩掉的安装，Host 干净关闭、重启之后：`installations()` 里它是 `disabled` 不是 `failed`，提示词是 `disabled`，没有 `generated.` 动作；启用能把它启动起来（`RAC-1195`）。

## 3. 不做

- 不动 `quarantined`、`uninstalled` 的拒绝，不动 `preserve_enabled` 路径，不动 `startOnce`、`recoverOnce`、`reportCrashOnce`、Supervisor。
- 不在 Host 另存「人关过」的标记，不写 Host 端的补丁去改 Runtime 记录。
- 不改 `packages/contracts/src/platform/plugin.ts:247` 的注释「Stop a running Plugin」：`packages/contracts` 在 `affected-tests` 的共享核心名单里（`scripts/affected-tests/rules.mjs:21-23`），碰它 `full` 会变 true，注释措辞留给以后顺带改。公开 API 快照不含注释，所以快照不变。
- 不修 `installed-plugin-host.ts:183`（关闭时对崩掉、没被人停用的安装抛出）；那是 T-035，本任务不顺手改。
- 不写兼容或迁移：存量记录里没有「人关过却丢了」的行可补——T-032 之前停用崩掉的安装整条被拒，没有写过任何记录；T-032 到 T-034 之间只在开发机上有。
- 不改 `home-plugin-http.ts`、`installed-plugin-exposure.ts` 的逻辑（T-005、T-032 的），不新增 S 号。
