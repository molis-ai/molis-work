## 怎么打开

在仓库根目录运行，然后打开 <http://127.0.0.1:4471>：

```sh
python3 -m http.server 4471 --bind 127.0.0.1 --directory docs/design/sessions-sources
```

也可以直接用浏览器打开本目录的 `index.html`。底下一条斜纹是**原型控制**，不是产品的一部分：选「块」「方案」「状态」，切中英文和浅深色；「标出组件」见下；「还原」清掉本页记住的选择（`localStorage` 键 `molis-proto.sessions-sources.v1`）。

## 三处要定的

| 块 | 方案 | 取舍 |
| --- | --- | --- |
| 发现会话 | **A 按工具分组**：列表按工具分节，每节标题带数量；没读成、暂不支持的工具在自己那一节里占一行，点开看原因 | 每个工具的状态最清楚；但同一件事在两个工具里做的会话被拆开，工具多了要往下翻 |
| | **B 按时间排，来源条看状态（推荐）**：所有工具的会话按最近活动排在一起，行里写是哪个工具；读取进度、哪几个来源没读成放在列表上方一条提示里，「看每个来源」展开逐个看和处理 | 天天回来看最顺手，跨工具接着做的事挨在一起；来源都正常时只剩一行安静的说明。代价是来源细节要多点一下 |
| | **C 先看来源总览**：三栏，最左是来源（每个工具的数量和状态），中间是会话，右边是历史；1024 以下来源栏收成工具下拉 | 来源多、经常排查读取问题时最直观；平时多占一栏，详情变窄 |
| 归属建议 | **A 在会话里就地确认**：打开一个待归类的会话，顶上就是 AI 建议、理由与依据，确认、改选或先不归 | 不用另进一处；但要一个个打开，看历史时也一直被问 |
| | **B 待归类集中处理（推荐）**：「待归类 N」一处，每个会话一张卡：建议、理由、依据，下拉可改选，确认或先不归；看历史时只留一行提示和入口 | 一次处理完，看历史不被打扰；理由和依据都摆在眼前 |
| | **C 按建议的项目成组**：「建议归到 Molis Work · 3 个」一组，勾选后一次归入；没找到合适项目、没生成建议的各成一组 | 会话多时最快；但容易不看理由就整组确认 |
| 查看历史 | **A 原文对话（推荐）**：你、那个工具、它的工具步骤按原样往下排；顶上可搜索，往上读更早的 | 最接近原工具，什么都不加工；长会话靠搜索和往上读 |
| | **B 左边提问目录，右边原文**：左边是你每一次提问，点了跳过去；1100 以下目录收成下拉 | 长会话找段落快；详情区更挤 |
| | **C 要点在上，原文在下**：AI 按原文整理定下的、做出来的、还没完的，每条连回原文第几条，可纠正、按最新内容重整 | 冷启动接手最省事；要点是 AI 推断，要标清、要能纠正，模型不可用时只剩原文 |

三处在所有方案里都一样的：读取只在「读取范围」一处允许（Sheet：勾选工具、选目录；暂不支持的工具不能勾、写明原因），查看和搜索不会让原工具运行或发消息（详情顶上写明「只读」），改归属只改这一个会话（Dialog：不改目录与项目的关系、不搬文件、不改原工具里的记录）。

## 每块的状态

| 块 | 状态 |
| --- | --- |
| 发现会话 | 正在读（先出一部分）；全部读完；有来源没读成（需要登录、这一版读不了、没读成可重试，与「没有会话」分开）；读完了范围内没有会话；还没允许读；收窄了范围 |
| 归属建议 | 有建议待确认（含多候选、AI 没找到合适项目）；建议没生成（模型不可用，保持待归类）；你改选后来了新建议（不覆盖你的选择）；都处理完了 |
| 查看历史 | 正常（原工具还在运行，只显示已读到的）；长历史在读更早的；会话里搜索；读到一半断了（已读的照常显示）；这一版读不了（不是没有历史）；已停止读取这个工具（之前读到的也不显示）；这个工具暂不支持读取（回到原工具） |

分叉出来的会话是新会话，带「从……分叉」的来源（盘点 §4 第 2 条）。

## 放在哪里

外壳用组件板「栏与内容框」（`.mw-layout-primitives` 下的插件栏、目录栏与内容框），列表是 Directory Panel，详情是 Frame。左边插件栏里的「外部会话」只占位：入口放在工作台的哪里随[第 03 批](../../../specs/post-anticorruption-roadmap/reference/batches/03.md)的工作台定样，不在本批定。

## 对照组件板

原型控制里点「标出组件」：每个构件用虚线框出并写组件板上的名字；红框是**组件板新增**。

| 用到的组件板构件 | 在哪里 |
| --- | --- |
| Sidebar（栏）、Directory Panel、Directory Row（带数量、状态）、Frame | 外壳、会话列表、来源栏、提问目录、详情 |
| Toolbar、Input Group（搜索）、Toggle Group、Select | 顶上的范围与工具筛选、会话内搜索 |
| Alert（带动作行 `mw-ix-actions`）、Progress、Status mark、Item Row、Mark | 读取进度、来源没读成、每个来源一行、归属提示 |
| Empty（含 `mw-empty--error`）、Loading、Skeleton | 没有会话、读不了、没读成、往上读更早的 |
| Card、Checkbox Group、Radio Group、Sheet、Dialog、Field | 待归类卡片、成组归入、读取范围、改归属 |
| Who（人是圆的，AI 是方的） | 原文里的你与工具 |

**组件板新增**（进产品前由 D 轨先在组件板补标本，再用）：

| 新增 | 为什么已有的不够 | 原型画法 |
| --- | --- | --- |
| 外部会话原文 | 组件板只有助理与 Coding 的气泡，没有「别的工具里的一段对话」：要分清你、那个工具和它调用的工具步骤，长历史能往上读、能就地搜索并标出命中 | 每条一行：Who 头像、名字、时间、正文；你的话放在 `--wash` 底的气泡里；工具步骤是带细边的一行（动作、对象、结果）；会话开始等说明居中淡色；命中用 `--amber-soft` 底加 `--amber` 下划线 |

## 模拟边界

所有工具、会话、目录、对话都是示例数据（`data.js`），没有读任何工具的记录，没有调用模型，也没有连真实 Home。按钮只改本页状态：允许读取后用计时器模拟读完；「在终端接着做」「打开原工具」「去登录」「重试」不做任何事。
