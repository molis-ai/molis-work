# 平台记忆系统 Goal Prompt

让 Molis Work 拥有达到“内部完整”的平台记忆系统。个人与项目记忆成为平台能力，助理、Agent 运行、插件、界面推荐（Jev 判断）和外部 MCP 共用同一套记忆和同一组开关。记忆能按规则自动形成并可撤销；用户在设置里看得见、改得了、停得掉、删得净。唯一 spec 是 [spec.md](spec.md)，本文件写目标状态和推进方式。

## 最终应达到的状态

1. **记忆是平台能力，不再属于助理。** Host 记忆服务通过统一能力目录提供 `memory.*` 动作。助理第一版的开关、停用名单和候选全部迁移过来，一条不丢，助理原有行为不退化。
2. **维度清楚、隔离可信。** 个人记忆在所有项目可用，项目记忆只在本项目可用。换项目、换角色、委托子任务、换插件都不越界。每条记忆有类别、适用情境、来源、依据、状态、有效期和版本历史。
3. **能形成，能更新。** 五条来源都能用：明确要求、工作结束时提炼、界面行为信号、手动编辑、导入。新的明确要求能修正旧记忆，推断不能覆盖明确要求。
4. **自动写入可信。** 由确定性的写入门批准，模型只提议不批准；门的规则版本写在来源里。只有低风险类别、反复明确出现的内容会被自动写入。单次行为、仅靠推断的内容、背景事实、像指令的文字、形似秘密的文字都不会被自动写入。每次自动写入都出现在“最近变动”里，并且可以撤销。
5. **使用统一、说得清。** Agent 运行以 Prologue `memory-recall` 数据档注入，有预算、有出处；各使用方的开关和上限真实生效。能回答“你记住了我什么”“这次为什么这样做”；每条记忆显示最近用在哪次工作。
6. **不会过时。** 重复会被合并或提议合并，冲突交给用户选择，到期和长期未用的会停用，依据失效的会暂停召回。整理靠持久队列，重启不丢。从不自动物理删除。
7. **用户能管理。** 全局设置“个人 → 记忆”和项目设置“项目记忆”页面完整：最近变动、等你认可、逐条修改 / 停用 / 删除 / 查看历史 / 改范围、怎么形成、谁可以用、导出导入、先预览再清空。项目记忆可以“升级为项目说明”，走原有的确认流程。
8. **隐私与安全。** 秘密不进入长期记忆；召回来的记忆不能提权；个人记忆不因参与项目而共享；插件和外部 MCP 只按授权读取。停用和删除的语义不同，删除后任何路径（缓存、整理结果、子代理返回、重启后）都不再带出该条。
9. **优先用 Prologue。** spec 第 8.1 节列出的能力直接使用。第 8.2 节的 S1–S5 补进 SDK；补好之前用过渡办法，而且过渡办法不得变成第二套记忆运行系统。
10. **失败可恢复。** 模型失败、提炼超时、迁移中断、重复提交时，不产生半条记忆，不重复写入，不丢失已有记忆。

验收以 spec 第 14 节 AC-M01–AC-M16 为准，用真实代码路径、真实模型（MiniMax-M3 经 Prologue；需要判断时用真实 Jev）和真实浏览器操作证明。

**完成的判断**：用户在任何 AI 入口都不必重复交代同样的偏好和项目约定；自动记住的内容对得上、撤得回；设置里能准确看到并控制记住了什么、为什么被用上。工程验证、真实场景验证和用户本人验收分别如实记录；不能把可演示或局部可用当作内部完整。

## 推进方式

**位置**
- 分支是 `feature/memory-system`（基于 `feature/system-assistant` 2e837e8f，已含 spec 和本文件）。在你自己的工作树里执行 `git switch feature/memory-system`。
- `feature/system-assistant` 有新提交时再合进来；它合入 main 后，改为以 main 为基线。

**SDK**
- 只有本线改 Prologue SDK。
- 先核对当前 vendored 包：`feature/system-assistant` 上是 `prologue-sdk-0.0.0-rc.1-assistant-intake.tgz`，并确认它是否已含 project 作用域（`~/code/prologue-assistant` 的 `ac4d1135`）。
- 改动在单独的 prologue 工作树里做，父提交用当前包所在的提交。平台侧栏那条线也会从同一个 SDK 父提交打补丁，两边按顺序叠加，后落地的一方负责变基。
- 同步 `scripts/workspace-packages.mjs` 里的包名。旧的 tgz 只能由用户删除。

**顺序**
- 按 spec 第 13 节的 M1 → M5 推进。
- M1 的第一件事是定下 `memory.recall`（按情境读取）和“界面信号上报”的合同，写进 `packages/contracts/src/services/memory.ts`，然后发给动态交互会话（它在分支 `feature/contextual-interaction` 上，先用替身对接）。

**决策**
- 范围清楚、可以撤回的取舍按 spec 推荐直接做，写进 spec 第 16 节并附理由。
- 只有影响目标、权限或关键产品取舍的问题才问用户。
- 必须先问用户的对外操作：push、开 PR、推 prologue 上游、删除 vendored 文件。

**与其他会话的边界（开工前先对齐）**
- **助理会话**（系统级个人工作助理，`~/code/goalboard-assistant`，端口 4240/4241）：`apps/local-host/src/assistant/` 里只改记忆调用处；约定助理表的迁移方式和它合入 main 的节奏；别进它的工作树，也别用它的端口。
- **page-interaction-flow 会话**（`.claude/worktrees/page-interaction-flow-redesign-49fe35`）：它正在收拢设置分类（`settings-sections.ts`、`settings-navigation.ts`、`settings-assistant.ts`），记忆设置页挂在它的新分类表上，先和它对好方式。
- **面板改版会话**（分支 `claude/determined-stonebraker-06644e`）：底栏和助理面板归它。要在工作面板里显示“已记住 · 撤销”“用到的记忆”，先和它对好区块。
- **动态交互会话**：只通过 `memory.*` 合同对接，不改对方的文件。

**验证环境**
- 隔离 Home：`--home` 加 `MOLIS_WORK_HOME`，并设置 `MOLIS_WORK_SECRET_BACKEND=file`。不要拷贝别的会话或真实 Home 的密钥库。
- 真实模型只能在进程内从真实 Home 读取模型配置，不打印、不落盘；做不到就停下来问用户。
- 在 `.claude/launch.json` 里新增自己的预览项，端口避开 4173、4207、4208、4240、4241、4270、4281。
- 改源码后按包 build，再重启预览（服务进程会缓存 dist）。
- 跑回归期间不要改文件。全量回归先和基线比对，区分既有失败和本线引入的失败。
- 界面改动过 craft-finish 设计门禁（`tests/soft-workbench-refinement.test.ts`），并在 1440、1024、800、390 宽度和深色下用真实浏览器操作。

**记录**
- spec 第 17 节写进度与证据。
- 跨会话要点写进自动记忆 `memory-system-platform-goal`。
