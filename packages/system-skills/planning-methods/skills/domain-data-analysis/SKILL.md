# 数据分析

从决策问题、口径和数据质量走到可复现结论。

适用于：指标分析、因果探索、预测与分群。

## 规划路径

1. 定义决策问题和分析单位
2. 固定口径、时间窗和数据来源
3. 清洗并检查偏差
4. 分析、敏感性检查和可复现交付

## 必须覆盖

| area | label | question |
| --- | --- | --- |
| data_question | 分析问题 | 结果要支持什么决定？ |
| data_quality | 数据与口径 | 来源、缺失、偏差和定义是什么？ |
| analysis_validity | 分析有效性 | 哪些假设、对照和敏感性需要检查？ |
| decision_delivery | 决策交付 | 结论怎样被使用和复现？ |

## 依赖规则

| rule_id | statement | direction_hint |
| --- | --- | --- |
| analysis-after-quality | 正式分析依赖冻结的口径和通过检查的数据集。 | analysis depends_on validated data |
| decision-delivery-after-analysis | 结论交付和决策建议依赖已完成的分析、反证与敏感性检查。 | decision delivery depends_on validated analysis |

## 完成证据

- 数据来源和口径
- 可复现查询或脚本
- 质量与敏感性检查

## 收口检查

- 结论回答原决策问题
- 限制和外推边界明确

## 常见误拆

- 先画图再定义问题
- 混用口径
- 把相关性当因果

## 怎样用这份方法

- 先按「规划路径」把事情想完整，再把每个能独立交付、独立验收的结果列成一项；一项里不混入几个主要结果。
- 「必须覆盖」里与当前任务有关的每个问题都要有答案；答不上来的关键问题列为待确认，不用含糊的条目盖过去。
- 依赖只表示结果消费：乙开始或完成时必须用到甲的可验收产出，乙才依赖甲。讨论顺序、时间先后、同一个人负责、改同一份文件都不算依赖；没有结果消费关系的保持并行。逐条判断「依赖规则」，不适用的要说得出缺了哪一种产出消费。
- 每一项写明完成时拿什么证明（见「完成证据」），收尾前过一遍「收口检查」。
- 只描述有限、能完成的改变；持续运行的事不写成永远做不完的一项。
- 和别的规划方法一起用时，把各自的关键结果放在一起看谁消费谁，缺了提供方的再补上相应的方法。
- 拆出来的结果先给用户看。用户要落到某个工具里（例如已装的 Goals 插件）时，用那个工具自己的动作写入，由用户确认。
