## 做了什么

Host 执行的 Runtime 插件可在自己的并发动作里，经 `context.services.materials` 调用现有平台材料提取与公开来源读取能力。`materials:read` 只给 `extract`，`materials:fetch` 只给 `readSource`；授权来自真实运行中的安装、动作与调用者。取消、撤权、停用、升级或动作结束后拒绝结果和业务写入。对应防腐唯一 spec 的 RAC-25–30，后续灵光迁移复用本服务。

模型下载只接受可信 `user` 调用中的明确允许；Agent、MCP、工作流和插件传 true 仍不下载。沙箱、升级预检、启动钩子、直接路由、外来安装和串行动作没有调用资格。SDK 的 `decodeMaterialUpload` 成为唯一上传检查，拒绝路径、坏扩展名、非规范 Base64、空内容及超过 25 MiB 的字节。

已有平台实现的 Jelly 前缀改为材料服务命名，来源错误统一由 `material.*` 拥有；当前灵光调用方同片更新。原生格式提取、原件业务身份、模型配置与 `{home}/lingguang/models` 位置保持；没有库结构变化，也不接触真实 Home。

前置为流式路由 #703；本候选尚在本地，按 Todo → 流式路由 → 材料顺序开放 PR，不增加第三个在途 PR。材料编号按用户决定为 S-34；新 #699 也使用该号，开 PR 前须由用户转达统筹协调，当前没有更改其他线。

## 公开合同与 API 影响

材料客户端与请求类型加到插件服务合同，`contracts/services/materials` 提供共同上传与来源结果类型，SDK 导出上传解析与支持格式工具。API 快照 `contracts/platform/plugin`、`contracts/services/materials`、`plugin-sdk/index` 同片更新。现有 Host 调用方与灵光错误处理同步，没有动作 schema、版本或 MCP 名称变化；第三方插件需在 Manifest 和并发动作中分别声明实际所需的材料权限。

能力不新增第二套注册；身份只取原调用上下文。外部请求、原生提取和结果交付前后复查 `beforeEffect()`，无新增数据库、后台作业、缓存兼容路径或宽松兜底。原来一次性材料整合里的安全表缺号问题已通过纳入现行 S-32/S-33 消除，未修改门禁。
