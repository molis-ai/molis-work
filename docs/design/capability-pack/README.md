## 模型

```
能力包（写作工具 · acme.writing 2.0.0）
├─ 角色和它的提示词
│   └─ 写作编辑 ── 写作编辑的说明
├─ 技能：写周度复盘、会议纪要、排日程
├─ MCP：（没有）
└─ 工具：read_file、write_file、web_search
```

- 示例里有 8 个包：写作工具（签名内容包）、Coding 开发（2 个角色、3 条提示词、2 个 MCP、6 个工具，没有技能）、目标推进（对外的 Molis Work MCP）、日常助理、我的研究（你自己组的）、本机导入 · Claude Code（只有技能、没有角色）、法务审阅（插件停用）、合同助手（已卸载）。
- **包没有自己的开关**（spec §4.3「不新造开关」）。包的状态从它装的东西和它的插件读出：在用；N 项要处理（逐项写出，如「排日程：暂时用不了」）；已停用（插件停用，去处是「启用插件」）；已卸载（只剩历史）。
- **工具是系统的**，几个包可以声明同一个；工具详情列出「在这些能力包里」。谁真正能用，仍由角色的工具名单决定。
- 每一条（角色、提示词、技能、MCP、工具）的详情沿用第一轮定好的写法：「现在」一块写状态与去处；用量写清范围（「近期 N 次」「只有最近一次」「次数随第 61 批」）；MCP 三种「开」分三行；提示词不显示正文；技能是 08 那一块原样。角色详情里多了「它的提示词」，提示词详情里多了「属于角色「…」」。

## 两个方案只差「包里的东西怎么摆、一条怎么打开」

| | A 列表＋包详情（推荐） | B 包卡片＋包内目录 |
| --- | --- | --- |
| 打开时看到 | 左边能力包列表（名称、带了什么的小图标计数、状态），右边选中那个包：状态与去处、角色卡（角色一行，下面是它的提示词）、技能、MCP、工具格、上次升级 | 能力包卡片：名称与来源、状态、一句说明、搭配的角色、带了什么 |
| 打开一条 | 在右边就地打开，顶上一行「回到「写作工具」」和路径（包 / 角色 / 这一条） | 点卡片进包页：上面是包本身（状态与去处），下面是 08 的列表＋详情——左边按「角色（提示词缩进在下）、技能、MCP、工具」分组，右边是选中的一条，默认第一个角色 |
| 一屏的主焦点 | 右边那个包 | 卡片时是全部包；进包以后是包里的列表 |
| 和 08 | 列表＋详情部件照用（左边是包）；包详情里的角色卡、工具格是新的 | 包内就是 08 的目录，只多了分组标题和缩进的提示词行；卡片是新的 |

### 取舍

**A 列表＋包详情（推荐）**

- 注意力：一屏同时看到「有哪些包」和「这个包里有什么」；要处理的写在包详情顶上的一句里，列表行末的状态让你不用点开就知道哪个包有事。
- 认知负荷：包的结构（角色→提示词、技能、MCP、工具）一次摊开，正好就是用户说的那个层级；打开一条后路径一直写着，不会迷路。
- 主路径步数：看一个包有什么 1 步（点包）；看一条并去改 2 步（点那一条 → 去处按钮）；开关技能 2 步（点技能 → 三档）。换一个包 1 步，左边列表一直在。
- 和 08 的一致：同一个列表＋详情部件；技能那一块原样。
- 组件板新增：包的状态与去处块、角色卡、工具格、路径行、小图标计数（下文）。
- 代价：右边一栏要装下包的全部内容，再打开一条就是第三层，靠路径行兜住；1024 宽时右边偏窄，角色卡的说明会折两三行。

**B 包卡片＋包内目录**

- 注意力：卡片页一眼看全部包和各自的角色，第一次来最好懂；进包以后注意力全在这个包上。
- 认知负荷：包内和 08 的技能目录同一个样子，熟悉；但卡片和包页是两种画面，要记得自己在哪一层。
- 主路径步数：比 A 多 1 步（先进包）；在包里切换条目很快（左边列表一直在）；换一个包要先回到卡片。
- 和 08 的一致：进包以后最高。
- 组件板新增：能力包卡片、包内列表的缩进提示词行；加上两个方案共用的几件。
- 代价：常来的人每次多一步；换包要回卡片页；包头和列表一起占掉首屏的上半截。

### 推荐 A，理由

1. 正好是用户说的层级：包列表 → 一个包 → 角色带提示词、技能、MCP、工具，同屏摊开，不用切页。
2. 常用路径最短：看包、换包、打开一条都不多走一步，左边列表一直在。
3. 和 08 一致，组件板新增少：同一个列表＋详情部件，技能那一块原样。
4. 三种宽度都成立：窄屏一次一边（包列表 → 包 → 一条），每一层都有回去的按钮。

## 和 spec 不一样的地方（选定后先改 spec）

spec 现在写的是「五类条目由各自主人上报、能力包只汇总」的目录（§2、§4、§5）。按用户的模型，**「包」成了一个装东西的对象**，下面几件 spec 还没写，要在 spec 和 9-8 合同稿里补：

1. **谁说一个包里有什么**：插件和第 08 批的内容包可以在自己的声明里写（插件本身就是一个包）；用户自己组的包（示例「我的研究」）是新的用户数据，要有主人和存储，碰「不新建注册表」那条，要用户拍板。
2. **角色和提示词怎么连**：今天提示词挂在插件和调用处（Manifest `agent.prompts`），没有「属于哪个角色」。要在角色或提示词的声明上加这条关系；不属于任何角色的提示词放哪里（示例把 Feed 的「消息摘要」放在日常助理的角色下）也要定。
3. **一条可以在几个包里**：工具肯定是；技能、MCP 能不能也在几个包里，示例只让工具重复。
4. **导出导入以包为单位**：「导出这个包」把技能包、角色引用、提示词改写、工具和 MCP 的引用放进一个文件，导回时各部分仍走 spec §5 各自的路（技能走 08 的安装确认、提示词改写逐条确认、其余只核对在不在）。
5. **包的状态**：从内容和插件读出，不加开关；如果用户要「整包停用」，是新开关，另问。

### 交互与动效

- 打开一个包、打开一条、回到包时，右边从下方轻轻升起（`craft-rise`、`--dur-move`、`--ease-quint`），首次打开不播；导出菜单、导入面板同样升起；`prefers-reduced-motion` 下都不动。
- 窄屏（列表＋详情部件自己的容器宽度 ≤ 640px）一次一边：A 是包列表 → 包 → 一条，每层顶上有回去的按钮；B 是卡片 → 包页列表 → 一条。焦点移到新打开那一层的标题。
- 宽屏时右边贴在滚动区顶上，自己太长时自己滚。
- 搜索同时找包和包里的东西；按包里的东西找到时，那一行写「包含：写周度复盘」。
- 技能改三档立即生效，提示里可以撤销（照 08）；菜单 Esc 关上，焦点回到「导出这个包」。

### kit 缺的（不是组件板新增）

- `window.mwKit` 没有 `renderEmpty`、`renderInput`、`renderSkeleton`、`renderToast`、`renderRadioGroup`、`renderCollapsible`：原型照 SDK 的同一份标记写，建议 D 轨加进 `kit/build.mjs`。
- `kit.css` 不带条目行规则（`catalog-patterns.ts` 的 `ITEM_ROW_STYLES` 与 `.mw-mark`）：`pack.css` 里标 `[kit 缺]` 照原样写了一份。

## 模拟边界

- 数据是编的（`data.js`），不读任何 Home，不调任何动作。
- 改技能三档、导入套用、导出只改本页内存或只弹一句提示；刷新或「重置」后回到初始。
- 「去 X」一类按钮只弹一句提示，说明会去主人的页面。
- 原型画在全局设置上，项目范围写在标题下；产品里能力包按调用上下文的项目汇总（spec §9）。
