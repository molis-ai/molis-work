# 插件列表对象的管理闭环

## 目标与证据

当前多个原生插件允许创建列表项，却无法从对应列表移除，部分可编辑设置也缺少更新入口。目标是让用户创建的对象在原插件中完成创建、查看、修改和移除，并在操作后看到最新状态。目标等级：功能可用。

## 范围与行为

- 图片：连接可编辑、删除；生成记录可删除，运行中的记录须先取消。删除连接时保留既有生成记录。
- 定时任务：可编辑标题、说明、时间和通知设置，可归档并移出活动列表；归档应停止后续唤醒并保留已执行的对话。其他插件注册的定时 Job 只在其所属插件管理。
- Cognia：用户建立的领域、来源可改名和删除，资料可更新和删除，草稿可归档并从列表移除；领域或来源删除后相关暂存预览失效，被历史版本引用的材料须保留版本可读性。
- 实验：可删除未运行或已完成的实验；正在运行的实验先取消。自定义模型可删除，内置模型的已存覆盖配置可删除并恢复默认值。
- 插件工坊：可移除未发布的构建草稿；已发布插件及其 release 保持可用，不由列表删除破坏安装。
- Coding：可移除或归档用户会话，同时保留正在执行任务的安全边界。
- Alchemist Studio：方向可归档并从活动列表移出，相关点子和报告继续可读。

删除/归档操作要验证对象归属与状态，失败时给出可理解的错误，成功后刷新当前列表和详情。历史、引用、发布产物按已有产品语义保留。只修改这些对象及实现所必需的 Host 路由、存储、客户端和测试；不重做只读、派生或历史记录列表。

## 方案与验证

沿用各插件现有存储与路由，不引入跨插件通用 CRUD。按对象现有持久化语义选择硬删除或归档，服务端先实现状态转换，再加页面入口。验证包含直接调用服务/路由的成功与边界用例、相关 UI 操作、定向测试和类型检查。涉及调度的任务验证删除后不会再次唤醒；涉及文件的记录验证文件清理与跨项目隔离。

开放问题：运行时若发现某项与历史引用或发布契约冲突，以保留历史和发布可用性为准，并在交付中注明限制。
