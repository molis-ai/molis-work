## 1. 口号与开场

**Work, People, AI, Tool, get connected better than ever.**

人、AI、工具与工作，前所未有地连在一起。

**工具和 AI 围着你转，你还是你。**

Molis Work 是装在你电脑上的 AI 工作台：工具按你的做法长出来，AI 照你的规矩做事，要紧的决定留给你。

> 口号由负责人 2026-10-19 定，替换工作室原定的首屏标题"让工作，在人、工具与 AI 之间继续"。英文按语法建议写成"Work, people, AI and tools — connected better than ever."，用哪一种待负责人选；中文句、副标题和解释句是本稿建议。几家 AI 共用项目说明，已有 AGENTS.md 这类通行文件；能接外部 Agent 的中枢也已经有了（Notion、Linear、Conductor）。Work 的不同在于：说明之外，目标、要求、依据、进度、谁验收过，也是几家都读写、带版本、存在你电脑上的记录；同一个动作目录给界面、助理和外部 AI 共用。

### 开场

我们相信，每个人在工作里的价值都不一样。你做过的项目、踩过的坑、慢慢养成的习惯和判断，让你成为现在的你，也让你有了自己的做事方式。Molis Work 想帮你守住这些。

所以在这里，工具和 AI 围着你转：

- **你的工具，长成你的样子。** 需要什么就装什么；缺一个顺手的，描述一句，让 AI 做出来（开发中）。用久了，你的工作台会和别人的不一样，因为里面的插件、规则和做法都是你攒的。
- **你的 AI，按你的做法做事。** 模型你自己选；你的规矩和做法写一次，你用的几个 AI 都读得到；系统和插件交给模型的提示词放在设置里，你看得见、改得了。
- **要紧的事，你说了算。** AI 可以记录、提议、动手；放宽要求、替你验收、动你没允许的东西，得你点头。
- **工作接得上，而且换了一种样子。** 线索挂在事情上，不挂在某一段聊天里，换个 AI 也接得上；AI 缺信息时给你一张能填的卡片，要动手时给你一张能点的卡片；手上选中什么，就对它做什么，结果回到原处（开发中）。

如果你写代码：把你在 Claude Code 里攒的规则和 Skill 导进来（开发中）；每个功能写清要求，哪条要你亲自验收。Agent 说做完了，没过你那一关就不算完。

如果你管项目、天天在跟进别人：周会纪要贴进来，你答应的和在等别人的分开记，到了跟进日首页提醒你；约好的范围要改，得你点头。

如果你写东西、做研究：勾几条材料整理成带出处的稿子，选中一句交给 AI 改，结果回到原处（开发中）；缺个顺手的小工具，描述一句就做出来（开发中），你和你的 AI 都能用。

我们让工具辅助你，而不是让你被工具牵着走。

> 开场里每一句都对应今天的功能，成熟度不同：要求、本人验收、改约定要你点头、项目长期说明 **已发布 · v0.2.0**（源码，当时名 GoalBoard）；模型自选、提示词设置、提问卡与操作卡、纪要整理与跟进提醒（需模型）、带出处成稿（需模型） **main 可用**；导入规则与 Skill 成角色、选中一句交给 AI 并放回原处、描述一句做出工具 **main 部分**，对外标"开发中"。逐句的对应见第 5 节开头。

## 2. 一分钟介绍

### 通用版（约 230 字）

每个人做事都有自己的一套：怎么拆任务、怎么查依据、什么时候必须自己看一眼。AI 越来越能干，这一套却常常被挤到一边：换个 AI 要重讲，AI 说做完了你还得自己核，结果在几个应用之间来回搬。

Molis Work 把这一套留在你手里。目标、文档、待办、资料和代码各有一个家，你的助理、Claude Code、Codex 都读写同一份；你的规矩写一次，几家 AI 都读得到；要你验收的，AI 替不了。手上选中一段就能交给 AI，结果回到原处；缺一个顺手的工具，描述一句让 AI 做出来，你和你的 AI 都能用。资料存在你的电脑上，模型用你自己选的。

### 写代码的人（约 200 字）

你有自己的写法：项目约定写在 CLAUDE.md 里，Skills 攒了一堆，哪些地方必须在真机上亲手点一遍，你心里有数。今天用 Claude Code，明天换 Codex，后天开三个 Agent 并行。AGENTS.md 能让它们读同一份项目说明，可这个功能约好了什么、做到哪、哪条你亲自验过，还记在各家各自的会话和记忆里。

在 Molis Work 里，一个功能是一个目标：要达到什么、有哪几条要求、每条的依据是什么、哪条要你亲自验收。几家 Agent 经 MCP 读同一份、往同一份里报进度；Agent 想改约好的结果或放宽要求，要你点头；它说做完了，收尾会对一遍，手机排版还没验，就不算完。菜单栏看得见谁在等你。

### 写文档、管事情的人（约 210 字）

你有自己读资料、下判断、跟进人的方式。每天看很多资料，要写方案、周报和研究，还有一堆要跟进的事。对话 AI 开在旁边，复制进、复制出；资料在一处，稿子在一处，待办又在一处，你的那套方式被拆散在几个应用里。

在 Molis Work 里，订阅和邮件进信息流，按你设的规则把要你处理的送进收件箱，注明是哪条规则筛进来的。勾几条材料就能整理成一份带出处的稿子；在稿子里选中一句，记成待办、交给助理改写，结果放回原来的位置，出处跟着走。周报做成演示稿、问卷收回来做成表，都在同一张工作台上。重复的做法可以存成流程，下次照着跑。

### 技术视角（约 230 字）

Molis Work 是插件基座加多插件的本地平台。一个 Home 只有一个常驻宿主进程，管项目库、插件、动作目录和 AI 运行时；桌面 App、浏览器、命令行和 MCP 入口都连到它。

内容归插件：目标归 Goals，文档归 Pages，待办归待办，每项事实只有一个主人，别的插件只引用不复制。每个插件把自己的查询和操作注册进同一个动作目录，界面、内置助理、工作流程和外部 AI 客户端从这里发现和调用，按调用方逐项授权，调用留记录，被取消或撤权的调用不再写业务记录。模型调用统一走一个运行时，可接 Anthropic、OpenAI、DeepSeek、通义千问、Kimi、GLM、MiniMax 等十种模板，预算和凭据在一处管。数据存在本机 SQLite 里；用模型、联网查询和连接器时，相关内容会发到对应服务。

## 3. 哪些时候，人在围着工具转

下面五个时刻，都是人在迁就工具：替 AI 重讲、替 AI 核对、替工具搬东西。Molis Work 想把顺序倒过来。

| 时刻 | 今天的样子 | Molis Work 让它围着你转 |
| --- | --- | --- |
| **换个 AI，就得重讲一遍** | AGENTS.md 一类文件能让几家共用项目说明，但约好了什么、做到哪、谁验收过，还记在各家的会话和记忆里；换工具或隔几天回来，这些要重新交代 | 目标、要求、依据、进度、文档和待办存在你电脑上的一处，带版本，几家 AI 经同一个动作目录读写 |
| **AI 说做完了，不等于做完了** | Agent 过早宣布完成、测试没过也打勾，Agent 厂商公开的长时任务实践里也写过这种失败；人最后才发现 | 每条要求有依据，指定"要你验收"的项没有你的结论就收不了尾；改约好的结果要你点头 |
| **东西散在五六个应用里** | 资料、稿子、待办、代码、会议记录各在一处，AI 结果靠复制粘贴搬回去，出处在路上丢了 | 选中就能交给 AI 或别的插件，结果放回原位、出处跟着走；⌘K 一处搜 20 个插件的内容 |
| **缺一个顺手的工具** | 表格太散，专门的软件太重；让 AI 写个脚本，还得自己想办法接进日常工作和别的 AI | 插件创作台把一句描述做成插件，装上就能用；你、助理和外部 AI 调的是同一个操作 |
| **多个 AI 同时在干，不知道谁在等你** | 几个窗口、几个 Agent，各自停在不同的问题上，得挨个去问做到哪了 | "需要你看看"、问题卡、操作卡、菜单栏进度，把等你的事收到一处 |

背后还有一层：**你的东西应该是你的。** 工作资料不被锁在某一家 AI 里：存在本机，模型自己选、费用直接付给模型商，今天和明年用哪家 AI 都接得上。

## 4. 产品由什么组成

```
┌───────────────────────────── 工作台（桌面 App / 浏览器）──────────────────────────────┐
│ 主区：正在用的插件   右栏：Shelf · 浏览器 · 文件 · 讨论 · 插件侧栏   浮条：手上东西旁的动作 │
│ 底栏：项目与插件切换 · 助理 · 灵光   ⌘K 全局搜索   菜单栏：进度与等你的事                  │
├───────────────────────────────────── 插件（内容的主人）─────────────────────────────────┤
│ 项目插件：Goals · Inbox · Feed · Schedule · 成果 · Coding · Files · Git · Diff            │
│ 个人插件：Pages · 待办 · Jelly · 灵光 · Shelf · Cognia · PPT · Forms · Dataset · 图片 ·   │
│           炼金术士 · 工作流程 · 插件创作台               ＋ 你自己做的插件                  │
├──────────────────────────── 动作目录（能力注册一次，到处可用）─────────────────────────────┤
│   页面 · 内置助理 · 工作流程 · 外部 AI（Claude Code / Codex / Cursor / OpenCode … 经 MCP）│
│   按调用方逐项授权 · 调用留记录 · 取消/撤权后不写业务记录 · 副作用进审查                   │
├─────────────────── AI 运行时（Prologue）── Home 常驻宿主 ── 本机 SQLite ──────────────────┤
│   十种模型模板 · 预算 · 凭据 · 角色 · Agent 运行与恢复 · 记忆 · 搜索索引 · 连接器           │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

- **Home 与项目。** 一个 Home 里有个人空间和多个项目。项目插件在项目里按需添加；个人插件（文档、待办、日历笔记、知识库……）在每个项目里都能用。
- **插件。** 内置 22 个面向用户（项目 9 个、个人 13 个，即上图所列），另有 1 个只在开发者模式出现的参考插件；角色 10-22 起由宿主直接装配（#1008），是设置里的一节，所以画在运行时那一层。2026-10-18 改：上图里的成果、插件创作台今天还按插件装配，但按 10-18 的决定它们不再是插件——成果库是平台事实，代码迁走前用户看到的位置不变（依据：`specs/repository-anti-corruption/spec.md` §1 的 2026-10-18 各行）；插件创作台和炼金术士 2026-10-21 另定：不迁，防腐收尾后删除再重做（BL-376、BL-377），以前生成的插件不迁移；各管自己的内容，用户还能用插件创作台做自己的。插件只提供内容，位置由工作台给（主区、右栏、浮条、设置），不另开整页。2026-10-23 改：Sessions 已下线（SC-4），会话目录、跨 Runtime 交接和首页「说一句」都不再讲，重做见 BL-177。
- **动作目录。** 一项能力只注册一次，所有入口用同一份。插件动作有几百个，其中476 个对助理开放。这是"你做的工具 AI 也能用""外部 AI 能写你的文档"背后的同一个机制。
- **AI 运行时。** 文字、判断、图片和 Agent 运行都经同一个运行时；模型、凭据、预算一处设置；Agent 的副作用进审查，由人决定。

## 5. 八个价值支柱

开场的四句说的是"对你意味着什么"，八个支柱说的是"怎么做到"。对应关系：

| 开场的一句 | 主要靠 | 今天最能拿出来演的 | 还差的 |
| --- | --- | --- | --- |
| 你的工具，长成你的样子 | M5、M3 | 项目里按需加插件；PPT、Forms、Dataset 这些现成工具（main 可用） | 描述一句做出插件（main 部分）；技能包（规划）；把做法导出分享（建议 G3） |
| 你的 AI，按你的做法做事 | M1、M7、M5 | 项目长期说明（已发布 · v0.2.0，源码）；模型自选、提示词设置（main 可用） | 导入规则与 Skill 成角色（main 部分）；说明和角色不跨机器 |
| 要紧的事，你说了算 | M2、M7 | 本人验收、改约定要你点头、决定请求（已发布 · v0.2.0，源码）；操作卡、外部 AI 逐项授权（main 可用） | 依据是 Agent 自报（建议 B1）；Agent 变更的真人批准门（规划） |
| 工作接得上，换一种样子 | M1、M3、M6 | 目标上的约定、要求和进度，几家 AI 读写同一份（已发布 · v0.2.0，源码）；提问卡、操作卡、下一步（main 可用） | 浮条、落点（main 部分）；主动助理、工作简报（规划） |

最能体现"你的"的几样（做出插件、导入角色、技能包）恰好最不成熟。对外先用已发布和 main 可用的证据撑住开场；做出插件、导入角色标"开发中"，技能包还只有 spec，标"规划中 · 示意"。逐项功能见[功能全景第 1 节](功能全景.md#1-按价值支柱看)。

每个支柱写：你得到什么 → 一个画面 → 怎么做到 → 走到哪了。编号 M1–M8 在全部文档里通用。

### M1 同一份工作记录，你用的每个 AI 都对着记账

**你得到什么：** 不管用哪个 AI、隔几天回来，都从同一份目标、文档和待办接着做，不用重讲。

**画面：** 周一 Claude Code 写前端，周三 Codex 接后端。Codex 打开时读到的是同一个目标：三条要求、前端那条已有依据、上周你改过一次范围。它做完，把进度报回同一份。

**怎么做到：** Goals 是目标的唯一主人，几家 AI 经同一个动作目录读写它。项目的长期说明（背景、工作方式、硬约束、质量标准）带版本保存：助理和各插件的 Agent 每一轮都带上当前生效的一版；外部 AI 在经 MCP 读连接摘要时拿到当前版本，之后读不读由它自己决定。2026-10-18 改：今天 Sessions 还把会话关联到目标、跨 Runtime 交接经你确认，从目标打开终端时也会带上项目说明；但 Sessions 这一轮只清理、以后重做（BL-177），这几项在清理完成前不当作会继续承诺的能力来讲。仓库里的 AGENTS.md、CLAUDE.md 照常可用，Work 多记的是说明之外的部分：目标、要求、依据、进度和谁验收过，几家都读写同一份。你在 Claude Code、Codex、Cursor 里攒下的规则和 Skills，也能导入成 Work 里的角色。Codex、Claude Code、OpenCode、Pi Agent、Grok Build 有内置接入（一键预览 → 确认 → 写入，失败自动回滚），其他 AI 经 MCP。Pages、待办、Dataset 等插件的动作也按授权开放给外部 AI；外部 AI 和助理改已有对象时必须带上读取时的版本，缺了或已过期都会被拒、要求先重读，你在页面里改不受影响。

**走到哪了：** 目标、项目长期说明、五家接入和当时的 35 个 Goals 专用 MCP 工具 **已发布**（v0.2.0 源码版，当时名 GoalBoard；那批工具的旧配置在 main 上不再有效）；按客户端逐项授权的插件动作、现行 MCP 工具名、新界面 **main 可用**。会话、从目标打开终端、跨 Runtime 交接也在 v0.2.0 里，原生会话内容读取在 main 上只有 Codex（**main 部分**）；2026-10-18 改：这几项属于 Sessions，清理完成前不当作会继续承诺的能力来讲。

### M2 "完成"要对得上

**你得到什么：** AI 说做完了，Work 会对一遍：每条要求有没有依据、要你验收的你验了没有、依赖完了没有。没对上就不算完。

**画面：** Agent 报"测试 14/14 通过"，请求收尾。收尾没有生效：目标仍是"正在推进"，进度一行写着"完成要求 2/3 已满足"，页头说明原因：手机排版那条还等你亲手验。

**怎么做到：** Goal 把预期结果拆成要求，每条记依据（Agent 报告、测试、本人结论分开）；可把某条设为"必须由人验收"；Agent 能加要求、报进度、提议，但换掉约好的结果、放宽或撤掉要求、去掉"要人验收"、改目标树，要你决定；显式收尾才写入完成。要你决定的事，Agent 以决定请求发到目标页（页头出现"1 项待你确认"），写明要你回答什么、为什么现在要答，每个选项的影响由 Agent 写在选项里；菜单栏显示"需要你决定"。规划方法把复杂目标拆成可独立验收的叶子，并给出执行顺序。

同一个思路延伸到对话里：你中途补一句"别直接发给客户，我自己发"，输入回执说清这句话送到了没有、读到没有；AI 再说明打算怎么处理、在哪一步处理（助理和 Coding 都会说）。AI 自己说"我记住了"，界面用虚线标成"AI 的说法，未核对"，和系统确认过的事实分开显示；助理侧栏的"当前约定"列出它自述采纳了哪些补充，同样标成 AI 的说法。

**走到哪了：** 目标、要求、本人验收、决定请求与记录、改约定要你决定、显式收尾、规划方法库 **已发布**（v0.2.0 源码版，当时名 GoalBoard），完成确认的身份与"点头只对当轮有效"在 main 加强；输入回执、撤回与更正、AI 的处理说明（助理和 Coding）、助理侧栏的"当前约定" **main 可用**（回执还说不出一条补充改了哪些文件）；Agent 产出的变更须真人批准、批准绑定版本 **规划**（agent-approval spec）。依据分"Agent 自报 / 机器核过 / 人验收"三档、由 Work 自己跑检查，是**建议**（未立项，不对外，见[产品优化建议](产品优化建议.md) B1）。

### M3 接着眼前的东西做

**你得到什么：** 不用先切走、复制、解释背景。手上有什么，就对它做什么；结果回到你正在改的地方。

**画面：** 稿子写到第三节，你选中一段，浮条里出现"交给助理改写""记成待办""放进第二节"。助理给出三段建议，你只选第二段，在原位置先看预览，确认后替换。选中另一句"周五前和编辑对结构"，一点"记成待办"，不用再输入任何字，待办里带着来源。

**怎么做到：** 情境中枢知道你手上是什么（选中的文字、对象、文件）；同一个动作池按情境挑出合适的动作，显示在浮条上；"落点"记住对象、位置和读取时的版本，正文在你不注意时被改过，旧位置会拒绝写入；右栏（Shelf、浏览器、文件、讨论、插件侧栏）里的东西可以放进左边的位置；选中一段，推荐位里可以"记成待办""记下灵光""存为文档"，点一下就建好、带着出处；"拆成目标步骤"先出提案，你在 Goals 里确认才建；在插件标题栏写一句就新建的入口还在规划。助理输入框上方一行"下一步"告诉你现在该处理什么。

桌面上，按热键就能把浏览器当前网页、Finder 里选中的文件收进右栏的 Shelf；随口的想法丢进灵光，以后再决定留不留。以后还会加上口述：点麦克风说一段，文字先进草稿，你看过再发（规划中，交互要重新设计）。

**走到哪了：** 页面操作回到当前工作、Shelf 进右栏 **main 可用**；浮条 **main 部分**（推荐动作的模型没做命中率评估）；Pages 落点、助理结果放回原文、右栏插件标签里选一段放进左边文稿、悬停时在左边预示落点 **main 部分**（落点只有 Pages，本人验收未做；分屏的窗格还不预示落点）；桌面热键 **main 部分**（需辅助功能授权）；选中一段一键新建 **main 部分**（"记成待办""记下灵光""存为文档"点一下就建好、可撤销，"拆成目标步骤"先出提案；判断模型的命中率评估与本人验收未完成）；插件标题栏写一句就新建（✦）、追加到已有文档、一次提取多条待办、建好后"改放到"别处 **规划**（BL-330～BL-332）；统一输入框与本地语音 **规划**（先前的实现分支没有合入，界面与交互要重新设计）。

### M4 材料到成果一条线，出处跟着走

**你得到什么：** 从看到一条消息，到交出一份稿子、一份演示稿，中间不用重新找出处；交出去之后被追问，还能找回当时依据了什么。

**画面：** 周五写行业周报。收件箱里勾六条本周材料，"整理成一页"，文稿末尾附上本次用到的材料快照和来源。你改完结论，存一版固定成果交给客户，再让助理"做成 5 页给周会"。下周客户问"上周为什么建议暂缓"，打开那一版，依据都在。

**怎么做到：** 来源（RSS/Atom、网页查询、YouTube、GitHub、Gmail，以及已连接服务的只读列表）拉取到 Feed；捕捉规则默认先给建议，你设成自动后，命中的直接进 Inbox，并注明是哪条规则筛进来的；1–20 条材料可直接生成 Pages 文稿并附快照、来源与版本；Cognia 导入本地 Markdown / Obsidian 库，每次变化都留版本；PPT 从文字或 Pages 生成大纲并导出 PPTX；Notion、飞书、Google Docs 的文档和本地文件可以导入成快照，再"从这一版继续"写；成果库只收你要留存、引用的固定版本，每一版记得来源，能回原文、能看出"原文已改，这里仍是第 N 版"。网页、邮件、订阅这些外部内容按资料交给 AI：标明不可信、不进系统指令，降低 AI 被材料里的话带偏的风险。

第一天也不是空的：新建项目时勾选要接入的来源（本地文件夹、浏览器、最近的邮件、聊天导出），AI 读取你选定范围的内容，整理出带来源的工作总结和项目建议，你采用后就有一个带内容的项目。

**走到哪了：** Feed 与 RSS/YouTube/网页来源、把一条消息升格为 Goal、成果库的基础版 **已发布**（v0.2.0 源码版）；Inbox → Pages 带快照成稿（需模型）、PPT、成果库的来源与"从这一版继续" **main 可用**；GitHub、Gmail 账号来源，已连接服务进 Feed，Cognia、外部文档导入、首次使用的"带内容的项目" **main 部分**（真实第三方账号验收与正式 OAuth 发布配置未完成；10-23 起来源一步可以跳过，本地文件不限个数和大小、读的时候有进度）；"材料更新后，哪些旧结论要重看"是**建议**（未立项，不对外，见[产品优化建议](产品优化建议.md) D2）。

### M5 缺工具就长出来，你和你的 AI 共用

**你得到什么：** 一个顺手的小工具、一条每周都要跑的处理流程、一套你自己的判断标准，不用写代码就能有；做出来以后，你在界面里用，助理、工作流程和 Claude Code 也能调。

**画面：** 发版前你说"做个发版清单"。创作台先给方案，再写代码、过检查、在沙箱里试跑，底栏多出一个图标。第二天你在 Claude Code 里说"按发版清单检查一遍"，它调的是同一个插件、同一份记录。

**怎么做到：** 插件创作台：自然语言描述 → Agent 设计方案、写后端代码与测试 → 宿主类型检查、打包、沙箱试跑 → 你授权安装，界面由平台渲染；生成插件的操作注册进同一个动作目录。工作流程把插件排成一条链，两站之间的衔接可以是模板转换、AI 整理、人看过再交；面向流程的已授权命令都能作为一步（约 237 条，查询类还不能），判断规则可以拦下不该继续的一次；每次运行保留当时的链、进度和每段交接的内容。判断规则把你反复做的判断存成有版本的规则；Skill 是可读的做法；角色（Character）是你的 AI 做事方式，可以从 Codex、Claude Code、Cursor、OpenCode、Grok Build 导入已有规则和 Skills。

再往前一步，做法本身也能分发。技能包是一份只有文字的"同事做法"：产品经理怎么写需求、法务怎么审合同、运营怎么复盘，装上后助理和 Coding 都按它做事；它不授予任何权限，`~~日历`、`~~项目工具`这类占位让同一份做法接到你实际用的服务上。你也可以"做一遍，让它学会"：把一次做法存成 Skill，用你已知的答案回放检查，对不上就改。

**走到哪了：** 创作台 **main 部分**（仍需检查与返修；防腐收尾后删除再重做，没有日期，以前生成的插件不迁移）；工作流程 **main 部分**（查询类动作还不能当一步，外部 MCP 工具当一步没在真实服务上验过）；判断规则 **main 部分**（需判断服务连接，没做命中率评估）；角色导入 **main 部分**；技能包、从一次做法生成 Skill **规划**（skill-packs、proactive-assistant spec）；插件市场的上架与审核 **规划**（BACKLOG BL-058、BL-167）；把做法、流程、插件导出成文件分享是**建议**（未立项，不对外，见[产品优化建议](产品优化建议.md) G3）。

### M6 助理会主动推进

**你得到什么：** 不必每件事都开口。早上打开，助理已经整理好昨天做到哪、今天该先处理什么、哪件事卡住了；你点一个选项，它接着去做。

**画面：** 周一早上，首页的工作简报写着：上周三个目标里一个完成、一个等你验收、一个卡在客户回复；Feed 里有两条和你在写的方案有关。你点"准备周会材料"，助理用你配置的 Skill 拉出待办、文档和代码进展，写成一份带来源的简报。

**怎么做到：** 主动助理根据近期行为和插件内容发现值得推进的工作，按你配置的 Skill 决定关注什么、何时行动、怎样检查；工作简报插件承载周期报告、专题分析和准备材料，管理正文、版本和来源；Schedule 在你设定的时间跑任务（对话任务是只读的一轮，只能读项目绑定的工作目录），插件可登记提醒，到点送进 Inbox；助理能把独立的部分分成子任务并行，后台任务在标题栏可见。

助理也会先认识你的工作：第一次用时像新同事一样问几个问题，记下人名缩写、项目代号和你的习惯（写入前先给你确认）；之后每天更新，帮你盘点过期或漏掉的承诺。简报不是一篇写完就过期的周报，而是一页会刷新的状态：只报变化，取不到的数据标"过期"，风险必须指向具体记录。

**走到哪了：** Schedule、助理受托跟进 **main 可用**；插件提醒 **main 部分**；子任务与后台作业回报进度 **main 部分**（一层委托）；主动助理、工作简报、访谈式工作记忆 **规划**（spec 2026-10-15 已整理，#718 补充；主动助理还写了技能前门、跨来源找东西、可点选的决定，工作简报还写了会刷新的状态页、一页脉搏和使用回顾）；子代理查看与直接对话 **规划**（subagent-interaction spec）。注意：Work 在你的电脑上运行，本机服务没在运行（没装常驻服务又关了应用）或电脑休眠时，定时和提醒不会执行，不承诺 24 小时在线。

### M7 数据在本机，模型你来选，边界说得清

**你得到什么：** 工作资料不交给某一家平台；想用哪家模型就用哪家，费用直接付给模型商；AI 能动什么、动过什么，看得见、管得住。

**怎么做到：** 每个项目一个本机 SQLite 库，个人内容在 Home 级库里；JSON/Markdown 用于导入导出。模型模板覆盖 Anthropic、OpenAI、DeepSeek、通义千问、Kimi、GLM、MiniMax、OpenRouter 及兼容接口，保存前实际连通一次；"OpenAI / Anthropic 兼容"接受本机地址，填 127.0.0.1 就能接本机运行的模型；预算一处设置。外部 MCP 客户端逐个、逐项授权，不能在输入里冒充你；助理改你的内容时，不可撤销或你没明确要求的先把准确参数给你确认，可撤销且你明确要求的默认直接做（可改成每次都问）；写文件、跑命令、推送等副作用经审查或你设的放行规则；有撤销的操作可撤销；不可撤回的动作不进情境推荐。外部内容按资料交给 AI，标明不可信、不进系统指令，这能降低、但不能杜绝被网页或邮件里的话带偏的风险。往外发的请求类型列在 [`docs/platform/NETWORK.md`](../platform/NETWORK.md)（最近更新 10-11；对话里接入服务 #661 新加的受管理安装来源还没列进去）。

助理也能在你允许时操作这台 Mac 上的应用（Computer Use）：总开关默认关；银行、支付、密码管理器按名单放进禁区，证券、基金类按应用名识别，识别不到的你可以自己加。系统的打开、保存面板由目标应用承载：同一进程里的 sheet 照常操作；由另一个进程承载时助理不碰，请你自己完成。操作记录存在本机，截图 30 天后自动删除，文字步骤和回执保留，你可以随时整份删除。

接外部服务不用先去设置页。对助理说"接入公司的知识库 MCP，找出 Alpha 项目的上线要求，整理成文档"，它查重、选接入方式、安装、配置，只在需要你本人登录、填密钥、选账号或批准新权限时停下来，登录完回到原任务把事做完。凭据不进模型请求、对话、记忆和截图。设置里的 39 个目录连接器现在都只读：识别当前账号、拉取列表进 Feed，不写回对方服务。反过来，Work 自己也是一个 MCP Server：别的 AI 客户端在你授权的范围里使用 Work 的能力。

**走到哪了：** 本机存储 **已发布**（v0.2.0 源码版）；模型模板、预算、授权与审查 **main 可用**；经兼容接口接本机模型 **main 部分**（没有专门模板，没做质量验收）；对话里接入外部服务 **main 部分**（#661 已合入，真人 OAuth 与本人验收未完成）；Computer Use **main 部分**（默认关；收尾已合入，二十步整格等真机验收按负责人决定推后）；记忆设置 **main 可用**（10-23 起新 Home 默认"审过才记"，自动记住只放过反复要求的偏好与约定；真实模型下的候选质量没验）；记忆的四档选择、分类开关和用到时的回执 **规划**（Prologue 记忆策略，首期已授权）。不是离线 AI：用模型、联网查询和连接器时，相关内容会发往对应服务。

### M8 和别人一起，也接得上

**你得到什么：** 团队的讨论、决定和 AI 的工作在同一处。一封客户邮件进来，助理把它带进项目群 @ 相关的人；讨论出结论就成为目标，你的 Agent 接手，进展回到群里，产品验收。

**怎么做到：** 项目讨论（右栏的群聊与 Thread）、@ 提醒、助理进群组织讨论、把目标和成果带进讨论、讨论成目标；Agent 之间经任务板协作。

**走到哪了：** 项目讨论入口 **main 部分**；Agent 之间的任务板协作 **main 部分**；人与人的团队协作依赖服务端，**规划**（还没有 spec，需求记在 BACKLOG BL-071 等）；负责人已定官网对外标"开发中"，团队接下来就用 Work 协作（这条例外见 [README](README.md#成熟度标签)）。

## 7. 给谁用

官网保留两类读者入口：**写代码的人**，和**写文档、管事情的人**。角色是导航，不是已经验证的客户画像；角色之间可以重叠。

按开场的说法，最先适合的是**已经有自己一套做法的人**：他们不缺工具，缺的是让工具和 AI 照这套做法走。落到具体人群：

**最先适合的人（首批用户画像）：**

1. **同时用两个以上 AI 编码工具的独立开发者和小团队技术负责人。** 已经在为"Agent 说做完了""换 Agent 要重讲"付出代价；装得上 MCP、愿意配置；Goals 的核心已随 v0.2.0 源码版发布。
2. **自己掌握一批持续积累的材料、反复向别人交付有依据成果的人。** 独立顾问、研究和内容作者、产品负责人。他们要的是"交出去以后还能回答从哪来的"。
3. **想要一个顺手小工具、又不想写代码维护的人。** 一人公司、自由职业者、小服务商。这条最依赖创作台成熟度，而创作台要在防腐收尾后删除再重做。

**暂时不适合：** 需要全员实时共编和复杂权限的团队（团队协作尚在规划）；只想要一个聊天窗口的人；要在手机上随时处理的人；严格依赖 Windows 的人。

各角色的用法见[角色与使用链路](角色与使用链路.md)。

## 8. 它不是什么

- **不是另一个 Notion 或飞书。** 不追求全员共编和在线协作套件；它的重心是一个人（和接下来的小团队）带着多个 AI 把工作做完。
- **不是 Agent 调度器。** 它不替你给外部 Agent 和目标派单、不替你选谁来做。外部 Agent 自己读取、自己报告；助理和 Coding 内部可以把一件事拆成子任务（一层委托，Coding 按你保存的目录分工）；Schedule 只在你设定的时间跑你建好的任务。
- **不是又一个聊天 AI。** 助理是工作台的一部分，它的价值在于能读写你的目标、文档和待办，并把结果放回原处。
- **不是替你拿主意的 AI。** AI 可以提议、动手；放宽要求、验收、动你没允许的东西，留给你。
- **不是离线 AI。** 数据在本机，但用模型和联网能力时，相关内容会发给对应服务。
- **不是插件市场。** 可以自己做插件；现成的分发市场还没有。

## 10. 说法约定

**可以说：**

- "工具和 AI 围着你转，你还是你。"开场的四句（你的工具、你的 AI、你说了算、接得上），每句后面紧跟一个今天能演的画面，并标成熟度。
- "用久了，你的工作台会和别人的不一样"：因为插件、规则和做法是你自己攒的。
- 你的目标、文档、待办存在你的电脑上；你用的 AI 读写同一份。
- 内置接入 Codex、Claude Code、OpenCode、Pi Agent、Grok Build，其他 AI 经 MCP。
- Agent 能记录、能提议；换掉约好的结果、放宽要求、替你验收，得你点头。
- 收尾时缺依据、缺你的验收、依赖没完、有阻塞顾虑，就不生效。
- 选中就能交出去，结果放回原处，出处跟着走（标成熟度）。
- 描述一句，让 AI 做出一个插件，你和你的 AI 都能用（标"开发中"）。
- 模型自己选，支持 DeepSeek、通义千问、Kimi、GLM、MiniMax、Anthropic、OpenAI 等，费用直接付给模型商。
- 外部内容按资料交给 AI，标明不可信、不进系统指令，降低被材料里的话带偏的风险。
- 已发布的能力写成"已发布 · v0.2.0（源码，当时名 GoalBoard）"。

**不要说：**

- "你和别人的工具永远不一样"：刚装好时大家一样，说"可以长成你的样子"。
- "你的 AI 只属于你""AI 完全听你的"：模型仍是供应商的，调用时内容会发给你选的那一家；AI 也会出错，所以才要你验收。
- 说别的工具在"控制你""绑架你"：讲人迁就工具的时刻（重讲、核对、搬运），不点名指责别家。
- 只有信念、没有画面的句子："守护你的价值"后面要跟一个能演的东西。
- "核验""证明做完""测试已通过"：依据是 Agent 报的，写"Agent 报告"。
- "只有我们能让几家 AI 共享""别人都只有聊天""没有一份共用的记录"：AGENTS.md 和能接外部 Agent 的中枢都已经有了，讲 Work 多记的那部分。
- "编排""派活""自动并行"：Work 不替你给外部 Agent 和目标派单；助理和 Coding 内部的子任务是一层委托，照实说。
- 外部内容"不会变成指令"这类保证。
- "外部 AI 每一轮都读到项目说明"：外部 AI 在经 MCP 连接、读连接摘要时读到。
- 把从目标打开终端、跨 Runtime 交接、会话目录当作会继续的能力来讲：2026-10-18 改，Sessions 这一轮只清理、以后重做（BL-177）。
- 把成果库、插件创作台、角色叫作插件：2026-10-18 改，成果库与角色是平台的一部分，成果库代码迁完之前界面上仍按插件出现，角色 10-22 起已是设置里的一节；插件创作台 2026-10-21 另定为不迁、防腐收尾后删除再重做，也不说成"平台能力"。
- 把炼金术士、插件创作台当作会长期保留的能力来讲：两者防腐收尾后删除再重做，没有日期。
- "英文界面已完整"：页面固定文字和服务端的错误与状态句已是英文，Git 的上游跟踪句（改由页面按语言写，在开放 PR #1109 里）、日期、设置里能力列表的动作文字仍可能是中文。
- "决定中心"：这个页面已经没有了，说"决定请求"。
- "无缝接着对话"：交接带的是目标和必要上下文，不是完整原生聊天。
- "数据不出本机""私密 AI""离线"。
- "开源（MIT）""免费"。
- 把规划中的能力说成今天能下载；团队协作只标"开发中"。
- 对写文档、管事情的读者讲"换 AI 轮流写"。
- 任何地方出现 Issue 插件。
