## 给人讲清楚

插件创作台和它生成的插件，现在还走一条特殊通道，和普通插件不一样；安装时的可选权限、升级、卸载、损坏恢复也没有和创作台一起测过。这一批把创作台和生成的插件搬到和所有插件同一套机制上，用同样的方式调模型、读材料、跑后台、处理图片，再清掉旧通道留下的几处读取；同时把插件状态机的登记和只读查询接上（最小片），让安装预览能看见插件申报的状态。做完生成的插件和你自己装的插件待遇完全一样。需要你做的：看范围、权限、安装、升级和恢复的样子并定下；之前没定的几项要先定。

### 47-1 还剩的缺口（PG-083 今天的样子）

1. **每个项目有两套插件平台。** `apps/local-host/src/project-plugins.ts` 的监督器起一套（内置插件），`apps/local-host/src/installed-plugin-host.ts` 又 `createPluginPlatform` 起一套（创作台产物与签名包），各有各的 `UiHost`、路由和服务；后一套没有成果、过程项、调度等端口。
2. **创作台产物有一条不经签名包的安装路。** `AgentBuilderStore` 的发布记录 + 宿主合成的 Manifest（`generatedPluginManifest`）+ `UNSIGNED_TRUST` + `registerGeneratedPrompts`，与签名包（`packaged`）在 `installed-plugin-lifecycle.ts`、`installed-plugin-definition.ts`、`plugin-builder/installed.ts` 里处处分叉。
3. **创作台自己是宿主里手写接进去的。** `handleAgentStudioHttp` 直接处理 `/api/plugin-builder/studio/*`，`builderPorts` 把构建目录、检查、沙箱试运行、浏览器验收、签名发布、安装生命周期十几项宿主内部能力直接递给它；登记里没有 `project_runtime`。
4. **平台自己的东西放在以插件命名的目录里。** `apps/local-host/src/plugin-builder/` 下的 `catalog.ts`、`model.ts`、`secrets.ts`、`network.ts`、`exposed-actions.ts`、`installed.ts`、`installed-page.ts`、`prompts.ts` 其实是「已装沙箱插件」的平台运行部分，Home 包也在用。
5. N38 的三处旧读取、BL-586 的界面入口撞名、B12、`agent-studio.ts` 整理，见上文。

### 做法（主会话按推荐定，偏离与理由记在这里）

- **A 创作台产物只走签名包。** 发布就是用本机发布者身份（01 批已交付）打一个签名包，装进项目与装进个人空间都走平台已有的包安装路（预览、本人确认、S-84），升级、卸载、可选权限、损坏恢复沿 26-5、27 已做的那一套。删掉第 2 条那条旁路。全局看：第三方、个人、创作台三种来源从此只有一种安装形态，后面 48 的安装预演、68 的持续修订只接这一条。
- **B 一个项目一套平台。** 已装插件（签名包）由项目监督器的同一个平台启动，`installed-plugin-host.ts` 不再自己建平台，只留「已装包」的生命周期编排；成果、过程项、调度等服务随之对它们开放（按 Manifest 声明与授权，沙箱经 broker 的照 S-60）。
- **C 创作台按登记装配。** `plugins/native/plugin-builder` 给出 `project_runtime` 工厂，页面请求走 Manifest 路由；它需要的宿主能力（建构建工程、跑检查、沙箱试运行、界面验收、打签名包）收成平台的「插件创作服务」，经动作目录提供，创作台与以后的 CLI、助理用同一份；装包走平台已有的受保护安装入口。迁完从 `APPROVED_BUILD_TIME_EXCEPTIONS` 删掉 `plugin-builder`。
- **D 平台文件归位。** 第 4 条里的文件搬出 `plugin-builder/` 目录，按职责并进已装插件的平台文件，不改行为。
- **子分支顺序**：`47/breakpoints`（B12、`agent-studio.ts` 整理）→ `47/packages-only`（A、D、N38）→ `47/one-platform`（B、BL-586）→ `47/studio-runtime`（C）→ `47/state-machines`（47-2）→ 界面（定样确认后）→ `47/fixes`（小修）。47-2 不依赖前几步，等定样答复期间可先做。

### 47-1 细化（定样确认后，2026-11-21）

读完现行代码后的落点，偏离上面「做法」的地方在这里写明。

- **安装交接（平台能力，任何插件可用）**：沿第 18 批的「页面原处的平台区域」和连接卡的先例（`apps/workbench/src/browser/plugin-frame/framed-area.ts`、`connection-need.ts`）。插件后端把一份签了名的安装包交给平台，得到一个只在本项目、本人、短时间内有效的交接号；插件页面在自己留的空位上调 `packageInstall(place, { offer_id })`，外壳在页面外、空位之上画安装单。预览、同意、安装全在外壳里走平台已有的 `plugins.install.preview@1`、`plugins.install.confirm@1`（S-84，本人按键才算）；页面只听到结果（装好了哪一版、取消、没装上），听不到权限选择，也碰不到按钮。
- **创作台发布已是签名包**（`plugin-builder/studio-release.ts`，本机发布者身份）。缺的是安装：今天项目范围的安装走 `ports.lifecycle('install', …)`（不验签、`UNSIGNED_TRUST`、`agent-built:` 签名前缀）。改成只交接签名包；`lifecycle` 里非包的分支、`generatedRegistration`／`registerGeneratedPrompts`、`releaseFor` 读创作台发布记录、`records()` 的 `agent-built:` 过滤一并删除。试运行（预览沙箱）不是安装，照旧。
- **回退**：创作台页面上没有「回到旧版」的入口（只有安装、升级、启用、卸载），需求里也没有这一条；旧通道流程里的 `rollback` 动作随旁路一起删。包安装路照现行规则：升级没成功自动回到原版（现有实现），手动换回旧版仍是「先卸载并保留数据，再装那一版」。
- **密钥**：创作台现在在自己的同意框里收密钥值再随安装带上；包安装路今天没有收密钥的地方。改成由安装单收：包声明了要用密钥时，点「同意并安装」后安装单多一步「填密钥」（外壳画，值只进这台设备的加密存储，名字和请求头照包的声明），填完才开始安装；升级时只问新增的。创作台页面不再经手密钥值。定样里补这一步的样子。
- **可选权限**：安装单上的开关就是平台已交付的可选权限开关（`plugins.permissions.set@1`）；同意时把开了的一并带上，装好后在 设置 › 插件 改。
- **损坏恢复**：已装包的安装文件读不回时，插件自己的位置由外壳就地说明并给「装回这一版」「卸载」（沿 25 批的就地说明、27 批的损坏包卸载）；装回同一版、同一份已同意的权限，不再问同意，但包要重新验签且摘要与安装记录一致。
- **子分支顺序微调**：`47/packages-only` 先做平台的安装交接与安装单（含组件板标本），再让创作台改用它并删旁路；SMP-11（生成插件申报状态机）跟在它后面。其余顺序不变。

### 47-2 做成了什么（子分支 `47/state-machines`）

- **启动兑现**：插件在 `start` 的返回值里用 `state_machines` 交出代码运行的状态机，Plugin Runtime 启动前和 Manifest 逐台核对（`packages/plugin-runtime/src/contribution.ts`）。随宿主发布的安装双向核对；本地开发的交出才核对；沙箱里的生成插件没有代码声明，不做这项。不一致不启动，报错指到 `machine_id`，别的插件照常。触发动作引用不查（SMP-15）。
- **平台样板**：插件生命周期 `platform.plugin-runtime.lifecycle`（`lifecycle-machine.ts`），状态与家族取公开词表那一份；安装库套上守卫，机器没列的步子写库前被拒。转换表按现行行为列出（7 份生命周期测试实测到的 20 种步子，加代码允许的「隔离中卸载」），不改行为。
- **登记与只读查询**：`system.state-machines` 的 `state_machines.list@1`、`state_machines.get@1`（合同在 contracts，实现在 `packages/plugin-runtime/src/state-machine-registry.ts`，宿主只给来源并注册）。登记是投影：内置定义 + 安装记录对应的已存发行物，停用或没启动的也读得到；读不到或声明不合法标为未知并给原因；已卸载的不留条目；没有 Home 时照样注册、返回空清单与原因。受众是本人、Agent、MCP，不新增权限。
- **同名编号**：同一插件编号可能有两份安装（不同发布者，BL-586），所以登记条目带 `install_id`，`get` 可按它指定；这是对 spec §4.4 字段清单的一处补充。
- **3 条安全不变量**：`S-state-machine-lifecycle-steps`、`S-state-machine-redemption`、`S-state-machine-registry-metadata`，拒绝测试在 `tests/security-invariants-state-machine-registry.test.ts`，随 `test:security` 跑。
- **留给 47-1 一起做**：spec §13 写在 47-2 名下的「生成插件设计合同与校验」（SMP-11）要改创作台的设计合同与回放，和 47-1 的创作台改动同一处文件，放在 `47/packages-only` 之后一起做，仍在本批内。
