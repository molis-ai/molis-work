# Goal 事件工作流收敛

状态：执行完成，主验收通过，2026-09-11；验收见[acceptance.md](acceptance.md)。完成等级：4（内部完整）。基线 `8d2abd3`；分支 `feature/goal-event-workflow-cleanup`。

用户要求处理 [新流程逻辑审查](../goal-timeline-redesign/new-flow-audit.md) F1–F9；不以旧逻辑兼容作为保留理由，优先新流程干净、MCP 简洁、使用清楚。此要求替代上一轮保留 legacy_claim_run 作为正常 Runtime 路径的边界。生产实施继续使用直接 Grok CLI `grok-4.6 / xhigh / no-subagents`；主 Session 管需求、复现与验收，一个 writer 串行推进。

## 用户结果与边界

连接项目 → 创建/找到 Goal → 读取当前约定、要求与结果 → 在已有授权内工作 → 上报事实并得到当前差距 → 显式收尾。普通笔记和部分结果可以先保存，不要求角色、Run、完整规划、假设的输入输出或默认模板。树结构/依赖是按需使用的能力，不能把单 Goal 工作变成规划审批流程。

保留：真实历史、来源、文件版本、Host Session/终端绑定、项目权限、关系归属/图合法性、事务、幂等、正式状态版本检查与可信用户决定。替换：所有新建入口、旧动作投影/恢复指引、旧规划权威、MCP/Skill 里的双协议入口。忽略：旧角色阶段、固定拆分阈值和非空规划数组等原实现约束。

不删除真实用户数据，不在本轮安装或迁移用户正在使用的数据库，不修改凭据/依赖安装/lockfile，不扩展其他产品面或重新设计已通过的时间线视觉。历史事实仍可读取，但不保留旧执行协议作为备用工作方式。不为通过回归而隐藏失败或继续维护已退役行为；涉及删除的测试必须映射到退役功能或新的用户结果。

## 行为合同

### A. 当前约定、验收与演化（F1/F2/F9）

1. 结果约定的权威是事件模型中的当前约定，不是旧 definition_state。已有明确结果发生实质修改后，原完成结论保留历史并退出当前生效，相关要求/验收结论需要重新核对；不能通过把目标保留为 Draft 绕过权限或完成检查。
2. 正式收尾必须提供并验证当前约定版本及实际依赖的配置版本；缺失或过期的版本在任何正式副作用前拒绝。普通历史事实仍可按其实际类型版本记录，不把正式并发锁扩大到日常上报。
3. 新要求支持明确的 `human_decision_required`（默认 false）。false 表示当前 Runtime 报告可参与支持判断；true 必须有仍然有效的可信用户结论。此轮不伪造独立验证模式或要求固定 reviewer 角色。字段在 Module、MCP、Web 表单、持久化、当前状态和历史阅读中一致。未知控制字段拒绝，不能成功写入后静默丢弃。
4. 决定的用途有可表达语义：普通建议/讨论不阻塞；针对当前有效要求的验收决定，在未处理时不能被完成绕过；针对完成动作的决定继续阻塞对应动作。要求 ID、作用范围、当前约定与用户选择必须一致。拒绝和后续反证不能变成通过。
5. 当前要求可以明确新增、修订、退休；退休只退出当前判断，不删除历史要求和其报告。涉及已有结果替换、要求退休/降级、取消人工验收等承诺变化，Runtime 必须引用可信用户入口对**具体变化**的授权；不能仅自填 user/confirmed，也不能凭任意 authorize_action 放行另一份变化。同范围既有有效决定可以复用，不重复审批；首次结果补充、普通备注及授权范围内追加要求不机械制造新审批。
6. 用户 Web/受保护管理入口可直接提交可审阅的约定修改；Runtime 可请求、读取并引用决定。当前 Host 不提供可信用户消息时，不伪造对话确认 API；Skill 清楚说明仅需用户决定的动作转入现有保护入口，普通工作继续。
7. 类型的新版本可改变显示名、说明、字段集合和字段约束；旧事件始终按其保存的旧类型版本读取。不能重写已发布的同一个类型版本。当前要求的绑定/有效性变化单独受正式约定约束；不能通过类型演化偷偷取消验收要求。采用的规划可退出当前使用，历史来源仍保留。
8. 不再把两个版本字段作为不清晰的互相兜底。每个字段的意义、必填条件和报错恢复动作必须明确；若某个类型修改不影响承诺，不应使仍适用的用户授权失效。

### B. 新建、结构、发现与恢复（F3/F4/F5）

1. 默认 Web 新建、首次项目引导、Feed/Inbox 升格/开始处理、MCP 意图、结构提案生成的 Goal 汇入同一个事件意图应用入口；保留原来源/关联/优先级与明确输入，不丢弃这些入口的有效职责。新创建的 Goal 不出现“转交事件记录”或旧澄清提示。
2. 父子/依赖变更使用真实 Runtime/Session 来源、显式变更内容和版本；不要求 clarifier/executor Run，也不创建代用临时 Goal。保留图循环、跨项目引用、过期基线、并发与用户授权保护。选择规划方法按任务实际需要，不把 leaf_readiness、固定数组或二选三拆分判断作为合法写入的前提。
3. 工作发现/恢复、单 Goal 状态、目录/工作提示使用同一事件当前事实；提供简洁的 Goal 列表入口，替代旧 Available/Ready/Contract/Explain 的执行状态。不能一边“受阻”一边“可澄清”，不能把拒绝旧 Claim 显示为新 Goal 不可工作。
4. 终端不因切换 Goal 自动改绑或发送。项目连接/恢复保持现有真实 Session 和明确项目选择边界；不把恢复变成重复绑定或新的用户确认。
5. 旧事实存储只承担读取与必要的一次数据升级；新生产入口不能继续计算 legacy_claim_run 状态。实现若需处理已有 Goal，应选择一次转成事件当前事实或只读历史的明确方案，保留原始来源及完成历史，不伪造新批准；不维持第二套可继续执行的协议。具体数据切换方案在该工作项编码前写入其 spec。

### C. MCP、Skill 与常用上报（F6/F7/F8）

1. 删除旧 Runtime 的 claim/select/renew/release、run_start/report、evidence_submit/correct、review_submit、revalidate/rework_request/complete、draft_dialogue_*、旧 contract/candidate/dependency proposal 工具及专属 schema/dispatcher/handler。旧 Ready/Available/Contract/Explain 不再充当新工作入口；由新的列表/状态/历史与结构操作承接实际用途。不能仅隐藏 discovery，调用旧名字仍能走旧流程。
2. 保留工具按用户用途组织：项目连接管理、Goal 发现/创建/状态、普通上报/类型、正式约定/决定/收尾/继续、结构与历史。无需人为固定工具总数，不新增一个接收任意动作/对象的万能工具，也不保留同义旧别名。
   Runtime 的项目上下文与操作者由已绑定 Host 注入，不在每次普通调用中要求 board_id/actor_id；调用者仍明确传 goal_id，不能隐式写入另一个焦点。管理入口显式项目参数保留；Runtime 自填项目或身份覆盖应明确拒绝。状态回执只保留一份当前约定/状态，不用多组别名复制旧模型字段。
3. 普通笔记无需先登记局部类型。一次工作更新可带多个事实及必要进展说明；回执包含紧凑当前状态、差距和游标，避免立即全量重读。沿用当前整批事务：非法批次无写入，不丢掉此前其它已成功调用记录的历史事实；同键重试无重复副作用。
4. 明确继续覆盖 cancelled 和 completed；用户知道将开启新一轮，必须有原因，重试幂等。普通无关报告不自动重开。
5. Skill 与全部必读 references 只描述这一套新路径，给可实际调用的简洁示例、可省略字段、必要决定及失败恢复。无生命周期 projection、必须澄清 Run、租约续期、固定拆分门槛等普通流程。专业方法保留实质内容与真实依赖判断。
6. 旧写入/运行代码只在确有新的生产职责时保留并列出调用者；旧 CLI/管理入口或旧测试不能单独成为维护退役工作协议的理由。历史仓储、文件阅读和真实 Host 进程服务不按名字删除。沿实际注册/引用清理，避免把“新增层”当作收敛。

## 验收

- F1–F9 每项给通过/失败/未运行与真实证据，不用总测试数代替路径验收。
- 对 F1/F2/F4/F5 使用上一轮独立反例的生产公共入口，验证输入、返回、持久状态、后续读取和重启；修复后的断言必须与原错误行为相反。
- 所有新建入口各自从真实入口开始验证，不能预先 createIntent 代替 Web/首次使用/Feed 路径。
- 图变更无 Claim/Run，用户批准影响与范围一致；正式并发修改拒绝过期，重放无重复；新要求人工门禁和状态修订的失败/拒绝/已批准路径完整。
- 桌面与 390px 关键表单/错误/返回路径实际可操作；沿用已接受时间线布局，不启动新视觉设计。
- 真实新项目经历无模板意图、普通备注、局部类型、要求、可选结构变更、报告、用户决定、收尾、明确继续和 Host/SQLite 重启；Skill 示例通过公开 MCP 路径执行。
- 清理后 build、boundary、相应定向回归和最终全仓测试通过。移除已退役测试需说明行为去向，不能用跳过、放宽断言或只测测试工具凑绿。
- 交付可打开的实际预览、最终 MCP 名单与旧工具删除结果、调用链和保留理由、完成等级与真正缺口。

标准命令：`pnpm_config_verify_deps_before_run=warn pnpm build`、`pnpm_config_verify_deps_before_run=warn pnpm boundary:check`；build 完成后可直接 `env -u FORCE_COLOR NODE_NO_WARNINGS=1 node --import tsx --test --test-concurrency=1 tests/*.test.ts`。不改依赖配置或 lockfile。临时诊断 `/private/tmp/molis-work-flow-cleanup/`。

## 当前假设与未决实现细节

新要求提供报告/人工两种真实支持模式，不在本轮增加虚假的独立审查身份。可信用户决定仍用现有 Host 保护入口；不新增会话消息代理或外部服务。具体变化授权应绑定可审阅的 typed delta，而非含糊文本或新任意 JSON。工作项 writer 在开始编码前给出最小 wire/schema 设计，主依据此合同裁决后立即执行，不向用户重复索权。
