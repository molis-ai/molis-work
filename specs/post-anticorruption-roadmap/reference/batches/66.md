## 给人讲清楚

这一批给写代码（Coding）补上一套**「写时当场自修报错 + 交回前按需多层复查 + 证据分三档写进同一张验收卡」**的质量把关链，同时按你拍板的**三档按需启用规则**严防日常小改动乱烧十几倍模型额度，分 **2 个清晰的串行 PR** 交付：

1. **日常即时自修、有界改绿与三档依据验收卡闭环（`66-1`）**：
   - **日常默认轻量档（零额外子代理开销）**：把环境脚本与工具链摘要放进开局上下文；模型改完文件后立刻把语法 / 类型新增报错喂回给它当轮顺手修好（不再等最后出卡才看见）；收尾时写作角色按目标要求做一次自检；并支持设最大轮数、随时可停的「自动修到测试全绿为止」（绝不死循环）；
   - **三档证据写进同一张验收卡**：Coding 跑命令核验的结果（机器核验档）和第 `60` 批外部会话自报的结果（自述档），连同你亲自点头认可的结果（人工认可档），统一写回平台的验收卡（装没装目标插件都完整可用）。
2. **共享缓存前缀的 5 路多代理评审、简化／安全专科与对抗验证（`66-2`）**：
   - **多路评审档（按项目／会话开启，或在交回前点按钮触发）**：复用 `62-0` 的共享缓存分叉（`Cache-Safe Fork`，避免重复付五倍读代码输入费）并行跑 5 个独立评审员（查项目规范、明显 bug、历史提交、旧 PR 意见、注释一致性），由打分员过滤掉 80 分以下的凑数废话，只把真问题放进审查卡（每条带「去修复」一键进下一轮，不阻断本地保存；评审汇总浓缩为一条结论依据写回平台验收卡，细碎行内意见留在 Coding 内）；往远端 GitHub PR 发评论统一走 `plugins/native/git` 公开动作与 [`67-1A`](67.md#batch-67-item-1a) 无缝衔接，绝不在 Coding 里私写第二套 GitHub 请求；
   - **高敏专科／安全／对抗验证档（仅显式点选才跑，发起前明示子代理数并计入同一用量账）**：提供 5 类专科复查（含只改写法不改行为的代码简化）、配 1 个独立质疑员挑战的**安全评审（只生成补丁文件供你决定，绝不自动应用／提交／推送）**、以及高敏任务的「裁判 + 双独立核验员」对抗验证；单人本地项目不强制凑多人真人票门（多人票门归团队批）。

需要你做的：开工前看一次三档质量开关、审查卡「去修复」、安全补丁预览与验收卡三档证据展示的轻量样稿并定下。

## 交付与前置

- **阶段／类型**：3；产品线（Coding）；体验与效果
- **需求来源**：[Coding 质量保证][CQA]（`CQA-01～12`）、[Coding E6／E8][CN]、[Agent 批准][APP]、[智能呈现第二片][IUI]、[产品建议 B1][P]
- **前置／待决**：[`111`](111.md)（[决定 66](../decisions.md#decision-66)：Coding 基于 `109` 开放审查种类与对 `plugins/native/git` 的随启用依赖实施，保留无 Git 优雅降级与 `#2244` `install_id` 隔离）、32-2、39、[`53`](53.md)、59、[`60-1`](60.md#batch-60-item-1)（外部会话依据接入）、[`62-0`](62.md#batch-62-item-0)／[`62-1A`](62.md#batch-62-item-1)（`Cache-Safe Fork` 与 `FrozenCharacter.model` 子代理模型路由）及 [`65-1/2`](65.md#batch-65-item-1)；其中 `66-2` 远端 PR 评论发布另接 [`67-1A`](67.md#batch-67-item-1a)（`plugins/native/git` 公开 PR 动作）。[Coding 质量保证规格书][CQA] 原 7 项待定已于 2026-11-25 全部拍板收口。
- **可并行项**：68 的已安装插件修订交互设计
- **UI 要求**：先定样（三档质量选择、5 路评审／专科审查卡与「去修复」、安全补丁预览、验收卡三档依据标签）；**严守 Coding 72.1 KB 私有样式零增长**：100% 复用 `@molis-ai/molis-work-design-system` `mw-*` 原语（过 `pnpm plugin-styles:check`），全程遵循 `#2307` 中 / 英 / 日（`zh`/`en`/`ja`）三语零二元语言分支
- **质量保证 7 项待定拍板结论（2026-11-25 用户定）**：
  1. **三档按需启用**：① 日常默认仅开「写后报错当轮自修 + 收尾写作角色自检」（零额外子代理开销）；② 5 路并行评审按项目／会话开关或在交回前点选触发；③ 5 类专科、安全评审与对抗验证仅显式点选触发。
  2. **角色来源与缓存省钱**：内置角色经 `PluginDefinition.agent_prompts` 正式登记（单一基准模板 + 平台 `reply-language` 单点注入，进 `tooling/versions.json` 与 `WORDING_HISTORY`），5 路并行与专科评审强制走 `Cache-Safe Fork` 共享代码库／Diff 前缀，并经 `FrozenCharacter.model` 分级路由。
  3. **不通过时的行为**：审查卡列出 `≥80` 分问题并提供「去修复」入口，不阻断本地保存；仅当项目／对象明确启用了真人批准门时才阻断完成／合并。
  4. **用量透明**：所有评审子代理调用统一计入当前 Coding 会话与 `horizontal/observation` 同一用量账，显式触发多路／专科／对抗验证前明示预计派发子代理数。
  5. **写回 `32-2` 要求—证据的粒度**：浓缩为一条本轮评审总结结论与未决高置信问题引用写回 `modules/acceptance`，逐条行内评论留在 Coding 审查卡（不刷爆平台要求表）。
  6. **安全评审**：配 `1` 个独立 verifier 挑战复现与可达性，默认生成待确认 patch 预览，**绝不自动应用、不 commit、不 push**。
  7. **真人批准门**：单人本地项目默认 `1` 人且不强制开启多人票门（`AI 低风险代批` 不计真人票数）；多人票数门归团队服务端批 `SRV-3`。
- **粒度**（2026-11-25 拍板拆为 **2 个清晰的串行 PR**）：① **`66-1`（写后当轮即时自修 + 环境摘要注入 + 有界迭代 + 依据三档写回同一验收卡 PR）**；② **`66-2`（共享缓存前缀的 5 路多代理评审 + 简化／安全专科与对抗验证 PR）**。
