## ① 服务差异：每个服务现在能做什么、还做不了什么

「能做」不是手写名单，都从声明来：插件声明了来源 → **Feed 来源**；声明了文档导入 → **导入文档**；登记成读取记录动作 → **助理可读**；声明了网页搜索 → **网页搜索**；服务声明了类别 → **技能里的类别**（技能正文里的 `~~项目跟踪` 对上它）。「还做不了」来自声明里 `unfulfilled` 的能力和覆盖表的缺口，每条写原因和能走的路。

| 方案 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 行里写用途，展开分「能做／还做不了」**（推荐） | 行的说明改成「能用在：Feed 来源 · 助理可读 …」；展开后账号四行下面两栏：现在能做（每条带用途）、还做不了（原因＋能走的路）。顶上一排「按用途看」筛选 | 沿 13 批的就地展开，不加页面；一眼看到差异，要找「谁能做 Feed 来源」点一下筛选 | 服务多时同类之间要逐个展开对比 |
| B 「按服务／按用途」对照表 | 顶上切换；按用途是一张表（行是服务、列是五种用途，格子写「能」「要先连」或空）；窄屏改成按用途分组的列表 | 横向对比最快 | 多一个视图要维护；表格在 1024 以下要横向滚，信息密 |
| C 只在挑选时对比 | 连接页只写用途；真正要挑的时候（如技能要一个「项目跟踪」服务、同类有几个）在原处出一张对比卡，选一个只在这次工作里用 | 差异只在要做决定时出现 | 平时在连接页看不到「还做不了」 |

推荐 **A，并用 C 的对比卡做 ASC-39 的就地选择**：同一类别有几个连接时，在用到它的原处问一次（§3.1「询问一次并保留选择」），这张卡就是 13 批原处连接卡加一列候选。

状态：正常、按用途筛、能做的少（看缺口）、要管理员批准（ASC-47）、一个插件的服务没读到。

| 方案 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 发现可优化的就说，一张卡里勾选**（已选） | 每当发现新的可优化项（第一次进项目、项目文件有明显变化如加了测试框架或 CI、装了新插件或能力包、有新的可连服务）时，助理发一条消息：一张卡列最值得的三样，默认都勾上，「开启所选」→ 卡里确认 → 结果与撤销；只在 Dock 上亮一个点，不弹窗 | 一次说清、一次定；不打断手上的事 | 第一次进项目就多一条消息 |
| B 一次问一条 | 同样的时机，助理一样一样问（「要开『测试与质量』吗？」开／这次不要／以后别再提），答完折成一行，再问下一样 | 每次只想一件事 | 三样要答三次，消息拉长 |
| C 做相关的事时顺带提 | 进项目时不说；你让助理做相关的事（「CI 为什么挂了」），它答完后在下一步里给「开『测试与质量』」「连接 GitHub 读 CI 日志」，点了才出确认卡；末尾「看这个项目全部建议」 | 最不打扰，建议出现在正好用得上的时候 | 不相关的建议可能一直没机会出现；要靠你问「还能加什么」 |
