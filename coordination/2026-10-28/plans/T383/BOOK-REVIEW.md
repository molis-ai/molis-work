1. **重绑候选和锁。** 2026-11-01 当前远端 main 为 `328d5b612ef47214378ecd55e32a648228c120f3`（#1709 的 merge commit），PR #1709 已合入；它相对 B `3fd857792a27352030ac8f3544a3b57d418febc1` 只改 `tests/goals-dialogs.e2e.test.ts`，Pages 测试、两个 fixture、test-kit CDP、Workbench 均无差分。因此下一次诊断以新 main **E=`328d5b6...`** 为目标，开工仍重读远端 head/tree 和 scoped diff，构建绑定 E。现时 #1101 仍为 Draft、H=`2b38b5f5...`；其分页列出的 584 个文件包含 `tests/fixtures/goal-browser.ts`，不含 `tests/pages-actions.e2e.test.ts`。观测只改 Pages 测试本地，不改共享 fixture、test-kit 或生产 wrapper；其他在途锁在 writer 开工前重查。书中“T381 正在做”及 B 为当前候选的语气过期。
2. **把顶层与独立 session 映射写成判据。** 先用现有 `browser.command` 在 fixture 的 `sessionId` 上取 `Target.getTargetInfo` 与 `Page.getFrameTree`，记录顶层 targetId、无 parent 的 frameId、当前 loaderId；监听器须在 reload 前注册。每条事件记录收到时的 CDP `eventSession`，只将它等于顶层 session、frameId 等于顶层 frame 的事件算作本次 reload；`Page.frameNavigated` 要无 parent，`Page.lifecycleEvent` 的 `DOMContentLoaded` 要有本次 loaderId。`Page.domContentEventFired` 自身不带 frameId，不能单凭它或插件 iframe 的 `Runtime.executionContextCreated` 宣称顶层 DCL。插件帧的 `sessionId/frameId` 单独记映射，不借用 `plugin-frame-browser.ts` 的 contexts map 充当顶层证据。若 target/session 换代，标明旧映射失效并记录新映射；无法重建就标 UNKNOWN。
3. **只承诺现有 public `command/on` 能观察的事。** `Page.setLifecycleEventsEnabled({enabled:true})` 后才能依赖 lifecycle，`Network.enable` 后才能依赖 Document 请求事件；二者在顶层 session、reload 前启用，启用失败写“未观测”，不能写“没有事件”。原 `reloadPage()` 只暴露合并后的结果；要区分命令应答，在 Pages 测试里暂以同一现成 `navigate(() => command("Page.reload", {ignoreCache:true}, sessionId))` 路径包一层被动记录，监听仍由 `navigate` 在 action 前注册，记录命令调用前时间、promise 应答/错误和耗时，不改共享 fixture。public API 不暴露 CDP command id 或 socket 实际发送时刻，故称“调用/应答”，勿称已证实 wire send。`Page.javascriptDialogOpening/Closed` 及 `Target.detachedFromTarget`、可用的 crash 事件按 session/target 关联。Book 的“WebSocket 关闭”须区分产品 WebSocket 和 CDP 传输：现有 `browser.on` 不暴露 CDP socket close，不能承诺抓到它；CDP 断连只能由命令拒绝等可见结果间接判断。reload 前可读一次保存状态、`data-assistant-context.unsaved`；超时后同页 `Runtime.evaluate` 失败不丢既有事件，也不把 `beforeunload` 源码当命中证据。日志只留必要 ID、事件、时间和脱敏状态，不留正文或 URL 参数。
4. **让判断表不越级。** 分开报告命令应答、顶层新 loader 的导航/DCL、dialog、document 请求结果、target/renderer 可用性与本地等价 `navigate` 路径的最终结果。无命令应答但有 dialog 是一类；命令已应答而新 loader 未 DCL 是另一类；顶层 DCL 已到而 `navigate` 未返需查监听/session 或仍挂着的命令；只有 `navigate` 已返、随后 Pages 断言失败，才进入恢复分支分析。缺事件不能直接判 Chrome 未发，须同时写清是否成功订阅及 session/loader 归属。不要把 T381 的 Goals 导航竞争移植为 Pages 根因。
5. **一次运行与保全。** 指定准确 E 的隔离副本、匹配构建、独立 Home/profile 和机器 browser slot；用 `node scripts/run-tests.mjs --jobs 1 --retries 0 --verbose tests/pages-actions.e2e.test.ts` 跑**一次完整 4 例**，不用 `--test-name-pattern`、Full 或概率复跑。原样保留 raw stdout/stderr、退出码、每例结果、事件时间线、head/tree/build 绑定与清理记录；失败、超时、fixture teardown 失败也先保原件再只清本次资源。观测本身不能更改 30 秒、页面等待、断言、请求或导航时序。若未复现，结论仍 UNKNOWN；本地观测 patch 不作为修复永久入库，必要时保留隔离证据与可重放补丁，由根另定后续正常路径。
