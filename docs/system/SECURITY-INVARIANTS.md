# 安全不变量：每一条的代码位置和拒绝它的测试

本机的安全边界写成一张表：每条不变量写清**被拒绝的是什么**、**守住它的代码在哪**、**断言拒绝本身的测试是哪几个**。设计来源：[specs/repository-anti-corruption](../../specs/repository-anti-corruption/spec.md) §6（初稿）与 §4.18（W2-19）。

- 一条不变量的测试必须断言**拒绝**（状态码、错误码、没有被写的记录），不能只证明正常路径能走通。
- 表由门禁看住：`pnpm health:check` 的 `security invariants` 规则（`scripts/gates/security-invariants.mjs`）检查每一行点名的测试文件存在、「标题片段」确在文件里、「CI 里跑」一列的文件确实被 CI 跑到，每个 `tests/security-invariants-*.test.ts` 都被某一行点名。改了测试名就改这里。
- CI 里跑的集合是根 `package.json` 的 `test:security`，加上 `test:contracts` 里已有的几条（动作网关、`beforeEffect`、MCP 授权）。CI 是 Linux：只在 macOS 上能跑的（Seatbelt 沙箱）和较重的整机用例列在「只在本机跑」一列，等 Linux 探针（`linux-probe`，决定 #14）确认能过后再移进 CI 一列（W2-16）。
- 范围外：Computer Use 还没进 main（只有分支 `docs/computer-use-goal` 上的 spec），它的站点策略与确认节奏等功能落地时再加一行。

## 2. 怎么跑

```bash
pnpm test:security   # CI 里的这一步：上表“CI 里跑”一列的集合
node scripts/run-tests.mjs tests/security-invariants-local-entry.test.ts   # 单个文件
```

测试里的写法：

- 新测试只经包的公开入口和 `launchers/web/server.ts` 起真实的 Web 宿主（`health:check` 不许新文件引用包内部）；需要内部函数的断言，加进已经引用那个内部的旧测试里。
- 起宿主用 `createMolisWorkWebServer({ homeDirectory, controlToken })`，每个测试一个临时 Home。需要换 `Host` 头、不带 `Origin` 的请求，用 `http.request` 直接发（`fetch` 不让改 `Host`）；每个请求新开连接（宿主拒绝时不读请求体，复用连接会被挂断）。
- 升级后的 WebSocket 不是 HTTP 连接，`server.close()` 不会等它也不会关它：测试结束先 `terminate()` 再关服务。
- 这台开发机的代理会把 `198.18.0.0/15` 的地址转给本机监听的端口，所以“别的地址连不上启动器”按启动器自己的 `process_id` 判断，并跳过这个网段（原因见 `S-01` 的测试）。

## 3. 加一条不变量

1. 写清它拒绝什么，写一个**会失败的**测试（先在没有这条保护的代码上看它红）。
2. 找不到拒绝的代码，就是安全缺陷：补最小的拒绝，在提交说明和 PR 里写明这是补洞。
3. 往上表加一行：编号接着排（不复用），写代码位置和测试（路径加「标题片段」）。测试能在 Linux 上稳定跑过，就放进 `test:security`，并写进“CI 里跑”一列；否则放“只在本机跑”并说明原因。
4. 门禁红了就按它说的改表。

## 4. 开放项（没有守住，或守住的范围有限）

- **桌面 IPC 的可达范围没有实测（F15 的另一半）**：S-14 钉住了能力文件，但 `pty_spawn` 可以以任意命令、环境变量起一个进程，权限开给整个 `127.0.0.1:4173` 来源。同源的 iframe（插件侧栏 `apps/workbench/src/side-panel.ts` 的 frame 没有 `sandbox` 属性）能否直接调用这些命令、`tauri.conf.json` 的 `csp: null` 对壳加载的页面意味着什么，要有一次真实构建才能回答（c-end-readiness 的 S5 探针）。已知的缓和：同一个页面里的脚本本来就能拿到控制令牌去连 `/pty` socket 起进程（S-04），所以 IPC 没有给同源脚本新增能力；别的本机进程占着 4173 时壳会加载它的页面，但本机进程本来就以用户身份运行。
- **页面可以被任何网站嵌进框架（点击劫持）**：页面的 `PAGE_CSP`（`apps/local-host/src/web-composition.ts`）没有 `frame-ancestors`，也没有 `X-Frame-Options`（只有群聊挂载 `server/src/http.ts` 有）。变更请求要的令牌就在被嵌入的页面自己里，点击发生在真页面里，所以拒绝跨站 Origin（S-03）挡不住这一类。建议给 `PAGE_CSP` 加 `frame-ancestors 'self'` 并补一条断言它的测试：插件框架是同源的，桌面壳顶层加载，都不受影响。这一片没有动它，因为浏览器端用例的整套回归不在这里跑，嵌入方是不是只有同源也要用户确认。
- **`/locale`、`/health` 等 GET 路由没有“只读”断言**：S-03 保证的是变更不绕过令牌，GET 路由是否真的只读靠评审；页面 HTML 里内嵌控制令牌是设计（只给回环 `Host`，S-02），没有跨域读的头（宿主不发 `Access-Control-Allow-*`，见 S-03 的测试）。
- **控制令牌文件已存在但权限过宽时不会收紧**：新文件是 0600（S-06），旧文件（别的版本或手工放的）原样沿用。处理需要用户定：沿用并收紧权限、或换新令牌（换新令牌会让常驻服务与 MCP 进程重连）。
- **提示注入的“伪造标记中和”在上游**：伪造的结束标记不会跳出数据（S-13 的断言：它们留在 JSON 字符串里），但上游 `f40af26c`（在数据条目里把伪造的 system、围栏、封套标记中和掉）不在随仓库发的 `vendor/prologue-sdk` 里。换 SDK 是用户的决定（`dependencies-and-sdk-plan.md`）。
- **五处公网地址实现仍是五份**：S-10 用同一张表钉住了行为，没有合成一份：Jelly 与插件创作台各有自己认可的 `198.18.0.0/15` 例外（用户 2026-09-27 的决定），AnySearch 用 `BlockList`，RSS 在插件包内。合成一份要先决定放在哪（`contracts` 的纯函数不能引 `node:net`）。
- **Seatbelt 沙箱用例永远不会在 Linux 上跑**：S-15 里读写、起进程、直连网络被拒的断言只在 macOS 上有；Linux 上的沙箱继任者属于 C 端就绪方案的 D4。
- **Computer Use 不在 main**：站点策略与逐步确认的 S-16 目前只覆盖侧栏浏览器。
- **GitHub 的 secret scanning 与 push protection 在这个公开仓库上是关的**：要在仓库设置里开，属于用户的操作（`spec.md` §7）。
