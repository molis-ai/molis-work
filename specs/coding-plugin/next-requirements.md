### A 期：写代码天天用到，不涉及权限和费用

#### A1 读仓库说明文件，`/init` 生成

- **需求**：Coding 的每一轮自动带上仓库里的 AGENTS.md / CLAUDE.md；用户能看到这一轮读到了哪些说明文件、来自哪里；`/init` 能让模型读仓库后起草一份 AGENTS.md。
- **参照**：五家都会自动读说明文件（Cursor 读 `.cursor/rules`）；Codex 的 `/init` 生成 AGENTS.md。
- **现状**：SDK 的 `config.context.instructionNames` 默认读 `AGENTS.md`、`CLAUDE.md`、`.prologue/instructions.md`，但 Coding 的轮次里有没有真的读到还没核实。Molis 另有"项目指引"。
- **实现要点**：核实并打开 SDK 的读取；在"本轮身份与提示"里和项目指引并列显示读到的说明文件与来源；新增 `/init`，起草结果写入仍经审查。
- **验收**：在 coding-sandbox 和 Molis 仓库各跑一轮，模型遵守 AGENTS.md 里的一条约定；`/init` 起草的文件经审查写入。

#### A2 自定义斜杠命令、提示模板

- **需求**：用户能把常用任务写成命令，在斜杠菜单和命令面板里一键使用，可带参数。
- **参照**：Claude Code `.claude/commands`、Codex 自定义提示、OpenCode commands、Pi prompt templates。
- **实现要点**：项目级 `.molis/commands/*.md`，兼容读取 `.claude/commands`；再加用户级一份。支持 `$ARGUMENTS` 参数。命令只是一段提示文字，不带权限。
- **验收**：定义一个"补测试"命令，真实模型按它完成一轮。

#### A3 图片输入

- **需求**：用户能在输入框粘贴或拖入截图、设计稿，模型能看到；模型也能自己查看工作区里的图片。
- **参照**：五家都支持；Codex 有 `view_image` 工具。
- **现状**：SDK 的 Anthropic 兼容和 OpenAI 兼容两种协议都能发图片；Coding 输入框不收图片。
- **实现要点**：图片存为固定版本的附件（和材料一样可复查），作为图片内容发给模型；再给模型一个只读的看图工具。当前模型不支持看图时，界面明确说明，不能悄悄丢掉图片。
- **前提**：先用一次真实调用确认 MiniMax-M3 能不能看图；不能的话，功能照做，换一个能看图的模型来验收。
- **验收**：贴一张界面截图，让它照图改样式。

#### A4 代码智能

- **需求**：模型能查定义、引用、实现、符号和调用链；写入或修改文件后能看到新增的编译或类型错误；写入的代码自动格式化。
- **参照**：OpenCode 的 `lsp` 工具（goToDefinition、findReferences、hover、documentSymbol、workspaceSymbol、goToImplementation、调用层级），写入后回传诊断，26 种格式化器。
- **实现要点**：SDK 新增语言服务器模块，Node 宿主按文件类型需要时才启动，会话结束时关闭。新增只读工具"代码智能"，不经审查。写入或修改后附上该文件新增的错误。格式化放在审查之前，审查卡上显示格式化后的最终内容，用户批的就是最终写入的内容。先支持 TypeScript/JavaScript、Python、Rust、Go。
- **工具获取（2026-10-28 用户已定）**：按项目版本要求、运行环境及已启用语言能力，优先使用项目或本机已有适用版本；缺少时自动下载本次任务所需的公开代码分析工具到平台管理的隔离工具目录，无须用户先手动安装或逐包确认。沿已有环境准备与 B2 的目录、执行和联网规则，来源与版本由有效配置及语言插件声明确定，不为每种语言在宿主写下载分支，不另配一套联网许可。
- **安装与范围**：工具目录用于运行支撑，不成为项目第二个输出目录；保持项目依赖、版本约束、系统全局安装和个人环境设置。已准备的兼容版本可复用，不每轮重下或自动升级；只按任务实际需要获取工具，不因打开项目安装全部语言服务。工具进程及子进程沿当前项目／任务授权，下载许可不扩大代码读取、写入或外部上传权限；需要登录、付费、私有来源或系统级安装时仍按对应授权处理。
- **失败与恢复**：遵守项目／任务／来源禁网与撤权；可用本地版本仍可在授权内工作。缺少兼容版本、下载中断、安装或启动失败时说明原因和修复／重试入口，未完成产物不被当作可用工具；恢复与重启核对实际安装状态。保留成果，允许已有文件搜索、阅读等独立工作继续，不能把语言服务不可用误报为“没有错误”；停用语言能力和会话结束沿原生命周期释放本次进程。
- **验收**：保留真实跨文件改名、诊断回传与 `tsc` 验证，并增加以下编号；证明用例在测试名或注释引用编号。

| 编号 | 验收标准 | 证明方式 |
| --- | --- | --- |
| CLS-01 | 项目／本机已有适用版本时复用；缺少时按需下载到隔离工具目录并实际完成查定义、查引用和错误诊断；重开复用，无逐包确认或无关语言下载 | 隔离 Home 的已有工具与冷目录任务，对照真实语言服务进程、网络请求、工具结果及跨文件修改后的编译结果 |
| CLS-02 | 下载遵守有效版本、来源和网络限制；禁网／撤权阻止未获准请求，工具及子进程不越过项目权限；项目依赖、全局安装和个人环境未被改写 | 实际目录及配置前后对比、出站请求与权限交错；已有本地工具在许可内继续 |
| CLS-03 | 中断、失败和重启不把半成品标为可用；恢复后原任务可接续，独立工作继续，不冒称诊断通过；停用／结束后本次进程正确退出 | 真实下载、安装及启动故障与恢复，核对文件、进程、诊断状态和最终任务结果 |

- **需求**：默认允许模型搜索和读取公开网页，如查一个库的 API 文档；用户可在项目或本次任务关闭，其他操作按对应授权处理（2026-10-28 已定）。

- **运行边界**：关闭后不派出新的相关外部请求，不借已加载工具、缓存目录、浏览器、命令或派生任务绕过；已取回的材料可保留作依据，但不能假装刚刚联网或已核对最新内容。这个开关只管公开资料查询，不改变模型服务连接及其他独立获准能力；用其他能力达到同一被禁查询目的仍受限制。
- **实现要点**：通过统一目录向规划、讨论、执行等角色提供实际可用的搜索/网页读取能力，按任务需要选择；沿同一有效配置与授权链，不让角色、浏览器入口各存一份开关。开启后查询获准的公开资料不逐网址/域名确认，也不要求先手工维护白名单；地址、重定向、凭据与既有明确限制仍由可信执行边界核对。普通网页正文仍是不可信资料，不能成为更改目标或授权的指令。
- **其他操作**：上传私有文件/内容（包括塞进搜索请求）、访问需登录的内容、账号登录、表单提交、购买、下载后安装或执行等不能从公开资料许可推导，继续按对应授权处理。公开搜索的请求方式不决定它是否只读，按实际目的和效果判断。
- **公共搜索与配置**：复用平台已连接服务，在统一设置中选择默认来源，Coding 不保存专用配置（2026-10-28 已定）。连接复用、默认切换、持久化、实际来源展示与失败恢复以 [服务接入 §8.2、ASC-54～55](../assistant-service-connections/spec.md#82-公开搜索与默认来源2026-10-28) 为唯一合同；同一目录供 Coding、助理及其他获准消费者使用。
- **依赖与缺口**：默认允许不等于服务已经配置或实际可用；实施时核对当前公共搜索适配与来源。缺服务/凭据、服务失败、访问受限或内容不可读时说明具体原因，经统一入口补齐后接续，保留已取得材料与其他可做部分，不伪造检索结果、自动购买或切换到未获准服务。

#### B2 按规则放行、沙盒、网络白名单

- **需求**：用户能定下"这类操作以后都放行 / 永远拒绝"的规则，而不必逐条批；命令在操作系统沙盒里执行，越界操作被拒并说明原因。
- **参照**：Claude Code 的权限规则面板、沙盒模式和自动模式；Codex 的 `execpolicy` 前缀规则、bwrap / seatbelt 沙盒、网络代理。
- **实现要点**：沿统一授权入口提供可查看、可撤销的命令规则；AI 可提出项目／用户级长期放行规则，由用户明确同意后经现有授权服务保存；本次任务许可不自动升级为"以后都放行这个命令前缀"。命令真正跑在操作系统沙盒里（macOS sandbox-exec，Linux bwrap）。命令联网按下述已定默认与当前有效限制执行；统一网络边界在实施时接通，不以旧“只放模型和白名单”阻断已经获准的公开查询或依赖下载。
- **已定默认（2026-10-28）**：命令默认使用受限执行环境，允许当前任务有效授权覆盖的工作目录修改及必要临时／构建缓存写入；已获准构建、测试连续执行，不逐条重新确认。项目多个输入、唯一输出、同目录双角色、临时工作树与实际位置均沿[统一目录模型 §2.1、WMD-11～12](../product-flow-governance/workspace-and-materials-design.md#21-命令范围沿用同一目录模型2026-10-28)，不另做沙盒目录设置。路径许可不等于任何命令或外部副作用均获准，实际操作仍沿已有权限选项和授权。
- **执行与恢复**：Host 将同一目录与授权范围传给文件工具、命令及其子进程，在实际执行边界限制越界访问；不能只设置当前目录或依赖模型自觉。新增位置说明路径、用途与必要范围，经已有授权覆盖或补充授权后继续；只暂停依赖该位置的部分，不自动扩大到整台电脑。沙盒不可用时明确原因与恢复方式，不悄悄完全放开运行；停止、撤权、目录变化及未知结果沿既有规则处理。
- **长期放行规则（2026-10-28 用户已定）**：AI 可以根据实际任务提出建议，讲清允许的操作、适用项目／目录或其他目标、持续范围与结束条件；用户可调整、拒绝或明确同意保存。沿统一授权入口接受可辨认的自然语言同意或明确操作，不强制填写规则表或另走一套批准流程；批准执行一次不等于批准长期保存，沉默、重复批准和任务成功也不生成规则。建议本身不产生授权，保存后的实际生效范围和撤销入口可查看；扩大的内容须有对应明确同意，不把用户同意保存的窄范围改成更宽匹配。
- **当前工作与规则保存分开**：本次任务已有有效授权时直接继续，不必提出或先保存长期规则。规则建议等待、被拒、关闭或保存失败，只影响该规则是否建立，不暂停已有授权覆盖的工作，也不反复追问同一建议；当前操作确实缺授权时仍只暂停依赖部分。保存失败准确显示未保存，成功后按实际范围持久化并供后续任务使用；用户可查看、修改、撤销，收窄与撤权立即约束后续操作。规则仍受当前有效限制和平台硬边界约束，不因长期保存而变成任意命令、任意目录或全账号许可；不把记忆或 Skill 文本当作授权事实。
- **命令联网默认（2026-10-28 用户已定）**：已授权开发任务可以自动下载项目所需的公开依赖，使用项目有效的依赖配置、版本约束和来源，无须逐包或逐次重新批准。默认许可限定于任务所需下载，不自动扩大为任意联网、任意升级或服务采购；上传代码／私有内容、登录账号、私有依赖访问、推送、发布及其他联网操作仍按各自有效授权，已有明确授权直接复用。
- **联网限制与执行**：用户对项目／本次任务／来源的有效联网限制优先，明确禁止联网或禁止该来源时不派出请求；已有本地缓存可在授权内使用并如实标明来源。B1 的公开资料查询开关只约束其声明范围，不自动取消独立获准的依赖下载；不能把被禁止的查询或私有内容上传伪装成依赖下载，也不能通过安装脚本／子进程绕过限制。文件与执行范围继续沿统一目录合同，下载成功不等于安装脚本或其他副作用额外获准。界面准确区分用户限制、源不可达、需要账号与下载失败；保留已完成结果，恢复后按实际依赖状态接续，不把网络失败误报为任务完成。
- **AI 低风险自动审批（2026-10-28 用户已定）**：保留已有三种权限方式，在统一授权入口增加可选模式，本次新增范围为 Coding 命令。用户启用时明确委托范围，默认仅本次任务；长期启用沿前述明确同意保存规则，不自动替换用户原有选择。开启后，原本需要确认、尚未被逐条放行且在委托范围内的命令可交由 AI 评估，判断为低风险后自动批准并执行，无须用户再确认该条命令。此能力不能退化为只执行原本已经放行的命令；已有有效许可直接复用，不再附加一次模型审批。
- **评估依据与职责**：结合本次任务、完整命令及参数、真实目录与目标、预计读写／联网／外部效果、可恢复性和影响范围判断，不只看命令名字或执行 AI 的自述。复用现有 Agent Host／Prologue 评估能力，使用与执行请求分开的评估上下文及当前有效模型、用量配置，不另建模型服务；评估方不执行命令或修改权限。命令、文件、网页及工具返回里的指令是待评估材料，不能替代用户委托。Host 根据委托、当前状态和评估结论完成实际审批；记录“AI 自动审批”及简明理由，不冒充用户亲自批准，也不自动写成长期规则。
- **边界与恢复**：明确拒绝、平台硬边界、未启用或超出自动审批委托范围的操作不能由评估放行；非低风险、缺少关键依据、模型不可用、超时或返回无效时回到具体的用户确认，只暂停依赖部分，不靠重复评估直到得到允许。用户可查看审批记录、收窄或关闭模式，后续审批与尚未派出的操作按新状态核对；命令、参数、目标或相关权限变化后，旧结论不授权新操作。等待和重启沿原任务有效委托恢复，已执行或效果未知的操作先核对，不重复执行。其他工具仍按各自权限方式工作，不因 Coding 启用就获得自动审批。
- **验收**：保留用户命令规则的允许／拒绝回归；新增真实命令与产物证据如下，不能只凭路径配置或替身返回成功验收。

#### B3 用户钩子

- **需求**：用户能在特定时机自动跑自己的脚本（如写完文件跑 lint），钩子能拦下一次工具调用并把理由告诉模型。
- **参照**：Codex 与 Claude Code 使用同一套事件：PreToolUse、PostToolUse、Stop、SessionStart、UserPromptSubmit、PreCompact、SubagentStop。
- **实现要点**：项目里放 `.molis/hooks.json`，兼容 Claude Code 格式；钩子脚本在沙盒里跑；Coding 里加"钩子"面板，可查看、启用、停用。
- **启用与授权（2026-10-28 用户已定）**：首次启用时展示触发时机、实际执行的脚本／规则及读写、联网和其他允许范围，由用户确认；导入或发现配置不自动启用。之后同一钩子在有效范围内自动运行，不逐次弹窗，用户可查看许可、运行结果并随时停用。复用统一授权与 B2 的受限执行、项目目录和联网边界，不另建钩子权限系统；普通命令许可或 AI 代批模式不代替首次启用确认，钩子也不能放宽被它检查的工具调用权限。
- **修改与恢复**：执行脚本（包括配置引用的脚本）、规则或允许范围改变时，展示差异并重新确认；新内容待确认期间不执行，不因文件热更新、配置导入或重启沿用旧许可。已确认且未改变的配置跨轮、等待与重启复用，不重复启用确认；停用和撤权立即约束后续触发、排队及尚未派出的操作，在途调用沿现有取消边界处理，不承诺撤销已经发生的效果。重新启用仍核对实际配置与当前授权。
- **失败与接续**：沙盒不可用、越界、超时和脚本错误给出具体原因及恢复入口，不降为无限制执行或把失败当通过。前置阻断钩子未通过时不派发目标调用；写后检查失败保留已经发生的修改，把诊断交回模型继续修复，只暂停实际依赖失败检查的部分。重启先核对已运行及效果未知的操作，不重复有副作用的脚本。
- **验收**：按以下编号记录真实脚本、工具调用、磁盘或外部结果及持久状态，不能仅以弹窗次数或配置字段验收。

| 编号 | 验收标准 | 证明方式 |
| --- | --- | --- |
| CHK-01 | 首次启用明确确认脚本及范围；未确认或仅导入时不执行；确认后多次写入触发真实 lint，错误回到模型并得到修复，无逐次确认 | 正式 Coding 入口的真实模型与脚本任务，核对启用记录、调用、诊断及最终文件 |
| CHK-02 | 修改规则、被引用脚本或允许范围后，旧许可不能运行新内容；用户确认差异后才恢复，新范围外操作仍被实际拒绝 | 修改与触发交错，核对实际派发、文件及出站副作用；覆盖子进程和路径越界 |
| CHK-03 | 用户随时停用／撤权后不再触发或派出待执行操作；未改变且仍有效的许可跨轮和重启复用，停用或待确认状态不被恢复流程重置 | 持久化回读、重启及排队／撤权交错，检查真实执行和副作用 |
| CHK-04 | 阻断钩子失败阻止目标调用，写后检查失败保留修改并支持修复；沙盒失败不放开，超时／重启保留真实结果且不重复未知效果，独立已获准工作继续 | 实际脚本失败、超时、环境缺失与恢复任务，对照调用顺序和业务终态 |

CHK-01～04 当前未实现或验证；实施用例须在测试名或注释中引用编号。

### C 期：会话与上下文

#### C1 会话分叉

- **需求**：用户能从任意一轮分叉出一个新会话，另走一条路；能看到会话之间的分叉关系。
- **实现要点**：SDK 已有 `forkSession`。新会话带着到那一轮为止的历史，可选同时把文件回到那时的检查点；会话列表显示分叉关系。
- **验收**：对同一任务分叉出两种做法，各自做完，再比较结果。
- **入口**（2026-10-02）：「从这里分叉」作为对象级动作出现在情境浮条上，见 [情境动作总纲 8.5](../context-program/spec.md)。

#### C2 整段导出、分享

- **需求**：把一整段会话导出成可读文件，或分享给别人看。
- **实现要点**：SDK 已有会话导出。导出为 Markdown 或 HTML，包含工具调用、审查决定和成果链接，去掉密钥；分享发布为私有页面或文件，不上传第三方。
- **验收**：导出一段带子任务的会话，内容能逐条对上。

#### C3 长期记忆

- **需求与唯一规范（2026-10-28 用户已定）**：Coding 接入并遵守 [Prologue 记忆方案](../prologue-memory-strategy/spec.md) §1.3、§4～8；该方案统一定义内容归属、四配方、分类、形成与读取、候选批准、保留及纠错。用户在当前会话纠正后，后续相关任务采用新内容，旧值不继续干扰；Coding 不保留一套独立的逐条确认／自动保存规则或第二份配置。
- **配置与批准**：复用现有 off/manual/reviewed/assisted 配方及产品开关，新 Home 默认 reviewed，存量保留有效选择；assisted 仅按已有授权、来源核验和类别规则晋升候选，模型不能接受自己的候选。明确保存沿已有可信用户授权处理，不把普通模型工具调用当作本人批准。关闭形成、关闭读取和关闭自动保存分别按原合同生效，不相互偷换。
- **内容与调用链**：由执行 AI 按原工具说明选择记忆、项目长期说明或 Skill；一次性要求留在会话，业务事实仍归原插件。Coding 的可信原输入、形成队列、记忆写入口和 SDK 召回沿原 Memory P0 接入；复用项目／场景隔离、去重、期限、纠错和重启恢复，不自建存储、提炼循环或审批器。提炼失败不把已完成的主任务改为失败，未知保存结果和来源缺失按原方案核对并准确显示。
- **验收**：直接复用原方案编号和证明方式，不另建重复标准：MEM-12、MEM-24 验四配方和独立开关；MEM-05、MEM-32、MEM-35 验跨项目／场景读取、纠正后换会话及遗忘后不被重试学回；MEM-41～44 验内容去处、实际持久结果、授权与可纠正回执；质量、总 token 成本、性能及用户体验按 MEM-37～39 验收。实施用例引用相应编号，候选、局部工程通过与完整产品验收分别记录在原方案 §13。

Q4 产品对齐已完成，不代表 Memory P0 已交付；原负责人、依赖、暂停边界及未完成验收保持。

#### C4 旁问

- **需求**：用户能借当前会话的上下文问一个问题，答案不进会话历史，也不打断正在跑的一轮。
- **实现要点**：开一个只读的临时一轮来答，答案显示在旁边。
- **入口**（2026-10-02）：做成平台级的「问一下」，答案在情境浮条下方的面板槽里，见 [情境动作总纲 8.5](../context-program/spec.md)。

#### C5 多模型对比

- **需求**：把同一个任务交给几个模型各自做，结果并排比较，挑一份整合回去。
- **实现要点**：复用现有的并行写入、并排对比和整合，每个模型一个独立工作树。费用是单个的倍数，按用户定的上限。
- **待定**：Q6。

### D 期：离开页面也能用

#### D1 非交互运行、JSON 输出、供其他 agent 调用

- **需求**：在终端或脚本里直接交给 Coding 一个任务，拿到结构化结果；其他 agent 也能调用 Coding。
- **参照**：`codex exec`、`opencode run` 与 `serve`、Pi 的 print / json / rpc 模式、`claude -p`。
- **实现要点**：`molis-work coding run "任务"` 经本机服务执行，输出 JSON 事件流；审查照旧，命中放行规则的直接跑，需要人批的就停下并给出打开审查的链接。把 Coding 的会话能力作为工具加进 Molis 自带的 MCP 服务。
- **验收**：在终端跑一个只读评审任务，拿到 JSON 结果。

#### D2 GitHub：PR 跟进、评论触发、PR 评审

- **需求**：建完 PR 后自动盯住 CI 和评论，CI 失败时开一轮去修；能在评论里点名触发；能评审 PR。
- **实现要点**：本机轮询 `gh`，不需要公网回调；修好的改动仍经审查后推送。
- **待定**：Q7。
- **验收**：在 coding-sandbox 的真实 PR 上，CI 失败后它自动修一轮，CI 通过。

#### D3 模型操作浏览器

- **需求**：模型能打开本地开发服务器的页面、点击、截图、读控制台，用来验证自己做的界面。
- **实现要点**：SDK 已有浏览器操作能力，并在真实浏览器上测过。把 Coding 里现在禁用的"浏览器"一栏接上；公开网页查阅按 B1 的有效默认/关闭与限制执行，不另设逐网址确认；登录、私有内容读取、提交表单等按各自授权，其他浏览器操作沿 B2 与现有 Computer Use 边界。
- **与右栏浏览器的关系**（用户 2026-10-02 定）：共用右栏浏览器，不另起一个。Coding 的模型在右栏浏览器里操作，网站授权、接手与交还、截图遮蔽沿用侧栏的一套；Coding 里的「浏览器」一栏改为打开右栏的浏览器格；助理和 Coding 同时要用时排队并告知。见 [情境动作总纲 8.5](../context-program/spec.md)。
- **权限与依赖**：公开网页查询默认及公共搜索来源管理已定；其他操作按对应授权与适用的 B2 规则处理。搜索来源未就绪不阻塞已获准的直接网页读取或本地页面验证。
- **验收**：让它改一个页面的样式，再用浏览器截图证明改好了。

### E 期：体验与生态

- **E1 语音输入**：浏览器自带的语音识别或本机模型（如 Whisper）。待定 Q6。
- **E2 Vim 模式、自定义快捷键**：输入框支持 Vim 键位；快捷键可改。
- **E3 状态栏、输出风格**：状态栏显示当前模型、用量、分支、后台任务数；输出风格（简洁或讲解）作为角色提示的变体。
- **E4 编辑器集成**：ACP 服务，让 Zed 等编辑器直接使用 Coding 的会话与审查；VS Code 扩展放侧栏会话和审查；Tab 补全、行内编辑放到最后。待定 Q8。
- **E5 导入配置**：从 Claude Code / Codex 导入 MCP、命令、钩子和说明文件；读取 `~/.claude`、`~/.codex` 的范围由用户确认。

## 6. 顺序

1. A 期四项：说明文件、自定义命令、图片输入、代码智能。每项做完就测试、真实模型验收、提交。
2. B 期：按已定 B1 接通平台公共搜索、统一默认来源和公开查询设置；直接网页读取不等待搜索服务。按已定 Q2 接通命令隔离、长期规则、依赖下载及 AI 低风险自动审批；按已定 Q3 接通钩子启用、修改确认、停用及恢复。
3. C 期：分叉、导出、旁问、多模型对比；记忆按已定 Q4 随原 Memory P0 接入与验收，不重复建设。
4. D 期：命令行与 MCP 调用、GitHub 跟进、浏览器操作。
5. E 期：语音、Vim 与快捷键、状态栏、编辑器集成、导入配置。

每一期开工前先给用户看这一期的做法。

## 7. 前提与风险

- MiniMax-M3 能不能看图还没确认（A3）。
- 语言服务器按 A4、Q5 优先复用项目／本机已有适用版本，缺少时按需下载到隔离工具目录；实际可用性与版本在任务准备时核对。
- 打开操作系统沙盒后，部分构建或测试可能需要额外的读写权限，要按实际情况加规则（B2）。

## 8. 不在本阶段

- 云端 / 远程执行：云端 agent、自托管执行机器、本机与云端互相接手。
- 用户自己的中等复杂度验收任务（七块能力的最终验收）另行安排，不属于本需求。

| A4-2 | 写后诊断 + 审查前格式化 | Claude Code 的 LSP diagnostics | 写入/修改后回传该文件新增诊断；格式化放在审查之前，审查卡显示最终内容 | 改名改全、诊断为零、`tsc` 通过；审查卡看到的是格式化后的内容 |

| B3-2 | 钩子走**现有 hook bus** | Prologue `runtime.hooks` | 复用 `tool-before/after/failed`、`session-stop`、`prompt-submit` 等事件；插件 manifest 与项目规则都注册到同一条 bus；归属/作用域/阻断语义沿用现有实现 | 平台钩子与用户钩子同时生效；停用后立即不再触发 |
| D2-1 | PR 评审是**多代理工作流**，不是单个动作 | `claude-code/plugins/code-review`、`pr-review-toolkit` | 资格检查 → 读根/修改目录的 AGENTS.md → 5 个并行评审（规范、bug、git 历史、旧 PR 评论、代码注释）→ 独立置信分 0–100，低于 80 丢掉 → 只评改动行 → inline comment 或 review 卡 | 种子 bug 被抓到、已知误报被过滤、意见带文件/行 |
| D2-2 | 评论产线化 | `claude-code-action` 的 `classify_inline_comments`、`include_fix_links`、sticky progress | 未确认评论先缓冲并分类“真评审/测试探测”；每条意见带“去修复”链接；长任务用一条进度评论更新，不发多条 | 子代理测试评论不发到 PR；点“去修复”能带着上下文进入新一轮 |
| D4 | **Agent 产出的 PR 真人批准门** | `claude-code-action/agent-approval-check` | N 个有写权限的不同真人批准；`/approve <sha>` 绑定 head；push 后旧批准过期；Agent/bot 不计；分支名不作信任依据 | 未达 N 票不能合并；push 后需要重新批准 |
| D5 | 提交签名与身份 | Claude Code Action 的 `use_commit_signing` / `ssh_signing_key` | Coding 推的 commit 可配置 GitHub API 签名或 SSH 签名；bot 身份可配置；审查卡显示这次提交是谁签的 | 真实 PR 上 commit 显示 verified；身份与配置一致 |
| D6 | PR 场景的**配置来源与注入清洗** | Claude Code Action 的安全模型 | 评审/CI 场景先从 base 分支恢复 `.molis/`、`.mcp.json`、`AGENTS.md` 等项目配置，PR head 的版本只作参考；清洗 HTML 注释、不可见字符、alt、隐藏属性、实体 | PR 作者改配置不能提权；隐藏指令不进模型上下文 |
| D7 | 非交互结构化输出 | Claude Code Action 的 `--json-schema` | D1 的 `molis-work coding run` 支持 JSON Schema，结果按 schema 校验后作为单一 JSON 输出；用于 flaky 判定、发布说明、Issue 分诊 | 脚本/CI 能稳定消费；schema 不符时失败而不是猜 |
| E6 | **有界迭代** | `claude-code/plugins/ralph-wiggum` | 用 Stop 事件做“同一目标反复跑”，必须有完成承诺、最大轮数、可取消；不取代正常一轮的停止判断 | 修到测试全绿后停止；达到上限/取消后不再跑 |
| E7 | 计划即页面 | `claude-plugins-community/html-plan`、`playground` | 实施计划可生成为一张交互页：claim 树 + 每种 claim 一个 exhibit + 决策放在它影响的 claim 上；用户在页面里勾选/评论，最后把一份 response 交回 Coding | 计划页能评审、能回答决策、能把结果带回新一轮 |
| E8 | 代码简化与安全评审作为专科角色 | `code-simplifier`、`claude-security` | 评审面板可选“简化但不改行为”“安全 finding + 独立 verifier + 只出 patch”；安全评审不自动应用 | 简化不改行为；安全 finding 经过复核才进待处理项 |
