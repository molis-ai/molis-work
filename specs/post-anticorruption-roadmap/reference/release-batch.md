## 发行批（REL）

现在还在开发阶段，只有开发人员在用（用户 2026-11-14 定，[决定 45](decisions.md#decision-45)）。只为对外发行才需要的事——签名与公证、正式授权与审核、随包组件、给外部用户的日志与诊断、合同过渡与副本演练、第二台 Mac 上的验收——从 01～90 拆出来，独立成这一批，像[服务端批](server-batch.md#server-batch)一样另排。以后再有只为对外发行的事，也加进这一批，片号接着往下编。

- **什么时候开工由你定**：01～90 不等它；开工前这一批只做只读核查和设计，不占写手和机器额度。外部要等的（证书、审核、公开文件）可以随时先办，不占开发时间。
- **配置不重写**：发行用到的身份、签名、公证、运行时、账号与连接服务地址、发布者密钥都收在 [26-9](batches/26.md#batch-26-item-9) 的那一份发行配置里，开发档就是现在的行为。发行批只把发行档填满、把凭据放进它引用的位置、把发行步骤接上，不再改产品代码。版本号照旧只在 `tooling/versions.json`。
- **M1 在这一批**：M1（第一个装到开发机之外的版本）是 [REL-5](batches/rel-5.md) 的发出；合同兼容起点、读取兼容起算（`docs/system/CONTRACT-CHANGES.md`）都从这时算。服务端批要等 M1 的，等的是 REL-5。
- **批内顺序**：REL-1 随时可办；REL-2、REL-3、REL-4 互不等待；REL-5 等 [57](batches/57.md)、[44](batches/44.md) 和 REL-1～REL-4。
- **轨道**：F（场景引导与发布）；`apps/desktop/` 与发行工作流由 F 落；改 CI 工作流、动凭据和真实账号是红线，先问用户。
- **原编号**：原 26-1～26-4、26-6 整项移到这里，26-5 只移 U5；原 57 的发行部分（第二台 Mac、安装、日志与诊断、U5／U6 演练、合同兼容起点）移到 REL-5；71-2 的字体分发核对、45-2／52-3 官方包的正式签名移到 REL-2。原文件留着编号写去处。


各片的交付、前置与 Goal Prompt 在各自的文件里：[REL-1](batches/rel-1.md)、[REL-2](batches/rel-2.md)、[REL-3](batches/rel-3.md)、[REL-4](batches/rel-4.md)、[REL-5](batches/rel-5.md)。
