## 剧本

| 步 | 发生什么 | 看哪里 |
| --- | --- | --- |
| 开始 | 线上只有插件登记的事件：Feed、Inbox、Coding 会话在已办一侧，待办和等你回的邮件在接下来一侧 | 线头的数字是等你的事件数 |
| ① | 说「把定价页改成三档，发布前给我看一眼」 | 先出回应，再写出去处「新事件」；线上多一个事件，面板出现一行 |
| ② | 随口问「上周访谈里谁提过价格」 | 去处是「不属于事件 · 在后台任务里」；线上不多东西，面板多一行 |
| ③ | 「发布前检查里的链接帮我都点一遍」 | 去处是「为『发布前检查』办」；那条待办的胶囊上出现在办的标记 |
| ④ | 查访谈的任务办完 | 助理自己说话，标着「任务交回」；面板里这一行到「刚交回的」 |
| ⑤ | 定价页要你定一件事 | 事件变成等你、排在现在旁边，线头数字加一；点事件或「去定」开卡作答 |
| ⑥ | 定价页办完，助理在原交办范围内接着改了发布说明 | 回应下面写着「自己接着做了 · 第 1 次，最多 3 次」；事件卡里是逐项对照的概况和「逐项审阅」 |
| 逐项审阅 | 点「逐项审阅」，主区左边出现要求栏（沿用 2026-11-03 定样「[要求与成果对照](../assistant-proactive-paths/README.md)」） | 三项要求各写所核版本、方法、证据；机器核过的不用你管，只有自述的不算通过，要你认可的只认你；认可或退回（写原因）都在栏里，点一项高亮文稿里那一段 |
| ⑦ | 退回一项之后才有：返工交回，再次复核 | 事件回到在办，面板多一项「返工」；交回后版本成 v4，退回的那项重新核过、等你，另两项标「沿用 v3」，栏底写这一轮改了什么 |
| 补充（随时） | 在事件的标签里说话（比如第 ①～④ 步点开「定价页改成三档」再发送） | 话作为补充交给这件事的任务，回执先「已收到」，下一步变「已用上」 |

发送按钮在前三步等于「下一步」（在事件的标签里发送则是给这件事的补充）。任何时候都可以点：事件（开卡）、面板的一行（开任务卡）、「改」（换去处：新事件、不属于事件、为线上某个事件办）、「发给」（助理，或平台能跑的 Character；本机导入的原生角色列出但不能选，写明原因）、停止、停到侧边、线头（等你的清单）。键盘：事件上左右方向键移动，Esc 依次关菜单、卡、面板。

## 三个方案比的是什么

| 比较项（需求书 §10） | A | B | C |
| --- | --- | --- | --- |
| 后台任务面板 | 贴在输入框上沿的一行（几项在办、几项等你、当前这一步），点开向上展开成列表，最多约五行 | 输入框上方一排任务片，一项一片，点一片开任务卡 | 比输入框宽的一块，左边是最近的回应、右边常开着任务列表 |
| 事件卡开在哪 | 浮在输入框上方，工作面不动；可一步停到侧边 | 停靠在工作面下半，工作面让位 | 默认开在侧边 |
| 回应与去处 | 回应浮在面板上方；去处一行带「改」 | 同 A，在任务片上方 | 在左栏里，和任务并排 |
| 事件背后有任务 | 胶囊上状态环加数字 | 胶囊上小圆点，一项一点 | 状态环加「N 项」 |
| 顶部固定插件 | 只有图标 | 当前插件带名字 | 只有图标 |
| 让位 | 只有面板占的高度让位，回应与卡浮着 | 面板一排加停靠的卡都让位 | 整块都让位 |

三个方案相同的部分：线的排法（已办在左、接下来在右、在办和等你的贴着现在）、线头、去处的三种取值和「改」的菜单、「发给」、任务卡的内容、异常状态的写法。390 宽时线变成输入框上方一条可横向滑动的轨道，停在「现在」；侧边变成盖在工作面上的一层。

**方案 D（用户 2026-11-14 看过 A～C 后提的）**：助理对话框留在输入框上方正中（回应与去处；点线上的事件时，事件卡就开在这个框里）。对话框右上角有一个图标（状态环加在办的数量，有等你的就变色）；点它，后台任务浮窗出现在对话框右边，紧挨着、底边对齐；点一行在浮窗里看任务卡，可以回到列表。对话框和浮窗都浮在工作面上，工作面不让位、不变窄；右边放不下时（1024 以下、390）浮窗叠到对话框上面。胶囊用状态环加数字，顶部当前插件带名字（这两项用户已定）。第一版 D 把图标放在输入框角上、浮窗放到屏幕右下，用户指出对话框不该到右边去，已改掉。

**方案 E 整体版（用户看过 D 后要求「结合助理对话框综合设计」）**：展开时就是产品里现有的助理对话框——同一个面板、同一条标签栏、同一套消息样式（`kit.css` 里 `.assistant-panel`、`.assistant-tabbar`、`.assistant-thread`、`.assistant-msg`），不另画一套。在它上面只加四处：① 标签栏右上角的后台任务图标（状态环加数量，有等你的变色），点开后任务浮窗贴在对话框右边、上沿对齐，右边放不下时盖在对话框右侧；② 第一个标签是和助理（或所选 Character）的主对话，点线上的事件就在同一个对话框里多开一个标签，标签里先是事件卡、下面是关于这件事的对话；③ 助理的每句回应下面带去处一行和「改」，任务交回的回应标出来自哪项任务；④ 收起时输入框上方只留最近一句回应（同样带任务图标和展开按钮）。对话框和浮窗都浮在工作面上，不让位。

方案 E 细化后的各处（2026-11-14）：

| 处 | 现在怎样 |
| --- | --- |
| 主对话的标签 | 每个对话对方一个：助理在最前，选过的 Character 各一个，和输入框里的「发给」同步。交给谁办的事，结果回到谁的标签；不在看的那个标签上亮一个点 |
| 事件的标签 | 点线上的事件就开一个；标签里先是事件卡（右上角可「停到侧边」），下面是关于这件事的对话；这时输入框写「关于这件事，对助理说…」，说的话给这个事件 |
| 标签很多 | 标签宽度随名字（96～184），放不下横向滑，右边渐隐，当前的标签始终看得见。产品里现在是等分收窄到 96，名字只剩两三个字，这里改了，记作组件板新增 |
| 等你 | 事件排到「现在」旁边、线头数字加一、任务图标变琥珀色；助理在主对话里说一句并带「去定」。不替用户打开事件、不切标签 |
| 收起时 | 输入框上方留最近一句回应；点了工作面这一句收起，只剩任务图标和展开按钮，不挡正文；有新回应再出现 |
| 手边 | 「＋」打开菜单：Shelf、灵光、项目资料、这台电脑；选一项就附在输入框上面一行（可横向滑、可移除），发出后清空 |
| 多行输入 | 输入框向上长，最多五行，再多在框里滚；只有这一项让工作面让位，线的高度不变；对话框跟着上移并相应变矮 |
| 顶部标签 | 放不下的收进「+3」，点开是菜单 |
| 失败 | 事件描红、任务图标描红；助理在对话里说明没办成和留下了什么，带「重试这一步」「看任务」 |
| 断线 | 任务图标描虚线带警示；浮窗底下一行「断线了，状态停在 09:41」和「重连」；在办的行标「状态待核对」 |
| 1024 | 浮窗放不下右边，盖在对话框右下角 |
| 390 | 线是输入框上方一条可横向滑的轨道；对话框是轨道上方的一层，不盖轨道和输入框；浮窗是再上面的一层；胶囊、线头、输入框按钮高 44 |

A～C 里我原先建议 A：面板只占一行，不抢工作面；点开才展开，和助理的回应上下排，眼睛不用左右找。B 的任务片在任务多时要横向滑，C 常驻占的高度最多。

## 异常状态

- **排队**：同时只跑一项时，后来的任务标「排队」并写原因。
- **任务失败**：第 ⑤ 步定价页失败，事件描红边，助理说明没办成和留下了什么；卡里可以重试这一步。
- **断线后核对**：面板出现断线提示，在办的任务标「状态待核对」；重连后提示核对过、没有重复派出。
- **一个来源读不到**：Feed 读不到时线上其余事件照常，线的一端有一个虚线的「读不到 · 重试」。
- **没有任务**：A、B 不显示面板；C 的右栏写一句空状态；E 的图标不带数字，浮窗里写一句空状态。
- **停止**：停下的任务标「已停止」，提示停下之后才回来的结果不会写入。

## 组件板新增（标本已补，待合审）

标本在组件板的「事项线」一节（`/__ui/catalog#work-line`，框架页 `/__ui/catalog/navigation?sheet=work-line`，复用工作台导航的框架页，没有新增整页）。样式在 `apps/workbench/src/styles/work-line.ts`（并进工作台样式表），标记由 `apps/workbench/src/work-line-parts.ts` 的函数画，产品接入时调同一组函数。做标本时对照产品现有控件收掉了两样：「发给」沿用输入框已有的接收者标签（点开是助理与 Character 的菜单），手边附上的条目沿用输入框上方已有的「随下一句带上」的那一条（`.assistant-context-strip`），都不另做新部件。任务面板头上的三个数改成状态环加数字（等你、失败、在办），文字放在读屏名字和提示里，中英文都放得下。

方案 E 用到的：线（两翼与现在）、线头按钮、事件胶囊（含等你、失败、待核对、读不到四种状态和背后任务的标记）、「发给」按钮、手边附上的条目、后台任务图标（平常、等你、失败、断线）、后台任务浮窗（列表、任务卡、断线提示）、任务行上的「为哪个事件」标签、对话一轮里的去处行与「任务交回」标记、事件标签里的事件卡、收起时输入框上方的那一句回应。对话框本身、标签栏、消息气泡是产品已有的（`kit.css` 的 `.assistant-*`），只有标签宽度随内容这一处改了。卡里的决定请求、逐项对照沿用[智能呈现四种形态](../intelligent-surfaces-forms/README.md)和第 24 批已有的写法，只是摆进卡里。

## 走查（2026-11-14，主会话在浏览器里逐步做）

路径：交办「定价页改成三档」→ 随口问访谈 → 为「发布前检查」交办点链接 → 在「定价页改成三档」的标签里补充一句（回执「已收到」→「已用上」）→ 访谈的结果回到助理 → 定价页要你定（去定、作答）→ 定价页办完，助理在原交办范围内接着改发布说明 → 逐项审阅：认可一项、退回一项 → 返工交回，只重核退回的那项，再认可 → 回到主对话。

| 看什么 | 结果 |
| --- | --- |
| 1440 中文浅色，整条路径 | 走通；每一步线、对话框、任务图标与面板、事件卡状态一致 |
| 1024（中文浅色、英文深色） | 走通；任务面板盖在对话框右下，不出横向滚动 |
| 390（中文浅色、英文深色） | 走通；线可横向滑、对话框与面板不盖线和输入框，页面无横向溢出；要求栏落到文稿上面 |
| 异常：排队、任务失败、断线后核对、一个来源读不到 | 各有明确的状态与下一步（排队原因、重试这一步、重连后核对、读不到 · 重试） |
| 键盘 | Esc 依次关菜单、任务面板、对话框；事件上左右键移动；回车发送、Shift+回车换行 |
| 多行输入与附件 | 输入框向上长，工作面让出同样高度，线不动；附上的条目一行、可移除 |

## 这份原型没做的

侧边的其他页是占位；手边里「钉到侧边」没画；切换事项（线头菜单）是第二片；对话框里现有的会话列表侧栏、语音没有带进来（沿用产品现状）。
