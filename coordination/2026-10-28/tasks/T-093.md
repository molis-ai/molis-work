# T-093 Issue 起名时模型给的标题、追问和编辑中的描述按 Unicode 字数数上限，与动作 schema 一致

> **这条在 main 上成立：Issue 起名的动作 schema 按字数数上限，主人自己却按 UTF-16 单元数。**
> - `issues.suggest_name@1`（`plugins/native/issues/src/actions.ts:41-43`）：
>   - 输入的描述 `maxLength: 100000`（`:11`）；
>   - 输出的标题 `maxLength: 200`（`:10`）、追问 `maxLength: 200`（`:35`）。
> - `issues.name_draft@1`（`:36-38`）的输出用的也是这两个上限。
> - 动作层用 Ajv 校验，Ajv 的 `maxLength` 按 Unicode 字符（码点）数：`packages/kernel/src/action-schema.ts:41-42` 的选项里没有 `unicode: false`。
>
> 主人却按 `string.length` 数，有两处（第 1 节的表）。一个 emoji 或扩展 B 区以后的生僻字在 JS 字符串里占 2 个单元。所以：
> - 模型起的 101～200 个这样的字的标题或追问，被当成坏答复，以 `issues.model_reply_invalid`「模型没有给出可用的标题和类型，点开补全后保存」拒；
> - 编辑中 50001～100000 个这样的字的描述，过了 schema，重新起名时又被拒为「请描述问题或添加图片」。
>
> 起草时只读了代码，没有跑；第 5 节的先红就是复现。这是 T-092（同一个插件的记录与录入草稿）的另一半，T-077、T-079、T-080、T-083、T-086、T-090、T-091 的同类。
>

## 1. 背景

- 合同口径（都按 Unicode 字符）：
  - `plugins/native/issues/src/actions.ts`：
    - `:10`：`title`，`maxLength: 200`；`:11`：`description`，`maxLength: 100000`；
    - `:35`：`question`，`question` 字段 `maxLength: 200`；
    - `:36-38`：`issues.name_draft@1`，输出是 `saved` 加记录，或 `question`；
    - `:41-43`：`issues.suggest_name@1`，输入是 `description`、`images`、`page`，输出是 `named` 加 `title`、`type`，或 `question`；
    - `:72`：它的处理器，先 `editing(input)`，再 `nameIssue`。
  - Ajv：`packages/kernel/src/action-schema.ts:41-42` 的选项、`:79` 的 `new Ajv(options)`。没有 `unicode: false`，`maxLength` 走 Ajv 的 `ucs2length`，按码点数。
- 按 UTF-16 数的两处：

  | 位置 | 现在的写法 | 谁会走到 |
  | --- | --- | --- |
  | `naming.ts:28`（`line`） | `const line = (value: unknown, max: number): value is string => typeof value === "string" && value.trim().length > 0 && value.trim().length <= max && !/[\r\n]/.test(value.trim());` | `issueNaming`（`:31-36`）：标题在 `:33` 量 200，追问在 `:34` 量 200，都不合就在 `:35` 抛 `issues.model_reply_invalid`。`nameIssue`（`:44-54`）在 `:53` 用它；`issues.suggest_name`（`actions.ts:72`）和 `issues.name_draft`（经 `capture.ts:68`）都走 `nameIssue` |
  | `actions.ts:62`（`editing`，`:61-65`） | `if (typeof input.description !== "string" \|\| input.description.length > 100000 \|\| !input.description.trim() && !input.images?.length) throw new ActionError("actions.input_invalid", "请描述问题或添加图片");` | 只有 `issues.suggest_name`（`:72`）：编辑一条已存的记录时重新起名，在问模型之前查 |

- `line` 的第一个判断 `value.trim().length > 0` 只问是不是空的，按单元数和按字数数结果一样，不改。
- 改了以后，下游放得下，起草时逐处读过：
  - `issues.suggest_name` 不写入：标题和追问原样回给页面（`actions.ts:72`）。人再保存时走 `issues.update`，记录的标题由 `store.ts:34` 量；
  - `issues.name_draft` 拿到标题就存（`capture.ts:70` → `:83` 的 `store.create`），也由 `store.ts:34` 量。`store.ts:34` 现在按单元数，T-092 把它改成按字数数。所以 T-092 合入之前，模型起的 101～200 个 `🟢` 的标题会在存的时候被拒为「标题格式不正确或太长」，不再是「模型没有给出可用的标题和类型」。合并排在 T-092 之后就没有这一段；
  - 追问只回给页面，`issues.name_draft` 回追问时不写入（`capture.ts:69`）；
  - 描述作材料交给模型（`naming.ts:50-51`）。`fencedMaterials`（`packages/contracts/src/platform/model-prompts.ts:60-62`）不截不限；起草时没找到宿主对插件模型调用材料长度的上限。
- 没有测试量到这两处：
  - `tests/issue-naming.test.ts` 里模型答的标题、追问和描述都是几个汉字或 ASCII（如 `:53`、`:180-182`）；
  - `:186` 只量了空描述，没量长度。
- 页面不受影响：页面包从 `src/browser/factory.ts` 打，`src/browser/**` 只引同目录的文件，不引 `../naming.js`、`../actions.js`。所以 `/assets/molis-work-plugins/issues.js` 的字节不变（`tooling/gates/page-assets.json:28`）。

## 2. 目标

1. 模型起的标题 200 个、追问 200 个非 BMP 字符（如 `🟢`）原样收下；各多一个仍以 `issues.model_reply_invalid`「模型没有给出可用的标题和类型，点开补全后保存」拒（`RAC-1664`）。
2. 编辑中 100000 个这样的字的描述能拿去重新起名，原样交给模型；100001 个仍以 `actions.input_invalid`「请描述问题或添加图片」拒，不问模型（`RAC-1664`）。

上限本身不变。

```ts

test("RAC-1664 naming counts Unicode characters: a 200-character title or question from the model is taken and 201 are refused; 100000 characters of edited words go to the model and 100001 are refused before it is asked", async t => {
  // suggest_name's schema (src/actions.ts) counts characters for the words and for the reply; one 🟢 is one character but two UTF-16 units.
  const { store } = await issues(t);
  const wide = (count: number) => "🟢".repeat(count);
  const answers: unknown[] = [
    { status: "named", title: wide(200), type: "bug" },
    { status: "needs_input", question: wide(200) },
    { status: "named", title: wide(201), type: "bug" },
    { status: "needs_input", question: wide(201) },
  ];
  const fake = model(() => answers.shift());
  const suggest = issueActionHandlers(store, fake.client).find(binding => binding.capability_id === issuesActions.suggestName.capability_id)!;
  assert.deepEqual(await suggest.handle(caller, { description: wide(100_000) }), { status: "named", title: wide(200), type: "bug" },
    "100000 characters of words reach the model, and a 200-character title is taken");
  assert.equal(data(fake.calls[0]!).description, wide(100_000), "the words go to the model whole");
  assert.deepEqual(await suggest.handle(caller, { description: "保存没反应" }), { status: "needs_input", question: wide(200) }, "a 200-character question is taken");
  await assert.rejects(suggest.handle(caller, { description: "保存没反应" }),
    { code: "issues.model_reply_invalid", message: "模型没有给出可用的标题和类型，点开补全后保存" }, "a 201-character title is still past the limit");
  await assert.rejects(suggest.handle(caller, { description: "保存没反应" }),
    { code: "issues.model_reply_invalid", message: "模型没有给出可用的标题和类型，点开补全后保存" }, "a 201-character question is still past the limit");
  assert.equal(fake.calls.length, 4);
  await assert.rejects(suggest.handle(caller, { description: wide(100_001) }),
    { code: "actions.input_invalid", message: "请描述问题或添加图片" }, "100001 characters of words is still past the limit");
  assert.equal(fake.calls.length, 4, "the refused words did not reach the model");
});
```

3. 几处为什么这样写，别改：
   - 用 `🟢`（U+1F7E2）：一个码点、两个 UTF-16 单元，没有变体选择符。T-077、T-079、T-080、T-090、T-091 和 `tests/content-owner-regressions.test.ts:58` 用的也是它。
   - 值正好压在上限上（200、100000），多一个（201、100001）就拒，才分得清按字数和按单元。不要缩短。
   - 直接调处理器，不经动作服务：schema 按码点数，100001 个 `🟢` 的描述本来就过不了 schema；模型的答复也不经 schema 回到主人。本单要证的是主人不再多拒，只能直接调处理器。`:181` 已有的用例也这样取处理器。
   - 模型答复按顺序排在 `answers` 里，一次调用取一条：`model()`（`:21-34`）每次 `complete` 都调一次 `answer`，把它的返回值作 `value`；`nameIssue` 用的就是 `result.value`（`naming.ts:53`）。
   - 后三次的描述用几个汉字：本单要看的是答复的长度，描述的口径第一次已经量了。
   - `data(fake.calls[0]!)`（`:35`）从交给模型的材料里读出描述，证明 100000 个字没被截。
   - 先断言 `fake.calls.length` 是 4，再断言被拒的描述之后仍是 4：`editing`（`actions.ts:62`）在问模型之前拒。
   - `assert.rejects` 的第二个参数比对 `code` 和 `message`：
