## 1. 背景

2026-10-20 的清理审计找出 54 个完全没人用的导出，分批删。main 上现在只剩 4 个还在：`apps/workbench` 的这两个，`apps/local-host/src/material-native.ts:14` 的 `materialImageExtensions`，和合同里的类型 `GoalEventSystemOperation`（公开合同，不动）。审计当时把 `apps/workbench` 的这几个留到「视觉线合入后」（`docs/reviews/cleanup-audit-2026-10-20.md:391`）；`specs/repository-anti-corruption/spec.md:2918` 写着 `renderPluginRailAccountFooter`「没有调用方，已作为单独任务提出来」，这就是那个任务。视觉线早已合入：当时拦着的 #851、#864 已合并，#934、#946、#970 已关闭（`specs/repository-cleanup/inventory.md:168-169` 还写着「开放 PR」，是旧的）。

核下来的事实：

- `renderPluginRailAccountFooter`：定义在 `apps/workbench/src/settings-directory.ts:27-38`，返回一段 `<footer class="personal-sidebar-footer">`，里面是「Dock 与插件」按钮和占位注释 `<!-- account-global-items -->`。全仓库（不含 `docs/`、`specs/`、`archive/`）`git grep -n -w renderPluginRailAccountFooter` 只有这一处定义，没有 import、没有调用、没有测试引用。
- `sideViewKeys`：定义在 `apps/workbench/src/side-view-document.ts:93-97`（`93` 是注释，`94-96` 是函数），全仓库同样只有这一处。它在注释里说「给 Host 对其余一切回 404」，但这件事不是它做的：`apps/local-host/src/web-project-platform-routes.ts:62-64` 调的是 `workbenchRenderer.renderSideViewDocument(...)`，返回空就回 404；`renderSideViewDocument` 在 `side-view-document.ts:46`、`:49` 已经对「插件没启用」「没有这个侧栏」返回 `null`。所以删它不会少一道把关，只是少一个没人调的重复写法。
- `apps/workbench/src/settings-directory.ts` 删掉后仍导出：`SettingsDirectoryPrimitives`（`:6`）、`renderPersonalMenuItems`（`:41`）、`renderSettingsDirectorySection`（`:80`）、`renderProjectSettingsDirectorySection`（`:91`）、`renderSettingsWorkSurface`（`:102`）、`renderProjectSettingsWorkSurface`（`:118`）。它们的使用方：`primitive-catalog.ts:18`、`shell-page-renderer.ts:19`，和通过 `apps/workbench/dist/settings-directory.js` 引用的 `tests/functions-plugin.test.ts:21`、`tests/plugin-global-settings.test.ts:39`。
- `apps/workbench/src/side-view-document.ts` 删掉后仍导出：`SideViewModel`（`:21`）、`SideViewDocumentInput`（`:29`）、`renderSideViewDocument`（`:44`）、`sideViewBridgeScript`（`:100`，删后上移 6 行）。`apps/workbench/src/index.ts:1` 只转出类型 `SideViewDocumentInput`，不转出 `sideViewKeys`；`renderer.ts:102` 包的是 `renderSideViewDocument`。
- 删后那两个文件里的 import 还都有人用：`sideEntries`（`side-view-document.ts:7` 导入，`:45` 使用）、`ProjectPluginId`（`:2` 导入，`:34` 使用）。`tsconfig.base.json:15-16` 开着 `noUnusedLocals`、`noUnusedParameters`，所以漏了会在 `tsc` 里直接红，不会悄悄留着。
- 页面资源：这两个都是服务端拼 HTML 的函数，不在任何 `/assets/` 文件里，页面资源字节不应变。公开 API 快照（`tooling/gates/api/`）和动作合同快照（`tooling/gates/actions/`）只管 contracts 子路径、插件 SDK 与动作，不含 `apps/workbench`。
- 一个相关但这次不动的地方：`apps/workbench/src/immersive-shell.ts:120` 的 `renderPluginRail(primitives, enabled, accountFooter, …)` 有一个 `accountFooter` 参数，`:204` 用它的内容替换占位注释。生产调用方（`shell-page-renderer.ts:260`、`primitive-catalog.ts:54`）传的都是 `""`，只有测试还传非空串（`tests/agent-built-plugins-workbench.test.ts:9`、`tests/characters-appearance.test.ts:52`）。这个参数以后可以连同 `:204` 的替换一起去掉，但 `immersive-shell.ts` 被 #1348（T-006）锁着，见第 3 节。

## 2. 目标

1. `apps/workbench/src` 里没有 `renderPluginRailAccountFooter` 和 `sideViewKeys`（`RAC-1190`）。
2. `apps/workbench` 能类型检查、能构建，已有测试照常通过，两个文件的导出只少了这两个名字（`RAC-1191`）。
3. 健康门禁数字、页面资源、API 与动作快照都没有变化（`RAC-1192`）。

- `apps/workbench/src/i18n/gap-en.ts:54` 的 `"Dock 与插件": "Dock and plugins"`：删掉 `renderPluginRailAccountFooter` 之后，仓库里就没有别处用这句中文（`git grep -n "Dock 与插件"` 只剩这一行）。翻译门禁对无用键只报告、不拦。这个文件在 #1348 里，不碰；列进【交接】。
- 样式 `.personal-sidebar-footer`、`.account-global-*`：别的标记和测试还在用（如 `tests/visual-foundation.test.ts`、`tests/chrome-inner-scroll.test.ts`），而且动样式会改页面资源字节，要走视觉探针。不做。
- `specs/repository-anti-corruption/spec.md:2918` 那一行：#1335、#1101 在改这份 spec，不碰；做完后列进【交接】，由统筹在 spec 里改成已做。
- `docs/reviews/cleanup-audit-2026-10-20.md`、`specs/repository-cleanup/inventory.md`：历史记录，不改。
- `apps/local-host/src/material-native.ts` 的 `materialImageExtensions`：另一个包。不做，另起一个任务。

## 5. 做法

1. 动手前先验证没人用，在仓库根目录：

   ```
   git fetch origin main
   git grep -n -w -e renderPluginRailAccountFooter -e sideViewKeys -- . ':!docs' ':!specs' ':!archive'
   ```

   应当只有两行，就是第 1 节说的两处定义（`settings-directory.ts:27`、`side-view-document.ts:94`）。多出任何一行（import、调用、测试），停，见第 11 节。再用 `gh pr list --state open --json number,files` 看有没有在途 PR 改这两个文件。
2. 先量一遍删之前的导出，记在手边：

   ```
   node --input-type=module -e "for (const f of ['settings-directory','side-view-document']) console.log(f, Object.keys(await import('./apps/workbench/dist/'+f+'.js')).sort().join(' '))"
   ```

   这要先有构建；没有就先 `node scripts/machine-slot.mjs run build --label "<谁> T-031" -- pnpm build`。
3. `settings-directory.ts`：删第 27-39 行。第 26 行那个空行留着，这样下一个导出前面的注释（原第 40 行 `/** Personal entries under the project button …`）上面仍然隔一行。
4. `side-view-document.ts`：删第 93-98 行。第 92 行的空行留着，这样下面原第 99 行 `/** The same parent protocol …` 的注释上面隔一行。
5. 只删这两段，不动 import 行。`tsc` 若报某个 import 未使用，只可能是你多删了；先对照第 1 节的行号检查，不要靠删 import 压过。
6. 不要顺手改同文件里的其他函数、注释、空行，也不要给删掉的东西留「已移除」之类的注释。
