# 「这条规则在别处改过」定样（第 05 批 N14）

状态：用户已定（2026-11-06）：方案 A「就地接住」。决定、理由和否掉的 B、C 记在[第 05 批的定样决定](../../../specs/post-anticorruption-roadmap/reference/batches/05.md#batch-05-n14-sample)。产品未实现，实现等定样合入和 N14 合同（`specs/action-input-contracts/spec.md`，在 [#1868](https://github.com/molis-ai/molis-work/pull/1868)）。

场景：你在判断规则编辑器或 Feed 的规则页改了内容，提交时这条规则已经被别处改过（另一个窗口、助理或别的调用方）。N14 把这些提交改成必须带版本检查之后，这件事会更常被发现，所以要给它一个样子。

## 怎么打开

在仓库根目录运行，然后打开 <http://127.0.0.1:4431/rule-stale-reload/>：

```sh
pnpm build
node docs/design/rule-stale-reload/export.mjs
python3 -m http.server 4431 --bind 127.0.0.1 --directory docs/design
```

第二步生成产品标记和页面样式（`dist/`，不入库）。顶上两行斜纹条是原型控制，不是产品界面：选页面、状态、数据量（常规、最挤、最空），切中英文和深浅色；第二行写这个状态里什么是模拟的。

某个状态可以从地址直接打开，例如 `#h=editor&st=conflict&d=plain&l=zh&t=light`。

**直接试一遍：** 状态选「正常编辑」，在「判断说明」里打几个字。280 毫秒后自动保存碰到别处的改动，光标不动，底部出现提示。点「载入最新版」，再点「放回」。

- **画面是什么做的：** 控件和令牌取自组件板实件 [`../kit/`](../kit/README.md)；编辑器和 Feed 的标记由产品自己的 `renderFunctionsWorkbench`、`renderFeedWorkbench` 生成，样式是产品样式表，英文来自产品词典。Feed 上方的标签条省略了，与这件事无关。
- **什么是模拟的：** 规则内容、别处的改动、保存、断网和时长。不连任何服务，不碰任何 Home。

## 这一屏要回答什么

- **用户此刻要知道：** 我写的没丢；这条规则变了；这次没存上。
- **最想做的：** 接着把事做完，别把别处的改动盖掉，也别丢自己的。
- **主焦点：** 提示里那一个主按钮。这时「下一步」从主按钮退成次按钮，一屏只留一个主操作。
- **不丢内容：** 表单不动、不清空，自动保存暂停，可以继续打字。
- **不出现的词：** 版本字段名、409、错误码、「冲突」「过期」「刷新」都不出现。

## 定下的方案 A

提交碰到别处的改动时，底部反馈位出一条提示和一个按钮「载入最新版」，表单不动、光标不动。载入后最新版进表单；两边都改的字段，你写的摆在该字段正下方，点「放回」取回，放回后可「换回」；只有你改的字段留着。

- **决定数：** 零到若干；不处理也不丢。每个字段可来回换。
- **打断：** 不抢焦点，不挪正在打字的框。
- **代价：** 改完才看得见差别，看的是真实表单；字段分散在不同步骤时，要靠提示和步骤上的小点找。

同时定下：只有你改的字段留着（存下去的可能是两边都没见过的组合，提示里写明）；不提供一键「用我的覆盖」，要覆盖就先载入看过，再点「放回」。否掉的 B「对比后决定」和 C「拦下来问」及原因见决策记录，代码已从这里删掉，要看取定样 PR 的第一个提交（`565de2014`）。

## 十个状态

| 状态 | 样子 | 依据 |
| --- | --- | --- |
| 正常编辑 | 和今天一样，状态行走「有更改 → 正在保存 → 已保存」 | |
| 发生冲突 | 琥珀色提示「这条规则在别处改过 / 你写的都还在，还没存」＋「载入最新版」。焦点留在输入框 | 要处理的事用琥珀色，不用红（DESIGN「Reading load」） |
| 未保存内容还在 | 继续打字、换步骤都行。点发布或试跑：提示轻跳一下，焦点到「载入最新版」。要离开：确认一次「你写的还没存」，默认「留在这里」 | 覆盖类动作至少确认一次（开发流程第 5 节） |
| 已载入最新版 | 绿色提示，带一个落定的对勾；换了内容的字段淡淡亮一下；键盘焦点到第一个「放回」。别处改到的、不在当前步骤的字段，步骤上有小点 | 完成时刻才用回弹；用现有的 `[data-craft-new]` |
| 重新载入失败 | 「最新版还没载入 / 连接好像断了。你写的都还在，连上后再试一次」＋「再试一次」。同样琥珀色 | 坏消息说得平和，给下一步 |
| 已被删除 | 编辑器：「存成新规则」或「不要了」。Feed：「重新预览」，草稿会再建好 | Feed 里用户写的话才是主角，草稿只是载体 |
| 连续第二次冲突 | 分量不升级，只说「可能还有人在改它」，多一条出路「存成新规则」，以免一直撞 | 不制造焦虑 |
| 没有未保存内容 | 没什么要保护，直接换成最新版，并拦下这次发布：「发布前看一眼」＋「看看改了什么」。再点一次就发布 | 不让人发布一个没看过的版本 |
| 别处改了又改回（补充） | 什么都不显示，接上新版本再存 | 版本变了但内容没变，见下面「实现时要动的」第 2 条。别处只试跑、加样例或发布不推版本，根本不会走到这里 |
| 已在别处发布（补充） | 「发布后不能再改」＋「存成新规则」或「查看 v1」 | 见下面「实现时要动的」第 4 条 |

重新载入不到 250 毫秒时不出转圈，慢了按钮里出现小转圈。

提示的位置：编辑器的提示本来就在固定的底部；Feed 的提示钉在可见区域底部（`position: sticky`），跟编辑器同一个意思，这样它不会被底栏遮掉，键盘焦点也不会落到它后面。代价是往上滚时，它会盖住下面一小段内容，滚到底就回到按钮下方，也可以收起。

## 组件板新增（D 轨合审）

样式在 [`proto.css`](proto.css) 标了 `[组件板新增]` 的段，定下后交 D 轨补标本。

| 部件 | 写法 | 现有的为什么不够 |
| --- | --- | --- |
| `mw-alert` 动作槽（提示里的按钮） | `.cand-alert-actions`：`mw-alert` 文字下面一排 `mw-btn` | `renderAlert`（`packages/plugin-sdk/src/ui/feedback.ts`）只有标题和正文。按钮写在提示外面，读起来像属于表单，也看不出它解决的是这条提示说的事 |
| 「你写的」行 | `.cand-kept` | 要贴着一个字段，同一格能在「你写的」和「最新版」之间换，还带一个操作。`mw-alert` 是一整块提示，贴不到字段上，也换不了内容；`mw-diff` 只显示差别，不能放回；字段的说明文字只放字，放不下操作 |
| 步骤上的小点 | `.functions-steps [data-cand-dot]` | 步骤条只有「当前」和序号，说不出「这一步有东西要看」。状态环表示进度，用在这里会读成「这一步没做完」。`_catalog` 的 `.cand-pin-dot` 是 Dock 的，贴的是图标按钮、不在组件板上 |
| 字段到达光 | `[data-craft-new]` 在字段上的半透明变体 | 现有的到达光是实色，为列表行设计，盖在字段上会遮住字。时长和曲线不变，只改底色 |

**动作槽请 D 轨提成统一标本，不要变成第四份。** 第 17、18、19 批的原型里已有三份同样的本地写法：`.rk-alert-actions`（[risk-plugin](../risk-plugin/README.md)）、`.gr-alert-actions`（[schedule-task-grants](../schedule-task-grants/README.md)）、`.sk-alert-actions`（[skill-packs](../skill-packs/README.md)）。这里沿同一个形：DOM 上是 `mw-alert` 的标题、正文之后一个 `div`，声明也一样（`flex`、`gap: 8px`、可折行、`margin-top: 8px`，紧跟正文时 `margin-top: 0`）。没有另加「一行放得下就放右边」的变体，用 `.cand-` 前缀只是这份样还在组件板之外的占位。标本出来（建议 `renderAlert` 加 `actions`）后四处一起换成它。

同一条提示上还有两个小动效，不算新部件，D 轨顺带看：`.cand-band` 上碰到被拦的操作时轻跳一下（`cand-nudge`），成功时对勾落定（`cand-land`）；进场用现有的 `craft-rise`。都只用 `--dur-*`、`--ease-*`，减少动态效果时去掉。

## 以后能否复用

这个状态是通用的，Dataset 等其他插件可以用，这里不替它们改。

1. **部件：** 动作槽和「你写的」行进组件板后，任何插件都能用。
2. **做法：** 四步写进 DESIGN：暂停自动保存、留住输入、载入不丢、就地放回；再加一条「只是元数据变了就不打扰」。
3. **脚本：** 等第二个插件真要接时，再看要不要在 SDK 里沉淀一个帮手。现在两种宿主的脚本写法不同（工作台是内嵌脚本，插件是编译的浏览器模块），先不抽。

## 实现时要动的

合同以 `specs/action-input-contracts/spec.md`（[#1868](https://github.com/molis-ai/molis-work/pull/1868)）为准：§2.4 版本只代表定义内容，§2.6 每种情况得到什么，§2.7 页面怎样判断、握住哪些数据。下面只写它和这份样的对应，以及样里多出来的要求。

1. **状态怎么判断：** 按 §2.7 的表，编辑器和 Feed 同一套。过期得 `functions.draft_stale`，再 `functions.authoring.get`：读不到进「已被删除」；`status === "published"` 进「已在别处发布」；定义字段和基准版不同进「发生冲突」。页面拿到过期不自动覆盖表单。样例没了（`functions.sample_not_found`）不提示，只刷新样例列表。
2. **「别处改了又改回」：** 试跑、加删样例、发布、无变化的保存都不再推 `updated_at`（§2.4），所以别处只试跑一次，这边保存照常成功，页面不用为此写任何逻辑。只有定义字段真的被改过、又改回和基准版相同时才走到这个状态：接上新的 `updated_at` 静默重存，不打扰（§2.7）。
3. **规则被删时不丢输入：** `client-records.ts:128`、`:138` 的 `closeEditor()`，有未保存输入时不关，进「已被删除」（§2.7）。这边没写东西时照旧关掉，但今天是没有任何说明就消失，要给一句「这条规则已被删除」（样里没画这个组合）。
4. **已在别处发布：** 保存得 `functions.published_immutable`，或过期后读到已发布，都进这个状态，`get` 拿版本号供「查看 v1」。发布按 §2.6：传的是发布的那一版，幂等成功；传的是更早的版本，得 `published_immutable`。编辑器发布前先存（`client-events.ts:274`），所以第一步存就报了。这边没写东西时不说「你写的都还在」，直接进只读的 v1（样里有 `查看 v1` 之后的画面，没画这个入口）。
5. **存成新规则：** 按 §2.7，`create` 再 `update`，不传原来的 `function_key`，不带样例和试跑结果。第二步失败时表单还在，可以再存。
6. **Feed 的会话存储：** 载入最新版必须用新记录替换 `saved.function`（`rule-authoring.ts:16`），并清掉 `previewContent`，因为启用前要求预览过当前内容（`:87`），否则下次提交还是旧值（§2.7、AIC-08）。碰到 `published_immutable`、`not_found` 的清理也照 §2.7。
7. **编辑器的输入只在内存里：** 冲突期间写一份到会话存储，刷新页面才不丢；Feed 已经这样做了。
8. **「谁改的」：** 记录上没有，只有 `updated_at`。样里只说「别处」，不猜是谁。
9. **`functions.conflict`（草稿用途变了）：** 不是这个状态，§2.6 说它的出路是重新检查，不是载入最新版。这份样没有画它，沿用现有提示；实现时如果发现现有提示留不住输入，回定样再问。
10. **读屏：** 样里提示是带 `role="status"` 的节点整个插进去的，读屏软件常常不报告新插入的节点。实现时 `[data-band]` 这一格常驻 `role="status"`，只换里面的内容，并真听一遍。
11. **「已保存」别说早：** 样里点放回后提示立刻写「已保存」。实现时等保存回来才说，存失败走「连续第二次冲突」。
12. **AIC-07 的界面断言照这份样补：** 碰到过期时焦点不离开输入框、输入还在；载入后只有两边都改的字段出现「你写的」；放回后存上；连续第二次出现「存成新规则」。

## 走查结果

重新生成：`node docs/design/rule-stale-reload/shots.mjs <目录> --all`（截图和版面检查）、`node docs/design/rule-stale-reload/keys.mjs`（键盘）。截图不入库（[仓库卫生](../../system/REPOSITORY-HYGIENE.md)）。

**这次做了的（2026-11-06）：**

- **版面：** 程序检查 480 个视图（十个状态 × 两种页面 × 中英文 × 1440、1024、390；常规数据深浅各一遍，最挤、最空只跑浅色，因为版面不随深浅变）：页面不横向滚动、部件不出窗口、按钮字不被截、提示不被它所在的滚动区裁掉。0 个问题。上一轮这条新检查抓到 72 个 Feed 视图里提示被裁，所以 Feed 的提示改成钉在可见区域底部。
- **深色：** 240 张常规数据的图覆盖全部状态、三种宽度和中英文，一半是深色。深色全状态的总览图看过，另外细看了三张整图。其余的图只跑了程序检查，没有逐张看。
- **键盘：** 用真实按键事件走了 28 步（Tab、Shift+Tab、Enter、空格、Esc），全部通过：冲突时焦点不离开输入框；Tab 走到「载入最新版」，沿途每一站都看得见、有焦点环；载入后焦点到第一个「放回」；放回、换回时焦点留在同一行；发布被拦时焦点到「载入最新版」；离开确认框开着时 Tab 不出框，Esc 关掉后焦点回到「载入最新版」；断网、已删除两条出路；Feed 在 1440 和 390 下焦点都不会落到提示后面。
- **减少动态效果：** 提示、「你写的」行和对勾的动效都有退路，上面的截图和按键都是在这个模式下跑的。动画开着时的样子只在定样时看过，这一轮没有重看。

**还没做到的：**

- **手机高度只在模拟窗口（390×844）看过。** 没上真机；本机没装 Xcode，也没有 iOS 模拟器。屏幕键盘弹起后留给提示的高度没看过，实现时要上真机再看。手机上提示占去一部分高度，所以提示在时编辑器收起上一步、下一步，靠顶部步骤切换。
- **读屏软件没有实际听过。** 提示用 `role="status"`，只查了标记。
- **编辑器上用键盘要按得多一点。** 从「判断说明」到「载入最新版」，三个结果时按 13 次 Tab，结果越多越远，因为提示在表单后面。按发布或试跑会直接把焦点送过去。没有另加快捷键。
- **Feed 的提示钉住时会盖住内容。** 1024 下载入后它盖住「处理方式」和预览按钮，要往下滚或收起。这是不让提示被底栏裁掉的代价，请评审时看一眼。

## 原型没做的

- 「存成新规则」只改了提示和状态，没有真的多一行；放弃后的列表是两条示例。
- 编辑器只画了选择结果这一种判断，发布、试跑、绑定页面动作没有展开。
