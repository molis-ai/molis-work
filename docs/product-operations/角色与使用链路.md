## 1. 怎么读一张链路卡

| 字段 | 写什么 |
| --- | --- |
| 触发 | 最近一次具体发生的事：对象、时间压力 |
| 链路 | 4–8 步，每步是哪个插件、哪个动作，Work 替人做了什么 |
| 交付物 | 能检查的结果，落在哪里 |
| 机制 | 用到产品介绍里的哪几根[价值支柱](产品介绍.md#5-八个价值支柱)：M1 同一份工作记录 · M2 完成要对得上 · M3 接着眼前的东西做 · M4 材料到成果、出处跟着走 · M5 长出人和 AI 共用的工具 · M6 助理主动推进 · M7 本机优先、模型自选、边界清楚 · M8 和别人一起 |
| 成熟度 | 按整条链最弱一环标，并写出瓶颈是哪一环 |
| 原来怎么做 | 熟练用户现在的工具组合，先承认它做得好的部分，再说卡在哪一步 |
| 不适合 | 谁不该用这条链 |
| 频率 / 痛感 | 高中低，加一句依据：外部调研的数据或社区原话，没有就写"推断" |

**成熟度的口径。** 链路几乎都用到 v0.2.0 之后才合入 main 的能力，所以一律不标"已发布"。按整条链最弱的一环标，有三条例外，和 [README](README.md#成熟度标签) 一致：
- 写作、整理、问答这类只因要先配模型的环节不降级，标签后注"需模型"；推荐、判断这类决定流程走向、又没做命中率评估的，标 main 部分。
- 标了"可选"的步骤不拉低整条链，卡里单独注出它的成熟度。
- 对方进不来、由你代记别人的结论，不降级，记作瓶颈（团队协作还没做）。

这次的成熟度来自代码、README 和 spec 状态句，没有运行产品，不是实操结论。

**几个数字。** 136 条链路里，main 可用 54 条，main 部分 71 条，分支 2 条，规划 9 条（审查前是 39、82、5、10。16 条从 main 部分升到 main 可用，主要是按上面三条例外重标；INV-02、INV-05 从 main 可用降到 main 部分；UX-02 随 #712 合入，从分支升到 main 部分；LAW-03 从规划改为 main 部分；10-19 AIDEV-05 随 #726 合入，从分支升到 main 可用；10-22 FND-06 从分支改为 main 部分：它唯一在分支上的一步是输入框口述，那个 PR 于 10-20 关闭未合、改为规划，这一步可选，其余几步按最弱的 main 部分标）。机制出现的次数：M4 96、M3 56、M1 51、M2 42、M7 42、M5 33、M6 31、M8 3。

读法：

- **M4 是骨架。** 七成的链路靠"材料进来、出处跟着走、成果固定成版"。这也是 Work 今天最完整的一段。
- **M2 走出了开发者圈子。** "要求、本人验收、改约定要你点头"原本是为 AI 编码设计的，在产品、交付、法务、自由职业、学术、家庭装修的链路里都在用（见第 3 节模式 1）。
- **M8 几乎没出现。** 不是用户不需要和别人一起，而是团队协作还没做，起草时只能绕开：法务点头、导师确认、客户签字、家人一起看，今天都只能由你代为记录。这是全部链路里最一致的空缺（[建议 I8](产品优化建议.md)）。

## 3. 跨角色反复出现的十个模式

把四个分册的链路放在一起看，同一种用法在很多角色身上反复出现。每个模式写：它是什么、出现在哪些链路、对应哪个 killer、证明[开场](产品介绍.md#1-口号与开场)四句里的哪一句、共同卡在哪。

### 模式 1 "AI 说做完了"和"我认可做完了"分成两本账

- `pages.artifacts.compare` 只判断固定版和原文现在是否一致（未改、已改、已移走、已删除），不给两版之间的逐段差异。
- Shelf 七个配方里只有"提取文字"在本机、不调模型；"敏感信息脱敏"本身要把原文发给所选模型，所以"先脱敏、再交给云端模型"今天不成立。
- 本机模型可以在"OpenAI 兼容"里填回环地址接入，但没有专门模板，也没有质量验收。
- 没有按月、按季重复：Jelly 的重复只按星期，Schedule 只有一次、每天、每周。
- Feed 的 Gmail 来源只带主题和 Gmail 的摘要片段，默认只看收件箱未读；"从已有资料开始一个项目"的向导另算，最多读 20 封邮件的正文，都不读附件。Dataset 只有文本、数字、日期三种列，不能合计。
- Form 有「存成数据表」按钮，但只收当时已有的答卷，之后的新答卷不会自动进那张表。
- 外部 AI 和助理改已有对象时必须带读取时的版本，缺了或过期都被拒、要求重读；你在页面里改不受这条约束。
- Schedule 的对话任务只能读项目工作目录里的文件，读不到待办、目标、Inbox，所以"每天早上自动列一张单"今天做不到。
