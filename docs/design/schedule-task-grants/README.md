## 三个方案（都不弹窗）

三个方案里，平台那一块的内容相同：

- 顶上一行「Molis Work · 只有你能改」；
- 一句「只能读，不能改；只给这个任务；随时可以撤回」；
- 插件的数据按提供它的插件分类，一类一行：写明包含什么，配一个开关；
- 「平台」下面是项目资料，默认不勾。

| 方案 | 样子 | 取舍 |
| --- | --- | --- |
| D 就地展开 | 详情里「能读的数据」平时是一排标签和「修改」。点「修改」，就在原处展开成平台那一块。改完先看一句摘要（允许什么、撤回什么、撤回后下一次运行起读不到），再点「确认」，收回成标签 | 不离开任务，改动先看后定。要补一个新的平台能力：在插件页面里挂一块由平台画、平台写的区域（见下文「要平台补的」） |
| E 平台侧栏 | 点「修改」后，工作台右边的平台侧栏（讨论、文件那一栏）多一个「能读的数据」页签。Schedule 让出宽度，不被盖住。侧栏里一类一行配开关，并写出这一类包含的读取能力，底部是摘要和「确认」 | 用现成的平台侧栏，不用新机制，最透明。多占一栏；窄屏时侧栏占满工作区 |
| **F 开关即生效（推荐）** | 平台那一块一直摆在详情里，一类一行一个开关，拨一下就生效。下面一行说刚才发生了什么（例如「已撤回待办，下一次运行起读不到」），可以「撤销」。有新的读取能力时，那一行多一个「允许」 | 最安静，最像设置页，没有编辑态，也没有确认按钮。同样要平台补「插件页面里的平台区域」；拨错了靠撤销 |

**推荐 F**：用户要的是不弹窗、好看。F 没有多余的一步，结果和撤回后果就写在那一行下面；授权的分量靠平台标头和「只有你能改」交代。如果不想为此给平台加新机制，选 E。

**要平台补的（D、F）**：插件页面里一块由平台画、平台写的区域。

- 插件只能决定它放在哪里，读不到也改不了里面的开关。
- 平台只认真实的点按（`isTrusted`）。
- 写入照旧只走 `agent.task_grants.set` 的 `user` 受众。
- 这块区域怎样挂进插件页面、怎样防止插件在上面盖一层假的，P3 由 D 轨定，要过安全评审，并新增一条安全不变量。

E 不需要这些，因为侧栏本来就是平台的。

## Schedule 一侧（三个方案共用）

- **新建不弹窗**：「新建」在右边详情里直接写（标题、要做什么、每天几点、提醒），不再是对话框。能读的数据属于这条任务，所以建好之后再在任务里选：
  - 新建表单里只写一句「建好之后在这条任务里选它能读的数据；不选就只读项目文件」；
  - 创建后，详情顶上一句「选好它能读的数据，下一次运行就能读到」。
- **列表**：每条任务前一个种类图标（读数据／读文件，悬停有字）。需要重新确认时，状态换成「需要重新确认」。
- **详情**：标题下面是「能读的数据」一段，样子按方案 D／E／F。对话里写出「依据」读了多少条；撤回后，下一次运行如实说读不到哪一类。

## 组件板新增（交 D 轨补标本）

| 部件 | 原型里的写法 | 为什么要 |
| --- | --- | --- |
| 平台区域（D、F） | `.gr-slot`：浅底、一圈细线，顶上是平台标头 | 插件页面里由平台画的一块，要一眼就和插件自己的内容分开 |
| 平台标头 | `.gr-kicker`：盾牌图标加「Molis Work · 只有你能改」 | 三个方案都用，说明这是平台在管 |
| 条目行末尾的开关 | 在 `mw-item__end` 里放 `mw-switch` | 组件板的条目行末尾只有状态或按钮，没有开关的标本 |
| 插件色标 | `[data-hue]` 给 `mw-mark`、`mw-tag` 里的图标着 `--hue-*`（与第 19 批相同） | 一类就是一个插件，靠颜色分得开 |
| 提示里的按钮 | `.gr-alert-actions`（与第 17、19 批相同） | 读不到、保存失败时要就地重试 |
| 侧栏的「能读的数据」页签（E） | 工作台侧栏的 `mw-tabs` 多一页 | 侧栏现在只装讨论、浏览器、文件和插件视图，平台自己的一页是新的 |

## 模拟边界

- 数据是编的（`data.js`），不读任何 Home。产品里的类别名单由宿主从目录生成（只读动作按提供方分组），这里写死了 6 类做示例。
- 开关、确认、撤回、撤销只改本页内存，刷新或「重置」后回到初始。不调 `agent.task_grants.*`，也没有授权检查。
- 列表里别的任务，以及编辑、暂停、归档、选择工作区，点了只弹一句提示；侧栏里讨论、文件两个页签只是摆着。
- 运行结果是写死的样例，不调模型。
- 侧栏在原型里画成工作面旁边的一栏；产品里是工作台现有的右侧分屏。
