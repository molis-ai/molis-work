## 1. 背景

- 五处的共同点：用户（或模型）给的是 schema 放行的值，代码再按 UTF-16 单元数截一次。`.length` 与 `.slice` 数单元，Ajv 的 `maxLength` 数码点；😀 是 2 个单元、1 个字。只有两个单元的字（emoji、CJK 扩展 B 区的生僻字等）受影响，普通中文和英文每个字 1 个单元，一字不变。

| 位置（main `5a88022f7`） | 上游放行 | 代码怎么截 | 一个放行的输入会怎样 |
| --- | --- | --- | --- |
| `input-actions.ts:78`，`goals.inputs.bind` 的 `title` 成为 `input_name` | `title` 1～200 个字（`:44`，`{ ...identifier, maxLength: 200 }`；`identifier` 是 `{ type: "string", minLength: 1 }`，`goal-event-action-schemas.ts:8`） | `slice(0, 200)` 按单元 | `a` 加 150 个 😀（151 个字、301 个单元）被截成 `a`、99 个 😀 和半个字；200 个 😀（200 个字）被截成 100 个 😀 |
| `input-actions.ts:98`，`goals.inputs.confirm` 的 `name` 成为 `input_name` | `name` 1～200 个字（`goal-entry-actions.ts:111`） | 同上 | 同上 |
| `event-acknowledgement.ts:65`，`goals.events.acknowledge` 的记录标题 | `note` 1～300 个字（`acknowledge-actions.ts:17`），代码先 `.trim()`（`:62`） | `slice(0, 80)` 按单元 | 标题是说明的前 80 个单元：第 80 个单元是两单元字的前半就以半个字结尾；全是 😀 的说明，标题只有 40 个 😀 |
| `event-state.ts:255`，`goals.note` 的记录标题 | `body` 非空，没有上限（`actions.ts:91`，`body: identifier`） | `slice(0, 80)` 按单元 | 同上；正文 `body` 原样存在 payload 里（`:257`），只有标题受影响 |
| `fragment-offers.ts:21`，`clip`，用在 `:29`（步骤，80）、`:60`（提案摘要，200）、`:64`（卡片行里每步的名字，20）、`:70`（进展摘要，200） | 片段每段文字至多 4000 个字，对象标题、Goal 标题至多 200 个字（`action-fragments.ts:110`、`:114`、`:123`、`:127`） | 判断 `text.length > max` 和 `slice(0, max - 1)` 都按单元 | 81 个 😀 的一步被截成 39 个 😀、半个字和 `…`；恰好 80 个 😀（160 个单元）本来放得下，也被截 |

- 五处都没有「拒绝」的一端。绑定名称、确认名称和笔记标题在 schema 里合法，代码不报错、不告知，存下去的是另一个值。

  - 不是文字的：数组的 `slice`（`MAX_STEPS`、`limit`）、日期的 `slice(0, 10)`、随机 id 的 `slice(0, 8)`、`request_id.slice(0, 36)`（`fragment-offers.ts:46-47`，请求 id 由平台生成，拼进目标 id）；

## 2. 目标

1. `goals.inputs.bind` 的 `title` 与 `goals.inputs.confirm` 的 `name`：放行的值（至多 200 个字）原样存下，不被截短，也不以半个字结尾；
2. `goals.events.acknowledge` 与 `goals.note` 的记录标题是说明（正文）的前 80 个字，不以半个字结尾，不少于 80 个字；
3. 片段提案的 `clip`：上限 80、200、20 都按字数判断和截取；放不下时留 `max - 1` 个字加 `…`，放得下的原样；两单元的字算 1 个字；
4. 没有两单元字的文字（普通中文、英文）和现在一字不差；
5. 用例钉住上面四条：撤销任一处、改错截点或数，各自都红。

## 3. 不做

- 不改按字素截的问题：由几个码点拼成的一个「字」（带肤色的 emoji、ZWJ 序列、字母加组合符号）仍可能被截开，和 T-079 一样只按码点；
- 不改 `planSteps` 的 `part.length >= 4`（`fragment-offers.ts:28`）：那是下界，不是截取；不改 `request_id.slice(0, 36)`、`MAX_STEPS`；
- 不改 `module/event-system-payload.ts:243-246`：`parseGoalProgressSource` 对来源的 `artifact_id`、`title`、`item_id` 用 `.length > 1000` 判断，超过就丢掉整个来源（返回 `undefined`），按单元数，是「拒」的一端，不是截取；schema 里这几个字段的上限若是按字数，两边会差一倍。另一本的事，建议统筹加一行 MISC，本单不碰；
- 不改 `event-acknowledgement-body.ts:44`、`tree-presentation.ts:171-174`（第 1 节）；
