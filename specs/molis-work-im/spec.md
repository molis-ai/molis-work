# Molis Work 群聊与共享 Thread

用户已确认概念图并授权实现。完成目标是**功能可用**：真实成员在同一群中发消息、开公开 Thread、同屏回复，刷新和服务重启不丢失消息；不以静态演示替代多人行为。视觉依据为本目录的 `concept.png`。

## 视觉与交互返工（2026-09-26）

用户实际体验后否定首版 UI、动效、交互与视觉；之前的工程证据不构成视觉验收。保留服务端、协议、同屏布局和公开 Thread 语义，重做 `packages/im-ui/src` 表现层；不修改其他并行任务的宿主源码、共享构建产物或全局设计体系。

以已确认图的空间关系为依据，采用与工作台一致的中性浅色/石墨暗色表面，绿色只标识当前话题、来源和发送。压缩标题和导航，头像保留可区分的成员色，统一消息、上下文、输入框的排版。群目录使用紧凑列表；源消息与右侧上下文互相呼应。创建 Thread 在右侧直接命名，取消后回到群流。打开/收起与切换话题有短促过渡，减少动态偏好时关闭；不做装饰性页面入场。

新增体验约束：恢复每个群上次打开的话题；实时同步复用未变化的消息 DOM，保留焦点与滚动；输入框随内容自适应且各目标草稿隔离；源消息可回看。真实空群保持空，不自动填充演示消息。桌面与 390px 窄屏检验均使用实际服务，附加针对状态变化的回归。完成后独立只读复核，用户本人视觉认可单独记录。

## 范围与行为

- 群聊入口与灵光、Assistant 平级，保留既有工作台功能。
- 群聊与选中的 Thread 同屏。桌面左右并列；窄屏上下分区，群聊不被另一个页面替换。每个输入框明确发送对象，切换 Thread 保留独立草稿与群聊阅读位置。
- 首次使用设置显示名、创建群，或通过邀请加入群。成员身份由服务端会话确定，不能用请求中的作者 ID 冒充成员。群内所有成员可看全部 Thread；非成员不可读写。
- 从群消息创建带标题的 Thread，引用原消息及相邻上文；Thread 保留自己的讨论流，并能将选中的回复分享到群聊，保留回链。
- 消息存储、分页历史、重试去重、实时通知和断线重连。发送失败保留草稿；写入成功但刷新失败不能导致重复发送。空白群不伪造成员或消息。
- 群创建者可以获取和更换邀请链接。邀请链接作为加入凭证，不作为读取消息凭证。

本轮不实现私聊、音视频、文件上传、企业 SSO、AI 自动参与或公网部署。现有 Runtime Session 消息不改语义。

## 分包与数据

2026-09-26 并行分工更新：依照 `specs/bp-delivery-parallel/spec.md`，跨端团队任务统一负责 Server、成员身份、权限和断线同步。本任务已暂停独立身份/同步实现，`server/src/` 的未接线草稿交给该 owner 裁决；不再建立第二套身份或事件服务。本任务继续负责群聊/Thread 界面与客户端交互，通过下列 DTO/API 与统一服务接线。AI 能力如后续加入，一律使用 Prologue；当前聊天路径不需要模型调用。

- `server/`（`@molis-ai/molis-work-server`）：公共身份、会话、数据库连接、HTTP 与事件流由跨端团队维护；本任务拥有 `server/src/im/**` 的群、Thread、消息、引用、邀请与幂等收据。
- `apps/server/`：跨端团队的独立启动与业务适配，依赖 Server core；core 不反向依赖 local-host，避免循环。
- `packages/im-ui/`：纯界面、样式、浏览器客户端，不依赖服务端实现。
- `packages/contracts/src/services/im.ts`：共享的消息、成员、群、Thread 和 HTTP 读模型类型。
- `apps/local-host`：挂载服务并负责生命周期；`apps/workbench`：仅接入口和工作区容器。
- 群聊使用 `<homeDirectory>/server/server.sqlite`，与公共身份/事件使用同一事务数据库，不依赖某个 Project 或 Runtime Session。所有 SQL 外部值参数化，读写入口核验群成员；客户端输入只决定正文与目标，作者由会话解析。
- 独立服务默认 loopback；部署配置 host / public origin 后才接受对应来源。当前任务不对外暴露运行服务。会话凭证使用 HttpOnly cookie，服务端只存哈希。

选择独立聊天服务而非复用 Runtime 消息，是因为后者属于个人与 AI 的会话且禁止跨 actor 读取。采用同源客户端和 SSE，减少浏览器凭据传输与连接复杂度。

## 验收与验证

1. 两个独立浏览器身份加入同一个群，互相收到群消息和 Thread 回复；非成员访问拒绝。
2. 从群消息创建至少两个 Thread；切换时主群聊仍在，原消息与 Thread 上下文对应，回复不会串到其他 Thread。
3. 将 Thread 回复分享到群聊，返回链接打开正确 Thread；同一幂等请求重试不重复记录。
4. 重启服务仍能读取群、成员、上下文与消息；历史分页不会跨群/Thread 泄露。
5. 断线、发送失败和恢复时提示真实状态且草稿保留；键盘操作、中文输入法、桌面和窄屏可用。
6. 新增包的 build/typecheck、定向服务测试与 workspace 边界检查；真实启动后浏览器实操并留截图。现有无关失败单独记录，不借机修改。
