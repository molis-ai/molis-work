# 减少生成记录冲突与重复 CI

状态：执行中——实现与本地回归完成，待独立 PR 的 CI 实测（2026-11-06）。负责人：Codex。用户已明确批准页面资源改为自动实测比较、任务独立增量许可，并要求检查历史 PR、优化其他同类高频冲突文件。作为 PR #1897 之外的独立后续补丁；不改变该 PR 已验证的候选。目标为功能可用，CI 的采用与实测另记。

## 目标与证据

消除只为同步共享数字、生成快照或集中登记表而产生的人工冲突修复与重复提交。历史调查区分真实冲突、人工合并整理和普通高频编辑；以近期 PR 与 Git 合并重放为证据，不因某文件改得多就重构业务代码。

页面资源当前有两个耦合点：`tooling/gates/page-assets.json` 要逐字节等于构建，缩小也必须提交新数字；`scripts/gates/page-assets.mjs` 中的增长许可绑定绝对旧基数，main 改动后同一许可必须重新登记。已发现历史上的 +14 B、+315 B 重登提交，以及多项在途 PR 同改这两个文件。

## 范围与方案

保留真实 Host 下发资源的测量、漏发现路径的拒绝、默认不得增长、必要增长须审阅、单资源超过 10 KB 或新增资源须用户批准。替换人工维护绝对预算和门禁代码内的任务许可；不改产品资源、压缩方式、断言或安全边界，不跳过真正改变产品代码后的验证。

页面资源使用当前事件实际比较基点（PR 合并候选的第一父提交、合并组 base、push before，经现有 `ci-health-base.mjs` 解析）与候选的构建实测。缩小直接通过，下一次以已采用提交的真实大小为基点，不保留可被重新使用的额度。当前 CLI 的本地比较取与指定 ref 的 merge-base。

基线优先复用同一提交、同一测量实现与工具链的可信 CI 测量产物；只接受成功的默认分支或合并队列运行，不信任任意 PR 提交的基线文件。没有可用产物、过期、API 不可读或格式不符时，在临时检出中安装并构建基点，再用同一测量器实测。失败必须失败，不回退为空基线、不接触真实 Home。临时检出正常、失败与取消时均清理。冷基线的额外构建成本单列实测。

每个任务用单独的 JSON 记录获准的资源增量、理由和审阅出处；大于 10 KB 和新资源记录用户批准出处。门禁只使用比较基点尚未包含的新许可，已在基点的许可不再使用，避免重复消费；不允许修改已采用的许可来增加额度。多个任务合入同一组时，只累加这个组新增的许可，仍对整个组的实际净变化作比较。旧共享预算和旧许可在切换时退出；已经在 main 的增长已体现在基点构建中，不能再次折算成额度。在途 PR 按其剩余已批准增量转为独立记录，不扩大原授权。

[历史核查](audit.md) 已确认 198 个可核对 PR 中 67 个含真实文本冲突。其他治理对象：

- 健康快查 `baseline.json`：移到工作树自己的 Git 元数据目录，不再提交；没有本地快查时自动对照 `origin/main`，显式 `--base` 永远重新测量两棵树，不能因快查缺失放行。包清单报告独立从当前源码计算巨大单元，不读过期快查。
- 巨大单元例外：按源码文件分开登记，仍逐项检查 kind、理由和精确 size，重复 unit 拒绝；不改变批准条件。
- 安全不变量：独立记录避免共同表尾和连续编号争用，保留旧 ID、正文、实现与拒绝测试引用；新增使用可读语义 ID，聚合检查唯一性、测试存在、标题片段及 CI 覆盖。入口文档保留安全说明和查阅入口，不提交重复的生成总表。
- 待办：独立条目保留 ID、来源、状态、依赖、优先级与负责人；统一入口仍为未完成事项的唯一来源，完成删条目，不复制到各 spec。新增用语义 ID 避免争抢数字，原 ID 不重编。
- 设计索引：把每项描述与已选状态放回相应设计目录，父目录只保留稳定阅读入口，不维护重复状态表。保留所有决策和来源链接。
- API/动作快照与生成名单：保留现有从合并后源码重生成的做法，明确只跑影响到的验证；同一合同、业务实现及金样期望的实质分歧必须人工处理，不把候选产出自动写成正确答案。

不得用自动选一边、union 合并或忽略断言掩盖语义冲突。独立记录以实际两分支并行修改、Git 合并和门禁验收证明效果。

## 边界、依赖与切换

实现归现有门禁与 CI；页面资源测量仍只有一份。允许修改页面资源门禁、必要的小型测量/基线/许可辅助模块、工作流页面资源步骤、对应测试、开发手册及适用规则说明。其他允许路径为上述登记文件及其消费者、回归测试和引用它们的现行开发说明。主检出与真实 Home 不动；独立工作树 `page-asset-delta`、分支 `feature/ci-conflict-reduction`，基于 main `223a1a50be`。

先完成历史调查和规则回归，再接自动基线与产物复用，随后切换 CI、移除旧记录并同步文档。新门禁一次切换，不长期维护两套判定。回滚还原本补丁，回到原门禁及其当时实测预算；不涉及业务库或产品数据迁移。

开工前已核对在途 PR：#1887、#1879、#1876、#1872、#1867、#1853、#1846 涉及页面资源记录；#1897 改 CI。只在本分支修改，不替这些 PR 改源码；交付切换说明和新许可写法。CI/门禁规则变更已由本轮用户明确批准。没有 UI、插件 API、事实表或模型调用变化。

## 验收

1. **CCR-01** [人工] 历史调查包含样本时间和范围、PR 对应证据、真正冲突与改动频率的分别统计；每个治理对象有原因和处理结果，未改对象说明具体理由。
2. **CCR-02** 资源缩小无需修改共享数字文件即可通过；下一提交从缩小后的实测值比较，重新增长一字节仍被拒绝。
3. **CCR-03** 同一任务的增量许可在 main 发生独立变化后仍适用；不同任务独立文件不冲突，已采用许可不重用，超额、无许可、新资源及大额缺用户批准均被拒绝。
4. **CCR-04** PR、合并组与 push 比较正确基点；合并组累计新增许可且按最终实测判定，不把已在基点的任务再算一次。
5. **CCR-05** 可信基线产物精确绑定提交、测量与构建条件；错误提交、PR 来源、失败运行和损坏产物不作为基线。缺失时真实构建回退，回退失败不放行。
6. **CCR-06** 实际 Host 测量与路径发现的拒绝仍有效；删除记录或改写路由不使仍下发的资源漏测，基点和候选使用一致测量口径。
7. **CCR-07** 临时检出、基线构建与测量在成功、失败和取消时均清理；本地通过公共机器槽，不碰真实 Home；无新服务或常驻进程。
8. **CCR-08** 其他获证实的高频生成记录冲突逐项消除或降低，回归能覆盖并行修改合并后的正确结果；没有以静默择边代替重新生成。
9. **CCR-09** [人工] 定向回归、整体构建、健康/包边界门禁及工作流检查通过；冷/热基线耗时、最终候选、云端采用与未验证项分别记录。
