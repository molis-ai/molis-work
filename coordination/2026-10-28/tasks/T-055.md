# T-055 Home 里已装的签名包再装一次，回 plugin.state_invalid，不再是原生 Error

> **这条在 main 上成立，修的是一处拒绝的回法，不放宽也不新增任何拒绝。** Home 范围的签名包已经装着时，再确认一次（任何版本），`PluginInstallService.confirm`（`apps/local-host/src/plugin-install-service.ts:140`）调 `installInHome`，一路到 `HomePluginHost.installPackage`（`apps/local-host/src/home-installed-plugins.ts:174-177`）。它在 `assertHomePackageAllowed` 之后无条件 `lifecycle('install', …)`，生命周期见到记录就抛原生 `Error('这个插件已经安装，可以直接打开或升级')`（`apps/local-host/src/installed-plugin-lifecycle.ts:146`）。这个 Error 没有码：出口的码是 `actions.execution_failed`，文案保留它自己的那句（`packages/plugin-sdk/src/errors.ts:78` 先取 `error.message`，`:81` 才给码），也就是错误地建议「升级」：Home 的签名包不能升级。这是读源码得出的；HTTP 出口和真实界面没有测过，先红时贴实际捕获的类型、码和文案。起草时只读了代码，没有在真实路径上复现；第 5 节第 3 步的先红就是复现。
>
> **和别的任务没有依赖。** 不碰 `installed-plugin-lifecycle.ts`（#1367 在改）、`installed-plugin-host.ts`（#1369、T-035 在改）、`plugin-install-service.ts`（第 3 节说明为什么留着）。

## 1. 背景

依据都在 main `4d0f52c91`：

- 设计上 Home 的签名包不就地升级：slice 写「Home 包同样：先卸载（可保留数据），再装新包。不在本片放宽（BL-711）」（`bl628-sandboxed-home-plugins.md:80`，`:105` 同），BL-711 在 `specs/BACKLOG.md:285`，未分配。项目一侧已经能升级（BL-623）：同样的情形项目走 `lifecycle(recordFor(release.pluginId) ? 'upgrade' : 'install', …)`（`installed-plugin-host.ts:209`）。Home 一侧只有 `lifecycle('install', …)`（`home-installed-plugins.ts:176`），所以已装就落到原生 Error。
- 这条路怎么走到：

| 步 | 在哪 | 做什么 |
| --- | --- | --- |
| 1 | `plugin-install-service.ts:129` | `present` 只读项目里的安装（`ports.installed(held.project_id)`），Home 范围的包不查 |
| 2 | `plugin-install-service.ts:138`、`:140` | 先把新包落盘（`packages.save`），再 `installInHome(release)` |
| 3 | `project-plugin-ports.ts:74-77` | `installPackageInHome` → `home.installPackage(release)` |
| 4 | `home-installed-plugins.ts:174-177` | `assertHomePackageAllowed`，然后 `lifecycle('install', …)`，不看有没有记录 |
| 5 | `installed-plugin-lifecycle.ts:145-146` | `action === 'install'` 且 `recordFor` 找到记录：`throw new Error('这个插件已经安装，可以直接打开或升级')` |

- `recordFor`（`home-installed-plugins.ts:68`）已经排除 `uninstalled`，所以「卸载后重装」不会碰到这一行：`tests/home-installed-plugins.test.ts:135-138` 断言保留数据的重装沿用同一个 `install_id`。
- 没有测试量到这条拒绝：`git grep -n "直接打开或升级" -- tests` 没有命中；`tests/home-installed-plugins.test.ts:99-147` 只测卸载之后再装。项目一侧同类的有一例，是照着写的样子：`tests/installed-plugin-host.test.ts:807`（T2-FIX-05 BL623-02：回滚回 `plugin.state_invalid`、升级到已装版本回 `plugin.upgrade_required`，安装、批准记录、固定、包都不变）。
- 怎么让它红：`tests/home-installed-plugins.test.ts` 里用 `fixture(t)`（`tests/fixtures/home-sandbox.ts:42`）装 `homePackage(publisher)`，再 `h.install(homePackage(publisher, { version: "1.1.0" }))`（`:21`、`:51`），断言 `refused("plugin.state_invalid")`（`:39`）。main 上抛出的不是这个码，断言红。出口给的是 `actions.execution_failed` 还是别的：未核（本机不跑），先红的断言不依赖它。

## 2. 目标

1. Home 里已有（未卸载）的签名包，再确认一次安装，不管版本更高还是同一份，都以 `plugin.state_invalid` 拒绝，文案说明「Home 里的签名包不就地升级：先卸载（可保留数据），再装新包」（`RAC-1505`、`RAC-1506`）。
2. 拒绝之后安装原样：同一个 `install_id`、版本、`running`、批准记录、固定的发布者、已写入的数据和动作都不变（`RAC-1507`）。

- 不改 `installed-plugin-lifecycle.ts:146`：#1367 在改这份文件；项目一侧走不到那一行（`installed-plugin-host.ts:209` 先选了 `upgrade`）；守卫放在 Home 自己的入口就够。
- 不改 `plugin-install-service.ts`。那里有另一处洞，读代码看到、没有复现：`confirm` 的 `present` 只查项目（`:129-130`），Home 范围的「另一个发布者的同 ID 包」会先被固定发布者（`:135` `pinPublisher`）、先落盘（`:138` `save`），然后才被 `installInHome` 拒绝。S-84 要求「在写任何记录之前先检查」（`docs/system/SECURITY-INVARIANTS.md:99`），这条顺序归 T-054（`tasks/T-054.md`），不并进本单。
- 不处理拒绝之后 `save` 留在磁盘上的新版本包目录（`plugin-install-service.ts:138`）：项目一侧的拒绝同样会留，本单没量过它留了什么。去向：不做。
- 不新增错误码、不改现有错误码或文案。不比较版本：Home 没有升级路径，比较版本等于假装有。
- 不改 `tests/security-invariants-*.test.ts`、`docs/system/SECURITY-INVARIANTS.md`、`apps/local-host/README.md`、`docs/system/CALL-CHAINS.md`。
- 不写兼容、迁移或回退读取；不加 `legacy`、`compat`、`@deprecated`、`backfill`。

## 5. 做法

统筹已定的决定，照做，不另选（【方案】里不用再问这几条）：

1. **守卫放在 `HomePluginHost.installPackage`。** 不放进 `installedLifecycle`（项目也走它，项目要升级，#1367 在改），不放进 `PluginInstallService.confirm`（那是 S-84 的顺序，归 T-054）。
2. **判断用 `recordFor(release.pluginId)`。** 它已经排除 `uninstalled`，卸载后保留数据的重装不受影响。不要换成直接查 `platform.runtime.list()`。
3. **守卫在 `assertHomePackageAllowed` 之后。** 范围不对的包仍先得到原来的 `plugin.home_scope_unavailable` 等码（`tests/security-invariants-sandbox-home-instance.test.ts:30-52` 的五种拒绝不变）。
4. **码用 `plugin.state_invalid`**，与 slice 写的 T2-FIX-05 同码，项目一侧回滚也是它（`installed-plugin-lifecycle.ts:153`）。文案一句：`这个插件已经装在 Home 里。Home 里的签名包不就地升级：先卸载（可保留数据），再装新包`。不写「可以直接打开或升级」。版本更高、相同，同一个码同一句。
5. **守卫在 `lifecycle` 之前，不碰 Runtime、批准记录、提示词登记。** 拒绝不留任何东西。
6. **测试造法：**
   - `const h = await fixture(t), publisher = newPublisher(), first = homePackage(publisher);` 先 `await h.install(first)`，再用 `operationsOf(h.homeClient(), h.homeCaller())` 和 `operate(…, "notes.add", { text: "kept" })` 写一条数据（写法照 `tests/home-installed-plugins.test.ts:36-43`）。
   - 拍快照：`h.host.homePlugins!.installation(PACKAGE_PLUGIN_ID)` 的 `install_id`、`version`、`state`；`valuesOf(h.home, "agent-studio:~home").filter(key => key.startsWith(APPROVED))`（写法照 `:112` 的 `approvalKeys`）；`h.ledger.publishers().length`。
   - 两次尝试：`h.install(homePackage(publisher, { version: "1.1.0" }))`（`RAC-1505`）；`h.install(first)`，用同一个 bundle 对象，`SandboxPackageStore.save` 对相同内容不改任何东西（`sandbox-package-store.ts:41-45`）（`RAC-1506`）。每次确认的结果先当成值收下（`.catch(error => error)`，成功也收下），每次之后都先采集护栏要看的状态（安装三字段、批准键、发布者个数、`hasPackage`、`notes.list` 和动作结果），最后再逐个断言码是 `plugin.state_invalid`、文案含「先卸载」。不要连着写两次 `assert.rejects`：main 上和 M1 时，第一处码断言一红就截断后面的场景和护栏，报不出「1505、1506 红，1507 绿」（Codex 预审 6476248846 第 1 条）。
   - 拒绝之后重读快照，逐项相等；`h.host.homePlugins!.hasPackage(PACKAGE_PLUGIN_ID)` 仍为 `true`；`notes.list` 仍是 `[{ id: "1", text: "kept" }]`（`RAC-1507`）。
7. 代码里不要出现 `legacy`、`compat`、`backfill`，不加空 `catch`、`as unknown as`、`any`、`console`（按文件计数只许减少）。

步骤：

1. `git fetch origin main`，重核第 1 节的行号（`git grep -n "installPackage" -- apps/local-host/src/home-installed-plugins.ts`），再看一眼没有在途 PR 改 `home-installed-plugins.ts`。

5. 弄红四次，每次改前先 `cp` 一份，弄红后 `cp` 还原（不用 `git checkout`，会丢本单的改动），PR 里贴出各自红在哪一句：
   - **M1** 删掉守卫：`RAC-1505`、`RAC-1506` 红（码不是 `plugin.state_invalid`），`RAC-1507` 仍绿。
   - **M2** 守卫改成 `platform.runtime.list().some(item => item.plugin_id === release.pluginId)`（把已卸载的也算上）：已有的 `RAC-970 RAC-971`（`tests/home-installed-plugins.test.ts:99`）红在保留数据卸载之后的 `await install()`（`:137`）。这是最像真的错修法：新用例都绿，卸载后重装却被挡住。

6. PR 正文写：对调用方的影响（Home 里已装的签名包再装，以前得到没有声明码的原生 Error（`actions.execution_failed`，文案错误地建议升级），现在得到 `plugin.state_invalid` 和「先卸载，再装新包」；项目一侧不变；Home 仍然不能升级）；没有改任何其他码或文案；没有放宽任何拒绝；`plugin-install-service.ts:129-138` 的顺序问题没有动，归 T-054；没有用真实界面点过，不要写成测过。
