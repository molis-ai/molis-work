# GoalDetail：整体进展、时间线与工作规划

## Overview

2026-09-09 第三版，模式为 Operate / Read。本文只描述本目录 `prototype/` 的实际设计，完成等级为 **2：可交互原型**，不作为 Molis Work 全项目设计规范。

**Creative North Star: "整体进展与双栏时间线"**

延续中性桌面工具气质：白灰画布、系统中文字体、克制蓝色和连续可扫描的时间索引。顶部回答现在的结果、下一步和风险，左侧定位发生过什么，右侧完整阅读或录入。工作规划进入同一阅读面。界面语言直接具体，目标标题和用户原话保持原样。

所有操作只保存示例 Goal 的浏览器会话数据；Runtime 自由规划使用明确标注的预写示例。生产 MCP、数据库和 Host 均未接通。行为合同见 [spec.md](spec.md)，体验验证见 [validation.md](validation.md)。

## Colors

- **Primary — blue / blue-soft**：链接、工作规划入口、主操作与次级操作底色；时间线选中行使用同色系浅底。
- **状态 — green / amber**：绿色用于结果节点和已有支持的要求；琥珀色用于缺口、未达到、阻塞与待关注事项。颜色配合文字或图标，“报告满足”同时保留报告者和“未独立核对”。
- **Neutral — canvas / paper / line**：灰色画布、白色阅读面与细分隔线；整体进展和时间线使用浅灰蓝层次。
- **ink / secondary / muted**：标题正文、解释内容、时间与来源的三级阅读层级。focus 用于可见键盘焦点。

## Typography

系统字体栈为 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`，无外部字体。

时间线标题最多两行，完整标题留在右侧；作者、时间、来源与使用范围低于业务结论。

## Layout

工作区最大宽度（1600px）。紧凑的目标标题和结果说明之后是一行“工作规划”入口。整体进展位于双栏上方，包含总体判断及“已经做成 / 接下来做什么与责任 / 风险与待决定”三个分组。

桌面时间索引默认宽（302px），视口不超过（1100px）时为（278px），达到（1400px）时为（326px）；右侧占剩余宽度。两区独立滚动，顶部整体进展保持可见。时间行最小高度通常为（54px），低高度桌面为（49px），手机为（56px）；长标题可自然增高。列表只放时间、短标题、类型和作者。

事件、材料、说明、规划、类型编辑和事件填写共用右侧空间。工具栏与阅读标题留在内容上方，正文和长表单在内部滚动。规划区采用纵向段落和细分隔线，顶部提供“新增事件类型”和“查看可记录的事件”直达入口。

视口不超过（680px）时改为“时间线 → 事件”的单栏往返阅读，返回后保留原选中项。顶部保留整体判断、下一步和责任人；完整进展分组按需展开为单列，最高（24dvh）并可滚动。规划入口隐藏辅助来源短句，完整信息仍在详情读取。

字段编辑器中，字段名独占一行，内容形式、必填开关和移除操作在下一行。手机提交按钮占满可用宽度；规划和表单使用同一阅读区，不使用模态覆盖层。

## Elevation & Depth

主页面通过白灰底色、细线与留白分区，不使用容器阴影。浅色底强调整体进展、选中状态、决定、演示提示或报告结论。临时保存提示是唯一使用轻阴影的浮层（`0 5px 22px #1c294025`）。

## Shapes

轻圆角与紧凑控件：双栏外框和决定区域（9px），整体进展与附件（8px），按钮和选中时间行（6px），规划输入（5px）。类型列表和字段阅读器使用直线分隔；时间轴使用细线与小圆点。内联 SVG 图标，无外部图片资产。

## Components

### 整体进展与当前要求

顶部概况、完成要求、目标说明、当前成果和交接内容读取同一组有效要求及报告来源。读历史不会使顶部退回旧判断。要求行显示具体结果、当前支持与来源，可定位对应事件；尚无记录时可进入相应类型的填写表单。

普通记录只补充涉及的事实，不会抹去独立的待决定事项、测试环境阻塞或会话断线。已有完成结论不会被无关记录撤销；新增未满足要求、相关反证或未知结论才带来当前差距。准备交接只表示内容已备好，不表示真实会话已连接。

### 时间线与阅读器

最新在前、按日期分组；点击、键盘上下键及右侧上一条/下一条切换事件。无匹配筛选同时清空左右内容。保存补充或有类型事件后进入最新位置并选中。

材料、来源、说明和规划提供“返回所选事件”；类型详情与填写页另有“返回工作规划 / 返回类型说明”。历史事件保留当时的字段定义、内容和附件结论；当前成果与交接从当前入口读取，不把旧材料中的缺口继续当成当前任务。

### 工作规划与事件类型

规划页展示采用来源与版本、当前完成要求、可记录类型及折叠的方法说明。类型行包含名称、用途、来源、作者和“完成前需要 / 涉及界面时使用 / 按需记录”等提示。登记类型与新增完成要求是分开的操作，类型目录不是固定阶段。

自由规划场景明确“未采用模板”。“演示 Runtime 设计并登记”载入故事交付、规则实验、玩家观察三个预写类型；前两类支持具体结果要求，玩家观察按需记录。模拟说明在操作前和配置事件中均可见。

### 类型编辑与事件填写

类型编辑包含名称、用途、通用分类、可增减的简短或详细文字字段；每个字段独立标记必填，至少保留一个字段。勾选“完成前需要”才展开具体结果要求。新增配置只作用于当前示例 Goal，并作为配置事件进入时间线。

事件表单由登记字段生成，包含一句话标题与必填/可选提示。可选择一项同类型完成要求，再选择支持、仍无法判断或尚未达到；默认只记录，不作完成判断。详情逐项展示实际字段，可选空值显示未填写。报告保留记录者与核对边界，支持不等于独立验收或目标自动完成。

必填缺失、仅空格、重复类型名或同类型内重复字段名使用浏览器字段校验指出具体输入，失败不生成事件。输入为白底细边框；禁用的结论选择使用灰底。

### 操作与保存反馈

主要保存操作为蓝底白字，次级操作使用浅蓝底或白底细边框，返回和定位使用文字按钮。键盘焦点为外扩描边（2px）；保存提示使用 `role="status"`。减少动态效果偏好会关闭动画、过渡和平滑滚动。

类型、要求、配置事件、工作报告和选择保存到 `sessionStorage`，刷新后保留。切换场景或显式重置会重置演示状态。原型没有现有类型版本编辑、规划库写入、正式授权或收尾状态变更控件。

## Do's and Don'ts

- **Do** 延续“上方看现在、左侧选时间、右侧读内容”的本原型结构，让新能力进入已有阅读空间。
- **Do** 同时展示具体要求、结论与来源；支持、未知、反证应形成可辨认的当前说明。
- **Do** 保留无模板起点、可选字段、按需记录与明确返回路径。
- **Don't** 在左侧时间索引铺开正文、附件或复杂表单，降低扫描密度。
- **Don't** 用记录数、绿色图标或登记类型本身暗示完成，让普通记录消除决定、阻塞或断线。
- **Don't** 改写历史材料来迎合当前结论，或把预写 Runtime 示例和浏览器保存解释为生产能力。
