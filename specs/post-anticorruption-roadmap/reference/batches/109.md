## 给人讲清楚

这一批完成最后一批插件的统一分区改造，把 Git 能力彻底收回 Git 插件，并将全系统所有插件（含主库插件、无库插件和第三方沙箱插件）合并进唯一一套按需启停装配、把历史双轨代码一次删光：

1. **最后 7 个业务插件数据收干净（`109-1`）**：目标（Goals）、写代码（Coding）、信息流（Feed）、收件箱（Inbox）、风险（Risk）、定时任务（Schedule）、每日简报（Work Brief）全部删掉业务表里多余的 `project_id` 列；信息流的原文引用迁入平台证据账本 `horizontal/evidence`；每日简报迁入分区独立库 `databases.partition` 并把跨分区简报摘要接入第 `108` 批上线的个人空间总览，从此全仓再无“全局一半 + 项目一半”的双实例插件，同时补齐备份检查表里 `evidence.db` 与 `personal-space/molis-work.db` 的金样覆盖。
2. **Git 底层代码整体搬回 Git 插件（`109-2`，D6=B）**：宿主里约 1,400 行 `workspace-git*.ts`、`projects.workspace.writers.*` 与 SDK `git-porcelain.ts` 整体搬进 `plugins/native/git`；AI 底座里的 `prologue-git.ts` 硬编码审批一并改成插件通用审查申报（保留 `#2244` 按 `install_id` 隔离），顺手清零 `44C` 留给本批的 Git 点名；启用 Coding 时默认随启用 Git（V9），允许单独移除 Git 并在确认框说明影响（V10）；在非 Git 普通文件夹（如个人空间默认输出目录）下，Git 平静提示非仓库、Coding 与 Diff 按普通文件夹平顺工作不报错。
3. **第三方沙箱开放独立库 + 全部插件合流唯一装配 + 旧双轨大扫除（`109-3`）**：向第三方签名沙箱包开放 `databases.partition`；将第 `106` 批的新每分区装配升级为**通吃全部 20 个内置插件（独立库、分区主库、无库）与已装沙箱包**，全部统一读 Home 单张安装表并按需启停，随后删除项目数据库里的旧安装表、`HomePluginHost`/`HomeInstalledPlugins`、`dual_instance`、`runtime.scope:"home"`、`project_rows`、`artifact_join` 与 `projects:reach`，焊死 **G2 / G3** 防回流门禁。

需要你做的：无新增未决决策。按 2026-11-25 确认的粒度，允许本批按上述三块先后拆成 **3 个独立 PR（`109-1` → `109-2` → `109-3`）** 串行合入，每步保持 `main` 全绿、问题边界清晰。

## 用户拍板与实施记录

### 109-1（PR1）

- **主库六插件删 `project_id`（U13/V7 Clean v1，不迁移）。** Goals、Coding、Feed、Inbox、Risk、Schedule 的业务表去掉 `project_id` 列和 `WHERE project_id = ?`；Goals 的 `boards` 改为单例主键 `board_id = 1`。同步键改用 `{ scope: "projectId" }`，线上格式不变（键与记录仍写分区，同 108 的 Images）。库结构按 Clean v1 同版登记 `same-version-exceptions.json`，不升版本。
- **同步声明校验随之放宽一处（共享核心）。** 表上没有 `project_id` 时，`existsAny` 允许空 `match`（指那张表的任意一行），分区声明允许不带 `projectColumn`；表上还有 `project_id` 时仍按原规则拒绝。SDK `sync-schema.ts`、`plugin-sync.ts`（审批结果声明不再要求 `project_id` 列）与 `plugin-runtime` 的两个校验器同改，`tests/plugin-sync-service.test.ts` 正反两向断言。审批结果读取（`horizontal/project-approvals/src/outcomes.ts`）在表无 `project_id` 时取 `project_root` 的分区。
- **Feed 证据持有迁入平台。** Feed 经 `services.evidence`（`evidence:collect`）登记、收回、释放正文；`feed.content.hold/release/reclaim` 三个 Home 动作、Feed 的 Home 半与 `feed-content` 顶层库删除。后台作业 `feed-reconcile` 的权限由 `actions:invoke` 改为 `evidence:collect`，按本分区库留着的正文重新登记，所以旧账本的行不迁移。旧 Home 的 `feed-content/` 在升级时删除（`home-upgrade.ts` 的 `RETIRED_HOME_LIBRARIES`，与 108 删旧 Home 顶层库同一保留机制，登记在 CONTRACT-CHANGES「当前保留机制」）。`companions` 改为 Manifest `dependencies[].enable_with`。
- **Work Brief 迁 `databases.partition`。** 简报库在 `<分区>/libraries/work-brief.db`，不带项目列；`personal.get/refresh` 与 `projects:reach` 删除，每个分区的首页简报在同一提交里写一行总览（`overview.read@1`，WBR-24），`work-brief` 顶层库删除（随 108 的 `removedHomeStores()` 一并清掉）。WBR-07 回归在分区入口重跑（`tests/work-brief-plugin.test.ts`、`tests/work-brief-page.e2e.test.ts`）。
- **金样就地改写（44B「金样不重生」）。** `0.1.0`、`0.1.0-dev.1`、`0.1.1-dev.8` 三份金样与 Goal 历史夹具按现行代码造的参照主库改写：六插件的表重建、同步触发器与声明账本 `tables_json` 同步，`feed-content`、`work-brief` 两个顶层库的导出删除，每个 Home 加平台证据账本 `evidence/evidence.db`；摘要重算。新增金样写入 `personal-space.ts`（个人空间主库与 `libraries/todo.db`）与 `work-brief.ts`（分区简报库），`golden-coverage.json` 相应移出 `uncovered`。
- **`evidence.db` 的金样写入仍是 `none`（偏离，用户 2026-11-27 确认）。** 账本只在 Feed 真的拉到正文时写，拉取要联网，金样不联网，所以金样里只有结构；持有、收回与释放由 `tests/dual-instance-services.test.ts`（S-98）与 `tests/feed-evidence-holds.test.ts` 覆盖。账本按需建库，新造的金样里没有这个库，三份旧金样里的空库是就地补的。
- **定向测试顺带查出并修好的产品问题。** ① Feed 来源历史读取（`historyReads.refs/operations`）删参数后调用方仍按旧参数位传，收回与释放正文时读不到任何一页，TypeScript 因函数参数少者可赋给多者而没有报；② Goals 输入绑定的 `sourceLocator` 仍读已删的 `row.project_id`，改为读本库 `project_root`；③ Listener 投递表的插入语句仍带 `project_id` 列。
- **Feed 改为分区插件后的两处随带变化。** ① 它不再是 Home 插件，平台给它 `services.overview`，于是每次写入都会刷新第 108 批的排期摘要；原实现逐个来源读检查点与条目数（每个来源约 10 次授权核对），改为一条语句读来源本身。② 新建演示项目时 Feed 的示例与其他项目插件一样在建库时写入（原先 Home 范围插件跳过这一步，首次打开时才写）；只认空 Feed 的测试改为只看自己的行。
- **后台命令之后刷新项目插件的视图。** 宿主原先只在 Home 插件完成命令后让它的页面重读；Feed 移出 Home 后，定时拉取改了来源但页面不再刷新。现在命令所在项目已打开时，同时刷新该项目平台（含按分区实例）上这个安装的视图，不打开也不启动任何东西。
- **Home 插件机制的测试改用登记探针。** 109-1 后不再有内置插件带 Home 半或 Home 库，`HomePluginHost`、`project_rows` 等机制要到 109-3 才删除；在那之前，相关测试把探针临时加入内置登记表（`shippedParts` 本就允许测试这样扩充），按内置插件的方式登记它的 Home 库，产品代码不为测试开口子。
- **Work Brief 页去掉「各处」模式（偏离，用户 2026-11-27 确认）。** 原计划让简报页在「各处」里读 `overview.read@1`，但[总览读取权限](../../../unified-partition-plugins/spec.md#overview-readers)只认本人与获授权的个人助理，插件页的调用一律拒绝。改为与第 108 批 Todo「所有项目」相同的处理：简报页只显示本分区的简报，每个分区的简报照样写总览行（`tests/work-brief-plugin.test.ts` WBR-24），跨分区列表由个人空间总览页面画（`64-3`）。`mode.*`、`personal.*` 三语词条删除，帮助说明改为「个人空间和每个项目各有一份简报」。
- **Feed 的 Functions 开关改在项目安装上。** Feed 不再有 Home 半，`functions:manage` 由项目里那份安装的授权决定；改授权会让已打开的插件页面失效（原先改的是 Home 半，项目页面不受影响），所以测试在每次切换后重新打开 Feed 页。关掉后 `functions.authoring.*` 仍从页面的动作目录隐去（`actions.dependency_missing`），拒绝、记录不变、判断服务不被调用的断言不变（`tests/feed-capture.e2e.test.ts` RAC-2910）。
- **Goals 同步按单行看板校验、分区上下文提前填。** 看板只剩库里的一行（`id` 1），收方校验原来还比 `boards.project_id`，每份 Goal 内容都被拒（`personal-goals-sync*` 全红），改为校验这一行；去掉 `project_id` 的表以库的唯一项目记同步键，库里还空着的同步上下文在打开插件表时即填（`openPluginTables`），插件启动前写入的行（示例数据、夹具）不再记成空键（S-115）。已绑到别的项目的上下文仍由插件启动与升级去核对，不在这里报错。
- **前个人插件一次性补写改按登记标记取（用户 2026-11-27 定）。** 原先按 `databases.partition` 取，Work Brief 迁入分区独立库后会被补进旧 Home 的每个分区，而它此前是项目插件；改为登记上的 `formerly_personal`（十一个插件各标一次，随这条保留机制在第 111 批或首个发行版一起删），平台源码不写插件名，CONTRACT-CHANGES「当前保留机制」同步。
- **随宿主内置 Home 插件的用例暂跳过（用户 2026-11-27 定）。** SCS-16「a built-in Home enable waits on the installation line」要一个构建自带、宿主信任的 Home 插件，109-1 后构建里没有了，夹具又从不拿宿主信任（S-75），只能在 109-3 随 Home 运行时一并删除或改证分区装配；RAC-1745（构建内的双实例插件按提供视图的一半绘制）删去，同一规则由构建外的 RAC-1740/1741 证明；S-72 的 Home 调用一侧只剩拒绝。
