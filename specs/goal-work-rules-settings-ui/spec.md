# Goal 工作规则设置式阅读

## 背景目标

「目标与要求 → 工作规则」现在是生效规则卡片、继承箭头、再套一层手风琴表单。对照 Cursor / Codex 桌面设置：分组、一行一项、左说明右控件。

## 当前行为与问题证据

打开工作规则后先看到「当前最终生效规则」三列卡和 01→02→结果流程图，Goal 额外规则收在 `details` 里，带 GOAL OVERRIDE 编号。字段和保存语义没问题，版式不像设置页。

## 范围

- 只改 Goal 详情里工作规则 tab 的 `renderPolicyEditor` 版式。
- 项目设置里的项目工作规则页面保持现有表单。
- 字段、锁定规则、保存接口、修改原因不变。

## 非目标

- 不改 Policy 数据、合并算法或 HTTP。
- 不重做项目设置整页。
- 不把工作规则并进其他 tab。

## 方案与关键决策

- 去掉手风琴、编号徽章和继承流程图。
- 顶部一行说明；项目默认入口做成设置行（左说明、右「打开」）。
- 「当前生效」做成只读设置行（合并后的权威值）。
- 可写时，「当前 Goal」是同一套设置行：左标题/说明，右下拉、开关或数字，对照 Cursor / Codex 桌面设置。
- 高级字段（能力、领取时长、检查人数）直接作为第二组，不折叠。
- 变更原因和保存放在最后一组。

## 验收标准

- 工作规则 tab 能看到当前生效值和 Goal 表单字段，不再出现 GOAL OVERRIDE / 01·02 流程图。
- 项目底线锁定的选项仍 disabled。
- 无写权时仍只读、无表单。
- 项目工作规则设置页仍用原表单保存。

- `tsx --test tests/goals-policy-ui.test.ts tests/goals-status-ui.test.ts`
- 浏览器：目标与要求 → 工作规则，核对设置行和保存区。
