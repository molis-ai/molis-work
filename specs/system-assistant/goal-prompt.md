# 系统级个人工作助理 Goal Prompt

让应用拥有一个达到“内部完整”程度的系统级个人工作助理，以 main 底部常驻的 Assistant 为统一主入口。用户可以在任何工作界面发起、继续和管理工作；助理理解用户正在看的内容、此前的相关操作、当前诉求和已有约定，使用已授权的能力与角色，把事情推进到可使用、可检查、可继续修改的结果，并在合适的时候主动协助。

最终应达到以下状态：

1. **它是贯穿全局的个人助理。** 能协调不同插件、项目和任务，也能在没有项目或代码目录时处理一般个人工作。统一的助理身份与多项独立工作并存；每项工作的资料、目标、授权、会话和成果归属清楚，用户不会因为切换页面而让原任务改变目标或写错对象。

2. **它真正理解用户当下要做什么。** 理解当前页面与面板、对象和版本、选区、未保存内容，以及选择、拖入、引用、修改、撤销等输入前操作。显式输入与明确引用优先于猜测；能正确处理“这个”“再短一点”等连续表达，吸收用户对结果的修改，区分讨论、规划、执行、纠正和停止。用户回答问题或表单后能够接续原事项，拒绝不会变成批准，过期回答不会重新启动旧动作；用户在插件内手动完成或撤销工作后，助理也能更新理解，停止不再需要的操作和提醒。只询问确实影响结果或授权的问题，已有授权范围内持续推进，不反复要求用户重述背景或确认开始。

3. **输入和交互足够完整。** 用户既可直接用自然语言，也可引用对象、发现快捷操作、添加文件和图片、选择 Character 与 Skill、回答结构化问题、查看和调整本轮材料。尚未输入时，也能在合适的场景获得与当前内容有关的起步建议；用户可以忽略，浏览和选中本身不启动执行。输入框前的选择让本次发送的范围、角色和材料清楚可见，不重定向正在执行的工作。当前页面、当前任务和执行角色容易辨认；搜索、选择和执行的含义清楚。长任务有完整工作视图，可查看进展、切换任务、保留草稿、补充要求、暂停、恢复、停止并打开成果。未发送内容不会被擅自当成指令。

4. **专业插件与 Assistant 连贯协作。** 选择 Coding Agent 后，可以直接从底部发起和完成真实 Coding 工作，并使用相应专业工作区。插件可由统一入口承接对话，也可保留与 Assistant 同步的同一会话，或在确有独立边界时明确转交。不同入口不会产生重复运行、矛盾状态、错误答复或草稿覆盖；专业界面和已有成果保持可用。

5. **插件对 AI 友好，并且能够持续扩展。** 插件可以提供可理解的上下文、行为、业务能力、真实结果、领域 Prompt、Character、Skill、预装与推荐配置，以及适合工作的交互内容。助理能区分背景更新、业务变化、待用户发起的建议、用户已明确发起的委托和返回成果；插件传来信息不一律变成执行指令。用户从插件发起工作后，无需重新搬运资料或复述诉求。新插件可以按统一约定参与助理工作，无需逐个增加专属逻辑。贡献有明确来源、适用范围、版本和生命周期；安装或更新不等于自动启用全部内容，也不扩大既有授权。开发者能了解接入要求并诊断问题。

6. **能够充分使用统一能力与 Prologue。** 系统、插件、MCP 等已授权能力可被正确发现、理解和使用；用户配置的 Character 可以直接承担工作，也可以被助理按需委托。显式选中的角色真实负责本次工作，不只改变回复语气；实际执行者、委托关系和不可用状态清楚可见，个人助理的全局管理与交互规则仍然有效。插件提供的方法只在适用范围内生效。统一以 Prologue 支持完整 AI 工作，全面覆盖实际版本的相关功能，包括会话与持续目标、规划、TaskBoard、subagent、协同、评审与修复、后台跟进与交付、记忆、上下文、角色与技能、工具和资源、多模态、专业工作环境、权限、成果、观测和预算等，不限于这些示例。每项相关能力都具有实际用途、准确的可用状态和可验证的用户结果；按任务需要使用，避免为了展示能力而增加复杂度。

7. **复杂工作能够持续推进到真实完成。** 需要时具有清楚的计划、依赖、分工和验收条件，支持专业委托、适当并行、结果检查与修正。用户能够知道谁在做什么、为什么等待、结果在哪里，并能介入。多项任务的优先关系和资源冲突可理解、可调整。子代理自报成功、计划节点完成或模型结束回复，不代替业务目标达成；成果必须真实存在并满足用户要求。

8. **主动协助有价值且尊重注意力。** 对相关新信息、关键变化、完成、失败、必要决定和已授权跟进作出合适响应，解释依据和可行动的下一步。无关、重复和过期事项不反复打扰，助理自身行为不引发提醒循环。用户可以采纳、调整、稍后处理、忽略或关闭一类提示。“不要在写文档时打扰，当前任务失败除外”等规则能够准确生效；临时不提醒、长期勿扰、暂停任务和停止执行各自含义清楚。主动发现问题不自动取得执行授权。

9. **具有可管理、可纠正的多维记忆。** 正确区分即时状态、任务约定、项目背景、个人偏好、交互规则和相关工作经验。明确的长期要求能够持续生效，临时要求只影响相应范围，一次操作或一次忽略不会擅自成为永久偏好。用户能知道记住了什么、为何适用，并查看、修改、停用、忘记或要求不记忆；能够按有意义的维度和范围分别控制新记忆形成、已有记忆使用以及是否用于主动协助。关闭长期学习不使当前任务遗忘必要约束，换角色或插件不绕过已生效的禁用规则，长期记忆、会话记录和业务数据的保留影响清楚可辨。过期、错误或已删除内容不再被当作有效记忆召回，原事实优先于摘要；不同项目、角色及私人资料的边界始终有效。

10. **权限、状态与成果可信。** 用户能够理解本次用了什么资料、由谁处理、会产生什么效果以及工作完成到了哪里。读取、模型使用和实际操作符合当时有效的授权；资料变化、撤权、插件停用或升级后仍保持正确边界。普通业务工作与代码、文件、命令及界面控制的授权范围清楚。插件内容不能伪装成用户指令，私人记忆不自动共享，秘密不进入长期记忆。原业务事实与执行事实保持一致，不出现多份互相竞争的任务、成果或状态。

11. **长时间工作、失败与恢复值得信任。** 遇到网络或模型故障、低质量结果、部分成功、子代理中断、重启、版本变化及重复提交，能够保留有效成果、说明实际状态并继续正确的工作，不重复产生业务效果，不覆盖用户的新修改。后台跟进、定时和关闭应用后的运行承诺符合真实环境；超时、错过时间、暂停和恢复可理解。时间、成本和并行程度受约束，停止和回退只承诺真实能够做到的事情。

12. **体验达到内部完整。** 首次使用、没有数据、缺少配置和能力不可用时都有可操作的路径。键盘、中文输入法、辅助技术、窄窗口、明暗主题、长内容及异常状态能够顺畅使用，后台变化不抢焦点。用户可以获得可打开、可编辑、可引用和可继续迭代的成果，而不只是聊天中的完成声明。

13. **建议在必要时可以直接操作。** 文字建议能够附带根据当前情境动态生成的按钮、选项、简短表单或可编辑预览。按钮携带明确的具体操作、目标和可直接使用的参数，用户看得懂效果，点击即可执行或启动约定的工作，无需复制建议或重新描述诉求；缺少必要信息时只补问缺失项。用户修改选择后，可见说明与实际参数保持一致；页面切换不改变原目标，状态变化或权限失效时不再执行过期操作。建议本身可展示实际进度、问题、成果和后续操作，连续点击或恢复后不会重复产生效果。系统、插件、MCP 与专业角色提供的交互建议具有一致的操作体验，点击仅代表用户选择了明确可见的效果。

验收以代表性真实工作为依据：包括发送前的场景帮助、结合当前选区处理资料并连续修改、回答问题与手动操作后的接续、动态建议按钮携带参数执行及调整、跨插件完成工作、无项目的个人任务、从底部使用 Coding Agent、多个入口继续同一会话、多任务切换、TaskBoard 与子代理协作、接入新插件、主动提醒与勿扰、记忆分维度控制、修正与遗忘，以及撤权、超时、重启、升级和后台恢复。所用模型、Prologue、能力和成果必须真实，未支持或未验证的部分明确说明，不能用模拟结果替代。

完成的判断是：用户能够更少地解释背景、搬运资料、切换工具和处理无意义提醒，持续获得符合诉求、依据可靠、确实可用的结果，同时始终清楚助理在做什么，并能随时纠正和接管。工程通过、真实场景通过和用户本人验收分别如实记录；不得把可演示或局部可用当作内部完整。
