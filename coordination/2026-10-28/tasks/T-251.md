## 1. 背景

来源：T-228 二审（#1499 评论 6504032319）的建议。T-228 把 `plugins/native/pages/src/generate.ts` 里生成文稿的长度检查改成：

```ts
if (!output || output.length > 200_000 || [...output].length > 100_000) throw pagesErrors.invalid("模型返回的文稿为空或过长");
```

新用例 `RAC-2186`（`tests/feed-inbox-pages-loop.test.ts`，约 `:208`）用 `"😀".repeat(100_000)` 证明收下，用 `"😀".repeat(100_001)` 证明被拒。但 100,001 个 😀 是 200,002 个单元，被前一半 `output.length > 200_000` 先拒了，**从没走到 `[...output].length > 100_000` 这一半**。二审实测：把字数那一半整句删掉，两个新用例仍全绿，100,001 个 `a`（100,001 个单元，不到 200,000）会被收下——而验收说“超过 100,000 个字就拒”。

## 2. 目标

1. 加一个用例：100,001 个只占一个单元的字（如 `"a".repeat(100_001)`）被拒，100,000 个 `"a"` 被收下。
2. 变异：把 `generate.ts` 里 `|| [...output].length > 100_000` 删掉，新用例红在“拒”那一句。

## 3. 不做

- 不改 `generate.ts` 和别的产品代码；不改 `RAC-2186` 原有的两个断言。
- 不加兼容或迁移逻辑。

## 4. 范围

`tests/feed-inbox-pages-loop.test.ts`（紧挨 `RAC-2186` 那个测试，加一个新的 `test("RAC-2275 …")`）。

锁定：T-228（#1499）也改这个文件，所以依赖 T-228，合入后才领。

## 5. 做法

照 `RAC-2186` 的写法（同一个文件里的 `generate(store, { ...request(), request_id, request_hash }, async () => 文本)`，`openPagesStore(home)`，`finally` 里关库删目录）写一个新测试，测试名以 `RAC-2275` 开头：

```ts
const accepted = await generate(store, { ...request(), request_id: "ascii-accepted", request_hash: "hash-ascii-accepted" }, async () => "a".repeat(100_000));
assert.equal(accepted.replayed, false);
await assert.rejects(generate(store, { ...request(), request_id: "ascii-refused", request_hash: "hash-ascii-refused" }, async () => "a".repeat(100_001)), /文稿为空或过长/);
```

（`request_id`、`request_hash` 的取值照该文件里别的用例，别和它们重复。）

## 6. 验收

- `RAC-2275`：100,000 个单元字的文稿被收下，100,001 个被拒（拒绝只由字数判断挡住）。
- 余下号备用。
