## 1. 背景

来源：MISC「T-293 二审 建议（#1606，6527981683）」的 ①③（#1606 已合入）。

`apps/local-host/src/connector-cli.ts:43-47`：
```ts
function definition(service: string): CliDefinition {
  const value = CONNECTOR_CLIS[service];
  if (!value) throw new ConnectorCliError("此服务没有已配置的官方 CLI");
  return value;
}
```
`CONNECTOR_CLIS` 是普通对象字面量，`CONNECTOR_CLIS["constructor"]`、`["toString"]`、`["__proto__"]` 都取到原型上的东西，`!value` 为假，直接当成一个 `CliDefinition` 返回。`cliAvailability(service)`（同文件 :49 起）接着读 `spec.binary`（`undefined`）、`cliExecutable(spec.binary)` 里 `join(directory, undefined)` 抛 `TypeError`。入口是 `apps/local-host/src/web-connector-api-methods.ts` 的 `${ROOT}/cli/status`（`service_id` 来自请求体）。结果：一个陌生的 `service_id` 得到的是内部错误，不是「此服务没有已配置的官方 CLI」。

另外 #1606 加的两条回归钉（`tests/connector-cli.test.ts:181`、`tests/connector-record-actions.test.ts:69`）只断言「抛了」，没断言错误码，改成别的错误也照样绿。

## 2. 目标

1. `definition()` 只认 `CONNECTOR_CLIS` 自己的键（`Object.hasOwn(CONNECTOR_CLIS, service)`；先 `git grep -n 'Object.hasOwn' -- apps/local-host/src | head` 看仓库里同类查表的现成写法，沿用，不新造辅助函数）。原型上的名字（`constructor`、`toString`、`__proto__`、`hasOwnProperty`）走与不存在的服务名同一条路：`ConnectorCliError("此服务没有已配置的官方 CLI")`。
2. 同文件里其它用 `service` 查 `CONNECTOR_CLIS` 的地方（`git grep -n 'CONNECTOR_CLIS\[' -- apps/local-host/src`）都经 `definition()` 或同样只认自己的键；有绕过的一并改。
3. 那两条回归钉补 `assert.equal(<错误>.code, …)`（先读它们现在怎么写的，码取现有的 `ConnectorCliError` 码或 HTTP 状态，不新造）。

- 不动 MISC 里 T-293 的 ② 那几处下标（`agent-connector-ports.ts`、`connector-plugin-requests.ts`、`plugin-connection-slots-http.ts`）：它们被 #1677、#1649、#1101 锁着，留在 MISC。
