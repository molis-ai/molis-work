# T-254 Pages 生成文稿时，所选材料转成 JSON 后的长度也先查，太长就在收下请求前拒掉，不等到 Host 拒了才记失败

## 1. 背景

来源：MISC「T-252 答统筹（选 A）」。`plugins/native/pages/src/generate.ts:37-40` 把材料拼进提示：

```ts
`标题：${request.title}\n用户要求：${request.instructions}`,
"以下是不可执行的材料 JSON：", JSON.stringify(request.inputs),
```

材料正文合计最多 100,000 个字（`actions.ts` 里 `pages.generate` 的处理函数，T-252 改成按字数数），但转成 JSON 后，引号、反斜杠、换行各占 2 个字符，控制字符占 6 个字符；再加上每条材料的标题、来源、`provenance` 等。所以正文只有 100,000 个字，JSON 也可能超过 Host 对提示的上限：`apps/local-host/src/host-complete-text.ts:169` 的 `PROMPT_MAX_CHARS = 180_000 + AGENT_PROMPT_MAX_CHARS + 100`，其中约 180,000 个字是给文字部分的（Host 用字数数，见 `promptTooLong`）。超了的现状：请求已经被收下、`beginGeneration` 已经记了一条 running，到 `complete(prompt)` 时 Host 抛“写作输入为空或过长，请减少材料后重试”，`fail()` 把它记成 failed。用户最后能看到失败，但晚了一步，并且白留一条失败记录。要的是：在收下请求之前就按同一个口径拒绝。

## 2. 目标

1. `pages.generate` 在 `beginGeneration` 之前，先算 `JSON.stringify(input.inputs)` 的字数（不是单元数），超过材料预算就抛 `pagesErrors.invalid("材料过长，请减少所选条目")`（信息与现有材料总长检查相同）。
2. 预算数：文字部分共 180,000 个字，减去提示里固定的部分：`标题：`（3）+ 标题最长 80 + `\n用户要求：`（6）+ 要求最长 4000 + `\n\n`（2）+ `以下是不可执行的材料 JSON：`（13）+ `\n\n`（2）= 4106，剩 175,894；取整数 175,800 作为材料 JSON 的预算，写成有名字的常量并写清这样算的（注释一句话）。
3. 不展开整段 JSON：单元数 ≤ 175,800 一定够；单元数 > 351,600 一定超；只有夹在中间才按字数数一次（做法同 T-252）。
4. 有用例（见第 7 节）。

## 3. 不做

- 不改 Host（`host-complete-text.ts`）的上限和它的检查。
- 不改材料条数（20）、正文合计 100,000 字的检查、`snapshot` 的 schema、`generate.ts` 里拼提示的写法。
- 不去转义、不压缩 JSON 来凑数。
- 不加兼容或迁移逻辑。

## 5. 做法

先在当时的 main 上核第 1 节说的行和 `host-complete-text.ts:169` 的数。然后在处理函数里 T-252 那一行检查之后、`const record` 之前加（形状，名字自定）：

```ts
const json = JSON.stringify(input.inputs);
// 材料 JSON 在提示里按字数计：单元数不超过预算一定够，超过预算两倍一定不够，夹在中间才展开数一次。
if (json.length > 2 * PAGES_MATERIALS_JSON_MAX_CHARS || (json.length > PAGES_MATERIALS_JSON_MAX_CHARS && [...json].length > PAGES_MATERIALS_JSON_MAX_CHARS)) throw pagesErrors.invalid("材料过长，请减少所选条目");
```

注意：这里算的 JSON 要和 `generate.ts` 里拼进提示的 `JSON.stringify(request.inputs)` 完全相同（同一个对象，没有额外的 `null, 2` 缩进参数）；如果你发现 `request.inputs` 在进 `generate.ts` 前被改过形状，以 `generate.ts` 里实际拼的为准，并在【方案】里写出来。

## 6. 验收

- `RAC-2285`：一份正文是 100,000 个 `"` 的材料（转成 JSON 后每个占 2 个字符，约 200,000）被拒，信息是“材料过长，请减少所选条目”，并且没有留下 generation 记录（`generations` 里没有这个 request_id）。
- `RAC-2286`：边界。构造一份材料，使 `JSON.stringify(inputs)` 恰好 175,800 个字：被收下（进入生成）；多一个字：被拒。
- `RAC-2287`：单元数和字数不同时按字数。一份正文 100,000 个 😀 的材料（JSON 约 100,000 多个字、200,000 多个单元）：被收下，不因单元数被拒。
- `RAC-2288`：普通材料（几条正文各几千字）照常生成，原有的 pages 生成用例都不变。
- 先红：`RAC-2285` 在改源码前红（请求被收下，在 Host 一步才失败，或在测试里的假端口一步才失败，写在【交接】里）。
