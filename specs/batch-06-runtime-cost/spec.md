# 06 批各包调用成本

状态：实施中（2026-11-09，Codex）。对应 [06-4](../post-anticorruption-roadmap/reference/batches/06.md#batch-06-item-4) 的 N47～51，目标为功能可用。N47、N51 的测量起点 `6fec1200b`；其余三项只有只读核查，尚未取得实测基线或实施。

## 范围与方案

**N47。** [Runtime 裁定与 BSH-12](../batch-06-shared-tools/spec.md#4-s3-公用-sdk-工具) 保留回调可修改的独立权限引用副本。当前 Runtime 在普通动作、可用性和场景回调建立时复制整份 `allowed_actions`，即使插件从未读取。改成对可信的当前调用快照取源，在最终视图建立后安装可枚举的惰性属性。首次读取复制数组及每条引用，重复读取同一份副本。插件赋值只更新自己的字段，先赋值可省去原副本的复制。缺省与空数组不同，序列化与展开是正常读取。动作和写场景先完成现有视图装配，再安装属性，避免 Runtime 自己展开时触发复制。继续使用原调用上的身份、作用域和实时授权控制；Host 入口快照及 `local-host-caller.ts` 不在改动范围。

**N51。** 第 07 批后 `placedViews` 仍对每个条目建一份 `UiViewRegistry`。隔离 Home 的真实 `GET /` 三次都建 115 份，项目首页中位数 1,487 份。每次目录投影共用一份注册表，选择页用同一份生成导航和底栏图标。注册表内部每个视图保留原 manifest 输入，新增 `placements(slot)` 供工作台投影取得来源。相同 manifest id 的不同 shell 条目仍各自归属，避免仅以 manifest id 反查造成误归属。既有 `slot`／`views`／`view` 返回同形状的副本。保留视图顺序、内置启用、个人分组、外装 stage 回退和命名来源。不同输入目录分别计算，下一次请求按当前目录读取。

## 验收

- **BRC-01**（N47、BSH-12）。动作、可用性、读写场景的回调不读时复制零条，首次读克隆全量引用。同一回调可改且 identity 稳定，其他回调和原权限快照不受影响。覆盖缺省、空列表、枚举、设置成 `undefined`、展开和 JSON；通过嵌套调用和 S-18 现有拒绝测试确认原权限。
- **BRC-02**（N47）。同一夹具走生产函数和真实简介请求，报告回调数、数组与引用的复制量，前后对照。
- **BRC-03**（N51）。同一组目录保留可见性、顺序、stage 回退、侧栏归属和命名，报告真实首页请求的注册表构造次数。

使用 Node 24.15.0，按机器槽运行 `pnpm build`、`node scripts/run-tests.mjs --jobs 1` 点名本片回归，以及 `node scripts/check-health-gates.mjs --base origin/main`。

## N48～50 的实施边界

2026-11-09 独立只读核查基于 `654cf8f97`。下列是下一片的实现与量测方案；没有对应构建产物，不能把旧审查数字记作本片实测。产品 writer 在 N12 交接后串行采用，先补该片开工检查。

**N48。** 搜索目前对每个提供方独立去抖，`refreshKnown` 与 `reconcile` 会各取目录。同一轮待刷新提供方按实际索引作用域归组，组内共用一次本人索引上下文与目录，只处理被标脏的提供方。保留 Home 来源扇出、注销清理、同 revision 短路、分页期间版本变化重试，以及每次动作实时授权。成功回执没有内容变更标记，实际变化仍由来源的 `collection_revision` 判定。改动留在 SearchService，不借此缓存执行授权。

**N49。** Inbox 与 Feed 的候选展示需要一次只读批量投影：同一原调用共用动作目录和场景声明，内核仍逐个核精确引用、意图、schema 和推荐来源；Inbox 筛兼容项，Feed 继续展示可用性与原因。保留 `services.scenes` 声明过滤及前后授权检查，绑定、预览、执行各自核当前权限。公共批量入口须在 #1999 的内核目录、#2000 的场景合同交接后确定，不为避冲突复制第二份内核判断。

- **BRC-04**（N48）。隔离项目经真实 `POST /api/search/query` 建三个来源的索引，在同一去抖窗口经实际动作修改其中两个。记录后台窗口的 indexer、全量 discover、各提供方列表及正文读取前后次数；两个修改能搜到，第三来源零列表读取，失败仍保留旧结果，停用后清理。沿 `system-search`、`system-search-host`、`system-search-lifecycle`、`system-search-authority` 验证。
- **BRC-05**（N49）。真实 Inbox `judgment` 与 Feed `out-rules/judgments` HTTP 分别使用单个和多个候选，混入不兼容、不可用项。记录目录发现、场景枚举、绑定读取；候选增加不增加全量发现，返回内容及拒绝原因保持，发现后撤权仍拒。沿 `feed-inbox-scene-runtime`、`inbox-action-scenes`、`functions-scene-configuration`、`security-invariants-plugin-scene-client` 验证。
- **BRC-06**（N50）。新隔离 Home 分别测首次 `GET /`、首开项目与一次重开，用测试侧钩子区分摘要入口、实际 canonical/hash 次数与可缓存对象数。自己持有的冻结对象重复调用省去摘要计算；同一外来对象改字段后摘要仍改变，发行物内容被改仍拒绝。沿 `platform-manifest-snapshot`、`plugin-release-artifact`、`plugin-upgrades` 验证。

### N48 作用域与实测

同一 800ms 窗口合并变更通知，按现有索引行的项目与 Home 分组。项目内调用还可能改变同一提供方的 Home 内容，Home 通知覆盖该提供方已有的各项目索引。每组共用本人上下文和目录，注销对照同一目录清理。不同作用域独立推进，同一作用域的新窗口等前一轮同步与清理结束，再读当前目录。组内已启用的各来源独立完成同步。动作成功触发核对，是否重读正文仍由原来源的 collection 与对象 revision 决定。

BRC-04 用真实项目 `POST /api/search/query` 建 Pages、Form、Goals 三个索引。固定时钟，真实更新 Pages 与 Form，推进搜索的 800ms 计时器，独立 Knowledge 的 2s 计时器仍待执行。两篇新正文已由后台写入索引，随后同一 HTTP 查询找到这两篇，旧词只剩 Goals。数字取两次写动作完成之后、下一次查询之前。

| 后台调用 | 基点 `5f95478b3` | 改后 |
| --- | ---: | ---: |
| 本人索引上下文 | 3 | 1 |
| 全量目录 discover | 3 | 1 |
| Pages、Form、Goals 列表 | 1 / 1 / 0 | 1 / 1 / 0 |
| Pages、Form、Goals 正文 | 1 / 1 / 0 | 1 / 1 / 0 |

同一个 HTTP 用例在旧产物只因上下文与目录各为 3 次失败。并发用例覆盖拿到目录后撤权、待刷新来源被拒且旧正文保留、另一来源成功、Home 来源扇出及注销清理。持有已取得的上一版列表期间再触发一次去抖，另一个项目先完成，原项目稍后落最后版本。注销发生在持有列表期间时，清理结束后该来源无索引记录。

测试侧加载钩子移除同作用域顺序后，最后一次 revision 未落索引，等待上界稳定失败。再移除注销清理等待在途读取的边界，迟到的列表让已注销来源重新出现，独立用例也失败。两个故障只在对应测试进程注入。

独立复核又复现两条前台交错。清理停用来源等前台旧列表期间，较早的共享目录可能误删后来登记并完成索引的来源。合批窗口也可能比原独立计时器更早遇到前台旧列表，直接合入在途任务会漏最新通知。目录准备前记登记观察序号，按来源的项目与 Home 登记检查后再删除或补读，保持一次目录。去抖队列带上各来源收到的变更序号。已在途读取只有在开始序号覆盖本次通知时才代替本次读取，否则等它完成后在实时动作校验下继续。来源登记改变后由对应的新窗口处理，过期目录不清理该来源，也不补读旧来源。回归须在发新前台搜索前检查最终索引。

旧合批产物中，刚索引的 B 和同键重登记的 C 均被旧目录删除，另一用例的最后 revision 停在 2。修复后保留 B 的 revision 1 和 C 的 revision 2，停用的 A 已清理，最后通知所在项目落 revision 3。六项 BRC-04 定向均通过，真实 HTTP 背景上下文与目录仍各一次。首个通知继承的 Web 会话若在合批前失效，这一交错目前只有静态疑点，待真实复现。

### N50 实测与验证

同一个 Node 24.15 测试侧加载钩子在摘要入口、实际 canonical 调用和 SHA-256 调用分别记数。以 Runtime 判定区分自有对象和外来对象。每组在新进程、新隔离 Home 建一个空项目，依次访问选择页、首开项目、关闭后重开。三个请求均为 200 且响应含该项目，建项目与关闭各为零。固定时钟并冻结周期任务，实际请求超时继续运行。

| 请求 | 摘要入口前后 | 自有对象数 | canonical 和 SHA-256 各自的前 → 后次数 |
| --- | ---: | ---: | ---: |
| 首次 `GET /` | 0 | 0 | 0 → 0 |
| 首次 `GET /projects/<id>/` | 68 | 17 | 68 → 17 |
| 同一项目关闭后重开 | 27 | 9 | 27 → 9 |

这组请求中命中的摘要入口全部接收 Runtime 自有快照。BRC-06 的直接计数用例在旧实现两次调用各做一次 SHA，改后首次做一次。已有缓存时在数组原型临时加 `toJSON`，照原判定重新计算。调用方的冻结外层对象可原地改嵌套声明，下一次摘要改变。SQLite 解码对象改写后保存被拒，篡改实际存储行后重启也在加载旧代码前拒绝。

以完整构建产物重复请求，计数相同。测试侧把缓存扩大到外来对象后，已算过摘要的 SQLite 解码对象被改写时漏掉拒绝，回归用例失败。

完整 `pnpm build` 通过。两项定向在独立 Home 顺序运行，搜索、引用与实时授权 56 项，Manifest、发行物与升级 35 项，共 91 项通过。
