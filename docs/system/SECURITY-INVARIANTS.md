# 安全不变量：每一条的代码位置和拒绝它的测试

本机的安全边界写成一张表：每条不变量写清**被拒绝的是什么**、**守住它的代码在哪**、**断言拒绝本身的测试是哪几个**。设计来源：[specs/repository-anti-corruption](../../specs/repository-anti-corruption/spec.md) §6（初稿）与 §4.18（W2-19）。

- 一条不变量的测试必须断言**拒绝**（状态码、错误码、没有被写的记录），不能只证明正常路径能走通。
- 表由门禁看住：`pnpm health:check` 的 `security invariants` 规则（`scripts/gates/security-invariants.mjs`）检查每一行点名的测试文件存在、每一个「标题片段」（一个文件后面可以连写几个，一个都不漏）确在文件里、「CI 里跑」一列的文件确实被 CI 跑到，每个 `tests/security-invariants-*.test.ts` 都被某一行点名。改了测试名就改这里。
- CI 里跑的集合是根 `package.json` 的 `test:security`，加上 `test:contracts` 里已有的几条（动作网关、`beforeEffect`、MCP 授权）。CI 是 Linux：只在 macOS 上能跑的（Seatbelt 沙箱、真 Chrome）和较重的整机用例列在「只在本机跑」一列，等 Linux 探针（`linux-probe`，决定 #14）确认能过后再移进 CI 一列（W2-16）。
- **这一步现在不挡合并**：`ci.yml` 的 `security-invariants` 作业（「Security invariants (not required yet)」）带 `continue-on-error: true`，不在 `Verify` 的 `needs` 里（红了在作业上显示失败，`Verify` 仍是绿的；单独一个作业，也不拖长挡合并的作业）。理由是决定 #14（先不挡产品用例，约两周后并入）：`test:security` 里有产品用例（目标树与决定动作、侧栏、记忆等），新写的 7 个 `security-invariants-*` 文件（含起启动器和整机的）也还没在 Linux 上跑过；`linux-probe` 作业会把它们跑进它的报告。探针连续两周没有这些文件的失败后，把它加进 `Verify` 的 `needs`、去掉 `continue-on-error`，它才挡合并（和 W2-16 一起做）。合并前至少要看到这个 PR 的 CI 里这一步在 Linux 上是绿的。
- Computer Use 已在 main：助理电脑 socket 在 S-04，桌面动作的拒绝在 S-25。

测试里的写法：

- 新测试只经包的公开入口和 `launchers/web/server.ts` 起真实的 Web 宿主（`health:check` 不许新文件引用包内部）；需要内部函数的断言，加进已经引用那个内部的旧测试里。
- 起宿主用 `createMolisWorkWebServer({ homeDirectory, controlToken })`，每个测试一个临时 Home。需要换 `Host` 头、不带 `Origin` 的请求，用 `http.request` 直接发（`fetch` 不让改 `Host`）；每个请求新开连接（宿主拒绝时不读请求体，复用连接会被挂断）。
- 升级后的 WebSocket 不是 HTTP 连接，`server.close()` 不会等它也不会关它：测试结束先 `terminate()` 再关服务。
- 这台开发机的代理会把 `198.18.0.0/15` 的地址转给本机监听的端口，所以“别的地址连不上启动器”按启动器自己的 `process_id` 判断，并跳过这个网段（原因见 `S-01` 的测试）。

## 3. 加一条不变量

1. 写清它拒绝什么，写一个**会失败的**测试（先在没有这条保护的代码上看它红）。
2. 找不到拒绝的代码，就是安全缺陷：补最小的拒绝，在提交说明和 PR 里写明这是补洞。
3. 往上表加一行：编号接着排（不复用），写代码位置和测试（路径加「标题片段」）。测试能在 Linux 上稳定跑过，就放进 `test:security`，并写进“CI 里跑”一列；否则放“只在本机跑”并说明原因。
4. 门禁红了就按它说的改表。

## 4. 开放项（没有守住，或守住的范围有限）

- **桌面 IPC 的可达范围没有实测（F15 的另一半）**：S-14 钉住了能力文件，但 `pty_spawn` 可以以任意命令、环境变量起一个进程，权限开给整个 `127.0.0.1:4173` 来源。同源的 iframe（插件侧栏 `apps/workbench/src/side-panel.ts` 的 frame 没有 `sandbox` 属性）能否直接调用这些命令、`tauri.conf.json` 的 `csp: null` 对壳加载的页面意味着什么，要有一次真实构建才能回答（c-end-readiness 的 S5 探针）。已知的缓和：同一个页面里的脚本本来就能拿到控制令牌去连 `/pty` socket 起进程（S-04），所以 IPC 没有给同源脚本新增能力；别的本机进程占着 4173 时壳会加载它的页面，但本机进程本来就以用户身份运行。
- **“是不是本机”在两处不是共用那一份**：桌面壳的 Rust（`apps/desktop/adapters/tauri/src/main.rs`、`context_directories.rs`）是另一种语言；OAuth 代理 Worker（`apps/local-host/cloudflare/worker.ts`）单独用 `wrangler` 打包部署，今天不引用工作区里的任何包，部署步骤（`apps/local-host/cloudflare/README.md`）也不先构建，而 `contracts` 的子路径只导出构建产物。Worker 的那份与共用的那份等价，由 `tests/connector-oauth-broker.test.ts` 逐个写法比对钉住；要合成一份，先要让 Worker 的部署带上构建步骤（它是线上服务，由用户决定）。
- **`/locale`、`/health` 等 GET 路由没有“只读”断言**：S-03 保证的是变更不绕过令牌，GET 路由是否真的只读靠评审；页面 HTML 里内嵌控制令牌是设计（只给回环 `Host`，S-02），没有跨域读的头（宿主不发 `Access-Control-Allow-*`，见 S-03 的测试）。
- **控制令牌文件已存在但权限过宽时不会收紧**：新文件是 0600（S-06），旧文件（别的版本或手工放的）原样沿用。处理需要用户定：沿用并收紧权限、或换新令牌（换新令牌会让常驻服务与 MCP 进程重连）。
- **提示注入的标记中和随当前包验证**：SDK 对 pinned memory 伪标记的中和（Prologue `f40af26c`）在当前 vendored 包 `prologue-sdk-0.0.0-rc.1-after-write-check-marker.tgz`（Prologue main `a51607fb`）里，S-13 的 `tests/prologue-memory-boundary.test.ts` 对这份包断言拒绝（`pnpm test:security`）。换包时同一条用例必须在新包上再过一次。进度见 [采用 spec](../../specs/prologue-adoption/spec.md) §6。
- **五处公网地址实现仍是五份**：S-10 用同一张表钉住了行为，没有合成一份：Jelly 与插件创作台各有自己认可的 `198.18.0.0/15` 例外（用户 2026-09-27 的决定），AnySearch 用 `BlockList`，RSS 在插件包内。合成一份要先决定放在哪（`contracts` 的纯函数不能引 `node:net`）。
- **Seatbelt 沙箱用例永远不会在 Linux 上跑**：S-15 里读写、起进程、直连网络被拒的断言只在 macOS 上有；Linux 上的沙箱继任者属于 C 端就绪方案的 D4。
- **Computer Use 的拒绝没有真机记录**：S-25 的用例都用假驱动、不要 macOS，都在 CI 一列：`pnpm test:security` 跑 `tests/security-invariants-computer-*.test.ts`（选择器不编译正则、菜单路径指向 Molis 窗口）和 `tests/computer-use-gaps.test.ts`（四种拒绝、确认入口跟持有轮次；main 的夜间 Full suite 在 Linux 上跑过它并通过，`739e6cb29`，CI run 39157724720）。真机上终端打字、系统设置、被挡住的落点和自批四种拒绝还没有记录（`specs/computer-use/spec.md` 状态句与 CU-G04）。
- **等外面的结果只证明「在」**：S-27 的 `molis.file-present@1` 看的是文件在、比登记它的那一轮新、带完成标记，不看内容；这一轮自己（或同一目录里别的进程）写下的文件也算。它放行的只是这一步接着做，接着做的那一轮照常过派出前复核与逐笔审查，所以不是越权，但「文件在」不等于「生成成功」，备注里也这样写给人看。
- **GitHub 的 secret scanning 与 push protection 在这个公开仓库上是关的**：要在仓库设置里开，属于用户的操作（`spec.md` §7）。
