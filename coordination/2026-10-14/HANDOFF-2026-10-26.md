## 批流程（MERGE-QUEUE §1a）

1. 评过的片并进当前批头 `batch/<日期>-NN`，冲突由统筹一次解完。
2. 构建：`node scripts/machine-slot.mjs run build --label X -- pnpm build`。`pnpm api:update` 和 `pnpm actions:update` 应当没有改动；有改动就随批提交。
3. 页面资源：跑 `node scripts/gates/page-assets.mjs --base origin/main`。
   - 必需的增长，在 `scripts/gates/page-assets.mjs` 的 `APPROVED_CEILINGS` 里写成 `[merge-base 字节数, 实测字节数]`，用完的条目删掉。
   - `tooling/gates/page-assets.json` 要等于实测。
4. 跑 `node scripts/check-health-gates.mjs --base origin/main`，必须通过。改到的切片用例这样跑：`node scripts/machine-slot.mjs run browser --label X -- node scripts/run-tests.mjs --jobs 1 <文件…>`。
5. 推送前：`git fetch origin main && pnpm secrets:check`。然后推批头，把批 PR 转为正式（正文列各片，带「防腐复查」一节）。
6. 把同一个头推到 `integration/carrier-<日期>-NN`，触发全量。carrier 的全量在排队或在跑时，不再推它。
7. 全量红的文件，和 `known-red-main.md`、上一批的红单比对。本批引入的就在批头修，不重跑全量；在 PR 里写归因评论。
8. Verify 绿后入队：`gh pr merge <n> --squash --match-head-commit <sha>`。
9. 落地后：
   - 核对 main 的树等于批头；删掉 carrier 分支；
   - 下一批先 `git merge -s ours origin/main`；
   - privileges.md 对应的行补上「随 batch-NN（#PR，main `sha`）」；
   - `LINES.md` 和 `RISKS-AND-DEFERRED.md` 各记一条。
