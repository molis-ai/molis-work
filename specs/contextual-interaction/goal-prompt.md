# 情境驱动的动态交互 Goal Prompt

为 Molis Work 设计并实现一套由用户当前行为和内容语义驱动的动态交互体验，让主内容区、底部菜单栏和助手对话框协同变化。用户在操作内容的过程中，自然获得当下最合适的工具、建议和下一步，减少寻找功能、切换界面和重复向 AI 解释上下文的成本。唯一 spec 是 [spec.md](spec.md)。

（以下目标状态依据用户 2026-09-30 的原始需求整理，要点和措辞尽量保留原意。）

## 最终应达到的状态

1. **系统理解当前情境。** 用户在主内容区浏览、选择、编辑、比较或完成某项操作时，系统能理解当前情境。感知粒度覆盖页面、对象和对象内部的局部内容：选中一段文字、一个词、一个内容块，或选中多个对象，都可能产生不同的界面组合。同一种动作会因内容含义、周围上下文和当前任务而产生不同结果。
2. **底栏与助手协同变化。**
   - 底部菜单栏中的操作组合、排序、分组和重点随情境变化；
   - 助手对话框中的上下文、建议、问题、选项、预览、结果和操作入口随情境变化；
   - 两个区域分工清楚、衔接自然，共同服务于当前工作。
3. **判断真正影响界面。** 评估使用 Jev 这类判断模型，结合项目现有的模型能力，理解用户动作、操作对象的语义、周围内容、当前目标和近期工作状态，再选择合适的能力和界面元素，并决定它们的组合、陈列和重点。不能只按页面类型或选区类型切换几套预设按钮。优先复用产品已有的能力和组件，并明确哪些新的表达形式能带来实际的体验提升。
4. **动作来自统一能力体系。** 可供模型选择的动作来自统一能力目录，沿用公开 Contract 和 Prologue Runtime，不另建一套与插件、权限、实际执行能力脱节的菜单名单。
5. **推荐与执行边界清楚。** 选择内容可以触发判断和展示；修改内容、创建记录和其他副作用，只能由明确的用户操作或已有授权触发。用户可以直接执行，也可以继续用自然语言调整，或者忽略建议、打开完整操作。
6. **及时、稳定、可预测。**
   - 保留必要的导航和通用入口，用户始终知道自己在哪里；
   - 避免频繁跳动和重复推荐，不移动用户正在点击或输入的元素；
   - 用户切换选区、页面或目标后，过期的判断不会覆盖新情境，后续操作作用于用户明确选择的对象；
   - 点击底栏或助手元素时，原来的选区和上下文正确保留；
   - 模型等待、判断不确定、失败或超时时，基础操作仍然可用，并有自然的恢复方式；
   - 助手能以建议、选项、预览、比较和结果等形式参与，输入框随时可用于表达更具体的意图；
   - 上下文采集适量、有明确边界，不把无关内容或敏感信息无差别地发给模型。
7. **场景覆盖有代表性，并继续探索。** 启发场景包括：
   - 选中一个观点：找依据、提出反例、展开讨论；
   - 选中一段计划：拆解步骤、关联目标、识别依赖；
   - 选中两段内容或多份材料：比较、建立联系、提炼、合并；
   - 编辑内容：助手呈现局部建议、可比较的版本和修改预览；
   - 推进目标或完成一个步骤：呈现与后续工作相关的工具和内容。

   这些例子不构成固定菜单，也不是功能上限，要继续探索有价值的场景和交互形式。

## 完成标准

目标完成程度为“内部完整”：代表性场景使用真实上下文、真实判断模型和真实动作，能顺畅试用，并有必要的失败与恢复处理。验证至少要证明：

1. 相同类型的选择，在不同语义和任务情境下，可以得到有意义的不同组合；
2. 从选择内容到执行操作、结果反馈，形成完整闭环，作用对象正确；
3. 快速切换选区、持续编辑和模型延迟，不会导致错配、覆盖或操作丢失；
4. 动态推荐不可用时，原有基础能力仍然可以访问；
5. 关键页面、状态和适用的屏幕尺寸，都经过真实浏览器操作验证。

最终交付可操作的体验、实现代码、必要文档和验证证据，并明确哪些已实现、哪些是模拟、哪些未验证。工程验证、真实场景验证和用户本人的体验认可分别记录。

## 推进方式

- **顺序**：先检查项目现状，建立唯一 spec（体验目标、上下文流转、模型输入输出、组件边界、动作执行、验收标准）。大规模实现之前，先做一个有真实或逼真内容的高保真可交互切片，走通“操作内容 → 界面变化 → 选择操作 → 预览或执行 → 结果反馈”，覆盖有代表性的局部选择和对象操作；标明模拟部分，通过实际交互检验设计，然后再做真实接入。
- **决策**：范围清楚、可以撤回的选择自主推进，写进 spec 的决策记录；只有影响目标、权限或关键产品取舍的缺失信息才问用户。对外操作（push、开 PR）先问用户。
- **位置**：分支 `feature/contextual-interaction`，工作树 `.claude/worktrees/contextual-interaction`，从 origin/main fa27207a 开出。真实接入阶段改为以包含面板改版第二期的助理分支为基线。
- **边界**：
  - 底栏和助手面板的结构归面板改版会话 [3c6203]；挂载点已约定，见 spec §6.3。
  - 页面位置与状态暂存归页面动线会话 [47c510]。
  - 记忆归记忆会话 [9c322a]，本线只通过 `memory.*` 合同使用。
  - 本线不改 Prologue SDK。
- **验证环境**：
  - 用隔离 Home；真实 Jev、TypeSafe 和模型只能在进程内读取，不打印、不落盘；
  - 用自己的预览端口，避开 4173、4207、4208、4240、4241、4270、4281；
  - 改源码后按包 build，再重启预览；
  - 界面改动过 craft-finish 设计门禁，并在 1440、1024、800、390 宽度和深色下用真实浏览器操作。
