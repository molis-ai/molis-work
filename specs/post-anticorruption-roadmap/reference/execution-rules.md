# 执行与阅读规则

[执行目录](../spec.md) · [参考分类](../spec.md#reference)

[执行目录](../spec.md#execution-batches)是 01～89 顺序的唯一清单，**从 01 往下做**；要服务端的需求单独在[服务端批](server-batch.md#server-batch)。前面的阶段 0～4 保留为能力与退出条件的总览。保留 01～89 的连续编号，移到服务端批的 23、48～50、73、78～80、86、87 留着编号、在行里写去处；本次将 14 调整为字体皮肤语言 A 段、15 调整为首页公共呈现，使合同先于消费者，相关依赖一并改号。新增需求并进对应批次，不另起聊天版排期。批次不是一个 PR：同批的合同、服务、界面和验收仍按原需求拆片，先交前置，再接消费者；各子项分别满足前置即可推进，不把同批无关子项串成新的阻塞。

- **范围与状态**：每行保留原需求书作为验收依据。全产品文案与引导、智能呈现四片、主线三片、升级 U0～U7、11-02 的平台余项和 11-03 的开发流程已纳入。已有实现先核回，只做缺口；表中有交付位置不等于已实现、已验收或已获发布授权。在途防腐 PR 的成果与需求变更在 01、02 按实际合入结果核回；近期需求 PR 的逐项去处见 [近期 PR 来源对照](requirement-prs.md#recent-requirement-prs)，#1730 的新增验收仍以该 PR 固定头的需求为准，未宣称已在 main。
- **阶段与决策**：阶段表示所属能力，不要求其他轨道整段结束才开始；16 在阶段 1 完成 B 段验收和现有入口的一次切换。类型沿 [需求映射](requirements.md#section-3-9)；前置栏和 UI 栏合起来写决策，未列待决的部分沿原需求直接做。[决策记录](decisions.md#section-7) 第 18、19 项仍待决定，暂按现有 M1 范围、含生成首页的场景闭环执行；第 17、21、22 项 11-04 已定（C 轨不拆写手；不碰真实 Home 的部分提前启动；会话按轨道跨批做到底）；第 20 项已定（16 一次切换，见下）。Memory 的原暂停、同步接入方式、CGS 本体与真实 Home 操作各按原边界。
- **可并行项**：批次详情列可穿插的设计、只读核查、评审、外部审核与长期观察；并行仍需符合当前人员与机器额度。C1/C2/C3 是职责分工，不在第 17 项确认前自动增加写手。共享合同、同路径与换包串行。明确交办和助理团只有核实缺 SDK 能力时才等 31。
- **字体切换边界**（[决策记录](decisions.md#section-7) 第 20 项，用户 2026-11-03 定）：14 交完整 A 段；16 先在真实工作台验 B 段，随即按 C 段把现有全部入口一次切到新格式，不按插件逐个切，也不新增新旧双认的兼容读取。15 的稳定键呈现、17／19 等新格式消费者在切换前只在隔离集成树开发验证，不合入稳定键配旧 EN 的半成品；16 的切换落地后即合入，此后新入口直接按新格式写、正常合入。窗口期间 E 不改插件界面文字与样式（规则 3）；55 只复核切换后新增入口的文字与翻译缺口，56 证明全入口与发行物。07 等已有格式的独立工作照常合入。
- **开工说明**：每个批次及其中每一片开始前，按[开发流程 §2.1](development-workflow.md#kickoff-brief)在执行会话先用大白话给用户讲清楚：这批做什么、解决什么问题、做完能看到什么、为什么排在这里、需要用户做什么，不拽技术词（用户 2026-11-03 定）；再说明具体交付、边界／主人、前置与待决、顺序／并行、验证和目标完成程度。小修也要简短说明。讲完就继续，已有授权且前置满足不等回话，只有未定的事才停下问，不把说明变成逐项重复审批。
- **批次文件**：每批一个文件，在 [`batches/`](batches/01.md) 下按批次号命名（服务端批是 `srv-N.md`）。文件依次是「给人讲清楚」（开工说明的大白话底稿）、「交付与前置」（交付、来源、前置、可并行项、UI 要求，以及进展与证据）和「Goal Prompt」（整段交给执行这一批的会话；提示本身写得薄，细节链回本文件与原需求）。三部分说法不一致时以「交付与前置」为准，并在同一个改动里改正另外两处。
- **UI 沟通**：“先定样”是按[开发流程 §5](development-workflow.md#5-界面先定样)做可操作高保真，覆盖正常与异常状态，用户本人看实物定下后实施；“复用”沿已定交互，新增差异再定样；“无需”没有新增界面。普通文案、已有控件与缺陷修复直接做，不重复定样。各片均应用 VUX-51～59、ONB-47～49，生成页面与后续新入口也在覆盖内。
- **升级顺序**：U0 在 02，U1/U2 在 05，U3 在 25，U4/U5/U6 在 26，U7 在 72，U6 接自动更新在服务端批 SRV-8。统一起点之后首次改库结构前先有 U1；换 Prologue 包与发布前过全部金样回放。动作／Manifest／MCP 的过渡期从 M1 实际外发起算，与库的统一起点分开。
