# T-046 接入授权的读取与取消只认准备者：补上 BL-180，两个动作也走 `requireConnectorInitiator`

> **这条在 main 上成立，而且比 BL-180 写的重。** `connectors.authorization.read` 与 `.cancel` 的处理器（`apps/local-host/src/connector-management-actions.ts:98-103`）只按授权请求 id 取记录，不比发起者；四个继续动作（S-37）都先走 `requireConnectorInitiator`。读会把别人那次接入的整份 `setup`（本机启动的可执行文件、参数、目录、环境变量名，CLI 安装目录，端点，`connection_id`）连同 `intent_revision`、`commit_held` 交出去；取消不只是翻一个状态，还会丢掉协议暂存、取消 Gmail/Notion 流程、删掉受管理的安装目录和密钥库里的暂存（`cancelConnectorAuthorization` → `clearConnectorAuthorizationPresentation`）。我只读了代码，没有在真实路径上复现。**没有一个现有的正常调用者会被收紧挡住**（第 1 节的表）；要改的只有三个测试里「谁来读、谁来取消」。

## 1. 背景

依据都在 main `9688a61b5`：

- 现状：`authorization` 与 `cancel` 两个定义在 `connector-management-actions.ts:51-56`，受众 user/agent/mcp，权限 `connectors:management:read` / `:write`。读的处理器 `:98` 直接 `authorization(id)`（`:61-65`，查不到抛 `connector.management.authorization_unknown`）；取消的处理器 `:99-103` 先 `authorization(id)`，再 `beforeEffect()`，再 `cancelConnectorAuthorization(home, id)`。两处都不比发起者。
- 对照：`requireConnectorInitiator`（`connector-authorization-status.ts:124-128`）比 `actor_id`、`project_id`、`runtime_session_id` 与库里 `initiator_json`，不符或没有发起者抛 `connector.setup.foreign_request`（forbidden，`:11`）。三处在用：`connector-setup-execute.ts:19`、`connector-local-actions.ts:52`、`connector-cli-actions.ts:34`，都先核、后 `beforeEffect()`。
- S-37（`docs/system/SECURITY-INVARIANTS.md:51`）写的是「四个继续动作」只接受同一用户、项目与会话；读与取消不在里面。规格站在收紧这边：`specs/assistant-service-connections/spec.md:345`「不同会话不自动共享取消权」、`:178`。
- 谁在调读与取消（我查了 `apps`、`packages`、`plugins`、`skills`、`tests`）：

| 调用者 | 怎么到 | 传的 actor / 项目 / 会话 | 收紧后 |
| --- | --- | --- | --- |
| 设置页轮询与取消 | `GET` / `DELETE /api/settings/connectors/authorizations/<uuid>`（`web-connector-connections.ts:28-33`，`web-connector-settings.ts:14`；页面脚本 `apps/workbench/src/scripts/connectors-settings.ts:109`、`:130`、`:330`）直接调 `connectorAuthorizationStatus` / `cancelConnectorAuthorization`，不经动作，不读 actor | 无 | 不受影响 |
| 助手在自己那一轮读、取消自己准备的接入 | 动作目录 | `ASSISTANT_ACTOR` + `work.session_id` + 项目，与准备时相同 | 放行 |
| 其他 Agent | 动作目录 | `agent:<runtime>` + Host 核过的会话 id，与准备时相同 | 放行；别的会话拒 |
| MCP 客户端 | 动作目录 | `client_id` 当 actor；`runtime:` 客户端另带 `runtime_session_id` | 同一客户端同一会话放行，别的客户端拒 |

| 人在 Home 经动作目录 | audience user | `LOCAL_PERSON_ACTOR_ID`，无会话 | 只能读和取消自己在 Home 准备的 |

- 助手侧的 `connector-setup-checker.ts`、`connector-setup-intent.ts:22-28`、`connector-setup-retain.ts`、`assistant/assistant-setup-material.ts` 直接调函数，`connectors.setup.resolve` 有自己更严的核对；`assistant/assistant-connection-authority.ts` 只是发现这个动作。都不受影响。
- 现有测试里读或取消「别人准备的请求」的只有三处，收紧后会失败，要改的是读取者，不是断言：`tests/connector-setup.test.ts:86`（`cancel` 助手 `:14-15` 写死用 `caller`）；`tests/security-invariants-connector-intent.test.ts:68`、`:236`（`read` 助手 `:16` 写死用 `caller`）；`tests/assistant-connector-continuation.test.ts:10`（`authorizationState` 以 `LOCAL_PERSON_ACTOR_ID` 读助手准备的请求，`:104`、`:108` 用）。准备者和读取者相同的例子（`connector-managed-install`、`connector-local-actions`、`connector-setup.e2e`、`connector-mcp.test.ts:875/926/961` 等）不受影响。页面路由的正向对照已在：`tests/connector-setup.test.ts:140`（GET）、`tests/connector-connections.test.ts:386`（DELETE）。
- 为什么不放过「读」：读出的 `setup` 就是别的会话准备好、尚未执行的本机命令计划；读与取消都是拿一个 uuid 当唯一凭据，uuid 不可猜但会出现在页面链接（`/capabilities/connections?setup=<id>`）和动作返回里，不能当授权。

## 2. 目标

1. 读：准备者（同人、同项目、同会话）读得到；另一个人、另一个会话、同人同会话换了范围（Home 与项目互换）、没有发起者的请求，都以 `connector.setup.foreign_request` 拒绝，什么都不返回（`RAC-1478`）。
2. 取消：同上的四种调用者被拒，请求保持 `prepared`，受管理安装目录和暂存不动；准备者取消照旧（`RAC-1479`）。
3. 页面发起、没有发起者的请求，经动作读与取消被拒，经设置页的两条路由仍能读与取消（`RAC-1480`）。
4. 不存在的 id 与别人的 id 得到同一个拒绝，读与取消的接口不泄露请求是否存在（`RAC-1481`）。
5. 本单只收紧归属，不改到期合同：`requireConnectorInitiator` 不看到期，准备者读自己已过期的请求照旧得到 `status: "expired"`（`connectorAuthorizationStatus` 在 `connector-authorization-status.ts:96-108`，`:103` 把过期的 `prepared`/`pending` 报成 `expired`）；别人读一个过期的请求照样被拒（`RAC-1482`）。

## 3. 不做

- 不改动作定义、输入输出 schema、权限、受众；不改 `connector-authorization-status.ts` 的 `cancelConnectorAuthorization`、`connectorAuthorizationStatus`（页面路由和助手侧直接调它们）。
- 不给设置页的两条路由加发起者核对：它们是本人的页面，S-37 写明本人的设置页走自己的路由。
- 不动 `connectors.local.cleanup@1`（`connector-local-actions.ts:39-42`）：它按 `installation_id` 删受管理的安装，对象是安装不是请求，没有「发起者」可比；它要不要守卫是另一个问题，不顺手改。
- 不动 `specs/assistant-service-connections/spec.md`（#1324 在改它）；不写兼容或迁移：这是新增的拒绝，不碰存量数据。
