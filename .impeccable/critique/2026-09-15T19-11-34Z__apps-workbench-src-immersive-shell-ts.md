# 视觉、注意力与连续动线复查

结论：整体视觉语言已经统一，但用户定位、当前事实与下一步、键盘连续性仍有明显缺口。上一轮功能可用的结论不能替代本轮注意力审查。保留 Coss 中性色、常驻外层标签、自由分屏、真实 Goal Frame 和独立设置；改进这些结构里信息与操作的优先级。

范围：隔离演示项目的首页→Goals→Frame→工作区→备注→取消、设置→返回、Inbox空态，以及 Feed 开合/返回、标签收起/键盘切换、390px导航和表单。没有提交领域数据或启动 Runtime；本次新增问题尚未修复。

## 优先问题

### 1. P1：当前对象的标识不一致

从画布打开另一条 Goal 的 Frame，外层标签和 Frame 标题已经切换，目录仍高亮旧 Goal；进入工作区才同步。收起当前标签组还会完全隐藏当前页，只剩插件组名。内容标题仍能辨识对象，但导航不再提供一致锚点。

修正：目录当前态、标题与当前外层标签同步；图上选择若独立保留，应与当前工作对象区分。标签组收起时保留当前页名称与可访问的当前态。保留标签分组、画布内部放大和自由分屏。

证据：assessment-a-frame.png / assessment-a-workspace.png；assessment-b-collapsed-goals.png。源码：scripts/client/tab-workspace.ts 的 Frame 分支提前返回、styles/tab-workspace.ts 的整组隐藏。建议 harden / polish。

### 2. P1：当前事实和下一步被空白执行区、历史详情压过

Goal 工作区主区是一大块空终端，真正的“添加终端”入口在远处；右侧只说“有事项挡住完成”，未直接说明具体未满足要求或待决定事项。首条历史关系默认展开，“Goal 关系变更”的大标题比当前事实醒目。

修正：当前 Goal → 当前真实状态/缺口 → 对应下一步 → 工作内容 → 历史追溯。明确列出真实未满足项和对应入口，不编造下一步。空终端中就地提供已有的添加入口；普通首次进入时历史紧凑展示，返回时保留用户主动展开的事件。关系标题统一为次级字号。

证据：assessment-a-workspace.png；event-document-ui.ts 默认首事件与状态摘要、event-history-body.ts 关系 header 内 h2、goal-canvas.ts 仅覆盖直接子 h2。建议 clarify / layout / typeset。

### 3. P2：进入阅读与表单时，键盘焦点脱离当前任务

演示 Feed 首条按 Enter 展开后焦点落到 BODY，下一次 Tab 回到搜索框；窄屏 Goal 随手备注打开后焦点同样落到 BODY，下一次 Tab 落到表单外的信息开关。取消备注则正确返回“记一笔”。这不是已证明的数据丢失，但会打断键盘用户的操作顺序。

修正：展开时保留在披露按钮，或明确进入阅读区；收起时回原条目。表单进入聚焦标题或首个输入，取消保持已有正确返回。根因尚需跟踪重绘顺序，不能仅凭观察断言某次渲染是唯一原因。建议 harden / audit。

证据：Assessment B 的真实 AX/DOM 焦点序列；assessment-b-feed-open.png。窄屏表单 DOM 坐标确认可达，截图合成异常不作为产品缺陷。

### 4. P2：空 Frame 要求人先学会跨页面搬运

提示“从目录拖入消息、会话或资料”，而此时目录只有 Goals。用户需要自己发现切插件、返回 Frame 或先分屏，才能添加第一份内容。

修正：空 Frame 增加“添加已有内容”，在原地选择真实消息、会话或资料引用；继续保留跨分屏拖入。不得静默创建或关联领域记录。建议 onboard。

证据：assessment-a-frame.png；frame-container.ts 当前仅有工作区/定位入口，frame-empty 无可操作添加入口。这是可发现性问题，不是声称现有拖拽坏了。

### 5. P2：首页主要视觉锚点不可操作，自动轮换文字持续抢注意

首页日期、日历和名言营造了个人工作空间，但最像主要动作的输入框不可用；名言每五秒变化，减少动态效果仅去淡入淡出，内容仍会换。

修正：保留首页构图，在不可用输入附近提供一个真实继续工作入口；名言采用手动切换或更长停留。将动效用于用户主动触发的反馈和空间变化。建议 clarify / quieter。

证据：assessment-a-home.png、project-home.ts 轮换计时器。这是对注意力的设计建议，不将文字轮换直接判为无障碍违规。

## 应保留的部分

- 独立设置的四类导航、单列内容和返回同一 Goal 的行为。
- 记一笔三类用途、相邻取消/保存；取消恢复原焦点。
- 外层标签、自由分屏、Feed就地展开及返回保留展开状态；布局菜单四方向、Escape回触发按钮。
- 不自动启动终端，空Inbox如实显示无事项。正常控件120/180ms反馈，减少动态效果实测有效。

## 认知负担与用户动线

产品有自己的工作空间特征，不是通用后台；安静的配色没有自动解决信息取舍。问题集中在进入 Goal 时并行出现的导航、空 Frame、工作区、历史和状态之间，当前对象和当前动作不够突出。记录表单与设置则能把选择收敛到眼前任务。

熟练用户：目录/标签的当前态冲突与焦点跳走打断连续工作。首次用户：Frame空态与不可用首页输入需要额外探索。使用多个 Runtime 的项目负责人：需要先看到真实缺口和下一步，再按需回看历史。

情绪动线：首页平静→不可操作入口犹豫→Frame标题明确→缺内容入口再次犹豫→工作区泛化阻塞最难判断→备注取消与设置返回恢复确定性。

## 次要观察

390px内容操作已是44px双列，目录、RSS添加和Goal备注可达；标签栏关闭22px、组标签24px、布局30px仍需要更大的触控热区。未观察到页面水平溢出。正常tab/chevron为0.12/0.18秒，减少动态效果后为0.00001秒；没有测试帧率或原生触觉。

四个源码目标的单次自动检测返回0项；它没有发现当前身份错位、信息优先级和焦点问题，不能据此判定体验通过。两个评估彼此隔离，A完成后才读B。

## 下一轮顺序

先处理当前对象同步与焦点连续性，再重排Goal当前状态/历史的视觉优先级，随后补Frame首次添加入口、首页可用动线和触控尺寸。首个验证切片应覆盖“打开Goal→看懂当前状态→添加首份内容/开始工作→记一笔→取消/返回”，以真实可操作页面验证。

本轮不重复询问全量范围与视觉参考，沿用用户已明确的全产品体验要求。真正开放的问题是在具体设计时如何呈现现有真实下一步，而不是是否需要继续保护注意力。
