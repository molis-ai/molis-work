# T-202 评论交给助理的上下文按整字截到 30000 个单元以内，不再留下半个字，提示语与截法一致

> **可领，依赖无。成立：Pages 把评论交给助理的上下文（正文、评论线程）各按 UTF-16 单元截到 30000，截点落在一个两单元的字（如 `🟢`，U+1F7E2）中间时，留下半个字；提示语写的是「前 30000 字」「最近 30000 字」，与截法不符。**
>
> - `plugins/native/pages/src/comment-actions.ts:57-59`，在 `context` 动作的处理器里（main `6ac428940`），原样：
>
>   ```ts
>         const truncated = document.length > 30000 || messages.length > 30000;                                                                     // :57
>         return { title: page.title, revision: String(page.version), truncated,                                                                    // :58
>           text: `Page: …\n引用: ${found.anchor.excerpt}\n…正文${document.length > 30000 ? "（前 30000 字）" : ""}:\n${document.slice(0, 30000)}\n\n本评论线程${messages.length > 30000 ? "（最近 30000 字）" : ""}:\n${messages.slice(-30000)}`,   // :59（中间一段 `…` 是我省略的，原行是整行）
>   ```
>

>   - 正文取开头：`document.slice(0, 30000)`。第 30000 个单元若是 `🟢` 的前一半，末尾留下一个孤立的高位代理（`\ud83d`）；

- 现在的样子（`comment-actions.ts:49-61`，`context` 动作的处理器；`:57-59` 是要改的三行）：

  ```ts
      bind(pagesCommentActions.context, (input, caller) => stores.read(store => {
        const page = store.get(input.subject_id, project(caller));
        const found = store.comments.get(input.subject_id, input.thread_id, project(caller));
        const request = found.messages.find(message => message.message_id === input.message_id && message.author === "user");
        if (!request) throw pagesErrors.not_found("找不到要回复的用户消息");
  ```

  - 所以预算还是 30000 个**单元**，只修两件事：不留下半个字；提示语不再说「前 30000 字」。
- **提示语怎么改**：被截时写

  - 线程：`（只取最近的部分，不超过 30000 字）`；
  - 没被截不写。「不超过 30000 字」不论「字」按单元数还是按码点数都成立：30000 个单元以内的文字，码点数不会更多。`truncated` 的含义不变（任一部分被截就是 true）。
- 两个新函数为什么只看一个单元、不遍历：预算是单元，截点就是下标 30000（头）或 `length - 30000`（尾）。头：下标 `limit - 1` 是高位代理（一对的前一半），它后面必然是它的后一半，那一对就被劈开了，退一格。尾：下标 `length - limit` 是低位代理（一对的后一半），它前面的前一半被截掉了，进一格。其余照原样。长度没超过的原样返回，不拷贝。

## 2. 目标

1. 正文部分取开头 30000 个 UTF-16 单元；截点落在一个两单元的字中间时，把这个字整个留在外面（得 29999 个单元），不留下半个字。截点在两个字之间、一个单元的字、没超过的，与现在一字不差。
2. 线程部分取最近 30000 个单元，同样的规则（起点落在字中间时，从下一个整字起）。
3. 提示语：被截的正文上方写「（只取开头的部分，不超过 30000 字）」，被截的线程上方写「（只取最近的部分，不超过 30000 字）」，没被截的不写；说明里的数字对「字」按单元数或按码点数都成立。`truncated` 的含义不变。
4. 全是表情的正文、线程、2000 个表情的引用，整段上下文文字也不超过 Host 收的 100000 个单元。
5. `RAC-1970`～`RAC-1973` 钉住上面几条：第 6 节九个变异，每个都有一句断言红。

   ```ts
   /** What of a document and of a comment thread the assistant is handed: at most this many UTF-16 units of each (the opening of the document, the latest of the thread). The Host refuses a context text over 100000 units, and these two parts are most of it. */
   const CONTEXT_PART_UNITS = 30000;
   /** The first `limit` UTF-16 units of `value`; a character the cut would split (an emoji is two units) is left out whole, never half of it. */
   function headUnits(value: string, limit: number): string {
     if (value.length <= limit) return value;
     const end = /[\uD800-\uDBFF]/u.test(value[limit - 1]!) ? limit - 1 : limit;
     return value.slice(0, end);
   }
   /** The last `limit` UTF-16 units of `value`, with the same rule at the other end. */
   function tailUnits(value: string, limit: number): string {
     if (value.length <= limit) return value;
     const start = value.length - limit;
     return value.slice(/[\uDC00-\uDFFF]/u.test(value[start]!) ? start + 1 : start);
   }

   ```

这几个用例为什么成立（写进【方案】，PR 里也写）：
- **每个 test 都走真的动作分派**：`ActionService.invoke(..., pagesCommentActions.append, …)` 发评论、`invoke(..., pagesCommentActions.context, …)` 读上下文，与 `PAS-08 PAS-10`（`:49-77`）同一种造法。上下文里的「正文」用 `draft`（未保存草稿，`maxLength: 100000` 个字，`comment-actions.ts:33`）来给，不用造一份很长的存档正文；`draft.revision` 要等于 `page.version`（`:54`）。评论 `maxLength: 20000` 个字（`:30`），`RAC-1632` 已经走通 20000 个表情。
- **`contextParts`** 按固定的版式把上下文文字拆成两段加各自的说明：`…\n引用: …\n正文<说明>:\n<正文>\n\n本评论线程<说明>:\n<线程>`。正则不带 `u` 标志，所以落单的代理也能被 `[\s\S]` 吃进去。
- **`RAC-1970`**：
  - 草稿 `"评" + 🟢×15001` 是 30003 个单元。第 30000 个单元（下标 29999）是第 15000 个 `🟢` 的前一半，按单元 `slice(0, 30000)` 得 `"评" + 🟢×14999 + "\ud83d"`；整字规则退一格，得 `"评" + 🟢×14999`（29999 个单元，15000 个字）；
  - 草稿 `🟢×15001` 是 30002 个单元。下标 29999 是第 15000 个 `🟢` 的后一半，整整 30000 个单元截在两个字之间，得 `🟢×15000`，一个单元也不少留（防「见到代理就退」的写法）；
  - `"评"×30001` 一个单元一个字，截到 30000 个，与现在一字不差，标已截；`🟢×15000` 恰好 30000 个单元，整份留下，不标已截，上方没有说明（防 `>` 写成 `>=`）。
- **`RAC-1971`**：
  - 一条评论 `🟢×19999 + "尾"`（39999 个单元）。线程部分是 `user [<id>]: ` 加评论，共 45 + 39999 个单元；从尾数第 30000 个单元的下标是 `45 + 9999`，也就是评论里的下标 9999。评论里 `🟢` 占下标 `2k`、`2k+1`，9999 是奇数，是第 5000 个 `🟢` 的后一半。按单元 `slice(-30000)` 得 `"\udfe2" + 🟢×14999 + "尾"`；整字规则进一格，得 `🟢×14999 + "尾"`（29999 个单元）。这个结论与那一行 45 个单元的长度无关（都是相对下标），所以不依赖 id 的长度；
  - 评论 `"评" + 🟢×19999`：评论里 `🟢` 占下标 `1+2k`、`2+2k`，9999 是 `1+2×4999`，是第 5000 个 `🟢` 的前一半，起点正好在两个字之间，得 `🟢×15000`（30000 个单元）；
  - 「恰好 30000」和「多一个」用 `"评"` 造：评论 `30000 - 45` 个字，线程部分正好 30000 个单元，整份留下，不标已截；`30001 - 45` 个字，多一个单元，截掉最前面的一个单元（`user` 的 `u`），得 `ser [<id>]: ` 加评论。45 是 `user [<id>]: ` 的长度：`user`（4）+ 空格和 `[`（2）+ id（36）+ `]`、冒号和空格（3）；用例里先断言了它。
- **`RAC-1972`**：没被截时整段文字逐字对上版式（连标题、版本、引用都对）；被截的各写各的说明；说明里的 30000 用 `.length` 和 `[...x].length` 都查。
- **`RAC-1973`**：
  - 守边界用的：正文草稿 `🟢×40000`（80000 单元）、两条评论各 `🟢×20000`、引用 2000 个表情（评论的锚点是一个盖着 2000 个表情的 `comment` mark，T-158 以后摘录取前 2000 个字）。取前 30000 个**字**，正文 60000 个单元、线程约 60000 个单元，加引用 4000，约 124000，超过 Host 的 100000；取前 30000 个**单元**，约 64000；
  - 两个部分各不超过 30000 个单元，整段不超过 100000；断言里带着实际数字。
