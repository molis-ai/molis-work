## 1. 背景

- `partTitle(title, part, parts, max)` 有三个调用点（main `d369d019d`），`max` 是下游的字数上限，下游怎么数、有没有别的限，逐个读过：

| 调用点 | 位置 | `max` | 下游 | 下游数的单位 |
| --- | --- | --- | --- | --- |
| Todo 的材料标题 | `context-onboarding-service.ts:357`（`todoBatches`，T-180 后 `:375`） | 200 | `todo.organize.extract` 的 `materials[].title`：`plugins/native/todo/src/organize-actions.ts:41` 的 `maxLength: 200`（还有 `minLength: 1`）；Todo 存的时候又 `[...material.title].slice(0, 200)`（`organize.ts:116`） | 字（AJV 按码点；存的时候按字） |
| Pages 的源文档标题 | `:482`（采用时每份材料的每一部分一个文档，T-180 后 `:500`），传进去的是 `` `[${ref.label}] ${ref.title}` `` | 80 | `pages.documents.import` 的 `documents[].title`：`plugins/native/pages/src/actions.ts:36` 的 `fields.title` 是 `maxLength: 80`，`:124-125` 用它；存储 `store.ts:389-393` 的 `normalizeTitle` 是 `[...title].length > 80` 就拒 | 字 |
| Pages 的摘要文档标题 | `:538`（`pageTitle`，`partTitle(title, 1, 1, 80)`，T-180 后 `:556`），传进去的是 `summaryTitle`，即 `L("{title} · 工作摘要", { title: 项目名 })`（`:491`） | 80 | 同上 | 字 |

  所以今天按单元截到 200、80，截得比下游肯收的早：Todo 的标题最长 99 个 😀 加 `…`（100 个字，实际能放 199 个），Pages 的源文档标题最长 `[S1] ` 加 37 个 🙂 加 `…`（实际能放 74 个）。含两单元字的标题其实不多（emoji、生僻的 CJK 扩展字），但开始使用读的是用户的邮件、文档，标题里带 emoji 不稀奇。
- `:492` 的作用：摘要文档的标题放不下时（`pageTitle` 会截），把项目名整个放在正文开头（「项目：…」），免得项目名丢了。它用 `summaryTitle.length > 80` 判断「放不放得下」，数的是单元，和 `pageTitle` 里的数是一回事；改了 `partTitle` 的数法，这一行不跟着改，就会出现标题放得下（≤ 80 个字）却还补一段「项目：…」，或者反过来（放不下又不补）不会出现，因为单元数永远 ≥ 字数；所以只会多补，不会少补。
- 项目名的长度限制在 `:436`（`title.length > 120` 就拒，提示写「1–120 字」）：数单元。所以进到这里的项目名最多 120 个单元，也就是最多 60 个 🙂；`summaryTitle` 再加 ` · 工作摘要` 7 个字。第 6 节的用例选项目名时守着这个限。
- 材料标题（`ref.title`）的来源：`context-onboarding-documents.ts:28`，T-181 之后至多 500 个字（`[...x].slice(0, 500).join("")`）。所以 `[...title]` 展开的最多是 `[S1] ` 加 500 个字，量小。
- 英文界面的部分号是 ` · part {k} of {n}`（`apps/workbench/src/i18n/onboarding-en.ts:8`），宽度和中文的 ` · 第 {k} / {n} 部分` 不同，所以位置要按实际的 `suffix` 量，不写死 13。两种界面的部分号都是一单元一个字的字符，`[...suffix].length` 和 `suffix.length` 相等。
- 项目里已有的写法（T-079，main `bc20f3667`）：`plugins/native/ppt/src/store.ts:279` 的 `[...x].slice(0, n).join("")`，`plugins/native/pages/src/content-actions.ts:42`、`plugins/native/todo/src/organize.ts:116` 同样。

## 5. 做法

统筹已定之外的决定都是起草线定的，照做；觉得不对在【方案】里说，不要自己换（第 8 节写了理由）：

1. **`context-onboarding-service.ts` 的 `partTitle`**：下面的块整个换掉原来的五行（原来的一行文档注释加四行函数）。

   原样（要被换掉的，两个空格缩进）：

   ```ts
   /** A part's title: the name, cut to fit, then which part it is, so the cut never takes the part number. */
   function partTitle(title: string, part: number, parts: number, max: number): string {
     const suffix = parts > 1 ? L(" · 第 {k} / {n} 部分", { k: part, n: parts }) : "";
     return (title.length + suffix.length <= max ? title : title.slice(0, max - suffix.length - 1).replace(/[\uD800-\uDBFF]$/u, "") + "…") + suffix;
   }
   ```

   换成：

   ```ts
   /**
    * A part's title: the name, cut to fit, then which part it is, so the cut never takes the part number. `max` counts whole characters
    * (a 🙂 is one, though two UTF-16 units), the way Todo and Pages count a title, so a cut never ends inside a character.
    */
   function partTitle(title: string, part: number, parts: number, max: number): string {
     const suffix = parts > 1 ? L(" · 第 {k} / {n} 部分", { k: part, n: parts }) : "";
     const characters = [...title], room = max - [...suffix].length;
     return (characters.length <= room ? title : characters.slice(0, room - 1).join("") + "…") + suffix;
   }
   ```

   说明：
   - 放得下的判断 `characters.length <= room` 等于原来的 `title.length + suffix.length <= max`，只是按字；放不下取 `room - 1` 个字，加一个 `…`，正好 `room` 个字，再加部分号，正好 `max` 个字；
   - 原来结尾的 `.replace(/[\uD800-\uDBFF]$/u, "")` 不要了：按字取的数组不会把一对劈开；
   - 一个本来就带落单高代理的标题（`decodeMaterialText` 严格解码，从文件读出来的不会有；只有 T-181 之前存下的、500 个单元处被劈开的才有）：它一定超过 200 和 80，截的时候落单的那个在被截掉的部分里；
   - `suffix` 为空串（一个部分）时 `[...suffix].length` 是 0；
   - `room - 1` 不会是负数：部分号至多二十来个字，`max` 是 80 或 200。
