# 敏感数据与隐私

为涉及个人、健康、财务或机密数据的工作叠加最小化、授权和生命周期约束。

适用于：个人数据、敏感业务数据、跨主体数据共享。

## 规划路径

1. 识别数据主体、敏感等级、处理目的和禁止用途
2. 映射收集、推断、使用、共享、保留和删除生命周期
3. 设计最小化、授权、访问、隔离和可撤回机制
4. 补齐审计、主体请求、泄露响应和供应方约束
5. 用权限越界、撤回、删除和恢复场景验证

## 必须覆盖

| area | label | question |
| --- | --- | --- |
| data_purpose | 数据目的 | 每类敏感数据为何必要，哪些用途明确禁止？ |
| data_subject_control | 主体控制 | 数据主体如何知情、选择、访问、更正、导出或删除？ |
| sensitive_data_flow | 数据流 | 数据从哪里来，到哪里去，谁能看到或推断？ |
| retention_deletion | 保留与删除 | 保留依据、期限、备份和删除证明是什么？ |
| third_party_data | 第三方处理 | 外部服务、模型和合作方获得什么，责任如何约束？ |
| privacy_incident | 隐私事件 | 越权、误传或泄露后如何限制影响并恢复？ |

## 依赖规则

| rule_id | statement | direction_hint |
| --- | --- | --- |
| processing-after-purpose | 数据采集、共享和推断消费明确的目的、最小范围和授权边界。 | data processing depends_on purpose and authorization |
| launch-after-lifecycle-proof | 敏感数据功能发布消费权限、撤回、删除、审计和事件响应验证。 | sensitive-data launch depends_on lifecycle evidence |

## 完成证据

- 数据清单、目的、流向和访问矩阵
- 授权撤回、导出和删除验证
- 第三方处理与事件响应记录

## 收口检查

- 没有为未来可能使用而无目的收集数据
- 用户撤回后数据和权限真实停止生效
- 日志、缓存和备份没有绕过删除边界

## 常见误拆

- 把隐私等同于一份政策文本
- 用用户同意覆盖不必要的数据处理
- 只删除主库不处理派生数据和备份

## 怎样用这份方法

- 先按「规划路径」把事情想完整，再把每个能独立交付、独立验收的结果列成一项；一项里不混入几个主要结果。
- 「必须覆盖」里与当前任务有关的每个问题都要有答案；答不上来的关键问题列为待确认，不用含糊的条目盖过去。
- 依赖只表示结果消费：乙开始或完成时必须用到甲的可验收产出，乙才依赖甲。讨论顺序、时间先后、同一个人负责、改同一份文件都不算依赖；没有结果消费关系的保持并行。逐条判断「依赖规则」，不适用的要说得出缺了哪一种产出消费。
- 每一项写明完成时拿什么证明（见「完成证据」），收尾前过一遍「收口检查」。
- 只描述有限、能完成的改变；持续运行的事不写成永远做不完的一项。
- 和别的规划方法一起用时，把各自的关键结果放在一起看谁消费谁，缺了提供方的再补上相应的方法。
- 拆出来的结果先给用户看。用户要落到某个工具里（例如已装的 Goals 插件）时，用那个工具自己的动作写入，由用户确认。
