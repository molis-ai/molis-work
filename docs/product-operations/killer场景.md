## 1. 结论先说

**定位：Molis Work 是你用的那些 AI 之下共用的一层本地工作台。** Claude、ChatGPT、Cursor、Notion 等已把项目、记忆、定时与连接器打包进云端订阅，Molis Work 不与它们拼「谁更会干活」，而补它们各自缺的一环：**目标级的要求、依据、本人验收与改约定审批带版本留在你本机，同一个动作目录给界面、内置助理、工作流和外部 AI 共用，交付时固定采用的材料版本**（[外部补研 §1、§6](research/2026-10-18-外部补研.md)）。

## 3. 主推剧本

### K1 多个 AI，一本账

> **Agent 说做完了，Work 说还差你。**

- **给谁**：同时用两家以上 AI 编码工具的独立开发者、技术负责人与开源维护者（代表归档卡：`DEV-01`、`AIDEV-01/02`、`TL-02`、`QA-01`、`OSS-01`）。
- **Work 怎么做**：
  1. 在按需启用的 Goals 中立一条目标，挂接平台要求与认可（`modules/acceptance`），把「手机端真机验收」标为**必须由本人验收**；项目规则写入平台项目指导（`modules/projects`）。
  2. Claude Code、Codex 等经一键配置的 MCP 动作目录（第 44 批已删除 `goal-advance` Skill，直接通过已授权动作描述发现能力）读写同一份目标并上报进度与依据（写明为 Agent 报告）。
  3. Agent 提出放宽范围或取消本人验收时，走平台可信决定入口（`horizontal/project-approvals`），在工作台「等你」与决定请求卡中写明影响，等本人核对精确版本拍板；没有有效授权即被拒绝。
  4. Agent 请求收尾时，缺依据、缺本人验收或存在阻塞则收尾不生效，页头明确列出未满足项；需要接续本机终端时可按平台对象工作终端服务显式打开 TUI，另可通过外部会话服务（`horizontal/sessions`，10 适配器）只读查阅分散在各外部工具里的历史会话摘要。
- **60 秒演示**：目标三条要求（手机排版标本人验收）→ Claude Code 经 MCP 报前两条测试依据（Agent 报告）→ Codex 读取同一份目标与最新项目指导 → Codex 提议删掉旧数据兼容，工作台弹出决定请求，你点拒绝 → Codex 报完成被收尾门禁拦截，标明「完成要求 2/3 已满足」→ 你真机验收并记结论，收尾生效。
- **成熟度与瓶颈**：目标、要求、本人验收、决定留痕与五家 MCP 接入核心 **已发布 · v0.2.0（源码）**；平台统一决定/认可/终端、逐客户端授权与外部会话只读索引 **main 可用 / main 部分**（原菜单栏胶囊已于第 44 批删除、待按全插件重做；外部会话恢复与跨工具交接控制仍在 BL-177 规划）。瓶颈：缺签名安装包（A1）、外部 Agent 自报尚未由机器自动复核（B1）。
- **验证与推翻**：找 5 位双 AI 开发者拿真实小功能跑三天，中途换 Agent、改约定、留本人验收；若仍维护两份账或仓库规格 + CI 同样省事则推翻。

#### K1 约定版：约好的事，改了要你点头

面向不写代码的自由职业者、产品经理、法务、销售与学术返修者（代表归档卡：`FREE-02`、`PM-01`、`LAW-02`、`SALES-02`、`ACA-04`）：把交付范围与底线写成要求，变更经决定记录留痕，约定一改旧验收作废。**限制**：客户与合作方暂无法直接进入 Work，由本人代记；痛感与 K8 一并在首轮访谈验证。

### K2 交出去的判断，答得上依据

> **交出去的每一份结论，都留着当时的依据与版本差异。**

- **给谁**：独立顾问、行业与投研分析师、产品经理、研究型作者、法务（代表归档卡：`CON-01`、`LAW-01`、`INV-02`、`DATA-02`、`SALES-06`；原 `UX-01` 涉及的本机录音转写按决定 68 不再以 `jelly-whisper` 作为卖点）。
- **Work 怎么做**：
  1. Feed 订阅 RSS/Atom、网页查询、YouTube、GitHub、Gmail（表头与摘要片段），按规则筛入 Inbox 并注明命中规则。
  2. 勾选 1–20 条可读材料生成 Pages 文稿，文末自动附带本次采用的**材料快照、来源与版本**。
  3. 选中段落让助理挑反例或改写，审阅后放回原位；存为成果库固定版本交出，并可按需导出 PPTX 或记带来源待办。
  4. 新一轮修订后再存固定版，可用 Pages 现役的**固定版本逐段差异对比（`pages.artifacts.diff@1`）**直接查看两版文字改动前后；被追问时打开交出的那一版即可回查当时材料。
- **60 秒演示**：Inbox 6 条标明命中规则 → 勾 4 条生成一页带本期采用材料附录的文稿 → 选段让助理提反例并插回原位 → 存固定成果并导出 PPTX → 一周后客户追问，打开固定版回查当时依据，修订后用固定版逐段对比看清两版差异。
- **成熟度与瓶颈**：Feed→Inbox→Pages 带快照成稿（需模型）、成果固定、固定版逐段对比与 PPT 基础导出 **main 可用**；账号来源依赖正式 OAuth 发布配置（A3），出处自动贯穿 PPT（D3）与 Cognia 来源变化自动复核清单（D2）仍在规划。
- **验证与推翻**：找 3 位周报作者同一专题连做两期，含一次客户追问与一次材料更正；若 20 条上限不够或原有 Feedly + NotebookLM 流程更顺则推翻。

### K8 你答应的、在等别人的，分开记（先验痛感）

> **AI 抽了 8 件事，Work 说 3 件你已经记过、1 件在等法务。**

- **给谁**：项目经理、交付协调、产品经理、自由职业者、财务与人事（代表归档卡：`PMO-01`、`FIN-02`、`FREE-04`、`TL-04`、`HR-03`）。
- **Work 怎么做**：把会议纪要或邮件正文放入 Pages 或待办整理入口 → AI 按「要你处理 / 你的承诺 / 在等别人 / 可考虑建议」四栏抽取，每条绑定原句 → 与已有待办比对标出可能重复或改期 → 相对日期由程序确定性换算（不让模型算日期）→ 确认采用（整批可撤销），等别人的记清对象与跟进日，到日首页提醒，催办草稿由助理起草、本人发出。
- **60 秒演示**：贴 2000 字周会纪要 → 抽出 8 条分四栏且带原句 → 标出 3 条已记过、1 条建议改期 → 「下周三」确定性换算具体日期 → 跟进日首页出现提醒，一键起草催办。
- **成熟度与瓶颈**：**main 可用**（需模型）。瓶颈：尚缺外部痛感访谈证据、重复识别准确率未系统评测（J1）、尚缺按月/季重复（H10）与等待天数计数（J4）、提醒仅在本机服务运行时出现（A5）。

### K3 一句话长出你和 AI 共用的工具（开发中演示）

> **缺个工具？交给平台创作台，做出来的插件你和你的 AI 调同一份。**

- **给谁**：一人公司、自由职业者、运营、独立开发者（代表归档卡：`DEV-06`、`FREE-01`、`FIN-05`、`QA-05`、`LAW-06`）。
- **Work 怎么做**：在平台自带的**插件创作台**（`horizontal/plugin-studio`，非插件）描述需求 → Agent 产出方案、代码与测试 → 宿主检查、打包并在沙箱试跑 → 本人确认权限后安装，其操作进入同一套动作目录，界面、助理、工作流程与外部 MCP 客户端共用同一份本地数据与逻辑。
- **成熟度与路线**：当前基础创作链路为 **main 部分**（从想法到安装、独立使用与修订的完整体验仍在 **BL-377** 推进，不对外宣称「一句话稳出商用系统」）。**说明**：旧炼金术士已于第 44B 批删除；按决定 68，后续组合场景不造第三种包格式——纯组合产 `Blueprint`（`horizontal/blueprints`），确需独立领域表时补最小插件（如第 82 批重建薄领域表 Alchemist），并在创作台支持重开编辑。
- **验证与推翻**：用 4 个真实小工具（发版清单、报价前核对、选题库、面试评分表）连续跑 4 周，覆盖规则变更、失败恢复与数据导出；若维护成本高于表格或每次需作者救火则推翻。

### K4 你攒下的做法，换哪个 AI 都在（开发中演示 · 增长入口）

> **规则和做法写一次，你用的每个 AI 都照着做。**

- **Work 怎么做**：把 `CLAUDE.md`、`AGENTS.md` 与外部工具里的 Skills 导入为带版本的角色（`modules/characters`）或写入项目长期指导（`modules/projects`）；系统和插件提示词可在设置中查看修订并追踪版本；系统自带 37 份「规划与拆解」技能包可供助理选用。
- **成熟度与瓶颈**：项目指导与提示词管理 **main 可用**；角色导入 **main 部分**；导入技能升级为按需披露的通用技能包与自动选用、以及导出分享仍在规划。

### K5 第一天就有内容（开发中演示 · 激活入口）

> **新项目第一天：把材料丢进来，一分钟理出项目起点。**

- **Work 怎么做**：新建项目时选择本机文件夹、文档、浏览器或授权来源（可跳过，本机文件分批读取带进度且离开可续），生成带来源的项目摘要、来源文稿与待办草稿；授权后亦可结合外部会话服务（`horizontal/sessions`）查阅既有编码工具上下文。
- **成熟度与瓶颈**：**main 部分**（需模型）；正式 OAuth 发布配置（A3）、按用途预览配置的首日旅程闭环（A6）与角色模板包（I1）在路线书推进中。

### K6 打开就知道今天先做什么（演进中 · 底座已合入）

> **状态、变化、风险与待你处理收在一页，点一下接着做。**

- **现役已落地底座（修正旧文档过时判断）**：
  - **工作简报（`plugins/native/work-brief`）** 已合入主线（项目与个人双实例），经首页概况把带精确版本依据的现状摘要交由平台首页（`horizontal/home`）呈现，人工修改不被新草稿覆盖，读不到的来源标过期/缺口、不编造。
  - **风险（`plugins/native/risk`）** 已合入主线，记录项目风险、关联对象并委托 Schedule 安排复查。
  - **Schedule 对话任务已解除「只能读文件」限制**：现已接入平台任务授权（`agent.task_grants.*`）与 `brief` 角色，可在本人勾选的类别范围内只读项目数据（待办、Inbox、目标等）；无授权类别时才回落为只读项目目录的 `reader` 角色。
  - **主线与后台任务总表（`horizontal/mainline`）** 及 **工作记录采集（`horizontal/observation`）** 均已落地。
- **尚未闭环（规划中）**：每日自动定时出简报、主动发现异常与连续后台交办、以及电脑休眠后的补跑策略（A5）仍在路线书推进；本机服务未运行时定时不触发。

### K7 一封客户邮件，变成团队的一个目标（愿景 · 官网标「开发中」）

- **目标形态**：客户邮件进 Feed/Inbox → 项目讨论群确认结论 → 升格目标并交 Agent 推进 → 同事按权限共享项目、实时增量共编文稿并由对应负责人验收，团队记忆沉淀决定与风险（个人空间与个人外部会话保持隔离）。
- **成熟度**：本机项目讨论 IM 与 Agent 任务板为 **main 部分**；多人共享、实时共编与团队记忆属服务端批 `SRV-1`～`8`（**规划**，按负责人决定官网对外标「开发中」）。

## 4. 支撑场景（S1–S3）

- **S1 选中就交出去，结果回到原处**：选区一键转待办/灵光/文档/目标提案，右栏 Shelf（平台部件）选段拖入 Pages 并在原位预览替换（浮条评估与落点全覆盖为 `main 部分`；统一输入框与原生听写＋云端轻量语音双通道在规划）。
- **S2 重复的处理，存成你说了算的流程**：Workflows 串联 Feed/Inbox/Pages/Forms/Dataset/PPT 等内容站与授权动作，配合判断规则拦截异常、保留每次运行快照（`main 部分`）。
- **S3 AI 能动手，但动不了不该动的**：外部 AI 按客户端逐项授权、撤权即拒且取消零业务写入；外部内容标不可信材料缓解注入；Computer Use 默认关闭并把银行/支付/密码管理器/系统设置列入禁区（`main 可用 / main 部分`）。对外只讲「具体拒绝了什么」，不泛称「数据不出本机」。

## 6. 不做或降级的场景

- **会议录音采集与转写**：Granola 等已成熟且开放 MCP，更适合作为上游来源接入；决定 68 亦已明确退役本地 Whisper 大包转写。
- **专业法律/合规依据库**：缺乏行业法规库与责任界定，仅服务通用文档依据留痕，不以法律审阅品类竞争。
- **泛化团队知识库 / 重型 CRM / 每日新闻群发**：由 Notion、飞书、Feedly 等覆盖，不正面硬拼。
- **对写文档读者主推「换 AI 轮流写」**（负责人 10-16 决定）或以「AI 帮你写软件」替代「做出来的工具你不用自己养」。
