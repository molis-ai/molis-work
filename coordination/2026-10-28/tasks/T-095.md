> **这条在 main 上成立：「AI 生成题目」的动作 schema 按字数数要求的上限，Form 自己却按 UTF-16 单元数。**
> - `form.questions.draft@1`（`plugins/native/form/src/actions.ts:47-49`）的输入 schema 是 `FORM_DRAFT_INPUT_SCHEMA`（`src/drafting.ts:25-27`），其中 `prompt` 是 `maxLength: 500`（`:26`）。

## 1. 背景

- 合同口径（按 Unicode 字符）：
  - `plugins/native/form/src/drafting.ts:25-27`：`FORM_DRAFT_INPUT_SCHEMA`，`:26` 的 `prompt` 是 `{ type: "string", maxLength: 500 }`；
  - `plugins/native/form/src/actions.ts:47-49`：`form.questions.draft@1` 用它作输入 schema；
  - Ajv：`packages/kernel/src/action-schema.ts:41-42` 的选项、`:79` 的 `new Ajv(options)`。没有 `unicode: false`，`maxLength` 走 Ajv 的 `ucs2length`，按码点数。
- 按 UTF-16 数的一处：

  | 位置 | 现在的写法 | 谁会走到 |
  | --- | --- | --- |
  | `drafting.ts:115`（`draft`） | `      if (!request \|\| request.length > 500) throw formErrors.invalid("生成要求须为 1 到 500 个字");` | `actions.ts:107-116` 的 `form.questions.draft` 处理器在 `:111` 调 `drafting.draft`。`request` 在 `:114` 取：第一次是 `input.prompt.trim()`；回答补充问题后是当初存下的要求（`:126` 存的就是过了 `:115` 的那个值） |

- `!request` 只问是不是空的，不改。
- `:115` 量的是去了首尾空白的要求，schema 量的是原值；去空白只会变短，本单只换数法，不改量哪个值。
- `formErrors` 是 `defineErrorCodes("form", …)`（`src/error.ts:7-8`），`defineErrorCodes`（`packages/contracts/src/platform/action-errors.ts:109-115`）给的码是 `form.invalid`。
- 改了以后，下游放得下，起草时逐处读过：
  - 要求只作材料交给模型：`:117` 放进 `data`，`:118` 经 `instructed`（`packages/contracts/src/platform/model-prompts.ts:39-41`）原样交出，不截不限；
  - 要求不存进问卷：模型拟的题由 `actions.ts:113` 的 `store.update` 存，存的是题，不是要求；
  - 先问补充问题时，要求只留在内存里（`:126`），回答后原样再交给模型（`:114`）。
- 没有测试量到这一处：`tests/form-draft-questions.test.ts` 的要求都是 `fixture` 给的「做一份试用反馈问卷」（`:41`）。
- 页面不受影响：页面包从 `src/browser/factory.ts` 打，`src/browser/**` 里不是 `import type` 的引用只有 `browser/fields.ts:2` 引 `../fillpage.js`，`fillpage.ts` 只 `import type`（`:1`）；不引 `../drafting.js`。所以 `/assets/molis-work-plugins/form.js` 的字节不变（`tooling/gates/page-assets.json:23`）。

## 2. 目标

1. 500 个非 BMP 字符（如 `🟢`）的要求原样交给模型，拟的题照常追加进问卷；501 个仍以 `form.invalid`「生成要求须为 1 到 500 个字」拒，不问模型，不写问卷（`RAC-1667`）。

上限本身不变。

```ts

test("RAC-1667 a drafting request is counted in Unicode characters like the action schema: 500 go to the model whole, 501 are refused before it is asked", async t => {
  // FORM_DRAFT_INPUT_SCHEMA (src/drafting.ts) counts characters; one 🟢 is one character but two UTF-16 units.
  const wide = (count: number) => "🟢".repeat(count);
  const f = await fixture(t, [DONE, DONE]);
  const done = await f.call({ prompt: wide(500) });
  assert.equal(done.status, "done", "a 500-character request is drafted");
  assert.equal(done.form.questions.length, 3);
  assert.equal(f.heard.length, 1);
  assert.equal(JSON.parse(JSON.parse(f.heard[0]!).data).request, wide(500), "the request goes to the model whole");
  await assert.rejects(f.call({ prompt: wide(501) }), { code: "form.invalid", message: "生成要求须为 1 到 500 个字" }, "501 characters is still past the limit");
  assert.equal(f.heard.length, 1, "the refused request did not reach the model");
  assert.equal(f.forms.get(f.form.id, "p").questions.length, 3, "and wrote nothing");
});
```

3. 几处为什么这样写，别改：
   - 用 `🟢`（U+1F7E2）：一个码点、两个 UTF-16 单元，没有变体选择符。T-077、T-079、T-080、T-090、T-091、T-092 和 `tests/content-owner-regressions.test.ts:58` 用的也是它。
   - 值正好压在上限上（500），多一个（501）就拒，才分得清按字数和按单元。不要缩短。
   - 直接调处理器，不经动作服务：schema 按码点数，501 个 `🟢` 的要求本来就过不了 schema。本单要证的是主人不再多拒，只能直接调处理器。文件里已有的用例也这样调（`:38`、`:41`）。
   - 假模型排两条 `DONE`：第二条只在第 6 节 M2 放过 501 个字时才用到，让那个变异红在「501 characters is still past the limit」那句，而不是红在假模型没有答复上。
   - `f.heard` 每次记的是 `JSON.stringify(prompt)`（`:37`），`prompt` 是 `instructed` 给的 `{ instruction, data }`，`data` 是 `:117` 的 `JSON.stringify({ request })`。所以解两层 JSON 读出 `request`，证明 500 个字没被截。
   - `assert.rejects` 的第二个参数比对 `code` 和 `message`：抛的是 `formErrors.invalid(…)`，码是 `form.invalid`，文案原样。
   - 只用文件里已有的 `assert`、`test`、`fixture`、`DONE`（`:1-42`），不加 `import`。
