## 本批核账（2026-11-04，E 轨只读核查；基线 main `063b036bd`，没改任何产品代码）

**结论（先看这几句）**：

1. **读数据的动作基本都有。** 待办、Inbox、日程（Jelly 日历）、目标各有公开的只读查询，内置 Agent 受众都能看到；缺的主要是「定时任务这条路接不上它们」，不是缺查询。
2. **接不上的原因有三处**，都在 Schedule 到点启动 Agent 这一条线上：①Schedule 的角色是「要项目目录的只读角色」，只带读文件和搜索，没有动作入口；动作入口（能力网关）只给「不碰目录的业务角色」；②平台替插件启动 Agent 的服务从来不请求动作入口（Assistant 启动时会请求，插件启动时不请求）；③内置 Agent 默认只放开项目资料类读取，待办、Inbox、目标、日历的查询要在「对外接入」里逐条授权。
3. **这一批不一定要改公开合同。** 平台启动 Agent 的请求里已经有 `action_gateway` 字段（`packages/contracts/src/services/agent-host-start.ts:340`），合同注释也写着业务角色「真正的工作是启动时给它的统一动作」（`packages/contracts/src/platform/plugin-agent.ts:22-23`）。所以最小改法只动宿主里的 `apps/local-host/src/plugin-agent-service.ts`、Schedule 自己的角色与任务，不加字段。
4. **与 02② 的关系**见下文「和 02② 的重叠」：主体不碰它的共享核心文件，可以按第 21 项提前开工，但有三个贴边处和一个前提。
5. **需要统筹或用户裁定的一件事**：内置 Agent 对待办、Inbox、目标、日历查询的授权怎么给（见「待裁定」）。

### 今天 Schedule 怎么跑

到点后 `plugins/native/schedule/src/runtime-wakeups.ts:36-41` 调 `services.agents.run({ role_id: "reader", ... })`；角色在 `plugins/native/schedule/src/roles.ts:5-20`：`execution: "read-only"`、`host_tools: ["read-file", "search"]`、没写 `workspace`（即必须有已授权的项目目录）。就绪检查 `tasks.readiness` 只看「文字模型」和「项目绑了工作区」（`plugins/native/schedule/src/actions.ts:50`）。认领板与原需求里提到的 `apps/local-host/src/schedule-task-runner.ts` 已经不存在，现行位置就是上面这两处（产品建议 E1 的路径需订正）。

### 用户的决定（2026-11-04）

经统筹转达：

1. **按任务勾选授权**：建定时任务时由用户勾选它能读哪几类（待办、Inbox、日程、目标）；这份授权只给这一个任务，可以随时撤回，不跟助理共用。核账里原列的三种做法以此为准（近于原方案 ①，但授权主体是任务，不是共用的内置 Agent）。
2. **「日程」口径**：Jelly 日历加 Schedule 的提醒；待办的日期算在待办查询里。
3. **任务种类**：读文件的任务与读数据的任务是两种；按实施方案，种类由有没有任务授权决定，不改 Schedule 的表。
