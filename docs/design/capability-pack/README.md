## 已定的规则（用户 2026-11-09）

```
能力包（写作工具 · acme.writing 2.0.0）
├─ 角色和它的提示词
│   └─ 写作编辑 ── 写作编辑的说明
├─ 技能：写周度复盘、会议纪要、排日程
├─ MCP：（没有）
└─ 工具：read_file、write_file、web_search
```

**包怎样划分（照合同第 4 稿，`contract-design.md` §4.1–4.5，每次读的时候算出来，不存）：**每个插件一个包（应用插件和第 08 批内容包一样，里面有什么由它自己的声明写）；另有两个系统包——「Molis Work 自带」（个人助理和它的提示词，宿主自有主人的角色与提示词如创作台、Alchemist，全部 Agent 工具、对外的 Molis Work MCP 与 goal-advance 技能、平台自己的连接带的 MCP）和「你的角色」（你写的角色，各带自己声明的工具；角色的工作方式不算提示词）。插件包里的工具是它的角色的工具名单合起来算的；提示词靠 `role_id` 挂到角色下，没有的挂在一行「个人助理」下——这一行只是引用自带的个人助理，不是一份拷贝。技能、MCP、提示词各只在一个包里；工具可以在几个包里。

原型里的包：Molis Work 自带、你的角色、写作工具（内容包）、Coding、Goals、Feed、本机导入 · Claude Code（内容包）、法务审阅（内容包，插件停用）、合同助手（已卸载）。

1. **页面先是能力包列表**；一个能力包下面列它的技能、MCP、工具，以及搭配的角色，**角色带着自己的提示词**。
2. **方案 A**：左边能力包列表，右边选中那个包；包里的一条就在右边打开，顶上一行「回到「包」」和路径（包 / 角色 / 这一条）。
3. **没有归属角色的提示词默认归个人助理**：在包里挂到「个人助理」角色下，行上写「没有归属角色，默认归个人助理」，详情里写「没有归属角色，默认归「个人助理」」；不单列「其他提示词」。这一行写「Molis Work 自带的个人助理，这里只是引用」。示例：Feed 包没有自己的角色，「消息摘要」「消息分类」挂在个人助理下；写作工具包里的「提纲要求」也是。
4. **用户自己组包本批不做**：原型里没有自组包。
5. **没有整包停用开关**：包的状态从它装的东西和它的插件读出——在用；N 项要处理（逐项写出，如「排日程：暂时用不了」）；已停用（插件停用，去处「启用插件」）；已卸载（**只给包头**：名称、版本、一句说明和「重新添加…」，不列卸载前的条目，也不列已删除的 MCP 服务器）。「要处理」只看能不能用（合同 §4.4：`attention` 只看 `availability`）；提示词「默认已更新」不算要处理，只在那一行和它的详情里提示。「已卸载」用中性色，不用红。两个系统包只会是「没读全」「N 项要处理」或「在用」。有上报者失败、它的条目可能在这个包里时，状态是「没读全」（合同的 `unknown`），不报「在用」。
6. **工具用量只显示「最近一次」**，界面里不出现批次号；范围说明写「工具只记最近一次是什么时候」。界面里也不出现内部名（Agent Host、Prologue SDK）：工具的来源写「Molis Work 自带」。读不到最近一次的工具（合同的 `not_counted`，如 fetch_url、change-reversible）不出用量一节，不写次数也不写原因。
7. **英文名 AI kits**（单个叫 AI kit）。
8. **设置页合并**照下文的表。
9. **按类别筛（CPK-01，用户原话 R1；主会话 2026-11-09 定）**：工具条里加「按类别看」——全部类别 / 技能 / 提示词 / 角色 / 工具 / MCP，与状态筛并存。选一类后，各包只显示那一类（选「提示词」时显示带提示词的角色卡），没有这一类的包不列出，行上的图标计数与顶上一句（「2 个能力包里有 MCP」）随之变；搜索也只在这一类里找。合同第 4 稿去掉了 `kit.catalog.list@1` 的 `kinds` 输入、改在页面里筛，正好一致。

另外沿用第一轮定好的写法：每条的「现在」一块写状态与去处；用量写清范围（「近期 N 次」「只有最近一次」）；MCP 三种「开」分三行；提示词不显示正文，改去「提示词」；技能是 08 那一块原样。工具是系统的，几个包可以声明同一个，工具详情列「在这些能力包里」；谁真正能用，仍由角色的工具名单决定。

## 为什么选 A，为什么不要 B

**选 A 列表＋包详情**：

1. 正好是要的层级：包列表 → 一个包 → 角色带提示词、技能、MCP、工具，同屏摊开，不切页。
2. 常用路径最短：看一个包 1 步（点包）；看一条并去改 2 步（点那一条 → 去处按钮）；开关技能 2 步；换包 1 步，左边列表一直在。
3. 注意力和认知负荷：一屏同时看到「有哪些包」和「这个包里有什么」；列表行末的状态让你不用点开就知道哪个包有事；打开一条后路径一直写着，不迷路。
4. 和 08 一致：同一个列表＋详情部件，技能那一块原样；组件板新增少。
5. 三种宽度都成立：窄屏一次一边（包列表 → 包 → 一条），每层顶上有回去的按钮。

**不要 B 包卡片＋包内目录**（卡片页 → 进包页，包内是 08 的分组列表＋详情）：

1. 每次多一步：常来的人都得先进包；换包要先回卡片页。
2. 两种画面要记得自己在哪一层；包头和列表一起占掉首屏上半截。
3. 多出两件组件板新增（能力包卡片、缩进的提示词行），只为一个页面。
4. 它的长处（第一次来一眼看全部包）A 的列表行（名称、计数、状态）已经给到大半。

第一轮的「五类按类汇总的一张目录」（A 一张目录、B 先总览、C 按来源）不是用户要的模型，整体否掉。

### 交互与动效

- 打开一个包、打开一条、回到包时，右边从下方轻轻升起（`craft-rise`、`--dur-move`、`--ease-quint`），首次打开不播；导出菜单、导入面板同样升起；`prefers-reduced-motion` 下都不动。
- 窄屏（列表＋详情部件自己的容器宽度 ≤ 640px）一次一边：包列表 → 包 → 一条，每层顶上有回去的按钮，焦点移到新打开那一层的标题。
- 宽屏时右边贴在滚动区顶上，比滚动区高时自己滚；滚到头后滚动照常交给整页（不用 `overscroll-behavior: contain`）。这是页面要时才开的修饰 `data-sticky-detail`，08 技能页不变。滚动区的高度应由设置外壳给出（`--settings-view-h`，今天没有，原型量出来写上，见「kit 缺的」）。
- 从一条回到包时，焦点回到刚才打开的那一行。
- 搜不到时列表里一句加「清除搜索」，右边是空状态（同样带「清除搜索」）；按类别筛空了时给「看全部类别」。
- 搜索同时找包和包里的东西；按包里的东西找到时，那一行写「包含：写周度复盘」。
- 技能改三档立即生效，提示里可以撤销（照 08）；导出菜单是组件板 `mw-menu` 一层面，放在顶层（popover API），从「导出这个包」下沿展开、不盖按钮，也不被会滚动的容器裁掉；下面放不下时先把按钮滚上去，再不够就菜单自己滚；左右不出窗口。「导出这个包」排在这一行最后，菜单不会盖住旁边的按钮。Esc 关上，焦点回到「导出这个包」。
- 英文界面按英文拼：冒号、分号、括号、列举的逗号和标题后的计数都用英文标点，不混中文标点。

## 模拟边界

- 数据是编的（`data.js`），不读任何 Home，不调任何动作。
