# 第 27 批 Jelly 工作区读写成本

状态：本片工程验证通过（2026-11-09，负责人 Codex），待统筹合回批次分支并验证最终集成。

[第 27 批第 5 项](../../../post-anticorruption-roadmap/reference/batches/27.md#batch-27-item-5)承接 [N25](../../../../docs/reviews/adversarial-review-2026-11-01.md)，性能实测同时对应[第 2 项](../../../post-anticorruption-roadmap/reference/batches/27.md#batch-27-item-2)。普通操作从动作处理器进入 Jelly Home Runtime 的数据库事务。现状是一次命令调用 `initialize()` 和 `read()`，两次取同一行并完整解码。命令暂存复制整库，日历再复制一次并校验，保存前和 SQLite 回读再校验，返回时又复制。每次普通写还会两次为全部笔记写版本记录。

一次命令只解码一次 SQLite 当前工作区，在这份本次命令独有的对象上编辑。普通笔记和日历操作验证改到的记录和相关约束，整体导入、历史恢复以及跨记录的复杂改写保留对应的完整校验。提交前验证变更内容的实际 JSON 形态，SQLite 回读核对版本、内容和校验值。保留原事务、版本冲突和确认机制，写已新增、修改或被移除的笔记版本，不按全库笔记数重复写。命令编辑记录只列这次改到的对象和关系组，复用完整校验所用的同一份对象与关系规则。公开 calendar 和 content 入口使用独立的暂存对象，成功才发布修改。直接 content 调用的失败原子性另作回归，生产命令此前已经由事务隔离。

范围为 `plugins/native/jelly/src/store.ts`、`calendar.ts`、`calendar-validation.ts`、`content.ts`、`index.ts` 和私有的 `workspace-edit.ts`、`content-validation.ts`，以及 `tests/jelly-content.test.ts`、`tests/jelly-calendar.test.ts`。已由 HTTP、Agent、MCP、工作流和内容站点使用的动作及对象读取合同沿原入口。既有单行 JSON 和历史快照结构继续使用，整库编码与传输成本仍随内容增长。真实 Home、浏览器界面、SDK、合同、同步协议、版本与门禁在本片范围外。

## 验收

- **JLY-27-01** 在同一 Node 24.15.0、本机 SQLite WAL、相同小型、代表性合成和较大工作区下，比较读、编辑有排期任务的笔记、完成关联事项和移动普通事项。记录样本数、耗时中位和 P90、操作前后 JS 堆增量中位、SQL 调用及全工作区校验和深复制次数。普通写消除重复的整库验证与复制，笔记版本写入量与实际改变的笔记有关。真实用户规模若无授权样本则保留证据缺口。
- **JLY-27-02** 普通笔记、事项、重复、分类、跨对象关联与任务同步继续持久化正确，错误输入不修改业务记录。旧读取与旧命令返回的快照不被后续修改或输入对象改动影响。
- **JLY-27-03** 完整拒绝校验值错误和校验值正确但内容无效的工作区、导入及历史。若提交失败，当前状态、历史、版本与预览均回滚。成功确认单次消费，成功无变化操作版本不增加。
- **JLY-27-04** 工作区 revision 冲突仍拒绝，笔记 revision 经过撤销、重做、删除后恢复仍高于旧草稿。Runtime 撤权与取消继续在原事务权限点拒绝。
- **JLY-27-05** 公开直接命令在失败时保持调用者状态原样，继续使用原签名、命令和错误 owner。复现基线 content 已把笔记标题和区块发布给调用者后才报关联任务错误，新增用例覆盖同一失败。

- **JLY-27-01** 通过。基线与候选共用同一数据构造、命令和统计探针。真实用户规模、HTTP 传输、页面反馈仍待后续证据。
- **JLY-27-02** 通过。定向用例执行真实 SQLite 读写，核对事项与任务双向同步、重复实例和笔记关联迁移、分类重新分配、非法日历命令拒绝，以及旧读取、旧写入结果与输入的独立性。
- **JLY-27-03** 通过。包括校验值正确的无效 DB 与历史、导入拒绝、稀疏标记数组序列化成无效 `null` 时不写入，及 SQLite 触发器改写提交内容后的整笔回滚。失败后原预览可再用，成功只用一次；无变化的导入保留 revision。
- **JLY-27-04** 通过。不同连接的旧 revision 被拒；笔记退出工作区后重启再重做，版本仍高于原最高值。隔离 Home 的 Runtime 探针在事务前等待授权时分别取消、撤权，验证业务表和预览原样，恢复授权后可用同一预览完成。两条同版本真实动作并发发出，只提交一条。
- **JLY-27-05** 通过。公开 content 同一失败操作在基线泄露部分修改，候选保持原对象内容；公开 calendar 的原子性用例通过。TypeScript 语义对照检查 86 个导出名（58 个值、29 个类型，`JellyStore` 同时有两种含义），本片涉及的公开函数、类构造与成员签名一致。
