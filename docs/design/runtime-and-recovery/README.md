第 25 批（本机常驻与升级 U1～U3）和第 26 批（M1 发行准备与升级 U4～U6）都写了「先定样」，两批的界面是同一件事的两半：Molis Work 在后台怎样一直干活、某一块出问题时怎样说、新版怎样装上和退回、第一次打开时怎样自检、上次出事后怎样恢复。所以合成一份可点的预览。

画面用的是产品自己的框架和组件板实件：页面加载 [`../_catalog/`](../_catalog/README.md) 生成的产品样式表，到达开场和工作台底栏用 `arrival.css`，设置页用 `settings.css`（两张表按画面切换，和产品换页一样）。部件用组件板的 `mw-*` 标记。只有 macOS 的菜单栏和桌面是原型画的，因为那是系统的东西，不是我们的产品。本目录只剩版面编排（`proto.css`）和交互（`app.js`）。

## 怎么打开

在仓库根目录运行，然后打开 <http://127.0.0.1:4431/runtime-and-recovery/>：

```sh
pnpm build
node docs/design/_catalog/export.mjs
python3 -m http.server 4431 --bind 127.0.0.1 --directory docs/design
```

第二步生成产品样式（`docs/design/_catalog/dist/`，不入库）。不跑这一步，页面没有样式。顶部斜纹条是原型控制，不是产品界面：选话题、状态，切中英文和深浅色，「从头再来」清掉点过的东西。数据全是示例，点按钮只在本页里变化，不连任何服务。

## 原型没做的

- 菜单栏、桌面与系统通知都是画出来的，不是 macOS 的真实控件；真实的菜单栏图标和面板尺寸以实现时的系统规范为准。
- 副本演练、升级、回退、修复组件的时长与结果都是定时器模拟；「重启后正在升级」的进度按每步 0.65 秒走完。
- 进度存在浏览器的 `localStorage`（`molis-proto.runtime-and-recovery.v2`）；`window.protoJump` 只用于截图时直接跳到某个状态，不是产品接口。
- 诊断号是示例；导出的文件不会真的生成。
- 插件页面的内容只画了首页与说明卡，其余页面不展开。
