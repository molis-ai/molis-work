先讲清楚，Molis Work 到底在做什么

它不是把消息堆进任务列表，而是让一个结果从出现、执行到验收，始终有上下文、责任和证据。

从一条信息，到一个被验证的结果

Molis Work 把外部信息、个人行动、团队 Goal、人和 Agent 的执行、交付物与验收连接成一条可继续的工作主线。用户知道现在该处理什么，团队知道结果是否真的完成。

信息不自动变任务 外部内容先进入 Feed，由用户决定忽略、保存还是行动。
小事不必成为 Goal 轻量事务保留为 Action，需要持续投入和验收时再升格。
结果必须可以证明 执行带回 Artifact 和 Evidence，经过 Review 才进入共同真相。

3 分钟讲解稿

先讲问题：今天的信息散在邮件、消息、网页和本地工具里，任务被建立后又常常失去来源、执行过程和验收证据。

再讲方法：Molis Work 先把内容作为 Signal 放入 Feed。用户可以忽略、建立轻量 Action、关联已有 Goal，或者创建新的个人 Goal。

接着讲协作：个人工作需要进入团队时，通过 Promotion 提交为 Team Goal。成员或 Agent 认领后执行，必要时交接，产出 Artifact 和 Evidence。

最后讲结果：Review 判断验收条件是否成立。身份、权限、同步和恢复贯穿全程，让工作跨设备、跨成员和跨会话继续，而不是重新开始。

一条连续的工作主线

对象不会被悄悄改成另一种类型。每一步都创建清楚的关系，保留来源和决定。

接收信息 连接邮件、IM、RSS、网页、本地文件和应用。 Source → Signal → Feed
判断是否行动 忽略、保存、建立 Action，或关联已有 Goal。 FeedEntry → Action
定义结果 建立可澄清、拆解和验收的个人 Goal。 Goal + Criterion
进入团队 披露必要信息，提交提议，接受后成为 Team Goal。 Promotion → Team Goal
认领并执行 成员或 Agent Claim、Run、Handoff，保留真实状态。 Claim → Run → Handoff
交付与验收 结果、证据和决定可复核，完成后仍可追溯。 Artifact → Evidence → Review
贯穿全程：Identity & Space 管理个人、团队与权限边界；Sync & Replication 保证 Server、Desktop 和离线副本最终收敛；Attention & Resumption 告诉用户下一步从哪里继续。

十类能力，组成同一个 Molis Work

这些是功能边界和团队分工边界，不是十个孤立产品。界面可以组合，数据写入仍回到各自负责的模块。

人、团队与数据边界

Identity & Space

账号、个人空间、团队空间、成员关系、角色和授权。

Sync & Replication

增量同步、游标、确认、冲突处理、离线副本和重连恢复。

信息接入与处理

Source & Connector

连接外部来源，管理安装、凭据、订阅、同步和回写。

Signal & Feed

规范化、去重、路由信息，并记录每个人的阅读与处理状态。

个人轻量工作

Personal Action

承载不需要完整 Goal Contract 的小事、提醒和临时行动。

Attention & Resumption

聚合该关注的 Feed、Action、Goal 和 Run，并保存恢复入口。

Goal 与真实执行

Goal Core

管理 Goal Contract、验收条件、关系图、风险、策略和拆解提议。

Work & Execution

管理认领、运行、取消、重试、超时、并发和执行状态。

团队协作与共同真相

Evidence & Artifact

保存可版本化交付物、证据、纠正记录和完成条件的验证结果。

Collaboration

管理 Promotion、Proposal、Review、Decision、Handoff 和共享上下文。

用户会在四种真实时刻感受到它

介绍功能时从场景进入，比逐个念模块更容易让团队理解为什么要做。

个人恢复工作

此刻：昨天被打断，今天不知道先继续哪一件事。

Molis Work：把 Feed、Action、Goal 和 Run 汇入个人注意力队列，回到上次上下文和下一步。

外部信息变行动

此刻：邮件、RSS 或消息里出现值得处理的内容。

Molis Work：先去重进入 Feed，再由用户决定忽略、建立 Action、关联 Goal 或创建新 Goal。

个人工作进入团队

此刻：一项私人探索变成值得团队投入的结果。

Molis Work：只披露必要内容，通过 Promotion、Review 和 Handoff 形成可协作的 Team Goal。

Agent 交付可验收结果

此刻：Agent 可以执行，但团队不知道做了什么、是否可信。

Molis Work：Agent 围绕 Goal Claim 和 Run，回传 Artifact 与 Evidence，由人或规则完成 Review。

所有分工最终汇合到真实闭环

模块实现可以并行，完成判断必须回到用户能够连续走通的端到端结果。

可部署基础

第一套持续运行的云端环境

部署→ 账号→ Team Space→ Goal API→ 设备连接
新环境可以部署、登录、创建空间和保存一个真实 Goal，重启后状态仍然存在。

个人真实闭环

验证 Feed、同步和本地执行

Server RSS→ Personal Feed→ Desktop→ Personal Goal→ 本地 Run→ Evidence
用户从一条真实外部信息创建 Goal，本地执行后把结果和证据可靠带回。

团队协作闭环

验证私人工作进入团队真相

Team Goal→ Work Context→ Private Task Context→ Run→ Disclosure Bundle→ Proposal→ Review→ Decision→ Materialization→ Canonical Context
两名真实成员完成私有执行、选择性披露和复核；未披露过程不会进入团队空间，重复接受或重启只落地一次。

消息协作闭环

验证消息入口和结果回写

Slack 或飞书→ Action / Goal→ 审批→ Agent Run→ Review→ 原线程结果
重复消息不重复创建任务，越权操作被拒绝，外部平台故障后可以恢复。
