# T-054 Home 里已有这个插件时，另一个发布者的同 ID 签名包在固定发布者、保存包之前就拒绝（S-84 的顺序）

> **这条在 main 上成立，修的是写记录的顺序，不放宽任何拒绝，不新增错误码。** Home 里已经装着插件 X，另一个发布者的同 ID 签名包走预览和确认：`PluginInstallService.confirm`（`apps/local-host/src/plugin-install-service.ts:116-143`）里的 `present`（`:129-130`）只读项目里的安装（`ports.installed(held.project_id)`），Home 范围的包不查；于是这个包先被 `pinPublisher` 固定了发布者（`:135`）、先被 `packages.save` 落了盘（`:138`），之后才在 `installInHome`（`:140`）里被拒：`HomePluginHost.installPackage`（`home-installed-plugins.ts:174-177`）进生命周期，生命周期见到同 ID 的记录就抛原生 `Error('这个插件已经安装，可以直接打开或升级')`（`installed-plugin-lifecycle.ts:146`，记录按 `plugin_id` 找，不看发布者，`:142-148`），出口回 `actions.execution_failed`。S-84 写的是「Host 在写任何记录之前先检查」（`docs/system/SECURITY-INVARIANTS.md:99`），项目一侧在固定发布者之前就拒（`ac-trust-install.md:427`，测试 `tests/security-invariants-plugin-lifecycle.test.ts:68-88` 的 BL623-02 量过「也不固定它」），Home 一侧漏了。起草时只读了代码，没有在真实路径上复现；第 5 节第 3 步的先红就是复现。
>
> **和 T-055 并行，没有依赖，也不撞锁。** T-055 改 `home-installed-plugins.ts`（同一发布者、已装，回 `plugin.state_invalid`），本单不碰那个文件，也不依赖它先合。两单都合入之后，另一个发布者的包得到 `plugin.definition_conflict`（在确认处，什么都没写）；`plugin.state_invalid` 留给同一发布者的包。哪一单先合都行，本单的测试两种情形都认同一个码。

## 1. 背景

依据都在 main `4d0f52c91`：

- 项目一侧的样子（照着写）：
  ```ts
  const present = (await this.ports.installed(held.project_id)).find(item => item.record.plugin_id === held.pkg.manifest.plugin_id);
  if (present && present.record.publisher_signature !== held.key_id) throw pluginErrors.definition_conflict('这个插件已经由另一个发布者装进了这个项目，两边不能互相替换：先卸载，再装');
  ```
  （`plugin-install-service.ts:129-130`）。注释（`:128`）写「another publisher's is refused before it can be pinned」，这句对 Home 不成立。
- 这条路怎么走到：

| 1 | `plugin-install-service.ts:78-96`（`preview`）、`:104-110`（`assertScopeKept`） | 预览与范围检查对 Home 包都放行：同范围、集成包以外都过，另一个发布者的同 ID 包预览得出来 |

- 现成的端口：`PluginInstallPorts.homeInstalled?()`（`plugin-install-service.ts:44`）已经在，生产装配也已接上（`apps/local-host/src/plugin-trust-actions.ts:16-24` 的 `homeInstalled: () => installedHomePlugins(source.homePlugins())`）。它等 Home 就绪后给出 `installations()` 里不是 `uninstalled` 的记录和各自的 Manifest（`project-plugin-ports.ts:123-127`）；`installations()` 是 Home 的 `platform.runtime.list()`（`home-plugins.ts:126`），含宿主自己构建的 Home 插件。所以不需要新增任何生产接口。

## 2. 目标

1. Home 里已有（未卸载的）签名包 X，另一个发布者的同 ID 签名包确认安装，以 `plugin.definition_conflict` 拒绝，文案说明「已经由另一个发布者装进了 Home，不能互相替换：先卸载，再装」。拒绝发生在固定发布者和保存包之前：对方发布者没有被固定（`RAC-1500`），已经被固定的发布者也不多保存一个包目录（`RAC-1501`）。
2. 不管 Home 里那条记录是运行中还是已停用，都占着这个 ID（`RAC-1502`）。
3. 这道检查只拦「另一个发布者」：同一发布者的包照旧通过它，交给后面（`RAC-1503`）。
4. 拒绝之后旧安装原样：`install_id`、版本、`state`、批准记录、固定的发布者、已写入的数据和动作都不变（`RAC-1504`）。

## 3. 不做

- 不改 `home-installed-plugins.ts`：T-055 在改它；`installPackage` 里的同 ID 拒绝（同一发布者）归 T-055。
- 不改预览。预览什么都不写（S-84），本来就不固定、不保存；项目一侧也只在确认处拒（`plugin-install-service.ts:129`）。人会先看到预览，确认时才得到拒绝，和项目一侧一致。
- 不处理同一发布者的更高版本（或同一份包）在 Home 已装时仍先 `save` 再被 `installPackage` 拒绝：新版本的包目录会留在盘上（`:138`）。T-055 第 3 节也把它列为不做。去向：报告里交给统筹，T-055 合入后看要不要把那个拒绝挪到确认处。
- 不处理宿主自己构建的 Home 插件的 ID 被签名包占用：Home 的记录 `publisher_trust` 不是 `pinned`，这道检查不认它，仍由 Runtime 回 `plugin.id_namespace_conflict`（`packages/plugin-runtime/src/install-identity.ts:38-40`），同样是先固定、先落盘再拒。去向：报告里交给统筹，默认不并进本单（见第 5 节第 2 条）。
- 不新增错误码、不改现有错误码或别的文案；不改 `PluginInstallPorts` 的形状；不改 `plugin-trust-actions.ts`（`homeInstalled` 已接）、`project-plugin-ports.ts`、`sandbox-package-store.ts`、`installed-plugin-lifecycle.ts`。
- 不写维护去清「以前已被固定、已落盘的残留」，不写兼容、迁移或回退读取；不加 `legacy`、`compat`、`@deprecated`、`backfill`。
- 不改 `docs/system/SECURITY-INVARIANTS.md`（第 8 节）、`apps/local-host/README.md`、`docs/system/CALL-CHAINS.md`。

## 5. 做法

写到函数级，照做；动到下面没写的地方先停（第 11 节）。

1. **只改 `confirm` 里的 `present`（`:129-130`），不改别处的顺序。** 检查已经在 `pinPublisher`（`:135`）和 `save`（`:138`）之前，只是对 Home 范围不读 Home。
   ```ts
   const inHome = held.runtime_scope === 'home';
   // Home 范围的包看 Home 里的安装（只算签名包的：publisher_trust 为 pinned），项目范围的包看项目里的。
   const entries = inHome ? await (this.ports.homeInstalled?.() ?? []) : await this.ports.installed(held.project_id);
   const present = entries.find(item => item.record.plugin_id === held.pkg.manifest.plugin_id && (!inHome || item.record.publisher_trust === 'pinned'));
   if (present && present.record.publisher_signature !== held.key_id) {
     throw pluginErrors.definition_conflict(`这个插件已经由另一个发布者装进了${inHome ? ' Home' : '这个项目'}，两边不能互相替换：先卸载，再装`);
   }
   ```
   项目范围的那一支文案和语义一个字不变（`这个项目`）。写法可以不同，行为这样：Home 范围读 `homeInstalled`、项目范围读 `installed`；仍在 `publisher_revoked` 检查（`:127`）之后、`pinPublisher` 之前。

3. **`homeInstalled` 缺（Host 没有 Home）按没有已装处理：`?? []`。** 这个 Host 没有 Home 时 `installInHome` 自己会拒（`project-plugin-ports.ts:74-78`）；`tests/security-invariants-plugin-install.test.ts:181` 的桩没有接 `homeInstalled`，要继续通过。
