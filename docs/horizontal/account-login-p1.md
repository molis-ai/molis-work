## 开工前检查与设计依据

档位：独立片；类型：横向账号能力、登录体验与 CI。采用用户已确认的五项 P1 范围，沿用当前登录布局，只按能力隐藏入口；不引入新页面、控件或视觉方向。

| 检查 | 结论 |
| --- | --- |
| 1 事实主人 | Auth 持有身份、能力、撤销和合同；Work 只持有本机账号会话与 Home。 |
| 2 插件同等待遇 | 沿用 Host 账号服务，不为任何插件添加专用通道。 |
| 3 能力注册 | 中央能力读取在生成合同登记一次；不新增用户或 Agent 可直接传入凭据的动作。 |
| 4 合同 | Auth 1.3.0 与两个消费者同批更新；Work 增加只读 DTO 导出，动作版本不变。 |
| 5 放置位置 | 中央适配在 horizontal/account，Host 仅有窄 HTTP 映射，界面仅消费安全结果。 |
| 6 表与存储 | 无新表、无库结构更改，凭据存储归属不变。 |
| 7 兼容迁移 | 无兼容读取、迁移、fallback 到旧登录协议。 |
| 8 安全边界 | 复用既有控制 Token、同源和安装入口守卫，clientId 只读受信任配置；失败和迟到结果有拒绝断言。 |
| 9 调用次数 | 匿名登录入口增加一次能力读取；密码仍一步、验证码仍两步。OAuth 保留现有轮询，本次不增加后台循环。 |
| 10 升级数据 | 不迁移 Home 或持久项目文件；A/B/A 及退出隔离回归。 |
| 11 成果过程项 | 不涉及：登录配置不是成果或插件过程项。 |
| 12 外壳文字 | 复用现有稳定文案键与布局；仅隐藏不可用方式。已有文件小额增长按精确许可记录。 |
| 13 错误 | 使用已有账号错误码，不增加 Error 子类。 |
| 14 冲突面 | 独立工作树修改账号模块、生成 DTO 和 CI；原工作区未提交修改保留，未修改正在使用的 Home。 |
| 15 全局最优 | 保持中央事实和生成合同；先补一致性证据与门禁，避免在本期引入未经授权的共享 SDK 重构。 |
