## 给人讲清楚

这一批完成最后一批插件的统一分区改造，把 Git 能力彻底收回 Git 插件，并将全系统所有插件（含主库插件、无库插件和第三方沙箱插件）合并进唯一一套按需启停装配、把历史双轨代码一次删光：

1. **最后 7 个业务插件数据收干净（`109-1`）**：目标（Goals）、写代码（Coding）、信息流（Feed）、收件箱（Inbox）、风险（Risk）、定时任务（Schedule）、每日简报（Work Brief）全部删掉业务表里多余的 `project_id` 列；信息流的原文引用迁入平台证据账本 `horizontal/evidence`；每日简报迁入分区独立库 `databases.partition` 并把跨分区简报摘要接入第 `108` 批上线的个人空间总览，从此全仓再无“全局一半 + 项目一半”的双实例插件，同时补齐备份检查表里 `evidence.db` 与 `personal-space/molis-work.db` 的金样覆盖。
2. **Git 底层代码整体搬回 Git 插件（`109-2`，D6=B）**：宿主里约 1,400 行 `workspace-git*.ts`、`projects.workspace.writers.*` 与 SDK `git-porcelain.ts` 整体搬进 `plugins/native/git`；AI 底座里的 `prologue-git.ts` 硬编码审批一并改成插件通用审查申报（保留 `#2244` 按 `install_id` 隔离），顺手清零 `44C` 留给本批的 Git 点名；启用 Coding 时默认随启用 Git（V9），允许单独移除 Git 并在确认框说明影响（V10）；在非 Git 普通文件夹（如个人空间默认输出目录）下，Git 平静提示非仓库、Coding 与 Diff 按普通文件夹平顺工作不报错。
3. **第三方沙箱开放独立库 + 全部插件合流唯一装配 + 旧双轨大扫除（`109-3`）**：向第三方签名沙箱包开放 `databases.partition`；将第 `106` 批的新每分区装配升级为**通吃全部 20 个内置插件（独立库、分区主库、无库）与已装沙箱包**，全部统一读 Home 单张安装表并按需启停，随后删除项目数据库里的旧安装表、`HomePluginHost`/`HomeInstalledPlugins`、`dual_instance`、`runtime.scope:"home"`、`project_rows`、`artifact_join` 与 `projects:reach`，焊死 **G2 / G3** 防回流门禁。

2026-11-26 补记：一骏决定由 44C 提前实现 M13 通用审查种类登记、工具绑定及卡片渲染供本批使用。109-2 接入 Git 工具并验 V9／V10，109-3 继续负责统一装配。

需要你做的：无新增未决决策。按 2026-11-25 确认的粒度，允许本批按上述三块先后拆成 **3 个独立 PR（`109-1` → `109-2` → `109-3`）** 串行合入，每步保持 `main` 全绿、问题边界清晰。

## 用户拍板与实施记录

### 109-1（PR1）

- **主库六插件删 `project_id`（U13/V7 Clean v1，不迁移）。** Goals、Coding、Feed、Inbox、Risk、Schedule 的业务表去掉 `project_id` 列和 `WHERE project_id = ?`；Goals 的 `boards` 改为单行，主键 `id = 1`。同步键改用 `{ scope: "projectId" }`，线上格式不变（键与记录仍写分区，同 108 的 Images）。库结构原地改，仍是 v1（[决定 69](../decisions.md#decision-69)：开发前阶段零迁移）。
- **同步声明校验随之放宽一处（共享核心）。** 表上没有 `project_id` 时，`existsAny` 允许空 `match`（指那张表的任意一行），分区声明允许不带 `projectColumn`；表上还有 `project_id` 时仍按原规则拒绝。SDK `sync-schema.ts`、`plugin-sync.ts`（审批结果声明不再要求 `project_id` 列）与 `plugin-runtime` 的两个校验器同改，`tests/plugin-sync-service.test.ts` 正反两向断言。审批结果读取（`horizontal/project-approvals/src/outcomes.ts`）在表无 `project_id` 时取 `project_root` 的分区。
- **Feed 证据持有迁入平台。** Feed 经 `services.evidence`（`evidence:collect`）登记、收回、释放正文；`feed.content.hold/release/reclaim` 三个 Home 动作、Feed 的 Home 半与 `feed-content` 顶层库删除。后台作业 `feed-reconcile` 的权限由 `actions:invoke` 改为 `evidence:collect`，按本分区库留着的正文重新登记，所以旧账本的行不迁移。旧开发 Home 的 `feed-content/` 不处理，按[决定 69](../decisions.md#decision-69)需要时删掉重建。`companions` 改为 Manifest `dependencies[].enable_with`。
- **Work Brief 迁 `databases.partition`。** 简报库在 `<分区>/libraries/work-brief.db`，不带项目列；`personal.get/refresh` 与 `projects:reach` 删除，每个分区的首页简报在同一提交里写一行总览（`overview.read@1`，WBR-24），`work-brief` 顶层库不再登记；旧开发 Home 里留下的 `work-brief/` 目录不处理，按[决定 69](../decisions.md#decision-69)需要时删掉重建。WBR-07 回归在分区入口重跑（`tests/work-brief-plugin.test.ts`、`tests/work-brief-page.e2e.test.ts`）。
- **金样与金样覆盖不再做（[决定 69](../decisions.md#decision-69)，合入 `main` 时对齐）。** 本批原计划的金样写入、`golden-coverage.json` 兑现、三份金样就地改写与同版例外登记，随决定 69 删除金样夹具与这些门禁一并取消；Goal 历史夹具四份转储仍按现行结构就地改写。
- **定向测试顺带查出并修好的产品问题。** ① Feed 来源历史读取（`historyReads.refs/operations`）删参数后调用方仍按旧参数位传，收回与释放正文时读不到任何一页，TypeScript 因函数参数少者可赋给多者而没有报；② Goals 输入绑定的 `sourceLocator` 仍读已删的 `row.project_id`，改为读本库 `project_root`；③ Listener 投递表的插入语句仍带 `project_id` 列。
- **Feed 改为分区插件后的两处随带变化。** ① 它不再是 Home 插件，平台给它 `services.overview`，于是每次写入都会刷新第 108 批的排期摘要；原实现逐个来源读检查点与条目数（每个来源约 10 次授权核对），改为一条语句读来源本身。② 建库时写示例（`seedDemoProject`，只给测试夹具用）不再跳过 Feed（原先跳过带 Home 半的插件）；真实演示项目照旧在首次打开时写 Feed 示例。**测试夹具保持不带 Feed 示例（用户 2026-11-27 定）**：`seedDemoProject` 加不点名插件的 `leaveOut` 选项，测试侧的 `tests/fixtures/demo-seed.ts` 列出 Feed，夹具项目内容与 `main` 一致。带了 Feed 示例后，壳层事项线的等待卡片与提醒条在细指针下按钮只有 18px、字号 18px 不在字阶上、320px 下标签条图标与「全部标签」按钮重叠，这些问题真实演示项目里已有，另立后续处理（壳层正由第 108 批评审修复改动）。
- **Feed 自己告诉打开的页面重读。** Feed 的 Home 半原先每条命令成功后都由宿主让它的页面重读（定时拉取没取到东西时回执 `view_changed: false`，不刷新）；移出 Home 后，别处调来的收录、定时拉取、标为已读都不再刷新页面。改由 Feed 在自己的每条命令成功后调 `services.ui.invalidate()`，同样尊重 `view_changed: false`（FBR-07），宿主不另加钩子：曾试过让宿主在任何项目插件命令后刷新，Schedule「打开即标为已读」这类不改画面的命令也算进去，Schedule、Inbox 页面因此多读一次。
- **Home 插件机制的测试改用登记探针。** 109-1 后不再有内置插件带 Home 半或 Home 库，`HomePluginHost`、`project_rows` 等机制要到 109-3 才删除；在那之前，相关测试把探针临时加入内置登记表（`shippedParts` 本就允许测试这样扩充），按内置插件的方式登记它的 Home 库，产品代码不为测试开口子。
