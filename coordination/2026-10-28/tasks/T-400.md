## 1. 背景

T-131 做了两件事：
- 在 `mcp-action-grants.ts:8` 用 `defineErrorCodes("mcp", { action_revoked: "forbidden" })` 让「没有授权的动作」在源头带上被拒的 kind；
- 删掉 `host-log.ts` 的 `answeredRefusal` 里按码补认的那一行（`apps/local-host/src/host-log.ts:117-125`），读的人只按 kind 认。

二审 6527887667 的建议第 3 条列了范围外、同一类的三处，第 2 条指出 RAC-2495 缺变异实证。MISC 第 97 行把这四件事合成一单，定为甲：碰 S-08，`mcp.permission_revoked` 优先。

kind 决定两件事：
- 状态码：`packages/plugin-sdk/src/errors.ts:8-11` 的 `KIND_STATUS` 是唯一一张 kind 到状态码的表；
- 读的人怎样分辨被拒与失败：`host-log.ts:121`、`horizontal/agent-host/src/adapters/prologue-checkers.ts:81-84`、`plugins/native/coding/src/wake-loop.ts:34-39`、`apps/local-host/src/demo-plugin-seed.ts:216`。

码不带 kind、码表里也没有它时，按 `errors.ts:65-70` 读成 `invalid`。被拒因此被当成调用方写错了输入：
- 读的人认不出被拒；
- 跨进程时状态码是 400，不是 403。

## 2. 目标

1. MCP 客户端缺场景或后台任务要的权限时，四处检查抛的都是 `mcp.permission_revoked`、kind `forbidden`：
   - `mcp-action-client.ts:26` 的 `validate_permissions`；
   - `mcp-action-client.ts:46` 的 `assert_authority_current`；
   - `mcp-background-authority.ts:14`，保留时就缺；
   - `mcp-background-authority.ts:18`，保留后被撤。

   这四处共用 `mcp-action-grants.ts` 里的同一份声明。MCP 进程经网关读回来的也是 `forbidden`；MCP 客户端读到的 `tools/call` 结果一字不差。
2. 搜索的读取器检查只按 kind 认被拒：
   - 错误自带 kind `forbidden`，或码在平台码表里是 `forbidden`，这个读取器就不用，查询照常回答，不论码是什么；
   - 别的失败照旧让查询失败：不是这个 kind 的、普通 `Error`，以及码是 `mcp.action_revoked` 却没带 kind 的。
3. 下面三条路上抛的 `assistant.action_revoked` 都是 kind `forbidden`：
   - 发出时的复查（`assistant-authority.ts:78`）；
   - 输入检查（`:104`）；
   - 操作卡规则的拒绝：`assistant-offers.ts:16`、`:180` 经 `assistantErrors`。

   宿主 HTTP 出口（`native-plugin-http.ts:96-97` 的 `actionErrorResponse`）回 403，响应体 `{ error, code }` 不变。
4. 补上 RAC-2495 的变异实证：把 `mcp.action_revoked` 的 kind 改回 `invalid` 时，`tests/artifact-source-and-links.test.ts` 的「RAC-2088 RAC-2495 …」红在 `:155`。
