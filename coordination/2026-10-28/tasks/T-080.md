# T-080 灵光的标题、正文与对话消息按 Unicode 字数数上限，没写标题时取正文首行按整字截取，与动作 schema 一致

> **这条在 main 上成立：灵光的库比它自己声明的合同更严，没写标题时还会截出半个字。** 动作 schema 给出的上限是：`create`、`update` 的 `title` `maxLength: 80`、`body` `maxLength: LINGGUANG_BODY_LIMIT`（200000，`plugins/native/lingguang/src/actions.ts:18`、`contract.ts:4`）；头脑风暴里接着说的话 `body` `maxLength: 2000`（`actions.ts:63`）。动作层用 Ajv 校验，Ajv 的 `maxLength` 按 Unicode 字符（码点）数：`packages/kernel/src/action-schema.ts:41-42` 的选项里没有 `unicode: false`。README 写的也是字：「正文上限 20 万字」（`plugins/native/lingguang/README.md:13`）。
>
> 库里四处却按 `string.length` 数，也就是 UTF-16 单元：拒绝的三处是标题 `store.ts:342`、正文 `store.ts:349`、对话消息 `store.ts:356`；截取的一处是没写标题时取正文第一行 `store.ts:345`。一个 emoji 或扩展 B 区以后的生僻字在 JS 字符串里占 2 个单元。所以 41～80 个这样的字的标题、100001～200000 个这样的字的正文能过 schema，却被库以「标题须为 1 到 80 个字」「正文须为 0 到 200000 个字」拒掉。1001～2000 个这样的字的一句话更糟：库在模型答完之后才查它（`store.ts:243`），按次计费的模型调用（`actions.ts:63` 的 `cost: "metered"`）已经花了，回复却以「这句话须为 1 到 2000 个字」拒掉、不保存。没写标题时，正文第一行被截成 80 个单元，截在一个字中间就留下半个代理对。起草时只读了代码，没有跑；第 5 节的先红就是复现。这是 T-077（Dataset）、T-079（PPT）的同类问题，出在另一个插件。

## 1. 背景

- 合同口径（都按 Unicode 字符）：
  - schema：
    - `actions.ts:18`：`fields`，`title` 最长 80、`body` 最长 `LINGGUANG_BODY_LIMIT`；`create`（`:51-53`）、`update`（`:54-55`）都用它；
    - `contract.ts:4`：`LINGGUANG_BODY_LIMIT = 200_000`；
    - `actions.ts:63`：`conversation.message` 的 `body` 最短 1、最长 2000、带 `pattern: "\\S"`。
  - Ajv：`packages/kernel/src/action-schema.ts:41-42` 的选项、`:79` 的 `new Ajv(options)`。没有 `unicode: false`，`maxLength` 走 Ajv 的 `ucs2length`，按码点数。
- 按 UTF-16 数的四处（`plugins/native/lingguang/src/store.ts` 共 361 行）：

  | 位置 | 现在的写法 | 谁会走到 |
  | --- | --- | --- |
  | `store.ts:342`（`normalizeTitle`，`:340-346`） | `if (title.length > 80) throw lingguangErrors.invalid("标题须为 1 到 80 个字");` | `store.create`（`:97`）、`store.update`（`:145`）。会走到它的有：`lingguang.create@1`、`lingguang.update@1`（页面经 `POST /sparks`、`POST /sparks/:id` 两条路由调它们，`manifest.ts:34`、`:41`）、流程内容站的 `create`、`receive`（`content-actions.ts:26`、`:28`）、选中文字的「记下灵光」（`actions.ts:75-84` 准备的输入交给 `lingguang.create`） |

- 没有测试量到这几处：
  - `git grep -n -e '标题须为 1 到 80' -e '这句话须为' -e '正文须为' -- tests` 没有命中；

## 2. 目标

1. 41～80 个非 BMP 字符（如 `🟢`）的标题、100001～200000 个这样的字的正文，经 `create`、`update` 都能收下；81 个字的标题仍由 schema 拒（`RAC-1620`）。上限本身不变。
2. 没写标题时，取正文第一行的前 80 个整字作标题，不截出半个字；`create` 和把标题改空的 `update` 都是这样（`RAC-1621`）。
3. 头脑风暴里 1001～2000 个这样的字的一句话，模型答完以后连同回复一起存下；2001 个仍由 schema 拒，不调模型（`RAC-1622`）。

```ts

test("RAC-1620: 灵光 counts a spark's title and body in Unicode characters, as its action schemas do", async () => {
  // create/update in src/actions.ts allow an 80-character title and a 200000-character body (LINGGUANG_BODY_LIMIT in src/contract.ts);
  // one 🟢 is one character but two UTF-16 units.
  await fixture(async ({ bound }) => {
    const wide = (count: number) => "🟢".repeat(count);
    const { spark } = await bound.invoke(actions.create, { title: wide(80), body: "想法" });
    assert.equal(spark.title, wide(80), "create keeps an 80-character title");
    const written = (await bound.invoke(actions.update, { id: spark.id, body: wide(200_000) })).spark;
    assert.equal(written.body, wide(200_000), "update keeps a 200000-character body");
    await assert.rejects(bound.invoke(actions.update, { id: spark.id, title: wide(81) }), { code: "actions.input_invalid" }, "81 characters is still past the schema");
  });
});

test("RAC-1621: a spark without a title takes the first 80 whole characters of its body's first line, never half of one", async () => {
  // normalizeTitle in src/store.ts falls back to the body's first line; a cut by UTF-16 units would end inside a 🟢.
  await fixture(async ({ bound }) => {
    const wide = (count: number) => "🟢".repeat(count);
    const { spark } = await bound.invoke(actions.create, { body: "灵" + wide(80) + "\n第二行" });
    assert.equal(spark.title, "灵" + wide(79), "create titles it with 80 whole characters");
    const retitled = (await bound.invoke(actions.update, { id: spark.id, title: "", body: "感" + wide(80) })).spark;
    assert.equal(retitled.title, "感" + wide(79), "an update that empties the title does the same");
  });
});

test("RAC-1622: a brainstorm message of 2000 Unicode characters is kept with the reply the model wrote for it", async () => {
  // conversation.message in src/actions.ts allows a 2000-character body; the store checks it again only after the model has answered.
  const prompts: string[] = [];
  await fixture(async ({ bound }) => {
    const wide = (count: number) => "🟢".repeat(count);
    const { spark } = await bound.invoke(actions.create, { title: "长句", body: "想法" });
    const { conversation } = await bound.invoke(actions.openConversation, { spark_ids: [spark.id] });
    const state = await bound.invoke(actions.message, { id: conversation.id, body: wide(2000) });
    assert.deepEqual(state.messages.map(row => row.body), [wide(2000), "回应"], "the 2000-character message and its reply are both kept");
    await assert.rejects(bound.invoke(actions.message, { id: conversation.id, body: wide(2001) }), { code: "actions.input_invalid" }, "2001 characters is still past the schema");
    assert.equal(prompts.length, 1, "the model was asked once, for the message that was kept");
  }, async prompt => { prompts.push(prompt); return "回应"; });
});
```

3. 几处为什么这样写，别改：
   - 用 `🟢`（U+1F7E2）：一个码点、两个 UTF-16 单元，没有变体选择符。T-077、T-079 和 `tests/content-owner-regressions.test.ts:58` 用的也是它。
   - `RAC-1621` 在 emoji 前面放一个汉字（`灵`、`感`），让 80 个字的边界落在一个 emoji 中间：按单元截，最后一个 emoji 只剩半个，长度却正好；按整字截，留下汉字加 79 个 `🟢`。不放汉字，按单元截出的是整 40 个 emoji，看不出半个字。第一行后面的 `\n第二行` 守的是只取第一行。
   - `RAC-1620` 的顺序是标题、正文、81 字。前两处在 main 上是抛错，红在那一步的 `invoke`。第三句守的是上限没有被放宽：81 个仍由 schema 拒（码是 `actions.input_invalid`，`tests/lingguang-actions.test.ts:46`、`:79` 用的也是它）。正文只改 `body`，标题不变，所以 `update` 不经 `normalizeTitle` 的拒绝那一句。
   - `RAC-1620` 的正文是整 200000 个 `🟢`（40 万个单元、约 800 KB）：正好压在上限上，才分得清按字数和按单元。不要缩短。
   - `RAC-1622` 的模型是测试给的函数（`fixture` 的第二个参数），每次被调就记一笔。第一句话在 main 上已经调过一次模型，才在存的时候被拒；改好以后存下。2001 个字由 schema 在处理器之前拒，不调模型，所以最后 `prompts.length` 是 1。
   - 三个用例只用文件里已有的 `assert`、`test`、`actions` 和 `fixture`，不加 `import`。`LINGGUANG_BODY_LIMIT` 没有从包的公开入口导出（`src/index.ts`），所以测试里写 `200_000`，注释点明出处。
4. 代码里不要出现 `legacy`、`compat`、`backfill`，不加空 `catch`、`as unknown as`、`any`、`console`（这些按文件计数，只许减少）。
