# UI 性能基线

状态：初始 Host HTTP 基线已采集，浏览器与原生体验基线待补（2026-10-15）。代码基线 `f9f9a1676640188f98b792d4a04fd24adcfedb7a`，尚未修改产品实现。负责人：Codex。

这是当前版本的隔离实测，不沿用 10 月 1 日旧审计数值。它证明 HTTP 响应、响应体规模和条件缓存行为，**不证明首屏绘制、界面可操作、输入延迟、帧率、真实模型或 macOS 壳性能**。

## 环境与测量口径

- 时间：2026-10-15 01:42–01:43，America/Los_Angeles。机器 Apple M5、10 个逻辑 CPU、16 GiB 内存，macOS 26.3.1 / Darwin 25.3.0，arm64；Node 24.14.0、pnpm 11.9.0。
- 独立工作树：`feature/visual-ui-baseline`。离线锁定安装及整体 `pnpm build` 成功，使用该构建的生产 `createDesktopWebHost`。不连接真实 Home，不调用模型。
- 数据：每次新建临时 Home、一个项目，启用 11 个项目插件；仓库现有 `seedDemoBoard` 产生 19 个 Goal、25 条关系，无历史助理会话。进程退出关闭 Host 并清理自己的临时数据。
- 三个独立进程，各记录首次项目请求，再按固定顺序重复健康、项目目录、项目主页、Coding 分屏文档各 10 次。各路径 30 个重复请求；操作是顺序 HTTP GET，未运行浏览器脚本。
- `headersMs`：发出 fetch 到取得响应头；`bodyMs`：发出 fetch 到读取完整响应体。表内用 `bodyMs`，响应体字节为读取后的字节数，不称网络传输量。p95 用排序后第 `ceil(n×0.95)` 个样本；首次请求仅 3 次，报告范围而不据此推断尾延迟。
- “首次”指本次 Host 进程第一次请求该页面或资源；操作系统文件缓存未清理，不能称整机冷启动。“重复”含 JIT/缓存继续预热，不剔除慢样本。
- **机器并非空闲**：另一个工作树的浏览器用例批次仍在运行，测试进程约占一个 CPU 核；采样开始 1 分钟 load average 为 3.20–3.34。按仓库规则未并发启动第二个浏览器批次。本任务的构建、回归已结束后才采正式样本；早先与本任务回归重叠的三次试跑不纳入数据。

该干扰使耗时只能作为初始观察。后续改动前须在无竞争的时段复测相关路径、确定比较目标；不能拿本次带负载的耗时与空闲时的结果直接宣称优化收益。资源字节与 304 行为可独立核对。

健康从真实 `503 starting` 转为 `200 ok`，按 25 ms 间隔探测，就绪时间含采样粒度。该时间不含模块加载、建库和种数据，也不含页面准备；不能用来代表产品启动。原始文件另记录 fixture 准备约 562–580 ms、进程启动至 fixture 就绪约 1,473–1,523 ms，后者包含测试设置而非实际用户启动链。

事件循环使用 Node `monitorEventLoopDelay`、10 ms 分辨率，窗口覆盖上述请求；客户端与 Host 在同一进程，包含夹具与响应处理的开销，不能归因成浏览器长任务。内存只测末值，未强制 GC、未测峰值或持续使用趋势，不能据此判断泄漏。

## 原始证据与复现

测量脚本：[http-baseline.mjs](evidence/http-baseline.mjs)。完整样本：[04](evidence/http-04.json)、[05](evidence/http-05.json)、[06](evidence/http-06.json)。原始文件保留响应头/响应体耗时、状态码、字节、环境、数据规模及进程统计；不输出控制令牌或真实数据。

```sh
pnpm install --frozen-lockfile --offline
pnpm build
node specs/visual-ui-experience/evidence/http-baseline.mjs /tmp/molis-visual-http-repeat-1.json
node specs/visual-ui-experience/evidence/http-baseline.mjs /tmp/molis-visual-http-repeat-2.json
node specs/visual-ui-experience/evidence/http-baseline.mjs /tmp/molis-visual-http-repeat-3.json
node scripts/run-tests.mjs tests/workbench-asset-cache.test.ts tests/catalog-read-contention.test.ts
```

先按并行开发规则确认构建/浏览器时段，构建和回归结束后再单独测量。复现输出使用新文件，不覆盖这里的原始基线；若改动范围无需重建，不重复构建。

本轮相关回归：资源缓存 1/1、目录读争用 4/4 通过。前者证明相应用例的缓存合同，后者证明已有锁处理行为；它们不证明整套 UI 性能。构建通过并有既有 xterm FitAddon 导出告警。

## 尚未测量的用户路径与比较要求

| 路径 | 必须区分的观察点 | 当前状态 |
| --- | --- | --- |
| 浏览器首次打开/重开项目 | 反馈可见、主控件可操作、必要内容完成；请求数/总字节/长任务 | 未测；浏览器批次被其他会话占用 |
| 助理长历史恢复、持续输出 | 恢复到可读/可输入、每次更新工作量、输入延迟、选区/滚动稳定 | 未测；本夹具没有历史会话或模型输出 |
| 多分屏、拖拽、调整尺寸、折叠 | 按下到反馈、逐帧更新、落定；取消/反向后的最终状态 | 未测 |
| 反复切换、隐藏与恢复 | 重复请求、隐藏渲染/轮询、恢复完整度，资源随使用轮数的趋势 | 未测 |
| 代码/Diff/媒体 | 明确文件/行/图片规模，首见、可用、完成及追加开销 | 未测 |
| macOS 原生壳 | 启动、拖区、全屏、嵌入恢复、焦点与后台工作 | 未测；本轮只有 Node Host |

相关实现动手前，补齐对应生产路径的可复现操作、规模、起止点和同条件基线，再固定量化目标。动效采样须分别记录真实启用与减少动态效果；现行自动化条件可能关闭动效，不能以禁用状态的结果证明动画顺畅。

已确定的约束：不放宽页面资源预算；保留资源再验证行为与真实功能；不增加无必要查询/轮询；首次反馈、实际可操作与业务完成分开比较，不能拿更早占位替代完成更快。耗时改善须大于同条件重复测量的波动，关键非目标路径不得显著退化；新增效果的成本、内存和请求代价一并报告。尚无干净浏览器样本，因此本轮不编造整体验收阈值或“已流畅”的结论。
