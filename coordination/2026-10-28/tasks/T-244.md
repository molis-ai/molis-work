## 1. 背景

来源：MISC「T-089 起草」行；统筹 2026-10-29 已定选 A（该行末尾：「删掉 `removeEmptyWorkspace` 参数」）。

`modules/projects/src/workspace.ts:133-151` 的 `unlink(workspaceId, projectId, actorId, removeEmptyWorkspace = true)` 在成员删光后只有 `removeEmptyWorkspace` 为真才删目录记录。设置页的路走默认值（真），Runtime 解除关联那条路（`modules/private-work-context/src/project-binding-commands.ts:130-135`）传 `false`，成员删光后留下一条没有成员的目录记录。T-089 已把现状钉进测试（`tests/runtime-binding-error-codes.test.ts:178` 的注释写着「the workspace record stays with no member」）。参数还穿过 `modules/projects/src/index.ts:139-140` 的 `unlinkWorkspaceMembership` 和 `project-binding-commands.ts:15` 的端口签名。

用户拍板的方向（统筹转述）：统一，删掉参数，两条路行为一致（空了就删）。

## 2. 目标

1. `unlink` 不再有 `removeEmptyWorkspace` 参数：成员删光时总是删目录记录；仍有别的项目成员时不删。
2. Runtime 解除关联后，目录记录在成员删光时不再留下。
3. T-089 钉现状的那一句测试改成钉新行为，并说明为什么改（不是放宽）。

## 3. 不做

- 不处理「删除项目」留下空目录记录的那一条（MISC「T-182 待起草」行：`apps/local-host/src/managed-project-deletion.ts:57-58`，走 `ProjectDeletionService`），范围更大，另行。
- 不加兼容或迁移逻辑。存量里已有的空目录记录不在本单处理，在【方案】里写出「存量里有没有、要不要维护清」，由统筹定。

## 4. 范围

`modules/projects/src/workspace.ts`、`modules/projects/src/index.ts`、`modules/private-work-context/src/project-binding-commands.ts`（T-169 也改，见依赖）、`tests/runtime-binding-error-codes.test.ts`，以及改参数后其它调用者/测试（`git grep -n unlinkWorkspaceMembership` 与 `workspaces.unlink` 全查）。

锁定：`project-binding-commands.ts` 被 T-169（#1443）占着，所以依赖 T-169，合入后才领。

## 5. 做法

先在当时的 main 上核第 1 节的行，并 `git grep -n unlinkWorkspaceMembership` 与 `workspaces.unlink` 看还有没有别的调用者；有就在【方案】里列出。然后改（行号按 main，T-169 合入后会偏几行）：

1. `modules/projects/src/workspace.ts:133-145`：`unlink(workspaceId, projectId, actorId, removeEmptyWorkspace = true)` 去掉第四个参数；`if (removeEmptyWorkspace) this.repository.workspaces.removeWorkspaceIfEmpty(workspaceId);` 改成 `this.repository.workspaces.removeWorkspaceIfEmpty(workspaceId);`。`removeWorkspaceIfEmpty`（`workspace-repository.ts:133`）本身不动，它只在没有成员时才删，所以仍有别的项目是成员时目录记录会留着。
2. `modules/projects/src/index.ts:139-140`：`unlinkWorkspaceMembership: (workspaceId, projectId, actorId, removeEmptyWorkspace) => this.workspaces.unlink(workspaceId, projectId, actorId, removeEmptyWorkspace)` 去掉第四个参数（`:75` 的类型取自 `ProjectWorkspaceService["unlink"]`，自动跟着）。
3. `modules/private-work-context/src/project-binding-commands.ts:15` 的端口签名去掉 `removeEmptyWorkspace: boolean`；`:130-135` 的调用去掉末尾的 `false`。
4. `tests/runtime-binding-error-codes.test.ts:178-181`：(d) 的注释 `the workspace record stays with no member (unlinkWorkspaceMembership(…, false))` 改成「the empty workspace record is removed with its last member」；`assert.deepEqual(directoryRecord()?.project_ids, [])` 改成 `assert.equal(directoryRecord(), undefined)`（目录记录没有了，`directoryRecord()` 就是 `undefined`）。
5. 加一个用例：同一个目录有两个项目是成员，解除其中一个后，目录记录还在、`project_ids` 只剩另一个（RAC-2241）。

`full` 预计为 true（`private-work-context`、`storage` 相关），以 `affected-tests` 为准。

## 6. 验收

- `RAC-2240`：Runtime 解除关联后，成员删光时目录记录不再留着。
- `RAC-2241`：仍有别的项目是成员时，解除一个项目不删目录记录（设置页那条路原有行为不变）。
- `RAC-2242`：端口签名与转发里没有 `removeEmptyWorkspace`（可用类型检查或 `git grep` 为证）。
- 余下号备用。
