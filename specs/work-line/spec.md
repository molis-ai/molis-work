## 1. 要解决的问题

对照 main `c2266974b9` 的现状：

- **底栏是一排互不相干的东西。** 左边是 Dock 与插件切换，中间是输入框，右边是个人插件入口和项目头像。它们各管各的，看不出「我现在在办哪件事、办到哪了」。
- **输入框写到多行就不好看。** 框向上长时盖住主区底部，或把底栏撑高，版面跟着跳。第 11 批把静止高度收成一行（62px），多行时的样子没有解决。
- **助理的对话是另一块面板。** 交给助理的事、它的进展、要你点头的地方，都在助理面板里一条条消息往下排。要看一项工作办到哪，得翻对话；对话一长，早先交办的事被顶上去。
- **后台任务的入口还要再加一条。** 主动助理 §12.8 定的是「对话顶上的任务条」（2026-11-03，方案 A）：助理面板顶上再加一条概况，点开换成任务详情。它解决了看得见，但任务仍然关在助理面板里，和主区、和手头这件事没有关系。
- **事项切换器在顶部，和底部的输入没有关系。** 主线 §4.1 把切换器放在标题栏最前。切了事项，底部看不出变化；助理范围靠输入框上一行小字说明。
- **等你、待办、日程、建议各在各的地方。** 等你在底栏的数字里，待办在待办插件，今天的会在日程，下一步在 Goal 页。它们都是「这件事接下来要处理的」，但没有一个地方按先后排在一起。
- **卡片有了规格，缺一个把它们串起来的地方。** 智能呈现定了名字片、行、卡片、活卡、决定请求、验收卡等形态，落点是对话、讨论、首页、Shelf、等你。它们各自出现，没有时间上的先后。

- **任务和事情混在一起。** 2026-11-12 的写法里，线上第一批东西就是助理交办的工作本身（进行中、等你、已办），线成了一条任务条：随口交代的小事也要占一个位置，而待办、日程这些真正「接下来要处理的事」要等后面几片才上线。用户 2026-11-14 改：线上放的是事件，任务在它背后（§12）。

要的不是再加一块面板，而是让版面本身说清三件事：办过什么、现在在办什么、接下来该办什么。

## 2. 一条线是什么

三个词（用户 2026-11-14 定）：**事项**是窗口左上角那一格切换的那一层（[主线](../work-mainline/spec.md)里的容器）；**事件**是清单里的一行；**任务**是事件背后的执行。代码和合同里「事件」另有系统事件的意思（DOM 事件、Board 事件），本书里不加限定的「事件」都指这一种，系统事件写「变更通知」。

界面的位置 2026-11-17 改为底栏第十三版（§16），这一节按它写。「事项线」留作这项平台能力的名字，界面文字里不出现「线」。

- **事项线。** 把当前事项的事件按先后读出来的这项能力；没选事项时读的是这个项目的。界面上它是三张清单和一叠卡：
  - 「办完」：办完的事件，最近的在前；
  - 「在办」：背后有任务在办或排队的事件；
  - 「接下来」：有时间的（日程、到期的待办）按时间排，然后是建议的下一步；
  - 卡叠：等你处理的事件，在输入框右边，最前面一张能直接回答。

  对话关着时，三张清单是输入框里面右上角的三个图标带件数；对话开着时，是信息栏顶上的一行标签。一件事在哪一处只看它的状态（POLISH-40），不因为被点开而挪地方。
- **事件。** 清单里的一行：登记方的图标、名字、一个状态词或一句现状。它是平台能力：插件按同一份登记（§5）把自己的对象放上来，助理也按这一份登记，平台不为它另存内容：

  | 事件 | 是什么 | 谁登记、事实归谁 |
  | --- | --- | --- |
  | 插件对象 | 这件事里带时间或要处理的对象：待办、日程、Coding 会话、要你看的条目 | 各插件 |
  | 结果 | 办完交回的东西（一份文稿、一张表、一次改动） | 结果对象的主人插件 |
  | 交办的工作 | 你交给助理、值得跟的一件工作：有产出物、你说了要跟，或和已有的事件相关（§6.4） | 助理；工作的事实在任务板与助理工作 |
  | 建议 | 一个可以开始的下一步 | 来源对象的主人（装着 Goals 时是 Goal 的下一步）；第三片起也来自主动助理 |

  随口问一句、当场答的不是事件；一次对话、一项后台任务本身也不是事件。
- **任务。** 为某个事件在后台办的一次执行：助理或 Character 派出的工作、Coding 的一次运行、工作流程的一次运行、插件自己的后台作业。
  - 一个事件背后可以没有任务、有一个、有几个；任务办完了事件还在（一份公告先后有过起草、改语气、配图三个任务）。
  - 任务也可以不属于任何事件：随口交代的小事列在「在办」清单末尾「不属于事件」一组，不计入三个数；它等你时照样进卡叠。
  - 任务的事实在任务板和发起它的一方；「这个任务为哪个事件办」由任务的主人记，经 placement 的关联声明统一列出、挂上、解开（和今天文稿挂 Goal 是同一个机制），平台不另存。
  - 任务分给子代理的一步叫子任务，在清单里缩在任务行下面；它不是事件（[子代理交互 §11](../subagent-interaction/spec.md#11-第-58-批开工与定样2026-11-16)）。
- **事件的状态。** 来自两处，读出来不另存：主人给的对象状态（到期、已完成、要你看），和它背后任务的状态（有任务在办就是进行中，有任务停下来等你就是等你，任务都办完就回到主人给的状态）。
- **对话栏与信息栏。** 对话从输入框向上展开，分两栏。**对话栏**和输入框一样宽，只放说过的话；它顶上有一行小标题，写这句话是对谁说的，内容滚动时不动。**信息栏**在对话栏右边、卡叠正上方，和卡叠一样宽；它一次只是一样：眼前这件事的信息，或者三张清单之一，由它顶上的标签（信息、办完、在办、接下来）选。对话顶上没有标签栏。
- **焦点。** 对话栏一次只对一样东西说。平时是主对话：和助理随口说、当场答，不产生页签、不进清单、不计数。点一件事件（清单里的行、卡叠的卡、主区里的行、顶上的页签），焦点到它：对话栏换成为这件事件办的那件工作的对话，小标题换成它的名字，顶上开它的页（主人插件的对象页；主人没有页的，平台按事件的组合呈现画一页），这时说的话是对这个事件说的。小标题、输入框的提示语、顶上亮着的页签、发出去那句话的对象是同一个（POLISH-66）。
- **这件事的信息。** 信息栏选中「信息」时从上到下三张，由平台来画：
  1. **该你做的**：为这个事件办的任务停下来等你定时的决定请求（见下一条），或者主人说它在等你时的组合呈现与主人声明的动作。没有要你做的时这一张不出现。
  2. **这件事现在怎样**：一行「谁登记 · 现在怎样」（读取的原话）与「停到侧边」；组合呈现——页面向 `POST /api/mainline/event/surfaces` 要这个对象的组合呈现（和对话里的对象同一套组合服务、同一个页面部件），宿主先按本人读一次，对象不在读取里就拒绝（`actions.subject_unavailable`），插件页不能调，助理自己的工作没有这一段；「在办」——任务总表里为这个事件办的每件任务一行（等你的排前），子任务缩在任务下面，行与停止和「在办」清单里同一件任务的相同；挂了要求的再出一行逐项概况。
  3. **上下文**：谁来办、这句话带着什么、放在哪件事项。

  工作台里没有按事件种类或插件写的内容（WLN-08、WLN-09）。一件工作派出的部分，没另说为谁办、也没登记成新事件时，算为这件工作所在的事件办；主对话派出的不属于任何事件，等安放。没有焦点事件时，信息栏写这件事项（或项目）现在怎样：该你、在办、接下来、办完各几件，和从这里交办出去的任务。
- **停到侧边。** 信息栏「这件事现在怎样」右上角和清单头上的图钉：这件事的信息（或这张清单）停到侧边栏，对话收起；停着的卡带事件的图标与名字，内容与信息栏里是同一套读取与操作，随读取和任务总表一起更新。卡上「放回对话」回到它的对话，「关闭」只把卡收掉。哪些卡停着记在本机（按人按项目），刷新后还在（WLN-14）。
- **决定请求。** 为这个事件办的任务停下来等你定时，信息栏「该你做的」里一项一块：要你定的事、为什么问（不是这件事件自己在问时先说是哪个任务在问）、同意后会改动的地方一处一行，下面是同意、改一下、拒绝。第一块的「同意」是这一屏唯一的主按钮；等你这件事由状态环和文字一起表达，不只靠底色。「改一下」把光标放进底部输入框并带上这个事件，说的话作为修改意见交回这项任务，没写不发。每块各答各的；答完这一块收掉，任务接着办，事件回到进行中。同一条记录也在卡叠那张卡上：只有一道题、最多两个回答、不用补信息时能在卡上直接答，否则卡上只有「打开」（POLISH-44）。这些都来自任务总表行上的 `decisions`，回答经主线服务再问一遍主人后才执行（合同设计稿 §4），页面上的那份不算数。给不出回答动作的登记方（现在是 Coding）仍是「去处理」，到它自己的地方定（WLN-10）。
- **后台任务在哪看。** 没有单独的任务面板，入口就是「在办」的图标（或标签）：正在办的、排队的任务缩在所属事件的行下面，写当前这一步或排在谁后面、谁在办（助理、哪个 Character、哪个插件）；不属于任何事件的在清单末尾单独一组；等你的进卡叠。点任务行，信息栏的位置换成这项任务的卡（浮窗，可回到清单）；点子任务，同一个位置换成和它说话的浮窗，自带输入框，底部输入框的对象不变（决定 49）。右侧没有「后台任务」页（§8）。
- **对话的对方。** 输入框平时发给个人助理；在「给谁」里可以选一个 Character 直接对它说，对话栏换成和它的主对话，小标题写它的名字。两者是同一套：先回应、能后台办的派到后台、结果回到说话的这一方。
- **回流。** 任务办完、失败、缺信息、要你定，或它等的条件到了，结果先回到派出它的助理（或 Character）；它按当时的上下文判断：告诉你、接着派下一步、问你，或者先不打扰。行为与边界归[主动助理](../proactive-assistant/spec.md) §7.5.4，本书管它在清单、卡叠和信息栏里怎样显示。
- **手边。** 输入框下面一行左边的「＋」：Shelf、灵光、资料，拿一样附到正在写的话上；可以钉到侧边。
- **左上角那一格。** 窗口左上角写着「项目 › 事项」的一格：事项的状态环、名字、等你的琥珀数字。点开向下展开清单，切换项目和事项（内容照主线 §4.1；事项部分随第 37 批）。
- **安放。** 说完一句话，助理先马上回应，再判断这件事的去处：是对某个事件背后任务的补充，是为某个事件办的一个新任务，值得登记成一个新事件，属于另一件事项，还是不属于任何事件、只在「在办」清单末尾那一组里。去处写在回应里，一点就能改。

## 3. 原则

1. **线是读出来的，不是存出来的。** 一个事件背后的事实各有主人（任务板、插件、工作记录）。线只存两样属于它自己的东西：焦点在哪、用户对建议的移走与固定，都放在已有的地方（§6.2）。
2. **一个输入框，一个焦点。** 工作台仍然只有底部这一个输入框（UIV-18）。焦点决定这句话发给谁：在「现在」是交办新的事，在事件上是对这件事接着说。发给谁在框里一直看得见。
3. **不盖住正在做的内容。** 输入框多行时向上长，被它压到的主区和侧边栏向上让出同样的高度，底部另外两块的高度不变。
4. **点和说都能办。** 卡叠和信息栏里能点的（同意、勾掉、打开、开始办）不要求打字；要说的（改一下、补充）不要求先找到对话。两种办法作用于同一件事，结果一致。
5. **查看不等于切换。** 聚焦一个事件不改当前事项，不改在跑工作的范围；点开另一件事项的事件先切事项（切换是显式的，主线原则 4）。
6. **进展是真的。** 事件的状态词、步骤、等待原因都来自任务板和插件的事实；读不到就写「读不到，最后更新于…」，不沿着旧状态转圈（PWA-132）。
7. **插件同等待遇。** 任何插件按同一份登记让自己的对象成为事件、给出下一步；助理登记「交办的工作」走的也是这一份；宿主里没有按插件名的分支。
8. **安静。** 清单里只放有时间意义或要你处理的东西；资料、文稿这类静态的东西在「这件事的东西」里（侧边栏），不进清单。后台更新不抢焦点、不推走正在读的内容（PWA-139）。
9. **先回应，再安放。** 输入送达后助理先给一句真实的回应（接单、直接回答或缺什么），不等判断完放到哪、更不等办完。安放是助理的判断，可能不准：结果一定显示、一步能改，改了不重做已经做的部分。安放只决定这件事显示在哪、带哪件事项的上下文，不授予任何权限。
10. **不是每件事都是事件。** 随口交代的、和当前事项无关的事照样能办，不为了进清单硬登记成事件；它在「在办」清单末尾「不属于事件」一组，有自己的卡。
11. **版面就是引导。** 新用户不用学：输入框在正中，右边一叠是该你的，输入框里三个图标是办完、在办、接下来，点开一件就开始。不靠常驻的说明文字。
12. **事件在清单里，任务在背后。** 清单的行是事件，三个数数的也是事件。任务不单独占一行的位置：它让所属事件的状态变化，自己缩在事件行下面（用户 2026-11-14 定；位置 2026-11-17 按 §16 改）。
13. **结果回到说话的那一方。** 后台任务的结果、提问和失败先回到派出它的助理或 Character，由它判断并推进；不要求用户去各个任务里收结果、再回来转告。

## 4. 用户能做什么

可点的原型是 [`docs/design/screen-polish/helm.html`](../../docs/design/screen-polish/README.md)（第 34 屏，2026-11-17 定稿，§16）；第 32 批的方向原型在 [`docs/design/work-line/`](../../docs/design/work-line/README.md)，只留作记录。下面写行为，样子以定稿原型为准。

### 4.1 外壳

窗口从上到下三段：

- **顶部一条。** 后退、前进；左上角「项目 › 事项」那一格；当前事项里打开的页签；「＋」打开起始页（全部插件与快捷入口）；最右只有侧边栏开关和分屏。顶部没有留用插件的图形，也没有头像。
- **中间。** 主区（页签对应的页面，可分屏）和右侧的侧边栏。侧边栏保留：Shelf、灵光、资料、浏览器、停到侧边的卡，以及「这件事的东西」（主线 §4.3）。
- **底部三块。** 一样高、一样的圆角、等间距：左边账户条（头像、名字、通知、插件、设置；同步状态是头像上一个点），中间输入框，右边卡叠。输入框固定在窗口正中，宽度按窗口档位固定，不随旁边的东西移动或变窄。对话从输入框向上展开（§4.2），浮在主区上、不让主区让位；只有多行输入让位，这时输入框向上长，另外两块不动。

这是对第 07 批工作台分区的改动，见 §8。

### 4.2 说一件事

- 输入框两行：上面一行是字，下面一行是带着什么、给谁、语音、发送。回车发送，Shift 加回车换行，输入法组合输入时不发送。写到多行，框向上长，主区和侧边栏的下边一起向上让，内容不被盖住；删回去，原样落回。
- 「＋」打开手边：Shelf、灵光、资料三页，点一项附到这句话上；右上角可以把它钉到侧边。
- 输入框上方是**助理的对话**，沿用产品现有的那一个面板和消息样式，不另画一套。它分对话栏和信息栏（§2）。对话关着时输入框上面什么都没有：输入框里面右上角是办完、在办、接下来三个图标和一个展开键；回复到了而对话关着，展开键上一个点，助理在等你确认时这个点是琥珀的，并且卡叠里有一张「助理在等你确认」。点主区、换页签、开设置，对话完全收起；收起键或 Esc 也收回。
- 对话栏右上角三个键：最大化（对话和信息栏顶到页签下面）、更多（「另起一件」「全部工作」）、收起。小标题写这句话是对谁说的：专注到事件时是「状态点 事件名 · 类型 · 事项名」；主对话是「助理 · 主对话 · 事项名（或项目名）」；和 Character 的主对话写它的名字。
- 对话有七种，对话栏一次只是其中一种，由焦点和「给谁」定：和助理的主对话（默认）；和某个 Character 的主对话（「给谁」里选它）；另起的一件工作（「更多」里的「另起一件」，助理把它登记成事件）；为某个事件办的那件工作（专注到那个事件时）；主对话交出去的后台任务（在「在办」清单末尾「不属于事件」一组，等你的进卡叠）；页面自己接话（如 Coding 会话：输入框发给这一页，对话栏只写一行「这一页自己接话」和「改成问助理」，不重复页面里的对话）；以前的工作（「更多」里的「全部工作」）。发出去的话去哪的规则不变：没专注到事件，去这个范围和这个对话方的主对话；专注到事件，去为它办的那件工作；页面接话，去页面。
- 发送后输入框立即清空，可以马上说下一件；上一件还在办也一样（PWA-128）。助理（或你选的 Character）的回应出现在对话栏里，分两拍：
  1. **马上回应**：一句话说明收到了什么、打算怎么办；能当场答的直接答；缺必要信息就问那一处。要持续办的派到后台，这一轮就结束，不占着对话。
  2. **安放**：回应末尾写明去处，例如「为：设计评审会 · 新任务」「补充给：起草公告」「新事件：发布公告」「放到：整理评审反馈（另一件事项）」「不属于事件 · 在后台任务里」，旁边一个「改」。
- 安放的五种去处：
  - 对某个事件背后已有任务的补充或修改：成为那项任务的一轮输入；
  - 为某个事件办的新任务（比如为「设计评审会」准备材料）：任务出现在「在办」清单里这个事件的下面；事件变成进行中；
  - 值得跟的新工作：助理登记一个新事件（「交办的工作」），进「在办」清单，任务挂在它后面；交办出去时一个点从发送键飞到「在办」的图标。什么算值得跟见 §6.4；
  - 另一件事项的工作：事件或任务落在那件事项里，当前的清单不变；回应里可以一步切过去；
  - 不属于任何事件：只在「在办」清单末尾「不属于事件」一组。
- 拿不准而且放错会影响结果时，只问必要的那一处（「是给『起草公告』的补充，还是另一件事？」），其余照常进行；不默认塞给最近的事件（PWA-129）。
- 用户自己选了去处时不再判断：专注在一个事件上说的话就是给它的（§4.4）；在「给谁」里选了收件人的照选的来。
- 点「接下来」清单里的一个建议：焦点到它，信息栏最上面写着它从哪来，「开始办」把它填进输入框，可以改了再发。
- 临时问一句、能当场答的，直接在主对话里答，不建事件（PWA-127），留在这条对话的记录里。
- 一句话里交代几件事，各成一个任务，值得跟的各登记事件；有先后的，后一个标「等前一件」。
- 后台任务有了结果、要你定或办不下去时，助理在派出它的那条主对话里说一句归属明确的话：哪个任务、结果或问题、能点的下一步。你正在写字或在看别的事件时不抢焦点、不替你换对话，对话关着时展开键上亮一个点，等你的进卡叠（PWA-133、PWA-139）。助理在原交办范围内自己接着派了下一步的，也说一句做了什么（主动助理 §7.5.4）。
- 回复在任何地方都渲染 Markdown：对话栏、信息栏、卡叠、子任务浮窗里都不露出 `**`、`##`、反引号这类记号（POLISH-20）。

### 4.3 看进展

- 有任务在办的事件在「在办」清单里显示当前这一步的名字（「查资料」「起草中」），不是百分比；缩在它下面的任务行显示同一句。排队的写排在谁后面。
- 任务需要你的时候，它所属的事件进卡叠，卡叠亮一次，左上角那一格的琥珀数字加一；主对话里由平台直接写一行（不调模型、立刻出现，按任务与决定去重，不再等你时收起），带一个「去处理」，点它或点卡就到这个事件。不替你打开对话、不打断正在写的话；指针或焦点在卡叠里时，最上面那张不被换掉（POLISH-42）。不属于事件的任务等你时也进卡叠。专注着的那件不在卡叠里，它在信息栏最上面。
- 任务办完，事件回到主人给的状态；产出的结果对象由它的主人登记成事件，进「办完」清单，到达的那个图标（或标签）亮一次。
- 助理用到浏览器时，侧边「浏览器」页亮一个点，打开能看到它在看什么；不打开不影响你。

### 4.4 点一个事件

点一件事件（清单里的行、卡叠的卡片本体、主区里的行）：对话栏换成为它办的那件工作的对话（对话没开就先打开），小标题换成它；顶上多它的一页，主区换成那一页；信息栏是它的信息，从卡叠、主区或页签点开时标签自己回到「信息」，从清单里点开时清单留着、点的那行亮着，可以接着点下一件。下文说的「专注到事件」就是这个状态。信息栏按种类：

| 事件 | 信息栏里有什么 | 能点什么 | 接着说会怎样 |
| --- | --- | --- | --- |
| 交办的工作 | 交办的原话；背后的任务与拆解，每步写明谁在办、做到哪一步 | 暂停、停止；点一步看它的产物 | 作为补充交给对应的任务，回执写明「已收到」还是「已用上」 |
| 结果 | 结果的预览、来自哪里、关联到什么；过程折叠 | 打开结果、放到 Shelf、验收或再改改 | 在这个结果上继续改，产生新版本 |
| 待办 | 标题、备注、计划日期 | 主人声明的动作（勾掉、改期） | 让助理处理其中一项：一个为它办的新任务 |
| 日程 | 时间、地点、参加的人 | 让助理准备材料 | 同上 |
| Coding 会话 | 这次会话在做什么、改动概况 | 停止 | 页面自己接话：话发给这次会话；改成问助理后是助理为它办的那件工作 |
| 建议 | 从哪来、为什么是现在 | 开始办、以后再说、不再建议 | 改了说法再开始 |

- 任何事件背后有任务时，「这件事现在怎样」多一段「在办」：一个任务一行，写当前这一步或等待的原因，可以就地暂停、停止，点开是信息栏位置的任务卡。
- 有任务停下来等你时，信息栏最上面是决定请求（§2）。
- 顶上的页：主人插件登记了打开方式的，开主人的对象页（`objects.open`）；主人没有页的，平台用这件事件的组合呈现画一页（方案第九节第 7 条）。关页签只关页，那件事还在办；关掉后回到整件事项（或项目）的主对话。
- 点「信息」、再点一次选中的标签、按 Esc：信息栏回到这件事的信息。Esc 由里到外关：菜单、清单、浮窗、对话。专注不改当前事项。
- 「停到侧边」（「这件事现在怎样」右上角的图钉）：这张卡搬到侧边栏，一直开着，对话收起，可以一边在主区做事一边看它、点它。

### 4.5 后台任务

- 没有单独的面板，也没有对话右上角的任务图标。入口是「在办」：对话关着时是输入框里的图标，带在办的事件数；对话开着时是信息栏顶上的标签。
- 「在办」清单一行一件事件，背后的任务缩在它下面：名字、当前这一步或等待的原因、谁在办；派给子代理的步骤再缩一层。最后一组是「不属于事件」：主对话交出去、没安放到事件上的任务，不计入三个数，行尾的「改」能把它挂到一个事件或登记成新事件。清单头上有「这件事项 / 全部」的切换（「全部」跨事项，随第 37 批）和「停到侧边」的图钉。
- 可以就地停止、重试；更新不移动正在操作的行、不抢焦点（PWA-132、PWA-139）。断线时每行写「正在核对」，不给动作。
- 点任务行：信息栏的位置换成这项任务的卡（可回到清单）：谁在办、为哪个事件、结果回给谁、步骤，可以补充、停止、重试、改去处；挂了要求的出逐项概况。对话栏不换，顶上不多页。
- 点子任务：同一个位置换成和它说话的浮窗，自带输入框；底部输入框的对象、对话栏、页签都不变（POLISH-66，决定 49）。
- 可以把一项「不属于事件」的任务挂到一个事件，或登记成新事件；也可以把任务从事件上移开，它回到「不属于事件」。已经在办的不停、不重做。
- 所有插件的后台工作按同一个形状报上来（§6.4），清单里没有按插件名的分支。没有第二份任务清单：清单、卡叠、任务卡三处读同一份（PWA-138）。

### 4.6 切换事项

- 窗口左上角那一格显示「项目 › 事项」；点开向下展开清单：左列项目，右列这个项目的主页、最近切过的 3 件、按组折叠的事项（各带等你的件数）、搜索、「新建事项」「整理主线」。内容与规则照主线 §4.1、MLN-23。没有事项容器的界面以前，那一格只有「项目 › 项目主页」，清单里只有项目（事项部分随第 37 批）。
- 切换后整页都换：那一格、页签、主区、侧边栏、输入框的提示语、卡叠、三个数和点开的清单；没发出去的字和手动选的「给谁」按事项各留各的。正在跑的工作不停、不改归属，切回来还在原处。
- 别的事项有事件等你时，卡叠最后一张写「别的事项还有 N 件等你」，点开是左上角的清单。

### 4.7 助理对话并进来

- 主对话就是默认的对话栏：交办、提问都从这里；对方是个人助理，或在「给谁」里选的 Character。主对话每一轮都短：回答、派出、收尾；持续的工作在后台任务里办，所以随时能说下一句（主动助理 §7.5）。
- 每项任务的来往在它的卡里（从「在办」清单或信息栏打开）：交办的原话、回复、你的补充、它的提问，按这项任务排，不和别的任务混在一起。
- 要按时间看全部（跨事件的来往），打开「整条线」（第三片）：一条时间线，每段标明属于哪个事件或任务，点一段专注过去。
- 没有第二个助理面板，对话顶上也没有标签栏。原来标签栏上能到的地方各有去处：主对话是默认；Character 从「给谁」进；事件的对话是专注到它；「另起一件」「全部工作」在对话栏右上角的「更多」里；提醒里要人处理的进卡叠，系统类的在账户条的通知键（WLN-15）。

### 4.8 侧边联动

- 主区条目上的「放到 Shelf」落到侧边 Shelf；Shelf 里点一项附到正在写的话上。
- 一件事的信息停到侧边后，主区、侧边、信息栏三处是同一件事：在侧边点了同意，清单和卡叠跟着变。
- 侧边栏开合前后输入框的位置和宽度不变（POLISH-59）。对话打开时信息栏盖在侧边栏的下半部分上，点主区或侧边栏的空白处收起。

### 4.9 窄屏与键盘

- 按窗口宽度三档。**960 及以上**：账户条、输入框、卡叠三块并排；信息栏在对话栏右边、卡叠正上方。**541–959**：底栏只有输入框一块，卡叠收成输入框里面右上角的「该你 N」，点开的卡在输入框上方、能直接回答；头像只一枚，在顶部最右；信息栏收进对话里面，在右边，宽 232。**540 及以下**：同上一档，对话占满主区，信息栏叠在对话上面（清单也在这里），只留该你做的和现状；触控目标不小于 44px（WLN-18）。
- 清单的一行放不下时先截事实（步骤、时间、一句话），名字至少保留六个字（POLISH-09）；要留意的状态（等你、失败、已停止、待核对、已不在、无权查看）的状态词在任何宽度都留着，状态不只靠颜色区分。信息栏顶上的标签窄到放不下名字时，只有选中的带名字。
- 键盘：Alt+L 把焦点放到卡叠最前面那张，没有卡时放到输入框里的三个图标；标签之间左右键移动；清单里上下键在行间移动，回车打开，Esc 回到这件事的信息；信息栏里 Tab 走按钮，回车是主操作。全程不用鼠标能走完交办、同意、打开（WLN-17）。
- 读屏：清单是一个列表，每个事件读出登记方、名字、状态；状态变化用礼貌的播报，不抢断。
- 减少动态效果时，卡和数字直接换，不飞。

### 4.10 异常

- 发送失败：话留在框里，写明原因，可重发（沿输入回执）。
- 排队、缺授权、模型连不上：任务行和它所属的事件写真实状态（「排队中」「缺授权」「连不上模型」），信息栏里给下一步。
- 工作失败或部分完成：事件带红点进卡叠，信息栏里列出做成的和没做成的，可以只重做没成的；结果不确定的卡上只有「去核对」，不给重试（POLISH-43）。
- 对象被删、被移走或没有权限：事件显示「已不在」或「无权查看」，可移走，不显示旧内容（主线原则 7）。
- 断线、宿主重启：回来后清单和卡叠先显示最后一次确知的样子并标「正在核对」，核对完以前没有可点的动作，核对完再更新；不重复派出（PWA-137，POLISH-54）。
- 事件很多：「办完」清单先列最近的 8 件，末尾写「更早 N」，点它看更早的；清单里的事件数不随历史无限增长（WLN-24）。
- 某个登记方读不到：它作为一个虚线条目固定在打开的清单标题下面、不随清单滚走，可以重试；清单里其余事件照常（WLN-37）。

## 5. 插件要登记的

线上的事件靠登记，不靠宿主认识插件。登记是一份声明加一个读取动作，不是往平台里存东西：

| 登记什么 | 说明 | 写在哪 |
| --- | --- | --- |
| 哪些对象是事件 | 对象种类（`ActionSubject` 的种类），以及一个读取动作：给定项目（第二片起加事项）与时间范围，返回这个插件此刻该在线上的事件引用 | 一个插件只报一遍：首选在今天的首页事项读取上扩（Feed、Inbox、待办已在报），线和首页读同一份；是扩它还是并成一份新的，由第 32 批的合同稿定 |
| 时间角色 | 对象的哪个时间是「发生于」（办完的时间）、哪个是「排在」（开始或到期）；没有时间、也不等你的对象不上线，只进「这件事的东西」 | 呈现声明的字段（智能呈现 §4.1 已有「时间」这个语义角色，补上两种用途） |
| 要你处理 | 对象处在哪些状态时算「等你」 | 呈现声明的状态映射（§4.1 已有「要你决定」「要你验收」） |
| 下一步（可选，第二片） | 一个读取动作：给定一个对象，返回它的下一步（文字、能不能直接开始、开始时调哪个动作） | 事项来源声明里，与「自家关联」并列 |

- 事件卡用哪种形态、带哪些操作，全由呈现声明和组合服务定；插件不为线另写样式或另给一套操作。
- 状态变化经呈现声明里的变更通知（智能呈现 §4.6）告诉线，线不轮询。
- 全部是动作目录里的动作，按调用方的权限调用；可信身份从调用上下文来。
- 助理按同一份登记放「交办的工作」，没有只给助理的通道。登记写在插件的 Manifest 里：声明一个用事件读取合同的查询动作，装上的插件和内置的一样（用户 2026-11-14 确认）。第一片的登记方是五家：助理、Coding（会话）、待办（到期的待办）、Feed、Inbox（后两家今天已在报首页事项，随合同改名一起上线；用户 2026-11-14 定），另加一个测试用的沙箱插件，证明装上的插件同样能登记；日程、Inbox、工作流程、Pages 在第三片接。
- 后台任务不在这份登记里：插件自己的后台工作报到后台任务总表（§6.4）。一个插件可以两样都报，用同一个对象引用把任务挂到事件上。
- 第一个用上「下一步」的是 Goals；待办的到期、日程的开始时间走「时间角色」。Goals 不在时线照常工作，只是没有 Goals 的下一步（2026-11-13 按插件同等地位收口改，[决定 42](../post-anticorruption-roadmap/reference/decisions.md#decision-42)）

## 6. 平台负责的

### 6.1 线读取

- 主线服务（主线 §6 的 `horizontal/` 包）多一个只读的系统动作：给定项目与事项（可以不选），返回这条线上的事件引用和排法。它自己不存事件，一次调用里合并：
  - 各插件与助理登记的事件（§5）；
  - 这件事里装的、带时间角色或处在「等你」的对象（placement 关联加来源插件的自家关联，第二片）；
  - 每个事件背后任务的状态：后台任务总表（§6.4）的每一行带着它为哪个事件办，对上事件，推出进行中与等你；
  - 来源对象的下一步（§5，第二片）；
  - 第三片起：主动助理给的建议。
- 返回的是引用（`ActionSubject`）、种类、时间、状态家族和排位，不带标题和正文；标题、状态词、卡的内容由组合服务按呈现声明取。
- 页面、助理、工作流程、MCP 调同一个动作；外部 Agent 读到的是同一条线的文本形态（智能呈现 §4.5）。
- 调用次数：切到一件事项，线读取一次、组合服务一次批量给出两翼的胶囊；事件卡在聚焦时才取。不按事件逐个请求。

### 6.2 每样事实归谁

| 事实 | 主人 | 线怎样用 |
| --- | --- | --- |
| 事项、分组与顺序、当前事项 | 主线服务 | 线头与切换 |
| 哪些对象是事件 | 登记它的插件；一件交办是不是事件记在助理工作上 | 线读取 |
| 任务、步骤、依赖、等待、接续 | Prologue 任务板（采用线），经 `horizontal/agent-host` 读 | 事件背后的任务与拆解；后台任务面板 |
| 还在跑或等人的后台工作（跨插件的概况） | 各插件与平台按同一形状报的后台任务总表（§6.4） | 后台任务面板；事件的进行中与等你 |
| 交办的原话、补充、回执 | 发起这项工作的一方（助理工作、Coding 会话）与输入回执 | 事件卡里的对话 |
| 插件对象的标题、状态、时间 | 各插件 | 待办、日程、结果等事件 |
| 这件事里装了什么；一项工作归哪件事项 | `horizontal/placement` | 哪些对象可能上线；安放的结果 |
| 一个任务为哪个事件办 | 任务的主人（助理工作、Coding 会话…）；placement 按主人的关联声明列出、挂上、解开，自己不存 | 事件背后的任务；面板里每行标的事件；安放与「改」 |
| 发生过什么、先后 | 工作记录（观测和采集层） | 「整条线」的时间线 |
| 卡长什么样、能点什么 | 插件的呈现声明加组合服务 | 胶囊与事件卡 |
| 焦点在哪个事件、卡停没停到侧边 | 工作台状态（PFG-22，按事项那一层） | 切回事项时恢复 |
| 移走、固定、不再建议 | 组合服务的纠正记录（智能呈现 §5「纠正」） | 建议的显示 |

线读取的结果可以缓存，但不是事实：缓存和主人不一致时以主人为准，重读即可。

### 6.3 输入框与焦点

- 专注到一个事件，等于在统一输入里把它选成收件人（UIV-23）：输入框的提示语写它的名字，「给谁」菜单里「这件事项的事件」一组和清单里的是同一批，只是另一种选法。输入框固定在窗口正中，不跟前台页面的对话栏对齐（[统一输入 §10.5](../unified-input-voice/spec.md)）。
- 页面登记的收件人（比如 Coding 页里的会话）也是事件；页面自己接话时输入框发给这一页，对话栏不重复它的对话。
- 草稿按收件人分开存：专注到事件时写了一半，回到主对话再回来，字还在。
- 助理工作的范围不因聚焦别的事件改变；补充何时生效按输入回执如实写。
- 「发给」里也能选一个 Character：这句话由它接，它派出的任务结果回到它；框里一直看得见现在是对谁说。切回助理后，两边的草稿、对话与任务互不串。

### 6.4 安放与后台任务总表

- **谁来判断。** 接这句话的一方（助理或所选的 Character，经 `horizontal/agent-host` 调模型）。平台给它两样东西，插件和页面不各写一份：
  - **提示词**：平台维护的一段安放说明，随角色定义下发（[Prologue AI 手册](../../docs/platform/PROLOGUE-AI.md)的提示词管理），讲清五种去处、什么算值得跟、什么时候该问、不该默认塞给最近的事件；回复语言照平台给的回复语言。
  - **工具**：动作目录里的系统动作，助理和页面、MCP 用同一组——读这条线的文本形态（当前事项、线上的事件、别的事项的名字）；把一个任务挂到线上的一个事件；把一件交办登记成事件；作为补充交给已有的任务；把工作归到另一件事项（第二片）；标为不属于事件。
- **什么算值得跟。** 会交回东西的（一份文稿、一张表、一次改动）、用户说了要跟的、和线上已有事件相关的，登记成事件或挂到那个事件；随口的、当场能了结的不登记。这是模型的判断，写在安放说明里，不写成关键词规则。
- **顺序。** 输入送达 → 第一句回应开始输出（不等安放）→ 安放的工具调用 → 回应末尾补上去处。安放没完成时这件事已经在后台任务面板里（去处写「正在安放」），不会看不见。
- **改。** 「改」调同一组动作换去处；已经开始的任务不停、不重做，只换它显示在哪和之后带的上下文。
- **事实。** 一个任务为哪个事件办，由任务的主人记，经 placement 的关联声明统一操作；一项工作属于哪件事项是 placement 的关联（第二片）；一件交办是不是事件记在助理工作上。都不在线上另存。安放不改这项工作的授权、预算与数据范围（PWA-135）。
- **模型不准时。** 不为个别说法加措辞禁令、正则或特例；靠三件事兜住：去处永远显示、一步能改；改不产生副作用；安放的工具只接受这个调用方读得到的事项与事件，别的引用被拒。
- **后台任务总表。** 后台任务面板读一份总表（[平台能力审查](../../docs/reviews/platform-capability-audit-2026-11-14.md)第 3 项）：平台跑的后台作业与调度任务由平台自动报，插件自己的长任务用现有的首页聚合读取报，助理与 Character 派出的工作也报这一形状；暂停、停止沿用行里带的命令。面板和线读取是同一份事实的两种排法，不另存任务清单（PWA-138）。
- **等你只读一处。** 线头的数字、事件上的等你、面板里的等你读同一份（平台能力审查第 4 项的读侧）；写侧的收拢在第 56 批。
- **回流。** 任务的结果回到派出它的一方，由它判断并推进；归[主动助理](../proactive-assistant/spec.md) §7.5.4 与 [Prologue 采用](../prologue-adoption/spec.md) §4.6.11，这里不另造消息通道。

### 6.5 外壳

- 顶部一条、底部三块的版面由工作台外壳提供；插件只提供内容，不各自画清单、卡叠或在页面里放第二个输入框（`AGENTS.md` 外壳约束、UIV-18）。
- 让位：只有多行输入让位——外壳量出输入框比静止时多出的高度，给主区和侧边栏加同样高的下边距；对话栏和信息栏浮在主区上，不让位；账户条和卡叠的高度是常量。
- 清单的行、卡叠的卡、信息栏的三张卡与标签、对话栏的小标题、任务卡是共用部件，先成组件板标本再进产品。

**实现时的调整（2026-11-14 随第 32 批落地；下面各条讲线头、事件标签、任务面板和对话框标签栏的画法已由第 36A 批按 §16 换掉，现行的落点见本节末尾「第十三版的落点」）。**

- **底部。** `renderWorkbenchBar` 只画线（`renderWorkLine`），助理输入框放在线中间的槽里，侧边面板仍是它的兄弟节点。线自己排版（`work-line-layout.ts`），原来给底栏分三列的脚本 `bar-column` 删掉；线是一行时，输入框仍按 UIV-19 以工作区（或前台页面报的对话栏）居中、不越过工作区右边（右侧面板打开时不压到它），由线的排版来做。
- **线的读取。** 线、线头的等你数和后台任务面板都不自己轮询（合同设计稿 §11）：页面原有的那一次「等你」读取（`GET /api/attention`）在项目页多带两段——这个项目的线（前 30 天到后 2 天）和任务总表，都由主线服务按本人读；浏览器里一段程序（`apps/workbench/src/browser/work-bar.ts`）从这一次读取的通知（`molis-work:attention`）里画，两次读到的一样就不重画。点重试、停下一项任务、打开面板、助理的工作换了状态时，请页面马上再读一次（`molis-work:attention-refresh`）。画事件、读不到的来源、线头的等你数用的是组件板同一套部件（`work-line-parts.ts`）。
- **线头**在第一片点了回到项目首页；切换事项的菜单随事项（主线）那一片做。
- **主对话。** 对话框第一个标签是主对话（助理一件；每个用过的 Character 一件），不能关；没有选中别的工作时发出去的话带 `main: true`，落在这个范围的那一件上。标签栏右边的 ＋ 是「另起一件」，这时发出去的才是新的一件工作。在主对话里「发给」另一个对话方，宿主把这句话转到那个对话方自己的主对话（`mainSendInput`），不在一件主对话里混两个对话方。
- **后台任务。** 任务图标在对话框标签栏右上角，数字是在办的件数，有等你的变色；点开的面板浮在对话框旁边，不挤对话框也不让工作面让位。停下走 `/api/mainline/tasks/command`，由主线服务再问一次主人。项目页右侧的「后台任务」页和标题栏图标删掉，`/api/attention` 在项目页不再带跨项目的后台任务一段；首页（选项目那一页）没有线和对话框，它标题栏的跨项目列表照旧。
- **事件标签。** 点线上的一个事件，线告诉助理对话框（`WorkBarHost.openEvent`），对话框开出这个事件的标签（标签上是登记方的图标与事件名），对话框反过来告诉线哪个事件的标签在前面，线给它描边（`aria-current`），事件不动位置。助理自己的工作登记成的事件，开的就是那件工作原来的标签。哪些事件开着只记在这一页里，刷新后回到主对话。
- **事件卡。** 标签里最上面是事件卡：页面向 `POST /api/mainline/event/surfaces` 要这个对象的组合呈现（和对话里的对象同一套组合服务、同一个页面部件 `host.positions.mount`），宿主先按本人读一次线，对象不在线上就拒绝（`actions.subject_unavailable`），插件页不能调。工作台里没有按事件种类或插件写的卡片内容（WLN-08）。
- **在事件标签里说话。** 这个标签下面的对话是「为这个事件办的那件工作」：最近一件 `serves` 指向它、由用户自己说出来的助理工作。还没有时，第一句话带 `for_event`（事件对象的 kind 与 id），宿主核对这个事件确实在本人这个项目的线上，再建一件 `serves` 它的工作；它是这个事件背后的任务，不是线上新的事件（WLN-12），可以在面板里移开，移开后它自己成为事件。主对话不能带 `for_event`。输入框的提示是「关于这件事」，「发给」显示事件名，旁边的叉回到主对话（WLN-03、WLN-07）。
- **插件页交办。** 插件页把一个对象交给助理（如待办的「交给助理」）时，这句话是关于那个对象的，不进主对话（WLN-33）：对象在线上，就开它的事件标签，接着那里已有的对话说；不在线上，另起一件工作，这件工作自己成为线上的事件。页面点名了某件工作的，仍回到那件工作。
- **键盘。** Alt+L 把焦点放到线上：有事件标签在前面就落在那个事件上，否则落在紧挨「现在」的那件；左右键按线上的顺序在事件间移动，回车就是按下这个事件，Esc 回到现在（主对话在前、光标回到输入框）（WLN-17）。
- **草稿。** 有工作的标签，草稿跟着那件工作（宿主存）；还没有工作的事件标签，草稿按事件各存一份在这台设备上，和主对话、新工作的草稿互不串（WLN-13）。
- **任务卡与改去处。** 面板里点一行，面板换成这项任务的卡（返回键回到列表）：状态、谁在办、为哪个事件、交回给谁、当前这一步，可以停止、一步到它所属事件的标签、在它的插件里打开。「改」列出线上的事件、「登记成新事件」「不属于事件」，现在的去处打勾；选了以后走 `/api/mainline/place`，由任务的主人记，在办的不停（WLN-36）。助理这一侧的规则：助理派出的任务三种去处都行；用户自己说出来的工作（在事件标签里说的）可以挂到别的事件或登记成新事件，不能「不属于事件」——它不挂在别的事件上时，自己就是线上的事件，主人会拒绝并说明。
- **回应末尾的去处。** 一段回应里交到后台的每件任务，在这段回应末尾各有一行：为哪个事件办、登记成了新事件、或不属于事件，带「改」（WLN-32）。这一行由线来画（事件的名字用线上的），放在交出它的那一轮之后（按任务的交出时间落在哪一轮里算）；「改」打开后台任务面板里这件任务的卡和去处菜单，改法与面板里相同，任务总表还没读到这件任务时等这次读取回来再打开。去处改了以后，对话按任务总表发现不一致就重读这件工作，这一行、线和面板一起变。补充给已有任务的话不另出一行：那件任务的去处没有变，过程里已写明追加给了谁。收回的任务不出这一行。
- **「发给」。** 项目里，框里的标签点开就是「发给」菜单（不在项目里时仍是打开对话）：「现在」一组是助理和能对话的 Character（说过话的排前，其余是项目里现在可用的），「线上的事件」一组与线上显示的是同一批，选一个等于在线上点它；有页面接话时前面多「这一页」、后面多页面自己的别的会话。菜单的勾和标签显示的一致。选了还没说过话的 Character：它有自己的标签（可关，关了回到助理）和自己的草稿，发出去的第一句带 `main: true` 与这个 Character，由宿主开成它的主对话；说过话的直接到它的主对话。Character 的主对话派到后台的任务，没有另点角色时由这个 Character 办、结果回到它的主对话，后台任务面板「谁在办」写它的名字（WLN-40）。Character 停用或移除后，它的主对话与在办的任务照常显示、可停止，再发话由宿主如实拒绝。
- **逐项概况与要求栏（32-2，2026-11-15）。** 事件卡在决定请求下面多一段：这个事件自己的对象和为它办的每项任务，只要挂了要求（`acceptance.read@1`，`modules/acceptance`），各出一行「执行／核验通过 n/总数／你的认可 n/需要你的项数」和「逐项审阅」；没挂要求的不出这一段。点「逐项审阅」，要求栏出现在工作面左侧（320px，工作面让出这一栏；390 宽时盖在工作面上），助理对话框收起，关掉要求栏时回来，焦点回到「逐项审阅」；要求栏开着时又点了线上的事件（对话框重新打开），要求栏自己收起。一条要求一张卡：状态环加状态词、所核版本与对象、工程检查和产品实操各一行（方法）、证据小片、不算通过时的一句原因、各轮记录；栏里只有第一条等你的那一项是主按钮。认可带屏幕上的交付版本和这条要求的版本；退回必须写原因，空着不发；改要求只有本人能改。页面走本人入口 `/api/acceptance/{read,decide,requirements}`（S-work-line-person-doors），拒绝时显示服务给的原话并重读；同一刻要读的对象（线上各张卡、开着的要求栏）合成一次读取，同一个对象只问一次。重画保留列表位置。画法在 `apps/workbench/src/work-acceptance-parts.ts`，控制在 `apps/workbench/src/browser/work-acceptance.ts`；验证 `tests/work-line-acceptance.e2e.test.ts`（PWA-144～146，1440 中文与 390 英文）。
- **助理交办时带要求，交回时记交付（32-2，2026-11-15 用户定）。** 助理把一部分工作交给后台任务时，可以随 `delegate-work` 写最多 20 条要求（一句话、可选的预期结果、要不要本人认可）；宿主给它们编号 r1、r2……，以这项任务自己的身份挂到任务自己的对象上（`io.molis.work.assistant.rules` 的 `assistant_work`），任务说明里列出同一份。挂了要求的任务多一个工具 `report-delivery`：说这一版做了什么、这次动到哪几条、每条怎么核的、看到了什么，宿主据此记一个交付版本（第 n 轮就是 `v n`，带做出它的那一轮）和逐条核对；它写不到别的对象上，也不能替本人认可（S-assistant-delivery-own-object、S-acceptance-person-decides）。交回给助理的材料和 `check-delegated-work` 的结果里是平台现算的逐条状态（没交付、只有自述、机器核过、等你认可……），不是任务自己的话。个人范围（没有项目）的工作没有地方挂要求，要求只写进任务说明，不给 `report-delivery`，助理会被告知这一点。给别的对象（待办、Goal 等）改要求仍走 `acceptance.requirements.set@1`、先问本人。任务浮窗里这项任务的卡在事实下面出同一行逐项概况和「逐项审阅」（卡窄，三个读数一行、按钮在下一行），点了浮窗收起、要求栏打开，关掉要求栏时焦点回到任务图标：不为任何事件办的任务也能进要求栏。实现 `apps/local-host/src/assistant/assistant-delegation.ts`、`horizontal/agent-host/src/adapters/prologue-action-gateway.ts`、`apps/workbench/src/browser/work-task-panel.ts`；验证 `tests/assistant-delegation-acceptance.test.ts`、`tests/work-line-event-tab.e2e.test.ts`（PWA-144～146）。
- **样式守规矩。** 线的样式用共用的进场动效（`craft-rise`、`craft-rise-from-bar`）、共用的「轮到你」（`molisCraft.ask`，事件变成等你时响一次）、共用的溢出渐隐（`data-overflow-fade`），字号都在字阶上，不自己写滚动条规则。

## 10. 定样

- **方向原型**（不是定样）：[`docs/design/work-line/`](../../docs/design/work-line/README.md)。单文件、演示数据、自带一套颜色，没有用组件板的实件。用户 2026-11-12 看过第二版并认可方向；第三版加了线头切换、分种类的事件卡、点事件到中间、助理对话并入，以及用户看过第三版后提的右下角后台任务列表和「先回应、再安放」。原型早于 2026-11-14 的改动：里面线右端的后台任务按钮、把交办直接画成线上一项的做法是旧写法，定样不照它。
- **正式定样**在第 32 批开工时做，照[需求开发流程](../post-anticorruption-roadmap/reference/development-workflow.md)第 5 节：用组件板实件重做，1440、1024、390，中英文，深浅色，正常与异常（排队、失败、断线后核对、读不到）都有。至少对比这几处的方案：
  1. 事件卡展开时主区怎么办：浮在线上方（可一步停到侧边）、让主区让位、还是默认就开在侧边；
  2. 顶部一条里固定插件与标签的排法，以及标签很多时怎么收；
  3. 侧边打开时线的宽度；
  4. 390 宽的线；
  5. 回应与去处的样子：两拍怎样出现、「改」怎样选；
  6. 后台任务面板：收成一行与展开的样子、展开多高、和助理的回应怎样上下排、让位的动效；「发给」选了 Character 时框里怎样显示；
  7. 事件背后有任务时胶囊与卡怎样表达（进行中、等你、几个任务）。
- **定样结果**（用户 2026-11-14，§12）：方案 E 整体版，原型在 [`docs/design/work-line-32/`](../../docs/design/work-line-32/README.md)。上面七处的结论：事件开成助理对话框里的标签，主区不动；顶部当前插件带名字，放不下的标签收进「+N」的菜单；390 宽的线是输入框上方一条可横向滑的轨道；回应与去处在对话的每一轮下面；后台任务面板是对话框右上角的图标加浮窗，不让位；事件背后有任务时胶囊上是状态环加数字。
- 线、事件、线头按钮、后台任务图标与面板、对话里的去处行与「任务交回」标记、事件标签里的事件卡、收起时留在输入框上方的那一句回应是组件板新增，标本在组件板「事项线」一节（`/__ui/catalog/navigation?sheet=work-line`）。「发给」沿用输入框已有的接收者标签，手边附上的条目沿用输入框上方已有的随消息带上的那一条，不另做新部件（2026-11-14 做标本时对照产品现有控件定）。
- 主线切换列表（`docs/design/work-mainline-switch/`）与四种基础形态（`docs/design/intelligent-surfaces-forms/`）已定的部分照用。

## 11. 验收标准

位置和样子 2026-11-17 改为底栏第十三版。下面各条已照 §16 末尾那张表改进正文：WLN-01、02、06、16、17、18、24 随第 36A 批第 2 项（2026-11-18），WLN-03、07、15、35、36 和各条里讲位置的用词随第 36A 批壳层对话批（2026-11-21）；WLN-19、20 讲事项，随第 37 批第 2 项改。

9. **WLN-09** 背后有任务的事件，信息栏里显示交办的原话与任务板的拆解，每一步标出谁在办与状态；一个事件有几个任务时各自列出；拆解与任务板不一致的用例失败。

11. **WLN-11** 办完的事件在信息栏里显示结果预览；「打开结果」把它开成顶上的一页，「放到 Shelf」落到侧边 Shelf；过程默认折叠。

13. **WLN-13** 专注到事件时写了一半的话，回到主对话再回到这个事件仍在；各事件与主对话的草稿互不串。
14. **WLN-14** 「停到侧边」（信息栏和清单头上的图钉）后，卡在侧边栏保持打开；在侧边点的操作与在信息栏里点的结果相同，清单和卡叠同步变化。

16. **WLN-16**（2026-11-18 按底栏第十三版改写，§16）顶部从左到右是前进后退、左上角那一格、页签、＋、侧边栏开关、分屏；头像和插件入口在账户条；底部没有 Dock；从 ＋ 起始页能打开任一已装插件。
17. **WLN-17**（2026-11-18 按底栏第十三版改写，§16）键盘：Alt+L 把焦点放到卡叠最前面那张，没有卡时放到输入框里的三个图标；清单开着时上下键在行间移动、回车打开、Esc 关清单；交办、同意、打开三条主路径不用鼠标能走完；读屏读出事件的名字、种类与状态。
18. **WLN-18**（2026-11-18 按底栏第十三版改写，§16）960 以下底栏只有输入框一块，卡叠收成输入框里面右上角的「该你 N」，头像在顶部最右；540 及以下对话占满工作面；触控目标不小于 44px。
19. **WLN-19**（位置已由 §16 改到左上角那一格、向下展开；正文随第 37 批第 2 项改写，见 MLN-02）线头按钮显示当前事项的名字、状态环与等你的数量；点开的列表向上展开，内容与规则符合 MLN-23；没选事项时显示项目的线。
20. **WLN-20**（换事项整页都换，§16；正文随第 37 批第 2 项改写）切换事项后，线、标签、侧边换成那件事的；切换前聚焦的事件与停在侧边的卡，切回来时恢复；在跑的工作不停、不改归属（MLN-06）。
21. **WLN-21** 线读取是主线服务的一个只读系统动作，返回事件引用、种类、时间、状态家族与排位，以及登记方当次给出的名字与状态词；主线服务不存标题、状态词或正文，返回里的名字不当成事实缓存，下一次读取重新向登记方取（2026-11-14 改写法，见[合同设计稿](contract-design.md) §2：胶囊不为名字另调一次呈现取值）。
22. **WLN-22** 一个装上的第三方插件在事项来源里给了下一步后，它的对象与内置插件一样带着下一步出现在线上；宿主没有按插件名的分支；项目里没装 Goals 时，线与事件照常工作（事件登记本身在第一片验，WLN-37）。
23. **WLN-23** 「整条线」按时间列出这件事的来往，每段标明所属事件，点一段聚焦该事件；内容读工作记录与各主人，不另存一份对话。
24. **WLN-24**（2026-11-18 按底栏第十三版改写，§16）「办完」清单末尾写「更早 N」，点开看更早的；清单里的事件数不随历史无限增长（「之后 N」方案没画，不做）。
25. **WLN-25** 用了子代理的工作，拆解里能看到各子代理这一步；聚焦这一步即对它直接说话，输入归属正确（子代理交互的验收照原样验）。
26. **WLN-26** 主动助理的建议出现在「接下来」，可开始、以后再说、不再建议；移走后同一位置不再出现同一条，记录在组合服务的纠正里。
27. **WLN-27** 切到一件事项时，线读取一次、三张清单的行由一次批量组合给出；这件事的信息在专注到它时才读取；状态更新靠变更通知，没有定时轮询。
28. **WLN-28** 对象被删、被移走或调用方失去权限时，事件显示「已不在」或「无权查看」并可移走，不显示旧标题或内容；未授权的线读取被拒并留诊断行。
29. **WLN-29** 刷新、断线与宿主重启后，线先显示最后确知的状态并标明正在核对，核对后更新；不重复派出工作，已取消的不恢复（PWA-136、PWA-137）。
30. **WLN-30** [人工] 用真实项目连续工作半天：交办三件事、中途补充一件、同意一次、打开两个结果、切换两次事项。全程看得出每件事办到哪，不需要翻对话找进展；多行输入、事件卡、切换时版面不跳、不盖住正在读的内容；深浅色、中英文、三种宽度都看过。

31. **WLN-31** 发送后助理的第一句回应不等安放完成、不等工作办完就开始出现；回应是真实的接单、回答或提问，不是固定的占位话（PWA-128）。输入反馈、首次有意义回应、安放完成三个时刻分别计时。
32. **WLN-32** 每次交办的回应末尾写明去处（补充给某个任务、为某个事件办的新任务、新事件、另一件事项、不属于事件），带「改」；改去处后这项工作不停、不重做，清单与任务卡随之更新。
33. **WLN-33** 专注在事件上、或在「给谁」里选了收件人时，不再做安放判断，话直接给所选的对象；助理不把它改投别处。
34. **WLN-34** 安放经动作目录里的系统动作完成，页面、助理、MCP 调同一组；提示词由平台随助理角色下发，插件与页面里没有另一份安放提示词；工具收到调用方读不到的事项或事件引用时拒绝并留诊断行；安放前后这项工作的授权、预算、数据范围不变。
35. **WLN-35**（2026-11-21 按底栏第十三版改写，§16）后台任务的入口是「在办」的图标（对话开着时是信息栏顶上的标签），没有单独的任务面板，对话右上角也没有任务图标；在办的任务缩在「在办」清单里所属事件的下面，写当前这一步、谁在办，不属于任何事件的在清单末尾单独一组、不计入三个数；等你的进卡叠，失败的带红点进卡叠；断线时原地写「正在核对」；右侧没有「后台任务」页（POLISH-69）。
36. **WLN-36**（2026-11-21 按底栏第十三版改写，§16）在「在办」清单或信息栏里点一项任务，信息栏的位置换成它的任务卡（可回到清单），内容与操作和信息栏「在办」那一段一致；对话栏不换，顶上不多页；挂着事件的可一步专注到那个事件，别的事项的可切过去或把卡停到侧边；把任务挂到事件、登记成新事件或从事件移开后，已在办的不停、不重做。清单、卡叠、任务卡三处状态一致，没有第二份任务清单（PWA-138）。
37. **WLN-37** 事件登记：登记是插件在 Manifest 里声明的事件读取动作；助理、Coding、待办、Feed、Inbox 和一个装上的沙箱插件按同一份登记把事件放到线上；宿主与工作台里没有按插件名、也没有按「是不是助理」的分支；一个插件只报一遍，线与首页读同一份登记；某个登记方读取被拒或失败时，线照常显示其余事件并标出读不到的来源。
38. **WLN-38** 事件的状态来自主人的对象状态与它背后任务的状态：有任务在办显示进行中，有任务等你显示等你，任务都结束后回到主人给的状态；任务结束不移走事件；同一事件先后的几个任务都能在卡里查到。任务为哪个事件办由任务的主人记、经 placement 的关联声明操作，主线服务不存任务进度的副本：线读取随返回带上同一次读到的任务总表（第 32 批，一次「等你」读取只读一遍总表），进度仍以任务主人报的为准。
39. **WLN-39** 后台任务总表：平台跑的后台作业与调度任务、Coding、助理与 Character 派出的工作，以及至少一个别的插件的长任务，以同一形状出现在「在办」清单里，并能用行里带的命令停止；清单与工作台里没有按插件名的分支。左上角那一格的数字、卡叠的张数与清单里等你的读同一份，三处件数一致。
40. **WLN-40** 在「给谁」里选一个 Character 后，对话栏换成和它的主对话、小标题写它的名字，这句话由它先回应、能后台办的派到后台、结果回到它，任务行标出是它在办；切回助理后两边的草稿、对话与任务互不串；这个 Character 被停用或移除时，它在办的任务如实显示并可停止。

### 15.2 平台能力检查

1. **别的插件会不会也要做。** 会。事件登记：待办、Feed、Inbox 今天已在报首页事项，Coding、助理本批接，日程、工作流程、Pages 在第 53 批接。后台任务总表：Coding 已在报，生图、Feed 拉取、定时执行、Alchemist、助理本批接。对象引用与打开：第 44、53、56 批都要用。「等你」读取：第 53、56 批读同一份。
2. **平台里有没有现成的。** 有四份底子，都是补，不另写：首页事项读取、首页聚合的后台任务合同、呈现声明与组合服务、placement。没有的只有两样：线读取（新的主线服务包）和「启动接续」的宿主回调（SDK 里已经留了口子，Molis 没实现）。
3. **是不是插件之间怎样协作的问题。** 是。「谁的任务为谁的事件办」是跨插件的关联，由任务的主人记、经 placement 的关联声明统一操作，不按一对插件各写一条路。
4. **第三方插件能不能同样做到。** 能：登记、报任务、声明呈现都在 Manifest 与 SDK 里，沙箱插件用例验证。只有内置做得到的一处要收掉：今天总表的停止命令是插件自己的路径，改成动作引用后装上的插件同样能给。
5. **助理和 Agent 能不能发现、调用。** 能：线的文本形态、安放、总表、等你都是系统动作，MCP 读到同一条线；没有界面时，助理靠这几个动作就能说清一件事在哪、谁在办、卡在哪。

### 15.3 五个场景与比较过的做法

| 场景 | 结论 |
| --- | --- |
| 插件 | 作者多做的只有一件：给要上线的对象补呈现声明里的时间与等你。登记本身沿用已有的首页事项读取，已经在报的三家不用报第二遍 |
| 平台 | 线读取、总表、等你读取归平台；内容与状态仍归各主人。外壳要跟着变（顶部一条、底部的线、多行输入的让位），运行时与授权不变，只是启动接续多一次复核 |
| 助理 | 主对话变短、任务在后台、结果回流，都落在助理已有的工作、委派与接续上，不新造调度；Character 用同一套 |
| 各类平台能力 | 接统一输入（「发给」里加 Character、聚焦事件即选收件人）、呈现与组合（事件卡）、placement（任务与事件的关联）、Attention（等你）、观测采集（聚焦、同意、安放写工作记录）、输入回执（补充的两步）。和技能包、连接器、成果库、同步没有重叠 |
| 后续开发 | 第 36 批在主线服务包上加事项与存储，第 53 批只多接登记方，第 58、59 批沿用「发给」，第 56 批做等你的写侧，第 44 批让 Goals 消费要求认可能力。再加一家登记方只改那个插件自己的 Manifest 与一个读取动作 |

比较过的做法：

- **事件登记另起一份合同，还是扩首页事项读取。** 选扩。另起一份会让待办、Feed、Inbox 报两遍，线与首页对不上；扩的代价是要同时改三家提供方和三处消费者，本批付。
- **任务与事件的关联放哪。** 比过三种：每个任务主人各做一个「改挂到哪」的动作（面板里的「挂到事件」就得按插件分支）；平台另存一张关联表（多一个主人，主人本来就知道的归属要再写一遍）；主人记、平台按声明统一操作。选第三种：placement 已有这个机制（文稿挂 Goal：主人声明列出、挂上、解开几个动作，placement 按声明找到它们），只是今天只服务一个关联名。代价是把它放开成能服务多个关联名，这一步第 36 批本来也要做，提前到本批。
- **等你在读的时候合并，还是写的时候投成 Attention 条目。** 本批选读时合并：写侧的收拢排在第 56 批，本批先让三处读同一份、件数一致。代价是读取要问几处，用并行与变更通知压住；第 56 批收拢后读取变成只问一处，调用方不用改。
- **回流在宿主里补，还是改 Prologue。** 选改 Prologue（用户已授权并定了随本批换包）：在宿主里补要另写一份「子任务要输入」和「一个会话同时一轮」，以后还得搬回去。代价是本批多一次换包。
- **主对话是新的一种东西，还是一项助理工作。** 选后者：每个范围（个人、每个项目）与每个对话对方有一项常驻的工作当主对话，后台任务是它名下的子工作。不新增存储与运行时概念；代价是今天「子任务只能一层、同时三个」的限制要按预算重定。
- **本机导入的原生 Character 能不能直接对话。** 本批不能：它在终端里跑，不经平台的运行时，没有回流与记录。「发给」里只列平台能跑的 Character，原生的标明原因；等它接进运行时再开。

让谁多付了代价：本批多了换包、placement 的一步、六十来个浏览器用例的重写；第 37 批的定样要按没有「线右端列表」重看一处（已在认领板留言）。
