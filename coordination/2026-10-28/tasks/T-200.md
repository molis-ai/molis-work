# T-200 Goals 进展来源的成果 ID、标题与来源条目 ID 按字数数 1000 的上限，含两单元字的来源不再被整个丢掉

**修法起草时定、写死：**

## 1. 背景

- 链路：进展来源由调用方放在 `goals.progress.record` 的输入里 → 应用 `GoalEventApplication.recordProgress`（`goal-event-application.ts:283`）→ `GoalEventState.recordProgress`（`module/event-state.ts:177`）在事务里依次查摘要、游标、`expected_goal_cursor`，然后 `:197` 调 `parseGoalProgressSource(input.source)`，返回 `undefined` 就抛 `goals.event_progress.invalid_source`（`state-error-codes.ts:72`，种类 `invalid`）→ 过了就 `structuredClone` 存进事件载荷（`:208`）→ 读回时 `parseGoalEventSystemPayload` 与 `readWorkState` 各再调一次同一个函数。
- 受影响的位置：

| 位置（main `0c7fdcc7c`） | 怎么管长度 | 本单之后 |
| --- | --- | --- |
| 写入检查 `module/event-state.ts:197-198` | 调 `parseGoalProgressSource`，不过就整条进展拒绝 | 含两单元字、不超过 1000 个字的来源收下 |
| 读进展摘要 `module/event-state.ts:68` | 同一个函数，不过就没有 `source` | 同上，读到的与写进去的一致 |
| 读事件载荷 `module/event-system-payload.ts:31` | 同一个函数（调两次） | 同上 |
| 动作 schema `goal-event-action-schemas.ts:7`、`:45` | `text = { type: "string" }`，无 `maxLength` | 不变（第 3 节） |
| 渲染 `plugins/native/goals/src/event-history-body.ts:9` | `escapeHtml(source.title)`，不截 | 不变；标题最长 2000 个单元，页面照常画 |
| 库 | 事件载荷是 JSON，没有长度约束 | 不变 |

- 所以只有这一处在管，单位只能由它自己定。写入与读出对称：存进库的来源一定满足写入时的规则，新规则比旧规则宽，所以库里已经存的来源读出来结果不变，不需要处理存量。
- 没有现成的测试钉住这个上限：`git grep -n -E "repeat\((1000|1001|2000|2001)\)" -- tests` 里与 Goals 来源有关的没有。唯一端到端经过 `parseGoalProgressSource` 的旧用例是 `tests/coding-goal-context-http.test.ts:219-227`（Coding 路径，标题很短）。

## 2. 目标

1. 来源的 `artifact_id`、`title`、`origin.item_id` 各自最多 1000 个字（码点）都收下，不论每个字占一个还是两个单元（最长 2000 个单元）；收下的来源原样记下，写入返回的、`readState` 的进展摘要里的、`readEvent` 的事件载荷里的 `source` 都与传入的相同；
2. 超过 1000 个字的仍拒绝，错误码仍是 `goals.event_progress.invalid_source`，不留事件、没有进展摘要；
3. 单元数超过 2000 的文字先拒绝，不展开成数组、也不迭代；
4. 其余规则（空白、类型、`version`、`plugin_id` 的正则）一字不动；
5. 用例钉住上面四条：撤销任一处、改错上限或单位，各自都红。

## 8. 与默认不同的

1. **单位：字（码点），上限数仍是 1000；不是「2000 个单元」。**统筹觉得要保持按单元（只把 1000 改成 2000），在【方案】阶段说，起草线改书。理由：
   - 房子里同类的上限都按字数数（T-093、T-094、T-096 已合入），动作 schema 的 `maxLength` 也按码点数；一个字最多两个单元，「2000 个单元」会让只有一单元字的标题放到 2000 个字，比原意宽一倍；
   - 放宽不收紧，没有任何来源因此变成被拒（第 5 节第 1 条的说明）；
   - 代价：含两单元字的串要数字数，所以有第 2 条的有界写法。
2. **有界写法：先比 `value.length <= limit * 2`，再展开；不是循环数到 1001 个字就停，也不是无条件 `[...value].length`。**统筹的指示就是「单元数超过 2000 的先拒、不展开」。另外两种，统筹可以裁：
   - 循环（T-197 的 `wholeCharactersWithin` 的写法，逐个字取、超出就停）：也有界，最多走 1001 个字，但会迭代超长串的开头；T-197 里它是必要的，因为那里要截取；这里只要判断，一行比较更直白；
   - 无条件 `[...value].length <= limit`：就是变异 M6，三个字段没有 schema 上限，几百万单元的串会占几百 MB。
3. **用例走公开应用，不直接调 `parseGoalProgressSource`；RAC-1962 靠改写 `String.prototype[Symbol.iterator]` 计数。**
