## 给人讲清楚

给 AI 用的东西有五类：技能、提示词、角色、工具和 MCP。现在它们各登记在各处，助理和 Coding 也各看各的，你想知道「有哪些、从哪来、什么版本、干什么用、用在哪、开没开、用了多少」得翻好几页，有的根本看不到。这一批把五类东西的说明收进同一个能力包：一个地方都能看到、管起来，技能照第 08 批的三档开关，其余的给出去改它的地方；助理和 Coding 读同一份目录，用到同一个版本，从助理交给 Coding 的活也带上同一个技能。工具、MCP 和技能真正的执行还走原来的路，能力包只管清单和说明。顺手把仓库里重复、过时的同类登记清掉。需要你做的：看一下能力包目录页的样子并定下（名字已定：界面叫「能力包」）。

### 一、一句话结论

**09 现在不能开实现，缺的不止 08。** 08 只交共同目录；09 要让同一个技能在助理和 Coding 里**用到同一个精确版本**，而这中间还断着一环：助理把工作交给 Coding 的协议（工作执行方协议）里**没有「这一轮用哪些技能」这个位置**。所以 09 实际有三块活：

1. 助理一侧改读共同目录（A 轨）；
2. Coding 一侧改读共同目录、方法选择改存精确引用（B 轨）；
3. 委派协议加上「技能」这个位置，且信任要由宿主带过去（合同归 C 轨，助理与 Coding 各跟一半）。

第 3 块不在批次文件原来的两句话里，下面第四节讲。
