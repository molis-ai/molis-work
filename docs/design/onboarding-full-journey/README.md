## 怎么打开

在仓库根目录运行，然后打开 <http://127.0.0.1:4411>：

```sh
python3 -m http.server 4411 --bind 127.0.0.1 --directory docs/design/onboarding-full-journey
```

也可以直接用浏览器打开本目录的 `index.html`。顶上一条斜纹是**原型控制**，不是产品的一部分：切方案、场景、状态、中英文和浅深色；「重置」清掉本页记住的进度。

## 三个方案只差在「准备放在哪里」

三个方案共用同一套步骤内容（目的、材料、模型、读取与整理、补问、方案、采用、第一件事）和同一份「已准备」草稿，只换承载方式：

| 方案 | 放在哪里 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 独立引导页 | 打开项目之前的进入页（已登记的 `/onboarding`）：左边步骤、中间当前一步、右边已准备的内容；从页面帮助进入时也跳到这一页，做完再跳回去 | 专心、步骤一眼看全，和现在的引导最接近 | 从 Coding 之类的页面进来要离开原页面，回去靠「回到 Coding」；进入页和工作台是两套外壳 |
| B 对话加方案草稿 | 个人助理一问一答，当前一步作为卡片嵌在对话里；右边是一路长出来的方案草稿。从页面帮助进入时，对话在工作台右侧窗格里 | 最像「秘书带你走」；回答哪一项、方案哪里变了，一眼对得上 | 对话越往后越长，往回改要翻；设置对照表这种宽内容在对话卡片里偏挤 |
| C 在工作台里就地准备 | 一开始就在工作台里（第一次用时是个人空间）：准备是主区的一个标签，右侧窗格是准备清单和已准备的内容；从页面帮助进入时，准备只在右侧窗格打开，原页面不动 | 首次使用、新项目、从页面帮助进入都是同一种做法；原页面和输入一直在眼前，做完直接回来；和第 03 批定下的窗格一致 | 第一次打开就看到工作台的外壳，比独立页面杂；窄屏上要在主区和右侧之间切换 |

## 推荐走一遍

1. **首次使用**（场景默认）：选一个例子 → 「从已有材料开始」→ 展开「下载」，点文件名看详情（长 PDF 只读前 20 页，可以读全部；Keynote 读不了正文，原件还在）→ 连模型（点「检查连接」）→ 读取与整理 → 补问（选「发到团队频道」后会多问一句发到哪里；选「公开发布」问的是别的）→ 看方案（成员、插件、运行条件、设置存在哪）→ 采用 → 进入项目 → 「开始」第一期，看「做法已配好」和「第一期已写好」的区别。
2. **状态切到「整理失败：超时」**，走到读取与整理：已读好的材料留着，失败原因写清楚。点「缩小范围」，回到材料，取消勾选大 PDF，再继续：只说明去掉了哪份，不重读其余材料，摘要按新范围重新出。另外两种失败（密钥被拒、额度或限流）给的处理方式不同。
3. **场景切到「从 Coding 的缺项进入，再回去」**：Coding 说缺模型和工作目录，输入框里已经写好一句话；点「补齐这两项」，连上模型，从资料里选工作目录并给出新增的授权，回到 Coding，那句话还在，可以直接发送。三个方案在这里的差别最明显。
4. **场景切到「给已有项目加一套做法」**：原有资料、成员和首页都不动；项目里已有同名的「研究员」，要你选沿用还是复制一个。
5. 其余状态：大文件夹还在清点（已清点的先能用，可以停止）、方案缺一个插件（说明只影响哪一步，看看要什么权限）、采用时一项没成（其余已生效，只重试这一项）、关掉后重新打开（从停下的地方接着走）。

每一步都有「说明」，点开以后不会丢输入，Esc 关闭，焦点回到按钮。首次使用时的提示点「知道了」就不再出现。

## 宽度、键盘与外观

- 1440、1024 宽度下三栏或两栏并排；760 以下：A 的步骤收成顶上的进度条，B 用「对话／方案」切换，C 用「主区／右侧」切换；点按目标 44px，按钮文字可以换行，不横向溢出（390 宽度逐步检查过）。
- 浅色、深色都能切；系统设了「减少动态效果」时去掉所有动效。

## 占位与模拟边界

- **项目首页是占位**：首页长什么样，要等第 03 批的「智能呈现」定样后补上（原需求 §3.10）。成员的「改」只演示入口，还没有展开成员职责与资料范围的编辑；这一块要接第 03 批第三项的助理路径，同样等它定样后补。
- 所有文件夹、文件、模型、摘要、成员和采用结果都是示例数据（`data.js`），用定时器模拟读取、整理和采用。没有读任何真实文件夹、没有调用模型，也没有连真实 Home。密钥输入框不保存任何内容。进度存在浏览器的 `localStorage`（`molis-proto.onboarding-full-journey.v1`），不代表产品的持久化、授权或恢复已经做好。
- `window.protoJump` 只用于截图时直接跳到某个状态，不是产品接口。
