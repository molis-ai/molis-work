# 创作台答卷与验收证据整理

状态：2026-11-24 本地整改与定向验证完成，待合入。创作台答卷、界面刷新和验收编号报告的结果见下文。

创作台在线工作流和离线回放分别实现了方案答卷、返工要求的业务判断。改由 `horizontal/plugin-studio` 提供同一份纯判定，保留各入口的输入、运行状态、错误阶段，以及宿主使用发布版本和语言设置的检查。原始语料、已有拒绝断言及历史测量继续保留。

验收编号报告应区分权威表中的定义和进度、证据表中的引用。Rust 行为用例沿用测试清单的识别规则；引用只能说明找到了测试文字，某次运行结果仍以该次运行的记录为准。保留报告模式和原有门禁。统一账号历史中的窗口重连与登录回流分别由 WUA-35、WUA-36 定义，原编号和实测记录可回查。账号切换规格的 ASR-09 保留其原意，用同一安装内的 A → B → A 验证 A 的模型连接在 B 明确被拒，切回 A 仍可使用。

## 验收标准

- QEV-01 宿主和回放采用同一套方案、澄清和返工判断。对已澄清后再次提问、未登记的能力、无效返工与合法答卷，分别检查宿主结果和回放阶段。
- QEV-02 同一要求列在定义表、进度范围和证据表时只定义一次。两条真正的重复定义仍应报告。同前缀的多个测试编号用斜杠逐个列出时，仅关联列出的编号。带 Rust 测试属性的用例可为编号提供引用，生产代码和夹具中的文字不能充当原生测试证据。
- QEV-03 在已展开协作记录和错误详情的创作中切换语言。即使期间安装了另一个插件，经模型就绪事件重读当前创作时也要保留草稿、焦点、选区、展开状态、原始错误和协作节点。展示中的方案仍响应能力目录变更，已发布版本的安装状态仍按当前实例更新。

创作台浏览器测试在切换语言后的第二次状态读取复现 QEV-03：输入仍在，协作记录与错误详情的 DOM 节点被替换。检查点为现有 `agent-studio.e2e` 的中英文往返与再次读取。修复限定在创作记录实际依赖的数据和刷新逻辑。

验证使用 `pnpm build`、已有的创作台回放与冒烟、`tests/studio-replay.test.ts`、`tests/health-gates-spec-coverage.test.ts`、`node scripts/check-spec-coverage.mjs` 与文档引用检查。未来分区行为及其验收归[统一分区规格](../unified-partition-plugins/spec.md)，已拍板的产品边界归各自的现行规范。
