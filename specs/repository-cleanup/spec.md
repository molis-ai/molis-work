# 两仓存量代码一次性清理

状态：已实现（本地清理完成；#996 已合入 main，2026-10-23），负责人 Codex。覆盖 Molis Work 与 Prologue 的现役存量代码，不是增量巡检或定期维护。原审计与首批候选是线索，不是范围上限；本 spec 为唯一执行需求书。

## 目标、基线与范围

在保持当前产品行为、公开合同、安全拒绝、恢复和打包安装能力的前提下，系统盘点并清理两仓现役存量。实施基线经 `git fetch origin main` 核实：Work `6d2361652bd167d07815d930cd04f802967292a3`；Prologue `95e177093a4efb60a286272892a89dc1e7ed31ba`。均使用 `feature/stock-code-cleanup` 隔离工作树；主检出与他人的工作不改。

覆盖全部 workspace 包及现役原生 Host：产品源码、内部导出、依赖、注册与构建接线、相关测试/夹具/工具、重复实现与已退役旧路径。按包及 Prologue 模块盘点，记录检查覆盖和每项处置。原先 8 个闲置定义与 12 个内部 export 只是首批候选，不用其数量决定完成。近期 PR 和 SYS 修复清单只用于依赖与冲突核对。

保留：当前有效消费者、已接受在途/后续计划的具体依赖、公开 API、拒绝与恢复语义。旧工作树仅继承过时调用，不自动构成有效依赖；检查未合提交及实际改动。没有足够证据的候选逐项写出缺口，不宣称排除所有未知未来用途。

不做：长期架构重写、新功能、真实 Home 数据维护、清理其他会话的工作树/文件、发布或定期清理。Alchemist/创作台等已有删除迁移继续遵守明确的先后、备份及通用验证替代条件；未满足则具体保留。后续授权已覆盖两仓 PR 的推送、CI/评审跟进、问题修复，以及全部通过后的合并；不绕过失败检查或待处理评审。

## 方法与边界

1. 全量建立包/模块与源码、测试、工具、原生文件覆盖表。复用已有有效证据，重新测量当前基线。静态图只产生候选，不能独自证明可删；动态 import、manifest/registry、Worker、构建脚本、字符串模板、公共入口和本机消费者必须核对。
2. 候选按三类处理：无消费者且无保留依据的定义/旧路径删除；只有文件内使用的内部 export 去掉 export、保留定义；重复实现核对输入输出、错误、状态与边界，同一主人内可合并，跨主人或公开合同变更先写明方案再实施。相似名称或相同短工具不强行抽象。
3. 依赖删除检查发布/安装/原生打包/动态构建消费；原生与脚本由其构建入口、调用和既有 lint/test 证明。不把测试导出和公开库 API按无生产 import 删除，不移除仍验证产品合同的测试或放宽断言。
4. 对照当前开放 PR、本机未合且有效的工作和已接受计划。与修复 chat 实际相交的文件依赖相应修复结果，其他文件可继续；不再等待一个历史 PR 波次全部关闭。修复仍在写入且会影响候选时，记录准确路径及依赖。
5. 分批本地提交，删除与公开面调整可分别回滚。每批结束审阅 diff、定向验证；全部覆盖完成后统一工程验收。基线若前进，只复核与本轮相交的变化，不把新增开发无界并入任务。

所有修改限定上述两隔离树。产品包保持 SSOT、合同层和写主人，不为清理添加平台私路、兼容层、门禁例外或新进度系统。扫描中间结果放已忽略 `.tmp/audit/`，候选及模块覆盖记录在本目录 `inventory.md`。

- 尚在退役计划中的 Alchemist 与同文件在途路由组，在其原负责人给出替代结果前不借清理重写。

## 风险与回滚

静态扫描无法独自识别全部动态消费者；逐项核对 manifest、构建、公开入口与有效未合差异。无法证明的项保留并写出缺口。清理前后行为证据由现有生产路径测试、类型/构建、公开合同快照及打包消费共同支撑，不造额外 schema/hash 证明流程完成。本地按逻辑批次提交；回滚用对应提交的 revert，无数据迁移，不触碰真实 Home。
