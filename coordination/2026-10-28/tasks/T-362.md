## 1. 背景

来源：MISC「T-290 统筹答 登记（6520548585）」；T-290 已随批 PR #1687 落在 main（`0ac344d8c`）。

`apps/workbench/src/settings-address-params.ts` 是 T-290 新增的表：外壳把插件页交来的设置地址（`molis-work:open-settings-path`）转给设置页时，只保留各设置页声明认的查询参数与 hash。内置的全局／项目设置页各有自己的 `*_QUERY_EXTRAS`；**插件自己的设置页（来自 Manifest）现在只认每个设置页都有的默认值**：`SETTINGS_ADDRESS_DEFAULTS = { global: "project desktop", project: "desktop" }`（文件头注释最后一句写明了）。所以插件想让自己的设置页读别的参数（比如 `?tab=`、`#section`），现在没有办法声明，外壳会把它们丢掉。

统筹的答复（6520548585）：插件要带别的参数，就在 Manifest 的 settings 贡献里声明它认哪些查询参数与 hash，外壳按声明过滤。这是合同改动。

## 2. 目标

先在 #1332 贴【方案】（乙档，涉及合同，写到类型与函数级）：
1. 在 `packages/contracts/src/platform/ui.ts` 里 `slot: "settings"` 的视图声明上（看 :128 `UI_VIEW_SLOTS`、:160 `UiSettingsDataDeclaration` 一带）加一个**可选**声明，列出该设置页额外认的查询参数名与 hash（如 `address_params?: { query?: readonly string[]; hash?: readonly string[] }`，具体形状在【方案】里定；名字走现有命名风格，不新造概念）。校验规则：参数名只许 `[A-Za-z0-9_-]{1,32}`，数量有上限（比如 8），不许与默认值或保留名重复，不许声明 `project`／`desktop` 以外的“控制类”参数（如果有的话，列在方案里）；Manifest 解析在 `packages/plugin-sdk` 的 Manifest 解析处（共享核心）校验。
2. `apps/workbench/src/settings-address-params.ts` 与调用它的 `scripts/client/settings-directory.ts`：插件设置页的过滤改为「默认值 ＋ 它声明的」，不声明的页行为与现在完全一致。
3. 先红用例（`tests/security-invariants-plugin-pages.test.ts` 已有 S-47 的断言，沿用它的夹具）：声明了 `tab` 的插件设置页，外壳转交时保留 `?tab=x`、丢掉未声明的 `?evil=1`；没声明的页仍丢掉 `tab`；非法声明（名字不合法、超数量、与默认值重复）在 Manifest 解析处被拒。
4. 开发手册（`skills/molis-plugin-dev/` 或 `docs/platform/PLUGIN-DEVELOPMENT.md` 里讲设置页的地方）写一句这项声明；`pnpm api:update` 刷新 API 快照。
