# 技能包：安装预览、启用和管理的可点定样（路线书第 08 批）

状态：三个方案待用户定（2026-11-04）。定下后写进[技能包 spec](../../../specs/skill-packs/spec.md) 的决策记录。

这是参考原型，不是产品界面。

- 需求见[技能包](../../../specs/skill-packs/spec.md)（SKP-01、02、07、08、10）。
- 排期见[第 08 批](../../../specs/post-anticorruption-roadmap/reference/batches/08.md)。
- 字段照 C 轨的合同设计稿 `specs/skill-packs/contract-design.md` §5～§9（在途，分支 `claude/roadmap-08-skill-pack-contract-design`）：
  - 安装预览每项是 `SkillInstallPreview`；
  - 目录每行是 `SkillCatalogEntry`；
  - 不可用写 `SkillUnavailableReason`；
  - 升级标 `change` 与 `kept_state`。

已定的不再问：

- 装上、导入、打开看都不等于启用（spec §5）。
- 启用只走 `skills.settings.set@1`，按范围（项目，或个人空间）记，一个技能有三种状态：关、自动、仅手动。
- 升级、停用再启用都不改原来的设置。
- 技能不带任何权限。

控件都由组件板的渲染函数画出（`window.MW`，见[组件板实件](../component-board/README.md)），用到的有：

- 条目行、徽标、分段选择、开关、勾选、单选组；
- 折叠、预览卡、提示、空状态、页签、状态标记、按钮；
- 带「撤销」的提示（toast）。

`skills.css` 只排位置，只用组件板令牌。

## 怎么打开

先按[组件板实件](../component-board/README.md#生成)生成 `component-board/dist/`。再在仓库根目录运行下面的命令，然后打开 <http://127.0.0.1:4422/skill-packs/>：

```sh
python3 -m http.server 4422 --bind 127.0.0.1 --directory docs/design
```

页面顶上一条斜纹是**原型控制**，不是产品的一部分。用它可以切换：

- 方案（A／B／C）；
- 区域（安装预览／从本机导入／技能目录）；
- 状态；
- 中英文和浅深色。

「重置」会清掉本页记住的选择（`localStorage` 键 `molis-proto.skill-packs.v1`）。

宽度 1440、1024、390 都看过。

## 三个方案

三个方案的差别在两处：**什么时候启用**，以及**目录怎么排**。

| 方案 | 什么时候启用 | 目录 | 取舍 |
| --- | --- | --- | --- |
| **A 装完接着启用（推荐）** | 安装确认里只看、不选。点「同意并安装」后，同一块就地换成「在这个项目里用哪些」。每项一个三档分段：关／自动／仅手动，默认关，上面三句话说清三档的意思；「完成」或「以后再说」。导入也一样 | 设置里「技能」一节：按包分组，一个技能一行；行末是三档分段，改了立即生效，提示里可以撤销；「看详情」就地展开 | 安装（同意权限）和启用（让 AI 用）分成两步，不混在一起，又不用另找地方。三档摆在明面上，一眼看出现在是哪一档。代价是装完多一步（可以「以后再说」） |
| B 确认时一并选 | 安装确认里每项一个开关，默认关；打开以后才出现「仅手动点名」勾选。按钮写「安装并启用 N 个」。装完回到目录 | 同 A，按包分组；行末是开关，开着时旁边多一个「仅手动」勾选 | 步数最少。但「同意权限」和「让 AI 用」挤在同一个按钮里；三种状态拆成「开关＋勾选」两个控件，要读两处才知道是哪一档 |
| C 到目录里再开 | 安装确认只列出技能，装完说「都还没启用」，给「去技能」 | 左边是列表（每行带状态），右边是一个技能的全部：三档单选（每档一句说明）、什么时候用、工具、附带文件、正文开头、最近一次被用、整包操作。窄屏先列表，点进去看详情 | 安装最干净；一个技能讲得最完整，技能多时好找。代价是装完还要另走一趟才能用；改状态要先点进详情 |

**推荐 A**：

- spec 要求「装上不等于启用、启用时说明默认用途与范围」，A 把这两件事分开做，又放在同一处。
- 三档用分段选择，比「开关＋勾选」少一次理解。
- 目录按包分组，和停用、卸载以包为单位的事实一致。
- 技能变多以后，C 的左右两栏更好找。若你更看重目录里的完整说明，可以选「A 的启用步骤＋C 的目录」。

## 三个方案共用的部分

- **安装预览**：这一块是现有「设置 → 插件」安装审阅面板加出来的「这个包带的技能」一节（原型里把权限、作用等其他节缩短了）。
  - 每项写名字、什么时候用（`description`），以及适用于助理、Coding 还是两边。
  - 有脚本的标「会执行脚本」，用到连接器类别的标「用到：~~日历」。
  - 「看详情」里有：什么时候用和什么时候不用、声明的工具（写明只是说明、不给权限）、附带文件（路径、大小、脚本会执行）、正文开头。
  - 升级时每项标「新增」「正文变了」「会移除」「仅手动会保留」；被移除的技能列在最后，加删除线。
- **包有问题**：写明哪一项不对（如某个 SKILL.md 找不到），并说「什么都没装，原来的也没动」（SKP-08）。
- **从本机导入**：
  - 来源有 Claude Code、Codex、项目目录，写明扫的是哪个路径。
  - 候选每项给文件数和大小，并标出：能不能在内置助理里用（「只有本地 Agent 能用」要写原因）、会执行脚本、已装过同名的会升级成新版本。
  - 导入到「这个项目」或「个人空间」。
  - 导入的是这一刻的拷贝。
  - 没找到时写明看的是哪个路径。
- **目录**：
  - 顶上是一句说明，加上「共 N 个，在用 M 个」。
  - 搜索框，筛选：全部／在用／没启用／用不了。
  - 「从本机导入」。
  - 每行写最近一次被用：什么时候、助理还是 Coding。
- **用不了**：每个原因对应一件能做的事（照合同的原因码），状态和「用不了」分开显示。

  | 原因 | 写 | 能做的事 |
  | --- | --- | --- |
  | 插件停用 | 插件「法务审阅」停用了，暂时用不了；设置保留为「自动」，恢复后照旧 | 启用插件 |
  | 发布者撤销 | 发布者已撤销，只能卸载 | 卸载 |
  | 正文或资源坏了 | 正文或附带文件缺失 | 重新安装 |
  | 依赖不满足 | 缺少某插件 | 去添加 |
  | 没有连接 | 没有连接日历，暂时用不了（状态仍可改） | 去连接 |
  | 只有本地 Agent 能用 | 写原因 | 无 |

  插件停用、发布者撤销、资源坏了这三种情况，三档控件会变灰。
- **保存失败**：那一行就地写「没能保存，『X』还是『自动』，什么都没改」，给「重试」。
- **还没有技能**：空状态，给两个入口：「从本机导入」「去插件市场」。

## 组件板新增（交 D 轨补标本）

| 部件 | 原型里的写法 | 为什么要 |
| --- | --- | --- |
| 条目行末尾的三档分段（A） | `mw-item__end` 里放 `mw-toggle-group`；窄屏挪到文字下面 | 组件板的条目行末尾只有状态、按钮，没有分段选择 |
| 条目行末尾的开关＋勾选（B） | `mw-item__end` 里放 `mw-switch` 与 `mw-check` | 同上；第 18 批也要「条目行末尾的开关」 |
| 条目行里的折叠详情 | `mw-collapsible` 放在条目行下面、缩进到文字对齐，摘要行压低 | 组件板的折叠是独立一段，摘要行有 12px 上下留白，放进条目行太高 |
| 提示里的按钮 | `.sk-alert-actions`（与第 17、18、19 批相同） | 装不上、保存失败、导入完成要就地给下一步 |
| 状态旁的链接按钮 | `mw-btn--link`，触控高度用内边距撑出、不占行高（同组件板提示里诊断号的写法） | 「去连接」一类要和状态标记同一行、同一中线 |

## 模拟边界

- 数据是编的（`data.js`），不读任何 Home，不调 `plugins.install.*`、`skills.*` 动作。
- 安装、导入、改状态、撤销只改本页内存，刷新或「重置」后回到初始。
- 「保存失败」状态下，任何改动都当作写入失败。
- 「看全文」、整包的停用和卸载、「去连接」、插件市场、取消、重新选文件，点了只弹一句提示。
- 设置页在原型里画成一页带「插件／技能」页签；产品里「技能」是现有设置里「插件」旁边的一节。
- 目录只画了「这个项目」的范围；装在个人空间的包也列出来，状态按这个项目记（合同 §7）。
