审查范围包括根目录的 Node 回归、包内测试、原生测试、Auth 与同步 Worker 专项，以及发版、截图和需要外部服务的入口。核对发现规则、执行环境、断言重复与现有 CI 职责。已合入的 PR #2268 将 Full 调为 60 片并拆分文档门禁，本次沿用其职责划分。只改测试、测试调度及其开发文档。

## 验收标准

1. **TSA-01** 能从当前检出复核每个测试文件的集合与入口，区分 PR、Full、专用环境和历史材料。全库扫描发现的相同名称、无直接断言、平台关键词均需结合实际调用判断。
2. **TSA-02** 移除已核对输入、断言和触发范围的重复检查。保留设计系统的章节顺序、生产 bundle、CSS 顺序、快捷键与 Inbox 焦点回归。
3. **TSA-03** 环境选择、角色与定时任务同步经当前生产入口纳入常规发现。验证冲突后内容、接收端任务停用、无回声与源端状态。
4. **TSA-04** Linux 能执行混合文件里的可移植用例。平台专有场景、需要真实服务的用例和空选择各有明确结果。
5. **TSA-05** 减少重复的测试准备工作。在同一批文件上记录本地改前、改后耗时，核对选择结果。云端整条流水线耗时另以候选提交的 Actions 实跑为准。文档门禁的每个错误样例验证实际规则，命令行同时证明退出码、基线更新与防放宽行为。
6. **TSA-06** 完整 Full 包含 17 份隔离的同步 Worker 文件，定向重跑只执行所选文件。用当前 Home 的证据存储和平台创作台，验证两个个人 Home 经实际 WASM、D1 与 R2 往返，目标项目回收期间拒绝继续写入、恢复后补收。六份账号专项在锁定 Auth 版本上定向执行，检查资料、订阅、租户、切换与异常恢复。

## 验证方法

验证用独立 Home、已锁定的运行时、`pnpm build`、受影响文件的定向 runner、测试类型与健康门禁。本机只做集合盘点与定向执行。历史归档、真实账号凭据和发布操作均不属于本轮执行目标。

对 2,418 份 JS/TS 测试入口检查了测试注册、空函数、显式跳过、相同回调体、相同断言操作数和跨文件重名，再核对候选的调用对象与执行路径。8 份没有直接断言的文件把不同插件交给同一套固定版本或生命周期夹具，断言在夹具里，因此全部保留。同一操作调用两次以验证幂等性、字节稳定性或缓存引用的断言也保留。

- Web health 原先用同一个回调启动两次服务；现在保留一次。项目目录原有两行将 ID 与自身比较，改为从目录重新列出项目，核对两个同名项目各自的 ID。
- 视觉基础测试里的 4 个重复用例移除。CSS 顺序、生产 bundle、组件板和快捷键的保留用例进入原来的 PR 产品集合。Inbox 行焦点的真实交互检查仍保留。
- 角色和定时任务同步的两份包内 Node 测试原先未被根目录或包脚本发现。角色改从有名称的 v1 草稿开始，定时任务改走当前项目库与同步服务。环境配置回归移入安全集合。
- 基线的 Linux Full 根据源码与夹具里的平台词汇整文件跳过了 95 份。其中混合文件的普通用例也被跳过。现在只有明确声明整文件平台要求的文件才提前剔除。其余由 Node 逐用例判断。重试只跑到 skip 会保留原失败诊断，整文件跳过在摘要里独立计数。
- 分片及受影响用例的发现过程在一次扫描内复用文件与依赖解析。下一次扫描重新读磁盘。根文件、共用夹具、循环引用、相对仓库路径与修改夹具后重扫都有定向验证。

同一组 2,336 份输入安排为 24 个分片，交替运行新旧实现各三次，每次核对各片文件、顺序与预测负载。规划中位数从 3.615 秒降到 0.657 秒。同步 60 片主干后，在 2,359 份输入、每片 3 个测试进程及 1 个浏览器槽上交替复测三轮，新旧均得到相同的分片、顺序与预测负载，中位数为 0.890 秒与 0.670 秒。边界作业也改为消费已有的构建产物，本地独立入口保留依赖构建。另抽取 8 份产品回归对比 Node 编译缓存，运行时间区间重叠，未采用这项改动。

运行 `node scripts/check-spec-coverage.mjs --json` 可核对需求编号和测试引用。83 份现行 spec 中按「文件与编号」去重后有 1,542 个验收编号，884 个可找到测试引用，523 个未标为人工或退役且未找到编号引用。其余编号只标为人工或退役。一个编号可有多段定义或涉及多条行为。引用证明能定位测试，实际覆盖仍需看断言和运行结果。

发版的标签、版本、签名和发布作业有独立入口。本次云端验证对象是草稿 PR 的 CI 与 Full；打包签名、发布和真实线上服务另需对应运行证据。

首次 Verify 的 47 份门禁自测中，46 份通过，文档门禁在 1,200 秒到期。其中 57 个文档错误样例先后多次重跑整套健康 CLI 并重写本地基线。它们现在直接调用生产文档检查，合计减少 171 次整套 CLI 启动。其他用例继续从命令行覆盖正常出口、文档错误、基线更新、指标上限与 merge-base。改后本机 85 项全部通过，用时 45.2 秒。

浏览器实跑另发现 Attention 检查在看见任意操作后就查找「保存为资料」，刷新期间曾因目标尚未出现而空引用。验收保留真实指针点击、本人确认、端点、版本及持久化结果断言，准备条件改为等待当前对话框内那个具体按钮可见并可用。表单放置回归在重进详情时也曾把临时标记留在重绘前的行；有稳定定位的步骤直接交给现有插件框架，按记录 ID 回到列表、重新定位并真实点击。

Full 第 20 片曾在测试通过后用 31 分钟等待耗时缓存保存，7,129 字节已报告传完，随后达到作业时限。同步 #2268 后，完整 60 片直接按已提交的分片顺序执行，省去 60 次恢复和 60 次保存。仅指定文件的重跑仍使用此缓存，读写各限 1 分钟。测试、构建产物与分片汇总保持阻断。

独立同步 Worker 专项在修复前为 52/54。Feed 仍使用升级前的目录，创作台夹具仍尝试安装已经归平台的创作台。改后 17 份文件在当前源码编译的 Rust WASM 和临时 D1/R2 上实跑 54/54，用时 148 秒，无跳过。本轮另把专项接入完整 Full，缓存仅保存锁定版本的编译工具。账号专项复用 P1 登录测试中的手机号、隐私同意及验证码表单操作。

锁定 Auth 的六组专项均已在本机执行通过。账号历史回归改用实际项目搜索控件保存同账号范围，退出后通过历史记录核对缓存与身份。错误、过期验证码均核对当前 Auth 的拒绝原因；浏览器在登录请求未完成时重启，旧入口收到占用提示，当前身份仍为空。已完成登录的重复提交由会话所有者测试验证。

针对 Linux 首次实跑中整文件跳过的 32 份 macOS 文件，在隔离 Mac 上逐份补跑 186 项。六份文件的失败来自过时前置条件、控件或断言，修正后分别通过：项目按需安装 Goals、模型夹具勾选可选调用权限、语言切换与重载等待页面事件、预览识别具体技能行和命令、关闭时按目标安装计数。取消预览与实操的断言保留，日常回归省去这两份浏览器测试的评审截图。另在灵光回归中让其他调用方的写入发生在实际离开流程的读取之后，避免初始化读取抢先消耗并发夹具。

这 32 份修正后有 29 份通过，182/186 项通过。另 3 份整文件声明 macOS 的用例 8/8 通过。Mac 实跑仍有四项失败：创作台安装单内容 174px，在就绪后可视区域仅 76px；撤销已选发布者后，两项列表与启用测试读到运行态；签名双实例插件在 Home 授权后，项目可选权限入口仍拒绝设置。三个文件及其回归断言保留。这些是对应环境中的失败，Linux Full 的状态另计。

新增的 Worker 作业也实际抓到回收站测试只按一种顺序写预期：永久删除先完成后，新的恢复请求得到 `404 SYNC_RECOVERY_MISSING`。现保留同一数据上恢复与删除的真实并发，逐一核对胜负与附件结果，并固定验证两种先后顺序、错误码、恢复事件不重复及最终墓碑。修正后并发用例本机连续通过五次，整个保留策略文件 13/13 项通过。
