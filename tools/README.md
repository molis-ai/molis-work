# 需求全景图的生成脚本

`index.html` 由这里生成。进展不用重新生成：页面打开时直接读 Issue #1743。

路线书的批次、依赖或交付项变了才要重新生成：

```bash
tools/rebuild.sh <molis-work 检出目录>
```

检查输出里「批次」「边」的数字，看一眼页面，再提交 `index.html` 和改过的脚本，推到 `gh-pages`。需要已登录的 `gh`。

| 文件 | 内容 |
| --- | --- |
| `data.py` | 手工录入的交付单元及依赖。**依赖变了要改这里**：脚本不会从批次文件读出新依赖 |
| `build_data.py` | 读批次文件的标题和介绍，修正几条判读的依赖边，输出中间数据 |
| `build.py` | 按批次汇总，生成页面数据。`MAP` 写明拆开的单元各对应哪几个交付项 |
| `template.html` | 页面本身，含解析 #1743、计算状态的逻辑 |

依赖写法见 `data.py` 开头：无前缀是必须先做完，`~` 核出缺口才等，`^` 可先开发、合入要等，`?` 只挡其中一部分，后缀 `*` 表示由批次号判读到子项，还待核实。页面的「可领」只看硬依赖和认领状态，不看轨道占用。有未满足的部分前置时标明「部分可领」，详情列出剩余前置；这只表示可以核对并推进不受阻的切片，具体合同输入仍按批次文件检查，不表示整项就绪。整项「已完成」仍取认领板的整项合入状态。

## 轨道、人名和进展

- `tracks.json`：交付项的主轨道与工作类型，由路线书推导后经用户确认（2026-11-04）。路线书增删或改名交付项时要补，对不上时 `build.py` 打印「轨道表对不上」。`occupy` 仅标识实现工作，不再表示整轨锁定。决定 26 已取代整轨互斥：轨道显示进行中的协作方，是否冲突由具体文件及合同快照决定，不据轨道自动阻塞其他工作。C1～C3 的分组只用于显示。
- 人名缩写：`template.html` 的 `PEOPLE`，表外账号取前三个字母。认领人取自 #1743 的编辑历史（`claimers.py`），是第一次填这一行的人，不一定是实际做的人；认领列直接写成 `Claude-WYJ-本机` 时以它为准。
- 进展：页面同时读 `board-data` 分支的 `board.json`（`board_json.py` 生成，main 上的 `roadmap-board-sync` 工作流在 #1743 变化时写入，不受接口限额影响）和 GitHub 接口，用更新的那份；都读不到就用内嵌快照并说明。

## 定向回归

认领板的状态列必须以固定词开头（已认领、定样中、实施中、待评审、已合入、暂停、放弃、待认领、移到服务端批，开头加粗也算）。读不出固定词的行仍按有人认领显示，但算进页头的「对不上」，不会悄悄当成进行中。

重新生成后执行 `node --test tools/status.test.cjs`。用例直接执行模板的状态算法，覆盖同轨道不互锁、真实硬前置、暂停／认领／完成、部分前置提示，以及生成数据的合同顺序与硬边无环。本机沿主仓规则经公共 machine-slot 排队。
