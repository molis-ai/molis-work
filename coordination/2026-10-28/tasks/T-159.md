## 1. 背景

- 现状：`runtimeReleaseBytes`（`:21-47`）一次下载做这些：
  1. `:25`：地址必须是 https、无用户名密码、主机在白名单里，否则抛 `invalid`；
  2. `:26`：`fetch`，`redirect: "manual"`，信号是 120 秒超时和调用方信号合在一起（`AbortSignal.any`）；
  3. `:27`：`signal?.throwIfAborted()`，调用方取消了就抛它的 `reason`；
  4. `:28-32`：重定向，丢掉正文（`:29` 的 `await response.body?.cancel()`），换地址再来，最多 6 次；
  5. `:33`：`!response.ok || !response.body` 抛 `failed("运行时下载失败，请检查官方发布源与网络")`；
  6. `:35-43`：逐块 `reader.read()`，每块之后再 `throwIfAborted`，累计超过 `limit` 抛 `failed("运行时下载超过允许的大小")`（`:40`）。
- 三种失败怎么逃出去：

  | 情形 | 抛什么 | 本单 |
  | --- | --- | --- |
  | 断网、拒绝连接、域名解析不了 | `:26` 的 `fetch` 以 `TypeError: fetch failed` 拒绝；没有字符串 `code` | 收，`RAC-1691` |
  | 120 秒超时 | `AbortSignal.timeout` 触发，`fetch`（还没有响应）或 `read`（读正文时）以 `DOMException` 拒绝，`name` 是 `TimeoutError`，数字 `code` 23 | 收，`RAC-1691`（`fetch` 这一半） |
  | 正文中途断开 | `:38` 的 `reader.read()` 以 `TypeError: terminated` 拒绝 | 收，`RAC-1692` |

  `read` 时的超时与 `fetch` 时的超时同一个来源，两处 `.catch` 都收下；用例只在 `fetch` 一侧造超时，`read` 一侧造的是断开（`RAC-1692`）。
- 为什么取消能原样通过、超时却变成 `failed`：
  - 调用方取消时，`AbortSignal.any` 把来源信号的 `reason` 原样带在合成信号上，`fetch` 和 `read` 以那个 `reason` 拒绝；
  - `signal` 参数就是调用方的信号，`signal.throwIfAborted()` 抛的就是 `signal.reason`，和 `controller.signal.reason` 是同一个对象；
  - 120 秒超时只让合成信号中止，调用方自己的 `signal` 不会因此变成 aborted，所以 `throwIfAborted()` 什么都不抛，往下走到 `failed`。
- 为什么只包 `reader.read()`、不包整个循环：`:40` 的「超过允许的大小」那句拒绝和 `read` 在同一个 `try` 里，包整个循环会把它改写成「运行时下载失败」（第 6 节 M7）。
- 失败以后的收拾已经是对的，不用改（起草时逐句核过）：
  - `installManagedConnectorTool`（`connector-tool-install.ts:53-74`）的 `catch`（`:73`）删掉候选目录后原样抛出；
  - `ensureManagedNode`（`connector-tool-runtime.ts:42-69`）的 `finally`（`:64`）删掉 `.node-` 暂存目录；
  - 所以 `fetch` 一拒绝，`installs` 是空的，`runtimes` 里没有 `node-`、`.node-`。已有的 `:19`、`:37` 两个用例量的就是这两样。

## 2. 目标

1. 下载的请求失败（断网、拒绝连接、120 秒超时）：安装拒绝带 `code: "connector.install.failed"`、`kind: "unavailable"`，文案是「运行时下载失败，请检查官方发布源与网络」；只发 1 次请求；`installs` 空，`runtimes` 里没有 `node-`、`.node-`（`RAC-1691`）。
2. 响应开始后正文中途断开：同样的码、kind、文案，同样不留东西（`RAC-1692`）。超过大小上限的拒绝仍是它自己的那句「运行时下载超过允许的大小」，同码同 kind（`RAC-1692` 的另一半，用来钉住只包 `read`、不包整个循环）。
3. 调用方取消：不管落在请求还没返回、还是正文正在读，拒绝的都是调用方自己的 `reason`，不是 `connector.install.failed`（`RAC-1693`）。

```ts
/** Network failures and the download's own timeout are install refusals; the caller's cancellation passes through unchanged. */
function downloadFailed(signal?: AbortSignal): never {
  signal?.throwIfAborted();
  throw toolInstallErrors.failed("运行时下载失败，请检查官方发布源与网络");
}

/** Downloads only official runtime releases; redirect destinations stay in the release-provider allowlist. */
export async function runtimeReleaseBytes(raw: string, limit: number, signal?: AbortSignal, allowedHosts: ReadonlySet<string> = releaseHosts): Promise<Buffer> {
  let url = new URL(raw);
  for (let redirects = 0; redirects < 6; redirects++) {
    signal?.throwIfAborted();
    if (url.protocol !== "https:" || url.username || url.password || !allowedHosts.has(url.hostname)) throw toolInstallErrors.invalid("运行时下载地址不属于已支持的官方发布源");
    const response = await fetch(url, { redirect: "manual", signal: AbortSignal.any([AbortSignal.timeout(120_000), ...(signal ? [signal] : [])]), headers: { "user-agent": "Molis-Work" } }).catch(() => downloadFailed(signal));
    signal?.throwIfAborted();
    if ([301, 302, 303, 307, 308].includes(response.status)) {
      const location = response.headers.get("location"); await response.body?.cancel();
      if (!location) throw toolInstallErrors.failed("运行时下载缺少重定向地址");
      url = new URL(location, url); continue;
    }
    if (!response.ok || !response.body) throw toolInstallErrors.failed("运行时下载失败，请检查官方发布源与网络");
    const chunks: Buffer[] = []; let size = 0;
    const reader = response.body.getReader();
    try {
      while (true) {
        const result = await reader.read().catch(() => downloadFailed(signal)); signal?.throwIfAborted(); if (result.done) break;
        size += result.value.length;
        if (size > limit) { await reader.cancel(); throw toolInstallErrors.failed("运行时下载超过允许的大小"); }
        chunks.push(Buffer.from(result.value));
      }
    } finally { reader.releaseLock(); }
    return Buffer.concat(chunks);
  }
  throw toolInstallErrors.failed("运行时下载重定向次数过多");
}
```

// RAC-1692: a body that breaks after the response began (undici rejects the read with "terminated") ends in the same declared failure.

// RAC-1693: the caller's own cancellation is not a download failure. Whichever moment it lands in, the request still pending or the body
// being read, the install rejects with the caller's reason itself. It passes before the change too; it keeps the two catches honest.
test("S-36 ASC-25 RAC-1693: cancellation while a runtime download is pending or being read rejects with the caller's reason, not a declared install failure", async t => {
  for (const moment of ["request", "body"] as const) {
    const home = await openTestHome(t), controller = new AbortController(), entered = Promise.withResolvers<void>(); let requests = 0;
    const fetch = t.mock.method(globalThis, "fetch", async (_url: unknown, init: RequestInit) => {
      requests++; const stop = init.signal!;
      if (moment === "request") return new Promise<Response>((_resolve, reject) => { stop.addEventListener("abort", () => reject(stop.reason), { once: true }); entered.resolve(); });
      return new Response(new ReadableStream<Uint8Array>({
        pull(body) { entered.resolve(); return new Promise<void>(done => stop.addEventListener("abort", () => { body.error(stop.reason); done(); }, { once: true })); },
      }, { highWaterMark: 0 }));
    });
    try {
      const pending = installManagedConnectorTool(home.home, input, { ...control, signal: controller.signal });
      const rejected = assert.rejects(pending, (error: unknown) => { assert.equal(error, controller.signal.reason, `${moment}: the caller's own reason, not a declared install failure`); return true; });
      await entered.promise; controller.abort(); await rejected;
      assert.equal(requests, 1);
      assertNoCandidate(home.home);
    } finally { fetch.mock.restore(); }
  }
});

几处为什么这样写，别改：
- **源码**：
  - `downloadFailed` 返回 `never`，所以 `fetch(...).catch(() => downloadFailed(signal))` 的类型仍是 `Promise<Response>`，`reader.read().catch(...)` 仍是读结果，不用转型；
  - `signal?.throwIfAborted()` 放在 `downloadFailed` 里而不是两个调用点各写一遍：取消的判断只有一处，M3 一次拆掉；
  - 两个 `.catch` 都不读错误：任何拒绝都当下载失败，取消在 `downloadFailed` 里先分出去；
  - `.catch(() => …)` 不是空 `catch`，不动「空 `catch`」那一栏的数字。
- **用例入口**：`installManagedConnectorTool(home.home, input, control)`，`input.node_version` 是 `24.99.99`（`:8`），和本进程的 Node 不同，所以 `ensureManagedNode` 不会用 `process.execPath`（`connector-tool-runtime.ts:43`）；本机 PATH 上的 node 版本对不上（`matchingToolRuntime`，`:27-39`），回到官方下载。第一次 fetch 是 `https://nodejs.org/dist/v24.99.99/SHASUMS256.txt`（`:56`，限 1 MiB）。已有的 `:19`、`:37` 两个用例走的是同一条路。
- **stub 必须返回 Promise**（`async` 函数）：真 `fetch` 不会同步抛。stub 要是同步抛，错误不经过 `.catch`；要是直接返回 `Response`，`fetch(...).catch` 根本不存在。
- **`RAC-1691` 的循环**：照 `:20` 的 `for (const mode of …)`，每轮一个新 Home、一个新 stub，`finally` 里还原。第一轮红了第二轮就跑不到（见第 6 节 M1 的写法）。`DOMException` 的第二个参数 `"TimeoutError"` 是它的 `name`；`failure.name` 只用在断言消息里。
- **`RAC-1692` 的 `pulls`**：默认的 `ReadableStream` 水位是 1，构造后马上 `pull` 一次，送一块；读走这一块以后再 `pull` 一次，这次报错。所以第二次 `read` 拒绝，`pulls` 恰好是 2。`assert.equal(pulls, 2, …)` 证明错是在「读了一块之后」出的，不是 `fetch` 一侧。
- **超大小的用例**：`new Response(new Uint8Array(1024 * 1024 + 1))` 的正文是一整块 1 MiB 加 1 字节，超过 `:56` 的上限 `1024 * 1024`，在第一次 `read` 之后就走 `:40`。在 main 上这条也是绿的（护栏）。
- **`RAC-1693` 的两个时点**：
  - `request`：`fetch` 的 Promise 一直不完成，直到信号中止才以 `stop.reason` 拒绝；`entered` 在 stub 里 resolve，所以取消发生在请求还没返回时；
  - `body`：响应已经返回，`highWaterMark: 0` 让 `pull` 只在有一个读请求挂着时才跑，所以 `entered` 恰好在 `reader.read()` 等着时 resolve；默认水位的话 `pull` 会在构造时就跑，早于读；
  - `init.signal` 是 `AbortSignal.any([AbortSignal.timeout(120_000), signal])` 的合成信号，它的 `reason` 就是 `controller.signal.reason`；用例不用睡眠，也不等 120 秒；
  - 校验用函数加断言消息，不用 `error => error === …`：失败时能看到读回的错误和是哪个时点，M3 到 M5 靠这句分辨。
  - 这条在 main 上是绿的，它是护栏：包住两个网络调用以后，取消不能变成安装失败。
- **`assertNoCandidate` 的两句**照 `:31-32`、`:45-46` 原样，只加了断言消息。四个用例共用，不在每个里重复。
- 新用例只用文件里已有的 `assert`、`test`、`readdirSync`、`join`、`installManagedConnectorTool`、`openTestHome`、`input`、`control`，和 Node 全局的 `Response`、`ReadableStream`、`DOMException`、`Buffer`、`AbortController`、`Promise.withResolvers`，不加 `import`。`init!` 一类非空断言可以，不要出现 `as unknown as`。
- 标题前缀：`RAC-1691`、`RAC-1692` 用 `S-36 ASC-14`（「在解压执行之前拒绝」那一组，同 `:19`）；`RAC-1693` 用 `S-36 ASC-25`（同 `:37`）。每个用例前一行的 `// RAC-169x: …` 是英文，照 `:62-63` 的口气。
- 代码里不要出现 `legacy`、`compat`、`backfill`，不加空 `catch`、`as unknown as`、`any`、`console`（这些按文件计数，只许减少）。
