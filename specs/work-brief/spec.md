# 工作简报插件

状态：需求已整理（2026-10-15），尚未实现。用户已确认纳入独立的工作简报插件，仍由个人助理与场景 Skill 驱动。目标完成程度为**内部完整**。本文只明确已确认内容的归属和使用要求，不增加场景范围。

## 1. 目标与范围

跨插件产生的综合结果需要有明确的内容归属，能够持续查看、修订和引用。工作简报承载周期报告、专题分析、准备材料与方案对照，管理它们的正文、版本、来源和修订。

例如，一份周度复盘同时引用待办、文档、代码和会议。它属于工作简报；被引用的待办、文档、代码和会议仍由原插件管理。用户从简报中选择“准备交付说明”后，由同一个人助理接续，使用适用的 Skill 和业务工具完成。

临时提示、一句建议和普通运行通知继续留在助理中，不要求每次都生成简报。本文不新增另一套助理、调度、任务板、审批或业务完成状态。

## 2. 职责与事实归属

| 承载方 | 负责什么 |
| --- | --- |
| 平台 | 统一采集、数据工具、授权、调度、运行恢复、评测记录、定位高亮 |
| 个人助理与 Skill | 发现工作、选择材料、分析判断、组织结果、提出选项、执行与跟进 |
| 工作简报插件 | 综合结果的正文、版本、来源和修订 |
| 原有业务插件 | 待办、文档、日程、代码等原始内容及业务状态 |
| 首页与侧边栏 | 展示同一份简报的摘要和操作，打开对应内容，不另存一份结果 |

插件提供创建、读取、更新、比较和展示简报的通用能力。不同 Skill 使用这些能力决定写什么、怎样分析、提出哪些下一步；不在插件代码中固化“周报流程”“会议准备流程”或“阻塞分析流程”。

源插件缺少读取、修改或定位能力时，应由对应主人补齐；工作简报不能替原插件拥有这些能力。建议处理状态、真实批准和业务完成状态沿用原有归属，简报只展示引用。

## 3. 内容、版本与修订

用户能从首页、侧边栏或助理打开同一份简报，查看正文、范围、周期或主题、材料截止时间和来源。报告中的重要结论能够对照原始依据；缺数据、资料过期和无法取得历史内容时，保留可靠部分并明确影响。

用户能查看过去的简报及其修订，区分当时版本与当前内容。刷新或重新生成不能悄悄修改已经保存或分享的版本；源内容后续改变也不能使历史依据被新内容冒充。

用户可以改写和补充简报。再次生成时保留人工修改，对冲突提供可对照的差异，允许继续调整、采用或放弃；不能用新的 AI 输出直接覆盖人工内容。简报文字的修改不自动写回源插件业务事实。

临时回顾、正式留存和对外分享保持清楚区别。需要留存或引用的固定版本按现有成果机制处理，不把过程候选都当作正式成果。分享和外部效果遵循原有授权要求。

## 4. 后续操作与恢复

简报中的选项具体、可理解，保留自由补充和暂不决定的方式。查看正文、来源和历史版本不额外运行模型；需要继续分析或准备的选择交给同一个人助理及适用 Skill，明确的业务操作调用原插件真实能力。

执行前核对原工作、对象、有效版本和当前权限。旧简报、项目切换、内容变更、事项已处理或权限撤销时，不能沿用失效选项误操作。简报引用实际执行进度与产物，不维护第二份任务状态。

生成失败、中断或部分成功时保留已有有效内容和实际缺口；重试与恢复不重复生成相同用途的内容或重复执行后续操作。取消、停用、撤权后的迟到结果不能产生新效果。通用运行和恢复由平台及个人助理负责。

## 5. 验收标准

| 编号 | 用户可观察结果 |
| --- | --- |
| WBR-01 | 周期报告、专题分析、准备材料和方案对照能由个人助理按 Skill 生成并保存在工作简报中；临时提示不被强制保存为简报。 |
| WBR-02 | 首页、侧边栏和助理打开的是同一份内容及其版本；原业务内容、建议状态、批准和完成状态仍来自原主人。 |
| WBR-03 | 正文的重要结论能核对来源、范围和材料时点；缺失、过期或不可用资料的影响明确，不编造依据。 |
| WBR-04 | 保存或分享过的版本可以回看；后续刷新、修订和源内容变化不暗改历史正文或依据。 |
| WBR-05 | 用户修改后再次生成，可以对照差异、处理冲突、采用或放弃；人工修改不丢失，正文修改不自动改写源业务事实。 |
| WBR-06 | 简报的后续选择接回同一个人助理及真实业务能力；旧版本、错误对象、项目切换和撤权不会造成误操作。 |
| WBR-07 | 中断、失败、部分成功及重试保留有效结果，不重复生效；停止或撤权后的迟到结果无新增效果。 |
| WBR-08 | 保持平台及插件代码不变，修改场景 Skill 后，取材、分析和结果随有效做法变化；插件没有按场景名称固定的生成流程。 |
| WBR-09 | [人工] 在真实跨插件工作中完成生成、来源对照、人工修订、再次生成、历史回看与后续接续，结果可用且归属清楚。 |

当前均未进入功能验收。使用真实内容和实际入口验证；模拟结果只证明对应局部，不代表内部完整。

## 6. 关联需求与边界

[主动式助理与场景 Skill](../proactive-assistant/spec.md) 定义主动理解、周期报告质量、统一交互、权限、运行恢复与评测的完整要求；本文独立定义工作简报的内容归属和生命周期，不替代该需求书。现有平台和插件边界沿用 [事实归属](../../docs/SSOT-MATRIX.md) 与 [插件开发约定](../../skills/molis-plugin-dev/SKILL.md)。

本需求没有指定新的存储协议、动作名称、框架或额外场景。实现时沿用现有公开合同和 Plugin Runtime；需要确定的技术细节不得被当作已经完成的产品能力。
