## D0103 调查证据与影响面

[此前合并队列失败日志](https://github.com/molis-ai/molis-work/actions/runs/42806028453)只显示 D0103 在约1.3秒失败，进程到1200秒被杀，没有具体断言／钩子错误。因此本轮确认的是独立可复现的清理缺陷，不能把该次 CI 的首次失败原因认定为目录删除失败。

Node 24.15.0 最小复现：同一 test 注册两个 after，第一个抛错、第二个打印标记；结果失败且第二个标记不出现。当前用例恰在浏览器存活时先 rm profile，存在该失败路径。检查 tests 中29个使用 ChromeHarness.start 的文件：D0103 是其中独立目录删除钩子排在浏览器关闭前的直接实例；goal-browser 公共夹具已有逐资源释放与错误收集。不替换公共驱动，也不扩成全库清理重构；其他初始化失败或 close 自身挂起不由本修复宣称解决。

故障验证从修改后的用例生成三份临时副本，分别在实际 `await rm(...)`、`await browser?.close()` 后抛带 `D0103 injected` 的异常，或把最后一个断言替换成 `assert.fail`；依次用 Node 的 `--import tsx --test` 子进程运行。父进程验证退出码1、signal为空、输出含注入错误。副本放在忽略的 `.impeccable/qa/d0103-cleanup-probes/`，不引入产品调试开关。
