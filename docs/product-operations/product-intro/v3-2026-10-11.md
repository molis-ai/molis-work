# Molis Work 产品介绍 V3

## 一分钟介绍

Molis Work 是一款装在电脑上的 AI 工作软件，把资料、文档、任务和 AI 放进同一个工作环境。比如做一份行业研究，你可以收集资料，让 AI 协助整理报告，再把后续事项变成待办；隔几天回来，或者换一个 AI 工具，也能沿着记录继续。

它背后是**一个常驻宿主和一组业务插件**。插件各自管理业务和数据，平台统一提供模型接入、搜索和权限检查。同一项操作只登记一次，界面、助理和外部 Agent 按授权调用，让 AI 能使用这些工具，结果也留在对应的文档和任务里。

工具可以按需组合；缺一个顺手的工具，还能通过正在预览的创作功能，让 AI 帮你试做。Work 想把你的工作方法变成可反复使用的工具，同时让你看清过程、掌握决定、核对成果。

## 较 V2 的调整

- **沿用原来的思路和写法。** 仍是「一句话与目标用户 → 平台和插件 → 八个场景 → 功能全景 → 竞品 → 五条差异 → 官网建议」。场景继续写「场景、麻烦、怎么做、用到」，主要更新事实、进展和边界。
- **插件清单从 26 个改为 25 个。** 实验插件已删除（#370），不再介绍多模型实验功能；旧 Casebook 接入也已删除（#369），不能再列为可用能力。Text stats 只在开发者模式出现。角色仍在「设置 › 角色」，代码上仍是插件，不能把「计划并进平台」写成已经完成。
- **场景 2：完成确认更具体。** 开了「完成前必须你点头」的项目，旧的点头不能放行另一轮工作或改过的约定；点「完成」本身不等于验收（#340）。
- **场景 3、4：把权限和撤销说准确。** 外部 MCP 客户端逐项授权；随宿主发布、由 Plugin Runtime 托管的内置插件自动获得清单声明的权限（#381），两者不是同一种授权方式。记忆写入、撤销和「你说过」的依据已补修（#338）；撤销只适用于提供了撤销的操作。
- **场景 5：资料升格后，由本人确认输入。** Feed 经 Goals 自己的动作创建和登记输入，沿用调用者权限；本人操作可记已确认，Agent 操作只记待确认；取消、停用后不再继续下一步写入（#362、#387）。本人现在可以在 Goal 的输入列表里认可或移除待确认的来源材料，这一步不能由 Agent 代办（#388）。
- **场景 6：第一次配模型的流程补上了。** 常用供应商模板、保存前连通性检查、失败保留表单，以及配好第一个模型后回到原页面、更新「没有模型」提示，都已合入（#367）。底栏和标签栏的触摸目标、拥挤时的收纳也有一轮修正（#366）。
- **场景 7 与提示词：创作台有了新的检查依据。** 380 份历史真实设计答卷已进入离线回放；这证明设计检查的表现，不是生成插件的成功率。选区推荐、创作台选能力和选组件的判断题面现在也能在设置里改（#378、#379）。
- **协作分开写。** 项目讨论已有工作台入口；跨设备接续已有独立启动器和验证记录，但没有正式产品入口，也不随 Desktop/npm 发布；完整团队空间与多设备同步仍在后续。V2 的「讨论必须自行部署 Server」和「跨设备全部只有规划」都不够准确。
- **质量与发布更新。** V2 点名的插件生命周期、记忆、删除项目、助理记忆工具，以及问卷停止收集后的提交问题，相关修复均已合入；删除项目又补上 Sessions 清理（#361）。公开版本仍是 v0.2.0，Release 提供标签和源码，没有公开 macOS 安装包；0.3.0 尚未发布。

Molis Work 是装在你电脑上的工作平台，由一个平台和一组插件组成。你可以在一处跟进目标、整理资料、写文档、安排待办和写代码，项目里只加要用的工具；缺一个顺手的工具，还能在插件创作台描述需求，把它做出来。内置助理和 Claude Code、Codex 这些外部 Agent 经同一个能力目录使用这些内容，做到哪、还差什么、交的是哪一版，都有地方核对。

这版按 2026-10-11 的 main 核对。公开版本仍是 [v0.2.0（9/11）](https://github.com/molis-ai/molis-work/releases/tag/v0.2.0)，发布时还叫 GoalBoard，只含 Goals、Work（现在叫 Sessions）、Feed、Artifacts（现在叫成果）的基础能力。Release 只有标签和源码，没有公开 macOS 安装包。下一版已定为 0.3.0，还没发；下文介绍当前开发版，并逐项标明用户现在能拿到什么。

顺序沿用 V2：先认识平台和插件，再看场景，最后看功能与替代品。场景里的例子都是示意，不是客户案例；源码里已有、历史上实操过和用户本人认可，是三件不同的事。

## 一句话与目标用户

对外一句话沿用：**让工作，在人、工具与 Agent 之间继续。** 它背后仍是四件事：

- **一个平台，按需加插件。** 写代码的项目放代码工具，做研究的项目放资料和文档工具；常用的日历、笔记和待办在不同项目里都能用。
- **每样东西只有一个主人。** 目标归 Goals，待办归待办，文档归 Pages，留存的一版成果归成果库。助理读写的是这些原处的内容，换一个入口不会多出另一套进度。
- **能力只登记一次。** 同一项插件能力，可以按它声明的使用范围，交给页面、助理、工作流和外部 Agent 调用；权限由平台统一检查。
- **工作资料留在本机，联网范围说清楚。** 目标、笔记、文档和记录保存在电脑上；使用模型、搜索、连接器等能力时，相关材料仍会发往对应服务。本地优先不等于离线 AI。

先给谁用，仍按前两版的顺序：

| 用户 | 他们现在的状态 | 最先用到 |
| --- | --- | --- |
| 同时用好几个 AI 编码工具的独立开发者、技术负责人 | 今天用 Claude Code，明天换 Codex；除了代码，还要做产品、查资料、整理反馈 | Goals、Sessions、Coding、MCP 接入，以及 Feed、Pages |
| 产品负责人、研究和内容工作者 | 每天看大量资料，要写方案和周报，还有一堆琐事要跟 | 个人助理、Feed → Inbox → Pages、待办、Jelly |
| 小团队里牵头的人 | 想看清每件事卡在哪、等谁拍板，并把讨论和工作放近一点 | Goals 的依赖画布和决定中心、项目讨论预览 |

当前能承诺的主场景仍是一个人在自己的电脑上使用。团队是继续建设的方向；已有讨论和接续底座，也还不能把它介绍成完整的团队办公产品。

## 平台和插件

这一节继续用于官网「它由什么组成」的区块。

**平台**每个 Home 一份，所有插件共用：

- **一个常驻宿主。** 管项目、插件、能力目录与 AI 执行。浏览器和 macOS App 打开同一个本机工作台，命令行和 MCP 连接到同一个宿主。
- **一个能力目录、一套检查。** 查询和操作登记在一起，调用时检查身份、范围和权限。外部 Agent 只能发现和使用授予它的能力；会改变内容的调用留下记录。
- **一个工作台。** 底栏、侧栏、⌘K 搜索和设置共用。插件提供内容，放进工作台已有的位置。
- **一个 AI 运行时。** 模型、连接和预算集中设置，助理与插件共用；不用每装一个工具就重新接一套模型。
- **跨插件的服务。** 助理、记忆、搜索和选区推荐帮助你找到内容、继续操作；内容仍由原插件保存，搜索索引只是可重建的本地缓存。

**插件**在当前代码目录中共有 25 个：

| 类别 | 怎么用 | 插件 |
| --- | --- | --- |
| 项目插件（11 个） | 在每个项目里按需添加、移除；Goals 每个项目都带 | Goals、Sessions、Inbox、Feed、Schedule、成果，以及 Coding 一族（Coding、Files、Git、Diff、Text stats） |
| 个人插件（14 个） | 在不同项目里可用；某个项目用不上，可以在那里隐藏 | 待办、Jelly、灵光、Pages、Forms、Dataset、PPT、图片、Cognia、Shelf、炼金术士、工作流程、插件创作台，以及角色 |

这份清单有三处要说清：

- **Text stats 是开发者参考插件**，只在开发者模式的列表里出现；25 是代码目录的数量，不是默认给每个人展示 25 个入口。
- **角色仍在「设置 › 角色」**。把它从插件并入平台设置的方向已定，代码身份尚未完成调整。实验插件已经移除，不再列进功能墙。
- **个人插件的隐藏只是界面选择。** 还不能把它说成「在这个项目停用、助理和 MCP 也不能用」；这项停用语义仍在待办里。

插件创作台做出的插件可以装进项目。安装别人发布的第三方插件、分享与市场分发，仍只有后续方案。

## 八个场景：什么场景下的什么问题

每个场景仍可直接做成官网区块：「麻烦」帮助读者认出自己，「怎么做」讲实际变化，「用到」交代能力和状态。

### 1. 按需拼一个自己的工作台

- **场景**：一个项目只管目标和代码，另一个要盯信息流、写周报；日程、笔记、待办哪个项目都要用。
- **麻烦**：每件事一个 App，资料和进度散在不同地方；什么都有的大工具，又塞满你用不上的东西。
- **怎么做**：
  - 在底栏的插件选择器里给项目添加、移除工具，就地生效；常用的钉在底栏。
  - 个人插件在不同项目里都能打开，用不上的入口可以隐藏。
  - 一个插件离不开另一个插件的产出时，添加它会一起加上所需的插件。
  - 所有插件共用搜索、助理和工作台。日常内容留在原插件，需要交付或留存时再固定成一版成果。
- **用到**：插件选择器、底栏、侧栏、成果库。main 未发版；隐藏个人插件不等于撤销它的能力。

### 2. 换了工具，工作不用从头讲

- **场景**：周一用 Claude Code 搭登录页，周三换 Codex 接着做支付，周五回来，要知道现在还差什么。
- **麻烦**：会话各记各的。换工具、隔几天回来，都要再解释背景；AI 说做完了，也不等于已经满足要求。
- **怎么做**：
  - 要达成什么、做成了什么、还差什么，记在 Goals 的同一个目标里。
  - Codex、Claude Code、OpenCode、Pi Agent、Grok Build 有内置接入；其他工具可经 MCP 和统一 Skill 使用。换 Runtime 时，按你确认的交接内容继续，不是把所有原生聊天自动同步一遍。
  - Agent 可以报告进展、提出新需求；改掉已经认可的目标需要对应的用户决定。
  - 完成要显式收尾，核对当前要求、依据和阻塞。项目开启「完成前必须你点头」时，要有当前这一轮、当前约定下有效的用户结论；重开工作或改了约定，不能拿旧点头直接结案。点击「完成」本身不替代验收。
  - 收尾时选交付物：成果库已有的一版，或把文档当场固定一版。助理和 Coding 可以提议，由你确认；原文以后再改，仍能查到当时交的版本。
- **用到**：Goals、Sessions、依赖画布、决定中心、项目选择页、成果库。目标与会话基础能力随 v0.2.0 源码发布；新界面、交付物和这轮完成确认修复在 main，未发版。

### 3. 放心让 AI 动手

- **场景**：你想让 AI 改文档、建待办、开 PR，但不想事后才发现它动了什么。
- **麻烦**：能读什么、能改什么说不清；说了停下，后面的步骤还在写；出了错也找不到对应记录。
- **怎么做**：
  - 插件能力登记在共同目录，平台按实际调用者检查权限。外部 MCP 客户端按客户端和范围逐项授权，不能在输入里把自己说成你。
  - Agent 写文件、跑命令、推送等副作用经宿主审查，或按你已设定的放行规则处理。
  - 提供了撤销的操作，做完可以撤销。取消、撤权或停用后，后续写入要重新检查并被拒绝；已经发生的外部操作不会因此自动倒回。
  - 助理在侧栏浏览器里点击、输入时逐步确认，你可以接手；停止操作后交还控制。
- **用到**：统一能力目录与 MCP、审查队列、撤销、侧栏浏览器。main 未发版。

这里不写「所有入口都有同一张授权表」。随宿主发布、由 Plugin Runtime 托管的内置插件，会自动拿到自己声明的权限，不能逐项关闭；外部 MCP 客户端和生成插件仍按各自的授权规则使用能力。共同的是调用时的检查，不是所有调用方拥有相同权限。

### 4. 一个看得见你在做什么的助理

- **场景**：你在 Pages 写周报，想让助理把 Inbox 里三条客户反馈整理进去，再建两个待办。
- **麻烦**：要先复制材料、解释当前页面，再把回答搬回文档；下次继续时，又要交代自己的习惯和要求。
- **怎么做**：
  - 从底栏叫出助理，带上当前页面、选区或你明确引用的材料。
  - 用 @ 引用内容、用 / 选能力，也能读 PDF 和图片；需要实际操作时，通过插件登记的能力执行。
  - 建议可以呈现为操作卡，看到要做什么再继续。复杂工作可以拆给子任务，写代码的部分交给 Coding。
  - 个人和项目记忆分开管理，看得见、改得了、删得掉；助理说「你说过」，要能对上本人消息的依据。忘掉记忆有撤销，撤销自动记忆也不应抹掉本人后来明确保留的内容。
  - 到期和失败可以提醒，也遵守勿扰、暂停和稍后处理。
- **用到**：个人助理、操作卡、记忆、主动提醒、待办、Jelly。main 未发版。历史真实模型审查出现过「说做了、实际没调用」，已有拦截与后续修复，官网仍不写「说到做到」或「不会出错」。

提醒与后台执行依赖本机宿主继续运行。关窗口、退出程序、停止宿主和电脑关机不是同一个状态；这版不承诺电脑关机后仍继续工作。

### 5. 信息很多，只把要处理的送到面前

- **场景**：你订了十几个 RSS，关注几个 GitHub 仓库，每天几十封邮件，月底要交一份行业观察。
- **麻烦**：来源各看各的，重要的漏掉；写的时候找不回出处；把资料转成任务后，又分不清哪些是自己认可的。
- **怎么做**：
  - RSS/Atom、网页查询、YouTube、GitHub、Gmail 的内容统一进 Feed。
  - 按你配置的规则，把需要介入的送进 Inbox，并写明原因；选中的材料可以继续交给 Pages 整理。
  - 需要跟进的一条资料，可以升格成 Goal。创建目标和登记输入由 Goals 自己检查，不能借 Feed 绕过权限；本人操作可以确认输入，Agent 提交的仍是待确认。
  - Agent 提议的来源材料，在 Goal 输入列表里标成「待确认」。你可以点「认可这条输入」，也可以移除；移除只解除输入关系，原材料保留。Agent 不能替你认可，也不能移除你已经确认的来源输入。
  - 外部正文按资料处理，其中的指令不能替你授权。来源、原文和关联继续保留，方便回查。
  - 删来源可以保留历史；选择连本地历史一起删时，没有别处再用的缓存正文也一起清理。
- **用到**：Feed 与来源的基础能力随 v0.2.0 源码发布；Inbox、Pages、Schedule、新的升格检查与输入认可在 main，未发版。历史上走过「Feed 新资料 → Inbox → 转待办 → 放进项目 → 搜索打开」；本次核对了新输入确认的界面与动作实现，没有重新跑完整产品流程。

### 6. 第一天就有内容，以后都找得到

- **场景**：刚装好，不想先研究模型接口和一堆设置；用了一个月，记得写过「Q4 预算」却想不起在哪。
- **麻烦**：新工具是空的，配错模型也不知道错在哪；工具一多，东西又散开了。
- **怎么做**：
  - 第一次连接模型，可以先选供应商模板，由它填好已知的地址和格式，再补密钥和需要的模型名。
  - 保存新的连接配置前，先实际检查一次能不能连通；失败就说明原因、保留填写内容，不把失败配置当成功保存。
  - 从当前页面进入设置，配好第一个可用模型后回到原处，原先的「没有模型」提示会更新。同一浏览器中的开始使用页也会收到更新；桌面壳若把设置交给系统浏览器，仍需要手动点「已连接，继续整理」。
  - 勾选要接入的来源并授权，AI 整理出带来源的工作总结、项目建议和待办草稿。采用后生成项目，从待办开始；不要求先写 Goal。
  - 之后按 ⌘K，搜索已接入插件的真实内容，包括没有打开过的对象。短中文、Q4 这类词也可检索；打开时由原插件核对，定位到命中处。
- **用到**：模型设置、首次使用与新建项目、系统搜索。main 未发版；来源读取需要相应账号授权，正式 OAuth 发布配置仍是外部条件。

### 7. 缺一个顺手的工具，自己做出来

- **场景**：你想要一个账单到期提醒，或一份按自己习惯整理的客户反馈表；表格太散，专门找软件又太重。
- **麻烦**：做小工具要会编程；单独生成的网页应用，还要再想办法接回现有资料和工作。
- **怎么做**：
  - 在插件创作台描述需求，Agent 先给方案，再在沙箱里写代码。
  - 通过宿主检查和浏览器验收后装进项目，使用平台的界面、存储与能力。
  - 做出的插件把能力登记到共同目录；助理、Coding、外部 Agent 按声明和授权调用。它自己也只能调用宿主开放、安装时获准的能力，不能直接读写别的插件的库。
  - 选能力、选界面组件时使用的判断题面，也可以在「设置 › 提示词」里查看和修改；修改题面不会扩大权限或绕过检查。
- **用到**：插件创作台。main 预览，未发版；仍需要试用、检查，有时需要返修。

以前的 12 个真实需求记录里，4 个第一次到 ready，修过问题后 12 个都至少到过一次 ready。本轮又加入 380 份历史真实设计答卷的离线回放，记录中的首轮完整设计为 42/80 通过当前检查。两组数字的分母和含义不同，不能拿来宣布成功率从 33% 提升到 53%，也不能把设计通过写成插件已经可用。官网保留「预览」，不承诺一句话一次做成。

### 8. 写代码的会话，住在项目里

- **场景**：一个功能要改十几个文件，做到一半网断了，你也要去开会。
- **麻烦**：计划、执行记录、代码改动和需要审查的东西散开；几个会话之间接手，还得重新解释。
- **怎么做**：
  - 在项目里开 Coding 会话，计划、子任务、中断和审查留在连续的任务记录里，之后从已有状态继续。
  - 会话之间可以发信、提出委派，由接收方接受或拒绝；平台不自动给 Goal 派单。
  - Files 看文件，Git 看工作区改动，Diff 对比变更；需要留存的执行报告进成果库，计划和变更集保留为工作过程中的内容。
  - 写文件、跑命令、推送和开 PR，经宿主审查或你设定的规则放行。
- **用到**：Coding、Files、Git、Diff。main 未发版。代码智能、联网工具、沙箱规则、导出和编辑器集成等仍有后续需求，不把它宣传成已经替代专用编码 Agent。

仍按「用户现在拿什么解决问题」分六类。下表选取本次能重新核对官方资料的代表，保留前两版的比较方式；「Molis 的不同」是产品机制的比较，不是效果更好的实测结论。没有做同一任务下的完整竞品实操。

| 用户现在用的 | 代表产品 | 它擅长 | Molis 的不同 | Molis 目前不如它 |

| 编码 Agent | [Claude Code](https://code.claude.com/docs/en/overview) | 读改仓库、执行命令、接开发工具；支持多种使用入口、MCP、Skills 与并行工作 | 接住不同编码工具推进的共同目标、依据和交付版本，旁边还有资料、文档与日常工作插件 | 自带 Coding 的代码智能、联网、沙箱与编辑器集成仍有缺口；不以取代专用编码 Agent 为承诺 |
| 编码 Agent 的任务与规格工具 | [OpenSpec](https://github.com/Fission-AI/OpenSpec) | 把需求与变更规格放进开发流程，配合已有 AI 编码工具使用 | 用可视目标、决定与收尾记录承接工作，也覆盖研究和内容等非代码场景 | 更重：需要常驻宿主与工作台；只想在仓库里维护规格的人，文件工具更直接 |

| 通用 AI 助手 | [ChatGPT](https://help.openai.com/en/articles/11487775-connected-apps-in-chatgpt) | 用对话连接外部内容，已连接的应用可按权限执行支持的操作 | 助理直接围绕本机工作台里的页面、对象和插件工作，结果留在对应内容里；可调整已登记的角色、提示词和记忆 | 用户要自行配置模型与连接；本机持续运行、安装与维护还有成本，不能只比较回答效果 |
| 一句话做应用 | [Lovable](https://docs.lovable.dev/introduction/welcome) | 描述需求、迭代应用、发布到线上网址，也可把代码同步到代码托管平台 | 做出的工具留在已有工作台里，共用界面与授权，并按允许的能力接上其他插件 | 创作台仍是预览，可能返修；没有面向他人的完整插件分发和安装流程 |
| 人和多个 Agent 的协作空间 | [OpenAgents](https://openagents.org/docs/en/workspace/what-is-workspace) | 人与多个 Agent 在同一线程工作，用 @ 委派，并共享文件和知识 | 以 Goal 与各插件拥有的内容为工作依据，明确记录要求、版本和完成核对 | 完整多人协作不是当前交付范围；讨论与局部接续还不能组成同等完整的团队体验 |

三点提醒：

1. 能接 MCP、能改外部内容、能保存记忆，都不是 Molis 独有。不能把通用 AI 助手写成「只能聊天」，也不能说其他 Agent 都没有跨会话能力。
2. 「多个 Agent 一起干活」和「用 AI 做工具」都有现成产品。Molis 应展示的是做出的工具怎样接回已有资料、权限和交付流程。
3. 插件平台本身也不是空白。需要比较的是同一个真实任务：接入花多久、哪里需要人介入、改需求后怎么办、下次能否复用结果；这版没有这类对比数据，不写效率倍数或领先结论。

## Molis 的五条差异

仍沿用 V2 的五条。单看每一项，都有近似做法；这里说明的是它们在同一个本机工作台里怎样配合，不作「别人都没有」的判断。

1. **能力登记一次，多个入口用同一项操作。** 页面、助理、工作流和外部 MCP 客户端按受众与权限使用共同目录。调用方身份、项目范围和写入前的复查由平台统一处理；不用给每个入口再做一套业务能力。
2. **每样东西一个主人，工作接回原处。** Goal、待办、文档、日历各归自己的插件；助理经它们的能力读写，搜索打开原对象。要留存或交付时固定成一版成果，工作过程中的交接数据另有归属。
3. **缺的工具自己做，做出来能接进现有工作。** 创作台生成的是项目里的插件，按平台允许的能力使用资料、保存内容、接受助理调用。价值在于把自己的工作方法做成可反复使用的工具；当前仍是预览，不承诺一次成功或任意接通。
4. **一份目标供多个 Agent 继续，“完成”有依据。** Goals 记要求、进展、决定和交付版本。需要本人验收时，Agent 的自述不能替代；旧的认可也不能随意沿用到新的约定和工作轮次。
5. **AI 使用的规则可以看，也可以改。** 已登记的角色、提示词和判断题面集中在设置里；选区推荐与创作台的选择题面本轮也补进来了。改提示词不改权限，记忆可以管理，不把所有行为藏进一句「AI 会处理」。

「数据在本机」是这五条的基础，但还需要和 [联网说明](../../platform/NETWORK.md) 一起讲：模型、判断服务、网页搜索、账号连接、插件依赖下载各有自己的外发内容。不能把本地存储写成材料从不离开电脑。

容易写过头的几句，本版统一收窄：

- 不说「唯一」「首个」「支持所有 Agent」；写内置接入名单和 MCP 的实际边界。
- 不说「所有操作都能撤销」；写「提供撤销的操作可以撤销」，外部已发生的操作另看结果。
- 不说「所有权限都能逐项关掉」；外部客户端与内置插件的授权方式不同。
- 不说「隐藏插件后 AI 也不能用」；目前隐藏不等于停用。
- 不说「本地模型」「完全离线」「只会发送选中那段」；外发范围随实际使用的能力而定。
- 不说「关机也在后台干活」「自动给目标派单」；前者未交付，后者不属于当前产品承诺。
- 不说「25 个插件都已发布」「插件市场已经开放」；25 是当前开发版目录，第三方安装还在方案阶段。
- 不说「团队版、手机版已经可用」「一键无损升级」；完整产品入口、真实设备验收和旧数据升级都有未完成项。

## 给官网的建议

**页面顺序**继续沿用 V2，从上到下：

1. 首屏：原来的一句话，加一行具体解释——「目标、资料和工具放在一处，AI 接着做，做到哪都能查。」再列内置接入的 Agent。
2. 平台和插件：解释平台共用什么、插件各自提供什么；展示当前项目怎么选工具，不把 25 个图标全堆在首屏。
3. 三个主场景仍选 1、2、3：按需组织工作台、换工具继续、可控地让 AI 动手。
4. 五条差异，用实际界面和结果承接。
5. 次级场景仍是 4–8，助理放第一张；首次模型配置讲「配好后回到原处」，创作台明显标预览。
6. 功能墙，沿用上面的四组；已发布、开发中和规划中分别标明。
7. 和现在的做法比，说明适合谁、何时还不适合。
8. 本地优先、联网说明与真实发布状态，再结束页面。

**竞品仍不在官网点名比较。** Claude Code、Codex 等放在「配合使用」的接入名单里。上面的对比表用于内部判断和常见问题；官网主要展示自己的真实路径，不靠弱化别人来解释差异。

**这次值得换成新演示的三处**：

- 第一次配模型：从一个缺模型的实际页面出发，故意填错一次，看见具体原因；修好后回到原处继续。
- 完成要核对：先记录一条有效认可，再改变要求或重新打开目标，展示旧认可为什么不能直接放行新的完成。
- 自己做工具：用一个真实需求展示设计、返修、试用、安装，再由助理调用已经获得授权的能力。保留失败和人工检查，不只剪成功的最后一步。

这三条是建议的演示路径，本次没有重新跑产品，也没有新增真人验收。

**上线仍跟下一次发版走。** 截至本次核对，0.3.0 没有发布日期，也没有可公开下载的当前版 macOS 安装包。下载或试用按钮必须对应实际入口，不能把 main 的功能墙接到旧版源码包上，当作同一份产品。

- **版本与旧数据。** 0.3.0 是已经决定的下一产品版本。当前多数权威库只认现行结构，旧 Home 不能直接无损打开；现有一次性维护和开发机上的备份记录，不是交给普通用户的升级工具。
