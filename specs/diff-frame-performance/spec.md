# 大型代码变更的逐帧高亮性能

状态：执行中（2026-10-22），负责人 Codex。目标为功能可用；修复 Work #996 全量回归暴露的性能失败，单独开 PR。既有清理改动已合入，本任务只处理这项后续问题。

## 问题、范围和方案

CI Full suite 39745490860 的 `code-diff-scale.e2e` 两次失败，逐帧最长 518 ms、中位数 215 ms，原门槛为 200/80 ms。本机可用 CPU 降速复现。当前证据显示测试构造整份参考结果、反复序列化 DOM 与页面逐次高亮后的 grid 布局都贡献开销。缩小批次不能单独解决，不作为结论。

保留首帧完整纯文本、顺序渐进着色、超长压缩行纯文本、复制与选择、统一/并排布局、行号对齐和横向滚动。诊断后只减少高亮引起的重复工作，测试的参考构造移到计时前、完成检查改为最后一行并在完成后逐行全量比较。禁止降低性能阈值、跳过测试、修改 CI 或引入截断/删除屏幕外 DOM 的虚拟列表。公共 API、动作、数据与模型调用不变。

修改边界为 Coding 高亮客户端及必要的 Diff 行布局、对应浏览器测试和本 spec。输入是既有变更行与 token；输出仍是同样的文本、token 节点和行布局。隐藏/卸载后的帧任务沿用现有生命周期取消。布局方案以浏览器测量为依据，不固定像素宽度或字体假设。现已测得着色前后列表宽度 867096 px、高度 79868 px 和行高 20 px 均不变：采用浏览器 `contain-intrinsic-size: auto` 记住首次纯文本的自然尺寸，再由 `content-visibility: auto` 跳过屏幕外行的重复布局；全文与 token DOM 始终保留。首次纯文本布局后再启动高亮，容器宽度、字体度量或行高改变时重新记尺寸；长于一批的行持续渲染，避免滚到长行时一次性布局全部 token。若需改变产品语义，先补充决定。

## 验收标准

- **DFP-01** 2,000 行输入的 3,993 行变更完整可读，120,000 字符压缩行始终完整纯文本，30,000 字符行完成着色；每行结果与独立构造的完整参考相同。
- **DFP-02** 着色跨至少 3 帧且进度单调，沿用最长低于 200 ms、中位数低于 80 ms，以及变更/长对话单节点插入低于 50 ms 的原门槛；测试自己的参考构造不混入帧计时。
- **DFP-03** 统一与并排布局、缩放、缺失字体、中文/表情/Tab、行号对齐与长行横向滚动不回退。

## 验证与证据

先整体 `pnpm build`；定向 `node scripts/run-tests.mjs --jobs 2 --browser-jobs 1 tests/code-diff-scale.e2e.test.ts tests/code-rows-geometry.e2e.test.ts tests/code-diff-reader.e2e.test.ts`。按实际改动补 Coding/Diff README 所需测试；推送前检查 health（对照 origin/main）、boundary、page-assets、secrets。独立 PR 跟进 CI 和评审；工程验证不代表一骏本人验收。

阶段验证：首次改动后三个原浏览器用例均通过，正常速度最长 85 ms、中位数 17 ms。2.5 倍 CPU 降速中位数 40 ms，但长行仍有 241 ms 峰值；分段保留长行尾部的实验未证明稳定收益，已撤回。新增大文件缩放/字体回归发现字体与行高改变后缓存尺寸未更新，已用持续渲染的一行及其行号单元观察度量变化；最终实测与几何验证仍待补齐。尺寸缓存依据 [CSS Sizing 4 的 last remembered size](https://www.w3.org/TR/2026/WD-css-sizing-4-20260904/#last-remembered)。
