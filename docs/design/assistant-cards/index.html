卡片解剖

一张卡片回答五件事：针对哪个对象、为什么是现在、内容是什么、依据在哪、我能做什么。所有卡型共用这个骨架；不同卡型只换中间的块。

  1. 状态环与意图。环说状态，字说意图（需要你决定、卡住了、已备好…）。意图不配颜色，颜色只用于状态。
  2. 主对象与时间。主对象由主人解析，带插件图标；点卡片主体会打开并定位到它。右侧是生成或更新时刻，处理后这里换成建议状态（已暂缓、已处理、已失效）。
  3. 标题：对象 + 结果。一句话，至多 60 字。不写「建议继续完善」这种没有对象的话。
  4. 为什么是现在。时机与代价，至多 120 字。
  5. 块区。按卡型放 1–3 个块。这里是一个选项块（只改待提交的参数）和一个对象列表（主人的字）。依据标 1 悬停可看来源。
  6. 动作行。至多一个实心主按钮，名字写对象和结果，随选项改变；其余是幽灵按钮。说一句、更多在右端。
  7. 依据条（宿主写）。用了哪个 Skill 与版本、截至、依据数、读了哪些来源，以及读不到的缺口（琥珀点）。模型改不了这一行。
基础 · 2

三种字：谁说的，一眼分得清

卡片里的每个字都有来源。主人的事实永远由主人给，助理只决定选哪些、怎么排、加一句注；助理的断言挂依据；读不到、谁完成、变了什么由宿主写，模型压不掉。

不要这样

不给意图上色颜色只说状态。「需要你决定」不是一个紫色卡片，是琥珀待答环加一个词。
不叠卡中卡卡片是纸上的一块浅底，里面的对象行是纸色的行，不再加边框和阴影。
不出没有来路的数「效率提升 30%」「节省 2 小时」没有方法就不出现；口述的标「你口述」。
不用名字假装对象对象必须经主人解析；解析不了，卡片不生成，而不是显示一个点不开的名字。
不写「执行」「确定」按钮写对象和结果：「采用到第 3 节」「导入 48 份到『内测反馈』」。
不画模型给的 HTML附图是结构化数据由渲染器画；第三方内容一律按数据转义。
不在简报里存第二份任务状态要打勾就转成待办；简报只引用原主人的状态。
不为每个场景做页面周报、会前准备、阻塞分析都是卡型配方加 Skill；新场景先找现有卡型。
