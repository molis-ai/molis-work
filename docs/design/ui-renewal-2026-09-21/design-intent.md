# 设计探索的边界与取舍

> 已归档：用户已明确决定不再参考或继续优化首轮 Demo。本文仅保留当时的方案与探索过程，不作为后续设计或实施基础。最新原则、研究提炼与推进方向见[产品设计共识与研究总结](design-consensus.md)。

本轮是 UI 升级方案与可交互样张，不是生产改造。分支 `codex/ui-visual-renewal`。现有业务、用户数据、`taste.md` 和已生效规格保持原样，候选变更写在本目录，校准后再合入正式设计系统。

## 先做什么

1. 核对实际产品与用户偏好，读取指定竞品任务；把主要竞品与早期参照按真实使用问题一起比较。
2. 先完成一条会因操作改变下一步的工作路径：新反馈 → 对照影响 → 修改文稿 → 交回版本 → 审阅与返工。两个导航方向共享同一批对象与变化。
3. 用浏览器观察实际页面、主交互、窄屏与深色，记录问题与验证边界。
4. 给出逐模块方案、共性和独特设计分析，以及规格候选差异。

## 复杂度审查

- 当前必须：真实内容、高保真交互、可切换的布局方向、目标/注意事项/信息/成果之间的连续关系，来源与状态含义清楚。
- 可以延后：生产组件迁移、原生桌面适配、团队权限与共享、真实 Agent 执行、复杂拖拽分屏。正式实现时逐项接现有 owner。
- 应当删除：装饰性统计仪表盘、默认 AI 大聊天框、凭活动次数推断进度、为了演示重建一套后端、每种方向重新造组件。

已有 HTML Slot、字体、Lucide、palette 和本地界面状态足够支撑探索；不新增框架和依赖。Demo 的组合样式独立，不对生产层叠补丁。

## 方向 A：续流

以当前工作为主角。插件身份留在窄轨，目录提供定位；中心是连续工作面。首页的继续入口直接恢复专业制作面。对象详情把结果、当前依据、缺口放在历史之前；没有可执行对象的等待项收起，不把所有未知都推成需要人的通知。

```text
插件轨 | 当前目录 | 当前目标 / 工作标签
       |          | 结果预览             | 还需确认
       |          | 当前要求与工作记录   | 输入版本
```

## 方向 B：对照台

导航合成带文字的窄侧栏，比较时让内容本身占主位。核对变化时并排当前要求与候选要求，说明哪些成果受影响；审阅时并排上版与本版，意见输入就在所选段落下方。制作时回到同一份工作稿，带着当前依据与返工意见。

```text
文字导航 | 当前工作 / 本版依据 / 操作
         | 上版正文          | 本版正文
         |                   | 所选段落的意见 → 返回原稿
```

导航与工作方式分开比较：A/B 是候选布局，同一件工作均可进入制作、变化对照和审阅。静态三栏仅保留为布局样张；核心验证是实际文本的前后版本对照与段落反馈。常规 Feed/目录仍为密集对齐行。

## 共用视觉骨架

浅色：外场 `#f1f3f5`，纸面 `#ffffff`，墨色 `#262a30`，次字 `#626b77`，细线 `#e3e7ec`，靛色 `#626ac5`。插件色沿用当前语义，警示为琥珀、完成为绿。B 的石墨导航只是层次选择，不改状态词。深色使用独立语义值，不做 CSS 反相。

Inter Variable 与现有 Noto Sans SC；常规文字 13px/400，文档正文 14px，标题 22–28px/400。只在小范围成果预览中允许更鲜明的排版。普通工作区不出现巨型营销标题。控件 28–32px、触屏 44px；焦点内侧墨线；阴影只用于浮层。

记忆点放在操作后准确变化的关系：采用反馈后带入写作依据，提交后保留精确版本，意见返回对应段落，首页据此更新下一步。删去默认欢迎大数字、装饰图形、进度百分比；不以默认聊天占据专业工作面。

## 原型状态边界

固定示例项目「Molis AI 网站更新」，所有人物、版本、进展均为演示数据，不代表真实项目状态。允许本地演示决定、记录、筛选、模式切换和恢复草稿；不连接生产 API、执行 Runtime、发送消息、发布成果或形成真实授权。
