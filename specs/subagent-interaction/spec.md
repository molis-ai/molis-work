# 子代理查看、直接对话与父子任务动线

状态：需求已整理（2026-10-15），尚未实现或验收。本轮仅整理需求、更新交接并提交推送，不开发。负责人：Codex（需求整理），Prologue 与 Molis Work 实施负责人待分配；已有统一协作、输入回执及交互线负责人保持原归属。

## 1. 目标与现状

个人助理与 Coding 内都有位置稳定、容易找到的子代理组件。用户能看到谁在做什么、查看过程与结果、进入指定子代理的独立对话，直接提问和补充要求，再顺畅回到父任务。子代理继续受原工作范围、权限和协作关系约束；父任务能获知影响整体工作的变化，不需要用户在几个对话间手动传话。

目标完成程度是**内部完整**：两处入口的真实子任务、直接对话、执行中补充、结束后继续、父任务回报与失败恢复均可实操；位置、阅读、输入、切换和反馈形成完整体验。工程通过、真实产品实操通过与用户本人验收分别记录。

## 2. 范围与保留项

覆盖个人助理内的子工作、Coding 内的 SDK 子代理，以及这些任务在现行协作合同下的父子关联。可见和可对话的范围只包含当前用户有权访问的工作。已有任务内容、原会话历史、身份、成果与审批记录继续由各自主人保存。

复用 [Prologue 采用与统一协作](../prologue-adoption/spec.md)、[输入回执](../ai-input-receipts/spec.md)、[跨插件 AI 交互](../ai-interaction-experience/spec.md)的事实和端口。组件统一的是用户交互和共享视图合同，不将助理 Work 与 SDK 子运行强行改成同一种数据库对象，不为 UI 另造任务图、消息账或运行状态机。

不新增独立的 Agent 管理产品、外部聊天页面或浏览器标签页；不加入跨项目自由通信、多人群聊、自动扩大权限或无限并发；不改变 Coding 的成果整合授权。已停止、失败、重启中断的任务不会因打开组件自动执行。

## 3. 用户路径与组件行为

### 3.1 从父任务发现子代理

子代理入口位于个人助理和 Coding 各自工作界面的稳定位置。父任务派出子代理后，入口显示数量、进行中状态、待用户处理和未读结果；展开后列出名称或角色、任务摘要、状态及必要的等待/失败原因。过程和大段结果按需展开，常用操作不埋在日志里。没有子代理时保持简洁，不造占位卡片。

同名角色靠任务说明区分；嵌套任务可看清父子层级。SDK 子代理与助理子工作使用一致的状态语言，但不能伪造底层未提供的状态或把“本轮结束”显示成“任务已完成”。数据暂不可读应显示读取失败和重试，不能当作子任务消失。

### 3.2 打开、阅读、返回

点击某个子代理即可在当前助理或 Coding 工作区域打开它的详情和对话，不经全局会话列表中转。显示清楚的子任务标题、所属父任务和返回入口；父任务不因为查看子任务而停止。查看结果、过程、问题、审批和成果能相互到达；已有审批及整合能力继续使用原组件。

返回父任务、切换兄弟任务、再次打开同一子任务时，恢复各自草稿、滚动位置和展开状态。宽屏可以保留任务列表与对话，窄屏允许列表和详情逐级切换；具体布局在高保真切片中确定，不能依赖增加层层弹窗维持导航。不会重复打开同一个任务、挤走正在编辑的页面或新建一个无关聊天。

### 3.3 直接对话

输入框始终明确显示当前接收者。用户发给子代理的消息以用户输入进入该子任务自己的上下文；不要求父模型代转，也不伪装成父代理或系统消息。子代理的回复留在自己的对话里，用户可连续追问；父任务收到必要的变化与结果引用，而非整段子对话重复灌入。

复用[统一输入](../unified-input-voice/spec.md)的键盘、IME、草稿和发送语义，输入回执沿原规范区分接收、进入上下文和实际处理。发送等待期间切换任务不改变已冻结的目标；响应返回也不切走用户当前阅读的任务。失败保留文字，结果未知可按原请求查询或重试，不重复提交。

### 3.4 执行中与结束后

| 子任务状态 | 用户发送后的行为 |
| --- | --- |
| 运行中 | 将输入交给该子任务既有控制/输入通道，按明确模型边界生效；显示“已接收/待处理”等真实回执，不声称已读或立即生效 |
| 等用户回答或审批 | 回答通过原待答问题入口接续；普通补充仍是输入，不能隐式批准审批或替代结构化回答。清楚区分“回复子代理”和“回答这个问题” |
| 正常结束 | 允许在同一逻辑子任务下继续对话；创建新的执行尝试并保留旧结果与历史，不复活旧 Run。沿当前有效权限、预算、模型及角色配置复核 |
| 已停止、失败或中断 | 仍可查看；用户明确选择“继续此子任务”等动作后才尝试接续，按钮解释会启动新的执行。未知副作用先核对，不能自动重做 |
| 已收回、换负责人、失去权限或来源失效 | 保留可访问的历史，说明当前不能向原执行者继续；给出返回父任务或实际可用入口。旧页发送应明确失败，不能改投其他目标 |

用户在普通提问中没有授予额外副作用权限。结束后继续沿用有意义的上下文与子任务身份；跨执行尝试的任务、对话与原始派出关系可查。子任务拥有的工作范围如果已交回或被重新分派，由现有协作合同核对权威归属，不能仅凭历史 Session id 再启动执行。

### 3.5 父任务获知变化

用户对子任务的新要求、子任务的状态变化和新结果，应有来源明确、可追踪的关联记录。父任务进行中时按现有协作输入/通知语义获得必要变化；等待子任务时继续按同一等待与接续合同处理。影响原目标、分工或已接受成果的变化须可见，不能让父任务继续把旧结果当成最新结果。

父任务已停止或结束时，展示子任务有新进展并保留通知，不因子任务聊天自行重启父任务。用户不必手工复制消息；也不为每条消息额外调用一次模型生成汇总。现有回报、输入引用和接续能力足够时直接复用，必要摘要由原执行路径产生。

## 4. UI 与交互质量

“能打开、能发送”不足以完成本需求。沿用[视觉细节与 UI 性能](../visual-ui-experience/spec.md)、[字体、皮肤与语言](../font-and-skin-system/spec.md)和现有设计系统；实施前给出含真实或逼真任务内容、运行/等待/失败状态的高保真可操作切片。

- **动线可理解**：父任务 → 子代理列表 → 指定子代理对话 → 返回父任务；常用操作在当前工作区域完成。当前任务、输入接收者及返回目的地清晰可辨，不把所有子对话平铺进父时间线。
- **更新不打断**：新结果用局部状态和未读提示呈现，不自动展开、切换任务、移动焦点或推走阅读位置。仅在用户处于对话底部时跟随新消息，离开底部后提供返回最新的位置入口。
- **输入稳定**：流式输出、列表刷新和进度变化不重建正在输入的区域；保留光标、选区、IME 合成与草稿。切换对象前后均能明确下一次发送的目标。
- **反馈连贯**：加载、发送、已接收、失败与恢复有就近反馈；不以完整页面刷新、反复闪烁、整段重播或重复 toast 告知普通进度。动效用于解释展开、切换和状态变化，支持减少动态效果。
- **适配与可达**：浅色、深色、中文、英文和窄宽度下可读可操作；键盘能进入、选择、返回、发送并处理问题，焦点恢复到合理位置；状态不能只靠颜色表达。
- **长任务可用**：长历史、多个并行子任务和持续流式输出下仍能输入、滚动和切换。复用已有性能测量方案，对同一机器、内容和负载比较，不以 HTTP 响应时间证明交互顺畅，也不未经测量另定一套数字门槛。

## 5. Prologue 需要补的通用能力

Prologue 提供无 UI 的公共合同，不包含 Molis Work 文案、组件、Work 表或业务分工。先核对现行 Session 输入与 TaskBoard API 可以复用的部分，再补真实缺口；下面是行为要求，不预先冻结新方法名。

| 能力 | 输入、输出与边界 |
| --- | --- |
| 受信用户输入 | App 按精确子任务/协作节点、当前执行归属和请求标识提交用户输入；可信来源由 Host 接入决定，不能由模型文本冒充。输出可查询回执和实际目标引用，保留现有输入的生命周期 |
| 观察与对话历史 | 复用子 Session 的公开历史、进度、事件与分页，提供足以关联逻辑子任务及各次执行的稳定引用。公开可展示消息、工具活动、结果和问题引用，不暴露私有推理、密钥或未授权材料 |
| 已结束子任务接续 | 在原逻辑节点下开始新的合法执行尝试，复用统一接续入口与 App 的准入；一次请求只启动一次。核对代次、归属、父级约束和未知副作用，不改写旧终态 |
| 父子通知与恢复 | 用户干预和新结果可关联到原父任务；投递去重、接续、父停止及重启恢复沿现有协作机制。迟到消息不能落到已换手的执行者，不新增另一套消息队列 |

需要协调修订当前“App 只看和取消、不给发话”的子代理合同，明确用户输入与父模型 `steer-subagent` 的身份差异；不能通过调用私有控制对象或伪造父消息绕过合同。原 Session、输入回执、任务图仍各自拥有事实。现有能力若已经满足某条，应记为复用并提供证据，不为本需求再造同义 API。

## 7. 异常、持久化与并发

刷新、关闭再打开组件后能回到同一子任务并读到持久历史；草稿沿现有统一输入存储约定恢复。宿主重启后展示真实的可恢复、已停止或需核对状态；打开页面不重新派出任务。订阅关闭时释放，重新订阅按已有游标和版本接回，不能把历史事件再次当作新回复。

同时出现用户补充、父代理转向、任务结束或取消时，按共享输入与协作合同决定接收和生效顺序，并能从回执解释。请求未知时按相同标识查询/重试。停止一个子任务只影响其合法子树，兄弟任务继续；取消父任务按原向下传播规则处理。停止、撤权、换手后到达的输出不再触发未获准的新效果。

## 8. 依赖、实施顺序与文件边界

本 spec 是此项产品行为的唯一需求来源；统一协作、输入回执和其他 UI spec 继续拥有其基础合同。实施时核对最新主线与在途 PR，不按本文现状快照重做已完成的采用工作。

顺序：核对并补齐 SDK 用户输入/接续合同与公开入口 → Agent Host 接入 → 共用组件高保真切片 → 助理与 Coding 分别接通 → 双入口真实操作和恢复验证。可并行的设计工作不等于授权几个 writer 同时改共享文件。SDK 合同与 Molis 产品接入由原采用/统一协作线协调，输入来源和回执由原输入线协调，视觉与输入沿对应需求；两产品体验由本项验收收口。

预期文件边界为 Prologue 的现有编排、Session、公开组合入口及相关需求/测试；Molis 的 Agent Host 适配与公共合同、助理原服务和客户端、Coding 子任务组件与路由，以及必要的共享 UI。实现前根据当时结构确认具体文件，不整文件覆盖在途拆分，也不复制 SDK 私有代码。跨仓切换按 [合同变更流程](../../docs/system/CONTRACT-CHANGES.md) 和当前 SDK 打包流程完成；生产切换与回退方案在实际接入时记录，不能同时留两套正式入口。

## 9. 验收标准

| 编号 | 可观察标准 | 证明方式 |
| --- | --- | --- |
| SAI-01 | 个人助理和 Coding 均有稳定的子代理入口；真实派出后显示正确任务、角色、状态和归属，未知状态不冒充完成 | 两入口产品用例 |
| SAI-02 | SDK 子代理与助理子工作均可进入自己的对话，用户直接发给指定对象并连续追问；不经父模型代转或生成无关会话 | 真实 SDK/Host 端到端；检查子上下文与回复 |
| SAI-03 | 运行中补充按共享输入边界生效；回执区分接收和处理，来源为用户；子代理实际消费正确正文 | SDK 行为测试与 Molis 输入回执用例 |
| SAI-04 | 切换对象与发送完成交错时消息不串任务，失败保留草稿，未知结果重试不重复输入或启动 | 制造真实发送/切换/回执交错 |
| SAI-05 | 正常结束后继续同一逻辑子任务，只创建一个新尝试并保留旧结果；停止/失败/中断只有明确继续才启动，需核对状态不自动重做 | SDK 接续与产品用例 |
| SAI-06 | 待答问题、普通聊天和审批互不冒充；回答能接续原问题，普通消息不授予额外权限 | 问询、审批和输入联合用例 |
| SAI-07 | 子任务用户输入及新结果正确关联父任务；父任务获得必要变化且不重复回报，已停止或结束的父任务不自行重启 | 父运行中、等待、终态三类联合用例 |
| SAI-08 | 伪造身份、越项目/安装/任务访问、旧代次及已收回对象的输入被拒绝，零错误投递/派出；沿原权限预算复核 | SDK 与 Host 拒绝用例 |
| SAI-09 | 子任务取消、父取消、撤权、换手与迟到结果交错符合原协作约束，兄弟任务不被误停 | 并发与取消回归 |
