## 1. 背景

GLOSSARY 第 5 节的「内部改名」清单（R-A1～R-A11）要把代码里把项目叫 Board 的名字改掉，W5-14 一片一片做。main 上已做四片（`docs/system/GLOSSARY.md` 里 `W5-14 片 1` 到 `片 4` 各出现一次，没有片 5）。R-A1 那一行（`docs/system/GLOSSARY.md:411`）里，`requireBoard` 是其中唯一一个完全在 Goals 包里、不出包、不在合同导出里的名字。

核下来的事实：

- 定义只有一处：`plugins/native/goals/src/module/command-support.ts:21-25`，`GoalsCommandContext` 的方法：库里没有这个项目的根记录（`this.repository.boardExists(projectId)` 为假）就抛 `goals.board.not_found`，文案「这个项目还没有初始化目标资料库」。
- 调用共 24 处，分在 `plugins/native/goals/src` 的 12 个文件里，别处没有（`git grep -n requireBoard -- plugins packages apps horizontal modules server tests scripts tooling` 只有这 24 处）：

- 没有测试、没有 `packages/`、没有 `apps/` 引用 `requireBoard`。它不在合同导出里，不出现在动作 schema、Manifest、MCP 工具名里。所以第一道证明是 `tsc`，不是测试。

名字的选法：R-A1 的建议列已经写定 `requireGoalsLibrary`（`docs/system/GLOSSARY.md:411`），照它。「目标资料库」是 Goals 根记录的文档名（`docs/system/GLOSSARY.md:188-190`）。

## 5. 做法

1. 机械替换，只在 `plugins/native/goals/src` 下。macOS 的 `sed` 不认 `\b`，不要写；`requireBoard` 不是任何别的标识符的一部分（第 1 节的 24 行全是整词），直接替换：

   ```
   git grep -l requireBoard -- plugins/native/goals/src | xargs sed -i '' 's/requireBoard/requireGoalsLibrary/g'
   ```

   改完看 `git diff --stat`：12 个文件，24 行加、24 行减。多一行少一行都先查原因。改后最长一行 57 个字符，不会撞行宽。
2. `docs/system/GLOSSARY.md:189`：把 `command-support.ts:32` 改成 `command-support.ts:23`。
3. `docs/system/GLOSSARY.md:411`（R-A1 那一行）：只改第 4 格（规模格）。写法照 R-A3 那一行（`docs/system/GLOSSARY.md:413`）：
   - 规模格里去掉「`requireBoard` 10、」。
   - 格末加一句「**2026-10-28 已做（W5-14 片 5）**：」，内容是：Goals 包内 `requireBoard` → `requireGoalsLibrary`，12 个源码文件、24 处（`GoalsCommandContext` 的方法，加 `goal-tree-decision.ts`、`goal-tree-submission.ts` 两个类里的同名私有方法）；没有测试引用它；`getBoard`、`GoalsBoardRecord` 在合同导出里、`boardExists` 在库层，错误码 `goals.board.not_found` 属 R-B3，都没动。
   - 第 1～3 格不动（旧名仍留在第 1 格，和 R-A3 的写法一致）。
   - 「片 5」是 main 上下一个空号。动手前再 `git grep -n "W5-14 片" -- docs specs`：若 main 已有片 5，用下一个号。
4. 不要自己造别的名字，也不要顺手改同文件里的其他 Board 名字。
