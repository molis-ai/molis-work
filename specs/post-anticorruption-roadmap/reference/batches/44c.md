## 实施记录

一个 PR、按交付项分提交（`44C-1`、`44C-2`、`44C-3`）。不改产品语义，没动真实 `~/.molis-work`，旧取值直接删、没写迁移。

### 44C-1 统一提供方身份与平台登记

- **提供方身份一处算**：`resolveActionProviderId` 只留在 `@molis-ai/molis-work-plugin-runtime` 一份（随包放行的是插件编号，其余是安装编号），六处三种算法收成一处；插件启动时由 Runtime 给 `PluginStartContext.provider_id`，插件不再自拼 `plugin:<编号>`。
- **平台登记**：`apps/workbench/src/platform-settings-registry.ts`（平台设置一张表）、`runtime-plugin-directory.ts`（运行时插件目录）、`platform-surfaces.ts` 与 `packages/ui-host/src/platform-surfaces.ts`（成果库、Characters、Sessions 进 `HostSurfaceRegistration`，M15），宿主路由从 `platform-surface-routes.ts` 读同一份登记。
- **`"shelf"` 专名**：定成平台部件身份，合同里的接收站写 `PLATFORM_RECEIVE_STATION`（`system.shelf`），呈现槽与 DOM 事件同改，桌面壳按平台部件打开；`CODING_QUESTION_TYPES` 收掉，问题卡按声明。`tooling/versions.json` 的 `sync.collection.platform.attention` 排回字母序。
- **保留、说明理由**：`scripts/check-package-boundaries.mjs` 钉住的 `plugin-workbench.ts` 导入 `BUILTIN_PLUGIN_CATALOG` 与 `stage-renderers.ts` 的 `.find(...)`，是 Goals 页面宿主的现行边界核对，换写法要改门禁，留给搬 Goals 页面的批次；`scripts/gates/artifacts-platform-ui.mjs` 钉在 `plugin-registry.ts` 的那处同理。

### 44C-2 集成驱动收尾与厂商分支清零

- **一份驱动合同**：`IntegrationDrivers` 是集成包交给宿主的唯一合同（`integrations`、`accounts`、`documents`、`web_search`、`marks`、`cli_release_file_hosts`、`managed_environment`）；`integration-registry.ts` 并入统一运行时，签名沙箱集成与内置集成进同一个登记。宿主删 `account-providers.ts`、`github-connector.ts`、`gmail-connector.ts`、`catalog-connector.ts`、`connector-execution-mode.ts`，工作台删 `connector-icons.ts`。
- **厂商分支清零**：Salesforce、Atlassian、Microsoft Graph（含 PowerShell 与工具来源的包名）、HubSpot／Hugging Face 环境变量、Gmail／GitHub 读取表都进了各自集成包的驱动；`settings-connector-guide.ts` 与 `connector-marks.ts` 不再写服务 id，卡片的用途、账号提供方、首选方式、分栏凭据写在声明的 `card` 里，图标由集成包的 `marks` 带来。除生成的 `plugin-registry.generated.ts` 外宿主不导入集成包。
- **门禁改动（用户 2026-11-25 定）**：`scripts/check-package-boundaries.mjs` 的集成节原来要求宿主必须有 `github-connector.ts`、`gmail-connector.ts` 并各自导入集成包，和本批目标冲突；改成更严的反向核对——这两个旧文件名不许再出现，宿主与工作台除生成的清单外任何文件（含注释与字符串）不许写集成包名、不许写 `gmail.googleapis.com`，测试 `tests/package-boundary-must-contain.test.mjs` 的「44C-2 PSD-08」逐项证拒绝。
- **权限名单**：`HOME_ACTION_PERMISSIONS` 的 `feed:read`、`inbox:read` 与项目页的 `inbox:write` 删去——本机网页授权（`localWebAuthority`）本来就按运行中安装声明的动作与授权给插件权限，名单里这几项是多余的。
- **「同一服务两份声明拒绝启动」**：重复检查改在驱动表建好时就做，宿主导入即拒；`tests/builtin-integration-providers.test.ts` 的「44C-2 PSD-08」补了拒绝测试。
- **保留、说明理由**：平台自己的服务（`model-api`、`image-api`、TypeSafe、`mcp-bearer`）可以点名，它们是平台服务不是集成插件；上手的来源种类 `"gmail"` 是已存的取值，保留，服务改从邮箱驱动取；`EXTERNAL_DOCUMENT_SOURCES` 是成果库模块自己动作的输入枚举，保留；中央账号登录的 GOOGLE／GITHUB 归 Auth 合同；约 60 个内置集成不存成 Home 行（D3=A，启动成本，也免得漏进列表）。
- **偏离**：文档导入的来源下拉改按声明顺序排（Google Docs 在前，原来 Notion 在前）。
