## 三个方案只差「怎么走到一条」

三个方案用同一份数据、同一套条目详情、同一个导入导出入口；差别只在页面怎么组织五类条目。

| | A 一张目录（推荐） | B 先总览，再进一类 | C 按来源 |
| --- | --- | --- | --- |
| 打开时看到 | 第 08 批的列表＋详情。顶上「按类别」分段（全部 · 技能 6 · 提示词 4 · 角色 4 · 工具 10 · MCP 3），「全部」时列表按类分组，每组先列 4 条加「看全部 N 个」；右边是选中那一条 | 五张类别卡片：这一类是什么（一句话）、有几条、要你看的（在用、用不了、你改过、默认已更新、会写的）、最近用的一条、改在哪里。上面一条提醒「3 项用不了」和「只看这些」 | 列表按来源分组：写作工具、法务审阅、本机导入、你的角色、Coding 插件、系统 · Agent Host、服务连接……组头写版本和带来几类；点组头看来源详情（带来什么、上次升级的差异、去管理） |
| 找某一条 | 搜，或点类别，再点那一行 | 点卡片进那一类（或在总览搜），再点那一行 | 搜，或按类别筛，再在它的来源下点那一行 |
| 一屏的主焦点 | 列表 | 总览时是那条提醒和五张卡；进一类后是列表 | 列表（来源组头比条目更显眼） |
| 和第 08 批 | 同一个部件，多了列表里的分组标题 | 每一类就是 08 的单类目录，原样；多了总览卡片和页签 | 分组的想法同 08 当时否掉的「按包分组」；多了来源组头和来源详情 |

### 取舍

**A 一张目录（推荐）**

- 注意力：一屏一个主焦点（列表），详情一直在旁边；「共 25 项 · 3 项用不了 · 只看用不了的」一行把要处理的事放在列表顶上，不另弹提醒。
- 认知负荷：五类在同一个列表里分组摆出来，一眼能认出「有哪几类、各有几条」，不用记住在哪一页；每组只先列 4 条，长的类（工具、条目很多时的提示词）不淹没别的类。条目详情一类一个样子，但顺序一样（现在 → 用量 → 用在哪 → 版本），换类也不用重新学。
- 主路径步数：找到一条并去改它 3 步（搜或点类别 → 点那一行 → 「在提示词里改」一类的按钮）；看哪些用不了 1 步；开关一个技能 2～3 步（点类别或那一行 → 三档）。
- 和 08 的一致：最高。同一个列表＋详情部件、同样的选中、窄屏一次一边、同样的状态色调；技能那一块原样。
- 组件板新增：列表里的分组标题与「看全部 N 个」；加上三个方案共用的几件（见下文）。
- 代价：「全部」时列表很长（条目很多时尤其），要靠分组上限和搜索兜住；不像 B 那样先讲清「五类是什么」。

**B 先总览，再进一类**

- 注意力：总览一屏就是「要你看的」：提醒排在最上，五张卡各写这一类要处理的。第一次来最好懂，也最适合「看一眼有没有问题」。
- 认知负荷：最低的第一印象（卡片上一句话讲清每类是什么、改在哪）；但多了一层：总览和某一类两种画面，要记得自己在哪一层（页签和「总览」页签兜着）。
- 主路径步数：比 A 多 1 步（先进那一类）；总览里直接搜可以省掉这一步。开关一个技能 3 步。
- 和 08 的一致：进到一类以后和 08 的技能目录一模一样；总览卡片是新的。
- 组件板新增：类别卡片（一张卡是一个按钮：标记、名称与一句说明、个数、状态标记、最近一条、去处）；进一类后的页签带个数（用现有 `mw-tabs`）。
- 代价：常来的人每次多走一步；五张卡在 1440 是 3＋2、在 1024 是 2＋2＋1，不如列表齐。

**C 按来源**

- 注意力：最贴「从哪来、装卸以包为单位」：停用或卸载一个插件前，一眼看到它带来的技能、提示词、角色和 MCP；升级差异在来源详情里一处看完。
- 认知负荷：一组里混着几类，每行要靠标记认出是哪一类；想看「全部 MCP」得先按类别筛。工具几乎都在「系统」一组里，那一组很长。
- 主路径步数：和 A 相同（3 步）；但浏览时要先知道它从哪来。
- 和 08 的一致：中等。列表＋详情部件照用，组头是新的（展开、可选中、带状态）。
- 组件板新增：来源组头（展开按钮＋可选中的组头，带版本与「带来几类」）；来源详情（带来什么、上次升级的差异、去管理）。
- 代价：最密；来源对第一次来的人不是自然的找法（他们想的是「我那个提示词」，不是「Goals 插件 4.2.0」）。

### 推荐 A，理由

1. 一个地方、一张列表：用户的诉求是「一个地方都能看到、管起来」，A 不加层级，五类同屏。
2. 常用路径最短：找一条、看哪些用不了、开关技能都不多走一步。
3. 和 08 最一致：同一个部件只加分组标题，组件板新增最少，实现风险最小；技能那一块原样。
4. 三种宽度都成立：窄屏「按类别」换成选择框，列表与详情一次一边，和 08 一样。
5. B 和 C 的长处可以以后小步借来，不必换方案：A 已经有「N 项用不了 · 只看用不了的」（B 的提醒）；详情里的来源一行以后可以做成「只看这个来源」的入口（C 的视角）。

## 三个方案共用的部分

### 条目详情：一类一个「现在」，其余顺序相同

每条的详情都是：类别 → 名称与一句说明 → **来源一行**（来源、版本、「这个项目」或「个人空间」）→ **现在**（这一条的状态与去处，放在一块浅底里）→ 用量 → 用在哪 → 版本与升级。各类的「现在」：

| 类 | 现在 | 改去哪里 |
| --- | --- | --- |
| 技能 | 第 08 批那一块原样：三档（关／自动／仅手动）、用不了的原因与去处、给谁用、什么时候用和不用、声明的工具、附带文件、正文开头、打开全文、启用记录、最近使用、管理这个包。能力包另记的（近期次数、升级差异、用在哪）放在下面一道细线之后，不改 08 的那一块 | 就在这里 |
| 提示词 | 默认版／你的版本（基于 vN）／默认已更新；**不显示正文**，写明改写、对比和恢复默认都在「提示词」里、下一轮生效 | 「在提示词里改」「对比新的默认」 |
| 角色 | 在用／停用；**在哪里生效**（如「季度发布」的项目默认、你的默认），写明生效范围和继承由角色设置给出（第 36 批）；声明能用的工具（只是说明，不是授权） | 「去角色」（你写的角色）或「在 Coding 设置里看」（插件声明的） |
| 工具 | 只读／会写（标签，不是开关）、属于哪一种（系统工具、平台网关、子代理、计划步骤）、开放给哪些角色；写明不能在这里开关 | 「去角色」 |
| MCP | **三种「开」分三行**，每行写它是哪一种、自己的状态、在哪里改：① 服务器（开着／已连接／断开了／已删除）② 给外部客户端（开给 2 个：Claude Code、Codex；接进来的服务器写「不适用」）③ 工具可用（28 个里开放 19 个）。写明列目录只读已存的清单，不去连服务器 | 对外接入、Coding 的 MCP 设置、服务连接、能力库（各行自己的去处） |

**用量**一律写清范围（CPK-04）：技能、提示词、角色、MCP 有近期次数时显示一个数字和「近期 N 次」，下面一句写这个数从哪来、为什么不是总数（如「每个提示词只留最近 200 次记录，这里不是总数」）；工具只有「只有最近一次」和标签「次数随第 61 批」；没有记录写「还没有使用记录」。

**版本与升级**：技能写 08 的差异（如「2.0 起正文变了」）；提示词写默认版本和你的版本基于哪一版；角色写修订号或声明版本、新增的标出来；工具写随哪个 SDK 版本、0.38 新增的标出来；MCP 写清单版本和上次读清单的差异（新增绿标签、移除红标签）。C 的来源详情另有整个来源的升级差异。

### 状态色调

沿第 08 批定的表：在用（技能的自动和仅手动、提示词的默认和你的版本、角色在用、MCP 已连接或对外开着）`idle`／`ready`；关、停用 `quiet`／`paused`；能就地修好的用不了（插件停用、没连接、断开了）`hold`／`unavailable`；只剩卸载、重装或重新添加的（已撤销、主人已卸载、已删除）`blocked`／`blocked`。另加一种：提示词「默认已更新」是要你看一眼、不是坏了，用 `attention`／`stale`。工具没有开关，行末是「只读」（中性）或「会写」（黄）标签，不用状态标记，免得读成开关。

### 交互与动效

- 选中另一条时详情从下方轻轻升起（`craft-rise`、`--dur-move`、`--ease-quint`），首次打开和刷新不播；导出菜单、导入面板同样升起；`prefers-reduced-motion` 下都不动。
- 窄屏（列表＋详情部件自己的容器宽度 ≤ 640px）一次一边：点一行进详情，焦点移到详情标题，「全部条目」回到列表并回到那一行（照 08）。
- 宽屏时详情贴在滚动区顶上，列表滚到哪都看得见；详情自己太长时自己滚。
- 技能改三档立即生效，提示里可以撤销（照 08）。
- 菜单 Esc 关上，焦点回到「导出」。
- 按类别：宽于 900px 是分段（带个数），窄了换成选择框，不横向滚动。

| 页 | 建议 | 理由 |
| --- | --- | --- |
| 技能（全局设置 AI 组，第 08 批） | **并进**：08 的整节就是能力包的「技能」类，导航里「技能」换成「能力包」（同一个位置）；旧地址 `/settings/skills` 打开能力包并选中技能类 | 同一个部件、同一份数据，留两处就是两份视图 |

| 角色 | **保留**，能力包列出角色并链过去 | 写、发布、导入是角色自己的编辑；作用范围与继承第 36 批会改成角色设置 |

| Coding 的方法页 | **删**（9-4、9-5），不链 | 旧方法路，spec §8 已定删 |
| Goals 的规划方法库 | **保留**，不并 | Goals 的业务数据，要不要变成技能是产品决定（spec §8 记 BL） |

## 组件板新增（定样后交 D 轨补标本）

| 部件 | 原型里的写法 | 用在 | 为什么要 |
| --- | --- | --- | --- |
| 三种「开」 | `.kp-ons`：一行一种，名称和一句说明、状态标记、去处按钮同一行；窄处去处挪到下一行 | 三个方案的 MCP 详情 | spec §4.3 要求三种「开」分开显示、各写清是哪一种；组件板没有「一个对象的几种状态并排、各带去处」的行 |
| 状态与去处块 | `.kp-now`：浅底（`--surface-soft`）里放状态行（`mw-status-line`）、一句说明和去处按钮 | 三个方案的每条详情 | 「只看、改去别处」是这一页的基本句式，要和下面的事实分开；`mw-alert` 是提醒，分量太重 |
| 用量 | `.kp-usage`：一个数字（只在有近期次数时出现）、一句「近期 N 次 · 最近一次」、下面一句范围说明 | 三个方案的每条详情 | CPK-04 要求写清范围；组件板没有「数字＋口径」的小块 |
| 地点行 | `.kp-places`：纸面容器里一行一个「用在哪」 | 三个方案的详情 | 界面通用规则：文字放进容器 |

### kit 缺的（不是组件板新增）

- `window.mwKit` 没有 `renderEmpty`、`renderInput`、`renderSkeleton`、`renderToast`、`renderRadioGroup`、`renderCollapsible`：原型照 SDK 的同一份标记写，建议 D 轨把它们加进 `kit/build.mjs`。
- `kit.css` 不带组件板页面自己的条目行规则（`catalog-patterns.ts` 的 `ITEM_ROW_STYLES` 与 `.mw-mark`）：`pack.css` 里标 `[kit 缺]` 照原样写了一份，kit 带上以后删掉。

## 要用户定的

1. 选 A、B 还是 C（推荐 A）。
2. 设置页合并（上表）：尤其「提示词」从导航去掉、编辑页只从能力包进。
3. 英文界面名：推荐 **AI kit**（短，和代码 `kit` 对得上，和「能力库」的英文 Capability library 分得开）；备选 Kit、Capability pack（和 Capability library 太像）。
4. 工具次数的字：需求原文是「次数随第 61 批」（原型照写），但界面里出现批次号是内部的说法；建议产品里写「次数稍后提供」，或等第 61 批再加这一行。
