## 9. 用户能感觉到的边界

推广前要心里有数的地方，详细建议见[产品优化建议](产品优化建议.md)：

- 没有签名公证的安装包（路线图 1·F）；只有 macOS 桌面 App（浏览器版可在其他系统前台运行，跨平台桌面不排进本轮）。
- 大多数 AI 功能要先配模型；判断规则要先连判断服务。
- 本机服务没在运行时（没装常驻服务、又关了应用或终端）或电脑休眠时，定时、提醒、Feed 拉取都不执行。
- 邮箱、Google 等账号来源依赖尚未发布的正式 OAuth 客户端。
- 英文界面：项目页与各插件在播种状态下的固定文字、服务端的错误与状态句、Diff 与 Git 里带路径的句子、Git 的上游跟踪句（#1109）已是英文；浏览器默认格式的日期、插件自带的错误文字仍可能是中文；设置里能力列表的动作标题与说明仍是中文（用户 10-23 定暂不实现，见 2.1）；Coding 写给模型的文字有意保持中文。有真实数据的页面没有逐页查过，不要讲成"英文已完整"。
- 没有账户：个人菜单里的"登录"是灰掉的占位，暂未开放（#1000）；个人账号与同步只在 `personal` 分支上，见第 4 节，对外不讲"换电脑接着做"。
- 插件创作台从想法到可用插件还没完整跑通过；升级（BL-377）在防腐收尾之后，没有日期，炼金术士以后并进它，作为场景组装的落地场景。
- 已知体验债：Feed 失败提示露原码、Feed 详情里作者和标签偶尔露出内部写法（BL-096）、首次打开 Feed 详情较慢、窄屏助理面板会盖住确认卡；"今天的工作"把同步来的 Feed 消息也算成个人事件（BL-098）；操作卡跑完后，可撤回的改动只列在侧栏，卡上没有"撤销"（BL-343）；Pages、灵光的多选列表还不能只用键盘选多项（BL-340）；重启后恢复的待审项只能拒绝，界面却仍给"批准这一次"（BL-360）。
