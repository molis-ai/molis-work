# 创作台做的插件怎样安装、升级和恢复（第 47 批定样）

状态：已定（2026-11-21，用户选 C：确认嵌在安装阶段里；第二版同日确认「可以，照这个做」）。产品实现随第 47 批；整页是按情形演的模拟，不连 Home、不调模型、不真的打包或安装，插件「会议签到」和它的数据都是假的（沿[创作台主路径定样](../plugin-studio-main-path/README.md)的例子）。

需求出处：[第 47 批](../../../specs/post-anticorruption-roadmap/reference/batches/47.md)「先定样：范围、权限、安装／升级／恢复」；[创作台升级](../../../specs/plugin-builder-upgrade/spec.md) §3.1「安装」「持续迭代与恢复」、PBU-13～15；[防腐 PG-083](../../../specs/archive/repository-anti-corruption/privileges.md)（创作台做的插件和别的插件同一套机制，只按签名决定安装信任）。

## 为什么要定

第 47 批把创作台做出来的插件搬到和所有插件同一条安装路上：创作台只打一份在这台 Mac 上签了名的安装包，装不装、给哪些权限，由 Molis Work 自己画的确认界面让本人确认——和装别人做的插件是同一个确认。插件页面（包括创作台）不能替人显示、预先勾选或按下这个确认。

所以要定的是：**这个确认出现在哪里、长什么样**。创作台「对话加阶段」的版面已在第 03 批定过，不在这里重选。

## 选定的方案（2026-11-21，用户选 C）

**确认嵌在安装阶段里。** 安装阶段的右边就是一张「安装单」，由 Molis Work 自己画，顶上一条写着「Molis Work 安装确认 · 这一块创作台改不了」。不弹框、不跳转。

用户同时提的要求，第二版已照做：要有设计感，不能像在看文档；压在一屏里，不出现滚动；内容和文案简洁；交互合理。

没选的两个：A 就地弹出确认框（内容多时框里要滚）、B 去 设置 › 插件 确认（来回两次跳转）。

## 安装单长什么样

| 部位 | 放什么 | 怎么动 |
| --- | --- | --- |
| 来源条 | 盾牌与「Molis Work 安装确认」，右边「这一块创作台改不了」 | 不动；是这一块由谁画的唯一标记 |
| 头 | 插件图标、名字、版本（升级时「1.0.0 → 1.1.0」）；三个小标记：谁做的、装到哪、（升级）记录都保留 | 升级时下面多一行「1.1.0 新增：…」 |
| 左栏「一定要用」 | 必需的权限，一项一块，带锁；下面一行后台会做的事 | 不能点 |
| 右栏「你来决定」 | 可选的权限，一项一块，行尾开关；会联网的标「联网」，这一版新要的标「新」 | 整块可点；开了变成强调色描边，第二行从「不开就…」换成开了会怎样；底栏小结跟着变 |
| 底 | 左边小结「必需 2 项 · 可选开了 1/2」，右边「先不装」「同意并安装」 | 点同意后换成三步进度（检查安装包 → 装进项目 → 启动） |
| 结果 | 占安装单自己的位置：状态环、一句话、两个按钮 | 装好：「打开会议签到」「管理权限」；没装上／升级没成功：三步里标出停在哪一步，「回构建去修」「再试一次」 |

每一行只有一行字，放不下就省略，不折行；整张安装单在 1440×900、1024×768 和手机宽度（390×844）下都在一屏里，不滚动。

- **范围**：装进项目还是个人空间，在「方案」阶段就定了，这里只在头上如实写出来（情形「装进个人空间」）。
- **升级**：头上是「1.0.0 → 1.1.0」和「46 条记录都保留」，多要的可选权限标「新」，不开也能升级。
- **要用密钥**（2026-11-21 补，情形「要用密钥」）：包声明了要用密钥时，「一定要用」里多一块「用 1 个密钥…」，点「同意并安装」后安装单先换成一步「填密钥」：密钥名、一句用途、密钥输入框和请求头（默认 Authorization），填了才能按「保存并安装」；值只进这台 Mac 的加密存储，创作台和插件都拿不到原文。这一步原来在创作台自己的同意框里，现在归 Molis Work 画。
- **安装没通过**：什么都没装、数据没动，停在第一步。
- **升级没成功**：自动回到 1.0.0，数据没动，停在第三步。
- **安装文件坏了**：在打开这个插件的地方由 Molis Work 就地说（沿第 25 批定的「就地说明」）：记录还在、权限照原来的，一键「装回 1.0.0」，不再问一遍同意（同一版、同一份已同意的权限）；也可以卸载。
- **装好以后**：改权限、停用、卸载都在 设置 › 插件（沿第 27 批已定的卸载交互）。

旧通道以前装过的创作台插件和它们的数据**不带过来**：不再启动、不再列出、不迁移；创作台里的草稿还在，重新装一次按新方式装上。和 10-30 定的「真实 Home 清空重建、不迁移」一致，不新增迁移代码。

## 建议走一遍

1. 情形「第一次安装」：点开一项可选权限，看那一块和底栏小结的变化；点「同意并安装」，看三步进度和「装好了」。
2. 情形换成「升级到 1.1.0」「安装没通过」「升级没成功」「安装文件坏了」「装进个人空间」，各走一遍。
3. 换 EN、深色，把窗口缩到 1024 和手机宽度（手机上创作台用「对话／阶段」切换）。

## 组件板新增

选定后先在本批分支上补成组件板标本，再写产品界面：

- **安装单**（`.ps`）：来源条、头、两栏、底、结果五个部位的一张卡。
- **权限块**（`.ps-tile`）：彩色图标、名字、一行说明；必需的带锁，可选的整块可点、行尾是 `mw-switch`。图标底色按种类分：存数据蓝、读文件中性、调别的插件绿、联网琥珀、用模型强调色。
- **小标记**（`.ps-chip`）：图标加一句短话的胶囊，用在头上和结果里。
- **三步进度**（`.ps-steps`）：状态环加步骤名，横排，步骤之间一条短线。

其余是组件板已有的：`mw-btn`、`mw-switch`、`mw-badge`、`mw-toast`、`mw-toggle-group`、状态环。

实现上，「插件页面里放一块由外壳画的区域」沿用已有的界面位置机制做成平台能力，任何插件页面都能放这张安装单，不是创作台的私路。

## 模拟的部分

- 安装、升级、恢复都是定时器，每步约半秒；「安装没通过」「升级没成功」第一次必定失败，「再试一次」就成功。
- 创作台只画了标题、阶段条、几句对话和安装阶段；别的阶段不展开。插件自己的页面只画了一张签到名单。设置页不在这份原型里。
- 「回构建去修」「管理权限」「先不装」「卸载」只弹一条提示。
- 状态存在浏览器 localStorage（键 `molis-proto.studio-package-install.v2`），「重来」清掉；`window.protoJump` 只用于截图时直接跳到某个状态。
