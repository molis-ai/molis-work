# 产品优化建议

最近更新：2026-10-18 · 依据 main `5f03d1e45`、全部开放 PR 与远端分支、31 份活跃 spec、BACKLOG、内部官网调研的结论和本目录 research/。

这里记的是写产品介绍、挖场景时发现的缺口与建议，供产品排期参考。**它们是建议，不是立项、承诺或排期。** 每条写"问题 → 建议 → 依赖 → 怎么验证 → 什么结果推翻它"，并标优先级：

- **P0 推广阻断**：不补，对外推广会直接伤到第一批用户。
- **P1 killer 关键**：不补，某个 killer 场景的瓶颈环节过不去（编号对应 [killer 场景](killer场景.md)）。
- **P2 体验与增长**：补了会明显更顺、更容易传播。

处理过的条目在"去向"列写 spec、PR 或"不做"及理由，不删行。

| H9 | Shelf 七个配方里只有"提取文字"在本机；"敏感信息脱敏"本身要把原文发给所选模型，"先脱敏、再交给云端模型"今天不成立 | 加一个本机、不调模型的规则版脱敏（手机号、证件号、邮箱、银行卡、金额、自定义词表），配方面板写明"会发给哪个模型" | D 组链路（LAW、FIN、HR）；`plugins/native/shelf/src/actions.ts` |

| H11 | Gmail 来源不带附件，合同、发票、简历要人存下来再拖进 Shelf | 来源条目带附件，可一键存进项目材料或 Shelf | D 组链路（LAW、FIN、HR） |
| H12 | Dataset 只有文本、数字、日期三种列，没有合计和分组计数 | 加只读的汇总行（合计、计数、按列分组）；精确计算仍交给插件代码 | D 组链路（FIN、FREE）；B 组、C 组的问卷链路 |
| H13 | 判断规则要先连 TypeSafe：9 条链路（GitHub 分拣、反馈筛选、规则监控、爆料邮箱……）卡在这一步 | 评估没连 TypeSafe 时能否用已配模型降级判断，或把"连判断服务"放进首次设置；规则编辑页先说明为什么要连 | [角色链路](角色与使用链路.md#5-链路暴露的产品缺口) |
| H14 | 灵光的转写、读网页和字幕依赖本机原生组件，没构建时显示不可用：13 条链路（访谈、录音、播客、选题）卡在这里 | 随安装包预置并在首次使用时自检，缺失时给一步修复，不让用户看到 `native_unavailable` | 同上 |
| H15 | Form 收回的答卷要先导出 CSV 再导入 Dataset：8 条问卷链路都绕这一步 | "答卷进表格"一键衔接，并保留"同一份答卷只算一次" | 同上；B、C、D 组共性 |
| H16 | PPT 不含图片与图表：7 条汇报链路要回 PowerPoint 补图 | 把 Pages 里的图片、Dataset 的汇总图带进演示稿 | 同上 |
| H17 | Pages 没有用户自建模板，只能在固定版上"从这一版继续"代替 | 允许把一篇文稿存成个人或项目模板 | D 组共性 |

## 五、旧研究里仍然成立的建议

以下来自 [10-17 work-split 审读](research/2026-10-17-work-split审读.md)、[10-18 场景选择](research/2026-10-18-场景选择与验证.md)、[10-18 工作链对照](research/2026-10-18-工作链对照与迁移判断.md)，合并去重后保留：

- 在情境条上把"对象是否已加入当前工作、落点是否仍有效、为什么失效"说清楚，不另建上下文数据库（并入 S1 组）。
- 流程实例回看要能一眼看出哪段是 AI 候选、哪段是人交出的稿（并入 K2、S1）。
- "承诺核对台"作为样例插件：无出处不能标已核、来源变了需重看（并入 C5）。
- 角色多选、可跳过，选完立刻给一件具体任务与交付物（并入 I1）。
- 研究成功不以"看起来不错"计，看用户能否用自己的材料做完原本要做的事、并且下一次还用。
