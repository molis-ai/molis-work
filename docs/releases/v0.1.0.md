## 兼容与升级

0.1.0 是新的开发编号，不是旧 GoalBoard v0.1.0、v0.2.0 或开发机 0.3.0 Home 的自动升级或数据降级路径。现行各库与带版本文件以[检查清单第 3 节](CHECKLIST.md#3-各库版本表)为准；不能只把旧文件的版本数字改成 1，不能用新构建直接打开待搬开的旧 Home。

真实 Home 按[检查清单第 4 节](CHECKLIST.md#4-真实-home搬开后干净重建)执行：先验证旧安装、原密钥与完整备份可恢复，再在用户在场的维护窗口停写、搬开旧 Home、干净重建。装过 0.3.0 的开发机须在该窗口手动重装经过验证的 0.1.0 构建，不能靠桌面端的常规版本检测完成降版。旧助理轮次按 BL-937 不导入，新项目、连接、授权、重启与回退分别留实操证据。

内置插件沿现有宿主构建跟随规则运行；版本跟随不提供旧私有数据的格式转换。独立安装的插件继续按其发布者、版本与授权规则处理。本次源码复位不登记存储升级链的真实 Home 统一起点，也不启动首次外部安装后的读取兼容阶段。

MCP、Runtime 和 Skill 应来自同一构建；已经运行的旧会话不会动态加载新工具。固定动作引用和工具名须按当前目录核对，详见 CHANGELOG 的第 02 批升级须知。

若分发 npm 归档，飞书/Lark 连接器沿用用户 2026-10-10 接受的两项约束，详见[安装说明](../installation.md)的「npm 路径上的飞书/Lark 连接器」和[检查清单第 2 节](CHECKLIST.md#2-验证)：

- npm 归档安装所解析的 `basic-ftp` 是带高危公告 GHSA-c475-qrg2-pj4r 的 5.x；只有用户把代理配成指向 FTP 上的 PAC 文件时才会走到这条路径。工作区的依赖覆盖不随 npm 归档安装生效。
- `keytar` 的安装脚本需要联网获取预构建包，或依赖本机编译工具链。按安装说明中已登记的代码检查（尚未在构建出 `keytar` 的机器上实测），装好后连接器每次启动读取钥匙串服务名 `lark-mcp`、账户名 `encryption-key` 的条目，没有时生成并写入，并创建 `lark-mcp-nodejs` 数据目录；这些状态在 Molis Work Home 之外。其日志目录 `~/Library/Logs/lark-mcp-nodejs/` 同样在 Home 外，且不限于 npm 安装路径。

实际发布 npm 归档前，仍须按检查清单核实固定上游版本、依赖解析与打包策略是否保持已接受的前提；本次源码版本复位未重新核验上游发布状态。
