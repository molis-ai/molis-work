## 给人讲清楚

这一批把记忆系统升级成**「懂上下文、空闲时自动回头纠错整理、又不打扰你、不破缓存」**。鉴于现役记忆核心服务文件已经长到了 106 KB（3000 多行），按你拍板的方案分 **3 个清晰的有序 PR** 稳步交付：

1. **先给巨型代码搬家理清结构（`63A-0` 纯重构先行，`111` 后即可开工）**：不改任何功能表现，先把 106 KB 的 `MemoryService` 按四块职责拆清（顺手给 76 KB 的记忆设置页文件做局部瘦身，并清掉 P1 残余债），让后面的改动干干净净、一眼能审。
2. **让「记下什么」更聪明（`63A-1` 形成质量与情景记忆，无需再改上游 SDK）**：平时聊天不用特意说「记住」也能判断什么值得记；能结合前文看懂「以后按第二种写」指什么；分清「只是这周临时改一下」与「以后长期都改」，并修掉以前因为去掉标点把「金额 > 1000」和「金额 < 1000」当成同一句话合并的乌龙。
3. **空闲时自动回顾整理（Dreaming）、按需查以前原话与静态常驻层（`63A-2`）**：
   - 当你纠正过 AI、退回返工过或有了新验证结果，后台在空闲时按每天极低预算自动对照当时的原话补漏、纠错、合并和自然衰减；默认只在记忆设置里留一行简短摘要，绝不在聊天或通知里弹窗打断你；
   - **严守人工优先与分区隔离红线（2026-11-25 拍板）**：Dreaming 后台只许自动修改/合并/衰减「AI 自己自动记下的条目」；凡是你亲手写、亲手点头确认过的记忆，以及涉及「升入常驻层」或「把某个项目/个人空间的局部习惯升级为全局习惯」，Dreaming 一律只生成带原话依据的待审建议放进候选箱等你点头，绝不擅自自动覆盖；
   - 助理和 Coding 需要时可按权限查以前对话的原话摘录（供下一批 `64` 历史搜索直接复用）；少量确认过的高频称呼和核心习惯只在新建会话或压缩节点冻进最前面的静态缓存区（防中途破缓存），并用 `63-2` 的记忆标准考题跑完三组前后对比，把得分写进「设置 › 评测」后台的实验记忆账本。

需要你做的：在 `63A-2` 开工前看一次记忆整理改动依据展示与四种反馈说法的轻量样稿并定下；真实模型对照按红线问你。

- **阶段／类型**：3；横向能力（Memory、Agent Host）
- **需求来源**：[Memory §14、§15][MEM]（验收 `MEM-45～75`）、[主动助理 §5.7][PAST]
- **前置／待决**：三步有序推进——① `63A-0`（巨类拆分纯重构）只等 [`111`](111.md)（统一工作分区，严格按 `R15` 拆清本人级跨区偏好 `null`、个人空间 `"personal"` 与具体项目 `project_id`，守 `S-person-settings-private` 与 `#2250` 精确提供方绑定），Memory P0/P1（`31-2`）与 `44-2`/`44-5` 已合入，**无需等 `62`/`63` 即可先行合入**；② `63A-1`（P2-01 形成质量）等 `63A-0`、[`104-1`](104.md#batch-104-item-1)（宿主文字模型统一调用与观测记账，结清 `BL-b42-followups ①`）与 [`105-3`](105.md#batch-105-item-3)（对话栏「AI 记下的约定」行内编辑/遗忘单主人入口；现役 `memory-extractor.ts` 已持 `existing` 版本与 `replacement` 槽，**无需再改上游 SDK**）；③ `63A-2`（Dreaming、查会话原话与常驻层）等 `63A-1`、[`62-1A`](62.md#batch-62-item-1)（Host 按 `scope` 区间列记忆行，上游 `#144` LRU 已随 `91-2` 入库）与 [`63-2`](63.md#batch-63-item-2)（`MEM-65/75` 冻结样本与「设置 › 评测」实验记忆账本）。§15.9 已定：① 90 天没用的自动条目退出自动召回、仍可显式查与按原文查；③ 常驻层不设硬上限，主动助理 §5.7 的 50～80 行作可调参考值。
- **可并行项**：`63A-0` 与 `62`/`63` 并行；`63A-1`/`63A-2` 与 `64` 中不碰 Memory 的项并行
- **UI 要求**：记忆整理的改动与依据展示、四种反馈（这次不用、纠正长期偏好、拒绝建议、彻底遗忘）沿现有记忆设置与候选／变更入口（及 `105-3` 对话栏行内入口），新增按钮与文案先出轻量样稿确认；**默认精简呈现**（[决定 57](../decisions.md#decision-57) ②）：整理结果默认只在记忆设置一行摘要，点开看逐条依据，不在对话、卡叠或通知里打断人；全程遵循 `#2307` 中 / 英 / 日（`zh`/`en`/`ja`）三语零二元语言分支
- **后台学习的预算、频率与人工优先硬边界**（[决定 57](../decisions.md#decision-57) ② + 2026-11-25 拍板）：
  - **预算与频率**：形成（`63A-1`）一次工作结束最多一次提炼调用（连续几轮合并）加有候选时最多一次批量语义比对（零候选不发比对）；整理（`63A-2`）只在有「待整理」且宿主空闲时跑，每个范围（本人级 `null`、个人空间 `"personal"`、每个项目）每天最多一轮，初始每轮上限 50 条、当天宿主文字模型用量的 5%，到上限即停留待下一轮、连续失败不重试；记忆设置可一键彻底关掉后台整理；用量统一走 `104-1` / `63-1` 观测记账（`MEM-74`）。
  - **人工优先与分区隔离硬边界（2026-11-25 拍板）**：Dreaming 后台仅可对 `source = auto`（AI 自动形成且未经人工锁定的条目）执行自动合并、修正或半衰期降级；凡属用户手动新增、手动编辑或明确认可过的条目，以及任何「提议进入 P2-05 常驻层」或「跨分区提升适用范围（如单项目／个人空间 → 本人全局 `null`）」，**一律禁止后台自动生效**，只能附原话依据写入待审候选箱等本人决定。
- **粒度**（2026-11-25 拍板拆为 **3 个清晰的有序 PR**）：① **`63A-0`（拆分 106KB `MemoryService` 巨类纯结构重构 PR）**；② **`63A-1`（P2-01 记忆形成质量与情景记忆 PR）**；③ **`63A-2`（Dreaming 空闲整理、按需查会话原话、四种反馈与 Zone 1 静态常驻层 PR）**。

**按下一次任务验 Dreaming。** `63A-1` 留下临时要求与同义／反转边界的形成回执；`63A-2` 接入受范围与许可约束的会话原话查询与常驻层后，按 [`MEM-75` 三组对照](../../../prologue-memory-strategy/spec.md#dreaming-comparison)在 `63-2` 标准样本上从相同起点跑三组，比较下一次任务成品质量与后台用量，结果记入「设置 › 评测」的 `improvement_experiments` 实验记忆账本，并把待长期观察项交 [76](76.md)。
