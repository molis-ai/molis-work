# 插件创作工作台：看得见的协作构建（"Manus 时刻"）

2026-09-23。承接 [Prologue 正式接入](../prologue-runtime/spec.md) 与已批准的 [视觉基准图](../../ui/design/approved-comp.png)。目标：用户亲眼看见 Agent 在创造，成果在眼前持续成形，并且可以立刻上手使用。

本轮只改变“构建过程如何发生、如何被看见”，不改变正式插件的运行、发布、版本兼容与数据隔离（这些沿用上一轮的实现与测试）。

## 1. 用户看到的完整过程

1. **表达**：一句话需求，可附上已有的 CSV 或文字资料。资料以原文附在需求后交给主线设计。空画布提供三个起点示例，均只是预填输入框，不会自动生成。
2. **理解中**：左侧显示“正在分析谁会用、怎么用、留下什么结果”，画布显示用户的原话和骨架占位，不伪造页面。
3. **比较方案**：2–3 个方案以缩略图并排，自动选中第一个并在右侧渲染**实际界面**；方案可带 2–4 条示例内容（标为“示例”），让比较有内容。点任一方案即时切换；也可以在输入框里要求组合或补充，主线设计会重新给出方案。
4. **双线构建**：选定后，UI Agent 从**规格板**逐个放入零件，功能 Agent 同时编写数据与行为，完成后逐个接通零件。
5. **随时介入**：可以暂停、继续、停止、撤回；Jev 无法给出合法选择时由用户在候选里挑下一个零件；点画布任一区域即可“指着它”提修改。
6. **检查与交付**：全部接通后由宿主做一次完整性检查，通过才进入“可试用”。试用、发布、独立打开、再编辑沿用既有能力。

## 2. 协作步骤（BuildStep）是唯一的真相源

`BuildDocument.steps` 记录每个可见动作：`agent`（design / ui / behavior / host）、`action`（understand / propose / decide / plan / place / remove / connect / verify）、`status`（queued / active / done / waiting / failed / cancelled）、`target`（零件 id）、`selection`（零件如何被选出）。

- 状态只随真实的文档变更改变。没有计时器推进、没有回放伪装成运行。
- 画布上的蓝色 UI 指针、绿色功能指针、选中框、接通提示、底部规格板高亮，以及左侧“协作现场”，全部由同一份 steps 推导。
- 客户端唯一的本地动画是两个真实状态之间的过渡：零件已经进入文档，先以占位出现，指针抵达后显形（约 720ms，减少动态效果时直接显示）。

| 表达 | 触发条件 |
| --- | --- |
| UI 指针停在规格板上方，思考点 | Jev 选择步骤为 active |
| UI 指针琥珀色“等你选零件”，左侧决定卡 | ui/decide 步骤为 waiting |
| UI 指针移到新零件、蓝色选中框 | place 步骤 done，零件刚进入文档 |
| 功能指针在表单附近思考 | behavior 运行中 |
| 功能指针移到目标零件、绿色虚线提示 | 下一个 queued 的 connect 步骤，且目标零件已在画布上 |
| “✓ 保存已接通”闪现 | 该零件在 `connected` 中由假变真 |
| 左侧红色说明与“继续构建” | 阶段 failed，步骤 failed 并带原因 |

## 3. 规格板 + Jev：可控的零件选择

用户要求：零件选择要可控，不能无限发挥；每放入一个零件后，由 Jev 从规格板给出的可选列表里选择下一个。

- **规格板**（`spec-board.ts`）是唯一的零件来源：标题区、录入入口、记录集合、搜索框、标签筛选、汇总、导入导出。每个零件写明用途、是否必需、何时不可用（例如没有标签字段就不能用标签筛选）。
- **合法候选**由宿主按当前设计和已放入零件计算：标题区永远是唯一的第一个候选；必需零件没放齐之前不提供“完成”。
- **选择者**，逐个记录、从不混报：
  - 候选只有一个：规则选择，理由“唯一合法候选”，不调用模型。
  - Jev 可用：一次有界的 choice 提问，只包含设计摘要与已放入零件，不含任何记录。返回值必须在候选之内；步骤记录模型、候选数、耗时、置信度。
  - Jev 未配置：规格板顺序（先必需，后可选），明确标“规则选择 · Jev 未配置”。
  - 用户：可在决定卡或规格板上点选，标“你选择”。
- **失败与迟到**：Jev 报错或答出候选之外的值时，不放入任何零件，转为等用户决定；“继续构建”会撤回这次请求并重新交给 Jev。暂停、停止或界面已变化后才到的答案不会被采用，步骤记为已取消。
- 宿主侧的 `choose` 端口复用 Functions 的 TypeSafe Provider，构造瞬时 choice 记录，不会写入用户的 Functions 列表。旧的“整页 UI 模型运行”已移除，Agent 角色只剩主线设计和功能 Agent。

## 4. 逐个接通：功能是否可用由服务端决定

- 功能 Agent 在方案确定后立即启动，与 UI 装配并行。
- 行为通过校验后，按“读取 → 保存 → 搜索 → 筛选 → 汇总 → 导入导出”的顺序，每个节拍接通一个已在画布上的零件，写入 `connected`。
- 预览数据接口按操作检查接通状态（读取 / 保存 / 搜索 / 筛选 / 导入导出）。没接通的操作会返回“还在接通中，已输入的内容会保留”，不会假装成功。
- 保存接通后，功能 Agent 用方案里的示例内容走一遍真实保存（同一套字段校验）。未通过校验的示例会被丢弃，不做修补。结果写进步骤，画布出现真实的预览记录。
- 全部接通后由宿主检查：重新解析设计、零件、行为，读出全部预览记录并完成计算，且确认没有漏接的零件。通过后才进入“可试用”，失败会停在失败状态并说明原因。
- 旧草稿没有 `connected` 字段时，有行为就视为全部接通（兼容上一轮的数据）。

## 5. 指着画布提修改（revise）

- 构建模式下点任一零件：出现选中框和检查器，输入框上方出现“指向 · 某零件”。发送的修改带上该零件。
- 主线设计以 `mode: "revise"` 接收当前设计、已放入零件和目标零件，返回一份完整的修订设计（保持字段 id 与类型）。
- 宿主计算差异，写成“修订主线设计”步骤：名称、布局、字段增删改名、计算、导入导出、展示方式。
- 保留已经成立的部分：只影响外观时，零件、接通状态和记录全部保留，受影响的零件记一条“调整 X”，指针会移过去。字段或计算变化时，行为作废，由功能 Agent 重写并重新接通。新字段让可选零件变得合法时，交还给选择者决定是否加入。不再合法的零件会被移除，并有记录。
- 每次修改前都会保存快照，“撤回”可以恢复设计、零件、行为和接通状态。

## 6. 直接操作：选中、拖动、编辑

- 悬停零件出现轮廓，点击后打开检查器，显示零件名、是否已接通、显示文字，以及“对这里提修改”。
- 构建停下来后（没有运行中的 Agent，也没在装配），零件可以在所在区域内拖动排序：页头、查询行、内容区。落点处出现蓝色插入线。服务端只接受同一区域内的移动，跨区域的交换或拖放一律拒绝。
- 装配过程中，规格板上尚未放入的合法零件可以直接拖到画布上放入，也可以点击，效果与决定卡相同，记为“你选择”。
- 以上改动都会先保存快照，可以撤回。

## 7. 本地预览与验证方式

- `pnpm exec tsx scripts/preview-plugin-builder.mts --port 4205 --fixture`：真实 PluginPlatform、SQLite 和 HTTP 路由；Prologue 与 Jev 由**标明为替身**的固定输出代替（模型名写明“预览替身 · 固定输出，非真实模型”“fixture-jev（预览替身）”）。
- 加 `--fixture-jev-miss N` 可以让第 N 次 Jev 回答落在候选之外，用来检查“交给用户决定”的状态。
- `.claude/launch.json` 中的 `plugin-builder-preview` 与 `plugin-builder-preview-jev-miss` 对应上述两种启动方式。

## 9. 真实模型验证 · 2026-09-24

在用户配置好的环境里（MiniMax · MiniMax-M3，经 Prologue；Jev = TypeSafe jev-1.13.0；用户"测试"项目、工作区 goalboard），通过另起的本地服务（端口 4207，使用真实数据目录）实跑。

**读书清单**：
1. 需求 → 两轮澄清（评分分制、状态取值、"今年"如何表达）→ 3 个方案。
2. 选卡片方案 → Jev 依次选记录集合、录入入口、导入导出、标签筛选、完成装配（每次 3–6 个候选，439–1259ms）→ 功能 Agent 接通 4 项操作，并用示例内容试跑保存 → 完整性检查通过。
3. 这一轮暴露汇总没有被放入，于是规格板改为：设计里有计算时，汇总为必需零件。

**库存小账本**：
1. 需求 → 一轮澄清 → 6 秒给出 2 个方案。
2. 选表格方案 → 功能 Agent 第一次写的行为没通过校验，自动修正一轮后通过。
3. Jev 依次选录入入口、记录表格、导入导出、标签筛选、汇总、完成装配 → 完整性检查通过。
4. 试用里新增"测试马克杯 4 × 12.5"，库存价值 50，总库存价值更新为 4971.5。
5. 指着汇总说"只合计数量和库存价值，去掉计入总额标记"：主线设计删掉那项计算并声明合计项，功能 Agent 重写行为并重新接通。4 条记录全部保留，汇总只剩数量和库存价值（[截图](screenshots/real-inventory-revised.png)）。

真实模型暴露的问题及对应改进（每项都有测试）：

| 现象 | 处理 |
| --- | --- |
| MiniMax 在回答前输出 `<think>` 推理段 | 解析前剥掉推理段 |
| 深层嵌套的长 JSON 经常括号配错，偶尔截断 | 方案改为紧凑格式：共享的 base 与 samples 只写一次，每个方案只写差异，由宿主展开后严格校验；计算可以写成一行公式（受控语法，只生成原有表达式树，不执行代码）；单轮输出预算提高到 32000 |
| 模型答案被校验拒绝后直接失败 | 把拒绝原因和原答案交还同一角色修正，最多连续两轮，每轮在协作记录里可见；失败详情带上回答开头、结尾、输出 token 数和语法出错位置 |
| 展示提示指向类型不合适的字段 | 模型方案里不合适的展示提示被丢弃并记录，不改指向；已保存和发布的设计仍然严格校验 |
| 澄清问题一轮接一轮 | 回答后结束该轮问题；最多澄清一轮，之后必须给方案，并在说明里写明假设 |
| 统计"已读 / 今年已读"写不出来 | 表达式新增 `contains`、`and`、`or` |
| 汇总把单价也加总 | 设计可声明 `totals`，只合计有意义的数字 |
| 失败后没有重试入口 | 设计阶段失败也能"重新理解需求" |

仍为 `UNVERIFIED`：

- 真实模型只验证了 MiniMax-M3 这一个模型、两个场景，没做质量和延迟的统计。真实环境里的发布和独立打开没有在用户项目里实跑，以免在用户数据里产生插件实例；这条链路由浏览器端到端测试覆盖（真实 HTTP、PluginPlatform、SQLite）。
- 附件只支持文字与 CSV。参考图片不在支持范围内：`AgentStartRequest` 只有 `task` 和 `text_materials` 两种文字输入，图片送不到模型，所以界面上没有提供图片入口。要支持参考图，需要先给 Agent Host 加上图片输入。
- 中文输入法候选窗、主观手感与审美、最终用户验收。
