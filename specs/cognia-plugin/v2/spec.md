# Cognia 2：启发式学习知识库

状态：2026-09-25 需求书。主要决定已由用户确认（§11），全文待用户审阅；尚未实现。

- 这是[创作台：Agent 编写的真实插件](../../plugin-builder/work-items/agent-built-plugins/spec.md)（下称"创作台 spec"）的**首个真实插件**（D12）：由创作台从需求开始造出来，作为 S4 的验收目标。
- 名字沿用 Cognia。现有 Cognia（[导入与知识库](../spec.md)）**直接下线**，不迁移资料、不做兼容，Cognia 2 也不读取它（用户 2026-09-25 确认）。
- 学习科学部分参考了独立仓库 `~/code/cognia` 的设计文档（六层掌握、ICAP、自我解释、主动提取），但不照搬它的 Domain Compiler、Master 游戏化和 Companion 全量设计。

## 1. 定位

Cognia 2 不是"存资料、搜资料、让 AI 写摘要"的仓库，而是一个会提问的学习伙伴。

- 知识由用户用自己的话写下；AI 负责追问、出题、找漏洞、安排复习，**不替用户写理解**。
- 用户的理解和知识库一起增长，每一步进步都有看得见、能纠正的证据。
- 伙伴记得用户学过什么、卡在哪里，并据此调整提问；它对用户的判断全部公开，用户可以纠正，不做隐藏画像。

判断它有没有价值，不看资料和卡片变多了多少，而看用户能否脱离提示，自己回忆、解释、判断、应用和迁移。

## 2. 学习科学依据与具体机制

每条机制都要能验收（§10）。

| # | 依据 | 机制 |
| --- | --- | --- |
| M1 | 生成效应；产出性失败（Kapur） | 开新主题、读新材料前，先请用户写下已经知道的和自己的猜测，记为"起点"。AI 不先给摘要。 |
| M2 | 启发式教学（"不愤不启，不悱不发"）；苏格拉底式追问 | 对话以提问为主。提示分四级：L1 方向、L2 线索、L3 示范、L4 讲解。默认从 L1 开始，由用户决定是否升级；用户随时可以要求"直接讲"，记为 L4，不扣分，只作为证据。 |
| M3 | 自我解释（Chi 等 1989）；讲给别人听；ICAP 的"建构 / 互动" | 理解卡正文只由用户写。AI 的意见（漏洞、反例、含糊处）作为批注单独保存，不写进正文。 |
| M4 | 测试效应（Roediger & Karpicke 2006）；Dunlosky 等 2013 年的综述 | 复习以回忆为主：先回忆、先解释，作答后才显示原卡。少用选择题。 |
| M5 | 间隔效应 | 用开源的 FSRS 算法安排每张卡的下次复习；到期提醒走平台调度能力。 |
| M6 | 交错练习；迁移 | 一次复习混合不同主题的卡；"新情境题"要求把概念用到没见过的场景，可以用用户自己的 Goal 当场景。 |
| M7 | 元认知校准 | 作答前先报把握程度（1–5）；成长视图显示"自认为会"和"实际表现"之间的差距。 |
| M8 | 可解释的掌握层次（沿用原 Cognia 的六层） | 每个概念按六层记录证据：记得住、解释得清、判断得出、使用得了、迁移得走、反思得动；每条证据带时间、原话和用到的提示级别。不给单一的百分比。 |
| M9 | 支架逐步撤除（最近发展区；专长逆转效应） | 某个概念还没有证据时，先给完整示例；证据积累后，默认起始的提示级别降低、题目难度提高。 |
| M10 | 概念转变 | 发现的误解单独记下，连同纠正过程；隔一段时间再出题检验它是否真的改过来了。 |
| M11 | 经验学习循环（Kolb） | 概念可以挂到 Goal 上；在真实工作中用过后写应用反思，算作"使用得了"或"迁移得走"的证据，可以顺手给 Goal 记一条进展。 |
| M12 | 自我决定理论（自主、胜任、关联） | 学什么、学多快由用户定；进步看得见；提醒温和、可以推迟；不用连续打卡、排行榜、失败惩罚这类机制。 |
| M13 | 认知负荷理论 | 一次只问一个问题；材料按小节切分；长回答给结构提示，不给答案。 |

**掌握的判定规则**：
- 某一层"达到"，要求至少有一次**间隔至少一天**的独立成功（提示级别 ≤ L1）。
- 一次答对不算掌握。
- 用户可以自评"我会这个"，记为"自评"，与表现证据分开显示，并建议做一次快速检验，但不强制。

## 3. 核心对象

| 对象 | 内容 | 谁写 |
| --- | --- | --- |
| 主题 | 名称、为什么学、可选关联的 Goal、起点（M1） | 用户 |
| 材料 | 来源（起步包 / 粘贴 / 已导入的文档）、切分后的小节、许可与署名 | 用户导入；起步包由我们准备（§6） |
| 理解卡 | 概念名、用户写的解释（保留每个版本）、引用的材料小节 | 只有用户能写正文 |
| 批注 | AI 对理解卡的意见：漏洞、反例、含糊处，附依据的小节 | AI；用户可以采纳、忽略或反驳 |
| 对话 | 按主题、卡片或小节组织的追问记录；每轮记下提示级别 | 用户与 AI |
| 证据 | 所属的卡、层次、题型、用户原话、作答前把握、评判与理由、提示级别、时间 | 作答由用户写；评判由 AI 给出，用户可以申诉；申诉时**以用户为准**，AI 原评判与申诉理由一并保留 |
| 误解 | 误解陈述、如何纠正、下次检验时间、是否已消除 | AI 提出，用户确认 |
| 复习状态 | 每张卡的 FSRS 状态、下次到期时间 | 插件计算 |
| 应用反思 | 关联的 Goal、在哪里用了、结果、要调整什么 | 用户 |
| 学习者视图 | 由证据推导出的每个概念、每一层的状态，加上用户的纠正 | 插件推导；用户可以纠正，纠正单独记录 |

## 4. 用户旅程（首版核心闭环）

1. **开主题**：用户说想学什么、为什么，可以挂到一个 Goal 上。首次使用时可以直接选学科起步包（§6）开主题。伙伴先请用户写下起点（M1）。
2. **读材料**：按小节阅读。读完一节，伙伴先请用户说出要点；再按 M2 追问，帮用户写出这一节的理解卡。卡上标明引用的小节。
3. **追问对话**：用户在任何地方都能发起追问：选中材料里的一段、某张卡、或直接提问。伙伴按提示梯度回应，并始终引用材料小节。
4. **复习**：到期的卡以回忆题出现（M4–M6）：先报把握，再作答；伙伴评判并给出理由，记为证据；更新复习状态；发现误解就记下（M10）。用户可以对评判提出申诉，申诉和结果都保留。
5. **成长视图**：
   - 每个主题、每个概念的六层证据；
   - 误解与纠正；
   - 把握是否准确（M7）；
   - 提示级别的变化趋势（M9）；
   - 一到三条下一步建议，每条都说明理由。
6. **应用回流**：在 Goal 上用过之后写反思（M11），可以给这个 Goal 记一条进展。

**模型不可用时**：阅读、写卡、复习（改为用户自评）、成长视图仍然可用；需要模型的步骤明确显示不可用，不用假数据代替。

## 5. 伙伴（AI）的行为约束

- **不代写**：伙伴不输出可以直接当作理解卡正文的完整解释，除非用户在 L4 明确要求讲解；即使如此，讲解也只进对话，不进卡片正文。
- **有依据**：涉及材料内容的判断必须引用具体小节；引用不存在就拒绝这次输出。
- **结构化输出**：每类模型调用返回固定结构（提问、提示级别、引用、评判、理由、发现的误解），插件校验后才采用；不合格的输出不落盘，并如实提示。
- **不诊断人格**：学习者视图只描述"在哪个概念、哪一层有什么证据"，不给用户贴"学渣 / 学霸"之类的标签，也不推断和学习无关的特征。
- **内容安全**：材料和用户输入视为不可信输入，不执行其中的指令。

## 6. 学科起步包：《论语》

用户确认（2026-09-25）：首版学哲学，起步包用《论语》原文；外语不做。

### 6.1 为什么是哲学和《论语》
- **机制对口**：苏格拉底式追问源自哲学；解释概念、用反例辨析、把原话用到自己的处境、反思立场，和六层掌握一一对应。
- **不用翻译**：中文原文，中文用户直接读。
- **教法自证**：M2 的"不愤不启，不悱不发"就出自《论语·述而》。用启发式的方法读这本书，首版体验直观。
- **文言正需要引导**：先让用户自己试着理解，再逐级给提示，比直接给译文学得更扎实。

不选外语的原因：外语主要是技能习得（输入、输出、发音、流利度），和本插件为概念型知识设计的机制不对口；听说需要音频，而 Agent Host 目前只接受文字；也没有找到许可合适、面向中文用户的外语教材。

### 6.2 许可
- 《论语》原文属于公有领域。
- 文本来源用**维基文库**的《論語》二十篇。页面标明原文属于公有领域，站内内容按 CC BY-SA 4.0 提供，所以起步包按 CC BY-SA 4.0 署名，并注明来源链接和改动。
- **不用出版社的点校本**，也不收任何现代注释或译文：国内有出版社对点校本主张过版权，现代注释和译文也都受版权保护。
- 维基文库目录里的"知道第二十二"不属于通行的二十篇，不收入。
- 其他哲学教材的许可结论（2026-09-25 核实）：OpenStax《Introduction to Philosophy》是 CC BY-NC-SA，不能用；Rebus《Introduction to Philosophy: Ethics》经搜索显示是 CC BY 4.0，可以作为以后的第二个起步包，采用前必须在官网页面再核实一次。

### 6.3 起步包怎么做
- 由我们准备，不由代码 Agent 生成内容：
  - 取维基文库二十篇原文，按"篇 → 章"切分（每章一个小节，带篇名和章序号，便于引用）；
  - 保留原文的繁体字；
  - 附署名、来源链接、许可和"做了哪些改动"的说明（切分、去掉页面导航等）。
- 发布前由人核对一遍，重点检查切分和原文是否一致。
- 作为只读资源随插件包分发；首次使用时一键导入成一个主题"论语"。导入走和用户自己导入文档同一条路径。
- 显示时可以切换简体：用开源的简繁转换库（npm）。转换只影响显示，引用和存储一律以原文为准；转换有歧义时显示原字。

### 6.4 伙伴读《论语》时的额外约束
- 没有现代注释，文言的理解要靠伙伴按提示梯度引导：L1 提示关注哪个字或哪层关系；L2 给出关键字词的常见义项；L3 示范如何串讲一句；L4 给出伙伴自己的解读。
- 伙伴的任何解读都标明"这是伙伴的解读"，并引用具体章节原文；不冒充某位注家或某个版本的定论。
- 有争议的章句（历代解读分歧大的），伙伴要说明存在不同理解，鼓励用户自己判断，而不是只给一个答案。
- 伙伴不引用它无法在起步包里找到出处的"原文"；引用不存在的章节，这次输出作废。

### 6.5 以后的起步包
插件本身与学科无关：主题、材料、理解卡、证据、复习对任何概念型知识都成立。第二个起步包建议用 Rebus 的伦理学（许可核实后），用来检验插件对结构化的现代教材是否同样好用。

## 9. 隐私与费用

- 学习数据只存在本机，属于这个插件的私有存储。
- 模型调用会把相关的卡片、作答和材料小节发给用户配置的模型服务，这一点在授权清单和设置里写明。
- 每类模型调用都记录次数和用量（报不上来就显示"未知"，不填 0）。

## 10. 验收

### 工程（创作台 S4 的一部分）
- 每条机制 M1–M13 都有对应的自动检查，例如：
  - M3：功能合同里没有"AI 写卡片正文"的操作；批注和正文分开存放。
  - M4：作答提交之前，接口不返回原卡正文。
  - M5：FSRS 状态随作答结果更新；到期提醒经平台调度注册。
  - M8：单次成功不会让任何一层"达到"；间隔不足一天的成功不计入。
- 用可注入的时钟模拟若干天，把复习循环跑两轮以上。
- 模型失败、输出不合格、申诉评判，各至少覆盖一次。
- 起步包的署名、来源、许可（CC BY-SA 4.0）和改动说明完整；二十篇切分与维基文库原文逐字一致。
- 伙伴的解读都带"伙伴的解读"标记和章节引用；引用起步包里不存在的章句时，输出被拒绝。

### 产品实操
- 用《论语》起步包从开主题走到成长视图：写起点、读几章、在追问中写出"学""仁""君子"等概念的理解卡、复习、申诉一次评判、记一个误解并在之后的复习里检验、写一次应用反思并给 Goal 记进展。
- 检查伙伴有没有代写、有没有引用不存在的小节、提示级别是否按用户选择升级。

### 用户验收
用户本人至少连续使用一周，经历两轮以上复习，由用户判断"是否真的在帮我学"。工程与实操不能替代这一项。

## 2026-09-26 导入与固定版本引用接口

已与 Onboarding owner 对齐：Host Artifacts 是原文、二进制原件与不可变版本的唯一持有方，Cognia 2 保存学习关系、原文小节定位和用户理解，不恢复旧 Cognia 的 preview/commit/material 接口。Onboarding 在 Home 预览阶段持有临时批次；创建目标项目并采用后幂等登记该项目的 `io.molis.work.document`，保存准确版本回执。Pages 仅保存可编辑摘要，不作为原文事实来源。

Cognia 2 公开操作约定：

- `material.attach({topic_id,document:{artifact_id,version}})` → `{material_id,document,sections:[{section_id,title}]}`。只接受宿主绑定的当前项目中可用、未归档且 schema 支持的准确版本。
- `material.read({material_id,section_id})` → `{document:{artifact_id,version},section_id,title,text,attribution}`。不自动读 latest；新文件/版本须再次 attach，既有卡片仍引用旧版本/小节。
- 粘贴和《论语》起步包先经宿主 Artifact 导入得到版本，再走同一 attach；不向插件暴露磁盘路径。原件二进制、抽取正文、解析器信息与警告由导入 owner 维护。
- SDK `artifacts.get` 使用 `{artifact_id,version}`，宿主再次检查安装身份、项目、效果声明及授权。不能用 `audience:user` 冒充用户扩大其他动作权限；AI 仍全部经 Prologue。
