## 1. 背景

来源：MISC「T-302 二审 登记」（#1605，评论 6530917115，BL-694 放开前必须做）。`apps/local-host/src/integration-declarations.ts` 约 :43-52 的 `assertFree(manifest)` 只查 `service_id`（连接服务）和 `integration_id`（集成）有没有被别的插件占着；`document_import` 集成里的 `document_source`（如 `notion`，由 `packages/plugin-sdk/src/integration-declarations.ts` 校验形状）没有唯一性检查。T-302（#1605，在合入路上）把文档导入的来源表改成读 Home 登记表，`documentImports(home)` 用 `Object.fromEntries(...listIntegrations("document_import").map(entry => [entry.declaration.document_source, …]))` 建表——两个声明用同一个 `document_source` 时，后声明的会静默盖掉先声明的（包括内置的 `notion` 等）。今天到不了：沙箱包的 `document_import` 被 `sandbox-package.ts:144` 拒收，所以生产里只有内置四个来源；BL-694 放开后就能到。行号以 `origin/main` 为准，开工先核。

## 2. 目标

先在 #1332 贴【方案】（乙档，写到函数级）。
1. `IntegrationDeclarations.assertFree` 里对 `kind === "document_import"` 的集成，若 `document_source` 已被**另一个插件**声明（遍历已登记的 `this.integrations`），照现有 `conflict("集成", …)` 的写法抛 `integration_declaration_conflict`，文字写“文档来源 X 已由 Y 声明”（沿用 `conflict(...)` 的参数，不新造错误类）。同一个插件重复声明自己的来源不算冲突（与 `integration_id` 的判断一致）。
2. 同一个 Manifest 里两个集成写同一个 `document_source`，也在 `assertFree` 拒绝（先看 SDK 的解析是否已拦；已拦就不重复，写进【方案】）。
3. 用例（放进 `tests/integration-registry.test.ts`，沿用该文件的 `manifestOf`、`registry.attach` 夹具）：RAC-2447 另一个包声明与已登记来源同名的 `document_source` → `assertFree` 与 `attach` 都以 `plugin.declaration_invalid` 或现行的冲突码拒绝（以 `integration_declaration_conflict` 在代码里的实际 code 为准），拒绝后原来源仍在 `listIntegrations("document_import")` 里、`documentImports` 对应项不变；RAC-2448 同一插件再次 `declare` 自己的来源不报冲突，且 `release` 之后来源可被别的包声明。先对旧源码证明 RAC-2447 红；变异：去掉新加的检查 → 红。
