## 1. 结论先说

**定位：Molis Work 是你用的那些 AI 之下共用的一层工作台。** 用哪家 AI 都行；目标和资料放在同一处，"做到哪、等你什么、算不算完、依据是什么、AI 能动什么"也都在这里查。

这个定位来自外部补研的判断：Claude、ChatGPT、Cursor、Notion 已经把"项目 + 记忆 + 定时 + 连接器 + 审批提示"打包进订阅，**和它们比谁更会干活没有胜算**。跨厂商这件事也已经有人在做，而且各有做得好的地方：Notion 3.8 让外部 Agent 经 MCP 读写工作区，管理员看得见、撤得掉；Linear 能把 issue 委派给 Cursor、Codex、Devin 等；Conductor 在一个应用里并行跑几家 Agent，待办没勾完不能合并；Superset 能换一家 Agent 接着做，侧栏显示哪个在等你；Traycer 先让你批规格和评分标准，再逐批评审；仓库里的规格文件加分支保护、CODEOWNERS 和钩子，也能拼出"改规格要人批"。

**开场换成信念以后，killer 场景的角色变了：它们不再是开头，而是开场四句的证据。** 开场说"你的工具长成你的样子、你的 AI 按你的做法做事、要紧的事你说了算、工作接得上"（全文见[产品介绍第 1 节](产品介绍.md#1-口号与开场)）；下表"证明哪一句"一列写每个场景替哪一句作证。打分量的是痛感、契合和成熟度，不随讲法变，所以分数和用途都没有改。

我们查到的方案各缺一环：Notion、Linear 的单位是页面和 issue，我们没查到它们有逐条要求的本人验收、改约定要你批这一层（用审批流、自定义字段可以搭出近似的做法）；Conductor、Superset 的单位是工作区和终端会话，换 Agent 时带过去的是对话；Traycer 以一次任务的规格为单位，任务同步到云；仓库规格那条路要自己配，审批不跟某一条要求的版本绑定。Work 想补的就是这一环：**目标级的要求、本人验收、改约定要人批，并绑定到约定的版本**；存在本机；同一个动作目录给界面、助理和外部 AI 共用；交付时把采用的依据固定到当时的版本（[外部补研 §1、§6](research/2026-10-18-外部补研.md)）。

| --- | --- | --- | --- | --- | --- |

| 愿景 | **K7 一封客户邮件，变成团队的一个目标** | 讨论、决定和 AI 的工作在同一处 | 工作接得上（和别人一起） | 规划 | 团队协作依赖服务端 |

另有三条**支撑场景**，不单独拉新，但每个 killer 的演示里都会用到：**S1 选中就交出去，结果回到原处**；**S2 重复的处理，存成你说了算的流程**；**S3 AI 能动手，但动不了不该动的**。

读者的主线：每条主线都先讲同一段开场，再进场景。开场四句里，"你说了算""接得上"今天就有现在主推的场景作证（K1、K2、K8）；"你的 AI"一句先用 K4 里已经能用的部分作证（项目长期说明已发布 · v0.2.0（源码），提示词设置 main 可用），角色导入标"开发中"，技能包标"规划中 · 示意"；"你的工具"一句由 K3 演，标"开发中 · 示意"。这是新开场最大的风险：最打动人的两句，证据最薄。

按读者：**写代码的人从 K1 进**，接 K3、K4；**写文档、做研究的人从 K2 进**；**管事情的人（项目、交付、自由职业、财务、人事）从 K8 进**；后两条都接 K5、K3，以 K6 收尾。K1 还有一个**约定版**，讲给不写代码、但要对客户或上级交付的人。K7 放在最后，标"开发中"。

K8 和 K1 约定版是这一轮从[角色与使用链路](角色与使用链路.md)的 136 条链路里补出来的：同一种用法在十几个角色身上反复出现，四组起草时也各自把它选成了某个角色的 killer。这两条的依据目前只有链路推断，还没有外部调查，所以痛感都按 3 分记，推之前先验证。

## 2. 怎么挑的

### 打分维度（每项 1–5 分）

| 维度 | 问什么 | 5 分的样子 |
| --- | --- | --- |
| 痛感 P | 这件事多常发生、多疼，有没有外部证据 | 每周都发生，出错有明确代价；有调查数据或大量社区原话 |
| 契合 F | 用到几项 Work 的根本机制，替代方案要拼几样工具 | 至少两项机制叠加；熟练用户要拼三个以上工具、还得手工维护一份账 |
| 起步 T | 不搬家能不能开始，从装好到第一次"啊哈"多远 | 不迁移旧资料，从下一件事开始；十分钟内看到结果 |
| 演示 D | 60 秒能不能演出反差 | 有一个"AI 说……，Work 说……"式的反转 |
| 覆盖 B | 能跨多少角色复用 | 换个对象，五类以上角色都在用同一条链 |
| 传播 S | 产出能不能被分享、复用 | 产出本身是可分发物：插件、流程、技能包、带出处的报告 |

**总分 = 2P + 2F + T + D + B + S**，满分 40。痛感和契合加倍：不疼、或者别人一个工具就做得很好的场景，演得再好也留不住人。

**成熟度单独记，不进总分。** 它分两件事记：

- **最弱一环的成熟度定用途。** 整条链里最弱的一环是已发布或 main 可用，放"现在主推"；是 main 部分或分支，放"开发中演示"（官网可以"开发中 · 示意"全演，同时进产品优先级）；是规划，放"愿景"。可选的步骤不拉低整条链，在卡里单独标出。
- **推之前要补的缺口另列。** 安装包、正式 OAuth、按月重复这类还没做的东西，不改变用途，但决定什么时候能对外推、推给谁。第 1 节的结论表把这两件分成两列。

**淘汰条件**：熟练用户在一个现成工具里已经做得同样顺；价值只是"都在一个地方"，说不出少了哪次搬运、重讲或核对；要先把整个工具栈搬进来才有价值；依赖团队全员同时使用（团队协作上线前）。

**几处打分的理由：**

- **K1 契合给 4，不给 5**：它要的几样，别人已经各有一部分。Conductor 的待办没勾完，工作区就不能合并；Superset 能把一个终端会话换给另一家 Agent 接着做（带最近 36,000 字符），侧栏和 Dock 角标显示哪个 Agent 在等你；Traycer 跑你已有的几家 Agent，先让你批准规格、评分标准和验证方法，执行中产品偏离就停下交回你；仓库规格加分支保护、CODEOWNERS 和 Claude Code 的钩子，能拼出"改规格要指定的人批、没做完不让报完成"。Claude `/goal` 由另一个小模型读对话判定完成，Codex Goals 由 Agent 自己判定，都只看一家一个会话。Work 的差别只剩具体一环：要求、本人验收和改约定的授权落在同一份带版本的目标约定上，几家 AI 读写同一份，约定一改，之前的验收跟着作废。差别是真的，但不足以给"熟练用户要拼三个以上工具"的满分。
- **K1 约定版单独一行**：机制和 K1 相同（契合 4）；自由职业、产品、律师、销售、学术、个人事务六类角色都能用（覆盖 5）。痛感只给 3：依据是本仓库的链路卡，没有外部调查或社区原话。它不单独拉新，用途随 K1。
- **K2 契合只给 3**：带引用回答已经是 Gemini Notebook（原 NotebookLM）、Readwise、Capacities 的标配。Work 能讲的只有"随成果固定当时采用的材料版本，并一路带到演示稿、待办和目标交付物"，不是"有引用"。
- **K3 痛感只给 3**：想要顺手的小工具是真的，但"个人小工具难维护"是社区里最稳定的反对声；所以 K3 的说法必须是"做出来的东西你不用自己养"，而不是"AI 帮你写软件"。
- **K4 起步 5、传播 5**：从 Claude Code、Codex 已有的规则和 Skills 导入，零迁移；做法本身就是可分享的东西。它是最好的**增长入口**，但单独作为用户故事不够有画面，所以不放首屏。
- **K6 契合给 3**：和 K2、K8 用同一把尺。ChatGPT Pulse、Tana 的每日简报、Notion 的定时 Agent、Cowork 的定时任务都在做早报；Work 能讲的只有"底下的事实在本机、每个选项接上真实操作"这一环，而且它还在规划。
- **会议转行动项**：Granola 已经很强，Anthropic 对 120 万条 Cowork 会话的分类里"会议智能"只占 1.8%，Work 也没有会议采集。不投入。这里不做的是**会议采集**；从已有的纪要、邮件里分出"你的承诺"和"在等别人的事"是另一回事，见 K8。
- **K8 痛感给 3，契合给 3**：痛感和"会议转行动项"用同一把尺。K8 的依据只有本仓库链路卡里十几个角色反复出现的用法，是链路推断，没有外部调查；外部补研里项目经理、咨询、小团队的角色痛点也没找到可用的证据。所以先记 3，等第 7 节的对照访谈补上。契合 3：会议工具抽行动项、任务管理器记"等待"、Todoist 从一段话建任务都已经成熟；Work 能讲的是一串连起来的事：和你已有的待办比对，分出"你的承诺"和"在等别人"，每条指回原句，再挂到目标上。覆盖给 5，是因为项目、产品、交付、销售、财务、人事、自由职业、个人事务都用同一条链（[模式 4](角色与使用链路.md#模式-4-你答应的在等别人的分开记)），这一项和痛感分开算。它仍放"现在主推"：成熟度高，起步成本在所有场景里最低（粘一段纪要就能开始），但对外推之前先验证痛感。

## 3. 主推场景

每个场景按同一结构写：一句话 → 给谁 → 触发 → 原来怎么做、卡在哪 → Work 怎么做 → 60 秒演示 → 官网文案 → 为什么是 Work → 成熟度与瓶颈 → 推广与运营抓手 → 怎么验证、什么会推翻它 → 不适合谁。代表链路编号指向[角色与使用链路](角色与使用链路.md)。演示里引号中的文字取自现有界面；界面上没有的说法标"示意"。

### K1 多个 AI，一本账

> **Agent 说做完了，Work 说还差你。**

**给谁：** 同时用两个以上 AI 编码工具的独立开发者、技术负责人、开源维护者。Stack Overflow 2026 年度调查（30,000 多份回复）里，开发者用的 Agent 中 Claude Code 占 66%、Copilot 59%。同一机构 2026 年 4 月的脉冲调查（约 1,100 人）里，约三分之一在工作流里用多个 Agent（17% 用多个专门的 Agent，16% 用相互协调的 Agent），这些人每天用 Agent 的比例更高。注意脉冲调查的"多 Agent"指一个工作流里有几个 Agent，不等于同时用几家工具；"两家都用"的比例，两份来源都没有给。

**代表链路：** [DEV-01](角色链路/A-写代码与技术.md#dev-01-测试全绿了可退款在手机上我还没亲手点过)、[AIDEV-01](角色链路/A-写代码与技术.md#aidev-01-四个-agent-同时在跑我不知道哪个卡在等我)、[AIDEV-02](角色链路/A-写代码与技术.md#aidev-02-周一-claude-code-写到一半周三换-codex-接着做周二我改过接口约定)、[TL-02](角色链路/A-写代码与技术.md#tl-02-冲刺中途范围变了派出去的四个-agent-下次读约定或收尾时都按新范围)、[QA-01](角色链路/A-写代码与技术.md#qa-01-发版前-12-条关键路径开发说好了我要亲手过其中-5-条)、[OSS-01](角色链路/A-写代码与技术.md#oss-01-周六上午清-issue30-条新的里挑出能复现的交给-agent)

**触发：** 周一 Claude Code 写前端，周三换 Codex 接后端；周五 Agent 报"全部通过"，你准备上线。

**原来怎么做、卡在哪：** 仓库里的规格文件、`CLAUDE.md` / `AGENTS.md`、PR 和 CI。`AGENTS.md` 已被二十多家工具共用，项目说明这一层已经能跨厂商；但目标做到哪、哪条要求有依据、谁验收过，仍分散在各家的会话、记忆和"目标"里，换工具或隔几天回来要重讲。Agent 过早宣布完成是公开记录里反复出现的失败模式（Anthropic 的长任务 harness 文章、Claude Code 有报"ALL PASSED"实际 7 个失败的 issue）。几个 Agent 停在不同问题上，你得挨个去问。

**Work 怎么做：**

1. 功能是一个目标：预期结果、几条要求，其中"手机排版"标为**必须由你验收**。
2. Claude Code、Codex 经内置接入或 MCP 读同一份目标。项目长期说明在两处带上：内置助理和插件 Agent 每一轮都带当前版本；外部 AI 经 MCP 读连接摘要时拿到同一份（要先给它授权读项目说明），之后读不读由它自己决定。
3. Agent 往同一份里报进度和依据（写明是 Agent 报告）。
4. Agent 想换掉约好的结果、放宽要求、去掉"要你验收"，要在目标页发起决定请求，自己写明影响；目标页出现"N 项待你确认"，你决定。没有你的决定，这类改动会被拒。
5. 收尾时逐条对：缺依据、缺你的验收、依赖没完、有阻塞顾虑，就不生效，页头写出原因。
6. Agent 发起决定或验收请求时，菜单栏显示"需要你决定"。只标了"要你验收"、但 Agent 没发请求的要求，不会点亮菜单栏，要你打开目标页看。

3. 在稿子里选一段，用"提反例与反驳""读者视角"让助理挑刺；删掉不要的，留下的插到这段后面。
4. 存一版固定成果交给客户；让助理做成演示稿，导出 PPTX；选中还缺证据的句子，记成待办，出处跟着走。
5. 被追问时打开那一版：当时依据了什么，都在。
6. （可选，建议未立项）材料更新后，Work 列出曾采用旧版的结论，由你逐条复核。

**Work 怎么做：** 在插件创作台描述需求 → Agent 先给方案，再写后端代码与测试 → 宿主类型检查、打包、沙箱试跑 → 你授权安装，底栏多一个图标 → 它的操作进同一个动作目录：你在界面里用，助理、工作流程、Claude Code 调的是同一个操作、同一份本机数据 → 改规则出新版本，在用的版本不受影响。

**官网文案：** 表格太散，专门的软件太重。描述一句，Work 把它做成一个插件：有界面、有自己的数据、装在你的电脑上。做出来以后，你在工作台里用，你的助理和 Claude Code 也用同一个操作、同一份记录。

**为什么是 Work：** 对话生成小应用已经是红海：Claude Artifacts 是无后端的单页；ChatGPT Sites 是云端托管的小应用，自带数据库和文件存储；Cursor 有 canvas。Work 的差别不在"有后端"，而在两处：做出来的工具**跑在你本机**，有安装、权限和升级，你不用自己养；它**进同一个动作目录**，界面、你的 AI 和工作流程调的是同一个操作。生态的速度也说明分享前要先想好审核：Obsidian 社区的插件和主题合计 8,000 多个，5 月以来翻了一倍多；Obsidian 在 5 月因为编码 Agent 推高了投稿而改成自动审查，并计划逐步披露插件能动的网络、文件、剪贴板。

**成熟度与瓶颈：** **main 部分**（仍需检查与返修，仅 macOS；2026-10-21 定：插件创作台不迁移，防腐收尾后删除再重做，下面几条瓶颈随重做另议，重做前不新增演示）。瓶颈：生成的插件搜不到、成果库不认、不能当流程一站（C1；10-18 已定所有插件同等待遇，缺的平台能力由防腐线补）；业务数据导出与升级未验（C2）；成功率没有可信口径（C3）；没有可直接改的样例（C5）。

**推广与运营抓手：** 鼓励晒工具（"我用一句话做的报价核对器"）；每个主推角色配 2–3 个样例插件；后续做分享与导入（G3），上线前先设计审核与权限披露（C4）。**激活**：第一个装上、并被 AI 调用过一次的插件。**留存**：第二次改规则后仍在用。

**怎么验证、什么会推翻它：** 四个真实小工具（发版清单、报价前核对、选题库、面试评分表），各跑四周，含一次规则变更、一次失败恢复、一次数据导出。**推翻**：每次都要作者救火；比表格更难查错；升级丢数据。

**不适合：** 一张表就够的事；必须全团队实时共用的业务系统。

### K4 你攒下的做法，换哪个 AI 都在

> **规则和做法写一次，你用的每个 AI 都照着做。**

**给谁：** 已经在 Claude Code、Codex、Cursor 里攒下 `CLAUDE.md`、`AGENTS.md` 和 Skills 的人；想把"我们怎么写需求、怎么审合同、怎么复盘"交给 AI 的小团队负责人。

**代表链路：** [AIDEV-03](角色链路/A-写代码与技术.md#aidev-03-我在-claude-code-里攒的-12-个-skill-和规则想让所有-ai-都按它做)、[TL-05](角色链路/A-写代码与技术.md#tl-05-新人入职把团队的做法装进他的-ai)、[MKT-03](角色链路/B-产品与业务.md#mkt-03-把在-claude-code-里攒的品牌语气审稿skill-带进-work官网文案改动都按它审)、[DEVREL-04](角色链路/A-写代码与技术.md#devrel-04-我写文档claude-code-改示例代码我们改的是同一份说明)、[ACA-06](角色链路/C-研究内容与教育.md#aca-06-分析代码在-claude-code-里写实验记录要和方法笔记放在一处)

**触发：** 第 N 次把同一段规则粘进另一个 AI；社区里常见的抱怨是 `CLAUDE.md` 只在 Claude Code、只在一台机器上有效，而且存得下规则、存不下"为什么"。

**Work 怎么做：** 从 Codex、Claude Code、Cursor、OpenCode、Grok Build 导入规则与 Skills，发布成固定版本的角色，Coding 和助理都能选用（助理要在输入区手动选角色）；项目长期说明（背景、硬约束、质量标准）带版本，内置助理和插件 Agent 每一轮都带当前版本，外部 AI 经 MCP 读连接摘要时拿到同一份；系统和插件的提示词都能看、能改，每一轮记录用的是哪一版。规划中的**技能包**是只有文字的"同事做法"，助理和 Coding 共用，`~~日历`、`~~项目工具`这类占位接到你实际用的服务，不授予任何权限。

**60 秒演示：** 选"从本机导入" → 列出 `~/.claude/skills` 里的五个 Skill，勾三个 → 发布成角色 → 在 Work 助理的输入区选这个角色，说"按我们的发版说明写法写这次的更新" → 切到 Codex，它读连接摘要时拿到的是同一份项目说明。

**为什么是 Work：** `AGENTS.md` 已被二十多家工具共用；Notion 的 Skills API 把 Notion 里的 Skills 同步到 ChatGPT 和 Claude，Readwise 给 Claude Code 和 Codex 发 Skills：大家都在做"做法跨 AI"。Work 的差别是本机、有版本、看得到每一轮用的是哪一版，并且做法不带权限。

**成熟度与瓶颈：** 导入与角色 **main 部分**（导入后 Coding 和助理都能选用；助理侧没有用导入快照的测试；导入的 Skills 只在选了这个角色的那一轮里全文展开，不进助理的方法目录，见 G2）；项目长期说明 **main 可用**；技能包 **规划**；纯内容技能包现在助理看不见（G1）。

**推广与运营抓手：** 这是**增长入口**：从用户已有的 AI 配置零迁移导入；技能包本身可分享。和 K1 一起讲给开发者，和 K2、K5 一起讲给产品与研究角色（"装一个产品经理技能包"）。

**不适合：** 只用一个 AI 且对现有配置满意的人。

### K5 第一天就有内容

> **新项目第一天：把材料丢进来，一分钟读完你现在在做什么。**

**给谁：** 接新客户的顾问和自由职业者、接手项目的产品经理、材料散落一地的创始人。也是**所有新用户**的第一次体验。

**代表链路：** [CON-03](角色链路/C-研究内容与教育.md#con-03-新客户项目第一周一堆附件变成能开工的范围三周后按约定验收交付)、[AIDEV-06](角色链路/A-写代码与技术.md#aidev-06-接手一个陌生仓库想在半小时内让-agent-能可靠地干活)

**触发：** 新客户发来几份旧报告、一堆聊天记录和邮件；周一要开第一次会。

**原来怎么做、卡在哪：** 把文件逐个上传到 ChatGPT Projects、Claude Projects 或 Gemini Notebook，问"帮我总结一下"；得到一段总结，然后还是一个空的待办、一个空的文档、一个不知道项目背景的编码助手。新工具最大的问题是空。

**Work 怎么做：** 新建项目时选来源：本地文件夹、下载和桌面里的文件、浏览器、最近 7 或 30 天的邮件（最多 20 封）、聊天记录导出 → 先预览范围，在本机读取 → AI 分批读完，合成一份一分钟可读完的项目建议：背景、进展、下一步、待确认 → 你改两条、采用 → 一个带内容的项目：项目简介、一份"工作摘要"文稿、每个来源一份文稿、待办草稿。来源可以一项不选直接跳过；本地文件不限个数和大小，长文整篇分段读入，显示进度和"约还要几分钟"；中途离开回来接着读，已读的材料保留（#1030、#1041）。

**60 秒演示：** 拖进一个"客户资料"文件夹和最近 7 天邮件 → 进度"已读 23 份" → 项目建议四段 → 删一条、改一条，"开始" → 待办里多了三条，Pages 里是"{项目名} · 工作摘要"和每个来源的文稿。

**为什么是 Work：** 别处的项目空间要你上传；Work 在本机读你选定的范围，并直接产出后续工作要用的东西：工作摘要、来源文稿、待办草稿，都落在各自的插件里，接着就能用。

**成熟度与瓶颈：** **main 部分**（需模型；真实 Gmail 已在测试应用上验过；10-23 合入的新来源步骤没在打包的桌面 App 里点过）。瓶颈：正式 OAuth 客户端（A3）、首日旅程没有端到端设计（A6）、按角色的模板包（I1）；采用时不写项目长期说明，外部 AI 拿不到这份背景，除非它自己去读那份文稿；刚采用的待办草稿没有日期，不会出现在首页。

**推广与运营抓手：** 它就是新手引导本身。**激活指标**：装好到"第一个带内容的项目"的时间；第一周内回来处理那几条待办的比例。

**不适合：** 材料主要在团队共享盘、需要全员协作编辑的项目。

**代表链路：** [LIFE-02](角色链路/D-专业服务与个人.md#life-02-12-周备考计划ai-拆计划采纳了才算数每天早上告诉我今天学什么)、[OPS-05](角色链路/B-产品与业务.md#ops-05-新渠道冷启动-30-天目标拆好每天早上日历上就是今天要推的事)、[SALES-05](角色链路/B-产品与业务.md#sales-05-每天早上的跟进清单哪些客户该回哪些承诺快到期)、[PMO-02](角色链路/B-产品与业务.md#pmo-02-周五-1700-前的项目周报状态从记录里读出来不靠回忆)

**Work 要做成的样子：** 早上打开，首页是一页会刷新的简报：昨天三个目标里一个完成、一个等你验收、一个卡在客户回复；Feed 里两条和你在写的方案有关；你答应周五交的东西还没开始。底部三个按钮，绑定当前版本："准备周会材料""给客户发提醒草稿""把这两条加进方案"。你点一个，助理按你配置的 Skill 去做。没有实质变化时它保持安静；取不到的数据标"过期"，不编。

**成熟度与瓶颈：** **规划**（proactive-assistant、work-brief，#718 补了状态页与访谈式工作记忆）。先做最小切片：每日一页状态简报（建议 E0）。前置：本机服务不在运行、电脑休眠时不执行，这一点要先说清（A5）；今天的定时对话任务只读项目工作目录里的文件，读不到待办和目标（E1）。

### K8 你答应的、在等别人的，分开记（新）

> **AI 抽了 8 件事，Work 说 3 件你已经记过、1 件在等法务。**

**给谁：** 项目经理和交付协调、产品经理、自由职业者、会计、招聘人事、顾问：每周被会议、邮件和电话推着走，手上同时有"我答应的"和"别人欠我的"。这是链路推断，还没有外部调查支撑，推之前先按下面的"怎么验证"补上。

**代表链路：** [PMO-01](角色链路/B-产品与业务.md#pmo-01-周会纪要一出来你的承诺在等别人的事各进各的待办和日历)、[FIN-02](角色链路/D-专业服务与个人.md#fin-02-谁还欠我什么从客户邮件里理出在等别人的事到了跟进日首页提醒)、[FREE-04](角色链路/D-专业服务与个人.md#free-04-客户电话里临时加了三件事挂电话五分钟内落成待办和一条变更提议)、[TL-04](角色链路/A-写代码与技术.md#tl-04-线上事故后的复盘承诺要落到人和日期上)、[HR-03](角色链路/D-专业服务与个人.md#hr-03-新人下周一入职it行政用人经理各有一件事在等别让人第一天没有电脑)，同类用法见[模式 4](角色与使用链路.md#模式-4-你答应的在等别人的分开记)。

**触发：** 周二跨部门周会，2000 字的纪要里藏着 8 件事：有你答应的，有在等法务的，也有上周已经记过、只是改了日期的。

**原来怎么做、卡在哪：** 飞书妙记、Granola 已经能从会议里抽出行动项；Todoist、Things 管得住清单，Todoist 的 Ramble 还能把随口说的一段话整理成带日期的任务；不少人手动维护一份"等待"清单；让 ChatGPT、Claude 从纪要里列待办也很顺。卡在：抽出来的东西不知道你已经记了什么，重复和改期要自己对；"在等别人的事"没有单独追踪；"下周三"出自哪句话，事后找不到。

**Work 怎么做：**

1. 纪要写在 Pages 里，或把会议工具导出的文字粘进来。邮件经 Gmail 来源进 Inbox 时只有主题和摘要片段；要整理长邮件，先把正文粘进 Pages，或交给助理。
2. 从材料整理出待办：分出"要你处理""你的承诺""在等别人""可考虑的建议"，每条的依据必须是原句。
3. 和已有待办比对：标出可能重复的，建议更新哪条的截止日。
4. 日期由程序换算，不让模型算"下周三"。
5. 你逐条采用、合并或忽略，整批可撤销；等别人的设成"在等"，写清等谁、等什么、哪天跟进。
6. 要动手的定计划日或截止日、挂到对应目标；到了跟进日，首页出现"约定今天跟进"的提醒。催办话术可以让助理起草，由你自己发。

**60 秒演示：**

| 镜头 | 画面 | 字幕 |
| --- | --- | --- |
| 1 | 周会纪要，2000 字 | 会开完了，事藏在字里 |
| 2 | 整理结果：8 条，分成四栏，每条下面是纪要原句 | 你答应的、在等别人的，分开 |
| 3 | 3 条标"可能与已有待办重复"，1 条"建议把截止日从周五改到下周三" | 已经记过的，不再记一遍 |
| 4 | "下周三"变成"10 月 29 日"，旁边是原句 | 日期不靠模型猜 |
| 5 | 到了跟进日，首页出现"法务回复合同 · 约定今天跟进 法务"；你让助理起草一段催办 | 别人欠你的，到日子提醒你 |

**官网文案：** 开完会、读完邮件，事情都藏在字里。Work 把你答应的、在等别人的分开记下，和你已有的待办对一遍，日期换成具体哪天，每一条都能点回原话。等别人的事记着等谁、哪天跟进，到那天首页提醒你。

**为什么是 Work：**

| 熟练替代 | 已经做好的 | Work 的差别 |
| --- | --- | --- |
| 飞书妙记、Granola | 会议转写，抽行动项 | 我们没查到它们会和你已有的待办比对；会议以外的邮件、合同、复盘不归它们管 |
| Todoist、Things、OmniFocus | 清单、提醒、"等待"标签；Todoist 能从一段话或语音建任务（Ramble），自然语言日期解析多年前就有 | 和你已有的待办比对，分出"你的承诺"和"在等别人"，每条保留原句，能挂到目标 |
| ChatGPT、Claude 从一段文字列待办 | 快，理解好 | 每次从零列；日期按模型理解；列完还要搬进待办 |

**成熟度与瓶颈：** **main 可用**（需模型）。瓶颈：痛感没有外部证据；整理出的"可能重复""在等别人"准不准没有评测（建议 J1）；没有按月、按季重复（建议 H10）；待办不记已经等了几天，只有 14 天未更新的标记（J4）；提醒只出现在这台电脑上，关机或服务没开时不送达（A5、I5）；读不到个人微信；邮件来源要正式 OAuth（A3），且只有主题和摘要片段。

**推广与运营抓手：** 入口最短：粘一段纪要就能开始，不用搬任何资料。渠道是项目经理、交付和自由职业者社群，少数派一类的效率作者。**激活**：第一次整理就采用三条以上，至少一条设成"在等"。**留存**：第二周还有"在等"的事被标完成。

**怎么验证、什么会推翻它：** 先验证痛感：找 5 位每周开三次以上会的项目或产品经理、3 位自由职业者，先问他们现在怎么记"别人欠我的"、上一次因为漏跟进出过什么事；再连续两周把纪要和客户邮件交给它。看重复识别准不准、首页的跟进提醒有没有被点开、是否停掉了原来的手抄清单。**推翻**：大多数人说不出漏跟进的代价；去重误报多到要逐条核；他们已经用会议工具接任务管理器的集成且满意。

**不适合：** 会少、事少、记得住的人；主要在个人微信里沟通的人；需要团队共享任务看板的小组（团队协作还没做）。

## 4. 支撑场景

这三条不单独拉新，但几乎每个 killer 的演示都要用到。

**S1 选中就交出去，结果回到原处。** 在稿子里选一句"周五前和编辑对结构"，点"记成待办"，不用再输入，待办带着来源；选中助理回复里的一段，在原位置预览后替换；选中一段修复计划，拆成几条目标步骤（每句一步、最多 6 步，提交成提案，你在 Goals 里确认后才建），Codex 经 MCP 读这条目标时出处跟着走（2026-10-18 改：原稿写"交给 Codex，背景跟着走"，靠的是从目标打开终端，属于 Sessions，清理完成前不演）。按 ⌃⌥W 把当前网页收进 Shelf，在右栏选一段放进左边的稿子。*成熟度：浮条、落点、右栏选段放进左边（含悬停时在左边预示落点，#720 已合）main 部分；"记成待办"点一下就建好、可撤销（#730）；输入框口述 规划（先前的实现没有合入，交互要重新设计）。* 2026 年在文档里让 AI 动手已是标配，S1 的差别在于**跨插件**：一句话能去待办、目标、演示稿、另一个 AI，带着出处。

**S2 重复的处理，存成你说了算的流程。** 每周读三份行业报告写成一页：Feed → AI 整理 → 你看过再交 → Pages → 待办。每一站是一个插件，每段交接是模板、AI 或人；判断规则拦下不该继续的一次；大多数已授权的命令都能当一步（查询不算；外部 MCP 工具当一步还没在真实服务上验过）；每次运行留着当时的链和每段交接的内容。*成熟度：main 可用 / main 部分。* 比起 n8n、Zapier，它的站点就是你自己的文档和待办，人在关键处把关。

**S3 AI 能动手，但动不了不该动的。** 外部 AI 客户端逐个、逐项授权，撤销后下一次调用立即被拒；写文件、跑命令、推送进审查队列；被取消或撤权的调用不再写业务记录，处理器开始前就被拒的只留一行"未执行"的诊断；外部内容标成不可信材料、不进系统提示，降低被里面的话带偏的风险（这是缓解，不是保证；侧栏浏览器的页面、外部 MCP 工具的返回、电脑操作看到的屏幕文字不在这条覆盖内）；电脑操作把银行、支付、密码管理器和系统设置设为禁区，证券、基金按应用名识别，识别不到的可以自己加；灵光里的录音在本机转写。*成熟度：外部 AI 授权与撤权 main 可用；电脑操作 main 部分（总开关默认关；系统的打开、保存面板由你自己完成）；灵光录音转写 main 部分（依赖原生组件）；输入框口述 规划。* OpenClaw 的传播同时伴随大量安全事件（权限过大、提示注入、国内对国企与银行的限制），**本机 Agent 的需求和对失控的担心同时存在**。Work 讲"可控"，要讲到具体拒绝了什么，而不是泛泛说"更安全"。

| 位置 | 写代码的人 | 写文档、管事情的人 |

| 第二组"拼一张自己的工作台" | K3、K4、S2（Feed 里 GitHub issue → 判断 → 目标） | K3（选题库）、S2（每周读报告写成一页）、K4（装一个产品经理技能包） |
| 第三组"和别人一起" | K7（开发中） | K7（开发中） |

## 6. 不做或降级的

| 场景 | 为什么不做 |
| --- | --- |
| 会议采集与转写 | Granola 已很强且已开 MCP；Cowork 用量里只占 1.8%；Work 没有会议采集。更现实的是把 Granola 当上游来源接进来；从已有纪要里分出承诺和等别人的事归 K8 |
| 合同或法律审阅作为一个品类 | 需要行业依据库和责任界定，Work 没有；只靠"数据在本机"撑不起。律师用 K2 的链（每条意见指回自己那一版审查要点，Word 仍是交付标准，见 LAW-01）可以讲，但不做法律依据库 |
| 通用 CRM、团队知识库 | Notion、飞书、成熟 CRM 已覆盖；单机与"每项事实一个主人"不适合做团队知识库 |
| 写文档时"换 AI 轮流写" | 负责人 10-16 决定；调研也没找到这个需求 |
| 每日新闻摘要群发 | Feedly、自动化工具已覆盖；Work 不比谁会群发 |
| "AI 帮你写软件"作为口号 | 维护负担是最强的反对声；改说"做出来的东西你不用自己养" |
| "本机 Agent 能做更多事" | 那是 OpenClaw 的赛道；Work 讲可控 |
