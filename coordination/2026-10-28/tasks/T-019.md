## 1. 背景

`node-pty`（`apps/local-host`、`horizontal/runtime-host` 和根 `package.json` 依赖它，`pnpm-workspace.yaml` 的 `allowBuilds` 放行它的构建）没有 linux-x64 的预编译包，所以 Linux 上每个作业的 `pnpm install --frozen-lockfile` 都会让 node-gyp 现场去 `https://nodejs.org/download/release/v24.14.0/node-v24.14.0-headers.tar.gz` 下载头文件，再编译。正常情况下这一步 12～21 秒（main 的 run 40623292647）。

2026-10-28 04:40Z 起，nodejs.org 的下载反复出问题。最近 60 轮里，这一步失败的 6 轮都在这一小时内，之前一轮也没有：

- 下载被掐断：`gyp ERR! stack TypeError: terminated`（run 40636064866 的 Gates）。
- 卡几分钟后报 `gyp ERR! Completion callback never invoked!`（run 40635208039）。
- 一直挂着不动：T-003 的两个作业挂了 25 分钟，最后经用户同意取消。

受影响的有 T-001 的合并队列、T-003、T-009。ci.yml 里装依赖的作业大多没设 `timeout-minutes`，挂住了要等默认的 6 小时；取消 CI 又要用户本人同意，所以每次挂住都要人来处理。

## 2. 目标

1. CI 上装依赖不再从网络下载 Node 头文件：node-gyp 用 `actions/setup-node` 装好的那份 Node 自带的头文件（`<Node 安装目录>/include/node`）。
2. 装依赖这一步挂住时，几分钟内失败，可以直接重跑失败的作业，不用取消。
3. 以后新加的作业也照这样写，有测试盯住。

## 3. 不做

- 不动 `.github/workflows/release-macos.yml`：那是发版流程，红线；macOS 上 node-pty 有预编译包，也不受影响。
- 不加「失败就自动重试安装」的循环：会把真问题藏起来。
- 不换、不升、不删依赖，不改 `pnpm-workspace.yaml` 的 `allowBuilds`，不改锁文件。
- 不改仓库设置与分支保护，不改哪些检查是必需的。
- 不重排作业结构，也不抽 composite action，只在现有每个装依赖的地方加最少的几行。

## 5. 做法

推荐的做法如下，【方案】里可以反驳，但要说明理由：

- **头文件**：在 `actions/setup-node` 之后、装依赖之前，把 Node 的安装目录写进环境变量 `npm_config_nodedir`，例如一步 `echo "npm_config_nodedir=$(dirname "$(dirname "$(command -v node)")")" >> "$GITHUB_ENV"`；也可以写在装依赖那一步自己的 `env` 里。不要写死 `/opt/hostedtoolcache/...` 的路径。node-gyp 拿到 `nodedir` 就读本地的 `include/node`，不再下载。
- **快速失败**：每个 `Install dependencies` 步骤加 `timeout-minutes`。正常 12～21 秒，建议 5 分钟。【方案】里给出你选的数字和理由。
- **备选**：本地头文件这条路走不通（比如工具缓存里的 Node 不带 `include/node/common.gypi`），备选是用 `actions/cache` 缓存 node-gyp 的下载目录，键里带 Node 版本。走备选要在【方案】里写清楚为什么第一条不行。

【方案】必须回答下面五条，统筹转给用户，**用户批了才改工作流**：

1. 工具缓存里的 Node 24.14.0 带不带 node-gyp 要的头文件。要拿证据，不靠记忆：可以在任务分支上先推一个只加探测步骤的提交，列出 `include/node` 下的文件，看它的 CI 日志；这个探测提交在正式提交里去掉。
2. 你打算在 7 + 1 个装依赖的地方各怎么写，贴出一处完整的改前、改后。
3. `timeout-minutes` 的数字和理由。
4. 哪些现有测试或脚本读这两份工作流（`git grep -ln "ci.yml\|full-suite.yml" -- tests scripts`，现在有 `tests/fixtures/ci-workflow.ts`、`tests/ci-product-subset*.test.ts`、`tests/ci-linux-probe.test.ts`、`scripts/gates/security-invariants.mjs`、`scripts/gates/native-checks.mjs`、`scripts/ci-linux-probe.mjs` 等），改了之后它们会不会受影响。
5. `node scripts/affected-tests.mjs --base origin/main --json` 的 `full` 与原因。
