# Jelly 成为 Molis Work 插件

## 目标和依据

在 Molis Work 内复刻 Jelly 当前已有功能，界面和交互遵循 Molis Work。不能把完整目标默默改成一个日历演示。

原件：`/Users/oreal/adeptify-home/repos/Jelly` 当前 main（含现有本地分类保存修复）。产品入口与 Sources 是功能依据；README 对素材摘要的描述已过时。实现工作树：`codex/jelly-plugin`，从 Molis Work `f25ea17` 创建。

## 使用闭环

1. 在 Jelly 日历快速记事项，分类、优先级、置顶、跨日和每周重复；在日历/列表切换、搜索筛选、移动和完成。
2. 写连续笔记，使用标题、格式、列表、代码和任务；关联事项，将笔记或任务安排到日历；任务完成双向一致。
3. 原样捕捉灵感（文字、链接、文件），提取素材、生成有来源的摘要、转为笔记；保留来源与幂等写回。
4. 从原文“拆解并安排”：先生成可编辑提案，人工选择及调整时间，再一次性写入，重复提交不重复创建；进展回顾可追溯到事项。
5. 分类管理、归档恢复、搜索、导入导出、撤销重做和重启恢复。
6. AI 客户端通过 Molis Work 现有 MCP 对同一套日历事实读写，沿用工具启用和授权机制。

## 实现决定与复杂度审查

- 当前必须：独立 native 个人插件、Molis Work 现有 HTML Slot/设计系统/插件目录/HTTP/MCP 装配、插件私人库、日期及重复语义、关联原子写与版本冲突校验。
- 复用现有导航、主题、按钮、弹窗、Host AI 接口和 SQLite 工具；不另建 App 壳、Runtime、事件总线或网络服务。
- 原 Jelly 仓库与日常数据只读。默认新建 `{home}/jelly/jelly.db`，导入先预览再明确操作，不双写原 App，不自动切换写入方。
- 原生 macOS 的文件授权书签、Vision/PDFKit/OCR/WhisperKit、Foundation Models 不能直接在浏览器兑现，必须在对照矩阵保留并给出真实替代实现/阻塞状态，不能以文本框冒充。
- 不涉及跨设备同步、Watch、团队分派，也不把它们宣称为 Jelly 现成功能。
- 回滚：回到原分支/构建；插件私人库与原 Jelly 数据均保留。此次不提交、推送、发布或替换日常 App。
