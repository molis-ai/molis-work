# Session 工作记录重设计

> 归档（2026-10-01，合入后梳理）：判定为**已实现**。Sessions 收进 work 插件（plugins/native/work/src/ui），工作目录后又移入项目设置。没有剩余事项。

## 背景与目标

当前项目工作台把 `Sessions` 与“工作目录”作为两个同级入口，但工作目录本质上只是 Session 启动、恢复和关联时使用的运行位置。两个入口拆开后，用户需要在目录管理、Session 管理和执行内容之间来回理解关系；Session 正文又以密集的小字号事件块呈现，无法快速还原一次工作的时间、参与者和关键结果。

本任务把项目内的工作目录能力收回到 Sessions 模块，并将 Session 正文重做为可阅读的工作时间流。完成等级为 **4：内部完整**。

## 当前行为与问题证据

- 项目工作台左侧同时出现 `Sessions` 和“工作目录”两个一级入口。
- 新建 Session 默认先展示“关联已有 Session”，工作目录仅为无结构的路径输入框。
- Session 正文是平铺事件列表；人物消息、工具调用、状态和长输出的视觉权重接近，正文与元信息字号过小。
- `/projects/:id/workspaces` 会进入独立工作目录页面，进一步强化了不必要的一级概念。
- 已确认的高保真方向包含：单一 Sessions 目录、从 Sessions 新建、结构化工作目录选择器、按日期和时间组织的执行流、保留右侧关系与 Goal 历史。
- 视觉复核发现首版实现虽然接通了行为，但与已确认稿仍有结构级差距：桌面项目头占了两行、Session 目录过密、日期与首个事件距离不足，技术事件被画成大块卡片，右侧上下文又过窄。上述差距属于本任务验收范围，不能以“功能已通”替代高保真完成。

## 范围

### 包含

- 从项目工作台移除“工作目录”一级入口、独立目录和详情表面。
- 保留工作目录后端记录与兼容 API，作为 Session 启动和关联的运行位置数据源。
- 重做“新建 Session”流程：默认创建新 Session，可切换为关联已有 Session；在同一弹窗内选择 Runtime、Goal、标题和工作目录。
- 将已知工作目录呈现为可识别、可选择的列表，并支持输入其他绝对路径或不关联目录。
- 让创建 Session 的接口接受 `workspace_id`，校验项目归属、目录状态与路径一致性。
- 将 Session 执行内容改成按日期分组的时间流，区分用户、Runtime、工具、状态、审批、产物与终端输出。
- 增加事件类型筛选；长技术输出默认折叠；搜索与筛选共同生效。
- 保留并整理右侧当前关系、Goal 历史和工作目录信息。
- 桌面、窄屏、明暗主题均具备清晰层级和可用交互。
- 更新受影响文案、重定向、设计说明和测试。

### 不包含

- 删除工作目录注册表、工作目录 API 或迁移已有数据。
- 改变 Runtime 原生 Session 的内容采集格式。
- 重做 Goal、Feed、来源或全局设置模块。
- 把 Session 改名为新的产品概念。
- 发布、安装包与外部用户升级流程。

## 用户场景

1. 用户进入项目后打开 `Sessions`，可在同一目录浏览历史 Session 并启动新的工作。
2. 用户新建 Session 时，先确认 Runtime、Goal、标题和运行位置，再一次性启动。
3. 用户需要接回已有 Runtime Session 时，在同一个弹窗切换到“关联已有 Session”，发现或输入原生 Session ID。
4. 用户查看一次执行时，先看到用户与 Runtime 的对话，再按时间定位工具、状态、产物与终端证据；长输出不会淹没正文。
5. 用户在手机或窄窗口查看时，目录、正文和关系信息按单列顺序展开，不出现横向溢出。

## 方案与关键决策

### 信息架构

- 项目工作台一级入口只保留 `Sessions`；工作目录是 Session 的属性和启动参数。
- 旧工作目录项目 URL 重定向到 `#sessions`，保持旧链接可恢复。
- 现有工作目录 API 继续可用，避免破坏已有调用链。

### 新建与关联

- 弹窗默认动作改为“启动新 Session”。
- Runtime、Goal、标题与工作目录在同一表单内完成。
- 已知目录来自项目操作数据中的 `workspaces`；健康目录可直接选择，异常目录展示状态但不用于创建。
- 支持“不关联工作目录”和“选择其他目录”。自定义目录在创建时必须是存在的绝对目录。
- 关联已有 Session 复用同一弹窗，并保留发现原生 Session 与手动输入 ID 的能力。

### 执行时间流

- 事件仍使用既有 Session 内容接口，不修改采集契约。
- 客户端按 `occurred_at` 的本地日期分组，并在左侧时间轨显示时间、连线和类型节点。
- `user_message`、`runtime_message` 为主叙事；`tool`、`status`、`approval`、`artifact`、`terminal_output` 为紧凑证据行。
- 技术类事件的长内容默认进入可展开详情；用户与 Runtime 正文保持直接可读。
- 搜索匹配正文、标签与来源；事件筛选支持全部、对话、工具、状态、产物与终端。
- 空状态、加载失败与内容截断仍明确呈现。

### 高保真视觉基线

- 桌面 Sessions 状态沿用一行标题栏：项目选择器与工作标签同处第一行；不得为 Sessions 额外制造一行空白原生控制区。
- Session 目录在首屏保持约五条主要记录的阅读密度；每条记录必须清楚分出标题、Runtime/ID、Goal 摘要、状态与更新时间。
- 时间流的日期标记、时间、轨道和正文使用稳定三列对齐；对话承担主要阅读重量，技术事实采用带图标的水平记录行和细分隔线，不使用整块灰色卡片堆叠。
- 技术事件在同一行明确呈现事件名、来源或耗时、完成状态与“查看详情 / 查看变更 / 展开输出”动作；展开后才显示长输出。
- 当前关系与 Goal 历史保持与正文并列的足够宽度和纵向节奏；不因内容少而缩成两个矮小卡片。
- 新建 Session 弹窗的宽度、标题区、字段间距、工作目录选择区和底部动作比例以已确认高保真稿为准，同时不得以遮挡底部按钮换取视觉相似。

## 输入、输出与依赖

### 输入

- `ProjectOperationsData.sessions`
- `ProjectOperationsData.workspaces`
- `ProjectOperationsData.goals`
- `ProjectOperationsData.runtimes`
- `/api/sessions/:id/content` 返回的 canonical events
- 新建/关联表单中的 `runtime_id`、`goal_id`、`title`、`workspace_id`、`workspace_path`、原生 Session ID

### 输出

- Session 目录与详情 HTML。
- 新建/关联 Session 请求。
- 按日期分组且可筛选的执行时间流。
- 保持兼容的 Session/工作目录关系数据。

### 依赖

- Session 注册表与 Runtime adapter。
- 项目 Goal 数据。
- 工作目录目录表及路径可用性检查。
- 现有桌面工作台状态恢复机制。

## 文件与模块边界

- `src/web/project-session-workspaces.ts`：Sessions 目录、详情、弹窗、时间流样式和客户端交互。
- `src/web/server.ts`：Session 创建/关联输入校验、兼容重定向与页面文案。
- `src/web/render.ts`：只处理移除工作目录表面后的状态恢复兼容（如确有需要）。
- `tests/session-web.test.ts`：渲染、时间流和表单行为契约。
- `tests/session-workspace.e2e.test.ts`：项目入口和兼容 API 的端到端行为。
- `tests/web.test.ts`、`tests/desktop-tui.test.ts`：受影响的页面文案与一级导航契约。
- `DESIGN.md`：记录工作目录从一级模块降为 Session 运行位置的设计事实。

## 验收标准

- 项目工作台不再渲染“工作目录”一级入口、目录或详情表面。
- Sessions 目录仍可搜索、筛选、选择和添加 Session。
- 新建弹窗默认创建模式，能选择 Runtime、Goal、标题和工作目录；可切换为关联已有 Session。
- 创建请求可提交已知 `workspace_id` 或自定义绝对路径；异常、跨项目或不一致目录被拒绝。
- 旧 `/projects/:id/workspaces` 地址进入 Sessions。
- Session 执行内容按日期分组，并具备清晰的时间、节点、角色与事件类型层级。
- 桌面标题栏、Session 目录密度、时间流技术记录行、上下文侧栏和新建弹窗可与已确认高保真稿并排对照，不再存在结构级差异。
- 搜索和事件筛选同时工作；长工具、产物和终端输出默认折叠。
- 右侧当前关系、Goal 历史和运行位置仍可查看和管理。
- 桌面宽屏、窄屏、明暗主题无明显溢出、遮挡、错位或低对比度问题。
- 受影响测试、类型检查、构建与真实浏览器主流程通过。

## 验证方式

1. 运行项目的类型检查和受影响测试。
2. 运行完整测试套件与生产构建。
3. 启动构建后的本地服务，以真实项目数据验证：
   - 进入 Sessions。
   - 打开新建弹窗，切换创建/关联模式并操作工作目录选择器。
   - 打开有内容的 Session，搜索、筛选和展开长事件。
   - 验证旧工作目录链接重定向。
4. 截取桌面亮色、桌面暗色和窄屏关键状态，逐项检查层级、对齐、字号、对比度、滚动和弹窗边界。

## 假设与开放项

- 既有工作目录 API 仍可能被其他入口或自动化调用，因此本次只移除 UI 一级入口，不删除数据能力。
- 自定义目录创建需要服务器本机可访问；浏览器端不能替代系统目录选择器时，保留绝对路径输入作为回退。
- 当前任务不引入新的文件选择原生桥接；若桌面端已有可复用桥接，可在不改变契约的前提下接入。
