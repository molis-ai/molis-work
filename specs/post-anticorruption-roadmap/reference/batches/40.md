- 写手一律用子代理（isolation: "worktree"），一片派一个，本批可以同时有多个写手。按片挑模型：
  - 安全、沙箱、共享核心、跨模块、合同代码：Opus 5.5 high；
  - 范围清楚、跨几个文件的：Opus 5.5 medium；
  - 一般实现：Sonnet 5.5 xhigh；
  - 小而清楚的：Sonnet 5.5 high。
  写手只做派给它的那一片：合同先单独开小 PR（tracks.md 规则 1）；批次文件的合入记录随实现 PR 一起写；目标用例走 machine-slot、--jobs 1；不跑全量、不定样、不碰别轨的文件；开 PR 后把 PR 号交回你。
- 子会话：本批用得上哪几台就开哪几台，各开一个，做完就收：
  - 设计台（Opus 5.5 high；新的视觉方向和大页面，即首页、Onboarding、工作台外壳，用 xhigh）：本批和下一批要定样的项；不写产品代码，不审自己的样。
  - 合同台（Opus 5.5 high）：本批和下一批的合同、SDK、存储、动作 schema 设计稿；不定样，合同代码交写手。
  - 评审台（Opus 5.5 high 审实现、合同、界面；纯文档用 Sonnet 5.5 xhigh）：照第七节审，界面 PR 另按第五节走一遍体验；过了在 PR 上写「【评审台】审过（头 <sha>）」，退回写清挡合并的点，不挡合并的写成小修条目；不改被审的 PR，不入队。写手的 PR 一律由评审台审，你不审自己派的片。
  - 小修台（Sonnet 5.5 high）：本批的 BL 小项、评审里不挡合并的意见、文案和单文件缺陷，一条一个小 PR，记进 #1743「小修与插队」；不改在途 PR 正在改的文件，不改合同。
  - 核查台（按需，Sonnet 5.5 high）：为本批或下一批的某一项核账、只读核查、调用链清点；不改代码，不核更后面的批。
