## 运行原型

在仓库根目录：

```bash
node --import tsx docs/design/project-arrival-flow/prototype/build.mjs
node docs/design/project-arrival-flow/prototype/serve.mjs
```

打开终端给出的地址（默认 `http://127.0.0.1:4344/`）。`#状态` 可以直接跳到某个画面，例如 `#chooser.personal`、`#sources.filled`、`#result`；加 `&dark` 用深色，加 `&capture` 收起审阅条，加 `&still` 关闭动效。

`build.mjs` 把**产品真实的样式表**（`renderMolisWorkWorkbenchStylesheet()`）、设计系统 `dist` 里真实的 `render*` 函数和原型自己的脚本打成一个自包含的 HTML，所以控件、底栏几何、颜色、字重、焦点环和减少动态效果的规则，都是产品里那一份，不是照着画的。前提是 `packages/design-system` 已经构建过（`./node_modules/.bin/tsc -p packages/design-system`）。

| 文件 | 作用 |
| --- | --- |
| `prototype/src/views.js` | 所有画面的标记：设计系统的 `render*` + 候选组件 |
| `prototype/src/main.js` | 状态与动线、键盘、草稿、后台任务、创建项目（模拟） |
| `prototype/src/motion.js` | 字标打字机、AI 字幕、到达动画（只动 opacity / transform） |
| `prototype/src/data.js` | 示例数据（九个项目名取自截图，其余为设计示例） |
| `prototype/prototype.css` | 只写原型自己的类，全部用共享 token |
| `prototype/capture.mjs` / `record.mjs` | 渲染设计图 / 真实点击录屏 |
| `prototype/verify.mjs` | 72 项检查，结果在 `prototype/verification.json` |

## 设计怎么落在组件板上

- **同一个外框，三个画面共用**：桌面色标题栏、工作面（`--paper`，14px 圆角，`--sheet-shadow`）、桌面色底栏（真实的 `.workbench-bar`）。位置、高度、外框不动，换画面只换里面的内容。
- **项目选择页**沿用产品的「目录在桌面上、右边一张白色工作面」：左为搜索 + 目录（`renderDirectoryRow`，meta 密度），右为项目简介。简介里的目标卡沿用 Home「正在推进」的暖光卡片，下面的「接下来」仍是目录行加状态标记（`renderStatusMark`）。
- **新建项目**左边是这一步的问题和来源（来源也是目录行，选中的那一行就地展开配置），右边是材料清单或预览。「命名并开始」右侧的预览和项目选择页的详情是**同一块简介**，采用之后它在列表里就是这个样子，待办草稿就是它的「接下来」。
- **Welcome**内容和节奏不变（语言、外观，`renderChoice`），只放进同一个外框；暖光只在新用户的开场和 Welcome，沿用「渐变只属于 onboarding」。项目选择页和新建项目不用渐变。
- **字号只用产品的固定阶梯**（11 / 12 / 13 / 15 / 17 / 20 / 24 / 30），字重 400 / 500 / 600。开场的巨型字标是「问候字」，规范允许超过 30px；原型按窗口宽度分档（200 / 160 / 128 / 96 / 68px），不用流体字号。

底栏在每一屏的内容：

| 屏 | 左 | 中 | 右 |
| --- | --- | --- | --- |
| 开场 | — | — | 开始 ↵ |
| Welcome | 稍后再说 / 上一步 + 进度短线 | — | 继续 ↵ |
| 项目选择 | 所选项目（徽标 + 名字 + 预览中 · 回车进入） | 助理输入，作用于所选项目，按项目保留草稿 | 新建项目 · 进入项目 ↵ |

## 动效

- **字标打字机**取自 Molis Club Edition C 的节奏：250ms 起、逐字打出、光标闪动；新用户的完整开场每字 170ms 并停一个下划线光标，老用户在标题栏里每字 90ms、光标闪两下后收起，不挡任何操作。
- **AI 字幕**：A / I 常驻，后面的词按 90ms 一字打出，停 2.3 秒，再以 45ms 一字逆序删除；换词时两列用 420ms 平移到新位置。悬停、聚焦、点按、页面隐藏、离屏和「减少动态效果」都会暂停；按最长的一组词预留宽度，周围不会跳。
- **到达**：列表行依次出现（最多 12 行，28ms 间隔），详情从 40% 透明度上浮 7px（420ms），目标条逐段画出，底栏上浮。切换项目只重放详情，**不重播字标**。进入项目时项目名从详情里的位置飞到项目首页的位置；新用户点「开始」时大字标缩进标题栏。
- 脚本驱动的动画只动 `opacity` / `transform`，不触发布局；`verify.mjs` 实测过换词时字幕宽度与周围位置不变、切换项目时字标不重播、工作面不跳。

## 实现前要确认的事

1. **项目选择页的助理输入作用于所选项目**（预览谁就问谁，按项目保留草稿；个人空间则是个人范围）。现在这一页的助理固定在个人范围里。
2. **项目简介要一份新的数据投影**：描述（项目背景，或引导采用时保存的摘要）、目标进度与当前目标（Goals）、等你确认（Inbox）、助理在做（后台任务）、最近动静、最近打开（需新增本机记录）。原型用标注过的示例数据，各项的 owner 还要按 `docs/SSOT-MATRIX.md` 确认。
3. 老用户的轻开场**每次冷启动**都有，约 1.3 秒，只在标题栏里发生。
4. 上次没完成的材料清单：再点「新建项目」会接着上次，并给「重新开始」；整理进行中离开则进后台任务，不丢。

## 范围与已知局限

- 材料只记名称和大小，不读正文；整理的进度是模拟的，不调用模型；创建项目是模拟的。
- 标题栏没有画原生窗口的红绿灯，实现时沿用产品的 `data-native-desktop` 安全边距。
- 手机宽度只做了基本适配（底栏沿用产品的两行布局），没有逐屏打磨。
- 首次启动的语言、外观之外的其他设置页不在这次范围里。
- 验证只覆盖这个原型和模拟的路径，**不证明**真实导入、模型调用或生产功能可用。
