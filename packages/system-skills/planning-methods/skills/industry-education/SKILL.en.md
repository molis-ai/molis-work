# Education

Connect learning goals, activity, feedback, assessment and teaching roles to demonstrable learning.

For: Learning products, Teaching services, Educational content.

## Planning path

1. Define learner starting point, ability goal and real context
2. Design content, practice, feedback, collaboration and teacher intervention
3. Establish formative and summative assessment and learning evidence
4. Define boundaries for teachers, parents, administrators and learners
5. Verify transfer, continued learning and equitable access

## Required coverage

| area | label | question |
| --- | --- | --- |
| learner_context | Learner context | What are their background, aims, constraints and situations? |
| learning_outcomes | Outcomes | What can they do afterwards, and how do recall, understanding and transfer differ? |
| learning_experience | Learning experience | How do content, practice, feedback and social learning build ability? |
| assessment_evidence | Assessment | What performance proves learning rather than activity? |
| educator_governance | Teaching roles | What can teachers, parents, admins and AI observe, decide or interrupt? |
| access_inclusion | Equity and access | How do people with different abilities, devices, languages and resources participate? |

## Dependency rules

| rule_id | statement | direction_hint |
| --- | --- | --- |
| experience-after-outcomes | Content, practice and assessment need clear goals and learner baselines. | learning experience depends_on outcomes and learner context |
| scale-after-learning-proof | Expanding teaching or courses needs learning, transfer and accessibility evidence. | education rollout depends_on learning evidence |

## Completion evidence

- Goal-to-assessment correspondence
- Real learners' practice, feedback and change
- Role, exception and accessibility checks

## Closeout checks

- Completion or viewing time does not stand in for learning
- Assessment matches the intended ability
- Add the minors overlay where relevant

## Common mistakes

- Stockpiling course material before defining outcomes
- Treating right answers as transfer
- Ignoring teachers and administrators

## How to use this method

- Think the work through along the planning path first, then list each result that can be delivered and accepted on its own as one item; do not mix several main results into one.
- Every required-coverage question that bears on the task needs an answer; a key question without one is listed as open, not hidden behind a vague item.
- A dependency means consuming a result: B depends on A only when B cannot start or finish without A's accepted output. Order of discussion, timing, the same owner or the same file are not dependencies; work with no such relation stays parallel. Judge each dependency rule, and say which output is missing when one does not apply.
- State for each item what proves it is done (completion evidence), and run the closeout checks before finishing.
- Describe finite changes that can be completed; ongoing operation is not an item that never ends.
- When used with other planning methods, put their key results side by side, see which consumes which, and bring in the method that provides anything missing.
- Show the breakdown to the person first. When they want it in a tool (for example an installed Goals plugin), write it with that tool's own actions, with their confirmation.
