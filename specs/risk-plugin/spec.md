# 风险插件：专门记录风险

状态：基础完整路径已实现，待本人验收（第 17 批 [#2058](https://github.com/molis-ai/molis-work/pull/2058)，2026-11-14 合入 main `3b296a6337`；本人验收看 RISK-06 复查段偏离定样、RISK-09 没装 Goals 的人工核对；结果并入简报随第 19 批；复查的历次结果与采纳见 [BL-risk-review-history-adopt](../backlog/BL-risk-review-history-adopt.md)）。来历（2026-10-05 用户提出：做一个专门记录风险的插件；2026-10-27 确定风险独立记录、Goal 顾虑按需引用、结合 Work Brief 的项目风险总览，以及按需复查、结果并入简报）。三项产品决定已明确；2026-11-04 用户看原型定了记录、总览与复查的样子（见[定样决定](#design-decisions)）。

## 为什么

Goal 里原有的风险（风险表、Goal–风险关联、风险决定与安全面板）在防腐整理中连表带显示删除（#272）：它们是旧「领取」流程的一部分，与事件流程两套记账。用户希望风险作为独立的东西被认真记录，而不是挂在 Goal 结构里，所以另做一个插件。

## 要做到

- 记一条风险：说明、影响、可能性、处置办法、负责人、状态（打开、缓解中、已接受、已关闭）。
- 风险可以关联 Goal、Coding 会话、Feed 消息、成果等对象，关联字段是通用关联对象引用（插件、类型、id）的列表，Goal 只是其中一种；经公开的对象引用，不 import 其他插件的实现。没装 Goals 的项目里，风险记录、总览、复查、Work Brief 来源和首页接入全部可用，界面不出现 Goal 入口（2026-11-13 按插件同等地位收口改，[决定 42](../post-anticorruption-roadmap/reference/decisions.md#decision-42)）
- 风险独立记录，Goal「顾虑」按需引用（2026-10-27 用户已定）：风险说明、影响、可能性、处置和状态只由风险插件拥有；同一风险可以关联多个 Goal，不在 Goals 复制风险记录。
- 装了 Goals 时，人或执行 AI 判断某条风险确实影响当前 Goal，可通过动作目录里 Goals 声明的「提出顾虑」动作提出并引用它，写明对具体要求、事件或动作的影响（可选集成：没装 Goals 时这一项不出现，其余功能不受影响）。风险不自动生成顾虑，也不要求所有顾虑都关联风险。
- 风险与顾虑各自表达状态：风险被接受、缓解或关闭，不自动接受/解除顾虑，也不直接决定 Goal 是否能完成；顾虑处理使用平台的要求—证据—认可规则。反过来，一个 Goal 的顾虑解决也不自动关闭其他 Goal 仍在引用的风险。
- 能力注册到共同目录（列出、读取、记录、更新状态），页面、工作流、Agent、MCP 用同一套动作。
- 只走 Plugin Runtime 装配，插件只提供内容，挂在工作台的位置。

## 项目风险总览与 Work Brief（2026-10-27 已定）

项目内提供统一风险总览，由风险插件展示在工作台内，覆盖本项目全部风险，包括尚未关联任何对象的风险。默认关注未关闭风险，可查看已关闭记录，并按状态、影响、负责人、关联对象筛选（候选只列本项目已装插件里确有关联的对象类型，没装 Goals 就没有 Goal 这一项）。总览、Goal、会话与简报打开的是同一条风险详情，用户可查看来源、关联对象和处置进展，更新通过风险插件的公开动作执行。总览直接读取业务事实，普通浏览不必先生成一份 AI 简报。

[Work Brief](../work-brief/spec.md)承担跨插件的综合说明：个人助理按场景 Skill 和本次范围选取值得关注的风险变化、具体影响及下一步，与目标、任务、交付等来源放在一起解释。简报提供打开风险详情和项目风险总览的入口，不复制一份可独立编辑的风险登记册，也不要求每次把全部未关闭风险重写一遍。风险登记、状态修改与处置仍归风险插件；简报文字的修改不自动写回风险事实。

当前风险事实与简报当时的依据分开：总览读取当前状态，已保存简报固定其版本与材料时点；刷新按 Work Brief 原版本规则形成更新，不能用新状态冒充旧依据。取不到风险来源时标明缺失或过期，保留其他可靠内容，不当成“没有风险”。跨项目简报只读取当前获准的项目；缺少风险插件不阻塞其他来源的简报生成。

展示复用 Work Brief 设计中的公共对象、风险、来源与动作表达，经公共合同和 SDK 接入，不让两个插件互相 import 实现。后续高保真切片应覆盖“简报看到风险 → 打开详情 → 更新处置 → 返回总览/刷新简报”，同时展示未关联 Goal、空数据、读取失败和旧简报状态；具体布局通过可交互结果对齐，本次不以文字代替 UI 验收。接入简报不默认创建提醒任务，复查按下一节的已定规则安排。

## 按需复查、结果并入简报（2026-10-27 已定）

用户或执行 AI 可在已有委托与权限内，为确需跟进的风险安排复查时间；不要求每条风险必填日期，也不因为风险尚未关闭就自动反复提醒。复用 Schedule / 平台调度的公开能力安排唤醒，用户能查看、改期、暂停或取消；风险详情展示对应安排与结果，不在风险插件另建调度器或第二份任务状态。

到期由个人助理按适用 Skill 读取风险原件、关联对象和最新依据，判断有何变化及是否需要下一步。风险状态和处置仍通过风险插件的公开动作按授权更新，不因日期已到、用户未回应或读取失败就自动接受/关闭风险。取不到资料或模型不可用时如实保留未完成复查与缺口，不冒充“无变化”。

普通复查结果并入相应范围的 Work Brief；没有值得行动的变化时保持安静，不强制每次单独生成简报或通知。重要变化或需要用户决定时，按[主动助理的注意力与通知规则](../proactive-assistant/spec.md#127-注意力与主动程度)请求关注，遵守渠道、时段、频率、合并与例外设置；用户未回应不提高打扰频率。关闭风险、取消委托、停用或撤权后停止已无必要的后续复查，重启和重试不得重复生成同一结果或重复通知。

## 定样决定（2026-11-04 用户定）

用户在可点的原型 [`docs/design/risk-plugin`](../../docs/design/risk-plugin/README.md) 上逐块比过三个方案后定下（[第 17 批](../post-anticorruption-roadmap/reference/batches/17.md)）：

| 块 | 定的方案 | 要点 |
| --- | --- | --- |
| 风险记录 | B 两栏整页 + C 侧栏打开 | 整页左边是说明、处置办法与进展，右边一块要点面板（状态、影响 × 可能性小格、负责人、关联、复查）；从 Goal 顾虑、Coding 会话、简报等别处点开时先在右侧栏打开同一条风险，不离开原页面，可展开成整页 |
| 项目风险总览 | A 按状态分组 | 一行筛选（未关闭／全部／已关闭、影响、负责人、关联对象），下面按 打开／缓解中／已接受 分组，已关闭默认收起 |
| 复查 | A 详情里的复查段 | 复查是风险详情里单独一段：下次时间、要看什么、改期／暂停／取消，下面是历次结果；到期结果给建议，由人采纳才改处置 |

原型里正常与异常状态都要照着做：没关联对象（含项目没装 Goals，原型不重画，只补这一种状态到清单）、关联对象已删除或无权查看、保存冲突（两边对照、不覆盖）、已关闭只读、无修改授权、单条或总览读取失败（写明不代表没有风险）、筛选无结果、部分关联读不到、还没有风险；复查的未安排、无变化（安静）、复查没完成、已暂停、关闭后停止；简报旧版本与风险来源读不到。

2026-11-04 按组件板实件重做，用户确认：版式与取舍不变，原型里的控件、卡片、状态标、菜单、弹出层都换成组件板的 `mw-*` 实件（[组件板实件](../../docs/design/component-board/README.md)）；组件板上没有的影响 × 可能性小格和提示里的按钮标「组件板新增」，由 D 轨补标本。

## 不做

- 不在 Goals 存储里恢复风险表、风险决定或安全面板。
- 旧数据：#272 前的风险不迁入（用户已定「当做没有旧版数据」），新插件从空开始。

## 已定要求的验收

以下为后续实现的标准，本次只写需求；证明行为的测试须引用对应编号。

| 编号 | 可观察结果 |
| --- | --- |
| RISK-01 | 风险可独立存在，关联字段是通用关联对象引用（插件、类型、id）；同一风险被多个 Goal 等对象引用时只有一份风险事实；修改风险后各引用可读取该事实，Goals 不复制风险字段与状态 |
| RISK-02 | 记录或关联风险不自动创建顾虑；装了 Goals 时，人或执行 AI 可经 Goals 声明的动作提出具体范围的顾虑并引用风险，未关联风险的顾虑仍可正常使用 |
| RISK-03 | 装了 Goals 时，风险与顾虑的状态变化不互相机械覆盖；风险关闭不绕过 Goal 收尾条件，一个 Goal 的顾虑解决不替其他 Goal 关闭风险，既有证据与授权检查有效 |
| RISK-04 | 项目风险总览覆盖关联及未关联 Goal 的风险，默认展示未关闭项，可按状态、影响、负责人和关联对象筛选并查看已关闭项；普通读取无需生成 AI 简报 |
| RISK-05 | 总览、Goal、会话和 Work Brief 打开同一条风险；通过公开动作更新处置后，总览回读当前事实，简报按自身刷新与版本规则展示，不出现第二份可编辑风险台账 |
| RISK-06 | [人工] 高保真切片与后续真实内容验证覆盖简报到风险详情、处置更新、返回总览和刷新简报；空数据、来源失败、未关联 Goal 与旧版本均有可辨认状态，工程与用户体验验收分别记录 |
| RISK-07 | 用户或 AI 按已有授权安排复查，Schedule 到期唤醒后读取当前风险和依据；改期、暂停、取消、重启与重试不重复执行或投递，停用/撤权后的迟到结果无新业务写入 |
| RISK-08 | 普通复查结果并入简报，无实质变化不单独打扰；重要变化或必要决定仍遵守用户通知规则；读取/模型失败与无变化可区分，到期或未回应不自动接受/关闭风险 |
| RISK-09 | 项目没装 Goals：风险记录、总览、复查、Work Brief 来源和首页接入全部可用，界面不出现 Goal 入口（2026-11-13 按插件同等地位收口改，[决定 42](../post-anticorruption-roadmap/reference/decisions.md#decision-42)） |
