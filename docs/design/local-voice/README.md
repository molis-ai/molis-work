## 这次看什么

- **A 框内（已选）**：文字下面一条紧凑录音反馈，与输入框同一容器。
- **B 浮层**：同样的反馈单独放在输入框上方，草稿与录音视觉分开。
- 两者均由下往上覆盖展开，输入框底边、左右入口和主内容位置保持稳定。灰色焦点边，不用彩色高亮。
- 接收者只出现在现行底栏标签；切换到别处时，录音栏才补充原归属与返回入口。不重复项目名、不显示“声音 0/8”等刻度文字。
- **停止录音**：保留这一段，转成文字放回原草稿，尚未发送。**丢弃录音（×）**：丢掉这一段，保留原有文字。转写过程中仍可编辑；原文变了则先确认插入位置，不能覆盖或恢复刚清空的文字。
- 首次下载需明确点击，下载后本机准备单独显示；准备完成不自动开启麦克风。权限拒绝、设备断开、空结果、下载/转写失败均有恢复入口。模型和原生组件是不同层的状态。

顶部可切换三种宽度、明暗与中英文；“场景”可以直接打开异常状态。“慢转写”场景可以编辑、切换接收者，再点预览顶部的“模拟转写完成”观察归属。模拟录音从正常按钮开始后，停止约 3.2 秒自动完成只是演示时间，**不是性能指标**；直接打开“正在录音”场景时停在 0:06，方便对比截图。

## 来源与范围

- 基点：main `a08903b8e0dd9c9dd70a745e835780f6f3613006`。
- 沿用 [共享 kit](../kit/README.md) 的令牌、按钮、图标、状态环；`components.js` 从上述主线的真实 `renderComposer` 与 `COMPOSER_STYLES` 生成。没有改共享组件。
- 录音条、波形与待插入结果是**组件板新增候选**。选择后需按第 53 批规则交 D 轨补成组件板标本、完成走查，再进入正式实现。
- 工作台背景为布局示意，不替代主线工作台定样；接收者菜单只有演示草稿归属需要的三项，不是新菜单设计。
- 所有音频、波形、模型下载、权限恢复、识别文字、发送和重启状态均为内存模拟。没有 `getUserMedia`、模型调用、持久化草稿、真实 Home 或外网请求。
- 原生组件设置只给入口说明，不假装第 26 批安装已实现；单段上限待真实采样确定，不在定样里承诺分钟数。

## 本地查看

从工作树根目录生成预览组件：

```sh
node scripts/machine-slot.mjs run build --label 'voice53 design preview' -- node docs/design/local-voice/build-preview.mjs
node docs/design/local-voice/serve-preview.mjs
```

打开 `http://127.0.0.1:4453/`。服务只提供明确列出的 8 个预览资源；其他仓库文件请求返回 404。需要已有 esbuild 依赖，不构建 Host 或原生 helper。

## 核验与待定

本轮只验证定样的可浏览性、模拟操作与布局；结果见[复用清单](../../../specs/unified-input-voice/voice-reuse-audit-2026-11-12.md)末尾。最终 App、真实语音质量与速度、系统权限、中文 IME、VoiceOver 连续听感及用户审美认可，均不能用这份原型代替。

用户于 2026-11-12 明确选择 A「框内紧凑栏」。A 保留一个视觉容器，录音反馈与草稿关系直接；B 独立浮层多一个容器，本轮不采用，仍保留在预览里便于追溯。该选择只确认交互方向，不代表真实语音、系统权限或最终 App 已验收。正式接入仍等待第 25 批和第 26 批原生组件准备；新增组件还需 D 轨标本与走查。
