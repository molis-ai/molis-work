## 和组件板对齐（2026-11-04）

按[需求开发流程 §5](../../../specs/post-anticorruption-roadmap/reference/development-workflow.md)，定样用组件板 `/__ui/catalog` 现成的控件。样里的控件就是组件板的 `mw-*` 标记和样式：`board.css`、`board-icons.js`、`board-ring.js` 由 `extract-board.mjs` 从构建好的工作台样式、组件板和图标表里抽出来，不手改；`pnpm workspace:build` 之后重跑：

```bash
GIT_SHA=$(git rev-parse --short origin/main) node docs/design/unified-input/extract-board.mjs
```

B 轨的共用组件包 `docs/design/kit/`（`kit.css`、`kit.js`）合入后，本原型改为引用 `../kit/`，删掉这里的三个生成文件和 `extract-board.mjs`。

用到的组件板控件：按钮（主、次、幽灵、链接、危险描边）、分体按钮 `mw-btn-group` 加 `mw-menu`（分组、快捷键、勾）、标签 `mw-tag`（发给谁、底行附件）、上传行 `mw-upload` 与进度、拖放区 `mw-drop`、状态环 `mw-status`、提示条 `mw-alert`、轻提示 `mw-toast`、弹出层 `mw-popover`（改键提示）、键帽 `mw-kbd`、字段说明 `mw-field__hint`、切换组 `mw-toggle-group`、徽标 `mw-badge`、补充的回执 `mw-receipt`。

组件板没有、这次新做的三处，样里用虚线框和「新增 n」标出（顶上可以关掉）；交 D 轨补组件板标本，先进组件板再进产品：

| 编号 | 新增 | 现有的为什么不够 |
| --- | --- | --- |
| 1 | 多行输入框外壳（`.mwc`） | 组件板只有首页底栏的单行输入框（胶囊形，样式挂在首页外壳上），放不下「发给谁」、附件、状态几行。外观照它：`--r-composer` 圆角、`--lift-1` 阴影、聚焦时 `--line-strong` 描边；文字区沿用 `data-fit`（240px 或 40% 封顶）。里面全是现成控件 |
| 2 | 菜单项的说明行（`.mw-menu__desc`） | `mw-menu__item` 只有名称、快捷键和勾；「打断并改向」会丢掉正在写的回复，选之前要看得到后果 |
| 3 | 麦克风图标（`icon-mic`） | 图标表里没有；语音在第 53 批，这里只占位置 |

和改之前比，看得出的变化：框里的附件是组件板的上传行（一行一个，带进度和失败原因），比原来的小块高；发送键不再写快捷键，快捷键写在 ▾ 菜单和按钮提示里；停止用 Coding 现在的危险描边按钮。方案卡、目录、对话气泡和斜纹条是评审页自己的样子，不进产品。

## 七块要定的

每块 2～3 个方案，点方案卡切换，样张跟着变。推荐项标「推荐」，用户 2026-11-04 全部选了推荐项。

| 块 | 定什么 | 已定（＝推荐） |
| --- | --- | --- |
| 1 编辑器层 | 附件放在哪（框里、底行、框外），恢复草稿时怎么说 | A：附件在框里，恢复的草稿一行说明加「清空」 |
| 2 对 AI 的送达菜单 | 补充、打断并改向、下一轮再做放在哪 | A：发送按钮带 ▾ 菜单（[输入回执 §4.1](../../../specs/ai-input-receipts/spec.md) 的原样） |
| 3 新键位的一次提示 | 助理、项目讨论、创作台改成 Enter 换行后怎么提醒 | C：按老习惯回车时才提醒，用 ⌘↵ 发过一次就不再出现 |
| 4 发给谁 | 「发给：对象」放在哪 | A：框上方一行（03 定样已用） |
| 5 状态 | 发送中、运行中、失败、待确认、被丢弃、离线写在哪 | A：框里、发送键上方一行 |
| 6 插件扩展的入口 | 插件加进来的资料、方法、关联对象放在哪 | A：左下角一个 + 菜单，按来源分组；/ 和 @ 都能用 |
| 7 H4 用词 | 工作／任务／子任务三个方案，加三条小决定 | 方案一；下一轮再做；发给；turn |

几处要注意：

- 第 2 块：统筹 11-04 第 3 条写「创作台另加明确的『打断并改向』按钮」，需求 §4 允许按钮或菜单；用户 2026-11-04 选定创作台和别处一样走 ▾ 菜单。
- 第 7 块的小决定 2 推荐「发给」，和盘点时写的「发到」不同：03 已定的连续对话样张和 PWA-130 用的是「发给」，项目讨论现在写「发到」。
- 带虚线下划线的词随 H4 变；顶上的「用词」会把整页换掉。

## 建议走一遍

1. 第 1 块：点「加两个附件」「填一段长文」，看长高到上限后在框里滚动；拖一个文件进框；点「模拟刷新或切回来」看草稿恢复；点「模拟输入法选词」（或者直接用中文输入法打字，选词时按 Enter 不会发）。
2. 第 2 块：写一句按 ⌘↵（补充，回执从「已收到」变「已用上」），再写一句按 ⌘⇧↵（排到下一轮，可撤回）；从 ▾ 选「打断并改向」再发。关掉「AI 正在运行」看平时的样子。
3. 第 3 块：点「模拟刚升级」，写一句后像以前那样按 Enter。
4. 第 4 块：切换发送对象，看标签和 × 回到助理。
5. 第 5 块：六种状态并排；切换方案看三种写法。
6. 第 6 块：点 +，或在框里打 / 或 @；Esc 只关菜单。
7. 入口切到「项目讨论」：没有送达菜单和停止，标题栏有关闭；切到「创作台」「Coding」看场景选项的位置。
8. 换 EN、深色，窗口缩到 1024 和手机宽度。

## 2026-11-08 追加（实现阶段）

K2／K3 落进产品时按用户 2026-11-08 弹窗加了一条窄屏规则，样里没有画：手机（≤ 600 宽）与矮窗口（≤ 560 高）里，没人写字、没有附件也没有状态时，输入框静止收成一行——＋、「发给」缩成框内左侧的小标签、输入、发送；一写字、有附件或有状态就长回多行，长高不跳、焦点与光标不丢。桌面照定样多行。写进[需求 §10.1](../../../specs/unified-input-voice/spec.md) 的「发给谁」一行，经过见 [10.md](../../../specs/post-anticorruption-roadmap/reference/batches/10.md#batch-10-progress) 的「决定与偏离」。

共享资源的最终字节经用户 2026-11-08 弹窗批准：新增 `/assets/molis-work-composer.js` 42466 B，`/assets/molis-work-plugin-frame.js` 相对基线 +2672 B；登记在 `tooling/gates/page-asset-allowances/10-composer.json`，批准经过同样见 [10.md](../../../specs/post-anticorruption-roadmap/reference/batches/10.md#batch-10-progress)。

## 模拟的部分

- 回复、回执的变化、附件读取都是定时器演的；「停止」只把「AI 正在运行」关掉。
- 状态块里的按钮（重试、查看、放回输入框）只弹一条提示。
- 语音按钮只占位置，语音在第 53 批。
- 拖放只演示组件板拖放区的样子，产品里接 `molisDropZone`；长高用 `data-fit` 的上限，没有接它的脚本。
- 状态存在浏览器 localStorage（键 `molis-proto.unified-input.v1`），「重置」清掉。
