## 1. 背景

- 送达的位置：
  - `runScheduledOperation`（`operations.ts:185-240`）先在 `:218-223` 的事务里把本次记成 `running`，再调执行入口，拿到结果后在 `:228-238` 的第二个事务里送通知、记终态；
  - `:230`：`outcome.state !== "unknown"` 且（失败，或这个定时操作勾了 `inbox`）才送通知。**失败的一定送，成功的看 `inbox`，结果未知的不送；**
  - `deliver` 就是 `runtime-wakeups.ts:77-79`，`runtime.notify` 是平台的通知服务。
- `text` 从哪来（`operations.ts:227` 调 `operationResultText`，`:242-251`）：
  - 结果是字符串：整串；
  - 结果是对象：`text`、`summary`、`message` 里第一个非空字符串，没有就取第一个非空字符串的值；
  - 都不是：`JSON.stringify(value)` 的前 2000 个单元（`:250`，也是按单元截，本单不碰）；
  - 失败时是错误信息（`runtime-wakeups.ts:73` 的 `error.message`）。
- 标题怎么拼：「插件名」＋「：」＋（成功时结果文字压成一行后的前 80 个单元，没有文字就用操作名；失败时操作名前 40 个单元加「没有完成」）。
  - 插件名是安装记录里的 `name`（`runtime-installations.ts:34-38` 的 `title: record.name`），来自 Manifest 的 `name`（`apps/local-host/src/plugin-installation-directory.ts:21`），没有长度上限；
  - 操作名是动作的 `title`（`runtime-installations.ts:38` 的 `description: view.action.title`），`operations.ts:121` 取 `operation.description || operation.id`，也没有长度上限。
- 下游怎么数长度：
  - 通知服务（`plugin-notification-service.ts:39-43`）：`key` 300、`title` 200、`summary` 1000、`body` 100000，都按 `.length`（UTF-16 单元）；`title` 与 `body` 还不许全是空白；超了抛 `actions.input_invalid`「通知字段无效：<字段>」，在 `:48` 入队之前；
  - Feed 的接收动作（`plugins/native/feed/src/notification-actions.ts:22`）：`title` 200、`summary` 1000、`body` 100000，AJV 数的是码点，服务放行的它一定放行；
  - Feed 入库时 `normalizeTitle` 是 `trim().slice(0, 300)`、`normalizeSummary` 是 `trim().slice(0, 2000)`（`plugins/native/feed/src/store/items/rows.ts:9-15`），本单的值都在它们下面，不会再被截；`body` 原样存（`store/items/ingest.ts:85`）。
- 所以：
  - 标题：80 个字最多 160 个单元，加上无上限的插件名，随时可能超 200，由 `notificationTitle` 兜；
  - 摘要：280 个字最多 560 个单元，小于通知服务的 1000，不需要再兜；
  - 正文：整段结果，不截（第 3 节、第 8 节第 6 条）。
- 同一个文件里，提醒的送达（`runtime-wakeups.ts:48-49`，原 `:37`）T-099 已经用 `notificationTitle` 包好；闹钟名称（`reminders.ts:75`、`operations.ts:123`）T-153 已经改好。`notificationTitle` 现在是：

  ```ts
  // plugins/native/schedule/src/runtime-wakeups.ts:14-23
  /** The notification service takes a title of at most 200 UTF-16 units; a longer one is cut at a whole character and ends with 「…」. */
  function notificationTitle(title: string): string {
    if (title.length <= 200) return title;
    let cut = "";
    for (const character of title) {
      if (cut.length + character.length > 199) break;
      cut += character;
    }
    return cut + "…";
  }
  ```

## 2. 目标

1. 定时操作送达的通知标题经 `notificationTitle`：整串不超过 200 个单元时原样；超过时整字截到不超过 199 个单元，加「…」，一共不超过 200 个单元。插件名再长，成功和失败的通知都送得进收件箱。
2. 成功通知的标题里，结果文字取前 80 个字（原来是前 80 个单元）；失败通知的标题里，操作名取前 40 个字（原来是前 40 个单元）。
3. 通知的摘要取前 280 个字（原来是前 280 个单元），最多 560 个单元，仍在通知服务的 1000 以内。
4. 正文仍是整段结果（没有结果时是「操作已结束」）。
5. 不含两单元字、整个标题本来就不超过 200 个单元的通知，与现在一字不差。
6. 用例钉住上面几条：标题改回按单元截、摘要改回按单元截、去掉 `notificationTitle` 的包裹、失败标题改回按单元截、把正文也截了，都红。
