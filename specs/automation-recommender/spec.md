# 项目自动化建议（Automation Recommender）

状态：第 39 批已接通项目到达、助理和插件创作台的只读建议入口，完成工程与 dev `4207` 真实界面走查，用户 2026-11-16 委托主会话实测并视作验收通过；第 61 批接上主动推荐与采用（§7）：助理在项目对话里放一张勾选卡，以本人身份开启技能、准备连接，可撤销。目标完成程度为**内部完整**。项目建议由已授权的目录和当前可用的能力生成，报告可显式存到 Pages，安装和配置沿原入口确认。

## 1. 问题

Molis 的扩展面很多：hooks、技能包、MCP/连接器、子代理/角色、命令、项目设置。新项目上手时，用户不知道哪些值得加、为什么加、加了会怎样；插件创作台能“从零做一个插件”，但不会先告诉用户“这个项目最需要哪两件事”。

现有的项目到达/引导（BL-106、BL-107）解决的是项目简介、材料数和后台整理；没有“读项目 → 推荐自动化”的只读流程。

## 2. 范围与非目标

**做**：

- 只读扫描当前项目：语言/框架、包管理器、测试、lint/format、CI、目录结构、已有 `.molis`/`.claude`/`AGENTS.md` 配置、已装插件/技能包。
- 按类别各推荐 1–2 个最值得的自动化：hooks、技能包、MCP/连接器、子代理/角色、命令。
- 每条建议带证据（文件/配置/依赖）、预期效果、前置条件、风险/费用、置信度。
- 建议可保存成一份报告；用户可以选择“去安装/去创建”，安装仍是独立确认。
- 在助理、项目到达、插件创作台可达；不新增第二套项目扫描事实。

**不做**：

- 不自动安装、不自动改项目配置、不自动跑命令。
- 不虚构项目没有的能力；只推荐已注册的动作、技能包、连接器和角色。
- 不把扫描结果写成项目的正式事实或 Goal。
- 不做云端代码扫描；只读本机已授权工作区。

## 3. 扫描与建议

### 3.1 扫描信号

| 信号 | 看什么 | 影响 |
| --- | --- | --- |
| 语言/框架 | `package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、锁文件 | hooks、LSP、技能包 |
| 测试 | Jest/Vitest/pytest/Playwright 配置、`tests/` | 测试 hook、测试子代理 |
| 质量工具 | ESLint/Biome/Ruff/Prettier/tsc | 写后 lint/format/typecheck hook |
| CI | `.github/workflows`、`.gitlab-ci.yml` | PR 评审、CI 修复、批准门 |
| 已有配置 | `.molis/`、`.claude/`、`AGENTS.md`、`CLAUDE.md` | 避免重复建议 |
| 外部系统 | 连接器/官方集成、`.mcp.json` | MCP/连接器建议 |
| 项目类型 | 前端/后端/数据/文档/研究 | 技能包与子代理 |

### 3.2 建议格式

每条建议至少写：类别、名称、证据（路径/依赖/配置）、为什么现在值得、预期效果、前置条件、风险/费用、置信度、下一步（安装/创建/查看）。

### 3.3 类别

- **Hooks**：写后 format/lint/typecheck、测试、阻止 `.env`/锁文件/敏感路径、Stop 前要求测试。
- **技能包**：按项目类型推荐角色包/场景包（工程、设计、数据、产品等）。
- **MCP/连接器**：按依赖和外部系统推荐（文档、数据库、浏览器、Issue 跟踪）。
- **子代理/角色**：代码评审、安全评审、测试编写、性能分析、UI/无障碍评审。
- **命令**：提交/PR、Issue 分诊、去重、发布说明。

## 4. 交互

- 入口：项目到达、个人助理、插件创作台；只读，不阻塞页面。
- 输出：一份可保存的“项目自动化建议”报告；按类别分组，默认每类 1–2 条，可展开更多。
- 用户点“去安装/去创建”后，进入现有的安装/创建流程；安装前仍展示权限、来源、版本。
- 用户可以忽略某条建议、标记“已经有”、或让它以后不再出现；这些偏好按项目保存。
- 扫描失败/部分失败：说明缺什么，不用猜测补齐；只基于读到的内容给建议。

## 5. 验收标准

| 编号 | 用户可观察结果 |
| --- | --- |
| AUT-01 | 在一个真实项目里打开建议，能在合理时间内完成只读扫描，不修改任何文件、配置或业务数据 |
| AUT-02 | 建议按 hooks/技能包/MCP/子代理/命令分组，每类 1–2 条，每条都有证据、预期效果、前置条件与风险 |
| AUT-03 | 推荐只包含当前实际可用的动作、技能包、连接器和角色；没有的能力不编造，缺依赖时说明 |
| AUT-04 | 已有 `.molis`/`.claude`/`AGENTS.md` 配置时，不重复推荐已经存在的自动化 |
| AUT-05 | 项目信息不完整或扫描失败时，如实说明缺口，仍能基于已有信息给出有限建议 |
| AUT-06 | 点击“去安装/去创建”进入现有流程，安装/创建前仍展示权限、来源、版本；不自动安装 |
| AUT-07 | 建议可保存为报告，用户可忽略/标记已有/不再提示；这些偏好不改变项目事实 |
| AUT-08 | `[人工]` 在一个真实项目上按建议加一个 hook 或技能包，验证它确实生效；撤销后不残留 |

### 第 39 批证据

- AUT-01～05。 `tests/security-invariants-automation-recommender.test.ts` 在空项目和有实际文件的隔离项目走真实目录读取，断言权限撤下后迟到结果无法保存。有现行签名 Skill 时才出具体选择，已枚举的配置去重，目录与偏好不可读取时显示缺口。当前无可核对的通用 Hook 与命令配置入口，两个分组会显示缺口。
- AUT-01 实测使用候选 `9851240666` 的 Molis Work 版本库快照，包含 12,693 个文件。通过项目到达页点击建议，专用 Chromium 在约 24 ms 显示加载反馈、56 ms 显示原签名 Skill 的建议。首次打开包含按需脚本加载。随后四次重开的反馈为 15～16 ms，建议均在约 33 ms 可见。每次打开只发一个建议请求。五次前后快照摘要一致，没有新建 Pages 文稿、保存建议偏好或启用 Skill。运行环境为本机专用浏览器和临时 Home。
- AUT-06～07。 `tests/automation-recommendations.e2e.test.ts` 通过实际项目到达、助理和创作台打开同一项目的建议，查看原 Skill 设置，保存为 Pages 文稿。工程用例另验证同一报告保存两次只有一个文稿，跨项目凭据被拒，偏好冲突不覆盖原保存。
- AUT-08。隔离项目从建议打开原设置，启用签名 Skill，在助理输入框选用并发送。实际模型请求包含签名正文，原目录恰好记录一次使用。撤下后，输入框不再列出该 Skill，新一轮的请求不含原正文，目录保留原来的一次使用。2026-11-16 在本机 dev 环境（Auth `8787` + Work `4207`，隔离 Home）与真实 Chromium 980px 窄视口复核全流程（从助理新对话区打开「项目自动化建议」→ 开启签名技能 `review-tests` 仅手动 → `/review-tests` 斜杠调用并验证模型请求含技能正文 → 关闭技能后斜杠菜单消失且模型请求不再携带）；用户委托主会话验证并视作通过（未由用户手点）。

### 第 61 批实现

- **卡由 Host 放、以本人身份跑。** 主动推荐不另开路：助理的操作卡加了两样通用能力——`choices`（字段只能在给出的选项里选，数组字段是多选）和 Host 放给本人的卡（`placeForPerson`，`runs_as: "person"`，按本人在该工作范围里的动作运行，结果按动作声明的 `undo` 记进工作，可在工作里撤销）。页面放的卡、Agent 轮次的建议仍按助理能用的能力核对，不能以本人身份运行（[S-automation-adoption](../../docs/system/security-invariants/S-automation-adoption.md)）。
- **开启动作。** 「开启所选」先在原卡显示本次选择、来源、发布者、版本、声明工具和用法。本人确认后，Host 用原项目、原工作与卡片修订派发 `automation.adoption.adopt@1`。技能按选择开启，连接经 `connectors.setup.prepare@1` 准备并由本人在原处完成，「以后别再提」写项目偏好。开技能的修订与可撤销回执一起记录。有权限时，后一步失败会撤回本次开启的技能与本次新建、尚未开始的授权请求。取消或撤权后停止后续步骤，已开启的技能可以在工作里由本人用新请求撤销，已有授权请求可在重新接入时继续。撤销只恢复本次开启且仍停在原修订的技能，并说明保留项。规则见 [S-automation-adoption](../../docs/system/security-invariants/S-automation-adoption.md)。
- **什么时候说。** 项目页打开约 1.5 秒后问一次 `automation.recommendations.offer@1`，页面可见期间每 30 秒再查，返回可见时补查。同人同项目的多个标签页共用 30 秒间隔与进行中的扫描。出现以前没说过的技能或连接才放卡，按「新的在前、证据强的在前」最多 3 项，连接最多 1 项。放卡时 Dock 亮一次。`config/automation-offers.json` 按人、项目与项目身份存已提示记录与开启回执，随项目删除。
- **连接候选。** 服务声明 `project_hints`（`git_hosts`、`files`、`dependencies`）。扫描读根目录文件名、实际依赖字段和 Git 远端段落里的主机名。证据只保留匹配的线索。冷进入项目时也可从内置说明取得候选，扫描保持只读。
- **证据。** `tests/automation-adoption.test.ts` 覆盖项目线索、去重、采用、连接只准备、补偿与恢复。`tests/security-invariants-automation-adoption.test.ts` 覆盖拒绝路径。隔离 Home 操作见[第 61 批复核修复](../batch-61-audit-fixes/spec.md)。操作卡字段名的多语言合同跟随第 62 批 G-11。
