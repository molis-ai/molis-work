代理实现使用 Worker Secrets 和 AES-GCM 封装的短时授权 state/返回票据、加密 refresh envelope；令牌不持久化到云数据库。Host 自生 PKCE verifier，Worker 验证其 challenge 后才交换上游授权码；上游授权码自身单次消费。回调仅允许固定路径的 loopback 地址；拒绝任意外部返回地址、自定义 scope/token endpoint。加密载荷区分用途并校验服务、client id 和有效期，刷新令牌带独立用途。前端不接触 Client Secret。测试需覆盖过期/篡改/错误 verifier/错误服务/恶意 callback/提供商拒绝/原始敏感错误不泄漏以及完整 Host 集成。

部署维护补充：Cloudflare Secret 不可回读，当前 Google 凭据已保存到 OAUTH_APPS。为继续注册其他服务而不重填或覆盖 Google 密钥，Worker 支持独立的 OAUTH_APP_<SERVICE_ID_UPPER_UNDERSCORE> JSON secret；存在时整体替代该服务条目，不能将不完整的新条目与旧秘密混合。旧 OAUTH_APPS 保留兼容。/providers 只展示协议目录内且配置有效的服务。验证独立条目完整换码、旧 Google 配置仍可启动、坏条目不回退借用秘密，且公开响应不含 secret；不迁移已有生产秘密。

本阶段复用现有 API OAuth、MCP 动态注册、专用账号登录和密钥连接。Host 统一读取产品方配置，仅下发就绪状态，不将 Client Secret 输出给浏览器；预配置可用 API 优先，其次官方可自动注册的 MCP（明确仅工具用途）。普通账号没有就绪授权时呈现“登录接入准备中”，不冒充能一键连接；密钥型服务保留获取密钥的正常主流程。目录点击就绪服务直接启动授权，详情与已有账号管理保持可达。等待、失败、取消与重试复用原有流程。
