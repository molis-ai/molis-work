# 运行与恢复定样（第 25、26 批）

状态：定样中（2026-11-04），等用户逐题选方案；选定后记进原需求的决策记录，再写产品代码。

第 25 批（本机常驻与升级 U1～U3）和第 26 批（M1 发行准备与升级 U4～U6）都写了「先定样」，两批的界面是同一件事的两半：Molis Work 在后台怎样一直干活、某一块出问题时怎样说、新版怎样装上和退回、第一次打开时怎样自检、上次出事后怎样恢复。所以合成一份可点的预览。

画面沿用 04 已批准的引导框架（`docs/design/onboarding-full-journey/`，随 [#1757](https://github.com/molis-ai/molis-work/pull/1757) 入库）：启动时的整屏开场、左右两栏、底部主按钮；进入工作台后沿用 Soft Workbench 的底栏与主区。界面规则按 [DESIGN.md](../../../DESIGN.md) 2026-11-03 的通用规则：按钮有边界；绿色是 Molis 已核过的，琥珀色是要你处理的，蓝色是要知道的事实，红色是失败；状态不只靠颜色；行不折行。

## 怎么打开

直接用浏览器打开 `index.html`，或者在本目录起一个静态服务（如 `python3 -m http.server`）。顶部斜纹条是原型控制，不是产品界面：选话题、方案、状态，切中英文和深浅色，「从头再来」清掉点过的东西。数据全是示例，点按钮只在本页里变化，不连任何服务。

## 五个话题

每个话题两个方案，A 是推荐的。

| 话题 | 方案 A（推荐） | 方案 B | 可切的状态 | 要定的是 |
| --- | --- | --- | --- | --- |
| 运行状态（25） | 菜单栏面板：点菜单栏图标弹出小面板，看正在运行、错过的、接下来的，可「现在做／跳过」；退出前列出退出后不会运行的事 | 设置 › 运行：同样的内容放在设置页，菜单栏只留图标 | 窗口关着仍在运行、睡眠醒来错过 2 件、退出后再打开、没联网、模型连不上 | 后台状态放在哪里看；错过的事是否让用户选「现在做／跳过」（不自动补跑） |
| 某块暂不可用（25） | 就地说明：打开那一块时，主区换成一张说明卡，写原因与「回到上一版／发送诊断」，其余照常 | 顶部提示条：首页顶部一条提示，底栏那一块带点 | 升级没成功、数据来自更新的版本、插件需要更新 | 出问题时在哪里告诉用户，以及给哪几个动作 |
| 更新与回退（25） | 设置 › 更新：显示当前版本、新版在副本上演练的结果、更新说明，「重启以更新」；下面是「回到上一版」 | 底栏提示：新版演练通过后底栏右侧出一颗「重启以更新」 | 新版已演练通过、正在副本上演练、演练没通过、重启后正在升级、已回到上一版 | 更新入口放在哪里；回退前是否默认先把现在的数据另存一份 |
| 安装与自检（26） | 开场时检查，只报问题：自检在第一次打开的开场里静默做完，全通过就不出现；缺组件时在当前步骤下面出一张琥珀色卡 | 单独一步：引导里多一步「检查本机组件」，逐项列出 | 全部通过、缺一个组件、修复没成功 | 自检是否作为单独一步出现 |
| 升级失败与恢复（26） | 不挡启动，进来后说：上次没做完的升级在开场里接着做完，进入后首页顶部一张卡说明；意外退出也是进来后说 | 启动时先说：开场先停在一页，让用户选「接着完成／全部退回」，或看恢复了什么 | 上次升级没做完、上次意外退出、导出诊断 | 出事后的下一次启动，先让用户进来还是先停下来问 |

「导出诊断」一页两个方案相同：列出诊断包里有什么、明确写不含什么（消息正文、文件内容、密钥、带用户名的路径），给「存成文件／先看看内容」，以及一个可复制的短诊断号。

## 原型没做的

- 菜单栏、桌面与系统通知都是画出来的，不是 macOS 的真实控件；真实的菜单栏图标和面板尺寸以实现时的系统规范为准。
- 副本演练、升级、回退、修复组件的时长与结果都是定时器模拟；「重启后正在升级」的进度按每步 0.65 秒走完。
- 诊断号是示例；导出的文件不会真的生成。
- 插件页面的内容只画了首页与说明卡，其余页面不展开。
