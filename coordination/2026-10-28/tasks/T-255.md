## 1. 背景

来源：T-231 二审建议（#1504 评论 6504271858）。`modules/shelf/src/item-names.ts:26-31` 的 `safeFilename`：

```ts
return base.length <= 180 ? base : base.slice(0, 180).replace(/[\uD800-\uDBFF]$/u, "");
```

名字超过 180 个 UTF-16 单元时从头留 180 个，尾巴整段被切掉，扩展名一起丢。例：`"x".repeat(200) + ".pdf"` 存成 `"x".repeat(180)`。`admissions.ts:73` 先用这个名字存，再由 `classify(filename, mime)`（同文件）按扩展名定类型：没有 `.pdf` 就掉成 `file`，Shelf 里不再能当 PDF 预览（改前就有，T-231 只是把 Host 一半的同类问题修了）。Host 一半（`apps/local-host/src/browser/browser-host.ts:763` 的 `safeFilename`）已经是“先摘末尾扩展名，再切前面的部分”：

```ts
const extension = /\.([A-Za-z0-9]{1,10})$/u.exec(cleaned)?.[0] ?? "";
const room = 200 - extension.length;
const base = cleaned.slice(0, cleaned.length - extension.length);
const kept = base.length <= room ? base : base.slice(0, room).replace(/[\uD800-\uDBFF]$/u, "");
```

（两个 `safeFilename` 不是同一个函数，上限也不同：Host 200，Shelf 180。本单不合并它们，只让 Shelf 这个也留扩展名。）

## 2. 目标

1. Shelf 的 `safeFilename` 在名字超过 180 个单元时，先摘末尾的扩展名（形状同 Host：`/\.([A-Za-z0-9]{1,10})$/u`），把前面的部分切到 `180 − 扩展名长度` 个单元（仍在整字处切，不留半个字），再接上扩展名。总长不超过 180。
2. 名字不超过 180 个单元时和现在完全一样；没有扩展名的名字（如 250 个 `z`）和现在完全一样，仍是 180 个。
3. 其余清理步骤（取 basename、去 `\0`、`\` 换 `_`、trim、空名与 `.`/`..` 变 `untitled`）不变。
4. 现有用例 `RAC-2201` 里 `x×179 + 🙂 + .md` 的预期要跟着改（见第 7 节）。

## 3. 不做

- 不合并 Shelf 与 Host 的两个 `safeFilename`，不改任何一个的上限。
- 不改 `classify`、`safeRelative`、`uniqueName`、文件夹名的处理（`admissions.ts:82` 那一处文件夹名没有扩展名，行为不变）。
- 不加兼容或迁移逻辑；库里已经存下的旧名字不动。

## 4. 范围

`modules/shelf/src/item-names.ts`（只 `safeFilename`）、`tests/shelf-item-names.test.ts`。

锁定：2026-10-29 核，没有在途 PR 改着 `modules/shelf`；开工前 `git fetch` 后 `gh pr list --state open --json number,files` 再核一次。

## 5. 做法

先在当时的 main 上核第 1 节的行。把 `safeFilename` 末尾的一行改成（形状，名字自定）：

```ts
if (base.length <= 180) return base;
const extension = /\.([A-Za-z0-9]{1,10})$/u.exec(base)?.[0] ?? "";
const room = 180 - extension.length;
const stem = base.slice(0, base.length - extension.length);
return stem.slice(0, room).replace(/[\uD800-\uDBFF]$/u, "") + extension;
```

注意：扩展名最长 11 个单元（点加 10 个字符），所以名字超过 180 时 `room` 至少 169，`stem` 一定比 `room` 长，不会为负或为空；这一点在【方案】里用一句话确认即可。

改完把 `RAC-2201` 里 `x×179 + 🙂 + .md` 的预期改成新结果（`x×177 + .md`，180 个单元、180 个字、没有半个字），并在测试注释里写一句为什么变。

## 6. 验收

- `RAC-2290`：`"x".repeat(200) + ".pdf"` 存成 `"x".repeat(176) + ".pdf"`（180 个单元），且 `item.kind === "pdf"`。
- `RAC-2291`：`"x".repeat(176) + "🙂" + ".md"`（前面部分 178 个单元，要切到 177，正好落在 🙂 的两半之间）切在整字处：前面留 `x×176`：名字以 `.md` 结尾、没有半个字（`LONE_HALF` 不匹配）、不超过 180 个单元，`kind === "markdown"`。
- `RAC-2292`：不超过 180 个单元的名字（含刚好 180）原样不变；`"z".repeat(250)`（无扩展名）仍是 180 个 `z`。
- `RAC-2293`：扩展名超过 10 个字符的（如 `"a".repeat(200) + "." + "b".repeat(11)`）不当作扩展名，行为同改前（切到 180，不留尾巴）。
- `RAC-2294`：以点开头、超过 180 个单元的名字（如 `"." + "a".repeat(250)`）不抛错、结果不为空、不超过 180。
- 先红：`RAC-2290` 在改源码前红。
