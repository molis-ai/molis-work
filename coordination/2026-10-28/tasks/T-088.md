# T-088 终端进程自己退出时，也删掉它的重放缓冲

> **这条在 main 上成立：终端进程自己退出后，它的重放缓冲还留在表里，没人读，也没有清掉的路径。**
> - `MolisWorkPtyHost`（`horizontal/runtime-host/src/adapters/terminal-pty.ts:350`）用两张表管终端：
>   - `sessions`（`:351`）放进程句柄；
>   - `replay`（`:352`）放重放缓冲，每个面板最多 200,000 字（`:16`、`:346-348`）。
> - 进程自己退出时，`proc.onExit`（`:393-397`）只删 `sessions`（`:395`），不删 `replay`。
> - 删 `replay` 的只有两处，退出后都不会走到：
>   - `kill`（`:416`）：`killAll`（`:420-422`）只遍历 `sessions`，已经退出的面板不在里面；
>   - 同一面板再起进程时的置空（`:388`）。

## 1. 背景

- `replay` 表的每一处读写（`terminal-pty.ts`）：

  | 位置 | 做什么 |
  | --- | --- |
  | `:388` | 起新进程时，把这个面板的重放置成空串 |
  | `:389-392` | 进程每来一段输出，追加，再截到最后 200,000 字（`clipReplay`，`:346-348`）；然后转发给 `handlers.onData` |
  | `:363-367` | 面板上有活着的进程时，接入拿到它的重放 |
  | `:368` | 没有活着的进程时，`attachOnly` 拿空串，不读 `replay` |
  | `:393-397` | 进程退出：先看守卫（`:394`），只认这个面板当前的那个进程；再删 `sessions`（`:395`），通知 `handlers.onExit`（`:396`）。**不删 `replay`** |
  | `:413-418` | `kill`：删 `sessions`，删 `replay`（`:416`），再结束进程（`terminatePtyProcess`，`:325-344`） |
  | `:420-422` | `killAll` 对 `sessions` 里的每个面板调 `kill` |

- 守卫 `:394` 为什么在：同一面板先 `kill` 再 `spawn` 就是重启。旧进程的退出晚到，那时 `sessions` 里已经是新进程。没有守卫，旧进程的退出会删掉新进程的句柄，还会替这个面板报一次退出。本单加的一行放在守卫后面，跟着受它保护；`RAC-1646` 把这一点钉住。
- 时序为什么稳（node-pty 1.1.0，在 `node_modules/.pnpm/node-pty@1.1.0/node_modules/node-pty/lib/` 下）：
  - `unixTerminal.js:65-89`：进程退出后，要等 PTY 的 socket 关掉才发 `exit`；socket 一直不关，200 ms 后强行销毁（`DESTROY_SOCKET_TIMEOUT_MS`，`:35`）。所以输出都在 `exit` 之前到，`exit` 之后不会再有输出；
  - `terminal.js:93`：`exit` 转成 `onExit` 的回调；
  - `eventEmitter2.js:35-43`：`onExit` 的回调按注册顺序调。宿主自己的回调在 `spawn` 里先注册（`:393`），测试后注册的回调被调到时，宿主的已经跑完了；
  - `unixTerminal.js:226-230`：`IPty.kill(signal)` 发信号，进程已经不在时吞掉错误。
- 没有测试量到这一处：`tests/runtime-host.test.ts:39-42` 看了进程自己退出（`exit 17`）会报告、`alive` 变假，没有看 `replay`。

  | --- | --- | --- |
  | `terminal-pty.ts:389-392` | `onData` 没有守卫：被 `kill` 的旧进程若在重启后还有输出，会追加进新进程的重放，并以这个面板的名义转发 | 是另一件事，去向由统筹定（见报告） |

## 2. 目标

1. 进程自己退出后，`replay` 表里不再有这个面板。退出后用 `attachOnly` 接入，仍然拿到 `{ attached: false, started: false, replay: "" }`，和现在一样（`RAC-1645`）。
2. 同一面板 `kill` 后重新起进程，旧进程晚到的退出不删新进程的重放、不删它的句柄，也不替这个面板报退出（`RAC-1646`）。这一条 main 上已经成立（`:394` 的守卫）。本单的新行要放在守卫后面，这个用例把它钉住。

test("RAC-1645: a terminal process that exits by itself leaves no replay behind, and attaching afterwards still gets nothing", async () => {
  // docs/horizontal/runtime-host.md「有限 replay 与退出清理」: the exit handler in src/adapters/terminal-pty.ts drops the replay with the handle.
  let output = "";
  const exited: string[] = [];
  const host = new MolisWorkPtyHost({
    onData(_panelId, data) { output += data; },
    onExit(panelId) { exited.push(panelId); },
  });
  const tick = () => new Promise<void>(resolve => setTimeout(resolve, 25));
  try {
    host.spawn({ panelId: "self", command: "/bin/sh", cwd: os.tmpdir(), args: ["-c", "printf done"] });
    assert.equal(host["replay"].has("self"), true, "a started terminal has a replay");
    await waitUntil(() => exited.includes("self"), tick);
    assert.match(output, /done/);
    assert.equal(host.alive("self"), false);
    assert.equal(host["replay"].has("self"), false, "the replay leaves with the process that exited by itself");
    assert.deepEqual(host.spawn({ panelId: "self", attachOnly: true }), { attached: false, started: false, replay: "" }, "attaching after the exit still gets nothing");
  } finally { host.killAll(); }
});

test("RAC-1646: when the old process of a restarted terminal exits late, the new process keeps its replay and stays alive", async () => {
  // kill() then spawn() on one panel is a restart; the guard at the top of the exit handler ignores the old process's exit.
  let output = "";
  const exited: string[] = [];
  const host = new MolisWorkPtyHost({
    onData(_panelId, data) { output += data; },
    onExit(panelId) { exited.push(panelId); },
  });
  const tick = () => new Promise<void>(resolve => setTimeout(resolve, 25));
  // The old shell ignores the SIGHUP and SIGTERM that kill() sends, so it outlives the restart until the test ends it.
  host.spawn({ panelId: "restart", command: "/bin/sh", cwd: os.tmpdir(), args: ["-c", 'trap "" HUP TERM; printf "old:%s\\n" "$$"; exec cat'] });
  const old = host["sessions"].get("restart");
  let next = old;
  let oldExited = false;
  old.onExit(() => { oldExited = true; });
  try {
    await waitUntil(() => /old:\d+\r?\n/.test(output), tick);
    host.kill("restart");
    host.spawn({ panelId: "restart", command: "/bin/sh", cwd: os.tmpdir(), args: ["-c", 'printf "new:%s\\n" "$$"; exec cat'] });
    next = host["sessions"].get("restart");
    await waitUntil(() => /new:\d+\r?\n/.test(output), tick);
    assert.equal(oldExited, false, "the old process is still running after the restart");
    assert.match(host["replay"].get("restart") ?? "", /new:\d+/, "the restarted terminal has its own replay");
    old.kill("SIGKILL");
    await waitUntil(() => oldExited, tick);
    assert.match(host["replay"].get("restart") ?? "", /new:\d+/, "the old process's exit leaves the new process's replay in place");
    assert.equal(host.alive("restart"), true, "the old process's exit leaves the new process running");
    assert.deepEqual(exited, [], "the old process's exit is not reported for the panel");
  } finally {
    host.killAll();
    old.kill("SIGKILL");
    next.kill();
  }
});

3. 几处为什么这样写，别改：
   - **读私有字段用 `host["replay"]`、`host["sessions"]`。** 这两个字段是 TypeScript 的 `private`（不是 `#`），方括号访问是 TypeScript 允许的写法，运行时就是普通属性。测试经 `tsx` 跑（`scripts/run-tests.mjs:97` 的 `--import tsx`），不做类型检查；构建出的 `.d.ts` 里私有字段不带类型，所以这两处在类型上是隐式的 `any`。它们不是写出来的 `any`，静态检查不数。不要改成 `as unknown as`、`any` 或给类加 getter。
   - **`RAC-1645`**：
     - 量的是表里这一项没了（`has`），不是内容空了（第 6 节 M4 区分这两样）；
     - 起进程后马上看 `has` 为真（`:388` 同步置了空串），证明退出后的假不是一开始就没有；
     - 退出后接入那一句是对外行为。main 上就是绿的，第 6 节每个变异下也都绿；它守的是本单不改调用方看到的东西。
   - **`RAC-1646` 的旧进程用 `trap "" HUP TERM`。**
     - `kill()` 给进程组发 SIGHUP、SIGTERM，再对进程发 SIGHUP（`terminatePtyProcess`，`:325-344`）；
     - 被忽略的信号在 `exec` 之后仍被忽略，所以 `cat` 活下来，直到用例在新进程的输出到齐后用 `old.kill("SIGKILL")` 结束它；
     - 不这样写，旧进程的退出和新进程的第一段输出谁先到要看运气。旧进程的退出要是先到，在 M2 下新进程随后的输出会把重放这一项重新建起来（`:390`），重放那一句就量不到 M2。
   - **等旧进程退出，靠在它的 `IPty` 上注册的 `onExit`。**
     - 守卫让宿主的回调什么都不做，从外面看不到它跑没跑；
     - node-pty 按注册顺序调回调（第 1 节），`oldExited` 为真时宿主的回调已经跑完；
     - 不要换成 `setTimeout` 等一会儿。
   - `assert.equal(oldExited, false, …)` 检查的是构造本身：旧进程要是已经退了，这个用例什么也量不到。
   - **`finally` 里三句都要留。** `killAll` 正常结束新进程。`old.kill("SIGKILL")`、`next.kill()` 管断言失败的时候和 M2：M2 下新进程已经不在 `sessions` 里，`killAll` 够不着它，不杀掉文件会挂住。进程已经不在时 `IPty.kill` 吞掉错误（第 1 节）。
   - 两个用例只用文件里已有的 `assert`、`test`、`os`、`MolisWorkPtyHost` 和 `waitUntil`。`processExited`、`waitUntil` 是函数声明，追加在它们后面也能用。工作目录用 `os.tmpdir()`，照 `:63`、`:95`；不加 `import`。
   - 两个用例各用自己的 `host` 和面板名，`tick` 照 `:60`、`:92`。
4. 代码里不要出现 `legacy`、`compat`、`backfill`，不加空 `catch`、`as unknown as`、`any`、`console`（这些按文件计数，只许减少）。

M2 的说明（「关守卫」类变异，照统筹 10-29 的规矩先查守卫后面的路径）：
- **守卫后面没有别的路径做守卫的事。** 后面三句（`sessions.delete`、新加的 `replay.delete`、`handlers.onExit`）都不看退出的是哪个进程。`kill`（`:413-418`）在重启前删过旧进程的句柄和重放，不会在旧进程退出时再跑一次。
- **也没有路径把删掉的重放放回去。** 能重建这一项的只有 `onData`（`:390`），要新进程再有输出才会走到。用例等新进程的 `new:` 那一行到齐才结束旧进程，之后没人往新进程里写（`exec cat` 不会自己输出）。所以红的就是重放那一句。
- **后面两句跑不到。** `"the old process's exit leaves the new process running"`、`"the old process's exit is not reported for the panel"` 在 M2 下也不成立，但一个用例在第一句失败的断言处就停了。
- **原有的第一个用例（`:9`）在 M2 下也可能红**，通常在 `:41`：`:35` 被 `kill` 的进程，退出不再被忽略，会多报一次。红不红、红在哪一句取决于它的退出赶在哪一步，照实记下，不算异常。
