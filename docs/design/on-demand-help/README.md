# 按需帮助定样（第 03 批交付项 2）

状态：用户 2026-11-05 选定方案 A「就近卡片，长的转右栏」（决定记在[视觉体验需求](../../../specs/visual-ui-experience/spec.md)「产品决定」）；B、C 留作对照。这是参考原型，不是产品界面；没有接 Home 或模型，服务商检查、费用和收件人都是示例。

需求来源：[视觉体验 §copy-guidance](../../../specs/visual-ui-experience/spec.md#copy-guidance)（VUX-55 帮助入口、打开收起与焦点，VUX-56 决定时刻直接可见的事实，VUX-57 从帮助接到准备再回来）、[Onboarding §3.15](../../../specs/onboarding-coverage/spec.md#315-从页面帮助到渐进式引导)（ONB-47、ONB-48）。第 03 批界面要求列了六块先定样，帮助是其中一块；[第 40 批](../../../specs/post-anticorruption-roadmap/reference/batches/40.md)写明复用这里的定样，给全部插件和设置补帮助入口。[文案清点](../../../specs/visual-ui-experience/copy-help-inventory.md) F-06 记下 23 个插件首屏都没有帮助入口。

## 定的是什么

用一页真实会有的插件页说明全产品的帮助怎样出现：Schedule 的「新建定时任务」。同一页上有三样东西，三个方案只在第一样上不同：

1. **帮助在哪里打开**：页头一个写着「帮助」的按钮（不只是一个问号），字段旁一个「了解此项」。
2. **哪些事实不进帮助**：表单下面「每次运行会」一直列着读什么、用哪个模型和大约多少钱、发给谁（发到项目外、收不回）。帮助开着关着都在，缺的那一项（没连模型）就地给「连接模型」，只限制「启用」，可以先存草稿。
3. **从帮助接到准备再回来**：帮助末尾「要按时运行，还差一步 · 连接模型」。看帮助不改任何设置，选了这一项才进入准备；准备用 04 已定的沉浸式框架（这里只画到连模型这一步），连好回到定时任务，写的内容都在，焦点落在「保存并启用」。

| 方案 | 帮助怎样打开 | 好处 | 代价 |
| --- | --- | --- | --- |
| **A 就近卡片，长的转右栏** | 点哪个入口，卡片就贴在旁边；宽屏放在表单右侧不压表单，1024 收窄到放得下；手机变成底栏上方的半屏。卡片底部「在右栏继续看」把同一份帮助移进右栏，边看边填 | 离要解释的东西最近；短的问题一眼看完；要长看再移到右栏 | 两种形态（卡片、右栏），实现和测试多一份；手机上半屏会盖住下半页 |
| **B 右栏里的帮助标签** | 帮助是右栏的一个标签；「了解此项」打开同一份帮助并滚到那一节、标出来；右栏原来是关的，关帮助时一起关上 | 只有一种形态，用现成的右栏和标签；边看边填，不挡表单 | 离字段远，要来回看；1024 下右栏占宽；手机上要切到「右栏」窗口，看不到表单 |
| **C 就地展开** | 页头帮助在表单上方展开，「了解此项」在字段下展开一小段；不浮在上面，也不另开地方 | 不盖任何东西，读屏和键盘顺序最自然 | 把表单往下推，长帮助会把要填的东西推出屏幕；同时只能开一处 |

**已选 A（用户 2026-11-05）。** 帮助大多是「这个字段是什么意思」这种短问题，卡片贴在旁边最省事；要长时间对照着看，再一步移到右栏，和 B 一样。B 的代价是每次都要往右栏看，C 的代价是把正在填的东西推走。

三个方案共用的规则：

- 入口写字（「帮助」「了解此项」），按下后入口显示为按下状态；Esc、关闭按钮、再点一次入口都能关；关后焦点回到入口；打开和关闭都不丢输入，也不动阅读位置。
- 第一次打开这一页时只有一行可跳过的提示（「看例子」「跳过」）；跳过后重新打开这一页不再出现，右上角的「帮助」一直都在。
- 帮助读不出来时，帮助里写清楚并给「再试一次」；页面照常能用，「每次运行会」照样列着。
- 补配置中途关掉（Esc 或左上「定时任务」）：选好的服务商留着，页面上方说明「连接模型还没做完 · 接着连接」。
- 动效只用 kit 的进场（贴着入口落下、从底栏升起、展开时上浮）和令牌时长；减少动态效果时没有动画。
- 从帮助进入准备，中途离开时焦点回到当初打开帮助的那个入口（「帮助」或「了解此项」）。
- 原型里「看例子」会整份覆盖已填的内容；第 40 批实现时只填空着的字段，或填完给「撤销」。

## 怎么看

```bash
python3 -m http.server 4437 --bind 127.0.0.1 --directory docs/design
```

打开 <http://127.0.0.1:4437/on-demand-help/>。顶上的原型条切方案、情况（新建任务没连模型／已有配置／第一次打开／帮助读不到／补配置中途关掉）、语言和外观；「重新打开这一页」模拟离开再回来；「标出组件板新增」给每一处新增加虚线框和名字。地址加 `?lang=en&theme=dark` 直接打开英文深色。

推荐走一遍：方案 A → 点「了解此项」（卡片在表单右边）→「在右栏继续看」→ 帮助末尾「连接模型」→ 选 MiniMax、回车、回车 → 回到定时任务，「保存并启用」亮了；再切 B、C 各点一次两个入口；情况切「第一次打开」，点「跳过」后点「重新打开这一页」。

## 用到的组件板部件

全部来自 `../kit/`：`mw-btn`（含 `mw-btn--link`：字段旁的「了解此项」按文字链处理）、`mw-field`、`mw-input`、`mw-textarea`、`mw-select`、`mw-collapsible`（高级）、`mw-alert`（补配置没做完）、`mw-empty--error`（帮助读不到）、`mw-choice`（服务商）、`mw-toast`、`mw-badge`；外框、标签、右栏和底栏沿用 `../workbench-shared-paths/` 的版面层。

### 组件板新增（交 D 轨补标本）

打开「标出组件板新增」能在页面上看到每一处（虚线框加名字）。定下后先补成组件板标本，再进产品。

| 新增 | 类名 | 用在 | 为什么组件板现有的不够 |
| --- | --- | --- | --- |
| 按钮按下态 | `mw-btn` 加 `aria-expanded="true"`（原型里是 `.help-btn`） | 页头「帮助」；以后所有打开、收起一块内容的按钮 | 帮助入口本身就是 `mw-btn--ghost`，不另立部件；缺的是按下态：kit 只给 `mw-choice`、`mw-toggle-group` 画了 `aria-pressed`，普通按钮打开一块内容后看不出它开着。补在 `mw-btn` 上（`aria-expanded`／`aria-pressed` 两种都认），底色用 `--nav-active` |
| 每次运行会 | `.facts`、`.fact-row` | 表单下方，列每次运行会读什么、用哪个模型和约多少钱、发给谁 | `mw-receipt` 是做完之后的回执，带时间和撤销，不是决定之前的预告；`mw-ix-impact` 是一行内联的琥珀小标，放不下图标、主次两行文字和行尾按钮，也没有就绪、外发两种状态；`mw-dir-row--meta` 是可点的目录行，有悬停和选中，事实行不可点，只有缺项那行带一个按钮 |
| 帮助内容 | `.hc`（含 `section.hl`、`.next`） | 卡片、右栏、页内三种形态共用的正文 | `mw-card` 分区每节都有边框、标题栏和内边距，一份帮助五节，会变成五张卡片叠在卡片里；`mw-collapsible` 只解决「高级」一节的折叠，管不了分节标题、按入口高亮其中一节（`.hl`）、末尾「还差一步」这三件事 |
| 帮助卡片 | `.hpop` | 方案 A：贴在入口旁的卡片，手机上是底栏上方的半屏 | `mw-popover` 是菜单式的小浮层（最小 180 宽、6px 内边距、没有头和脚），不能滚动长内容，也没有固定在底下的「还差一步」；`mw-sheet` 是从右边滑出的整高面板，带遮罩、挡住整页，帮助要边看边填；`mw-drawer--bottom` 也带遮罩，高 70dvh，盖住「每次运行会」和保存按钮 |

**D 轨做标本要的规格**

- 按钮按下态：`mw-btn--ghost`、`--secondary` 两种各画一个关着、开着；浅深色；键盘焦点环与按下态同时出现时都看得到。
- 每次运行会：三种行——就绪（绿，`--hue-green`）、缺项（琥珀，`--amber`，行尾一个 `mw-btn--secondary` 按钮）、外发（粉，`--hue-pink`，副文字写「发出后收不回」）；普通行用中性图标底。每行左侧 24×24 图标块（圆角 `--r-tag`），主文字一行、副文字 12px。宽于 1180 时主副文字同一行、放不下省略号；1180 及以下副文字换到第二行、不省略（这是有意的：这里每个字都是要看到的事实，与「行不折行」的口径不冲突，状态仍和条目同一行）。缺项的按钮不随宽度换行，始终在行尾。
- 帮助内容：分节标题 13px／600，正文 13px、行高 1.65、最宽 60ch；`.hl` 是从「了解此项」打开时被点到的那一节，底色 `--accent-soft` 60%，向外扩 6px，进入时用 `--dur-hover` 过渡；「高级」用 `mw-collapsible`；末尾「还差一步」与正文用一条 `--line` 分开，标题＋一句说明＋一个主按钮。帮助读不到时换成 `mw-empty--error` 加「再试一次」。
- 帮助卡片（方案 A）：
  - 宽 380（不超过窗口宽减 24），最高 `min(62vh, 520px)`，正文自己滚动；头（标题＋关闭）和脚（「Esc 关闭」＋「在右栏继续看」）固定；「还差一步」放在正文和脚之间、不随正文滚动，所以 1024 下卡片 460 高时也一直看得到。
  - 位置：表单右侧放得下 380 就放右侧，顶边对齐入口；放得下 300～380 就收窄到放得下（1024 时是这种）；都放不下才放在入口下方。底边不低于底栏上方 84px。
  - 760 及以下：左右各留 8px、底边在底栏上方（124px）的半屏，最高 50vh，从底栏升起（`craft-rise-from-bar`）；「在右栏继续看」收成头里关闭按钮左边的图标按钮，「还差一步」只留标题和按钮。打开时页面底部加出与卡片重叠部分一样高的空白，「每次运行会」和「保存并启用」都能滚到卡片上方。
  - 进场 `craft-drop`，时长 `--dur-move`；减少动态效果时没有动画。层级在外框浮层之上、原型条之下（原型里记为 `--help-layer-card`）。
- 三种宽度（1440、1024、390）、中英文、浅深色各画一遍。英文下标题与按钮更长，卡片宽度不变、标题省略。

## 开工前检查（需求开发流程第 4 节）

| 项 | 结论 |
| --- | --- |
| 事实主人 | 帮助的呈现与措辞归视觉体验需求；准备、采用与恢复归 Onboarding；模型连接归设置 › 模型；定时任务的内容归 Schedule。本稿不新建事实 |
| 插件同等待遇 | 帮助入口与内容由各插件按同一公开规范提供，平台不为某个插件另写帮助；第 40 批落地时要给插件声明帮助内容的位置（那时再核合同） |
| 能力注册一次、合同 | 本稿只定样，不改动作、Manifest 或导出 |
| 放在哪个包、表与存储 | 只有 `docs/design/` 下的原型；「跳过的提示不再出现」只是界面偏好，第 40 批实现时由现有引导 owner 承接，不建第二套完成标记 |
| 兼容与迁移、升级与数据 | 不涉及 |
| 安全边界 | 看帮助不授予权限、不改任务状态；外发、费用在帮助关着时也看得到 |
| 调用次数 | 帮助内容随页面一起给，打开不另发请求；读不到时只重试帮助本身 |
| 成果与过程项、页面与外壳 | 帮助在工作台的位置里（卡片、右栏、页内），不出整页、不开新标签页 |
| 错误码、冲突面 | 不涉及；只新增 `docs/design/on-demand-help/` 一个目录 |
