## 1. 背景

来源：MISC「T-136 二审 建议（6537161974）」的 `plugin-projects-service.ts` 一半（T-136 已合入）。

`apps/local-host/src/plugin-projects-service.ts:22-31`：
```ts
export function pluginProjectsPort(home: string): PluginProjectsPort {
  return {
    async existing(ids) {
      const catalog = pluginCatalogFor(home);
      if (!catalog) throw new ActionError("actions.unavailable", "项目目录暂时读不到");
      const present = await catalog({ homeDirectory: home }, projects => new Set(projects.listProjects().map(project => project.project_id)));
      return new Set(ids.filter(id => present.has(id)));
    },
  };
}
```
`catalog(...)` 读项目目录库，库打不开或读失败时抛出的是 SQLite／文件系统的原生错误（信息里会带库的本机路径等）。这个 `existing()` 被 `services.projects` 的客户端（含沙箱经 broker）调用，非 `ActionError` 的错误原样交给了插件。函数头注释写的是「读不了就什么也不说」（读不了不能报 id 已不存在），所以对插件应只露出 `actions.unavailable`。

同样的写法还在 `apps/local-host/src/plugin-terminal-service.ts:105` 附近，但那个文件被 #1654、#1643 锁着，本单不动，留在 MISC。

## 2. 目标

1. `existing()` 里把 `catalog(...)` 包起来：`ActionError` 原样抛，其它错误转成 `new ActionError("actions.unavailable", "项目目录暂时读不到")`；原错误只进宿主自己的日志／诊断出口——先 `git grep -n -E 'diagnostic|stderr|reportError|logError' -- apps/local-host/src | head -20` 找 local-host 里现成的出口，沿用；找不到合适的就**停下来问**，不要新造日志器，也不要 `console`（门禁数 `console`）。
2. 新用例 RAC-2735：让项目目录库读失败（用 `port`／可注入的 `pluginCatalogFor`，或在临时 Home 里把 `projects` 库弄坏，沿用 `tests/` 里现成的做法：`git grep -ln pluginProjectsPort -- tests` 以及 `git grep -ln 'services.projects' -- tests`），断言插件拿到的是 `actions.unavailable`，且错误信息不含库的路径。
3. 新用例 RAC-2736：读失败时**不**把任何 id 报成「已不存在」（保住函数头的承诺）。
