# Goal 画布工作区

状态：2026-09-12 已按用户反馈完成 Goal 信息浮窗和操作精简，完成等级 3。本文件是本次实现的唯一需求书；早期方案中的固定右侧详情和展开后可拖动均失效。不再修改示意图。

## 目标与完成等级

交付等级 3：本地功能可用。项目主工作区是可平移、缩放的 Goal 依赖画布；点击 Goal 直接展开为当前 Goal 工作区，默认占主内容区大部分面积，保留约 18px 边距。左侧保留项目切换和目标列表。展开状态固定，角落收起后恢复之前的画布位置、缩放与节点布局。

展开内部左侧默认 70%，真实 Runtime 终端占满高度；右侧 30% 顶部为类似 Codex 环境信息的可收起 Goal 浮窗，下方为时间线。浮窗不遮挡终端输入。分隔线可拖动、可键盘调整，比例按项目与 Goal 保存在本机。一次阅读一个展开 Goal，切换复用工作区；各 Goal 的终端由已有 Work 模块独立持有。

## 当前证据与影响面

- `apps/workbench/src/scripts/client/editing-graph.ts` 的 `setWorkspaceMode` 令图、详情、终端互斥。
- `plugins/native/goals/src/momentum-viewport-client.ts` 使用有限滚动区；图的 fit 只按宽度；`momentum-ui.ts` 把节奏统计、队列和图混在一起。
- `event-document-ui.ts` 是顶部摘要、左时间索引、右事件正文，并有成果/决定筛选；不符合已确认的整条时间线。
- `event-document-model.ts` 的列表状态和详情 `currentJudgment` 可给同一空白 Goal 不同判断；配置类型或无阻塞并不证明正在执行。
- Work 终端已有按 Goal 分组、显式打开、断开恢复及 resize 行为，不能在每次详情刷新时销毁其 DOM 或改变绑定。

## 场景与行为

1. 项目/Goals 入口显示真实当前 Goal 图；直达 Goal URL 展开该 Goal。空项目显示创建入口，加载失败有就近重试。
2. 依赖箭头从产出提供者指向消费者，保留已完成节点；父子归属用文字分组/归属说明表达，不伪装成依赖。点击列表与节点进入同一 Goal。图不承担依赖编辑或自动排期。
3. 空白拖动画布，滚轮平移，Ctrl/Command+滚轮缩放，按钮放大/缩小/适应全部。紧凑节点可拖动，仅保存本地布局；展开节点、表单、终端、时间线的拖动不移动画布或 Goal。
4. 右上 Goal 信息浮窗显示目标、预期结果、当前状态、真实要求进度与待确认，可收起。移除终端上方重复的 Goal 标题/状态；真实 TUI 初始未打开就是空状态，绝不自动启动或发送。
5. 右侧时间线按时间整合全部事件。成果、关注/阻塞、待决定、决定结果、普通记录有可识别的文字和色标。点击时间点在该条下阅读正文；不再切换成果/决定筛选或独立正文列。更早记录可加载；失败可重试。
6. 时间线保留单一「记一笔」入口，展开后用短说明区分「随手备注」（保存想法、事实）、「同步进展」（更新当前进展与下一步）、「问题与风险」（记录或处理影响完成的问题）；沿用已有表单和保存契约。Goal 信息内保留目标/完成要求、按需出现的待确认及继续动作；记录配置改名「记录模板」并移入更多菜单。移除「设为当前 Goal」入口和对应前端处理，不改后台当前目标协议。普通备注不等于给 AI 发送指令。
7. 表单、详情读回失败、版本冲突继续走现有安全 API；成功写入后读回真实状态。自动刷新不得覆盖正在编辑的表单，切换 Goal 不得把旧异步响应画到新 Goal。
8. 窄屏仍可在列表与工作区之间返回；展开保持边距，内部变为上下排列，允许分别滚动，避免挤压终端与时间线。
9. 阅读器/表单打开后，焦点进入当前内容；被覆盖的终端不参与键盘操作，桌面仍可见的 Goal 信息与时间线保留可操作。窄屏全区域覆盖时同时隔离信息与时间线；返回时恢复到可见触发入口，记录菜单关闭后恢复到「记一笔」。761–1180px 终端仍归属左侧全高网格，不复用旧浮层布局。

## 本次精简的验收增量

当前问题证据：Hero 占用左侧大段高度；同一 Goal 标题/状态又在 Terminal 头部出现；五个同级按钮混合了配置、阅读和写入。用户明确要求改为 Codex 环境信息式浮窗、扩大 Runtime、简化操作并去掉设为当前 Goal。

保持画布、固定展开/收起、默认宽度比例与拖动持久化、时间线正文、真实终端归属及所有写入契约。只调整 Goal 文档渲染/样式/交互文案、前端废弃动作、定向测试与设计说明；不改数据库、后台 active API 或已安装 App。

验收：桌面 Runtime 高度接近整个展开内容区；Goal 信息处于右上且可收起，收起增加时间线空间；记一笔菜单通过真实点击/键盘进入已有表单并可返回，备注/进展/问题写入仍能读回；信息与编辑焦点隔离遵循实际遮挡；窄屏无横向溢出且信息默认收起；界面不再出现设为当前 Goal。验证命令沿用下方构建与受影响浏览器测试。本轮结果：全部通过。全仓构建通过；最后调整后 Goals 与 Workbench 包构建通过；15 项受影响检查通过（7 项浏览器回归、8 项文档渲染单元）。桌面实测 Runtime 全高，收起信息增加时间线空间且不重建终端；窄屏默认收起、展开与表单返回正常；三类记录保存和读回通过；归档恢复保留历史，浏览和更多菜单不再修改 active Goal。

## 模块、输入输出与边界

- Workbench `goals-page-renderer.ts`、`scripts/client/*`、新增画布组合样式：页面位置、入口、展开/收起和 Runtime / 信息时间线的 70/30 组合。保留其他 Feed / 来源 / Sessions / 设置。
- Goals `momentum-ui.ts` / `momentum-client.ts` / viewport：消费既有 GoalMomentumView，渲染真实节点和边，输出本地视图状态；不新增后端协议。
- Goals `event-document-*` / timeline：消费现有 state 与 history 接口，调整摘要、动作和事件展开；原提交与鉴权/幂等/版本契约不变。
- Work terminal DOM 与 controller 复用；只去除已经失效的「返回聚焦」表现，终端进程生命周期不由收起动作控制。
- 只改本任务文件，已有项目设置/删除/引导改动保留。文档更新真实实现，不修改已交付 HTML 示意。

## 非目标与取舍

不更换渲染框架、不引入图依赖、不开发新 Agent Chat、不做关系拖线编辑、不改数据库/权限/完成算法、不发布安装包。仅一个活跃展开工作区，避免重复渲染同一终端与表单；多个 Goal 可以从列表切换且终端会话仍由原模块保留。
