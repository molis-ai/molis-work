# Molis Work 一键启动脚本方案（v5：向导式界面）

## 交互形态（本次核心变化）

不再用命令行参数，改成**安装器风格的逐步向导**：`pnpm start` 后出现菜单和确认项，方向键选择、回车确认，每步给默认项，一路回车即可完成启动。实现用轻量库 `@clack/prompts`（新增为根 devDependency；若不想引依赖可换手写 readline 菜单，界面简陋些）。非 TTY 环境（管道/CI）自动跳过向导、按默认值直启，原有 flags 保留作为自动化逃生口。

```
┌  Molis Work 启动向导
│
◆  启动目标？
│  ● 桌面端 App（推荐）
│  ○ Web 服务（浏览器访问 127.0.0.1:4173）
│
◇  检测到正在运行的实例
│  · 常驻服务 LaunchAgent（PID 1234，占用 4173）
│  · 桌面端旧实例（PID 5678）
│  · MCP 进程 ×2（仅提示，不清理——kill 会打断对话中的 Agent）
│
◆  清理以上实例后重新启动？
│  ● 是，清理后启动（推荐）   ○ 跳过清理
│
◆  检测到构建产物落后源码，重新构建？
│  ● 重新构建（推荐）   ○ 跳过，直接启动
│
│  清理完成 ✓   依赖完整 ✓   构建完成（12.3s）✓
│  桌面端启动中… 等待 web 子进程就绪
└  已就绪（3.2s）——窗口已弹出
```

向导步骤：① 选目标（默认桌面端）→ ② 展示检测到的实例并确认清理 → ③ 构建产物异常时确认是否重建 → ④ 汇总确认并执行，执行阶段用 spinner 逐步报告进度和耗时。依赖缺失、dist 缺失这类「没得选」的事项不提问，直接自动补齐并告知。

## 各入口定位（同前）

| 入口 | 形态 | 脚本负责 |
| --- | --- | --- |
| 桌面端（Tauri） | 常驻 App，自带 web 子进程 | ✅ 默认目标 |
| Web（4173） | 常驻 HTTP 服务 | ✅ 可选目标 |
| CLI | 一次性管理命令 | ❌ 不启动；清理时借用 `service` 子命令停常驻服务 |
| MCP | Runtime Session 启动时自行拉起的 stdio 进程 | ❌ 不启动不清理，只报告数量并提示重开 Session |

MCP 与主服务共享 `~/.molis-work` 数据库、进程内直连；Web(4173) 为可选查看/确认界面。重装后新 Session 自动用新代码，旧 Session 的 MCP 保持旧代码直至重开。

## 新增/修改文件

1. **新增 `scripts/start.mjs`**（向导 + 执行逻辑，纯 ESM Node）
2. **根 `package.json`**：加 `"start": "node scripts/start.mjs"`；devDependencies 加 `@clack/prompts`

## 执行逻辑（向导背后做的事，同 v4）

1. **检测**：LaunchAgent 是否安装且在跑、4173 是否被占（lsof 定位 PID）、桌面 App 是否在跑（pgrep）、MCP 进程数、`node_modules`、`dist/web/pty-client.js`、dist 与 src 新旧。
2. **清理**：常驻服务优先 `molis-work service` 子命令停止（否则 `launchctl bootout`），端口残留进程 kill，桌面旧实例退出；每步打印。
3. **补齐**：`node_modules` 缺失自动 `pnpm install --frozen-lockfile`；`dist/web/pty-client.js` 缺失自动 `pnpm build`。
4. **启动**：桌面端 = 确认 cargo 存在后 `cargo run --manifest-path apps/desktop/src-tauri/Cargo.toml`（编译进度透传）；Web = 子进程跑 `tsx apps/desktop/launchers/web/server.ts`，透传 home/port 与 `MOLIS_WORK_HOME`，信号转发。
5. **就绪**：轮询 `http://127.0.0.1:<port>/` 到 200（60s 超时报错）；Web 模式默认 `open` 浏览器（向导里给开关），桌面模式等 web 子进程健康后报「已就绪」。
6. **退出**：Ctrl+C 转发信号给子进程，干净退出无残留。

保留 flags（`--web/--port/--home/--build/--no-clean/--no-open/--no-install`）仅供非交互场景，向导是默认体验。

## 非目标

不做预热/缓存性能优化（另开一轮）；不常驻启动 CLI 和 MCP；不改变 service 生命周期语义。

## 验收标准

1. `pnpm start` 出现向导界面，一路回车（全默认）能完成：清理 → 起桌面端 → 窗口可用。
2. 向导正确展示检测到的运行实例，选择清理后连续两次 `pnpm start` 不出现双实例/端口冲突；LaunchAgent 不会被 kill 后又被拉起。
3. 选 Web 目标时健康检查通过并打开浏览器。
4. 依赖/dist 缺失自动补齐；dist 落后时向导询问重建。
5. 管道调用（非 TTY）时跳过向导按默认直启，flags 生效。
6. Ctrl+C 干净退出，无残留进程。
7. `pnpm typecheck` 通过，不影响现有测试。
