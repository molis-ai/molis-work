## 81 · Alchemist 与 CGS 场景

- **阶段／类型**：4；产品线（创作台、场景）；横向能力
- **具体交付**：**Alchemist 与 CGS 场景**（用户 2026-11-03 定同批）：Alchemist 完整场景——方向、候选、Brief、两条 Lens、结构化生成、真实证据、同版本决策、偏好／研究做法边界、讨论／注释、活动与导出；CGS 自媒体创作场景——盘点 CGS 分支，七项创作 Skill 改成内容技能包，用同一场景组装能力配成「带材料讨论→比较候选→定主稿→出各平台稿」的场景，插件本体按 [决策记录](decisions.md#section-7) 第 14 项的决定做或不做
- **需求来源**：[创作台 §4／PBU-07～08][PBU]、[Prologue 结构化生成][PAD]、[CGS 原需求][CGS]、[技能包][SKP]
- **前置／待决**：61、76、77；CGS 另依赖 41 与 [决策记录](decisions.md#section-7) 第 14 项；两个场景互不等待；记忆依赖仅在原边界允许时接入
- **可并行项**：83 的 Coding 交互计划设计
- **UI 要求**：先定样：完整研究与决策旅程；CGS 创作与出稿旅程

## 89 · 整条路线最终交付对账

- **阶段／类型**：全程收口；体验与效果；横向能力
- **具体交付**：**整条路线最终交付对账**：逐项对照全部原需求、Backlog、实际功能目录及近期新增需求；核实现、工程验证、真实操作、本人验收、全部插件／入口覆盖与保留缺口；未完成项继续归原任务，暂停或未批准项保留原状态，不以排期表填满结项；按 [近期 PR 来源对照](requirement-prs.md#recent-requirement-prs) 的 PR 对照逐项核最终合入内容，条件项 BL-925 未触发则保持待触发，不冒充漏做或完成；[服务端批](server-batch.md#server-batch)服务端批单独记状态，未开工的记作未开工
- **需求来源**：[路线图维护][R]、[Backlog][BL]、[产品治理][PFG]、[文案帮助][VUX]、[引导][ONB]、[智能呈现][IUI]、[主线][MLN]、[升级持续可用][UPG]及各原需求书
- **前置／待决**：所有已纳入交付的批次完成；暂停／未批准条件项明确保留状态
- **可并行项**：无
- **UI 要求**：无需新设计；未解决交互缺口仍算未完成
