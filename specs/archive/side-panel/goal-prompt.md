# 平台侧栏 Goal Prompt

用户 2026-09-30 设定，并授权：“我授权你持续推进，遇到决策点，从大局角度考虑，按你推荐方式推进即可”。

把"项目讨论"使用的右侧分屏发展为平台级侧栏。用户不离开当前工作，就能在同一个分屏里使用浏览器、查看助理工作和各插件中的文件、参与项目讨论，并看着助理在浏览器里完成操作、随时接手。侧栏是平台能力：插件可以按统一约定向其中提供内容，而不需要平台为每个插件增加专属逻辑。

最终应达到以下状态：

1. **一个侧栏，承载多种内容。** 右侧分屏以标签承载项目讨论、浏览器、文件预览以及插件提供的内容，延续已确认的分屏体验：左侧工作真实让出宽度而不是被覆盖，可以拖动和用键盘调整宽度，收展动效连贯，窄屏改为上下分屏，不提供全屏聊天或遮罩。一次看一个标签；切换标签不重复整个入场动效，也不丢失各标签自己的状态（讨论草稿与阅读位置、浏览器当前页面、文件的阅读位置）。收起再打开恢复原状。

2. **从正在做的事自然打开。** 右下角入口保留。助理开始浏览网页、用户在助理对话里点开文件、插件请求展示内容时，侧栏打开并切到对应标签。打开侧栏不改变当前路由，不抢输入焦点；Escape 与收起按钮的行为一致、可预期。侧栏与底栏、助理面板的几何关系清楚，互不遮挡。

3. **内置浏览器可以真实使用。** 用户可以在侧栏里输入网址、前进后退、刷新、点击和输入，始终知道当前在哪个网站。它的登录状态与用户自己的浏览器分开，并且如实说明。页面打不开、被拒绝或浏览器崩溃时，有看得懂的状态和恢复办法。桌面应用和本地网页模式都能用。

4. **助理能在浏览器里动手，用户始终看得见、管得住。** 助理可以观察当前页面，点击、输入、打开网址、上传和下载文件；用户在侧栏里实时看到它在做什么，可以随时暂停、停止或接手，接手后也能交回。操作按网站授权：可以只允许这一次，可以允许这个网站以后不再询问，也可以禁止某个网站，禁止后连看都不行。向网站上传本机文件算对外发送，必须确认，并且看得到发的是哪个文件；敏感路径一律拒绝。页面跳走或换了网站之后，不会拿旧的观察结果去点新页面。截图按策略处理后才交给模型。本次范围是侧栏里的浏览器；操作电脑上的其他应用不在本次范围内，界面上也不暗示可以。

5. **把网页交给助理。** 用户可以把当前页面或选中的部分作为材料交给助理。材料带来源和时间，可以被引用，不需要靠截图来读文字。

6. **助理工作里的文件可以就地查看。** 对话附件（文本、PDF、图片）以及工作的起点、材料和成果，都能在侧栏里预览，也能跳到所属插件继续编辑。已经失效的附件（例如重启后失效的图片）如实标出，并给出补救办法。文件清单和预览怎么分工与助理面板保持一致，不出现两份互相竞争的清单。

7. **插件的文件可以统一查看。** 有文件的插件（例如 Files、Coding 工作区、Pages、Artifacts）按统一约定说明自己有哪些文件；侧栏用一致的方式列出、预览并跳回插件。没有文件的插件不出现空入口。权限和项目边界照旧：原本看不到的项目和对象，不会因为侧栏而变得可见。

8. **侧栏是平台能力，插件可以扩展。** 插件在清单里声明侧栏内容。简单情况只声明文件来源，由平台统一显示；需要时可以提供一整块自己的侧栏界面，和其他插件界面一样在隔离环境和授权范围内运行。插件声明会操作哪些网站时，安装时展示给用户。这些声明随插件的安装、启用、停用、升级和卸载而生效或撤下。插件不能自己决定侧栏的位置和尺寸，也不能借侧栏越权。这套约定写进插件开发手册并纳入自动检查。

9. **充分并正确地使用 Prologue。** 观察和操作界面用 Prologue 已有的界面控制能力，包括它的策略、审批、执行回执和截图脱敏，不在 Molis 里另造一条绕过策略的通道。网页摄取用 Prologue 的资料源能力。需要补充 SDK 时，在当前 SDK 版本线上改，main 里始终只有一条 SDK 版本线。实际用上了哪些 Prologue 能力、哪些仍没接通，在能力对照表里如实更新。

10. **体验达到内部完整。** 明暗主题、键盘与读屏等辅助技术、中文输入法、1440/1024/800/390 各种宽度、长内容和异常状态都能顺畅使用；动效遵守现有设计规范，尊重"减少动态效果"的设置。项目讨论现有的能力不退化。

验收以真实操作为准，至少包括：从右下角打开侧栏并在讨论、浏览器、文件之间切换且收起再打开后状态保留；用户在侧栏浏览器里登录并使用一个真实网站；助理在侧栏浏览器里完成一件多步任务、提交前停下等确认、中途用户接手再交回；按网站允许和禁止都生效、上传需要确认；把当前网页交给助理并被助理引用；从助理对话里打开 PDF、图片和成果并跳到所属插件；查看 Files、Coding、Pages 里的文件；一个新插件只靠声明就向侧栏加入文件来源和自己的界面、停用后自动撤下；在手机宽度和深色主题下走通上面的主要流程。所用的浏览器、模型、Prologue 和网站都必须是真的；没支持或没验证的部分明确写出来。

完成的判断是：用户在同一个地方就能看资料、看文件、上网、让助理动手，不用在不同应用之间来回切换；同时始终清楚助理在哪个网站做了什么，并能随时拦下和接手。工程通过、真实场景通过和用户本人验收分别如实记录；不能把能演示或局部可用当作完成。
