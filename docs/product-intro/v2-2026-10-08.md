---

Molis Work 是装在你电脑上的工作平台，由一个平台和一组插件组成。平台管宿主、能力目录、授权和 AI；目标、会话、信息流、文档、待办、代码这些内容各由一个插件提供，项目里只加要用的。内置助理和 Claude Code、Codex 这些外部 Agent 经同一个能力目录、同一套授权使用这些插件，做没做完可以核对。

这版按 main 最新代码核对（1cdb31d，2026-10-08）。公开版本仍是 v0.2.0（9/11），只含四个插件：Goals、Work（现在叫 Sessions）、Feed、Artifacts（现在叫成果）。下一版已定为 0.3.0，还没发。所以下文的状态一律以「用户现在能不能下载到」为准。

顺序沿用 V1 的「场景 → 功能 → 竞品」，前面加一节「平台和插件」。读者先知道这是一个平台、能装哪些插件，后面读每个场景时，就知道它落在哪个插件上。

## 一句话与目标用户

对外一句话沿用：**让工作，在人、工具与 Agent 之间继续。** 它背后是四件事：

- **一个平台，按需加插件。** 平台负责常驻宿主、能力目录与授权、工作台和 AI 运行时；目标、会话、信息流、文档、待办、代码由插件提供，项目里只加要用的。
- **每样东西只有一个主人。** Goal 归 Goals，待办归待办，文档归 Pages，固定下来的版本归成果库。插件之间不复制彼此的内容，助理和搜索打开的都是原处的当前内容。
- **能力只登记一次。** 每个插件把能力登记到同一个目录，页面、助理、工作流和外部 Agent 都从这里调用，权限在一处管。
- **数据在你的电脑上。** 一个 Home、一个常驻宿主，浏览器和 macOS App 打开的是同一个工作台。

先给谁用，按优先级排：

| 用户 | 他们现在的状态 | 最先用到 |
| --- | --- | --- |
| 同时用好几个 AI 编码工具的独立开发者、技术负责人 | 今天用 Claude Code，明天换 Codex，一个项目跨几十个会话 | Goals、Sessions、Coding、MCP 接入 |
| 产品负责人、研究和内容工作者 | 每天看大量资料，要写方案和周报，还有一堆琐事要跟 | 个人助理、Feed → Inbox → Pages、待办、Jelly |
| 小团队里牵头的人 | 要知道每件事卡在哪、等谁拍板 | Goals 的依赖画布和决定中心 |

团队空间、成员权限和多设备同步还在规划，所以首发只对个人讲，小团队写成「牵头的那个人」。

## 平台和插件

这一节可以直接做成官网「它由什么组成」的区块。

**平台**每个 Home 一份，所有插件共用：

- **一个常驻宿主。** 数据、插件、能力目录和 AI 都由它管；浏览器、macOS App、命令行和 MCP 都连到它，不各跑一份。
- **一个能力目录、一套授权。** 插件把能做的事登记一次，页面、助理、工作流、外部 Agent 都从这里调用。授权按调用方逐个给，调用留记录。
- **一个工作台。** 底栏、侧栏、⌘K 搜索和设置各只有一套。插件只提供内容，挂在工作台的位置上，不另开整页，也不开第二个浏览器标签页。
- **一个 AI 运行时。** 模型、密钥、预算配一次，助理、插件和 Agent 共用。
- **跨插件的服务。** 个人助理、记忆、搜索属于平台。它们向各插件读内容，不拥有插件的数据；搜索的索引只是可以重建的缓存。

**插件**在 main 上内置 26 个：

| 类别 | 怎么用 | 插件 |
| --- | --- | --- |
| 项目插件（11 个） | 在每个项目里按需添加、移除；Goals 每个项目都带 | Goals、Sessions、Inbox、Feed、Schedule、成果，以及 Coding 一族（Coding、Files、Git、Diff、Text stats） |
| 个人插件（15 个） | 在所有项目里都开着；某个项目用不上，可以在那个项目里隐藏 | 待办、Jelly、灵光、Pages、Forms、Dataset、PPT、图片、Cognia、Shelf、炼金术士、实验、工作流程、插件创作台，以及角色 |

角色在界面上一直是「设置 › 角色」。10/8 已定把它并进平台的设置，之后不再算插件，届时个人插件是 14 个。用插件创作台做的插件也装进项目，和内置插件一样只经能力目录被调用。第三方插件还不能装，见功能全景的最后几行。

## 八个场景：什么场景下的什么问题

每个场景都能直接做成官网的一个区块：小标题当区块标题，「麻烦」是让读者认出自己的那句话，「怎么做」是正文。例子都是示意，不是客户案例。

### 1. 按需拼一个自己的工作台

- **场景**：一个项目只管目标和代码，另一个要盯信息流、写周报；日程、笔记、待办哪个项目都要用。
- **麻烦**：每件事一个 App，各管各的账号和数据，AI 只进得了其中一个；什么都有的大工具，又塞满你用不上的东西。
- **怎么做**：
  - 在底栏的插件选择器里给项目添加或移除插件，当场生效，不用刷新页面；常用的钉在底栏。
  - 个人插件在每个项目里都在，日程、笔记、待办不用每个项目各建一份；某个项目用不上，就在那里隐藏。
  - 一个插件离不开另一个插件的产出时，添加它会把那个插件一起加上。
  - 所有插件用同一个底栏、侧栏、⌘K 搜索和助理。插件之间交东西，交的是固定下来的一版或一份交接数据，不去改对方的内容。
  - 缺的插件可以自己做，见场景 7。
- **用到**：插件选择器、底栏、侧栏、成果库。main 未发版。

### 2. 换了工具，工作不用从头讲

- **场景**：周一用 Claude Code 搭好登录页，周三换 Codex 接着做支付，周五回来，两边对“做完了”的理解并不一样。
- **麻烦**：每个 AI 工具只记得自己的会话。换工具、隔几天回来，都要重新交代背景；AI 说做完了，你没法核对。
- **怎么做**：
  - 要达成什么、做成了什么、还差什么，记在 Goals 插件的同一个 Goal 里，每个项目都带 Goals。
  - Codex、Claude Code、OpenCode、Pi Agent、Grok Build 有内置接入，其他 Agent 经 MCP 读写同一份 Goal。
  - Agent 可以提新需求，不能悄悄改掉你认可的目标。“完成”要过显式收尾，核对当前要求、依据和阻塞。
  - 每天打开先停在项目选择页：上次的项目已预选，看得到当前目标、等你确认的事和助理在做的事，回车就接着做。
  - 收尾时选这次交付了什么：成果库里已有的一版，或者把文档当场固定一版。助理和 Coding 可以提议，由你确认，Goal 页上看得到交付物。
- **用到**：Goals、Sessions、依赖画布、决定中心、绑在 Goal 上的终端、菜单栏当前 Goal、项目选择页、成果库。核心已发版（v0.2.0）；新界面、项目选择页和交付物在 main，未发版。

### 3. 放心让 AI 动手

- **场景**：你想让 AI 改文档、建待办、开 PR，但不想事后才发现它动了什么。
- **麻烦**：AI 能动哪些东西说不清；改错了撤不回；在一个入口关掉权限，另一个入口照样能写。
- **怎么做**：
  - 所有插件的能力登记在同一个目录，页面、助理、工作流、外部 Agent 都从这里调用。
  - 权限按调用方、按每个 MCP 客户端逐一授予。外部 Agent 只看得到你授权给它的能力，每次调用留记录。谁在调用由宿主按连接认定，不看 Agent 在输入里怎么说。
  - 写文件、跑命令、推送先进审查队列；能撤销的操作直接做，做完给你撤销。被取消或撤权的调用，不会再写入任何数据。
  - 助理在侧栏浏览器里操作网页时，点击、输入这类操作逐步确认，你随时能接手。停下或关掉总开关，浏览器立刻交还给你。
- **用到**：统一能力目录与 MCP、审查队列、撤销、侧栏浏览器。main 未发版。

### 4. 一个看得见你在做什么的助理

- **场景**：你在 Pages 写周报，想让助理把 Inbox 里三条客户反馈整理进去，再顺手建两个待办。
- **麻烦**：通用聊天助手看不到你正在做的东西，要复制粘贴；它给建议，执行还得你自己来；提醒要么没有，要么太烦。
- **怎么做**：
  - 底栏助理在任何页面都能叫出来，知道你在看哪一页、选中了哪段。
  - 用 @ 引用内容、用 / 选能力，能读 PDF 和图片。
  - 它的建议是点一下就执行的操作卡。它会跟进到期的事，也守你定的勿扰规则。
  - 记忆看得见、改得了、删得掉。
  - 复杂的事拆给子任务并行做，写代码的部分交给 Coding。
- **用到**：个人助理、操作卡、记忆、主动提醒、待办、Jelly。已合入 main，未发版，等你验收。
  - 合入后审查用真实模型走过，出现过嘴上说做了、实际没调用的情况，已加拦截（#151），所以官网不写「说到做到」。
  - 10/8 又修了 5 处（#311），包括撤销会被执行两次、归档后定时还在跑。

### 5. 信息很多，只把要处理的送到面前

- **场景**：你订了十几个 RSS，关注几个 GitHub 仓库，每天几十封邮件，月底要交一份行业观察。
- **麻烦**：来源各看各的，重要的漏掉；写的时候找不回出处。
- **怎么做**：
  - RSS/Atom、网页查询、YouTube、GitHub、Gmail 的内容统一进 Feed。
  - 按规则把需要你介入的送进 Inbox，并写明为什么进来。
  - 选中的材料交给 Pages，写成带来源的文稿。
  - 外部内容一律当资料，不会变成给 AI 的指令。
  - 删来源时可以保留历史；选「连同本地历史删除」，没有别处再用的缓存正文也一起删掉。
- **用到**：Feed 与来源已发版；Inbox、Pages、Schedule 在 main，未发版。合入后审查用真实模型走通了「Feed 新资料 → Inbox → 转待办 → 放进项目 → 搜索打开」。

### 6. 第一天就有内容，以后都找得到

- **场景**：刚装好，不想先填一堆设置；用了一个月后，记得写过「Q4 预算」却想不起在哪。
- **麻烦**：新工具第一天是空的，要自己搬资料、建项目；工具一多，东西散在各处。
- **怎么做**：
  - 勾选要接入的来源并授权，AI 整理出带来源的工作总结、项目建议和待办草稿。采用后生成项目，并从待办开始；不要求先写 Goal 或配 Agent。
  - 之后按 ⌘K，能搜到所有插件里的内容，包括没打开过的；两个字的中文、Q4 这样的短词也能搜。点开时由原插件核对，定位到命中处。
- **用到**：首次使用与新建项目（10/1 按新设计重做，#159）、系统搜索。main 未发版；真实 Gmail 链路验证过，第三方 OAuth 应用的正式审核是外部条件。

### 7. 缺一个顺手的工具，自己做出来

- **场景**：你想要一个“账单到期提醒”，表格太散，专门找软件又太重。
- **麻烦**：做个小工具要么得会编程；用一句话生成的网页应用又和你的资料、你的助理不相通。
- **怎么做**：
  - 在插件创作台描述需求，Agent 先给方案，再在沙箱里写代码，过宿主检查和浏览器验收后装进项目。
  - 做好的插件和内置插件一样，只经统一能力目录：助理、Coding 和外部 Agent 都能调用它，它也能读写 Goals、Inbox、Pages。
- **用到**：插件创作台。main，建议标「预览」：12 个真实需求里 4 个第一次就做成，修过问题后 12 个都至少做成过一次。

### 8. 写代码的会话，住在项目里

- **场景**：一个功能要改十几个文件，做到一半网断了，你也要去开会。
- **麻烦**：编码 Agent 的会话一断就散；几个会话各干各的，互相不知道。
- **怎么做**：
  - 在项目里开 Coding 会话，计划、子任务、中断和审查都在同一条任务记录里，停下后从断点继续。
  - 会话之间可以认领任务、互相发信。
  - 写文件、跑命令、push、开 PR 都先经你审查。
- **用到**：Coding、Files、Git、Diff。main 未发版。和 Claude Code、Codex、Cursor 比还差 20 项功能，见竞品一节。

## 和同类产品比

Molis Work 没有一个正面对手，它要替换的是用户现在拼凑的一套做法。所以仍按「用户现在拿什么凑合」分六类。这一版只按新定位改了「Molis 的不同」和「Molis 目前不如它」两列，竞品本身沿用 V1 在 10/1 的核对，上线前请再核一遍。

| 用户现在用的 | 代表产品 | 它擅长 | Molis 的不同 | Molis 目前不如它 |
| --- | --- | --- | --- | --- |
| 编码 Agent | [Claude Code](https://code.claude.com/docs)、[Codex](https://github.com/openai/codex)、[Cursor](https://cursor.com) | 写代码本身：读改代码、跑命令、子代理、计划，模型和工具链最成熟 | 不替代它们，而是接住它们：几家的会话推进同一份 Goal，换工具不丢上下文；“完成”不由 Agent 自己宣布 | 自带的 Coding 还差 20 项（斜杠命令、代码智能、联网、沙盒规则、VS Code 等），官网不对标它们写代码的能力 |
| 编码 Agent 的任务与规格工具 | [Task Master](https://github.com/eyaltoledano/claude-task-master)、[GSD](https://github.com/gsd-build/get-shit-done)、[OpenSpec](https://github.com/Fission-AI/OpenSpec)、[Beads](https://github.com/gastownhall/beads) | 轻：放进仓库就能用，命令行和文件贴近开发者，和多种编码 Agent 搭配 | Goal 写给人看，有依赖画布和决定中心；“阶段走完”不等于完成，要核对要求与依据；同一个工作台里还有会话、信息流、文档等插件，调研、内容这类非代码工作也能放进来 | 更重：要装应用、跑一个常驻宿主；对只想管代码任务的人不如它们直接 |
| AI 工作管理与知识库 | [Notion](https://www.notion.com)、[Linear](https://linear.app)、[Asana](https://asana.com)、[ClickUp](https://clickup.com)、[monday.com](https://monday.com) | 团队协作、多视图、成熟的权限与云同步；Notion、Linear 已有官方 MCP，编码 Agent 能直接读写 | 数据在本机；项目里只加要用的插件，缺的自己做；所有插件共用一个能力目录和一套授权，撤权后不再写入；Agent 只能提议、不能改掉你认可的目标 | 团队、多设备、手机上用都还没有；只有 macOS；生态和模板少得多，第三方插件还不能装 |
| 通用 AI 助手 | [ChatGPT](https://chatgpt.com)、[Claude](https://claude.ai) | 对话体验和模型能力强，联网、记忆、连接器都成熟 | 助理是平台的一部分，能调用每个插件登记的能力：看得到当前页面和选区，建议是点一下就执行的操作卡，改动可撤销；记忆存本机、可见可删；提示词全部可见可改 | 模型能力取决于你自己配的服务；关掉应用后定时任务和提醒不跑；助理还没经你验收 |
| 一句话做应用 | [Taskade Genesis](https://www.taskade.com/genesis)、[Lovable](https://lovable.dev) | 生成快，做出来的应用能部署、分享 | 做出来的是装在你项目里的插件：只经统一能力目录，助理和外部 Agent 能直接调用，能读写 Goals、Inbox、Pages；装前过门禁和浏览器验收 | 第一次做成的比例低（4/12）；不能发布给别人用 |
| 人和多个 Agent 的协作空间 | [OpenAgents](https://openagents.org/docs/en/workspace/what-is-workspace) | 人和多个 Agent 在同一个线程里协作，@ 一下就能委派；本机的 Agent 也能连进来 | 以 Goal 和各插件里的内容为准，而不是以聊天线程为准；完成有门禁；整个工作台和数据都在本机 | 多人协作已经是它的主线，我们只有早期的项目讨论 |

三点提醒：

1. Notion、Linear 都已提供官方 MCP，不能说“只有我们能让外部 Agent 读写”。
2. 仓库里的研究已经指出 OpenAgents 是直接近邻，“多个 Agent 一起干活”不是市场空白；要比的是结果能不能看懂、接续、核对。
3. 「插件平台」本身也不新，Notion、Obsidian、Raycast 都有自己的插件或集成生态。要讲的是插件之间守同一个能力目录和同一套授权，内置助理和外部 Agent 都能直接调用；不要只说「可扩展」。

## Molis 做了什么别人没做的

单看每一项，都能在某个竞品里找到近似的做法；少见的是下面五件事在同一个本机工作台里，守同一套规则。前两条是平台本身，后三条落在具体插件和助理上。官网可以写这五条：

1. **能力登记一次，四个入口守同一套权限。** 页面、助理、工作流、外部 MCP 客户端调用的是同一项能力，按调用方逐个授权，调用留记录，撤权或取消后不再写入。谁在调用由宿主认定，Agent 不能自称是你。外部 Agent 和内置助理没有两套规矩。
2. **每样东西一个主人，AI 用的是原处的内容。** Goal 归 Goals，待办归待办，文档归 Pages，固定的版本归成果库。插件之间不复制、不改对方的内容，交东西交的是固定下来的一版。助理经各插件的能力读写；搜索索引只是可以重建的缓存，点开时由原插件核对，所以打开的总是原处的当前内容。
3. **缺的工具自己做，做出来就能被 AI 用。** 生成的不是一个孤立的网页应用，而是装进项目的插件。它和内置插件守同一套规则，只经统一能力目录，助理和外部 Agent 马上能调用。
4. **一份目标，所有 Agent 共用，“完成”要核对。** 这是 Goals 插件做的事。内置接入 5 家编码 Agent，其他经 MCP。Agent 只能提议，不能悄悄改掉你认可的目标；完成要过显式收尾，报告条数、子 Goal 数量都不算数。收尾时记下交付的是哪一版，原文之后再改，也查得到当时交的是什么。多数任务工具里，标成完成是一次状态切换；Molis 把它做成一次核对。
5. **AI 怎么做事，你看得见、改得了。** 系统和每个插件的提示词、角色都在设置里可见可改，可以恢复默认，每次运行查得到用的是哪一版；记忆看得见、删得掉。这在 AI 产品里不常见。

「数据在本机」是这五条的底子，但不单独当卖点：Claude Code 这类工具本来就在本机跑。

比较时容易写过头的几句（完整口径见[「官网核心亮点」文档](https://claude.ai/code/artifact/a3272ef7-9969-4095-9a37-754a71b7c245)的「写作口径」）：

- 不说「唯一」「首个」，每一项单拿出来都有近似做法。
- 不说「替代 Claude Code、Cursor」，我们接住它们；也不说「支持所有 Agent」，写「内置接入 5 家，其他经 MCP」。
- 不说「本地模型」「离线 AI」，本地指数据和执行，模型仍调用你配置的服务。
- 不说「随时在后台工作」，关掉应用后定时任务和提醒不跑。
- 不说「自动派单」「替你分配工作」，产品明确不派单。
- 不说「插件市场」「海量插件」，第三方插件还不能装；写「内置 26 个，缺的自己做」。
- 不说「一键升级」「自动更新」「跨平台」：没有自动更新，v0.2.0 的数据不能直接带到新版本，目前只有 macOS。

## 给官网的建议

**页面顺序**，从上到下：

1. 首屏：一句话，加一行「一个平台，按需加插件」，再加内置接入的 Agent 名单（Codex、Claude Code、OpenCode、Pi Agent、Grok Build）。
2. 平台和插件：一张图，平台在下、插件在上，内容用上面那一节。
3. 三个主场景，选场景 1、2、3：
   - 1 讲平台怎么用，接住上一节；
   - 2 是唯一已发版的核心，也是开发者最先用到的；
   - 3 是平台机制，撑起后面所有功能。
4. 五条差异。
5. 次级场景卡片：场景 4–8。助理（场景 4）面向的人最多，放第一张。
6. 功能墙：直接用上面功能全景的分组。
7. 和你现在的用法比。
8. 本地优先与边界，然后结尾。

**竞品不点名。** 对 Claude Code、Codex 这类写成「配合使用」，名字出现在接入名单里反而加分。对 Notion、Linear 等，用「如果你现在用笔记或任务工具记 AI 做到哪了……」这样的说法，不做点名对比表。点名对比要跟着对方更新一直改，很快就过时；我们的差异在机制上，不靠比别人。上面的竞品表留作内部判断和常见问题的素材。

**上线跟下一次发版走。** 现在能下载到的 v0.2.0 只有四个插件，八个场景里用户只拿得到场景 2 和场景 5 的一部分。下一次发版要一起处理这几件事：

- **版本。** 10/8 已定只有一个产品版本，下一版是 0.3.0（[发版策略](../releases/POLICY.md)），变更记录已起草（[CHANGELOG](../releases/CHANGELOG.md)）。0.3.0 排在防腐路线第 5 波，发版日期还没定。GitHub Release 还叫「GoalBoard v0.2.0」，发 0.3.0 时改成 Molis Work。
- **旧数据。** 新版本的每个库只认当前版本，没有随发行的升级工具，所以 v0.2.0 的 Home 不能直接打开。按旧名写的 Runtime 接入也要重新接。发版说明和下载页要写清楚，官网不写「一键升级」。
- **装到别人的 Mac 上。** C 端就绪方案（10/8）列了四件用户会先撞上的事：
  - 没有公证，首次打开会被系统拦下；
  - 升级后打不开旧库；
  - 出问题没有能发回的诊断；
  - 核心 AI 包的再分发许可还没有书面答复。

  前三件是第一个里程碑，估 15–25 人日，另要等 Apple 开发者账号和证书。用谁的名义注册、更新清单放在哪，等你定（方案 §8 的 D8）。在这之前，下载按钮按实际状态写。
- **验收。** 统一待办清单里「待你验收」仍是 20 项；成果库这批也只差你验收，还没列进清单。
- **逻辑复查。** 10/7 按插件分区查出 63 条成立的问题（高 7、中 25、低 31），其中 10 个修复 PR 已在 10/8 合入。还在修的有四组：插件生命周期（#313，开着）、记忆、删除项目时清掉各插件里该项目的数据、助理的记忆工具。另外，问卷停止收集后拒绝非本人提交，要另外补一个修复。建议这些合入后，你再按八个场景亲自走一遍。
