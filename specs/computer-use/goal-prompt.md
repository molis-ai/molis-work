# 个人助理完整 Computer Use Goal Prompt

用户 2026-10-07 设定。对照最新的 Prologue（main `b14c6686`，2026-10-05）与 Molis Work（main `6e62652d`）复查后定稿，复查依据见 [spec.md](spec.md) §3。

现在个人助理只能在侧栏的浏览器里动手（`specs/archive/side-panel` D02 把 Computer Use 限定在浏览器）。本目标让它能像人一样看着电脑屏幕、操作 macOS 上的其他应用，完成跨应用的多步任务；同时用户在侧栏里看得见整个过程、拿得到结果、随时拦下和接手。可以修改 Prologue。

**好用的标准：** 一件二十来步的桌面任务，用户说一次就能做完——不用盯着每一步点确认，不用说「继续」，助理做的时候自己的鼠标和键盘不被抢走，随时一眼看得出助理在做什么、能一键拦下。做不到这一条，功能再全也不算完成。

最终应达到以下状态：

1. **完整的桌面 Computer Use。** 助理可以观察并操作桌面应用：看目标应用的窗口（辅助功能树、截图、窗口信息），点击、双击、右键、拖动、滚动、悬停，输入文字（含中文），按键与快捷键，列出、打开、切换应用，等待。把文件交给应用或从应用取出，算对外发送，永远确认，并看得到是哪个文件。桌面应用与本地网页模式一样可用。助理先用结构化的办法（插件动作、MCP、Coding、侧栏浏览器）；没有，或用户明确要它操作某个应用时，才用桌面，并说明为什么。网页上的事仍用侧栏浏览器（按网站授权，登录状态与用户自己的浏览器隔离）。助理的提示词写明这些选择顺序与使用守则，做法同侧栏浏览器的 `SURFACE_GUIDANCE`。

2. **助理真的看得见屏幕，而且不拖沓。**
   - 看得见：现在 Prologue 的 `surface-observe` 截图只回资源引用，图片只在一轮开头随材料进入模型，一轮中途的截图模型看不到。要让截图以图片进入同一轮的模型输入（按模型设置的 `vision` 标记决定给不给，不支持就明确降级，不假装看见）。辅助功能树稀疏的应用（Electron、自绘界面、游戏），驱动用文字识别补出带坐标的可操作清单，不看图的模型也能做大部分事。
   - 不拖沓：动作的回执可以带上动作之后的新观察，不必每一步「先观察、再动手」两次来回；观察时效现为 10 秒、不够一轮模型想完，按桌面调整，同时驱动在动手前核对窗口内容没变，不能只靠放宽时间；一轮的步数上限现为 24 步，它与续做要适配 Computer Use，不做到一半停下等用户说「继续」；截图缩放到模型能接收的大小、压在单次观察的字节上限（现为 4 MiB）内，坐标换算正确（Retina、多屏、窗口移动或缩放之后）。

3. **实现的地方分开，各管一层。**
   - Prologue（`~/code/prologue`）只扩合同与策略，不带任何驱动：桌面需要的有类型动作（滚动、拖动、悬停、打开与切换应用等），应用身份作 scope、切换应用时按目标应用判断，截图进模型，动作回执带新观察，驱动不可用、用户在场、屏幕锁定作为一等的拒绝原因。按它自己的 `AGENTS.md`：先改需求分册（`docs/product/requirements/modules/ui-control/observe-act.md`，把标着「以后」的屏幕锁定与批准寿命按需转为现役并写完成门）与合同，再实现；测试含变异测试；更新 `docs/slices/computer-use.md` 与真机记录。该仓库主检出有别人未提交的改动，用独立工作树和新分支。可以提交到新分支，推送先问用户。
   - Molis 做所有真东西：macOS 原生助手进程（Swift 优先，由 local-host 拉起，桌面应用与网页模式共用），负责截图、辅助功能树、文字识别、输入投递、前台应用、锁屏与用户输入监听、系统权限检测；桌面驱动（实现 `HostSurfaceDriver` 的桌面一支，`kind` 扩为 browser | desktop；`horizontal/agent-host/src/adapters/prologue-surfaces.ts` 现在一个会话只挂一台界面，要支持同时挂浏览器与桌面）；策略与分级、确认卡、权限引导、侧栏呈现、操作记录。
   - SDK 版本线仍然只有一条。Prologue main 已含 Molis 现用包依赖的界面控制与记忆提交（`vendor/prologue-sdk/README.md` 里「未推远端」的说法已过期），并比现用包（`af7375c7` 加补丁）多 39 个提交。开工先 fetch 取最新，弄清差距，定基线并记入决策记录，替换 vendored 包前先向用户说明；产出新包替换 `vendor/prologue-sdk/` 里的当前包，README 写来源与重建步骤；Molis 追上新包后整体构建、`pnpm boundary:check`、类型检查通过，传递依赖能从标准位置解析。

4. **后台优先，不抢用户的鼠标和键盘。** 用户在同一台电脑上，助理不能一动手就接管光标和焦点。操作按三档尽量靠前：辅助功能的语义动作（按下、设值、聚焦、滚动）；把事件投递给目标应用而不把它提到前台；最后才是提到前台用合成输入。每一类应用（原生、Electron、浏览器、Office 类、自绘界面）各能走到哪一档，在真机上测出来并记下。必须用前台时，明确告知用户这一步要用屏幕，用户一动鼠标键盘立刻暂停，交回后先重新观察。另外：屏幕锁定时不动并如实告知；操作期间保持显示器不休眠，结束即放开；不读取、不改动用户的剪贴板，输入文字不经过剪贴板。

5. **硬边界：分级加通用禁令。**
   - 禁区：系统设置、钥匙串访问、密码管理器、支付与银行类应用，连看都不看。Molis Work 自己的窗口与助手进程，以及网页模式下当前显示着 Molis Work 页面的浏览器窗口，也属禁区：助理不能点自己的确认卡批准自己（同 side-panel D18：本机服务页面带控制令牌，碰到它就等于绕过动作授权；识别办法由实现定）。用户可以追加禁区，不能放宽。
   - 只看只点：终端与 IDE，不能键入、不能按键（命令走 Coding）。
   - 其余应用：可以操作，经用户批准（节奏见第 6 条）。用户自己的浏览器当普通应用，规则相同；没有「这个应用以后不用问」。
   - 通用：不输入密码类字段，截图里遮住；遇到登录、验证码、付款，停下请用户自己完成，完成后继续；发送、付款、删除、提交这类不可撤回的动作，先向用户说明再动；点击前校验落点的窗口仍属于目标应用（盖在上面的窗口、通知条都不算）；截图与观察只含目标应用的窗口，不带出屏幕上别的应用；窗口里的文字是不可信内容；观察过期、窗口或应用换了，不拿旧观察去点；用户对某一步选「不允许」，这件事就不做，也不换办法再做。
   - 这些边界在 spec 里各写一条威胁（自批、越界落点、屏幕内容外带、提示注入）与对应的挡法，并有测试守住。

6. **确认的节奏与「整台电脑只有一份」。**
   - 一件二十几步的任务不能每步都问。用户对某个应用批准「本轮内允许在这里操作」之后，这一轮里在该应用点击、输入、滚动不再逐步问；到本轮结束即收回，不持久、不记住。禁区与只看只点不适用；上传下载、发送/付款/删除/提交这类不可撤回的动作、切换到没批准过的应用，仍逐步问。这一条改变了此前「每步都问」的口径，开工后第一批弹窗问用户。
   - 同一时间只有一项工作能用桌面，被占用时明确告知；委托出去的后台工作不碰桌面；只读轮次只能看。用户可以随时暂停、停止、接手，接手期间助理的一切动作被拒，交回后先重新观察。助理使用电脑有总开关，默认关闭（它要系统授权、影响整台电脑，与浏览器不同），用户在设置里开启并完成授权后才可用。

7. **屏幕上与侧栏里，随时看得见、管得住。**
   - 屏幕上：助手放一个小的悬浮条（点击穿透、不进截图、不遮挡操作），显示助理在做什么、点到哪里，提供停止、暂停、接手，以及确认的批准与拒绝。侧栏被别的窗口盖住时也管得住，确认不依赖 Molis 窗口在最前面。
   - 「电脑」标签：新增，与「浏览器」并列，不混两种信任级别。助理开始操作电脑时，侧栏自动打开并切到它，不抢焦点（同浏览器）。显示助理正在看的那个应用窗口的实时画面与点击标记，当前目标应用与这一步在做什么，停止、暂停、接手、交还，确认卡（哪个应用、做什么、点哪个控件、输入什么、给哪个文件），各应用的权限状态与禁用，系统权限状态与引导。
   - 对话：沿用现有的助理步骤展示（`presentActivity`），把桌面步骤写成人读得懂的话（看了什么、做了什么、等你确认、被拒绝或失败的原因），结束时给一句结论并能打开记录；不另造一套展示。确认卡在对话、「电脑」标签、悬浮条里是同一张，答复一处，各处同步。
   - 「文件」：每一轮产生一份操作记录——目标、按时间的步骤、每步脱敏后的截图与回执、结果与没做完的部分。它作为这一轮助理工作的「产出」，在「文件」标签预览，也能在对话里引用。用户选择保留时才成为带声明的成果。归属与形态按成果库规则与 `specs/artifact-positioning` 定，先弹窗问。
   - Shelf：记录或其中的截图、结论可以放上 Shelf 作材料，用 Shelf 现有的入口。右栏 Shelf 格是情境动作总纲（PR #180）里的设计、尚未实现，本目标不依赖它，也不为它另造入口。
   - 对话、「电脑」标签、「文件」记录读同一份运行事实，不各存一份。

8. **记录与隐私。** 记录里的截图含屏幕内容：默认只留在本机 Home，按保留期清理，用户可以删除；密码类输入的内容不进记录；不自动进入搜索与记忆。

9. **系统权限、签名与安装。**
   - 需要 macOS 的屏幕录制、辅助功能（以及输入监听）权限。macOS 把权限记在「负责进程」上，从 Node 或终端拉起的助手可能算到别人头上，所以助手以什么形态存在、权限显示在哪个名字下，要先在真机证明；桌面应用拉起与常驻 LaunchAgent 拉起两种方式下，授权都对得上同一个名字。
   - 授权引导：识别缺哪一项，带用户去系统设置的对应面板，授权后助手自动重启并自检，不需要重启 Molis Work；缺权限或被收回时界面如实说明，不假装可用。
   - 签名：本地构建现在是 ad-hoc 签名，macOS 通常把每次重新构建当成新应用，授权会失效。开发期用同一个稳定的本地开发证书签助手，让授权不随构建丢失；发布用的 Developer ID 与公证（BL-021）未定，它直接决定用户更新之后要不要重新授权，是开工后最先问用户的决定之一。
   - 助手随发布包分发（Apple Silicon 与 Intel 各一份，随 `pnpm desktop:build:macos`），随版本升级，纳入安装与卸载流程（卸载时说明怎样撤销系统授权）。本目标只做 macOS，界面不暗示 Windows 与 Linux。

10. **先做最小真机切片，再展开。** 在用户这台 Mac 上先证明并记下数字：只截目标应用窗口（含被别的窗口挡住时）；读到辅助功能树（含 Electron 与 Chromium 类）；后台三档在各类应用上各能走到哪；落点校验；用户输入监听与锁屏检测；两种拉起方式下的权限归属；坐标换算；一次「观察、动作、新观察」往返的耗时。有一件证明不了，先回来说明选型，不带着缺口往下做。

11. **充分并正确地使用 Prologue。** 观察和操作只走 `surface-list / surface-observe / surface-act`，经 Prologue 的策略、审批、执行回执和截图脱敏，不在 Host 包工具里另造绕过策略的通道。实际用上了哪些 Prologue 能力、哪些仍没接通，在能力对照表里如实更新。

12. **体验达到内部完整。** 明暗主题、键盘与读屏、1440/1024/800/390 各宽度、中文输入、界面文案的中英文对照（`apps/workbench/src/i18n/`，门禁 `tests/i18n.test.ts`）、长内容与异常状态（助手崩溃、权限被收回、应用被关闭、窗口消失、模型换成不看图的）都顺畅；动效遵守现有设计规范；侧栏浏览器与讨论等现有能力不退化；`pnpm boundary:check`、`pnpm health:check` 与相关门禁保持通过。主 CI 跑在 ubuntu 上：助手的协议与驱动用假助手测，真实 macOS 的证据在本机跑并记录，不为变绿跳过断言。

验收以真实操作为准，至少包括：

- 在真实 macOS 上、用真实模型，助理一次说完，完成一件二十步左右、跨两个应用的任务（例如从一个应用读到内容、整理进另一个应用）：不说「继续」，确认只出现在首次进入应用和不可撤回动作处；过程在「电脑」标签实时可见，对话里有步骤摘要，结束后有记录，能放上 Shelf、能在对话里引用。
- 助理做事时，用户在另一个应用里正常打字、点鼠标，不被打断（后台档）；必须前台的步骤，用户一动鼠标助理立刻暂停，交回后先重新观察。
- Molis 窗口和侧栏被别的窗口盖住时，悬浮条仍看得到状态，能停止、能批准。
- 看图的模型与不看图的模型各走一遍：前者截图进了模型，后者靠辅助功能树与文字识别也能完成；一个辅助功能树稀疏的应用（Electron 类）也能完成。
- 用户拒绝一步后不换办法再做；禁区应用被拒，终端不能键入；浏览器与其他应用同样经批准；落点被别的窗口盖住时拒绝；助理试图点 Molis 自己的确认卡被拒；密码框不输入、截图被遮住；锁屏时不动。
- 从没有任何授权的干净状态开始，按引导完成授权并自检，无需重启 Molis Work；开发签名下重新构建后授权仍在；桌面应用与本地网页模式（含常驻 LaunchAgent）各走一遍。
- 窄屏与深色主题下侧栏呈现走通；助手崩溃、权限被收回、应用被关、窗口消失时，界面如实说明并能恢复。
- Prologue 一侧的测试与变异测试通过，新包能按 README 重建；Molis 全量回归对干净基线没有新增失败。

所用的 Mac、模型、应用和 Prologue 都必须是真的；没支持或没验证的部分明确写出。

完成的判断是：用户让助理去操作电脑上的应用，就能在侧栏里看着它做、随时拦下和接手，自己的鼠标键盘不被抢走，事后在文件里拿到记录；助理碰不到禁区，碰不到自己的确认卡，也不会把屏幕上无关的内容带出来。工程通过、真实场景通过和用户本人验收分别如实记录；不能把能演示或局部可用当作完成。

决策规则：已定的不再重问（用户 2026-10-07）——原生助手归 Molis、Prologue 只扩合同；浏览器当普通应用、按应用授权、不能记住；侧栏新增「电脑」标签、每轮记录进「文件」；分级边界。开工后第一批弹窗问用户：确认的节奏（第 6 条，推荐「本轮内允许」）、发布签名与公证（BL-021）、截图记录的保留期、记录的归属与形态。替换 vendored 包、动真实 Home 数据、推送 Prologue 先问；其余小的按推荐做，记入 spec 的决策记录。
