## 1. 背景

来源：MISC「T-295 二审 建议」①②③；T-295 #1599 已合入 main。`apps/workbench/src/settings-connectors.ts` 约 :91 的 `renderCardButton` 把来源行写成 `L("来自 {package}", { package: card.declared_by?.title ?? L("Molis Work（内置）") })`：

1. **没限长**：`declared_by.title` 是 Manifest 的 `name`，Manifest 只校验非空；5000 字的包名会渲染成 5003 字一行。同卡片的名称、说明已经走 `connectorCardText(…, CONNECTOR_NAME_MAX_CHARS／CONNECTOR_SUMMARY_MAX_CHARS)`（`settings-connector-guide.ts:12-16`，整字截），来源行是这一张卡里唯一漏掉的包文字。
2. **缺失也标「内置」**：`??` 同时吃掉 `null` 与 `undefined`。合同里 `declared_by: null` 才是“平台自己的”（`tests/connectors-settings-behaviors.test.ts` 的 RAC-2419 钉了 `model-api`、`typesafe`、`image-api`、`mcp-bearer` 为 null），`undefined`（宿主没给）只是“不知道”，却被写成“Molis Work（内置）”，信任标签默认放行。
3. RAC-2419 只锁了搜索里的包名，没锁说明与 id 兜底。

行号以 `origin/main` 为准，开工先核。

## 2. 目标

先在 #1332 贴【方案】（乙档，写到函数级）。
1. 来源行的包名也过 `connectorCardText`，上限用一个新常量放在 `settings-connector-guide.ts` 里与前两个常量并列（值你定，建议同 `CONNECTOR_NAME_MAX_CHARS`，理由写进【方案】）；整字截沿用 `connectorCardText`，**不新写截取函数**。
2. `declared_by === null` → 「Molis Work（内置）」；`declared_by` 为对象 → 包名；`undefined` → 不渲染这一行（连 `data-connector-source` 那个 span 也不要留空壳）。先读 `ConnectorSettingsCardView.declared_by` 的类型（`settings-view.ts:91` 是可选的）与宿主给值处，确认哪些调用方会给 `undefined`，写进【方案】。
3. 用例 RAC-2440：5000 字（含两单元字）的包名渲染后来源行不超过上限且不留落单代理项；RAC-2441：`declared_by` 缺失时没有来源行，`null` 时仍是内置，对象时是包名（并把 RAC-2419 里“说明与 id 兜底”漏掉的断言补一条，若它们本来就在别处被锁，只在【交接】里说明）。每条先对旧代码证明红（变异：去掉限长；把 `??` 改回）。
