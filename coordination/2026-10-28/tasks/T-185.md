## 1. 背景

- 两把尺：
  - `pages.ai` 的 `text` 有 `maxLength: 180000`。内核编译 schema 的选项（`packages/kernel/src/action-schema.ts:40-41`）没有关掉 Ajv 的 `unicode`，所以 `maxLength` 按字（code point）数。起草时在 ajv 8.20.0 上跑过：180000 个 U+1F7E2（一个字，两个单元）收下，180001 个拒绝；
  - 模型端口 `validatePrompt` 对整段提示数 `prompt.length`，即 UTF-16 单元。U+1F7E2 这类字是两个单元。
- 提示是什么拼的：
  - `composeInstructedPrompt(body, data)` 是 `${body.trim()}\n\n${data}`（数据为空时只有 body），在 `packages/contracts/src/platform/model-prompts.ts:49-51`；
  - body 是人保存的指令（长度上限 `AGENT_PROMPT_MAX_CHARS` = 20_000，`packages/contracts/src/services/agent-definitions.ts:19`，保存时在 `apps/local-host/src/agent-definitions/agent-definitions.ts:180` 查）或随包的默认指令（Pages 的默认指令 285 字，`plugins/native/pages/src/prompts.ts:6-16`）；
  - 解析在 `apps/local-host/src/agent-definitions/instructions.ts:14-18`；
  - `pages.ai` 的数据是 `命令：${label}\n\n${text}`（`plugins/native/pages/src/ai-run.ts:22`）；最长的命令名是「比较异同（相同点、不同点、冲突）」，16 字（`ai.ts`）。
- 固定部分，手算：
  - 最长：20_000（指令）+ 2（`\n\n`）+ 3（`命令：`）+ 16（命令名）+ 2（`\n\n`）= 20_023 字；正文 180000 字时总数 200_023 字；
  - 默认指令加最短命令名（2 字）：285 + 2 + 3 + 2 + 2 = 294，正文超过 179_706 字，一单元字的正文也会让总数过 180_000；最长命令名时从 179_693 字起。所以不止两单元字，连一单元字的正文也在 schema 许可的最后几百字被端口拒。
- 上限怎么定：`PROMPT_MAX_CHARS = 180_000 + AGENT_PROMPT_MAX_CHARS + 100` = 200_100 字。
  - 180_000 是正文的上限，`AGENT_PROMPT_MAX_CHARS` 是指令的上限，100 是给命令行（最多 21 字）和两个 `\n\n` 的：20_023 比 20_100 少 77，余量 77；
  - 正好 200_000 不够：最长的 `pages.ai` 提示是 200_023 字，被拒（M6 钉住）；正好 200_023 没有余量，命令名再长一点就拒；取整数 100。
- 怎样数：单元数永远不少于字数，也永远不多于字数的两倍。所以：
  - 单元数不超过上限，字数一定不超过，放行，不用展开；
  - 单元数超过上限的两倍，字数一定超过，拒绝，不用展开；
  - 只有中间一段要 `[...prompt].length` 数一次字，之后的检查不再展开。
  - 数字用 `[...x].length` 的先例：`apps/local-host/src/browser/surface-driver.ts:217`、`apps/local-host/src/computer/computer-inject.ts:61`。
- 谁调这个端口。入口只有两个，都在 `host-complete-text.ts`：配置的模型（`:81`）和环境变量配置的开发模型（`:114`），都先 `validatePrompt(prompt)`。走到它的调用方（读过，main `892879eba`）：

  - 经过的人没有一个把端口的 `> 180_000` 当作安全边界：安全不变量表里没有一条写它（S-18 只在一长串文件里点了 `host-complete-text.ts`，说的是模型服务的授权边界）。
- 对模型一侧：
  - 端口只把提示字符串原样交给 Prologue 的 `completeTextResult`，不是 token 的卡口。`apps/local-host/src` 与 `horizontal/agent-host/src` 里没有别的地方再按提示长度拒绝（`grep` 过；Prologue SDK 里面没读）；

  - `request.system`（指令走 system 的调用）的 64_000 仍按单元（`completeTextRequest` 里的 `request.system.length > 64_000`），本单不动（第 8 节第 6 条）。
- 没有现成的用例钉这个长度：`tests/` 里没有一处断言端口的 180_000 或「写作输入为空或过长」这句信息（`git grep` 过，只有源码里的一处）；`docs/` 里也没有（`docs/platform/PROLOGUE-AI.md:136,465` 讲的是插件的长度上限，不是端口的）。

## 2. 目标

1. 模型端口的两个入口都按字数查提示长度：字数不超过 200_100 放行，超过拒绝；
2. 字数一样时，一单元字和两单元字待遇一样：180000 个 U+1F7E2 放行；
3. 最长的 `pages.ai` 提示（20_000 字指令加最长命令名加 180000 字正文，200_023 字）放行；
4. 超过上限一个字，不论怎样凑成的（一单元字、两单元字、两者混合），仍拒，信息还是「写作输入为空或过长，请减少材料后重试」，没有发给模型；空白提示仍拒；
5. 用例钉住上面四条：改成按单元、全放行、快路径放行、边界差一个、没有余量、余量太大、任一入口不查、不查空白，各自都红。
