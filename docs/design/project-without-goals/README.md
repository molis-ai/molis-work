# 没有 Goals 的项目：新项目首屏与移除、加回（第 44 批定样）

状态：用户 2026-11-17 选定 **首屏 A（一个入口）** 与 **移除 A（就地再点一次）**。本目录是静态交互定样，不是产品实现。需求见[插件同等地位](../../../specs/plugin-equal-standing/spec.md)：
- PEQ-02：移除后再添加，数据都在；
- PEQ-07：首屏不再默认 Goals；
- PEQ-11：人工走一遍添加、移除、再添加。

批次设计建议见[路线书第 44 批](../../../specs/post-anticorruption-roadmap/reference/batches/44.md#design-language-44)。

## 两个界面

**新项目首屏。** 第 44 批起，新项目不默认装 Goals。今天的新项目只带日程（`default_enabled`），外加常开、没有标签的成果库，所以首屏取决于「项目首页」在空项目里画什么。三个方案：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A · 一个入口（推荐） | 项目首页按三问排：项目名、一句「还没有内容」、一个墨蓝「添加插件」，打开的就是现有的 + 菜单。旁边一行浅字提示可以直接问助理 | 最轻，与批次建议一致。添加后首页照常按插件分组。没有 Goal 字样 |
| B · 加起步组合 | A 的下面再给三组常见组合（写作与资料、推进目标、写代码），每组列出要加的插件，一键加一组 | 新人更快有东西可用，但首屏多一层选择。组合是平台写的推荐，后续要维护；「推进目标」这一组仍然点了 Goals 的名 |
| C · 落到首个插件 | 照 PEQ-07 原文：没有历史时打开首个已装插件（日程）。页顶一条提示「这个项目目前只有日程」，带「添加插件」 | 改动最少，但新用户第一眼看到的是一个空的日程，不知道这个项目能做什么 |

不管选哪个，PEQ-07 的「有历史时回到上次的面」都不变。若选 A 或 B，没有历史时的落点是平台的「项目首页」，要同步改 PEQ-07 的措辞：把「首个已装插件」改成「项目首页」。

**移除与加回。** 沿用 + 菜单里每个插件格子上的垃圾桶。两个方案：

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| A · 就地再点一次（推荐） | 现有模式：第一次点，格子第二行变成「再点一次移除 · 数据保留，加回即恢复」，3.2 秒后自动收回；再点就移除。移除后格子回到「可添加」，带「数据已保留」小标；底部提示「已移除 Goals。数据保留，重新添加后恢复。」，附「撤销」（等于加回） | 和其他插件同一套，不为 Goals 开特例；话短，放得进格子 |
| B · 确认气泡 | 第一次点弹出确认气泡，写清什么会保留（Goal、关系、工作历史、要求认可）、什么先收起（Goals 页面和首页卡片），按钮是「移除」和「取消」。移除后的状态与 A 相同 | 说得最完整，但多一步。「保留什么」要每个插件自己申报，等于给插件加一项新声明 |

两个方案的共同部分：
- 加回后，插件的身份色和格子位置不变，首页的 Goals 卡片原样回来；
- 提示写「Goals 已加回，原来的 2 个 Goal 和认可记录都在」；
- 移除失败时，提示「无法移除插件。项目没有变化。」，格子回到原样；
- 文案按插件通用来写，`{name}` 的数据会保留，不写死 Goal。

## 打开

从工作树根启动：

```sh
python3 -m http.server 4439 --bind 127.0.0.1 --directory docs/design
```

访问 `/project-without-goals/?surface=first&scheme=A`。可用参数：
- `surface=first|remove`；
- `scheme`：首屏可选 `A|B|C`，移除可选 `A|B`；
- `scene`：首屏可选 `normal|menu|error|loading`，移除可选 `idle|asking|removed|readded|error`；
- `lang=zh|en`；
- `theme=light|dark`。

顶部控件可以切换，不属于产品界面。按钮只改当前页的内存，刷新就重置。

## 实件与走查

用的是[共享组件板 kit](../kit/README.md) 里的部件：按钮、提示条、空状态、标签、状态标记、输入框、切换组、提示（toast）、骨架。本目录的样式只补布局，颜色只引用 kit 变量。

kit 没有带正文字体，所以 `prototype.css` 照 `system-sans` 基线写了一份字体栈。建议以后由 kit 导出字体角色，不再各写一份。没有提出组件板新增。

- 覆盖 1440、1024、390（手机模拟）× 中英 × 深浅 × 14 个方案与状态组合，共 168 页；
- 检查整页横向溢出、越出视口的元素、缺图标、主题错配、脚本异常，**全部通过**；
- 实际看过：桌面首屏 A、B、C，加载失败，移除 A 与 B 的确认，已移除，已加回；手机深色英文首屏、气泡、已移除。

截图在已忽略的 `.impeccable/qa/review/batch-44-dingyang/`，不入库。

这只证明静态样的路径能走通，不证明以下几项：

- VoiceOver 的连续听感。

这些都是 `UNVERIFIED`。
