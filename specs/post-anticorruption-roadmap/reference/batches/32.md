## 给人讲清楚

现在交给助理一件事以后，主对话就被占住了：这一轮没跑完，你再说的话只能当成对它的补充，没法一边让它做 A，一边再交 B、问 C；做到一半也看不清进展，重启后可能丢了。这一批让你能一直和助理（或你选的一个 Character）说话：它先马上回答，能在后台办的就派到后台，这一轮就结束，你接着说下一句。后台在办什么，点助理对话框右上角的图标看后台任务面板：正在办的、排队的、等你的，各是为哪件事办、谁在办，可以补充、暂停、停下，重启后能接着做。任务办完、办不下去或要你定的时候，结果先回到助理，由它按前后文判断：告诉你、在你原来交代的范围内接着派下一步，或者只问你必要的那一处；超出范围、要花钱、对外发的都先问你。

工作台底部换成一条线：左边是办过的，中间是输入框，右边是接下来。线上的每一项是一个事件，由各个插件和助理按同一种办法登记上来——一条到期的待办、一个会、一个 Coding 会话、一份交回的结果、一件值得跟的交办。点一个事件，它移到中间展开成卡，在卡上点或接着说就能办；卡里能看到它背后有哪些任务在办。任务不占线上的位置（2026-11-14 你改的：线不是任务条，任务是事件的后台）。为此插件图标从底部搬到顶部和标签放在一起，原来的助理面板并进卡和面板里，右侧的「后台任务」页去掉。

多项交付还能逐项看产物、逐项认可或退回重做，没受影响的部分保持不变。

需要你做的：看这条线、事件卡、助理对话框与后台任务面板、回应与去处、新的顶部一条的样子并定下，在上面走一遍完整交错使用（交办两件 → 问另一个问题 → 补充第一件 → 第二件要你定 → 第一件办完助理自己接着派下一步 → 回到对话）；以及逐项证据、部分退回、再次复核的样子并定下。

<a id="deviation-32-2026-11-12"></a>

**偏离记录（2026-11-12，用户弹窗定，[决定 38](../decisions.md#decision-38)）**：原来第 1 项的任务入口按主动助理 §12.8 的定样做「对话顶上的任务条」（2026-11-03 方案 A）；现在按[事项线](../../../work-line/spec.md)做。为什么更好：任务和手头这件事放在同一条线上，不关在助理面板里；多行输入不再盖住主区；不先做一遍任务条再重做。影响：本批多一项外壳重排（改第 07、11 批落下的底栏实现，行为不变），类型加上「工作台」；原属第 53 批的活卡、决定请求、验收卡三种形态提前到本批；主线服务包从第 36 批提前到本批建（第 36 批在它上面加事项容器与存储）；第 37 批的切换器位置改到线头。PWA-127～140、PWA-144～147 的验收一条不减。

<a id="deviation-32-2026-11-14"></a>

**偏离记录（2026-11-14，用户看过本批写法后改方向并弹窗定八项，[决定 45](../decisions.md#decision-45)）**：原来第 3 项的线上第一批东西是助理交办的工作本身（进行中、等你、已办三种节点），线右端放全部后台任务的列表，右侧保留「后台任务」页；第 1 项只要求结果回到主对话给用户看。现在：线上是插件与助理按同一份登记放的事件，任务是事件背后的执行；交办里值得跟的才登记成事件，随口的只在面板；全部任务在后台任务面板（定样选方案 E 后，入口是助理对话框右上角的图标，不再常驻在输入框上方），线上不放任务按钮、右侧去掉「后台任务」页；任务的结果回到派出它的助理或 Character，由它在原交办范围内判断并推进；Character 能直接对话，和助理同一套；为此改 Prologue 并在本批换一次包；仍是一批一个 PR。为什么更好：线不再是一条任务条，待办、日程这些「接下来要处理的事」第一片就能上线；用户不用到各个任务里收结果再回来转告；任务只有一个地方看。影响：事件登记合同从事项线第二、三片（36-2、53-2）提前到本批，53-2 从「补时间角色」变成「多接几家登记方」（日程、Inbox、工作流程、Pages）；37-2「在途任务归属不变」改用面板里每行标的事项来表达；第 07 批的右侧「后台任务」页删掉；直接对 Character 说话的入口比第 58、59 批早做，那两批的子代理直接对话沿用同一个「发给」；本批多一次换包。验收一条不减：PWA-127～140、PWA-144～147、WLN-01～36 照验（措辞随新写法改），新增 WLN-37～40、PWA-155～159。

<a id="design-language-32"></a>

**设计语言增强建议（2026-11-13，[体验升级方案](../../../workbench-experience-upgrade/spec.md)第一轮，用户要求写进本批）**：以下是建议，供本批定样时采用，不增减本批的交付与验收，采纳与否由用户看定样时定。2026-11-14 改方向后，下面的「节点」读作事件，「后台任务列表」读作后台任务面板（措辞已照改）。规则在 `DESIGN.md` 的 Colors → Pairing、Layout → Zones、Motion，实件在组件板 `/__ui/catalog` 的「设计语言」一章。

- **三个区各答一问。** 顶部一条答「我在哪」（项目名和事项名常驻，标题用对象自己的名字），工作面答「现在怎样」，底部的线答「下一步」。定样按组件板「布局分区」那张表逐区核对；事项线落地后，用实件替换那一节的方向稿。
- **线上只有一种暖色。** 进行中用雾蓝，等你用琥珀，等别人用青，失败用红，已办用绿或灰。整条线上只有「等你」是暖色，所以不用加粗、角标或放大也找得到。事件卡里只有一个墨蓝主操作（验收、决定），其余退成浅底。
- **事件展开是同一个对象走过去。** 点事件移到中间成卡，用 `molisCraft.carry`，事件自己走到卡的位置，人不用重新找；收回原路返回。线上往前、往后翻用 `molisCraft.turn`，新事件出现用 `molisCraft.land`，完成用 `molisCraft.celebrate`。有任务在办的事件只靠状态环，不加循环动画。
- **轮到你只提醒一次。** 事件变成「等你」时先换状态，再调一次 `molisCraft.ask`（一圈琥珀色的环散开），之后靠琥珀色自己留在那里。现在底栏「等你」胶囊数量增加时的弹跳（`assistant-bump`）建议并到这一种，全产品「轮到你」只有一个样子。
- **后台任务面板先摆例外。** 等你的排最前，失败的其次；都正常时收成一句（例如「3 件在办，都正常」），不逐条占位。逐项认可时一项一行，状态和条目在同一行，墨蓝按钮只在第一条待认可的项上，部分退回用琥珀加文字说明。
- **要实测的一件事。** `carry` 用浏览器的视图转场，桌面壳（WebKit）、分屏和插件 iframe 里还没有实测，不支持时直接换内容。定样时在桌面壳里走一遍，结果记进体验升级方案的 UXUP-03。
