# 空间同步协调

空间级策略、增量传输、重试和状态。插件通过公共条目适配器提供格式与落库；不认识 Pages 的表结构。

- Status: `partial`
- Contract entrypoint: `@molis-ai/molis-work-contracts/modules/sync-replication`
- Migration Goals: `goal-reorg-f2`.

## 开发要求

项目分区通过可信 `projectPartition` 映射复用对应 owner 的未结算计数，只观察该分区、不推进队列或加载其他项目；未提供映射或分区已停用时拒绝 `hasProjectChanges`，不能以空列表冒充已同步。Home 内容中的项目关系仍由业务 owner 解释。

`SyncRegistration.dependencies` 由可信组合根从同一声明派生完整身份。保存策略前校验所选依赖闭包，缺失、循环或未接入时拒绝，不自动扩张用户选择；共享策略不完整时只阻止对应消费者，原队列和其他健康集合保留。依赖不能由同名的另一发布者或格式替代。

可信组合根可给 `PersonalSync` 提供 `discover`，每轮与保存策略前原子刷新动态集合；构造函数不发现、不传输。固定 owner 优先，动态重复身份拒绝整份新投影并保留上次目录。`available` 只投影当前生命周期，失效集合不冒充空同步成功；原策略保留并显示不可用。发现新格式不自动勾选或改写策略。Web 的实际 Host 在自己的空间内接入此端口，Host 拥有作用域映射，协调器仍不解释插件业务内容。

一轮开始时核对所选集合的完整精确身份。缺失、已停用或格式变更的选择使整轮标为未完成，保留上次成功时间；不打开失效 owner，也不阻止其余健康集合继续传输。恢复原实例或明确复核格式后，后续成功轮次才更新成功时间。

每轮先经原鉴权读取 `/v1/round` 的现行格式 1：空间策略、容量和每个精确所选 namespace 的普通变更 head。摘要必须完整、无重复和其他集合，错误格式在写策略缓存之前拒绝；不回退旧接口。head 只用于跳过首个无变化的正文请求，不确认上传、不前移任何游标。小于已消费游标的 head 按服务恢复回退拒绝，保留本机原件和队列。只读空闲轮次只有一次同步 API 请求；发生过写请求（包括结果不确定的失败）仍重新读取容量。

每个集合每轮最多 40 次处理。达到上限但没有确认读取/上传已排空时，本轮明确标为未完成，不更新成功时间；下一次手动或既有自动轮次沿原游标/冻结操作继续，不因手动执行另起计时器。该边界不表示存在冲突的资产已被解决，也不代表真实设备/免费计划已验收。

`status().progress` 只统计空间策略已选的集合：待上传、非等待冲突、等待关联资产、失败项及逐身份不可用数。未勾选的本机队列不混入。`complete` 只在存在选择、已有成功检查、当前未运行且无错误/剩余项时为真；新设备、未配置、达到轮次上限、离线或仍有冲突都不能据连接时间冒充完成。它是只读观察，不是回执，不保证最后检查之后远端没有新写入。

`prepare(event, {retry})` 收到与随后接收完全相同的重试语义，普通流、临时延迟重放和显式失败重试均传递此选项。准备不得删除或恢复业务内容；Projects 先复用 Storage 的只读接收判定，忽略事件、本人回执或已有本机冲突不创建缺失项目。准备后的接收仍重新检查日志；此步骤尚不等于完整异步项目生命周期接纳。

集合生命周期检查也贯穿实际传输：令牌等待后、请求派出前、响应和附件字节返回后均复查 `available`；停止的插件不能借已经冻结的上传继续提交或清队列。附件请求预算仍按整轮共用，不因为集合增加而重置。手动重试与回收操作复用同一检查。

`refreshCatalog()` 只刷新本机已启用 owner 的目录，不获取令牌、不请求云端策略或传输正文。设置和新设备提示的状态读取会先调用它，所以第一次进入即可选择独立插件，不必先执行一轮同步。构造函数仍不发现、不传输；原来无消费者的 `loadPolicy` 方法已移除，不保留并行入口。

- 负责：个人空间同步配置缓存、协议协调、进度、冲突入口。
- `resolveSyncEndpoint` 只接受可信 Host 的规范 HTTPS 来源或显式固定本机联调，默认不连接；请求禁止跟随重定向。每轮读取服务端容量，满额仍下载并选择独立删除，正向队列不丢弃；最终并发准入归 D1。
- 本机选择保存在该账号 Home 的 `sync/device.json`（格式版本 1，绑定 spaceId），不进入云端空间策略；新设备未选择时无后台传输。关闭自动同步不删除队列或业务内容。
- `run()` 只执行一轮；`start()` 只在已明确开启时建立循环并立即尝试。保存集合仅在自动开启时衔接业务同步；`setDevice(false)` 中止并等待在途轮次退出，之后仍可手动执行。
- 不负责：身份签发、插件正文解释、跨 owner SQL、团队授权。
- 冲突选择先保留云端未采用分支：选本机时固定已有远端事件，选远端时按原 owner codec 归档所读本机内容；归档不进入业务下载流、不确认原上传队列。随后把原比较的 revision/state 交回 owner 同事务校验，不能以重新读取的新 state 替旧确认授权。容量不足、附件失败、格式未接入或停止期间的迟到回执均保留原件与冲突；已经成功的备份本身不表示选择已提交。
- `history` 是同一协调器的云端历史端口：按集合分页查找保留资产、按键分页版本、只读查看、按所查看的 source/head 恢复和明确确认的版本清理。只读查看复用原 content codec、附件清单/摘要及本机保护，不调用 prepare、接收或业务 SQL；JSON 错误不携带原文。恢复在云端生成新 CAS 事件，再运行原同步/owner 校验，本机新编辑仍按原机制保留为冲突。固定原控制器 signal、账号、生命周期及策略跨越所有等待；正常目录重新发现不凭 JavaScript 对象地址认定实例失效。设置页独立显示云端与本机保留版本，两者不静默回退；语义化对比和定位仍未完成。
- 新控制库基线 v5 保存逐项隔离、临时接收延迟及共同流游标。每轮先自动重试至多 20 条临时失败，再继续读取其他资产；永久格式/归属失败只接受显式重试。两者重访旧事件均不得覆盖该键更高版本，关闭自动同步仍不启动计时器。未通过的项保留本机源、队列和错误定位，健康资产继续。冲突对比/保留版本由 owner 的公开 replica 端口读取，恢复按当前修订及本机未提交检查执行。
- `SyncRegistration.content` 由 owner 提供纯内容投影，声明字节摘要与长度，平台统一分块收发。当前接入 Artifact 原文件、Goal 聚合、Pages/Issue 内嵌图片、Images 保存终态图片、Cognia 固定历史及原件；其余已登记 DTO 使用 SDK JSON 内容切片，未接入的 owner 不因此获得附件支持。每轮最多 32 个附件请求，服务端回执及本机分块缓存可续传；完整校验、租约重查与 owner 接收完成后清除暂存。`sync/sync.db` 当前基线 v5，旧库只拒绝，不自动补表。
- 可信 `SyncRegistration.protection` 保护该集合的本机下载分块与延迟事件；模式在新库固定，端口被移除或改变即拒绝。分块按 namespace 隔离，完整摘要验证和 owner 接收后只释放该集合缓存；密文绑定集合、digest、长度、分块位置和校验和。私密失败原因只留固定诊断，密钥不可用不前移失败游标。`hasProtectedSyncPayloads` 是供可信密钥 owner 使用的只读技术检查，不创建缺失库；并不表示 Work owner 已接线。
- 成功上传和幂等重放均带已提交 revision；`replica.acknowledge` 只确认匹配的冻结操作前缀，不前移共同下载游标，不清掉之后的新编辑。永久校验失败持久隔离；临时不可用的键只在本轮跳过，下轮再试，不能让同集合健康资产饥饿。

- 依赖：`@molis-ai/molis-work-contracts`、`@molis-ai/molis-work-storage`。
- 不变量：

生命周期 owner 可以在 `SyncRegistration.withMutation(scope, commit)` 中持有异步预留，最终在预留内调用一次同步 `commit`；普通接收、自动/显式重试、冲突选择和本机历史恢复都走同一边界。协调器在等待后、真正调用 adapter 前和返回后复核授权；最终 CAS 仍由 adapter 事务决定。`prepare` 仍不能删除或回收业务事实。未调用或重复调用 commit 均拒绝，不能把未执行的生命周期操作当成功。

项目分区检查可由可信装配声明 `projectPartitions`（含已停用/回收原件）及 `projectAbsent`（已刷新权威目录明确没有原件）；被动计数不加入普通上传分区，也不允许普通接收。仅在权威目录明确缺席时返回无分区内容，不能把停止或失联实例当作不存在。

同步注册可提供 `locate(key)`，仅由可信 owner 绑定产生本机导航；冲突与恢复检查一并返回位置。比较界面显示变化字段并保留完整版本导出，原内容定位只接受同源地址；不通过导航授予编辑或执行权限。

可信注册的可选 `prepareUploads` 仅在用户已选择集合、下载处理后、冻结上传值前执行；返回的失败 key 保留队列并独立跳过，本轮其他 key 与下载继续。`refresh` 仅刷新被动目录，不初始化 Agent Runtime 或导出正文。Coding 原 SDK 派生历史使用此端口；终态变更保留未结算日志，不能在完整历史未导出时删除项目。

已选集合在正常轮次完成上传处理后可通过 `SyncReplicaAdapter.maintain()` 执行 owner 的有界文件清理；未选择的集合不调用。共同层不扫描目录或启动任务，owner 保留当前与恢复引用，Runtime 与分区包装仍执行原账号/安装/激活检查。此端口不代表全局运维演练。
