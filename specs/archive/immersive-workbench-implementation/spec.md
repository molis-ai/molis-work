# 沉浸式工作台生产接入

状态：2026-09-12 生产接入完成，功能可用（等级 3），提供隔离开发预览。用户已确认 `docs/design/immersive-workbench/` 当前原型（包括 32px 对齐标题栏、纯文字浮起插件标签），并明确要求「开始开发」。本文件是生产接入的唯一需求书；原型 spec 保留设计历史。相关旧 `goal-canvas-workspace` 的固定 70/30、顶部 Goal tabs、手机上下堆叠不再作为本次验收。

## 目标、完成等级与范围

目标完成等级 4：在本地真实项目中，项目首页 → 插件目录 → Goal 画布 → 终端 → 信息与工作记录 → 返回的主链路可内部使用。功能使用真实持久化数据和 Runtime 能力；测试以隔离项目和受控 Runtime 验证，再报告真实本机 Runtime 检查结果。若某项必要环境不可用，明确降低交付结论，不能用演示数据或测试替身宣称真实接通。

视觉依据：已确认原型及 `review/aligned-titlebar-{user,light,mobile}.png`。保留项目与插件边界、Goal 事件语义、精确 Artifact 版本、现有 Runtime/Session/PTY 所有权和权限；替换主工作台布局及导航表达。忽略原型的虚构记录、模拟发送/安装、旧界面中的规划占位、旧 70/30 约束。不重做设置和 onboarding 的功能，不改 MCP 业务协议，不发布/安装新 App、不改用户真实项目数据来制造演示效果。

范围包括工作台布局、禁用的对话入口、工作记录/成果、现有四种内置插件的按项目添加和持久化、项目间 UI 状态隔离、中文/英文及深浅外观。市场只提供随应用交付的 Goals / Sessions / Feed / Artifacts；「添加到项目」激活项目入口，不下载远程代码或授予新外部权限。

## 实施前证据与调用链

- `goals-page-renderer.ts` 组合树、工作面、固定 Goal 框和 TUI；当前右侧顶部仍显示打开的 Goal tabs，左侧含 Inbox/来源/规划占位，Artifacts 会整页离开。
- `navigation-feed.ts` 已有同栏下钻与独立工作面；`documents-state.ts` 按项目保存 UI 状态。当前其他工作面藏在 Goal 框的 document pane 内，需要把插件内容与展开 Goal 的边界分清。
- Goals Plugin 的 momentum 已有真实关系图、视角、节点拖动和固定展开；event-document 提供真实约定、要求、备注、上报、决定和历史读回。
- Work Plugin 已有 Session 列表、按项目/Goal 关联、内容读取、恢复与 PTY；Codex adapter 已经使用 app-server 的 thread 和 turn 协议，但尚无普通对话发送/停止的产品契约。不能把模拟文本或原始终端输出冒充 AI 消息。
- 通用 Plugin Runtime 管扩展包生命周期；内置产品插件由 Host 装配，没有项目入口激活状态。项目激活由 Projects 的持久化目录管理，和外部插件包安装分开。

## 用户场景与行为

1. 打开项目先见根目录和独立项目首页（真实项目名称、简短导览、插件入口），不默认打开 Goals 或某个 Goal；刷新/后退可以恢复工作面，显式 Goal 深链仍打开对应 Goal；左侧项目选择固定。进入插件后，在同一栏显示返回行、当前项目插件横条及其 item。标签无多余图标、选中用轻微卡片阴影；溢出可横滚，选中完整可见。返回根层不丢右侧工作。
2. 左右顶栏同为 32px，收起按钮、插件标题、画布/目录操作和外观切换居中对齐。左侧项目头位于第二行；桌面原生拖动区及系统窗口控件仍可用。侧栏 264px，中等宽度 236px；手机抽屉进入插件保持打开，选择具体 item 后收起。
3. 真实 Goal 在画布上按关系排列。点击后在右侧插件区域内打开固定工作框，保留外部画布感；关闭还原视角、节点位置、焦点。框内不可拖动；目录和顶栏继续可用。
4. 框内主区默认终端；对话标签置灰禁用，说明尚未接入；右侧同时显示简短 Goal 信息和完整时间线，可收起。窄内容区右栏按需覆盖，避免将终端与时间线挤成纵向长页。备注、要求、编辑、记录与决定沿用正式事件接口，保存失败保留输入，成功读回。
5. 用户最新纠正：对话暂不实现，保留禁用标签；不新增 send/interrupt、投递状态或虚构消息。打开 Goal 或切换插件不自动发消息、启动进程或创建 Session。
6. 现有 Session 内容读取、恢复与 PTY 生命周期仍归 Work，本次验证可见性与所有权保留。
7. 已有 Session、Feed、来源管理和 Artifact 精确版本仍可达。Inbox/来源作为 Feed 内的视图/入口保留；Artifacts 在同一个主工作区展示原有插件目录与详情，保留导出/版本链接。
8. 插件市场使用真实内置插件卡片、搜索与当前项目已添加筛选；添加时选择项目，写入该项目激活记录，重复添加返回已添加且无重复记录。老项目保留原有入口；新项目至少保留 Goals，其他入口可从市场添加。项目未添加的入口不混入其目录，数据不会从别的项目借用。
9. 切换 Goal/插件/项目保留各自视角、展开状态、右栏偏好和终端所有权。新项目和新 Goal 只有自己的创建事实，没有示例成果与旧记录。长名称/空状态/错误均有可理解的界面。

## AI 输入、输出与干预

AI 继续通过现有 Runtime 终端和 Session 工作；本次不扩展对话、发送或停止协议。用户通过终端与 Goal 信息/记录观察和干预，结构化对话等待后续明确接入。

## 模块边界与分组

串行执行，主执行方是唯一 writer，避免 Workbench 共享脚本/布局的交叉修改。各 Work Item 的自包含范围见 `work-items/*/spec.md`。

| Work Item | 输入与产出 | 依赖 |
| --- | --- | --- |
| shell | 已确认原型 → 生产目录、标题栏、画布与固定工作框；复用真实 Goal/PTY，准备对话插槽 | 无 |
| conversation | 用户要求延期；shell 交付禁用对话标签与默认终端 | 无 |
| plugins | Projects 目录及内置插件贡献 → 项目激活、市场、Artifacts 同页和入口隔离 | shell |
| verification | 最终代码与隔离真实数据 → 定向回归、构建、桌面/手机/深浅视觉与主路径、交接文档 | 前三项 |

## 假设与非目标

- 对话延期，最新用户纠正优先于原型交互和旧计划。项目首页使用真实项目身份与插件入口，不编造活动、指标或示例记录。
- 老项目迁移保留已有四个入口；新项目默认 Goals，插件添加是项目 UI 能力配置而非 API 权限边界。
- 当前工作树已有前序功能改动，按实际代码承接，不清理无关 diff，不改 macOS 托盘/发布配置。
- 本次不升级模型、不下载/执行远程插件、不自动将工作发送给他人，不发布或替换已安装 App。
