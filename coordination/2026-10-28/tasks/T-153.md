# T-153 提醒与定时操作登记的闹钟名称按整字截到 120 个单元，不再留下半个字

> **这条在 main 上成立：两处闹钟名称按 UTF-16 单元硬截，截点落在一个两单元的字中间时，留下半个字。**
> - `plugins/native/schedule/src/reminders.ts:75`：提醒登记闹钟时，名称是 `input.text.slice(0, 120)`；
> - `plugins/native/schedule/src/operations.ts:122`：定时操作登记闹钟时，名称是 `(current.title + "：" + title).slice(0, 120)`；
> - 第 120 个单元若是表情（如 `😀`，U+1F600，两个单元）的前一半，`slice` 就留下一个孤立的高位代理。这个名称存进 Scheduler，日程页的闹钟列表（`plugins/native/schedule/src/ui.ts:149`）和详情标题（`:172`）原样显示它，看到的是一个「�」。
>
> **修法起草时定、写死：截到 120 个单元以内，截点落在字中间就少截这一个字。** 不照搬 T-079 的 `[...文字].slice(0, N)`：
> - Scheduler 按 UTF-16 单元数名称，超过 200 个单元就拒（`horizontal/scheduler/src/index.ts:478-484` 的 `normalizeTitle`，`scheduler.job_invalid`「标题无效」）；
> - 插件名（`current.title`）和操作说明都没有长度上限，按 120 个**字**截，全是表情时可到 240 个单元，定时操作就登记不上了。第 6 节的 M3 就是这个写法，用例里它直接抛「标题无效」；
> - 按 120 个单元截、不切开字：不含表情的名称与现在一字不差，含表情的最多少 1 个单元。
>
> 来源：协调分支 `611a1238d` 的 `coordination/2026-10-28/MISC.md:44`（「T-091 起草」：`reminders.ts:75`、`operations.ts:122`、`runtime-wakeups.ts:67-68` 按单元截取）。本单只收前两处：

## 1. 背景

- 两处登记闹钟的代码，现在的样子：

  ```ts
  // plugins/native/schedule/src/reminders.ts:73-75
          const id = randomUUID(), due = new Date(at).toISOString();
          const job = schedule.register({ plugin_id: SCHEDULE_PLUGIN_ID, capability_id: SCHEDULE_REMINDER_WAKEUP, object_ref: id,
            title: input.text.slice(0, 120), due_at: due, recurrence: repeat === "none" ? { kind: "once" } : { kind: "interval", interval_ms: repeat === "daily" ? DAY : 7 * DAY } });
  ```

  ```ts
  // plugins/native/schedule/src/operations.ts:120-122
          const id = randomUUID(), title = operation.description || operation.id, due = new Date(at).toISOString();
          const job = schedule.register({ plugin_id: SCHEDULE_PLUGIN_ID, capability_id: SCHEDULE_OPERATION_WAKEUP, object_ref: projectId + "|" + id,
            title: (current.title + "：" + title).slice(0, 120), due_at: due,
  ```

- 各自的输入从哪来、有多长：
  - 提醒文字：`reminders.ts:67` 只收 1～200 个单元（`input.text.length > 200` 就拒），所以截到 120 个单元的截点可以落在任何位置；
  - 定时操作名称：插件名（安装记录的名字）加「：」再加操作说明（没有说明时是操作 id），三者都没有长度上限。
- Scheduler 存名称前先 `trim()`，再查「非空、不超过 200 个单元」（`horizontal/scheduler/src/index.ts:478-484`，`:150` 调它），不满足就抛 `scheduler.job_invalid`「标题无效」。登记在 `db.transaction(…)` 里，抛了整个 `add` 回滚。
- 闹钟名称只用来显示：
  - 日程页的闹钟列表，`<strong title="…">`（`ui.ts:149`）；
  - 详情页的 `<h1>`（`ui.ts:172`）。

  到点送达用的是提醒的原文与插件名（`runtime-wakeups.ts:37-38`）、操作的记录（`:66-68`），不读闹钟名称。
- 同包里将有同类写法：T-099 要在 `runtime-wakeups.ts` 里加一个不导出的 `notificationTitle`，逐字累加、单元数到上限就停（T-099 任务书第 5 节第 1 条）。本单的新函数用同一个路子，两处读起来一样。两者的上限不同（通知 200、闹钟 120），截完是否加「…」也不同，所以不合成一个。

## 2. 目标

1. 提醒登记的闹钟名称：提醒文字不超过 120 个单元时原样；超过时，取最长的、不切开字的前缀，不超过 120 个单元。
2. 定时操作登记的闹钟名称：对「插件名：操作说明」照第 1 条截。
3. 不含两单元字的名称与现在完全一样（仍是前 120 个单元）。
4. 名称永远不超过 120 个单元，所以 Scheduler 不会因名称拒掉登记。
5. 用例钉住上面几条：改回按单元硬截、改成按字截 120 个、或者少截一个单元，都红。

1. **新文件 `plugins/native/schedule/src/job-title.ts`**，全文原样如下：

   ```ts
   /**
    * The Scheduler counts a job title in UTF-16 units and refuses one past 200; Schedule names its jobs in at most 120,
    * cut at a whole character so a name never ends in half of one.
    */
   export function jobTitle(title: string): string {
     let cut = "";
     for (const character of title) {
       if (cut.length + character.length > 120) break;
       cut += character;
     }
     return cut;
   }
   ```

   说明：
   - `for…of` 逐个码点取字，两单元的字一次取两个单元，所以截点不会落在字中间；
   - 不超过 120 个单元的名称整串原样返回，不另写提前返回；
