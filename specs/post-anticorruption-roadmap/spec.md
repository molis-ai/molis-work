## 2. 怎么排

**重要度**看三条，同时满足得越多越靠前：

1. **工作接得上**：中断、关掉应用、隔天、换一个入口之后，要求、进度和结果都还在，能接着做。
2. **体验**：常用路径顺、快，不露内部值，不出莫名其妙的错。
3. **易用**：第一次就能用上，不用先弄懂产品的结构。

**依赖**：被好几条线用到的东西先做。这样的地基包括统一输入框、技能包、完整工作记录、真人批准门、Schedule 的只读查询、字体皮肤语言的文件格式，以及场景所需的角色与设置公开读写、生成交互页面的承载和恢复能力。已有能力先复用，只补当前场景所需缺口。

**冲突**：按文件把工作分成七条轨道，一条轨道同一时间只有一个写手；会碰到全仓的改动（换 Prologue 包、字体皮肤语言的整体切换）排进固定窗口。细则在第 5 节。

**兼容起点**：第一个装到开发机之外的版本（M1，阶段 2 的退出条件）发出去以后，合同改动要带读取兼容（[合同变更流程](../../docs/system/CONTRACT-CHANGES.md) 第 7 节）。所以改合同多的地基——技能包、字体皮肤语言 A 段、同步合同、工作记录的结构、场景与生成页面的必要合同——都排在 M1 之前落；阶段 3 起的合同改动按兼容流程做，成本更高，排的时候算进去。

**不排日历。** 每一段只写退出条件，到了就进下一段；一条轨道提前做完，就从后一段同一轨道的活里往前拿。

规则：

1. **合同先行。** 要改 Manifest、SDK 或 `packages/contracts` 的，先单独开一个只改合同的小 PR（带 `pnpm api:update`、`pnpm actions:update` 的快照），C 轨评审、尽快合；功能 PR 叠在它后面。同一时间只有一个合同 PR 在途。技能包、场景与生成页面、情境 W4、卡片撤销、字体皮肤语言 A 段的合同改动按这条排队，先核已有合同能否复用。
2. **换包窗口。** 每个阶段最多换一次 Prologue 包，放在阶段中段。这一阶段要上游补的东西提前列进窗口清单一起提，窗口外不换包。阶段 1 不换包：记忆 P0 在 1·C 只做不要上游的部分（#1101、#1059 都不换包），要上游的进窗口一。阶段 2 的窗口一装子代理、P5 协作和记忆 SDK 余项，并补项目助理团实际执行所必需、当前 SDK 尚缺的能力；阶段 3 的窗口二装 Skill、Context、MCP、Tool 四份策略要的上游能力。
3. **切换窗口。** 字体皮肤语言的 C 段（全部插件的文字与样式一次切换）占一个窗口。窗口里 E 轨不改插件的界面文字和样式，只做逻辑；G 轨不改插件的 Manifest；新插件在窗口之前就按新格式写，不留到窗口里转。
4. **同路径一起落。** 碰同一批聚合文件（`scripts/gates/page-assets.mjs`、`tests/ci-product-subset.txt`、`packages/contracts/src/platform/dom-events.ts`、`pnpm-lock.yaml`）的 PR 按批落规则合成批 PR，冲突由统筹一次解。
5. **新插件放空档。** 风险、工作简报这类新包不和任何轨道抢文件，哪条轨道闲下来就先做它们。
6. **一条轨道一个会话跨到底。** 同一条轨道在各阶段尽量由同一个会话接着做，少交接；开发本身也讲工作接得上。
7. **借文件由主人落。** 别的轨道的需求要改某条轨道独占的文件时，由那条轨道的会话落这处改动，需求方叠在后面。阶段 1 已知两处：技能包要改助理的 `methods()`（`apps/local-host/src/assistant/assistant-service.ts`），harness R2 要改委派入口（`apps/local-host/src/assistant/assistant-executor.ts`），都在 A 轨。A 轨先落这两处小改动，再开输入框的大改。场景引导同理：F 轨负责需求与完整路径，个人助理接点由 A 落，角色/设置/Runtime 公共能力由 C 落，工作台页面与视觉由 D 落，插件配置和工作流程由 E 落；F 不横跨这些独占文件另写一套。
