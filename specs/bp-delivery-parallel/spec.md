## 目标与证据

定位与承诺见 `outputs/molis-work-positioning-2026-09-25/bp.zh-CN.md`。当前已有 Connector、首页建议/动作、Artifact 固定版本、Character、Prologue、Alchemist 局部方法沉淀及首次资料导入；Builder、动作架构、Connector、Onboarding、Shelf 和整体体验均有其他活跃任务。新增工作补齐启发式个人助理、跨任务复利、跨端团队，不重建现有能力。

各新增任务目标为所声明范围的「内部完整」：真实存储、真实业务调用、首次使用及异常恢复可实操。工程、真实模型/产品实操和用户本人验收分开记录；不可把固定响应、窄屏截图或本机模拟双用户当作真实模型、真机手机或外部团队验证。首条路径用于尽早验证方案，不替代最终约定范围。

## 全局约束

- 所有模型推理、总结、建议、排序、学习和 Agent 执行均走项目已有 Prologue/Agent Host。Connector 负责取数及业务工具，不作为绕过 Prologue 的模型入口。不得增加模型供应商直连、另一套 Agent Runtime 或独立隐性记忆。
- Character 沿用现有系统；用户偏好属于用户可查看、纠正、停用的数据，不把一次忽略自动升级为永久规则。
- 建立在授权材料、现有项目/成果身份和共享动作体系上；不自动读取所有账号、外发消息、发布或购买服务。
- 新任务使用独立工作树，延续当前工作代码；启动时核对基础是否含当前动作迁移、Prologue 及既有插件。原 checkout 仅作只读对照，不能覆盖其他任务修改、清理工作区或全量提交现有变动。
- 每个实施任务最多一个 writer。共用入口、Agent Host、动作核心、全局存储迁移、workbench 导航和依赖锁文件按原 owner 串行接入；新任务先形成专属模块和精确接入需求。依赖不足时继续独立部分，不造第二套共用机制。
- 新界面先做真实或逼真内容的高保真可交互切片，覆盖加载、失败、低质量、空态、继续和用户介入，再完成已授权实现。

## 必须交接的接口与顺序

1. 助理与复用任务先约定最小交接：项目/任务上下文及用户授权范围进入；固定版本候选、来源、适用条件、时效疑点和用户确认的方法引用返回。字段服从现有身份体系，避免双份事实。
2. 助理输出建议，用户确认后调用现有 Action；方法服务输出可用方法及采用记录，均不自行拥有业务副作用。
3. 跨端任务先用现有项目进度与成果实现两客户端路径；助理与方法能力可在接口稳定后追加同步，不让云端决定本机私有数据事实。
4. Cognia 2 将替代旧知识库，而当前 Onboarding 依赖旧 Cognia 保存原文与版本。Builder 与 Onboarding 原 owner 明确新的资料持有方和引用/继续路径；不恢复用户已否定的旧数据兼容，不让知识库改版切断新用户导入。
5. 三次同类真实工作作为联合验收：第一次交付；第二次沿用确认成果/方法；第三次因相关变化得到可执行建议。统计解释、准备、修正投入和错误，不只统计自动化数量。
