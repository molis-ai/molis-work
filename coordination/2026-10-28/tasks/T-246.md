## 1. 背景

来源：MISC「T-210 起草」第一行。`apps/local-host/src/context-onboarding-service.ts:458` 与 `:567` 用 `title.length > 120`（UTF-16 单元）拒，错误信息写「请输入 1–120 字的项目名称…」；页面 `apps/workbench/src/scripts/context-onboarding.ts:347`、`:368` 两个项目名输入框都是 `maxlength="120"`（HTML 按单元）。含两单元字的名称（emoji、部分生僻字）只能写到 60 个字，却被说成 120 字。T-210（#1489，已合入）已把同一文件里的分段标题与摘要标题改成按字数数。

先查下游：项目名最终落到 `projects` 模块的创建/改名动作，它按什么数上限（读 schema 与库）；不一致就以下游为准，不能出现「引导收下、下游拒」。

## 2. 目标

1. 两处 Host 检查按字数数 120，与信息一致，也与项目名在下游的上限一致。
2. 页面两个输入框能输入 120 个两单元字，超出时封顶（做法照 T-203 或 T-234 合入后的页面写法，或读 T-210 的 Host 一半）。
3. 有真浏览器用例。

## 3. 不做

- 不改引导别的字段、不改别的页面。
- 已存下的、长度超限的名称（若有）不在本单处理（要读真实 Home，另议）。

## 4. 范围

`apps/local-host/src/context-onboarding-service.ts`（只 `:458`、`:567` 两处检查，T-214 也改这个文件的 organize、draftTodos 两个 catch，所以依赖 T-214）、`apps/workbench/src/scripts/context-onboarding.ts`（`:347`、`:368`）、`tests/context-onboarding.test.ts` 等对应测试、一个浏览器用例文件（新）；页面资源字节变了要过门禁（`scripts/gates/page-assets.mjs` 的 `APPROVED_CEILINGS` 与 `tooling/gates/page-assets.json` 经 `--update --base`，别的任务也涨同一个资源时后合的重量）。

## 5. 做法

1. 先在当时的 main 上读下游：项目名最终交给 `projects` 模块的创建/改名动作，找它的 schema（`packages/contracts/src/modules/projects.ts`）和库里的检查，写下它的上限和数法（单元还是字）。
2. Host 两处（`context-onboarding-service.ts:458`、`:567`）：`title.length > 120` 改成 `[...title].length > 120`（名称只有 120，直接展开没问题）；信息文字「1–120 字」不用改。若下游上限不是 120 字，停下来问（见第 11 节）。
3. 页面两个输入框（`context-onboarding.ts:347`、`:368`，是字符串拼出来的 HTML）：去掉 `maxlength="120"`，在各自输入框的 `input` 事件里把内容按字数封顶在 120 个字（`const chars = [...input.value]; if (chars.length > 120) input.value = chars.slice(0, 120).join("");`）。事件挂在哪里，照该文件里已有的 `input` 处理写。写法也可参考 T-203（Pages 评论输入框）。
4. 页面脚本变长，页面资源字节要涨，按第 11 节第 3 条办。

## 6. 验收

- `RAC-2250`：Host 创建/改名检查：120 个两单元字的名称被收下，121 个被拒，信息与数法一致。
- `RAC-2251`：页面输入框能填满 120 个两单元字，121 个被封顶。
- `RAC-2252`：项目名在下游（创建动作）也被收下。
- 余下号备用。
