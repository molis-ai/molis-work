## 固定写法

1. **最新产品介绍**：用户视角和技术架构视角分别写，各在一分钟内。
2. **今日新上功能**：区分公开发布、main 合入、分支推进、需求设计与历史补齐；逐章 review 当天证据的影响。
3. **功能全景**：结构化分类，按用户完成工作的价值排序，覆盖现有与未实现方向。
4. **用户场景**：按可重叠的角色/职责给具体任务，先枚举再抽象；写用户具体卡在哪一步、Work 凭什么少重讲/搬运/重配、仍需人做什么，以及交付物、证据、替代、摩擦与反例；完整比较省掉、转移和新增的劳动，纳入首次、每轮、并存与退出成本。
5. **为什么是 Molis Work？**：从场景中挑真正痛、与产品优势吻合的部分，讲清主流方案已解决什么、还剩什么，以及 Work 的证据边界。

完整执行方式见 [日更规范](日更规范.md)。此规则替代此前“一段综合一分钟、只追 main”的默认写法；V3 原文保留。每日同时追主线、全部分支、未提交进展和已有设计/需求，只有方向不能算已实现，合入 main 不能算公开发布。日更不自动修改官网或提交发布。
