## 协同第一期：认领与任务图摘要（2026-09-26，按你拍板的协同方案）

方案与拍板见 [`benchmark.md`](benchmark.md) 末两节。这一期做"每一步都有负责人、看得出谁在做"和"任务图摘要"。

**SDK（vendored `prologue-sdk-0.0.0-rc.1-claims.tgz`，累计补丁 `claims.patch`；2026-10-08 起树里只留补丁的大小、SHA-256、git blob 与来源，见 [vendor/prologue-sdk/patch-history.json](../../vendor/prologue-sdk/patch-history.json)）**

- 任务图的负责人从"只能是角色"扩成三种：角色、会话（包括子任务自己的会话）、人。
  - 只有负责人能报告这一步；报别人名下的步骤明确失败，错误里写着现在归谁。
  - 报告记下是哪个会话、哪个人报的。
- 新增"交接"：把没结束的一步从一个负责人交给另一个，状态和进展不动，并在图上留一条"从谁到谁、为什么"的记录。已结束的步骤不能交接。
- 宿主可以替人记录决定（跳过、给出决定、标记结果），不受负责人限制，但必须写明是哪个人；模型的任务图工具做不到这一点。
- 派子任务时可以写 `claims`，把本会话名下（或没人认领）、还没结束的几步交给它：
  - 派出前整体核对，任何一步不符合就整次失败，不会生出子任务；
  - 子任务开跑前这几步就归它，只有它能报告；
  - 子任务结束时没做完的，自动交回派它的会话；
  - 子任务总能看到并使用读图和回报两个工具，即使它的角色没列这两个工具；但不会超出父任务本身有的工具。
- 读图时负责人写成 `you (this session)`、`subagent <引用>`、`the session that dispatched you`，不是一串会话编号。
- 图的变化事件带上是哪张图，宿主可以只跟自己那一轮的图。
- SDK 全量 3311 项：3288 通过、20 跳过、3 失败。
  - 3 个失败（模块环、事件账回放、重开后回执唯一）和 1 处测试类型错误，在上一版 coding-inference 包里就有，README 里记着（共享推理线尚未收口的问题）。

**Molis**

- 确认计划开跑时，每一步都登记在本会话名下。
- 子任务可以读、报它所属那一轮的任务图（宿主钩子沿父子关系找到那一轮）；`claims` 只能指向本轮的图。
- 每一轮开头带一份**任务图现状**（摘要）：每一步的状态、负责人、最近一条回报，以及没人认领的步骤。
  - 它跟这一轮的任务放在一起（参考材料），注明比之前对话里的说法新；规则（谁能报、怎么用 `claims` 交出步骤）留在固定指令里。放在固定指令里时模型常按旧聊天回答，见下方实测。
  - 没有计划的普通一轮，如果本会话还有没结束的图，也带上现状，并说明这一轮没有任务图工具。
- **图有变化时告诉执行中的这一轮**：子任务的回报、步骤交回这类"不是它自己报的"变化，停 1.5 秒后合成一条"任务图有更新"送进去。
  - 本会话自己的回报不重复送；人的调整本来就有自己那条说明，也不重复送。
- TaskBoard 和对话里的计划卡：
  - 每一步显示负责人：本会话（和执行它的角色）、子任务「键」、你、没人认领；
  - 子任务挂在它负责的那一步下面；
  - 顶部写"N 步在子任务手上 · 你负责 N 步 · 没人认领 N 步"。
- 你可以：
  - 「由我处理」：把一步改派给自己；
  - 「交回本会话」：把一步交回本会话（没人认领的写作「交给本会话」）；
  - 在自己负责的一步上「标记完成」「标记失败」，写明做了什么；
  - 插入步骤时勾选「由我处理」。
  - 每一项都记在图上，并用你的口吻告诉执行中的这一轮。
- 步骤详情和保存的报告里，每条回报写明是谁报的（本会话、子任务、用户记录、改派）。
- 会话列表和标题栏的后台任务清单也写"你负责 N 步 · N 步在子任务手上 · 没人认领 N 步"。
  - 后台清单跨项目读各项目记下的数字，不打开项目；一轮已经结束、但有一步由你负责的会话也列出来，因为那一步在等你。

**实测中发现并已修的问题**

- 摘要放在固定指令里，模型更信之前的聊天：改为放进这一轮的参考材料（见上）。
- 我在执行中改派，那一轮除了我的说明，又收到一条"任务图有更新"。原因是交接没记下是谁做的；现在 SDK 的交接可以记人，宿主把人的交接记成人的，不再重复通知。
- 问过一句话之后，计划就不能再调整、也不能「继续计划」：按钮、宿主和继续路由都只认"最新一轮"。
  - 现在最近的计划轮在其后只有已结束的普通对话时，仍可调整和继续。
  - 后面有新的计划轮或仍在进行的一轮时照旧拒绝（新测试）。
- 「评价并整合成果」在较早轮次的子任务卡上点了没反应：结果面板只拿当前加载窗口的子任务。改为加载过的所有轮次都给面板。
- 人改完图之后，TaskBoard 里加载窗口之外的那一轮不刷新：修改后强制重读。
- 人标记完成的一步显示成"模型报告完成"：改为"你标记完成 / 你标记失败"。
- 一次对"锁被自己占住"的排查：4208 首次启动时锁在 4207（另一个会话的服务）手里，之后重试拿到，不是泄漏，没有改代码。

**还没做**

## 协同第二期：会话之间看得见、范围重叠先提示、可以让一轮等另一轮（2026-09-26）

方案第二期的内容：开工时比对范围、写入时提示、事项重复提示、你的协调入口；第一期挪过来的"项目任务图登记每个会话正在做的事"也在这一期。

**SDK**

- 常开的任务图（`standing: { keepFinished }`）：不因节点都结束而终止，可以空着开，只留最近加入的若干个已结束节点（还有节点在等的不丢），重启后照旧（新测试）。

**宿主**

- 每个项目一张常开任务图，就是"项目里进行中的工作"。
  - 每一轮是一项工作，负责人是它的会话；"等另一轮"是图上的依赖。状态、负责人、等待都在 SDK 图上。
  - 每项工作记下它在哪个目录、点名或写入了哪些文件（放在宿主加密存储里，一个项目一条），用来找重叠。
  - 服务重启后不再运行的轮次，读的时候记为"这一轮没有在运行"，不再算进行中。
- 开跑时，这一轮的参考材料里有"项目里其他会话正在做的事"：每项的会话、任务、范围；和这一轮登记范围重叠的会写出来，并要求模型改这些文件前先告诉用户，不替用户决定先后。
  - 模型可以用 board-read 读这张图看最新状态，不能改它。
- 写入审查卡：同一目录下另一个进行中的会话也登记了这个文件时，卡上写"另一个会话也在改这个文件：会话「…」（进行中）"。

**Coding**

- 发送前查同一目录下的重叠。有重叠时弹出选择：
  - 「等「…」完成后自动开始」：这一轮作为等待项挂在对方那项工作后面，不开始；
  - 「照常同时进行」；
  - 「不发送」。
- 等待中的会话：
  - 输入框上方写"下一轮在等「…」那一轮结束，结束后自动开始"，可以「现在开始」或「取消等待」；
  - 对方那一轮结束后自动开始（你拍板的"自动继续"），用的是你当时发送的内容；
  - 对方失败或被停止时不自动开始，写明原因，等你决定；
  - 服务重启后照样接着等。
- 会话列表和标题栏后台任务清单显示"等其他会话"；同一个 Goal 下有两个进行中的会话时提示"可能与「…」重复"。

## 第四期：后台任务的挂起与唤醒，做成 SDK 的通用能力（2026-09-27）

你 2026-09-27 补充的需求：后台跑耗时长的脚本时，依赖它的 Agent 或子任务应该挂起；任务有状态变化时通知它们继续，防止空转；这些应该是 Prologue SDK 的能力。方案、对照和你的拍板见 benchmark.md 的"后台任务的挂起与唤醒"：
- 后台命令属于会话，这一轮结束后继续跑，每个会话同时最多 4 个，服务停止时收掉；
- 第二、三期的两种等待一起改用 SDK 的挂起与唤醒；
- 唤醒后自动继续；
- 这一项作为第四期，原第四期顺延为第五期。

**SDK**（claims.patch 累计补丁；包的 SHA-256 见 vendor/prologue-sdk/patch-history.json）

- `runtime.background`：后台命令登记到发起它的会话。
  - 记录跑没跑完、退出码、起止时间，并落盘。
  - 打开 `outliveRun` 后，这一轮结束也不收掉；每个会话同时运行的数量有上限，超了会明确报错 `BACKGROUND_LIMIT`。
  - 重启后，原先在跑的记为"被打断"（`interrupted`）。
  - Runtime 关闭时，还在跑的命令停掉并记为被打断。
  - 进程直接退出、没关 Runtime 时，Node 宿主也会停掉它起的进程组，不留孤儿进程。
- 后台命令和普通命令一样经宿主审查。以前它不走审查，在"要审查"的规则下根本起不来；现在审查内容会标明"后台运行、这一轮结束后继续跑"。
- `runtime.waits`：会话挂起。
  - 可以等的东西有四种：后台命令结束，后台命令输出里出现指定字样，一封信被答复或了结，任务图上一个节点结束。
  - 挂起记录落盘；重启后，挂起期间已经满足的条件会补上唤醒。
  - 触发后由 App 接着开下一轮，也可以恢复（`resume`）或取消。
  - 一个会话同一时间只有一个挂起，再挂起就是往里加条件。
  - 默认 7 天过期。
  - 可以存 App 自己的数据，最多 64KB。
- 新系统工具 `await-commands`，两种用法：
  - 默认在这一轮里阻塞等，等的时候不调模型；
  - 带 `park: true` 时挂起并结束这一轮。如果要等的事已经发生，直接告诉模型"已经发生了，接着做"，不挂起。
  - 子任务只能阻塞等，但可以等父会话的后台命令。
  - `command-output` 和 `command-stop` 也认得这个会话之前几轮、以及父会话起的命令。
- 后台命令结束时，在下一次工具调用的结果后面提醒一次。
- `session-send` 带 `wait` 时，挂起在那封信上。

## 第五期：其余协同场景（2026-09-27，按你的四项拍板和"扩展 SDK，迁过去"）

**做了什么**

- 循环等待：挂起会成环时拒绝（SDK 的 `WAIT_CYCLE`，沿"等信 → 等收信的会话、等节点 → 等它的负责会话"往下查）。模型发出的信照常送到，只是不挂起，回执里说明为什么；你排的"等另一轮"成环时拒绝，并释放排队的那一项。
- 交接：模型可以把本会话名下没做完的步骤交给已有的会话（`session-send` 的 `handoff` 带 `board`/`steps`）。步骤在原任务图上换负责人、留交接记录；接手的会话下一轮开头看到交给它的步骤，可以在别人的任务图上读和回报这几步；接手的那一轮正常结束，交接信就算了结。
- 广播：`to: "overlapping"` 发给范围重叠的会话（最多 5 个），不审查。
- 优先级：你把一个会话标为优先，范围重叠、还在做的会话会收到"请让出这些文件"的信；不暂停任何一轮，谁停下来仍由人决定。
- 认领过期：会话已经结束、仍认领着、2 小时没有动静的步骤，在任务图上标"认领已过期，N 小时没有动静"；不自动收回。
- 委派迁到信封：
  - SDK 的信扩展了 4 样：附带引用（`attachments`，比如固定成果的版本）、每一步的回执（`history`：事件、之后的状态、时间、谁、为什么）、接受/拒绝/完成/取消可以带理由、只给人看的信（`audience: "people"`，不交给模型、不占模型发信的上限、允许人自己写的路径）。
  - 委派现在是一封给人的请求信：发起时建好对方会话（任务放在输入框里）并立即送达；对方接受或拒绝（拒绝写原因）；对方发第一轮即视为接受，并记"开始执行"。
  - 交付是一封答复信，带上固定的报告或变更；发起方收下（委派完成，成果加入下一轮材料）或退回（写原因，工作仍在对方）。
  - 界面和操作不变；"会话间的信"里不显示这类给人的信。
  - 迁移前存在插件自己存储里的委派照常显示，标"迁移前的委派记录，只读"，不能再操作。

## 左栏各面回到左栏，任务图成为主区域的视图（2026-09-30，你指出）

你指出的问题：左栏点「TaskBoard」标签之后，内容却出现在右边的主区域，不对劲。核实的现状：这个标签只把左栏标题改成 TaskBoard，左栏内容仍是会话列表，主区域被整张任务图顶掉；还没打开会话时点它，右边什么都不变（板子的提示藏在被隐藏的对话区里）。左栏五个面里只有「会话」「产物」「文件」真的在左栏换内容，「目标」是弹一个对话框。

**定下的口径**

- 左栏的五个面只改左栏：会话列表、当前会话的任务大纲、当前会话的目标、已保存的成果、工作区文件。点哪个面，主区域都保持原样。
- 整张任务图是主区域自己的视图，用对话区标题栏的「对话 / 任务图」切换，任务图标签上带最新任务图的进度（例如「任务图 2/2」）；板子里的「回到对话」和左栏大纲的「展开任务图」都是同一个开关。
- 左栏「TaskBoard」面显示同一棵树的紧凑大纲：分组标题、每行一个状态标记、编号、标题、执行者头像；点一行和板子一样导航（步骤打开回报与验收，轮次和子任务回到原位置）。大纲不带调整控件——调整在主区域的任务图做。没打开会话时，大纲说明去「会话」里选一个。
- 左栏「目标」面显示当前会话下一轮关联的目标（或"还没有关联目标"），有「关联 / 更换目标」（原来的对话框）和「打开目标」；说明关联只影响下一轮。
- 左栏「产物」面的行改成和会话行一样的目录行：图标区分执行报告与固定变更，标题、保存时间、版本与归档标记；搜索框在这个面上可见（原来被会话面的隐藏规则一起藏掉了）。
- 主区域任务图按自己的宽度收列：不到 820px 先收「前置」，不到 620px 再收「进度」，状态和执行者始终保留；时间不再折行。
- 右侧「结果与审查」面板顶部加一行分区索引（协作 · 计划 · 概况 · 成果 · 检查点……），只列当前显示的分区，点一下滚到那一节；只有一个分区时不显示。
- 「在看的会话」以打开和关闭标签为准：关掉会话标签或归档后，任务与目标两个面回到「先选一个会话」；窄屏上按「返回会话列表」不算关闭，两个面继续描述刚离开的会话。
- 顺手修掉：会话列表还没读到（冷启动要几十秒、或恢复标签先读了会话）时，打开会话不再把服务端画好的列表换成「还没有编码会话」；列表读到之后才接管。
