# Feed 来源工作台

目标为内部完整：在 Feed 内完成选择来源、阅读消息、配置拉取和编写捕捉规则。当前来源分组与配置弹窗分离，规则依赖先到 Functions 创建和发布；本次缩短该路径，并保留 Sources、Feed、Functions 各自的数据所有权。

桌面使用固定来源栏与消息工作面：左侧列全部消息及每个来源，显示连接/暂停状态和消息数量，提供添加来源；右侧随选择切换消息、来源设置、捕捉规则。消息阅读留在右栏，返回恢复列表；窄屏来源栏收为可展开导航，不挤成三栏。保留检索、筛选、读取、归档、入箱、资料及 Goal 路径。

添加来源及来源设置使用右侧工作面，替换模态弹窗。配置按资料、拉取计划、运行记录分组，保存范围明确；取消恢复已保存值，失败保留输入。切换来源保留未保存草稿。账号授权沿用 Connectors，Feed 清楚显示连接情况及恢复入口。

捕捉规则在来源内编写：默认关键词，可选自然语言判断，进阶可复用已发布 Functions。自然语言模式通过既有 Functions 公开 HTTP 创建/更新草稿、试跑与发布，Feed 只保存 function_key 引用，不引入第二套判断引擎。真实近期消息用于预览；关键词预览使用生产匹配函数，AI 预览使用 Functions preview。预览不运行 Feed evaluate，不生成 Artifact、不入 Inbox。规则启用后处理新消息；应用已有消息为另一个明确动作。AI 凭据缺失、无样本及调用失败清楚呈现；未试跑/改过内容不可直接发布。保留已有规则和可复用高级入口。

范围：Feed UI/样式/规则预览端点、Workbench Feed 客户端及 i18n/pack 接线、针对性测试、开发说明。Functions 的公开契约与持久化不变；不重做 Functions 整个插件，不修改用户来源或凭据，不部署外部环境。已有工作树改动保留。

验证：Feed/Workbench/Local Host 定向 build 与 typecheck、Feed 规则和来源回归、生产预览无副作用测试；隔离真实 Host 中实操来源选择、阅读返回、内联设置取消/保存、规则预览/保存及失败恢复；桌面/390px/深浅主题截图。AI 成功流程用可控 provider 证实接线，未获明确授权不调用用户真实付费模型。

设计沿用当前中性色与共享控件。首屏明确呈现左侧 GitHub/Gmail/RSS 来源和右侧内容；主要交互是选来源后，消息与配置在同一右侧工作面切换。无需再选视觉方向或审批。

用户授权本任务统筹 Connector 交叉影响。Feed UI 由本任务负责；`修复 Gmail 授权状态不一致` 负责连接身份、Feed 绑定与迁移；`梳理 Connector OAuth 授权逻辑` 负责 OAuth/CLI/手填鉴权方式与 Connectors 页面。共享 Connector 文件由两任务明确单一 writer。Feed 保留项目上下文，消费连接状态与账号选择接口，不复制 token。接口落地后组合验收：选连接 → 配范围/计划 → 拉取 → 写规则；重授权保留游标和设置，失效显示统一原因。Functions UI 任务已同步 Feed 使用的公开 authoring 契约。

连接切换契约补充：供应商去重键也归属 source_id，因此切到不同 connection_id 会创建新来源，暂停旧来源并保留历史；新来源继承计划及捕捉规则。PATCH 返回新 source，UI 刷新后选中新来源。相同连接重授权保留游标，不创建新来源。
