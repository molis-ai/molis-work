## 给人讲清楚

项目首页之后要升级成可选装的 Work Brief：一个能刷新的项目状态页，可以固定成某个版本、看依据来自哪里、改过什么、和上次比有什么变化，还能接上风险。这一批做它的首页和简报核心；不装它的时候仍保留基础首页。做完你能在一页上看清项目现在的状态和下一步。需要你做的：看首页、版本、来源和下一步这几处的样子并定下。

### 开工前五项核对（2026-11-14，main `e0a3b23893`）

1. **首页归平台，现有接口不够，缺口补成平台能力。** 现状：`horizontal/home` 这个包还没有；首页的事实今天在三处——基础首页的组合在 `horizontal/surfaces`（`surfaces.compose@1`，`slot: home`，第 15 批）；首页事项、建议与判断在宿主的 `system.home`（`apps/local-host/src/home-actions.ts`）；「项目用哪个首页」与生成页面的版本只有合同（`packages/contracts/src/services/home.ts`，`contract-only`，运行在第 37 批）。插件今天能给首页的只有卡片：一句概况、几行对象和开始入口（`presentation.overview`），放不下定样的一页简报。**缺口：首页主区内容的通用挂载**（原需求 §1.1「通过通用首页挂载能力承接项目综合首页」）。做法：
   - 合同：`presentation.overview` 加可选的 `lead: { view_id }`，指本插件自己的主区视图；组合服务在 `slot: home` 的描述里多给一组 `kind: "lead"`（宿主此刻选定的那个安装与视图），与卡片同一次目录发现，不点插件名。任何插件（含第三方、沙箱包）都能声明。
   - 页面（用户 11-14 弹窗定）：有这一组时简报占满首页，走主区同一条装载路；右上角「看基础首页」随时切回插件卡片那一页，只是页面状态。否掉「简报在上、卡片在下同页滚动」（要改 S-47）和「不挂首页只给卡片」（WBR-22 做不到）。11-04「不替换平台首页」的原文随本批改成「主区内容可由插件的主区视图承接，本人可切回」。
   - 回退：插件停用、卸载、装载失败或宿主复核不过时没有这一组，首页就是第 15 批的基础首页（15-3 已做的回退不改）。
   - 不做：不在 `UI_VIEW_SLOTS` 加 `home`（场景合同 §6.2），不走侧栏文档（评审查出不支持签名与沙箱包、撞 S-30），不给宿主加按插件名的分支。`horizontal/home` 由第 37 批随生成页面运行建包；到时「选了生成页面」优先于这里的主区内容（随本批 PR 写进 37 批文件）。
   - Work Brief 只拥有简报正文、版本、来源、修订，和它声明的首页概况与主区视图。Home 级、双实例；项目简报与个人简报都做（用户 11-14 弹窗定：个人简报是个人事项的集合汇总，带项目／个人标签和到对应项目的跳转）。形状见[合同设计稿](../../../work-brief/contract-design.md)。
2. **没装 Goals 也完整。** Work Brief 只经目录读来源：各插件的首页概况（`presentation.overview`）、对象读取器与呈现取值、`read_groups`；代码里不出现 Goals 的动作名或状态词。15 批核账点过的 `project-home.ts` 旧写法已随 #2017 删掉（现在只画框架）。验收里至少一组（首页、简报生成与保存、风险接续 WBR-17／18）在没装 Goals 的项目里走通；装着 Goals 时多出的只有 Goals 自己声明的来源与「提出顾虑」动作。
3. **布局与设计语言。** 版式照 11-04 定样不重出；颜色、动效、部件按 07 的工作台布局、`DESIGN.md` 的 Colors → Pairing、Layout → Zones、Motion（#2056、#2063）和组件板分章对照，差异清单与实物先给用户看，再写产品代码；组件板缺的三个部件（插件色标、句后角标、提示里的操作区）先核组件板现状，仍缺的补标本、请 D 轨合审。对照结论：差异八处（来源状态按轮到谁、主人色块、一屏一个墨蓝、提示操作区、「现在」浅底块、变化洗底、弹出层动效、窄屏标题栏），逐处见[原型 README](../../../../docs/design/work-brief-core/README.md)；用户 11-14 看过更新后的原型确认照此写，记入[原需求 §7](../../../work-brief/spec.md#design-decisions)。组件板新增只剩句后角标一处，插件色标与提示里的按钮已有实件。
4. **对象引用与「等你」。** 32-2 的通用对象引用与打开（`objects.open@1`、`OpenTarget`）和 32-3 的「等你」统一读取（`attention.waiting.read@1`）在 `batch/32` 上只有设计稿（`specs/work-line/contract-design.md` §6、§7），合同代码还没写，本批拿不到。最薄的接法：
   - 来源角标和「打开它」不拼地址：对象交给平台已有的挂载位（Work Brief 的主区视图声明 `accepts_forms` 的 slot，经 `host.view.surfaceSlot` 让平台按主人的呈现声明画名片，打开、速览、定位都是平台的那一份；一页至多 4 个，按段用）。Work Brief 的代码里没有 `?openPlugin=`。
   - 「等你」不另读：首页的「等你」仍是组合服务给的那一组；简报里「要你处理」的是简报自己引用的对象，同样交平台画。
   - 32 合入后把 slot 里的打开换成 `objects.open@1`、首页「等你」换成统一读取，改动只在 Work Brief 的一处封装和首页组合里；已在 #1743 的 32 行下评论。
5. **决定卡与授权去处。** 简报的定时生成是 Schedule 的任务（原需求 §1：不新增调度），Work Brief 不声明 `task_subjects`、不调 `host.taskGrants.place`。「去勾选授权」：这一版简报记着是哪个任务跑出来的，就打开那个任务的详情（平台区域在那里）；没有任务信息时去项目设置的「授权与放行」页。卡型里的决定走 39-2 的通用决定入口（先行合同 #2069 还没合入）：本批的「下一步」是选项卡片（原插件的真实动作用 SDK 操作卡，本人点了才以本人身份经动作目录执行；或交给助理，发平台已有的委托消息），做不到决定卡就不引入，不挡首页与简报核心。

- **定样（2026-11-04 用户定）**：首页用一页简报，版本用版本条加「当时／现在」，来源用句后角标，下一步用选项卡片。原型在 [`docs/design/work-brief-core`](../../../../docs/design/work-brief-core/README.md)，决定记在[原需求 §7](../../../work-brief/spec.md#design-decisions)；15 批公共呈现未定样处按原型 README 的假设画。合同、服务与界面实现未开工。

### 实现记录（2026-11-14，分支 `batch/19`）

**做了什么。**

- 平台：首页主区内容（`presentation.overview.lead`、`home` 描述的 `lead` 组、首页把主区视图收进主区与细栏「看基础首页／回到」、打不开时回基础首页）；概况动作的受众加 `workflow`（持有 `actions:delegate` 的插件才读得到别的插件的概况）；插件页面调本安装自己的动作时，持有 `actions:delegate` 的安装带本人的调用者（S-43）。
- Work Brief 插件（`plugins/native/work-brief`，Home 与项目两个实例）：项目简报的保存、刷新（不调模型、只报变化、没变化不存新版本）、逐句依据与缺口、本人修改与补句、草稿与本人修改冲突时的提案、版本与「当时／现在」、固定成成果、下一步（执行一次、暂不、交给助理）、首页概况与对象读取器、搜索来源；个人简报（跨项目汇总，带项目／个人标签与到项目的跳转）；风险接续（WBR-17／18）；移除后首页回基础首页（WBR-23）。
- 页面：一页简报（各来源、现在怎么样、要你处理、和上次比、下一步），句后角标与弹层，版本弹层；别的插件的对象都交平台挂载位，Work Brief 的代码里没有 `?openPlugin=`，也不另读「等你」。

**用户决定（2026-11-14 弹窗）。**

1. 首页挂法：简报占满首页，可切回（开工前第 1 项）。
2. Home 级范围：项目简报和个人简报都有；个人简报是个人事项的集合汇总，带项目和个人标签，带到对应项目的跳转。
3. 页面里的刷新和下一步怎么拿到本人权限：**页面读写都放开**——插件页面调用该插件自己的动作、且插件被授予 `actions:delegate` 时，这次调用带本人权限，刷新和下一步在页面里一次点击完成。代价已在弹窗里说明：有该授权的插件页面脚本可不经点击以本人身份调用别的插件。登记在 S-43，拒绝测试两条（WBR-06）。
4. 新增页面资源 `work-brief.js`（约 37 KB）放行，许可在 `tooling/gates/page-asset-allowances/batch-19-work-brief.json`。
5. 个人简报跨项目跳转：平台加一个窄入口——页面链接是另一个项目的裸首页 `/projects/<项目>/`（不带查询和片段）时外壳才跳转；S-47 正文与拒绝测试同步改（第一轮评审发现原来的链接点了没反应）。

**与原型的差异（照现有平台能力取舍，待本人看实物）。**

- 下一步用 SDK 的通用卡片画，不是助理的操作卡部件：页面在 iframe 里取不到 design-system 的操作卡渲染；执行规则仍是 SDK 的操作卡规则。
- 对象（依据、要你处理、变化、下一步的对象）是平台挂载位画的行：名字、状态、打开都由主人的呈现声明给，每个位置上方带平台自己的一行说明与「只改你在本项目这个位置的显示」。原型里的主人色块没有做：挂载位里已有主人的图标。
- 句后角标的样式在插件自己的样式表里（`.wb-fn`），没有提进组件板：现在只有 Work Brief 一个使用者；有第二个使用者时再做成 SDK 部件并补标本。提示里的操作区用的是 SDK 现成的 `renderAlert` 的 `actions`。请 D 轨在合审里定是否现在就要标本。
- 「要你处理」里不放决定卡：39-2 的通用决定入口（#2069）还没合入，按批文件的要求不引入。

**没做、留给后面的。**

- 决定卡：等 39-2 合入后接（批文件第 5 项）。
- 32 批的通用打开与「等你」统一读取：现在是最薄接法（平台挂载位、组合服务的「等你」组），32 合入后只改 `src/browser/parts.ts` 的 `slot` 与个人简报的项目链接。
- 定时生成：是 Schedule 的任务，第 52 批接；本批给了 `save`、`refresh` 与 `produced_by`。
- 来源名（`SourceRow.name`）存的是保存时读到的插件名原文，不随界面语言变。
- 示范项目不自动启用 Work Brief（`apps/local-host/src/demo-plugin-seed.ts` 的保留名单）：示范项目里还没有一份可看的简报，启用了首页就是一页空简报，盖住各插件的卡片。要让示范项目带简报，先给它种一份有依据的简报再从名单里拿掉。
- 下一步「执行中途被取消」没有自动化用例：`unknown` 状态与清除的逻辑在 `src/next.ts`，要在目标动作运行当中取消调用才能触发，现有夹具做不到确定地复现；合入后由本人实走或 52 批接定时任务时补。
- 下一步的结果句（SDK 操作卡的 `outcome`）是 SDK 给的中文句子，原样存在标记里、英文界面也显示中文；这是 SDK 操作卡现有的写法，不在本批改。

**验证。** `tests/work-brief-plugin.test.ts`（9 条，项目里没有 Goals；含提案等待期间的修改、窄权限调用者的刷新、依据从缺口恢复）；`tests/work-brief-page.e2e.test.ts`（1440、1024、390 三个宽度走完依据、刷新、修改、提案、版本、固定、下一步、个人简报、基础首页；英文深色三个宽度各一条；都断言不横向滚动；个人简报点到另一个项目；WBR-11 内容里的标记不成元素、不执行）；`tests/surface-home-lead.test.ts`；`tests/security-invariants-plugin-action-delegation.test.ts` 的 WBR-06 四条（含跨项目的页面 id、声明了但没被授予 `actions:delegate`）；`tests/security-invariants-plugin-pages.e2e.test.ts` 的 WBR-24 S-47 一条。本机基线同样红、不是本批引入的：`tests/security-invariants-signed-form-gateway.test.ts` 的 3 条（main `6306758c22` 的工作树上同样失败，报 `capabilities:call` 未开启）。
