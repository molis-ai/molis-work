# T-035 Host 关闭时，只停 Runtime 记录里确实在跑的安装，崩掉的不再让整次关闭失败

> **这条在 main 上成立，修的地方在 Host 的关闭循环，不在 Runtime；同意 T-034 不放宽 `preserve_enabled`。** 关闭循环只看 Supervisor 的内存镜像是不是 `running`（`apps/local-host/src/installed-plugin-host.ts:183`），而 Runtime 一侧把安装写成 `crashed` 时不会通知 Supervisor。于是镜像说在跑、记录说已崩，`stopOnce` 抛 `plugin.state_invalid`（`packages/plugin-runtime/src/index.ts:496-498`），整次关闭以 `AggregateError` 失败。同一个仓库里项目内置插件的关闭循环已经多核了一步 Runtime 记录（`apps/local-host/src/project-plugins.ts:97`），Home 的循环本来就按 Runtime 记录走（`home-plugins.ts:167-168`）；只有这一处还信镜像。起草时没有跑任何东西，下面全是读 main 的代码。

## 1. 背景

依据都在 main `c660f1709`：

- 关闭：`installed-plugin-host.ts:175-187`。对 `supervisor.enabledPluginIds()`（`:181`）里每个插件，只有 Supervisor 的状态是 `running` 且有 `install_id` 才带 `preserve_enabled` 调 `runtime.stop`（`:183`），抛错收进 `failures`，最后抛 `AggregateError('安装插件停止失败')`（`:186`）；`revoke` 不管停没停都会做（`:184`）。重启：`:189-205`，除 `disabled`、`quarantined` 以外的记录都登记成 `enabled` 再启动（`:195`）。
- Runtime 的 `stopOnce` 只放 `running`，`disabled` 当重放，其余抛 `plugin.state_invalid`（`index.ts:493-498`）。
- Supervisor 的 `#states` 只由它自己的方法写（`supervisor.ts:267-283`、`:633-662`），不订阅 Runtime。所以「Supervisor `running`、Runtime `crashed`」可以同时成立。生产里到这个状态的路是 `regrant`：它在 Runtime 上直接做，不经 Supervisor（`project-plugin-ports.ts:114`），先带 `preserve_enabled` 停、再 `startOnce`（`index.ts:420-425`、`regrant.ts:38-44`），启动失败写 `crashed`（`index.ts:477-486`）并抛给调用的人。`reportCrash` 在非测试源码里只有定义（`index.ts:447`）和合同接口（`packages/contracts/src/platform/plugin.ts:249`），没有调用方（`git grep` 过 `apps`、`packages`、`plugins`、`horizontal`、`modules`、`server`），测试里只能拿它造同一个状态。
- 后果：`closeProjectRuntime` 收集每一步的失败（`project-host.ts:432-442`），项目库照样关、别的安装照样停（循环里 `failures.push` 后继续），但 `host.close()`、`closeProject` 的调用方拿到 rejection。我没有在真实路径上复现，只读代码。
- `installed` 同理：Supervisor `running` 时有人对它做过一次带 `preserve_enabled` 的停止，记录就是 `installed`，关闭时第二次带 `preserve_enabled` 的停止抛同一个错。生产里除 `regrant` 的中间态（持锁，`regrant.ts:33-44`）外到不了；测试里 `runtime.stop(id, { preserve_enabled: true })` 一句造出来（回答 MISC 里 T-032【方案】问题 1）。

为什么在 Host 修：

- Runtime 这边：带 `preserve_enabled` 的停止对 `crashed` 记 `installed` 会抹掉崩溃，记 `disabled` 会替人做决定；T-034 也让它们继续被拒（`packages/plugin-runtime/README.md:79` 写明该选项只保留 installed，失败仍记 crashed）。Runtime 不该为 Host 的关闭放宽。
- Host 这边三个关闭循环，别的两个已经对：项目内置插件两头都核（`project-plugins.ts:97`，注释 `:94-96`）；Home 的 `release` 遍历 Runtime 记录、只停 `running`（`home-plugins.ts:162-181`）；Home 安装插件自己的 `close` 只撤曝光（`home-installed-plugins.ts:147`），进程由上一条停，没有同类问题。Supervisor 自己的 `revoke` 也先读 Runtime 状态，不是 `running` 就不停（`supervisor.ts:286-292`）。
- 不取的做法：吞 `plugin.state_invalid`（把「该停的 running 却被拒」也吞了）；让 Supervisor 跟着 Runtime 变（共享核心，三个 Host 的行为都会动）。

有没有东西依赖「关闭会 reject」：`git grep` 整个仓库，`安装插件停止失败` 只在源码 `:186` 和 `tests/installed-plugin-host.test.ts:651`。那一例把 `runtime.stop` 换成「真停了再抛」（`:648-649`），关闭时安装是 `running`，修后仍走 stop、仍 reject，不受影响。项目内置插件的 `tests/project-plugin-startup.test.ts:70-77` 是另一处，不动。

## 2. 目标

1. Runtime 记录是 `crashed` 而 Supervisor 仍 `running` 的安装，关闭 Host 不再 reject；记录保持 `crashed`（不是 `disabled`、不是 `installed`）；重新打开后提示词是 `enabled`、不是 `disabled`（`RAC-1196`）。
2. 记录是 `installed` 而 Supervisor 仍 `running` 的安装，关闭不再 reject；重新打开后它 `running`（`RAC-1197`）。
3. 在跑的安装关闭时仍然被停：恰好一次 `stop`、带 `preserve_enabled`，重新打开后它 `running`（`RAC-1198`）。

- 不改 `home-plugins.ts`、`home-installed-plugins.ts`、`installed-plugin-lifecycle.ts`、`installed-plugin-exposure.ts`。
