状态：待用户选（2026-11-04 出样）：平台确认面 A 对话框／B 侧板／C 弹层三选一；Schedule 的「能读的数据」一行和列表标记三个方案共用。用户定下后写进[主动助理 §5.4.1](../../../specs/proactive-assistant/spec.md) 的决策记录。产品代码还没写。

这是参考原型，不是产品界面。需求是[主动助理 §5.4.1](../../../specs/proactive-assistant/spec.md)（PWA-148～153），实施方案见[定时任务按任务授权读取业务数据](../../../specs/proactive-assistant/schedule-task-reads.md)（§3.7 与 §5 的 P1），排期见[第 18 批](../../../specs/post-anticorruption-roadmap/reference/batches/18.md)。已定的不再问：勾选和写入只在平台确认面上完成（方案 §3.7 A，统筹 2026-11-04 定）；项目资料作为一类出现，默认不勾。这里要定的是确认面长什么样。

确认面归平台，以后由 D 轨实现（P3）；Schedule 一侧（E 轨，P2）只有表单里一行入口和列表里的标记。按统筹派单，两块的样由 E 轨一并出，确认面这一块请 D 轨共审。

控件、对话框、侧板、勾选、开关、条目行、状态都由组件板的渲染函数画出（`window.MW`，见[组件板实件](../component-board/README.md)），样式就是组件板现行的那一份；`grants.css` 只排位置、只用组件板令牌。

## 怎么打开

先按[组件板实件](../component-board/README.md#生成)生成 `component-board/dist/`，再在仓库根目录运行，然后打开 <http://127.0.0.1:4422/schedule-task-grants/>：

```sh
python3 -m http.server 4422 --bind 127.0.0.1 --directory docs/design
```

顶上一条斜纹是**原型控制**，不是产品的一部分：切确认面方案（A／B／C）、区域（任务表单／任务列表）、状态、中英文和浅深色；「重置」清掉本页记住的选择（`localStorage` 键 `molis-proto.schedule-task-grants.v1`）。确认面默认开着；关掉后点表单或详情里的「修改」「选择能读的数据」「重新确认」再打开。宽度 1440、1024、390 都看过。

## 确认面：三个方案

三个方案的内容相同：标头一行「Molis Work · 只有你能确认」（让人分清是平台在问，不是插件）、「每日简报能读哪些数据」、插件的数据按提供它的插件一类一行（写明包含什么）、「平台」下的项目资料（默认不勾）、底部一句改动摘要（允许读什么、撤回什么、撤回后下一次运行起读不到）、取消／确认，以及「只能读，不能改 · 只给这个任务 · 可随时撤回」。

| 方案 | 样子 | 取舍 |
| --- | --- | --- |
| **A 居中对话框（推荐）** | 叠在 Schedule 的表单之上，一类一张选项卡片（组件板的 `mw-ix-option`，可多选），两列 | 一眼看全、选中很醒目，平台身份最清楚；看不到身后的表单。窄屏一列 |
| B 右侧板 | 从右边滑出（组件板的 `mw-sheet`），一类一行加开关，每行再写出这一类包含的读取能力（「列出待办、读一条待办」） | 最透明，身后的表单还看得见；占地大，窄屏铺满全屏 |
| C 锚在那一行下面的弹层 | 从「修改」按钮下弹出（组件板的 `mw-popover`），紧凑的勾选行，不写长说明 | 最轻、不离开表单；平台身份弱，像插件表单的一部分，类多时要滚动，窄屏局促 |

推荐 A：这是一次授权，平台身份要清楚，摘要和撤回后果要看得见；B 次之（愿意多占地方换透明）；C 只在希望极轻时选。

## Schedule 一侧（三个方案共用）

- **表单里一行「能读的数据」**：已授权的类用标签列出，旁边「修改」；没选时写「没有选，只读项目文件」，按钮「选择能读的数据」，这时才显示「读文件的任务要先选工作区」的提示（选了数据就不需要工作区）。
- **列表**：每条任务前一个种类图标（读数据／读文件，悬停有字），需要重新确认时状态换成「需要重新确认」。
- **详情**：标题下一行「能读」，与表单同一份写法，可以直接改；结果后面写「依据」读了多少条。

## 状态

| 状态 | 表单与详情 | 确认面 |
| --- | --- | --- |
| 已授权 4 类 | 标签列出待办、Jelly、Schedule、Goals | 已选 4 类，摘要「没有改动」，确认不可点 |
| 还没选（只读项目文件） | 「没有选，只读项目文件」＋工作区提示 | 全部不勾；勾上后摘要「允许读：…」 |
| 没有可读的插件数据 | 同上：只读项目文件，带工作区提示 | 插件部分是空状态，写明装了哪类插件会出现；项目资料仍可勾 |
| 需要重新确认 | Jelly 多了一项读取能力：一行「确认前读不到」，按钮换成主按钮「重新确认」；列表状态「需要重新确认」 | Jelly 那一类标「新：读笔记全文」，摘要「确认 Jelly 新的读取能力」 |
| 一类的插件已停用 | 「Jelly 已停用，这一类暂时读不到」，授权留着 | Jelly 标「已停用」 |
| 撤回一类 | 确认后标签少了待办；对话里一条系统记录「你撤回了待办」，下一次运行如实说「没有授权读待办」 | 待办已取消勾选，摘要「撤回：待办。下一次运行起读不到」，按钮「确认撤回」；另有「全部撤回」 |
| 失败 | 详情：「暂时读不到这个任务的授权状态」，说明到点照常按上次确认的范围读，给重试 | 表单里打开时先读不到可选的数据（写明不代表没有），重试后能选；点确认又保存失败（原来的授权没变），给重试 |

## 组件板新增（交 D 轨补标本）

| 部件 | 原型里的写法 | 为什么要 |
| --- | --- | --- |
| 平台确认面的标头 | `.gr-kicker`：盾牌图标＋「Molis Work · 只有你能确认」 | 插件请平台打开的确认面要一眼分得出是平台在问；组件板的对话框、侧板、弹层都没有这一行 |
| 插件色标 | `[data-hue]` 给 `mw-mark`、`mw-tag` 里的图标着 `--hue-*`（与第 19 批相同） | 一类就是一个插件，靠颜色分得开 |
| 提示里的按钮 | `.gr-alert-actions`（与第 17、19 批相同） | 读不到、保存失败要在提示里直接重试 |
| 选项卡片里的图标与状态 | A 方案在 `mw-ix-option` 的标题前放 `mw-mark`，描述下加一个状态标 | 组件板的选项卡片只有标题、描述和勾；这里要标出插件和「新：…」「已停用」 |
| 条目行里的开关 | B 方案在 `mw-item__end` 放 `mw-switch` | 组件板的条目行末尾是状态或按钮，没有开关的标本 |

另：组件板 `mw-ix-option` 选中是整张深色（单选设计的），多选里 4 张都选中时分量很重；A 方案照用，请 D 轨看是否要给多选一个轻一些的选中样子。

## 模拟边界

- 数据是编的（`data.js`），不读任何 Home；类别名单在产品里由宿主从目录生成（只读动作按提供方分组），这里写死了 6 类做示例。
- 勾选、确认、撤回只改本页内存，刷新或「重置」回到初始；不调 `agent.task_grants.*`，没有授权检查。
- 表单的保存、取消、关闭，列表行、暂停、归档、新建、选择工作区、重试只弹一句提示。
- 运行结果是写死的样例，不调模型。
- 原型里对话框用 `open` 摆在舞台上、不进顶层模态，是为了不挡住原型控制条；产品里照组件板用模态对话框和侧板。
