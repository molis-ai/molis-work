# Coding 与 Agent 工作流优化需求书

状态：需求已整理（2026-10-15），2026-10-24 补充 TaskBoard 斐波那契 Story Point 与整体进度估计（R14）；2026-10-27 用户确定 R1 的 A 方案：默认联动，临时查看别处不改变执行目录（BL-023），并确定每项目多个输入目录、一个可修改的固定输出目录，输入输出可相同；见[整合方案](../product-flow-governance/workspace-and-materials-design.md)。本次交付为需求与职责划分，尚未授权本需求的实现。目标完成程度为**内部完整**：真实目录、真实模型、完整任务、异常恢复和关键界面可以顺畅试用；不以工程测试通过代替产品实操或用户认可。

需求统筹：本会话 Codex；Coding、平台及 Prologue 实现负责人待分配。输入回执与用户纠正继续由 **Claude「正在做｜输入回执与任务关联」**负责，不重新分配。本文是本轮优化的总合同，既有产品合同与专门需求保持各自所有权。

## 1. 要交付的结果

用户可以在项目中选择真实目录，从 Coding 或个人助理发起开发任务，使用正确的项目规则、Skill、工具和模型设置，连续完成修改、验证及结果交付。中途补充、更正、失败、模型超时或宿主重启后，仍能知道当前要求、完成到哪里、为什么停下以及如何继续。执行中的界面保持稳定，长会话与较大 Dataset 可正常操作。

Coding 可在授权范围内操作浏览器与桌面，协调有依赖关系的多项动作；Git 区域以紧凑方式呈现分支、改动、PR、当前提交的检查与部署结果。Plugin Builder 能从需求走到一个可安装、可实际使用的插件，并在失败后保留有效成果与明确的修复入口。

Coding 的 TaskBoard 按每项任务的 Story Point 加权展示整体预计进度，让用户看到已完成多少相对工作量、还有多少，以及任务范围变化为何影响百分比；估计不代替实际完成与验收事实。

### 1.2 边界

保留已有会话、角色、文件与命令工具、TaskBoard、子代理、工作树、动作目录、审查、检查点、执行回执和恢复机制；先接通和修正现有能力。本文不授权自动推送、开 PR、部署、发布或修改真实 Home；实现后的这些动作仍由用户已有授权和平台策略决定。

本轮不重写 Agent 引擎，不增加第二套任务板、输入账或权限系统，不强制每个任务先规划或启用多代理，不新增云端执行、IDE 扩展、所有 Git 托管平台支持。语义索引、语言服务器扩展和额外评审角色只在任务评估证明有收益后进入具体实现范围。

## 3. 职责与唯一事实来源

这里的“Molis 平台”包括 Host、agent-host、工作台壳、设计系统和统一动作服务；Coding、Dataset、Git、Plugin Builder 是 Molis 内的领域插件，不能通过彼此实现文件通信。

| 事项 | Coding / 其他领域插件 | Molis 平台 | Prologue |
| --- | --- | --- | --- |
| 开发任务与完成标准 | Coding 拥有任务语义、计划输入、变更与验证报告；Goal 状态仍归 Goals | 提供动作、资料、运行与回执访问 | 执行 Session/Run；提供 hook、停止/继续与 TaskBoard 原语 |
| TaskBoard 估点与整体进度 | Coding 提供 AI 初估、用户调整入口、估计依据及进度展示 | 经公开合同执行授权写入与事件投影，不另存一份任务进度 | TaskBoard 保存节点估点与进展事实；通用加权汇总沿现有模块扩展，整体百分比由同一份事实推导 |
| 目录与运行环境 | 展示/选择工作区、提出任务所需启动与测试步骤 | 真实目录、信任、路径授权、工作树、进程、端口和 OS 操作 | 通过 Host ports 使用资源；不拥有 App 的项目与安装事实 |
| 模型与上下文 | 提供领域保留策略与任务资料；展示设置 | 模型目录、凭据引用、用户配置、生效配置解析与跨入口传递 | 通用预算校验、上下文打包/压缩/续接、实际模型请求与用量事实 |
| 项目规则与 Skill | Coding 展示来源、选择与任务用途 | 决定项目可信性、版本及来源，挂载授权能力 | 复用已有分层规则、按需 Skill 与工具加载机制 |
| 用户补充与纠正 | 消费公共输入视图；Coding 接好摘要和续做路径 | Claude 输入回执线拥有 App 来源、用户操作、投影与跨入口接入 | 输入身份、队列、读到/处理说明事件与通用上下文原语；不证明业务已完成 |
| 工具、并发与副作用 | 声明业务动作与依赖，不自建调度循环 | 统一目录、可用性、审查、撤权、驱动与外部集成 | 通用工具批次、锁、等待、取消、回执、未知结果恢复 |
| UI 与性能 | 各插件自己的渲染、编辑状态和交互 | 共享状态组件、请求与事件投影、面板与可访问性 | 提供运行事实；不含 DOM、滚动或视觉样式 |
| Git、PR、CI/CD | Git 拥有仓库操作语义和紧凑工作区；Coding 只引用结果 | 平台连接、身份/凭据、受授权的托管服务适配 | 不内置 GitHub UI、部署业务或第二份 Git 状态 |
| Builder / Dataset | 各自拥有构建/安装业务与数据编辑规则 | 复用共同模型、授权、动作与插件运行设施 | 只承接被多个消费者实际需要的通用运行机制 |

通用能力下沉顺序：先核对 SDK 当前公开合同和已实现能力，再接适配器；只有多个消费者存在同类缺口时才扩展 Prologue 既有模块。Molis 不绕过 agent-host 直接依赖 SDK，Prologue 不 import Molis 业务类型。共享状态写回原 owner，禁止靠另一份状态表“对齐”。

## 6. 行为要求

### R1 · P0：目录选择到真实执行

等待 OS 选择器真正完成，区分选中、取消、窗口占用、不可用、超时与非法目录。选中后回填完整路径；关联完成后输入可用于获准的读取，输出可用于获准的修改及运行验证。取消保留原值；失败可重试且不留下假成功。中文、空格、符号链接按 Host 现有规范化与授权规则处理。UI 明确选择的是输入还是输出目录；文件附件入口不冒充目录选择。

**2026-10-27 用户决定（BL-023，A）**：每个项目可选多个输入目录，固定一个输出目录；输入集合与输出位置都可由用户修改，输入与输出允许相同。现有代码仓库可同时作为输入和输出以直接修改原仓库，其他输入目录作为参考，不因关联而获得写入／执行权限。新轮次使用项目当前输出，临时并行工作树沿既有整合审查交回该输出，不另设会话长期输出配置；项目输出与原生插件内容存储的边界见[整合方案 §2](../product-flow-governance/workspace-and-materials-design.md#2-已确定多个输入一个输出)。

### R14 · P1：TaskBoard 斐波那契估点与整体进度

**任务估点。** Coding 创建或拆解 Task 时，AI 根据当前任务的相对工作量、复杂度和不确定性给出初始 Story Point 与简短依据；用户可查看并调整。可选点数采用去重后的正斐波那契数列：**1、2、3、5、8、13、21、34、55……**，后续值由前两项相加；不采用 0、任意整数或小数作为估点。点数不等于小时、token 或费用，大点数任务可以建议拆小，不强制按点数拆分。无法合理估计时显示“未估点”，不悄悄当作 0 或 1；已有未估点任务可补估。用户调整值优先，AI 不得在无说明的情况下覆盖。

**计算口径。** 整体范围是当前 Board；计算只包含当前范围内不重复的可执行叶子任务，包括已完成任务。任务点数为 `sᵢ`，有依据的完成比例为 `pᵢ`（0 至 1），则：

**整体预计进度 = Σ（sᵢ × pᵢ）÷ Σsᵢ × 100%。**

例如 2、3、5 点的三个任务，前两个完成、第三个未开始时为 **50%（5 / 10 点）**，不是按数量计算的 67%。未开始为 0，满足任务完成标准的为 1；进行中只有明确的子步骤或阶段及其完成依据时才计入部分进度，不能按耗时、工具调用次数、token 消耗或模型自述自动增长。若上述 5 点任务有可核对的 50% 阶段完成，则整体预计进度为 75%。阻塞、等待、失败或暂停本身不增加进度；已验证的部分成果仍有效时保留相应进度，失效或重开时按剩余工作回调并说明原因。

**层级与范围。** 父任务展开为子任务后，父任务的展示点数与进度由子任务汇总，原父估点不再额外计入；父级汇总点数可以不是斐波那契数，这是求和结果，不是另一项独立估点。独立的父级工作须列为子任务，避免遗漏；共享依赖按同一任务身份只计一次。新增、移出范围、拆分、合并或重新估点时按新范围重算，说明范围或估点变化造成的上升/下降；不为保持百分比单调上升而隐去剩余任务。停止执行不等于从需求范围移除，取消运行仍保留未完成任务；只有明确移出范围的任务才退出分子与分母。无任务时显示“暂无任务”，有未估点任务时标明数量，只能展示“已估算部分”的进度，不能冒充完整范围的总进度；没有可计算点数时显示待估算，不显示 100%。

**用户体验与事实。** Task 上能看见点数、估点依据和调整入口；Board 在现有紧凑布局内显示“预计进度 50% · 5 / 10 点”，可展开查看组成及最近变化原因。有部分任务进度时，将分子称为“折算进度点数”，不把它说成已经完成的任务点数。未完成任务仍在范围内时不得因四舍五入显示 100%；百分比不自动触发任务完成、Goal 验收或外部发布。保留 R5 的执行、验证与验收状态，阻塞原因同时可见。

**职责与恢复。** 节点估点、进展及修改走 Prologue TaskBoard 现有版本化合同，由 Molis 授权入口传递，Coding 负责领域估计与交互；整体百分比从这些事实推导，不作为第二份可独立写入的状态。刷新、重启、切会话后从同一 Board 恢复，用户改点与 Agent 更新进展并发时沿现有冲突处理，不静默覆盖；不改调度优先级，也不因点数推导时限或费用承诺。实施前与 Prologue 采用线核对最新公开合同和已有进展字段，先对齐共同合同再接 Coding，避免重复建设。
