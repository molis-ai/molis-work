## 1. 背景

- **工作台另存文件的两条路，最后都进同一个函数 `downloadPageBlob`（`links.ts:13-18`）**：
  - **A：页面自己给名字。**插件页面调 `page.host.download(blob, 文件名)`（`plugin-frame/files.ts:14-17` 用 `postMessage` 发 `{ type: "download", bytes, filename, mime }`）→ 工作台外层 `parent.ts:156` 检查 `filename` 是字符串 → `downloadPageBlob(new Blob(…), message.filename, scope)`，用 `<a download>` 点一下另存。`filename` 是页面代码给的任意字符串，没有长度上限（只受内存限制）；
  - **B：页面里的链接带 `download` 属性。**`child.ts:116` 把点击发成 `{ type: "link", url, download: true }`（`download` 属性的值不用，名字由服务端定）→ `parent.ts:169` 调 `downloadFrameFile`（`links.ts:4-11`）：同源检查，带页面凭据取文件，名字从响应头 `Content-Disposition: …filename*=UTF-8''<编码>` 里取（没有这个头就叫 `download`），`:10` 先 `.slice(0, 200)` 一次，再交给 `downloadPageBlob`；
  - 两条路的名字最后都落在 `:15` 的 `link.download = filename.slice(0, 200)`。所以**截一次就够，放在 `downloadPageBlob` 里**（第 5 节第 2 条）。

- **Jelly 的退化窗口，数字**（独立脚本验过，`E` 是 `😀`）：标题 k 个 `E`，导出文件名的单元数是 `2k + 5`（HTML）或 `2k + 3`（Markdown）。旧截点在 200：
  - k ≤ 97：HTML 至多 199 个单元，Markdown 至多 197 个，不动；
  - k = 98：HTML 201 个单元，被截成以 `😀.htm` 结尾；Markdown 199 个单元，不动；
  - k = 99：Markdown 201 个单元，被截成以 `😀😀.m` 结尾；HTML 203 个单元，被截成以 `😀😀.h` 结尾；
  - k = 100：Markdown 203 个、HTML 205 个单元，都被截成整整 100 个 `😀`（200 个单元），**扩展名一个字都不剩**。
- **Cognia、成果库的例子**：`"a"×226 + ".pdf"`（230 个单元）旧代码另存成 `aaaa…`（200 个 `a`，没有 `.pdf`）；新代码是 196 个 `a` 加 `.pdf`。`"x"×240 + ".md"`（243 个单元）旧代码末尾是 `xxxx`，新代码末尾是 `x.md`，共 200 个字。
- **「截在字中间」的后果**：一个落单的高代理（半个字）能原样通过 `postMessage` 和 `link.download`，落到文件系统的 UTF-8 名字里变成 U+FFFD（T-190 书里用 `Buffer.from` 验过同一件事）。
- **不展开整串的理由**（第 8 节第 1 条）：路 A 的名字是页面代码给的，没有上限；`[...name]` 要把整串变成数组，几百万个字就是几百毫秒到几秒、上百 MB。所以只对「扩展名之前的部分的前 400 个单元」展开：400 个单元里至少有 200 个完整的字，取前 `200 - 扩展名长度` 个，和展开整串再取前 n 个结果相同（独立脚本对 40 万个随机串比过，0 个不同）。`RAC-2163` 钉住「至多展开 400 个单元」。
- 浏览器和系统对一个文件名另有自己的处理（上限按字节、非法字符、改名）；`200` 是工作台自己定的上界，不是系统的上限，本单不改这个数，也不依赖浏览器的处理：`RAC-2164` 读的是 Chrome 下载开始时报的 `suggestedFilename`，不是落盘后的名字。
- 项目里按整字截的先例（`[...x].slice(0, n).join("")`，T-079；T-184、T-190 同一类）：`plugins/native/ppt/src/pptx.ts:166`、`plugins/native/form/src/fillpage.ts:100`、`plugins/native/jelly/src/actions.ts:74`（先截两倍再展开，T-190 的写法，本单照它）。工作台这一包里框架脚本是 esbuild 从 TS 打的（`apps/workbench/package.json:28`，`entry.ts` 打成 `dist/plugin-frame-client.js`），所以 `links.ts` 里可以写 TS，不是 `String.raw` 字符串脚本。

## 2. 目标

1. 工作台另存插件页面的文件时，文件名**按整字数**：至多 200 个字（含扩展名），一个两单元字（如 `😀`）算 1 个字；截的位置落在字与字之间，不会以半个字结尾；两条下载路（页面自己给名字、带 `download` 的链接）都是；
2. **截的时候留住扩展名**：名字末尾的一个点加 1 到 10 个 ASCII 字母或数字（`.pdf`、`.html`、`.tar.gz` 里的 `.gz`）原样接在截后的名字后面，整个名字仍不超过 200 个字；
3. **放得下的名字一字不差**：不超过 200 个字的名字（含 400 个单元的 200 个 `😀`、Jelly 的 205 个单元、Form 的 171 个单元）原样另存；没有 `Content-Disposition` 的链接仍叫 `download`；
4. 超长名字的截取代价有界：一个几百万个字的名字，至多展开 400 个单元；
5. 用例钉住上面四条：撤销任一处、改错任一个数，各自都红；真实 Chrome 里 Jelly 导出标题是 100 个 `😀` 的笔记，下载开始时报的名字是 100 个 `😀` 加 `.html`。

   ```ts
   import type { FrameScope } from "./types.js";

   /** The most characters a file name saved from a plugin page may have. */
   const FILE_NAME_LIMIT = 200;

   /**
    * Whole characters, not UTF-16 units (a two-unit character such as an emoji is one), and a cut keeps the extension: a dot and up to ten
    * ASCII letters or digits at the very end, which is why only the last 11 units are looked at. A name from a page has no limit of its own,
    * so only a bounded piece is spread into characters. A name that fits comes back unchanged.
    */
   function savedFileName(name: string): string {
     const extension = /\.[A-Za-z0-9]{1,10}$/u.exec(name.slice(-11))?.[0] ?? "";
     return [...name.slice(0, name.length - extension.length).slice(0, 2 * FILE_NAME_LIMIT)].slice(0, FILE_NAME_LIMIT - extension.length).join("") + extension;
   }

   /** Downloads use the page's exact read authority. The plugin never receives the owner's blob URL. */
   export async function downloadFrameFile(url: URL, pageId: string, scope: FrameScope): Promise<void> {
     if (url.origin !== location.origin) throw new Error("Download refused");
     const response = await molisWorkRequest<Response>(url.href, { headers: { "x-molis-plugin-page": pageId }, as: "response", scope, signal: scope.signal });
     if (!response.ok) throw new Error(molisWorkRequest.text(await response.json()));
     const blob = await response.blob(); scope.assertCurrent();
     const encoded = /filename\*=UTF-8''([^;]+)/i.exec(response.headers.get("content-disposition") ?? "")?.[1];
     downloadPageBlob(blob, encoded ? decodeURIComponent(encoded) : "download", scope);
   }

   export function downloadPageBlob(blob: Blob, filename: string, scope: FrameScope): void {
     const address = URL.createObjectURL(blob), link = document.createElement("a");
     link.download = savedFileName(filename);
     link.href = address; link.hidden = true; document.body.append(link); link.click(); link.remove();
     scope.own(() => URL.revokeObjectURL(address));
   }
   ```

   行号对应：旧 `:3`（`downloadFrameFile` 的注释）变 `:16`，旧 `:10` 变 `:23`，旧 `:15` 变 `:28`。

   说明：
   - **`extension`**：`name.slice(-11)` 只看名字最后 11 个单元（一个点加 10 个字母或数字正好 11 个）；正则带 `$`，所以点和字母数字必须一直到名字末尾。一个名字没有扩展名（或扩展名含中文、超过 10 个字母）时是空串。`.tar.gz` 只匹配 `.gz`（正则从点开始，中间不许再有点）；
   - **先把扩展名拿掉再截**：`name.slice(0, name.length - extension.length)` 是扩展名之前的部分；`.slice(0, 2 * FILE_NAME_LIMIT)` 先按单元截到 400，再 `[...]` 展开成字：400 个单元里至少有 200 个完整的字（一个字最多两个单元），多出来的一个落单的高代理（400 个单元切在两单元字中间时）排在第 201 个以后，被后面的 `.slice(0, 200 - 扩展名长度)` 丢掉；
   - **`.slice(0, FILE_NAME_LIMIT - extension.length)`**：取前 `200 - 扩展名长度` 个字，`.join("")` 合回串，再接扩展名，整个名字至多 200 个字；
   - **放得下的名字原样**：不超过 200 个字的名字，扩展名之前的部分不超过 `200 - 扩展名长度` 个字，展开再取前 n 个就是它自己，接回扩展名，一字不差（独立脚本对 40 万个随机串验过，其中短于 200 个单元的 0 个被改）；
   - **不加「名字不超过 200 个单元就直接返回」的一行**：加上它多 26 字节（第 8 节第 4 条），结果一样；
   - 注释是英文（界面翻译门禁只管中文，翻译调用外的注释不算）；
   - `savedFileName` 不导出；通过 `downloadPageBlob`、`downloadFrameFile` 两个导出的函数测（第 3 条）。

2. **为什么 `:10` 的 `.slice(0, 200)` 去掉，而不是留着**：两条路最后都进 `downloadPageBlob`，名字在那里截一次。留着 `:10` 的话，路 B 的名字先按单元截到 200（可能截在字中间、丢扩展名），`savedFileName` 再也救不回来。

3. **纯 Node 用例 `tests/workbench-download-file-name.test.ts`（新文件）原样**。不起浏览器、不起 Host：用 `esbuild` 把 `links.ts` 的源文件打成一段脚本，放进 `node:vm` 的上下文，上下文里只有 `links.ts` 用到的几样东西（`document`、`location`、`molisWorkRequest`、`URL`、`Blob`）的最小替身，`<a>` 的替身记下被点击时的 `download` 属性；另外给上下文里的 `String.prototype[Symbol.iterator]` 装一个计数器，数「被展开成字的单元数」。写法照 `tests/security-invariants-assistant-thread-offer.test.ts`、`tests/form-draft-retry.test.ts:14`（`esbuild.buildSync` 加 `new URL(…, import.meta.url)` 读源文件，不是 `import`）。

   // one cut: a page hands the shell a file it named (`downloadPageBlob`), and a page link marked `download` is fetched under the page's
   // authority and named by the response's Content-Disposition (`downloadFrameFile`). The name is at most 200 whole characters (a
   // two-unit character such as an emoji is one), and a cut keeps the extension. The source runs bundled, on a small page port that
   // records the `download` attribute of the link the shell clicks.
   import assert from "node:assert/strict";
   import test, { type TestContext } from "node:test";
   import { fileURLToPath } from "node:url";
   import vm from "node:vm";
   import { buildSync } from "esbuild";

   const LINKS = buildSync({ entryPoints: [fileURLToPath(new URL("../apps/workbench/src/browser/plugin-frame/links.ts", import.meta.url))],
     bundle: true, write: false, format: "iife", globalName: "Links", platform: "browser", target: "es2022" }).outputFiles[0]!.text;

   /** The shell's page, as links.ts uses it: links that remember their `download` when clicked, and a response that says what the case gives. */
   const shell = () => {
     const saved: string[] = [];
     let disposition: string | null = null;
     const request = Object.assign(async () => ({ ok: true, headers: { get: () => disposition }, blob: async () => new Blob(["x"]), json: async () => ({}) }), { text: String });
     const context = vm.createContext({ URL, Blob, location: { origin: "http://localhost" }, molisWorkRequest: request,
       document: { createElement: () => ({ download: "", href: "", hidden: false, click() { saved.push(this.download); }, remove() {} }), body: { append() {} } } });

     vm.runInContext("globalThis.spread = 0; { const iterate = String.prototype[Symbol.iterator]; String.prototype[Symbol.iterator] = function () { spread += this.length; return iterate.call(this); }; }", context);
     vm.runInContext(LINKS, context);
     const links = vm.runInContext("Links", context) as Links;
     const scope: Scope = { signal: undefined, assertCurrent() {}, own() {} };

         saved.length = 0; disposition = name === null ? null : `attachment; filename*=UTF-8''${encodeURIComponent(name)}`;
         await links.downloadFrameFile(new URL("http://localhost/api/plugins/x/file"), "page-1", scope); return saved[0]!;
       },
     };
   };

   const E = "😀"; // U+1F600: two UTF-16 units, one character
   /** Every case goes down both roads, and both must save the same name. */
   const both = async (t: TestContext, cases: Array<[string, string, string]>) => {
     const page = shell();
     for (const [name, given, saved] of cases) {
       await t.test(`page: ${name}`, () => assert.equal(page.byPage(given), saved));
       await t.test(`link: ${name}`, async () => assert.equal(await page.byLink(given), saved));
     }
   };

   test("RAC-2160 a name over 200 characters is cut between characters, never inside a two-unit one", async t => {

       ["only the last part of .tar.gz", "c".repeat(250) + ".tar.gz", "c".repeat(197) + ".gz"],
       ["an extension of ten letters", "d".repeat(250) + ".abcdefghij", "d".repeat(189) + ".abcdefghij"],
       ["a part of eleven letters is no extension", "d".repeat(250) + ".abcdefghijk", "d".repeat(200)],
       ["a part that is not letters and digits is no extension", "e".repeat(250) + ".中文", "e".repeat(200)],
     ]);
   });

   test("RAC-2162 the limit is 200 characters, not 200 UTF-16 units: a name that fits is saved as it is", async t => {
     const fits: Array<[string, string]> = [

   为什么成立（写进【方案】，PR 里也写），期望值手算（`E` 是 `😀`，2 个单元、1 个字）：

   - **RAC-2160**（6 个子例，3 个例子）：
     - 例 1：`a×199 + E + 尾×10` 是 211 个单元、210 个字，没有扩展名；展开后取前 200 个字：`a×199 + E`。旧代码在第 200 个单元截，199 个 `a` 加一个高代理，以 `\ud83d` 结尾；

     - 例 3：`尾×201`，改前改后都是 200 个，绿，守的是一字一单元的路径；
   - **RAC-2161**（14 个子例，7 个例子）：
     - 例 1：`a×230 + .pdf`（234 个单元）。扩展名 `.pdf`（4 个），前面 230 个 `a`，取 `200 - 4 = 196` 个：`a×196 + .pdf`，共 200 个字。旧代码是 200 个 `a`，没有 `.pdf`；
     - 例 2：`E×250 + .md`。扩展名 `.md`（3 个），前面 `E×250` 先截 400 个单元（200 个），取 `200 - 3 = 197` 个：`E×197 + .md`；

## 8. 与默认不同的

1. **200 的单位：整字（码点），不是 UTF-16 单元。统筹觉得要换，在【方案】阶段说。**理由：
   - 仓库的约定是按字数数（T-079、T-184、T-190 和合同 schema 的 `maxLength` 都数码点）；这几个任务合入以后，各插件产出的名字都是按字数定的上限（Jelly 100 个字、Form 80 个字…），工作台最后一道关用单位不同的数，会把前面按字数放行的名字再砍一次：Jelly 100 个 `😀` 加 `.html` 本来合规，被按单元砍掉扩展名，这是本单的起因；
   - 用户看到的「200」是字：200 个汉字是 200 个单元，200 个 `😀` 是 400 个单元，按单元数就让含表情的名字只剩一半容量；
   - 文件系统的上限按字节（常见 255 字节），既不等于 200 个单元，也不等于 200 个字；200 是工作台自己定的上界，本单不改数，不替系统管字节。
   - **另外几种选择，统筹可以裁（页面资源字节数是起草时在 main 的一份拷贝上、用 `apps/workbench/package.json:28` 的参数量整个 `entry.ts` 得到的，基数 69170）：**
     - B：仍按单元，截到 200 再去掉结尾落单的高代理，扩展名照留：`name.slice(0, name.length - extension.length).slice(0, 200 - extension.length).replace(/[\ud800-\udbff]$/u, "") + extension`。不用展开整串，**页面资源 +143 字节（比本单写法的 +137 还多）**，所以省字节不是理由；代价是含两单元字的名字只能放 100 个字，Jelly 的 100 个 `😀` 加 `.html`（205 个单元）仍被截成 97 个 `😀` 加 `.html`，和 T-190 刚放宽的 100 个字对不上；用例的期望值要改（例 1：`a×199 + E` 的 `E` 被去掉；例 2：`E×100`；`RAC-2162` 的 400、303、205 个单元三个例子要改成被截的）；
     - C：按 UTF-8 字节数截到 255（文件系统的口径）：最对得上系统，但仓库里没有按字节截名字的先例，要选截在哪个字节（不能截在一个字的字节中间）、`.slice(0, n)` 没有现成的写法，Jelly 的 100 个 `😀`（400 字节）也要被砍；
     - D：只把数从 200 提到别的值（比如 260），不改单位：不修半个字，不修丢扩展名，只是推迟；
     - E：不在工作台截，在每个来路截（Cognia、成果库各截一次）：违背「最后一道关只有一个」，别的插件传来的名字没有保证，MISC 要的就是最后一道关；
     - F：只按整字截、不留扩展名：**页面资源只 +41 字节**，但没修丢扩展名这一半（本单的起因就是扩展名），不选。
   - 本单的做法写死为：整字，200 个，含扩展名；统筹要换成 B，在【方案】里说，由统筹改书，不要自己换。
2. **截点只在 `downloadPageBlob`，去掉 `:10` 的那一处。** 两条下载路都进它；留着 `:10`，路 B 的名字先按单元截一次，`savedFileName` 救不回来（第 5 节第 2 条）。代价：路 B 的名字在 `downloadFrameFile` 里到 `downloadPageBlob` 之间没有长度界；它来自 `Content-Disposition` 响应头，受 HTTP 头大小限制（Node 的默认上限 16 KB），不会无界，所以不用单独再截。
3. **「扩展名」的定义：名字最末尾的一个点加 1 到 10 个 ASCII 字母或数字。**
