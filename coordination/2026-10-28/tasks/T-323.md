## 1. 背景

来源：MISC「T-218 二审 建议 S1」（6521665349）；T-218 #1558 已合入 main（`07b73f9f8`）。`apps/local-host/src/plugin-page-authority.ts` 约 :75-81：`close(id, reason = refused)` 先 `this.pages.delete(id)`，对 `install_id === null` 的页面再 `this.activations.delete(page.activation)`，然后才对每个在途请求 `request.abort(reason())`。当调用方传的是 `() => this.left(page)`（约 :99、:117），`left()`（约 :87-93）第一句 `if (!this.activations.has(page.activation)) return refused()`——此时这类页面的 activation 刚被 `close()` 自己删掉了，所以一律返回 403（撤回），而不是 `cancelled()`（499）。结果：登记页面和创作台试用页（`install_id` 为 null）的人自己离开页面时，在途请求回 403，而有 `install_id` 的页面回 499。比现行文档写的更严，没有安全问题，只是两类页面行为不统一。MISC 给的二选一：先算原因再删（统一到 499），或在 S-47 与 spec 里写明例外。**选前者**：S-47 所在的 `docs/system/SECURITY-INVARIANTS.md` 被很多在途 PR 改（#1101、#1549、#1564、#1575、#1588、#1591、#1594），本单不碰它。行号以 `origin/main` 为准，开工先核。

## 2. 目标

先在 #1332 贴【方案】（丙档，写到函数级）：改前改后的 `close()` 几行、新用例的输入与期望、先红预期。
1. `close()` 改成：在 `this.pages.delete(id)` 与 `activations.delete(...)` **之前**把每个请求的结束原因算出来（保持“每个请求各取一次 `reason()`”的语义；不要让所有请求共用同一个错误对象，除非 `request.abort` 明确可共用——先读 `abort` 的实现），再删，再 abort。`install_id` 不为 null 的页面行为不变。
2. `left()` 的注释（约 :83-86）如受影响同步一句；不改 `left()` 的判断。
3. 用例 RAC-2442：用 `tests/security-invariants-plugin-pages.test.ts`（或开工时 `git grep -n 'plugin-page-authority\|PluginPageAuthority' -- tests` 找到的、已经建立登记页面的用例）的夹具，建一个 `install_id` 为 null 的页面，挂一个在途请求，人关闭页面：请求以 499（取消）结束；撤权关闭（`revoke`/`withdrawPages`）仍是 403。先对旧代码证明红。
4. 变异：把 `close()` 的求原因挪回删除之后，RAC-2442 红；贴输出。
