用户 2026-11-09 明确「就用第一版，不升，没用户现在」，随后澄清「我指的是版本号不升，其他照常，不用考虑迁移」。`database.assistant_store_baseline` 保持第 1 版，通知与跟进直接采用现行结构；不增加第 2、3 版，不写旧记录转换或读取兼容。这取代此前的升版／迁移计划，功能、原文保留与验证目标照常。第 10 批同一库的草稿版本保护也保留，最终同步 main 时按实际代码整合到当前 v1 结构，不因版本号不升而撤回功能。

### 日期时区合同

日期 `TextArg`、`TextArgValue` 增加可选 `time_zone`；SDK 的日期参数构造工具及 `format.date` 接受只含该项的选项。统一校验与格式化，非法时区不静默回退。固定时区提醒保存时间点和原来的时区；普通无指定时区的展示保持原行为，纯日期不变日，relative 仍按时间点差计算。此项补齐 FSS-39，不改 `next_at`、`due_at`、每日/每周与夏令时调度规则。

合同代码限 `packages/contracts/src/platform/ui-text.ts`、SDK 的 `text-ref.ts`、`message-format.ts`、`text.ts` 与必要调用方，更新公开 API 快照。验证同一时间点在宿主和浏览器不同时区下的指定时区显示、夏令时边界、无效时区拒绝以及普通日期行为。

#### 保留原有秒精度（2026-11-09 已批准）

固定头 `30797ac522` 的 Coding 等待截止时间和部分事件、诊断、同步与文件时间，原先显示到秒，接入共用 `time` 或 `datetime` 后只显示到分钟。实际用候选的 SDK 在英语、UTC 下复现，原来的 `12:34:01 PM` 和 `12:34:59 PM` 均变成 `12:34 PM`。普通时间保留原展示精度属于 FSS-39。已有短样式继续供本来只显示到分钟的入口使用。

用户 2026-11-09 选择增加两种到秒样式，随界面语言切换。在共同格式表增添 `time-with-seconds` 与 `datetime-with-seconds`，分别使用时、分、秒和数值年月日加时、分、秒。只将原来显示到秒的入口改用这两种样式，仍按界面语言、原时间值与原时区格式化。SDK 原位切换时从原时间值重新绘制，沿用纯日期与无效时间的处理。两种样式通过现行文字参数校验，旧 App 收到使用它们的引用会拒绝。本批使用它们绘制界面，持久化记录、同步包与版本沿用现行形式。

核对实际 Coding 时间线内同分钟不同秒仍可区分、中英切换保留两个时间点，并用事件或历史行证明带日期的到秒格式。保留现行短格式、纯日期、时区及非法参数的拒绝验证。共享枚举与引用 schema 的改变随本批公共合同复核和快照核对。
