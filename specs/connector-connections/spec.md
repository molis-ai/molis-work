# Connector 连接统一管理与插件绑定

目标：把外部服务和用户授权分开。当前设置页每个服务只显示一张卡、一份 `connector:<provider>:token` 凭据；Feed 来源另存凭据引用，因而全局显示“已连接”不能说明某个项目来源真的可用。改造后，同一服务可有多个命名连接，OAuth、令牌及 CLI 的状态均在 Connectors 查看；Feed 来源明确选择其中一条连接。

范围：本机 Home 连接库保存非敏感元数据（`connection_id`、服务、显示名称、鉴权方式、账号标识、状态、时间），SecretStore 保存凭据；已有凭据与 Gmail 按邮箱保存的授权无损纳入连接清单。设置页上方呈现已连接账号列表和每条连接状态，下方保留服务目录用于添加；详情可新增、验证、重连、重命名、断开。Feed 来源可选同服务连接并保存 `connection_id`，使用该连接的凭据拉取；来源的游标、计划、启停和历史仍由项目保存。

账号配置入口盘点与收口：Feed 的 GitHub/Gmail/目录服务、Models 的供应商 API Key、Jelly 的自定义模型 Key、Images 的生图服务 Key、Functions 与 Experiments 共用的 TypeSafe Key、Coding 的远程 MCP Bearer 密钥，均改为在 Connectors 新建/维护连接，对应插件设置只保存连接选择与自身业务配置。依赖环境变量或外部 CLI 的现有连接显示为只读外部来源，不能假装由本机管理其密钥。插件自身仍管理模型 ID、图片尺寸、Feed 游标、函数定义及 MCP 工具配置等非鉴权设置。新插件需要使用同一连接选择/解析接口，不能再自行增加明文密钥表单。

行为：一个服务可以保存多条 Token 或 OAuth 连接，名称可区分；不同连接的 SecretStore 引用互不覆盖。新授权或粘贴令牌建立新连接，重新授权仅更新指定连接。插件绑定一条连接时校验服务类型与可用状态；断开被使用的连接会让绑定来源显示“需重新选择连接”，不会悄悄切到另一账号。列表以可读凭据显示“凭据已保存”，不把它冒充远端验证成功；远端授权失败由 whoami 或实际同步报错，并在对应来源呈现。同一连接重授权保留来源游标；切换到另一账号时创建新的来源 ID，复制拉取计划和以旧来源 ID 过滤的捕捉规则（含 Function 引用），旧来源暂停且保留游标、规则和消息历史。这样 Listener checkpoint 与 Signal 去重键不会跨账号复用；操作失败时不删除旧连接或重置来源游标。凭据不返回给网页、不写日志。

方案与边界：Home 连接库是连接元数据的唯一事实来源；SecretStore 是密钥唯一事实来源；项目与插件库只保存 `connection_id` 和业务状态。现有固定凭据通过确定性的 legacy 连接记录导入，保留原 secret ref，读写路径在迁移后以连接 ID 解析。OAuth 回调把账号身份、权限和 token 写入指定连接；state 绑定待完成连接以防串号。飞书 CLI 是本机 CLI 凭据的一条外部管理连接，若 CLI 只能维持一套登录，就不允许 UI 伪造第二套独立 CLI 身份。现有 Feed 专属授权端点在过渡期可用，但设置页和新来源走统一连接接口。Coding 既有远程 MCP 凭据在 Prologue 存储中保留兼容，新增或更换鉴权均从 Connectors 选择。服务目录说明可用鉴权方式；未配置的服务仍显示为待接入，而非一个“未连接账号”。模型、图片和远程 MCP 的连接在首次选择时绑定目标 origin；后续路径变化可沿用，同一 Key 不会被插件静默发往另一主机，访问另一 origin 需新建连接。

依赖与协作：并行 OAuth 任务负责飞书、Gmail、Notion 的连接方式、授权协议和专属凭据操作；本任务负责通用连接存储、设置页结构、通用令牌连接以及 Feed 选择和解析。两个任务共用的 `settings-connectors.ts`、客户端脚本和 HTTP 路由由 OAuth 任务先完成，本任务收到交接后串行整合，不同时写同一文件。

验收：同一服务建两条不同 Token 连接后列表显示两条且凭据独立；选择其中一条用于 Feed 来源后同步只读取该连接；切换账号新建来源且不复用旧 Listener/Signal 身份，旧消息历史仍在，同连接重授权则保留游标；断开其中一条不影响另一条，相关来源显示需处理。Models、Jelly、Images、Functions、Experiments 与 Coding 不再提供直接写密钥的表单；每条调用实际从选定连接解析凭据。迁移前凭据和现有来源继续可用；无关的本地列表读取不因 Connector 或旧模型密钥探测提前解锁 Keychain。OAuth 完成后能绑定到正确连接；失败和重启后可恢复。验证使用定向存储/路由/来源测试、typecheck/build，以及桌面和窄屏实际界面操作。真实第三方授权需账号和开发者配置，未操作时单列为未验证。

假设：本机 Home 的连接为同一使用者管理，当前不引入跨用户权限。旧的无明确账号的 provider 凭据作为一条“原有连接”；已有 Gmail 邮箱来源按邮箱建立独立连接。连接 ID 为不含密钥的随机 ID，可在 URL 和项目记录中引用。
