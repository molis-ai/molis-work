# 五区导航、快速记录与只读完整记录

## 背景与目标

这是 `ux-goal-factors-navigation` 的实现规格。先建立稳定的信息骨架：用户能找到 Goal 关键因素、随时快速补充事实，同时“完整记录”恢复为可信的只读审计入口。

## 范围与非目标

范围：新增“关联与约束”顶层入口及四个内部入口；标题区新增“快速记录”；把现有写入表单迁出完整记录；完整记录按基础、执行、历史和技术信息只读组织；更新深链、键盘和刷新状态。

非目标：本 Work Item 不完成所有表单的渐进式精简，不迁移项目默认规则设置；这些分别由后续两个 Work Item 完成。

## 主要路径

1. 从标题区打开快速记录，选择完成依据、风险、影响范围或 Goal 关系。
2. 在不离开当前 Goal 的前提下显示对应表单；取消回到原面板，保存走现有 API 并显示回执。
3. 进入“关联与约束”，一次只看一个因素区；风险摘要链接能直达风险区和具体记录。
4. 进入“完整记录”审计，页面中不存在写入控件。

## 方案与边界

- `renderGoalDocument` 负责五个顶层面板和标题区快捷操作。
- 新增因素导航/面板渲染函数，暂复用现有关系、风险、Impact 和 Goal Policy 维护组件。
- 新增只读 Evidence、关系、Risk、Impact、Policy 渲染组合；历史记录不复用带表单的工作台函数。
- 快速记录使用受保护焦点的对话框：先选类型，再显示与当前 Goal 绑定的表单；不在弹层里处理编辑或停用已有记录。
- 客户端统一管理顶层 Tab、因素 Tab、hash、对话框焦点和回执。

## 验收标准

- `ux-factors-five-tabs`：存在五个顶层入口；写入只在“关联与约束”或快速记录出现；完整记录只读。
- `ux-factors-quick-entry`：四个快捷入口绑定当前 Goal；取消保留上下文；保存显示结果。
- `ux-factors-record-readonly`：完整记录按基础信息、执行与检查、变更历史、技术记录组织，且没有新增、编辑、解除、停用或保存控件。
- 风险深链和键盘导航打开正确的顶层及内部面板。
- 现有写入 API 与原始记录没有丢失。
