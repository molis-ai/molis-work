# Generated plugins: implementation

Implement one frozen sandbox operation at a time. The build has `contract.json`, `manifest.json`, `package.json`, `src/index.ts`, `src/operations/<number>.ts`, `tests/operations/<number>.ts`, `developer/README.md` (examples), `developer/sdk.d.ts` (SDK types) and `developer/capabilities.json` (platform contracts). Do not look for extra instructions, tsconfig or node_modules. Write `src/**/*.ts` except the index, `tests/**/*.ts`, and `package.json`. Where a task lists `writable`, edit only those two files; other operations may be in progress. Put shared logic needed by this operation in its own file and follow shared modules and keys from completed operations without editing those files. Do not edit frozen contract, manifest, index or developer materials. The task already gives the contract, writable files, operations marked `implemented: true` and shared modules; do not reread all those files repeatedly because turns are limited. Read already accepted code only to reuse an actual convention.

- Export a default async operation `(input: SandboxJson, sdk: SandboxSdk): Promise<SandboxJson>`; import types from `@molis/plugin-sdk`. For JSON-compatible storage use a type alias such as `type Entry = { id: string; ... }`; interfaces may lack the index signature. Strict TypeScript needs an input assertion such as `const { text } = input as { text: string }`. Validate stored values, including missing fields from older entries. Await storage `get`, `set`, `delete` and `list`; get returns null for absent values. All operations share a store, so agree on keys; the first write operation establishes conventions and shared logic. Use plain JavaScript and permitted pure JS dependencies without install scripts; no Node, direct network, crypto or eval. Return exactly the declared fields and types. Throw a declared error such as `throw Object.assign(new Error("explanation"), { code: "code from the contract" })` on failure. Use the actual date rather than hardcoding today.
- Call only a declared capability through `await sdk.capability.call(id, input)`; follow its provided schema. Declared network/capability effects must actually be used, no fabricated results. Use a saved idempotency key based on the same business intention (e.g. the same saved revision), not a timestamp per attempt or a field users enter. Preserve it after timeout.
- Use `sdk.network.request` for exact approved HTTPS domains; headers, method, body and secret references are allowed by the declaration. Response includes status, headers and text body. No redirects; over 1 MB fails. Preinstall GETs are real, writes stand in with status 200 and empty body. Handle invalid structures and non-2xx with declared errors; don't fabricate website results in tests.
- `reminders.add`/`schedules.add` receive ISO time; save a returned ID if cancelling later. Scheduled work is your own operation, and `inbox: true` publishes its returned `text` (or `summary`). Checks/trial use stand-ins.
- For `model.generate`, declare literal `prompts` in this operation and call by literal ID with only `prompt` and `input`. The check stand-in returns `［模型替身］` plus the first 40 input characters. Validate and save accepted output; keep original input and earlier results on failure. State output, structure and length appropriate to this operation (for a short hint, one open-ended question, no numbering, explanation or answer). Decode and validate structured output; preserve original on decode failure. The AI chapter specifies exact-source, override and authority rules.
- Keep user data unchanged. Use stable owner keys and `ui.locales` for package interface copy. Use SDK `t`/`say` for full messages and `format` for dates/numbers; the platform supplies the language. Do not choose language from the brief or treat a translated label as a business value.

Export `tests: SandboxTest[]` as async functions `(sdk, call, assert)` (not objects). Tests run in sequence in isolated operation storage; set up with storage when needed. Use `assert.same`, `assert.includes`, or `await assert.rejectsCode`; each test asserts something. Cover success, every declared error, and persistence later tests rely on. Don't fix today's date in an expectation; use an input date. Stand-ins only justify output shape and data you store.

Read the Host's placeholder before first write; reread if a file changed, use write for whole replacement and edit for small changes. When both files are ready, run `plugin-checks`; use raw output to fix the actual failure and rerun. The Host checks again independently. Never weaken the contract or tests, hardcode an example's result, or edit frozen files to get a green check.
