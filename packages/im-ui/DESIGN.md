# 群聊与 Thread 界面约定

## Overview

本文件只约束 `packages/im-ui` 的 Operate 界面：让成员在同一空间看群聊、展开公开 Thread、继续讨论。需求与验收仍以 [任务 spec](../../specs/molis-work-im/spec.md) 为准；样式和行为的实现来源是 `src/styles.ts`、`src/page.ts`、`src/views.ts`、`src/client.ts`。

## Colors

浅色用白色消息区、浅灰目录与面板（`#fff` / `#f6f7f8` / `#fbfcfc`）；暗色用石墨色（`#1b1c1e` / `#151618` / `#1e2022`），由共享主题脚本解析。分区靠色阶与细边线，不用整面绿色背景。

绿色强调色（浅色 `#397357`，暗色 `#91c6a8`）用于当前话题、可操作控件、焦点、连接状态和源消息关系；错误用独立红色。成员头像保留五组低饱和色，辅助区分作者。

## Typography

采用 Inter 与系统中文无衬线回退。消息正文 14px，桌面行高 1.75、窄屏 1.65，最长 75ch；标题 15–17px，作者 12px，时间与辅助标签 10–12px。紧凑导航不抢过聊天内容；连续同作者消息收起重复头像和元信息。窄屏输入文字 16px。

## Layout

桌面目录宽 216px（≤1150px 时为 190px），群聊与已展开 Thread 左右并列，各自滚动和输入。≤1100px 隐藏常驻目录，通过标题栏按钮打开覆盖式目录；≤640px 群聊在上、Thread 在下，仍同屏保留两条消息流与输入框，不跳转到另一个聊天页面。

短屏进一步压缩标题和上下文。Thread 来源区用细绿线呼应群流中的源消息；常规消息平铺，避免把每条消息做成独立卡片。

## Components

- **公开 Thread**：从群消息的“展开话题”在 Thread 区内命名，显示来源和相邻上文；所有群成员可参与。取消返回群流，定位原消息可补载较早历史；回复分享回群后保留 Thread 回链。
- **阅读与草稿**：按当前成员、群保存上次打开的 Thread，主动收起会清除该群的恢复目标。群消息与各 Thread 的草稿独立保存在浏览器本地；输入框随内容增高。切换话题保留群流阅读位置，关闭时恢复焦点。
- **实时更新**：SSE 触发服务端数据刷新；消息按 ID 复用未变化的 DOM，导航不变时也不重建。保持焦点和滚动锚点，阅读旧消息时提示“回到最新”，不强制跳到底部。
- **动效**：交互反馈、Thread 展开/切换、新消息和对话框使用 120–220ms 过渡；定位来源的提示持续 1.2s。遵循 `prefers-reduced-motion`，关闭动画、过渡和平滑滚动；不做装饰性页面入场。
- **真实空态**：生产入口不预置演示群聊或消息。未加入时引导创建或邀请加入，空群提示发送第一条消息；共享事实来自统一 Server，截图用数据不能变成产品默认内容。

## Do's and Don'ts

保留清楚的发送目标、加载/重连/失败反馈和失败后原文。不要扩大本地浏览器状态为身份、权限或消息持久化的第二事实来源，也不要把静态视觉通过写成用户验收通过。
