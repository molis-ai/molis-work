# 技能选用：选用解释、改选与停用的可点定样（路线书第 41 批）

状态：待用户定（2026-11-14）。三个方案都能点，默认打开方案 A。

这是参考原型，不是产品界面。

- 需求见 [Skill 策略](../../../specs/prologue-strategies/skill.md)（SKL-01、02、11、16）和[技能包](../../../specs/skill-packs/spec.md)（SKP-10）。
- 排期见[第 41 批](../../../specs/post-anticorruption-roadmap/reference/batches/41.md)。
- 设置里的「技能」目录和三档（关／自动／仅手动）沿用[第 08 批的定样](../skill-packs/README.md)，这里不重出。

已定的不再问：

- 你用 `/` 点名的优先；仅手动的技能 AI 不会自己选，知道精确名字也绕不过。
- AI 自动选时最多选三个，每个都说得出依据。
- 你点名的技能用不了时如实说明，不悄悄换成另一个。
- 几个技能一起用时，做完的留着，只有等失败那一步的部分停下，别的照常做。
- 改成仅手动、停用都立即生效，提示里可以撤销；保存失败就地说「什么都没改」。

## 怎么打开

先按[组件板实件](../component-board/README.md#生成)生成 `component-board/dist/`，再在仓库根目录运行下面的命令，打开 <http://127.0.0.1:4422/skill-selection/>：

```sh
python3 -m http.server 4422 --bind 127.0.0.1 --directory docs/design
```

顶上一条斜纹是**原型控制**，不是产品的一部分：切方案、位置（助理／Coding）、状态、中英文和浅深色。宽度 1440、1024、390 都看过。

## 三个方案

差别在两处：**选用结果显示在哪**，以及**什么时候能改**。

| 方案 | 显示在哪 | 什么时候能改 | 取舍 |
| --- | --- | --- | --- |
| A 回复上方一行 | 回复上面一行「用了」，每个技能是一个按钮，写着名字和「自动选的／你点名的」 | 回复出来以后，点技能按钮看依据，同一处换一个重做、这次不用、改仅手动、停用 | 平时只占一行，不抢回复；要看依据得点一下 |
| B 回复下方的卡 | 回复下面每个技能一张卡，依据一直摊开 | 回复出来以后，卡上的按钮 | 依据不用点就看得到；每轮都多出一到三张卡，回复被推远，技能多了很占地方 |
| C 发送前先告诉你 | 输入框上方先写「会用：…」，可以去掉；发出后同 A | 发送前就能去掉不想用的；发出后同 A | 能在跑之前拦下选错的；打字时就要算一次选用，输入框上方多一行会变的内容，多数时候你不会看它 |

## 状态

| 状态 | 看什么 |
| --- | --- |
| AI 自动选了一个 | 依据、对上的条件、来自哪个包哪一版；换一个重做（列出这次没选的和原因）；改仅手动、停用，带撤销 |
| 你点名一个，AI 又补一个 | 两个各写清来路：你点名的、自动选的 |
| 你点名的用不了 | 一轮没开始、没有换成别的；给三件能做的事：去连接、改用另一个、不用技能直接做 |
| 几个里有一个失败 | 每个技能一行：做完了、没做成、等上一步、还在做；重试只做没成的那一步和等它的 |
| 没有合适的 | 写明「这一轮没用技能」，可以选一个重做 |
| 改设置时保存失败 | 依据面板里就地报错，原来的状态不变，可重试 |
