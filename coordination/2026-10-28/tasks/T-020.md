## 1. 背景

W6-02 给已迁入 Plugin Runtime 的内置插件各走了一遍生命周期：加入项目、移出再加回、撤一项必需权限、升级、卸载再重启，共用 `tests/fixtures/shipped-lifecycle.ts` 的 `walk`。当时 C 线和 W5-10 还在改 Goals，所以把它留给了 BL-756（`specs/repository-anti-corruption/slices/w6-02-lifecycle-rest.md:23,50`，`tests/shipped-plugin-lifecycle.test.ts:5`）。现在 C 线（#1327）和 W5-10 批 A（#1317）都已合入。

Goals 和别的插件有三处不一样，所以是乙档、要贴【方案】：

1. **常开**：`plugins/native/goals/src/manifest.ts:83` 写着 `always_on: true`，项目不能把它移出。T-005 给夹具加的 `always_on` 分支处理这一点：移出时断言 `400 catalog.plugin_always_on`，写下的东西不变。
2. **双实例，人的数据在项目那一半**：`plugins/native/goals/src/registration.ts` 同时有 `project_runtime`（`createGoalsPlugin`）和 `runtime: { …, dual_instance: true }`（`createHomeGoalsPlugin`）。Goal 本身在项目那一半，个人规划在 Home 那一半（PG-094 的 S10/S11，`specs/repository-anti-corruption/privileges.md` 的 PG-094 行）。T-005 的 `dual` 是照置物架写的：人的数据在 Home 那一半，走查跟着 Home 那一半走。Goals 正好反过来。
3. **路由还在旧地址**：宿主在 `apps/local-host/src/web-request.ts:233` 一带把 Goals 的路由按旧地址 `/projects/<id>/api/<路径>` 分发，改走插件前缀是 BL-386，还没做。夹具的 `viewOf` 给的是 `/projects/<id>/api/plugins/io.molis.work.goals`。

## 2. 目标

1. `tests/shipped-plugin-lifecycle.test.ts` 里有 Goals 一项（`RAC-1230`），走完五步并通过：移出那一步是常开的拒绝；撤权、升级、卸载、重启这四步各自成立。
2. Goals 自己写下的东西（一个 Goal 的标题）经过移出的拒绝、撤权再还回、升级之后，都还在。
3. 文件头注释里「Goals … remains BL-756」那一句删掉，w6-02 文档和 `docs/system/RUNTIME-MIGRATION.md:242` 不再说 Goals 待加。

## 3. 不做

- 不改 Goals 的路由地址，不碰 `web-request.ts`：那是 BL-386，有浏览器批验证，单独一片。
- 不改 `plugins/native/goals/`、`apps/`、`packages/`、`tooling/gates/`。
- 走查在某一步撞上产品缺陷，不放宽断言，不删步骤，不把 Goals 拿出本轮：停下来报（第 11 节）。

## 5. 做法

**已定（main 上核过）**

- 项目键与 id：`goals`／`io.molis.work.goals`（`plugins/native/goals/src/manifest.ts` 的 `GOALS_PROJECT_PLUGIN_ID`、`identity.ts`）。
- 常开：条目写 `always_on: true`，用 T-005 加的分支。
- 撤的权限：Goals 的权限全是必需（双实例门禁要求，`manifest.ts:85-95` 的注释），默认的 `storage:private` 就行。
- 写入用 `goals.create`（`POST /goals`，`plugins/native/goals/src/http/create.ts`），读回用 `goals.directory`（`GET /goals/directory`，`plugins/native/goals/src/http/deliverables.ts:41`，回 `goals[].title`）。旧地址上的写法可以照 `tests/goal-event-http.test.ts:1199` 一带和 `tests/goal-artifact-inputs.test.ts:44`。新项目里本来有没有 Goal，以实际为准；有的话，`titles` 里只留你写入的那个（按标题过滤）。

**【方案】里要回答的问题**（先在本机把条目写出来跑一遍，结果写进去，再等批）

1. **路由地址**。在临时 Home 里，`/projects/<id>/api/plugins/io.molis.work.goals/goals` 能不能用，还是只有旧地址 `/projects/<id>/api/goals` 能用？`walk` 里对路由的几处断言（撤权后 `503 actions.plugin_unavailable`、卸载后 `404 actions.missing`）在旧地址上各答什么？给出实际的状态码和错误码，是哪一行发的。
2. **两半各有什么**。人的目录（`callable()`）里，Goals 项目那一半和 Home 那一半各出现哪些动作？只有项目那一半、只有 Home 那一半、两半都有，各是什么情况，列出来。
3. **跟哪一半走**。T-005 的 `dual` 跟 Home 那一半走，Goals 的 Goal 在项目那一半。三条路，选一条并说明理由，写出要改的全部代码：
   - A：条目写 `scope: "project"`，不写 `dual`，像 T-003 的 Feed 那样只跟项目那一半；条件是 `callable()` 里不混进 Home 那一半的动作（问题 2）；
   - B：给夹具的 `dual` 加一个「跟哪一半」的取值（比如 `dual?: "home" | "project"`，置物架是 `"home"`），对置物架和别的插件行为不变；
   - C：拆成两项：`RAC-1230` 跟项目那一半（Goal），`RAC-1231` 跟 Home 那一半（个人规划）。
4. **卸载常开插件**。`uninstall(…, { retain_private_data: false })` 对 Goals 的那一半成不成；重启之后，宿主会不会因为它是常开插件、又是内置的，把它重新装回来？这是产品的行为，以实际为准，不自己编。会装回来的话，`walk` 最后「重启后仍是 uninstalled」那一步怎么写，等统筹定。
5. **先红**：把用例弄红一次的办法。例如临时去掉 `write`，看第一个读回断言红，确认用例真读到了东西。写出你打算怎么做。
