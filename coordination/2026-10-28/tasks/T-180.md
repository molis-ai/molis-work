## 1. 背景

- 开始使用（Context Onboarding）把人选的材料交给两个插件：
  - Todo：每份材料先切段，每段是一份「材料」，每 50 份一批发给 `todo.organize.extract`（`:351-362` 的 `todoBatches`）。每段的标题是 `partTitle(ref.title, 第几段, 共几段, 200)`，多于一段时标题带「 · 第 k / n 部分」；空白的段跳过（`:356`）；
  - Pages：每份材料的整段文字（前面加「原标题」「来源」两行）切段，每段由 Pages 自己的动作转成正文再导入（调用在 `:479`，`pageParts` 在 `:402`）。
- `textParts` 的规则（现在，数单元）：
  - 一段最多 `size` 个单元；
  - 不是最后一段时，如果段内后半（从 `offset + size / 2` 起）有换行，就切在最后一个换行之后；
  - 否则切在 `size` 处，若这一刀劈在一对代理中间，就往前退一个单元。
- Todo 一边：
  - T-163 之前，Todo 的 `materialReadText` 按单元读，宿主按单元切是配套的：每段不超过 60000 个单元，Todo 原样读；
  - T-163 起，Todo 读前 60000 个整字。宿主这边的注释（`:316-319`、`:344`、`:348`）和常量名（`TODO_PART_CHARS`）一直写「characters」，`tests/context-onboarding-todo.test.ts:202-204` 的 RAC-822 钉着 `TODO_PART_CHARS === TODO_ORGANIZE_MATERIAL_CHARS`（两边同数）；
  - 含大量两单元字的材料因此每段不到 60000 个字，段数最多多一倍。
- Pages 一边：
  - Pages 的正文上限量的是编码后的长度，`JSON.stringify(body)` 里一个 🟢 是两个单元；
  - `:401` 的 400,000 是起点，`:408` 量编码后的长度是否不超过 1,400,000，不行就对半（`:405-411`，对半时也避开一对代理）。数单元，是对的，不动。
- 同一个函数两边数的不一样，所以拆成两种数法，而不是统一改成数字。

## 2. 目标

1. Todo 的每一段不超过 `TODO_PART_CHARS`（60000）个**字**，一个两单元字算一个，不从一对代理中间切。90000 个 🟢 的材料是两段：60000 个字和 30000 个字。
2. 「后半段里有换行就切在换行之后」的规则保留，「后半」按字数算。没有两单元字的文字，切的位置与现在一字不差。
3. Pages 的切法一个字不变：仍按 400,000 个单元，仍在劈开一对代理时往前退一个单元。
4. 注释说清数的是字还是单元。
5. 用例钉住上面几条：Todo 改回按单元、Pages 改成按字、按字时劈开一对代理、后半段的边界差一、「后半」改回按单元、丢掉换行规则、最后一段也切在换行、Pages 丢掉往前退一个单元，各自都红（第 6 节）。

     ```ts
     /**
      * A text in parts of at most `size` characters or UTF-16 units (`unit`), cut after a line end where there is one in the second half of
      * the part, and never inside a surrogate pair. A 🟢 is one character and two units. Todo's organizer reads whole characters, so its
      * parts are counted in characters; Pages limits what a body encodes to, so its parts are counted in units. Pages and Todo each take a
      * bounded text per call; a material of any length goes as several.
      */
     function textParts(text: string, size: number, unit: "characters" | "units"): string[] {
       const parts: string[] = [];
       for (let offset = 0; offset < text.length;) {
         const end = unit === "characters" ? partEndByCharacters(text, offset, size) : partEndByUnits(text, offset, size);
         parts.push(text.slice(offset, end)); offset = end;
       }
       return parts;
     }
     /** Where the part that starts at `offset` ends, `size` counted in UTF-16 units. */
     function partEndByUnits(text: string, offset: number, size: number): number {
       let end = Math.min(offset + size, text.length);
       const line = end < text.length ? text.lastIndexOf("\n", end - 1) : -1;
       if (line >= offset + size / 2) end = line + 1;
       else if (end < text.length && /[\uD800-\uDBFF]/u.test(text[end - 1]!)) end--;
       return end;
     }
     /** Where the part that starts at `offset` ends, `size` counted in characters: a pair of units is one, so a part never ends inside it. */
     function partEndByCharacters(text: string, offset: number, size: number): number {
       let end = offset, count = 0, line = -1;
       while (count < size && end < text.length) {
         const code = text.codePointAt(end)!;
         if (code === 10 && count >= size / 2) line = end + 1;
         end += code > 0xFFFF ? 2 : 1;
         count += 1;
       }
       return end < text.length && line >= 0 ? line : end;
     }
     ```

   为什么这样写、为什么成立：
   - 抓的是宿主发给 Todo 的材料：`homeActions` 的 `invoke` 在转给真的动作之前，把 `todo.organize.extract` 的 `materials` 记进 `sent`。所以断言的是宿主切出的段，Todo 自己后面怎么读、证据找不找得到，都不影响（模型是假的，返回的 `TODOS` 引用的原文在这些材料里找不到，候选被丢掉，不抛错；T-163 头 `d0d51a7a9` 上 `organize.ts:157`）。这个写法照 ONB-LIM-05（`:145-181`）的 `homeActions` 包装；
   - `journeyOver` 只断言走到了 `review`，不断言 Todo 的状态是 `ready`：开始使用的整理对 Todo 的失败本来就不停（`:200` 的注释），本单也不依赖它；
   - 文件是 `.md`，进来的文字经 `trim()`，标题没有 `# ` 开头的行时取文件名去掉扩展名，所以标题是 `emoji`、`odd`、`late` 这样；多于一段时加「 · 第 k / n 部分」（`partTitle`，`:332-335`），只有一段（`last`）没有后缀；
   - 用「游程」比较而不是整串比较：一个 60000 个字的段打出来是 `🟢×60000`，看得出长度；劈在一对代理中间会显示成一个单独的游程（`�×1`），所以不需要另写「没劈开」的断言；
   - RAC-1853 的 `odd`：文字是一个 `a` 加 70000 个 🟢，共 70001 个字、140001 个单元。按字，第一段是 `a` 加 59999 个 🟢（60000 个字），剩 10001 个 🟢。如果错写成按单元走，第一段会是 `a` 加 29999 个 🟢；

   - 标题前的 `[S1] ` 是 Pages 部分的前缀（`:482`），用正则去掉，不依赖标签是几；
