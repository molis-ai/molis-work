## 给人讲清楚

界面的字体、皮肤和中英文文字现在写死在各处，想换外观或补翻译，要到处改，还容易漏。这一批先把规矩定下来：界面文字、字体、皮肤怎样登记、怎样引用，并给出完整的基础清单，同时量清楚页面加载的开销，确保换了以后不变慢。做完你基本看不到界面变化，但后面换外观、补语言就有了统一的做法。需要你做的：看外观选择的样子并定下；字体资源的预算、Folio 用哪款字体、除了中英文还要不要别的语言，要你定。

### 二、和需求、方案对不上的

1. **tray、pill 两套旧皮肤。** 和需求的皮肤定义不同；页面资源预算表的说明也写着「旧皮肤删掉之后再定真目标」。建议：B 段（16）引入皮肤文件时把它们当作被替代的样式删去，「圆润」方向由 Folio 承接，`DESIGN.md`「Skins」一节随 FSS-29 改写。交统筹排进 16；如果要保留它们作可选皮肤，到时再问用户。
2. **资源数字过时。** 实现方案 §12.2 引的是 10-12 的记录。现在 `tooling/gates/page-assets.json`：工作台 CSS 1,194,394，设置 CSS 826,705，到达 CSS 689,755，工作台 JS 1,074,570，Noto Sans SC 1,141,536，Inter 48,256；共 51 个资源 7,400,614 字节。方案里已标出过时并指到这里。
3. **语言切换会整页重画。** 不符合 FSS-35；属于 C 段的改造（实现方案 §6），这里只记。
4. **`DESIGN.md` 说皮肤不换颜色、是本机偏好。** 和需求冲突；随 FSS-29 改手册时一起改（E 段）。

### 三、决策第 23 项

- **已定（用户 2026-11-04，记在[需求 §12](../../../font-and-skin-system/spec.md#12-决策记录)）**：Folio 中英文都随产品带开源圆润字体、只在选用时加载；首批界面语言只做中文和英文。
- **仍待**：统一的资源登记与预算方案，以及实测（基础 CSS／JS、启动 JSON、语言与字体请求、首屏总传输与时间）。这是 A 段实现的第一步，要构建并在浏览器里量，按机器槽位排；量出数字后带着数字问用户。新增字体资源超过 10 KB，按页面资源规则先问。

### 四、实现时要做的（按依赖顺序，等 05 与 C 轨交接后派单）

3. 从 `palette.ts`、`typeface.ts` 提出 Soft Workbench 皮肤文件与系统字体方案的完整基线；Folio 与圆润字体在 16。
4. 资源登记与预算方案、实测（第 23 项其余部分）。
5. 真实 Host／浏览器消费者，以及只装公开两包的样例（`tests/plugin-sample.e2e.test.ts` 作起点）。
