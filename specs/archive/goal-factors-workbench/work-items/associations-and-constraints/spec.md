# 关系、风险、影响范围与工作规则交互

## 背景与目标

这是 `ux-goal-factors-controls` 的实现规格。用户应先理解每类因素为什么存在、什么时候需要记录，以及保存会如何影响 Goal；低频高级设置不应占据默认表单。

## 范围

- 四个因素区各有一句用途、当前摘要、清楚的新增入口和已有记录维护入口。
- 关系表单先选“这个 Goal 需要什么 / 什么依赖这个 Goal / 其他关联”，再选择目标和原因；技术方向与关系类型按需补充或由明确选择派生。
- 风险先记录“可能发生什么、会造成什么影响、什么时候重新看”；概率、负责人、受影响区域、处理与阻塞门禁进入高级设置，其中门禁不得默认替用户作出关键决定。
- 影响范围使用通用“区域/对象/流程”语言，先记录影响对象、会怎么影响和原因；快照、状态等技术字段按需展开。
- 工作规则先显示最终生效结果和项目来源，只允许编辑当前 Goal 的额外要求；按用途分组，不直接铺完整 Policy 对象。
- 新增、修改、解除和停用都有进行中、成功、失败与恢复路径。

## 非目标

- 不改变 Relation、Risk、Impact 或 Policy 的领域结构。
- 不自动推断会改变门禁的值；缺少关键信息时要求用户明确选择。
- 不在本 Work Item 新增项目默认规则页面。

## 验收标准

- `ux-factors-one-at-a-time`：四个因素区一次只显示一个，标题、用途和当前数量可快速理解。
- `ux-factors-progressive-forms`：默认只显示必要事实；高级字段由用户主动展开；关键门禁无静默默认。
- `ux-factors-safe-write-feedback`：所有写入显示保存中；保存后在对应因素区持续显示具体改了哪个对象、现在是什么状态；错误说明下一步并聚焦缺失字段；取消不改事实。
- 文案适用于产品、设计、运营、研究和 coding Goal，不假设用户正在改代码。
