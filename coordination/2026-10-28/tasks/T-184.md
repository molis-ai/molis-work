## 1. 背景

「导出填写页文件」（`form.fillpage`）与「导出答卷表格」（`form.results.csv`）除了内容，还交出一个文件名。名字由 `fillpage.ts` 的两个函数起（T-164 头原样）：

```ts
// :99-101
export function formFillPageFilename(title: string): string {
  return (title.replace(/[\\/:*?"<>|\u0000-\u001f]/gu, "_").trim() || "问卷").slice(0, 80) + " · 填写页.html";
}
// :117-119
export function formResultsCsvFilename(title: string): string {
  return (title.replace(/[\\/:*?"<>|\u0000-\u001f]/gu, "_").trim() || "问卷").slice(0, 80) + " · 答卷.csv";
}
```

`.slice(0, 80)` 数 UTF-16 单元。`🟢` 是一个字、两个单元。后缀 ` · 填写页.html` 是 11 个字、` · 答卷.csv` 是 9 个字，都在基本平面，一字一单元。

### 谁调它们，名字交给谁

| 谁 | 在哪 | 拿到什么 |
| --- | --- | --- |
| 动作处理函数 | `actions.ts:120-124`（`formActions.csv`）、`:125-129`（`formActions.fillPage`）；import 在 `:9` | 返回 `{ filename, mime_type, content }`（csv 另有 `count`）。输出 schema 里 `filename` 只是 `text`，不限长（`:59`、`:61`）。处理函数里没有 `publishArtifact`，**不写成果库** |
| 同两个动作的路由 | `plugin.ts:106-107`、`manifest.ts:55-56` | `bindPluginActionRoute` 把动作结果当 JSON 体交出（`packages/plugin-sdk/src/routes.ts:32` 的 `{ status: 200, body: … }`），不是字节响应 |
| 助理、MCP、流程 | 同一个动作（`audiences: ["user", "workflow", "agent", "mcp"]`，`actions.ts:29`） | 同一个 JSON |
| 工作台里问卷页的「导出」菜单 | `src/browser/commands.ts:232-239`：`page.request("GET", …)` 取文件，`page.host.download(new Blob([file.content], { type }), file.filename)`，再 `placed({ verb: "exported", … file: { name: file.filename, … } })` | 浏览器下载 |
| 页面框架到工作台壳 | `apps/workbench/src/browser/plugin-frame/files.ts:14-17`（把 `filename` 放进一条 `download` 消息）、`parent.ts:156`、`links.ts:13-18`（`link.download = filename.slice(0, 200)`，再点一下） | 浏览器另存 |
| 「已导出」卡片 | `apps/workbench/src/scripts/client/placement.ts:142`（`card(L("已导出") + " " + (file.name …`） | 界面上显示名字 |

结论：名字只交给浏览器的下载和「已导出」卡片，加上助理、MCP、流程拿到的 JSON 里的 `filename` 字段。

### 半个字会变成什么

起草线在 Node 里对孤立高位代理 `\ud83d` 试过：

| 环节 | 结果 |
| --- | --- |
| `JSON.stringify` | 写成转义 `\ud83d`，`JSON.parse` 读回同一个孤立代理。不报错，也不改。动作结果、路由体、`postMessage` 都是这样带过去的 |
| 按 UTF-8 写成字节 | 变成 U+FFFD（`efbfbd`） |
| `encodeURIComponent` | 抛 `URIError: URI malformed` |
| 浏览器另存时 `link.download` 的名字、「已导出」卡片上的字 | **没核实**（第 8 节第 6 条） |

`Content-Disposition` 是 Host 给**字节响应**写的，用的正是 `encodeURIComponent`，原文三处（main `892879eba`）：

```ts
// apps/local-host/src/plugin-route-operations.ts:158（进这一支的条件是 :154 的 result.bytes !== undefined）
"content-disposition": disposition + "; filename*=UTF-8''" + encodeURIComponent(result.filename ?? "material"),
// apps/local-host/src/artifact-native-plugin-http.ts:198
"content-disposition": `${file.inline ? "inline" : "attachment"}; filename*=UTF-8''${encodeURIComponent(file.filename)}` });
// apps/local-host/src/browser/browser-http.ts:91
"content-disposition": `attachment; filename*=UTF-8''${encodeURIComponent(download.filename)}`,
```

读回的一端是 `links.ts:9-10`：`/filename\*=UTF-8''([^;]+)/i` 取出，`decodeURIComponent(encoded).slice(0, 200)`。

Form 的两个动作**不走这三处**（上表：JSON 体，不是字节）。所以今天半个字不会让谁抛错，只是带到浏览器另存那一步。要是以后有人把 Form 的文件名接到上面任何一处，半个字会让整个响应抛 `URIError`。

### 谁数标题

标题进库前过 `normalizeTitle`（`store.ts:393-397`）：`[...title].length > FORM_TITLE_LIMIT`（`:47` 的 80）就抛「标题须为 1 到 80 个字」。写标题的入口都过它：`create`（`:104`）、`update`（`:130`）、`receive` 经 `create`（`:163`）；`duplicate` 抄源问卷已经过关的标题（`:242`）。动作的输入 schema 也是 `title: { …text, maxLength: 80 }`（`actions.ts:42`、`:43`，AJV 的 `maxLength` 数码点）。

所以库里的标题最多 80 个字、160 个单元。老写法对它的影响：

- 单元数不超过 80：不截，名字完整；
- 单元数超过 80（含两单元字，字数 41 到 80）：被截到 80 个单元，少几个字；切点正好在一个两单元字中间时，留下半个字；
- 新写法下 `slice(0, 80)` 对库里的标题**永远不再截**（最多 80 个字），它只是保留的一道防线（第 8 节第 2 条）。

### `form.js` 会不会变字节

- `fillpage.ts` 是服务端文件：动作处理函数 `import` 它（`actions.ts:9`）。客户端包的入口是 `src/browser/factory.ts`，整个 `src/browser/` 里只有一处取它：`src/browser/fields.ts:2` 的 `import { FORM_ANSWER_LIMIT } from "../fillpage.js";`（`git grep -n -F 'fillpage' -- plugins/native/form/src/browser` 只有这一行）；
- 打包命令（`plugins/native/form/package.json` 的 `build`）：`esbuild src/browser/factory.ts --bundle --format=iife --platform=browser --minify --charset=utf8 …`，包 `"sideEffects": false`。esbuild 摇掉没人用的导出，`formFillPageFilename`、`formResultsCsvFilename`、`formFillPageHtml` 都不会进包；
- 起草线实测：把 T-164 头的 `plugins/native/form` 复制两份，其中一份只做第 5 节的两行改动，用与 `build` 同一条 esbuild 命令（0.28.2）各打一次包：**都是 29642 字节，逐字节相同**（SHA-256 `a9db7506e55d744e77bd501af796b2cce68bfbd4f885209412b44afeca620d9d`），两份里都搜不到 `填写页.html`、`答卷.csv`、`molis.form.answer.v1`；
- 宿主发出的 `/assets/molis-work-plugins/form.js` 是这个包加一层包装（`apps/workbench/src/plugin-workbench.ts:160`：`globalThis.molisWorkbenchPluginFactories … = <包>;`），`tooling/gates/page-assets.json` 记 `form.js` 29708、`form.css` 8726（main 与 T-164 头一样，T-164 没改这个文件）。探针包加包装是 29742 字节，与 29708 差 34 字节，**没追**（见第 8 节第 3 条）；结论不靠它，靠的是「改前改后同一个字节」。开发在真实构建上再核一次（第 5 节步骤 2、5、7）；
- `form.css` 与 `fillpage.ts` 无关。

   ```ts
   // One 🟢 is one character and two units, so a cut by units kept only part of such a title and could stop between its two halves.

   const wide = (count: number) => "🟢".repeat(count);
   const PAGE = " · 填写页.html", TABLE = " · 答卷.csv";
   /** True when the name survives being written as UTF-8 and read back: half of a two-unit character does not. */
   const whole = (name: string) => Buffer.from(name, "utf8").toString("utf8") === name;

   /** A form with this title in a real Form library, and the names the two actions give its fill page and its results table. */
   async function exported(t: import("node:test").TestContext, title: string) {
     const home = await mkdtemp(join(tmpdir(), "form-export-names-"));
     const forms = openFormStore(home);
     t.after(async () => { forms.close(); await rm(home, { recursive: true, force: true }); });
     const handlers: ActionHandlerBinding[] = createFormActionHandlers({ ...ownFormStores(run => run(forms)), modelAvailability: () => ({ available: true }) });
     const caller: ActionExecutionContext = { actor_id: "web-user", project_id: "p", audience: "user", permissions: [], beforeEffect: async () => {} };
     const form = forms.create({ project_id: "p", title });
     forms.update(form.id, { questions: [{ id: "q1", type: "text", title: "你的建议", required: false, order: 1 }] }, "p");
     const filename = async (definition: { capability_id: string }) => {
       const handler = handlers.find(item => item.capability_id === definition.capability_id)!;
       return (await (handler.handle(caller, { id: form.id }) as Promise<{ filename: string }>)).filename;
     };
     return { page: await filename(formActions.fillPage), table: await filename(formActions.csv) };
   }

   test("RAC-1873 the fill page's file name keeps a title that runs past 80 UTF-16 units whole: no half character is left in it", async t => {
     // "a" and 40 🟢 are 41 characters and 81 units: the 80th unit is the first half of the last 🟢, where a cut by units stopped.
     const title = "a" + wide(40);
     const { page } = await exported(t, title);
     assert.ok(whole(page), "the name has no half of a character in it");
     assert.equal(page, title + PAGE, "the title is kept whole");
   });

   test("RAC-1874 the fill page's file name is cut at 80 characters, not 80 units: a title of exactly 80 characters is kept whole", async t => {
     // 80 🟢 are 80 characters and 160 units; a cut by units kept 40 of them.
     assert.equal((await exported(t, wide(80))).page, wide(80) + PAGE, "80 two-unit characters are kept whole");
     assert.equal((await exported(t, "x".repeat(80))).page, "x".repeat(80) + PAGE, "and 80 one-unit characters, as before");
   });

   test("RAC-1875 the results table's file name keeps a title that runs past 80 UTF-16 units whole: no half character is left in it", async t => {
     const title = "a" + wide(40);
     const { table } = await exported(t, title);
     assert.ok(whole(table), "the name has no half of a character in it");
     assert.equal(table, title + TABLE, "the title is kept whole");
   });

   test("RAC-1876 the results table's file name is cut at 80 characters, not 80 units: a title of exactly 80 characters is kept whole", async t => {
     assert.equal((await exported(t, wide(80))).table, wide(80) + TABLE, "80 two-unit characters are kept whole");
     assert.equal((await exported(t, "x".repeat(80))).table, "x".repeat(80) + TABLE, "and 80 one-unit characters, as before");
   });
   ```

   这四个用例为什么成立（写进【方案】，PR 里也写）：
