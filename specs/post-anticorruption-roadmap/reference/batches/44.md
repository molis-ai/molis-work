## 给人讲清楚

前面几批分别做了引导、助理、配置和首页，但第一次用、新建项目、打开已有项目时，还没有一条从头到尾走通的路。这一批把它们串起来：AI 按需要补问几句，配好个人助理或项目助理团、真实写入配置、生成新首页，再带你开始第一件工作；中途退出、从帮助进去再回来，都接着用你之前填的内容和材料。也在这一批交出两套官方场景包（行业观察与写作、写代码）：第一问旁可以直接挑，也可以先说目的、让助理推荐。需要你做的：看组合后的完整路径样子（含挑官方场景包的方式）并定下；还要你定是否先交不带 AI 生成首页的基础闭环（没定之前，生成首页留在完整闭环里）。只放材料的普通路径不等这一批。

八、验证与完成

- 合成一组的：途中只跑刚写的用例确认写对了，不跑受影响用例和浏览器批次。全组写完后先同步最新 main，统一构建，按全组改动挑用例，加上各包 README 的改动后必跑，一次跑完，不抽样；脚本不提示的也要跑（动共用样式跑 pnpm visual:compare，改创作台 Skill 跑 pnpm studio:replay）。每个验收编号都要有证据，PR 描述按编号列明，缺一项不合（需求开发流程第 8.4 节）。

- PR 粒度：一组写完测完，或者别的片真要先用到它时，才开 PR；同一组的后续步骤和后面的项叠在同一个分支上，不为每一步、每一项各开一个，也不开草稿 PR 占位；合同改动默认单独开小 PR（需求开发流程第 8、8.4 节、轨道规则 1）。
