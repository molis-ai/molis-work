# 项目讨论分屏：标签版设计与实现

日期：2026-09-27。设计已由用户在“可以，按这个设计方案”中确认；入口冲突时再次明确“以本轮右侧分屏为准”。当前实施目标与交付程度：**功能可用的项目讨论切片**。已接真实服务并在隔离测试项目实操；不是完整通信产品的发布验收。本文件是本轮唯一需求书。

用户最新约束：从右下角入口打开后采用**分屏**，原工作界面收窄到左边，讨论占据右侧一部分，并以合适的缩放/收展动效衔接。此约束替代上一版覆盖式浮窗；仍然不能让聊天独占全屏。聊天用于必要的项目对齐，不能成为新的工作中心。保留项目成员群聊、所有项目成员可见的 Thread、群流与 Thread 共享上下文；不做私聊。保留现有底部 Dock 的位置和职责。

已确认的产品结构：一个项目主群是公共空间，其下公开 Thread 集中可见、点击参与。用户最新指定将话题改为**标签**，替代目录列表与文字索引。不规划额外主题群，不恢复消息下的大段折叠回复。

最新视觉纠偏：用户认为文字索引版仍然一般，要求弱化 dashboard 感，并授权不拘泥旧设计、从头排版。本轮提出**轻量话题标签＋自然对话流**：标签按名称自然宽度排列，主群和各 Thread 在同一区域选择；会话用作者、段落、少量消息气泡形成阅读节奏。保留左右分屏等已确认行为，不把旧布局、标题或样例文档当作视觉约束。用户已确认标签版方向；最终产品体验仍需真实操作验证。

## 端到端复查修复合同（2026-09-27，用户授权“全部修复”）

修复结果：五项已修复，14 项定向回归及真实工作台复现验证通过，详见 [修复记录](review/e2e-audit/fixes.md)。

后续复查发现的五项问题以 `review/e2e-audit/report.md` 为证据，替代此前“无 P1”的判断。本轮全部修复：缓存话题跨页补齐、提交 A 不清除更新的草稿 B、本地会话失效后恢复原成员、390×400 下输入可达、搜索期间不覆盖阅读锚点。保留已确认的标签与分屏方向，目标仍为功能可用。

历史加载统一在 typed browser history 模块处理，合并缓存前补齐到重叠页，并保持正确的最旧分页游标。草稿以 client_id 标识提交版本，只清除已完成的版本。浏览器实现从原始字符串移为可类型检查的函数，按历史、草稿、连接、视图与控制器分责；客户端脚本仍由包导出，无新增运行服务。搜索与阅读查询归 ImReads，推进阅读游标归 ImWrites；协议增加具名 DTO。具名成员的稳定提交回执跨恢复后的会话识别，避免身份恢复后重试产生重复消息；匿名命名回执仍按会话隔离。

本地身份恢复使用现有 local control token、Origin 校验及真实项目目录作为本机操作者授权，只在当前匿名/失效会话下从该项目已持久化 owner_id 恢复原身份，复用共享 Identity 的一次性 bootstrap/connect。浏览器不能传入恢复成员 ID；已有其他具名成员不被替换，仍须通过 mw_access 检查。首次项目无 owner 时继续设置名字；远程共享服务不暴露此本机恢复桥。这个信任边界与本机操作者对目录项目的控制权一致，不按显示名猜身份、不新增第二份身份库。

短屏保持上下分屏，工作区仍留可见空间；压缩导航占高，Thread 来源在消息滚动区内可访问，输入始终保留。搜索或隐藏会话的零尺寸不能成为阅读位置。验收包括分页跨 50 条的真实补齐、延迟发布响应后新草稿保留、丢失/过期 cookie 与宿主重启恢复原成员及权限负例、390×400 布局与搜索切换锚点实操，以及相关包类型检查和领域/HTTP 回归。实体软键盘、跨设备登录和未实现长期能力仍不在本轮完成声明中。

## 产品判断与当前证据

目标是让成员迅速知道发生了什么、哪里需要自己判断，然后回到项目工作。完整度体现在上下文、可靠发送、可追溯结论与恢复能力，不以聊天时长、消息量或功能入口数量衡量。

实施前基线：main 的群聊入口在右下角 Dock，打开覆盖式浮窗，标题仍是“群聊与私聊”；room 没有 project_id、群成员独立管理。已有群消息、公开 Thread、来源定位、独立草稿、历史分页、发送重试和 SSE。本轮复用这些能力，补上项目绑定、mw_access 权限与新的分屏表达。

设计原则：**工作保持在原处，讨论就地展开；先理解变化，再参与必要的对齐，最后留下可引用的结论。**

## 选定形态与边界

- 右下角是入口，打开后为按需出现的右侧分屏讨论区。左侧工作真实让出宽度；两边没有覆盖关系。不提供全屏聊天页、最大化按钮或新的全局收件箱。不改当前工作路由、不加遮罩；顶部标签与底部 Dock 保持位置。
- 每个项目一个主群。右侧只保留项目名称、必要成员信息和一组常驻话题标签；“主群”作为固定首个标签，公开 Thread 紧随其后，下方为当前会话。无需找到源消息才能发现 Thread。
- 项目内群与 Thread 默认对全体项目成员可见。关注、静音和通知偏好只影响提醒，不改变可见权限。入口文案统一为“项目讨论”或“群聊”，移除“私聊”。
- 恢复约 65% 工作／35% 讨论的分屏起点，右侧通常约 520–600px。两块纸面位于同一浅灰底上，窄间隔与细边界区分区域，无遮罩或浮层阴影。保留分隔条尺寸调节和顶部、底部宿主位置。
- 标签带在当前会话上方常驻：按标题自然宽度折行，通常占两至三行，不做等宽网格、两列目录或卡片。标签只放名称，未读以轻量圆点表示；不常驻堆叠回复数、时间、状态、最新一句和头像。选择 Thread 只切换下方会话，主群标签始终可见，不改左侧工作或路由。
- 本轮图中的文档、成员、消息及计数均为设计样例。文档内容与 Dock 图标不构成修改其他插件、品牌或全局导航的要求；本轮宿主变化只涉及分屏布局。

## 长期完整使用路径（本切片以实施合同为界）

1. 用户正在编辑“首页方案”，右下角出现温和的提醒。普通未读用一个点；需要本人的提及或明确确认请求才有数字。不会弹窗打断，也不重复推送一串普通回复。
2. 打开主群时左侧工作同步收窄、右侧讨论展开，话题标签常驻，对话停留在上次阅读位置。“快速了解”按需展开自上次离开的变化、尚未解决的问题与来源；已有人工结论明确标注，没有可靠摘要时直接看原消息，不伪造“已对齐”。
3. 点“# 首页结构”标签，下方会话展示来源消息、当前结论和回复；选中标签与输入目标同步变化。“主群”标签一直可见，点回即恢复原位置和草稿；查看来源也只在同一讨论区定位，不跳页。
4. 用户补充判断，可引用当前文档的选区、Goal 或已有产物。当前会话只有一个主输入框，明确项目、主群或 Thread 目标；每个目标独立保存草稿，切换时恢复。
5. 将讨论整理成结论，明确确认人、时间与引用消息，并关联回“首页方案”。需要修改文档或目标时展示具体修改建议，由用户在对应工作能力中应用；聊天不会悄悄覆盖文档，也不会由 AI 擅自宣称共识。
6. 最小化，继续原工作。重新打开恢复同一个群、Thread、阅读位置、草稿和正在进行的上传；最小化不会取消已提交发送。

## 信息层级

右侧采用一个项目标题和一行必要成员信息，不再叠加“项目讨论／项目主群／公开话题 6／今天主群”等多重横条。标签直接以名称表达内容，例如“主群”“# 首页结构”“# 周五发布”；选中项为石墨色小胶囊，未选中为极浅中性底，未读仅用一枚轻点。“＋”创建新话题。标签表达独立 Thread，不是把主群消息按关键词过滤，也不改变公开权限。

标签下方直接进入当前对话，不用目录表头、计数栏、统计摘要或大分割线。详细进展在悬停、焦点或选中话题后查看，触屏可达；实时回复不打乱正在使用的标签顺序。“快速了解”、文件、置顶、成员管理与富文本按需出现。

消息以姓名、正文和自然段落形成节奏；他人消息靠左，自己的短回复可以右对齐浅灰气泡，不把所有消息做成整行表格或等宽卡片。头像小且克制，正文保持深色可读。附件默认一行文件引用。正文中的话题引用也使用同一标签样式，与顶部导航建立直接联系；不再为每个 Thread 引用生成大卡片。阅读历史时新消息不抢滚动。

选中 Thread 后，在当前会话中展示短来源引用、当前结论或待判断问题、回复流。更多回复按需加载；来源上文可在该区域展开。主群与每个 Thread 各自保存阅读锚点和草稿。底部输入对象随选择明确变为“发到 #项目主群”或“回复 首页信息架构”，不能在切换过程中误发到新目标。主群有新提及时，固定入口显示提醒，不夺取当前 Thread 焦点。

Thread 有“讨论中／已有结论”两个轻量状态。已有结论仍可回复；新消息不能自动覆写结论，修订保留作者、时间与旧版本。对话中的疑问与指派给具体成员的“请确认”区分：后者由人显式发起并显示对象，AI 推断的问题只能标为“可能需要确认”。不把 Thread 变成复杂工单状态机。

| --- | --- | --- |
| 顺手讨论 | 基础富文本、代码块、引用回复、表情回应、@项目成员、图片/文件上传预览 | 常用操作直接可达，其余渐进展开；附件显示上传进度及逐项重试 |
| 自然分话题 | 消息上“创建 Thread”携带来源进入当前会话；也可从标签带的“＋”新建 | 来源可选；第一条成功消息才创建正式 Thread，并向所有项目成员显示话题标签；取消空草稿不留下空话题 |
| 找到需要自己的内容 | 常驻话题标签、提及、关注、未读游标、明确确认请求 | 默认提醒提及、本人确认请求和关注话题；不制造在线榜、已读监视或聊天排行榜 |

| 连回工作 | 插入当前工作引用；关联文档、Goal、产物；复制消息/Thread 链接 | 链接打开时恢复正确项目范围及分屏讨论区，不打开全屏聊天；引用保留资源权限 |
| 固化对齐 | 记录、确认、修订结论；分享结论到主群 | 分享为带回链的引用；注明版本，结论变化可追溯，不悄悄修改历史消息 |

实施顺序按依赖推进：先项目权限与分屏完整状态，再可靠的消息表达、引用和检索，再 AI 追赶与结论回写。不能把只有外观和假数据的阶段宣称为完整通信能力，也不为了“丰富”加入私聊、音视频或联系人体系。

## AI 的具体角色

AI 使用现有 Prologue 能力与身份权限，作为按需的整理工具。可先提供“快速了解”和“整理结论”两个动作；上次已生成的摘要可直接展示，有新消息则注明更新范围。默认不因每次 hover 或每条新消息触发模型，也不在群内持续扮演一个发言成员。

- 输入：当前项目、选定群/Thread、明确的消息范围及引用资源；只读取当前成员可访问且本次需要的上下文。不读取个人 Assistant 私有会话，不扩大到其他项目。
- 输出：带消息来源的新增变化、未解决问题和建议结论草稿。摘要显示 AI 标识、生成时间与覆盖到的消息位置；人工结论显示确认人，两者不能混为同一个状态。
- 干预：可展开原文、修改草稿、重新生成、停止生成。生成中的内容保持草稿态；只有成员确认后才能成为项目结论或发出确认请求。
- 失败：超时或不可用仅影响摘要区域，原消息与发送仍能工作；允许重试。新消息到达使摘要标记“有更新”，不自动覆盖用户正在编辑的结论。
- 恢复：请求绑定项目、Thread 和消息范围。重开讨论区显示已完成结果或明确中断态；切项目后旧请求不能写入新项目。结论确认与分享各有幂等标识，重复操作不生成多条记录。

## 视觉、动效与操作细节

白色、极浅中性灰和石墨色；无绿色背景。艺术感来自对话的疏密、自然宽度标签、少量非对称消息与清楚的层级，不依靠装饰插画或彩色模块。标签、头像、气泡与输入区的圆角和大小形成一致但有区分的节奏；不把每一层都框成卡片。公开范围和发送对象仍明确。

左侧更换为实际工作中的发布说明草稿，不再复用“首页方案＋01/02/03条目”的示意排版，也不嵌套产品截图或仪表盘。此举用于表达工作与对话共处，不要求修改其他插件的真实文档内容。底部 Dock 保留入口职责，标签使线程可见、可参与，不能变成纯装饰。

正文 14–15px、约 1.6 行高，元信息通常不低于 12px；不通过缩小字号制造精致感。输入区默认是一条安静的书写边界，聚焦后展开格式与附件操作；“＋”、提及、项目引用和发送保持清楚可达。始终明确主群或 Thread 目标；Enter 发送、Shift+Enter 换行，中文输入法组合态不触发发送。

| 变化 | 动效意图 |
| --- | --- |
| 打开/收起 | 约 300–360ms，左右宽度共用同一个缓动 cubic-bezier(.22,1,.36,1)，工作区从全宽收至分屏宽度，右侧从边缘同步展开。关闭反向恢复；无先缩后弹、无弹跳 |
| 打开 Thread | 标签选择态短过渡，当前会话约 120–160ms 淡入；标签位置、左右宽度和 Dock 保持稳定 |
| 切换主群／Thread | 当前会话短淡入并恢复目标阅读位置；不重复整个分屏入场，不挤压左侧第二次 |
| 定位来源 | 滚到目标并短暂高亮，键盘焦点可见；减弱动态模式直接定位 |
| 发送与上传 | 局部状态反馈区分待发送、已确认、失败；动画结束不等于服务端成功 |

“缩放感”来自工作表面的连续收展与内容重新适配，不把整个应用长期 transform:scale 到小字号。文档保持正常字号；画布类能力响应新的容器尺寸并保留已有视口中心和用户缩放。宿主不能复制页面截图代替真实界面。保留左侧路由、编辑器选区、焦点、滚动锚点和进行中的任务，不卸载重建插件。动态布局时尽量先收边距、再调整内容排版；打开/关闭中途再次操作从当前位置反向过渡，不能排队播放。拖动分隔条直接跟手，释放后记忆比例，不叠加缓动。

左侧工作始终可点击，操作左侧不自动收起讨论。收起按钮关闭分屏，Escape 先关局部菜单/预览，再收起；焦点回到触发器。所有 hover 操作同样可通过键盘和触摸到达；减少动态偏好直接切换布局。打开讨论不强制聚焦输入框或弹出软键盘。

## 空间与关键状态

- 1600px 桌面可从左工作约 1040px、右讨论约 560px 开始；1280px 时右侧约 440px，标签按自然宽度折行。正文不缩字，用户可调分隔条。
- 标签带高度有界，较多话题时在常驻区域内滚动或用“全部话题”展开查找；主群、当前话题和重要未读优先保持可达，不能让无限标签挤掉对话。更窄设备采用上工作、下讨论，标签仍常驻。移动端和软键盘须另行验证。
- 空项目只显示真实主群、简短使用提示与“引用当前工作”；成员管理继承项目入口，不生成假成员或示例聊天。
- 草稿按账户＋项目＋群/Thread 隔离。外部切换项目不悄悄更换现有输入框的发送对象；显示原项目，显式切换后保存并恢复目标草稿。权限撤销时停止读取与发送，不把旧正文带入其他项目。
- 离线和发送失败保留消息、附件与稳定请求标识。成功写入但响应丢失时重试不重复发送；长历史分页保持阅读位置，单个上传失败不使其他文件重传。
- AI 不可用、缺失/删除的来源、已归档群、已撤权资源均显示真实原因与可用动作，不伪造加载成功。
- 原消息只有在讨论区可见、应用前台且进入阅读视口后推进相应读游标；群和 Thread 分开。收起讨论区、只看摘要或后台收到 SSE 不清空全部未读。

历史 room 没有 project_id，不能按群名猜测归属或自动放宽成员权限。本轮 schema 升级保留消息/Thread 标识与原记录；旧群仍未绑定，保持原访问边界，不向项目成员自动公开。旧群显式绑定项目的产品迁移入口留待后续。本次已验证 nullable Thread 来源字段的旧库迁移、引用完整性及重复迁移；不对用户生产数据执行额外绑定。

附件复用经过核验的现有资源存储能力；引用保存稳定标识与可展示信息，不复制另一个项目事实库。摘要不是结论事实源；结论确认以服务端记录为准。`packages/im-ui/src/host.ts` 旧侧栏/全屏宿主实现要在接入时核对调用方后收敛，不能保留第二条默认全屏入口。
