## 1. 背景

T-172（#1450，已合入 `1e99b21ca`）二审 6498366253 的建议与登记（MISC「T-172 二审 建议」「T-172 二审 登记」两行）：

- `apps/local-host/src/home-plugins.ts:168` 的 `release()` 只调一次 `platform.runtime.list()`；一条坏的 `record_json` 让 `list()` 抛错，整个 Home 关闭在停任何插件之前就中止，RAC-1923 对项目守住的「一条坏记录不挡别的插件关闭」对 Home 没守住。
- 同一个 `plugin_id` 有两条记录（已卸的旧包 + 另一签名的重装）时，`closePlugin` 经 `Supervisor.revoke` 不带 `preserve_enabled` 停掉在跑的安装，记成停用。
- `:168` 的注释不全；没有 Host 侧「记录已消失」的用例；没有 Home 用例断言「Home 插件关闭失败」。

## 2. 目标

1. Home 关闭时一条读不了的记录只让那一条记进 `failures`，其余插件照常关；最后仍以「Home 插件关闭失败」的 `AggregateError` 报出。
2. 同一 `plugin_id` 的旧记录不会把在跑的另一安装记成停用。
3. 上面每条有用例，含「Home 插件关闭失败」的断言。

## 3. 不做

- 不改项目一侧（`project-plugins.ts`）已有的行为，除非两边共用的 `closePlugin` 必须跟着改；改了要在【方案】里写明对项目的影响。
- 不加兼容或迁移逻辑。

## 4. 范围

`apps/local-host/src/home-plugins.ts`、`apps/local-host/src/plugin-platform-close.ts`（如需要）、`tests/home-plugin-close.test.ts`；Runtime 的 `list` 若要逐条读，先看 `packages/plugin-runtime` 有没有现成的逐条读法，没有就停下来问（Runtime 是共享核心）。

## 5. 做法

照 T-172 的写法与它的用例文件。先核 Runtime 的 `list()` 坏记录时怎样抛（文件与行），再定是在 Host 侧逐条兜住，还是 Runtime 已有逐条的读法可用。

## 6. 验收

- `RAC-2180`：一条坏记录不挡别的 Home 插件关闭，关闭最后报「Home 插件关闭失败」。
- `RAC-2181`：同一 `plugin_id` 两条记录时在跑的安装仍是启用。
- `RAC-2182`：记录在关闭途中消失（Host 侧）。
- 余下号备用。
