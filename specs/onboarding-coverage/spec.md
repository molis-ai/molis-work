## 1. 目标与依据

用户需要分别理解角色、插件、Skill、工作流程、资料和多处设置，才能拼出使用路径。引导应把这些配置组织成可开始工作的场景：**表达用途 → 补齐必要背景 → 预览场景与配置 → 采用 → 完成第一件事 → 继续使用与调整**。材料导入、空白开始和个人空间继续可用；场景目标与已有材料都可以作为起点。

### 1.1 实际使用反馈与首要闭环

2026-10-27 用户实际反馈：大文件夹清点久且无反馈，多位置选择、展开收起与点文件无效；连模型时仍显示文件，返回后八千多项变成 0；材料已读、DeepSeek 已配置，摘要停在笼统的“模型请求失败或超时”；缩小范围再确认无响应，最后进入的“数小智”项目没有材料，Coding 又要求另选工作目录。代码文件夹还只识别了部分文件，支持范围与遗漏原因不清楚。

这些是待复现的用户报告，不是已确认根因。本书将其归为一条必须贯穿的基础路径：**同时选择已有文件夹 → 看清文件与范围 → 在引导内复用或连接模型 → 读取并整理 → 带着材料和已有结果进入项目 → 接着工作**。正常、返回修改、生成失败和重启后都要走通，不能把若干按钮修好或某一步成功当作交付。先修顺这条路径，再扩展场景、助理团与新交互首页；普通材料带入不依赖这些高级能力完成。

## 3. 场景与行为

### 3.1 模型与无模型路径（保留 R1～R5）

- **R1** 首次使用、新项目和任务准备中，在第一次需要模型生成之前，可在当前流程完成最短配置和连接检查，回来继续同一轮。
- **R2** 已有可用模型直接复用，显示当前选择与更换入口；项目或角色的显式选择必须符合当前有效的供应商、权限和用量限制。
- **R3** 保存成功不丢已答问题、材料、场景预览与进度，不要求重新开始。
- **R4** 可以先用已有方案、手动配置或带入资料，稍后生成。摘要、团队建议或新页面尚未生成时明确标注，并保留继续入口。
- **R5** 模型失败、超时或输出不可用时，保留当前草稿和人工修改，允许修正或重试；不展示假摘要、假团队能力或假运行结果。

### 3.2 数据与信任（保留 R6～R8）

- **R6** 读取资料正文或本机规则之前，说明本次读取范围、数据存放位置、哪些内容会交给外部模型；原文件保持不变。读取授权与持续观察、写入授权分别表达。
- **R7** 数据说明能到达真实的导出、删除与撤销授权入口；场景退出不等于删除用户资料。
- **R8** 导入默认是一次性快照，持续同步、持续观察或周期执行另按有效委托启用。说明如何更新材料、停用后有什么影响。

2026-10-28 已定：[Sessions](../sessions-rebuild/spec.md)的外部 AI 工作记录是可接入的已有材料来源，覆盖国内外主流工具。首次使用、新建项目或为已有项目补资料时，工具接入并获准读取后自动发现范围内已有会话，无需逐个导入；发现进度、已有结果与失败可见，重试不重复建目录项，按 SRB-12～13 验证。会话已有明确的目录／仓库与项目关联时自动归入对应项目，不必逐个重新选择；关系不明确或有多个候选时，由 AI 建议、用户确认或改选，未决定保持未归类，不自动新建项目，按 SRB-14～16 验证。可在获准范围导入历史，形成带来源、可纠正的背景、决定、成果与未完成事项；已读材料不因 AI 整理失败而丢失，恢复与重复导入不重复计作新成果，按 SRB-09 验证。持续跟进和恢复／发消息／跨工具交接同样在 Sessions 完整范围内，但各按有效委托启用；导入不自动启动外部会话。Onboarding 复用其公共来源与控制能力，不自行维护厂商读取器、会话库或执行链。

### 3.3 采用后的下一步（保留并扩展 R9～R11）

- **R9** 采用后落到可工作的场景首页或明确的任务位置，有一个与本次目的相关的主要开始动作；同时提供可跳过的后续设置，覆盖记忆、能力与连接、工作目录、助理规则与用量。已完成的配置显示实际值，未完成的说明影响。
- **R10** 可跳过后续设置直接进入工作，之后从设置、场景首页或助理继续；不会因为跳过可选配置反复重播首跑。
- **R11** 跳过模型或依赖时，保留补齐并接续生成的入口。配置完成与实际任务完成分开记录。

### 3.4 更新页（保留 R12）

- **R12** 更新页显示版本与真实更新要点；没有要点时只说明版本与数据仍在本机。新能力可以成为已有场景的可选改进，不静默替换用户配置或重生成首页。

### 3.5 系统权限（保留 R13～R14）

- **R13** 首次启动不主动请求屏幕录制、辅助功能、输入监控等系统权限。
- **R14** 到具体场景首次使用相关能力时，说明用途、影响和开启位置，允许取消；取消后保留其他配置，不反复弹出，也不标成已经可用。

### 3.6 恢复、键盘与语言（保留 R15～R16）

- **R15** 可返回、跳过、保存草稿、离开后接续。问题答案、范围、人工修改、材料读取与生成进度均可恢复；更正一个答案时只重算受影响部分，并说明变化。
- **R16** 引导、设置预览、采用和生成首页的关键操作可全键盘完成，有可见焦点和读屏名称；中英文路径完整。布局适配桌面与窄窗口，状态变化不能吞掉输入或焦点。

### 3.7 首跑与各次准备的状态（扩展 R17）

- **R17** 首次使用的材料、空白、个人空间分支完成或跳过后，不因以后新建项目、增加场景或发起任务而重新触发首跑；更新提示仍按版本管理。各次项目/任务准备保存自己的进度，不能共用一个“已完成引导”标记。

### 3.8 场景与能力组合

“场景包”是面向用途的可复用配置方案，“能力组合”表达其中用到哪些能力（2026-11-08 起「能力包」专指平台统一管理技能、提示词、角色、工具、MCP 声明的[能力包](../capability-pack/spec.md)，这里原写的「能力包」改称「能力组合」，用户定）。它们与[技能包](../skill-packs/spec.md)配合：Skill 提供做法，场景把做法与角色、工具和入口接起来。具体包装与版本格式在实现设计时沿现行 Manifest、插件安装与信任合同确定，不开第二条注册或安装路径。

| 内容 | 必须表达的结果 |
| --- | --- |
| 场景目的 | 适用的人和工作、输入、预期输出、第一次可以做成什么 |
| 个人助理与项目助理团 | 个人助理负责接待与接续；各专业角色的职责、Skill、可用能力、材料范围、输出及协作关系 |
| 插件与连接 | 需要哪些实际可用的内容和动作，必要与可选依赖分别列明；缺失时指出受影响步骤 |
| 工作方法与流程 | Skill 表达可调整做法；已有工作流程承接适合固定的步骤；需要判断的部分保留 AI 与用户干预位置 |
| 项目与任务背景 | 项目说明、已选资料、工作目录、规则和规划方法；来源可查，采用后交给实际主人保存 |
| 运行条件 | 模型、用量、主动程度、周期、通知、观察与操作范围及对应设置来源 |
| 首页与起步内容 | 页面定义、真实内容和动作绑定、第一件任务与结果位置；示例内容明确标注 |

支持选用预置方案、AI 从目的生成方案、基于已有项目/获准资料/规则与 Skills 生成草稿，以及把满意的一次工作整理为个人可复用方案。AI 可以推荐未安装但真实可取得的依赖，采用前要显示来源和当前可用性；缺少能力时不能造一个按钮冒充已经接通。

一项目可保留多个场景；新场景复用已有角色、连接或配置前核对适用性，冲突时显示差异供选择。采用、复制、调整和停用均有明确作用域。模板升级展示差异，用户自己的覆盖不被自动抹掉。移除场景只解除其拥有的配置与绑定，用户产生的文稿、任务、资料和共享角色继续保留；删除业务内容走原主人的删除入口。

#### 3.8.1 官方场景包

Molis Work 自己提供几套做好、试过的场景包（下称**官方场景包**），让第一次使用的人不用先理解角色、插件和 Skill 就能挑一个起点开始工作。官方场景包是 §3.8 场景包的一种，和用户自己保存的个人场景包、AI 生成的方案走同一份声明、同一条采用路径，不另设注册、安装或宿主分支。

**首批三套**（2026-11-04 用户定）：

| 官方场景包 | 给谁、第一次能做成什么 | 主要组成（以实现时真实可用的为准） |
| --- | --- | --- |
| 行业观察与写作 | 要定期跟踪一个领域并写成观察的人；第一次做出一份本周观察，放在 Pages 里 | Feed 订阅来源、Pages 写稿；研究与编辑两个角色；取材、比较与写作的 Skill；起步首页是本周来源与本期稿件 |
| 写代码 | 在本机项目上写代码的人；第一次读懂选定的代码目录，并在 Coding 里接着做一项改动 | Coding、GitHub 连接、Todo；代码目录与执行授权在采用时由用户给；起步首页是当前改动、待办与最近会话 |
| 个人事务与每日简报 | 想让助理帮忙理清每天要做什么的人；第一次生成今天的简报并落到待办 | Todo、Inbox、日程查询、日报 Skill；起步首页是今日简报、待办与接下来的安排 |

每套必须写清 §3.8 表里的全部内容（目的、个人助理与项目助理团、插件与连接、做法与流程、背景、运行条件、首页与起步内容），并附一件**示范任务**：采用后立刻能做、能做完、结果落在真实位置。官方场景包不带示例数据冒充用户的内容；需要示例时明确标注，用户的第一件工作用自己的真实输入。

**在引导里怎样出现**（2026-11-04 用户定：两种都有）：

- 第一问「想用 Molis Work 做什么」旁放几张官方场景包快捷卡，挑一张就以它为起点，只补问这套与用户情况不同的地方（例如关注哪个领域、选哪个代码目录、看哪些日程）。
- 也可以直接写目的，由个人助理按目的推荐一到三套作为起点，并说明为什么推荐；都不合适时可以从空白开始或让 AI 生成。
- 新建项目和给已有项目增加场景时，同样能挑官方场景包；已在用的官方场景包不重复推荐。快捷卡的数量与排列由定样决定，不做成必须先挑一套的门槛。

**怎样交付与更新**（2026-11-04 用户定：随安装包带上，选了才启用）：

- 每套是一个只有声明、没有运行时的签名插件（同[技能包](../skill-packs/spec.md)的形态），随安装包带上，离线也能挑；按发布者签名决定安装信任，和其他插件同等待遇，不因为是官方的就跳过授权确认或依赖检查。
- 没被选中的官方场景包只在挑选处与助理的推荐里出现，不进工作台和项目；选中后才启用并按 §3.12 采用。
- 官方场景包里依赖的插件与连接，随包已有的直接启用；需要账号连接的（如 GitHub）在采用时补，缺了只挡受影响的步骤，并说清楚缺什么。
- 新版本带来官方场景包更新时，按 §3.8 的模板升级规则展示差异，用户改过的部分不被覆盖；用户可以不升级。
- 用户可以把采用后的官方场景包另存为个人场景包（§3.13），之后与官方版本分开演进。

### 3.9 动态渐进访谈与助理关系

秘书就是现有跨项目个人助理，沿用其身份、会话接续和授权范围。各项目可以有自己的助理团；同名角色不意味着共享本项目资料，修改一个项目的角色配置不能改掉其他项目或个人默认。专业成员必须具有实际可用的做法与能力，能承担并交付其工作；仅有头像和介绍不算助理团完成。后台执行继续使用同一个 Prologue 运行时，不要求每个成员常驻一个进程。

个人助理消费用户当前目的、已答问题、已选材料、获准的既有设置、能力目录和准备进度，产出下一项有用的问题、可修改的场景草稿、团队建议、页面草稿及采用后的下一步。用户能看见依据、待补项和即将改变的配置，可更正理解、改角色或流程、跳过、暂停和采用。

提问以当前目标和缺少的决定为依据，选择题与自由输入并用，不设人人必答的长问卷。已知内容预填并显示来源；只询问会影响结果、配置、费用或权限的差异。已有配置足够时可以直接预览并开始。用户更正后不重问已确认且未受影响的信息；不把临时回答自动写成永久个人偏好。

示例路径：“每周跟踪 AI 产品，形成一份观察”。先明确给谁看、已有来源和想拿到的结果；对外发布才补渠道和风格。方案逐渐出现研究与编辑角色、来源、写作做法、首页与本周输出入口；采用后先完成一次实际观察。开启定时运行或外部发布依照用户对此用途的有效委托，不由“创建场景”自动代替。

### 3.10 AI 生成新的交互首页

**2026-11-04 改**：用户定首页是平台能力，插件注册卡片，按描述生成的页面是首页自己的内容、不当插件；页面定义、版本、人工修改与恢复归平台的首页服务（[场景与生成页面公共合同第 6 节](../scene-and-page-contract/spec.md#6-首页与生成页面)），Work Brief 是给首页注册卡片与简报的普通插件。

首页是平台能力，保留未安装任何综合插件时的基础首页，并提供公开来源、呈现和隔离挂载能力；生成的页面是首页自己的内容，定义、版本、人工修改与恢复归首页服务，Work Brief 只给首页注册卡片、提供简报。本书继续拥有用途澄清、动态引导、配置预览、采用与第一件工作，不另存页面或另建首页实现。基础引导、材料带入及原插件工作不依赖 Work Brief；采用生成首页时只补齐页面声明用到的插件依赖，不能静默安装或让其他步骤等待它。

用户可描述希望怎样工作，由 AI 生成并迭代新的页面布局与交互，包括带真实内容的比较、筛选、编辑、参数输入、结果预览和下一步操作等。可以复用已有模块，也必须允许当前模块库没有的交互组合与页面实现。只换主题、文案或排列已有卡片不满足本项。

生成页面仍位于工作台现有首页/主区挂载位置，保留项目上下文、全局导航与个人助理入口；不另开产品外壳或浏览器标签。页面显示和写入的事实继续归原插件，经过公开合同与统一动作授权访问。生成代码按不可信代码处理，复用平台隔离、安装信任与生命周期；需要补的通用页面能力先进入平台合同，不能直接读取私有数据库、凭据、宿主文件或为某个场景加特权路由。

生成过程为：描述与材料 → 可操作预览 → 用户调整 → 展示依赖、权限与配置变化 → 采用 → 在目标项目打开。预览中的示例/模拟数据与真实操作明确区分；需要真实写入的试用沿现有授权，不用“预览”掩盖副作用。页面保存定义、版本和有效绑定，重启后可继续使用，能恢复上一可用版本。人工修改被后续生成覆盖之前展示差异。

生成失败、内容质量不合格、依赖停用、动作失败或页面无法加载时，保留草稿和原可用首页，显示具体受影响功能，提供修复、重试或回到默认首页的入口。页面切换项目不能把旧项目绑定带入新项目；跨项目读取仍按个人助理与原动作的授权处理。

“生成、预览、校验、保存与恢复页面”是本需求的依赖，须在首条场景闭环中交付；完整插件创作台重做继续按原需求推进。实现设计可复用 Runtime/SDK/UI 能力补齐最小通用路径，不能把新交互页面缩成静态模板，也不能把整项能力推迟到创作台重做之后。

### 3.11 全局、项目与插件设置覆盖

覆盖不是把全部设置排成首跑必填表。每项都要确定：由谁保存、作用在哪、是否已有可继承值、何时需要询问、跳过有什么影响、从哪里继续。下面是 2026-10-27 的入口级清单；实施时按实际目录展开到可配置字段，逐项标记“复用/本次询问/首次使用时引导/高级入口/尚不可用”，不得漏掉插件声明的设置。引导与设置页读写同一份有效配置，不保存第二套值。

### 3.12 采用、修改与恢复

采用前给出具体结果预览和变更：会新建什么、复用什么、修改哪些配置、属于个人/项目/本次哪个范围、有哪些必要依赖未就绪。用户可以局部调整和采用已可用部分；已授权的同范围操作继续使用既有授权，不机械重复确认。安装、外部发送、持续委托等仍按其真实权限处理。

采用写入各配置与内容的唯一主人，回读实际结果后标为可用。多步采用必须区分未执行、已生效、失败和待补部分；取消、重启或重试不重复创建项目、成员、流程和页面，也不重复外部效果。失败后接续尚未完成部分，未知结果先核对。撤权、项目切换或安装换代后迟到结果不能写进错误范围。

撤销只处理本次仍归该操作拥有的配置，不能覆盖此后人工修改、删除既有内容或把别的场景仍使用的连接/角色一起卸掉。新页面不合用可以回到原首页；暂停引导不会抹去已经完成的真实工作。

### 3.13 通用任务引导与复用

快速创建、插件入口或个人助理发起工作时，都能按已知上下文补齐缺少的信息，再进入真实执行。提供方描述需要的信息、校验、依赖、采用动作和完成后的落点；平台共用问题呈现、草稿、返回、恢复和采用反馈，复用现有问卷/动作/工作流能力，不为每个场景开发独立向导或另造工作流引擎。

首轮实现先走通一个从表达目的到真实成果的场景，再以不同类型任务验证可复用性。具体任务可一次完成，不强制建项目、建永久角色或存成模板。把成功做法保存为个人场景包、复制到另一项目或导出时，预览会携带的配置、内容和引用；凭据不导出，私人资料默认不随模板携带，跨项目绑定重新选择。公开市场与发布页面不在本书范围。

### 3.14 从已有材料到可继续工作的项目

#### 选择与清点

下载、文稿、桌面和其他目录可同时选择，也可补选文件；选择、排除和展开状态相互独立。目录可展开/收起，深层与下方条目可正常勾选，文件名可打开详情或在授权范围内预览。相同文件从重叠目录带入时能识别重复，不重复计入有效材料。大清单保持可操作，用户不必等整个文件夹清完才知道操作已接收。

清点开始立即显示正在检查的位置、已发现的条目和当前进展；总数尚不明确时不造百分比。清点结束给出文件名、可核对的数量及遗漏说明，失败或取消保留已完成部分并有继续入口。回到清单或重新打开时先恢复已保存的选择和数量；仍在加载/清点、读取失败、真正的空目录分别表达，不能先把未加载显示成“0 项”。

#### 真实文件支持与遗漏说明

文件发现不以一张窄扩展名白名单决定是否存在。代码目录至少覆盖常见源码、配置、脚本、文档与无扩展名文本，例如 TypeScript/JavaScript、Python、Rust、Go、Java、C/C++、Swift、Shell、HTML/CSS、JSON/YAML/TOML/XML、Markdown、普通文本以及 README、LICENSE、忽略规则等。按实际内容、编码和可用读取能力识别；不能因扩展名陌生就让可读文本从清单消失。此清单用于任务覆盖，不成为另一张只允许这些后缀的限制表。

混合目录中的 PDF、办公文档、表格、图片与其他二进制文件分别说明能否读取正文、需要什么解析能力、能否保留原件/引用。文件已被发现、已选、已读取/解析、已参与生成、最终带入项目是不同事实；对普通用户用简明结果表达，并可展开核对。不能用“发现了文件”宣称读懂，也不能因暂不能解析就假装文件不存在。

依赖目录、构建产物、版本控制内部目录等默认忽略有可查看的规则和数量；密钥等敏感材料不因目录被选中就自动送给模型。因类型、大小、数量、权限、编码或损坏未处理的内容逐项或按原因汇总，给出缩小范围、替换文件、补齐能力或保留原件/引用等适用处理方式。不能静默截断或将未处理项计为成功；技术限制只阻塞受影响材料。

#### 步骤与同一份进度

材料选择与模型连接是前后两步，当前步骤、标题、主要动作和右侧内容一致：选文件时看清单；连接模型时看模型配置与连接结果，保持引导布局，复用设置页的同一套保存、读取和连接能力，不跳进全局设置页。已有可用模型直接显示并可继续，不要求再次填写。

返回修改不被某个内部阶段名一概禁止。当前有效的选择、授权范围、已读材料、生成草稿和项目采用结果由其真实主人衔接；界面不能再维护一份相互矛盾的“已完成”。每个主要按钮要么开始相应操作并反馈进度，要么明确指出实际缺项或当前运行中的操作；“确认范围”不能无响应。先完成的本机材料工作不以摘要、团队或页面生成成功为前置；不为了满足固定向导顺序要求用户重选、重读或重复批准。

#### 读取、生成与修改后的恢复

先保存获准范围内的材料读取结果，再用当前有效模型生成摘要、待办等内容。用户看得出“材料已读好，正在生成”；生成失败不能丢掉已读材料、范围和人工修改。错误基于实际返回区分连接、鉴权、额度/限流、超时、输入限制或输出不可用等原因；无法确定时如实说明，不把所有错误统称为“失败或超时”。同时说明已完成什么，提供重试、更换模型、调整范围以及先带入材料稍后整理的可行入口。

更换模型可复用仍有效的已读材料；缩小范围后能重新确认并继续，新增材料只补读所需部分。只重做受变化影响的工作，旧摘要不能冒充基于新范围生成的结果；被移出范围的材料不再进入后续生成或采用。读取、外发和执行授权按实际变化处理，同范围已有授权不重复索取；撤权、取消和旧请求迟到仍遵守原边界，不产生未经授权的后续写入。

关闭、离开与重启后能恢复这一轮有效进度。重试前核对未知结果；重复点击、请求重试或采用中断不产生重复项目、重复材料或重复待办。实现可保留必要内部状态，但不得要求用户理解状态名或完成无关步骤才能恢复。

#### 项目落点与 Coding 接续

“进入项目”前，应确认这次有效材料及已生成的摘要/待办已经由各自主人保存，并在目标项目可打开、可引用和继续处理；不能只创建项目外壳就报导入成功。部分材料失败时明确显示已带入与未带入部分，允许采用可用部分并在项目内继续补齐。若保存失败，保留当前成果并提供续传/重试；用户明确选了空白开始才走空白路径。生成失败也可先带入已读材料，并在项目里更换模型或继续整理。

材料快照与可执行的工作目录有不同用途，系统应在这一条路径接好它们。用户选了代码项目根目录，后续 Coding 可直接复用该候选路径及仍有效的授权；若需要新增执行授权，或多个来源中需指定一个工作目录，只询问这项真实差异并说明影响，不让用户重新浏览和选择已经给过的路径。下载、桌面等材料来源不自动升级为可执行目录；摘要失败也不阻止访问已采用材料或执行其他已有权限的工作。

#### 贯穿验证

用有代表性的真实代码目录及混合材料验证支持范围与完整路径，覆盖大清单、多位置和深层文件；同时制造生成失败、采用部分失败和重启恢复，检查实际文件、材料引用、摘要、待办与工作目录接续。只证明 JSON 可解析、文件数相同、按钮可点或状态能转换不算完成。基础路径通过后继续本书其他场景，不因此缩小整项范围。

### 3.15 从页面帮助到渐进式引导

首次使用、新项目、已有项目补充配置和单次任务，共用[全产品文案与按需帮助规则](../visual-ui-experience/spec.md#copy-guidance)。一般说明由用户按需打开，选择其中的操作入口才进入准备；当前确实缺少的配置在相关动作处给出具体下一步。不要求用户先读完整教程，也不把所有设置集中成首跑问卷。权限、外发范围、费用和不可逆后果仍在相应决定前说明。

从插件空状态、设置、错误恢复或个人助理进入时，保留来源页面、当前对象/目的、已填内容、材料和有效配置；只在原授权范围内复用上下文。已有答案与设置足够时直接回到任务，缺少信息才补问，用户可查看为何需要这一项并修改已有答案。引导与原页面使用同一对象名称、动作含义和实际状态；设置保存仍归原主人，不额外复制一套值或“已完成”标记。

采用后回到原任务或明确的结果位置，显示真实保存结果和可以继续的动作。比如生成前缺模型，在流程内连接模型，返回后材料与草稿仍在，可以继续生成；连接本身不等于生成完成。跳过非必要设置仍可继续；缺少必要条件时说明受影响的那一步，并保留以后补齐的入口，不阻止无关工作。执行、外发和持续观察仍沿有效委托，查看帮助不产生授权。

帮助打开/关闭、返回、跳过、失败和重启均保持既有草稿与准备进度；结束教学不等于完成真实工作。后续使用直接进入工作，仍可主动查看帮助或调整设置；已跳过的一般提示不反复弹出。只有相关能力、配置或权限发生影响当前任务的变化时，重新提示具体缺项，不重播整套首跑。此路径继续满足 §3.6 的键盘、语言与恢复要求。

| ONB-46 | 真实代码与混合材料完整走通选择→模型→读取整理→项目内继续工作，并实走返回、失败、改范围和恢复；局部按钮、状态或计数测试不单独作为通过依据 |
| ONB-47 | 从插件、设置或个人助理的当前下一步进入准备，保留来源对象、输入、材料和有效配置，只补缺项；保存后原页面读取同一有效值并接续任务。已配置路径不重走首跑，跨项目不复用未获准材料 |
| ONB-48 | 帮助开关、返回、跳过、失败与重启后可继续同一准备过程；一般提示可跳过且不反复弹，帮助仍能主动找回。必要缺项只限制受影响操作，权限/外发/费用/不可逆后果在决定前可见，关闭帮助不授予权限或改变任务状态 |

| ONB-50 | 首批三套官方场景包都能从首次使用、新建项目、已有项目增加场景三处挑选；每套的目的、角色/Skill、插件与连接、运行条件、首页与示范任务可在采用前完整预览 |
| ONB-51 | 挑官方场景包与写目的两条路都可用：快捷卡挑一套后只补问差异；写目的后个人助理推荐一到三套并说明理由，都不选时可空白开始或让 AI 生成；已在用的官方场景包不重复推荐 |
| ONB-52 | [人工] 三套各自真实走通：从挑选、补问、采用到做完示范任务，结果落在真实位置（Pages 稿件、Coding 改动、今日简报与待办）；示例内容有标注，不冒充用户内容 |
| ONB-53 | 官方场景包随安装包带上，断网时也能挑选和采用不依赖网络的部分；没选的官方场景包只在挑选处与推荐里出现，不进工作台和项目；采用走与其他插件相同的签名信任、依赖检查与授权确认，代码里没有按场景包名或「官方」开的分支 |
| ONB-54 | 官方场景包依赖的连接或组件缺失时，只挡受影响的步骤并说明缺什么、去哪补；补好后从原处接续，不重走已完成的步骤 |
| ONB-55 | 新版本更新官方场景包时展示差异，用户改过的配置、角色与首页保留；不升级时原官方场景包照常可用；另存为个人场景包后与官方版本各自演进 |
| ONB-56 | 移除一个已采用的官方场景包只解除它拥有的配置与绑定，用户的稿件、待办、代码改动与共享角色保留 |
