# Molis Work 紧凑 UI 模式

## 完成等级

本轮目标是 **内部完整（Level 4）**：用户可以在系统设置中统一选择语言、主题和界面密度；当前 Project 的上下文与设置入口位于 Goal Navigator 上方；紧凑模式在浅色、深色的桌面 Goal 工作台中形成一眼可辨的高密度排版。

## 背景与问题证据

现有 Molis Work 工作台的 Goal 导航行高、分组留白、标题区和正文分区间距偏舒展。当 Goal Tree 较长、用户需要同时对照更多 Goal 和正文时，首屏可见信息不够。

用户提供的 Codex 工作台截图体现的目标密度是：左侧列表行紧凑、层级清楚；右侧正文使用较小但可读的排版节奏；在不让操作目标变小的前提下提高单屏信息量。

## 用户场景

- 用户在桌面宽屏中同时查看长 Goal Tree、选中 Goal 和 Goal 正文。
- 用户希望在当前设备上长期使用紧凑模式，但不改写项目、Goal 或 Runtime 数据。
- 用户可随时切回标准模式，无需刷新页面。

## 范围

- 顶栏右侧齿轮只进入「系统设置」，不再进入 Project 工作规则。
- 系统设置只保留系统级内容：「界面与语言」「AI 与执行工具」「诊断」。
- 「界面与语言」统一提供中文/English、浅色/深色/跟随系统、标准/紧凑。
- 移除普通工作台、项目列表和 Project 设置页顶栏中散落的语言与主题快捷控件。
- 顶栏只保留 Molis Work 品牌和系统设置，不显示 Project 名称、切换、项目设置、待决定或同步状态。
- 在左侧 Goal Navigator 上方增加 Project 层，集中显示当前 Project、切换项目、项目设置、待决定和同步状态；项目设置内继续提供工作规则和工作规划。
- 从 Project 设置返回当前 Project 的 Goal Tree，不要求先回到「所有项目」。
- Project 管理和规划方法不出现在系统设置导航中；已有专用页面与能力继续保留。
- 密度偏好作为当前设备的纯展示状态保存在 localStorage，并在首次绘制前恢复，避免模式闪动。
- 紧凑模式仅在大于 760px 的非决定中心 Goal 工作台中生效。
- 紧凑化 Goal 导航的分组节奏、行高、缩进、状态标签和工具区留白；状态文字保留，但减少胶囊感和横向占用。
- 紧凑化 Goal 正文的内边距、字号层级、标签导航、段落和分区间距，使其成为连续的高密度文档而不是仅轻微缩小留白。
- 中英文界面都显示正确的设置文案和选中状态。

## 非目标

- 不改变「当前 / 上下文 / 进展 / 关系 / 记录」五个 Goal 详情标签和信息架构。
- 不改变 Runtime/TUI、决定中心、设置页自身和 760px 及以下的布局密度。
- 不新增数据库字段、API、Goal 状态、项目级偏好或跨设备同步。
- 不把字号压缩到影响中英文可读性，不隐藏 Goal 状态文字。
- 不删除 Project 管理、个人规划方法库或现有 Project 工作规则/规划能力；只调整入口归属。
- 不覆盖工作区内已有的无关未提交文件。

## 方案与关键决策

### 空间主张

- **主路径：** 快速扫描 Goal 导航 → 选中 Goal → 阅读标题、结果和下一步 → 进入其他详情标签。系统设置和 Project 设置是两条清楚分开的辅助路径。
- **分组：** Goal 分组标题与其内容保持近距离；Goal 标题、结果、标签导航作为一个紧凑的文档头；主要段落仍用分隔线和间距区分。
- **层级：** Goal 标题与「下一步」仍是主层级；状态、数量、辅助说明保持次要。
- **密度：** 主要通过减少垂直留白、缩短行高、压缩缩进和弱化装饰提高信息量；正文主体保持可读，操作仍保留可用命中区域。Compact 应在相同宽屏首屏中比 Standard 多呈现至少约 30% 的 Goal 行，并明显增加正文分区可见量。
- **适应：** 小于等于 760px 时无条件回到标准密度；设置、决定中心和 Runtime 不响应紧凑样式。

### 展示状态契约

- 密度值只接受 standard 或 compact，无效或缺失值回退为 standard。
- HTML 根节点用 data-density 暴露当前偏好；选项用 aria-pressed 表达状态。
- 设置页内点击选项后即时更新；同源其他页签通过 storage 事件同步。
- 首屏启动脚本在 CSS 生效前恢复偏好，避免界面从标准闪到紧凑。

### 设置入口契约

- 工作台顶栏右侧只出现一个齿轮，语义和目标一致：始终打开系统设置的「界面与语言」。
- 当前 Project 的名称、切换与设置入口都位于 Goal Navigator 上方的 Project 层；Project 设置使用文字入口，不再制造第二个齿轮。
- 系统设置可以携带来源 Project 上下文；返回动作回到该 Project，否则回到项目列表。
- Project 设置侧栏只显示当前 Project 的工作规则和工作规划；返回动作回到该 Project Goal Tree。
- `/settings` 默认进入「界面与语言」，不再默认进入项目管理。

## 模块与文件边界

- src/web/visual-foundation.ts：密度类型、存储键、启动/交互脚本和只限桌面 Goal 工作台的紧凑样式。
- src/web/render.ts：系统/Project 设置导航、顶栏入口、「界面与语言」页面和中英文展示文案；不新增服务端写入逻辑。
- src/web/server.ts：系统设置默认路由与来源 Project 上下文解析，仍复用现有设置页渲染。
- tests/visual-foundation.test.ts：密度启动、持久化、范围隔离和窄屏回退的定向证据。
- tests/web.test.ts：「外观」设置路由、导航和控件渲染证据。
- DESIGN.md：记录标准/紧凑密度是与主题并列的本地展示偏好及其适用边界。

## 验收标准

1. 顶栏只保留品牌和一个系统齿轮；系统设置导航只有「界面与语言」「AI 与执行工具」「诊断」。
2. Goal Navigator 上方显示当前 Project 层，包含切换项目、项目设置、待决定和同步状态；项目设置直接进入当前 Project 的工作规则，并可在同一 Project 设置导航进入工作规划、返回 Goal Tree。
3. 用户可在「界面与语言」选择中文/English、浅色/深色/跟随系统、标准/紧凑；状态可识别，刷新后保持。
4. 紧凑模式在宽屏 Goal 工作台中形成明显不同的排版并提高首屏信息量，但 Goal 标题、状态、下一步和五个详情标签仍清楚。
5. 标准模式的现有样式不变；紧凑模式不改变 Runtime/TUI、决定中心、设置页内容密度或 760px 及以下布局。
6. 浅色、深色主题下的选中状态、分隔线、正文和状态文字均可读；键盘焦点保留。
7. 设置重组和密度偏好不改变 Molis Work 数据库、Goal 功能、Runtime 绑定和实时刷新状态。

## 假设与已确认决定

- 标准模式是新安装和无有效偏好时的默认值。
- 紧凑模式是用户级的当前设备偏好，不是项目设置。
- 现有五标签 Goal 详情信息架构保留。
- Runtime/TUI、决定中心、设置页和窄屏不跟随紧凑密度。
- 系统设置与 Project 设置不再共享一个含混的入口；Project 管理能力保留但不属于系统齿轮导航。
- Project 是 Goal Navigator 的上一级上下文，不属于应用顶栏；顶栏不并列展示两个设置入口。
