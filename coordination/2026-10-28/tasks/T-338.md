## 1. 背景

来源：T-225（#1639）的【验证 T-225】6538459045 与【问统筹 T-225】6538551545、统筹答 6538587997（用户 2026-10-31 同意另开单）。

现象：设备 B 本机跑 `tests/interaction-no-crosstalk.e2e.test.ts` 整份文件 3/4，失败的是第三个用例（“a reference question in one project finds and keeps only that project's objects”，约 :298），卡在约 :350 的 `waitFor("window.__sent.some(one => one.url.includes('/sessions/<path>'))", 10_000)`——等 `window.__sent` 里出现带新 session 路径的请求，10 秒超时；框架诊断当时 Coding 是 ready。干净基线 `19106b35d` 上同一文件、同输入、同时限单次也是 3/4、同一处。CI 上这份文件过（#1636 的 Full 报告记过同名文件在 `question_drafts` PATCH 处等待首败、CI retry1 后 4/4，另一候选、另一前置等待，只当线索）。

后面没跑到的断言（这些要保留）：伪造跨项目 answer 被拒（`status` 400、`code` `agent.answer_invalid`）、`runtimeFiles` 前后相等（磁盘无写）、`heard` 里没有 round 听到。

读代码得到的线索（只是线索，没验证）：`__sent` 由 `enter()` 约 :99-103 里装的 fetch 包装器写，**只记 `body` 是字符串的请求**，且 `if (window.__sent) return` 只装一次；用例里 `await enter(other)` 之后是 `ask()` 新开 session，再选引用、再等 `__sent` 里出现 `/sessions/<id>`（多半是选择后的草稿 PATCH，带防抖）。可能原因至少有：①草稿 PATCH 根本没发（选择没触发保存、或保存被别的状态吃掉）；②发了，但在包装器之外（页面重载后 `window.__sent` 已被换新，包装器没重装）；③发了、包装器记了，但 URL 形态与 `includes('/sessions/' + encodeURIComponent(id))` 对不上；④设备 B 的机器负载下防抖＋模型夹具比 10 秒慢。
