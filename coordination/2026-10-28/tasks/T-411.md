## 目标与证据

让生成插件沿现有 **input/form → submit query → 当前结果** 的公开表达完成真实查询：保留所有合法文本（包括 LF、Unicode、空串），提交当前值，显示对象完整结果并保留输入。无需增加读取组件、跨表单草稿状态或新 UI 字段。

当前冻结 counter 合同的输入是唯一必填 `text:string`，description 精确为 **“要统计的文本”**，无 maxLength/minLength；query 输出必填且仅 `characters/utf8_bytes/lines` 三个非负整数，effects 为空。

已核事实：

- required filter 空值被 typedValue→undefined 视为未填；本单不扩改 read/filter 路径。
- submit 已允许 query，但普通 HTML required 拦空串，未指输出路径的对象回执不显示，成功后还复位表单。
- 当前 textarea 关键词不包含“文本/text”。上述真实 text 描述会选单行控件，不能忠实接收 LF；这也是必须修正的产品行为，不能只补空串与输出。
- 原 W4 最近一次真实 G7 已越过 ready，G1–G6 通过；原设计把 editor 与 result 分成互不共享的 form，首例第3步失败、后三例未执行。产品补能力不会把这份旧设计自动改绿。

证据：`W4-COUNTER-UI-CAPABILITY-GAP.md`、`W4-COUNTER-G7-DIAGNOSIS.md`、`W4-COUNTER-PROJECT-ROUTE-RESULT.md` 和 `/tmp/codex-w6-closeout/w4-live-counter-project-route-fixed/`。原失败与真实来源保留。

## 范围、行为与取舍

只补现有 query submit 通路，不新增操作、schema 属性、Manifest/UI 字段、outputPath 根 token、跨组件 form 来源或恢复框架；不改变 text.count 的 kind、输入/输出约束、effects 或独立完整对象 oracle。

1. **存在与非空分开。** required 表示必须传键；当 string 合同允许空串时，用户清空后应派出 `{text:''}`，不能把它省略。真正 minLength/enum/pattern/format 等约束继续有效。不能只取消 HTML required，却在收值时仍按 DOM required 删除空值。只修 query 需要的语义，不让 optional filter 的“全部”变成空串、不改 command 原规则。
2. **真实多行文本。** 沿现有通用控件语义识别文本/正文/内容字段；本份 description=“要统计的文本”、无 maxLength 的 query 字段必须使用真实 textarea，保留一个 LF。不得依赖改 schema 描述/长度来诱导控件，也不能把任意 id/title/name 或带枚举/日期/URL 等明确语义的字段都改为多行。无需新 UI 配置位，按既有字段/schema 描述与语义优先级判断。
3. **完整 query 对象可见。** 未指定 outputPath 时，将 query 回执交既有对象 renderer 展示所有字段；明确 outputPath 仍按其原义显示指定值。复用指标卡，不把 JSON 字符串当用户界面，不新增字段、不只展示其中一项。command 沿既有显式显示/回执规则。
4. **保留输入、替换结果。** query 成功后当前文本仍在，下一次统计替换当前结果；不累积历史，不因显示结果而写存储。失败保留输入并允许再提交；等待中编辑的新草稿、换版和销毁仍按现有生命周期守护处理。

当前合法组件 binding 不变：`input` 部件的 `submit:{operationId:'text.count',input:{text:{source:'form',field:'text'}}}`。无需再建一个读自己筛选框的 result 卡片。具体新设计仍由后续公开 revise 产生，不能手改原答卷来伪造来源。

## 验收

### RAC-2924：query required string 的空串与 presence

- 用原 string 合同的真实输入控件提交空串，经公开 resolvePluginComponentCall/实际 Host binding 解析后核有自有 text 键且完整 `{text:''}`，不是 `{}`、空格、缺字段或另一个 literal 入口。不能只检查 callback 的 payload.form 或0/0/1结果，因为原 operation 对缺字段也退为空串。
- 生产查询返回完整 `{characters:0,utf8_bytes:0,lines:1}`；UI 三项可见，不能只检查成功反馈。
- 对照真正非空约束仍拒绝；required 的存在含义不被改为 optional，冻结 schema/effects 不变。

### RAC-2925：完整对象输出与重复查询

- 同一 query 表单经真实输入/提交，完整对象由既有 renderer 展示，三项字段和值分别可审；不是只显示 characters、JSON 字符串或成功标签。
- 原固定输入 `一行` + 一个 LF + `line` 的完整调用结果严格为 `{characters:7,utf8_bytes:11,lines:2}`；再输入 `A🙂界` 为 `{characters:3,utf8_bytes:8,lines:1}`，当前结果被替换，原输入保留，无历史追加。
- 既有明确 outputPath/primitive 和 command 显示策略保持有效，不自动摊出未请求展示的 command 内部回执。

### RAC-2926：精确真实描述的多行控件

- 回归 fixture 必须直接使用 `text.description='要统计的文本'`、无 maxLength 的当前真实 schema，不靠改成“内容”或新增长度/format 通过测试。
- 用户通过真实 textarea 输入含 LF 的字符串；实际派出文本逐字符含 LF，不能从单行 input 经替换/转义补回。统计 7/11/2 的值同时证明换行未丢。
- 对照普通 id/title/name 字段仍是单行；枚举与现有明确日期/URL控件沿原选择，并至少让日期/URL反例的 description 同样含“文本”，证明格式优先级不会被关键词抢占。只改当前语义所需，不把所有 string 默认成 textarea。

### RAC-2927：生命周期、原规则及模型说明同步

- query 失败保输入；pending 时编辑成新草稿后，旧回执不清新输入、不关新面板或覆盖更新版结果；换版/销毁后的 stale 回包不写当前 DOM/反馈。沿现有 draft/receipt 场景验证。
- optional filter 的空选择仍省略字段；command 的成功复位、prefill、失败保输入等原规则完整回归，不为本 query 修复放宽原断言。
- 必要 Skill/prompt 与真实能力一致，写可见 UI 期望而不是 JSON 字符串或不存在的跨 form 来源；`studio:replay` 离线与隔离 smoke 均完成。四项编号须在相应测试名或注释中登记。
