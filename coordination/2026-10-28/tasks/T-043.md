## 1. 背景

BL-386 的前提（S9：Goals 上 Plugin Runtime 监督器）已经成立：`plugins/native/goals/src/registration.ts` 登记了 `project_runtime` 和 Home 的 `runtime`，`plugins/native/goals/src/plugin.ts:144-145` 已经用 `goalsRoutes(...)` 把 31 条 Manifest 声明的路由（`plugins/native/goals/src/manifest.ts:39-62`，都没有 `permission`）挂在 Runtime 上，浏览器可以打 `/projects/<id>/api/plugins/io.molis.work.goals/<路径>`，经 `apps/local-host/src/project-plugin-http.ts:61-63` 的 `dispatchRuntimePluginRoute` 分发。

可是宿主还留着一条过渡改写：`apps/local-host/src/web-request.ts:233-242` 的 `goals` 条目，把 `/api/<路径>` 直接交给通用分发函数 `dispatchDeclaredPluginRoutes`（`apps/local-host/src/plugin-route-operations.ts:154-210`），用 `goalActions`（`bindGoalsWebActions`，`:146`）当调用者，授权传空数组。它上面的注释「Goals has no Runtime installation yet」已经过时。来源：`specs/BACKLOG.md:164`（BL-386）、`MISC.md` 的 T-020 【方案】一行（2026-10-28）。

这条不是「把旧地址换个名字」。插件前缀那边现在的挂载和改写**不等价**，直接把客户端指过去会丢行为，有四处差异（都在第 5 节逐个定）：

1. `goal_path`：改写传 `routePrefix: () => options.routePrefix`，创建 Goal 的回答带 `goal_path: /projects/<id>/goals/<goal>`（`plugins/native/goals/src/http/create.ts:64`）；Runtime 挂载传 `routePrefix: () => ""`（`plugin.ts:145`），回答变成 `/goals/<goal>`，页面跳转（`plugins/native/goals/src/dialogs-client.ts:149`）会跳错。
2. 幂等键：改写传 `idempotencyKey: () => requestHeader(request, "x-molis-work-idempotency-key")`；Runtime 挂载传 `() => undefined`，而 `PluginRouteRequest` 没有请求头。读 `context.idempotencyHeader` 的有五处（`http/create.ts:59`、`http/decisions.ts:16`、`http/event-decisions.ts:22`、`http/events.ts:66`、`http/relations.ts:41`）。其中 `relations.ts:41` 先取头再取 body，而 `plugins/native/goals/src/relation-client.ts:112,155` 只用头（`key:`）、body 里没有 `idempotency_key`：改指过去后关系加上重放会各生成一个新键，同一次点击重试会建两条。
3. 用户操作出处：改写的 `goalActions` 带 `entryUserAction("web", 项目, webEntryMessage(request))`（`apps/local-host/src/goal-callers.ts:17-19`）：消息名取自请求头里的幂等键，「确认整份提案」的控件另发 `x-molis-work-whole-confirmation: 1`（`apps/local-host/src/entry-user-action.ts:10,36`），出处里就带 `whole_confirmation_prompted`。Runtime 路由走 `projectRouteControl`（`apps/local-host/src/plugin-actions-client.ts:43-45`），出处写死成每个请求一个随机消息名、不带确认标记。后果：页面「确认整份」走插件前缀时，`goals.tree.decide` 读不到确认，在 `plugins/native/goals/src/goal-tree-decision-plan.ts:45-50` 被 `whole_confirmation_ambiguous` 拒（我读源码得出，没跑；`plugins/native/goals/src/proposal-client.ts:66-76` 的 `confirm_all_pending` 路径）。
4. 页面视图缓存：改写的 `changed: () => webViewCache.delete(options.databasePath)`（`web-request.ts:241`）在每次 Goals 写之后清项目页缓存；Runtime 挂载传 `changed: () => undefined`。缓存按日志游标加指纹取值（`cachedMolisWorkWebView`，`web-request.ts:161`），是否还需要这一清，我没有实测，第 5 节要求先写测试看。

## 2. 目标

1. 旧地址 `/projects/<id>/api/<Manifest 路由路径>` 不再被宿主认：对 `GOALS_ROUTES` 里每条（`manifest.ts:39-62`）的方法和路径答 404，`dispatchDeclaredPluginRoutes` 和 `DeclaredPluginRoutes` 从 `plugin-route-operations.ts` 和 `apps/local-host/src/index.ts:26` 里删掉（`RAC-1510`）。
2. 页面、Goals 自己的客户端、成果库的「作为 Goal 的输入」都改打 `/api/plugins/io.molis.work.goals/<路径>`，创建、关系、提案决定、事件写、交付物、输入、项目说明、策略这些写，在插件前缀下行为与改写时一致：创建回答能跳到 Goal 页，同一个幂等键重放得到同一个结果，「确认整份」仍然被认（`RAC-1511`、`RAC-1512`）。
3. 在插件前缀下写完 Goal，下一次读项目页就看到它（`RAC-1513`）。
4. `scripts/check-package-boundaries.mjs` 的 goals-command-owner 规则认新的挂载处（`plugin.ts`），并且多一条：宿主 `apps/local-host/src/` 里不得再出现 `goalsRoutes(` 和 `dispatchDeclaredPluginRoutes`（`RAC-1514`）。
