# 「这条规则在别处改过」定样（第 05 批 N14）

状态：待用户选方案（2026-11-06）。样放在未合并的分支上，还没有决策记录，也没有产品代码。用户选定后，把选定方案连同理由、否掉了哪些写进原需求的决策记录，删掉没选中的方案，再开定样 PR。

场景：你在判断规则编辑器或 Feed 的规则页改了内容，提交时这条规则已经被别处改过（另一个窗口、助理或别的调用方）。N14 把这些提交改成必须带版本检查之后，这件事会更常被发现，所以要给它一个样子。

## 怎么打开

在仓库根目录运行，然后打开 <http://127.0.0.1:4431/rule-stale-reload/>：

```sh
pnpm build
node docs/design/_catalog/export.mjs
node docs/design/rule-stale-reload/export.mjs
python3 -m http.server 4431 --bind 127.0.0.1 --directory docs/design
```

第二、三步生成产品样式和产品标记（`dist/`，不入库）。顶上两行斜纹条是原型控制，不是产品界面：选方案、页面、状态、数据量（常规、最挤、最空），切中英文和深浅色；第二行写这个状态里什么是模拟的。

某个状态可以从地址直接打开，例如 `#s=A&h=editor&st=conflict&d=plain&l=zh&t=light`。

**直接试一遍：** 方案选 A、状态选「正常编辑」，在「判断说明」里打几个字。280 毫秒后自动保存碰到别处的改动，光标不动，底部出现提示。点「载入最新版」，再点「放回」。

- **画面是什么做的：** 编辑器和 Feed 的标记由产品自己的 `renderFunctionsWorkbench`、`renderFeedWorkbench` 生成，样式是产品样式表，英文来自产品词典。Feed 上方的标签条省略了，与这件事无关。
- **什么是模拟的：** 规则内容、别处的改动、保存、断网和时长。不连任何服务，不碰任何 Home。

## 这一屏要回答什么

- **用户此刻要知道：** 我写的没丢；这条规则变了；这次没存上。
- **最想做的：** 接着把事做完，别把别处的改动盖掉，也别丢自己的。
- **主焦点：** 提示里那一个主按钮。这时「下一步」从主按钮退成次按钮，一屏只留一个主操作。
- **不丢内容：** 表单不动、不清空，自动保存暂停，可以继续打字。
- **不出现的词：** 版本字段名、409、错误码、「冲突」「过期」「刷新」都不出现。

## 三个方案

| | A 就地接住（推荐） | B 对比后决定 | C 拦下来问 |
| --- | --- | --- | --- |
| 发生时 | 底部提示，一个按钮「载入最新版」 | 同样的提示，按钮是「对比并决定」 | 打字时只在状态行说「未保存 · 别处有新版 · 处理」；点发布、试跑或「处理」才弹对话框 |
| 解决方式 | 最新版进表单。两边都改的字段，你写的摆在该字段正下方，点「放回」取回，放回后可「换回」。只有你改的字段留着 | 侧板里逐字段并排两个版本。只有一方改的已预选；两边都改的必须选一个，选完才能继续 | 对话框列出哪些字段不同，勾选「把我写的另存成一条新规则」（默认勾上），再载入。Feed 没有列表，改成「先复制我写的」 |
| 要做几个决定 | 零到若干；不处理也不丢 | 每个两边都改的字段一个，必须答完 | 一次定全部 |
| 能否撤回 | 每个字段可来回换 | 合好后可撤销 | 载入后想取回，要去打开另存的规则 |
| 打断 | 不抢焦点，不挪正在打字的框 | 同 A，但侧板会盖住半屏（手机上全屏） | 最重，模态。打字时靠状态行那一小句，容易错过 |
| 取舍 | 改完才看得见差别，且看的是真实表单；字段分散在不同步骤时要靠提示和步骤上的小点找 | 改之前就看全，最精确。但对一条小规则偏重，Feed 只有两个字段时尤其明显 | 组件板不用新增，也最接近 Dataset 现有做法。但多出一条「xx（我写的）」要收拾，而且改不了 Dataset 的根本问题：要在没看到内容时就做决定 |
| 组件板新增 | `mw-alert` 动作槽、「你写的」行、步骤小点 | `mw-alert` 动作槽、并排对比行 | 无 |

**推荐 A。** 三条依据：

1. **编辑器是自动保存的。** 代码里没有「保存」这一下，碰到别处改动的时刻是用户正在打字后的 280 毫秒（`client-records.ts:190`）。这时弹窗（C）或开侧板（B）都会打断。A 的提示长在底部已有的反馈位，底栏向上长，正在打字的框一动不动。
2. **载入不丢东西，就不用先问、先比。** Dataset 现在的写法是「请复制需要保留的内容，再重新读取」，并弹确认，因为读取会丢输入。A 让这一步变成安全的，确认和事先对比都省了，差别就地摆在真实字段下面。
3. **两种宿主都成立。** 编辑器和 Feed 用同一个部件，只是落在各自已有的反馈位。B 的侧板放到只有两个字段的 Feed 上偏重；C 在 Feed 上没有另存的去处，只能退回剪贴板。

## 十个状态

A、B 的提示相同，差别在载入之后；C 把这些话放进对话框。

| 状态 | A 的样子 | 依据 |
| --- | --- | --- |
| 正常编辑 | 和今天一样，状态行走「有更改 → 正在保存 → 已保存」 | |
| 发生冲突 | 琥珀色提示「这条规则在别处改过 / 你写的都还在，还没存」＋「载入最新版」。焦点留在输入框 | 要处理的事用琥珀色，不用红（DESIGN「Reading load」） |
| 未保存内容还在 | 继续打字、换步骤都行。点发布或试跑：提示轻跳一下，焦点到「载入最新版」。要离开：确认一次「你写的还没存」，默认「留在这里」 | 覆盖类动作至少确认一次（开发流程第 5 节） |
| 已载入最新版 | 绿色提示，带一个落定的对勾；换了内容的字段淡淡亮一下；键盘焦点到第一个「放回」。别处改到的、不在当前步骤的字段，步骤上有小点 | 完成时刻才用回弹；用现有的 `[data-craft-new]` |
| 重新载入失败 | 「最新版还没载入 / 连接好像断了。你写的都还在，连上后再试一次」＋「再试一次」。同样琥珀色 | 坏消息说得平和，给下一步 |
| 已被删除 | 编辑器：「存成新规则」或「不要了」。Feed：「重新预览」，草稿会再建好 | Feed 里用户写的话才是主角，草稿只是载体 |
| 连续第二次冲突 | 分量不升级，只说「可能还有人在改它」，多一条出路「存成新规则」，以免一直撞 | 不制造焦虑 |
| 没有未保存内容 | 没什么要保护，直接换成最新版，并拦下这次发布：「发布前看一眼」＋「看看改了什么」。再点一次就发布 | 不让人发布一个没看过的版本 |
| 别处只试跑过（补充） | 什么都不显示，自动接上新版本再存 | 见下面「现状」第 2 条 |
| 已在别处发布（补充） | 「发布后不能再改」＋「存成新规则」或「查看 v1」 | 见下面「现状」第 4 条 |

重新载入不到 250 毫秒时不出转圈，慢了按钮里出现小转圈。

## 请用户一并确认的两个判断

1. **「只有你改的字段留着」。** 载入时不是整张表换成最新版：只有你改过、别处没动的字段（样本里的名称）保留并存上，只有两边都改的才摆出来。好处是决定最少。代价是这一步有一点合并的意思，存下去的可能是两边都没见过的组合；提示里会写明「你改的名称留着」。没有采用「全自动合并、只有撞车才说话」，因为判断规则是一段连贯的话，不替人做这个决定。
2. **不提供一键「用我的覆盖」。** 覆盖要先看过最新版：载入后点「放回」，效果相同，且可以换回。

## 以后能否复用

这个状态是通用的，Dataset 等其他插件可以用，这里不替它们改。

1. **部件：** 动作槽和「你写的」行进组件板后，任何插件都能用。
2. **做法：** 四步写进 DESIGN：暂停自动保存、留住输入、载入不丢、就地放回；再加一条「只是元数据变了就不打扰」。
3. **脚本：** 等第二个插件真要接时，再看要不要在 SDK 里沉淀一个帮手。现在两种宿主的脚本写法不同（工作台是内嵌脚本，插件是编译的浏览器模块），先不抽。

## 现状（实现时要动的）

1. 规则被删时，编辑器会关掉并丢掉输入：`client-records.ts:128` 的 `loadList({ preserveForm: true })` 找不到规则就 `closeEditor()`。
2. 试跑和样例也会改 `updated_at`（`store.ts` 的 `savePreview`、`addSample`），所以别处只试跑一次，也会让这边的保存失败，而内容其实没变。样里这种情况不打扰：重读后比较用户能看见的字段，相同就接上新版本重存。
3. 记录上没有「谁改的」，只有 `updated_at`。样里只说「别处」，不猜是谁。
4. 在别处发布后再保存，报的是 `published_immutable`，不是冲突（`store.ts:102`）；在别处发布后再点发布，会直接按成功返回（`store.ts` 的发布分支）。两者都要归到这个状态或明确放行。
5. Feed 的旧版本存在会话存储里（`rule-authoring.ts:16`），载入最新版必须同时更新它，否则下一次还会失败。Feed 载入后要清掉预览结果，因为启用前要求预览过当前内容（`rule-authoring.ts:87`）。
6. 编辑器的输入只在内存里。冲突期间要写一份到会话存储，刷新页面才不丢；Feed 已经这样做了。

## 走查结果

- **宽度与语言：** 1440、1024、390，中英文，每个状态三种数据量，由 [`shots.mjs`](shots.mjs) 检查页面不横向滚动、部件不出窗口、按钮字不被截。
- **深浅色：** 各方案的关键状态都出了图。
- **键盘：** 全程原生按钮和 `dialog`。Tab 走得通，Esc 关对话框和侧板。载入后焦点到第一个「放回」，放回后焦点留在同一行的「换回」，关掉对话框后焦点回到主按钮。
- **减少动态效果：** 提示、「你写的」行、对勾和按钮的动效都有退路，状态变化直接到位，信息不靠动效传达。
- **截图：** 不入库（[仓库卫生](../../system/REPOSITORY-HYGIENE.md)）。重新生成：`node docs/design/rule-stale-reload/shots.mjs <目录> --all`。

## 原型没做的

- 对比用的是逐行比一个集合，只为示意；产品里用平台的 `compareTexts`（`packages/plugin-sdk/src/text-diff.ts`）。
- 「存成新规则」只改了提示和状态，没有真的多一行；放弃后的列表是两条示例。
- 编辑器只画了选择结果这一种判断，发布、试跑、绑定页面动作没有展开。
- 手机上底部提示占去一部分高度，所以提示在时收起上一步、下一步，靠顶部步骤切换。这一条实现时要在真机上再看。
