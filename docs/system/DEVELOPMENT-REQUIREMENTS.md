# 包的开发要求

每个工作区包的 README 都有一节 `## 开发要求`。它回答改这个包之前必须知道的事：管什么、不管什么、从哪里进、能依赖谁、哪些规矩不能破、改完跑什么、还要读什么。仓库级约束见 [`AGENTS.md`](../../AGENTS.md)，分层规则见 [包边界规则](PACKAGE-BOUNDARIES.md)，包清单与成熟度见 [`docs/SSOT-MATRIX.md`](../SSOT-MATRIX.md)。

## 一节里有什么

| 行 | 写什么 | 门禁怎么查 |
| --- | --- | --- |
| 负责 | 这个包唯一拥有的事实或职责，一句话 | 必须有 |
| 不负责 | 最容易被误放进来的东西 | 必须有 |
| 公开入口 | 包名、`src/index.ts` 经 `dist` 导出、对应合同 | 必须写出包名 |
| 依赖 | 工作区依赖逐个列出；组合根写“组合根” | 与 `package.json` 一致：不能多列，也不能漏列（组合根除外） |
| 不变量 | 改动必须保持的规矩，每条是可以被测试或复查推翻的句子 | 至少一条 |
| 改动后必跑 | 一条能直接执行的 `node scripts/run-tests.mjs …` 命令 | 列出的测试文件都存在 |
| 界面改动加跑 | 可选，浏览器用例 | 列出的文件都存在 |
| 相关手册 | 该读的手册、Skill、spec | 链接都存在 |

门禁在 `scripts/package-dev-requirements.mjs`，由 `pnpm boundary:check`（`pnpm workspace:verify` 与 CI 都会跑）调用。

## 什么时候改这一节

- 新建包：先写这一节，再写代码。负责与不负责写不出来，说明边界还没想清楚。
- 加或删工作区依赖：同时改「依赖」，门禁会报出差异。
- 修一个缺陷、发现一条之前没写下的规矩：把它加进「不变量」，并把守住它的测试加进「改动后必跑」。
- 职责迁到别的包：两个包的「负责」「不负责」一起改，不能让同一事实在两处都写“负责”。
- 测试改名或删除：同步这里，门禁会报出不存在的文件。

## 按层的通用要求

- **App 与组合根**（`apps/*`）：只装配与做 IO，不写业务规则；不直接写业务数据库。一个 Home 只有一个执行进程，其他入口转发给它。
- **平台包**（`packages/*`、`server`）：只依赖合同与更低层平台包；不拥有 Goal、Artifact、Feed、Session 等业务事实。
- **Module**（`modules/*`）：自己的事实只由自己写；跨 Module 只走公开合同，不导入另一个 Module 的实现或 Store；读取已存历史的结果合同接受历史取值。
- **横向服务**（`horizontal/*`）：提供机制（运行时、连接、监听、叫醒），不决定业务状态。模型调用只经 `horizontal/agent-host`。
- **插件**（`plugins/*`）：按 [插件开发 Skill](../../skills/molis-plugin-dev/SKILL.md) 写；能力注册一次进共同动作目录；等模型或外部服务的动作声明 `scheduling: "concurrent"`；被取消或撤权的调用不写任何记录。调模型或跑 Agent 时按 [Prologue AI Skill](../../skills/molis-prologue-ai/SKILL.md)。
- **工具**（`tooling/*`）：只依赖合同与 plugin-runtime；不启动插件、不自动发布。

## 写法

- 写事实和规矩，不写愿望；还没做到的写在「不变量」之外，或写成“还没有……，不要假设……”。
- 不重抄手册：详细机制链接到 `docs/modules/*.md`、`docs/horizontal/*.md`、`docs/platform/*.md` 或 spec。
- 测试选能在几分钟内跑完、直接守住上面不变量的那几份；全量回归另跑。
