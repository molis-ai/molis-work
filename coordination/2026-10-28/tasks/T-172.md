## 1. 背景

- 三处关闭，三份规则：

  | 处 | 谁决定「要停」 | 什么时候读 Runtime 的记录 | 读不到 |
  | --- | --- | --- | --- |
  | Host（`installed-plugin-host.ts:181-186`） | Supervisor 的镜像为 `running` | 停之前现读，在 `try` 里 | 记一条失败，仍然撤销 |
  | 项目（`project-plugins.ts:92-102`） | 同上 | 同上 | 同上 |
  | Home（`home-plugins.ts:167-172`） | 循环开头 `list()` 的快照里 `state === "running"` | 不再读 | 不会发生；但停被 Runtime 拒绝时记一条失败 |

- 为什么要现读：Supervisor 看不见 Runtime 一侧的事。记录在 Runtime 里崩了（`reportCrash`），或被人带 `preserve_enabled` 停成了 `installed`，Supervisor 仍写 `running`；关闭再去停，Runtime 抛 `state_invalid`（`index.ts:502-505`）。T-035 给 Host 加了现读，T-037 给项目加了现读并把读放进 `try`。
- Home 为什么不一样：Home 的循环按 Runtime 的记录走，不看 Supervisor 的镜像（`list()` 按 `install_id` 排，`repository.ts:24`；`install_id` 是插件 id 与签名的哈希，`runtime-rules.ts:46`，所以谁先谁后读出来、不预设）。它信开头的快照。轮到某个插件时，前面插件的停止钩子可能已经把它弄崩或弄停；这时去停它就是一次被拒绝的停止，整个关闭失败，后面的插件照样停、照样撤销，但这次关闭的结果是一个 `AggregateError`。
- 注释：Host 的 `:183` 只说「崩溃」；`:184` 实际也不停 `installed`（被别处用 `preserve_enabled` 停过的）。合成一个函数以后，这段话写在 `closePlugin` 的文档注释里，写全，一处。
- 撤销为什么在停止之后：`Supervisor.revoke`（`supervisor.ts:286-295`）对仍是 `running` 的记录会自己发一次不带 `preserve_enabled` 的 `runtime.stop`，记成 `disabled`，下次启动不再运行。三处的注释（项目那份最全）都讲这一点；合成后写在 `closePlugin` 的文档注释里。
- 能照着写的先例：
  - Host 的三个用例 `RAC-1196`～`RAC-1199`（`tests/installed-plugin-host.test.ts:972`、`:996`、`:1013`、`:1033`）：崩了的、被停成 `installed` 的、正常运行的（`runtime.stop` 的探针写法在 `:1018-1020`）、读不到记录的；
  - 项目的三个用例 `RAC-1453`～`RAC-1455`（`tests/project-plugin-startup.test.ts:128`、`:183`、`:216`）；
  - Home 的关闭用例没有这类的：`tests/home-plugin-model-lifecycle.test.ts:126-150`（W3-06-F-06）改 `behavior.stop` 来卡住一个插件的停止，注释写着「installations stop in install_id order」（`:139`）；`tests/home-plugin-private-store.test.ts:127-140`（W3-06-F-04）关闭后在同一个 Home 上重开，断言记录仍是 `running`。

1. **新文件 `apps/local-host/src/plugin-platform-close.ts`**，原样（28 行，双引号，同目录的 `plugin-platform.ts` 的写法）：

   ```ts
   import type { PluginPlatform } from "./plugin-platform.js";

   /** The parts of a platform that closing it touches. */
   type ClosingPlatform = Pick<PluginPlatform, "runtime" | "supervisor">;

   /**
    * Closes one plugin of a platform that is closing. Closing a Home, a project or the Host is not switching a plugin off: it is stopped with its record
    * kept enabled (`preserve_enabled`), so the next start runs it, and then revoked (the supervisor's own revoke would stop it as disabled).
    *
    * Only a record the Runtime itself reports as running is stopped. The Supervisor does not see everything the Runtime records: a plugin it counts as
    * running may have crashed there, or been stopped with `preserve_enabled` by someone else (now `installed`). The Runtime refuses a shutdown stop of
    * either (`state_invalid`), as it does of a quarantined one, so those are left as they are, and still revoked.
    *
    * A failure to read or to stop is one entry of `failures`; the caller throws them together once every plugin has been closed.
    */
   export async function closePlugin(platform: ClosingPlatform, pluginId: string, installId: string | null, failures: unknown[]): Promise<void> {
     if (installId) {
       // The read is inside the try: a record the Runtime cannot give is one failure of this close, not the end of the loop.
       try { if (platform.runtime.get(installId).state === "running") await platform.runtime.stop(installId, { preserve_enabled: true }); } catch (error) { failures.push(error); }
     }
     platform.supervisor.revoke(pluginId);
   }

   /** The installation the Supervisor counts as running for the plugin; none when it counts it as anything else. */
   export function supervisedInstall(platform: ClosingPlatform, pluginId: string): string | null {
     const state = platform.supervisor.state(pluginId);
     return state?.status === "running" ? state.install_id : null;
   }
   ```

   说明：
   - `:17` 的 `if (installId) {`、`:19` 的 `try` 行、`:21` 的 `revoke` 是第 6 节变异要改的三处；

   import { join } from "node:path";
   import { DatabaseSync } from "node:sqlite";
   import test from "node:test";
   import { MolisWorkLocalHost, type HomePluginPlatform } from "@molis-ai/molis-work-app-local-host";
   import { homeProbe, serveHomeRuntime } from "./fixtures/home-runtime.js";

   type Probe = ReturnType<typeof homeProbe>;
   type Visit = { probe: Probe; install: string };

   /** The two probes' installations in the order the close visits them: `runtime.list()` is by install_id, a hash, so the order is read, never assumed. */
   function inCloseOrder(platform: HomePluginPlatform, probes: readonly [Probe, Probe]): [Visit, Visit] {
     const visits: Visit[] = [];
     for (const record of platform.runtime.list()) {
       const probe = probes.find(candidate => candidate.id === record.plugin_id);
       if (probe) visits.push({ probe, install: record.install_id });
     }
     assert.equal(visits.length, 2, "both probes are installed");
     return [visits[0]!, visits[1]!];
   }

   /** Every `runtime.stop` asked of the platform from now on, with its options; the returned function keeps the calls for the given installations. */
   function recordStops(platform: HomePluginPlatform) {
     const calls: Array<{ install: string; options: unknown }> = [];
     const stop = platform.runtime.stop.bind(platform.runtime);
     platform.runtime.stop = async (...args: Parameters<typeof stop>) => { calls.push({ install: args[0], options: args[1] }); return stop(...args); };
     return (...visits: Visit[]) => calls.filter(call => visits.some(visit => visit.install === call.install));
   }

   /** A stop that keeps the record enabled, as the close asks for. */
   const kept = (visit: Visit) => ({ install: visit.install, options: { preserve_enabled: true } });

   /** The state of each installation's record in the Runtime's table, read from the file after the close, as a restart would find it. */
   function recordedStates(home: string, ...visits: Visit[]) {
     const db = new DatabaseSync(join(home, "plugin-runtime", "plugin-runtime.db"), { readOnly: true });
     try {
       const rows = db.prepare("SELECT record_json FROM plugin_runtime_installs").all().map(row => JSON.parse((row as { record_json: string }).record_json) as { install_id: string; state: string });
       return visits.map(visit => rows.find(row => row.install_id === visit.install)?.state);
     } finally { db.close(); }
   }

       assert.ok(!platform.supervisor.enabledPluginIds().includes(probe.id), `${probe.id} is revoked`);
       assert.equal(platform.supervisor.state(probe.id)?.code, "plugin.revoked");
     }
   }

     assertRevoked(platform, first, second);

     } finally { await restarted.close(); }
   });

   test("RAC-1826 closing the Home leaves a plugin the Runtime already shows as crashed as it is, stops the other, and revokes both", { timeout: 60_000 }, async t => {
     const one = homeProbe("closeone"), two = homeProbe("closetwo");

   test("RAC-1827 closing the Home does not fail for a plugin that the stop hook of the one before it crashed", { timeout: 60_000 }, async t => {
