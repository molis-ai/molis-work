## 给人讲清楚

这是阶段 2 的毕业总验收：把个人日常使用的完整路径，在开发版的**网页端和 macOS 桌面端（WebKit）**实打实从头走通一遍。

具体走通三组真实个人闭环，并用「现行 v1 隔离真实规模造数基准」复测性能：
1. **个人空间完整闭环**：从空白空间默认只开「日程（Schedule）」与快捷入口一键开启开始，装入「个人事务与每日简报」场景包，实走个人助理、瘦身后的 Jelly（日历 + 极简随手记，已无 626 MB 语音包袱）、每日简报（融合个人空间事项与你授权过的项目摘要）、到点提醒系统通知跨分区直达，以及「个人空间 ↔ 项目」星型版本化推送（同时确认拒绝项目直推项目）。
2. **不装目标（Goals）插件的真实项目闭环**：新建项目装入「写代码」或「行业观察与写作」官方场景包，在不启用 Goals 的前提下实走项目指导、助理与助理团、Coding 交付、跨重启续批、子代理浮窗、直接找角色说话、主线与智能卡片、「在办」清单、多项交付要求逐项认可／退回返工与外部 MCP 连接；随后实走「添加 Goals → 使用 → 移除（数据保留）→ 再添加回读」。
3. **大规模流畅度与多语言多皮肤一致性**：因为 `106`～`112` 已将数据库直接拍平为全新 v1 结构（不兼容旧版 `0.1.x` 老库，且严禁碰真实 `~/.molis-work`），性能复测统一用**现行 v1 隔离真实规模造数基准**（自动灌入个人空间 + 多项目、数千条信息流／待办／日程／瘦身 Jelly 随手记与长代码会话，辅以正常文件导入和挂载只读目录），并实测**中 / 英 / 日（`zh`/`en`/`ja`）三语 × 4 套皮肤**切换后所有表面文字与样式一致。

原来同在这一批的对外发行事项（第二台 Mac 安装、签名公证、日志与诊断包、安装版升级演练、记录合同兼容起点）已移到发行批 [REL-5](rel-5.md#rel-5)。走查中若抓到跨模块缺陷，按所属模块拆独立小修复 PR 先合入，最后由本批验收收口 PR 在干净最新头上跑完通关证据（绝不攒成跨十几个模块的巨型缝合 PR）。需要你做的：只有整改中若出现新增界面差异，才先出轻量样稿给你确认。
