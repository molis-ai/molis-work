## 2. 架构决定

1. **助理是 Host 级系统模块**，不是某个插件页面：服务代码在 `apps/local-host/src/assistant/`，对外约定在 `packages/contracts/src/services/assistant.ts`，界面在 Workbench 底栏。插件通过约定贡献上下文、能力、方法与交互，不需要助理为某个插件写专属分支。
2. **一项“工作”（work）是助理的事实单位**：有自己的作用域、标题、Prologue 会话、授权方式、草稿、材料和成果关系。统一的助理身份 + 多项独立工作并存。存储在 Home 级 `assistant` 库（`openHomeSqliteDatabase`），只保存助理自己的事实与引用；会话内容、运行状态、TaskBoard 归 Prologue，业务结果归原模块。
3. **作用域是真实的**：个人工作 = Home 作用域（动作服务已有的 `scope: "home"`、`homeActionClient()`），项目工作 = 项目作用域。不虚构项目，不虚构目录。
4. **一般业务授权与代码目录授权分开**：
   - SDK 新增 `workspace: "app"`：没有授权根；只能用这条会话安装的包工具（应用自己的业务动作）和不依赖目录的系统工具（提问、待办、任务图、会话协同、子任务等，逐步开放）；文件、命令类工具一律不可用。原 `workspace: "none"` 的纯推理语义不变。
   - Agent Host 新增角色工作区方式 `business`，映射到 SDK `app`；原 `none`、`required` 不变。
5. **动作按效果授权**：读取（query/read）助理可直接调用；可撤回的写入在本工作的授权方式允许时直接执行，否则停在审查上等用户对具体参数确认；不可撤回的每次都要确认。审查沿用 Host 已有的 AgentReviewQueue（tool-operation）。
6. **可直接操作的建议**：助理通过应用工具 `propose-action` 生成“动作意图卡”——绑定真实能力的精确版本与提供方、目标、已准备参数、可调整项与缺失项、前置状态；卡片由助理服务持久化，点击由服务端按当时状态核对后经动作服务执行，带幂等键，结果回写卡片。模型不能靠文字改变能力定义。
7. **Coding 从底栏进入同一会话**：选中 Coding Agent 时，底栏发送走 Coding 插件自己的会话与运行路由；助理工作只保存对该会话的引用，两个入口看的是同一份运行事实。
8. **主动协助与记忆**先用确定性规则（条件、范围、例外、到期）决定能不能打扰，模型只在规则放行后判断价值；记忆复用 Prologue Memory，并补齐项目作用域的真实隔离（见第 4 节缺口）。

### 2.1 用户拍板（2026-09-28）

- **助理的默认授权**：本作用域内所有对 Agent 开放的能力默认可用（个人工作：个人范围；项目工作：该项目与个人范围）。读取直接用；写入在执行前把准确参数交给用户确认；不可撤回的每次确认。助理有自己的授权集合，与 Coding、外部 Agent 分开；用户可在设置里对助理单独关掉某项能力（`/api/assistant/capabilities`）。
- **Character／Prompt／Skill 统一经 Host 登记并纳入开发流程**，是 P13 的前提（spec 第 9.1 节、AC45）。

## 4. 已知缺口与待用户决定

- SDK Memory 只有 user/app/character/session 作用域，不能把项目标签当项目隔离。P8 需要在 SDK 增加真实的项目作用域或按项目分库，届时再定。
- 关闭应用后的持续执行：当前 Host 只在服务进程活着时运行。P10 会如实标注，不承诺超出环境的后台能力。
