# Goal Detail 结构重设计

## 背景与目标

用户明确反馈当前 Goal Detail “又臭又长”、区域之间不清晰，也不知道该怎么用。真实页面显示，整个工作台没有占满视口高度，终端下方留下大块空白；正文同时展开概览、目标说明、完成要求、进展和技术记录，用户只能靠长距离滚动寻找信息。

本 Work Item 要让 Goal Detail 在首屏完成三件事：看懂当前状态、知道下一步、理解这条 Goal 要解决什么。完成要求、进展与阻塞、完整记录通过明确导航按需查看，不再一次性铺成长文。

## 当前行为和问题证据

- 桌面端工作台和终端没有撑满视口高度，终端下方出现大块无意义留白。
- Goal Tree、Goal 正文和终端需要长期并排工作，不能靠默认收起终端掩盖正文布局问题。
- “现在需要做什么”之后继续完整展示目标说明、完成要求、进展和技术详情，页面长度取决于所有模块之和。
- 章节只有标题、图标和细分割线，当前所在区域及可执行入口不够醒目。
- 部分状态文案为了追求“口语化”变得冗长，例如“正在把目标说清楚”，降低了扫读效率。
- 待决定中必填理由依赖浏览器原生校验，缺失时看起来像保存按钮无响应。
- “查看进展”等概览主操作指向延迟载入内容里的锚点；首次点击时锚点尚不存在，现有脚本无法判断应先打开哪个工作区，因此按钮看起来没有反应。

## 范围

- Goal Detail 改为“概览 / 完成要求 / 进展与阻塞 / 完整记录”四个明确工作区，一次只展示一个。
- 概览保留当前状态、唯一主操作、阻塞、Goal 结果、原因和运转方式。
- 完成要求集中展示完成标准、子 Goal、范围与硬依赖。
- 进展与阻塞集中展示执行者、最近进展、完成依据、检查、开放风险和规则摘要。
- 完整记录保留原始 Goal、结构化验收、完整范围、关系、执行、风险、影响、Policy 和历史。
- URL hash、键盘导航和主操作能切换到正确工作区；实时刷新保留当前工作区。
- 工作台和 TUI 始终撑满视口可用高度；保留用户现有的终端展开/收起选择，不改变默认行为。
- 状态和操作文案保持简洁、专业、直接，例如“目标澄清中”“执行受阻”“待复核”。
- 修复待决定必填理由无反馈，并显示有效提交中的保存状态。

## 非目标

- 不删除、改写或复制权威 Goal 事实。
- 不改变 Goal、Risk、Decision、Review 或终端绑定的领域语义。
- 不引入新前端框架、设计系统或图片资产。
- 不把 Goal Detail 改成卡片墙、数据大盘或多列信息迷宫。
- 不重新设计 Goal Tree、Decision Center 或 TUI 内部内容。

## 主要路径

1. 用户选择 Goal，默认进入“概览”，首屏看到状态、下一步和目标结果。
2. 用户需要判断完成条件时，选择“完成要求”；父 Goal 在这里查看并进入子 Goal。
3. 用户需要排查卡点或查看最近工作时，选择“进展与阻塞”。
4. 用户需要审计或维护时，选择“完整记录”，再展开技术内容。
5. 主操作或正文链接指向某一章节时，页面自动切到对应工作区并定位目标。
6. 用户进入桌面工作区时，Goal Tree、Goal Detail 和终端共同占满屏幕可用高度；终端按现有偏好保持展开或收起。

## 方案与关键决策

- 保留现有浅色 IDE / 文档视觉语言，做结构性重排，不换品牌世界。
- 使用语义化 Tab 导航减少页面长度。Tab 不是隐藏关键事实，而是把不同任务分到稳定入口。
- “概览”是默认且唯一的首屏操作面；其他工作区不重复状态和主操作。
- 工作区导航使用文字与图标，选中状态同时使用背景、字重和 `aria-selected`，不只依赖颜色。
- Tab 状态进入现有 UI state，在 Goal 切换、实时刷新和前进后退中保持合理连续性。
- 不通过收起终端解决正文拥挤；Goal Detail 自身通过稳定分区降低长度和认知负担。
- “说人话”指去掉协议黑话和含糊表达，不把专业状态改写成幼稚或冗长的句子。

## 输入、输出与依赖

- 输入：现有 `WebGoalView`、派生状态、阻塞、验收、子 Goal、关系、风险、执行和终端本地偏好。
- 输出：四个任务工作区、可定位导航、明确首屏、全高且保持现有展开逻辑的终端、简洁状态文案、表单内错误与保存反馈。
- 依赖：现有服务端 HTML 渲染、页面实时刷新、session/local storage、PTY 客户端。

## 文件与模块边界

- `src/web/render.ts`：Goal Detail 结构、Tab 交互、状态保存、响应式样式、待决定表单反馈。
- `src/web/pty-client.ts`：仅在需要时验证现有终端展开偏好未被改变。
- `src/web/i18n.ts`：新导航、辅助说明和表单状态文案。
- `tests/web.test.ts`、`tests/desktop-tui.test.ts`、`tests/i18n.test.ts`：结构、交互契约、默认值和双语回归。
- `PRODUCT.md`、`DESIGN.md`：最终信息架构与使用路径。

## 验收标准

- Goal Detail 默认只展示概览；首屏可找到当前状态、一个主操作、阻塞和 Goal 结果。
- 四个工作区名称直接说明用途，区域边界清晰；一次只显示一个工作区。
- 键盘可在工作区导航间移动，选中状态有 `aria-selected`，面板与控制建立 `aria-controls` / `aria-labelledby` 关系。
- `#completion-*`、`#progress-*`、`#risk-*` 等入口会打开正确工作区并定位内容。
- 延迟载入内容尚未进入 DOM 时，首次点击和重复点击“查看进展”等深链接都能立即切换工作区并开始载入；直接用同一 hash 打开页面也能恢复到正确工作区。
- 切换 Goal、实时刷新和浏览历史不会让面板内容与选中导航不一致。
- 桌面工作区和 TUI 占满视口可用高度，不再出现终端下方大块留白；终端默认展开逻辑不变。
- 状态文案简洁、专业、直接，不使用“正在把目标说清楚”一类冗长替代表达。
- 技术事实、ID、关系、风险、Policy、执行记录和历史仍可找到，没有丢失。
- 待决定缺少理由时显示内联错误并聚焦输入框；有效提交显示“正在保存”，成功后显示回执。
- 桌面和 390px 移动端无横向溢出，主要按钮不换行，减少动态效果保持可用。

## 假设与开放问题

- 用户的新反馈覆盖旧版“所有章节连续展开”的方向；完整事实仍连续存在于各自工作区，不再要求同屏纵向铺开。
- 不需要用户再选择视觉风格；现有产品气质保留，优先修复空间分配、层级和操作路径。
