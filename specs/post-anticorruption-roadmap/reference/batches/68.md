# 68 · 新插件交付后半与智能呈现第四片

## 给人讲清楚

创作台生成的插件装上以后，现在还很难接着改、升级，数据也带不走。这一批让已装的插件能继续修改、重新采用、升级且数据不丢；每个生成插件都能导出业务数据，升级后旧记录照样能打开、处理和导出；包缺失、损坏、卸载、重启后都能恢复；生成插件的操作面可以保存成视图或页面；给每个主推角色准备 2～3 个一键安装、能让 AI 改的样例插件；再按同一套评测跑一遍，记下失败和返修次数。需要你做的：修订和恢复中新出现的差异会做样给你看并定下；主推角色和用途还没定的要你定，没定的只暂停对应角色的样例。

## 交付与前置

- **阶段／类型**：3；产品线（创作台）；横向能力
- **需求来源**：[创作台升级][PBU]、[产品建议 C2／C3／C5][P]、[Harness R11／R12][CHO]、[智能呈现第四片][IUI]、[视觉 VUX-51～59][VUX]、[BL-711／915][BL]
- **前置／待决**：共享文件由原主人写；样例包分享接 73，改用率与整项验收接 83。
- **可并行项**：70 的内容工具新增交互设计
- **UI 要求**：复用 03、47、48；修订／恢复差异先定样
- **粒度**（批内子分支怎么分，全批仍是一个 PR；开工建议，执行时按[开发流程第 8.4 节](../development-workflow.md#batch-grouping)判断）：持续修订和缺包恢复一个子分支，恢复的验证证据取在最终的头上；业务数据导出要单独证明，单独一个 PR（第 8.4 节的提前切出）；呈现保存、角色样例、同口径评测各一个子分支。
