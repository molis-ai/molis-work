# 首次使用与新建项目的引导：首跑闭环、数据边界与下一步

状态：需求已整理，尚未实现（2026-10-19）。负责人：待定。本文只写要什么，不写怎么做；实现方式、页面位置与交互形态在设计与实现阶段定。

## 1. 要解决的事

现在 Onboarding 的主动线是「从已有材料开始」：语言 → 外观 → 来源 → 预览 → 整理 → 采用（[设计稿](../../docs/design/molis-work-onboarding/proposal.md)）。它把材料带进了项目，但产品里已经做好的几项能力首次都不出现，形成三个断点。

| 断点 | 现在的样子 | 后果 |
| --- | --- | --- |
| 模型不在流程里 | 只显示「尚未连接文字模型」，和一个跳到 `/settings/models` 的新标签页链接 | 没有模型的用户走不到核心价值（摘要、待办），只能中断去设置，回来还要自己找路 |
| 数据边界只讲了一半 | 预览页只有「原文先暂存在本机」「原文件保持原样」两句 | 用户不知道数据存在哪、怎么导出和删除、外部模型到底收到什么 |
| 采用之后没有下一步 | 采用完成直接进项目 | 用户不知道记忆、能力库、服务连接、项目工作目录、助理规则在哪；也容易把一次性导入当成会持续更新 |

模型这一条与设计稿不一致：设计稿要求「没有时，在同一准备流程完成最短可行配置和检查」（[proposal §2](../../docs/design/molis-work-onboarding/proposal.md)）。数据边界与下一步在设计稿里没有成节，但设置里已经有对应能力（记忆导出、能力库、服务连接、项目工作目录、助理提醒与用量），只是首次没有出现。

## 2. 目标

1. **首跑闭环**：有材料、空白、个人空间三条路径都能走到一个明确结果——要么有摘要，要么是一条说清楚的「先带入资料」路径。
2. **数据边界**：读取正文之前，用户能回答「数据在哪、谁收到什么、原文件会不会变、怎么导出和删除」。
3. **下一步**：采用之后知道还能配什么，但配置不塞满首跑。
4. **更新可解释**：更新页说明这次变了什么，而不是只报版本号。

### 非目标

- 不在首跑主动请求系统权限（屏幕录制、辅助功能、输入监控）。
- 不在首跑配置 MCP / 对外接入、调用记录、诊断、提示词、AI 与执行工具、Coding 设置、角色、planning、项目说明、项目记忆。
- 不做字体与皮肤、语音输入——这两项能力本身还没有实现。
- 不改变「从已有材料开始」为主线；不引入账号、云同步、多设备。

## 3. 需求

### 3.1 模型（P0）

- **R1** 首次使用与新建项目，在开始整理之前，如果没有可用的文字模型，流程内要能完成配置：用户不必离开当前流程；从设置返回后，流程状态保留并接着走。
- **R2** 已有可用模型时直接复用，只显示当前模型与「更换」，不重复询问。
- **R3** 配置成功后可以立即继续整理，不需要重新选择材料、重进流程。
- **R4** 用户可以选择「先带入资料、稍后整理」。选择后必须标明摘要尚未生成，并在进入项目后提供继续整理的入口。
- **R5** 模型不可用、连接失败或超时，要说明原因和下一步，不得显示整理完成，也不得用占位内容冒充摘要。

### 3.2 数据与信任（P1）

- **R6** 读取正文之前，显示三件事：数据存放的位置（本机 Home 与项目库）、本次会发给外部模型的内容范围、原文件不会被修改。
- **R7** 同一处能到达「导出」与「删除」的真实入口（记忆导出、项目删除）。
- **R8** 说明本次导入是一次性快照，不会自动持续同步；补充或更新材料要有明确的下一步。

### 3.3 采用之后的下一步（P1）

- **R9** 采用完成后展示一个可跳过的「下一步」，至少四项：记忆（默认与开关）、能力（能力库与服务连接）、项目工作目录、助理（提醒规则与用量上限）。每项一行说明加一个入口。
- **R10** 「下一步」整体可跳过，不阻断进入项目；跳过之后，同样的入口能从项目设置或全局设置找到。
- **R11** 用户跳过模型时，这里要有回到整理、配置模型的入口。

### 3.4 更新页（P2）

- **R12** 更新页显示版本号与本次更新要点；没有要点时不编造，只说明版本与「数据仍在本机」。

### 3.5 系统权限（P2，按需）

- **R13** 首次启动不主动请求屏幕录制、辅助功能、输入监控。
- **R14** 首次使用电脑能力之前，说明需要哪几项权限、用途是什么、去哪里打开，并允许取消；取消后不重复弹。

### 3.6 恢复、键盘与语言（P1）

- **R15** 新增步骤可跳过、可返回；离开再回来不丢失已选来源、范围与整理进度。
- **R16** 新增步骤可全键盘完成，焦点进入标题，读屏可读；中英文文案齐全。

### 3.7 状态（P1）

- **R17** 任一分支（材料、空白、个人空间）完成后，首跑不再出现；更新页只在版本变化时出现。

## 4. 验收标准

| 编号 | 标准 |
| --- | --- |
| ONB-01 | 没有可用文字模型时，开始整理前流程内出现配置入口；配置成功后不重进流程即可继续整理 |
| ONB-02 | 已有可用模型时，不出现配置步骤，只显示当前模型与「更换」 |
| ONB-03 | 选择「先带入资料」时，界面明确标注摘要尚未生成；进入项目后能找到继续整理的入口 |
| ONB-04 | 模型不可用、连接失败或超时，说明原因与下一步，不出现「整理完成」或占位摘要 |
| ONB-05 | 读取正文之前，页面显示数据存放位置、会发给外部模型的内容范围、原文件不会被修改 |
| ONB-06 | 同一处可到达导出与删除的真实入口 |
| ONB-07 | 采用完成后出现可跳过的「下一步」，包含记忆、能力库与服务连接、项目工作目录、助理四项入口 |
| ONB-08 | 采用完成后明确说明本次导入是一次性快照、不会自动持续更新，并给出补充或更新的方式 |
| ONB-09 | [人工] 更新页的更新要点与本次版本的实际变化一致；没有要点时只显示版本与「数据仍在本机」，不编造内容 |
| ONB-10 | 首次启动不发出屏幕录制、辅助功能、输入监控的权限请求 |
| ONB-11 | 首次使用电脑能力前，展示需要的权限、用途与跳转；取消后不重复弹 |
| ONB-12 | 新增步骤可跳过、可返回；离开再回来不丢失已选来源、范围与整理进度 |
| ONB-13 | 新增步骤可全键盘完成，焦点进入标题，读屏可读；中英文文案齐全 |
| ONB-14 | 材料、空白、个人空间三条路径完成后，首跑不再出现；更新页只在版本变化时出现 |
| ONB-15 | 现有到达流程的语义不变：语言、外观、来源、预览、采用，以及跳过授权、上限提示、无模型路径都不回归 |

## 6. 未决（留给设计与实现）

- 模型配置放在流程的哪一步（来源之前、预览之后，或采用之后补做）；需求只要求「开始整理前可达」。
- 「下一步」是独立一屏、采用后的浮层，还是项目首页的一块；需求只要求可跳过、不阻断。
- 更新要点从哪里取（发布说明、变更记录或人工填写）；需求只要求「有则如实显示，没有则不编造」。
