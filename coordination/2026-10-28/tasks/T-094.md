# T-094 Cognia 的名称、标题、导入路径与搜索词按 Unicode 字数数上限，与动作 schema 一致

> **这条在 main 上成立：Cognia 的动作 schema 按字数数上限，Cognia 自己却按 UTF-16 单元数。**
> - 领域名称 `maxLength: 120`（`plugins/native/cognia/src/actions.ts:28-29`）、来源名称 200（`:31`，`src/action-schema.ts:27`）、资料标题 500（`action-schema.ts:3`、`:26`）、导入文件路径 1000（`action-schema.ts:21`）、搜索词 500（`actions.ts:24`、`:25`）。
> - 动作层用 Ajv 校验，Ajv 的 `maxLength` 按 Unicode 字符（码点）数：`packages/kernel/src/action-schema.ts:41-42` 的选项里没有 `unicode: false`。
>
> Cognia 却按 `string.length` 数，有三处（第 1 节的表）。一个 emoji 或扩展 B 区以后的生僻字在 JS 字符串里占 2 个单元。所以：
> - 61～120 个这样的字的领域名称、101～200 个的来源名称、251～500 个的资料标题，过了 schema，又被 Cognia 以 `cognia.invalid`「请输入领域名称」「请输入来源名称」「请输入标题」拒；
> - 501～1000 个这样的字的导入路径，整批预览以「资料路径无效」拒；
> - 251～500 个这样的字的搜索词，以「搜索词过长」拒。
>
> 起草时只读了代码，没有跑；第 5 节的先红就是复现。T-077、T-079、T-080、T-083、T-086、T-090、T-091、T-092 的同类。
>

## 1. 背景

- 合同口径（都按 Unicode 字符）：
  - `plugins/native/cognia/src/action-schema.ts`：
    - `:3`：`id`，`maxLength: 500`；
    - `:21`：导入文件的 `path`，`maxLength: 1000`；
    - `:26`：`materialInput` 的 `title`，就是 `id`（500）；
    - `:27`：`importFields` 的 `name`，`maxLength: 200`；`source_id` 是 `id`（500）。
  - `plugins/native/cognia/src/actions.ts`：
    - `:22`：`question`，`maxLength: 2000`；
    - `:24`：`cognia.workspace.get` 的 `query`，`maxLength: 500`；`:25`：`cognia.material.search` 的 `query` 是 `s.id`（500）；
    - `:28-29`：领域的 `name`，`maxLength: 120`；`:31`：来源的 `name`，`maxLength: 200`。
  - Ajv：`packages/kernel/src/action-schema.ts:41-42` 的选项、`:79` 的 `new Ajv(options)`。没有 `unicode: false`，`maxLength` 走 Ajv 的 `ucs2length`，按码点数。
- 按 UTF-16 数的三处：

  | 位置 | 现在的写法 | 谁会走到 |
  | --- | --- | --- |
  | `types.ts:35`（`stringField`） | `export function stringField(value: unknown, label: string, max = 500): string { requireCognia(typeof value === "string" && value.trim().length > 0 && value.length <= max, label); return value.trim(); }` | `store.ts`：`:30` `createDomain`、`:31` `renameDomain`（120，「请输入领域名称」）；`:46` `renameSource`、`:69` 新来源的名称（200，「请输入来源名称」）；`:65` `source_id`（默认 500，「来源无效」）；`:111` `createMaterial`、`:122` `updateMaterial`（500，「请输入标题」）。`ai.ts`：`:11` 问题（2000）；`:42` 模型给的标题（500）和正文（100000） |
  | `content.ts:8`（`safeRelativePath`） | `requireCognia(typeof value === "string" && value.length > 0 && value.length <= 1000 && !/[\x00-\x1f\\]/u.test(value), "资料路径无效");` | `store.ts:73`：`preview` 逐个文件量路径。这一行在 `:75` 的 `try` 之外，一个路径不合整批预览就拒 |
  | `store.ts:53`（`materials`） | `requireCognia(query.length <= 500, "搜索词过长"); const terms = query.toLocaleLowerCase().trim().split(/\s+/u).filter(Boolean);` | `actions.ts:64` `cognia.workspace.get`、`:65` `cognia.material.search`。`ai.ts:29`、`search.ts:17`、`:21` 传的是空串或不传 |

- `stringField` 的 `value.trim().length > 0`、`safeRelativePath` 的 `value.length > 0` 只问是不是空的，按单元数和按字数数结果一样，不改。
- `stringField` 量的是没去空白的原值，和 schema 量的是同一个值；本单只换数法，不改量哪个值。
- 都是 `cogniaErrors.invalid`（`types.ts:22-25`、`:34`），`defineErrorCodes`（`packages/contracts/src/platform/action-errors.ts:109-115`）给的码是 `cognia.invalid`。
- 改了以后，下游放得下，起草时逐处读过：
  - 领域名称存在 `cognia_domains` 的 `name` 列，来源、资料整个以 JSON 存在 `cognia_sources`、`cognia_materials` 的 `body` 列（`database.ts:8-10`；写入在 `store.ts:30`、`:46`、`:108`），表上都没有长度的 `CHECK`；
  - 输出 schema 里资料、草稿的 `title`、`path` 都是不带上限的 `text`（`action-schema.ts:13`、`:17`），领域、来源的输出也不比输入严；
  - 路径的越界判断在下一行（`content.ts:9`），不改。
- 没有测试量到这三处：`tests/cognia-store.test.ts` 里的名称、标题、路径、搜索词都是几个汉字或 ASCII（如 `:56-59`、`:79`）。
- 页面不受影响：页面包从 `src/browser/factory.ts` 打，`src/browser/**` 对 `../types.js` 只有 `import type`（`browser/labels.ts:1`、`browser/types.ts:2`、`:34`），打包时去掉；不引 `../content.js`、`../store.js`。所以 `/assets/molis-work-plugins/cognia.js` 的字节不变（`tooling/gates/page-assets.json:16`）。

## 2. 目标

1. 领域名称 120 个、来源名称 200 个、资料标题 500 个非 BMP 字符（如 `🟢`）原样收下；各多一个仍以 `cognia.invalid` 和原来的文案拒（`RAC-1665`）。
2. 1000 个这样的字的导入路径能进预览；1001 个仍以 `cognia.invalid`「资料路径无效」拒。500 个这样的字的搜索词能搜；501 个仍以 `cognia.invalid`「搜索词过长」拒（`RAC-1666`）。

上限本身不变。

test("RAC-1665 names and titles are counted in Unicode characters like the action schema: 120 for a domain, 200 for a source, 500 for a material title, and one more is refused", fixture(store => {
  // The action schemas (src/actions.ts, src/action-schema.ts) count characters; one 🟢 is one character but two UTF-16 units.
  const wide = (count: number) => "🟢".repeat(count);
  const refused = (message: string) => ({ code: "cognia.invalid", message });
  const domain = store.createDomain("旧领域");
  assert.equal(store.renameDomain(domain.id, wide(120)).name, wide(120), "a 120-character domain name is taken on rename");
  assert.equal(store.createDomain(wide(120)).id, domain.id, "and found again by the same name");
  assert.throws(() => store.createDomain(wide(121)), refused("请输入领域名称"), "121 characters is still past the domain limit");
  assert.throws(() => store.renameDomain(domain.id, wide(121)), refused("请输入领域名称"), "also on rename");
  const pending = store.preview({ name: wide(200), kind: "markdown", locator: "local:/wide-name", files: [text("a.md", "# A")] });
  assert.equal(pending.source.name, wide(200), "a new source takes a 200-character name");
  assert.throws(() => store.preview({ name: wide(201), kind: "markdown", locator: "local:/wider-name", files: [text("a.md", "# A")] }),
    refused("请输入来源名称"), "201 characters is still past the source limit");
  const { source_id } = store.commit(pending.id);
  assert.equal(store.renameSource(source_id, wide(200)).name, wide(200), "a source is renamed to 200 characters");
  assert.throws(() => store.renameSource(source_id, wide(201)), refused("请输入来源名称"), "also on rename");
  const material = store.createMaterial({ title: wide(500), body: "正文" });
  assert.equal(material.title, wide(500), "a 500-character title is taken");
  assert.equal(store.updateMaterial(material.id, { title: wide(500), body: "新正文" }).title, wide(500), "and kept on update");
  assert.throws(() => store.createMaterial({ title: wide(501), body: "正文" }), refused("请输入标题"), "501 characters is still past the title limit");
  assert.throws(() => store.updateMaterial(material.id, { title: wide(501), body: "新正文" }), refused("请输入标题"), "also on update");
  assert.equal(store.read(material.id).revision, 2, "the refused update wrote nothing");
  assert.deepEqual(store.domains().map(d => d.name), [wide(120)], "the refused domain was not created");
}));

test("RAC-1666 an import path is counted in Unicode characters up to 1000 and the search words up to 500, like the action schema", fixture(store => {
  // The import file path (src/action-schema.ts) and the search words (src/actions.ts) count characters; one 🟢 is one character but two UTF-16 units.
  const wide = (count: number) => "🟢".repeat(count);
  const path = wide(997) + ".md";
  const p = preview(store, [text(path, "# 很长的路径")]);
  assert.deepEqual(p.entries.map(entry => [entry.path, entry.status]), [[path, "new"]], "a 1000-character path is read");
  assert.throws(() => preview(store, [text(wide(998) + ".md", "# 多一个字")]), { code: "cognia.invalid", message: "资料路径无效" }, "1001 characters is still past the path limit");
  const material = store.createMaterial({ title: "很长的正文", body: wide(500) });
  assert.deepEqual(store.materials(wide(500)).map(m => m.id), [material.id], "500 characters of search words find the material");
  assert.throws(() => store.materials(wide(501)), { code: "cognia.invalid", message: "搜索词过长" }, "501 characters is still past the search limit");
}));

3. 几处为什么这样写，别改：
   - 用 `🟢`（U+1F7E2）：一个码点、两个 UTF-16 单元，没有变体选择符。T-077、T-079、T-080、T-090、T-091、T-092 和 `tests/content-owner-regressions.test.ts:58` 用的也是它。
   - 值正好压在上限上（120、200、500、1000），多一个（121、201、501、1001）就拒，才分得清按字数和按单元。不要缩短。
   - 直接调 `CogniaStore`，不经动作服务：schema 按码点数，多一个字的值本来就过不了 schema。本单要证的是主人不再多拒，只能直接调主人。文件里已有的用例也这样调。
   - 路径是 `wide(997) + ".md"`，正好 1000 个字：`.md` 是三个 ASCII 字符，换成别的扩展名就不是文本文件（`content.ts:5`、`:12-16`），会被跳过，量不到。
   - 预览不提交：`RAC-1666` 里的搜索只该找到手动建的那一份资料。路径里也有 500 个 `🟢`，提交了就会被同一个搜索词找到。
   - 新来源用 `kind: "markdown"` 和两个各不相同的 `locator`：来源的身份由 `locator` 算出（`store.ts:65`），同一个 `locator` 第二次预览时，已有来源就不再量名称（`:69`）。
   - `assert.throws` 的第二个参数比对 `code` 和 `message`：抛的都是 `cogniaErrors.invalid(…)`，码是 `cognia.invalid`，文案原样。
   - 只用文件里已有的 `test`、`assert`、`text`、`fixture`、`preview`（`:1-17`），不加 `import`。
