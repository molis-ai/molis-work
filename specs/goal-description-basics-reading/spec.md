# 基础信息阅读分区与主题

## 背景目标

「目标与要求」里的基础信息是一串同级小标题叠正文，扫读累；底部历史覆盖卡片写死浅色底，Dark 里一块白。

## 当前行为与问题证据

打开基础信息后，要得到什么 / 为什么 / 运转 / 有效决定 / 范围用同一套 `h3 + p`。范围五项是「标签：值」段落。底部「历史对父 Goal 的贡献」卡片 `background: #fbfcfd`，Dark 下仍是浅底。

## 范围

- 基础信息分三块阅读：主结论、说明、事实行。
- 范围改成标签/值行，空值弱化。
- 小标题用现有 Lucide 图标井和短标签排成一行，不是纯文字，也不套装饰卡片。
- 历史 Contract 覆盖改由「历史覆盖」标签承接，不留在基础信息里。覆盖卡片表面仍用主题 token。

## 非目标

- 不重写关系 / 风险 / 影响 / 规则工作面。
- 不改覆盖数据或写入入口。

## 方案与关键决策

- 主结论（要得到什么）字号略大；为什么 / 运转作说明；有效决定与范围作事实行。
- 层级靠字号、颜色、分隔，不加一层卡片框。
- 五个小标题同一行：Lucide 图标井 + 原标题 + 短标签（结果 / 动机 / 运转 / 数量或暂无 / 边界），沿用关系记录 pill，不另开色系。
- `.contract-coverage-group > article` 用 `var(--paper)` / `var(--ink)` 混色，Light / Dark 共用。

## 验收标准

- 基础信息能分出主结论、说明和范围事实行。
- 每个小标题是图标井、标题、短标签一行，不是裸 `h3`。
- Dark 下历史覆盖卡片不是浅色纸面，正文颜色跟主题走。
- 原字段（要得到什么、范围）仍可读；覆盖说明改在「历史覆盖」标签。

## 验证命令

- `tsx --test tests/goals-document-ui.test.ts tests/visual-foundation.test.ts`
- 浏览器：Dark / Light 打开「目标与要求 → 基础信息」，核对阅读分区和底部覆盖卡片。
