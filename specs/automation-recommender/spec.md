# 项目自动化建议（Automation Recommender）

状态：需求已整理，尚未实现（2026-10-18）。目标完成程度为**内部完整**：用户在一个项目里打开助理或项目到达流程时，能得到一份只读的、有证据的自动化建议，说明这个项目最值得加的 hooks、技能包、MCP/连接器、子代理/角色和命令；建议不自动安装、不自动改配置。

## 1. 问题

Molis 的扩展面很多：hooks、技能包、MCP/连接器、子代理/角色、命令、项目设置。新项目上手时，用户不知道哪些值得加、为什么加、加了会怎样；插件创作台能“从零做一个插件”，但不会先告诉用户“这个项目最需要哪两件事”。

现有的项目到达/引导（BL-106、BL-107）解决的是项目简介、材料数和后台整理；没有“读项目 → 推荐自动化”的只读流程。

## 2. 范围与非目标

**做**：

- 只读扫描当前项目：语言/框架、包管理器、测试、lint/format、CI、目录结构、已有 `.molis`/`.claude`/`AGENTS.md` 配置、已装插件/技能包。
- 按类别各推荐 1–2 个最值得的自动化：hooks、技能包、MCP/连接器、子代理/角色、命令。
- 每条建议带证据（文件/配置/依赖）、预期效果、前置条件、风险/费用、置信度。
- 建议可保存成一份报告；用户可以选择“去安装/去创建”，安装仍是独立确认。
- 在助理、项目到达、插件创作台可达；不新增第二套项目扫描事实。

**不做**：

- 不自动安装、不自动改项目配置、不自动跑命令。
- 不虚构项目没有的能力；只推荐已注册的动作、技能包、连接器和角色。
- 不把扫描结果写成项目的正式事实或 Goal。
- 不做云端代码扫描；只读本机已授权工作区。

## 3. 扫描与建议

### 3.1 扫描信号

| 信号 | 看什么 | 影响 |
| --- | --- | --- |
| 语言/框架 | `package.json`、`pyproject.toml`、`Cargo.toml`、`go.mod`、锁文件 | hooks、LSP、技能包 |
| 测试 | Jest/Vitest/pytest/Playwright 配置、`tests/` | 测试 hook、测试子代理 |
| 质量工具 | ESLint/Biome/Ruff/Prettier/tsc | 写后 lint/format/typecheck hook |
| CI | `.github/workflows`、`.gitlab-ci.yml` | PR 评审、CI 修复、批准门 |
| 已有配置 | `.molis/`、`.claude/`、`AGENTS.md`、`CLAUDE.md` | 避免重复建议 |
| 外部系统 | 连接器/官方集成、`.mcp.json` | MCP/连接器建议 |
| 项目类型 | 前端/后端/数据/文档/研究 | 技能包与子代理 |

### 3.2 建议格式

每条建议至少写：类别、名称、证据（路径/依赖/配置）、为什么现在值得、预期效果、前置条件、风险/费用、置信度、下一步（安装/创建/查看）。

### 3.3 类别

- **Hooks**：写后 format/lint/typecheck、测试、阻止 `.env`/锁文件/敏感路径、Stop 前要求测试。
- **技能包**：按项目类型推荐角色包/场景包（工程、设计、数据、产品等）。
- **MCP/连接器**：按依赖和外部系统推荐（文档、数据库、浏览器、Issue 跟踪）。
- **子代理/角色**：代码评审、安全评审、测试编写、性能分析、UI/无障碍评审。
- **命令**：提交/PR、Issue 分诊、去重、发布说明。

## 4. 交互

- 入口：项目到达、个人助理、插件创作台；只读，不阻塞页面。
- 输出：一份可保存的“项目自动化建议”报告；按类别分组，默认每类 1–2 条，可展开更多。
- 用户点“去安装/去创建”后，进入现有的安装/创建流程；安装前仍展示权限、来源、版本。
- 用户可以忽略某条建议、标记“已经有”、或让它以后不再出现；这些偏好按项目保存。
- 扫描失败/部分失败：说明缺什么，不用猜测补齐；只基于读到的内容给建议。

## 5. 验收标准

| 编号 | 用户可观察结果 |
| --- | --- |
| AUT-01 | 在一个真实项目里打开建议，能在合理时间内完成只读扫描，不修改任何文件、配置或业务数据 |
| AUT-02 | 建议按 hooks/技能包/MCP/子代理/命令分组，每类 1–2 条，每条都有证据、预期效果、前置条件与风险 |
| AUT-03 | 推荐只包含当前实际可用的动作、技能包、连接器和角色；没有的能力不编造，缺依赖时说明 |
| AUT-04 | 已有 `.molis`/`.claude`/`AGENTS.md` 配置时，不重复推荐已经存在的自动化 |
| AUT-05 | 项目信息不完整或扫描失败时，如实说明缺口，仍能基于已有信息给出有限建议 |
| AUT-06 | 点击“去安装/去创建”进入现有流程，安装/创建前仍展示权限、来源、版本；不自动安装 |
| AUT-07 | 建议可保存为报告，用户可忽略/标记已有/不再提示；这些偏好不改变项目事实 |
| AUT-08 | `[人工]` 在一个真实项目上按建议加一个 hook 或技能包，验证它确实生效；撤销后不残留 |
