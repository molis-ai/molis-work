### 动态数字布局补充（细化 VUX-06，2026-10-16）

- **VUX-42** 等宽数字：倒计时、耗时与动态计数的数字区域优先使用 `font-variant-numeric: tabular-nums`，确认实际字体支持等宽数字；不支持时使用支持该能力的数字字体或等宽后备。只应用于需要稳定对齐的数字区域，不强制所有正文改为等宽字体。相同字体、字号、字重与位数下，替换 `0–9` 不改变数字区域宽度或推动邻近内容；仅有 CSS 声明不算通过。
- **VUX-43** 稳定格式：按场景确定持续使用的格式，倒计时如 `MM:SS` 补齐前导零，验证 `00:10 → 00:09`、`01:00 → 00:59` 时分隔符、单位和邻近操作位置稳定。需要小时或其他格式时，明确转换边界并预留对应空间；不得因每次更新在不同格式之间来回切换。
- **VUX-44** 宽度预留：按组件支持的值域、显示格式和实际字体预留数字及单位所需宽度，覆盖 `9 → 10`、`99 → 100` 及反向变化。增长到预留范围边界时有明确的显示与布局策略，不靠隐藏真实数值、裁切或缩小字号掩盖溢出；窄面板与分屏仍能看清数字并操作相邻控件。
- **VUX-45** 字体加载与切换：在实际系统字体、可选字体与离线后备字体下分别运行上述变化，覆盖字体加载失败、后备切换到目标字体，以及计时过程中切换字体/皮肤。按生效字体重新校准预留宽度，切换过程中无裁切、重叠或控件错位，切换稳定后数字更新仍不推动邻近内容。字体切换本身允许由字体度量变化引起的合理重排，不要求不同字体尺寸完全一致。

本条针对动态数字更新造成的布局变化；等宽数字不能单独保证所有 Layout Shift 消失，也不能替代格式、宽度和字体加载验证。

### 版面秩序补充（用户 2026-10-22 提出）

用户原话的意思：各个模块和界面下，状态符号和字要等高；按钮的组织、组件与排列要整理、对齐；字号要合理；整洁清爽，信息陈列有组织。现在很多地方不一致。

- **VUX-46** 标记与字等高：状态环、圆点与徽标标记与旁边的字同高（字号 + 2px 以内），对齐第一行字的中线；图标与字同号或大一级（12–15px 字旁 12–16px，20px 只在 17–20px 字旁或单独站着时）。页面不为某一行另定环的尺寸，由共有部件跟随文字。
- **VUX-47** 同排的按钮同高、同一行、同一间距：变体不改变高度；间距 8px，紧凑组 4px，只有图标按钮或工具条 2px；页头的动作与标题在同一行。一排里刻意更大的目标要有理由并登记（现在只有底栏的发送）。
- **VUX-48** 字号守住字阶：只用 11/12/13/15/17/20/24/30px，一页至多四级；不出现 10、13.5、14px 之类。代码、输入框与编辑器自己的画布除外。字号按角色定，不按组件定（用户 2026-10-22 补：跟随文字的前提是各场景的字号有统一的设计逻辑，讲清视觉、心理与信息重心）：展示 30/600、页面标题 24/600、打开的条目标题 20/600、区段与弹窗标题 15/600、条目名称 13/500、动作（按钮、链接按钮与菜单项）13/500、正文与字段值 13/400、长阅读 15–17/400、浮条上的工具 12/500、看法的选择（分段、筛选、排序）12/500、事实（时间、计数、来源、状态词、说明）12/400 淡色、分组标签 11–12/500 淡色。理由写在 DESIGN「Typography · Roles」：眼睛先看大小、再看字重、再看对比，所以每降一个角色就是注意力的后退一步；一页从标题到名称到事实只有一条阅读顺序；相邻两级只差 1px 时必须再差字重或颜色；标记跟随所在文字的角色——比字高的标记会在读字之前被看到（前注意加工），把一行的重心从「这是什么」挪到「它的状态」，等高时名称为主、状态为辅，与一行的阅读顺序一致。同一角色在每个插件里同号同重，由审计的 `control-role` 等检查守住。
- **VUX-49** 组件与排列一致：同一类页面用同一种版式（列表页：标题、动作，再一列列表；说明仅在有助当前理解或操作时出现，沿 VUX-53、VUX-56；一行：前导标记、标题、事实、末尾动作），对齐同一条起始线与版心；不同插件之间不各自摆放。
- **VUX-50** 可检查：以上四条由页面上的实测几何守住（项目页、通用插件页、设置与组件板），不只看源码或截图；留下的例外逐条写理由。

### copy-guidance

目标是让用户看见名称就知道是什么，看见按钮就知道会发生什么，并能找到当前下一步。先改清楚名称和操作组织，再决定哪些说明值得保留。全产品文案不是逐句缩短：必要信息在需要决定的时刻出现，背景知识和技术细节留在可找回的帮助中。

#### 覆盖范围与记录

| 范围 | 需要逐项覆盖的表面 |
| --- | --- |
| 平台与桌面入口 | 安装/启动/更新中的产品提示、Welcome、项目选择与首页、导航、搜索、标签与分屏、通知、菜单、弹窗和操作回执 |
| 设置与准备 | 全局、项目、插件与本次任务设置，模型、连接、账号与权限，首次使用、新建项目、已有项目补充配置和任务准备 |
| AI 与执行 | 个人助理、Coding、子代理及后台任务的界面名称、输入提示、过程摘要、操作卡、审批、用量、错误和结果入口 |
| 全部插件与创作 | 各插件的目录、列表、详情、编辑/创建、空状态、设置与帮助；市场与安装、插件创作台、生成插件和生成页面中的同类表面 |

实施时按当时的入口和插件目录展开，沿已有验收记录补齐页面/状态、原问题、修改后的默认内容、帮助出现时机、下一步入口和验证结果，不另建产品进度系统。共用组件的证据可复用，但各消费者的对象、状态与落点仍需核对；安装型或生成插件按同一公开规范提供内容，平台不另造专用文案名单。新功能随所属需求接入，尚未实现的入口保留待接入状态。

本范围包含产品界面与系统生成的操作反馈，不自动改写用户文稿、Goal 标题、模型回答正文、代码、外部材料或原始日志；官网营销稿与开发文档全文重写不在本次范围。详细诊断保留原始事实，供排查时查看或复制。

#### 名称、按钮与下一步

名称使用用户认识的对象与动作，沿[术语表](../../docs/system/GLOSSARY.md)保持概念一致；内部状态名、协议字段与 ID 不作为普通用户唯一能看到的名称。同一个词不能在相邻入口分别代表保存、启用和执行。必要的专业词在第一次相关使用或帮助中解释；先核对象与流程是否分得清，不用补一段说明掩盖错误分类。

按钮表达实际操作，必要时带对象或结果，例如“连接模型”“保存设置”“生成草稿”“采用方案”“重试未完成项”。这些是表达示例，具体按钮以真实能力为准。上下文已清楚时可保留简短的“保存”或“下一步”；涉及外部发送、删除、收费或执行的按钮须能辨认后果，不能用“继续”替代。占位文字只给输入示例，不代替字段名称和必要约束。

当前路径应有容易找到的主要动作，其他选择按频率与影响组织；有合理并列任务时保留选择。操作后在原位置说明结果，并给出真实下一步或返回入口。首次为空、筛选无结果、未配置、未获准、载入中和读取失败分别处理；尚无任务时允许安静停留。错误先说明哪里没完成、已知原因和可行处理，未知原因不猜，部分成功不要求重做已成功部分。

#### 常驻内容与按需帮助

| 出现时机 | 保留什么、怎样呈现 |
| --- | --- |
| 页面默认 | 对象名称、必要状态、主要操作和影响当前判断的简短信息；不重复介绍页面名称或列出整页功能说明 |
| 首次相关使用或出现缺项 | 就近给出当前需要的一小步和开始入口；一般教学可跳过，必要配置说明影响；已有配置足够时直接开始 |
| 用户主动求助 | 通过“帮助”“了解此项”等明确入口展开概念、例子、操作方法和高级参数；Tooltip 只作简短补充，复杂帮助可持续打开和阅读 |
| 需要决定、失败或受阻 | 直接显示影响本次操作的权限、范围、外发、已知费用、不可逆后果和恢复方式；详细技术信息再展开，不把关键后果藏进帮助 |

帮助就近解释当前对象，不用满屏常驻说明、强制逐项教程或重复弹窗承担导航。阅读帮助不自动进入配置；用户选择其中的操作入口后才接续准备。用户可关闭、稍后继续和主动重开；普通帮助的展开/忽略只是界面偏好，不等于任务完成、配置采用或权限授予，也不能静默屏蔽新的风险和阻塞。帮助入口、返回焦点、窄屏和读屏沿共用组件行为；是否需要跨重启保存进度由现有引导 owner 承接，不建第二套完成标记。

#### 与渐进式引导衔接

[Onboarding §3.15](../onboarding-coverage/spec.md#315-从页面帮助到渐进式引导)负责从当下缺口开始准备并回到工作。比如从“生成草稿”进入模型连接，只补缺少的连接步骤，保留材料与草稿，连接成功后回原位置由用户继续；具体触发执行沿原有效委托，不把“看帮助”或“连接成功”当作新增执行授权。首次使用、日常设置、个人助理和插件入口使用同一名称、有效配置与进度。

AI 参与生成问题、页面或操作提示时，读取当前目的、获准材料、实际能力目录、配置和执行状态，产出相关问题或可执行下一步。输出缺少依据、生成失败或能力不可用时，保留可用的基础入口并说明具体缺口，不虚构按钮、权限或成功结果。表现与措辞归本书，提问/配置采用/恢复归 Onboarding，业务事实归原功能 owner。

### design-principles

**内容优先（Content First）与编辑式层级（Editorial Hierarchy）**：用户首先能找到结论、正在处理的对象和需要自己做的事，随后才读过程、来源和统计。标题的字号、字重、位置及段落节奏共同建立主次，不能靠处处加粗、加徽章和套卡片制造层级。留白允许存在；未知、空内容和读取失败分开说明，不用推荐或示例数据填空。次级信息使用现有可读文字角色，不能通过额外降低 opacity 把“克制”做成看不清。

**邻近关系（Proximity）与垂直节奏（Vertical Rhythm）**：沿用 4/8/12/16/24/32px 间距阶梯。图标和文字、同一行关联信息优先用 4/8px；同一组的条目与说明用 8/12/16px；主题间分隔用 24/32px，作为按用途校准的起点。标题应更靠近它解释的正文，段落间距表达段落关系；列表项内距小于不同分组间距。嵌套容器不逐层累加整份 padding，目录的密度与阅读区分别校准。

**微对比表面（Low-contrast Surface Layering）与因果动效**：沿用现有表面、文字和阴影角色，抬升对应真实浮层，选中对应真实选择，运动对应刚发生的操作或状态变化。默认静止，变化局限于所属对象；后台数据刷新不重新演整页到达。装饰不能覆盖用户判断所需的状态或让内容等待动画。一个语义角色只有一份生产定义，规格板与消费者共享，参数取舍见采用边界。

### layout-centering

**版心约束（Content Measure）与情境居中。** “居中”必须说明相对哪个容器、居中哪个盒子、内容内部如何对齐，不能用一个全局 `text-align: center` 代替。

| 场景 | 布局规则与几何锚点 |
| --- | --- |
| 助理回答、长文与输入 | 阅读列相对**所属面板的内容区**水平居中，使用 `max-inline-size` 与 `margin-inline: auto`；正文保持 `text-align: start`。现行阅读上限为 76ch；宽屏样张另比较 42rem、48rem 的容器上限，依据当前字体和中英文行长选定语义宽度。输入与回答共享版心轴线，不各自相对整个窗口居中。 |
| 用户消息 | 短消息按内容收缩并靠阅读列的 inline-end，气泡中的多行文字仍从 inline-start 排。75%/85% 阅读列宽度用于宽/窄样张比较；长内容允许增加可读宽度，不能为保留气泡比例把每行挤成几个字。 |
| 首次使用、主区空状态 | 短标题、简短解释与单个主动作可以作为一个整体居中，中心取可用主区，扣除标题栏、常驻输入和底栏。说明太长、出现字段或高度不足时改为从上向下的可滚动布局；不靠固定大段 padding 把按钮挤出屏幕。目录内空状态从列表起始线左对齐。 |
| 模态框 | 对整个对话框盒子做几何居中，内部标题、说明和字段按内容起始线排布。沿用 `min(560px, 100vw - 48px)` 宽度及 `min(100dvh - 96px, 720px)` 高度上限、窄屏 12px inset；固定头尾、单一滚动正文。高度或软键盘造成空间不足时保证顶部与操作区可达，不强行垂直居中造成上下裁切。 |
| 菜单、Tooltip、对象详情 | 跟随触发器、选择范围或所属边缘定位；用现有 `placeFloating` 处理翻转与移位，不为视觉对称脱离操作对象。面板从所属边缘进退。 |
| 图片预览 | 居中的是 `object-fit` 后的实际图像矩形，不是带留白的 `<img>` 元素外框。控制栏在图像视口之外保留空间，缩放以观察点为锚点，详见媒体几何。 |
| 图标、按钮与计数 | 控件盒子用 Flex/Grid 几何居中，文字与图标再按字体基线做光学校准。计数列、文件名列保持稳定起始线，不因相邻数字变化重新居中。 |
| 终端、编辑器、Diff、目录 | 内容从自己的起始边缘排布并充分利用面板宽度；长行局部滚动。阅读列的限宽不能套到这些工作区。 |

验证同时包括宽屏单面板、窄分屏、低高度窗口和长英文内容；比较的是内容轴线、可读行长与可达性，而非整个窗口看起来对称。

### type-optics

**语义字阶（Semantic Type Scale）与光学基线（Optical Baseline）。** 现行字号阶梯为 11/12/13/15/17/20/24/30px，每个页面最多使用四级；正文、控件、标题字重分别为 400/500/600。目录 13px、说明 12px，阅读正文 13–15px、行高 1.6–1.8；用角色决定字号，不给每个组件自造一套。

暗色字重采用 **Optical Weight Compensation**：对实际可变字体的 `wght` 轴比较 500→460、600→560 两组样张，再由字体方案确定；只有字体支持时才设置 `opsz`/`GRAD`，不对所有后备字体强加轴值，也不把“暗色固定减 40”当通用算法。保持 `font-synthesis-weight: none`，中文细笔画、小字号与离线后备必须可读。

行内 SVG 使用 `vertical-align` 做基线校准：14–16px 文字以 `-0.125em`、11–12px 说明以 `-0.075em` 为样张起点；在 Flex/Grid 控件里先 `align-items: center`，不能把仅对行内布局有效的属性当作已完成对齐。校准同时观察 x-height、cap-height、中文字面与图标可见轮廓，避免靠改行高补偿某一个图标。

**Text Wrapping**：短标题用 `text-wrap: balance`，稳定正文用 `text-wrap: pretty`；长路径/URL/标识符用 `overflow-wrap: anywhere; word-break: normal`，代码仍遵守原始空白和局部滚动。输入与正在增长的流式尾段不因均衡换行持续改写已读行。窄屏输入沿用 16px 下限，避免聚焦时页面缩放。

行内代码（Inline Code）的等宽字体、字号和基线与所在正文校准，使用轻背景及有限内距，不变成打断句子的独立卡片；长标识符可在展示层换行，复制仍保留原文。正文、行内代码与标点混排不因高亮或字体加载出现额外行高跳动；独立代码块继续使用自己的空白和滚动规则。

**Tabular Numbers 与 Clamp**：动态时间、用量、数量、行号采用 `font-variant-numeric: tabular-nums`；跨位数增长另预留列宽，等宽数字本身不保证 9→10 不挤动。目录标题单行、过程摘要两行、长说明三行是各角色的默认预览；`line-clamp` 只作用于可恢复的摘要，完整内容通过展开或详情可达，错误与主动作不在被裁切层内。

### geometry-boundaries

**同心圆角（Concentric Radius）**：相邻内外轮廓的关系是 `R_inner ≈ max(0, R_outer - inset)`，inset 包含两条轮廓间的实际距离。仅对几何上相套的轮廓使用此式，不把内部所有按钮都改成相同圆角。沿用当前 tag/control/row/card/sheet/composer/dialog 的 6/8/10/12/14/15/16px 角色；圆形与胶囊留给确有该语义的控件，不把所有组件变成 999px 圆角。

**视觉尺寸与命中区分离**：图标以 12/14/16/20px 四档检查，16px 为常用控件图标；保留本产品图标体系与描边比例。图标的 24 单位 viewBox 不等于新增 24px 显示档。紧凑控件命中区至少 28px、普通桌面至少 32px、触控至少 44px；较小可见图形放在更大的命中盒中，命中盒之间不能重叠。

**单闭合边界（Single Enclosure）与层次（Elevation）**：普通回答、过程文字、导航行靠留白、字阶和轻表面区分。独立输入、代码、文件对象和浮层需要边界时，由容器承担一次；内部工具栏改用 Ghost/轻填充，分组用单向 divider。输入焦点、错误、选中及真实对象边界不因此消失。微对比表面、近距接触阴影与远距弥散阴影表达不同深度，消费现有 `--surface-*`、`--lift-*`，不更换色板。

**Dual-Ring Focus**：输入外壳的 rest/hover/`:focus-within` 使用相同数量和顺序的 inset/outer 阴影层，只改变强度，不增减盒模型尺寸；键盘焦点使用 `:focus-visible` 保持独立可见。内部按钮之间转移焦点不让外壳失焦闪烁。Hairline 可以用 inset shadow 或预留透明 border，细线在 DPR 1/2 和缩放下复验；不能机械设置 `1px / devicePixelRatio`。

**动作层级与图标轮廓**：同一操作组由主动作、次动作和 Ghost 内联动作表达优先级；危险样式仅用于实际有破坏性的动作。默认、hover、按下、focus-visible、选中、禁用和处理中共享占位，处理中保留原标签或等宽反馈，不让 spinner 推动相邻按钮。图标沿用现有 SVG 目录、viewBox 与描边规则，不用字体字重数值推算 SVG 线宽；活动态不得改变外盒。装饰图标从可访问树隐藏，独立图标按钮有准确名称，选择与错误除颜色外还有文字或形状依据。

### bezier-timing

**运动令牌（Motion Tokens）与三次贝塞尔（Cubic Bézier）**。每种动效必须说明触发、属性、起终值、时长、曲线、`transform-origin`、中断和减动效终态。曲线的两个控制点定义的是时间到进度的映射；例如控制点 y=1.3 不代表物体必然超调 30%，CSS 贝塞尔也不等于能携带速度的真实弹簧。

| 语义 | 当前基准 | 必须比较的具体样本与适用边界 |
| --- | --- | --- |
| 按下与 hover | 130ms；按下回弹用 `cubic-bezier(.2,1.35,.4,1)` | 60ms 的首次反馈、`cubic-bezier(.32,.72,0,1)` 的快速到位。按下只产生小幅位移/缩放；打开浮层的触发器不缩放，以免锚点移动。 |
| 分段滑块 | 250ms + `--ease-spring`，即 `cubic-bezier(.2,1.35,.4,1)` | 分段 120ms + `cubic-bezier(.32,.72,0,1)`，比较落点清晰度和连续反向响应，不按每个页面单独挑曲线。 |
| 状态移动与折叠 | 250ms + `--ease-quint`，即 `cubic-bezier(.22,1,.36,1)` | 折叠 200ms + `cubic-bezier(.16,1,.3,1)`；仅在下述自然高度折叠范围内采用布局过渡。 |
| 菜单与面板进入 | 420ms 到达节奏，菜单沿用现行 250ms | 200–300ms + `cubic-bezier(.165,.84,.44,1)` 的减速进入。菜单由触发点展开，边栏从边缘移动；文本面板不作明显过冲。 |
| 小型完成标记 | 当前小控件 spring 曲线 | `cubic-bezier(.34,1.3,.64,1)` 的单次轻反馈，仅用于 check 等小图形；不能套到长段文字、弹窗正文或整个工作台。 |
| 新增文字显现 | 本任务限定的新增表达 | 90ms + `cubic-bezier(.215,.61,.355,1)`，透明度 0→1，模糊逐渐到 0；具体批次与边界见流式正文。 |

校准样本不是另一套长期设计系统：在同一真实组件、同一内容下与现行基准对照，选定后改原语义令牌和说明。640ms 的既有特殊时刻不变成每次响应的等待时间。`transition` 显式列属性，不用 `transition: all` 让尺寸、颜色和位置无意一起动；连续操作合并到最新目标，不等待前一段播完。大面积遮罩只淡入淡出，历史恢复和后台刷新不重播入场。

**2026-10-23 菜单快速关闭短合同（VUX-36、VUX-22，实施中）**：现役 `details` 菜单在入场尚未结束时关闭，不能继续变亮或跳到透明；从当前可见状态沿同一条可中断的 opacity/transform 过渡退出。保留进入 `--dur-move` 250ms、退出 `--dur-hover` 130ms 及原曲线，反向时由浏览器按已有进度缩短过渡；关闭立即禁止点击，内容盒只按现有 130ms 关闭时钟保留，随后释放。底栏导航菜单保留朝触发点的 +4px 起点，其余保留 -4px；无新增动画主人、脚本或关键帧。范围只有 `craft-finish.ts` 的现有 `details` 菜单规则、对应 README 和 `menu-exit-motion.e2e`；完整菜单生命周期样式与选择器由已有 `styles/motion.ts` 拥有，craft 层在原位置装配，插入顺序和生成 CSS 保持不变；普通折叠的自然高度、非 details 的 popover 与 Assistant 原路径不变，减少动态效果和自动化静止时，正文可见状态仍立即到终态，内容盒沿已有关闭时钟释放。

验收保留原八种菜单 host、动态父 class 与普通折叠高度断言；正常关闭以前一段动画实际完成为前置，不用墙钟等待冒充完成。另从入场早期、结束前关闭，逐帧验证 opacity 非增、仍有可见退出过程、禁止点击和内容释放。真实浏览器的 `has-anchors` 原 3ms 插入门槛与页面资源门保持，CSS 必要增量先实测评审再登记精确一次性上限；未取得新 Linux 结果前只报告本机工程证据。

### spring-interruption

**阻尼振子（Damped Harmonic Oscillator）**用 `m·x″ + c·x′ + k·(x - target) = 0` 描述，阻尼比 `ζ = c / (2√(mk))`。`ζ < 1` 可有过冲，`ζ = 1` 临界阻尼，`ζ > 1` 不振荡。只有手势释放、变目标连续续接等需要速度信息的路径才需要真实弹簧；普通已知起终点仍可用 CSS。

| 参数样张 `(k, c, m)` | 设计含义与采用条件 |
| --- | --- |
| `(600, 30, 1)`，ζ≈0.61 | 小控件回弹；观察是否过度弹跳，不用于阅读文字。 |
| `(320, 28, 1)`，ζ≈0.78 | 小浮层的短距离落定；内容较重时增加阻尼或使用无过冲曲线。 |
| `(380, 18, 1)`，ζ≈0.46 | 明显弹性完成标记的对照样张；只在小图形且单次反馈有价值时采用，不作默认。 |
| `(1200, 80, 0.1)`，ζ≈3.65 | 面板松手后的无过冲收敛对照；拖动过程中仍直接跟随指针，不把弹簧迟滞塞进指针位置。 |

不得把参数名、阻尼比或固定“收敛毫秒数”当作体验证明；收敛由距离、初速度与停止阈值共同影响。重定向（Retargeting）从当前视觉位置及可用速度继续；Escape、取消和减动效切换终止旧动画并落到确定状态，动画回调不再次提交动作。沿用现有运行能力，不为这些样张默认添加新依赖。

### disclosure-segmented

**渐进披露（Progressive Disclosure）**先呈现能判断状态的摘要，再按用户操作显示明细。组头是具有 `aria-expanded`、`aria-controls` 的可操作触发器；箭头、摘要和内容状态一致。后台运行不能强制展开或锁死折叠，执行完成也不能自动收走用户正在读的内容。

**CSS Grid 0fr→1fr**用于自然高度折叠：外层切 `grid-template-rows`，其直接子层 `min-height: 0; overflow: hidden`，实际 padding 放入更内层内容盒。箭头旋转与内容透明度共用同一状态；不用任意 `max-height: 9999px` 假装动态高度。尺寸持续变化或途中反向时，使用现有尺寸测量/动画能力续接当前高度；关闭后明细不可聚焦，若焦点在明细内，先归还组头。只有此类必要局部高度过渡进入本任务允许的动效范围。

**实测滑块（Measured Indicator）**的几何由真实选项盒子决定。等宽、固定间距时，轨道内宽 W、内边距 p、间距 g、数量 n，单项宽 `w=(W-2p-(n-1)g)/n`，第 i 项起点 `x=p+i(w+g)`；Molis 当前 p=3px，不把其它样张的 2px 硬写进业务。内容宽度不等、徽章或语言切换时，测选中项相对轨道的实际矩形，用 `ResizeObserver` 和字体完成事件更新，不再用等分公式。先批量读尺寸后写 transform/width，快速切换只追最新选择；空组、选项删除和无脚本状态仍有准确选中表达。

### stream-rendering

Coding 的流式状态、节点身份与恢复以 [CHO-14](../coding-harness-optimization/spec.md) 为准；本节将显现、排版和渲染成本要求接入该生产路径。共享能力供其它表面消费，不在 VUX 再建一套 Coding 消息渲染器。

**字素显现（Grapheme Reveal）**以 `Intl.Segmenter(..., { granularity: "grapheme" })` 或已有同等能力分段，不能用 `split("")` 把代理对、组合音标、emoji 序列拆开；不支持时直接显示完整新增片段，不新增一套存储格式。

显现样张使用单次 90ms、`cubic-bezier(.215,.61,.355,1)`、opacity 0→1，并比较 blur 6px→0 与较轻幅度；6px 是对照上限，不得施加到整段已读正文。单字级联 30ms 只用于低速短片段样张，生产展示不得为每个已收到的字累加等待。高吞吐时按短片段合并，待显现队列一旦落后就立即并入最新可读正文，不让模型结束后界面仍在慢慢补字。持续模糊整篇、永久逐字 span 和全局 `will-change` 均不采用。

**稳定块与流式尾块（Stable Blocks / Streaming Tail）**：原始消息由现有 owner 保存；展示层将已稳定的段落、列表、代码块保留为有稳定身份的节点，只更新未闭合尾块或实际变更块。先由现有 Markdown 渲染器确定结构，再在允许显现的文本节点中处理新增字素，不跨 HTML 标签、链接属性或代码语法直接切字符串。代码正文默认立即可读，块级到达与语法高亮更新分开处理。

**按帧合并（Frame Batching）**：一帧内到达的多个增量合成一次 DOM 提交；停止、错误、授权和用户输入及时处理，不能等装饰队列。纯追加沿现有 delta 合同前进；全量快照发生回改时定位受影响块，不能继续盲追加。生成结束与历史恢复使用同一语义渲染结果，清理临时动画包装而不丢失选区、复制内容、查找命中或可访问名称。屏幕阅读器只收到有意义的状态/内容更新，不因每个动画字素重复播报。

### composer-mentions

**内在尺寸（Intrinsic Sizing）**：输入优先利用 `field-sizing: content` 的可用能力，或沿用现有 `scrollHeight` 测量；先还原测量高度再算内容高度，避免只增不减。约束是 `H=min(max(contentHeight,Hmin),Hmax)`，达到上限后内部滚动且光标可见。两行加必要内边距作为多行样张起点；240px 与 24rem 作为中/高视口的上限对照，最终由可用面板高度限制，不能固定吃掉大半窄窗。常驻底栏输入继续沿用其紧凑角色，不搬成大号首屏输入框。

**IME Composition Guard**是 [UIV §4 的输入合同](../unified-input-voice/spec.md) 与共用输入框的职责；本任务在合成输入中验证浮层、布局与动效不破坏其事件处理、光标或草稿，不另写合成状态判断或按键分支。

**触发范围（Trigger Range）**由 UIV 共用输入框提供，候选浮层和引用片消费其范围、光标位置与版本；本任务不自行解析一份草稿或接管按键。按键与发送语义见 [UIV §4](../unified-input-voice/spec.md)，建议选择与引用定位按第 2 节的 UIV 依赖验收；输入框的几何变化不得让候选锚点、引用身份或原光标错位。

附件身份及添加、处理、就绪、失败与取消由 [UIV owner](../unified-input-voice/spec.md) 提供；类型图标、名称、进度/错误和移除各有稳定位置。新增附件推动邻项让位，移除时邻项收拢，状态变化保持同一条目的视觉身份。重试、取消与迟到结果在该 owner 的恢复路径验证，失败反馈与工具执行状态分开。

**附件形态与接收区（Tile / Chip / Drop Target）**：需要辨认缩略图的独立预览可使用磁贴，128×96px 是对照样张；输入旁的待发送材料优先使用紧凑条目，长名称、失败原因与移除仍可达，不强制所有文件变成同尺寸卡片。已有拖入入口区分接近、可接收、不支持和处理中，突出真实落点而非整页持续发光；穿过子元素时按相关目标或进入计数维持反馈，真正离开、drop、Escape 或窗口失焦后清除。文件选择、拖入和已有粘贴入口复用同一附件处理路径，视觉变化不新增文件类型支持或改变去重合同。已有行内引用控件的方向键、删除与撤销遵循其编辑语义，不把引用的显示标签当身份，也不让移除按钮顺便触发打开。

### assistant-information

**信息主次与 Scope & Provenance**：主区先回答“结果是什么、现在需要我做什么”；过程是按任务关系分组的次级信息。工具调用前的解释仍是普通正文，不被吞进工具输出折叠区；工具结果、固定成果、工作文件和过程项分别保留其身份。

六类分组使用同一个 Disclosure/明细行结构，而非六个固定卡片：工作环境显示项目/目录/仓库范围；上下文显示待发送/本次实际使用/历史引用；连接与工具显示连接、授权、可调用性；产出显示对象与版本；变更显示对象、影响和应用状态；后台任务显示当前阶段及是否等人。组头右侧摘要在数量、关键名称与异常之间按相关性选择，不堆所有徽章；展开明细顺序为类型图标、名称、辅助信息、状态/操作。长名称保留主阅读空间，操作列不随名称长度漂移。

**真实计量（Measured Usage）**只消费已确认口径的 numerator/denominator。若用环形进度表示比例 q，`q=clamp(used/capacity,0,1)`、周长 `C=2πr`、`stroke-dashoffset=C(1-q)`；分子与分母必须属于同一模型、范围和时间点，capacity 必须为正且统计有效。展示明确是已用还是剩余，未知不画伪 0%；缓存读写、输入输出、上下文占用与账户额度不直接混加。优先复用现有状态环/计量表达；模型与容量从共同目录读取，不新建静态名单或前端账本。

**能力驱动的模型选择（Capability-driven Model Selection）**：已有模型选择器显示当前可用模型与真实能力，推理档位等联动选项依目录合同呈现，不由模型名字猜测。正在执行时，界面同时区分本次实际模型与下次发送的选择；切换只按现有合同影响后续执行，不改写历史用量和执行信息。不支持的选项、失效模型、设置保存失败有明确反馈，不能静默替换模型并继续显示原选择。这里只精修已有入口，不另建模型配置产品。

### feedback-lifecycle

**状态驱动反馈（State-Driven Feedback）**：准备、等授权、已提交、运行和终态来自真实 owner。装饰动画只反映状态，不决定状态；批准按钮完成后进入“已提交/运行”所依据的是实际回执，不能用固定延时变成成功。处理器尚未开始就被拒绝时沿用平台诊断合同，不新增业务失败记录。

**复制衰减（Copy Decay）**：`idle → copying → success/error`；只有 `clipboard.writeText` 成功才显示已复制。成功标记以约 2.5s 静默保持为样张，再用短透明度过渡返回；重复复制按最近一次有效结果续期，旧计时器不能覆盖新失败，卸载时清理。成功与默认文案占同一预留宽度，失败提供准确反馈而非伪成功对勾。

**占位几何（Skeleton Geometry）与等待标记**：占位保留终态的主要行、图标和操作布局；短操作不闪一帧骨架，较慢操作先给真实受理反馈。复用现有状态环，同一操作不同时循环三点、环、扫光和呼吸。若某处确需三点表达，可用 1.9s 周期、150ms 相位差的样张验证，但不得替换全平台现有状态语义；等待结束、隐藏或减动效时停止装饰循环。减少动态效果仍显示文字/静态图形状态。

**截止时间（Deadline）**：限流倒计时由运行时截止时间与当前时间算剩余值，后台恢复重新计算，不靠每秒递减累积误差。重试、取消、停止和刷新恢复遵循原执行 owner 的幂等及状态合同；前端不私加指数退避、定时重发或新的授权级别。

**文字与操作的收尾**：已有消息操作栏使用稳定位置；细指针可在 hover/focus-within 时显现，触控和键盘始终有入口，不在每次流式更新时插入/删除整栏。流式尾标只指示当前仍有输出，不能插入复制正文或成为独立播报内容；若采用，2px×1.15em 是尺寸对照，完成、停止、失败和历史恢复均移除。不能为了复现尾标而增加第二个“正在运行”的循环标记。

### drag-split

**移动死区（Dead Zone）与指针捕获（Pointer Capture）**：按下先记录起点与原状态；鼠标位移 `hypot(dx,dy)` 约 4 CSS px 是越阈值样张，越过前仍保留点击/选字语义。拖动后识别 pointerId、调用现有捕获机制并区分释放、取消、失捕获、失焦；触控按实际手势选择 `touch-action`，不能让整个列表 `touch-action: none`。

**直接操纵与 FLIP（First, Last, Invert, Play）**：被拖对象跟随指针，不加位置 easing。列表邻项或附件让位可先读变化前后的矩形，再用逆向 transform 过渡到新布局；稳定 id 保留 DOM、焦点和选区。预览位置、占位与最终落点一致，取消恢复完整原状态，落定后的 click 不误打开对象。无需位移的更新不加 FLIP。

**分屏 Clamp 与吸附滞回（Snap Hysteresis）**：可用宽 W、两侧最小尺寸 Lmin/Rmin，对比例 r 取 `clamp(r,Lmin/W,1-Rmin/W)`；若 `Lmin+Rmin>W`，先进入既有窄布局，不能对倒置的范围硬夹取。吸附的进入区间小于退出区间，避免边界来回抖动；双击回本场景默认，只有对称场景才是 50/50。拖动时按帧写必要布局，不能让宽度过渡追着鼠标跑。

**跨 iframe 连续手势**：复用宿主捕获/遮罩方案；透明护罩只有实际截获事件、或子 frame 的 pointer events 被暂时停用才有作用，`pointer-events: none` 的护罩自身不能阻止事件落入 frame。分割条在按下候选期就启用该保护，使第一次跨 frame 移动仍能送回宿主；未越过约 4 CSS px 时比例和持久化均不变，点击与双击保留。结束与任何取消路径都恢复原值、光标与选区规则，遮罩不得残留。键盘调整使用 separator 语义与方向/数值/范围，保留等价菜单动作；持久化失败可见且可恢复。

### scroll-ownership

**底部跟随（Scroll Pinning）**是显式的 `following / detached` 状态。距离 `d=scrollHeight-scrollTop-clientHeight` 用来判断是否接近底部；当前实现的 48px 是现状基准，40px 是窄容差对照，不能在不同代码里各写一套。用户滚轮、触摸拖动、阅读导航或选字立即解除跟随；程序滚动不能被误记成用户操作。

**冷却闩（Cooldown Latch）**以最近用户操作的单调时间戳判断，150ms 只用于抑制紧邻事件的误触发，冷却结束不自动把 detached 改回 following。恢复跟随来自主动返回最新、明确发送行为约定或用户确实回到底部；离底有新增内容时入口稳定可达。流式跟随每帧至多一次直接定位，用户主动返回才可用一次 smooth，不为每个 token 排平滑滚动。

**阅读锚定（Scroll Anchoring）**保存可见内容的稳定身份及其视口偏移；图片解码、代码展开、补载历史或输入增高后，根据该锚点的新旧偏移调整。浏览器原生 anchoring 与应用手动补偿只选一个负责同一次位移，避免双重补偿。尾部缓冲按实际剩余视口计算，不能全局固定 35vh 空白；窗口变化后仍能看到最后一行与返回最新入口。

### overflow-fade

**多点非线性透明度遮罩（Multi-stop Alpha Mask）**只提示确实存在的溢出方向。28px 作为标本中的羽化距离；位置/透明度样本为 `0/0、15%/.05、30%/.15、45%/.30、60%/.50、75%/.70、87%/.85、100%/1`，共八个采样点，不以名称中的“几档”代替实际值。它是局部 mask，不是给背景盖一条渐变色带。

**Overflow Sensor**比较 scroll/client 尺寸及当前位置，带 1–2 CSS px 的舍入容差；内容、字体、容器和方向变化都重新判断。触到该方向的边界就撤去那一侧遮罩，初始无溢出时两侧全清晰；水平书写方向按实际滚动坐标归一。高频滚动只在边界状态改变时更新类或变量，不重渲染整棵列表。焦点环、错误、关闭按钮和主操作留在未被 mask 的层；强制颜色模式保留明确边缘提示或原生滚动条。聊天主阅读区不默认铺全局渐隐。

### media-affine

**实际图像矩形（Object-Fit Rect）**：可用盒宽高 W/H、图片自然宽高 Nw/Nh，在 `contain` 时 `s=min(W/Nw,H/Nh)`，渲染尺寸为 `(Nw·s,Nh·s)`；居中留白为 `(W-Nw·s)/2`、`(H-Nh·s)/2`，再叠加 border/padding。若 `object-position` 非中心，按真实位置计算；`scale-down` 再限制 s≤1。零尺寸、未解码与加载失败不参与变形测量。

缩略图为 `cover` 时使用 `s=max(W/Nw,H/Nh)`，按实际 `object-position` 定位后与内容盒求交，保留被裁切的源区域；到完整预览时不能把裁切片拉伸成整张图片。测量先确定 content box，再转换到同一视口坐标系，避免重复计入 border/padding。加载前预留已知宽高比，解码失败显示原位错误和已有重试，不让布局突然塌陷。

**共享元素转场（Shared Element Transition）**连接来源图像与已有预览，不连接整张留白容器。记录源/目标可见矩形、裁切和圆角；可用现有 FLIP/平台能力，`View Transitions API` 只是满足环境时的实现选项。转场名称在作用域内唯一，必要截图状态在对应生命周期准备好，结束/取消都清理临时样式；无来源、来源被虚拟化/移除或减少动态效果时直接切换/轻淡入，关闭仍可返回合理位置。

**仿射缩放（Affine Pan/Zoom）**是本任务在媒体预览中新增的观察点缩放与有界平移；已核对的现状只有原始尺寸/适应窗口切换。使用同一坐标系中的观察点 p、当前平移 t 与倍率比 `c=newScale/oldScale`：新平移 `t′=p-(p-t)·c`，x/y 各自计算后按图像与视口边界约束。滚轮 `exp(-delta·sensitivity)` 是平滑倍率样张，先处理 deltaMode 并限制范围；双指以中心点为锚，双击在观察点放大/回到 fit。图像小于视口时该方向居中，不保留任意漂移。仅当前媒体接管手势，不拦浏览器整页缩放；解码与相邻预载有界，关闭释放引用和监听，不要求新增画廊跑道。

### preview-readiness

**分阶段就绪（Readiness）**：已有预览区分别表达宿主外壳已打开、所需资源载入中、内容可操作、内容完成以及失败/超时。iframe 的 load 事件不自动等于内部内容就绪；沿用现有挂载合同，缺少就绪证据时不能展示“已完成”。资源失败保留对象、版本和已有重试入口，重试只加载失败资源，不再次执行生成、写入或授权动作。独立插件资源沿用每项最多等待 10 秒的现行合同；其它预览使用各自 owner 的时限，不全局套一个新定时器。

**实例与版本（Instance / Revision）**：来源、版本步进、已有 Code/Preview 切换及关闭入口指向同一个实际对象版本。切换版本或重载后旧实例的 ready/error/resize 消息不覆盖新实例；挂载、重载和卸载沿用既有生命周期，不因标题或尺寸变化重建有状态的 iframe。内层有自己的滚动边界，内容宽度不撑破外层分屏；窄布局和返回主区仍保留当前对象定位。

**受约束的嵌入（Sandbox / Message Channel）**：调用现有平台的来源、身份、载荷及动作授权校验，不复制第三方权限字符串或通道。`event.isTrusted` 和消息自报的 `hasUserActivation` 不能单独证明业务授权，Origin/source 检查也不能替代动作权限。来源隔离、打开链接/下载的用户操作约束、错误及退出处理遵守现行安全合同，本任务不扩大权限。无支持渲染器或嵌入失败时使用 owner 已有的查看/下载/错误路径，不落成无说明白屏。

### code-diff

**行高共轨（Shared Row Geometry）**：行号、符号和代码用同一行布局或同一组 Grid 轨道，不能各自独立堆叠后猜相同行高。默认代码 `white-space: pre` 并局部横滚；允许折行时对应行号随该行真实高度伸展。Unified 保留旧/新行号与增删符号；Split 给另一侧缺失内容留同高占位，切换保留行/变更定位。`tab-size`、字号、行高和等宽数字共有，字体验证包括后备与缩放。

**增量消费（Incremental Feed）**：区分追加、回改和完成。纯追加只交新增 delta 给现有渲染/高亮路径，保留解析状态和未完成尾行；全量快照只有前缀连续时才能提取后缀，回改则从受影响边界重新解析。代码围栏未闭合、Diff hunk 头未完整和文件头 `---/+++` 都有专门结构语义，不按单个 `+/-` 把所有头部当内容行；不能把 `useMemo` 包裹全文重解析称为增量。

高亮与 Diff 计算若经剖析确为长任务，才交给 Worker 或分批调度；结果带内容版本，过期结果丢弃，取消能结束待处理工作。保持现有 CSS 作用域；只有真实样式隔离边界需要时使用 Shadow DOM，不强制所有代码块换容器。语法高亮不得阻碍先显示可读原文，复制按原始代码/补丁的明确模式执行，不从装饰 DOM 抓文本，不 `trim` 原始首尾和空行。复制反馈遵守 Copy Decay。

**2026-10-23 修复短合同（VUX-33，实施中）**：大量短行代码的累计 inline 排版使后续布局读取超过原 50 ms 门槛。普通 Coding 代码块从第一片起按完整行边界形成约 8,000 字符的布局块；后续片只更新受影响的块，原文立即完整可读，纯追加保留前块、前面的着色节点及选区。仍由 `createCodingCodePaint` 持有 DOM 与作业状态、共享 `growCodeTokens` 决定颜色，复制读取现役原文来源。回改从受影响边界重新着色，替换/无语言/超过现有 400,000 字符上限终止旧作业，移出页面不继续写；不增加 Worker、tokenizer、缓存主人或隐藏屏外内容。Diff 行预算与 Assistant 的现役路径保持。物理长行保持同一显示行，行内着色仍最多按现有 16,000 字符推进一片，未着色尾部始终可读；其单行布局成本仍是现有边界，不改颜色或上限。

本刀允许修改 Coding 的现役 painter/必要样式、`tests/code-scale.e2e.test.ts`、`tests/code-incremental.e2e.test.ts` 及直接行为夹具、DESIGN 与本段。验收仍保留完整页面 RAF 的原 50 ms 门槛，并把本片引起的布局读取计入；颜色改以独立 DOM 文本/颜色投影逐字等于共享 tokenizer 的整段结果，不再把平铺 HTML 当作产品合同。同时验证 `textContent`、空行/CRLF/制表符、跨块多行 token、原生选区、滚动几何、小块连续长到大块、前块/前叶节点与复制来源，保留现有重开、回改、断开及上限检查。一次整体 build 后跑原 code-scale/code-incremental 与直接新增行为测试；Linux 原门仍是交付检查。仓外可见 300,002 字符对照中，8 KB 块的 4 倍 CPU 降速仍有一次 62.6 ms 全页回调，不能宣称所有降速情形已达标。

布局块也保留原 `pre` 与内联 `code` 共同形成的行盒：外层沿用原行框字体，内层保留代码字体，不能因拆块改变后备字体、字号不同时的行高、制表符位置或滚动范围。小块的首次着色可能在挂接前已完成；仍沿同一作业的下一帧在接入文档后解析字体，旧作业或已断开的节点不能回写，解析字体不增加观察器。`tests/code-layout.e2e.test.ts` 保留平铺参照和原断言，并覆盖字体不同、真实 Coding 的 13px/12px 字号与挂接前的小文本。

**2026-10-29 首次布局与着色分帧（VUX-33、VUX-36，用户 2026-10-29 定，T-281）**：大块（超过 16,000 字符）放入完整原文后，等浏览器把整块原文第一次排好（第一个布局块上的 `ResizeObserver` 在布局之后回调，只认非零高度——Chrome 对还不在页面上的节点也会先报一次 0×0——认到即断开；作业被替换或终止时断开），在下一帧才开始第一片，首次布局那一帧只排原文、不夹带着色。没排版的块等它排好再开始：不在页面上的挂上之后、`display:none` 的显示之后、浏览器跳过渲染的 `content-visibility:auto` 子树（Coding 屏幕外的轮次，`.coding-turns > [data-run]`）滚到附近之后才着色；以前是第一帧照跑，不在页面上的作业直接丢掉、挂回去也一直没颜色。本机核过：屏幕外 `content-visibility:auto` 里与 `display:none` 里的 60,000 字块 1.5 s 内 0 个着色片段，滚到附近、显示出来之后着色完成；`tests/code-layout.e2e.test.ts` 的「a large block put in before it is on the page…」（RAC-2077）证明挂上之后着色完成，在旧调度上红。`tests/code-scale.e2e.test.ts` 的着色帧照旧每帧 <50 ms，计入各自的强制布局，并收进页面对每片插入的观察者（等一个微任务）；整块原文首次布局单独量（放入、观察者、强制布局一次，不含帧间空闲），上限 150 ms，依据与数字见 `specs/archive/system-review-fixes/spec.md` 的 SYS-49。证据（不入库）：把 VUX-36 修掉的旧焦点漫游（每个插入的文字片段搜一次父元素）临时放回，着色帧里的观察者从不到 1 ms 涨到 14.5 ms；再让 painter 在放入时整块着色，首次布局从本机 16–20 ms 涨到 926.6 ms（线性焦点漫游下 304.1 ms），都超过 150 ms，而只看放入脚本的旧检查（<50 ms）在两种情形下都只有约 34 ms、看不出来。

### adaptive-focus

**容器查询（Container Queries）**以所属面板 `container-type: inline-size` 判断可用空间，不只看浏览器宽度。工具栏按“快捷键/说明 → 可恢复长名称 → 低频按钮进菜单 → 窄布局”逐级收缩，主动作/停止/取消/待处理入口保留。用 576/480/384/320px 及分段 254px 作为压力标本检查顺序，实际断点由当前字体、中英文长文案和命中区确定，不机械复制阈值或缩小整页。

**焦点漫游（Roving Tabindex）**每个语义组保留一个 `tabindex=0`，其余 -1；方向键、Home/End 按菜单/Tab/选项的语义导航，Tab/Shift+Tab 进出组。PageUp/PageDown 只在该组件确有分页语义时接管，不全局映射成首尾。跳过禁用/删除项；空组、筛选、重排后焦点回到合理可见项。`focus({preventScroll:true})` 后只在必要时局部滚入，不拉动整个页面；焦点移动不触发有副作用的动作。

**浮层避让与焦点归还（Focus Return）**：以现有定位函数计算触发器 rect、视口边缘和裁切祖先，按允许方向 flip/shift；transform-origin 与真实出现方向一致。Tooltip/子菜单允许指针跨越小间隙，触控有点击入口。模态按现有焦点陷阱限制导航，关闭归还调用者；调用者不存在时选合理父级入口，隐藏内容不可聚焦。macOS 标题栏拖区排除按钮、Tab、输入、分割条；后台工作与预览初始化不主动调用窗口聚焦。

**模态与嵌套浮层（Modal / Topmost Overlay）**：使用共享层级与遮罩，不逐个组件加大 z-index。模态有可访问标题、合适的初始焦点、真实焦点循环和不可交互的背景；`aria-modal` 本身不能代替这些行为。确认前说明对象与影响，破坏性动作不自动聚焦到提交按钮。只有最上层处理 Escape/外部点击，关闭子菜单不连带关掉父对话框或触发底下的按钮；输入法仍优先。点击遮罩是否可关闭、编辑草稿是否保留、提交中能否退出沿用各动作合同，不全局“一点就关”。关闭界面与取消任务分开；异步确认不能在调用开始时就关闭并报成功，失败保留原输入及准确重试入口。

### render-lifecycle

**分离读写（Read/Write Batching）与局部失效**：一次更新先读取需要的矩形/滚动值，再统一写 class、CSS 变量或节点；避免在循环中反复读布局、写样式、再读布局。持续输出、计数、工具状态只更新所属对象；稳定 key 由对象身份决定，不能随 index、时间戳或文本长度变化。保留编辑器、终端、iframe 等有内部状态的实例。

**按需初始化与生命周期**：未打开的重明细不提前恢复全历史，隐藏表面暂停无用渲染/观察/轮询但不取消真实后台任务；返回时补齐状态。每个监听、Observer、rAF、计时器、请求和临时动画都有对应释放位置；请求取消与会话切换后旧结果不能落入新表面。虚拟化或 `content-visibility` 仅在规模与实测支持时采用，查找、复制、选区、锚点定位和无障碍不能被当成可丢弃能力。

**同源标本与证据**：组件板直接调用生产组件，每个机制展示默认/边界/中断/减动效以及容器变化；同一块内容可切换参数对照，而非同时循环所有动画。正文样张包含中英文、emoji、长 URL、代码围栏、表格、复制失败、附件部分失败和任务状态交错。首个反馈、可操作、完成三个时间点分别标注；计算/解析/布局/绘制的耗时分开定位，网络与模型等待不归给 UI，测试禁用动画的结果不能证明动画性能。实现选定的规则同步写回 DESIGN、原组件说明和插件创作台，不留仅在本书里存在的第二套设计系统。

## 6. 模块边界、输入输出与取舍

| 边界 | 输入与输出、允许改动 |
| --- | --- |
| `packages/design-system` | 现行语义角色和真实组件状态 → 共有样式、行为、规格板标本；沿用 HTML Slot，不迁 React、不在业务端重画组件 |
| `apps/workbench` | Host 的视图与对象引用 → 助理分组、阅读、输入、浮层、分屏与生命周期；不写业务库，不把展示状态当执行事实 |
| `apps/local-host` / `horizontal/agent-host` | 现有 owner 公开查询与 Runtime 状态 → 准确视图/上下文/用量及必要性能改善；模型仍仅经 Agent Host，不复制账本或前端重试策略 |
| 插件 / `packages/ui-host` | 宿主共有表达与插件事实 → 正确挂载、释放、预览、状态呈现；不跨插件 import 实现 |
| `packages/contracts` / `packages/plugin-sdk` | 仅真实新增共享合同才改公开形状；作者可运行工具归 SDK，只依赖 contracts；版本/快照按现行规则 |
| `apps/desktop` | 现有宿主状态 → 安全留白、焦点与嵌入恢复；不改安全边界，不触真实 Home |
| 规范与插件创作台 | 已验证的公共规则 → 唯一可消费指导与校验；更新原入口，不复制整本规范 |

阶段顺序是基线与高保真可操作切片 → 阅读/字体/几何与确认卡顿 → 助理/输入/引用/附件 → 拖拽/分屏/滚动/媒体 → 消费者与恢复/性能/文档收尾。切片不构成新审批关卡。只有实际依赖和独立验证边界出现时才拆子任务，不预建进度系统。

页面资源预算按[现行决定 #17](../archive/repository-anti-corruption/spec.md)执行。上述每个阶段对每个受影响资源的默认净增长预算为 0 B，先在同一资源省回；这是默认控制值，不是承诺所有新增能力必然零成本。必要且省不回的增长在对应实现 PR 逐项列出基点大小、实测大小、增量、功能理由及已试省法，评审后用 `tooling/gates/page-asset-allowances/` 中的任务独立增量许可一次性放行，合入后从实际构建重新比较；单个资源一次增长超过 10 KB 或新增资源先问用户。未有实测前不预批增长额度，不以某个资源缩小抵消另一个资源超额，也不为守预算删掉约定体验。

实现取舍：CSS 能表达的已知起终点不用新动画库；需要保留手势速度再考虑真实弹簧；虚拟化、Worker、解析器等以实测需要为依据。字重数值、90ms、4px、40px/150ms 都是试验起点，最终参数以阅读质量、手势准确性、状态连续性和性能验证确定，参数接近候选值不代表完成。

#### Coding 原文来源设计（待 SDK 合审）

**2026-11-11 已实施，以下是历史设计记录：** 用户选 B1，SDK `/rich-text` 已换 Micromark + GFM；Marked 18.0.11 的原文限制不再适用。C 在 `03695c2691` 合审，最终头待补（见 `batches/27.md` 收尾检查）。

本次核对使用仓库固定的 Marked 18.0.11。SDK 入口当前先 trim 全输入，lexer 将 CRLF 和 CR 化为 LF，默认 fenced code renderer 强制输出一条末尾 LF，list 末项还会 trim、扩展 tab。预期是顶层及嵌套围栏里的逻辑代码保留去掉 Markdown 结构前缀后的原字符。封闭时去掉围栏开头的换行与闭合前的一个分隔符。开放到输入末尾时保留末尾实际分隔符。开放在嵌套容器结束时，退出该容器前的一个分隔符归容器，围栏里的先前空行保留。实际示例使用这里写出的可见转义表示行尾。

| 原输入或场景 | 正确来源 |
| --- | --- |
| `~~~~ts\nx`、`~~~~ts\nx\n`、`~~~~ts\nx\n\n` | `x`、`x\n`、`x\n\n` 三份不同原文。闭合紧随末行时，`~~~~ts\nx\r\n~~~~` 的正文是 `x`。 |
| `~~~~ts\r\nrepeat\r\n\r\n~~~~` 和 `~~~~ts\nrepeat\n\n~~~~` 各出现一次，其前另有 HTML 块和四空格缩进代码，内含同文假围栏 | 两个真实 fenced token 的规范化 `raw` 相同，原文分别是 `repeat\r\n`、`repeat\n`。HTML 和缩进代码须保留原 Marked 行为。全局按文本搜索无法分辨。 |
| `- > ~~~~ts\r\n  >   \tconst row = 1;  \r\n  > \r\n  > ~~~~` | 去掉结构前缀后是 `  \tconst row = 1;  \r\n`。实际 Marked list 会把这条正文里的 tab 扩为四个空格，token 文本无法还原。 |
| `> ~~~~ts\r\n> x  \r\noutside` | 引用里的代码是 `x  `，容器最后分隔符归外部段落边界，`outside` 继续是正文。 |

一个限于顶层围栏的实现可以在实际 Marked fences tokenizer 命中时用规范化根输入长度减去 tokenizer 收到的剩余串长度确定起点，再由同一 matcher 的正文范围和原行尾索引切原字符。保留现有 prose 的 trim，只有 matcher 识别为开放且消费到根末尾时，从原输入侧表恢复尾部。用一份纯函数 renderer 替换该 token 的正文，仍过现有 HTML 清洗，最后从已安全转义的围栏正文序列化 CR。它能解决已复现的顶层缺口。深层 tokenizer 收到的是去前缀、换行归一及扩 tab 后的合成字符串，缺少对回原输入的位置。实现嵌套原文须在真实 Markdown 解析器产生 token 时传播原始位置及结构前缀边界，或者使用已有源位置的解析器。前者将依赖 Marked 的多处 list、blockquote 重入、懒延续和 trim 实现。后者需要核对 Feed、Coding、外部插件的 Markdown 差异及依赖成本。未选定前暂缓 SDK 代码。批准后用真实 DOM 和剪贴板核各种行尾、缩进、空行、闭合、回改，另外核 `</code>`、字面 `&#13;`、`<script>` 与恶意语言标签只作为数据。SDK 公开签名、动作及路由形状可以保持。
