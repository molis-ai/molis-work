# Molis Work 功能全景

最近更新：2026-10-19（第 1 节加"按开场的四句看"）· 依据 main `63639a764`、7 个开放 PR、35 份活跃 spec 与 BACKLOG。成熟度标签见 [README](README.md#成熟度标签)。

这是 Molis Work 能做的每一件事：已发布的、main 上的、分支上的、只在 spec 里的，都在这里，各自标清走到哪一步。写介绍、挑场景、排演示都从这里取。编号 `F-xxx` 沿用[功能盘点](research/2026-10-18-功能盘点.md)，那里有每一项的文件、动作 id 和测试依据；分支和规划项的依据在[分支补盘](research/2026-10-18-分支补盘.md)和[spec 盘点](research/2026-10-18-spec盘点.md)。

**"已发布"指什么**：目前唯一的公开正式版是 2026-09-11 的 GoalBoard v0.2.0：旧产品名，只有源码、没有安装包，MIT 许可，main 打不开它的数据。它包含 Goals 的要求、本人验收、决定请求与记录、约定变更需人决定，五家 Runtime 接入，和 `goalboard_v1_*` 专用的 MCP 工具。本文标"已发布"的行只指这一版里已有的部分，对外写成"已发布 · v0.2.0（源码，当时名 GoalBoard）"。按客户端逐项授权动作的对外接入、现行的 `molis_work_v1_action_*` 工具名、菜单栏胶囊（桌面 App 没有公开安装包）、目标看板、"记一笔"、共用问题卡、GitHub 与 Gmail 账号来源，都不在这一版里，标 main。

## 1. 按价值支柱看

### 按开场的四句看

开场（[产品介绍第 1 节](产品介绍.md#1-口号与开场)）先讲信念，再讲四句"你的"。每一句由哪些功能撑起来、最弱一环在哪：

| 开场的一句 | 撑起它的功能 | 最弱一环 |
| --- | --- | --- |
| 你的工具，长成你的样子 | 项目里按需添加插件（F-132，main 可用）；PPT、Forms、Dataset 等现成工具（main 可用）；外观与语言（F-139，main 可用）；插件创作台（F-044，main 部分，预览）；工作流程（F-092，main 可用；动作当一步 F-094，main 部分）、判断规则（F-122，main 部分） | 生成插件不是一等公民（建议 C1）；做法还不能导出分享（建议 G3）；字体与皮肤（规划） |
| 你的 AI，按你的做法做事 | 项目长期说明（已发布 · v0.2.0，源码）；模型设置与国产模型模板（F-134，main 可用）；提示词设置（F-123，main 可用）；角色与导入规则、Skills（F-137、F-065，main 部分） | 技能包只在 spec；角色和项目说明不跨机器 |
| 要紧的事，你说了算 | 要求、本人验收、改约定要你点头、决定请求（已发布 · v0.2.0，源码）；操作卡（F-107，main 可用）；MCP 逐项授权、撤销即拒（F-124，main 可用）；Computer Use 禁区（F-116，main 部分） | 依据都是 Agent 自报（建议 B1）；Agent 变更的真人批准门（规划） |
| 工作接得上，换一种样子 | 目标上的约定、要求和进度，几家 AI 读写同一份（F-002，已发布 · v0.2.0，源码）；提问卡、操作卡、下一步（F-106–F-108，main 可用）；菜单栏胶囊（F-128，main 可用）；浮条、落点（F-112、F-113，main 部分） | 主动助理、工作简报（规划）；推荐动作的模型没做命中率评估 |

### 按八个支柱看

八个支柱的定义见[产品介绍第 5 节](产品介绍.md#5-八个价值支柱)。下表是每个支柱由哪些功能撑起来、最弱一环在哪。

| 支柱 | 主要功能 | 最弱一环 |
| --- | --- | --- |
| M1 同一份工作记录，多个 AI 记账 | Goals、Sessions、项目长期说明、MCP 对外接入、Runtime 接入、角色导入 | Claude Code 等的原生会话读取（只有 Codex 有原生适配） |
| M2 完成要对得上 | 要求与依据、本人验收、目标里的决定请求、显式收尾、输入回执、助理侧栏的当前约定 | 依据都是 Agent 自报，Work 不自己核（建议 B1） |
| M3 接着眼前的东西做 | 浮条、落点、右栏、一句话新建、下一步、提问卡、操作卡、Shelf 热键、语音 | 右栏选区的悬停预示（#720）、语音（#631，分支）、推荐模型未做真实评估 |
| M4 材料到成果，出处跟着走 | 来源、Feed、Inbox→Pages 带快照、Cognia、PPT、Forms、Dataset、成果库、外部文档导入、首次使用向导 | 正式 OAuth 与真实账号验收；来源变化复核（建议 D2） |
| M5 长出工具，人和 AI 共用 | 插件创作台、工作流程、判断规则、Skill、角色、提示词设置 | 生成插件不是一等公民（建议 C1）；技能包只在 spec |
| M6 助理主动推进 | Schedule、提醒、受托跟进、子任务、后台作业 | 主动助理、工作简报只在 spec；本机服务没在运行或电脑休眠时不执行 |
| M7 本机优先、模型自选、边界清楚 | 本机 SQLite、模型设置、预算、服务连接、授权、审查队列、调用记录、对话里接入服务 | 安装包未签名公证；真实账号 OAuth |
| M8 和别人一起 | 项目讨论、Agent 任务板 | 人与人的团队协作依赖服务端，规划中 |

## 9. 用户能感觉到的边界

推广前要心里有数的地方，详细建议见[产品优化建议](产品优化建议.md)：

- 没有签名公证的安装包；只有 macOS 桌面 App（浏览器版可在其他系统前台运行）。
- 大多数 AI 功能要先配模型；判断规则要先连判断服务。
- 本机服务没在运行时（没装常驻服务、又关了应用或终端）或电脑休眠时，定时、提醒、Feed 拉取都不执行。
- 邮箱、Google 等账号来源依赖尚未发布的正式 OAuth 客户端。
- 部分插件英文界面不全。
- 已知体验债：Feed 失败提示露原码、首次打开 Feed 详情较慢、窄屏助理面板会盖住确认卡。
