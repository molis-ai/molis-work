# T-071 助理的「添加定时」「取消定时」两处调用方错误，回助理自己的码，不再是原生 Error

> **这条在 main 上成立：两处调用方的错，都当成「宿主内部故障」报出去。** 问题在 `apps/local-host/src/assistant/assistant-rule-actions.ts` 的两个处理器：
> - `assistant.followups.add`（`:80-86`）：不是在一项助理工作里调用时，抛原生 `new Error("定时要在一项助理工作里添加")`（`:82`）。
> - `assistant.followups.remove`（`:92-97`）：一项工作的一轮要取消别的工作的定时时，抛原生 `new Error("这项工作没有这个定时")`（`:94`）。
>
> 没有码的原生错误经 SDK 的出口（`packages/plugin-sdk/src/errors.ts:13-15`、`:76-84`）答成 500 和 `actions.execution_failed`，意思是「bug 或故障，不是调用方的错」。`apps/local-host/README.md:204` 写的是：助理的拒绝由 owner 的 `ActionError` 声明 kind。助理已有现成的码（`apps/local-host/src/assistant/assistant-errors.ts:4-10` 的 `invalid`、`not_found`），同一个服务里 `save` 的拒绝也都用它（`assistant-followups.ts:121-130`）。只有这两句漏了。起草时只读了代码，没有跑；先红就是复现。
>
> **不依赖别的任务，也不撞锁。** 看板上锁过 `apps/local-host/src/assistant/` 的只有 T-009（已合入 #1335）。2026-10-29 查了全部 19 个在途 PR（#1101 的 584 个文件取全），两个文件都不在里面。注意：#1101 锁着 `tests/assistant-followups.test.ts` 和 `assistant-followups.ts`，所以用例加在 `tests/assistant-attention.test.ts`，产品只改 `assistant-rule-actions.ts`。

## 1. 背景

- 两个处理器如何认「这一轮属于哪项工作」：`callingWork`（`assistant-rule-actions.ts:68`）从调用上下文的 `audit_actor_id`（`assistant:<work_id>`）取。所以人自己经网关或 MCP 调用时取不到工作，Agent 在一轮里调用时取得到。
- `:82`：人自己（或 MCP）调「添加定时」就会走到这一句，处理器还没碰服务就抛出。
- `:94`：一项工作的一轮，用别的工作的 `followup_id`（或编出来的 id）调「取消定时」，会走到这一句。这句本身就是隔离：一轮只能取消自己工作的定时。本单只改它报出去的样子，不改这条规则。
- SDK 出口对原生错误的处理（`packages/plugin-sdk/src/errors.ts`）：`actionErrorBody` 保留 `message`，码落到 `FALLBACK_CODE`（`:14`）；`actionHttpStatus` 按 kind 给状态，没有码就是 `internal`，即 500。所以调用方现在看到的是 500 / `actions.execution_failed`：Agent 看到「内部故障」，不知道是自己给错了 id。
- 同一服务里同类拒绝已经这样写：`assistant-followups.ts:121`（`assistantErrors.state`）、`:124`、`:126`（`assistantErrors.invalid`）、`:319`（`assistantErrors.not_found("没有这条规则")`）。

## 2. 目标

1. 不在一项工作里调用「添加定时」：答 400 / `assistant.invalid`，原文「定时要在一项助理工作里添加」不变（`RAC-1602`）。
2. 一项工作的一轮取消不是自己工作的定时：答 404 / `assistant.not_found`，原文「这项工作没有这个定时」不变，两项工作的定时都还在；取消自己工作的定时照旧成功（`RAC-1603`）。

## 3. 不做

- 不改「人自己（不在工作里）取消一个不存在的 id 时照样成功、什么都不删」：这是现有语义（`assistant-followups.ts:140-145` 的 `remove` 返回 `false`，处理器不看）。`assistant.rules.remove` 同理。要不要改成 404，是产品决定，不在本单（统筹记进 `MISC.md`，由用户定）。
- 不改 `assistant.methods.read`（`:87-91`）和 `assistant-followups.ts` 里的任何东西（#1101 锁着）。
- 不加新的错误码，不改 `assistant-errors.ts`。
- 不改 `tests/assistant-followups.test.ts`（#1101 锁着）。
- 不改动作的 schema、标题、说明，所以动作合同快照不变。
