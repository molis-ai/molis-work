# 从本地 Agent 导入 Character

状态：实现完成，当前达到功能可用。内置模式已通过真实 Prologue / MiniMax 执行与浏览器主链路验证；原生执行通过真实 PTY fixture 验证。原定“内部完整”目标中的五家原生 Agent 模型实操尚未完成：遵循用户新增的 AI 验证仅使用 Prologue 要求，且本机未发现 Cursor/OpenCode CLI。不能据此声称五家原生执行已完整验收；详细证据与剩余边界见 validation.md。

## 实现分工与顺序
- A：本地配置发现、受控规则/技能读取、个人导入快照与版本更新；独立 writer 负责 Characters 合同/Module、新增 Host discovery 文件和定向测试。
- B：主 Agent 负责 Plugin 导入预览/选取/更新 UI、Host 路由与执行接线。消费 A 的合同，不同时修改 A 的文件。
- 原生执行优先复用 Runtime Host 的 PTY 和 Work Session 记录，保留原 Agent 的交互、登录、审批、取消和输出，不以无审批桥的 CLI adapter 冒充可写托管执行。内置执行复用 Coding / Prologue 固定 Character 路径。
- 内置模式按用户选定技能将正文与文本附件作为固定方法加载；需要原生环境/脚本/二进制资源的技能明确说明兼容性，原文件仍完整保存在导入包。不能静默截断超长内容。
- 已核实本机技能包可达 56MB：浏览器仅收文件元数据，原文按需预览。完整角色包保存在项目 Artifact；内置执行使用 `character_skill_ids` 明确选择本轮技能，Run 冻结选定资源、技能 ID，并保留原发布引用与 digest；未选技能时只加载规则。
- 原生任务在服务端登记后直接派发 PTY，浏览器只附着；相同请求只重连，不重复启动。工作目录在每次执行前从当前项目重新读取。
- 用户补充：所有涉及 AI 的真实验证使用 Prologue 和现有 MiniMax 模型配置，不另建模型或复制凭据。

## 目标与已确认范围
用户本机已有 Claude Code、Codex、Cursor、OpenCode、Grok Build 等 Agent 时，发现其角色规则、全局/项目指令与已安装 Skills，一键导入成为可管理的 Character。两种使用方式都包含：由 Molis 内置执行引擎使用导入配置运行；由对应本地 Agent 实际执行。

用户选择一个角色，再选择执行方式；不因执行方式不同创建两份难以同步的角色。自动发现、导入完成、具备执行能力是不同状态，界面必须如实展示。

## 实现前基线与复用点
- `packages/contracts/src/modules/characters.ts`：Character 只有名称、指令、工具范围、修订与发布来源，没有 Skills、导入来源或执行绑定。
- `apps/local-host/src/characters-host.ts`：已有个人草稿、项目精确版本发布与执行冻结；保留停用阻止新执行、历史内容不变的契约。
- `apps/local-host/src/installer/runtime-config-adapters.ts`：已有部分 Runtime 发现配置；其目的是把 Molis 接入原 Agent，不能视为反向角色导入或完整执行支持。
- `horizontal/agent-host/src/adapters/prologue-methods.ts`：已有项目范围的文本方法包发现/安装，把正文和文本附件组装为方法；不能据此宣称所有脚本、二进制资源或原生工具依赖都可迁移运行。
- `horizontal/agent-host/src/adapters/cli-runtime.ts`：现有 CLI adapter 是只读执行，明确拒绝 Character；需要新的完整接线与逐工具能力验证，不能直接去掉拒绝条件冒充支持。
- Work/桌面已有通用 PTY 启动和 Codex app-server 会话接线，可复用原生进程基础；PTY 能打开程序不等于 Agent Host 已能管理其 Character、结构化结果或权限。

## 用户流程与建议默认值
1. Characters 提供“从本机导入”，自动发现已安装 Agent，同时允许手动指定未被发现的位置。
2. 显示来源与可读取配置摘要。默认选择个人全局规则及 Skills；项目规则由用户选择一个项目目录后单独加入，保留目录范围、条件和优先级，不无差别拼接。
3. 一次确认导入所选内容，生成个人 Character：名称、做事方式、技能、来源和本地执行绑定。无需逐文件手工复制。
4. Character 详情可查看/编辑导入内容，并选择“内置引擎”或“本地 Claude Code”等可用执行方式。开始前显示工作目录、实际使用的配置来源、不可用的技能或依赖。
5. 内置模式消费选定角色与技能的固定版本；原生模式实际调用对应本地 Agent 并呈现状态、输出、等待用户输入/授权、取消与失败。两种方式均保存可回看的执行结果与配置来源。
6. 导入后的配置默认是快照。源配置更新时可重新扫描、查看差异、选择更新；不自动覆盖用户在 Molis 的编辑，已有执行保持原记录。

## 角色、技能与执行的一致性
- 角色正文保留原文与来源，不默认用模型摘要替代。技能保留 SKILL.md 及所需附件、相对目录关系和依赖说明；是否能用须按执行方式分别判断。
- 不把“读到了 Skills 名称”当作导入，不把“启动了一个进程”当作任务完成。
- 全局、项目和条件规则要保留适用范围。同名 Skills 要显示来源并让用户选择，不能按遍历顺序覆盖。
- 原生 Agent 可能继续读取本机实时配置。各 adapter 必须明确能否指定/隔离配置、怎样加载导入角色与 Skills，以及额外生效的本地配置；不能默默忽略 Character 编辑，也不能宣称两种执行方式行为完全一致。
- 登录沿用本地 Agent 自己的登录机制，不把 API Key、登录令牌、会话历史导入 Character。导入阶段不执行 Skills 脚本，不安装其依赖。
- Molis 内置模式沿用 Host 的权限与审查；原生模式如实呈现原 Agent 的权限机制。规则文件里的授权文字不会成为宿主操作权限。
- 不支持的能力明确显示原因；不自动换引擎、丢弃技能或降低任务范围。

## 模块与数据边界
- Local Host 负责受控的本地发现与文件读取，按 Agent adapter 解析规则/技能来源、作用域和依赖；插件不直接读任意磁盘路径。
- Characters Module 管个人导入快照、编辑修订与来源；现有 Artifact 服务保存项目固定发布版本和所需技能资源，兼容已有无技能 Character。
- Characters Plugin 提供发现、预览、导入、差异更新和执行方式选择界面；运行状态仍由执行服务拥有。
- Agent Host / Runtime Host 消费已选角色、技能版本、工作目录和执行选择，统一呈现可用性、启动、流式结果、等待、取消、失败和恢复。复用已有生命周期，不另建平行任务库。

## 验收与验证计划
- 有/无对应程序、有配置无可执行程序、手动路径、全局与项目规则、重复技能、读取失败，都呈现真实结果；失败不留下冒充完整的 Character。
- 导入后可查看原文、附件与来源；刷新/重启仍在；重复导入和源更新不会无提示覆盖人工编辑或重复创建技能。
- 内置模式真实完成使用某个导入 Skill 的任务，所需附件可访问，相关失败明确可恢复；验证返回、存储状态和真实产物。
- 每个宣称可执行的本地 Agent 单独通过真实启动、规则/技能加载、输出、取消和失败实操；缺少本地 CLI/登录/协议能力时标为未验证或不可用，不能用另一种 Agent 的成功代替。
- 执行记录可区分角色固定版本与原生实时配置；中断或宿主重启不重复派发任务，已有固定发布与历史记录不被改写。
- UI 先做真实本地发现 → 预览 → 导入 → 两种执行方式的高保真切片，再逐 adapter 完成；验证桌面、窄屏、空态、部分可用与失败恢复。
- 工程检查复用 Characters Module/HTTP、Agent Host、Runtime Host 定向测试，新增规则与技能包解析、个人导入到项目发布以及双执行路径的契约回归。具体命令随实现切片确定，不把尚未运行的测试列为通过。

## 非目标与待核实
不复制原 Agent 的账号/订阅，不把聊天历史当作角色配置，不承诺所有厂商独有工具可在内置模式等价运行。自动安装 Agent、依赖和迁移 MCP 凭据不包含在本次导入动作中。

开发前核实各产品当前官方规则路径、Skills 发现机制、CLI/非交互协议和配置覆盖能力（含 Cursor CLI 与仅安装编辑器的差异）。这些是技术事实待验证，不要求用户逐项决定。
