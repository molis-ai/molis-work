## 2. 用户只面对两个问题

**项目资料：这个项目能用哪些内容。** 统一展示已关联文件夹、导入的文件，以及 Pages、Shelf、成果库等已授权内容。内容仍保存在原主人处；入口统一不代表复制一份正文。

**当前工作目录：这次任务在哪里修改文件、运行命令。** 只有需要文件操作的任务才出现这个选择。它引用项目已关联的真实目录，可使用另行创建的工作树；切换它是明确的执行决定，临时打开另一份资料不会切换它。

文件夹在“项目资料”里登记一次。预览它是查看；“在此工作”才用于当前会话的后续执行。两种用途可以指向同一个文件夹，不建立“工作文件夹”和“资料文件夹”两份重复登记。关联、读取、写入与执行继续按各自授权判断。

## 3. 入口怎样合并

- 工作台提供统一“项目资料”入口，承接现有侧栏“文件”的聚合能力，也容纳本机文件树与预览。按来源展示，搜索和选取共用；不强迫把代码树拍平成文档卡片。
- 项目设置里的“工作目录”管理合入同一份“资料来源”管理界面，设置只提供跳转或复用该界面；关联、修复位置、移除关联不再各做一套。
- Coding 顶部保留紧凑的“当前工作目录”。默认的文件浏览和 Git 跟随当前会话；临时查看时显示所看的位置及“回到工作目录”。多个会话／窗口各自的查看状态不改写其他任务的执行目录。
- 项目内插件通过同一公开协议选择资料、列举来源、读取内容、预览与引用。需要本机文件写入的插件另调用已有受授权的工作区操作；修改 Pages 等对象则调用该对象主人的动作，不把所有内容伪装成本机文件。
- 去掉 Files 的安装、启用、独立导航、Runtime 实例与以 Files 为中心的嵌入接线。文件树、阅读器与选择器成为工作台的公共 UI 能力；Git 继续负责版本管理，Coding 继续负责任务执行。

保留：现有目录身份、真实文件、读取失败与截断提示、快照和选区、资料出处、权限与引用。替换：重复入口、项目全局浏览选择承载会话状态、必须启用 Files 才能使用公共文件能力的依赖。忽略：为保留旧插件形态而维持的专属配置与面板嵌套。

## 4. 三条完整路径

### 做代码，同时参考其他资料

进入“网站改版”项目，Coding 在 `website` 工作目录执行；公共文件树与 Git 默认显示同一目录。在项目资料中打开 `brand-guide.pdf` 或另一个已关联目录，Coding 仍在 `website`。把选中的段落加入任务后，显示其来源；回到工作目录即可继续看代码。

只有选择另一个目录的“在此工作”，才改变当前会话下一轮的执行位置。运行中的轮次保持冻结的目录。目录不可用、授权撤销或工作树删除时明确阻塞和给出修复入口，不偷偷落到其他目录继续写。

### 只有研究、写作和项目内容

项目可以没有本机工作目录。用户导入 PDF、写 Pages、引用成果或 Shelf 材料，助理与领域插件通过统一资料源使用它们；不会为了讨论或写作被迫先选磁盘路径。等确实需要生成／修改本机文件时，再关联和选择工作目录。

### 两个任务使用不同目录

同一项目中，任务 A 在 `website`，任务 B 在 `api` 或独立工作树。打开 A 时默认跟随 A，打开 B 时默认跟随 B；另一窗口继续运行的任务不受影响。各面板的临时浏览只是查看状态，不作为其他会话的新执行依据。

## 5. 文件、资料与 AI 的边界

| 来源 | 默认读什么 | 怎样改变内容 |
| --- | --- | --- |
| 已关联本机目录 | 当前文件；标明路径与读取时版本，变化后可刷新 | 具备写入／执行权限的任务经工作区公开操作修改 |
| 导入的 PDF、图片、Office 等文件 | 已导入的原件与可用解析结果；解析失败仍说明原件状态 | 由导入文件的现有主人更新；不把导入自动当作实时同步 |
| Pages、Shelf、成果等插件对象 | 由原主人返回当前对象或指定版本 | 调原主人公开动作；公共资料入口不越权写其表 |
| 文件快照、选区 | 取用时固定的内容与出处 | 新选取产生新版本；不让源文件变化改写历史引用 |

人可以主动选择，AI 也可以按任务查找。沿用既有资料目录摘要和按需读取机制，不把全部文件正文自动塞进上下文。引用显示来源、当前文件或固定版本，以及读取失败／截断情况。资料只读授权不等于命令执行或对象写入授权；内置、个人、创作台与第三方插件使用同一合同，按各自声明和获准范围访问。

文件预览、手工选择和原文检索不依赖模型成功。模型摘要失败时保留可用原文与人工入口；文件离线、来源插件停用或撤权时保留历史引用的说明，拒绝新的未授权读取，不用缓存绕过授权。已有固定版本仍按其自身 owner 与授权读取。

## 6. 复用现有主人，先接好再退役

目录身份和项目关联继续归 `modules/projects`；路径授权与文件系统操作沿用 Host 现有工作区服务；跨来源查找读取继续归 `horizontal/knowledge` 及系统搜索；正文和对象仍归原插件／Module。公共 UI 归工作台，对外可复用的客户端能力经 SDK 暴露，不让插件 import 工作台或彼此的实现。

Files 的集合、before／after 快照、选区当前是**过程项**，不是成果；迁移后仍保留这一语义。实施前必须把产生动作、版本读取、原输出绑定与历史引用逐项交给明确的现有 owner，优先使用既有工作区合同和过程项设施；不能简单删除 Files 安装记录而连带丢失历史过程项。具体承接位置和数据维护步骤须在实施切片中写清，本文不提前虚构一个新文件存储包。

推荐切换顺序：

1. 用现有目录与资料合同接出公共浏览、选择和引用路径；用真实目录、导入文件、插件对象及权限失败做高保真切片。
2. Coding、Git 和其他消费者改用共同入口，落实会话执行目录、临时浏览、运行冻结的职责；核对 Diff、Text Stats 与现有工作流绑定仍能消费固定快照／选区。
3. 完成过程项与引用的数据维护、消费者切换及回读，再删除 Files 包、登记、安装项和专属装配；同步生成包清单、公共 API／动作快照及相关文档。现行 owner 表在实际切换时更新，本次不虚报 Files 已退役。
4. 在隔离 Home 覆盖首次使用、旧项目、重启恢复后再安排真实 Home 的已授权维护。遵守仓库现行合同切换政策，不新增长期兼容层；有必要保留的临时机制先走已有规则。切换前保留可恢复备份，失败恢复同一批数据与对应版本，不让两套 owner 同时写入。

实现沿原路线：Coding 联动归 1·B 的 R1；跨入口整理归动线治理与项目资料；Files 退役与防腐线的插件装配事项协调为同一份切换。各部分都未因设计完成而标成实现完成，不新开一套排期。

**下一个产品决定：一个项目是否设置一个可选的主工作目录，作为新 Coding 会话的默认值？** 推荐“有主目录就默认使用，单个会话可改用其他目录或工作树；无主目录且无需文件操作则不要求选择”。另一种是每次新会话都显式选目录，不增加项目主目录。它与“按磁盘目录自动选项目”不同：项目身份仍由用户确认，不恢复 [PRODUCT](../../PRODUCT.md) 已取消的 workspace 默认项目绑定。用户尚未拍板前，不把推荐值写成现行行为。
