# 事项线卡片审批与工作台脚本去重

状态：本地验收通过，待合入（2026-11-23）。负责人 Codex（本机）。完成程度为功能可用，卡片至原审批回执的链路已在隔离 Home 验证。

接续 BL-work-line-held-review-on-card 与 BL-work-line-bundle-duplicate-sdk-text。第 32 批的 [任务合同](../work-line/contract-design.md#4-后台任务总表) 已支持插件自己的决定，Agent 的待审操作另由宿主登记和执行。Coding 的业务会话 ID 与 Agent 会话 ID 分立，任务提供方负责报出两者的关联。

任务行可为所绑定的 Agent 会话报告一组待审 ID。Coding 只在会话确实等审批时，经 Agent Host 的只读入口批量取得自己安装范围内的 ID。平台收到行后，从 Agent 待审队列核对项目、插件、安装、会话、状态和可决定性，取原提案的显示内容。卡片沿用已有的决定区域和按钮，只有本人在受保护的工作台入口提交时才可记录同意或拒绝。提交携带卡片所显示的提案版本，平台现读提供方和队列，沿用 Agent Host 的原决定、回执和计算机操作静默期。常规插件决定、助理的修改意见、会话内审批和后续许可仍走各自现行入口。未能显示的提案可回会话处理。

审批只呈现本次从队列读取的原提案。标签页恢复事项线时暂存事件和读取状态，重新获取审批。Home 的任务摘要在休眠缓存写入前去除待审引用。

工作栏与工作台已加载的项目首页浏览器入口合并构建，共用 SDK 文字与渲染函数。基线和结果取相同构建参数下静态路由的实际字节和 gzip。第 100 批已退役第 32 批逐项许可，净节省从现行 `page-asset-budgets.json` 的工作台预算扣回。

### 开工检查与复查

独立片，覆盖事项线和 Coding 产品路径、工作台体验及平台审批合同。沿用事件卡现有决定区和按钮。本人可从等你的事件打开原提案，答完由现有更新通道重读，失败时按卡片的现状处理，也可回会话查看。

| 项目 | 结论 |
| --- | --- |
| 1 事实主人 | 插件保有任务与 Agent 会话的关联，Agent Host 持有原提案和回执，事项线实时投影。 |
| 2 插件同等待遇 | 任务合同与读取动作可由现行插件装配使用，Coding 是第一个调用方。 |
| 3 能力注册 | 待审编号只读动作由 Agent Host 登记，身份从上下文取。审批沿用有并发控制的任务决定。 |
| 4 合同 | 提案提示和版本是可选字段，新只读动作从 @1 开始，同 PR 更新消费者与两份快照。 |
| 5 包边界 | contracts 定义合同，mainline 复读任务，宿主装配审批队列，工作台共用原提案渲染。 |
| 6 表与存储 | 沿用队列原决定存储，未新增表。 |
| 7 兼容与迁移 | 现有普通决定输入继续有效，无兼容分支或迁移。 |
| 8 安全边界 | 原提案只给受保护的本人页面。助理抄本仍可读任务状态；错归属、旧版本、静默期和失效任务关联有拒绝测试。 |
| 9 调用次数 | 页面复用现有注意事项读取，插件批量查询编号。提交时读对应任务提供方，原决定即将保存时再查该任务是否仍引用此提案。 |
| 10 升级与数据 | 沿用任务、会话、提案与回执的原引用和格式。 |
| 11 成果与过程项 | 不涉及，卡片读的是待审提案。 |
| 12 页面、外壳与文字 | 沿用工作台、现有事件、审批文案与语义样式。浏览器覆盖中英文、浅深色和宽窄卡片。合束降低资源预算。 |
| 13 错误 | 复用权限不足、决定变化、队列状态及静默期的错误码。 |
| 14 冲突面 | 核对 #1743 和在途 PR 中的项目宿主、合同快照与 spec 索引。 |
| 15 全局 | 采用平台的受保护页面入口、任务查询和队列。其他插件用同一合同；助理仍读任务状态；统一观测走现有动作。后续接入只需提供绑定会话的待审编号。 |

平台能力检查结论为用现成的。Coding 已使用这条路径，第三方的 Agent 插件可用同一任务合同与只读动作。所有调用方共用现行的审批队列和项目归属规则。助理可发现原有任务抄本动作，待审提案的读取和决定留给本人页面。接入其他任务提供方时沿用同一字段、渲染与回执。

全量 CI 的调用预算查出项目首页读 Schedule 时，即使没有已保存的定时操作也会枚举整个插件动作目录。新增待审编号动作因此多计一行。Schedule 列表先读本项目已有操作，只有列表含操作才查目录，并用同一次读到的记录生成回复。保留管理已有定时操作所需的现行安装和能力核对。用 `tests/call-budget.test.ts` 验证实际项目首页，预算维持原上限。

### 验收

1. **WLHR-01** 受保护的本人页面只显示当前项目里、任务提供安装和 Agent 会话相符的待审内容。错项目、错插件、错安装、错会话及已结束记录都得不到内容或审批入口。助理的后台任务抄本依然提供任务摘要，其中没有原提案及其标题。
2. **WLHR-02** 在事件卡看到原提案并同意或拒绝，两种回答分别写进同一待审队列，刷新后原按钮消失。会话或任务关联已改、提案版本已改、重复点击、非本人或计算机操作静默期内的提交均被拒。原决定即将保存时现读任务复核关联。标签页暂存与 Home 休眠摘要均省略待审记录的引用和内容。
3. **WLHR-03** 工作栏和项目首页由同一个浏览器入口构建，实测工作台脚本净字节下降，并按下降幅度收紧工作台路由预算。隔离浏览器复验工作栏、首页及语言切换。
4. **WLHR-04** Agent Host 与事项线合同都能从各自公开入口独立加载。两处共用的审批条数上限定义在审批合同中。

验证用 `pnpm build`、定向的主线／Coding／Agent 审批与浏览器测试、`pnpm api:update`、`pnpm actions:update`、`pnpm boundary:check`、资源及首屏核对。结果和例外在本需求书回填。
