# Goal 推进态势：尺度与拓扑可读性修正

> 归档（2026-10-01，合入后梳理）：判定为**已实现**。推进态势自适应与缩放拖动已在 goals-momentum-ui.ts。没有剩余事项。

## 背景与目标

真实项目的推进态势视图已经接入，但当前实现仍有三处直接影响阅读的布局问题：推进节奏只按 viewport 响应，在目录与工作台共同占宽时不会按组件自身宽度收敛；`part_of` 分组标题与第一排 Goal 节点共享网格空间，长标题会覆盖卡片；拓扑画布只按宽度适配并显示原生滚动条，密集图需要用滚动条才能浏览。

本任务完成等级为 **3：功能可用**。目标是在不改变 Goal、关系、节奏和行动排序语义的前提下，让节奏区在实际容器宽度下自动重排，让完整拓扑文字不重叠，并以自动适配、缩放和拖动取代可见 scrollbar。

## 保留、替换、忽略

- 保留：7/30 天切换、节奏数字与事实说明、全部/未完成过滤、拓扑缩放、节点选择、连线、分组语义、深链和行动队列。
- 替换：节奏区的 viewport-only 响应方式；分组标题与第一排节点共用空间；拓扑仅按宽度 fit 和可见原生 scrollbar。
- 忽略：改变拓扑排序、删除密集节点、引入 canvas/第三方图引擎、给节奏区增加独立的用户缩放状态。

## 行为方案

### 推进节奏

- 节奏容器建立 inline-size container，宽布局保持“结论 + 时间轨道”并列。
- 容器变窄时自动收紧字号、间距和轨道密度；再窄时改为上下排列，不依赖整个浏览器窗口断点。
- 7/30 天事实和日期标签保持可读，不通过整体 CSS transform 缩小文字。

### 依赖拓扑

- 分组标题保持单行并截断，Goal 数量固定可见；标题不得换行覆盖节点。
- 每个分组的第一排节点为标题预留独立垂直空间；后续节点保持紧凑节奏。
- “适应宽度”优先让从 L0 到末级的拓扑层级横向进入当前容器，同时保留 55% 的可读性下限；纵向深度通过滚轮、键盘或拖动浏览，不能为了把所有节点一次压入高度而牺牲文字可读性。
- 初次加载、筛选变化和容器尺寸变化后自动重新适配；用户手动放大/缩小后保留其选择，直到再次点击适应宽度。
- 容器适配监听拓扑视口的真实尺寸变化，而不是只依赖窗口事件，因此目录收起、展开和拖动改宽后都会重新计算。
- 画布保留键盘滚动、滚轮和拖动浏览能力，但不显示横向或纵向 scrollbar。

## 模块边界

- `src/web/render.ts`：标记每个分组的首排节点；实现宽高 fit、尺寸变化重算和拖动画布；更新拓扑可访问名称。
- `src/web/visual-foundation.ts`：容器查询、分组标题截断、首排避让、无可见 scrollbar 与拖动状态。
- `tests/goal-momentum.test.ts`：保留拓扑数据契约，不改变排序语义。
- `tests/visual-foundation.test.ts` / `tests/web.test.ts`：锁定容器响应、首排避让、宽高 fit 和无可见 scrollbar。

## 验收标准

1. 推进节奏在宽、中、窄工作台中自动重排，结论、指标、图例、日期和数据说明无溢出或遮挡。
2. 所有分组标题保持单行截断，第一排 Goal 节点与分组标题之间有明确间距；截图中的四节点分组和项目独立事项不再重叠。
3. 拓扑初次打开和点击“适应宽度”时自动覆盖横向层级，缩放不低于 55%；纵向内容可在无滚动条的视口内继续浏览。
4. 拓扑不显示横向或纵向 scrollbar；放大后仍可用拖动、滚轮或键盘浏览完整内容。
5. 7/30 天、筛选、缩放、选择、连线和窄屏触控回归通过，且不改变 Goal Momentum 派生数据。

## 假设与开放项

- “不要出现 scrollbar”解释为不显示原生滚动条，而不是禁止浏览超出视口的放大画布。
- 节奏区使用自动响应，不增加独立缩放控制；数据阅读区的文字需要保持真实字号和可访问性。
