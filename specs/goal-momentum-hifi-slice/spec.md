# Goal 推进态势高保真切片

Molis Work Goal：`goal-momentum-hifi-slice`

## 完成等级

本轮达到 **2 · 可交互原型**。它用当前项目的完整 Goal 快照、真实 `depends_on` / `part_of` 关系与执行状态验证信息结构、时间口径、拓扑阅读、瓶颈判断、行动排序和响应式交互；不会读取生产数据库实时计算，也不会替换现有关系图。

只有一骏能判断这套形态是否真的让人更快看懂“整体是否在推进、卡在哪里、现在该做什么”。通过这一人类判断后，后续 Goal `goal-momentum-internal-complete` 才接入真实数据并退出旧关系图。

## 背景与问题证据

- 现有关系图把 `part_of` 与 `depends_on` 混画成血缘网络，既没有稳定的阅读方向，也无法区分“归属”与“执行前置”，真实使用反馈表明它不能支持推进判断。
- GoalTree 列表能看层级和单项状态，却需要用户逐项阅读，无法形成整体节奏和关键路径。
- 通用 Kanban 会把 Molis Work 的派生工作状态压成第二套可拖拽状态，既重复又容易失真。
- 当前项目已经有真实 Goal 标题、依赖、完成状态、Claim / Run 与事件时间，可以构成足够逼真的验证样本。

## 保留、替换、忽略

### 保留

- 单目录工作台、GoalTree 列表、Goal 详情与现有视觉语言。
- `Goal`、`part_of`、`depends_on`、Claim、Run、Risk、Review 与事件记录作为唯一事实来源。
- 点击任何图节点或行动项后，都应回到同一个 Goal 详情继续工作。

### 替换

- 旧关系图的“完整血缘网络”表达，替换为覆盖当前全部 Goal、按 `depends_on` 拓扑层级从左到右展开的完整依赖图。
- `part_of` 不再伪装成先后依赖，而是通过父 Goal 分组带表达；`corrects` 等非执行顺序关系留在 Goal 详情，不进入拓扑边。
- 把散落的当前状态，组合为“时间变化 + 完整依赖拓扑 + 行动队列”一套连续判断路径。
- 把不透明优先级，替换为每一项都能解释“为什么现在处理”的行动顺序。

### 忽略 / 非目标

- 不实现 Kanban 分栏、拖拽、手工排序或第二套状态。
- 不实现人员 / Runtime 容量、工时和工作量估算。
- 不接生产接口、不写 Molis Work 数据、不移除旧关系图。
- 不做跨项目总览、任意日期查询或可配置报表。

## 用户问题与最短闭环

进入推进态势后，用户应在一个工作面内依次回答：

1. 最近 7 天（可切换 30 天）整体是在加速、停滞还是产生新阻塞？
2. 整张 Goal 图从哪些底层输入走向哪些最终结果，哪一个未完成 Goal 正在阻挡最多的下游结果？
3. 当前最值得处理的三项行动是什么，排序原因是什么？
4. 选择图节点或行动项后，能否看到同一 Goal 的状态、影响链和下一步，并打开真实 Goal 详情？

## 信息与数据口径

原型使用 2026-08-30 的当前项目快照构造代表性演示，包含 30 个 Goal、38 条 `depends_on`、24 条 `part_of` 与 1 条 `corrects`。拓扑画布完整显示 30 个 Goal 和 38 条执行依赖；24 条归属关系通过分组带表达，`corrects` 留在详情。时间统计仍是用于验证界面的固定样本，不冒充实时生产结果。页面必须持续显示这一边界。

### 时间变化

- 默认：近 7 天；可切换：近 30 天。
- 启动：Goal 第一次出现 executor Run 的时间落入窗口。
- 完成：Goal 首次成为可信 `satisfied` 的时间落入窗口。
- 新阻塞：窗口内首次出现 blocker 级原因或 completion-blocking Risk。
- 停滞：未完成 Goal 在窗口内没有 Run、Evidence、Review、Contract 或关系更新；缺少足够历史时标记“历史不足”，不把它判为停滞。
- 原型的 7 / 30 天数字必须随切换变化，并提供“样本快照”说明。

### 完整拓扑与瓶颈

- 默认展示当前项目全部 30 个 Goal 与全部 38 条 `depends_on`，不折叠低影响或已完成 Goal；可切换“只看未完成”，但不能改变默认完整性。
- 依赖提供者在左、消费结果在右；每个节点列号由 `max(所有未完成前置的层级) + 1` 决定，同层只调整纵向位置以减少交叉，不暗示额外优先级。
- `part_of` 通过父 Goal 分组带与可点击组标题表达，不绘制成拓扑箭头；一个 Goal 可以有多个前置，因此视觉是树状展开的 DAG，不谎称严格单父树。
- 箭头语义是“前置提供者 → 消费者”，与存储中的 `consumer depends_on provider` 方向相反但含义一致；页面必须明说。
- 瓶颈强度仍由“直接与间接受阻下游数”表达，不生成虚假的百分制分数；它只改变节点状态与相关边强调，不再决定哪些节点出现。
- 已满足节点完整保留但降低视觉权重；选择节点时，相关依赖边、行动队列和详情摘要共享同一个 selected Goal。

### 行动队列

第一版排序使用可解释的顺序层级，而不是隐藏加权分：

1. 需要用户决定且会阻塞后续工作。
2. 已在执行、接近可完成并能解除阻塞。
3. 无未完成依赖、可以立即开始且解锁范围大。
4. 其他可开始项。
5. 停滞但解锁影响较小的项。

每项至少显示状态、影响范围和一句“为什么现在”。相同层级只用最近有效变化时间稳定排序。

## 代表性场景

- `建立统一 Session 身份与 Runtime 适配基础`：未完成，解锁 Session 内容、目录、工作目录和 Handoff，是跨分支高解锁瓶颈。
- `接通 RSS 与 Atom 订阅来源`：已有 active Claim，完成后解除真实集成的一项前置。
- `接通 Gmail 邮件来源`：无未完成前置、可立即开始，但当前无人领取。
- `完成真实链路迁移、集成与内部试用验收`：被 Gmail 与 RSS 共同阻塞，不应进入可执行队列。
- `验证 Goal 推进态势高保真切片`：当前执行中，显示为正在验证本视图本身。

## 视觉与交互方案

- 延续 Molis Work 冷静浅色工作台：纸面灰白背景、深墨文字、克制钴蓝焦点、低饱和状态色。
- 顶部不是 KPI 卡片墙，而是一条连续的“节奏轨”：摘要句、7 / 30 天切换、事件刻度和少量数字融为同一时间结构。
- 完整依赖拓扑是主体主舞台并占满可用宽度：列标题固定解释拓扑层级，父 Goal 分组带承担树状归属，节点与边只使用真实关系。
- 行动队列与选择详情位于拓扑下方，继续解释“现在做什么”、状态、排序原因、影响链、数据可信度和“打开 Goal 详情”。
- 桌面宽度下拓扑横向展开并允许画布内双向滚动；`760px` 以下保持同一阅读顺序，节点不缩成不可读线团，图在独立视口中平移。
- 交互必须支持鼠标和键盘；选择状态、时间切换和队列筛选均有可见焦点。

## 必须覆盖的状态

- 正常推进：近期有启动和完成，存在清晰下一步。
- 新阻塞：时间轨能看到阻塞进入，关系图能解释受影响链。
- 历史不足：不显示虚假的停滞判断，并解释缺口。
- 密集关系：全部节点与依赖仍在；默认降低完成边权重，选择节点后强调其一阶前置与下游，避免靠隐藏关系解决线团。
- 空结果：筛选没有行动时提供清除筛选入口。
- 窄屏：行动优先，图不挤压成不可读线团。

## 验收标准

### `goal-momentum-slice-core`

使用代表性内容时，一骏能在同一工作面说明近期变化、首要瓶颈和行动队列前三项的排序原因，并能从选择项打开对应的真实 Goal 详情。

决策方式：`human_decision`。本轮自动检查和 Runtime 自检不能替代一骏的判断。

### `goal-momentum-slice-semantics`

近 7 / 30 天口径、停滞与新阻塞定义、解锁影响和行动优先级规则都有白话定义、来源、缺失数据处理和样本到结论的追溯。

决策方式：`inspection`。

### `goal-momentum-slice-states`

至少覆盖正常、空、缺历史、密集关系、阻塞与窄屏状态，并明确图、队列和 Goal 详情的联动行为。

决策方式：`inspection`。

## 风险与停止条件

- 如果一骏无法在短时间内说明“首要瓶颈 + 前三项行动原因”，不进入真实实现，回到信息结构调整。
- 如果完整图形成线团，先修正拓扑层级、父 Goal 分组、同层纵向排序与选择高亮；不得通过删除真实节点或依赖伪造清晰度。
- 如果排序必须依赖不可解释的综合分数才能成立，停止实现并重新定义业务顺序。
- 如果完成等级需要提高到真实功能，先切换到后续 Goal 并更新对应 spec；本切片不静默接入生产写入面。
