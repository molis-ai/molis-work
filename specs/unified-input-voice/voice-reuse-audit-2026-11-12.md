## 结论：保留语音处理的修复，沿新输入组件重新接

| 范围 | 主线与旧分支的实际差异 | 接续结论 |
| --- | --- | --- |
| 输入框、布局、键盘与发送 | 主线已有 `renderComposer`、`molisComposer`、底栏收件人与 Coding 框架桥；旧 `unified-input-client.ts` 通过三个表单选择器绑定 home/assistant/coding | **用主线，不搬旧壳。** 不恢复旧选择器、独立发送锁和手工插入的控制栏；语音进入公共组件，不能写死插件 |
| 草稿与会话归属 | 主线 `composer-drafts.ts` 与页面的 `draft.adapter` 已负责草稿；旧 `uivStorageKey` 另写 `molis.uiv.v1:*`，并有自己的 surface/project/session 身份 | **不搬旧存储。** 复用现有草稿主人；语音保留开始时的接收者与挂载代次。换收件人后桥会释放旧挂载，需新增明确的回填/待插入交接，不能只调用当前 `handle.insert()` |
| 录音浏览器链路 | 旧链路用主动 `getUserMedia`、AAC/MP4 `MediaRecorder`、AudioContext 声音反馈，监听设备结束，释放 track、分析器和音频上下文 | **可复用实现思路与用例，需改接。** 主线 voice 目前只是可选按钮文案，渲染为 `aria-disabled`，没有录音监听。格式能力、设备释放与主窗口/分屏单段录音范围需重验 |
| 取消与临时文件 | 主线 `material-native.ts` 已含 SIGKILL 取消、等待 child close、忽略取消后进度、finally 删除临时目录；与旧版差异主要是扩展名改由 SDK 管 | **主线已有，不重复搬。** 把旧取消用例迁到现行公开路径复验，尤其失败时浏览器保留重试音频、成功/取消清理的分工 |
| 本机模型与提取 | 两边都有 WhisperKit、`large-v3-v20240930_626MB`、显式允许才下载、缺 tokenizer 拒绝离线提取；主线入口已是 `extractHomeMaterial`，缓存受 `material-home.ts` 管理 | **复用现行提取链。** 旧 `local-voice.ts` import 的 `jellyModelCacheDirectory` 已不存在，旧 `MOLIS_JELLY_WHISPER_HELPER` 与现行 `MOLIS_MATERIAL_WHISPER_HELPER` 不同，不能直接拷贝服务 |
| 口述正文 | 旧 `spokenText` 优先取 segments，避免把素材时间戳塞进草稿；空结果转为“未听清” | **可复用的小逻辑。** 接入现行提取结果和错误模型；需要真实静音/噪声样本验证，过滤器不等于不会幻觉 |
| 中文识别修正 | 旧 Swift 显式 `detectLanguage: true`；当前主线未带这项 | **候选保留。** 在相同设备/模型及中英混说语料上复验后采用；不宣称当前主线已具备旧修复效果 |
| JSON 协议与慢转写诊断 | 旧 helper 用独立 stdout 句柄输出 JSON，将框架 stdout 日志转到 stderr；另有开关控制的阶段计时、model_loading 阶段。主线仍直接写 stdout | **候选保留。** 协议隔离和阶段计时是局部补丁，不需要复制旧 UI；计时只记耗时，不记音频/文字 |
| 首次准备 | 旧 prepare 用短静音文件实际走模型加载，成功后才表示准备完成；文件存在的 probe 不等于模型已完成编译加载 | **保留行为，重新设计准备入口。** 先下载、再本机准备，后者无真实比例时不能画假百分比。需要与 26 的组件自检分清 helper 与模型两层 |
| 构建软链防护 | 旧 build-whisper.sh 用临时文件再 mv，避免 cp 跟随目标软链更新另一工作树；主线仍直接 cp | **候选保留。** 改构建脚本时配符号链接反例测试；本次没有构建 helper |
| HTTP 入口与权限 | 旧 `/api/local-voice` 用 probe/prepare/transcribe 和 NDJSON；现行主线没有这个入口 | **需要重定合同。** 保留显式下载确认、断连取消、大小上限与错误边界；接现行动作/授权与可信 Home 上下文，不能照搬旧路由并绕过现行授权 |
| 原生权限和安装 | 旧分支新增 NSMicrophoneUsageDescription、audio-input entitlement 及 Tauri 配置；主线对应配置尚无这些增量 | **合并到 26 的最终安装配置。** 不覆盖其签名、公证和权限清单；须在最终包上验首次允许、拒绝后恢复 |
| 测试 | 旧规则、取消、原生识别及浏览器用例仍在旧分支；主线已有 composer、Coding 草稿、收件人桥和来源用例 | **迁移业务断言，不搬 DOM 假设。** 对取消/迟到结果/清空/切换/权限/离线保留拒绝断言；旧 Todo 390px 遮挡失败在新结构上仍待重验 |

## 本轮复杂度取舍与设计边界

- 当前必须：复用主线输入框及原草稿主人；让录音状态只有一份，原对象变了仍可返回；把模型下载和模型加载区分开；异常就地恢复。
- 延后：真实媒体、平台合同、打包权限与性能测量，随前置齐备后的正式实现做。流式逐字转写、云端兜底、后台监听不在本轮范围。
- 不带回：旧三入口选择器、旧草稿键、重复发送与录音 UI、旧布局 CSS、旧错误文本直出与旧主机路由。
- 本次预览复用组件板 kit 的按钮/图标/色板，以及冻结主线源码的 `renderComposer` 和 `COMPOSER_STYLES`。新增的紧凑录音条/波形与待插入结果样式仅在原型内标为“组件板新增候选”。不修改共享 kit 或产品代码。
- A：框内紧凑录音条（推荐），保持一个视觉容器；B：框上方独立录音浮层，正文更独立，但多一层容器。两者只有布局差异，归属、取消和隐私承诺一致。
- 配色沿主线雾蓝工作台与灰色描边，输入焦点不增加有色高亮；正文与操作统一左右边，内容向上覆盖展开，主区和左右入口固定。字体沿系统字体；按钮、状态环、阴影和动效取现有令牌。
- 本轮分支 `codex/voice53-preview-20261112` 为准备工作隔离分支。2026-11-12 用户授权将本轮核查、A 方案定样与 spec 更新提交并推送到该分支，仅备份准备成果；未用 `batch/53` 开正式实现，不重开 PR #631。定样已选 A，待前置齐备后再决定接续分支。

## 定样结论

用户于 2026-11-12 明确选择 **A「框内紧凑栏」**。A 将录音反馈保留在一个容器内；B 框上独立浮层本轮不采用，留作设计比较。认可范围仅为交互方向，预览不是产品实操验收；新增部件的 D 轨标本与走查、正式接入和真人验收仍待后续。模型大小 626 MB 来自主线当前模型常量，预览下载进度、音量和转写结果均为模拟，没有访问麦克风或 Home。
