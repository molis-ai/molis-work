# 43 · 助理团与 Dataset 能力

[执行目录](../../spec.md#execution-batches) · 阶段 2：个人工作完整可用 · [上一批 42](42.md) · [下一批 44](44.md) · [执行规则](../execution-rules.md)

## 给人讲清楚

项目里的「助理团」现在还不能真正分工接活；Dataset 缺汇总和追加，问卷收回来的结果不会自动进表，数据一多就慢。这一批让助理团真正承担任务、交付结果；Dataset 补上汇总行、追加、问卷结果自动追加，并在接近真实的数据量下保持流畅。两件事互不等待。需要你做的：看助理团控制、Dataset 编辑与追加的样子并定下。

## 交付与前置

- **阶段／类型**：2；产品线（助理、Coding）；横向能力
- **需求来源**：[Onboarding][ONB]、[主动助理][PAST]、[Harness R9][CHO]、[产品建议 H12／15／21][P]
- **前置／待决**：两项独立交付，互不等待。
- **可并行项**：46 的快速创建交互设计
- **UI 要求**：先定样：助理团控制；Dataset 编辑与追加
- **粒度**（批内子分支怎么分，全批仍是一个 PR；开工建议，执行时按[开发流程第 8.4 节](../development-workflow.md#batch-grouping)判断）：两项各一个子分支，助理团和 Dataset 完全独立。

| 交付项 | 做什么、产出什么 | 该项前置 |
| --- | --- | --- |
| <a id="batch-43-item-1"></a>项目助理团执行与交付 | 助理团真实承担任务并交付 | 24、32、36；子代理与续跑入口等 31-1（24 已核实的缺口） |
| <a id="batch-43-item-2"></a>Dataset 汇总、追加与规模性能 | Dataset 完成汇总行、追加、问卷结果自动追加及代表性规模性能 | 16 与既有数据接口 |
