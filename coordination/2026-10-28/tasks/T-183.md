## 1. 背景

- 谁给工作台这两个值：
  - 插件页面的按钮写 `data-context-intake="todo"`、`data-context-id`、`data-context-title`、`data-context-text`；
  - 灵光：`plugins/native/lingguang/src/browser/editor.ts:37-39` 把标题取 80 个单元的备用值、文字截到 3000（T-176 把这两处改成按字，文字最多 3000 个字，即最多 6000 个单元）；
  - Inbox：`plugins/native/inbox/src/ui.ts:142` 的按钮把条目标题 `entry.title` 原样放进 `data-context-title`，没有截，条目标题来自外部的订阅内容；
  - 别的插件按同一个约定，上限由页面自己定，工作台这里是最后一道。
- 三处各自的下游：

  | 处 | 值从哪来 | 下游 |
  | --- | --- | --- |
  | A，`intake.ts:26` | 插件框架里的按钮：`childIntake`（`:6-15`）把 `data-context-title`、`-text` 原样 `postMessage` 给上面的页面（不截），`pageIntake` 收到后截 | 在放框架的那块表面上派 `molis:context-intake`，到 C；`pageIntake` 要求框架可见、焦点在框架、有用户手势（`:23`），`id` 非空且不超过 256 |
  | C，`context-bus.ts:236` | `molis:context-intake` 的 detail：A 派的，或页面里的按钮点击直接派的（`:246-252`，不经过 A，值是 `data-context-*` 原样） | 取出声明（`known()`），交给 `starters.focusFor`（B），再 `create()`（`:142-155` 一带）向 `/api/contextual/create` 发 `{ focus, ...landing.with(focus), intake_id, request_id }`；`landing.with(focus)` 只有 `focus.place` 不是 main 时才有内容 |
  | B，`context-bus.ts:191` | `focusFor(context)` 的 `draft_text`（没有就取 `object.title`）；C 把 `draft_text: text || title` 交进来；助理也能单独问：`molis:assistant-starters-request`（`:204-216` 一带）把页面的对象交进来 | 作为 `focus.targets[0].text`，随 `/api/contextual/create` 或 `/api/contextual/candidates`（`pane_id: "assistant-start"`）发给 Host |

  C 先截一遍、B 再截一遍：从 C 来的文字，B 收到的已经不超过 4000。`focusFor` 里的 `object.title` 是 `String(object.title)`，不截（第 3 节）。
- Host 也按单元数，再数一遍（`apps/local-host/src/contextual/contextual-request.ts`）：
  - `readRef`（`:38`）把 `ref.title` 截到 200 个单元；
  - `MAX_TARGET_TEXT = 4_000`（`:25`），目标文字超过就截到 4000 并标 `truncated: true`（`:51-54`）；
  - `intake_id` 超过 40 个单元抛错（`:133`；create 那条路是 80，`contextual-http.ts:192`），`id` 超过 200 也抛错。
- 所以上限只能是单元，工作台这里改成字数会出两个问题：
  - 4000 个字最多 8000 个单元，Host 收到后在第 4000 个单元再截一次，截点又可能落在字中间，半个字只是挪到下一层；
  - 200 个字的标题最多 400 个单元，同样被 Host 截。
- 为什么不是 T-079 的原样写法：
  - T-079（`bc20f3667`）的 `[...x].slice(0, n).join("")` 数的是字，用在插件自己的字数上限上（`plugins/native/ppt/src/store.ts:279`、`plugins/native/pages/src/content-actions.ts:42`、`plugins/native/todo/src/organize.ts:116`、`plugins/native/dataset/src/store.ts:147`；T-176 对灵光也这样写）；
  - 这里的上限是 Host 数的单元，要的是「不超过 max 个单元，并且不以半个字结尾」；
  - 仓库里已有这种写法：`apps/local-host/src/material-text.ts:62`（`end` 前一个单元是高位代理就退一个）、`context-onboarding-service.ts:334`（`.slice(0, n).replace(/[\uD800-\uDBFF]$/u, "")`）；本单照后一个，不是第三种；
  - 工作台、SDK、contracts、design-system 里没有现成的函数可用：灵光的 `firstCharacters`（`plugins/native/lingguang/src/actions.ts:151`）是灵光自己的，`cutWhole` 在 main 里不存在。这是第 8 节第 2 条，请统筹定。
- `intake_id.slice(0, 40)` 不改：它是标识，`packages/contracts/src/platform/item-intake.ts:45` 写「小写字母、数字、`_`、`.`、`-`，至多 40」，`context-declarations.ts` 里的 `ID_PATTERN = /^[a-z][a-z0-9_.-]*$/u` 只认 ASCII，不会有两个单元的字；超长或不是 ASCII 的值本来就对不上任何声明的创建入口。
- 为什么 `cutWhole` 只动超过上限的值：
  - 如果 `cutWhole` 一律截并去掉结尾的落单高位代理，那么 C 如果还是旧写法 `slice(0, 4000)`（留下半个字，长度正好 4000），B 随后会替它修好，C 的错没有用例看得见；
  - 超过上限才动，B 收到长度不超过 4000 的值就原样放过，C 的退回会让 `RAC-1870` 红；
  - 同样，框架桥改对了，C 也不会替它收尾，见第 6 节的变异表；
  - 这一条的用例是「到达时就是半个字、但没超上限的值保持原样」（`RAC-1870`、`RAC-1871` 的最后一个子例，M8 钉住）。
- 页面资源（`pnpm page-assets:check`，`tooling/gates/page-assets.json`）：
  - `intake.ts` 进 `/assets/molis-work-plugin-frame.js`：`apps/workbench` 的 `build` 用 esbuild（`--minify --charset=utf8`）从 `src/browser/plugin-frame/entry.ts` 打成 `dist/plugin-frame-client.js`，`src/plugin-frame.ts:27` 的 `renderPluginFrameClientScript()` 读它；预算 190560；
  - `context-bus.ts` 进 `/assets/molis-work-workbench.js`：`CONTEXT_BUS_SCRIPT` 是 `String.raw` 字符串，经 `context-actions.ts:213` 的 `CONTEXT_ACTIONS_FACTORY_SCRIPT = compactScript(...)`，再被 `tightenServedJs` 压缩；预算 1148981；
  - 两个包不共用模块（一个是 esbuild 从 TS 打的，一个是字符串脚本），所以各写一份 `cutWhole`，每个包里一个定义、每处调用一次；
  - 手算多：框架包约 +70 字节，工作台包约 +95 到 +100 字节，没量；
  - `APPROVED_CEILINGS`（`scripts/gates/page-assets.mjs:243-256`）是一次性放行：`"资源": [merge-base 的字节数, 上限]`，只有 merge-base 的字节数等于第一个数才生效，写完要等于实测。

## 2. 目标

1. 框架桥（A）、意图处理（C）、起手式（B）三处，把按钮带的标题（200）和文字（4000）截到不超过上限的单元数，并且不以半个字结尾：
   - 截点落在两个单元的字中间，去掉这个字的前半，结果比上限少一个单元；
   - 恰好落在两个字之间，保持上限；
   - 放得下的值原样。
2. `intake_id` 仍是前 40 个单元。
3. 页面资源两个包各涨几十字节，用 `APPROVED_CEILINGS` 放行一次，冻结在实测数；别的资源一个字节不变。
