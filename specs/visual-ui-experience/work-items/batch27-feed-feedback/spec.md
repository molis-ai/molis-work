## 场景与边界

本片覆盖 [BL-094](../../../backlog/BL-094.md)、[BL-095](../../../backlog/BL-095.md)、[BL-134](../../../backlog/BL-134.md) 和 [视觉体验](../../spec.md) VUX-29／31／54 的现有失败反馈。先复现，已具备的体验只核回。

- Feed 用户立即拉取一个已添加来源。源站拒绝、网页或坏的 RSS/Atom、拉取未完成时，原有状态环与提示说明实际结果和下一步。Feed 继续保存已有内容、运行状态与诊断码，页面用该结果显示可行动的原因。同一次失败只在当前操作的位置反馈一次。错误跟操作及所在表单走，切换后别的表单没有旧提示，原输入仍可继续用。
- Feed 添加来源保持现有入口、类型、目录顺序和手动拉取频率。查看实际默认源，若默认落在已标明易被拦截的 36 氪，目录中选择当前可用的默认订阅。来源已经添加而拉取计划明确失败时，现有提示说明计划未保存。写入回执丢失时仍说明来源已添加，保留现有待核对提示。同一个按钮改为「保存拉取计划」，用保留的原来源重试计划，成功后进入刚添加的来源。
- Feed、Inbox 的列表读取和 Issue 打开的模型设置读取失败时，在调用方已有的反馈位置说明当前输入已保留，并沿现有路径重试。保留可行动的错误原因。先用真实页面核实原表单、筛选与选中项保留，再补缺失的反馈或恢复。
- Feed 拟改自己的 `src/browser/sources.ts`、`src/browser/factory.ts`、`src/ui.ts`、`src/stage-ui.ts`、`src/en.ts`、`src/source-sync-result.ts`，原因投影如需共享则用现有 `src/source-presentation.ts`。Inbox 拟改自己的 `src/browser/client.ts`，如需新增就地呈现再动 `src/ui.ts`。Issue 目前确认模型设置读取归工作台 `apps/workbench/src/scripts/home-model-settings.ts`，主会话已确认认领该路径及工作台共用的 `apps/workbench/src/i18n/renderer-gap-en.ts` 两句反馈。RSS 在 `plugins/official-integrations/rss/src/host.ts` 记录已收到的失败响应状态，Feed 的投影只读当前界面所需状态。只写复现证据要求的文件。
- 不改公共错误出口、动作合同、运行授权、RSS 出网安全策略、存储结构和调度；不增加通知通道、轮询或新资源。测试借用独立 Host、已安装插件与专用 Chrome，只在 RSS 外部传输或页面读取边界注入可控故障。项目与 Home 都使用临时数据。

## 本片证据

- B27-FF01／02。基点对受控 403 与断线提示 `provider_unavailable`，对返回 HTML 和被拒的跨站重定向提示 `protocol_invalid`，四次提示都带成功标记。候选按原收据显示拒绝访问、无效订阅、无效响应和暂不可用，四次都用失败标记，各显示一处即时反馈。诊断码在运行记录中仍可读取。两次收到响应的失败各记录 403、200，另外两次无收据，重定向目标收到零请求。首次拉取和恢复各导入一条消息；四次失败保留已有消息、成功时间及 ETag。六次显式拉取的提供方请求依次为成功、403、HTML、被拒重定向、断线、成功，各一次。收集结果丢失由 Feed 的真实同步服务经收集器替身复现，历史显示中断及重试说明。
- B27-FF02／03。添加表单的校验失败在基点与候选都只出现一个提示，基点切换类型后仍出现旧错误，候选切换后可见错误数为零，再切回仍可编辑原输入。默认从 36 氪改为目录中的下一项少数派，36 氪仍在目录首位。拉取计划明确拒绝和回执丢失分别显示相应原因。拒绝了一次不安全的订阅地址，随后注册一次真实来源。三次计划提交依次为受控拒绝、受控断线、真实 Host 保存，最后仍为同一个来源且计划为定时。
- B27-FF04／05。基点保留了 Feed 的筛选、选中来源和添加草稿，也保留 Inbox 的选中事项、材料与文稿草稿。候选在同一个提示中说明保留情况与原网络错误，恢复后的视图出现新数据、输入和选中项保持。两个版本中，每个列表的失败和恢复各一次视图文档请求。
- B27-FF06。初次打开与从账号连接返回到缓存模型表单时分别注入一次失败，各点一次 Retry 即获得真实 Host 文档。两处都显示英文错误原因与保留说明。回到 Issue 后按原描述实际保存。缓存表单的原始失败截图中提示在可见滚动区上方，几何断言也红；候选提示上沿 111、Retry 下沿 187.5，均在滚动区 82–882 内，草稿字段值保持。
- 最终 `pnpm build`、`node scripts/check-health-gates.mjs --base origin/main` 和 `git diff --check` 通过。最终定向运行 B27-FF01～06 及 RING-05 共 4 文件、6 用例，使用全机默认槽位、单文件并行、Chrome for Testing 和临时 Home。早期浏览器运行把临时目录传给了槽位进程，实际使用了片内槽位；最终运行仅在获得全机槽位后为测试进程设置临时目录。视觉实操覆盖 1440 浅色的 Feed 和英文 Issue、1024 浅色的 Inbox、390 深色的 Feed 添加来源。完整视觉矩阵、真实公共源联网和本人验收分别待核。
