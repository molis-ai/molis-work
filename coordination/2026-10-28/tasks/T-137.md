## 1. 背景

### 1.1 工作终端今天怎么起进程（T-136 第 1.1 节的路 ①）

1. 页面（`apps/workbench/src/terminal/panels.ts:33-35`）经共同 UiRequest 打宿主路由 `POST <project>/api/goals/:id/panels`。
2. 宿主 `apps/local-host/src/web-panel-routes.ts:96-136` 的 `openGoalPanel`：
   - 读 Goal（`web-panel.ts:66-83` 经 `goalsActions.collection` / `goalsActions.state`），父 Goal 拒（`:99-102`）；
   - **从请求体读** `runtime_kind`、`command`、`args`、`resume_session_id`（`:104-115`）和 **`cwd`**（`:116-118`：给了就用，不给才用项目首选工作目录）；

## 2. 目标

1. **起进程只有服务端一条路。** Goal 的终端由 Goals 自己的动作（受众 `user`、command、声明 `terminal:run` 与 `workspace:read`）经 `services.terminal.open` 在本项目已关联的工作目录里启动；页面只拿面板号、经 `molisPageTerminal` 附着。`/pty` 上任何连接——插件页面、工作台页面、control token——发 `spawn` 而不是只附着，一律拒，不起进程（S-103 加一分句，有拒绝用例）。
2. **宿主与工作台不再点名 Goals 的终端。** 删 `apps/local-host/src/web-panel.ts`、`web-panel-routes.ts` 与它们的路由（`web-project-platform-routes.ts:278-280` 的 `desktopPanelRoute`、`web-composition.ts:39`），路由表快照去掉对应行；工作台的 `startWorkTerminalClient` 与 `terminal/` 下的工作终端文件搬进 Goals 包（或删），`shell-page-renderer.ts` 不再画 `[data-tui-pane]`；`apps/desktop/src/web-host.ts:25` 的 `panel` 端口里只为面板路由存在的部分删掉。
3. **行为不变的部分照旧。** PRODUCT.md:123「终端必须持续显示所属 Goal，不自动发送」；父 Goal 的终端只读；多标签、关掉、重开、断线重连、续接运行时会话（若【方案】保留续接）。

## 5. 做法

### 已定的方向（细节在【方案】里给到函数级）

1. **启动只走 T-136 的服务。** Goals 项目一半加一个终端动作（例如 `goals.terminal.open@1`：输入 `goal_id`、运行时种类或自定义命令、`workspace_id`、可选续接会话；`scope: "project"`、`operation: "command"`、`audiences: ["user"]`、`permissions` 含 `terminal:run` 与 `workspace:read`、`scheduling` 照「等外部」的规则判断要不要 `concurrent`）。处理器读自己的 Goal、拒父 Goal（今天 `web-panel-routes.ts:99-102` 的规则搬进 Goals），再调 `context.services.terminal.open`。安装、项目、人从调用来，不收 `actor_id`、`cwd` 绝对路径（今天写死的 `"desktop-user"` 删掉）。
2. **程序由平台按配方选。** T-136 只收绝对路径；本单给服务加「按运行时种类」的程序（配方就是 `apps/desktop/src/launch.ts:55-61` 那一份，搬到平台能给服务用的位置，不复制第二份；`resolvePtyCommand` 解析命令名），并由服务设平台的环境变量（今天 `desktopPanelEnv` 的那一组，`MOLIS_WORK_GOAL_ID` 这种点名 Goals 的变量在【方案】里核有没有读者——起草时 `git grep` 在 `apps/mcp/src` 与 `apps/local-host/src/mcp-*.ts` 里没找到它的读者——没有就删）。自定义命令（`generic`）怎么收：只收绝对路径加参数数组，还是由平台用登录 shell 包一层，由【方案】提、统筹定；无论哪种，S-103 ⑤ 的有界检查照旧。
3. **`/pty` 只附着。** `pty-socket.ts` 对所有连接：`spawn` 必须 `attachOnly: true`，只许 `type`、`panelId`、`attachOnly`、`cols`、`rows` 五个键（今天 `:143` 只对页面连接这样查）；不符合就报错、不起进程。control token 连接附着哪个面板不加新限制（外壳是可信页面，S-04 的令牌照旧）。S-103 加分句 ⑦「`/pty` 上任何连接都不能启动进程，只能附着服务端已建的面板」，配拒绝用例。
4. **推进提示词归 Goals。** `desktopAdvancePrompt`（`apps/desktop/src/advance-prompt.ts`）与 `web-panel-routes.ts:60-85` 的读法搬进 Goals：Goals 自己读自己的 Goal、指引；Feed 的关联上下文经 Goals Manifest 的 `capabilities.consumes` 调 Feed 的公开动作（今天是宿主经 `feedQueryActions.linkedContext` 调，`web-panel.ts:84-88`），或按 BL-121 ② 的答复删掉。
5. **客户端只经 `molisPageTerminal`。** 搬进 Goals 的客户端不 import 工作台的 `terminal/connection.ts`、`panel-spawn.ts`（`tests/page-terminal.test.ts` 的 RAC-902 已经要求终端入口不点名插件；本单让它也不再含工作终端）。
6. **注释与词**：英文注释；不出现兼容标记词；不写迁移逻辑（红线）。错误码用 Goals 的主人名（`goals.<原因>`，`defineErrorCodes`），平台码照旧。
