## 1. 背景

插件作者和创作台生成的插件，读的是 `skills/molis-plugin-dev/`，不读 `docs/platform/PLUGIN-DEVELOPMENT.md`。BL-130 说，注册动作时的几条引用规则只写在后者里，Skill 里没有。现在核下来（`git grep -n -F -e background_job -e undo -e result_subject -- skills/molis-plugin-dev`）：

- **结果对象的推断规则写错了。** `skills/molis-plugin-dev/continuity.md:20` 写「不声明时按“输出里唯一带 id 与 version 的记录”推断」，和代码不符。真实规则在 `packages/contracts/src/platform/action-subjects.ts:66-72` 的注释里（`PLUGIN-DEVELOPMENT.md` 第 298 行写的是同一条）：
  - 只对「既不是查询也不是导航、恰好写了一种 `subject_kinds`」的动作生效；
  - 输出本身带字符串 `id`，就用输出本身；否则用输出顶层唯一一个带字符串 `id` 的对象字段；
  - 版本取那个对象的 `version`，没有就取 `revision`；
  - 输出里找不到这样的对象，就看输入：输入带字符串 `id`，就指它，没有版本；
  - 没有任何东西检查推断对不对，所以会写东西的动作应当声明 `result_subject`。
- **`undo` 的通用规则没有。** Skill 里只在 `contextual.md:36,56` 讲事项推荐（intake）时提到 `undo`，没有讲 `undo` 本身怎么声明（`PLUGIN-DEVELOPMENT.md` 第 304 行）。
- **`background_job` 一处也没有**（`PLUGIN-DEVELOPMENT.md` 第 306 行）。
- **「引用目标必须在同一次注册里」没有**（`PLUGIN-DEVELOPMENT.md` 第 303 行）：`undo`、`background_job.status`、片段与事项推荐的选项目标，都只能指向同一份 Manifest 的 `actions` 或同一次 `registerProvider` 的 `definitions`。
- 片段与事项推荐的选项已经写在 `contextual.md:13-24`，不用补。

## 2. 做什么

1. `continuity.md:20` 括号里那句推断规则，改成第 1 节列的真实规则。照代码注释写，不照记忆写。
2. 把三条规则补进 Skill：`undo` 怎么声明、`background_job` 怎么声明、引用目标必须在同一次注册里。放在 `continuity.md` 或 `host.md`，哪里贴切放哪里，开头一句写清什么时候用得上。内容以 `PLUGIN-DEVELOPMENT.md` 第 303、304、306 行和对应的注册检查代码为准：在 `packages/plugin-sdk` 与 `packages/kernel` 里找到检查这几项的地方，核对字段名和被拒的条件，【交接】里写出你核对的 `文件:行`。
3. BL-130 那一行：四项（撤销、后台任务、片段与事项推荐的选项、结果对象）都在 Skill 里写了，就删行；还差哪项，就把行改成只写还差的。
