## 阶段总览与执行批次

阶段总览保留各条线的目标与退出条件；实际逐批交付、依赖、可并行项及 UI 要求统一看[执行目录](../spec.md#execution-batches)；要服务端的需求看[服务端批](server-batch.md#server-batch)，不在阶段 0～4 里。

### 阶段 0：收口（防腐线合完立即开始）

[01～02](batches/01.md) 核准收尾基线、需求差距与归档／验收去处；升级基础接 [05](batches/05.md)。用户已指定 01 先行；[逐项结果](batches/01.md#baseline-01)与[试用单](acceptance-01.md)已备。02、真实 Home、Memory 仍按各自边界。

**退出条件**：

- 防腐收尾基线、需求与实现差距、原在途 PR 去向已核对
- 完成项可归档，未开始和未验收需求如实保留
- 验收单已备好
- 阶段 1 的目录、输入、用途分工与风险定位已有决定。验收方式等未定项按实际依赖处理，不阻塞独立设计。

### 阶段 1：基础路径与共同设计

[03～27](batches/03.md) 形成可运行基础路径与共同设计：公共资料、输入、首页、插件和升级基础；[16](batches/16.md) 完成文字与样式一次切换。

**退出条件**：

- 主对话与后台任务的连续交办、进展、控制及恢复已给出可操作切片，#1730 的三条新增路径可操作且模拟部分标明，公共合同可复用部分与必要缺口清楚
- 三处入口用同一个输入框
- 一个只有内容的技能包能装上，助理和 Coding 都看得见、用得了
- harness A 批在真实目录、真实模型下实走通过
- 风险和 Work Brief 两个插件能装、能用，基础首页在未安装 Work Brief 时可用，启用后的综合首页与停用恢复走通且共用来源／呈现
- Schedule 的任务能读待办、Inbox、日程、目标
- 采集设计与评测案例可审阅，覆盖和缺口清楚
- 公共资料、目录、工作台导航在 Coding 及另一消费者中接通
- 创作台真实断点及可操作切片已给出
- 引导的完整路径已有可操作高保真，所有全局/项目/插件设置有出现时机与保存主人，场景与生成页面必要合同已定
- 现有入口已在 16 一次切到新的文字与样式格式
- 实施可进入阶段 2。

### 阶段 2：个人工作完整可用

[28～56](batches/28.md) 把材料、历史、明确交办、场景引导、简报与真实发行物接成个人工作完整路径；M1 范围未定前保留原完整退出条件。

**退出条件**：

- 所声明覆盖的手动与 AI 工作可从实际操作追到版本、执行和结果，缺口、权限与恢复可核对，评测和其他消费者能经公共能力读取同一事实
- 分批接入未齐时不称采集内部完整。公共资料消费者、历史引用和过程项接好并回读通过后才退役 Files
- Sessions 已有历史可发现、读取并正确归入项目，未接通来源仍列缺口
- 采集、历史查询和最小评测路径使用同一真实事实，报告不把导入历史算作新增工作
- 真实代码与混合材料可多位置带入，返回、模型失败、改范围和重启后仍能在项目中接着工作，未处理文件有明确去处
- 用户能从用途或材料开始，经引导配成场景和可实际执行的项目助理团，生成新的交互首页、完成真实第一件工作，重启后继续
- 不同类型任务可复用同一准备过程，设置从引导与正式设置入口读写一致，关键失败/撤权可恢复
- 按用户设定周期生成的简报能刷新、追溯变化并点进去处理，跨重启和错过时刻可恢复
- 回执在中断、换轮、重启后说得清当前要求
- 个人助理能在 A 运行时接住 B、回答 C、把补充送回 A，任务进展和控制可见，刷新／重启无重复派出，真实操作与本人体验分别记录
- Coding 一个真实任务从开始到交付、中途补充和重启后都接得上
- 能装到第二台 Mac，升级不丢数据
- 语言与皮肤切换后所有插件文字、样式一致。

连续两周的简报效果观察从可用时启动，记录实际覆盖、失败及未完成项；与阶段 3 的独立开发并行。两周未结束不能宣称稳定性已验收，但不让所有能力共同等待。创作台的新能力插件路径可延续至阶段 3，阶段 2 的局部通过不代表 BL-377 完成。

### 阶段 3：持续工作与创作

[57～75](batches/57.md) 形成持续工作、子代理、服务接入、创作修订和真实效果验证。服务端需求另排，Memory 原暂停保留。

**退出条件**：

- 不发消息时，助理也能拿出经你点头就能用的下一步，并在中断、重启后接着做
- 建议依据与实际呈现、操作、后续结果可核对，评测能区分失败、拒绝、正确不行动与未知，并追到原始证据和判定方法
- 交出去的子任务能直接对话、能回到父任务
- Coding 按已选质量要求验证，并在有效授权或显式人审满足后生效，AI 代批不冒充真人批准
- Sessions 三类场景按完整厂商清单核验，未接通项不能算完成
- 新能力插件创作完整路径有正式安装、独立使用、修订及恢复证据，C2 业务数据可导出且同批旧记录升级后仍可处理，C5 每个已定主推角色有 2～3 个可安装、可改用的样例
- 四份 Prologue 策略各有真实任务连续性、质量与用量的对照结果，不以单纯省 token 宣称改善。

阶段 3 的主动行为、周期报告、直接对话、外观制作和导入导出都接到既有场景，按需补配置，不重新做一次首跑。阶段 2 的场景闭环不代表 Onboarding 整项完成；覆盖清单与 ONB-01～49 仍以原需求书逐项验收。

### 阶段 4：复杂场景

[76～89](batches/76.md) 完成复杂场景、两条创作路径与整条路线对账；团队、同步、团队记忆和 M2 在独立服务端批。

**退出条件**：

- [82](batches/82.md) 的创作台整项、[83～85](batches/83.md)、[88](batches/88.md) 对应产品原验收满足（86、87 已移到服务端批）
- [89](batches/89.md) 逐项对账，未完成、暂停、未批准和服务端未开工分别保留，不能以路线目录填满结项。
