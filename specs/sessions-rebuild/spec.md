# Sessions：外部 AI 工作导入、持续跟进与会话接续

状态：需求草案（2026-10-28）；用户已定覆盖国内外主流公司的 AI 开发工具，不限 Codex 与 Claude Code；冷启动导入、持续了解进展、直接控制外部会话三类场景都要；工具接入并获准读取后，自动发现范围内已有会话，无需逐个导入，查看历史不启动执行。已有明确的目录／仓库与项目关联时自动归入，关系不明确或有多个候选时由 AI 建议、用户确认或改选，不自动新建项目。跨工具交接时由用户选择停止原任务后接手，或保留原任务并行继续。场景、厂商、自动发现、项目归属及交接选择已定，交互与接入细节待继续梳理；尚未实现或验收。本轮交付为概念方案与需求记录，先不开发。负责人：Codex（需求维护），实现待分配。

## 1. 要解决的问题与既有决定

用户在不同 AI 工具中推进同一项目，既要把已经积累的背景带入 Molis，也要让后续工作进展持续可见，还要在 Molis 中恢复外部会话、发送消息和交接工作。不能只接两家海外工具，再把国内工具或其他主流厂商留为无期限后续。

旧 Sessions 已于 2026-10-23 随 SC-4 下线。当前 MCP 的 Runtime／项目关联不等于会话历史读取或恢复；现状见 [PRODUCT](../../PRODUCT.md)、[SC-4](../repository-anti-corruption/slices/sc-4-sessions-offline.md)。本需求承接 BL-177 与产品建议 B2；会话目录与恢复、普通消息、跨 Runtime 交接、会话搜索和首页「说一句」仍在完整范围内，不因本轮先确定厂商覆盖而删减。

沿用 2026-10-18 的决定：Sessions 是平台事实，不恢复旧 Sessions 插件。外部工具拥有原生会话与执行状态，Molis 维护自己的关联和访问入口；不能通过读到一份日志就声称接管了原工具的运行。

### 1.1 三类场景都保留（2026-10-28 用户已定）

| 场景 | 用户实际要做成什么 | 与已有能力的分工 |
| --- | --- | --- |
| 冷启动导入已有工作 | 已在外部工具讨论和开发一段时间后，把获准历史带入 Molis，了解项目背景、目标、约定、已定决定、已有成果与未完成事项，减少重新解释；可纠正整理结果并从当前进度开始工作 | [Onboarding](../onboarding-coverage/spec.md)承接首次使用、新建项目或已有项目补充资料的动线；Sessions 提供真实来源、历史与会话定位，项目资料及业务内容仍归原主人 |
| 持续了解工作进展 | 后续继续在外部工具工作，Molis 能取得获准的新记录和变化，助理、项目概览、Work Brief 可据此更新理解、建议及简报，用户能回到原始依据 | Sessions 的来源适配把可观察事实提供给平台共用采集；[观测和采集层](https://github.com/molis-ai/molis-work/blob/main/specs/observation-collection/spec.md)管理记录与缺口，助理和简报分别消费，不再各建一套历史读取与采集链 |
| 直接控制外部会话 | 从 Molis 找到并恢复指定外部会话、发送普通消息，或把任务及必要上下文交给另一工具继续；能看到实际接收对象、执行状态、结果与恢复入口 | Sessions 的公共控制能力调用外部工具的真实接入端口；原工具继续拥有会话与执行事实，平台复用服务连接、任务授权、输入回执和工作台交互 |

三类是同一需求的完整范围，不能用历史导入替代持续跟进，也不能用能读历史替代会话控制；第三类不再作为可有可无的后续方向。旧插件删除的决定保持：按平台公共能力组织三类用户场景，不恢复旧包、旧库或整套旧界面。

冷启动时，AI 基于获准原始记录整理可纠正的背景、决定与未完成事项，并保留来源和历史发生时间；用户陈述、工具回执与 AI 推断分别表达。读取完成后模型整理失败，应保留已取得的合法材料和有效结果，可重试或调整范围继续。原有成果不能因今天导入而记为今天新完成；长期说明、记忆与其他业务内容的正式写入沿各自有效授权与编辑流程，不仅凭一份摘要覆盖现有事实。

持续跟进沿已启用的读取／采集范围补读新变化，保留进度、来源截止时间和无法取得的部分。断线、重复读取、晚到记录与重启不能重复计算成果；用户在原工具或 Molis 中作出的有效纠正，后续理解应能反映。停止采集后显示记录截止时间，不能继续用旧记录声称当前状态。仅首次导入不自动启用持续跟进；沿用 Onboarding 已定的一次性导入与持续委托区分。

直接控制沿当前任务与连接的有效授权执行，已有许可不重复确认。读取、采集、恢复执行与发送消息的实际范围分别可见，读取许可不推导控制许可。恢复原会话和向另一工具交接是不同操作：前者验证原会话接续，后者保留来源关联并说明新接手方与已完成效果，不把新会话冒充原会话恢复。回执丢失、停止、撤权和重启沿真实结果接续，不能因重试重复发送或执行。

### 1.2 获准后自动发现已有会话（2026-10-28 用户已定）

用户接入某个工具并允许读取后，Molis 自动发现获准范围内的已有会话，用户无需逐条登记、粘贴会话标识或重复点击导入。账号、工具及允许读取的项目／目录／历史范围沿同一连接和授权配置；已有有效许可直接复用，不能因重新打开页面、断线恢复或重启再次要求相同确认。未接入或未获准的来源不参与扫描，发现不扩大读取范围。

发现过程显示正在读取的来源、已有结果与未完成部分，大量会话逐步呈现，不能长时间无反馈后突然出现全部内容。来源暂不可用、需要登录、权限不足和扫描失败与“没有历史”分别显示；已有有效结果保留，恢复后从实际进度接续。重试、重复扫描和不同入口读取同一原生会话不产生重复目录项或重复导入成果；不同账号、地区版本及工具中碰巧同名的会话也不能误合并。发现身份与去重沿公共来源合同，不另造各入口名单。

用户可查看并收窄读取范围、排除来源或停止读取；后续发现、历史查询和搜索结果遵守最新有效范围。异步读取返回前再次核对权限，不能把已撤权内容重新展示或写入。既有合法记录的保留／删除仍沿平台采集和资料规则，本次不隐式清理旧数据。查看列表或历史不会恢复 Agent、发送消息、启动命令或自动启用持续跟进；对应操作沿已定的三类场景及各自有效委托。

会话发现与项目归属是两件事，归属按下节已定规则处理；不把同名目录、会话标题或模型推断当成已确认的项目身份。暂不支持自动发现的工具保留为能力缺口，可提供实际可用的导出／手动接入路径，但不以该路径冒充自动发现已经完成。

### 1.3 复用明确的项目关联（2026-10-28 用户已定）

发现的会话已有用户明确确认的项目归属时沿用该归属；其余会话若能匹配用户已明确保存、当前仍有效且唯一的目录／仓库与项目关系，自动归入对应项目，不因来自另一工具、刷新列表或新发现一条会话重复要求选择。项目设置、资料入口和 Sessions 共用项目／目录关系的原主人，不另存一份 Sessions 专用默认项目规则。

“明确关联”必须是可核对的实际目录或仓库与项目的关系。单次历史选择、同名目录、相似标题、只有一个候选或 AI 推测，不单独构成自动归入依据；共享输入目录或仓库存在多个项目关联时按不明确处理。既有单条会话的人工指定优先，后续扫描或晚到的 AI 建议不覆盖用户改选。

没有明确关系、有多个候选或原关系失效时，由 AI 基于获准的来源信息给出项目建议及简短理由，用户确认或改选；用户未决定、拒绝或建议失败时保留未归类状态，仍可按原读取许可查看历史。不能猜一个项目落库、自动新建项目，或把没回应当作确认。缺少目标项目的操作只暂停依赖该归属的部分，不阻塞其他来源的发现与读取。

归属与依据可查看和纠正，保存后跨刷新、重连和重启保留；改变一条会话的归属不自动修改整个目录／仓库的项目关系。项目删除、失去访问权限或关联被移除后，后续访问与自动归入核对当前状态，不能靠旧绑定恢复访问，也不能自动创建替代项目。改变归属不搬移磁盘文件、不改写原工具历史或正在执行任务的目录。

本节明确发现会话的归属规则。现役 MCP 的 Runtime 项目连接仍有其已实现流程，产品文档须区分现状与待实现要求；新归属应经同一项目主人和公开合同接入。自动归入本身不授予读取、控制或执行权限；实际访问和发送继续核对当前调用者、目标与有效授权，已有有效许可直接复用。

### 1.4 交接时由用户选择原会话的处理方式（2026-10-28 用户已定）

把一项工作交给另一工具时，如果原会话仍在执行，由用户选择原任务如何处理，不固定为先停原任务，也不默认两边并行。界面用实际的工具、会话与任务名称说明选择对象，并展示原任务状态与接手目标：

| 选项 | 执行后发生什么 |
| --- | --- |
| 停止原任务后接手 | 只停止原会话中本次交接的当前执行，确认已停及已发生的效果后，再让目标工具接着做；原会话、历史和成果保留 |
| 保留原任务，并行继续 | 原任务继续运行，目标工具按本次选择的任务范围和有效授权开始工作；明确显示两边都在运行及各自执行位置，沿已有工作区隔离与成果审查规则处理共享内容 |

用户可以取消交接，取消选择不停止原任务，也不启动接手方。原会话已经空闲或完成时显示实际状态，无需要求用户选择一个没有运行的任务是否停止；不能为了交接重新启动原任务。

用户在本次请求中已经明确说“先停下这个，再交给另一个工具”或“两边继续并行”，即视为已作出对应选择，展示该选择并沿有效授权继续，不再重复提问。未表达选择时先呈现选项；预选、沉默、关闭界面和等待超时不当作决定，也不允许 AI 自行选择。该选择约束本次明确的原任务与接手目标，不自动形成所有未来交接的长期默认规则。

选择停止后若原工具不支持停止、停止失败或状态未知，保留交接准备和已完成结果，如实说明原因，不能假报已停并启动接手执行；用户可重新选择实际可行的方式。原任务停止成功而接手方启动失败时，分别显示两边真实状态，提供重试接手或继续原会话的入口，不隐式重启原任务。选择并行时不能暗中停止原任务；两边的状态、成果与失败分别可见，不将一边完成视为整体完成。

同一次交接的选择和进度跨等待、重连与重启保留；恢复时先核对真实效果，不重复停止、创建接手会话或发送同一工作。当前任务、目标或授权发生实质变化时沿对应规则重新核对，旧选择不覆盖新范围。任何选择都不停止其他无关会话或进程，不改写原历史，不扩大读取／执行许可。

2026-10-28 团队共享边界已定：发现、归入项目及持续采集个人外部会话不使它自动向项目成员公开。分享选定内容与控制原会话各自核对有效授权，不能因看到共享成果就恢复、发送、停止或交接原会话；列表、搜索和 AI 输出同样遵守[团队协作需求](../team-collaboration/spec.md)的访问范围。

## 3. 各家必须核对的用户能力

每个产品入口按三类场景分别核对：获准历史的导入与整理、后续变化的持续读取、发现与关联会话、读取可展示历史、搜索、返回原会话、恢复执行、发送普通消息、获知进展与需要用户处理的状态、向其他工具交接。来源、账号、项目、会话和当前执行目标须可辨认；同名项目或不同账号的同名会话不能混用。

官方文档已描述会话恢复的工具，也必须通过真实产品路径证明 Molis 能正确调用。仅找到日志、提供模型、配置好 MCP、打开应用首页或启动新对话，都不能记成“原会话恢复成功”。没有开放对应能力或尚未验证时，显示具体缺口及可用的返回原工具、导出或交接入口；不得显示空列表冒充没有会话，也不得以静默新建会话冒充续接。受限项仍记为未完成，改变承诺范围另行明确。

本机、IDE、桌面和云端采用各自实际存在的访问方式；优先公开接口、正式命令、协议或用户授权的导出／本地记录。不假设各家都提供完整 API，也不靠改写另一工具的私有库伪造可恢复会话。接入现有云端会话不等于在本需求中自建远程执行平台。读取会话也不自动授予发送、运行命令或修改文件的权限，沿用当前任务与服务连接的有效授权。

交接至少让接手工具得到原任务、有效要求、已确认决定、成果位置、未完成事项和必要来源；原始记录与交接内容分别标明。不能声称另一工具内部运行状态、私有推理或所有隐藏上下文已迁移。具体交接界面及默认带入范围在下一步产品设计中明确。

## 4. 机制、边界与依赖

- 各厂商差异收在其接入适配中，平台共用会话目录、展示、搜索、定位、输入和恢复合同；不在首页、每个插件或宿主路由分别维护厂商名单。先复用现有 Runtime 接入与公开合同，再补已证实的缺口。
- 保留原生记录的主人；Molis 的索引或展示缓存须能回到来源并反映读取失败、权限变化和来源变化。账号、凭据、授权归原服务；项目、目录及运行位置沿[项目资料方案](../product-flow-governance/workspace-and-materials-design.md)，不另配一套 Sessions 工作目录。
- UI 沿[统一输入](../unified-input-voice/spec.md)与[工作台布局](../product-flow-governance/spec.md)，实施前做包含多厂商真实或逼真内容、加载、长历史、失败与恢复的高保真可操作切片。
- 需要 AI 总结或整理交接时，经现有 Agent Host／Prologue 消费已授权内容，给出有出处、可检查和可修正的结果；失败保留原记录与有效草稿。普通列表、搜索与返回原工具不强制先等模型总结。
- 断线、取消、撤权、来源升级和重启后核对实际状态；结果未知的消息或执行不能盲目重发。浏览历史不启动执行，恢复必须针对明确会话及有效授权。
- 接入外部 IDE 的既有会话不恢复 Coding Q8 已取消的 Molis VS Code 扩展、Tab 补全或行内编辑开发，也不改变 ACP 原方向未排期的状态。旧 Sessions 数据清理沿 SC-5 的独立授权，本轮不读取或恢复旧库。

本轮只整理本文与 Onboarding、主动助理的场景接线，以及产品／安装文档中的现状与目标边界，更新需求索引及演进计划／Backlog 的关联条目；不开发或操作真实会话。后续实现边界预计涉及公共 Runtime／会话合同、外部工具适配、平台会话服务与工作台组件；具体文件在读取当时实现后确定。Coding、个人助理及原生外部工具的领域数据仍归原主人，不复制为第二份执行事实。

## 6. 接续事项

已定：冷启动导入、持续了解进展和直接控制外部会话三类都做；国内外主流工具都覆盖，不能收缩为两家首批；产品能力差异逐项保留为缺口。工具接入并获准读取后自动发现已有会话、无需逐个导入及查看不执行已定。明确且唯一的目录／仓库关系自动归入、不明确由 AI 建议并经用户确认、不自动新建项目已定。原会话运行中交接，由用户选择停止后接手或保留并行；明确请求直接复用，未选择不执行已定。下一步依次明确查看与继续的交互、交接带入范围，再完成技术方案与高保真；这些未定细节不改变已确认的三类场景和厂商覆盖。实施仍沿[演进计划](../post-anticorruption-roadmap/spec.md)的 C 轨与实际依赖，不因本轮建档自动开工。
