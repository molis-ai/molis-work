## 1. 背景

T-087 把「移除」那一半（`removeManagedConnectorTool`，`:76-93`）改成了声明过的拒绝，`:87-89` 的 `let owner: unknown; try {…} catch { throw toolInstallErrors.invalid(…) }` 是本单照抄的写法。本单收「读」这一半。

- 现状：`readManagedConnectorTool`（`:96-104`）依次做这些：
  1. `:97`：校验 id 的形状，不对就抛 `invalid`；
  2. `:98`：用 `realpathSync(home)` 拼出安装目录；
  3. `:99`：`realpathSync(directory)`，和目录不一致就抛 `invalid`；
  4. `:100`：读并解析 `installation.json`；
  5. `:101-102`：核对记录（id、`ready`、目录、方案、可执行文件在目录里且真实路径不变），不符就抛 `invalid`「已有安装与本次方案不符，请重新准备接入」；
  6. `:103`：返回 `{ id, directory, source, executable, runtime_path }`。

  `:99`、`:100`、`:101`、`:102` 任何一处先抛原生错误，后面的核对就走不到。函数只读，不写、不删任何东西，所以不存在「抛错前已经改了东西」的问题，只是码不对。
- 抛原生错误的情形：

  | 情形 | 抛什么 | 本单 |
  | --- | --- | --- |
  | 安装目录不在（`:99`） | `ENOENT`，`code` 是 `"ENOENT"`，消息带本地路径 | 收，`RAC-1694` |
  | 记录不在（`:100`） | `ENOENT` | 收，`RAC-1694` |
  | 记录不是合法 JSON（`:100`） | `SyntaxError`，没有 `code` | 收，`RAC-1694` |
  | `installation.json` 是目录（`:100`） | `EISDIR` | 收，`RAC-1694` |
  | 没有读权限（`:100`） | `EACCES` | 由同一个 `catch` 收下，不写用例：CI 有时以 root 跑，`chmod` 拦不住 root 读，用例会不稳 |
  | 记录是 `null`（`:101`） | `TypeError`（`value.id`），没有 `code` | 收，`RAC-1695` |
  | 记录是数组 | 不抛原生错误：`value.id` 是 `undefined`，`:101` 已经抛声明过的 `invalid` | 用例留着当守卫，main 上本来就绿 |
  | `ready` 记录缺 `executable`（`:102`） | `TypeError`（`value.executable.startsWith`） | 收，`RAC-1695` |
  | `ready` 记录缺 `source`（`:102`） | `TypeError`（`value.source.kind`） | 由 `readyRecord` 收下，不写用例 |
  | `ready` 记录缺 `runtime_path` | 读成功，把 `undefined` 交给 `managedCliLaunch`，到 `connector-cli-launch.ts:12` 的 `[...installed.runtime_path, …]` 才抛 `TypeError` | 由 `readyRecord` 收下，不写用例 |
  | 可执行文件不在（`:102`） | `ENOENT`（`realpathSync(value.executable)`） | 收，`RAC-1695` |

- 什么时候会碰上：
  - 安装成功时，`:71` 用 `writeFileSync` 重写记录（先截断再写）。进程在这中间被杀，记录就是空的或半截的。安装失败时 `:73` 的 `catch` 会删整个目录，但进程被杀时走不到它。
  - 有人手工改坏记录，或备份只恢复了一半（`docs/system/HOME-DATA.md:260` 写明，这些记录要和连接库一起备份）。
  - 安装目录或里面的可执行文件被清理工具、手工删掉，而连接还指着这份安装。
  - 注意：安装中途留下的早期记录（`:60` 先写的 `{ id, source, created_at }`，没有 `ready`）main 上就已经走声明过的拒绝，不在本单要修的范围里，改后仍是同一个拒绝。
- 出口，和 T-087 是同一条路：
  - 内核记下失败时，原生错误有 `code` 就照记（`packages/kernel/src/action-settlement.ts:93-95`）；
  - 进程内调用方拿到的是动作服务原样抛出的错误（`packages/kernel/src/action-service.ts:140`、`action-settlement.ts:115`）；

## 2. 目标

1. 安装目录不在：经 `connectors.connection.check@1` 检查指向它的 CLI 连接，拒绝的码是 `connector.install.invalid`、kind 是 `invalid`，文案是「受管理安装不存在，请重新准备接入」。连接原样留着（`RAC-1694`）。
2. 记录读不出来（不在、不是合法 JSON、是目录）：同样的码和 kind，文案是「安装所有权记录无法读取，请重新准备接入」（`RAC-1694`）。
3. 记录读得出来，但不是完整的 ready 记录（`null`、数组、缺 `executable`），或者记录里的可执行文件不在：同样的码和 kind，文案是现有的「已有安装与本次方案不符，请重新准备接入」（`RAC-1695`）。
4. 完整的 ready 记录、可执行文件在：返回值和以前一字不变。
