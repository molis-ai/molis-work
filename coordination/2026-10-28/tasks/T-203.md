# T-203 Pages 评论输入框按字数封顶 20000，不再用按 UTF-16 单元数的 maxlength，含两单元字的评论不再被页面截短

> **这条在 main 上成立：评论输入框的上限按 UTF-16 单元数，动作 schema 和库按字数，两单元的字多的评论在页面上先被截住。**
>
> - 发送评论的动作 `pages.comments.append@1` 的 schema 给评论正文的上限是 `maxLength: 20000`（`plugins/native/pages/src/comment-actions.ts:30`）。动作层用 Ajv 校验，Ajv 的 `maxLength` 按码点数：`packages/kernel/src/action-schema.ts:41-42` 的选项里没有 `unicode: false`。库也按字数：`plugins/native/pages/src/comments-store.ts:68` `if (!body || [...body].length > 20000) throw pagesErrors.invalid("评论须为 1 到 20000 个字");`（T-085 合入）。
> - 页面的输入框却写着 `maxlength="20000"`（`plugins/native/pages/src/comment-side-view.ts:12`）。HTML 的 `maxlength` 数 UTF-16 单元，仓库自己的浏览器用例也这么说（`tests/content-portable-regressions.e2e.test.ts:141`：「The input's maxLength counts units too, so the answers are set by script」）。
> - 后果（按代码推断，没跑过）：一个 🟢（U+1F7E2）是一个字、两个单元。评论里全是这样的字时，输入框只收 10000 个，多出来的部分浏览器悄悄丢掉，不提示；schema 和库本来收到 20000 个。10001～20000 个这样的字的评论，经动作或 MCP 发就收下，在页面里却写不出来。字数相同的汉字不受影响（每个一个单元）。
> - 为什么此前没人量到：`tests/pages-assistant-surfaces.e2e.test.ts:54` 用脚本直接给 `.value` 赋值，浏览器的 `maxlength` 只管用户输入，管不到脚本赋值，所以现有用例从没碰过这个上限。
>
> **修法起草时定、写死：**
> - 去掉输入框的 `maxlength` 属性（`comment-side-view.ts:12`）；
> - 在评论侧栏客户端 `comment-side-client.ts:70` 的 `input` 处理函数里，先把输入框的内容按字数封顶在 20000 个字（超过就改成前 20000 个字），再读它进草稿、再决定「发送」按钮；
> - 页面资源：`comment-side-client.ts` 只在 `/assets/molis-work-pages-editor.js` 里，涨约 108 字节（起草时用 esbuild `--minify-whitespace` 在一份拷贝上量过这一个文件，不是整包），需要一次性放行 `APPROVED_CEILINGS`，等【统筹答】（第 8 节第 1 条）；
> - 一个新的浏览器用例文件 `tests/pages-comment-draft-length.e2e.test.ts`，真打字（`Input.insertText`），不赋值。
>
> **没选的另一种修法：把 `maxlength` 放宽到 40000。** 每个字最多两个单元，所以 20000 个字不会超过 40000 个单元，输入框就不会拦住合法的评论，零字节、不动门禁。没选，因为它改变了超限时的体验：20001～40000 个字的评论（比如整段粘贴）不再在输入框里被截住，而是一路送到动作层被 schema 拒，页面显示的是 `validateActionValue` 拼的话：「输入不符合能力合同：/body maxLength」（`packages/kernel/src/action-schema.ts:114-115`），人看不懂。按字数在输入框封顶，超限时的样子和现在一样（输入框不收），只是单位对了。若统筹更想要零字节的那一种，见第 11 节末尾的问题。
>

## 1. 背景

- 三处口径（评论正文的上限，都是 20000）：

  | 位置 | 怎么数 | 超限时 |
  | --- | --- | --- |
  | 动作 schema，`comment-actions.ts:30` `body: { type: "string", minLength: 1, maxLength: 20000 }` | Ajv，码点 | `actions.input_invalid`，话是「输入不符合能力合同：/body maxLength」 |
  | 库，`comments-store.ts:68`（`PagesComments.append`，`body` 是去掉首尾空白的 `input.body`） | `[...body].length`，码点 | `pages.invalid`「评论须为 1 到 20000 个字」 |

## 2. 目标

1. 含两单元字的评论写得进输入框：粘贴或输入 12000 个 🟢（24000 个单元）以后，输入框里是完整的 12000 个，点「发送」收下，库里读回完整的 12000 个字（`RAC-1974`）。
2. 输入框仍然封顶在 20000 个字，按字数、不截在字中间：输入 20001 个 🟢，框里是正好 20000 个 🟢（40000 个单元，结尾是整字）；20001 个汉字，框里是 20000 个；封顶后的 20000 个字发得出去、被动作 schema 收下（`RAC-1975`）。
3. 留给刷新用的草稿（`localStorage` 里的 `body`）和发出去的就是封顶以后的那段，不是敲进去的更长的一段：页面不会发一条自己的输入框刚刚拦下的评论（`RAC-1976`）。
4. 输入框没有 `maxlength` 属性（`RAC-1977`）。
5. `pages-editor.js` 涨一次（约 108 字节），在 `APPROVED_CEILINGS` 里放行一次，冻结在实测数；别的资源一个字节不变。

## 3. 不做

- 不改动作 schema（`comment-actions.ts`）和库（`comments-store.ts`）：它们本来就按字数数。`pnpm actions:update` 应当没有 diff。
- 不新增文案、不加翻译调用（超限时的样子不变：输入框不收，不提示）。不加「还剩多少字」的计数器。
- 不把 `maxlength` 放宽到 40000（见开头「没选的另一种修法」）。
- 不抽共用函数，不放进 SDK、contracts 或 design-system（那会让 `full` 变 true）。「输入框按字数封顶」在整个仓库是同一类问题，一个由平台的插件框脚本一次做好的 `data-maxchars` 属性才是长久的办法，那是甲档，不在本单；见第 11 节末尾和交给统筹的报告。
- 不动块备注的两处 20000（`comment-side-client.ts:113`、`comment-editor-client.ts:60`）：口径一致，不是不一致；也不是评论。
- 不动 `comment-side-client.ts:41` 的线程标签 `slice(0,36)`、`comment-editor-client.ts:30`、`:41`、`:46` 的三处 `slice`：这是「按单元截可能留下半个字」那一类，不是上限口径。它们同样落在 `pages-editor.js` 里，各涨几十字节，要另放一次行；统筹要不要并进本单或另开一单，第 11 节末尾问。
- 不动 `editor-node-media.ts:36`、`:130`（网址卡名称 120、图片说明 200）：编辑器里的输入框上限，不是评论，也没有按字数数的库对着它。它们的另一端 `link.ts:71` 的 `raw.slice(0, 120)` 也按单元，同一类，不在本单。
- 不动别的插件和工作台里同样写法的 `maxlength`（PPT 的 `plugins/native/ppt/src/ui.ts:140` 大纲框 `maxlength="20000"`、问卷的 `plugins/native/form/src/browser/fields.ts:68` `input.maxLength = FORM_ANSWER_LIMIT`、角色的 `apps/workbench/src/characters/ui.ts:59` 与 `import-ui.ts:14` 的 `maxlength="20000"` 等）：各有各的 owner 和资源，另议。

2. **`comment-side-client.ts:70`**：一行换成两行，原样如下（上面多一行注释；缩进两格；除了 `const d=draft(),area=q('draft');`、`if(area.value.length>20000){…}`、`d.body=area.value;` 三处，其余和原行逐字相同）：

   ```ts
     // A comment is at most 20000 characters (comment-actions.ts, comments-store.ts). A maxlength attribute counts UTF-16 units and stopped 🟢 (two units) at 10000, so the box is cut here, to whole characters, before the draft reads it.
     q('draft').addEventListener('input',()=>{const d=draft(),area=q('draft');if(area.value.length>20000){const chars=[...area.value];if(chars.length>20000)area.value=chars.slice(0,20000).join('');}d.body=area.value;q('send').disabled=busy||needsSave()||!d.body.trim();delete d.message_id;d.request_id=crypto.randomUUID();persist();});
   ```

   说明：
   - `q('draft')` 的类型是 `HTMLTextAreaElement`（`comment-browser-types.ts:24`），`area.value` 是字符串；
   - 外层 `if(area.value.length>20000)` 先看单元数：单元数不超过 20000，字数一定不超过，这是绝大多数输入，不展开；
   - 超过时展开成码点数组 `chars`，字数也超过才改写：`chars.slice(0,20000).join('')` 是前 20000 个字，不会截在两单元字中间；字数没超过（12000 个 🟢 是 24000 个单元）就不动输入框，光标和撤销历史都留着；
   - 改写输入框只发生在超限的那一次输入里；`d.body=area.value` 在改写**之后**读，所以草稿、「发送」是否可点、`persist()` 存下的、`send()` 发出去的都是封顶后的那段（`RAC-1976`）；
   - 不加 `isComposing` 判断：只有超过 20000 个单元才会改写输入框，原来的 `maxlength` 到上限时同样会截断输入法的上屏；没人敲到这个数；

import test from "node:test";
import type { TestContext } from "node:test";
import { openPagesStore } from "./fixtures/plugin-home-stores.js";
import { pluginFrameBrowser } from "./fixtures/plugin-frame-browser.js";

// One 🟢 (U+1F7E2) is one character and two UTF-16 units. pages.comments.append@1 takes a comment of up to 20000 characters (comment-actions.ts,
// comments-store.ts); a maxlength attribute counts units, so the comment box stopped 🟢 at 10000. The box is filled through the browser's own text input
// (Input.insertText), which applies the box's limits. Setting `.value` by script, as tests/pages-assistant-surfaces.e2e.test.ts does, goes around them.
const wide = "🟢";

/** A real Pages document with its comments panel open in the side view, and what a person does in the comment box. */
async function openCommentBox(t: TestContext) {
  const browser = await openGoalBrowser(t, true); if (!browser) return null;
  const { command, sessionId, navigate, origin, projectId, homeDirectory } = browser;
  const pages = await pluginFrameBrowser(t, browser, "pages");
  const comments = await pluginFrameBrowser(t, browser, "pages", '[data-side-body="plugin:pages/comments"] iframe');
  const store = openPagesStore(homeDirectory);
  const page = store.create({ project_id: projectId!, title: "长评论", body: { type: "doc", content: [{ type: "paragraph", content: [{ type: "text", text: "已保存正文" }] }] } }); store.close();
  await command("Emulation.setDeviceMetricsOverride", { width: 1440, height: 960, deviceScaleFactor: 1, mobile: false }, sessionId);
  await navigate(() => command("Page.navigate", { url: `${origin}/projects/${projectId}/?openPlugin=pages&openItem=${page.id}` }, sessionId));
  await pages.waitFor(`document.querySelector('[data-pages-title]')?.value === ${JSON.stringify(page.title)}`);
  await pages.click("[data-pages-comments-open]");
  await comments.waitFor(`document.querySelector('[data-comment-title]')?.textContent === ${JSON.stringify(page.title)}`);
  return {
    /** Click into the box and type: a real click, then the browser's own text input. */
    async type(text: string) {
      await comments.click("[data-comment-draft]");
      await command("Input.insertText", { text }, sessionId);
      // The input handler has run once the Send button follows the draft.
      await comments.waitFor("!document.querySelector('[data-comment-send]').disabled");
    },
    /** What the box holds, counted both ways, and whether it is made only of `unit`. */
    box: (unit = wide) => comments.evaluate<{ units: number; characters: number; only: boolean }>(`(() => {const value=document.querySelector('[data-comment-draft]').value;return {units:value.length,characters:[...value].length,only:[...value].every(character=>character===${JSON.stringify(unit)})};})()`),
    /** The draft the page keeps for a reload, counted both ways; null when there is none. */
    kept: () => comments.evaluate<{ units: number; characters: number } | null>(`(() => {const saved=JSON.parse(localStorage.getItem('molis.pages.comments:${projectId}'));const draft=saved['${page.id}:'+saved.__active['${page.id}']];return draft?{units:draft.body.length,characters:[...draft.body].length}:null;})()`),
    hasMaxlength: () => comments.evaluate<boolean>("document.querySelector('[data-comment-draft]').hasAttribute('maxlength')"),
    /** A new whole-document discussion, with an empty box. */
    fresh: () => comments.click("[data-comment-new]"),
    async send() {
      await comments.click("[data-comment-send]");
      await comments.waitFor("document.querySelectorAll('[data-comment-messages] article').length===1 && document.querySelector('[data-comment-draft]').value===''", 20_000);
      assert.equal(await comments.evaluate("document.querySelector('[data-comment-error]').hidden"), true, "the person is told nothing went wrong");
    },
    /** The comments the document keeps, by length in characters, oldest first: what the store holds, not what the page shows. */
    stored() {
      const checked = openPagesStore(homeDirectory);
      try { return checked.comments.list(page.id, projectId!).flatMap(thread => thread.messages).filter(message => message.author === "user").map(message => [...message.body].length); }
      finally { checked.close(); }
    },
  };
}

  await box.type(wide.repeat(12000));
  assert.deepEqual(await box.box(), { units: 24000, characters: 12000, only: true }, "the box holds all 12000 🟢; a maxlength of 20000 stopped it at 10000");

});

test("RAC-1975 RAC-1976: the comment box stops at 20000 characters, never inside one, and the draft kept for a reload is the same cut text", { timeout: 120_000 }, async t => {
  const box = await openCommentBox(t); if (!box) return;
  await box.type(wide.repeat(20001));
  assert.deepEqual(await box.box(), { units: 40000, characters: 20000, only: true }, "20001 🟢 are cut to 20000 whole ones");
  assert.deepEqual(await box.kept(), { units: 40000, characters: 20000 }, "RAC-1976: the draft kept for a reload is the cut text, not the longer text that was typed");
  await box.send();
  assert.deepEqual(box.stored(), [20000], "the action takes what the box let through");
  await box.fresh();
  await box.type("字".repeat(20001));
  assert.deepEqual(await box.box("字"), { units: 20000, characters: 20000, only: true }, "20001 汉字 are cut to 20000, as before");
  await box.send();
  assert.deepEqual(box.stored(), [20000, 20000], "the second comment is kept whole too");
});

   为什么这样写，别改：
   - 打字用 `Input.insertText`（页面会话 `sessionId`），先 `comments.click("[data-comment-draft]")` 点一下让输入框拿到真焦点。浏览器的 `maxlength` 只管这种输入和粘贴，不管脚本赋值，所以**不要**改成给 `.value` 赋值再发 `input` 事件，那样 main 上也是绿的，证明不了什么（`tests/content-portable-regressions.e2e.test.ts:141` 的注释就是因此用脚本赋值的）；
