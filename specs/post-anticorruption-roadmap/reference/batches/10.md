## 给人讲清楚

首页、助理和 Coding 各有一个输入框，按键、附件、发送和打断的方式不完全一样，容易按错。这一批先做一个公共的输入框：文字、附件、发送、补充一句、排队、打断、选择发给谁，按键统一成已经定好的那一套，插件也能往里加自己的东西。做完后三处会换成同一个输入框（下一批接）。需要你做的：看输入框各种状态的样子并定下；还要定助理对外用哪几个词（比如「工作」「任务」「受托工作」怎么叫）。

### H4 对外用词方案

H4 的问题：「助理里『工作／工作简报／任务／受托工作／子工作』多词并存」。先查这五个词和相关词实际出现在哪。

**界面里实际有的**（括号里是英文）

| 词 | 在哪、指什么 |
| --- | --- |
| 工作（work） | 助理的单位：新工作、我的工作、切换工作、这项工作（`assistant-en.ts:29-70`，48 处）；「下一次发送给哪项工作」 |
| 任务（Task） | Coding 的任务框（「任务或补充要求」）和任务看板；Goals 规划里的任务；Jelly 的「拆解成任务」；Prompt 库里的一类（`assistant-en.ts:231`） |
| 子任务（sub-task，Coding 里是 Subtask） | 助理委托出去的一件：委托子任务、查看子任务、让子任务补改、停止子任务（`:114-121`、`:289-295`）；Coding 里同一件事的看板标签叫「子代理 · 角色」（Subagent） |
| 后台任务（Background job） | 由后台或定时发起的运行（`:12`、`:272`）；代码和错误信息里叫「后台作业」 |
| 受托于（Delegated by） | 被委托的一方看到的来源（`:284`） |
| 补充／打断／排队 | 补充：助理「补充这一轮」、Coding「补充：这步做完后读」。打断：Coding「打断：丢弃当前回复」。排队：助理托盘里的「排队」「回答留在排队里」，Coding 的同一个动作叫「下一轮再做」 |
| 轮（round／turn） | 同一个中文「轮」：助理英文写 round（38 处），Coding 英文写 turn（约 150 处） |
| 目标 | 在 Coding 和 Goals 里指 Goal（「关联目标」「下一轮关联目标」）；输入框的「发给谁」在需求里也叫目标，界面上则是「发到 主群」「回复 话题名」「下一次发送给哪项工作」「指向 组件」 |

**只在文档里、界面没有的**：「工作简报」（[work-brief 需求](../../../work-brief/spec.md)，还没做进界面）；「受托工作」（[主动式助理](../../../proactive-assistant/spec.md)里指被委托并持续推进的工作，界面写作「受托于 X」）；「子工作」（只出现在一份验证用例里，界面里只有「子工作树」，是 Git 的意思）。所以五个词里真正在用户眼前冲突的其实是「工作／任务／子任务」，其余是文档用词。

**三个方案**

| 方案 | 做法 | 好处 | 代价 |
| --- | --- | --- | --- |
| 一，两层（推荐） | 工作＝助理里一项持续的事，用户看到的单位；任务＝交给某个执行者（Coding、子代理、后台）去做的具体一件；子任务＝任务再委托出去的一件。简报单列为产物名，叫「工作简报」。「受托工作」「子工作」不对外：界面继续写「受托于 X」和「子任务」。英文统一 work／task／sub-task，一轮统一 turn | 与界面现状最接近：助理已经全说「工作」，Coding 与看板全说「任务」，要改的只是少数几处；层级清楚，三个词各管一层，也不与「工作区」「工作树」「工作流程」冲突（它们带后缀） | 要把 Coding 看板的「子代理」标签改成「子任务」（或明确它是执行者而不是对象）；英文 round 改 turn 约 38 处，subtask 改 sub-task 若干 |
| 二，全用「任务」 | 新工作→新任务，工作简报→任务简报，一切统一成任务／子任务／后台任务 | 口语、一个词 | 「任务」已被 Goals 规划、Jelly 拆解、Coding 看板各用各的意思，再当总词更挤；助理里 48 处「工作」和「我的工作」「切换工作」这套已经建立的说法都要换；改动面最大 |
| 三，全用「工作」 | 任务→工作，子任务→子工作，受托工作保留 | 词最少 | 与「工作区」「工作树」「工作流程」「工作简报」撞词，「工作」过载；Coding、Goals 规划与 Jelly 里的「任务」要整体改名；「子工作」读起来生硬 |

**推荐方案一**，理由：它基本是把现状写成规则，改动小；用户已经在助理里习惯了「工作」，在 Coding 里习惯了「任务」，两者指的本来就不是同一层；「受托工作」和「子工作」只存在于文档，不对外就没有改界面的成本。

**连带的三条小决定**（也建议随方案一定下来，因为输入框要用到）

1. **送达方式的三个名**：补充（默认）、打断并改向、下一轮再做。现在三处写法不一：[ai-input-receipts §4.1](../../../ai-input-receipts/spec.md) 写「这一轮结束后再做」，Coding 写「下一轮再做」，助理托盘叫「排队」。建议菜单用「下一轮再做」（短，Coding 已在用），键位说明里写「排队」（需求 10-27 已用这个词）。
2. **「目标」只指 Goal**：输入框的「发给谁」在界面上写「发到 {对象}」（英文 Send to），不再叫目标，避免和 Goals 撞词。需求正文里仍可叫目标（target）。
3. **一轮的英文**：统一 turn。Coding 约 150 处已是 turn，助理 38 处 round 一次替换。

**已定（用户 2026-11-04）**：随本批定样看实物时定，选方案一，三条小决定都照定样里的推荐。其中接收者那一行用「发给」，不是上面第 2 条写的「发到」：做定样时发现第 03 批连续对话定样和 PWA-130 已用「发给」，项目讨论现在的「发到」随实现改掉。记录见 [GLOSSARY](../../../../docs/system/GLOSSARY.md) U8 与[统一输入体验 §10](../../../unified-input-voice/spec.md)。

**按组件板实件重做，用户确认（2026-11-04）**：定样的控件换成组件板 `mw-*` 实件，版式与取舍不变；组件板没有的三处（多行输入框外壳、菜单项说明行、麦克风图标）标「组件板新增」，交 D 轨补标本，见[原型 README](../../../../docs/design/unified-input/README.md)。

定下来后再改 [GLOSSARY](../../../../docs/system/GLOSSARY.md)：现在 GLOSSARY 里没有「工作」「任务」「子任务」「受托」几个词的条目，需要新增，同时在「别叫」列写上被淘汰的叫法。本 PR 不动 GLOSSARY。

### 已定的点（统筹 2026-11-04 定）

盘点时列出的 5 个待拍板点，统筹 2026-11-04 在 [#1765](https://github.com/molis-ai/molis-work/pull/1765) 照推荐定下。它们都是落实已定的需求（10-27 的键位、「默认补充」、「Esc 只退局部菜单」），不改需求本身。

1. **分两层**：所有输入框共用编辑器层（长高、草稿、输入法守卫、附件条）；只有对 AI 说话的输入框带「补充／打断并改向／下一轮再做」送达菜单，对人和记录的输入框不显示。
2. **键位一起改**：助理、IM、创作台改成 Enter 换行、Cmd/Ctrl+Enter 发送；占位文案和说明弹窗同步改，改完后保留一次提示。
3. **创作台**：默认「补充」，「打断并改向」要明确可选，并接入输入回执合同。定样时用户 2026-11-04 选定和别处一样走发送按钮旁的 ▾ 菜单，不另加按钮（[统一输入体验 §10](../../../unified-input-voice/spec.md)）。
4. **决定理由型输入**（评审反馈、Jelly 指令、Goals 退回）：只对齐长高、输入法和草稿，不绑定发送键。
5. **IM 的 Esc**：只退出局部菜单，关面板另给明确入口。
