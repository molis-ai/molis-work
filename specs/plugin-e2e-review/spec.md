# 插件端到端复查与动线优化

用户 2026-09-30 提出：对已经有的插件功能逐个做端到端复查，找出功能不完整的地方和还有提升空间的地方；同时针对每个插件的功能做动线优化——用户进来就能用明白，但不是靠粗劣的文字提示，而是靠妥善的产品设计让产品自己解释自己的用法。

基线：共同分支 `feature/system-assistant`（2e837e8f，已含 Soft Workbench #101、放置 / Todo / 搜索 / 助理）。工作树 `~/code/goalboard-plugins`，分支 `feature/plugin-e2e-review`。

## 1. 「产品自解释」的判断标准

一个插件不靠说明文字也能被用明白，要同时满足下面六条。每条都能在界面上指出来，复查表按这六条给结论。

| 编号 | 检查什么 | 合格的样子 | 不合格的样子 |
| --- | --- | --- | --- |
| C1 入口 | 底栏切换器里的名字和一句话；进入后页头下的那句话 | 一句话说的是**用户会得到什么**，和页面上的第一个动作对得上 | 说的是实现方式（「导出 JSON」「本机 SQLite」）或和页面动作对不上 |
| C2 首屏 | 空状态与第一次进入 | 用户能看见**对象长什么样**（结构、示例、模板），只有一个主操作，点下去就进入对象本身 | 一张插图 + 一段话 + 按钮；或者主操作和次操作一样重；或者首屏是设置/配置 |
| C3 主路径 | 从新建到拿到结果 | 每一步的下一步都在视线内，控件本身说明它的作用（占位、标签、分组、顺序）；不需要先读任何东西 | 要靠 tooltip、说明段落、README 才知道下一步；关键动作藏在「更多」里；步骤顺序和页面顺序不一致 |
| C4 去向 | 做完之后 | 看得出**存在哪里、能用到哪、下一步是什么**（位置条、完成提示、关联、导出格式是人能打开的） | 结果只能下载 JSON；完成后页面不变；不知道别的插件能不能用它 |
| C5 状态 | 处理中、失败、部分成功、没配模型 | 在内容位置如实显示，有可点的恢复动作；没模型时仍能做手动的那部分 | 失败只在看不见的地方；没模型时整页不可用 |
| C6 再进入 | 列表与从别处回来 | 列表行能看出状态和最近动态；从搜索 / 助理 / Goal / 工作流回来能落在对象上 | 列表只有标题；链接打开落在空列表 |

「妥善的产品设计」在这里具体指：**结构先于文字**（用分组、顺序、占位、默认值、示例内容表达用法），**渐进展开**（用到再出现，不一开始把所有控件铺开），**一处主操作**（石墨按钮只有一个，它就是下一步），**结果有去向**（位置条、完成提示、可打开的格式）。文字提示只允许出现在控件自己的标签、占位与一句页头说明里。

## 2. 复查方法

- 在演示 Home（拷贝自助理会话的 Home：一个项目、个人空间、14 篇文档、4 条灵光、8 条待办、1 条工作流；PPT / 问卷 / 数据表 / Cognia 为空）上，用共同分支的构建（预览配置 `plugins-review`，4295）逐个插件走：入口 → 首屏 → 新建 → 主路径 → 完成 → 去向 → 再进入；1440 与 390 两种宽度；每个插件另看一次没配模型的情况。
- 结论分三类：**缺口**（承诺了但做不到、或断在中间）、**提升**（能用，但结果或效率明显可以更好）、**动线**（能用，但用户看不出来怎么用）。
- 每个插件一张表，末尾是「改法」：只写设计层面的改法，能落到具体控件、状态与顺序。

## 3. 逐插件复查

复查日期 2026-09-30。「结论」列用 C1–C6 标出不合格项；「改法」只写设计层面的做法。

### 3.1 入口层（所有插件共用）

| 看到什么 | 问题 | 结论 |
| --- | --- | --- |
| 底栏切换器只列插件名：Goals、Inbox、Feed、Pages、Forms、Dataset、PPT、Artifacts、Jelly、Cognia、Shelf、Coding、Characters | 中文界面里 13 个英文名，Cognia / Jelly / Shelf / Artifacts 从名字看不出用途；插件市场里每个插件都有一句话，切换器不显示 | C1 缺口 |
| 分组标题是「插件 / 工作 / 创作 / 更多」 | 「插件」没有信息量（列表里全是插件）；「更多」里混着待办、Jelly、Cognia、Shelf、Coding、角色、实验、炼金术士——这些恰是最需要解释的 | C1 动线 |
| 页头一句话与页面动作不一致：PPT「写幻灯片大纲，预览并导出 JSON」（页面已能放映、导出 PowerPoint）；Pages「保存在这台电脑」、Dataset「留下版本」说的是实现 | 一句话是用户进入前唯一的解释，说错比不说更糟 | C1 缺口 |

**改法：** 切换器每项两行——名字 + 一句「你会得到什么」（复用市场那句，逐条改写成结果导向）；分组按用途命名：**推进**（项目首页、Goals、Inbox、Feed、Schedule、工作流程）、**写与做**（Pages、Forms、Dataset、PPT、图片、Artifacts）、**个人**（待办、灵光、Jelly、Cognia、Shelf、角色）、**研究**（实验、炼金术士）、**编码**（Coding）；页头那句与切换器同源。

### 3.4 Forms（问卷）

| 阶段 | 看到什么 | 结论 |
| --- | --- | --- |
| 首屏 | 页头 + 新建问卷；空态一句话 | C2 通过 |
| 新建 | 空问卷：标题 / 说明；「题目 [填空 ▾] 加一题」；下面「题目或 AI 提示」输入 + 按题目加题 / AI 拟题加题（灰）；一段收集说明 | C3 动线：加题要先在下拉里选类型再点按钮，题目区是空的；两处「加题」并列（工具条 + AI 行）让人分不清 |

### 3.5 Dataset（数据表）

| 阶段 | 看到什么 | 结论 |
| --- | --- | --- |
| 新建 | 空表：标题 / 说明；工具条「筛选格子 · 文字 ▾ · 列名 · 加一列 · 加一行」；「AI 辅助加列」折叠；一行字「还没有列。先加一列，或打开下面粘贴 CSV。」；「导入 CSV（会覆盖当前表）」折叠；版本 备注 / 存一版 | C2 缺口：新表里看不到表；C3 动线：加列要填列名再点按钮；筛选框在没有数据时就出现；导入被藏在折叠里 |
| 列表行 | 标题 · 「数据表」标签 · 列 × 行 | 「数据表」标签多余 |

**改法：** 新表直接是 3 列 × 3 行的空网格，列头可编辑（列 A / 列 B / 列 C），列头末尾一个「＋」加列（点开选类型），表尾一行「＋」加行；筛选框只在有 ≥ 10 行时出现；「导入 CSV」与网格并列成为起点之一（空表时显示在网格上方的两个选择：从空表开始 / 导入 CSV）。
