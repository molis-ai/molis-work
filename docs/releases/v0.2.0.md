# Molis Work v0.2.0 — 事件工作流与 Runtime 简化

这一版让 Molis Work 更专注于保存工作事实、呈现当前差距和承接下一步。AI 可以按任务选择推进方法，普通工作不再要求先领取角色、建立 Run 或填完固定拆解模板；正式修改承诺、人工验收和完成结论仍有明确边界。

## 目标阅读与导航

- Goal 详情从五个分类页签收敛为当前整体进展、时间线和事件阅读。查看历史时仍能看到当前要求与差距，成果、决定和材料保留来源与定位。
- 可以先保存一句目标意图，再逐步补充事实、结果与要求。Web、首次引导、Feed/Inbox、MCP 和树结构创建使用同一个新建入口。
- 修复窄窗口点击「目标」却被详情遮挡的问题；目录、目标列表、聚焦与运行之间往返保留当前上下文，刷新后恢复所选视图。
- 推进态势缩窄后继续显示，点击「目标」可返回完整列表；导航保持单一选中项，支持键盘切换，触区和焦点行为同步改善。

## Runtime 与 MCP

- Runtime 工具从 57 个收敛为 35 个，移除旧 Claim、Run、Evidence、Review、Draft Dialogue 等执行入口及其写入实现。
- 绑定项目后，普通工具由 Host 注入项目和操作者；Runtime 仍明确传入目标 ID，减少重复参数并避免误写另一个目标。
- 普通笔记无需预先定义事件类型。一次工作更新可提交多个事实和进展，回执直接给出当前状态与剩余差距。
- 非法报告批次整体回滚；原键重试和重启重放不会重复创建 Goal 或记录。连接刷新优先复用已有绑定。
- 工作发现、单 Goal 状态、目录和交接摘要读取一致的当前事实；已退休要求与旧执行状态不再制造当前待办。
- 切换页面上的 Goal 不会自动改绑终端或发送内容。已完成或已取消的 Goal 通过带原因的明确操作继续，普通无关笔记不自动重开。

## 约定、验收与历史

- 当前结果约定与要求共同决定完成是否成立；完成使用显式收尾，记录数量和材料存在不代表验收通过。
- 人工验收要求真实保存，Runtime 报告不能代替可信用户决定。仍然有效、适用范围相同的授权可以复用。
- 正式修改与收尾检查当前版本，过期请求在产生副作用前拒绝；普通日常记录不被扩大为审批流程。
- 事件类型可以演化，旧记录继续按原版本阅读。要求可以修订或退休，原始要求、报告和决定保留历史。

## 架构与安装

- 完成 workspace 包与产品入口收敛：Local Host 承担实际安装、服务和应用组合职责，Web 与桌面共享工作台和业务事实。
- 清理退役协议的适配、注册和无用代码，保留真实 Session、终端进程、文件版本、历史查询和数据库升级能力。
- 安装器校验源码与构建产物的一致性；同版本内容更新也会刷新程序与共享 Skill，失败可恢复上一份程序。
- 修复重复构建把桌面缓存和旧 Runtime 包再次打入新包的问题；安装内容和更新检测遵守同一发布文件范围，保留运行代码、声明资产和原生依赖。

## 兼容与升级

**本版包含 Runtime 接口调整。** 旧工具名不再可调用，已有 Runtime 必须加载新版 MCP 与 `goal-advance` Skill，并新开 Session 后继续工作。

- 旧项目有数据库升级路径。Goal、关系、原始说明和历史执行／证据／审查记录保留；迁入的历史完成会明确标记，后续工作使用当前事件流程。
- 升级前停止 Molis Work 写入进程，并完整备份 Molis Work Home，保留 Catalog、项目、Session、配置和加密材料；不要只复制单个项目数据库。
- 更新 Core／App 后，检查常驻服务和已经接入的 Runtime。旧会话不会自动重载工具，不能作为新版运行证据。
- 安装和启动本身不会替用户创建项目、重新绑定 Runtime、启动目标工作或重置演示数据。

## 发布范围与验证

完整测试 647 项通过，0 失败、0 跳过。已验证当前事件主流程、旧库升级与历史读取、失败重试与重启恢复、临时及本机安装／升级，以及桌面和窄窗口的关键交互。终端渲染或模型推理速度没有在本版作性能收益声明。
