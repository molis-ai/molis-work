# 信息流工作台视觉层级统一

Molis Work Goal：`draft-8674359b-02ae-4281-8ba6-66c38dc1096b`

## 背景与目标

来源、Feed 与 Inbox 已经接通真实数据和主要业务操作，但详情工作台仍各自形成不同的容器、颜色和信息层级。目标是复用 Goal 详情已经验证的文档式工作台语言，让内部用户在三个模块之间切换时保持一致的阅读与操作节奏，同时保留每个模块的任务重点。

完成等级：内部完整。真实数据、首次进入、主路径、关键状态、桌面和窄屏均可顺畅使用；本任务不包含外部发布。

## 当前行为与问题证据

- Goal 详情以柔和纸面容器、低阴影、紧凑分段导航和“当前事项优先”的层级组织内容。
- 来源详情当前把标题、状态、事实表、当前运行、配置、计划、来源消息和运行记录直接铺在页面底色上；内容虽完整，但主次分组与 Goal 详情不一致。
- 来源事实使用网格分隔线，状态与操作缺少统一的“主工作面 / 辅助事实 / 次级操作”层级。
- 窄屏已具备列表与详情切换及 44px 触控路径，本轮必须保留并重新验证。

证据来源：`DESIGN.md`、`.impeccable/surfaces/src-web-render-ts.md`、`src/web/render.ts`、`src/web/visual-foundation.ts` 和现有 Web 测试。

## 范围

当前阶段在已验收的来源与 Feed 切片之后执行最后一个叶子 Goal：`goal-infoflow-visual-inbox`。

已完成的来源切片包含：

- 来源目录中的类型、名称、账号、同步事实与健康状态层级。
- 来源详情页头、分段导航、概览事实、当前状态与操作。
- 配置、拉取计划、来源消息、运行记录、空态和错误/同步状态。
- 桌面与 760px 及以下窄屏。
- Light、Dark、System 的语义颜色，以及焦点、禁用和触控状态。

当前 Feed 切片包含：

- Feed 高密度目录、来源/状态/时间元信息与已读状态。
- 消息详情页头、摘要、正文、标签、资料与既有操作。
- 选择、筛选、空态、错误/加载状态，以及目录到详情的桌面与窄屏路径。
- Light、Dark、System 的语义颜色，以及焦点、禁用和触控状态。

当前 Inbox 切片包含：

- Inbox 高密度目录、进入原因、紧迫度、来源和当前状态。
- 详情中的下一步、判断依据、关联对象、上下文和现有完成/忽略/重新打开操作。
- 选择、筛选、空态、错误/加载状态，以及目录到详情的桌面与窄屏路径。
- Light、Dark、System 的语义颜色，以及焦点、禁用和触控状态。

不包含：

- GitHub、Gmail、RSS Provider、授权、调度、数据模型或写入行为变更。
- 新增 Inbox 自动决策、通知规则或状态机。
- Goal 详情自身重设计、新业务功能或新导航。

## 方案与关键决策

1. 保留现有来源 DOM 数据属性、事件绑定和业务文案，只调整语义分组与展示类名。
2. 把来源详情改成与 Goal 详情一致的文档式工作台：
   - 页头负责身份、描述与可信状态；
   - 紧凑分段导航负责切换视图；
   - 每个活动面板使用单一柔和工作容器，不嵌套卡片；
   - 概览先显示当前运行和主操作，再显示辅助事实与危险操作。
3. 目录保持高密度列表，使用一致的 tonal selection、语义状态和清晰元信息，不改为卡片列表。
4. 窄屏保留目录 → 详情 → 返回路径，详情内容改为单列；标签、状态和操作不依赖横向滚动才能完成主任务。
5. 共享视觉值优先进入现有 `visual-foundation.ts` 选择器与 token，不创建第二套主题变量。
6. Feed 保留目录的高密度消息扫描能力；详情使用单一 paper 阅读面，正文是最高层级，来源/时间/状态退居元信息层，资料与关联内容以分隔区而非嵌套卡片组织。
7. Inbox 复用 Feed 的单一 paper 工作面，但把“为什么进入 Inbox”和“下一步”前置为行动区；关联内容与原消息正文随后展开，完成和忽略仍使用既有写入路径。

## 模块与输入输出

- `src/web/render.ts`
  - 输入：现有 `SourceWorkbenchEntry`、`FeedItem`、`InboxEntry` 和真实运行状态。
  - 输出：保持原数据属性与行为契约的来源、Feed 及 Inbox 目录和详情语义结构。
- `src/web/visual-foundation.ts`
  - 输入：现有 Goal 详情 token、纸面容器、阴影、间距和响应式约定。
  - 输出：来源工作台桌面与窄屏视觉层级。
- `tests/web.test.ts`
  - 输入：服务端渲染 HTML 与样式字符串。
  - 输出：来源结构、响应式和业务控制属性的回归证据。

三个视觉子 Goal 共享 `src/web/render.ts` 与 `src/web/visual-foundation.ts` 写入面，因此由主 Session 串行实现，不进行并行 writer 修改。

## 验收标准

1. 来源工作台已在桌面与窄屏中通过与 Goal 详情一致的容器、表面颜色、标题和元信息层级验收。
2. Feed 工作台在桌面与窄屏中使用同一 paper 阅读面；正文、摘要、元信息、状态与操作主次明确，没有嵌套卡片或额外颜色噪音。
3. 760px 及以下的 Feed 目录、筛选、详情、空态和加载/错误状态无页面级水平溢出，列表到详情与关键操作可达，触控目标不少于 44px。
4. Feed 的真实数据、路由、已读状态、Disposition 操作、来源跳转和打开原文继续使用既有业务路径。
5. Inbox 在同一 paper 工作面中优先呈现行动、原因和下一步；关联上下文与原消息内容随后展开，没有额外卡片堆叠。
6. 760px 及以下的 Inbox 目录、筛选、详情、空态和加载/错误状态无页面级水平溢出，列表到详情与关键操作可达，触控目标不少于 44px。
7. Inbox 的真实引用、路由、完成、忽略、重新打开和原消息跳转继续使用既有业务路径。
8. Light 与 Dark 下状态文本可读，状态不只靠颜色表达；键盘焦点可见。
