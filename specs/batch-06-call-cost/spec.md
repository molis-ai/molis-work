## 实现边界

- 静态检查在宿主源文件上用 TypeScript AST 数 `localWebActionContext` 和 `localPersonContext` 的调用表达式，按文件对照合并基点。声明、导入、注释和字符串不计入。该检查按调用语法识别，间接动态调用由代表性 HTTP 用例补充。
- 在隔离 Home 经产品 HTTP 入口测项目首页和简介、右侧资料状态、contextual、侧栏文件来源、列表、预览和参数拒绝。并发读取同项目两个 Goal 窗格作为 BL-943 对照。固定输入和时钟，停周期工作，测试侧探针转发到原调用。每项测三次并取各计数的中位数，推进时钟使短缓存过期。记录上下文准备、完整动作检查、动作发现、场景发现、项目插件目录读取及 `node:sqlite` 开库次数。先以报告模式测未改动产品代码的基线，再提交预算。健康检查按合并基点拒绝删预算项和提高数字，产品子集运行实测比较。
- `side-files-http.ts` 在发现前检查缺失的 `source` 以及内容或原始文件请求缺失的 `kind`／`id`，沿用对应 404／400。提供了必填值时，来源是否存在、类型是否由来源声明以及实际执行授权依旧走产品现有路径。同时缺来源和预览信息时先报来源缺失。有来源值而缺预览信息时先报 400，即使来源值已经失效。参数齐全时，已停用或不可见的来源仍报 404。
- 本片不改 N43／44／46、BL-943 的并发读合并、N45、N55、Files 退役及其合同。BL-943 后续优化仍须覆盖操作进行中撤权，证明下一次数据库操作及写入前均被拒且库中零写入。
