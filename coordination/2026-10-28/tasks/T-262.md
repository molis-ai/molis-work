## 1. 背景

来源：MISC「T-230 二审 建议（6504271568）」的 ①②。T-230（#1500）把起草（`apps/local-host/src/drafting/`）里按单元截的几处改成按整字截。二审指出两件事：

1. **一句不会失败的断言**。`tests/contextual-draft.test.ts` 的 `RAC-2196`（约 :85-94）最后一句：`assert.equal(LONE_HALF.test(calls[0]!.prompt), false, "no half of a character anywhere in what the model reads")`。`calls[0].prompt` 是 `JSON.stringify` 之后的文本，而 `JSON.stringify` 会把落单的代理字符写成 6 个字符的转义 `\ud83d`，字符串里就不再有真的落单代理；旧代码（按单元截）下这句也是绿的。真正会红的是它前面那句 `deepEqual`（解析后逐字段比）。这一句要么删掉，要么改成真断言：对解析出来的每个字段值（`data.材料`、`data.补充`、`data.来源.标题`）分别用 `LONE_HALF` 测，或者对 `JSON.parse(prompt)` 之后的各字符串测。
2. **同类的另一处**。`apps/local-host/src/drafting/draft-service.ts:55`：

```ts
if (isRecord(shape) && !present(base.request_id)) base.request_id = input.request_id.slice(0, typeof shape.maxLength === "number" ? Math.min(160, shape.maxLength) : 160);
```

`request_id` 按单元截到 min(160, schema 的 maxLength)。请求号如果含两单元字，会截出半个字；而 schema 的 `maxLength` 按字数数（Ajv），所以按单元截还会在 schema 允许的范围内多截。

## 2. 目标

1. RAC-2196 里那句空断言换成真断言：对解析后的三个字段值各测一次 `LONE_HALF`；并且证明它咬得住（见第 7 节的变异）。
2. `draft-service.ts:55` 的 `request_id` 按整字截到 min(160, schema 的 maxLength) 个字；只展开前 2×上限个单元，不展开整段。
3. RAC-2196 里（同一条用例，不新开号）加一段：`request_id` 为 `"r".repeat(159) + "🙂" + "尾"` 时，写进 `base.request_id` 的值恰是 160 个字（含整个 🙂），没有半个字；再一个 `"r".repeat(200)` 的普通请求号，结果是前 160 个字符，和改前一样。

## 3. 不做

- 不改起草的其他截取（T-230 已改的不再动）；不改 `cutUnits`、`cutHead`（二审③“两者语义重复是否合一”由统筹记账，不在本单）。
- 不改 `request_id` 的 schema、不改它的来源（谁生成请求号）。
- 不加兼容或迁移逻辑。

`apps/local-host/src/drafting/draft-service.ts`（只 :55 一行，必要时在文件里加一个小函数）、`tests/contextual-draft.test.ts`（只 RAC-2196 那条用例）。

## 5. 做法

1. 先在当时的 main 上核行号。
2. 空断言：`data` 已经是 `JSON.parse(calls[0]!.prompt)` 的结果，把最后一句换成对 `data.材料`、`data.补充`、`data.来源.标题` 逐个 `assert.equal(LONE_HALF.test(value), false, ...)`。
3. request_id：新增一个文件内小函数（或就地写）：`const max = typeof shape.maxLength === "number" ? Math.min(160, shape.maxLength) : 160; base.request_id = [...input.request_id.slice(0, 2 * max)].slice(0, max).join("");`。
4. 变异证明：(a) 把 `cutUnits`/整字截的调用临时改回按单元 `slice`，RAC-2196 红，且是新的真断言红（不是原来的 deepEqual 先红的话，把 deepEqual 临时注释掉再看）；(b) `request_id` 改回 `.slice(0, 160)`，第 3 个目标的新断言红。每个变异之后都改回，`git diff` 里不留变异。写进【交接】。
