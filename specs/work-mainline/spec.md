# 主线：按事项组织工作

状态：需求已整理（2026-11-02），尚未实现。在项目里给用户一条自己的主线：把正在做的几件事（事项）按自己的顺序和分组排好，像切换项目那样一下切到某件事，主区、标签、右侧、助理的范围和等你都换成这件事的；切回来时还是离开时的样子。事项是平台的轻量容器：可以只起个名字，也可以由插件的对象变成（一个 Goal、一条待办），里面装着这件事相关的对象；主线是用户对事项的排列（用户 11-02 定）。排进[路线书](../post-anticorruption-roadmap/reference/requirements.md#section-3-3)。

验收编号见 §10，前缀 `MLN`。

## 1. 要解决的问题

对照 main `b7072661f` 的现状：

- **导航按插件分，不按事情分。**
  - 底栏的 Dock 和插件切换器切的是插件；
  - 标签组按插件自动成组，或由用户手动成组（[插件标签组](../plugin-tab-groups/spec.md)）；
  - 插件自己的目录列（Goals 的目标树，`navigator` 槽位）只列这个插件的对象。
- **做一件事要来回跳。** 比如「发布 v2」：目标在 Goals，说明在文稿，代码在 Coding，反馈在 Inbox，讨论在项目讨论。每换一个插件，前一个插件里的位置、右侧开着的资料、助理正在说的事都要重新找。
- **没有「我现在在做哪几件事、先后怎样」的地方。**
  - Goals 的目标树是全部目标的结构，不是用户手头这几件事的顺序；
  - 待办是一条条任务，不是一件事的上下文；
  - 工作台记得标签和分屏，但不分属哪件事。
- **零件已经有，只是没串起来。**
  - `horizontal/placement` 记着对象之间的关联：各主人声明的关联（如装着 Goals 时的 Goal 资料）、来自、复制自（Context Ledger）；
  - 标签组有按对象身份成组；
  - [product-flow-governance](../product-flow-governance/spec.md) §4.6 把分屏、标签、右侧和底栏收成同一份工作台状态（PFG-22）；
  - [智能呈现与操作层](../intelligent-surfaces/spec.md) 给出对象在各处的形态与操作。

## 2. 主线是什么

- **事项。** 用户正在推进的一件事，是平台级的轻量容器（用户 11-02 定）：
  - 只有名字、装着的东西，以及可选的「由哪个对象变成」；不带要求、决定、负责人、截止这类工作语义，那些归 Goal、待办等插件；
  - 两种来路：
    - 直接新建，只起个名字；
    - 把一个插件对象变成事项（一个 Goal、一条待办、一个 Issue……，由声明了「事项来源」的插件提供，§5）。这时名字、状态、完成与否都向那个对象的主人读，事项不另存一份；
  - 直接新建的事项以后可以「变成 Goal」「变成待办」等（选项取声明了创建动作的来源插件，装着才出现）：在插件里建对象并和事项绑上，事项里装的东西不变。
- **事项里装的东西。** 和这件事相关的对象引用：文稿、数据表、Coding 会话、讨论、成果、待办……。
  - 装进去是一条 placement 关联（事项 ↔ 对象），不复制对象；
  - 由插件对象变成的事项，还带上那个对象原有的关联（装着 Goals 时比如 Goal 资料）。
- **主线。** 用户在一个项目里对事项的排列：
  - 哪些事项在主线上；
  - 分在哪一组、组里的先后、哪几件固定在前；
  - 哪件是当前事项；
  - 每件事项的工作台状态。

  主线是用户自己的事实：每人一条，由平台的主线服务保管（§6），不归 Goals，也不归宿主。
- **当前事项。** 此刻在做的那一件。可以不选：不选时就是今天的样子，整个项目一份工作台状态。主线是可选的，不用它的人什么都不会变。
- **和项目的关系。** 项目是工作边界，事项在项目里面。切换项目换的是整个项目；切换事项换的是项目里的工作上下文，逻辑相同、范围小一层。

## 3. 原则

1. **一项事实一个主人。** 事项容器（名字、由哪个对象变成）和主线的排列归主线服务；事项里装了什么是 placement 的关联；插件对象的内容归插件。主线服务不复制插件对象的标题、状态或正文，只存它们的引用（`ActionSubject`）。
2. **事项要轻。** 事项只做容器，不长出状态流、负责人、截止、评论这些。需要这些，就把它变成 Goal 或待办，由那个插件负责。
3. **插件同等待遇。** 任何插件声明了事项来源，它的对象就能变成事项；任何插件的对象都能放进事项。平台不按插件名单接；内置插件和装上的插件走同一份声明、同一套授权。
4. **切换是显式的。** 只有用户切换、或明确同意助理的切换建议，当前事项才会变。查看另一件事项的资料不改当前事项，沿用 PFG「位置不改变工作归属」。
5. **切换不打断正在跑的工作。**
   - 后台任务、Coding 会话、工作流程照常跑，归属仍是发起时的那件事项；
   - 草稿留在原来的事项里；
   - 切回去就能看到它们。
6. **不自动归入。** 新打开的对象不会自动收进当前事项。平台和助理可以提示「放进这件事」，由用户点了才放。
7. **读不到就如实显示。** 主线上的对象被删、被移走或调用方失去权限时，只显示「已不在」或「无权查看」，并给出从主线移除的操作，不显示旧内容。
8. **不新开全局左栏。** 主线的入口在底部事项线的线头（§4.1；用户 2026-11-12 定，原为顶部，见 §9 第 4 条）。

## 4. 用户能做什么

### 4.1 切换

- **事项切换器。**
  - 位置：底部[事项线](../work-line/spec.md)的线头（最左端），一个窗口一个（用户 2026-11-12 定，原为标题栏行的最前面）。
  - 内容：当前事项的名字片（形态见智能呈现 §4.2），带状态环和这件事里等你的数量；没选事项时显示项目名。
  - 交互：点开是锚定在它上方、向上展开的列表菜单，不是居中弹窗（同 PFG「＋」原地菜单的规则）。
- **列表菜单。**
  - 顶上是最近切过的 3 件（不含已完成）；下面按组和顺序列出事项，各组默认折叠，组头带件数和等你的件数，展开与否按用户上次的样子记住；搜索时不折叠，按组列出匹配的事项（用户 11-03 定，见 §9 第 3 条）；
  - 每行用智能呈现的「行」形态：标题、状态、等你的数量、最近一次动作；
  - 顶上有搜索；
  - 底下有「新建事项」「整理主线」「不选事项」；
  - 支持键盘上下选、回车切换、Esc 关闭并把焦点交还。
- **其他入口。**
  - ⌘K 搜索里，事项排在最前；
  - 有一个快捷键回到上一件事项；
  - 可以对助理说「切到发布 v2」，切换前先确认；
  - 手机上切换器收在线头（状态环与数字），列表菜单变成底部弹层。

### 4.2 有序组织

- **建事项：**
  - 从切换器「新建事项」，起个名字就有；也可以直接选「建成 Goal」「建成待办」等来源；
  - 在有事项来源的对象上「设为事项」（智能呈现的操作），比如一个 Goal；
  - 采纳助理的建议。
- **往事项里放东西：**
  - 任何对象的操作里都有「放进事项」，可以选当前事项或别的事项；
  - 从「这件事的东西」里移出一项，只删关联，不删对象。
- **变成插件对象：** 直接新建的事项可以「变成 xx」（Goal、待办……，候选取声明了创建动作的已装来源插件）。在来源插件里建对象并和事项绑上，名字以后向插件对象读，装的东西不变。
- **分组：**
  - 默认三组：「现在」「接下来」「等别人」；
  - 用户可以改名、加组、删组；删组时，组里的事项并到相邻的组，不会丢。
- **排序：** 组内可以拖动；键盘可以上移、下移、移到别的组；能把几件固定在最前。
- **完成：**
  - 由插件对象变成的事项，主人报告完成时（Goal 已完成、待办勾掉）显示完成；轻量事项由用户一键标完成；
  - 用户确认后收进「已完成」折叠区，确认是一次点击，可撤销；
  - 已完成的可以重新放回。
- **移出：** 从主线移出一件事项，不删除它装的对象，也不删插件对象。
- **整理主线：** 一页整理视图，是像「设置」「插件市场」那样的覆盖页：
  - 全部分组和事项一次铺开；
  - 支持拖动和多选移动；
  - 显示每件事项最近的动态和等你的数量。

### 4.3 每件事项带着的上下文

切到一件事项，这些一起换：

- **工作台状态。** 主区、分屏、标签与标签组、右侧打开的内容，各事项各存一份，在 PFG-22 的同一份工作台状态上加「按事项」这一层，不另起一份。第一次切到一件事项时，主区打开它主人插件里的对象页（比如 Goal 页），右侧打开「这件事的东西」。
- **这件事的东西。** 和事项相关的对象，按种类分组列出，用智能呈现的「行」和「名字片」形态显示：
  - 文稿、数据表、Coding 会话、讨论、成果、待办……；
  - 包括装进事项的对象；由插件对象变成的事项，还有那个对象原有的关联（Goal 资料装着 Goals 时才有；来自、复制自）和来源插件声明的自家关联（§5）；
  - 每项可以在主区或分屏里打开。
- **助理的范围。** 助理对话默认带上这件事项和它的相关对象作上下文，输入框上显示「在：发布 v2」，用户一点就能去掉；已经在跑的助理任务不换范围（[统一输入](../unified-input-voice/spec.md)的发送对象规则照旧）。
- **等你与通知。** 切换器和列表里显示每件事项等你的数量；等你面板默认先列当前事项的，其余的仍在下面，不藏起来。
- **项目讨论。** 讨论里可以把一段对话关联到某件事项；切到这件事项时，「这件事的东西」里能看到它。

## 5. 插件要声明的

想让自己的对象能变成事项的插件，在 Manifest 里声明「事项来源」（和智能呈现的呈现声明放在同一段或相邻段，由合同 PR 定）。不声明的插件，对象照样能放进事项：

| 声明 | 说明 |
| --- | --- |
| 对象种类 | 哪些 `ActionSubject` 种类能当事项，比如 Goals 的 goal、待办的 todo、Issues 的 issue、Coding 的 task |
| 读取 | 标题、状态、进度、是否完成，复用智能呈现声明里的字段与状态映射，不另写一份 |
| 新建 | 「建成 xx」「变成 xx」时调用的创建动作；没有就不出现在这两处的选项里 |
| 完成信号 | 对象完成、重开时发的事件，供主线更新显示 |
| 自家关联（可选） | 一个读取动作：这个插件里和某个对象相关的东西，比如 Coding 里挂在一个 Goal 上的会话；平台把它和 placement 的关联合在一起 |

全部是动作目录里的动作，按调用方的权限调用；可信身份从调用上下文来，不从输入读。

## 6. 平台负责的

- **主线服务。** 一个新的 `horizontal/` 包（用户 11-01 定新的平台服务不进宿主），宿主只装配。
  - 保管每人每个项目的事项容器（名字、由哪个对象变成）与主线（分组、顺序、固定、当前事项、已完成、每件事项对应的工作台状态）；
  - 事项登记成一种 `ActionSubject`，所以 placement 能把对象关联到它，搜索能找到它，智能呈现能画它；事项相关的关联类型由主线服务按 placement 的关联声明登记，placement 不为事项增加写死的关联名（2026-11-13 按插件同等地位收口改，[决定 42](../post-anticorruption-roadmap/reference/decisions.md#decision-42)）；
  - 不存插件对象的内容；
  - 合同落地时在 [GLOSSARY](../../docs/system/GLOSSARY.md) 加「事项」「主线」两行。
- **动作。** 主线的读取、放进、移动、分组、移出、切换都注册成系统动作，页面、助理、工作流程、MCP 用同一套，外部 Agent 读到的是同一份事实。
- **工作台。** 切换事项时换掉 PFG-22 状态里属于当前事项的那一份；有未保存的内容时，按插件自己的草稿规则保留，不弹窗拦截。
- **记录。** 放进、移动、切换、完成写进工作记录（[观测和采集层](../observation-collection/spec.md)），只记谁、哪件事项、什么操作，不记对象正文。
- **同步。** 主线是个人数据，随个人同步（路线书服务端批）在设备间同步；同步合同落地之前只在本机。

## 9. 已定

1. **事项是平台的轻量容器**（用户 11-02 定）。只是容器：可以只起名字，Goal、待办等插件对象可以变成事项；不长出插件该管的工作语义（§2、§3 第 2 条）。
2. **先做项目内的主线**（用户 11-02 定）。跨项目的个人主线放第三片。
3. **列表菜单用「最近切过加折叠分组」**（用户 11-03 定，定样 [`docs/design/work-mainline-switch/`](../../docs/design/work-mainline-switch/README.md) 方案 C）。顶上最近切过的 3 件，各组默认折叠、组头带件数和等你的件数，搜索时展开匹配项。没选的：A 按组全列（事项一多菜单太长）、B 带预览的两栏（菜单宽 700px，盖住主区，手机上没有预览）。切换器、提示条、「这件事的东西」、放进事项、整理主线等共用部分随原型一起看过，没有要改的。做产品前把原型控件换成 `mw-*` 组件再核对一遍。 11-04 按组件板实件重做，用户确认：版面与选定的方案不变，按钮、标签、分段、状态记号、状态环、进度条和提示条换成组件板的 `mw-*`（共用的 `docs/design/kit/`）。
4. **切换器放在事项线的线头**（用户 2026-11-12 弹窗定，[路线书决定 38](../post-anticorruption-roadmap/reference/decisions.md#decision-38)）。原来定的是标题栏行最前；用户在界面讨论里提出底部事件流前面要有能展开的列表来切换，看过[方向原型](../../docs/design/work-line/README.md)后确认。第 3 条的列表内容与规则不变，只是向上展开；位置部分的定样随[事项线](../work-line/spec.md)第一片重出。没选的：留在顶部（底部看不出切换的入口）。主线服务包因此在第 32 批先建（线读取与安放，不带存储），第 36 批加事项容器与存储。

## 10. 验收标准

1. **MLN-01** 未选事项时，工作台与今天的行为一致；不用主线的人看不到任何变化（除线头切换器显示项目名）。
2. **MLN-02** 切换器在底部事项线的线头、一个窗口一个；点开是锚定的、向上展开的列表菜单，键盘可选、回车切换、Esc 关闭并交还焦点。
3. **MLN-03** 列表按用户的分组和顺序列出事项；拖动或键盘移动后顺序立即生效，刷新、重启后保持。
4. **MLN-04** 默认三组可改名、增删；删组时组内事项并到相邻组，一件不丢。
5. **MLN-05** 切到一件事项：主区、分屏、标签、右侧换成这件事项上次的样子；第一次切到时主区打开主人插件的对象页、右侧打开「这件事的东西」。
6. **MLN-06** 切走再切回：草稿、滚动位置、选区与离开时一致；切换期间在跑的后台任务、Coding 会话不停、不改归属。
7. **MLN-07** 「这件事的东西」列出装进事项的对象，以及由插件对象变成的事项原有的 placement 关联与来源插件声明的自家关联，按种类分组，用智能呈现的形态显示，每项可在主区或分屏打开。
8. **MLN-08** 「新建事项」起个名字就建成轻量事项；选「建成 xx」（Goal、待办等）时，在来源插件里建对象并变成事项；没有声明创建动作的插件不出现在「建成」的选项里。
9. **MLN-09** 由插件对象变成的事项随主人完成而显示完成，轻量事项由用户一键标完成；用户确认后收进「已完成」，可撤销、可重新放回。
10. **MLN-10** 从主线移出一件事项，不删除它装的对象和插件对象；从事项里移出一个对象，只删这条关联，不删对象。
11. **MLN-11** 对象被删、被移走或调用方失去权限时，主线只显示「已不在」或「无权查看」并给出移除操作，不显示旧标题或内容。
12. **MLN-12** 主线服务只存事项容器（名字、由哪个对象变成）、插件对象的引用和排列；它的存储里查不到插件对象的标题、状态或正文。
13. **MLN-13** 放进、移动、切换、移出都经系统动作完成；页面、助理和 MCP 调同一组动作，未授权的调用被拒并留诊断行。
14. **MLN-14** 一个装上的第三方插件声明事项来源后，与内置插件一样出现在「设为事项」和「建成 xx」里，宿主没有按插件名的分支。
15. **MLN-15** 打开或查看另一件事项的资料，不改当前事项；只有用户切换或确认助理建议才改。
16. **MLN-16** 当前事项在助理输入框上可见，可一键去掉；切换事项不改已在跑的助理任务的范围。
17. **MLN-17** 切换器和列表显示每件事项等你的数量；等你面板先列当前事项的，其余的不被隐藏。
18. **MLN-18** 放进、移动、切换、完成写进工作记录，只记操作者、事项引用和操作，不记正文。
19. **MLN-19** 手机宽度下切换器在线头，列表变成底部弹层，触控目标不小于 44px。
20. **MLN-20** [人工] 用真实项目里的三到五件事连续工作一天：切换顺手，回到一件事时不用重新找东西，分组与顺序能表达先后。
21. **MLN-21** 轻量事项「变成」某个声明了创建动作的来源对象（例如待办；装着 Goals 时也验 Goal）后，装的东西一件不少，名字改向来源对象读；在来源对象里改名，事项随之改。
22. **MLN-22** 事项容器的合同里没有状态流、负责人、截止、评论这类字段；要这些只能变成插件对象。
23. **MLN-23** 列表菜单顶上列最近切过的 3 件（不含已完成）；各组默认折叠，组头显示件数与等你的件数，展开状态刷新后保持；输入搜索词时各组不折叠，列出匹配项。
