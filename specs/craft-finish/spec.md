# 工作室质感收尾（Craft finish）

## 背景与目标

用户反馈 Molis Work 整体「比较乱，动线没有设计好」，要求对整体页面和布局做打磨与重设计：统一视觉和质感，补上仪式感与体验感，并把各场景的按钮点击、拖拽、状态做成更好的微设计和微交互。用户授权可以不完全遵循设计板、组件板和现有布局，但要求**简洁、信息密度、操作便利**；同时授权升级开发 skill、架构文件、组件规格板与设计文档。

目标等级 3「功能可用」：真实页面在隔离预览里完成浅/深色与 1440 / 1024 / 390 三档宽度的目视核对，定向单元与浏览器回归通过或逐条说明。不宣称原生安装包已验收。

## 证据

在隔离预览（demo 项目，1440×900）逐面核对，得到六条具体缺口：

- **看不出身在何处。** 点左栏插件不会开标签，而是把窗格切到插件母页、没有标签处于当前态；标签条上只剩一个未选中的「项目首页」。工作台里也看不到项目名。
- **左栏像一摞药片。** 个人区、项目区、插件列表、底部区各是一只带阴影的胶囊，约 30 个图标每个一种颜色，最底下还被截断。
- **舞台没有统一的「纸」。** 首页自己画了一张内嵌圆角卡片，其他插件贴边平铺；设置页底色和外场一样，纸面边界读不出。
- **首页浪费一半宽度。** 事件流限宽 40rem 靠左，1440 下右半边空着；事项详情必须再点一次才出现。
- **Feed 头部占空间。** 大标题、说明和一个孤立的「消息」页签叠三行，约 140px 才到内容。
- **反馈不够有「手感」。** 按压只有色调变化；新建的条目、完成的 Goal 都没有任何「这件事发生了」的时刻；拖拽源和落点没有状态。

另外发现两处既有回归：新建 Goal 的书写行被后层规则加回了方框；暗色下左栏胶囊由一条更高特异度的规则继续画出。

## 范围与场景

范围：工作台、全局/项目设置、项目选择三张页面的共享表达层；少量结构改动限于标签条（位置芯片）、项目切换器与项目卡（项目徽标）、首页（问候与宽屏详情栏）、Goal 画布（首开视野与拖动态）。首次引导不动。

场景：进入项目；在插件之间切换与返回；打开市场/设置后返回；首页浏览与处理当天事项；Goal 列表、画布、看板；打开 Goal 工作区；Feed 阅读；新建 Goal；筛选菜单；Goal 完成；新条目落地；拖拽；浅/深色与三档宽度。

## 方案与取舍

新增 `packages/design-system/src/styles/craft-finish.ts`（`CRAFT_FINISH_STYLES` + `CRAFT_FINISH_CLIENT_SCRIPT`），样式在三张页面样式表的**最末**拼接，脚本并入 `VISUAL_FOUNDATION_CLIENT_SCRIPT`。沿用「最后一层」的做法：既有各层同时承载结构与密度契约，逐层改写风险大；单独一层可整体加载、整体回退。

- **空间：桌面与纸页。** 标题栏、左栏、目录都是桌面（`--desk` = `--page`），彼此之间不再画线或阴影。工作内容是一张纸页：`.tab-workspace` 右、下各留 8px 桌面，窗格与独占层圆角 12px、`--sheet-shadow` 轻抬。分屏时每个窗格各是一张纸，当前窗格边缘略深。首页不再自带内嵌卡片。嵌入窗格（iframe）与 600px 以下不留边。
- **位置芯片。** 窗格显示某插件母页时，标签条最前出现「图标 + 插件名」芯片并处于当前态；打开该插件的条目后，芯片变为可点的「返回插件首页」。市场与设置覆盖窗格时，最前再出现「插件市场 / 设置 / 项目设置」芯片，被覆盖的插件芯片保持可点。芯片不是标签，不参与拖动、分组与宽度分配。
- **左栏。** 去掉四只胶囊的底色与阴影，组与组之间是一根 20px 发丝线（画在组内部，组间 8px 间距不变）。图标静止时是插件色与 `--muted` 的 34% 混合，悬停与当前才是完整插件色；当前项在滑动色块之外，左缘再多一道 3px 插件色指示。项目入口换成**项目徽标**：首字母 + 由项目 id 决定的稳定色块，改名不变色。
- **提示与快捷键。** 左栏项的悬停/键盘聚焦提示由脚本在页面里放一个元素，不会被滚动列裁掉；提示里显示快捷键。新增 `⌥1…⌥9`：在非输入、非终端、非弹层时打开左栏第 1–9 个工具（首页起算，跳过插件创作台）。
- **控件手感。** 按钮、分段、创建按钮、项目卡按下时缩到 .97 再弹回；打开弹层的控件不缩，避免菜单偏移。主按钮加一道顶部高光；次按钮用发丝边抬升，悬停再抬一级。输入框聚焦是 1px 墨色边加一圈 3px 墨色 7% 的柔光（不用强调色画描边）。勾选框的勾会「画」出来，开关按住时把手先拉长再落位。
- **浮层。** 居中对话框上浮 10px 并从 .975 放大到位；贴边面板从右侧滑入；菜单与弹出层从触发点下落 4px。遮罩只压暗、不模糊（全屏模糊显脏且耗性能）。Toast 变成胶囊，带成功/失败标记，失败时轻摇一下。
- **首页。** 问候随本地时间变化（早上好 / 中午好 / 下午好 / 晚上好 / 夜深了）。日期列是半档桌面色的独立一栏。首页宽度 ≥ 1080px 时，当天第一件事的详情与可执行操作自动在右侧检查器栏展开；用户关掉后本次不再自动展开，处理完一件会接到下一件。检查器贴纸页右缘，不再是浮起的卡片。
- **Goal 画布。** 首次打开若整张图能以 ≥ 50% 的比例放下就适配全部，否则仍居中到当前 Goal（本 demo 适配只有 30%，按规则居中）。节点悬停抬升，拖动时抬到最高一级并有「拿起」态，选中节点是插件色细环加柔光；选中路径上的依赖线以虚线流动。
- **看板与市场。** 卡片悬停上浮 1px、抬升一级；市场条目依次到达，图标悬停微转。
- **Feed。** 标题与说明并成一行；只剩一个可见页签时整条页签隐藏。
- **仪式时刻。** 打开的 Goal 状态从「未完成」变为「已完成」时，状态标记弹一下，并从标记处放出一圈环和十几颗彩色碎片（打开一条早已完成的 Goal 不会触发）。新建的 Goal、新拉到的消息、新的 Inbox 事项第一次出现时，行上有一道从左缘淡出的插件色光（一次最多 3 条，避免整表重绘时误报）。进入项目时左栏依次入场、纸页随后升起，每页一次。插件可以调用 `molisCraft.celebrate(element)` 与 `molisCraft.land(element)` 标记自己的完成与到达。
- **拖拽。** 拖拽源留下半透明的「坑」；拖拽期间 Frame 画布等落点显示可放区域。标签自己的拖动排序不受影响。
- **取舍。**
  - DESIGN.md 原先写「按压是色调一步，从不位移」「左栏图标静止即着插件色」。本次改为按压有回弹、静止图标降饱和，是用户这次明确要求的「手感」与「统一、简洁」；记为新的现行规则。
  - 首页先试过「内容居中」，与「信息密度」冲突，改为宽屏自动展开检查器。
  - 自动化浏览器（`navigator.webdriver`）下本层所有动画静止，保证几何断言立即稳定；`prefers-reduced-motion` 下同样全部静止。
  - 第一轮保留了「个人区在项目区之上、插件创作台领头」的既有顺序；第二轮按用户要求整体重排（见下）。

## 输入输出与模块边界

输入：既有 DOM、主题偏好、插件色表、本地时间。输出：一层 CSS、一段只做呈现的脚本、少量标记。

改动文件：`packages/design-system/src/styles/craft-finish.ts`（新增）、`packages/design-system/src/monogram.ts`（新增）、`visual-foundation.ts` / `index.ts` 的导出、`primitives/catalog.ts` 的「质感 · 空间 · 动效」一节、`apps/workbench/src/page-assets.ts` 的拼接、`settings-navigation.ts` 与 `project-directory-renderer.ts` 的项目徽标、`scripts/client/tab-workspace.ts` 的位置芯片与独占芯片、`scripts/client/project-home.ts` 的问候与宽屏检查器、`i18n/gap-en.ts`、`plugins/native/goals/src/momentum-*-client.ts` 的首开视野与拖动态、`DESIGN.md`、`skills/molis-plugin-dev`。

脚本不写任何 Goal / Feed / Inbox 状态，不移动焦点，不取消其他处理器；没有它页面照常可用，只是少了提示、落地光与完成时刻。

## 验收

1. 任意插件母页、条目、市场与设置下，标签条最前都能说出「现在在哪」，且一键返回插件母页。
2. 左栏无胶囊底色；组间 8px、分隔线在组内；浅/深色一致；当前项有插件色色块与左缘指示。
3. 所有插件舞台都在同一张圆角纸页里；设置页纸面与桌面可分辨。
4. 首页 1440 下检查器自动展开并给出主操作；1024 与 390 下布局不被打乱。
5. 按压、悬停、聚焦、勾选、开关、菜单、对话框、Toast 有一致手感；`prefers-reduced-motion` 与自动化下全部静止。
6. Goal 完成与新条目落地各有一次性的时刻；打开已完成的 Goal 不触发。
7. 定向回归通过，未通过项逐条说明归属。

## 第二轮：左栏重排

用户指出「工具导航」开关放在项目与插件之间不合适，整个左栏视觉上仍然乱，要求重新设计。

**证据。** 展开名称后：开关像一个导航项夹在项目区和插件之间；个人区（灵光/对话/群聊）压在项目上方；20 多个插件平铺、无分组、最底部被截断；为图标栏设计的分隔线在 160px 宽栏里居中成一截短线；「能力」是链接，带着默认下划线。

**方案。** 左栏按「这个项目 → 它的工具 → 拓展 → 你」自上而下：

- 项目区：徽标（展开时带项目名）+ 项目设置齿轮；展开时第二行是带 ⌘K 的搜索框。
- 工具区：首页与工作组按动线排（Goals、Inbox、Feed、Sessions、Schedule、工作流程），再依次是「创作」（Pages、Forms、Dataset、PPT、图片、Artifacts）、「更多」（其余工具，**后加的插件默认落这里**，不需要改外壳）、「拓展」（插件创作工作台、插件市场、能力）。图标栏里组是 16px 发丝线，展开时是 11px 小标题。
- 你：灵光 · 对话 · 群聊（展开时并成一行），然后是设置与账号（展开时账号占一行、设置是行尾齿轮）。个人区不再是独立的导航地标，而是左栏里的一个分组。
- 「显示名称」开关移到标题栏最左，与前进/后退并排——macOS 放侧栏按钮的位置。
- 展开宽度 160 → 208px，行高 34 → 30px；提示气泡只在名称被隐藏时出现。
- 手机上个人工具收进抽屉，顶部少一行。

**取舍。** 这推翻了此前「个人区在项目区之上」「插件创作台领头」「市场与 Characters 在底部卡片」三条决定，是用户这次明确要求的重排。分组只点名「工作」「创作」「拓展」三组，其余全部归「更多」，以保持「加插件不改外壳」。相关测试（`characters-appearance`、`desktop-tui`、`immersive-directory`、`immersive-workbench`）改为守护新层级。

**改动文件。** `apps/workbench/src/immersive-shell.ts`（分组、个人区位置、标题栏开关）、`goals-page-renderer.ts`（装配顺序）、`settings-directory.ts`（「能力」移入拓展组）、`settings-navigation.ts`（搜索框文字与快捷键）、`scripts/client/immersive-navigation.ts`（键盘漫游包含链接项）、`craft-finish.ts`（左栏样式）、`i18n/gap-en.ts`，以及上述测试。
