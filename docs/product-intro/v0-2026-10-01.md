## 这一版写了什么

第一版，按「场景 → 功能 → 竞品」组织：一句话与目标用户、七个场景、27 项功能的状态表、按六类替代品做的竞品对比、四条差异和给官网的建议。

---

Molis Work 是装在你电脑上的 AI 工作台：目标、资料和工具放在一处，内置助理和 Claude Code、Codex 这些外部 Agent 在同一份事实上接着做，做没做完可以核对。

这版按 main 最新代码（d39e8e5，2026-10-01）核对。公开版本仍是 v0.2.0（9/11），只含 Goals、Work、Feed、Artifacts 四个插件。个人助理那批能力（原 PR #98）已在 9/30 合入 main，但和其他新能力一样还没发版，多数在等你本人试用验收。所以下文的状态一律以「用户现在能不能下载到」为准。

和你的提纲比，我把顺序调成「场景 → 功能 → 竞品」：官网读者先认出自己的麻烦，功能才有意义。功能单独成表，方便你随发版改状态。竞品按「用户现在拿什么凑合」分六类，每类都写上我们不如它的地方，避免官网写过头。

## 一句话与目标用户

对外一句话沿用 v1 首屏：**让工作，在人、工具与 Agent 之间继续。** 它背后是三件事：

- **目标只有一份。** 要做成什么、做到哪、还差什么，记在 Goal 里，不散在某个工具的聊天记录里。
- **能力只登记一次。** 每个插件把能力登记到同一个目录，页面、助理、工作流和外部 Agent 都从这里调用，权限在一处管。
- **数据在你的电脑上。** 一个 Home、一个常驻宿主，浏览器和 macOS App 打开的是同一个工作台。

先给谁用，按优先级排：

| 用户 | 他们现在的状态 | 最先用到 |
| --- | --- | --- |
| 同时用好几个 AI 编码工具的独立开发者、技术负责人 | 今天用 Claude Code，明天换 Codex，一个项目跨几十个会话 | Goals、Coding、MCP 接入 |
| 产品负责人、研究和内容工作者 | 每天看大量资料，要写方案和周报，还有一堆琐事要跟 | 个人助理、Feed → Inbox → Pages、Todo |
| 小团队里牵头的人 | 要知道每件事卡在哪、等谁拍板 | Goals 的依赖画布和决定中心 |

团队空间、成员权限和多设备同步还在规划，所以首发只对个人讲，小团队写成「牵头的那个人」。

## 七个场景：什么场景下的什么问题

每个场景都能直接做成官网的一个区块：小标题当区块标题，「麻烦」是让读者认出自己的那句话，「怎么做」是正文。例子都是示意，不是客户案例。

### 1. 换了工具，工作不用从头讲

- **场景**：周一用 Claude Code 搭好登录页，周三换 Codex 接着做支付，周五回来，两边对“做完了”的理解并不一样。
- **麻烦**：每个 AI 工具只记得自己的会话。换工具、隔几天回来，都要重新交代背景；AI 说做完了，你没法核对。
- **怎么做**：要达成什么、做成了什么、还差什么，记在同一个 Goal 里。Codex、Claude Code、OpenCode、Pi Agent、Grok Build 有内置接入，其他 Agent 经 MCP 读写同一份 Goal。Agent 可以提新需求，不能悄悄改掉你认可的目标；“完成”要过显式收尾，核对当前要求、依据和阻塞。
- **用到**：Goals、依赖画布、决定中心、绑在 Goal 上的终端、菜单栏当前 Goal。核心已发版（v0.2.0），新界面在 main。

### 2. 放心让 AI 动手

- **场景**：你想让 AI 改文档、建待办、开 PR，但不想事后才发现它动了什么。
- **麻烦**：AI 能动哪些东西说不清；改错了撤不回；在一个入口关掉权限，另一个入口照样能写。
- **怎么做**：所有插件的能力登记在同一个目录，页面、助理、工作流、外部 Agent 都从这里调用。权限按调用方、按每个 MCP 客户端逐一授予，每次调用留记录。写文件、跑命令、推送先进审查队列；能撤销的操作直接做，做完给你撤销。被取消或撤权的调用，不会再写入任何数据。
- **用到**：统一动作服务与 MCP、审查队列、撤销。main 未发版。

### 3. 一个看得见你在做什么的助理

- **场景**：你在 Pages 写周报，想让助理把 Inbox 里三条客户反馈整理进去，再顺手建两个待办。
- **麻烦**：通用聊天助手看不到你正在做的东西，要复制粘贴；它给建议，执行还得你自己来；提醒要么没有，要么太烦。
- **怎么做**：底栏助理在任何页面都能叫出来，知道你在看哪一页、选中了哪段。用 @ 引用内容、用 / 选能力，能读 PDF 和图片。它的建议是点一下就执行的操作卡；会跟进到期的事，也守你定的勿扰规则。记忆看得见、改得了、删得掉。复杂的事拆给子任务并行做，写代码的部分交给 Coding。
- **用到**：个人助理、操作卡、记忆、主动提醒、Todo、Jelly。已合入 main，未发版，等你验收。

### 4. 信息很多，只把要处理的送到面前

- **场景**：你订了十几个 RSS，关注几个 GitHub 仓库，每天几十封邮件，月底要交一份行业观察。
- **麻烦**：来源各看各的，重要的漏掉；写的时候找不回出处。
- **怎么做**：RSS/Atom、网页查询、YouTube、GitHub、Gmail 的内容统一进 Feed；按规则把需要你介入的送进 Inbox，并写明为什么进来；选中的材料交给 Pages 写成带来源的文稿。外部内容一律当资料，不会变成给 AI 的指令。
- **用到**：Feed 与来源（已发版）；Inbox、Pages、Schedule（main 未发版）。

### 5. 第一天就有内容，以后都找得到

- **场景**：刚装好，不想先填一堆设置；用了一个月后，记得写过「Q4 预算」却想不起在哪。
- **麻烦**：新工具第一天是空的，要自己搬资料、建项目；工具一多，东西散在各处。
- **怎么做**：勾选要接入的来源并授权，AI 整理出带来源的工作总结和项目建议，采用后生成项目；不要求先写 Goal 或配 Agent。之后按 ⌘K，能搜到所有插件里的内容，包括没打开过的；两个字的中文、Q4 这样的短词也能搜。
- **用到**：首次使用、系统搜索。main 未发版；真实 Gmail 链路验证过，第三方 OAuth 应用的正式审核是外部条件。

### 6. 缺一个顺手的工具，自己做出来

- **场景**：你想要一个“账单到期提醒”，表格太散，专门找软件又太重。
- **麻烦**：做个小工具要么得会编程；用一句话生成的网页应用又和你的资料、你的助理不相通。
- **怎么做**：在插件创作台描述需求，Agent 先给方案，再在沙箱里写代码，过宿主检查和浏览器验收后装进项目。做好的插件自动成为能力：助理、Coding 和外部 Agent 都能调用，它也能读写 Goals、Inbox、Pages。
- **用到**：插件创作台。main，建议标「预览」：12 个真实需求里 4 个第一次就做成，修过问题后 12 个都至少做成过一次。

### 7. 写代码的会话，住在项目里

- **场景**：一个功能要改十几个文件，做到一半网断了，你也要去开会。
- **麻烦**：编码 Agent 的会话一断就散；几个会话各干各的，互相不知道。
- **怎么做**：在项目里开 Coding 会话，计划、子任务、中断和审查都在同一条任务记录里，停下后从断点继续。会话之间可以认领任务、互相发信。写文件、跑命令、push、开 PR 都先经你审查。
- **用到**：Coding、Files、Git、Diff。main 未发版。和 Claude Code、Codex、Cursor 比还差 20 项功能，见竞品一节。

## 和同类产品比

Molis Work 没有一个正面对手，它要替换的是用户现在拼凑的一套做法。所以我按「用户现在拿什么凑合」分了六类，通用 AI 助手和 Lovable 是我补的常见替代品，其余都取自仓库里已有的竞品研究和 Coding 对标文档。竞品更新很快，上线前请再核一遍。

| 用户现在用的 | 代表产品 | 它擅长 | Molis 的不同 | Molis 目前不如它 |
| --- | --- | --- | --- | --- |
| 编码 Agent | [Claude Code](https://code.claude.com/docs)、[Codex](https://github.com/openai/codex)、[Cursor](https://cursor.com) | 写代码本身：读改代码、跑命令、子代理、计划，模型和工具链最成熟 | 不替代它们，而是接住它们：几家的会话推进同一份 Goal，换工具不丢上下文；“完成”不由 Agent 自己宣布 | 自带的 Coding 还差 20 项（斜杠命令、代码智能、联网、沙盒规则、VS Code 等），官网不对标它们写代码的能力 |
| 编码 Agent 的任务与规格工具 | [Task Master](https://github.com/eyaltoledano/claude-task-master)、[GSD](https://github.com/gsd-build/get-shit-done)、[OpenSpec](https://github.com/Fission-AI/OpenSpec)、[Beads](https://github.com/gastownhall/beads) | 轻：放进仓库就能用，命令行和文件贴近开发者，和多种编码 Agent 搭配 | Goal 写给人看，有依赖画布和决定中心；调研、内容等非代码工作也能管；“阶段走完”不等于完成，要核对要求与依据 | 更重：要装应用、跑一个常驻宿主；对只想管代码任务的人不如它们直接 |
| AI 工作管理与知识库 | [Notion](https://www.notion.com)、[Linear](https://linear.app)、[Asana](https://asana.com)、[ClickUp](https://clickup.com)、[monday.com](https://monday.com) | 团队协作、多视图、成熟的权限与云同步；Notion、Linear 已有官方 MCP，编码 Agent 能直接读写 | 数据在本机；所有插件共用一个能力目录和一套授权，撤权后不再写入；Agent 只能提议、不能改掉你认可的目标；缺的工具可以自己做 | 团队、多设备、手机上用都还没有；生态和模板少得多 |
| 通用 AI 助手 | [ChatGPT](https://chatgpt.com)、[Claude](https://claude.ai) | 对话体验和模型能力强，联网、记忆、连接器都成熟 | 助理就在你的工作台里：看得到当前页面和选区，建议是点一下就执行的操作卡，改动可撤销；记忆存本机、可见可删；提示词全部可见可改 | 模型能力取决于你自己配的服务；关掉应用后定时任务和提醒不跑；助理刚合入、还没经你验收 |
| 一句话做应用 | [Taskade Genesis](https://www.taskade.com/genesis)、[Lovable](https://lovable.dev) | 生成快，做出来的应用能部署、分享 | 做出来的是装在你项目里的插件：自动成为助理和外部 Agent 能调用的能力，能读写 Goals、Inbox、Pages；装前过门禁和浏览器验收 | 第一次做成的比例低（4/12）；不能发布给别人用 |
| 人和多个 Agent 的协作空间 | [OpenAgents](https://openagents.org/docs/en/workspace/what-is-workspace) | 人和多个 Agent 在同一个线程里协作，@ 一下就能委派；本机的 Agent 也能连进来 | 以 Goal 为准而不是以聊天线程为准；完成有门禁；整个工作台和数据都在本机 | 多人协作已经是它的主线，我们只有早期的项目讨论 |

两点提醒：第一，Notion、Linear 都已提供官方 MCP，不能说“只有我们能让外部 Agent 读写”。第二，仓库里的研究已经指出 OpenAgents 是直接近邻，“多个 Agent 一起干活”不是市场空白；要比的是结果能不能看懂、接续、核对。

## Molis 做了什么别人没做的

单看每一项，都能在某个竞品里找到近似的做法；少见的是下面四件事在同一个本机工作台里，守同一套规则。官网可以写这四条：

1. **一份目标，所有 Agent 共用，“完成”要核对。** 内置接入 5 家编码 Agent，其他经 MCP。Agent 只能提议，不能悄悄改掉你认可的目标；完成要过显式收尾，报告条数、子 Goal 数量都不算数。多数任务工具里，标成完成是一次状态切换；Molis 把它做成一次核对。
2. **能力登记一次，四个入口守同一套权限。** 页面、助理、工作流、外部 MCP 客户端调用的是同一项能力，按调用方逐个授权，调用留记录，撤权或取消后不再写入。外部 Agent 和内置助理没有两套规矩。
3. **缺的工具自己做，做出来就能被 AI 用。** 生成的不是一个孤立的网页应用，而是装进项目的插件，自动登记成能力，助理和外部 Agent 马上能调用。
4. **AI 怎么做事，你看得见、改得了。** 系统和每个插件的提示词、角色都在设置里可见可改，可以恢复默认，每次运行查得到用的是哪一版；记忆看得见、删得掉。这在 AI 产品里不常见。

「数据在本机」是这四条的底子，但不单独当卖点：Claude Code 这类工具本来就在本机跑。

比较时容易写过头的几句（完整口径见[「官网核心亮点」文档](https://claude.ai/code/artifact/a3272ef7-9969-4095-9a37-754a71b7c245)的「写作口径」）：

- 不说「唯一」「首个」，每一项单拿出来都有近似做法。
- 不说「替代 Claude Code、Cursor」，我们接住它们；也不说「支持所有 Agent」，写「内置接入 5 家，其他经 MCP」。
- 不说「本地模型」「离线 AI」，本地指数据和执行，模型仍调用你配置的服务。
- 不说「随时在后台工作」，关掉应用后定时任务和提醒不跑。
- 不说「自动派单」「替你分配工作」，产品明确不派单。

## 给官网的建议

**页面顺序**，从上到下：

1. 首屏：一句话，加内置接入的 Agent 名单（Codex、Claude Code、OpenCode、Pi Agent、Grok Build）。
2. 三个主场景：选场景 1、2、3。1 是唯一已发版的核心；2 是平台机制，撑起后面所有功能；3 面向的人最多。
3. 四条差异。
4. 次级场景卡片：场景 4–7。
5. 功能墙：直接用上面功能全景的分组。
6. 和你现在的用法比。
7. 本地优先与边界，然后结尾。

**竞品不点名。** 对 Claude Code、Codex 这类写成「配合使用」，名字出现在接入名单里反而加分。对 Notion、Linear 等，用「如果你现在用笔记或任务工具记 AI 做到哪了……」这样的说法，不做点名对比表。点名对比要跟着对方更新一直改，很快就过时；我们的差异在机制上，不靠比别人。上面的竞品表留作内部判断和常见问题的素材。

**上线跟下一次发版走。** 现在能下载到的 v0.2.0 只有 Goals 这一块，七个场景里用户只拿得到场景 1 和场景 4 的一部分。另外三件事要一起处理：

- GitHub Release 还叫「GoalBoard v0.2.0」，发新版时改成 Molis Work。
- 已签名并公证的 macOS 安装包还没有，是否申请 Developer ID 待你决定（BL-021）；下载按钮按实际状态写。
- 统一待办清单里有 17 项「待你验收」，建议上线前按七个场景亲自走一遍。
