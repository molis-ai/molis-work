# Molis Work 菜单栏工作胶囊纠偏

## 完成等级

功能可用（等级 3）：真实 macOS 桌面壳中的菜单栏入口、弹出面板生命周期、信息呈现和深链接能够工作，并通过自动测试、构建与真机检查。Pause、Resume、Start 等控制不在本次范围内。

## 背景与问题证据

现有切片已经能从 Molis Work 同一事实源投影当前 Goal、Run、待决定事项和 Next actionable Goal，但桌面呈现方式不符合已确认的产品模型：

- 胶囊窗口启动即显示，无法作为临时界面自然消失。
- 窗口没有锚定菜单栏入口，位置像一个独立浮窗。
- 菜单栏复用了应用方块图标，Retina 菜单栏尺寸下既丑也难识别。
- 胶囊仍有紧凑、展开、最小化三套窗口状态，增加了不必要的操作和状态分叉。
- 面板视觉偏网页卡片，信息层级、留白和控件质感不像 macOS 临时面板。
- 项目规模较大时，胶囊接口会在一次请求里重复读取同一份 Molis Work 快照。实测 162 个 Goal 的 Footballnia 项目单次读取需要约 0.7–2.5 秒，而 29 个 Goal 的项目约 10–30ms。
- 项目切换没有明确加载反馈，也没有取消或隔离上一项目的请求。用户会感觉下拉框“卡住”，快速连续切换时还可能短暂看到项目名和内容不一致。

用户已明确纠正：Molis Work 启动即出现菜单栏状态；胶囊默认隐藏；左键点击菜单栏入口时在其下方出现；再次点击、点击其他地方或按 Esc 消失。

## 目标

把工作胶囊改成 Molis Work 的 macOS “Now Playing”：菜单栏是唯一常驻入口，弹出面板只在用户查看时临时出现。用户打开后应能在几秒内看懂：现在是哪个项目、聚焦哪个 Goal、处于什么状态、刚完成什么、正在做什么、唯一主要问题是什么、下一步是什么。

## 范围

### 包含

- Molis Work 启动时创建菜单栏状态项，并使用专用透明单色图标。
- 胶囊 WebView 启动时隐藏；宽度固定，高度按当前列表和展开内容在最小值与上限之间收放，超过上限后只滚动列表。
- 左键点击菜单栏入口切换面板显示；右键保留少量系统菜单。
- 面板按菜单栏图标中心定位，落在图标下方并限制在当前屏幕可用区域内。
- 面板失去焦点、用户再次点击菜单栏入口或按 Esc 时关闭。
- 删除拖动、紧凑/展开/最小化三态；菜单栏本身承担紧凑状态。
- 重做弹出面板的信息层级、视觉样式、暗色主题、焦点态和错误态。
- 保留项目切换、状态轮询、菜单栏状态更新、精确打开 Goal/决定中心的行为。
- 项目切换后立即显示带转圈图标的加载状态；旧项目内容不能继续留在新项目名下。
- 同一时刻只允许最新一次项目读取更新界面；后台轮询不能抢占正在进行的项目切换。
- 胶囊沿用 `queryAvailable` 的权威判断，但一次查询只读取一次 Board 快照，不再为每个候选 Goal 重复读取整板数据。
- 修正 Focused Goal 选择：真实进行中的工作和等待用户处理的事项优先，不能被一个没有在工作的旧“当前 Goal”遮住。
- 把单 Goal 面板升级为横向状态标签页；每个标签页显示该状态下的 Goal 列表，点击一条后在列表内展开详情和唯一下一步动作。

### 不包含

- Goal Tree 编辑、新建或拖拽。
- 完整日志、Agent Chat 或大段证据。
- Pause、Resume、Start 等会改变执行状态的控制。
- 单独的胶囊数据存储。
- Windows/Linux 托盘窗口行为。

## 用户路径与行为契约

1. 用户打开 Molis Work。主窗口照常显示；macOS 菜单栏出现 Molis Work 专用图标和当前状态文字；工作胶囊不自动弹出。
2. 用户左键点击菜单栏入口。弹出面板显示在入口正下方，并获得键盘焦点。
3. 用户切换 Project。只改变胶囊查看焦点并继续消费该 Project 的事实，不停止其他 Project 的 Agent。
   - 下拉框先立即切换，面板在 100ms 内进入“正在读取「项目名」”的转圈加载态。
   - 加载期间不展示上一个项目的 Goal、标签和状态，也不禁用项目下拉框；用户可以继续切换。
   - 若用户连续切换多次，只展示最后选中项目的结果。较早请求即使稍后返回，也不能覆盖当前项目。
4. 用户点击面板内的“打开 Molis Work”或当前主动作。主窗口导航到准确页面并置前，弹出面板关闭。
5. 用户点击其他窗口、再次点击菜单栏入口或按 Esc。面板立即关闭，不改变 Goal/Run/Claim 状态。
6. 用户右键点击菜单栏入口。显示“打开当前目标”和“退出 Molis Work”；不把系统菜单与左键弹出面板混在一起。
7. 用户在弹出面板顶部横向切换“需要你 / 执行中 / 澄清中 / 检查中 / 待执行 / 待澄清 / 待检查 / 已卡住”等实际非空状态。标签不纵向排列、不换行，空间不足时在同一行横向滚动。
8. 用户点击列表中的 Goal。该 Goal 在当前列表内展开“为什么做、刚完成、当前情况、主要问题、下一步”和一个状态对应的主动作；再次点击收起，点击另一条时切换展开项。

### Focused Goal 选择规则

胶囊不把 `active_goal_id` 直接等同于“正在做的 Goal”。它只是一项用户焦点提示，必须结合当前事实判断：

1. 若项目的“当前 Goal”仍有进行中的工作，或正在等待用户处理决定，继续显示它。处于 blocked 但没有有效 Claim/Run 的 Goal 只表示暂时不具备执行条件，不算进行中工作。
2. 否则，优先显示等待用户决定的 Goal；有多项时选择最近活动的一项。
3. 没有待用户决定事项时，显示最近开始的真实进行中 Goal。多个 Goal 并行时只展示一个，并显示“+N 同时运行”。
4. 没有进行中工作时，刚完成的 Goal 短暂显示 10 秒；之后才显示权威 Available 集合中的第一项 Next actionable Goal。
5. `active_goal_id` 指向一条未在工作、未等待决定的 Goal 时，不得让胶囊误显示“可开始”或隐藏其他真实工作。

Molis Work 当前没有独立、权威的 Goal 暂停状态。本次不从 blocked、缺少 Run 或其他异常状态猜测“已暂停”；Paused/Resume 需在后续先补齐领域状态和写入语义，再接入胶囊。

### 标签页与唯一归属

- 同一 Goal 同一时间只出现在一个标签页，优先级为：需要用户决定 > 真实进行中 > 权威 Available > 已卡住。
- “进行中”按真实阶段拆成执行中、澄清中和检查中；“可以开始”按权威 `queryAvailable` 拆成待执行、待澄清和待检查。空标签不显示。
- 默认标签依次选择：需要你；仍在工作的当前 Goal 所属标签；最近活动的进行中标签；刚完成（只保留 10 秒）；权威 Available 第一项所属标签；已卡住。
- 标签内顺序保留事实源的执行顺序：待执行、待澄清和待检查沿用 `queryAvailable` 顺序；进行中按当前焦点和最近活动时间；需要你按最新待决定事项。
- 每个 Goal 的摘要行直接显示准确状态和下一步，不要求用户先展开才能知道要做什么。
- 状态轮询后，Goal 自动移动到新的唯一标签。当前展开 Goal 仍存在时保持展开；已完成时短暂展示结果，再从列表移除。

## 方案与关键决策

### 桌面壳

- Tauri `capsule` 窗口宽度固定、高度受控收放，`visible=false`、无标题栏、不可拖动、置顶、不进入任务切换器。
- 左键事件使用菜单栏图标提供的物理坐标计算面板位置：水平中心对齐图标，垂直放在其下方；靠近屏幕边缘时钳制到当前显示器工作区。
- 面板失焦由原生窗口事件关闭；Esc 通过一个最小 Tauri command 关闭。
- 主动作打开 Molis Work 后也关闭面板，避免它继续遮挡主界面。
- 左键不再显示原生菜单；右键仍使用原生菜单。

### 菜单栏图标

- 不复用 App icon。由桌面壳生成一枚 18×18pt 对应的 36×36 Retina 透明模板图：一个简洁目标环和中心点。
- 图标只使用 alpha 表达轮廓，交给 macOS 模板着色，自动适配浅色和深色菜单栏。

### 弹出面板

- 使用一个单一展开面板；短列表时贴合内容，展开或项目较多时增长到上限，之后只让列表区域滚动，不再在窗口内部模拟三套模式。
- 使用不透明纸面、清楚边框、克制阴影和 8px 圆角；不使用渐变、玻璃拟态或多层卡片。
- 顶部显示 Project 选择和总体状态；其下是单行横向状态标签；中部只显示当前标签的 Goal 列表和一个行内展开详情；底部保留“打开 Molis Work”。
- Goal 摘要行显示标题、准确状态、经过时间和一句下一步；展开区只保留“为什么做 / 刚完成 / 当前情况 / 主要问题 / 下一步”和一个状态相关主动作。
- 文案保持简短、具体、非技术化；不向用户暴露 Claim、Run 等内部名词。
- 明确项目切换才替换为加载占位；普通的 2.5 秒状态刷新保留现有内容，不反复闪烁。加载占位保留面板尺寸，转圈动画在“减少动态效果”设置下停止旋转。

### 读取性能与竞态

- `queryAvailable` 已经读取了当前 Board 快照；后续资格判断复用该快照，避免按候选 Goal 重复执行整板读取。判断规则和返回顺序不变。
- 浏览器端为每次读取分配递增序号并取消上一请求；只有“请求项目仍是当前项目且序号最新”的结果可以渲染。
- 定时刷新发现项目切换请求仍在进行时直接跳过这一轮，避免后台刷新取消用户主动切换。

## 输入、输出与依赖

- 输入：现有 `/projects/:project/api/capsule` 状态投影、项目列表、菜单栏点击位置、显示器工作区、主题设置。
- 输出：菜单栏标题与 tooltip、临时弹出面板、准确的 Molis Work 深链接。
- 依赖：复用 `capsule-real-state-slice` 的状态投影；后续 `capsule-project-attention`、`capsule-safe-controls` 和 `capsule-desktop-reliability` 应在本纠偏后重新检查。

## 文件与模块边界

- `desktop/src-tauri/src/main.rs`：菜单栏图标、点击事件、窗口定位、失焦关闭、Esc command。
- `desktop/src-tauri/tauri.conf.json`：窗口默认隐藏，并声明宽度与最大初始高度。
- `desktop/src-tauri/permissions/capsule.toml`、`capabilities/default.json`：只开放实际需要的胶囊命令；主窗口继续保留自定义标题栏所需的拖动权限，但胶囊页面不声明任何拖动区域。
- `src/web/capsule.ts`：单一弹出面板的结构、样式、轮询和交互。
- `tests/capsule.test.ts` 与 Rust 单元测试：状态投影、HTML 契约、图标 alpha 和跨屏定位边界。

## 验收标准

1. App 启动后菜单栏入口存在，胶囊不自动显示。
2. 左键点击菜单栏入口后，胶囊在图标下方显示；再次点击、点击其他地方、按 Esc 都会隐藏。
3. 靠近屏幕左右边缘时面板不会跑出可用区域；下方放不下时有确定的上方回退。
4. 菜单栏图标不再是方块，透明背景、轮廓清晰、模板着色正确。
5. 面板在浅色和深色主题下无截断、无页面级滚动条、无明显多余空白，层级清晰；项目、Goal、状态、刚完成、正在做、主要问题和下一步都可理解。短列表贴合内容，长列表在上限内滚动。
6. 项目切换不改变其他项目执行状态；打开主动作进入准确 Goal 或决定中心页面。
7. 胶囊状态定向测试、TypeScript 构建、Rust 测试和桌面构建成功。
8. 一个未在工作的旧“当前 Goal”与另一个真实运行 Goal 同时存在时，菜单栏和弹出面板显示真实运行 Goal；旧焦点不会遮住它。没有 Claim/Run、仅因依赖或规则未满足而 blocked 的 Goal 也不能抢占焦点。
9. 多个真实运行 Goal 并存时，仍在工作的“当前 Goal”保持焦点并显示正确的“+N 同时运行”；没有有效焦点时按最近活动时间稳定选择。
10. 没有有效焦点但存在待用户决定事项时，胶囊显示“需要你”并直达对应决定；只有在没有待决定和进行中工作时才进入 Complete、Ready 或 Empty。
11. 多个执行中、待执行或待澄清 Goal 会分别进入对应横向标签页；每条摘要行都能直接读到下一步，点击后只展开这一条的详情和主动作。
12. 同一 Goal 不会因同时存在 Run、Available 或待决定事实而重复出现；状态变化后会自动移动到唯一正确标签。
13. 空标签不显示；标签始终单行横向排列，列表和展开详情不会把整个窗口撑出屏幕。
14. 切换项目后 100ms 内能看到转圈加载态，且项目名、加载文案和最终内容始终属于同一项目；连续快速切换不会被旧请求反向覆盖。
15. 162 个 Goal 的真实项目在同机热态读取中位数不超过 250ms，并且相对本次 0.7–2.5 秒基线至少降低 60%；`queryAvailable` 每次调用只读取一次 Board 快照。
16. 普通轮询不闪烁加载占位；加载态有 `aria-busy` 和可读状态文本，并遵守减少动态效果设置。

## 验证命令与人工检查

- `pnpm test -- tests/capsule.test.ts tests/web.test.ts`
- `node --import tsx --test tests/v1.test.ts`（覆盖 Available 单快照回归）
- `pnpm build`
- `cargo test --manifest-path desktop/src-tauri/Cargo.toml`
- `pnpm desktop:build`
- 在真实 Molis Work macOS App 中连续检查：启动隐藏、左键显示、锚定位置、再次点击关闭、失焦关闭、Esc 关闭、右键菜单、浅/深色主题、项目切换和准确深链接。
- 在 Footballnia、Molis Work 体验优化和 Hearth 三个真实项目间连续切换，记录接口耗时，并检查加载反馈、最后一次切换生效和轮询不闪烁。
- 对变更界面运行 Impeccable detector，并人工检查浏览器渲染截图和真实桌面状态。

## 假设与风险

- macOS tray 事件返回的矩形使用物理坐标；实现必须按窗口 scale factor 统一换算，并用单元测试覆盖边缘位置。
- 隐藏 WebView 仍保持轮询以更新菜单栏状态；若未来要降低后台开销，单独设计事件推送，不在本次扩大范围。
- Tauri 无法提供原生 `NSPopover` 的全部系统动画；本次以正确生命周期、锚定、焦点行为和视觉一致性达到功能可用，不宣称已达到可发布等级。
