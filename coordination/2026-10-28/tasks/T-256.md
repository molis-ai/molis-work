## 1. 背景

来源：MISC「T-280 二审 建议（6512731197）」（#1530 的二审，建议 1、3、4）。T-280（#1530，已合入）把 `scripts/check-package-boundaries.mjs` 里 `workbenchContributionRegistered`（约 :1500-1521）的目录 `contributions` 列表改成在“去掉注释和字符串后的代码”上读：`const packs = derivesPacks ? code(descriptors).match(…)`。结果：

- `contributions: [feedUiContribution // note\n]`
- `contributions: [/* note */ feedUiContribution]`
- `contributions: [feedUiContribution /* note */]`

这三种写法，严的读法 `hasWorkbenchUiContribution` 收下（true），旧行为 `mentionsWorkbenchUiContribution` 不收（false）。方向无害（名字确实在代码里，旧的是误拒），但它让接受集变大，而测试 `tests/package-boundary-must-contain.test.mjs` 的 `RAC-2068`（约 :258）标题写的是“严的读法收下的，普通读法也收”，这句话对这三种写法不成立（RAC-2068 只随机剪 1～29 个字符，碰不到）。另有：

- 文档 `docs/system/PACKAGE-BOUNDARIES.md:162` 写“Feed 目录的 `contributions`”，其实读的是内置插件目录 `BUILTIN_PLUGIN_CATALOG`（Goals 提案界面的检查也读它）。
- `scripts/check-package-boundaries.mjs:1319` 的 `matchesStatementInCode` JSDoc 说“Only the start is looked at”，没提：`matchAll` 的匹配不重叠，字符串里一段以 `import { BUILTIN_PLUGIN_WORKBENCH, ` 开头的文字，其 `[^}]+` 可以吃到后面真 import 的 `}`，使真 import 的起点落进被吞的区间而被误拒。只会多拒、不会多收。

决定（统筹 2026-10-30）：不改检查的行为，只把说法改准并用用例钉住这个有意的收宽。

## 2. 目标

1. `RAC-2068` 的标题和注释改准：写明“除 `contributions` 列表按去掉注释后的代码读（旁边带注释的条目现在算登记）这一处有意收宽外，严的读法收下的，普通读法也收”。随机变异的循环不变。
2. 新增一条用例 `RAC-2296`：用真实的目录文本（`builtinCatalogText(repository)`），把 `feedUiContribution` 所在列表改成上面三种带注释的写法，各断言 `hasWorkbenchUiContribution(...)` 为 true、`mentionsWorkbenchUiContribution(...)` 为 false；再断言名字**不在**列表里、只在注释里时（如 `contributions: [ /* feedUiContribution */ ]`）两者都为 false（收宽不等于看注释）。
3. `docs/system/PACKAGE-BOUNDARIES.md:162` 的“Feed 目录的 `contributions`”改成“内置插件目录的 `contributions`”，句子其余不动。
4. `matchesStatementInCode` 的 JSDoc 在“Only the start is looked at”旁补半句，写明匹配不重叠、字符串里以同样开头的一段文字可能吞掉后面真语句的开头，后果只是多拒、不会多收。只加注释，不改代码。

2. 新用例的写法参考 RAC-2068：`const descriptors = builtinCatalogText(repository)`，在里面找到 `feedUiContribution` 所在的 `contributions: [...]`（`/contributions:\s*\[([^\]]*)\]/u` 里含它的那一个），把括号里的内容换成测试写的三种写法，再调用 `hasWorkbenchUiContribution(composition, registry, "feedUiContribution", mutated)` 与 `mentionsWorkbenchUiContribution(...)`（`composition`、`registry` 用 RAC-2068 里同样的 `read(COMPOSITION)`、`read(REGISTRY)`）。注意 `[^\]]*` 遇到注释里的 `]` 会提前结束，用例的写法里不要在注释中放 `]`。
