## 1. 背景

PG-070 把插件的样式从公共样式表里拆成按需加载的 `/assets/molis-work-plugins/<id>.css`（`specs/repository-anti-corruption/slices/pg070-plugin-styles.md`）。页面在框架里运行的插件（有客户端），把名字空间下的规则作为自己的 css，只有要用的框架（和外壳画的设置页）链接；别的规则留在共用样式表（`apps/workbench/src/plugin-workbench.ts:81-97` 的 `splitOf`、`pluginWorkbenchStyles`、`pluginOnDemandStylesheet`）。Coding 属于这一类：它的登记（`plugins/native/coding/src/registration.ts:13-22`）有 `clientFactory`、`stylesheet: CODING_STYLES`、`stylesheetShared: ["data-coding-workbench", "data-coding-line"]`、`clientUses: ["git", "files"]`。

工作台样式表已经只带 Coding 的共用部分：`page-assets.ts:90` 的 `${pluginWorkbenchStyles()}` 对每个插件取 `splitOf(pack)?.shared`。**设置样式表没有走这条路**，它在 `page-assets.ts:103` 直接拼了整张 `CODING_STYLES`：

```ts
// apps/workbench/src/page-assets.ts:16
import { CODING_STYLES } from "@molis-ai/molis-work-plugin-coding";
// apps/workbench/src/page-assets.ts:102-104（中间一段，原样）
export function renderMolisWorkSettingsStylesheet(): string {
  return `${STYLES}${MORE_STYLES}…${PAGE_PRIMITIVE_TAIL}${TYPEFACE_STYLES}${CODING_STYLES}${CHARACTERS_STYLES}${PLUGIN_STAGE_STYLES}${FUNCTIONS_STYLES}${CAPABILITIES_STYLES}${CRAFT_FINISH_STYLES}${NAVIGATION_FLOW_STYLES}`;
}
```

W5-04 第三组 A 的切片文字（`slices/w5-04-third-group.md:28`）写：「设置页的样式表仍带 `CODING_STYLES`（PG-072 另算）。按需加载样式要多出一个资源（要先问统筹），本片不做。」后半句现在不成立：按需加载的 `coding.css` 在 PG-070 第 1 片（#1302，batch-40）就已经存在并登记；PG-072（设置节由宿主按贡献 id 分支拼）也已经做完（`privileges.md` 的 PG-072 行、`slices/w5-02-shell-lists.md`），它与样式表无关。
