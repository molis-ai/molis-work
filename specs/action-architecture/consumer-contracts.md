## SDK 派发、Feed 调度与撤权

SDK 最后派发修复合同：沿用现有 Prologue Node Host 和 Molis 的调用级 AsyncLocalStorage，不改 channel 含义、不旁路 SDK、不全局改写 fetch。Node Host 提供可信 App 的网络派发前拒绝回调，覆盖模型、MCP HTTP 及重定向的每次实际 fetch，旧 model-only 回调保持兼容；回调不能放宽 Host 网络政策。Molis 将当前动作的 beforeEffect 和 signal 带入 SDK 工具调用上下文；并发调用各自隔离，调用结束后不泄漏给下一次调用。拒绝使用 SDK 的 EFFECT_NOT_AUTHORIZED，取消和超时保留原语义，不因撤权重发。以当前 claims 源码 af7375c7 加已提交的 03c6ba0b 拒绝语义修复为基线，在独立 SDK 工作树构建新本地包；不纳入其他工作树未提交的功能。验证使用真实 Node Host/HTTP 服务，覆盖网络准备后撤权零 tools/call、异步最后检查中的取消、恢复和并发调用；模型原回归、SDK 包构建和消费 App 实际链路都须通过。

SDK 取消接线补充：公开 invoke.signal 只取消审批等待，MCP 传输接受 runner 的 ToolAbort；应用适配器把原 signal 与已有工具 deadline 合并到这一公开取消口，不新增 SDK 状态。派发前取消返回 CANCELLED、零远端调用；已派发且未取得回应时取消必须保留 EFFECT_RECONCILE_REQUIRED，不假装未执行或自动重发。真实 HTTP 服务先写后挂起验证后者。

Feed 后续修复合同：公开来源、研究库与账号来源都将原调用的持续授权带到各自提交点。Feed owner 在每次异步等待后同时核对原来源仍启用、未删除、配置和账号引用未变；首次拒绝即终止本次尝试，错误收尾不能再写失败状态。账号来源的 Listener 在接受原始事件、创建 Signal、提交 delivery/cursor/run 前使用同一检查；释放自己的运行 lease 属于必需清理，仍执行。保留原存储、幂等键、已获授权的早期写入和重启恢复语义，不另建同步状态系统。验证覆盖网络成功/失败、停用/撤权/取消/配置变化、原材料与 Signal/游标/运行状态、重新授权后的原幂等键恢复。自动拉取当前绕过动作的调用链也属必须迁移范围；不能因外层 Feed 检查通过便认定 Listener 或定时触发已完成。

自动拉取通过 Feed 自身声明的 `feed.sources.tick` 动作进入同一执行核心，定时器只负责触发。批量调度和手动拉取复用同一个 owner 同步实现；原计划、游标、幂等键仍由原服务持有。调度器把同一次持续授权传至同步链及失败提醒、下次拉取时间的写入点；拒绝后不再推进计划。成功同步允许自己的账号元数据更新，后续计划提交以返回的已提交来源为基准重新检查。等待所有已发起来源退出后才结束动作，避免一个来源失败导致其他来源还在写入而原动作已结束。移除 Host 默认直调同步旁路。取消或上游失败已有终态回执时，显式重新拉取使用新幂等键，不能篡改原回执。

真实调度测试补出的原有断点：原计划键直接拼入 ISO 时间（含 `.`），与同步入口的 8–128 位字母/数字/冒号/下划线/连字符合同冲突，每次自动拉取在外部请求前即失败，旧 fake dispatch 测试未覆盖。计划键改为复用 owner 的 stableId，以来源 ID 和原计划时间确定身份；同一计划重试一致，不同计划不同。旧键从未通过同步入口校验，不迁移为业务回执或删除原数据。

定时动作使用既有 Host concurrent 调度合同，等待网络期间不占住项目命令队列，用户仍可经原动作暂停或修改来源；原 Scheduler 的来源 inFlight 集合保持在处理器生命周期内，防止重复定时触发重叠拉取。它只保存正在执行的来源集合，业务运行与恢复仍在原 SQLite 中。验证须实际在同一 Host 的待响应定时动作期间调用暂停/配置动作，并验证重叠 tick 跳过。

2026-09-28 main 复查修复合同：以 `review-2026-09-28.md` 的真实反例为依据。工作流在发起下游调用前按原完整 schema 校验映射；调用一旦发起，任何处理器/下游错误都保留 attempted 状态，不再从错误码推导“无副作用”，普通继续不得重发，原明确重试入口保留。MCP 连接层接收 Host-only 的持续授权回调，在连接/认证等异步准备之后及每次 HTTP 派发前重新检查；stdio 在实际工具/资源请求前检查。工具调用固定登记时的输入合同，在线发现与其不符即拒绝旧引用，并更新原工具快照和目录；不新增授权或版本存储。无法编译的外部 schema 保留在已有工具快照，目录用拒绝所有输入的占位合同明确标为不可用，不丢整组健康工具、不放宽为任意对象；有效合同重新发现后恢复。验证使用真实 MCP 协议和持久精确授权、真实 PluginRuntime/工作流状态及原业务写入，覆盖撤权交错、工具变更、部分成功重试、坏合同与同源健康合同共存。继续保护当前其他任务修改；完成这组修复不代替全量目标验收。

内置 Agent/Character 执行迁移合同：Character 原草稿与发布 Artifact 增加可选精确 action_tools；缺省/null 继承本轮显式选择，空数组不开放动作。旧记录不获得新权限，编辑无关字段保留引用。Agent 开始时从共同目录解析当前授权能力，固定身份、版本、提供方、输入合同与展示信息，Character 只能缩小本轮显式选择范围，未选择动作时不自动采用角色清单；只读角色只允许查询。运行时工具声明由该固定选择生成，执行逐次回到原 ActionClient，重查客户端授权、原提供方、项目和取消，不把业务输入中的身份字段当成授权。沿用现有逐客户端准确授权存储，内置运行时使用固定客户端身份，不因选择 Character 或发现能力自动授权。Prologue 使用 SDK 正式工具扩展与原审查队列，回调限定原会话与本轮；写操作保持现有审查，审核后仍复查权限。历史只存引用与原执行记录，不存回调或凭据。角色停用、动作撤权、升级或卸载时，新的运行或后续调用明确失败，不重放历史。产品能力选择、真实用途及 Coding/Character 管理动作须接通同一服务，不能以仅增加字段或模拟 adapter 宣称本范围完成。

Agent 判断用途迁移合同：作者目录中 Agent 可选能力来自同一次当前授权 ActionView 查询，过滤具有 agent/mcp audience 的真实能力，显示准确标题、来源、版本和可用原因，不再拼接旧 Manifest/MCP/System behavior 名单。原 Functions 表保存可选 action_map（输出键到精确能力/版本/提供方）；Choice/Noul 可映射，未映射结果仅返回原判断数据，Score 暂仅原评分。Agent 用途调用返回 recommended_actions 精确引用，不自动填参或执行。发布和调用前后检查原引用、当前权限、生命周期及取消；标准 MCP 客户端取得推荐后单独调用被授权业务能力，真实结果写回原 owner。旧 Agent 字符串选项/历史保留，不猜成新能力或自动授予权限。所有实际场景已走共同执行后，删除无生产调用者的 service.judge/allowed_behavior_ids 分支；历史查询继续使用原存储。旧连接凭据本身不生成可调用能力，其实际动作迁移单独核对，不能用账号绑定伪装完成能力注册。编辑器允许保存失效映射并解释原因，发布拒绝失效项。目录、记录、MCP schema 与实际返回共用合同，无新注册/授权库。完成后继续真实内置 Agent/Character 工具接入，不能以作者推荐代替该范围。

作者准确用途合同：原 Functions 记录增加可空的场景版本和提供方，选择用途时一起保存，编辑无关字段和来源失效时保留。目录允许选择同名多版本，标签/结果映射按准确场景隔离。发布时验证准确引用；旧草稿未固定来源仅在当前唯一且兼容时于同一次发布条件更新中固定，存在歧义则保留草稿要求选择。已发布旧记录不回写、不猜测原来源，保留原合同兼容；新发布动作携带可选 result_scene 约束，由共同核心在发现、绑定和执行检查准确场景，不能被另一个同名版本或替换提供方接走。场景停止不阻止独立调用已发布判断，但原用途保持失效。迁移仅为原表加可空字段，可回退代码读取原字段；不删除版本、历史或绑定。验证含同名版本独立标签、旧草稿升级、缺失/替换来源、并发发布和真实浏览器选择/绑定。

当前执行切片：Agent 作者目录与精确推荐已接通，Choice/Noul 保存准确能力引用；外部 MCP 取得推荐后单独执行原业务动作，撤权或停用在模型返回前生效。旧静态作者目录和无生产调用者的 judge/行为白名单分支已删除，原历史保留。内置 Agent/Character 的实际工具执行整合、旧连接账号检查动作注册仍待继续。共同作者目录、Feed/Inbox/Home 消费及通用配置位置已接通。系统编辑器不再按 Home/Inbox 分支启用，未知 Runtime 插件可由原 owner 提供位置并在真实界面保存。仅场景插件的三项管理动作自动注册，MCP 通过现有设置精确授权；配置权独立于运行权。作者用途已能选择并保存准确版本/提供方，新发布判断由共同核心固定原场景，旧草稿发布时仅在唯一匹配下补齐，已发布旧数据保持。MCP 撤权、并发覆盖、断连停用、桌面/窄屏操作已有证据，见 migration.md。生成插件模板与仓库样例已迁为 v2，轮询调用共同注册动作，公开健康查询可通过 MCP 使用；个人数据继续遵守原 owner 限制。完整 Goal 保持执行中，非推荐 typed 结果、来源撤回后的持续用途显示、Agent/Character 与工作流及其余全量迁移继续。

## 场景配置、授权与推荐选项

场景管理授权收敛合同：运行场景使用原 permissions，读取/停用原绑定使用独立 configuration_permissions。拥有配置权但缺少模型/运行权限时仍能读取实际位置和停用，不能因此启用或运行。Runtime 分别检查原安装的执行与配置 grants，来源生命周期检查保持共同。

每个兑现 targets 的场景由共同 Host 注册适配自动派生“读取配置位置、启用判断、停用判断”三项真实动作，身份由场景 ID/版本和原提供方决定，与原注册一起撤回；处理器调用同一个 Host 场景客户端和原 owner，不新增绑定或授权库。读取/停用动作只要求配置权限；启用动作还要求场景运行权限及具体目标附加权限，判断本身仍须精确授权。系统作者配置转发到这些动作；MCP 通过现有 action_grants 和设置界面授权准确动作，即可配置仅提供场景的插件。外部调用不能靠其他动作恰好授予同名权限跳过该场景的准确动作授权。提供方重载、撤权、过期 revision、模型不可用和保存期间修改仍在原路径复核。先用真实未知插件与原存储验证，再检查已有 Home/Inbox/Feed、网页和正式 MCP 回归。


生成模板迁移合同：CLI create 与仓库 plugin-sample 使用同一 v2 声明/实现，保留私人计数、个人 Artifact、轮询和 UI 的现有价值。公开健康查询通过共同动作可供 MCP 调用；读取私人结果和生成个人 Artifact 通过 owner-bound 动作，不借外部客户端身份冒充本地用户，也不绕过尚未定案的个人成果归属。轮询调用同一注册生成动作，不能留下另一份发布实现。示例从原 manifest 动作定义取得 handler，不复制动作目录。用打包的公开 SDK、实际 CLI/Runtime 的发现、调用、授权/停用、恢复和原数据验证；MCP 验证公开查询和个人入口的拒绝，不能将其写成外部个人成果写入已完成。


通用启用入口合同：消费场景的 owner 可声明配置权限并通过 targets 返回真实配置位置（binding_id、名称、跳转位置、当前配置 revision）。单一项目场景返回自己的固定位置；Feed 只返回已创建的来源规则，创建规则仍去原业务入口。共同服务附加准确场景版本、提供方、项目、原绑定及实时可用状态；不猜测新规则或默认绑定 ID。配置请求固定场景提供方和读取时的 revision，原 owner 在持久化时执行条件更新；并发修改、删除、来源替换和撤权均拒绝旧请求。停用保留原引用，重新启用必须重查兼容性及授权。旧内部 bind 调用保留同一持久化路径；通用界面必须采用带 revision 的配置合同。未知插件实现同一 targets/bind 合同即可进入系统作者入口，不能加入新的 Host 场景白名单。此合同实现后继续接通系统注册查询/命令、HTTP 薄适配和编辑器，不能以合同存在代替可操作产品完成。

配置授权的实时校验：配置权限与判断运行可用性分别返回，断连时仍可停用原引用。MCP 配置除管理动作和判断动作的精确授权外，还须在落库前从同一授权 owner 重查消费场景需要的权限；不能借调用开始时的权限快照继续写入。该检查通过可信上下文回调完成，不接受业务参数中的权限或回调。网页的场景发现也须覆盖只提供场景的已安装插件，权限来自原安装授权。

嵌套判断的调用者合同：工作流向 Inbox 交接内容时，创建材料、入箱及后续 Feed/Home/Inbox 判断必须使用原调用者上下文，不能在 flush 时切回后台身份。发起动作的精确提供方引用随嵌套调用保留；等待期间撤销发起动作或判断动作的授权后，消费前拒绝写入判断结果。已保存的材料和 Attention 是已完成事实，后续判断失败不伪装成回滚，也不自动重新创建。没有模型权限的交接仍可完成授权的材料写入，但不得借后台权限启动判断。通用合同提供小型上下文组合函数，Feed 和 Inbox 使用同一实现，不增加授权状态或注册目录。

Inbox 当前状态迁移合同：当前建议和绑定摘要通过 Inbox 的共同查询读取，内部、网页和 MCP 共用。绑定仍保存在原 Functions owner，历史仍在原判断表；新增判断使用既有 scene_provenance 固定绑定 revision、准确能力引用和实际事项内容摘要。当前建议必须同时满足原事项仍待处理、绑定启用且当前授权可用、判断对应当前绑定及原文，未知插件同样适用。旧历史缺少依据时保留供历史查阅，不能当作当前建议。网页移除静态 Functions 场景快照及数据库时间戳缓存依赖，每次刷新查询真实绑定和建议；未绑定、暂停及失效显示明确状态，更新按钮以真实可用性决定。原文读取复用已有解封服务，不能把加密占位文本送给模型。该段不提前声称旧作者启用控件、Inbox 推荐语义和所有后台委托已经清理。

Feed 迁移顺序：先将捕捉规则目录、创建、编辑、删除和关键词预览注册为 Feed 自己的能力，HTTP 仅解析旧字段并调用共同客户端；原项目规则表和原业务校验继续由 Feed 持有，不能新建规则副本。查询与写入分别要求 feed:read/feed:write，预览只读原始内容，不运行模型或产生捕捉结果。随后将全局旧函数绑定迁入规则 owner 的同一状态并接入共同场景触发，再迁移已有消息处理、来源自动事件及结果写入。第一步不把仍使用旧 judge 的 evaluate 或自动触发冒充完成；临时绑定兼容在对应场景切换后删除。

Feed 场景切换合同：捕捉规则的原项目表保存精确判断引用（能力、版本、提供方）及每次配置变化的 revision；没有判断引用的规则只是关键词或来源过滤（项目库第 5 版删掉了旧的函数键列与按规则的全局绑定）。规则写入前通过共同场景目录验证兼容性，异步检查后按原 revision 保存；停用或修改无关字段允许保留失效引用。共同 feed.capture 场景读取原消息并核对规则匹配，消费前重查消息内容与 revision，规则/绑定/权限由共同执行核心复核。仅原规则明确配置自动入箱时，inbox.admit 或 needs_review 才进入 Inbox；其他建议不自动执行。来源事件和手动处理均调用共同场景；手动/工作流调用透传原调用者，后台只使用既有来源事件的有限权限。旧 judge 分支移除。

Feed 产品合同同步：判断选择器、原消息试跑、已有消息处理和当前建议注册为 Feed 能力，界面从授权目录加载兼容能力与真实 usages，不限定系统函数。旧函数键 HTTP 输入保留为薄解析别名；新绑定保存精确引用。目录请求晚返回不得清空用户新选择；使用位置链接直接定位原来源规则。判断历史使用既有 scene_provenance 保存绑定/消息依据，当前建议按原 owner 和实时授权核验后展示。来源实例通过共同场景入箱时，由真正执行 Attention 写入的实例消费后续 Inbox 事件。共同场景在结果消费前再次检查可信授权回调，再核对绑定/对象；Feed 的嵌套判断保留发起动作授权，不能因转入来源事件身份扩大手动/工作流权限。

当前接线：规则作者目录纳入共同服务实际注册的消费场景，插件新增场景不再修改 Functions 的场景 ID 校验名单。用途保存只是作者意图，实际启用仍由原场景 owner 保存带版本和提供方的绑定；缺失场景的草稿/旧引用必须原样保留。编辑器从目录生成用途按钮、对象与有限推荐结果，选项标签按所选场景隔离，不能让两个插件的同名结果互相覆盖。暂不支持的结果合同及多版本用途歧义明确标为不可配置，不能猜测转换。Feed 已迁入共同消费场景；剩余旧作者常量、Agent 行为目录及通用启用控件继续清理。

作者目录与实际使用位置查询注册为系统能力，由原调用者上下文决定当前项目和授权范围；网页只转发到相同能力，MCP 和内部调用不再依赖网页专属拼装。查询不接受可伪造的项目/权限参数，不创建虚构项目，不因读取目录授予执行权。实际场景 owner 的 usages 优先；尚未迁移的旧绑定只保留当前项目范围，已由正式场景提供的记录不重复合并。该临时旧绑定兼容随剩余消费方迁移删除。

发布校验：草稿允许保留失效场景/选项并修改其他字段；发布到已注册场景时，系统能力根据调用者当前项目重读场景及动作目录，以共同兼容检查验证对象覆盖、输入输出合同和推荐引用。缺场景、权限、歧义版本或失效结果不能发布；校验失败不锁定草稿。异步目录检查后按原草稿 revision 提交，防止把未检查的新修改发布。编辑器携带当前项目 transport 发布，独立判断仍可在全局发布。Feed 发布也必须经过真实消费场景检查；旧的临时兼容绕过已移除。

推荐选项合同：可用于规则推荐的事项动作由原 offers 查询声明，包含稳定 offer_id、名称和本提供方的目标动作版本；完整输入仍由查询根据真实事项准备，声明不代替执行能力、不授予权限。共同目录从这些声明派生选项，身份包含原查询、查询版本、提供方、offer_id 和目标动作版本，不能靠裸按钮名跨插件匹配。模型的短选项 key 与具体动作映射分离；选项身份可以作为规则的稳定映射值，用户看到名称和来源。未声明为规则选项的动态按钮仍可人工操作，但不能假装它已能被规则配置。

按依赖顺序实现同一链路：先规范插件声明与共同目录解析、准备结果的身份核对；再接通首页判断及场景兼容性（发现/绑定/读取/执行都校验引用），最后替换作者界面的固定选项和旧数据接线。不得只放宽 Home 输出 enum，也不得提前把尚未能消费的选项当作可用配置。旧规则的有效引用需明确迁移；已删除的虚假动作保留历史及失效原因，不能偷偷改成别的动作或丢弃原条件。以未知插件自己的事项、真实动作、规则配置、推荐及执行结果为最终本段验收。

首页推荐消费合同：判断输出必须声明完整、有限的推荐 key；发现、绑定、运行及已使用位置均校验当前授权目录，包含 Host 的异步安装/权限策略。运行时按原对象准备实际选项；没有选项不调用模型，模型选择未准备的动作时记为 needs_review。保存和展示前重查原对象、选中动作的来源与完整输入、绑定和权限。历史只增加准备请求 ID 与输入摘要，不保存另一份原业务参数；准备列表本身超过 8000 字符输入合同则明确拒绝，不悄悄丢弃动作。

原 home.dock 规则中的 inbox.done/inbox.dismiss 只迁移到已知原生 Inbox 提供方的精确查询/目标版本。迁移只改 scene_map，不更改用户条件、模型 hash、版本、绑定和历史。已删除的导航/询问别名不推断成新的操作；保留引用并标记不兼容。新安装的默认首页规则仅处理已经声明真实动作的 Inbox 对象。模型配置 hash 不含映射，临时能力注册因此还必须比较实际发布合同，防止迁移后目录保留旧输出枚举。

## 首页、Session 与消息交接

规则编辑器读取当前选择项目的授权目录，来源停用后保留已选映射及失效提示，编辑其他字段不能清空引用。首页固定动作名单、按原生对象拼装推荐选项的旧辅助函数及旧默认导航声明删除。自动事件使用原事件调用者权限，不因新增推荐声明自动增加业务写权限；缺少目标权限时不能自动调用规则。后台事件的明确授权/绑定委托、其他消费场景目录、发布时检查与全部工作流接线继续纳入完整 Goal。

首页判断对象迁移合同：任意插件提供正式对象上下文后，首页判断可在原权限下读取对象；判断规则声明的非空对象类型决定实际适用范围，未限定对象类型的规则作为通用文本判断。不能把已限定类型的规则用于它未声明的对象。场景配置表达接受共同文本输入的规则，触发和批量执行逐对象校验适用性。提交判断及展示建议时重新核对原读取能力的身份、版本、对象内容和绑定；内容变化、对象消失、多个上下文提供方、停用或撤权时不保存过期结果、不回退其他提供方。只从当前项目/场景的最新历史逐对象核验，不再扫描 Feed 快照来决定哪些插件存在。原判断数据保持可读；旧记录缺少新来源身份时只保留历史，重新判断后显示建议。项目事件由 Host 共同 journal 记录，不通过 Feed 代写。Feed/WebView 上已经没有消费者的首页建议副本随本段清理；首页只通过共同 events/recommendations 获取建议。推荐动作身份及作者界面按前述合同迁移。

本段回归发现原 Functions 绑定存储丢弃共同服务固定的 provider_id，必须一并修复。绑定完整保存提供方，读出时原样给出，从不按能力名或当前安装的同名能力补出身份；没有提供方的绑定保留为已配置但不可用，统一 usages 给出原因，runScene 拒绝，用户明确重新绑定后恢复。验证存储重新打开、来源替换、缺失身份以及 Inbox 既有自动触发路径。

本段合同：首页事项改由插件注册的事件查询提供。查询接收明确时间窗口，返回原对象引用、稳定事件 ID、发生时间、日期摆放方式、标题/正文/事实及可选打开目标；Feed、Inbox、Work 各自拥有投影，Home 删除按插件拼接数据与分类的旧实现。提供方与事件 ID 共同确定页面身份，未知插件不能覆盖已有事件。停用、撤权、读取失败时撤回失效数据并说明原因，不继续使用旧快照冒充当前结果。

打开目标分为对象、分组或插件入口，均为声明式 UI 导航，不制造业务写入；Home 的注册查询在点击时重读原事件提供方并核对目标后才返回导航结果。Feed 自己的界面处理来源分组，Home 不保留来源 ID 专用分支。移除只打开对象的“问问怎么回事”，使用已接线的“说一句”；来源错误显示实际状态与“查看来源”，不能把查看配置称为已经重新授权。插件推荐动作通过 offers 合同执行，旧判断结果保留历史，按前述映射规则迁移。

首页重复读取必须合并排队，已完成的一次读取正常显示，变更期间请求的下一次刷新再读取最新事实，避免慢查询被定时器不断作废。一次共同能力发现中的依赖遍历复用同一次可见目录；该快照不跨发现请求，也不用于实际执行或副作用授权检查。定位单个能力时由原 Registry 按能力、版本、项目取对应描述，仅复制该描述；不得为一次权限或依赖检查复制整个目录。保留描述副本隔离、项目边界、撤权与重新注册检查。

场景适配同时验证对象覆盖：固定对象场景要求规则支持全部声明类型；首页使用开放对象场景，逐事项检查规则的 subject_kinds，且规则引用的每个推荐选项须与其对象范围相交。仅输入输出形状相同不足以证明可以处理不同对象。发现、绑定和执行使用共同检查，不在 Home 添加函数名单。

新启用绑定由公共场景服务固定实际提供方身份，保存到原 owner 的同一绑定记录；同 ID/版本的其他提供方不可静默接替。旧首页 Functions 绑定可确定来源为 system.functions，读取时补齐这一事实；判断历史不改写。首页初始页、定时刷新 Feed JSON 与系统规则详情均消费已授权的当前结果或绑定。

Session 接续执行：先将项目 Session 目录、内容读取和原生恢复注册为 Work 的共同能力，原 HTTP 只适配传输。Home 与后续消息投递从这个目录确认目标，不选择任意首条 Session。Registry、原生 Runtime adapter 和内容归一化继续归原 owner；其资源生命周期由系统 Host 持有，网页和 MCP 共用，不能由打开页面创建第二套实例。读取前后核对项目、原生身份和关联变更，跨项目不可读；保留原公开 Session DTO 与原生/本地历史差异、恢复失败语义。网页目录与工作区会话摘要消费 `sessions.directory.read` 的原事实；停用 Session 时拒绝列表、内容与恢复调用，首页不因缺少这个可选插件而整体失败，重新启用后原数据与授权引用保留。此项为实际普通消息投递与首页交互的必要接线，不代表“说一句”已完成；后续仍需持久消息请求、准确对象关联及不确定送达恢复。

普通消息执行合同：在原 Session 数据库和加密内容存储内保留消息请求、固定目标快照、调用者、幂等键、发送次数与 Runtime 回执。新增明确的 Runtime `message` 操作，只向已存在且明确选择的原生会话 `turn/start`，不创建新会话，不使用 Handoff 业务包。请求包括当前预期 Goal（允许明确 null）；关联变化后不自动换目标。调用者/项目/幂等键固定同一文本与上下文，重复提交不得重复发送；失败重试为独立显式动作。

在外部调用之前，原数据库以原子状态变更标记“送达结果未确认”；确认收到带原生 turn ID 的成功响应后才记 accepted 并写入原会话时间线。明确拒绝才能变为可重试失败；超时、连接中断、无有效回执、崩溃后遗留未确认请求均不得自动重发，也不以打开数据库推断前一进程死亡。记录写入确认与时间线事件同一事务；权限在外部等待前后复核，外部响应已发生的送达事实先落盘，撤权后不再返回受限内容。底层不可发送时明确不可用。验证真实交错下去重、相同键不同文本冲突、错误目标/跨项目、明确失败重试、未知送达重启、回执与时间线一致、权限在等待期间变化及既有数据升级；页面消费仍须另行完成并实际操作验证。

首页消息消费合同：插件以既有 input_type/output_type 声明统一“对象上下文”查询，输入为 subject_id，输出为对象身份、标题、正文快照、版本、关联 Goal 与明确 Session（如有）。Home 仅从共同能力目录发现与调用该合同，不新增插件名单；不兼容声明在注册时拒绝，多提供方不任意择一。首批 Feed、Inbox、Goal、Session 和来源由各自业务 owner 提供事实，未知插件以同一声明自动接入。

打开“说一句”时解析当前事项与最新可发送 Session。事项本身是 Session 时只允许该会话；已有 Goal 关联时只列同 Goal 会话；无关联时让用户明确选择项目内会话。单一关联会话可预选，无关联不得默认第一条。发送使用用户可见的正文快照与明确目标，实际 message 动作在执行时再核对目标关联；快照随后更新不会悄悄改写已提交文本。前端按事项保留原文、目标、幂等键和已返回的请求 ID，关闭/重新打开及刷新后可查询或以原请求恢复；结果未确认不显示普通“重试发送”，只允许检查状态/原请求，不换键重发。首页剩余动态动作与事件贡献仍按全量目标继续迁移。
