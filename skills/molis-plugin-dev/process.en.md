# Delivery: every plugin follows eight steps

First-party and Studio-generated plugins follow the same process. Who does each step can differ. An artifact may be unnecessary, but make the decision at its step.

1. Understand what the person sees, when, what clicking does and who needs the result. Ask one round only for decisions that change the feature.
2. Compare 2–3 distinct structures or behaviors, with each path, audience and tradeoff.
3. Specify consistent inputs, outputs, examples, parts and acceptance from empty data.
4. Choose actual catalog capabilities/components; ask for any inactive plugin before build.
5. Draw and connect operations after individual checks; mark unconnected work.
6. Check contract, types, package, scope, examples/tests and isolation; retain raw failure reasons.
7. Use main, empty, error and narrow paths in a browser before release.
8. Version the release, declare data compatibility and permissions; preserve upgrade data and offer keep/delete at uninstall.

Authors own their spec, catalog choices, implementation and validation. In Studio, the lead designer proposes and specifies; the Host reports normalization. Jev compares capabilities from the same provider with equal effect and relevance, keeping the designer's choice when unavailable; after specification Jev selects legal components and asks when uncertain. UI and code agents implement their parts. G1–G6 check contract, types, package, scope, tests and isolation; G7 walks acceptance in a browser. Studio manages release consent and lifecycle.

Text models preview each proposal with real components. When image generation is configured, request at most one illustration per proposal; do not retry a failed paid request. People can choose before the illustration arrives. A picture gives direction; the real component preview decides the result, including where a pictured component does not exist. If the model can read images, review the real screenshots after acceptance for empty states, density, alignment and copy. Missing model capabilities omit only their enhancement.

A passing unit test is not release acceptance. Click through changed UI in a browser; after installation use any platform capability for real once. Trial and acceptance use stand-ins, and preinstall network access is read-only. Report what actually ran, what you saw, and what remains unverified.
