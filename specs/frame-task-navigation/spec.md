# Goal Frame 与 Feed 任务入口重做

## 目标 / 等级
功能可用。用户明确纠正：单个 Goal 的 Frame 属于常驻外层 Tab；Goals 关系画布内部放大仍在母页。Frame 顶部需当前 Goal 信息。分屏需明确四方向及 VS Code 风格布局入口。Feed 取消孤立总设置，按来源完成添加任务，现有任务各自配置。

## 当前证据
frame-container applySurface/renderTabs 隐藏 tab-workspace/titlebar，以 container-tabs 另起导航；Goal item applyTabContent 强制 focus。Feed directory 齿轮打开所有来源/凭据/规则/迁移总抽屉；添加任务是列表底部 RSS 名称/URL 表单。

## 场景与决策
1. 目录打开 Goal 默认外层专属 Frame Tab；重复打开复用，切换恢复对应 Frame。Goal 的工作区保留为同一 Goal Tab 的内层视图；关系画布内部放大不创建 Tab。
2. Frame 顶部常驻真实标题、状态、预期结果，提供工作区与关系画布定位。画布内容/相机保留。主标签栏分屏时仍显示当前窗口标签，布局菜单提供窗口切换。
3. 布局图标打开菜单：左/右/上/下分屏、均分、切换窗口、关闭当前窗。四边拖动继续工作。
4. Feed 添加为独立模态流程：选择来源，再填该来源字段、清楚说明与创建动作；后退保留输入、失败留在表单、关闭返回入口。支持已有真实 RSS 目录/订阅地址、网页查询、YouTube、GitHub/Gmail连接。技术型授权配置仅按来源展开，不能捏造一键OAuth。
5. 目录每个来源有任务配置入口；对该任务展示真实状态、内容范围、同步/暂停及对应账号连接。捕捉规则归入任务配置，添加任务时可创建，见 `specs/archive/feed-capture-rules-task-config/spec.md`。列表去掉底部表单和预览空状态按钮。

## 边界与依赖
工作台标签/Frame/Goal导航、Feed UI及客户端，沿用真实API，不新增调度/账号协议、不运行外部拉取、不自动启动Runtime。保存现有未提交变更。

## 验收与验证
- Goal Frame Tab重用、标题/结果随Goal变化，最外层栏始终可见；关系画布内部放大仍留母Tab。
- 分屏菜单四方向可见可用、底部真实出现；窗口切换/刷新恢复、草稿移动保留无回归。
- Feed无孤立齿轮和列表底部表单；来源选择/后退/取消/提交失败/成功后任务可见可测试；任务配置只显示所选任务。
- 1440和390明暗页面截图、键盘和焦点检查；定向ops/Frame/Feed浏览器测试及构建。
