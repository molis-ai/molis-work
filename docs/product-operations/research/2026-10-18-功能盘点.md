## 〇、读这份盘点前先知道的五件事

1. **成熟度基线**：SSOT-MATRIX 对所有业务包的结论都是 `partial`（"真实实现，目标完整契约可能含未来能力"），不是"仅合同"。我的"已可用"指：有真实界面 + 动作 + 持久化 + 单测/e2e，README 没有声明主路径缺失。"部分可用"指：需要用户先配置（模型/账号）、或 README/spec 明确写了关键路径未接通、或用户本人验收未做。
2. **没有可安装的发布版**：唯一的公开正式版是 2026-09-11 的 GoalBoard v0.2.0（旧产品名），只有源码、没有安装包，MIT 许可，main 打不开它的数据。它含 Goals 的要求、本人验收、决定请求、约定变更需人决定和五家 Runtime 接入；不含按客户端逐项授权动作的现行 MCP 工具、菜单栏胶囊（桌面 App 没有公开安装包）、看板、"记一笔"、共用问题卡。macOS DMG 未经 Developer ID 签名与公证。下面所有"已可用"都是"main 上的开发版"。
3. **本地优先不等于离线模型**：所有 AI 功能经设置里配置的模型（Prologue Runtime），费用和数据去向由所选供应商决定；没配模型时多数 AI 功能如实显示不可用，不生成替身内容。
4. **规格书里写了、但 main 上没有的**：统一语音输入（`specs/unified-input-voice`，#631 草稿 PR 未合）、主动式助理完整版（`specs/proactive-assistant`）、工作简报插件（`specs/work-brief`）、风险插件、字体皮肤系统、团队共享/跨设备协作、第三方插件 `plugin install` 命令（`docs/system/THIRD-PARTY-PLUGINS.md` 只是方案）。这些我不列为已有功能，只在最后一节"边界/未核实"里点名。
5. **README 状态句的"自述"**：多数插件 README 同时写着"系统全量迁移和用户本人验收仍在进行"。这表示**没有人类验收记录**，不表示不能用。

## 一、项目插件（10 个，另有开发者参考插件 Text stats）

### 1. Goals（`goals`）——每个项目都带、不能移除

一句话：给每个项目建一棵"要得到什么、做到哪、凭什么算完成"的 Goal 树，AI Runtime 和人对着同一份账本记事；给长程工作（尤其是和 Codex/Claude Code 反复接力的开发）用。

**F-001 Goal 目录与 Goal 文档页** ｜ 能做：新建 Goal（只要标题，可附预期结果）；打开一条 Goal 看到文档式页面：标题、预期结果、当前状态说明、要求、时间线，事件在时间线里就地展开；目录/列表/依赖画布/看板是同一份数据的几种视图；「记一笔」分"随手备注 / 同步进展 / 问题与风险"三种用途。 ｜ 承载：`plugins/native/goals`；动作 `goals.create`、`goals.list`、`goals.document.read`、`goals.note`；页面 `plugins/native/goals/src/document-ui.ts`、`tree-ui.ts` ｜ 成熟度：SSOT `partial`；判断**已可用**（`tests/goals-document.e2e.test.ts`、`goals-actions.test.ts` 等 15 个必跑文件；README 自述画布工作区"交付等级 3，本地功能可用"，PRODUCT.md；v0.2.0 源码里有目标文档页、列表与依赖画布，没有看板和"记一笔"，这两项是 main 的） ｜ 可组合：被 Feed"升格为 Goal"调用（`goals.create`+`goals.inputs.confirm`）；被 Coding 的目标关联读取（`goals.contract.read` / `goals.state.read`）；被 Todo 的 `items.link` 关联；`goals.search.entries` 进 ⌘K；`goals.fragment.offers` 进情境浮条 ｜ 边界：新建 Goal 默认只存意图，不替人拆树、不派单。

**F-002 当前约定、要求与结构化报告** ｜ 能做：给 Goal 写"当前约定"（结果 + 一组要求）；要求可设为"必须由人验收"；AI 用类型化报告（`goals.events.configure` 定义局部类型 → `goals.events.report` 一次报多条事实）或无类型笔记（`goals.note`）、`goals.progress.record` 记进展；一批报告整批有效才保存，同幂等键重试不重复写。 ｜ 承载：`goals.agreement.set`、`goals.events.configure/report/list/read`、`goals.progress.record`、`goals.concerns.apply`；`docs/runtime.md` ｜ 成熟度：`partial`→**已可用**（`tests/goal-events-state.test.ts`、`goals-command-actions.test.ts`） ｜ 可组合：外部 Runtime 经 MCP 动作工具读写（`molis_work_v1_action_goals.*__v1`）；`skills/goal-advance` 是随安装发给 Runtime 的使用说明；进展可附成果引用（Coding 报告） ｜ 边界：Runtime 不能自填用户身份、不能替换已约定结果或降低要求，只能提议。

**F-003 显式收尾与"必须你点头"** ｜ 能做：`goals.closure.submit` 按当前约定、真实支持、适用阻塞核对后才写入完成；标了人工验收的要求没有有效的本人结论就不完成（原因码 `goals.event_closure.human_decision_required`；`human_approval_required` 是目标级策略 `human_approval` 的原因码，该策略默认关闭）；结论只对做出它时的约定和那一轮工作有效，约定一改要重新验收；完成/取消后可用 `goals.work.resume`（原因必填）继续。决定请求集中展示"问什么、为什么现在、依据或缺口、各选择的后果"（目标页里的决定表单和"{n} 项待你确认"按钮；独立的"决定中心"页 10 月上旬已删；各选择的"影响"是 Agent 在 `goals.decisions.request` 选项里自己写的一行文字，Work 不计算）。状态签是 正在推进 / 待继续 / 需要你决定 / 受阻 / 已完成 / 已取消，进度另起一行"完成要求 2/3 已满足"，收尾被拒时状态不变、页头显示原因。 ｜ 承载：`goals.closure.submit`、`goals.decisions.request/cite/record`、`goals.work.resume`；`specs/goal-closure-identity` ｜ 成熟度：`partial`→**已可用**（goal-closure-identity 已合 main；"本人验收"未做） ｜ 可组合：`goals.decisions.record` 只能由受保护的 Web/管理入口（user audience）写；外部 Agent 只能 `request` 和 `cite` ｜ 边界：只约束 Goal 完成，不是外部合并/发布门禁；结论不自动绑定代码 SHA/构建号；只标了"要你验收"的要求不会点亮菜单栏，要 Agent 发起验收请求（`requirement_acceptance`）才会。

**F-004 目标树、依赖与结构提案** ｜ 能做：Runtime 把拆分/依赖写成结构提案（`goals.tree.submit`），系统做整图检查（缺端点、自依赖、重复关系、父子/依赖循环），本人整组或逐条确认（`goals.tree.decide`，user 专用）后才进入树；依赖画布显示"提供者→消费者"，可拖动、缩放；父子归属和依赖分别表达。 ｜ 承载：`goals.tree.submit/read/check/decide`、`goals.relations.add/list/deactivate`、`modules/goals`；管理 MCP `goal_tree_decide`、CLI `goal-tree-*` ｜ 成熟度：`partial`→**已可用** ｜ 可组合：CLI `molis-work v1 goal-tree-propose|read|check|decide`；同一动作供页面/MCP 用；`goals.planning.graph.check` 复用同一图检查 ｜ 边界：已确认依赖是完成的硬门禁；代码变化只能触发重新核对，不会静默删依赖。

**F-005 规划方法库（可选，不强制）** ｜ 能做：按需读取并采用"方法包"：1 个元方法 + 7 个工作类型（分析决策/构建变更/内容沟通/设计规划/诊断修复/迁移重构/运营流程）+ 15 个专业领域（软件开发、产品 UX、增长、定价、安全隐私、可靠性发布、AI 数据产品、游戏设计……）+ 8 个行业（电商、教育、医疗、银行支付、投资理财、企业 SaaS、游戏、开发者工具）+ 6 个跨行业叠加层（支付资产、未成年人、UGC 信任安全、AI 人工复核、市场、敏感数据）；个人可保存自己的方法，优先级"项目 > 个人 > 内置"；可算"需求变更的影响子图"。 ｜ 承载：`modules/goals/methods/**`（共 37 个 Markdown）；`goals.planning.catalog/read/save/apply/impact/graph.check`、`goals.planning.personal.list/save`（Home 级） ｜ 成熟度：`partial`→**已可用**（`tests/goals-planning-actions.test.ts`；v0.2.0 源码已有 37 份方法与个人方法） ｜ 可组合：MCP 授权后外部 Runtime 先 `catalog` 再按需 `read` 正文；设置里"个人方法"跨项目生效 ｜ 边界：方法不自动成树；改树仍走提案+确认。

**F-006 项目长期说明（项目指导）** ｜ 能做：写"项目背景 / 工作方式 / 硬约束 / 质量标准 / 协作约定"等长期说明，带版本和变更原因；助理和各插件 Agent 每轮带上当前生效版本；外部 Runtime 只在经 MCP 读连接摘要（`context_resolve`）或从目标打开终端时拿到，Work 不往外部 Agent 的每一轮推送，读不读由外部 Agent 决定。 ｜ 承载：`goals.guidance.read/add/update`；设置页 `apps/workbench/src/project-settings-pages.ts` ｜ 成熟度：**已可用**（v0.2.0 源码已有项目说明与版本） ｜ 可组合：与"项目记忆"并列（说明是人写的规范，记忆是系统记的偏好）；记忆可"升级为项目说明"（`settings-memory.ts` 的"升级为项目说明"） ｜ 边界：只发送当前生效版本；说明里写"某类信息不发给境外模型"只是提示词，不路由、不过滤，发给哪家由模型设置决定，材料整份照发。

**F-007 Goal 的资料、交付物与成果引用** ｜ 能做：把文档、演示稿、问卷、数据表、Shelf 材料绑定为 Goal 资料（不复制、不移动原对象）；把成果库里的一个固定版本记为 Goal 的交付物或输入，或把某资料"当前内容固定成新一版再记入"；助理/Coding/工作流/MCP 添加的条目只算"待确认"，要本人认可。 ｜ 承载：`goals.inputs.bind/release/list/confirm/accept`、`goals.deliverables.add/remove/list/pin/candidates`、`goals.artifact_inputs.add/remove/list/pin`、`artifacts.goals.embeds` ｜ 成熟度：**已可用**（`tests/goal-artifact-inputs.test.ts`、`goals-input-confirm.test.ts`） ｜ 可组合：来源可以是 Feed 条目（`feed_item`，摘要为 sha256）、Pages/PPT/Form/Dataset 的成果版本；Goals 时间线可打开 Coding 固定报告；`artifacts.links` 反查"这一版被哪个 Goal 引用" ｜ 边界：Goals 不核对来源是否真实存在，只收严格形状的输入。

**F-008 回收站、归档与"当前 Goal"** ｜ 能做：移入回收站（需明确确认，可恢复，保留阻塞/历史/关系）、归档（须已完成）、设"当前 Goal"（只是焦点，不启动工作）。 ｜ 承载：`goals.trash.set/list`、`goals.archive.set`、`goals.active.set` ｜ 成熟度：**已可用**（v0.2.0 源码已有回收站、归档与当前 Goal） ｜ 可组合：CLI `active-goal`；macOS 菜单栏胶囊显示当前 Goal ｜ 边界：无。

### 2. Sessions（`sessions`，包名 `work`）

一句话：回到你和 Codex/Claude Code 等 Runtime 的会话，在 Goal 里开终端、跨 Runtime 交接；给同时用多个 AI 编码工具的开发者。

**F-010 会话目录与恢复** ｜ 能做：列出项目的 Session（来自 Runtime 原生或 Molis 兜底记录），读归一化内容，恢复指定原生会话（只加载，不等于发消息）。 ｜ 承载：`sessions.directory.read/list/content.read/resume/discover/create/archive`；`plugins/native/work` ｜ 成熟度：`partial`→**部分可用**（README 自述"创建、关联、交接与终端的旧业务入口仍在迁移"；原生 Session 只注册 Codex，其他 Runtime 登记 fallback，见产品介绍 2026-10-18） ｜ 可组合：`sessions.message.send/read/retry` 给助理/MCP 用；`sessions.search.entries` 进 ⌘K；`sessions.home.events` 进项目首页 ｜ 边界：Runtime adapter 声明"原生可读 / 兜底记录 / 不可读"，不支持时不猜内容。

**F-011 Goal 绑定终端（TUI）** ｜ 能做：从一条 Goal 打开 Codex、Claude Code、OpenCode、Pi Agent、Grok Build 或自定义命令的终端；终端始终属于这条 Goal，之后点别的 Goal 不会改绑，也不会自动发送；macOS 上也可在 Capsule 里看当前 Goal。 ｜ 承载：`apps/desktop/src/launch.ts`（5 个内置启动配方 + 自定义）、`plugins/native/work/src/terminal/*`、`/pty` WebSocket ｜ 成熟度：**已可用**（`tests/desktop-tui.test.ts`；README 称桌面窗口真实验收过，无公证发布） ｜ 可组合：打开 Goal 时 Molis 会把已脱敏、带"不可信数据边界"的上下文填进终端但不自动发送（PRODUCT.md "Sources, Feed and Inbox"）；Feed"开始处理"同理 ｜ 边界：打开页面不启动 Runtime、不绑 Session。

**F-012 跨 Runtime 交接（Handoff）** ｜ 能做：把当前 Goal 与必要上下文交给另一个 Runtime，创建新的目标 Session；逐次确认；交接包保持私人内容。 ｜ 承载：`sessions.handoffs.prepare/send/update/cancel`；`tests/session-handoff.test.ts` ｜ 成熟度：**部分可用**（"没有当前 Goal 必须先选 Goal"；跨 Runtime 能力受 adapter 限制） ｜ 可组合：读取授权约定+当前状态，失败不建交接包 ｜ 边界：不自动发布 Artifact/Team 数据。

**F-013 会话消息发送与送达状态** ｜ 能做：对指定 Session 发普通消息（带预期当前 Goal、幂等键），状态 `accepted/failed/uncertain/pending`，失败可显式 retry，未确认的不会自动重发。 ｜ 承载：`sessions.message.send/read/retry` ｜ 成熟度：**部分可用**（README 自述"首页'说一句'还需消费这些能力，后端接通不代表首页已完成"） ｜ 可组合：项目首页"对着这件事说一句"（`home.talk.prepare`） ｜ 边界：只有已接受的真实 turn 回执能收敛原幂等请求。

### 3. Inbox（`inbox`）

一句话：只放"需要你介入的事"的收件箱，来自 Feed 规则、来源故障、插件提醒；给想把信息流压成待办决定的人。

**F-015 待处理事项 / 完成 / 忽略** ｜ 能做：目录+详情读 Attention 事项（原因、关联对象、状态、下一步；来源只标"规则「名字」筛选进入"或"需要人工复核"，不写判断理由），按版本完成或忽略；完成/忽略不删除原 Feed 条目、Goal 或来源。 ｜ 承载：`inbox.list`、`inbox.entry.status`、`inbox.home.events`；`plugins/native/inbox` ｜ 成熟度：**已可用**（`tests/inbox-plugin.test.ts`、`inbox-native-plugin.test.ts`） ｜ 可组合：Feed 规则/Schedule 提醒/来源故障写入；"转为待办"（Todo）；首页事件 ｜ 边界：事项过期版本会拒绝覆盖。

一句话：把本地 Obsidian / LLM Wiki / Markdown 文件夹导成带版本的知识库，带来源地检索和问答；给手上有一堆本地笔记的人。

**F-041 导入本地知识（预览 → 确认）** ｜ 能做：选本地目录或浏览器上传，先预览固定快照，再明确提交；保留路径、原始字节、Markdown、frontmatter（title/tags/aliases）、每一次变更版本；相同预览重试返回原回执；源文件不被修改。 ｜ 承载：`plugins/native/cognia`；`cognia.import.preview/import.directory_preview/import.commit/import.cancel/directory.scan`；`specs/archive/cognia-plugin/compatibility.md` ｜ 成熟度：`partial`→**已可用**（10 个 cognia 测试文件） ｜ 可组合：onboarding"从已有资料开始项目"可导入；`cognia.files.entries` 进右栏"文件"；固定材料版本供其他插件引用 ｜ 边界：每批 ≤1000 条目 / 32 MB；文本≤2 MB、附件≤8 MB；图片/PDF/音视频只留附件不做 OCR；隐藏目录与符号链接跳过。

**F-042 检索、阅读与手工资料** ｜ 能做：全文搜索，按领域和来源过滤；站内链接按来源解析；手工新建/修改资料（每次产生新版本）；下载原始文件；领域增删改（删领域资料转"未分类"）。 ｜ 承载：`cognia.material.search/get/create/update/delete/download`、`cognia.domain.*`、`cognia.source.*`、`cognia.workspace.get` ｜ 成熟度：**已可用** ｜ 可组合：`cognia.search.entries` 进 ⌘K；MCP 默认关闭的只读检索（`cognia:read` 权限）；引用的版本在重新导入后仍可读 ｜ 边界：外部知识库不实时双向同步。

**F-043 AI 综合与知识问答（带固定版本引用）** ｜ 能做：选 1–5 份资料综合成草稿，或在选定领域提问（最多取 5 份资料，上下文≤100,000 字符，超限拒绝而非截断）；输出必须含合法的固定来源引用；草稿重启后仍在，点"保存到知识库"才入库。 ｜ 承载：`cognia.knowledge.synthesize/query`、`cognia.draft.get/save/archive`、`cognia-prologue.ts` ｜ 成熟度：部分可用（需配模型；无证据时不调模型） ｜ 可组合：采纳关系保留"最初采用过哪份材料的哪一版"（产品介绍 O04 的设想基础，复核清单**未实现**） ｜ 边界：生成期间资料被改，证据不变。

## 五、跨插件串联机制

### 5.1 动作目录：页面、助理、工作流、外部 MCP 共用一份

- **一次登记，四处调用**：插件在 Manifest `actions` 里声明动作（`capability_id` + `version` + 输入输出 schema + `audiences` + `permissions` + `scope` + `effect`），宿主登记进 `ActionService`。页面（HTTP 路由只是把请求转成同名动作）、内置助理/Agent（`find-capabilities` → `read-capability`/`change-capability`）、工作流程（动作步骤、内容站点）、外部 MCP 客户端（工具名 `molis_work_v1_action_<id>__v<版本>`）调用的是同一个处理器。依据：`specs/action-architecture/spec.md` §3；`docs/system/GLOSSARY.md` §2.1；`tooling/gates/actions/actions.tsv`（567 行）。
- **授权在调用方一侧**：声明不授权；实际授权来自安装授权 + 「设置 › 对外接入」里对每个客户端（外部 MCP 客户端、内置 Agent 各算一个）逐项授予；撤销后下一次调用立即被拒；被取消/撤权/停用的调用不再写任何业务记录，处理器开始前就被拒的在调用记录里只留一行"未执行"诊断（`AGENTS.md` 硬约束）。
- **版本即合同**：同一版本下动作形状变了，快照门禁会点出来；已固定引用的工作流/Skill/MCP 工具名要升 `version`。真实例子：`images.connections.list` v1→v2、`goals.tree.check` v2、`coding.runs.control` v6 都带来了外部工具名变化。
- **并发动作**：等模型/外部服务的动作声明 `scheduling: "concurrent"`（567 个里有 128 个），返回后再 `beforeEffect()` 按读取时版本提交，不占项目串行队列。
- **外部 MCP 服务的工具也进同一目录**（F-136），所以"助理 / 工作流 / MCP"对它们是同一待遇。

### 5.2 成果（Artifact）vs 过程项（Process item）

- **成果**：人要留存、引用的**固定版本**，类型在 Manifest `artifacts.produces` 声明（带显示名与预览动作），进入成果库、侧栏文件、搜索。内置类型：`文档`（Pages）、`数据表`、`问卷`、`演示稿`、`角色`（`character.definition.v1`）、`Coding 执行报告`（`coding.report.v1`）、`捕获的消息`（Feed）、`导入的文件`（`io.molis.work.document`）。每种成果类型可带 `pin`（当场固定）、`compare`（对比是否还匹配）、`continue`（"从这一版继续"）、`referrers`（被谁引用）动作。
- **过程项**：交给别的插件的数据，是生产方自己的，不进成果库、不进搜索、不进侧栏文件。内置类型：`file.snapshot`/`file.text-selection`/`files.collection`（Files）、`diff.changeset.v1`/`git.result`（Git）、`coding.plan/goal-context/changeset/diagram.v1`（Coding）、`shelf.text-material.v1`（Shelf）。通过 Manifest 的 `ports.inputs/outputs` 连线，`default_source` 给默认生产者；固定输入失效时**不**自动改读最新版本。
- 依赖自动补齐：有必需输入端口的插件加入项目时，市场会把能产出该类型的内置插件作为"伙伴"一起带上（`plugin-catalog.ts` 的 `requiredCompanions`）。

### 5.3 情境（context）与落点（landing）

- 页面把"手上有什么"（选区、对象、焦点）报给情境中枢（`molis:surface-*`、`/api/contextual/*`）；Host 从动作池里按"可用范围 + 规则 + Jev 判断"排出最多 3 个主动作与"更多"；**落点**由左边拥有对象的页面主动报告（光标/选区/末尾 + 版本），只有"不在左边"的东西（右栏、助理回复里选中的一段）才带落点，选中后先在落点处预览，确认后经 Host `attach` 写入，页面自己不能写。分屏里的 Pages 是它自己的文档，落点以带令牌的消息上送，令牌只有那个 frame 能用一次（S-30）。
- 依据：`apps/workbench/src/scripts/client/context-landing.ts` 文件头注释；`specs/context-program`。

### 5.4 Goals 与其他插件的关系

- Goals 只拥有 Goal 的事实（约定、要求、事件、关系、决定、项目说明），其他插件**不复制**：Feed 升格经 `goals.create`+`goals.inputs.confirm`；Coding 经自己在 `plugins/native/coding/src/goals-actions.ts` 里声明的 Goals 动作（`goals.contract.read`/`state.read`/`progress.record`/`progress.receipt` 等）读写；Todo 经 `items.link` 关联 Goal；Pages/PPT/Form/Dataset 经成果固定后记为 Goal 交付物（`goals.deliverables.*`、`goals.artifact_inputs.*`）；Shelf/Pages 等可作为 Goal 资料（`goals.inputs.bind`，不复制原对象）；项目首页和 Capsule 读 Goals 的当前状态。
- Goals 每个项目都带、不能移除；但 Feed 升格依赖的 Goals 动作若在某处不可用（例如授权没给全），升格入口会跟着消失，而不是报错后空转。

### 5.5 搜索

- 每个插件把"可搜对象"用 `*.search.entries`（`molis.search.entries.window.v1`/`page.v1` 输入输出类型）暴露，系统搜索按类型发现来源、建可重建的本地索引（`{home}/search/search.db`），查询时按调用者权限过滤，打开前先问所有者核对。⌘K、助理、工作流、MCP 同用 `search.query`。

### 5.6 记忆

- 平台记忆只记"用户想让系统记住什么"，不复制业务事实；`memory.recall` 在助理、Agent、界面推荐、MCP（需授权）按情境带出；写入走确定性写入门；"你说过"需整条消息原文。炼金术士另有自己的 Taste/研究方法记忆，不混用。

### 5.7 真实存在的跨插件链路（均有 Manifest/代码依据）

1. **Feed → Goals**：`feed.items.promote` 在 `item-actions.ts:44` 声明 `required_actions: GOALS_ACTIONS_FOR_PROMOTION`（`goals.directory.read`、`goals.create`、`goals.inputs.confirm`），升格后消息作为 Goal 的输入（`sha256:` 摘要）；用户升格=已确认，助理/Agent/工作流升格=待确认，等本人在 Goals 里"认可这条输入"（`goals.inputs.accept`）。
2. **Feed → Inbox → 判断 → Pages**：Feed 捕捉规则（`feed.capture@1`，判断规则来自 Functions 目录；规则默认只给建议，`admission` 设为 `inbox` 才自动入箱）命中→写 Attention→`inbox.next@1` 再判断下一步→用户选 1–20 条 Inbox 材料调 `inbox.pages.generate`，`plugins/native/inbox/src/pages.ts` 调 Pages 的 `pages.generate`（带 `entry_id/revision/content_digest` 的材料快照，`required_actions` 固定了 Pages 版本），得到的文稿保留快照与来源。
3. **Inbox / 灵光 → Todo**：Workbench 的"转为待办"（`data-make-todo`）调 `todo.items.create`，请求号 `inbox:<id>`、`lingguang:<id>`，同条再转找到原待办；来源只作来源保留，不改原条目状态。
4. **灵光 → Jelly 笔记**：`lingguang.placement.copy/move` 通过放置服务调 Jelly 的内容站点 `jelly.content.receive`，笔记记着来自哪条灵光；同一次交接只建一篇。
5. **工作流程：Feed → Inbox → Pages（或任意站）**：站点 = 实现了 `<站>.content.list/read/receive/create` 的插件：能收的有 Feed、Inbox、Pages、灵光、Jelly、Form、Dataset、PPT（`tooling/gates/actions/actions.tsv` 里的 `*.content.receive`），成果库只能当起点；衔接选 模板转换 / AI / 手动 / 判断规则；也可串进 **`workflow` 受众的命令类动作**（约 237 条，查询不算；`workflows.steps.actions`，如 `todo.items.create`、`dataset.import`、外部 MCP 工具）并做字段映射。交接幂等键 `workflow:<实例>:<步>`。
6. **Shelf ↔ Coding**：Shelf 产 `shelf.text-material.v1`（过程项，`ports.outputs: material`），Coding `ports.inputs: materials` 以它为 `default_source`（`coding/src/manifest.ts:89`）；反过来 Shelf 的 `ports.inputs: coding-report/coding-changeset`（默认源 Coding 的 `report`/`changeset`）→"接收项目成果"复制成个人副本，再保存为项目材料给下一轮用。
7. **Files → Diff / Text stats / Coding**：Files 的输出端口 `before`/`after`/`selection` 产 `file.snapshot`/`file.text-selection` 过程项，Diff 和 Text stats 的输入端口消费 `file.snapshot`，Coding 的 `before`/`after`/`selection` 端口默认连 Files。Text stats 只因这条连线才有意义。
8. **Coding ↔ Git ↔ Diff**：Coding 产 `coding.changeset.v1`，Git 的 `GIT_RUN_CHANGESET_INPUT_PORT` 与 Diff 的输入都消费它；Git 产 `diff.changeset.v1`+`git.result`，Coding 的 `git-changeset`/`git-result` 端口默认连 Git；Host 把 Prologue 已核对的真实操作回执通知 Git（`git-operation-notifications.ts`）并驱动 Files/Git 刷新。
9. **Pages / PPT / Form / Dataset → 成果库 → Goals / 其他插件输入**：各自 `*.promote` 固定版本（中断可恢复），成果页显示"继续"（`*.artifacts.continue`）、"被谁引用"（`artifacts.links`）；`goals.deliverables.pin`/`goals.artifact_inputs.pin` 把版本记为交付物/输入；`artifacts.plugin_inputs.bind` 让某插件端口固定读这一版。
10. **Pages → PPT**：`ppt.outline_pages` 以调用者自己的权限列出可用 Pages 文档，`ppt.outline`/`outline_ai` 按文档生成幻灯片大纲（`ppt.outline` 按 Markdown 规则分页，不调模型；`ppt.outline_ai` 调模型，最多 12 页）；Pages 未启用时返回空列表与原因。
11. **Characters → Coding / 助理**：`character.definition.v1`（Characters 发布的成果）被 Coding Manifest 声明消费（`artifacts.consumes`），起跑按精确版本选用；Characters 从 Codex/Claude Code/Cursor/OpenCode/Grok 的目录导入规则与 Skill。
12. **Coding ↔ Goals**：Coding Manifest `capabilities.consumes` 按 capability id 列 Goals 的动作（Coding 自己在 `plugins/native/coding/src/goals-actions.ts` 里声明 `goals.list`、`goals.contract.read`、`goals.state.read`、`goals.progress.record`、`goals.progress.receipt`，另有 `goals.subject.read`、`goals.search.entries`），不再引用共享的 `goalPluginActions` 表；会话关联 Goal→固定 `coding.goal-context.v1`；报告可回写进展（`goals.progress.record`，"进展附带的成果来源是提交者的引用，不表示系统已验证"）；Goals 时间线可打开原固定报告并回到原会话。
13. **Schedule → Inbox / 助理**：`reminders.add` 到点把提醒写进 Inbox（由 Scheduler wakeup 触发，Feed 装配时绑定同一判断触发器）；对话任务到点由项目 Agent 跑只读一轮（只能读项目绑定的本机工作目录，读不到 Molis 数据）。
14. **服务连接 → Feed / 图片 / 炼金术士 / 文档导入**：同一个 GitHub 账号连接既给 Feed 拉通知，也给炼金术士 GitHub 脉搏（`alchemist.pulse.github.configure`），连接页通过 `feed.connection.usages`/`images.connection.usages`/`models.connection.usages` 等反查"谁在用"。

16. **Form → Dataset**：Forms 界面有"存成数据表"按钮（`ui.ts` 的 `data-form-to-dataset`），把现有答卷做成一张数据表，之后的新答卷不会自动进那张表；也可以 `form.results.csv` 产出 UTF-8 CSV 后用 `dataset.import` 替换当前列与行。缺口是"新答卷不自动同步进已存的表"。
