## 1 放在哪里、归谁

- **一个新的平台服务包** `horizontal/observation`（名字待合同 PR 定），宿主只装配（用户 2026-11-01 定新的平台服务不进宿主）。它是 Home 级服务：一个 Home 一份记录，按项目、空间分区，跨项目查询沿用 S-74「只给本人、由宿主重算」。
- **自己的独立库**，在 Home 库登记里声明（盘点 §8 第 3 条：往已有基线加表会被存量库拒绝）。表只由这个包读写，别的包调它导出的函数或动作。
- **只拥有观察记录本身**：发生了什么、关联、来源类别、覆盖与缺口、保留与占用。业务内容、对象身份、正式状态仍归原插件和服务；采集层不建第二份可编辑的业务事实。
- **内容证据**：主人已经有固定版本的（成果库版本、记忆版本、Todo 前后值、对象关系修订、工作流交接正文、Goals 事件载荷），记录里只放引用。主人留不住历史的（Pages 正文、默认提示词与 Skill 正文、检索结果、模型实际收到的消息、界面上呈现的候选），由谁保留是本批要统筹拍板的第一件事，见 §9 D1。推荐由采集层存只读、按内容寻址的证据快照，随记录保留期一起删除。
- **现有调用记录不承担采集**。它按安全规则不存输入输出、被拒调用只留最小诊断，继续做诊断用；采集层从同一个调用挂钩取事实，但另存，并遵守同样的拒绝与取消边界（需求 §3 末段）。

## 2 一条记录回答什么

不定字段名，只定每条记录必须答得出的问题。合同 PR 把它们落成 schema。

| 问题 | 怎样答 | 从哪来 |
| --- | --- | --- |
| 谁的什么事实 | 事实主人（插件、服务、界面外壳）与事实种类 | 写入方的可信身份，不从输入读 |
| 谁做的 | actor 与调用方（本人、助理、插件 AI、工作流、定时、MCP 客户端、成员） | 调用上下文 |
| 在哪 | 项目、空间、安装、入口（工作台、桌面、助理、MCP、CLI、后台） | 调用上下文 |
| 对什么 | 对象引用和当时的版本 | 写入方给出，采集层核对主人能否解析 |
| 什么时候 | 真实发生时间、系统收到时间；补读与迟到的可以辨认 | 写入方给发生时间，采集层盖收到时间 |
| 属于哪项工作 | 工作编号、上一环、运行、调用编号；重试和新工作分开；不知道就留「未关联」 | 调用上下文的 call_id、`runtime_session_id`、运行编号；推断的关联另记来源 |
| 哪个阶段、结果怎样 | 阶段，以及结果：成功、失败、拒绝、取消、等待、不行动、无响应、接管、未知 | 写入方 |
| 来源类别 | 真实发生、首次读取已有、断线补读、用户导入、模拟（试用、回放、演示、系统检查） | 调用上下文与入口；见 §3 |
| 当时的条件 | 平台、插件、Skill、提示词、模型、配置的版本快照引用 | 运行冻结的版本、安装记录 |
| 内容证据 | 引用主人的版本或证据快照；缺的写明是未取得、截断、脱敏、到期清除还是无权访问 | 见 §1 |
| 能用在哪 | 采集、主动使用、评测、导出、上传各自是否允许 | 用户设置；见 §6 |

## 3 来源类别：真实、模拟、导入与新变化

第 28 批要按这里分。

| 类别 | 什么时候用 | 不能算成 |
| --- | --- | --- |
| 真实发生 | 用户、助理、插件、工作流、定时在真实项目里做的事 | — |
| 首次读取已有 | 首次接入项目、插件、资料来源时读到的现有内容、状态与关系 | 用户刚创建或编辑；本期成果 |
| 断线补读 | 记录中断或连接断开后补回的历史变化，带原发生时间 | 这次的新变化 |
| 用户导入 | 用户主动导入资料。导入本身是真实操作；原内容形成时间与导入时间分开记，之后的修改照常是真实发生 | 资料里原有的历史成果都算本期完成 |
| 模拟·试用 | 观察试用（§5）与 Skill 试用 | 实际执行、用户认可 |
| 模拟·回放 | 评测回放、隔离重评 | 当时发生的事；回放不产生真实副作用 |
| 模拟·演示 | `data_class = regenerable_demo` 项目里的一切 | 真实效果指标 |
| 模拟·系统检查 | 平台自检、健康检查、测试夹具 | 用户行为 |

模拟类默认不进用户成果、日周报、习惯推断与真实效果口径（OCL-13）。用户把试用候选采用为真实工作时，只从实际采用和生效处建立关联，不把试用期间的结果补成已发生。

Onboarding 采用现在以本人身份写入（盘点 §6）。接入时由入口给出「首次读取已有」或「用户导入」，不靠事后看成果的 `origin` 猜。

## 5 主线、智能呈现与观察试用：后续接入点与判定方法

这三类现在都没有代码，接入随第 36、52、63 批与主动助理落地。本批先把**独立预期**与**判定方法**定下来，后面接入时照着验，不由实现者看着自己的输出决定对不对。案例编号见 [eval-cases.md](eval-cases.md)。

### 5.1 主线（MLN-18）

- **记什么**：放进、移动、切换、完成，各记操作者、事项引用和操作；不记对象正文。
- **独立预期**：用一段脚本化的操作序列（谁、哪件事项、什么操作、先后），在跑之前写成期望序列。
- **判定**：确定性断言。记录序列与期望序列逐条相同（顺序、actor、事项引用、操作）；在对象正文里埋一个唯一字符串，断言任何记录里都找不到它。案例 EC-11。

### 5.2 智能呈现（IUI-23、OCL-07）

- **记什么**：助理组合的输入（引用）、确定组合给出的候选、助理的选择与先后、一句理由、用户纠正（换形态、移走、固定，带调用方与位置）；实际呈现与后续阶段（呈现、选中、定位请求、加载、目标可见、精确高亮、退化、失败、返回、提交）。不记对象正文。
- **独立预期**：候选集由确定组合给出，可重复，事先算好；「应该选哪几样」由人在看到助理输出之前按案例标好；纠正的期望是「同一位置下次先照纠正来」。
- **判定**：结构用确定性断言（选择是候选的子集，超出候选的被丢弃且有记录；纠正带调用方与位置；没有正文）。选得好不好由独立评审或评测器按事先标好的集合判，保留评测方法与版本；点击不算采用，进入可见区域不算已读。案例 EC-12、EC-13。

### 5.3 观察试用（PWA-142～143）

试用的记录和正式执行**分开记**：

| 分开记的 | 内容 | 不能变成 |
| --- | --- | --- |
| 试用本身 | 来源、工作范围、时段、预算；开始、结束 | — |
| 候选与不行动样本 | 每次判断：会暂不行动、准备、继续、请求决定，或无法判断；依据；当时的来源版本 | 接单、派出执行、改业务内容、逐条通知 |
| 当时的做法 | 生效的 Skill 与配置的版本 | — |
| 用量 | 每次判断实际消耗的模型用量 | 「零成本」 |
| 停止 | 停在哪一刻、为什么：用户停用、撤权、到了结束条件、预算用完 | — |
| 正式启用之后 | 新的真实判断只把试用当参考引用 | 把试用期间的候选整批补执行或补通知 |

- **独立预期**：每个试用案例事先由人对每条来源标「应处理／不应处理／无法判断」，作为评判误判、漏判的依据；不能只在助理找出来的事项里算发现率（主动助理 §14.3）。
- **判定**：确定性断言试用期间没有任何真实执行与通知记录、用量逐次可查、停止后不再有新判断；判断对不对按事先标注比较，误判、漏判、无法判断分开计。案例 EC-14、EC-15。

## 6 用途、告知与权限

- 采集、主动使用、评测、导出、上传分开表达，各自是否允许由用户设置，默认值随定样定（原型里：本机回看始终可用；主动使用、评测默认开；导出默认关；上传这一版没有）。同一条记录对一个用途可用，不自动授权别的用途；关掉某个用途后，相关消费者不能借旧副本继续用（OCL-11）。
- 读取一律经公开动作，按调用方权限与用途检查；身份、项目、安装从调用上下文来。被拒、取消、撤权的调用沿用平台最小诊断，不借采集之名多写（需求 §3、S-35）。
- 停用主动助理、场景 Skill 或评测，不停平台采集；停用采集（暂停记录）时，消费者看得到「记录截至何时」。
- 告知：用户能在设置「工作记录」里看到记了什么、不记什么、从何时开始完整、早期历史能取到哪里；首次接入时看到正在读现有资料的进度，且读到的算「原本就有」。具体样子见定样（§8）。

## 7 保留、清理、占用与缺口

照需求 §2.6 与 OCL-12（用户 2026-10-27 已定），这里只补落地细节：

- **保留**：默认一直保留。用户可选自动清理期限或「不自动清理，我自己清」。期限短于已开启的报告周期、跨周期比较或评测所需范围时，指出会失去哪些依据，不悄悄延长。
- **清理**：只清工作记录，可按时间、项目、记录种类选范围；清之前给出大小和影响。原文、插件版本、已存简报按各自规则，不连带删除。评测样本有自己的用途与期限，不随清理删除，到期前问用户。清掉的时间段在覆盖登记里标「到期清除」，不用当前内容顶替，也不从旧副本重新纳入。
- **占用**：显示工作记录的实际占用（记录库加证据快照），默认没有上限；用户可设、可改提醒线。到线只提醒、不删除；到期清理与提醒线分开呈现。
- **缺口**：覆盖登记按入口、插件、工作阶段、版本给出九种状态：完整、未接入、暂不可用、丢失、截断、已脱敏、到期清除、不适用、按规则不记。写入失败（含磁盘满）记成「丢失」的时间段和条数，已发生的业务效果照常生效、照常显示。「按规则不记」（被拒调用的内容、未发送的草稿）和「本应记却缺失」分开。
