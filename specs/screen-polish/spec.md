## 一、总的判断

界面的零件是对的，拖沓来自三件事，后面每一屏的问题几乎都能归到这三条里：

1. **位置线索不稳。** 「我在哪」在托盘、页签、设置小片之间跳：在首页时当前插件是托盘里带名字的纸片，进了 Coding 它变成页签组，进了设置它变成被截成「设…」的小片。＋ 悬在半空，右边排着八个没有名字的图标。
2. **焦点不跟着工作走。** 输入框的收件人、只读提示行、收起的回复卡都停在上一个地方：人已经在设置页了，底下还是 Coding 的提示和上一轮的回复。每换一处都要自己收拾一次，这是「拖沓」最直接的来源。
3. **元信息排在内容前面。** 对话框先开一栏 260px 的状态详情，每条回复前先说「这一轮没用技能」，Coding 的回答前先排两张准备卡，设置页先读一段说明。人要的那句话总在第二屏。

另外两条是全局性的：动效语法写进了 `DESIGN.md`，产品代码里基本没用上；色彩的含义有几处漏了（琥珀色用在普通提示上，发送键没有颜色）。

### 2.2 信息重点

- **三问的顺序是版面的顺序。** 我在哪（顶部栏、线头）→ 现在怎样（工作面的第一行）→ 接下来做什么（唯一的墨蓝）。一屏里这三样各只出现一次。
- **名字 → 状态 → 事实，截断时反着来。** 先截事实，再把状态词收成一个点，最后才截名字。现在 Coding 目录把会话名截成「format…」六个字，状态标签和时间却完整，是反的。
- **四个字以内的名字不截。** 「设置」「助理」「Coding」这类词被截掉比多占 20px 更糟。
- **一页最多四个字号。** `DESIGN.md` 规定页面标题 24/600；设置页实看标题约 30px、引言约 15px（按截图量的，开工时用计算样式再核一次）。
- **内容在前，来历在后。** 回复、回答、设置项先出；用了什么技能、环境怎么准备的、能力编号是什么，收在一行里，要看再展开。

### 2.3 认知心理学

| 原理 | 说的是什么 | 落到这里 |
| --- | --- | --- |
| 希克定律 | 选项越多，决定越慢 | 顶部右侧 8 个图标收成 1 个开关加菜单；对话框头 5 个图标键收成 3 个；Coding 输入框底排 6 个控件收成 4 个；记忆页 6 个筛选收成搜索加 2 个 |
| 费茨定律 | 目标越大越近，越快点到 | ＋ 紧跟最后一个页签；发送键 32px 且位置永不移动；对话框控件补到 28px 以上（BL-127）；回合结束后的下一步按钮放在阅读终点 |
| 接近与共同区域 | 靠在一起、围在一起的算一组 | 托盘只装插件，页签只装打开的东西，右端只管侧边和项目；对话框贴着输入框、同一条中轴，读起来是一个东西 |
| 组块 | 一次记得住四五块 | 助理设置里 22 个平铺的勾选框收成「N 处不提醒」一行，展开再看；设置类目 18 项分 5 组保持不变 |
| 渐进展示 | 先给够用的，其余按需 | 对话框详情栏默认关；准备卡就绪后收成一行；结果与审查里的工程事实收进「运行详情」 |
| 认出比回忆省力 | 看得见名字比记图标容易 | 没有名字的图标键：宽度够时带名字，不够时当前项带名字，其余 90ms 出提示 |
| 多尔蒂阈值 | 400ms 内有回应才觉得连贯 | 发出后 100ms 内出现自己的那句和「正在想」；切页签、切设置页 100ms 内换内容，慢的部分用骨架占位 |
| 序列位置 | 两端最容易记住 | 事项线左端是做过的，中间是现在，右端是接下来；最急的一条挨着输入框 |
| 蔡格尼克效应、目标渐近 | 没做完的事挂在心上，越接近完成越想做完 | 在办的胶囊写真实步骤（「第 2 步，共 5 步」），不用空转的圈 |
| 峰终定律 | 记住的是高点和结尾 | Coding 一轮的结尾是一句「改了什么」加一个主操作，不是用量条和模型名 |
| 雅各布定律 | 人带着别处的习惯来 | 页签像浏览器，设置像系统设置和 Codex 的文档式设置，⌘, 开设置 |
| 变化盲视 | 没有过渡的变化容易漏看 | 一个变化一个动效，对象换位置时带着走（`molisCraft.carry`） |

### 2.4 行为心理学

| 原理 | 落到这里 |
| --- | --- |
| 默认值的力量 | 收件人默认跟着当前的工作对象；去处、模式都有默认，一步可改 |
| 即时反馈 | 按下去 .97 回弹；发出的话立刻落在对话里；勾掉的事当场打勾 |
| 少一步就多做一次 | 事项胶囊上直接出主人声明的动作（如待办的勾掉）；目标是高频路径各少两步以上，见第八节 |
| 损失厌恶 | 能撤销的破坏性动作不弹确认，做完给「撤销」；没发出的草稿按收件人各存一份，切走不丢 |
| 间歇提醒会被忽略 | 该你了只提醒一次（`molisCraft.ask` 的一圈琥珀），不循环闪 |
| 位置恒常成习惯 | 输入框的位置和宽度不随上下文变；发送键和停止键是同一个位置 |

### 2.5 贝塞尔曲线与时钟

`DESIGN.md` 说全产品只有两条曲线加一条显现曲线。规则本身不用改，要做的是讲清每条曲线管什么，并把代码收进来。

| 曲线 | 形状 | 管什么 | 不许用在 |
| --- | --- | --- | --- |
| `--ease-quint` `cubic-bezier(.22,1,.36,1)` | 起步快，约前三分之一时间走完八成路程，尾巴长而软 | 一切有位移的进场、换位、面板展开；配 `--dur-move` 250ms、`--dur-arrive` 420ms | — |
| `--ease-spring` `cubic-bezier(.2,1.35,.4,1)` | 第二控制点 1.35，会冲过终点再回来 | 32px 以内、回应手指的小东西：按压回弹、打勾、计数跳一下；配 `--dur-press` 130ms | 任何面板、对话框、整行。大面积冲过头一两个像素看起来是抖，不是弹 |
| `--ease-reveal` `cubic-bezier(.215,.61,.355,1)` | 温和的三次缓出 | 新写出的文字、提示、悬停出现的小键；配 `--dur-reveal` 90ms | 位移 |

配套的四条约束：

1. **从哪里来就从哪里长出来。** 对话框从输入框长出（`transform-origin` 在底边中点，缩放 .98→1 加 8px 上移）；菜单从触发它的控件长出；结果面板从「结果与审查」键长出。
2. **走得短。** 上浮 8px，翻页 16px，超过 400px 宽的东西位移不超过 16px。
3. **离场比进场快。** 离场只淡出，用 `--dur-hover` 130ms，不做位移。
4. **可以打断。** 连点两次不排队，后一次从当前位置接着走。

现状（读代码得到）：

- `molisCraft.carry` 产品里 0 处使用，`molisCraft.turn` 0 处，`molisCraft.ask` 0 处（`DESIGN.md` 写明等你的事件要用它提醒一次），`land` 和 `celebrate` 各 2 处。事项线的样式里只有上浮和淡入。
- 令牌之外的曲线有五处：`apps/workbench/src/tab-reorder.ts`（`.16,1,.3,1`）、`plugins/native/pages/src/drag-preview.ts`（同上）、`plugins/native/workflows/src/browser/dom.ts`（三条：`.16,1,.3,1`、`.32,1.22,.52,1`、`.32,.72,0,1`）、`plugins/native/shelf/src/browser/arrange.ts`（220ms）、`packages/design-system/src/arrival-motion-client.ts`。`.16,1,.3,1` 和 quint 肉眼难分，直接换成令牌；`.32,1.22,.52,1` 换成 spring；`.32,.72,0,1` 换成 quint。

### 改成


1. **当前插件永远是托盘里带名字的那一片。** 留用的常驻；没留用的临时出现在托盘末尾，悬停时出「留用」。挪进托盘的只有「插件自己的那一页」（列表页），它不再占一个页签，所以页签里不重复插件名。这样「我在哪个插件」只有一个位置回答，换插件时是同一片纸在托盘里移动。

   - 放不下时：先各自收窄到 96px；再把别的插件的组收成「图形 + 个数」；最后才进「+N」。
   - **分屏**：每一栏的页签排在它自己那张纸的正上方；有焦点的一栏当前页签是浮起的纸片，没焦点的只留纸色。托盘只有一个，带名字的那片跟着有焦点的一栏，另一栏正在显示的插件只留纸色。事项线和输入框各只有一个，收件人跟着有焦点的一栏。

3. **＋ 紧跟最后一个页签**；没有页签时紧跟托盘后的细线。起始页浮层锚在 ＋ 下面，宽 560px，第一行是搜索，然后「最近」「留用」，再按用途分组；每项一行（图标、名字），说明只在选中那行出现。

### 方案 B：顶部去掉插件（用户 2026-11-15 提，待定）

托盘整个拿掉。样稿第 9、10、11 屏。

### 方案 C：把线画成线（2026-11-15，待定，推荐）

现在一条 68px 的带子上有：带框的线头、带框的胶囊、分段的细线、+N、输入框、又一组胶囊、任务图形、展开键。盒子太多，读起来像工具栏，输入框不突出。改成：

1. **一条贯通的细线**，从线头到线尾，输入框压在线上。**只有输入框是盒子。**
2. **事件是线上的珠子**（24px 的圆，里面是来源的图形）。状态看形状，不单靠颜色：
   - 做完：实心，越早越小越淡，最早的收成点；
   - 在办：一圈走着的环（真实进度）；
   - 等你：琥珀环，挪到输入框旁边；

   - 失败：红环。
3. **出字只有一条规则**：每一侧离输入框最近的那一处出字（名字加一个状态词），等你的优先，其次是在办的。其余的指一下才出。

6. **对着一件事说话时**，它的那颗描一圈墨色，收件人换成它。
7. **变窄时先收字再减珠子**，一行就够：541–959 不再折成两行，也不会出现被切半的胶囊。

得到的：静止时线是安静的，只有该你了的那一处有颜色有字；能看到的历史从两三条变成七八颗；输入框成为这一条上唯一的盒子。

- 静止时大多数事件没有名字，要靠指一下或键盘走过去才读得到；键盘和读屏要给每颗珠子完整的名字和状态。

### 定下的：方向一（用户 2026-11-16「就这个方向」）

1. **一栏正文加右边页边**，没有卡片、色带和成排的「打开」。正文 640px，页边 216px。
2. **从上往下四段**：

3. **页边的「依据」就是插件卡片表剩下的东西**：一个来源一行，一个词说轮到谁（正常、有变化、等你、卡住了、读不到）；没有新内容的合成一句「另有 N 个没有新内容」；最下面「全部插件 ⌘K」。

## 验收标准

顶部栏

1. **POLISH-01** 在任何插件页，托盘里有且只有一片带名字的当前项；没有留用的当前插件也出现在托盘末尾。
2. **POLISH-02** 页签不重复插件的名字，每个页签带自己插件的图形；切换插件后别的插件的页签仍在；页签图标在 1024、1440 两个宽度下不被裁切。
3. **POLISH-03** ＋ 的左边缘距最后一个页签（没有页签时距托盘后的细线）不超过 12px。
4. **POLISH-04** 起始页浮层的左边缘与 ＋ 对齐，宽度不超过 560px，第一个可聚焦元素是搜索。
5. **POLISH-05** 顶部栏右端在没有通知和同步提示时只有三个控件：侧边开关、布局、项目。
6. **POLISH-06** 四个字以内的名字（设置、助理、Coding 等）在顶部栏和收件人标签里不被截断。
7. **POLISH-07** 390 宽度时顶部栏是一行。

事项线

8. **POLISH-08** 事项线上不出现被切掉一部分的胶囊；放不下的计入「+N」。
9. **POLISH-09** 胶囊截断时先截事实，名字至少保留六个字；来源标记不带状态色。
10. **POLISH-10** 输入框的水平中心在首页、Coding、设置三处相同，宽度相同。
11. **POLISH-11** 收件人标签不含项目名；默认显示「助理」。
12. **POLISH-12** 输入框有字时发送键是墨蓝实底，且是这一屏唯一的墨蓝实底控件；运行中同一位置是停止键。
13. **POLISH-13** 换页签、换插件、打开设置后，收件人变成该处的默认对象，上一处的提示行消失；手动选的收件人和没发出的草稿在切回时还在。
14. **POLISH-14** 只读模式不在输入框上方增加一行；390 宽度时底部不超过两行。
15. **POLISH-15** 线头在有等你的事时显示琥珀计数，没有时不显示。

助理

16. **POLISH-16** 对话框与输入框的水平中心相差不超过 1px；详情栏默认关闭。
17. **POLISH-17** 对话框高度随内容变化，上沿不越过工作面头部（1024×768 下验证）。
18. **POLISH-18** 对话框头部右侧不超过三个键，每个不小于 28px。
19. **POLISH-19** 没有用技能的回复前后不出现技能提示行。
20. **POLISH-20** 收起到最新回复时显示的内容不含 `**`、`##`、反引号等 Markdown 记号。
21. **POLISH-21** 点击工作面（包括插件页面内部）、切换页签或打开设置后，对话框完全收起，只剩事项线右端的后台任务图形和展开键；设置页上没有浮层挡住内容。
22. **POLISH-22** 待办事件的事件卡显示标题、备注、计划日期，以及主人声明的动作。

Coding

23. **POLISH-23** 目录列 240px 宽时，会话名至少显示十个字；常态不显示状态词。
24. **POLISH-24** 准备就绪后，回答上方的准备信息只占一行；回答在首屏可见。
25. **POLISH-25** 对话正文列在 1440 宽度下不窄于 720px。
26. **POLISH-26** 普通提示不使用琥珀色；Coding 页面里琥珀只出现在等用户处理的地方。
27. **POLISH-27** 任务图和结果与审查里没有未翻译的英文标题；绝对路径和能力编号不在结果与审查的首屏。
28. **POLISH-28** Coding 输入框底排不超过四个控件。

设置页

29. **POLISH-29** 全局设置各页的标题字号、正文列左边线和最大宽度一致；类目行高 32px。
30. **POLISH-30** 设置页里没有卡套卡；空的分节和只有一页时的翻页不显示。
31. **POLISH-31** 助理设置页首屏的勾选框不超过五个。
32. **POLISH-32** 设置页里没有无说明的禁用按钮。

动效与色彩

33. **POLISH-33** 产品源码里除设计系统基线外没有 `cubic-bezier(` 字面量。
34. **POLISH-34** 事件变成等你时触发一次 `molisCraft.ask`，不重复。
35. **POLISH-35** `--ease-spring` 不用在宽或高超过 32px 的元素的位移和缩放上。
36. **POLISH-36** [人工] 换插件、开对话框、换会话、换设置页的过渡在真实窗口里连贯，可以被第二次点击打断；减少动态效果时直接切换。
37. **POLISH-37** [人工] 逐屏对照 `taste.md` 的四问（像不像真正好用的工具、和整站是否一致、动线顺不顺、会不会廉价）通过，浅色、深色各看一遍。
38. **POLISH-38** 分屏时每一栏的页签起点与该栏纸面的左边缘对齐；托盘里带名字的当前项随焦点所在的栏变化；收件人随焦点所在的栏变化。
