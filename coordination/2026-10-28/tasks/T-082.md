## 1. 背景

### 1.1 `tests/goals-personal-methods-stored-json.test.ts`（123 行，T-050 #1374 新建）

**`:46` 的返回类型**
- `:46` `function unreadable(error: unknown): void {`，`:54` `return true;`。
- 文件里只有两处用到它：`:66`（RAC-1495）和 `:109`（RAC-1497），都写成 `await assert.rejects(actions.invoke(personalPlanningActions.list, {}), unreadable);`。RAC-1496 不用它。
- Node 对 `assert.rejects`、`assert.throws` 第二个参数是函数时的规定：函数必须返回 `true`，否则报 `ERR_ASSERTION`。
  - 依据一：`@types/node` 的 `assert.d.ts` 把这一参数的类型写成 `type AssertPredicate = RegExp | (new() => object) | ((thrown: unknown) => boolean) | object | Error;`。
  - 依据二：同一文件的示例注释写明「Avoid returning anything from validation functions besides `true`」。
  - 依据三：起草时在 Node v24.21.0 上用 `node -e` 试过。校验函数不返回，报 `ERR_ASSERTION`，消息是 `The "v" validation function is expected to return "true". Received undefined`；返回 `true` 时通过。
- 所以：
  - 现在的用例是绿的，因为 `:54` 确实返回了 `true`。
  - 只是类型写成了 `void`。把 `void` 改成 `boolean`，运行时行为一点不变。
  - 改后的好处：以后谁删掉 `return true`，tsc 会报 `TS2355`（返回类型不是 void 的函数必须返回值）。现在删掉的话，tsc 不报，只能等跑起来报 `ERR_ASSERTION`。
- 仓库里的现成写法：`tests/desktop-launch-args.test.ts:70` `function refused(error: unknown): boolean {`，`:77` `return true;`。

**`:32` 的注释**
- 原文：`/** The stored text of B's row is made unreadable while no Host is open, the way a maintenance people would find it broken. */`
