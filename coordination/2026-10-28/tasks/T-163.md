# T-163 待办整理读材料：按整字取前 60000 个字，不把两单元的字截出半个，「只读了前 60000 字」按字数判断

> **这条在 main 上成立：待办整理读一份材料时，「前 60000 个字」是按 UTF-16 单元取的，「读没读完」「只读了前 60000 字」也按单元数判断。材料里有表情等两单元的字时，模型可能读到半个字，读到的字数比说明里写的少，没超过 60000 个字的材料还会被标成没读完。**
> - `plugins/native/todo/src/organize-model.ts:121`：发给模型的材料正文是 `text: material.text.slice(0, TODO_ORGANIZE_MATERIAL_CHARS)`；
> - `plugins/native/todo/src/organize.ts`：
>   - `:118` 读成了多少：`material.read === "truncated" || material.text.length > TODO_ORGANIZE_MATERIAL_CHARS ? "truncated" : "read"`；
>   - `:119` 说明：``material.note ?? (material.text.length > TODO_ORGANIZE_MATERIAL_CHARS ? `只读了前 ${TODO_ORGANIZE_MATERIAL_CHARS} 字` : "")``。
>
> 常量叫 `TODO_ORGANIZE_MATERIAL_CHARS`（`contract.ts:4`），说明里写的是「字」，上面三处的 `length` 和 `slice` 数的却是单元。`🟢`（U+1F7E2）是一个字、两个单元，所以：
> - ① 第 60000 个单元若是一个两单元字的前一半，`slice` 把它留下，模型读到一个孤立的高位代理（发出去的 JSON 里是 `\ud83d`）；
> - ② 满是两单元字的材料，60000 个单元只有 30000 个字：一份 40000 个字（80000 个单元）的材料，模型只读到前 30000 个字，说明却写「只读了前 60000 字」；
> - ③ 字数没超过 60000、单元数超过的材料，被标成 `truncated`，说明里还是那句「只读了前 60000 字」，人在复核页上看到的就是这一句（`organize.ts:154` → `browser/review-cards.ts:147`）。
>
> **本单加一个函数 `materialReadText`，三处都用它：取材料的前 60000 个字，在字与字之间截；`read` 和说明用「它取出来的和原文不一样」判断。** 分组用的 `organizeParts`（`organize-model.ts:104`）不改，见第 8 节第 2 条。
>

## 1. 背景

- 三处现在的样子（行号在 main `71924dd58` 上）：



  常量在 `contract.ts:3-4`：`/** Todo's organizer reads at most this much of one material; a caller with longer text sends it in parts of this size. */ export const TODO_ORGANIZE_MATERIAL_CHARS = 60_000;`

- 下游怎样数长度：
  - **进来的材料按字数限。** `todo.organize.extract` 的输入里，材料正文 `maxLength: 200_000`（`organize-actions.ts:41`）。动作网关的 AJV 用默认的 `unicode: true`（`packages/kernel/src/action-schema.ts:41-42` 没有改它），`maxLength` 数的是字，所以调用方合法地送来 200000 个 `🟢`（400000 个单元）。
  - **模型读到的就是 `:121` 截出来的。** 发给模型的提示是材料的 JSON：`fencedMaterials`（`packages/contracts/src/platform/model-prompts.ts:60-62`）把 `JSON.stringify(data)` 放在 `BEGIN_<边界>` 和 `END_<边界>` 两行之间。孤立的高位代理，`JSON.stringify` 写成 `\ud83d`，`JSON.parse` 读回还是那个半个字。提示语里没有任何一句说「只读前 60000 字」：`prompts.ts`、`roles.ts` 里都没有 60000，所以提示语不用改。
  - **人读到的只有 `organize.ts:119` 的说明。** `:118`、`:119` 存进批次的材料（`contract.ts:134-135` 的 `read`、`note`），`:154` 把没读完的材料写成一行「「标题」没读完：只读了前 60000 字」放进 `notes`，复核页逐行显示（`browser/review-cards.ts:147`）。
  - **分组。** `organizeParts`（`organize-model.ts:104`）按 `Math.min(material.text.length, TODO_ORGANIZE_MATERIAL_CHARS)` 估每份材料占多大，一次模型调用最多 `TODO_ORGANIZE_PART_CHARS`（`:28`，40000）。这是估「一次发多少」，不是「读多少字」，本单不改（第 8 节第 2 条）。

- 宿主的上传路径不受影响：`apps/local-host/src/context-onboarding-service.ts:320-330` 的 `textParts` 把长文字切成每段不超过 60000 个**单元**（`TODO_PART_CHARS`，`:345`），且不从一对代理中间切（`:326`）。每段先到 `todo.organize.extract`，长度都在 60000 个单元以内，`materialReadText` 原样还给它。
  - 它的注释和常量名写的是「characters」，实际数的是单元。含两单元字的长材料，每段因此不到 60000 个字。这不是本单的缺陷，不改，记在第 8 节第 6 条。

- 不含两单元字的材料，新旧写法一字不差：一个单元就是一个字，`slice(0, 60000)` 取的就是前 60000 个字，`length > 60000` 就是多于 60000 个字。

## 2. 目标

1. 整理读一份材料，取它的前 60000 个字（按码点），在字与字之间截：不超过 60000 个字的原样给模型，超过的取前 60000 个字，模型不会读到半个字。
2. `read` 是 `truncated`、说明是「只读了前 60000 字」，当且仅当材料多于 60000 个字（或调用方自己标了 `truncated`、自己给了说明，这两条和现在一样）。
3. 不含两单元字的材料：发给模型的正文、`read`、说明都和现在一字不差。
4. 用例钉住上面几条：把 `:121` 改回按单元截、把 `:118` 或 `:119` 改回按单元判断、把字数数多一个、把函数里的单元数改成按字加，都有一句断言红；改成「按单元、不切开字」（T-153 的写法），也红。

   ```ts
   /** What organizing reads of a material: its first TODO_ORGANIZE_MATERIAL_CHARS characters, cut between whole characters (a 🟢 is one character but two UTF-16 units). */
   export function materialReadText(text: string): string {
     if (text.length <= TODO_ORGANIZE_MATERIAL_CHARS) return text;
     let end = 0, count = 0;
     for (const character of text) {
       if (count === TODO_ORGANIZE_MATERIAL_CHARS) return text.slice(0, end);
       end += character.length;
       count += 1;
     }
     return text;
   }
   ```

## 8. 与默认不同的

1. **按字取，不照 T-153 按单元。** 这里的上限叫 60000「字」（`TODO_ORGANIZE_MATERIAL_CHARS`、说明里的「字」），进来的材料也按字限。按单元、不切开字（M6）不留半个字，但满是两单元字的材料只读到一半，40000 个字的材料还会被标成没读完。
