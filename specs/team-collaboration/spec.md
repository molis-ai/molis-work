# 团队协作：按项目明确共享

状态：需求草案（2026-10-28）。用户已确定以项目为单位明确共享，成员访问获准的项目内容；个人空间、其他项目和个人外部 AI 会话不会自动共享。首版按项目提供查看、编辑、管理三档，后续可细化到插件及具体资产的方向已定；团队记忆由成员选择发布、团队管理员管理；细粒度权限规则和完整交互待细化，尚未实现或验收。本轮交付为概念方案与需求记录，不开发。后续目标完成程度为**内部完整**：至少两名真实用户能共同使用一个项目，主路径、权限变化、同步失败与恢复可验证。需求维护：Codex；实现待分配，沿演进计划 3·C 细化、阶段 4 实施，个人同步仍为前置。

## 1. 目标与范围

让两个人围绕同一个项目的目标、资料与讨论开展工作，能看清哪些内容已共享、共享给谁，以及自己可以做什么。承接 BL-071 的团队空间与多人共享项目，并与 BL-013 的项目讨论、BL-022 的项目记忆衔接；当前决定不代表这些能力已经完成。

共享单位是明确选定的项目。加入团队不意味着获得团队里全部项目的访问权，分享一个项目也不公开用户的整个 Home。项目内容仍由各业务插件拥有，团队访问、发布与同步复用平台公共能力，不为每个插件另造成员表或权限规则。

本轮确定首版权限三档及后续细化方向，邀请流程和具体操作边界继续细化；不引入公开链接、匿名访问、市场或团队管理后台，也不把项目共享解释为远程控制成员电脑或运行其 AI 会话的许可。

## 2. 已定共享边界（2026-10-28 用户决定）

用户明确选择项目、接收成员和共享范围后，成员才能按有效权限访问获准内容。已有有效项目授权直接复用，不要求每次打开重新确认；扩大项目、成员或内容范围须有对应授权，团队管理员身份本身不公开个人数据。

| 内容 | 共享要求 |
| --- | --- |
| 已明确共享项目中的内容 | 按项目共享范围和成员有效权限访问；项目内有引用不等于引用对象本身可访问 |
| 个人空间、个人偏好与个人记忆 | 不因加入团队、共享项目或内容分类而自动公开；成员可按 §2.4 选择记忆发布到团队（BL-022） |
| 其他项目及跨项目汇总 | 不随当前项目共享；其中涉及本项目的内容也不能使整份跨项目汇总自动可见 |
| 个人外部 AI 会话 | 自动发现、归入某项目或持续采集均不等于向团队公开；共享其中内容及控制原会话各自需要有效授权 |
| 本机目录、连接与账号 | 项目关联不直接开放整块磁盘、私人连接或账号凭据；共享内容按资料和同步合同提供，使用个人工具另核有效许可 |

例如，甲将“官网改版”共享给乙，乙能访问该项目中获准的目标、资料与讨论。甲的另一个项目、个人简报，以及虽与官网仓库相关但仍属个人的 Claude Code 会话，不会因此出现在乙的项目列表、搜索或 AI 回答中。甲可以按有效授权分享选定成果，但不能由这次分享推导出原会话全部历史和控制权限。

### 2.1 工作记录、简报与 AI 使用

平台采集到的完整工作记录不等于团队可见日志。个人助理可以在自己的有效范围内工作，但面向共享项目成员的首页、搜索、引用预览、通知、简报和 AI 输出必须遵守接收者的共享范围。不能把未共享的内容改写成摘要、项目记忆或统计后展示给成员，也不能通过工具返回或缓存绕过限制。

Work Brief 的 Home 级运行范围不使个人简报成为团队简报。项目报告只使用获准向目标成员呈现的材料；需要额外分享某份个人材料时，先明确该材料、接收者和用途并取得相应授权。原始事实、记录和简报继续归原主人，团队功能不复制一份独立的完成状态。

Sessions 的项目归属只帮助组织工作。查看项目、看到一份已分享的成果或获准读取部分会话内容，都不自动授予恢复、发送消息、停止或交接原会话的权限；实际控制继续沿 Sessions 和统一授权合同。

### 2.2 变更与恢复

共享对象、成员及有效范围可查看和修改。成员被移除、共享收窄或撤销后，后续读取、同步、工具调用和呈现按最新状态核对；在途返回不能把已失去权限的内容重新交给该成员，刷新、重连或重启不能恢复旧许可。失败时保留真实状态并说明影响，不把共享失败显示成成功或把权限不足显示成没有内容。

撤回访问不承诺收回他人此前合法导出、另存的内容。离线副本失效和清理方式、历史已共享版本的保留及项目退出／删除后的归属仍需结合个人同步与团队权限方案明确；在未实现和验证前不宣称具备远程抹除或离线即时撤回能力。

### 2.3 首版三档权限与后续细化（2026-10-28 用户决定）

首版可以先按项目粗分权限，提供查看、编辑、管理三档，邀请时选择、之后可调整。用户不必在初次共享时逐个配置插件和资产。

| 首版权限 | 成员可以做什么 |
| --- | --- |
| 查看 | 阅读该项目中获准共享的内容 |
| 编辑 | 阅读并修改获准的项目内容、参与协作；不因此获得成员与共享范围的管理权限 |
| 管理 | 在查看、编辑基础上管理成员及项目共享权限；不因此获得其他项目、个人内容或私人账号的权限 |

三档是首版的简化配置。权限模型需保留后续在同一项目中，按插件及具体资产分别设置权限的空间，例如某成员可以编辑 Pages 内容，但对其中一份指定文档只可查看。这里的“资产”泛指有明确主人和身份的内容对象，如文档、目标、文件或已保存成果，不是要求把它们统一搬进成果库，也不另建一套资产事实。

为使后续细化能沿用首版，设计与实现须保留以下边界：

- 权限判断通过同一个公共访问入口，知道当前成员、所在项目、资源主人、目标对象及实际操作；成员身份来自可信调用上下文，资源归属经原主人核对。首版可按项目三档作出判断，但不能只把一个项目角色交给各插件自行解释，或在页面里写死“能编辑项目就能操作所有对象”。
- 插件范围绑定该项目中的实际插件内容与实例，资产范围引用原主人的稳定对象身份；同名对象、另一个项目的同一插件和 Home 级插件的个人内容不能混用。原插件继续拥有内容，平台拥有访问判断，不为每个插件另造权限系统。
- 后续更细的权限与项目默认权限仍走同一判断入口，覆盖列表、搜索、引用、AI 取材、直接调用和同步；不能只限制详情页。具体继承、覆盖、拒绝优先级和批量设置在细化时确定，新增粒度不得意外扩大原有授权。
- 首版只交付项目三档及支撑它的必要合同，不提前做完整权限矩阵、逐资产配置界面或通用策略语言；后续细粒度功能本次不排期。后续合同与存量数据变更遵守仓库现行规则，不为这个方向预建兼容层。

项目内容权限与动作执行授权共同约束实际行为。编辑内容不自动允许使用他人的账号、执行命令、控制外部会话或向外发布；查看权限也不能靠已有动作调用许可绕过内容限制。具体业务操作由原主人映射到统一访问判断，不由 AI 或插件自行扩权。

### 2.4 成员发布记忆，团队管理员管理（2026-10-28 用户决定）

成员可以选择自己有权分享的记忆发布到指定团队，团队管理员可以管理团队记忆。共享由发布行为决定，不因一条记忆被分类为项目规则、团队共识、偏好或经验就自动公开。个人记忆的形成、接受或归入项目也不等于向团队发布。

| 身份 | 团队记忆中的操作 |
| --- | --- |
| 团队成员 | 选择记忆、明确目标团队与实际共享内容并发布；在有效成员权限内读取和使用已发布的团队记忆 |
| 团队管理员 | 查看、整理、修改、停用或删除团队记忆；管理权限限于该团队，不扩展到成员未发布的个人记忆 |

成员发布不以管理员逐条批准为前置。用户已在请求中明确要发布哪些内容、发布到哪个团队且有权分享时，可沿有效授权执行；AI 可以协助选择和整理，但不能凭内容分类或个人记忆的自动形成设置自行发布。发布前能看清实际共享内容、目标团队及可见范围，发布后能查看结果、发布者和来源；未发布内容继续留在原范围。

发布只共享本次选定内容，不开放原会话、个人记忆库、私人背景或来源文件的全部内容。成员对来源只有读取权时，仍须核对是否有权向该团队分享。团队记忆可以保留来源说明，但打开原始来源继续受原权限约束。管理员修改或删除团队记忆不连带修改成员的个人原文；个人原文的后续变化也不凭一次发布自动同步给团队。发布后的本人修改／撤回方式和版本更新交互在本节继续细化。

团队记忆的管理与召回沿同一有效状态：停用、删除、成员退出或撤权后，后续和在途读取、AI 使用与同步都重新核对，不能靠旧缓存恢复。发布失败如实显示未完成；回执丢失、重试或重启先核对实际结果，不重复发布或覆盖管理员之后的修改。

复用[现行记忆方案](../prologue-memory-strategy/spec.md)的公开工具、版本、状态与作用域／授权机制，不新建第二套记忆系统。个人记忆的形成／候选批准与团队发布分别核对权限；团队身份、发布范围及管理员资格由可信成员关系和统一访问服务判断，不能只改分类标签或从项目的管理档推导团队管理员资格。项目长期说明仍是持续规则的主人，团队记忆保留必要提炼与引用，不另建规则副本，也不变成操作指令或执行授权。

## 5. 待细化决定

- 首版三档的业务操作映射、邀请流程与负责人职责；后续插件／资产粒度的继承、覆盖、拒绝优先级和批量设置。项目三档与向下细化方向已定，不再作为未决原则。
- 团队记忆：成员发布、团队管理员管理的原则已定（BL-022）；细化发布后的本人修改／撤回、版本更新及具体界面，不再按内容类别决定自动共享。
- 项目讨论的产品形态、实时或异步协作范围，以及冲突处理；不直接恢复归档实现（BL-013）。
- 离线访问、撤权后的副本处理、历史共享版本与退出／删除后的内容归属，沿个人同步和团队身份方案确定。

这些问题不改变已确认的项目共享、个人内容不自动公开、首版三档与后续插件／资产细化，以及成员发布／管理员管理团队记忆的方向；本次只记录已定范围，不以草案替代后续决定或开发授权。
