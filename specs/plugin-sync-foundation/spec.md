# 插件同步基础

状态：第一阶段已实现并验证；整体同步仍未完成。本轮交付可测试的契约和 Pages 本地快照适配，不宣称云端同步已接通。

后续进展：个人 Pages 增量与本机 Rust/D1 联调见 [下一阶段交付](../personal-pages-sync/spec.md)，本文件保留第一阶段历史范围。

## 对象与范围

用户在个人/团队空间选择插件的业务资产集合，而不是数据库表。配置属于 spaceId，插件只声明可选集合及必要依赖；授权由 Host 和服务端另行校验。本地空间永不上传，团队权限暂不实现。

比较过直接复制 SQLite、逐插件调用云接口、统一交换协议三种方式。采用最后一种：保留业务 Store，平台管理传输，插件解释自己的 payload。避免文件锁、机器路径和插件升级耦合。

## 本轮交付

- 可选 Manifest sync 声明：集合 ID、名称、数据格式版本、必要依赖；未知/循环依赖拒绝。
- spaceId 级配置合同：绑定准确插件发布者与签名、集合与数据格式版本；新集合不隐式加入旧选择，未适配不假装支持。
- SDK 暴露统一快照适配协议与依赖展开，不包含插件业务 SQL。
- Pages 作为第一个 owner：文档正文（含未发布草稿）、文件夹、收藏、Goal/Artifact 引用的项目级一致快照；本机版本与源版本分离；校验后事务恢复，冲突不覆盖。
- 同库持久修订计数随业务写入原子变化；不冒充逐资产 Outbox。保留本地编辑器版本保护。
- 引用不存在、发布未完成、运行中生成、非便携 URL、格式不兼容时明确拒绝，不能悄悄丢弃。
- 测试在两个临时 Home、相同个人空间与项目之间执行，不操作用户真实数据、不启用网络、不新增 UI/HTTP 入口。

## 验收

1. 旧 Manifest 无 sync 仍可用；非法、重复、循环、空集合声明失败。
2. 选择自动补必要依赖；未知类型/版本/发布者不会获得上传资格；配置不能跨空间。
3. 两个临时个人 Home 往返正文、文件夹、稳定 ID、收藏；来源本地编辑版本不覆盖目标版本。
4. 重复快照无副作用；并发修改、删除后旧重放、其他项目 ID 碰撞、跨空间、撤权、未解决引用不写入。
5. 重启后修订计数保留；同库事务回滚同时撤回计数变化；现有 Pages 回归通过。
