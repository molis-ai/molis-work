# 安全与隐私

从资产、信任边界和威胁建立预防、检测、响应与数据治理闭环。

适用于：安全设计、隐私治理、高风险功能。

## 规划路径

1. 盘点资产、主体、敏感数据、权限和信任边界
2. 建立威胁、滥用、隐私影响和风险优先级
3. 设计最小权限、数据最小化和关键控制
4. 补齐检测、审计、响应、恢复和通知流程
5. 用攻击路径、权限边界和恢复演练验证控制

## 必须覆盖

| area | label | question |
| --- | --- | --- |
| protected_assets | 受保护资产 | 哪些数据、能力、凭据和业务结果一旦受损影响最大？ |
| actors_trust_boundaries | 主体与信任边界 | 谁能访问什么，身份、权限和系统边界在哪里变化？ |
| threats_abuse | 威胁与滥用 | 哪些攻击、误用和内部滥用路径现实可行？ |
| privacy_lifecycle | 隐私生命周期 | 数据为何收集、如何使用、共享、保留和删除？ |
| controls_assurance | 控制与验证 | 哪些预防、检测和审计控制降低了具体风险？ |
| incident_recovery | 事件与恢复 | 发现问题后如何限制影响、恢复可信状态并通知？ |

## 依赖规则

| rule_id | statement | direction_hint |
| --- | --- | --- |
| controls-after-risk-model | 安全和隐私控制消费已经识别的资产、信任边界、威胁与影响。 | controls depend_on risk model |
| release-after-assurance | 高风险能力发布消费权限检查、攻击路径验证和事件恢复准备。 | high-risk release depends_on assurance evidence |

## 完成证据

- 资产、数据流、信任边界和权限清单
- 与具体风险对应的控制和验证记录
- 事件响应与恢复演练结果

## 收口检查

- 每项高风险数据和能力都有明确所有者
- 控制能对应具体威胁而非只满足清单
- 最小权限、删除和恢复路径实际可执行

## 常见误拆

- 上线前才统一做安全检查
- 把合规清单当成威胁模型
- 只防外部攻击不处理误用和权限漂移

## 怎样用这份方法

- 先按「规划路径」把事情想完整，再把每个能独立交付、独立验收的结果列成一项；一项里不混入几个主要结果。
- 「必须覆盖」里与当前任务有关的每个问题都要有答案；答不上来的关键问题列为待确认，不用含糊的条目盖过去。
- 依赖只表示结果消费：乙开始或完成时必须用到甲的可验收产出，乙才依赖甲。讨论顺序、时间先后、同一个人负责、改同一份文件都不算依赖；没有结果消费关系的保持并行。逐条判断「依赖规则」，不适用的要说得出缺了哪一种产出消费。
- 每一项写明完成时拿什么证明（见「完成证据」），收尾前过一遍「收口检查」。
- 只描述有限、能完成的改变；持续运行的事不写成永远做不完的一项。
- 和别的规划方法一起用时，把各自的关键结果放在一起看谁消费谁，缺了提供方的再补上相应的方法。
- 拆出来的结果先给用户看。用户要落到某个工具里（例如已装的 Goals 插件）时，用那个工具自己的动作写入，由用户确认。
