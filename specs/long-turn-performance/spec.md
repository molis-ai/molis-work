## 目标、证据与边界

[PR #1010](https://github.com/molis-ai/molis-work/pull/1010) 的 Linux diff 着色与插入断言通过后，`tests/code-diff-scale.e2e.test.ts` 的长对话插入断言失败：77.6 ms，门槛 50 ms。相同诊断在干净 `964ac46b7` 整体构建后、2.5 倍 CPU 降速下为 86.4 ms，#1010 分支为 78.8 ms；隐藏 diff 后仍慢。跟踪只见约 20 个元素重算样式，主要开销是测试中一条包含 30,000 个 span 的超长单行布局。

本任务先判明这条防回归断言应约束的行为，再做最小完整修复：若生产渲染的局部改动即可消除不必要工作，则保留全文、布局与复制语义；若断言混入与其声明目标无关的行布局，则让测量准确覆盖“单节点引起整段对话重算样式”，并用恢复坏选择器的负向对照证明仍能捕获目标缺陷。不能只放宽阈值、减少节点、改 CI、删断言或以重试掩盖问题。现有 diff 修复不搬入本分支。

允许修改对应浏览器测试、必要的测试测量助手、经证据确认需要调整的 Coding 客户端/样式及本 spec；不改公共合同、动作、存储、模型调用或无关 UI。输入仍为同一页面的长对话和新增节点，输出为可解释且可重复的性能证据；生产代码若有改动，文字、token、复制、滚动与卸载语义必须保持。

诊断后的方案：只修测试。使用 CDP `Performance.getMetrics` 的 `RecalcStyleDuration` 差值测单节点样式重算，另记总耗时和 `LayoutDuration`。保留原来的 30,000 个 span、内联新增 span 和 50 ms 门槛，布局仍真实执行，只不把它算成样式重算。将长对话检查从 diff 用例移入独立浏览器用例，避免一个场景的失败遮蔽另一个；同一用例注入 Coding 祖先 `:has()` 后接裸 `span` 的缺陷形状，并断言样式开销超过原门槛，证明新测量仍能抓住全局重算。这是对缺陷形状的负向对照，不声称逐字恢复历史样式。
