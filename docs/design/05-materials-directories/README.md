# 目录实现片与指定文件夹片定样（第 05 批）

状态：定样待用户拍板（2026-11-08）。两组各三个方案，推荐写在下面，没有决定。产品未实现；合同和规则见 [`specs/shared-sources-and-surfaces/spec.md`](../../../specs/shared-sources-and-surfaces/spec.md) 第 3 节「永久删除怎么做」和「另一台设备上的引用」。

- **A 永久删除项目：** 项目的默认输出目录里还有文件时，设置页的删除确认框要问一句删还是留。
- **B 指定文件夹：** 另一台设备上的引用，要在这台电脑上指定对应的文件夹才读得到。这一组定第 3 节列的六个状态。

## 怎么打开

先在仓库根目录生成产品标记和样式（`dist/`，不入库）：

```sh
pnpm build
node docs/design/05-materials-directories/export.mjs
```

然后有两种打开方式：

- 直接在浏览器里打开这个文件：`file://<仓库>/docs/design/05-materials-directories/index.html`。
- 或者起一个本机服务，再打开 <http://127.0.0.1:4436/05-materials-directories/>：

  ```sh
  python3 -m http.server 4436 --bind 127.0.0.1 --directory docs/design
  ```

顶上两行斜纹条是原型控制，不是产品界面。第一行选组、方案（★ 是推荐）、状态、数据量（常规、最挤、最空），切中英文和深浅色；第二行写这个状态里什么是模拟的。

每个画面都能从地址直接打开，例如 `#g=b&o=b1&st=refused&d=plain&l=zh&t=light`。

- **画面是什么做的：**
  - 控件、令牌和图标取自组件板（[`../kit/`](../kit/README.md) 和 `export.mjs` 从这次构建取的同一套）。
  - A 组的设置页和删除确认框是产品自己的标记（`createProjectSettingsFolds`），样式是产品的设置页样式表，英文来自产品词典。新加的部分写进这个确认框里。
  - B 组的资料面板按 03 定下的方案 A 搭：按来源分组，最上面是「最近用过」（[`../workbench-shared-paths/`](../workbench-shared-paths/README.md)）。
  - 工作台的外框是简化的：两张纸和一个输入条，标签条和底栏的其他部分没有画。
- **什么是模拟的：** 项目、文件夹、文件、对话、Goal、删除、读取结果和 Agent 的进展都是示例数据。斜纹小标「模拟」标在页面上发生的地方。原型不连任何服务，不碰任何 Home。

## A 永久删除项目

**这一屏要回答什么。** 你要永久删除一个项目，Molis Work 为它建的默认输出目录里还有文件，Agent 和插件写出的东西默认都在这里。你要决定这些文件跟着删，还是留在电脑上。两种都不能撤销：删了文件就没了（包括没提交的代码）；留下的文件夹以编号命名，Molis Work 以后不再列出它。

**焦点：** 这一个选择，加上一个写明后果的按钮。没有默认选中（用户定）。

**三个方案都有的部分：**

- 有这一问时，第一句改成「……你自己选的文件夹里的代码和文件会保留。」。原句是「关联工作目录中的代码和文件会保留」，旁边有「一起删除」时两句会打架。页面上标了「改了这句」。
- 空的、查看不了的都不问，按留。确认框和现在一样。
- 留下文件之后，确认框不关，换成「项目已删除」：
  - 一个容器写「默认输出目录留在这台电脑上」，下面是完整路径和「复制位置」。原型里的路径从 `~` 写起，因为文档里不放开发机上的路径；产品里显示完整路径。
  - 下面一句：「文件夹以项目编号命名，Molis Work 里不会再列出它。要用里面的文件，到这个位置去找。」
  - 唯一的按钮是「回到项目列表」。
  - 没问过、但删除时里面有文件，同样显示，前面多一句「里面有文件，删除时没有动它们。」。
  - 产品里没有「在访达中显示」，所以只给复制。
- 选了删、项目里还有任务在跑：平台拒绝。确认框里出一条琥珀色提示「现在删不干净这些文件」，写明等任务结束或先停下，并给一个「改成留下文件」。你的选择不丢；再按一次删，提示原地轻跳一下，不再弹一次。
- 清理没做完：沿用现在的提示和「重试清理」。删除已经开始，换一个选择重试会被平台拒绝，所以选择锁住、变灰，只剩重试；A2 的两个结束按钮这时收成一个「重试清理」，说明框里写出当时选的是哪个。
- 选了删、删除成功：和现在一样回到项目列表（原型用一条提示代替跳转）。

**三个方案：**

| 方案 | 样子 | 决定数 | 好处 | 代价 |
| --- | --- | --- | --- | --- |
| A1 问一句，再勾选 | 原框里加一组两个单选：「留在这台电脑上」「一起删除」，各带一句后果；原来的「我确认……」勾选照旧；按钮文字跟着选择变 | 选一项、勾一下、按一下 | 改动最小，全是设置页已有的样式（确认框、单选） | 三步，两处都在说「不能撤销」；勾选框和单选挤在一起，最后一下按的是什么要回头看 |
| A2 两个结束按钮 | 框里多一段说明「默认输出目录里还有文件」；勾选照旧；底部两个按钮「删除项目，留下文件」「删除项目和文件」 | 勾一下、二选一按 | 少一步 | 两个都是破坏性按钮并排，违背「一个决定一个主操作」；删和留的区别只在按钮字面上，容易按错 |
| **A3 选项就是确认（推荐）** | 两张选项卡代替勾选：「删除项目，文件留下」「删除项目和文件」，各带一句后果，下面一句「两种都会永久删除项目，不能撤销」；选了以后按钮才可按，文字写明后果 | 选一项、按一下 | 「想清楚」和「确认」是同一个动作，后果写在卡上，按钮再说一遍 | 有文件和没文件时确认框形状不同（空的仍是勾选）；设置页样式表要带上交互卡片的样式（组件板已有的 `mw-ix-option`，现在只在组件板和交互页里） |

**推荐 A3。** 这一问本身就是「我知道后果」的确认，没必要再勾一次。卡片把后果写在选项上，不用回头对照；按钮写着「删除项目和文件」，按下去之前还能再看一眼。A1 三步太多，A2 把两个破坏性按钮摆在一起。

**七个状态：** 有文件时问；空的不问；查看不了不问、按留；选了留之后的位置；没问过、有文件留下；选了删但还有任务在跑；清理没做完。数据量的「最挤」用最长的项目名和放在 iCloud 里的长路径。

## B 指定文件夹

**这一屏要回答什么。** 你在这台电脑上打开一个项目，对话、Goal 的输入或「最近用过」里有些资料来自另一台设备上的文件夹。那个文件夹叫什么、在哪，没有同步过来，这边只知道每份文件的相对路径，所以现在读不了。要做的是告诉 Molis Work：另一台设备上的那个文件夹，在这台电脑上是哪一个。一个文件夹指定一次，里面的引用一起接回来。

**最难的地方：** 原设备上两个文件夹各有一个 `README.md`，这边看起来一模一样，指错了也看不出来（spec 的验收例子）。所以三个方案都：

- 按来源文件夹分组，每组一个容器。组名下面写「同一个文件夹里还用过 接入指南.md、接口说明.md」，用同组的其他文件把两个文件夹分开。
- 指定后的提示说这个文件夹整体读得怎样：「3 份里找到 1 份，2 份 website 里没有」「3 份都找到了，1 份和引用时不是同一份」。指错了马上能看出来，并带「撤销」。

**三个方案都有的部分：**

- **状态的字（spec 第 2 节）：** 未指定的写「未指定文件夹」；指定后没有这个文件写「找不到位置」；内容不一样写「和引用时不是同一份」；没法比的写「内容没有核对」。每个都带图形，不只靠颜色。
- **组名：** 默认输出目录分「这个项目原来的默认输出目录」和「另一台设备的默认输出目录」，其余写「另一台设备上的文件夹」。
- **指定的去处：**
  - 这个项目已有的文件夹。
  - 「这个项目的默认输出目录」：会加回这个项目，作为参考。
  - 「选择另一个文件夹…」：系统的选择窗口，选中的文件夹作为参考加进这个项目。

  每一项都说明后果，确认按钮写「接到这里」。

  「这个项目原来的默认输出目录」不用选去处：它就是这个项目自己的文件夹，按钮是「加回这个项目」。
- **之后怎么看、换、取消：**
  - 本机文件夹下面多一行「对应另一台设备上的文件夹」，写着读得怎样，菜单里有「换一个文件夹」「取消对应」。
  - 「输入与输出」里每个文件夹也列出它对应着谁。
  - 打开一份文件时，出处行写「来自 website · 对应另一台设备上的文件夹」，旁边能改。
  - 取消对应后引用回到「未指定文件夹」，文件夹还留在项目里，也有「撤销」。
- **和引用时不是同一份：**
  - 打开时出一条琥珀色提示：「引用时读到的内容和 website 里现在这一份不一样：可能是后来改过，也可能对应到了别的文件夹。」，带「换一个文件夹」。
  - 「内容没有核对」只在行尾安静地写，打开时核对。
  - 没有记下内容的旧 Goal 输入，打开后说明为什么核对不了。
- **Agent 读不到之后：**
  - 对话里这一轮的结尾出一条提示「3 份资料读不到」，下面按来源分组列出这几份。
  - 指定好以后，提示换成「文件夹指定好了」，带「让它接着做」。读不到的会被跳过，提示里说几份。
  - 插件读不到时只拿到拒绝，「最近用过」也不把这些项给插件，所以人看到的就是对话和资料面板这两处。

**三个方案：**

| 方案 | 在哪里指定 | 好处 | 代价 |
| --- | --- | --- | --- |
| **B1 就地指定（推荐）** | 在碰到它的地方：「最近用过」、对话里读不到的提示、Goal 的输入、选资料的弹层。每组容器上一个「指定文件夹」，从按钮旁弹出选择 | 人在哪里碰到问题就在哪里解决，不换地方；对话里「读不到」紧接着就能指定、接着做 | 这些组容器在「最近用过」和选资料弹层里占地方，挤掉一些能读的行；同一个按钮出现在好几处（是同一个弹层） |
| B2 资料里一处 | 资料面板多一个来源组「另一台设备的文件夹」，只在这里指定。「最近用过」只列读得到的；别处的组容器只给「在项目资料里指定」，点了跳过去并亮一下那一组 | 只有一处要学，「最近用过」保持干净 | 从对话出发要多跳一次、换个地方找；「最近用过」里看不到刚才那份 README.md，要到下面的组里找 |
| B3 一次接回 | 一个对话框列出所有还没指定的文件夹，每个配一个选择，一个「接回 N 个文件夹」；之后在框里逐个报告结果。面板顶上一行「4 个文件夹来自另一台设备，还没指定」打开它 | 文件夹多时一次办完，结果一屏看全 | 离开了碰到问题的地方，卡片上只有文件名，判断哪个对哪个更难；会顺手去指定眼下不需要的；多一个要学的弹窗 |

**推荐 B1。** 未指定的引用一定是在某处碰到的：对话说读不到、Goal 的输入打不开。就地指定不打断手上的事，指定后的提示又马上说清楚指得对不对。B2 多跳一次，B3 离开上下文。

如果实际数据里一个项目常有很多文件夹要接，可以以后再把 B3 的对话框作为批量入口补上，两者不冲突。

**六个状态对应的画面：**

| spec 第 3 节 | 状态选单里 |
| --- | --- |
| 1 未指定的引用长什么样（最近用过、选择器、引用和出处行、Goal 的输入） | ① 资料面板与对话；① Goal 的输入；① 选资料加入任务 |
| 2 从哪里指定 | ② 从哪里指定、选哪个文件夹 |
| 3 指定时的反馈 | ③ 一次接回整个文件夹；③ 指定的文件夹里没有这个文件 |
| 4 之后怎么看、换、取消 | ④ 之后怎么看、换、取消 |
| 5 「和引用时不是同一份」「内容没有核对」 | ⑤ 和引用时不是同一份、内容没有核对；⑤ 指错了文件夹 |
| 6 Agent 或插件读不到之后 | ⑥ Agent 读不到之后 |

**数据量：**

- 常规：四个来源，两个 `README.md` 在里面。
- 最挤：六个来源，一个文件夹有 23 份引用，有一个特别长的文件名；第 6 份起「内容没有核对」。
- 最空：只有一份，来自另一台设备的默认输出目录。

## 组件板新增

没有。两组都只用组件板已有的件：

- 确认框、单选、勾选、交互卡片 `mw-ix-option`。
- 目录行、文件组、提示（带按钮）、状态环、菜单（带说明行）、弹层、对话框、toast。

实现时有三处样式要随第一个用到的产品页面进页面样式表：

- **交互卡片：** 设置页样式表现在不带它，A3 要带上。
- **提示里的按钮行 `mw-alert__actions`：** 组件板自己的规则（`catalog-keep-edits.ts`）。
- **菜单项的说明行 `mw-menu__desc`：** 组件板自己的规则（`catalog-composer.ts`）。

页面里的 `[编排]` 只是把这些件摆在一起：分组容器、文件夹下的对应行、留下的路径容器。规则在 `proto.css`。
