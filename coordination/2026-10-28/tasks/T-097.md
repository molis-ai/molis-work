# T-097 选中的内容「记下灵光」时，第一行超过 40 个字按整字截取

> **这条在 main 上成立：「记下灵光」的标题按 UTF-16 单元截取，截出半个字。**
> - `lingguang.fragment.offers@1` 的处理器是 `prepareLingguangFragmentOffers`（`plugins/native/lingguang/src/actions.ts:75-84`）。它为选中的内容准备一份 `lingguang.create@1` 的输入，取第一行作标题。
> - 标题在 `:79` 截取：第一行超过 40 个单元，就截到 39 个单元，再加「…」。
> - `lingguang.create` 的标题按字数数上限：`maxLength: 80`（`:18`）。Ajv 按码点数，见 `packages/kernel/src/action-schema.ts:41-42`。
> - 「40」是这里定的短标题长度，本单不改它，只把「单元」换成「字」。
>
> 一个 emoji 或扩展 B 区以后的生僻字，在 JS 字符串里占 2 个单元。第一行是 21～40 个这样的字时，本该整行作标题，现在被截成 19 个字、半个字和「…」。标题里留下一个落单的代理项（lone surrogate），人看到的是一个乱码方块。
>
> 起草时只读了代码，没有跑；第 5 节的先红就是复现。
> - 这是 T-096（待办「记成待办」按整字截取）的灵光一侧。
> - 截取的写法照 T-079（PPT 的页标题、要点按整字截取）。
>
> **不依赖别的任务，也不撞锁。**
> - 截到的标题最多 40 个字，也就是最多 80 个单元。所以 T-080（#1395，灵光主人按字数数）合入之前，灵光主人按单元数量（`store.ts:342`，80）也收得下，本单不用等它。
> - T-080 改的是 `store.ts` 和 `tests/lingguang-actions.test.ts`，与本单没有共同的文件。
> - 看板（协调分支 `ff78a142f`）没有任务锁 `plugins/native/lingguang/src/actions.ts` 或 `tests/contextual-interaction.test.ts`。
> - 2026-10-29 取全了在途 PR 的文件，没有别的 PR 改这两个文件。

## 1. 背景

- 合同口径。都按 Unicode 字符数，Ajv 的选项见 `packages/kernel/src/action-schema.ts:41-42`，`:79` 是 `new Ajv(options)`。选项里没有 `unicode: false`，所以 `maxLength` 走 Ajv 的 `ucs2length`，按码点数。
  - 选中片段的输入，在 `packages/contracts/src/platform/action-fragments.ts`：
    - `:110`：每段文字 `maxLength: 4000`；
    - `:125`：最多 8 段。
  - `lingguang.create` 的输入，在 `plugins/native/lingguang/src/actions.ts`：
    - `:18`：标题 `maxLength: 80`，正文 `maxLength: LINGGUANG_BODY_LIMIT`，也就是 200000（`contract.ts:4`）；
    - `:52`：请求号 `maxLength: 160`。
- `prepareLingguangFragmentOffers`（`:75-84`），处理器在 `:115`：
  - `:76`：把各段文字 `trim` 后，用空一行拼成 `text`；
  - `:78`：取 `text` 的第一行，作 `first`；
  - `:79`：由 `first` 得出标题；
  - `:80-81`：对象有名称时，正文末尾加「出自：…」；
  - `:82-83`：给出一个提议，`input` 就是 `lingguang.create` 的完整输入，`editable` 让人在执行前改标题和正文。
- 按 UTF-16 截取的那一行，main 上的原行（2 个空格）：

  ```ts
    const title = first.length > 40 ? first.slice(0, 39) + "…" : first;
  ```

- 同一个函数里不改的两处，为什么：
  - `:81` 的 `(text + from).slice(0, LINGGUANG_BODY_LIMIT)`：走不到。选中片段最多 8 段、每段 4000 个字（schema 拦着），全是两单元的字也只有约 64000 个单元，加上分隔和「出自：」远不到 200000。改了也没有用例能证明，本单不碰。
  - `:83` 的 `request_id.slice(0, 160)`：请求号是标识，由页面生成，不是人写的字，本单不碰。
- 改了以后，下游放得下：
  - 标题最多 40 个字，在 `lingguang.create` 的 80 以内；
  - 灵光主人在 `store.ts:342` 量标题，现在按单元数，上限 80。40 个两单元的字正好 80 个单元，也收得下。所以本单不用等 T-080。
- 现有的测试没量到这一行：`tests/contextual-interaction.test.ts:512-525` 用的是汉字。第一行 32 个字，不截；`:521` 只断言 `input.title.length <= 40`，汉字下按单元数和按字数数一样，改了以后仍成立。
- 页面不受影响：页面包从 `src/browser/factory.ts` 打，`src/browser/**` 里不是 `import type` 的，都不引 `../` 下的文件。所以 `/assets/molis-work-plugins/lingguang.js` 的字节不变（`tooling/gates/page-assets.json:32`）。

```ts

test("RAC-1669 灵光 cuts the first line of a selection in whole Unicode characters: 40 are kept, 41 become 39 and an ellipsis", () => {
  // lingguang.create's schema (plugins/native/lingguang/src/actions.ts) counts characters; one 🟢 is one character but two UTF-16 units.
  const wide = (count: number) => "🟢".repeat(count);
  const offered = (text: string) => prepareLingguangFragmentOffers({ request_id: "wide", fragment: { object: { kind: "pages_document", id: "d1" }, granularity: "range",
    targets: [{ kind: "text_range", text }] } })[0]!.input as { title: string; body: string; request_id: string };
  assert.equal(offered(wide(40)).title, wide(40), "a 40-character first line is the whole title");
  const cut = offered(`${wide(41)}\n第二行`);
  assert.equal(cut.title, `${wide(39)}…`, "a 41-character first line is cut to 39 characters and an ellipsis");
  assert.equal(cut.body, `${wide(41)}\n第二行`, "the body keeps the whole selection");
});
```

2. 改完以后新用例仍红，红在别处：
   - 不要缩短测试里的值，不要改 schema；
   - 把实际的值和调用栈贴到 #1332 问统筹。
3. 第 6 节的某个变异没有红，或红在别的句子：停下来问。不要为了让它红去加断言或改用例。
4. `contextual-interaction` 在你的机器上因为环境起不来（不是断言失败）：贴出错误，停下来问，不要跳过、不要改它。
5. 想顺手改的，都不在本单，问统筹：
   - `:81` 的正文截取、`:83` 的 `request_id.slice(0, 160)`；
   - `keptMaterial`（读文件和链接时只留前 198000 个单元，提示却说「字」）；
   - `conversationPrompt` 里交给模型的材料长度；
   - `store.ts`（T-080）；
   - 别的插件的同类写法；
   - 抽一个共用的「按整字截取」函数（放进 SDK 或 contracts 就是甲档）。
6. 下面任何一项出现，都停：
   - `affected-tests` 在真实改动上给出的 `full` 不是空的；
   - `pnpm actions:update` 出了 diff；
   - 页面资源、巨大单元或静态检查的数字变了。
