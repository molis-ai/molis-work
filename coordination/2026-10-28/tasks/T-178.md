## 1. 背景

- 快照怎样走到这一行（`apps/local-host/src/home-snapshot.ts`）：
  - `:41` 的 `assertSnapshotHomeInventory` 先查 Home 顶层有没有未登记的名字；
  - `:42` 的 `registry.stores.map(store => inventorySnapshotStore(home, store))` 把每个登记的存储逐个清点；这一步里每个名字问一次存储的 `snapshot.entry`（`home-snapshot-inventory.ts:45`）；
  - 清点是深度优先，同一目录里的子项按名字排序（`:77` 的 `readdirSync(path).sort()`），所以同一目录里多个不认识的文件，信息点的是排在最前面的那个；
  - `runtime` 这个存储（`connector-tool-download.ts:6` 的 `CONNECTOR_TOOLS_HOME_STORE`）挂着 `managedToolsSnapshot`（`home-stores.ts:41`）：`runtime` 自己、`connectors`、`connectors/installs`、`connectors/installs/<名>` 都是 `keep`，`<名>` 里面的每一项才进 `:136` 的 `entry`。
- 拒绝以后快照做什么：
  - `unknown(file)` 抛 `homeSnapshotErrors.unknown_data`，kind 是 `invalid`（`home-store-snapshot.ts:15`），message 是 `登记的存储含无法分类的条目，未生成快照: connectors/installs/<名>/<文件>`（路径是相对 `runtime` 的）；
  - 它从 `entry` 抛出，经 `disposition`、`visit`、`inventorySnapshotStore` 一路出到 `home-snapshot.ts:42`，还在创建输出目录的 `:44` 之前，所以没有输出目录、没有暂存；
  - 外层 `catch`（`:102-107`）只把 `actions.input_invalid` 改成 `host.home_snapshot.invalid`、`actions.conflict` 改成 `changed`，别的原样再抛，码保持 `host.home_snapshot.unknown_data`；
  - `finally`（`:108-113`）里 `publication` 还是空，清理什么都不做，然后释放存储 owner（`:112`）；
  - 快照没有跳过这个文件继续，也没有写出一部分：整个快照失败，Home 里的文件一个字节不变。这正是现有的 `unknown_data` 用例（`tests/security-invariants-home-snapshot-inputs.test.ts:12-36`）靠 `assertSnapshotRefused` 断言的三件事（`tests/fixtures/home-snapshot-small.ts:38-48`）：码、业务文件指纹不变、没有输出目录或暂存。
- 入口：`apps/local-host/src/cli-home.ts:42` 的 `home snapshot --to <目录>`。带 `--json` 时 `ActionError` 变成 stderr 上的 `{"error":{"code","kind","message"}}`、退出码 1（`:57-63`）；不带时错误原样抛出。
- 同一个函数的另一个调用者已经是这个写法：`apps/local-host/src/connector-private-state.ts:116-118` 的 `ownedInstallation` 是 `try { readManagedConnectorTool(home, id); … } catch { throw fail(); }`，接住一切，换成自己的拒绝。
- 现有用例没有覆盖「安装目录里有不认识的文件、记录又坏」这种快照：`tests/` 里 `runtime/connectors/installs` 只出现在连接器安装的用例和 `tests/fixtures/home-snapshot-fixture.ts:67`（完整的、能用的安装）里。

## 2. 目标

1. 受管理安装目录（`runtime/connectors/installs/<名>/`）里有不认识的文件，并且下面任一成立时，快照拒绝，码是 `host.home_snapshot.unknown_data`，信息是「登记的存储含无法分类的条目，未生成快照: connectors/installs/<名>/<文件>」，不生成输出、不留暂存、Home 里的文件不变：
   - 安装记录 `installation.json` 不在；
   - 记录不是合法 JSON；
   - 记录是合法 JSON 但不是完整的 ready 记录；
   - 记录完整，但里面写的可执行文件不在；
   - 目录名不是安装标识。
2. 记录可用、可执行文件在时，与现在一字不差：可执行文件被排除，旁边不认识的文件照旧按 `unknown_data` 拒绝，信息点名那个文件，不点可执行文件。
3. 用例钉住上面两条：撤销读的包装、换成放行、换成点错名字、改坏排除判断，各自都红。

1. **`home-store-snapshot.ts`**：只改 `:146` 这一行，其余一个字不动。

   原（四个空格缩进）：

   ```ts

   ```

   新（同样缩进，换成下面六行里的五行；`:147` 起原来的两行 `if (relative(…` 与 `return unknown(file);` 顺延）：

   ```ts
       // Whatever is wrong with the record, the snapshot's answer is the same: this file cannot be classified.
       let installation: ReturnType<typeof readManagedConnectorTool>;
       try { installation = readManagedConnectorTool(home, parts[1]!); }
       catch { return unknown(file); }
   ```

   说明：
   - 四行，不是六行：一行注释，三行读。改完文件是 `150 - 1 + 4 = 153` 行；上面第 4 节写的「六行」以这里的四行为准（第 4 节那一格只是概数，开工时别被它带偏）；

2. **`tests/security-invariants-home-snapshot-inputs.test.ts`**：在文件末尾（`:84` 的 `});` 之后）空一行，原样加下面的常量和两个 test。`join`、`test`、`smallSnapshotHome`、`assertSnapshotRefused` 文件开头已有，不加 `import`。

   ```ts

   test("RAC-1845 an unknown file in a managed install directory whose record cannot be used is refused as an unclassifiable entry, naming the file", async t => {
     // Telling the install's own executable from a stranger reads the install record, and readManagedConnectorTool throws connector.install.invalid
     // (connector-tool-install.ts) for each of these; the snapshot answers with its own code, the one every other unclassifiable entry gets.
     const id = "8fe2d9f4-f9a8-4cd0-bd86-4c96a73d0abc";
     for (const kind of ["record-missing", "record-not-json", "record-incomplete", "executable-gone", "invalid-id"] as const) await t.test(kind, async t => {
       const f = await smallSnapshotHome(t), name = kind === "invalid-id" ? "not-an-installation" : id, directory = "runtime/connectors/installs/" + name;
       await f.file(directory + "/stray.txt");
       if (kind === "record-not-json") await f.file(directory + "/installation.json", "not json");
       if (kind === "record-incomplete") await f.file(directory + "/installation.json", JSON.stringify({ id, ready: true }));
       if (kind === "executable-gone") await f.file(directory + "/installation.json", readyInstallRecord(f.home, directory, id));
       await assertSnapshotRefused(f, "host.home_snapshot.unknown_data", new RegExp("未生成快照: connectors/installs/" + name + "/stray\\.txt", "u"));
     });
   });

   test("RAC-1846 an unknown file beside a usable install record is still refused by name, and the install's own executable is not refused", async t => {
     // "tool" is the executable the record names and is let through; "zz-stray.txt" sorts after it, so it is the file the snapshot reaches and refuses.
     const id = "8fe2d9f4-f9a8-4cd0-bd86-4c96a73d0abc", directory = "runtime/connectors/installs/" + id, f = await smallSnapshotHome(t);
     await f.file(directory + "/installation.json", readyInstallRecord(f.home, directory, id));
     await f.file(directory + "/tool"); await f.file(directory + "/zz-stray.txt");
     await assertSnapshotRefused(f, "host.home_snapshot.unknown_data", new RegExp("未生成快照: connectors/installs/" + id + "/zz-stray\\.txt", "u"));
   });
   ```
