# 第 27 批 · 编辑控件名称与 PPT 色板回显

状态：本片实现与隔离 Home 实操通过，待第 27 批整体验证及一骏本人验收（2026-11-09）。

depends_on 为第 27 批基点 `8ad5927c3` 的工作台插件槽、内置插件字典和共用单选组键盘逻辑。本片承接 [第 27 批](../../../post-anticorruption-roadmap/reference/batches/27.md) 的 [F-17](../../copy-help-inventory.md#54-第二轮新增的跨页面问题)，对应 [BL-1038](../../../backlog/BL-1038.md) 和 [VUX-52、58](../../spec.md#4-验收标准)。

在真实 Host 的浏览器无障碍树中，Dataset 标题和表格图标，PPT 的标题、页标题与页操作，Jelly 的开始时间、结束时间和备注，Feed 和 Inbox 的图标动作已有名称。PPT 的主题色单选项名称仍是色值，例如 `#5e6ad2`。同时，普通保存将十六进制值规范成小写，打开编辑器时按区分大小写的字符串匹配，导致柔白背景和深灰文字的两个单选项在重开后失去已选状态。

补齐色板上三组十二个单选项的名称，把色值和双语色名键放在 PPT 原有色板定义中。浏览器名称由现有用途名与可区分的颜色名组成，例如「主题色 · 靛蓝」「背景 · 柔白」「文字 · 深灰」；英文为 “Accent · Indigo”“Background · Off-white”“Text · Dark gray”。屏幕上的色块与组标题继续由现有渲染器呈现。回显时按十六进制大小写等价判断已选项，原始输入继续交给现有保存动作。走工作台现有的 Tab、方向键和 Space 选择路径。

改动边界为 PPT 的 `src/colors.ts`、`src/messages.ts`、`src/ui.ts`、`src/browser/slides.ts` 及定向浏览器用例。其他四个插件只核回。Forms 已有[本批证据](../batch27-form-experience/spec.md)，SDK 与组件板已在代码核实图标按钮的必填 label。项目设置的插件行由在途改动占用，仍留原积压项跟踪。

### 验证记录

- **B27-NAMES-01 通过。** 基点和候选的 Dataset、Jelly、Feed、Inbox 在对应状态查到预期的浏览器名称。候选也核回中英文的 PPT 标题、页操作和大纲关闭按钮。Dataset 通过键盘改名、加列并打开同一张表；Jelly 用 Tab 到达起止时间，通过浏览器控件预置时间并用键盘写备注、提交。无效日期产生零次写请求，修正产生一次写请求，重开的同一事项含两段时间与备注。
- **B27-NAMES-02 通过。** 基点的十二个组合暴露十六进制名称；候选的十二个组合中，三组的十二个选项均在 AX 树有预期的双语用途和色名，每个色块中心都可命中。截图核对三个宽度与深浅主题的选中边框和布局。
- **B27-NAMES-03 通过。** 基点保存后 owner 有 `#fcfcfb` 与 `#292a2e`，重新打开后两个 radio 都返回未选中。候选重开显示已选中，Tab 与方向键零写；Space 一次更新将柔白保存为文字色，重开确认颜色、已选项与演示稿身份。另一次过期颜色更新被拒，保持本地草稿及原 owner 值；确认重新读取后恢复原选择与另一编辑器的说明，无附加写入。
- 候选整体构建通过，定向用例 23 项通过、零跳过。读屏软件实际朗读、桌面 WebKit、整批页面资源比对及本人验收仍待核。
