# 产品优化建议

最近更新：2026-10-24（事实基线挪到 main `5248af758`：H6 按服务端已按页面语言回话、Git 上游句在 #1109 里改写，H7 去掉已归档的 logic-diagnosis-fixes、插件数的说法跟上角色由宿主装配，新增 H23 记忆开关的说明与行为不符，其余条目不变）；2026-10-22（事实基线挪到 main `4591a1484`：B1、C1–C5、F4、H6、H8 按其后合入的 PR 与 2026-10-21 插件创作台的决定改写，其余条目不变）；2026-10-19 按新开场补"排序的变化"一节和 I10 · 依据 main `5248af758`、全部开放 PR 与远端分支、50 份活跃 spec、BACKLOG、内部官网调研的结论和本目录 research/。

这里记的是写产品介绍、挖场景时发现的缺口与建议，供产品排期参考。**它们是建议，不是立项、承诺或排期。** 每条写"问题 → 建议 → 依赖 → 怎么验证 → 什么结果推翻它"，并标优先级：

- **P0 推广阻断**：不补，对外推广会直接伤到第一批用户。
- **P1 killer 关键**：不补，某个 killer 场景的瓶颈环节过不去（编号对应 [killer 场景](killer场景.md)）。
- **P2 体验与增长**：补了会明显更顺、更容易传播。

处理过的条目在"去向"列写 spec、PR 或"不做"及理由，不删行。

## 新开场带来的排序变化

[产品介绍](产品介绍.md#1-口号与开场)的开场改成先讲信念、再讲四句"你的"之后，最打动人的两句（你的工具、你的 AI）恰好落在最不成熟的地方。下面几条建议往前挪；P0、P1、P2 的标签先不改，等负责人定。

| 开场的一句 | 证据缺在哪 | 建议往前挪 | 为什么 |
| --- | --- | --- | --- |
| 你的工具，长成你的样子 | 生成的插件搜不到、成果库不认、不能当流程一站；做法带不走、不能分享 | C1、G3 | "晒我的工作台"这类传播（[推广第 3 节](推广与用户运营.md#3-增长打法)）要先能导出；G3 现在只挂在 K4 下 |
| 你的 AI，按你的做法做事 | 技能包只在 spec；导入的 Skills 只在选了角色的那一轮展开 | G1、G2 | 导入一次、助理和 Coding 都照着做，才撑得起这一句 |
| 四句都要 | 第一天打开是通用的样子，什么都还不像"你的"；首日旅程没有设计 | A6、I1，新增 I10 | 开场承诺的是"你的"，第一天拿到的却是一张空工作台，落差最大 |

"要紧的事，你说了算"和"工作接得上"已经有已发布、main 可用的证据，排序不变。
