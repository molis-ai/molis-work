# 基础首页定样

状态：方案已定（2026-11-04，用户选「B 加插件卡片表」：上面是 B 的「等你」「接着做」，下面是 A 的完整插件卡片表），记入 [`specs/work-brief/spec.md`](../../../specs/work-brief/spec.md) §1.1 末尾的定样决定。原型里的 B 已改成选定的样子。产品没有实现；整页是模拟，不连 Home、不调模型，插件内容、计数和操作结果全是示例。

需求出处：[`specs/work-brief/spec.md`](../../../specs/work-brief/spec.md) §1.1～1.4（WBR-21～28）、[`specs/product-flow-governance/spec.md`](../../../specs/product-flow-governance/spec.md) §4.7、[`specs/intelligent-surfaces/spec.md`](../../../specs/intelligent-surfaces/spec.md) §13。排期见[第 15 批](../../../specs/post-anticorruption-roadmap/reference/batches/15.md)，界面要求是「先定样：基础首页、四种形态、跨位置操作与降级」。

四种形态（名字片、行、卡片、速览）已在第 03 批定为「插件领头」（[`intelligent-surfaces-forms/`](../intelligent-surfaces-forms/README.md) 方案 B）。九种状态与降级、操作与后果、同一份事实在各处一起变，也随那份定样看过。这一页不重定它们，直接照用，只定三件事：

- 首页怎么排；
- 四种形态放到首页上是什么样子；
- 首页自己特有的几种情况。

## 打开

```bash
python3 -m http.server 4410 --bind 127.0.0.1 --directory docs/design
```

再打开 `http://localhost:4410/basic-home/`。顶部斜纹条是原型控制：方案、情况、中英文、深浅、重置。

## 三个方案

三个方案用同一批插件、同一份事实，只差**首页怎么排**：

| 方案 | 怎么排 | 好处 | 代价 |
| --- | --- | --- | --- |
| A 插件卡片表 | 每个插件一张卡：插件色带、一句概况、两三行内容（行形态）、「打开」 | 最贴近需求原文；一眼看出项目里有哪些插件、各自怎样 | 要你管的事分散在各张卡里，要一张张扫；插件一多，页面很长 |
| B 先等你和接着做，再插件卡片表（已定） | 最上面「等你 N」（跨插件，同一件事只算一次），其次「接着做」，下面是 A 的完整插件卡片表；上面列过的不在卡里重复，卡里写「另有 N 件在上面」 | 先看到要你动手的和刚才在做的，各插件的全貌也还在 | 「等你」和底栏的「等你」入口内容重合；页面比 A 长一截 |
| C 今天的动静加插件栏 | 左边按时间列出今天各插件发生的事（行形态，带时刻），右边一列插件（概况、打开） | 接近现在的首页（当天事件加手边栏），换起来最少；按时间读最自然 | 要你管的事混在时间线里，靠状态标签找；没有动静的插件只在右栏一行 |

三个方案共用的部分（不在比较之列，也请一起看）：

- 基础首页只读各插件已有的内容、已产生的建议和声明的入口，不调模型，不假装是 AI 的结论；顶上写明这一点（WBR §1.1）。
- 插件卡与行都照 03 方案 B：插件色只在色块与色带里，状态色只在状态标签里。
- 同一件事只算一次：Inbox 那条和待办里的「回复王小姐」是同一件事，「等你」只算 1 件，并写明（WBR §1.4）。
- Feed 的归属按真实来源标「本项目」「个人」，同步来的资料写明「不算你接下的工作」，不计进等你或完成量（BL-098）。
- 没有声明首页内容的插件（例子里的「文本统计」）只显示名字和「打开」。
- 首页和对话里是同一份事实：在首页点「验收」，对话里那张卡也收成回执，反过来也一样。
- 「打开」进插件，首页留在原处；手机宽度上用「首页／助理」切换。

## 情况

| 情况 | 看什么 |
| --- | --- |
| 新项目，还没有内容 | 每个插件写「还没有内容」，配它自己声明的开始入口；顶上「从这里开始」：带入资料、开始一件工作、添加插件。不要求先配模型 |
| Goals 读不到 | Goals 的内容显示 2 小时前读到的值，标「读不到」，给「再读一次」；和「没有内容」分开 |
| Inbox 已停用 | Inbox 卡写「已停用，内容都还在」，给「启用」；它的事不算进「等你」，并写明少算了几件 |
| 后台在刷新 | 已有内容不清空，顶上写「正在更新…」；更新到的那一行轻闪一下，写「更新了 1 处」 |
| 装上了 Work Brief | 首页换成 Work Brief 组织的综合首页（模拟），用同一套行与卡片、同一份事实；可以「看基础首页」再回来 |
| Work Brief 的首页打不开 | 回到基础首页，顶上一条说明，内容和已打开的标签都在，给「再试一次」 |
| 写文稿时装好了 Work Brief | 当前停在「发布说明」标签，文稿不被打断；首页标签上一个小点，回去才看到综合首页 |

## 与组件板对照

按需求开发流程第 5 节（定样遵循组件板和整体设计规格，用户 2026-11-04 定）逐项对照组件板 `/__ui/catalog`。配色、字号、间距、圆角照 DESIGN.md 的令牌（原型里的 `:root` 是从它抄的）。

| 原型里的 | 组件板里用什么 | 说明 |
| --- | --- | --- |
| 按钮：主按钮、次按钮、图标按钮、「更多」 | Button | 现有 |
| 状态标签（要你验收、要你决定、失败、读不到）、「本项目」「个人」、计数「等你 3」 | Badge | 现有；状态色只用在这里 |
| 「Work Brief 的首页没能打开」那一条 | Alert | 现有 |
| 新项目的「从这里开始」 | Empty | 现有，带三个动作 |
| 「正在更新…」 | Spinner | 现有 |
| 首页、发布说明两个标签 | 工作台现有标签 | 现有，不是新控件 |
| 行：插件色块领头、标题、「时间 · 谁」、状态标签、主操作 | Item Row 加 **组件板新增**「呈现形态 · 行」 | 03 已定插件领头，组件板还没有这一节（IUI-21）。Item Row 没有插件色块和状态标签的位置，所以要新增 |
| 插件卡：插件色带、一句概况、几行内容、「打开」；读不到、已停用、没有声明三种样子 | Card 加 **组件板新增**「呈现形态 · 卡片」 | 色带是 03 定的插件领头卡片的头部；Card 没有插件色带和这三种降级的样子 |
| 对话里的卡片、回执 | **组件板新增**「呈现形态 · 卡片／回执」 | 同上，03 定样里已有，随 IUI-21 一起补 |
| 插件色 | **组件板新增** 插件色盘 | 05② 共审定为平台分配；色盘与状态色分开，浅深两套，进组件板「色板」一节 |

标「组件板新增」的几项，定下后先补成组件板标本，再进产品。

## 建议走一遍

1. 方案 A、B、C 各看一遍「正常」。在任一处点「验收」，看右边对话里那张卡一起变成回执，再撤销。
2. 情况一个个切，三个方案都看。
3. 换 EN、深色，窗口缩到 1024 和手机宽度。

## 模拟的部分

- 插件、对象、计数都是 `data.js` 里的示例；操作只等 0.65 秒写回执，「打开」「开始」「速览」「更多」只弹提示。
- Work Brief 的综合首页只是示意它接管首页、用同一套组件，内容组织不在这次定样里。生成首页归 Onboarding 与 Work Brief，以后另行定样。
- 控件是原型自己的样式，不是 `mw-*` 组件；做产品前换成组件板里的控件，按 IUI-21 在组件板加「呈现形态」一节。功能验收要用真实插件内容与持久状态再走一遍（WBR-21～28）。
- 状态存在浏览器 localStorage（键 `molis-proto.basic-home.v1`），「重置」清掉。
