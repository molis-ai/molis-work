## 1. 背景

来源：MISC「T-208 起草」`search-sources.ts` 一行。`packages/contracts/src/platform/search-sources.ts:79-84` 的 `searchText(value, max = 4000)` 去掉控制字符、折叠空白后 `.slice(0, max)`，`max` 是 UTF-16 单元数，截点落在两单元字（emoji 等）中间时，结果末尾留下一个落单的高位代理。它是插件搜索条目的共用写法：`plugin-sdk` 重导出（`packages/plugin-sdk/src/index.ts:50`），Alchemist、Cognia、Dataset、Feed、Form、Goals、Images、Jelly、Lingguang、PPT、Schedule、Shelf、Todo、`modules/artifacts` 都在用（`git grep -n "searchText("` 全列），标题与摘要因此可能带着半个字进搜索索引，再显示给人。

本仓库对同一问题的既有写法有两种：上限按单元、只去掉落单的高位代理（T-195 的 `cutHead`，`apps/local-host/src/contextual/`）；上限按字数（T-079 的 `[...text.slice(0, 2 * n)].slice(0, n).join("")`）。

## 2. 目标

1. `searchText` 截后的结果不以落单的高位代理结尾；`max` 的含义在 JSDoc 里写明（按单元，或按字数）。
2. 不让任何调用者的结果比现在更长超过 `max` 个单元（索引大小的预算有约束）。
3. 有用例：边界落在两单元字中间的输入。

## 3. 不做

- 不改各插件调用处的数字。
- 不改 `searchRevisionOf` 等同文件别的函数。
- 公开 API 的签名不变；若要改签名（比如加参数），先停下来问。

## 4. 范围

`packages/contracts/src/platform/search-sources.ts`（只 `searchText`）、一个新测试文件（`tests/` 下，名字自定，测试名带编号）；`tooling/gates/api/` 快照应当不变（签名不变），变了就是越界。

锁定：无（2026-10-29 核：没有在途 PR 和 `task/*` 分支改着这个文件）。

## 5. 做法

推荐 A：上限仍按单元，截完若最后一个单元是落单的高位代理（U+D800～U+DBFF）就去掉它。最小改动，结果只会短一个单元，不会更长。形状：

```ts
// 改前（search-sources.ts:79-84 的最后一行）
return raw.replace(/[\u0000-\u0008…]/gu, " ").replace(/\s+/gu, " ").trim().slice(0, max);
// 改后
const cut = raw.replace(…).replace(/\s+/gu, " ").trim().slice(0, max);
const last = cut.charCodeAt(cut.length - 1);
return last >= 0xd800 && last <= 0xdbff ? cut.slice(0, -1) : cut;
```

（`replace(…)` 是原来那两段，原样保留；`max` 为 0 或结果为空时要不出错。）如果你查到调用者依赖“按字数”，改选 B 并在【方案】里说明；不要把整个字符串展开成数组。更新 `searchText` 上面那句 JSDoc，写明“按 UTF-16 单元数截，截点落在两单元字中间时去掉落单的半个字”。共享核心，`full` 以 `affected-tests` 为准，预计为 true，排 Full 由统筹。

## 6. 验收
