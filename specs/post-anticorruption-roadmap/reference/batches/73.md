# 73 · 完整导入导出与升级 U7

[执行目录](../../spec.md#execution-batches) · 阶段 3：持续工作与创作 · [上一批 72](72.md) · [下一批 74](74.md) · [执行规则](../execution-rules.md)

<a id="batch-73"></a>

## 给人讲清楚

现在技能包、工作流、生成的插件、场景方案和整份数据，都还没法完整地导出给别人或换台机器导入。这一批做这些东西的导出和导入：导入前预览内容和权限、检查依赖和版本、处理冲突，部分失败能恢复；整份 Home 能稳定地导出导入，并和在线备份分开验证；生成插件的业务数据导出，单独验证能读回来。需要你做的：看分享范围、导入采用和恢复的样子并定下。

## 交付与前置

- **阶段／类型**：3；横向能力
- **需求来源**：[产品建议 G3／I2][P]、[技能包][SKP]、[Onboarding §3.13][ONB]、[创作台升级][PBU]、[升级 U7][UPG]、[智能呈现第四片][IUI]
- **前置／待决**：各子项分别满足下表条件；U7 不以服务端在线备份为前置。 各导入项都须验证内容／权限预览、依赖／版本、冲突、部分失败与恢复。格式只有插件或平台服务声明的段，不含固定的 goals 段或任何插件名字段，没有 Goals 的项目与 Home 完整导出、导入，所以等 44-5（资产包与同步按声明的段）（2026-11-13，[决定 42](../decisions.md#decision-42)）。
- **可并行项**：75 的统计与系统入口交互设计
- **UI 要求**：先定样：分享范围、导入采用与恢复
- **粒度**（批内子分支怎么分，全批仍是一个 PR；开工建议，执行时按[开发流程第 8.4 节](../development-workflow.md#batch-grouping)判断）：第 1、2 项（技能包、工作流、生成插件、场景方案、保存操作面）同一格式，一个子分支；整份 Home 导出和业务数据回读要单独证明，单独一个 PR（第 8.4 节的提前切出）。

| 交付项 | 做什么、产出什么 | 该项前置 |
| --- | --- | --- |
| <a id="batch-73-item-1"></a>技能包、工作流与生成插件导入导出 | 内容／权限预览、依赖／版本、冲突／部分失败及恢复；角色样例包可分享。 | 08、09、42、46、68；沿同一格式：按类导出导入的包形状与最小路径由 09 定（提示词改写、角色说明、工具与 MCP 只带引用），本项补齐预览、冲突、部分失败与恢复（2026-11-08 能力包扩展，见 [09](09.md#batch-09-capability-pack)）；导出导入的包不含 `goal-advance`（44-7） |
| <a id="batch-73-item-2"></a>场景方案与保存操作面导入导出 | 场景方案、保存操作面及后续组装产物使用同一格式，支持采用与恢复。 | 46、68、72 的格式 |
| <a id="batch-73-item-3"></a>整份 Home 导出与导入 U7 | 稳定、带版本的整份 Home 导出／导入，和在线备份分开验证；整份 Home 导出的段清单由各主人声明，缺某插件时该段跳过并如实记缺口 | 05 的 U1 与 Home 相关合同；按自身依赖推进，不等全部场景产物 |
