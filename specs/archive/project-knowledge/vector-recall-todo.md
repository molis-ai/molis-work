# 项目资料的向量召回：后续待办

2026-10-19 用户定：原 [spec](spec.md) 里的 K4（向量召回）拆到这里，和这一期分开。这一期只做 Agent 的工具式检索（参考 Claude Code、Codex 的 agentic search 和 PageIndex 的目录树推理，见 spec §6、§7）。本文只记以后要做什么、做之前要先回答什么，不是在做的需求；真正开工时，把它改写成一份带状态句和验收编号的 spec。

## 1. 什么时候再开

先看这一期的召回评测（spec §10.1）：工具式检索在哪类问题上找不到。只有评测里出现了「换个说法就找不到」这一类、而且改提示词和工具形状都解决不了的失败，才值得加向量。没有这类失败就不做。

## 3. 开工前要定的

- 向量放哪：本服务的 `knowledge.db` 旁表，还是搜索索引的存储里；删项目、换模型时谁清。
- 向量召回接在哪个动作上：并进 `knowledge.search` 的排序（Agent 看不出区别），还是另给一个「按意思找」的动作让 Agent 自己选。工具式检索的思路更偏后者。
- `summary` 可见度的来源仍不进向量索引（PMAT-04 不变）。
- 本机 embedding 服务没开、或远程失败时，召回退回关键字，界面怎样说明。
