# 待办详情页定样（可点）

状态：**已定稿**（2026-11-21 出样，同日用户定：正文加右侧属性栏、状态片点开菜单、主按钮是「完成」、修改记录平时收成一行）。Todo 插件里打开一件待办后的那一页。不是产品代码；定稿后在 `plugins/native/todo/` 里实现，实现时逐屏对照这里的各个状态。

前提：打开一条记录后它占满插件工作区、旁边不再并排列表（第 36A 批壳层的改动），所以这一页按整页宽来设计。

## 怎么看

从 `docs/design` 起服务（`../kit/` 才找得到）：

```bash
python3 -m http.server 4453 --bind 127.0.0.1 --directory docs/design
```

打开 `http://127.0.0.1:4453/todo-detail/`。页面顶上一排按钮各进一个状态，右边切宽度（1440、1024、820、390）、深浅色、中英文。窗口里的东西可以直接点：标题和说明能改，状态片、右边每一行、「关联一件待办」、⋯ 都能点开。

地址参数：`?do=<状态>` 直接进某个状态，`&w=1024`、`&theme=dark`、`&lang=en`；`&bare` 只留窗口、`&still` 关掉动效（截图用）。

| `do=` | 画的是什么 |
| --- | --- |
| `view` | 看一条待办（默认） |
| `title`、`title-empty` | 改标题；标题清空后离开 |
| `notes` | 改说明 |
| `status` | 状态菜单打开 |
| `waiting` | 等待他人：多出「在等谁、等什么、哪天跟进」一块 |
| `due`、`planned`、`remind` | 定截止、计划日期、提醒 |
| `place` | 换放在哪 |
| `important` | 标重要 |
| `delegate`、`review` | 交给助理推进；助理等你确认 |
| `done` | 已完成 |
| `overdue` | 已逾期 |
| `empty` | 只有标题：没有日期、说明、关联，来源是手动 |
| `link` | 加关联 |
| `history` | 修改记录展开 |
| `more` | 更多操作 |
| `conflict` | 这件待办在别处改过 |
| `delete` | 删除前确认 |

窗口的顶部页签和底栏只是示意（照[底栏第十三版](../screen-polish/README.md)简画），不在这次设计里。

## 现在的问题

- 一页宽约 1400，表单只占左边 730 一窄列，右边大片空白。
- 十来个灰底输入框一个摞一个，每个带小标签和说明，层次是平的，像后台表单。
- 「是什么、现在怎样、能做什么」和日期、归属、来源混在同一列里，没有主次。
- 右上角归属片、状态、「交给助理推进」「更多」挤在一行。
- 日期和时间用的是操作系统自带的控件，「关联」用的是系统下拉（[工艺底线](../../../specs/ui-craft-floor/spec.md)不许）。

## 这一版怎么排

**第一眼只有三样。** 最大的字（20 / 600）是这件事本身；标题下面一行是带颜色的状态片和最要紧的日子（「周四 18:00 截止 · 还有 2 天」）；右上角是能做的事，其中只有一个实心按钮「完成」。

**日期和归属退到右边一块浅底里。** 截止、计划做、提醒、放在、重要是这件事的属性，不是主角：一行一件，左边名字、右边值，整行可点；没填的写「未定」。这一块跟着页面滚动时停在顶上。

**标题和说明像文档，不像表单。** 没有灰底框和小标签：鼠标移上去有浅底，点进去是雾蓝框，停手自动保存；保存到哪一步写在页面右上角（尚未保存 → 保存中 → 已保存）。

**状态是一枚带颜色的片。** 蓝＝在办，青＝在等别人，绿＝做完，灰＝没开始或不做了（颜色的意思照 [DESIGN.md](../../../DESIGN.md) 的配对表）。点开是菜单：上面三种「还在办」，下面两种「结束了」，每种一句人话。最常用的「完成」单独是主按钮，不用进菜单。

**用到才出现。**

- 「在等谁、等什么、哪天跟进」只在状态是等待他人时出现，紧挨在标题下面，光标直接落进去。
- 「助理在办什么」只在交给助理以后出现，头部的「交给助理推进」让位给它（不重复）。助理要你点头时，这一块变成琥珀色，「去确认」成为这一屏唯一的主按钮，「完成」退成次要按钮。
- 修改记录平时收成一行，只说最近一次；点开才是全部，最近一次能撤销。
- 完成以后这一屏没有主按钮：右上是「重新打开」和「归档」。

**不同的东西长得不一样。** 来源是一张带引文的卡（哪来的、为什么成了待办、原话）；关联是一组行，关系是不同底色的小标签；助理的东西是浅蓝底。手动记下的待办，来源只有一行字，不画卡。

**日期不用系统控件。** 点一行，浮层从这一行长出来：先是最常用的几个日子，再是月历（组件板的 `mw-calendar`），截止和提醒下面还有时间（一个框加三个常用时刻）。点了就生效，不用另按保存。提醒的浮层底下一句话说清在哪提醒、应用关着会怎样。

**关联不用系统下拉。** 点「关联一件待办」：先选关系（三选一），再搜或点一件，点了就连上。

**出了岔子说在原处。** 标题清空：框变红、下面说原因，别的输入都留着。别处改过：页面顶上一条提示说清发生了什么、你的输入还在，并直接给「重新读取」（现在要去「更多」里找）。

## 宽度

版面跟着这一页自己的宽度变（容器查询），所以右侧栏打开、分屏时和窄窗口是同一套规则。

- **宽（页面 ≥ 880）**：正文一列、属性一列（312，页面 ≤ 1020 时 280），两列合起来最宽 1040，居中。
- **中（页面 < 880，例如 820 的窗口）**：属性块挪到标题下面，时间和归属左右各一半；正文接在后面。
- **手机（页面 < 560）**：一列；两个动作在状态下面一人一半；先说明、再属性；行高 44；浮层从底部升起、后面压暗。

## 动效

都用现成的时长和曲线，`prefers-reduced-motion` 时全部去掉。

- 菜单和日期浮层从触发它的那一行长出来（250ms）；手机上从底部升起。
- 「在等谁」和「助理在办什么」两块到达时上浮 6px（420ms）。
- 换状态时状态片里的环弹一下，颜色过渡 250ms；完成后底部出提示条，带「撤销」。
- 修改记录的箭头转 90°。

## 实现和原型不一样的地方

实现在 `plugins/native/todo/`（`src/ui.ts`、`src/styles.ts`、`src/browser/detail*.ts`）。下面几处是有意不同：

- **左边多一列待办列表。** 宽屏时产品里详情和列表并排（原型只画了详情一页）；正文和属性栏按详情区自己的宽度换排，不按窗口宽度。
- **归属下面那一句由平台给。** 原型画的是一把锁加「只有你和获授权的助理能看到」；产品里是平台的归属片，这里只留「谁能看到」那半句，去处由上面「放在」一行说。
- **标题和说明聚焦时是一圈细线，没有外圈光晕。** 平台规定输入框聚焦只用框内 1px 的线。
- **常用日子会少几项。** 「本周五」只在周一到周三出现（周四时就是「明天」，周五以后已经过了）；周日不出现「下周一」（就是「明天」）。
- **助理的工作一栏没有步骤文字。** 平台现在只给这项工作的名字和状态，没有「正在做哪一步」。
- **英文界面的 “Complete”。** `todo.action.complete` 由 “Completed” 改成按钮该用的 “Complete”。

## 没画的

- 待办列表、快速记下、整理审阅：不在这次范围。
- 助理对话框本身（交给助理后底部发生的事）：照底栏第十三版，这里只示意输入框里多了一枚「待办」片。
- 归档后的样子、其他项目的待办（来源不能点开）的样子：规则不变，没单独出图。
- 键盘走菜单（方向键、Home/End）：产品里由共用的 roving focus 负责，原型里只有 Esc 关闭和回车离开标题。
